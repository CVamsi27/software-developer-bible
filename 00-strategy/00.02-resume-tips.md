# Resume Tips for Senior Full Stack Engineers

## Definition

A resume is a short document used to screen candidates. It connects evidence of your work to the target role. It should help a reader find your responsibilities, contribution and results, and support the later interview discussion.

## First Principles

1. The reader has limited attention. Put the most relevant evidence where it is easy to find.
2. Claims must survive follow-up. Use truthful scope and observable outcomes rather than invented metrics.
3. Each role values different evidence. Tailor emphasis from a complete record of your work while keeping the facts consistent.

## Build From Evidence

Start with a role's requirements, then select the projects that demonstrate them. For each project, record the problem, your action, the result and how you know the result. This evidence also becomes material for [STAR stories](00.03-star-method.md).

```text
job requirement → relevant project → your contribution → supported outcome
```

Compare these bullets:

- “Responsible for API performance.” The scope and outcome are unclear.
- “Removed repeated catalog queries by adding a bounded cache and invalidation on edits; p95 response time fell from 800 ms to 120 ms in the production dashboard.” This names the mechanism and evidence.

Those numbers are an example, not values to copy. When exact measurements are unavailable, use a concrete result such as adoption by four teams, removal of a manual step or an incident's verified recovery. Do not turn an estimate into a precise percentage.

## Arrange the First Page

Use clear contact information, a short role-specific summary where useful, relevant experience, grouped skills and education. Add projects, publications or certifications when they supply evidence the experience section does not.

A summary should state the work you can substantiate: domain, scale and a significant contribution. “Experienced, passionate team player” provides little information by itself. Within a role, give enough product context to understand the achievement, then keep bullets focused on changes you helped produce.

Group skills by language, frontend, backend, data and platform when that matches the target. A relevant older technology is legitimate experience; age alone does not make it useless. Avoid claiming expertise from a brief workshop.

## Make the File Readable and Parseable

Application systems differ in parsing and screening behavior; there is no universal rejection percentage or fixed recruiter scan time. Use standard headings, consistent dates and simple layouts to reduce ambiguity. Follow the employer's requested file format. If submitting PDF, verify both its rendering and extracted text order.

| Check | Why |
| ---------------------------------- | ------------------------------------------------------------ |
| Plain, readable section headings | Humans and parsers can identify the content |
| Accurate role vocabulary | Relevant experience is discoverable without keyword stuffing |
| Consistent dates, titles and links | The record can be compared across documents |
| Readable font and spacing | Density does not make the evidence hard to scan |
| Correct PDF/text extraction | Visual correctness alone does not prove parsing order |

Use one or two pages according to relevant evidence and the application context; a ten-year threshold is not a rule. Remove repetition before shrinking the font. Avoid unnecessary personal details and follow the particular employer's application instructions.

## Tailor and Validate

Maintain one comprehensive achievement record, then choose material for each role. If the job asks for observability, describe genuine monitoring or tracing work in recognizable language. Do not add tools you cannot discuss.

Ask a peer to scan the resume briefly and explain what role, scale and contribution they remember. Check that every prominent claim has a supporting story. Verify contact details, links, spelling, dates and the exported file before submitting. Keep versions associated with applications so feedback can improve the next draft.

## Common Mistakes

| Mistake | Repair |
| ------------------------------------------- | --------------------------------------------------- |
| Listing responsibilities only | Explain a change and its outcome |
| Inventing numbers to satisfy a metric quota | Use verifiable qualitative or quantitative evidence |
| Listing every tool ever touched | Select relevant tools and truthful depth |
| Copying job keywords without experience | Show where the skill was actually applied |
| Packing in unrelated history | Keep evidence that helps assess this role |
| Sending an unchecked export | Inspect rendering, text order and links |

## Summary

Build the resume from evidence, place relevant contributions early, and use a readable format that survives export and parsing. Tailor emphasis without changing facts, then test whether a reader can explain your value and whether you can defend each claim.

# Declaration Files (.d.ts)

[![Category: Core](https://img.shields.io/badge/category-Core-blueviolet)](.)

ribe the shape of JavaScript code — types, interfaces, functions, classes, and modules — without containing any implementation. They provide type information for plain JavaScript libraries, ambient modules, global variables, and custom type definitions. Declaration files enable TypeScript to understand and type-check JavaScript code, including third-party libraries that don't ship their own TypeScript types.

## Why Do We Need It?

1. **Type existing JS libraries** — Add types to libraries that don't ship `.d.ts` files
2. **Publish TypeScript libraries** — Ship compiled JS + declarations for consumers
3. **Ambient declarations** — Describe global variables, APIs, and DOM extensions
4. **Module augmentation** — Extend third-party types with additional properties
5. **Type library boundaries** — Define public API contracts for packages

## How It Works

### Declaration File Types

```text
Declaration File Types:
═══════════════════════════════════════════════════════════════

.d.ts file categories:

┌─────────────────────────────────────────────────────────────┐
│ 1. Module Declarations                                        │
│    declare module 'some-lib' { ... }                         │
│    Used for: Libraries without built-in types                │
│    Example: @types/some-lib                                  │
│                                                              │
│ 2. Global Declarations                                        │
│    declare var $: JQueryStatic;                              │
│    declare function fetch(input: RequestInfo): Promise<...>; │
│    Used for: Script-loaded globals (jQuery, lodash)          │
│                                                              │
│ 3. Augmentation Declarations                                  │
│    declare module 'express' { interface Request { ... } }    │
│    Used for: Extending types from existing packages          │
│                                                              │
│ 4. Library Declaration Files                                  │
│    // Generated by tsc --declaration                          │
│    Used for: Publishing typed packages                       │
│                                                              │
│ 5. Ambient Declarations                                       │
│    /// <reference types="vite/client" />                     │
│    declare module '*.svg' { const src: string; }             │
│    Used for: Asset imports, environment variables            │
│                                                              │
└─────────────────────────────────────────────────────────────┘

```

### Declaration vs Implementation

```text
Implementation (.ts) vs Declaration (.d.ts):
═══════════════════════════════════════════════════════════════

// ─── Implementation (lib.ts) ────────────────────────────────
export function greet(name: string): string {
  return `Hello, ${name}!`;
}

export interface User {
  id: number;
  name: string;
}

// ─── Declaration (lib.d.ts) ─────────────────────────────────
export declare function greet(name: string): string;
export interface User {
  id: number;
  name: string;
}

// Note: The .d.ts file only has TYPES — no implementation
// Key differences:
// ├── declare keyword: Marks as "exists but not here"
// ├── No function bodies: Just signatures
// ├── No import/export: Only type references
// └── Can include: interfaces, types, declare class

```

## Code Examples

### 1. Basic Module Declaration

```typescript
// types/some-lib.d.ts
declare module 'some-lib' {
  // Exported functions
  export function parse(input: string): ParsedResult;
  export function format(data: FormatData): string;

  // Exported interfaces
  export interface ParsedResult {
    success: boolean;
    data: Record<string, any>;
    errors?: string[];
  }

  export interface FormatData {
    template: string;
    variables: Record<string, any>;
  }

  // Exported classes
  export class Parser {
    constructor(options?: ParserOptions);
    parse(input: string): ParsedResult;
    reset(): void;
  }

  export interface ParserOptions {
    strict?: boolean;
    encoding?: 'utf-8' | 'ascii';
  }

  // Default export
  export default function someLib(): void;

  // Re-export from other modules
  export { SomeType } from './types';
}
```

### 2. Global Type Declarations

```typescript
// types/global.d.ts
// Declarations that apply globally without import

// Global variables
declare var __APP_VERSION__: string;
declare var __DEV_MODE__: boolean;

// Global functions
declare function logEvent(eventName: string, properties?: Record<string, any>): void;

// Global interfaces
interface Window {
  gtag: (command: string, target: string, params?: Record<string, any>) => void;
  dataLayer: Record<string, any>[];
  __INITIAL_STATE__?: Record<string, any>;
}

// Augment existing global types
interface Document {
  startViewTransition(callback: () => void): ViewTransition;
}

// Ambient namespaces
declare namespace MyApp {
  function init(config: AppConfig): void;
  interface AppConfig {
    apiUrl: string;
    debug?: boolean;
  }
}

// Augment existing interfaces
interface Array<T> {
  // Custom method added via polyfill
  groupBy<K extends string>(keyFn: (item: T) => K): Record<K, T[]>;
}
```

### 3. Module Augmentation

```typescript
// types/express-augmentation.d.ts
import 'express';

// Augment the Express Request interface to add custom properties
declare module 'express' {
  interface Request {
    user?: {
      id: string;
      email: string;
      role: 'admin' | 'user';
    };
    tenant?: {
      id: string;
      name: string;
    };
    requestId?: string;
  }

  interface Response {
    sendSuccess(data: any, statusCode?: number): void;
    sendError(message: string, statusCode?: number): void;
  }
}
```

### 5. Class-Type Declarations

```typescript
// types/database.d.ts
declare module 'my-database' {
  // Declare a class with overloaded constructor
  export class Database {
    constructor(config: DatabaseConfig);
    constructor(url: string, options?: ConnectionOptions);

    // Methods with overloads
    query(sql: string): Promise<QueryResult>;
    query<T>(sql: string, params: any[]): Promise<T[]>;

    // Properties
    readonly connected: boolean;
    readonly config: DatabaseConfig;

    // Static members
    static create(config: DatabaseConfig): Database;
    static fromURL(url: string): Database;

    // Index signature
    [key: string]: any;
  }

  export interface DatabaseConfig {
    host: string;
    port: number;
    username: string;
    password: string;
    database: string;
    pool?: {
      min?: number;
      max?: number;
    };
  }

  export interface QueryResult {
    rows: any[];
    count: number;
    duration: number;
  }

  export interface ConnectionOptions {
    timeout?: number;
    ssl?: boolean;
    poolSize?: number;
  }
}
```

### 6. Generic Type Declarations

```typescript
// types/event-emitter.d.ts
declare module 'typed-emitter' {
  // Generic type-safe event emitter
  export class TypedEmitter<Events extends Record<string, any>> {
    // Method overloads for different event types
    on<K extends keyof Events>(
      event: K,
      listener: (payload: Events[K]) => void
    ): this;

    once<K extends keyof Events>(
      event: K,
      listener: (payload: Events[K]) => void
    ): this;

    emit<K extends keyof Events>(event: K, payload: Events[K]): boolean;

    off<K extends keyof Events>(
      event: K,
      listener: (payload: Events[K]) => void
    ): this;

    // Remove all listeners for an event
    removeAllListeners<K extends keyof Events>(event?: K): this;
  }

  // Utility type to extract event names
  export type EventNames<Events> = keyof Events;
}

// ─── Usage ──────────────────────────────────────────────────
interface AppEvents {
  'user:login': { userId: string; timestamp: number };
  'user:logout': { userId: string };
  'error': { message: string; code: number };
}

const emitter = new TypedEmitter<AppEvents>();
emitter.on('user:login', ({ userId, timestamp }) => {
  // ✅ Fully typed payload
});
```

### 7. Namespace + Module Hybrid

```typescript
// types/jquery.d.ts — Classic pattern for namespaced libraries
declare namespace $ {
  // Utility functions
  function ajax(settings: AjaxSettings): JQueryXHR;
  function get(url: string, data?: any): JQueryXHR;
  function post(url: string, data?: any): JQueryXHR;

  // Static properties
  const support: SupportMap;
  const mobile: boolean;

  // Interfaces
  interface AjaxSettings {
    url: string;
    method?: string;
    data?: any;
    headers?: Record<string, string>;
    success?: (data: any) => void;
    error?: (xhr: JQueryXHR, status: string) => void;
    timeout?: number;
  }

  interface JQueryXHR {
    responseJSON: any;
    status: number;
    readyState: number;
    abort(): void;
  }

  interface SupportMap {
    cors: boolean;
    opacity: boolean;
  }
}

// Make available globally
declare var jQuery: typeof $;
```

### 8. Conditional Type Declarations

```typescript
// types/async-utils.d.ts
declare module 'async-utils' {
  // Conditional return type based on input
  export function wrap<T>(
    input: T
  ): T extends Promise<any> ? T : Promise<T>;

  // Overloaded function
  export function debounce<F extends (...args: any[]) => any>(
    fn: F,
    wait: number,
    immediate?: false
  ): (...args: Parameters<F>) => void;

  export function debounce<F extends (...args: any[]) => any>(
    fn: F,
    wait: number,
    immediate: true
  ): (...args: Parameters<F>) => void;

  // Promise utility
  export type MaybePromise<T> = T | Promise<T>;

  // Recursive type
  export type DeepPartial<T> = {
    [K in keyof T]?: T[K] extends object ? DeepPartial<T[K]> : T[K];
  };
}
```

### 9. Publishing Generated Declarations

```typescript
// tsconfig.json — Generate declaration files
{
  "compilerOptions": {
    "declaration": true,           // Generate .d.ts files
    "declarationMap": true,        // Generate .d.ts.map files
    "declarationDir": "./types",   // Output directory
    "emitDeclarationOnly": false,  // Emit .js AND .d.ts
    "outDir": "./dist",            // Compiled output
  }
}
```

```json
// package.json — Point consumers to types
{
  "name": "my-library",
  "version": "1.0.0",
  "main": "dist/index.js",
  "types": "types/index.d.ts",     // Entry point for types
  "files": [
    "dist/",
    "types/"
  ]
}
```

### 10. Triple-Slash Directives

```typescript
/// <reference path="./other-types.d.ts" />
/// <reference types="node" />
/// <reference lib="es2020" />

// These directives tell TypeScript about dependencies:

// path: Reference another .d.ts file
// types: Reference @types/node package
// lib: Reference built-in lib (es2020, dom, etc.)

// Common example in ambient declaration files:
/// <reference types="vite/client" />

// Also useful for testing globals:
/// <reference types="vitest/globals" />
// Allows using describe, it, expect without imports
```

## Real-World Use Cases

| Scenario | Declaration Type | Example |
|----------|-----------------|---------|
| **Publish a library** | Generated `.d.ts` | React, Lodash, Express |
| **Type a JS library** | Manual `.d.ts` in `@types/` | `@types/react`, `@types/lodash` |
| **Custom window properties** | Global augmentation | `window.gtag`, `window.dataLayer` |
| **Add Express Request user** | Module augmentation | `declare module 'express' { ... }` |
| **Import SVGs/CSS** | Asset declarations | `declare module '*.svg'` |
| **Environment types** | ProcessEnv augmentation | `process.env.API_URL` |
| **Vite/Webpack features** | Ambient declarations | `import.meta.env`, `require.context` |

## Common Mistakes

### 1. Missing `declare` Keyword

```typescript
// ❌ BAD: Missing declare
module 'some-lib' {
  function parse(input: string): any; // Error: needs declare
}

// ✅ GOOD: With declare
declare module 'some-lib' {
  function parse(input: string): any;
}
```

### 2. Using `export` in Ambient Module

```typescript
// ❌ BAD: Both export and declare
declare module 'my-lib' {
  export declare function foo(): void; // Redundant!
}

// ✅ GOOD: Just export (or just declare)
declare module 'my-lib' {
  export function foo(): void;
}

// OR
declare module 'my-lib' {
  function foo(): void;
}
```

### 3. Not Excluding .d.ts from Build

```typescript
// ❌ BAD: .d.ts files in src/ end up in dist/
src/
  types/
    global.d.ts    // Compiled to dist/types/global.d.ts
  index.ts
  index.d.ts       // ❌ Manual .d.ts in source!

// ✅ GOOD: Keep .d.ts in a separate types/ directory
types/
  global.d.ts     // <!-- reference path="./global.d.ts" -->
src/
  index.ts
```

### 4. Overly Broad Typing

```typescript
// ❌ BAD: Loses type information
declare module 'my-lib' {
  export function process(data: any): any; // Too loose!
}

// ✅ GOOD: Preserve types
declare module 'my-lib' {
  export function process<T>(data: T): T;
}
```

## Best Practices

1. **Use `@types/` packages first** — They're community-maintained and comprehensive
2. **Generate declarations automatically** — Use `declaration: true` in tsconfig
3. **Ship declarations with packages** — Set `"types"` in package.json
4. **Keep `.d.ts` files in a `types/` directory** — Separate from source
5. **Use triple-slash references sparingly** — Prefer `tsconfig.json` paths
6. **Always use `declare` in ambient modules** — It's required
7. **Prefer `interface` over `type` in declarations** — Interfaces merge and extend better
8. **Document public API** — JSDoc comments carry through to IDE intellisense
9. **Test declaration files** — Run `tsc --noEmit` to validate

## Summary

- `.d.ts` files describe JavaScript types without implementation — enabling type checking for plain JS libraries
- Use `declare module 'name'` for module declarations, `declare var/func` for globals
- Module augmentation with `declare module 'existing-lib' { interface X { ... } }` extends existing types
- Generate declarations automatically with `declaration: true` in tsconfig for publishing
- Keep manual declaration files in a `types/` directory, separate from source code

# Call Stack

When deep recursion halts with `RangeError: Maximum call stack size exceeded`, what structure filled up, why is its memory bounded, and how does the runtime coordinate nested function returns?

```javascript
function first() {
  second();
}
function second() {
  third();
}
function third() {
  console.trace('Call Stack Snapshot');
}
first();
```

## Definition

The **call stack** is the runtime structure that tracks active function invocations, their local execution state, and return addresses on a **Last-In, First-Out (LIFO)** discipline. Calling a function pushes a stack frame holding its execution context; returning pops the frame and resumes execution at the instruction pointer stored in the caller's frame.

> **Textbook Definition:** A call stack is a last-in, first-out record of active function invocations and their continuation points. Completing an invocation returns control to its caller; implementation optimizations may alter the physical frames.

## First Principles

Single-threaded execution cannot evaluate two functions at once, so when `A` calls `B`, `A` must suspend, save its registers and next instruction pointer, and transfer control. Because calls nest symmetrically — the most recently invoked function finishes before its caller can continue — a stack models this lifecycle exactly. And because hardware stack buffers are fixed-size (typically 1MB–8MB per OS thread), unbounded nesting exhausts memory, which is why recursion needs base cases or iterative form.

## How It Works

### 1. Step-by-Step Frame Push and Pop Lifecycle

```javascript
function first() {
  console.log('1. first starts');
  second();
  console.log('5. first ends');
}

function second() {
  console.log('2. second starts');
  third();
  console.log('4. second ends');
}

function third() {
  console.log('3. third executes');
}

first();
```

The stack transitions through six states:

```text
Step 1: first() called     Step 2: second() called    Step 3: third() called
┌───────────────────────────────────────────────────────────────────────────┐    ┌─────────────────────┐    ┌─────────────────────┐
│                     │    │                     │    │ third() frame       │
├───────────────────────────────────────────────────────────────────────────┤    ├─────────────────────┤    ├─────────────────────┤
│                     │    │ second() frame      │    │ second() frame      │
├───────────────────────────────────────────────────────────────────────────┤    ├─────────────────────┤    ├─────────────────────┤
│ first() frame       │    │ first() frame       │    │ first() frame       │
├───────────────────────────────────────────────────────────────────────────┤    ├─────────────────────┤    ├─────────────────────┤
│ Global Context      │    │ Global Context      │    │ Global Context      │
└───────────────────────────────────────────────────────────────────────────┘    └─────────────────────┘    └─────────────────────┘

Step 4: third() returns    Step 5: second() returns   Step 6: first() returns
┌───────────────────────────────────────────────────────────────────────────┐    ┌─────────────────────┐    ┌─────────────────────┐
│                     │    │                     │    │                     │
├───────────────────────────────────────────────────────────────────────────┤    ├─────────────────────┤    ├─────────────────────┤
│ second() frame      │    │                     │    │                     │
├───────────────────────────────────────────────────────────────────────────┤    ├─────────────────────┤    ├─────────────────────┤
│ first() frame       │    │ first() frame       │    │                     │
├───────────────────────────────────────────────────────────────────────────┤    ├─────────────────────┤    ├─────────────────────┤
│ Global Context      │    │ Global Context      │    │ Global Context      │
└───────────────────────────────────────────────────────────────────────────┘    └─────────────────────┘    └─────────────────────┘
```

The stack records **who called whom** (the dynamic call graph). It does not resolve variables: `third` cannot see `second`'s locals unless it was lexically nested inside `second` in the source.

### 2. Anatomy of a Physical Stack Frame

In engines like V8, a frame is a contiguous block of native-stack memory holding:

- **Return address** — the hardware instruction pointer (e.g., `RIP` on x86-64) targeting the caller instruction after the `call`.
- **Saved frame pointer** — the previous frame's base pointer (`RBP`) for unwinding.
- **Parameters and arguments** — passed-in values (or pointers to register spill slots).
- **Local variables** — stack-allocated scalar bindings (`let`, `const`) that never escape into closures.

### 3. Stack Overflow: Causes and Mitigations

Recursion without a base case accumulates frames until the engine exceeds its limit — around 10,000–12,000 frames (~1MB) in V8:

```javascript
function recursiveBomb() {
  recursiveBomb(); // RangeError: Maximum call stack size exceeded
}
```

A common error is confusing total work with stack depth. Naive recursive Fibonacci does O(2ⁿ) work but never exceeds O(n) depth, because left branches unwind before right branches run. Naive recursive factorial does O(n) work at O(n) depth — and blows the stack around n = 100,000. The fix for unbounded depth is iteration or a **trampoline**, which converts recursion into a loop:

```javascript
// Iterative: O(1) stack space
function factorialIterative(n) {
  let acc = 1n;
  for (let i = 2n; i <= BigInt(n); i++) {
    acc *= i;
  }
  return acc;
}
```

### 4. Exception Unwinding and Stack Traces

A thrown error triggers **stack unwinding**:

```javascript
function alpha() { beta(); }
function beta() { gamma(); }
function gamma() {
  throw new Error('Database connection failed');
}

try {
  alpha();
} catch (error) {
  console.log(error.stack);
}
```

1. The engine looks for a `catch` in `gamma()`; finding none, it runs `gamma`'s `finally` blocks and pops its frame.
2. It repeats for `beta()`, then reaches the `try...catch` enclosing `alpha()` in the caller.
3. The `Error.stack` string snapshots the active frames at the moment the error was instantiated.

### 5. What Happens to the Stack at `await`

Async code never blocks the native stack:

```javascript
async function fetchUser() {
  console.log('1. Start fetch');
  await fetch('/api/user');
  console.log('3. Finish fetch');
}

fetchUser();
console.log('2. Synchronous caller continues');
```

`fetchUser()` runs synchronously and prints `1`. At `await`, the engine packages the function's state into a heap-allocated microtask continuation and **pops `fetchUser` off the stack**. The caller prints `2` and the stack empties. When the promise resolves, the microtask queue pushes `fetchUser()` back on to print `3`.

### 6. Tail Call Optimization (TCO) Reality Check

ES2015 specified Proper Tail Calls: `return fn()` in strict mode could reuse the current frame instead of pushing a new one. In production, only Apple WebKit / JavaScriptCore implements it — V8 and SpiderMonkey deliberately declined, citing lost debugging traces and spec conflicts. **Senior rule**: never rely on TCO for stack safety in cross-platform JavaScript; use explicit loops for unbounded depth.

## Summary

The call stack runs code as a LIFO stack of execution contexts and return pointers. Frames track dynamic calls while lexical scope chains resolve names. Deep or infinite recursion exhausts finite stack memory, so convert unbounded depth to iteration. Async functions release their physical frames at `await` and resume through the microtask queue without blocking the thread.

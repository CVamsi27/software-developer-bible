# This

Why does `account.describe()` return `'Alice'`, while `const fn = account.describe; fn()` throws `TypeError` in strict mode? The method body never changed — only how it was invoked.

```javascript
'use strict';

const account = {
  name: 'Alice',
  describe() {
    return this.name;
  }
};

console.log(account.describe()); // 'Alice'

const detached = account.describe;
try {
  detached(); // Throws TypeError: Cannot read properties of undefined (reading 'name')
} catch (error) {
  console.log(error instanceof TypeError); // true
}
```

## Definition

**`this`** is a receiver value used by executing code. For an ordinary unbound function, its invocation supplies that receiver, unlike enclosing variables which follow the defining environment. An arrow resolves the surrounding `this`; an ordinarily called bound function keeps its saved receiver. Function kind, construction and host callback rules therefore matter as well as call syntax.

> **Textbook Definition:** `this` is an execution-time receiver value resolved according to the function and invocation form. Ordinary calls establish a receiver binding; arrow functions obtain it from their surrounding lexical environment.

## First Principles

One method body is shared across thousands of instances via the prototype, so the executing function needs a dynamic parameter — the receiver — identifying which instance triggered the call. Variables resolve statically from source structure, but the receiver resolves dynamically from the caller. Detach the function from its call-site and the receiver falls back to default binding rules.

## 1. Follow the Invocation and Function Kind

For an ordinary unbound function, these call forms explain common receivers. Function kind and bound-function behavior add conditions; this is not one universal precedence algorithm:

| Precedence | Rule | Syntax Example | Resolved `this` |
| :-------------- | :------------------- | :---------------------------------------------- | :-------------------------------------------------------------------------------- |
| **1 (Highest)** | **`new` Binding** | `new Constructor()` | The constructed receiver; an explicit object return can replace the result. |
| **2** | **Explicit Binding** | `fn.call(ctx)`, `fn.apply(ctx)` | The supplied value for ordinary strict calls; sloppy functions substitute/box it. |
| **3** | **Implicit Binding** | `user.login()`, `api.client.fetch()` | The immediate object preceding the dot (`user`, `client`). |
| **4 (Lowest)** | **Default Binding** | `standaloneFn()` | `undefined` in strict mode; `globalThis` in sloppy mode. |

```javascript
'use strict';

function showReceiver() {
  return this;
}

const contextObj = { name: 'Context Object' };

// Rule 1: new Binding
function User(name) { this.name = name; }
const userInstance = new User('Charlie');
console.log(userInstance.name); // 'Charlie'

// Rule 2: Explicit Binding
console.log(showReceiver.call(contextObj)); // { name: 'Context Object' }

// Rule 3: Implicit Binding
const container = { show: showReceiver };
console.log(container.show() === container); // true

// Rule 4: Default Binding
console.log(showReceiver()); // undefined (in strict mode)
```

An ordinary call to a bound function uses its saved receiver, so another `call` or `bind` cannot replace it. If its target is constructible, `new boundFn()` ignores that saved receiver and keeps bound arguments. Arrows have lexical `this` and cannot be called with `new`.

## 2. The Detached Method Trap (Losing `this`)

Passing a method as a callback — to `setTimeout`, a promise chain, or an event listener — detaches it from its receiver:

```javascript
'use strict';

class Timer {
  constructor(name) {
    this.name = name;
  }
  tick() {
    console.log(`Tick from ${this.name}`);
  }
}

const timer = new Timer('Worker');

// BUG: Passing timer.tick detaches the function from 'timer'!
// setTimeout(timer.tick, 100); // Reads a host receiver, not this Timer
```

`setTimeout(timer.tick, 100)` passes the raw function reference. The host chooses the later receiver: browser window timers supply the window/global receiver, while Node supplies its timer object. Strict mode does not turn that explicit host receiver into `undefined`. The callback has lost this Timer either way; its exact output or error depends on what it reads. Promise reactions and DOM listeners have their own invocation rules. Three standard fixes:

```javascript
// Solution A: Explicit Function Wrapper (Preserves dot notation at invocation)
setTimeout(() => timer.tick(), 100);

// Solution B: Hard Binding with .bind() (Produces a bound function)
setTimeout(timer.tick.bind(timer), 100);

// Solution C: Class Field Arrow Function (Autobound on instance)
class AutoTimer {
  constructor(name) { this.name = name; }
  tick = () => { console.log(`Tick from ${this.name}`); };
}
```

## 3. Arrow Functions: Lexical `this` (No Runtime Receiver)

Arrow functions bind no `this` — their Function Environment Record has `[[ThisBindingStatus]]: "lexical"`. Inside an arrow, `this` resolves like any lexical variable by climbing outer environments. `.call()`, `.apply()`, and `.bind()` still execute, but the supplied `thisArg` is **silently ignored**:

```javascript
function makeReader() {
  return () => this;
}
const owner = { name: 'Owner' };
const lexicalArrow = makeReader.call(owner);
console.log(lexicalArrow.call({ ignored: true }) === owner); // true
```

**The object-literal trap**: braces in an object literal define data, not scope — so an arrow inside one does *not* see the object:

```javascript
const profile = {
  username: 'Alex',
  // WRONG: Object literals DO NOT create a lexical scope!
  getName: () => this.username
};

// In a classic browser script this reads the outer window's username,
// which may be absent. In an ES module, outer this is undefined,
// so reading this.username throws TypeError. It never selects profile.
```

Use method shorthand (`getName() { return this.username; }`) for implicit binding.

## 4. Class Constructors, `super()`, and Arrow Fields

- **Derived constructors**: in `class Child extends Parent`, `this` starts uninitialized. Touching it before `super()` throws `ReferenceError`:
  ```javascript
  class Base {
    constructor() { this.active = true; }
  }
  class Derived extends Base {
    constructor() {
      // console.log(this); // ReferenceError: Must call super constructor before accessing 'this'
      super();
      console.log(this.active); // true
    }
  }
  ```
- **Prototype methods vs. class field arrows**: prototype methods (`render() {...}`) live on `MyClass.prototype` — shared across instances (memory-efficient) but need manual binding as callbacks. Class field arrows (`render = () => {...}`) are created per instance during field initialization and retain that instance's receiver. They add per-instance function/retention cost; measure representative workloads before choosing between forms.

## 5. Host & Environment Variations

Default receivers differ by runtime:

- **Browser classic scripts**: top-level `this === window`.
- **ES modules (`<script type="module">`)**: top-level `this` is `undefined`.
- **Node.js CommonJS**: top-level `this` in a file is `module.exports` (initially `{}`), not the global object.
- **DOM event listeners**: `button.addEventListener('click', function(e) {...})` binds `this` to `e.currentTarget` — the element the listener is attached to.

## 6. TypeScript `this` Parameter Typing

TypeScript declares the expected receiver as a fake first parameter — erased at compile time, zero runtime overhead:

```typescript
interface UserAccount {
  id: string;
  deleteAccount(this: UserAccount): void;
}

function processDeletion(this: UserAccount) {
  console.log(`Deleting user: ${this.id}`);
}

const validUser: UserAccount = {
  id: 'usr_123',
  deleteAccount: processDeletion
};

validUser.deleteAccount(); // OK!

const detachedDelete = validUser.deleteAccount;
// detachedDelete();
// TS Compile Error: The 'this' context of type 'void' is not assignable to method's 'this' of type 'UserAccount'.
```

## Summary

For ordinary unbound calls, invocation supplies `this`: construction, explicit receiver calls, property calls or default binding. Bound functions preserve their stored receiver for ordinary calls, while construction ignores it; hosts can explicitly supply callback receivers. Arrows skip dynamic resolution and capture `this` from their enclosing scope. Detaching a method strips its implicit receiver — fix it with an arrow wrapper, `.bind()`, or a class-field arrow.

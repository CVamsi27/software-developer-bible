# This

## TL;DR

`this` is determined by how a function is called, not where it's defined. The four binding rules (default, implicit, explicit, `new`) cover all cases, with arrow functions as a lexical exception that inherits `this` from the enclosing scope.

## First Principles

`this` stops being mysterious once you accept what problem it solves:

1. **Some functions must work with whatever data they're handed.** A generic `describe()` cannot hardcode which object it describes — the language needs a way to pass "the object I'm currently operating on" *implicitly*, or every function would need an extra parameter for it.
2. **`this` is an argument.** Once you see it as a hidden parameter — filled by the call site (by `.`-binding), overridable by `call`/`apply`, preset by `bind`, erased by arrow functions — every "rule" collapses into one truth: *it's determined by how the function is invoked, not where it's written*.
3. **Arrow functions are the deliberate exception.** Lexical `this` isn't a fix for a broken system; it's the choice to *not* receive this hidden argument and reuse the enclosing one — the only way to keep closures (→ 10.1.1.06) from losing `this` in callbacks.


## Why It Matters

Lost `this` in callbacks, the difference between class methods and arrow class fields, and `bind` vs `call` vs `apply` are staple interview questions. Senior engineers also know the gotcha: extracted methods lose their receiver (`const fn = obj.method; fn();` → `this` is undefined in strict mode).

## Definition

The **`this`** keyword in JavaScript refers to the object that is currently executing the code. Its value depends on how a function is called (execution context), not where it's defined. This is called **dynamic binding** or **dynamic scoping** of `this`.


## How It Works

### Binding Rules

```text
┌─────────────────────────────────────────────────────────┐
│ THIS BINDING RULES                                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│ RULE 1: DEFAULT BINDING                                 │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ function greet() {                                  │ │
│ │ console.log(this);                                  │ │
│ │ }                                                   │ │
│ │                                                     │ │
│ │ greet(); // window (non-strict) or undefined        │ │
│ │                                                     │ │
│ │ // When function is called without context          │ │
│ │ // 'this' defaults to global object                 │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ RULE 2: IMPLICIT BINDING                                │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ const obj = {                                       │ │
│ │ name: 'Alice',                                      │ │
│ │ greet() {                                           │ │
│ │ console.log(this.name);                             │ │
│ │ }                                                   │ │
│ │ };                                                  │ │
│ │                                                     │ │
│ │ obj.greet(); // 'Alice' (this = obj)                │ │
│ │                                                     │ │
│ │ // When method is called on object                  │ │
│ │ // 'this' refers to the object                      │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ RULE 3: EXPLICIT BINDING                                │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ function greet() {                                  │ │
│ │ console.log(this.name);                             │ │
│ │ }                                                   │ │
│ │                                                     │ │
│ │ const obj = { name: 'Alice' };                      │ │
│ │                                                     │ │
│ │ greet.call(obj); // 'Alice'                         │ │
│ │ greet.apply(obj); // 'Alice'                        │ │
│ │ const bound = greet.bind(obj);                      │ │
│ │ bound(); // 'Alice'                                 │ │
│ │                                                     │ │
│ │ // call, apply, bind explicitly set 'this'          │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ RULE 4: ARROW FUNCTION                                  │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ const obj = {                                       │ │
│ │ name: 'Alice',                                      │ │
│ │ greet: () => {                                      │ │
│ │ console.log(this.name);                             │ │
│ │ }                                                   │ │
│ │ };                                                  │ │
│ │                                                     │ │
│ │ obj.greet(); // '' — window.name, not 'Alice'       │ │
│ │                                                     │ │
│ │ // Arrow functions inherit 'this' from parent       │ │
│ │ // They don't have their own 'this'                 │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
└─────────────────────────────────────────────────────────┘

```

When more than one rule could apply, precedence is: **`new` binding → explicit (`call`/`apply`/`bind`) → implicit (`obj.method()`) → default (plain call)**. Arrow functions never compete — they ignore all four and reuse the `this` of the scope they were written in.

### call, apply, bind

```text
┌─────────────────────────────────────────────────────────┐
│ CALL, APPLY, BIND                                       │
├─────────────────────────────────────────────────────────┤
│                                                         │
│ CALL:                                                   │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ function greet(greeting) {                          │ │
│ │ return `${greeting}, ${this.name}!`;                │ │
│ │ }                                                   │ │
│ │                                                     │ │
│ │ const alice = { name: 'Alice' };                    │ │
│ │ const bob = { name: 'Bob' };                        │ │
│ │                                                     │ │
│ │ greet.call(alice, 'Hello'); // 'Hello, Alice!'      │ │
│ │ greet.call(bob, 'Hi'); // 'Hi, Bob!'                │ │
│ │                                                     │ │
│ │ // Arguments passed individually                    │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ APPLY:                                                  │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ function greet(greeting, punctuation) {             │ │
│ │ return `${greeting}, ${this.name}${punctuation}`    │ │
│ │ }                                                   │ │
│ │                                                     │ │
│ │ const alice = { name: 'Alice' };                    │ │
│ │                                                     │ │
│ │ greet.apply(alice, ['Hello', '!']);                 │ │
│ │ // 'Hello, Alice!'                                  │ │
│ │                                                     │ │
│ │ // Arguments passed as array                        │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
│ BIND:                                                   │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ function greet() {                                  │ │
│ │ return `Hello, ${this.name}!`;                      │ │
│ │ }                                                   │ │
│ │                                                     │ │
│ │ const alice = { name: 'Alice' };                    │ │
│ │ const greetAlice = greet.bind(alice);               │ │
│ │                                                     │ │
│ │ greetAlice(); // 'Hello, Alice!'                    │ │
│ │                                                     │ │
│ │ // Returns new function with 'this' bound           │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
└─────────────────────────────────────────────────────────┘

```

## Code Examples

### Basic this Usage

```typescript
const person = {
  name: 'Alice',
  greet() {
    console.log(`Hello, ${this.name}`);
  }
};

person.greet(); // "Hello, Alice"

// 'this' refers to 'person' object
// because greet() is called on person

```

### this in Constructor

```typescript
class Person {
  name: string;

  constructor(name: string) {
    this.name = name; // 'this' = new object
  }

  greet() {
    console.log(`Hello, ${this.name}`);
  }
}

const alice = new Person('Alice');
alice.greet(); // "Hello, Alice"

```

### Arrow Function this

```typescript
const obj = {
  name: 'Alice',

  // Regular function: 'this' = obj
  greetRegular() {
    console.log(this.name); // 'Alice'
  },

  // Arrow function: 'this' = parent scope
  greetArrow: () => {
    console.log(this.name); // undefined (window)
  }
};

obj.greetRegular(); // 'Alice'
obj.greetArrow(); // undefined

// Arrow functions don't have their own 'this'
// They inherit from enclosing lexical scope

```

### Event Handler this

```typescript
const button = document.getElementById('myButton');

// Regular function: 'this' = button element
button?.addEventListener('click', function() {
  console.log(this); // <button id="myButton">
  this.style.color = 'red'; // Works!
});

// Arrow function: 'this' = parent scope (window)
button?.addEventListener('click', () => {
  console.log(this); // window
  // this.style.color = 'red'; // Error!
});

```

### call, apply, bind Examples

```typescript
function greet(greeting: string, punctuation: string) {
  return `${greeting}, ${this.name}${punctuation}`;
}

const alice = { name: 'Alice' };
const bob = { name: 'Bob' };

// call: pass arguments individually
console.log(greet.call(alice, 'Hello', '!')); // "Hello, Alice!"

// apply: pass arguments as array
console.log(greet.apply(bob, ['Hi', '.'])); // "Hi, Bob."

// bind: return new function with 'this' bound
const greetAlice = greet.bind(alice);
console.log(greetAlice('Hey', '?')); // "Hey, Alice?"

// bind with partial application
const greetAliceHey = greet.bind(alice, 'Hey');
console.log(greetAliceHey('!')); // "Hey, Alice!"

```

### this in Loops

```typescript
const obj = {
  name: 'Alice',
  items: [1, 2, 3],

  // Problem: 'this' lost in callback
  processItemsBad() {
    this.items.forEach(function(item) {
      // not 'Alice': the call site supplies this — the global object in
      // sloppy code ('' for window.name in a browser), and undefined in
      // strict code, where reading .name throws a TypeError
      console.log(this.name);
    });
  },

  // Solution 1: Arrow function
  processItemsGood1() {
    this.items.forEach((item) => {
      console.log(this.name); // 'Alice'
    });
  },

  // Solution 2: bind
  processItemsGood2() {
    this.items.forEach(function(item) {
      console.log(this.name); // 'Alice'
    }.bind(this));
  }
};

```

### this in Class Methods

```typescript
class Counter {
  private count = 0;

  increment() {
    this.count++;
    return this; // Enable chaining
  }

  decrement() {
    this.count--;
    return this;
  }

  getCount() {
    return this.count;
  }
}

const counter = new Counter();
counter.increment().increment().increment();
console.log(counter.getCount()); // 3

```

### this in React

```typescript
import React, { Component } from 'react';

class MyComponent extends Component {
  state = { count: 0 };

  // Arrow function: 'this' = component instance
  handleClick = () => {
    this.setState({ count: this.state.count + 1 });
  };

  // Regular function: need to bind in constructor
  handleClickBound() {
    this.setState({ count: this.state.count + 1 });
  }

  constructor(props: any) {
    super(props);
    this.handleClickBound = this.handleClickBound.bind(this);
  }

  render() {
    return (
      <button onClick={this.handleClick}>
        Count: {this.state.count}
      </button>
    );
  }
}

```

## Real-World Use Cases

### 1. Method Chaining

```typescript
class QueryBuilder {
  private table: string = '';
  private conditions: string[] = [];
  private limitCount: number = 0;

  from(table: string) {
    this.table = table;
    return this; // Return 'this' for chaining
  }

  where(condition: string) {
    this.conditions.push(condition);
    return this;
  }

  limit(count: number) {
    this.limitCount = count;
    return this;
  }

  build() {
    let query = `SELECT * FROM ${this.table}`;
    if (this.conditions.length) {
      query += ` WHERE ${this.conditions.join(' AND ')}`;
    }
    if (this.limitCount) {
      query += ` LIMIT ${this.limitCount}`;
    }
    return query;
  }
}

const query = new QueryBuilder()
  .from('users')
  .where('age > 18')
  .where('active = true')
  .limit(10)
  .build();

console.log(query); // "SELECT * FROM users WHERE age > 18 AND active = true LIMIT 10"

```

### 2. Event Delegation

```typescript
function setupEventDelegation(container: HTMLElement) {
  container.addEventListener('click', function(event) {
    const target = event.target as HTMLElement;

    // 'this' = container element
    if (target.matches('.delete-btn')) {
      const id = target.dataset.id;
      deleteItem(id);
    } else if (target.matches('.edit-btn')) {
      const id = target.dataset.id;
      editItem(id);
    }
  });
}

```

### 3. Object Pool Pattern

Pooling is fundamentally a memory-pressure technique — the annotated implementation with usage notes is owned by [Garbage Collection](../04-memory-and-data/10.1.4.07-garbage-collection.md) (see *Object Pooling*). What `this` adds: methods like `acquire()`/`release()` rely on `this.pool` binding, so they break if detached from their instance.

### 4. Decorator Pattern

```typescript
function debounce<T extends (...args: any[]) => any>(
  func: T,
  wait: number
): (...args: Parameters<T>) => void {
  let timeout: ReturnType<typeof setTimeout>;

  return function(this: any, ...args: Parameters<T>) {
    clearTimeout(timeout);
    timeout = setTimeout(() => func.apply(this, args), wait);
  };
}

function handleSearch(query: string) {
  console.log(`Searching: ${query}`);
}

const debouncedSearch = debounce(handleSearch, 300);

```

## Common Mistakes

### 1. Losing this in Callbacks

```typescript
class Timer {
  seconds = 0;

  // Bad: 'this' is NOT the Timer instance here — it comes from the
  // setInterval call site: window in a sloppy browser script, the
  // Timeout object in Node, undefined (so .seconds throws) when strict
  startBad() {
    setInterval(function() {
      this.seconds++;
    }, 1000);
  }

  // Good: Arrow function
  startGood() {
    setInterval(() => {
      this.seconds++; // this = Timer instance
    }, 1000);
  }

  // Good: bind
  startBound() {
    setInterval(function() {
      this.seconds++;
    }.bind(this), 1000);
  }
}

```

### 2. Arrow Functions as Object Methods

> *The side-by-side arrow-vs-method example lives in [Arrow Function this](#arrow-function-this) — writing the arrow at the object literal freezes the enclosing `this`, so `obj.greet()` never binds `obj`.*

### 3. Forgetting to Bind in Constructor

```typescript
class Component {
  constructor() {
    // Bad: 'this' not bound
    // this.handleClick = this.handleClick.bind(this);
  }

  handleClick() {
    console.log(this);
  }
}

// When passed as callback, 'this' is lost
const component = new Component();
button.addEventListener('click', component.handleClick); // this = button

```

### 4. this in Nested Functions

```typescript
const obj = {
  name: 'Alice',
  outer() {
    // 'this' = obj
    function inner() {
      // 'this' = the default binding (globalThis in sloppy code,
      // undefined in strict code) — nesting does not inherit it
      console.log(this.name);
    }
    inner();
  }
};

obj.outer(); // '' in a browser, undefined in Node (TypeError if strict)

// Fix: Use arrow function
const obj2 = {
  name: 'Alice',
  outer() {
    const inner = () => {
      console.log(this.name); // 'Alice'
    };
    inner();
  }
};

```

The mechanism behind all three fixes is the same: only `.`-style calls bind a receiver implicitly, so anything that detaches the function (passing it as a callback, nesting it, extracting it) falls back to the default binding — arrows sidestep it by never having a `this` to lose, `.bind(this)` and `const self = this` reattach it explicitly.

## Best Practices

1. **Prefer arrows for callbacks** — `forEach`, `setTimeout`, and event handlers invoke the function with no receiver, so an arrow keeps the `this` you already had (worked example in [this in Loops](#this-in-loops)).
2. **Bind once, not per render** — `this.handleClick = this.handleClick.bind(this)` in the constructor, or an arrow class field, keeps one stable function identity instead of allocating a new bound function every render.
3. **Pass data explicitly when `this` is only a lookup** — `processUser(user)` beats `processUser.call(ctx, user)`, because the call site then states what the function needs.
4. **Write the receiver down** — when something outside the file decides `this` (TypeScript's `this` parameter, JSDoc `@this`), record it in the signature so the next reader knows what will be bound.
5. **Debug at the call site** — `console.log(this)` inside the function tells you what the invocation bound; DevTools' Scope panel shows the live receiver, and a `this` parameter type turns a wrong receiver into a compile error.

## Performance Considerations

### Method Binding

```typescript
// Bad: .bind(this) inside render allocates a NEW function on every render
class Component extends React.Component {
  render() {
    return (
      <button onClick={this.handleClick.bind(this)}>
        Click
      </button>
    );
  }
}

```

The fix — bind once in the constructor, or use the arrow class field — is worked out in [this in React](#this-in-react) above.

### Where the Function Lives

Calling an arrow and calling a prototype method cost the same; the measurable difference is allocation — a method lives once on the prototype, an arrow class field is created per instance:

```typescript
class Shared { method() {} }            // one function, on Shared.prototype
class PerInstance { method = () => {}; } // a fresh function per instance

new Shared().method === new Shared().method;            // true  — same object
new PerInstance().method === new PerInstance().method;  // false — allocated twice
```

Use methods for behavior shared by every instance; reach for arrow fields only where lexical `this` pays for the per-instance copy.

## Summary

`this` is a powerful but confusing JavaScript feature:

1. **Dynamic binding**: Value depends on how function is called

2. **Four rules**: Default, implicit, explicit, arrow function

3. **call/apply/bind**: Explicit control over `this`

4. **Arrow functions**: Inherit `this` from lexical scope

5. **Common issues**: Lost `this` in callbacks

6. **Solutions**: Arrow functions, bind, explicit parameters

7. **Best practices**: Use arrows for callbacks, bind in constructor

## Revision Questions

**Definition**

1. **Q:** If `this` is "dynamic", what is it actually bound to — the function's source text or the call?
   **A:** The call. Where a function is written has no say in it, which is why one function can receive a different `this` every time it runs.

**How It Works**

2. **Q:** A method that was copied off its object is called plainly as `greet()` — what does `this` become, and how do the two modes differ?
   **A:** The default binding applies: the global object in sloppy code, `undefined` in strict code, where the first property read throws.

3. **Q:** When more than one binding rule could apply, which one wins?
   **A:** `new` first, then explicit (`call`/`apply`/`bind`), then the implicit `.`-call, then a plain call — arrows never enter the contest because they reuse the enclosing scope's `this`.

4. **Q:** What do `call`, `apply`, and `bind` share, and what sets them apart?
   **A:** All three impose a receiver explicitly; `call` passes arguments directly, `apply` takes them as an array, and `bind` hands back a new function with the receiver already fixed.

**Code Examples**

5. **Q:** Why does `const fn = obj.greet; fn()` behave differently from `obj.greet()`?
   **A:** Copying the function does not copy the receiver — with no `.` in front of the call, `this` falls back to the default binding.

6. **Q:** What breaks when an object literal declares `greet: () => console.log(this.name)`?
   **A:** The arrow froze the literal's surrounding `this` at creation time, so invoking `obj.greet()` still reads from the outer scope instead of `obj`.

**Common Mistakes**

7. **Q:** Inside `setInterval(function () { this.seconds++; })` on a `Timer`, which object does `this` refer to?
   **A:** Whatever the timer supplies as receiver — `window` in a sloppy browser script, `undefined` (and a TypeError) under strict mode — never the `Timer`, so the count lands on the wrong object.

8. **Q:** Why does a plain `function inner()` nested inside a method ignore that method's `this`, and what is the fix?
   **A:** Nesting grants no inheritance: a directly-invoked function takes the default binding of its own call. Declare `inner` as an arrow, or pass the receiver explicitly.

# Prototypes

When thousands of instances share identical methods, how does JavaScript avoid allocating thousands of duplicate function bodies? It delegates property lookups through the **prototype chain**.

```javascript
'use strict';

const userMethods = {
  describe() {
    return `User: ${this.name}`;
  }
};

const alice = Object.create(userMethods);
alice.name = 'Alice';

const bob = Object.create(userMethods);
bob.name = 'Bob';

console.log(alice.describe()); // 'User: Alice'
console.log(bob.describe());   // 'User: Bob'
console.log(alice.describe === bob.describe); // true (Single shared function in memory!)
```

## Definition

**Prototypal inheritance** lets objects delegate property and method lookups to an upstream fallback object. Every ordinary object holds an internal `[[Prototype]]` link to another object or `null`. On a property read, the engine searches **own properties** first, then walks up the `[[Prototype]]` chain until it finds the key or hits `null`.

> **Textbook Definition:** Prototype delegation resolves a property through an object and its prototype chain when the object lacks an own property. Ordinary prototype links terminate at `null`; inherited methods still receive the receiver supplied by the call.

## First Principles

Class-based languages copy class schemas into each instance's memory; JavaScript instead delegates — objects hold a live pointer to an archetype. The chain resolves dynamically on every read, so extending `Object.prototype` at runtime is instantly visible to all inheriting objects. Sharing one function body across instances is what makes this memory-efficient.

## 1. Prototype Delegation Mechanics

```text
alice { name: 'Alice' } ──[[Prototype]]──► userMethods { describe: fn } ──[[Prototype]]──► Object.prototype ──► null
```

Calling `alice.describe()` runs three steps: (1) does `alice` own `describe`? No. (2) Does `alice.[[Prototype]]` own it? Yes. (3) Invoke it with `this` set to `alice`, the calling receiver:

```javascript
console.log(Object.hasOwn(alice, 'name'));     // true (Own property)
console.log(Object.hasOwn(alice, 'describe')); // false (Inherited from prototype)
console.log('describe' in alice);             // true ('in' checks entire chain)
```

## 2. Disambiguating `[[Prototype]]`, `.prototype`, and `__proto__`

| Term | What It Is | Where It Lives | Primary Purpose |
| :------------------ | :---------------------------- | :------------------ | :------------------------------------------------------------------------ |
| **`[[Prototype]]`** | Internal hidden link | Every object | Spec mechanism defining the object's parent in the lookup chain. |
| **`.prototype`** | Ordinary object property | Functions & Classes | The archetype assigned as `[[Prototype]]` to instances created via `new`. |
| **`__proto__`** | Legacy accessor getter/setter | `Object.prototype` | Deprecated accessor property exposing `[[Prototype]]`. |

```javascript
function Person(name) {
  this.name = name;
}
Person.prototype.greet = function() { return `Hello, ${this.name}`; };

const person = new Person('Alice');

// 1. Instance's internal [[Prototype]] points to constructor's .prototype
console.log(Object.getPrototypeOf(person) === Person.prototype); // true

// 2. The constructor function itself is an object inheriting from Function.prototype
console.log(Object.getPrototypeOf(Person) === Function.prototype); // true

// 3. Person.prototype is an ordinary object inheriting from Object.prototype
console.log(Object.getPrototypeOf(Person.prototype) === Object.prototype); // true
```

## 3. Property Shadowing on Write

Reads consult the chain; writes do not — assigning a primitive creates an **own** property that shadows the prototype:

```javascript
const defaultSettings = { theme: 'light', flags: { debug: false } };
const userConfig = Object.create(defaultSettings);

// 1. Writing a primitive property SHADOWS on the own instance
userConfig.theme = 'dark';
console.log(userConfig.theme);       // 'dark' (Own property created!)
console.log(defaultSettings.theme);  // 'light' (Prototype untouched!)
console.log(Object.hasOwn(userConfig, 'theme')); // true

// 2. Deleting the own property unmasks the prototype
delete userConfig.theme;
console.log(userConfig.theme);       // 'light' (Falls back to prototype)

// 3. CAUTION: Mutating a nested object mutates the shared prototype!
userConfig.flags.debug = true;
console.log(defaultSettings.flags.debug); // true (Shared nested reference mutated!)
```

## 4. ES6 Classes: Syntactic Sugar with Strict Delegation

`class` compiles to prototypal delegation with two parallel chains — one for instances, one for statics:

```javascript
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
  static category() { return 'Fauna'; }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
}

const dog = new Dog('Buddy', 'Golden');

// Chain 1: Instance Prototype Chain (for methods)
// dog ──► Dog.prototype ──► Animal.prototype ──► Object.prototype ──► null
console.log(Object.getPrototypeOf(dog) === Dog.prototype); // true
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype); // true

// Chain 2: Static Constructor Chain (for static methods)
// Dog ──► Animal ──► Function.prototype ──► Object.prototype ──► null
console.log(Object.getPrototypeOf(Dog) === Animal); // true
console.log(Dog.category()); // 'Fauna' (Inherited static method!)
```

Three differences from function prototypes: class methods are **non-enumerable** (invisible to `Object.keys`/`for...in`), class bodies always run in **strict mode**, and classes **must use `new`** (plain calls throw `TypeError`).

## 5. Senior Security Concern: Prototype Pollution

**Prototype pollution** happens when untrusted JSON is deep-merged into objects without sanitizing special keys:

```javascript
// Vulnerable recursive merge function
function unsafeMerge(target, source) {
  for (const key in source) {
    if (typeof source[key] === 'object' && source[key] !== null) {
      if (!target[key]) target[key] = {};
      unsafeMerge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
}

// Malicious payload exploiting __proto__
const maliciousPayload = JSON.parse('{"__proto__": {"isAdmin": true}}');
const regularUser = {};

unsafeMerge(regularUser, maliciousPayload);

// Catastrophic: Object.prototype has been polluted across the entire runtime!
const stranger = {};
console.log(stranger.isAdmin); // true! (Security bypass across the process)
```

Four defenses, in order of strength: **null-prototype dictionaries** (`Object.create(null)` has no chain and ignores `__proto__`), **key filtering** (reject `__proto__`, `constructor`, `prototype`), **native `Map`** for dynamic lookups, and **`Object.freeze(Object.prototype)`** at startup.

## 6. Engine Performance: Avoid `Object.setPrototypeOf`

V8 optimizes access with hidden classes (Maps) and inline caches. `Object.setPrototypeOf(obj, newProto)` invalidates compiled optimizations and inline caches for that object and every downstream call site that touched it. **Senior rule**: establish prototype links at instantiation (`Object.create(proto)`, `new Constructor()`), never by mutating `[[Prototype]]` in hot code.

## Summary

JavaScript delegates property reads along the `[[Prototype]]` chain ending at `null`, with a function's `.prototype` serving as the archetype for `new`-created instances. Writes to inherited primitives create shadowing own properties; mutating nested objects touches shared memory. ES6 classes formalize delegation for instance and static methods. Production code must block prototype pollution and avoid runtime `Object.setPrototypeOf`, which discards engine optimizations.

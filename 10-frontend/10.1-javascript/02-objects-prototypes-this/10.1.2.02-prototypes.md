# Prototypes

When thousands of object instances share identical methods, how does JavaScript avoid allocating thousands of duplicate function bodies in memory? The engine delegates property lookups through the **prototype chain**.

```javascript
'use strict';

const userMethods = {
  describe() {
    return `User: ${this.name}`;
  }
};

const alice = Object.create(userMethods);
alice.name = 'Alice';

const bob = Object.create(userMethods);
bob.name = 'Bob';

console.log(alice.describe()); // 'User: Alice'
console.log(bob.describe());   // 'User: Bob'
console.log(alice.describe === bob.describe); // true (Single shared function in memory!)
```

## Definition

In JavaScript, **prototypal inheritance** is a mechanism where objects delegate property and method lookups to an upstream fallback object. Every ordinary object possesses an internal reference named `[[Prototype]]` that points to another object or `null`. When code reads a property on an object, the engine first searches the object's **own properties**; if the property is absent, it traverses up the `[[Prototype]]` chain until it either finds the key or hits `null`.

> **Textbook Definition:** Prototype delegation resolves a property through an object and its prototype chain when the object lacks an own property. Ordinary prototype links terminate at `null`; inherited methods still receive the receiver supplied by the call.

## First Principles

1. **Behavior Delegation Over Classical Duplication**: In class-based languages like C++ or Java, instantiating an object copies class schemas into contiguous memory. In JavaScript, inheritance is fundamentally delegation: objects simply maintain a live pointer to an archetype object.
2. **Dynamic Traversal**: The prototype chain is evaluated dynamically on each property read. If a method on `Object.prototype` is modified or extended at runtime, every existing object inheriting from it immediately reflects the change.

## How It Works

### 1. Prototype Delegation Mechanics

When code invokes `alice.describe()`, the engine performs a structured lookup:

```text
alice { name: 'Alice' } ──[[Prototype]]──► userMethods { describe: fn } ──[[Prototype]]──► Object.prototype ──► null
```

1. Does `alice` have an *own* property named `describe`? No.
2. Does `alice.[[Prototype]]` (`userMethods`) have `describe`? Yes!
3. The engine invokes `userMethods.describe` with `this` set dynamically to `alice` (the calling receiver).

```javascript
console.log(Object.hasOwn(alice, 'name'));     // true (Own property)
console.log(Object.hasOwn(alice, 'describe')); // false (Inherited from prototype)
console.log('describe' in alice);             // true ('in' checks entire chain)
```

### 2. Disambiguating `[[Prototype]]`, `.prototype`, and `__proto__`

A frequent interview trap is confusing these three distinct prototype concepts:

| Term | What It Is | Where It Lives | Primary Purpose |
| :------------------ | :---------------------------- | :------------------ | :------------------------------------------------------------------------ |
| **`[[Prototype]]`** | Internal hidden link | Every object | Spec mechanism defining the object's parent in the lookup chain. |
| **`.prototype`** | Ordinary object property | Functions & Classes | The archetype assigned as `[[Prototype]]` to instances created via `new`. |
| **`__proto__`** | Legacy accessor getter/setter | `Object.prototype` | Deprecated accessor property exposing `[[Prototype]]`. |

```javascript
function Person(name) {
  this.name = name;
}
Person.prototype.greet = function() { return `Hello, ${this.name}`; };

const person = new Person('Alice');

// 1. Instance's internal [[Prototype]] points to constructor's .prototype
console.log(Object.getPrototypeOf(person) === Person.prototype); // true

// 2. The constructor function itself is an object inheriting from Function.prototype
console.log(Object.getPrototypeOf(Person) === Function.prototype); // true

// 3. Person.prototype is an ordinary object inheriting from Object.prototype
console.log(Object.getPrototypeOf(Person.prototype) === Object.prototype); // true
```

### 3. Property Shadowing on Write

Reading checks the prototype chain; writing behaves differently:

```javascript
const defaultSettings = { theme: 'light', flags: { debug: false } };
const userConfig = Object.create(defaultSettings);

// 1. Writing a primitive property SHADOWS on the own instance
userConfig.theme = 'dark';
console.log(userConfig.theme);       // 'dark' (Own property created!)
console.log(defaultSettings.theme);  // 'light' (Prototype untouched!)
console.log(Object.hasOwn(userConfig, 'theme')); // true

// 2. Deleting the own property unmasks the prototype
delete userConfig.theme;
console.log(userConfig.theme);       // 'light' (Falls back to prototype)

// 3. CAUTION: Mutating a nested object mutates the shared prototype!
userConfig.flags.debug = true;
console.log(defaultSettings.flags.debug); // true (Shared nested reference mutated!)
```

### 4. ES6 Classes: Syntactic Sugar with Strict Delegation

ES6 `class` syntax compiles directly down to prototypal delegation, establishing two parallel inheritance chains:

```javascript
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
  static category() { return 'Fauna'; }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
}

const dog = new Dog('Buddy', 'Golden');

// Chain 1: Instance Prototype Chain (for methods)
// dog ──► Dog.prototype ──► Animal.prototype ──► Object.prototype ──► null
console.log(Object.getPrototypeOf(dog) === Dog.prototype); // true
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype); // true

// Chain 2: Static Constructor Chain (for static methods)
// Dog ──► Animal ──► Function.prototype ──► Object.prototype ──► null
console.log(Object.getPrototypeOf(Dog) === Animal); // true
console.log(Dog.category()); // 'Fauna' (Inherited static method!)
```

#### Key Class Differences from Function Prototypes:
- **Non-Enumerable Methods**: Class methods are defined with `enumerable: false`. They do not appear in `Object.keys()` or `for...in` loops.
- **Strict Mode Enforced**: Class bodies always evaluate in `'use strict'`.
- **Must Use `new`**: Calling a class without `new` throws a `TypeError`.

### 5. Senior Security Concern: Prototype Pollution

**Prototype Pollution** is a critical vulnerability that occurs when an application recursively merges or deep-assigns untrusted JSON payloads into JavaScript objects without sanitizing special keys:

```javascript
// Vulnerable recursive merge function
function unsafeMerge(target, source) {
  for (const key in source) {
    if (typeof source[key] === 'object' && source[key] !== null) {
      if (!target[key]) target[key] = {};
      unsafeMerge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
}

// Malicious payload exploiting __proto__
const maliciousPayload = JSON.parse('{"__proto__": {"isAdmin": true}}');
const regularUser = {};

unsafeMerge(regularUser, maliciousPayload);

// Catastrophic: Object.prototype has been polluted across the entire runtime!
const stranger = {};
console.log(stranger.isAdmin); // true! (Security bypass across the process)
```

#### Senior Defenses Against Prototype Pollution:
1. **Null-Prototype Objects**: Use `Object.create(null)` for key-value dictionary stores. They have no prototype chain and ignore `__proto__`.
2. **Key Filtering**: Reject or strip properties named `__proto__`, `constructor`, and `prototype`.
3. **Use `Map`**: Use native ES6 `Map` instances for dynamic lookups instead of plain objects.
4. **Freeze Prototypes**: Execute `Object.freeze(Object.prototype)` during system startup.

### 6. Engine Performance: Avoid `Object.setPrototypeOf`

JavaScript engines like V8 optimize property access using hidden classes (Maps) and Inline Caches (IC).
- When you use `Object.setPrototypeOf(obj, newProto)`, V8 must invalidate all compiled optimizations and inline caches for that object and every downstream call site that touched it.
- **Senior Rule**: Always establish prototype links at object instantiation time using `Object.create(proto)` or `new Constructor()`. Never mutate `[[Prototype]]` dynamically in performance-critical code.

## Summary

JavaScript leverages prototypal inheritance to delegate property lookups along a static `[[Prototype]]` chain terminating at `null`. Functions provide a `.prototype` property that serves as the archetype for instances created via `new`. Writing to inherited primitive properties creates own shadowed bindings without modifying the prototype, whereas mutating nested objects alters shared memory. ES6 classes formalize this delegation model for instance and static methods, while production systems must guard against prototype pollution and avoid runtime `Object.setPrototypeOf` mutations that invalidate engine optimizations.

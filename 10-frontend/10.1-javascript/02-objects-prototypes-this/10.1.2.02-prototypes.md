# Prototypes

## Definition

A prototype is another object consulted when an object does not own a requested property. Ordinary objects have an internal `[[Prototype]]` link whose value is an object **or `null`**. Following those links forms a prototype chain; reaching `null` ends lookup.

## First Principles

Several objects may need distinct data but shared behavior. Copying the same function onto every object is one option; delegating missing-property lookup to a shared object is another. JavaScript uses delegation for ordinary inherited properties. The receiver remains the original object even when lookup finds a method farther along the chain.

## Where does an inherited method find instance data?

```js
'use strict';
const accountBehavior = {
  describe() { return `Account ${this.name}`; }
};
const alice = Object.create(accountBehavior);
alice.name = 'Alice';
const bob = Object.create(accountBehavior);
bob.name = 'Bob';

console.log(alice.describe()); // Account Alice
console.log(bob.describe());   // Account Bob
console.log(alice.describe === bob.describe); // true: one shared function
console.log(Object.hasOwn(alice, 'name'));     // true
console.log(Object.hasOwn(alice, 'describe')); // false
console.log('describe' in alice);             // true: inherited counts too
```

```text
alice {name: Alice} ─┐
                    ├→ accountBehavior {describe} → Object.prototype → null
bob   {name: Bob}   ─┘

alice.describe(): lookup finds shared describe; call still supplies alice as this
```

Lookup and invocation are separate. Finding `describe` on `accountBehavior` does not make that prototype the receiver. If you extract the function and call it plainly, ordinary [this rules](10.1.2.01-this.md) apply instead.

## How do constructors establish the link?

A normal constructible function has a `prototype` property used by `new` when creating instances. That property is an ordinary property of the function; it is different from the function object's own internal prototype.

```js
'use strict';
function Person(name) { this.name = name; }
Person.prototype.greet = function () { return `Hello, ${this.name}`; };

const person = new Person('Alice');
console.log(person.greet()); // Hello, Alice
console.log(Object.getPrototypeOf(person) === Person.prototype); // true
console.log(Object.getPrototypeOf(Person) === Function.prototype); // true
console.log(person instanceof Person); // true
```

`Person.prototype` normally inherits from `Object.prototype`. `Person` itself normally inherits from `Function.prototype`. Arrow functions have no constructor `prototype` property and cannot be used with `new`; neither “all functions have `.prototype`” nor “every object has `__proto__`” is correct.

`__proto__` is usually an inherited legacy accessor on `Object.prototype`, not the internal link itself. A null-prototype object has no such inherited accessor; an object may also own a data property with that name. Prefer `Object.getPrototypeOf` for inspection and `Object.create` to establish a chosen link at creation.

## What does class inheritance add?

```js
'use strict';
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
}
class Dog extends Animal {
  constructor(name, breed) { super(name); this.breed = breed; }
  speak() { return `${super.speak()}; ${this.name} barks`; }
}
const rex = new Dog('Rex', 'Shepherd');
console.log(rex.speak()); // Rex makes a sound; Rex barks
console.log(Object.getPrototypeOf(rex) === Dog.prototype); // true
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype); // true
console.log(Object.getPrototypeOf(Dog) === Animal); // true: static inheritance
```

Instance lookup follows `rex → Dog.prototype → Animal.prototype → Object.prototype → null`. The constructor objects also have an inheritance link for static behavior. `super.speak()` finds the parent method but calls it with the current receiver, `rex`.

Classes use prototype delegation, but add semantics beyond a text substitution: class bodies are strict, methods are non-enumerable, constructors require `new`, derived initialization has `super()` rules, and private fields have their own checks. Public instance fields belong to individual instances rather than their shared prototype.

## When does a write change the shared object?

A normal assignment to an inherited writable data property generally creates or updates an **own** property on the receiver, shadowing the inherited value. It does not normally mutate the prototype. An inherited setter can run instead; non-writable properties can block assignment.

```js
'use strict';
const defaults = { theme: 'light' };
const settings = Object.create(defaults);
settings.theme = 'dark';
console.log(settings.theme); // dark
console.log(defaults.theme); // light
console.log(Object.hasOwn(settings, 'theme')); // true

delete settings.theme;
console.log(settings.theme); // light: inherited value visible again
```

By contrast, mutating a shared nested object obtained through inheritance changes that same referenced object. Prototype delegation does not clone data. Take care with inherited mutable collections, and avoid altering built-in prototypes: all dependent code in that realm can observe the change.

## How do you inspect membership without running behavior?

Use `Object.hasOwn(object, key)` to distinguish own properties from inherited ones. It also works when an object shadows `hasOwnProperty` or has a null prototype. `Object.keys` lists own enumerable string keys; `for...in` can also enumerate inherited enumerable string keys. Symbols and non-enumerable methods require different inspection APIs.

This helper records own keys at each ordinary prototype level without reading their values or invoking getters:

```js
function inspectChain(object) {
  const levels = [];
  for (let current = object; current !== null; current = Object.getPrototypeOf(current)) {
    levels.push(Reflect.ownKeys(current));
  }
  return levels;
}
console.log(inspectChain({ name: 'Alice' })[0]); // ['name']
```

A Proxy can intercept these operations, so inspection is not a sandbox for arbitrary hostile objects. Default `instanceof` checks whether a constructor's prototype occurs in the instance chain; custom `Symbol.hasInstance`, cross-realm values and altered chains need additional care. It is not runtime validation of an arbitrary network payload's shape.

## Borrowing methods does not require inheriting from them

```js
const arrayLike = { 0: 'a', length: 1 };
Array.prototype.push.call(arrayLike, 'b');
console.log(arrayLike[1], arrayLike.length); // b 2
console.log(Object.getPrototypeOf(arrayLike) === Array.prototype); // false
```

`push` is generic for a compatible writable array-like receiver. It operates on indexed properties and `length`; it does not require that receiver to inherit from `Array.prototype`. Other built-ins may require internal slots and reject borrowed use, so check the method's contract.

A mixin copies selected behavior onto a target; `Object.assign` does not create an inheritance link and does not preserve all property descriptors. Plugin registries and event subscriptions have additional lifecycle contracts; their canonical mechanisms live in the [design-pattern chapters](../../../30-architecture/30.1-design-patterns/INDEX.md), rather than duplicating an incomplete event emitter here.

## How do shared prototypes affect safety and cost?

Choose prototype relationships during object creation where possible. Repeated `Object.setPrototypeOf` changes can disrupt optimization assumptions. Lookup semantics follow the chain, but engines can cache/optimize property access; do not claim every read physically walks every link at the same measured cost.

Prototype methods share one function; functions created in constructors or arrow fields typically allocate per instance. Use that distinction when behavior must capture instance state or preserve a callback receiver, and measure any meaningful performance decision.

Replacing `Constructor.prototype` affects future default instances, not existing ones' links. The old `constructor` property may disappear, but it is an ordinary property rather than the authority that created an object. Freezing an owned prototype can prevent modification, while inherited non-writable data properties also affect shadowing; apply it deliberately rather than as a universal default.

**Prototype pollution** occurs when unsafe property assignment/merging lets untrusted keys modify shared prototypes or unintended object relationships. Do not blindly `Object.assign(this, JSON.parse(input))` as a deserializer. Validate allowed fields, handle special keys safely and choose suitable data containers. Null-prototype dictionaries avoid inherited names, but they do not make an arbitrary recursive merge safe.

## Summary

Prototypes provide fallback property lookup while each call still supplies its receiver. Distinguish an object's internal link, a constructor's `.prototype`, and own properties. Create deliberate relationships, validate external data independently, and treat shared mutation as a behavior change for every dependent object.

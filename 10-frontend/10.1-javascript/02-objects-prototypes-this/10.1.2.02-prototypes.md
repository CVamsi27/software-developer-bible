# Prototypes

When thousands of instances share identical methods, how does JavaScript avoid allocating thousands of duplicate function bodies? It delegates property lookups through the **prototype chain**.

```javascript
'use strict';

const userMethods = {
  describe() {
    return `User: ${this.name}`;
  }
};

const alice = Object.create(userMethods);
alice.name = 'Alice';

const bob = Object.create(userMethods);
bob.name = 'Bob';

console.log(alice.describe()); // 'User: Alice'
console.log(bob.describe());   // 'User: Bob'
console.log(alice.describe === bob.describe); // true (Single shared function in memory!)
```

## Definition

**Prototypal inheritance** lets objects delegate property and method lookups to an upstream fallback object. Every ordinary object holds an internal `[[Prototype]]` link to another object or `null`. On a property read, the engine searches **own properties** first, then walks up the `[[Prototype]]` chain until it finds the key or hits `null`.

> **Textbook Definition:** Prototype delegation resolves a property through an object and its prototype chain when the object lacks an own property. Ordinary prototype links terminate at `null`; inherited methods still receive the receiver supplied by the call.

## First Principles

Objects can share behavior without copying a function into every instance. JavaScript models that sharing through prototype links; class-based runtimes can also share methods, so this is not a universal memory-layout contrast. A property read observes the current chain, subject to shadowing and accessor rules; engines may optimize the lookup without changing its observable result.

## 1. Prototype Delegation Mechanics

```text
alice { name: 'Alice' } ──[[Prototype]]──► userMethods { describe: fn } ──[[Prototype]]──► Object.prototype ──► null
```

Calling `alice.describe()` runs three steps: (1) does `alice` own `describe`? No. (2) Does `alice.[[Prototype]]` own it? Yes. (3) Invoke it with `this` set to `alice`, the calling receiver:

```javascript
const userMethods = { describe() { return `User: ${this.name}`; } };
const alice = Object.assign(Object.create(userMethods), { name: 'Alice' });

console.log(Object.hasOwn(alice, 'name'));     // true (Own property)
console.log(Object.hasOwn(alice, 'describe')); // false (Inherited from prototype)
console.log('describe' in alice);             // true ('in' checks entire chain)
```

## 2. Disambiguating `[[Prototype]]`, `.prototype`, and `__proto__`

| Term | What It Is | Where It Lives | Primary Purpose |
| :------------------ | :-------------------------------- | :-------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------- |
| **`[[Prototype]]`** | Internal hidden link | Every object | Spec mechanism defining the object's parent in the lookup chain. |
| **`.prototype`** | Ordinary object property | Common constructible functions and classes (not every function) | Used for ordinary default instance construction; bound functions and explicit return values add rules. |
| **`__proto__`** | Legacy accessor getter and setter | `Object.prototype` | Deprecated accessor property exposing `[[Prototype]]`. |

```javascript
function Person(name) {
  this.name = name;
}
Person.prototype.greet = function() { return `Hello, ${this.name}`; };

const person = new Person('Alice');

// 1. Instance's internal [[Prototype]] points to constructor's .prototype
console.log(Object.getPrototypeOf(person) === Person.prototype); // true

// 2. The constructor function itself is an object inheriting from Function.prototype
console.log(Object.getPrototypeOf(Person) === Function.prototype); // true

// 3. Person.prototype is an ordinary object inheriting from Object.prototype
console.log(Object.getPrototypeOf(Person.prototype) === Object.prototype); // true
```

### What `new Constructor(...args)` Actually Does

Invoking a function with `new` executes four runtime steps:

1. **Allocate and link:** creates a new ordinary object whose internal `[[Prototype]]` points to `Constructor.prototype` (falling back to `Object.prototype` if `.prototype` is not an object).
2. **Bind `this` and `new.target`:** executes `Constructor` with `this` referencing that new object and `new.target` set to the invoked constructor (otherwise `undefined` in ordinary calls).
3. **Inspect the return value:** checks what `Constructor` returns explicitly.
4. **Select the result:** returns the explicit return value if it is an object or function; otherwise returns the newly created `this` object (returned primitives are ignored).

```javascript
'use strict';

function Token(value) {
  if (!new.target) {
    throw new TypeError('Token must be called with new');
  }
  this.value = value;
  return 42; // Primitive return is ignored; returns the constructed instance
}

function Wrapper(inner) {
  this.ignored = true;
  return inner; // Object return overrides `this`
}

const token = new Token('abc');
console.log(token.value); // 'abc'

const custom = { custom: true };
console.log(new Wrapper(custom) === custom); // true
```

## 3. Property Shadowing on Write

Every property on an object is backed by a **property descriptor** inspectable via `Object.getOwnPropertyDescriptor(obj, key)`: a **data descriptor** stores `value`, `writable`, `enumerable`, and `configurable`, whereas an **accessor descriptor** stores `get` and `set` hooks instead of `value` and `writable`. Assignment consults both own descriptors and inherited descriptors along the prototype chain before writing.

For an inherited **writable data property**, ordinary assignment can create an **own** property on the receiver, shadowing the inherited value. The value being primitive is not what decides this: assignment also consults inherited descriptors. An inherited setter receives the receiver, an inherited non-writable data property blocks assignment, and the receiver must permit the new own property:

```javascript
const defaultSettings = { theme: 'light', flags: { debug: false } };
const userConfig = Object.create(defaultSettings);

// 1. This inherited data property is writable, so an own property is created
userConfig.theme = 'dark';
console.log(userConfig.theme);       // 'dark' (Own property created!)
console.log(defaultSettings.theme);  // 'light' (Prototype untouched!)
console.log(Object.hasOwn(userConfig, 'theme')); // true

// 2. Deleting the own property unmasks the prototype
delete userConfig.theme;
console.log(userConfig.theme);       // 'light' (Falls back to prototype)

// 3. CAUTION: Mutating a nested object mutates the shared prototype!
userConfig.flags.debug = true;
console.log(defaultSettings.flags.debug); // true (Shared nested reference mutated!)
```

```javascript
'use strict';
const parent = {
  set score(value) { this.savedScore = value; }
};
Object.defineProperty(parent, 'fixed', { value: 1, writable: false });
const child = Object.create(parent);
child.score = 7;
console.log(child.savedScore, Object.hasOwn(child, 'score')); // 7, false
try { child.fixed = 2; } catch (error) {
  console.log(error instanceof TypeError); // true: inherited non-writable property
}
```

## 4. Classes: Delegation With Stricter Rules

`class` defines prototypal delegation with two parallel chains — one for instances, one for statics:

```javascript
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} makes a sound`; }
  static category() { return 'Fauna'; }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);
    this.breed = breed;
  }
}

const dog = new Dog('Buddy', 'Golden');

// Chain 1: Instance Prototype Chain (for methods)
// dog ──► Dog.prototype ──► Animal.prototype ──► Object.prototype ──► null
console.log(Object.getPrototypeOf(dog) === Dog.prototype); // true
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype); // true

// Chain 2: Static Constructor Chain (for static methods)
// Dog ──► Animal ──► Function.prototype ──► Object.prototype ──► null
console.log(Object.getPrototypeOf(Dog) === Animal); // true
console.log(Dog.category()); // 'Fauna' (Inherited static method!)
```

Three differences from function prototypes: class methods are **non-enumerable** (invisible to `Object.keys` and `for...in`), class bodies always run in **strict mode**, and classes **must use `new`** (plain calls throw `TypeError`).

### Checking Prototype Membership: `instanceof`, `isPrototypeOf`, and `Symbol.hasInstance`

`obj instanceof Ctor` delegates to `Ctor[Symbol.hasInstance](obj)`, whose default implementation walks `obj`'s `[[Prototype]]` chain checking whether `Ctor.prototype` appears anywhere along it. Cross-realm values (such as an array or `Error` created inside a browser `iframe` or Node `vm` context) return `false` for the host realm's constructor because each realm owns distinct built-in prototypes — use realm-safe checks like `Array.isArray` or `Error.isError` at realm boundaries. When you already hold a prototype object rather than a constructor, call `protoObj.isPrototypeOf(obj)`, or define `[Symbol.hasInstance]` for custom type guards:

```javascript
'use strict';
const vm = require('node:vm');

const baseProto = { kind: 'record' };
const item = Object.create(baseProto);
console.log(baseProto.isPrototypeOf(item)); // true

class EvenNumber {
  static [Symbol.hasInstance](value) {
    return typeof value === 'number' && value % 2 === 0;
  }
}
console.log(4 instanceof EvenNumber, 5 instanceof EvenNumber); // true false

const foreignArray = vm.runInNewContext('[1, 2, 3]');
console.log(foreignArray instanceof Array, Array.isArray(foreignArray)); // false true
```

## 5. Senior Security Concern: Prototype Pollution

**Prototype pollution** happens when untrusted JSON is deep-merged into objects without sanitizing special keys:

```javascript
// Vulnerable recursive merge function
function unsafeMerge(target, source) {
  for (const key in source) {
    if (typeof source[key] === 'object' && source[key] !== null) {
      if (!target[key]) target[key] = {};
      unsafeMerge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
}

// Malicious payload exploiting __proto__
const maliciousPayload = JSON.parse('{"__proto__": {"isAdmin": true}}');
const regularUser = {};

unsafeMerge(regularUser, maliciousPayload);

// Catastrophic: Object.prototype has been polluted across the entire runtime!
const stranger = {};
console.log(stranger.isAdmin); // true! (Security bypass across the process)
```

Defend against prototype pollution at merge boundaries:

- **Validate and filter keys at every depth:** use allowlisted schemas and maintained merge helpers that reject `__proto__`, `constructor`, and `prototype`, and iterate only own keys (`Object.hasOwn` and `Object.keys`) rather than inherited input.
- **Isolate dynamic key maps:** prefer `Map` or `Object.create(null)` dictionaries when storing arbitrary user keys (where `__proto__` is an ordinary own key, though copying back into a plain object can reintroduce the setter hazard).
- **Treat `Object.freeze(Object.prototype)` as defense in depth:** it helps where compatible with dependencies, but it does not protect other built-in prototypes or replace input validation.

```javascript
'use strict';

const safeDict = Object.create(null);
safeDict['__proto__'] = { isAdmin: true };

console.log(Object.getPrototypeOf(safeDict));          // null
console.log(safeDict.hasOwnProperty);                  // undefined
console.log('toString' in safeDict);                   // false
console.log(Object.hasOwn(safeDict, '__proto__'));     // true (ordinary own property)
console.log(({}).isAdmin);                             // undefined (Object.prototype untouched)
```

## 6. Engine Performance: Avoid `Object.setPrototypeOf`

V8 optimizes property access with hidden classes (`Map`s) and inline caches; mutating a chain after allocation forces hidden-class invalidation and cache misses (see [V8 Execution and Optimization](../01-execution-and-scope/10.1.1.07-v8-execution-and-optimization.md)). `Object.setPrototypeOf(obj, newProto)` swaps prototype pointers across existing instances, triggering deoptimization; the exact affected sites depend on engine and workload. **Senior rule**: establish prototype links at instantiation (`Object.create(proto)` or `new Constructor()`), never by mutating `[[Prototype]]` in hot code.

## Summary

JavaScript delegates property reads along the `[[Prototype]]` chain ending at `null`, with a function's `.prototype` serving as the archetype for `new`-created instances. Writes may shadow inherited writable data properties, invoke inherited setters, or fail descriptor checks; mutating a nested shared object affects all holders of that reference. ES6 classes formalize delegation for instance and static methods. Production code must block prototype pollution and avoid runtime `Object.setPrototypeOf`, which can disrupt engine optimizations.

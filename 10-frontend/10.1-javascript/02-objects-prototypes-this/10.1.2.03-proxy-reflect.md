# Proxy & Reflect

How do you validate `user.age = -5` at assignment time, or build Vue-3-style reactivity that notices property reads and writes — without forcing callers to abandon dot-syntax for helper functions? Both are one tool: a **`Proxy`** wraps the target and intercepts the operation (`set` to validate at assignment time, `get`/`set` to track reads and writes), while **`Reflect`** performs the forwarded operation with the correct receiver semantics, so a trap can pass the assignment through unchanged instead of reimplementing it.

```javascript
'use strict';

const user = { name: 'Alice', age: 30 };

const validator = {
  set(target, prop, value, receiver) {
    if (prop === 'age' && (!Number.isInteger(value) || value < 0 || value > 150)) {
      throw new TypeError('age must be a positive integer between 0 and 150');
    }
    return Reflect.set(target, prop, value, receiver);
  }
};

const proxyUser = new Proxy(user, validator);
proxyUser.age = 31; // Works seamlessly!
// proxyUser.age = -1; // Throws TypeError: age must be a positive integer between 0 and 150
```

## Definition

A **`Proxy`** is an exotic wrapper that intercepts fundamental operations (property lookup, assignment, enumeration, invocation, construction) through handler functions called **traps**. **`Reflect`** is a built-in namespace exposing each interceptable operation as a function, so traps can forward work to the underlying target with correct receiver bindings.

> **Textbook Definition:** A proxy mediates selected internal operations on a target through handler traps, subject to language invariants. Reflect exposes corresponding operations as functions so a trap can forward an operation with an explicit receiver.

## First Principles

Every object manipulation compiles to spec-level internal methods (`[[Get]]`, `[[Set]]`, `[[Delete]]`, `[[Call]]`) — `Proxy` hooks developer code directly into those primitives. A proxy duplicates no memory: operations without a custom trap fall straight through to the target. And to keep metaprogramming from corrupting runtime guarantees, the engine enforces **invariants** — traps can never contradict non-configurable or non-writable target state.

## 1. Step-by-Step Assignment Interception

Assigning `proxyUser.age = 31` flows through a pipeline:

```text
proxyUser.age = 31
       │
       ▼
1. JavaScript engine invokes the handler's set() trap:
   set(target, prop, value, receiver)
       │
       ▼
2. Custom Validation Logic runs:
   Verifies that 31 is an integer between 0 and 150
       │
       ▼
3. Reflect.set(target, prop, value, receiver) forwards the operation:
   Applies the write to user.age and returns true
       │
       ▼
4. Assignment completes successfully!
```

## 2. Why `Reflect` is Mandatory: The Receiver Argument

Forwarding with raw assignment (`target[prop] = value`) drops the receiver and breaks inherited getters:

```javascript
// WRONG: Breaks inheritance and getter/setter reactivity!
const badHandler = {
  get(target, prop, receiver) {
    return target[prop]; // Loses 'receiver'!
  }
};

// CORRECT: Uses Reflect to preserve the calling receiver
const goodHandler = {
  get(target, prop, receiver) {
    return Reflect.get(target, prop, receiver); // 'this' points to proxy!
  }
};
```

With an inherited getter, the difference is observable:

```javascript
const parent = {
  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  }
};

const child = { firstName: 'Alice', lastName: 'Smith' };
Object.setPrototypeOf(child, parent);

const childProxy = new Proxy(child, {
  get(target, prop, receiver) {
    // If you return target[prop], 'this' inside fullName binds to parent (missing child fields!)
    // Using Reflect.get(target, prop, receiver) ensures 'this' inside fullName binds to childProxy!
    return Reflect.get(target, prop, receiver);
  }
});

console.log(childProxy.fullName); // 'Alice Smith'
```

Without `receiver`, inherited getters bind `this` to the static target instead of the calling proxy — silently breaking reactivity.

## 3. The 13 Proxy Traps (The Complete Metaprogramming Surface)

Exactly 13 traps mirror the 13 internal ECMAScript methods:

| Category | Traps | Triggered By |
| :------------------------ | :------------------------------------------------------ | :-------------------------------------------------------------------------- |
| **Property Operations** | `get`, `set`, `has`, `deleteProperty` | `obj.x`, `obj.x = 1`, `'x' in obj`, `delete obj.x` |
| **Descriptor Operations** | `getOwnPropertyDescriptor`, `defineProperty`, `ownKeys` | `Object.getOwnPropertyDescriptor`, `Object.defineProperty`, `Object.keys()` |
| **Prototype Operations** | `getPrototypeOf`, `setPrototypeOf` | `Object.getPrototypeOf`, `Object.setPrototypeOf`, `instanceof` |
| **Extensibility** | `isExtensible`, `preventExtensions` | `Object.isExtensible`, `Object.preventExtensions`, `Object.freeze` |
| **Function Invocations** | `apply`, `construct` | `fn(...args)`, `new Constructor(...args)` |

## 4. Engine Invariants: Protected Target Rules

The engine rejects traps that contradict locked target state. If `target.id` is non-configurable and non-writable with value `42`, a `get` trap **must** return `42` — anything else throws `TypeError`. If `Object.preventExtensions(target)` ran, the `isExtensible` trap must return `false`:

```javascript
const locked = {};
Object.defineProperty(locked, 'secret', {
  value: 42,
  writable: false,
  configurable: false
});

const invalidProxy = new Proxy(locked, {
  get() { return 999; } // Invariant violation!
});

try {
  invalidProxy.secret;
} catch (e) {
  console.log(e instanceof TypeError); // true: Invariant violation throws TypeError
}
```

## 5. Production Architectural Use Cases

1. **Reactivity engines (Vue 3)** — the `get` trap registers the rendering computed/template as a subscriber (`track(target, prop)`); the `set` trap detects changes and schedules re-renders (`trigger(target, prop)`).
2. **Dynamic RPC clients** — a recursive proxy builds URLs instead of a hundred-line SDK:
   ```javascript
   function createApiClient(baseUrl) {
     return new Proxy({}, {
       get(target, prop) {
         return (id = '') => fetch(`${baseUrl}/${String(prop)}/${id}`);
       }
     });
   }
   const api = createApiClient('https://api.example.com');
   // api.users(123) automatically calls fetch('https://api.example.com/users/123')
   ```
3. **Revocable proxies (`Proxy.revocable`)** — temporary access for untrusted plugins in a sandbox:
   ```javascript
   const sensitiveData = { token: 'xyz123' };
   const { proxy, revoke } = Proxy.revocable(sensitiveData, {});

   console.log(proxy.token); // 'xyz123'
   revoke();                 // Immediately cuts off access!

   try {
     console.log(proxy.token);
   } catch (e) {
     console.log(e instanceof TypeError); // true: Cannot perform 'get' on a proxy that has been revoked
   }
   ```

## 6. Senior Gotchas: Internal Slots and Identity Transparency

- **Internal slot failures (`Map`, `Set`, `Date`, `#private`)** — built-ins store native pointers in slots like `[[MapData]]`. Calling `mapProxy.get('key')` fails the slot check because `this === mapProxy`, throwing `TypeError: Method Map.prototype.get called on incompatible receiver`. Fix: re-bind collection methods to the underlying target.
- **Identity mismatch (`proxy !== target`)** — a proxy is a distinct object, so `Map` keys or identity checks must consistently use the proxy or the target, never a mix.

## Summary

`Proxy` intercepts internal operations through 13 traps for validation, reactivity, dynamic RPC, and revocable sandboxing. `Reflect` forwards each trapped operation with the correct receiver, which inherited getters depend on. Engines enforce invariants that forbid contradicting locked target state. Watch for internal-slot incompatibilities with built-ins like `Map` and `Date`, and remember proxies never equal their targets.

# Proxy & Reflect

How do you reject `user.age = -5` at assignment time, or build Vue-3-style reactivity that notices property reads and writes, without making callers abandon dot syntax for helper functions? Both use one pair of tools. A **`Proxy`** wraps the target and intercepts the operation: `set` validates an assignment, while `get` and `set` can track reads and writes. **`Reflect`** then performs the forwarded operation with the correct receiver, so the trap does not have to reimplement the engine's behavior.

```javascript
'use strict';

const user = { name: 'Alice', age: 30 };

const validator = {
  set(target, prop, value, receiver) {
    if (prop === 'age' && (!Number.isInteger(value) || value < 0 || value > 150)) {
      throw new TypeError('age must be a positive integer between 0 and 150');
    }
    return Reflect.set(target, prop, value, receiver);
  }
};

const proxyUser = new Proxy(user, validator);
proxyUser.age = 31; // Works seamlessly!
// proxyUser.age = -1; // Throws TypeError: age must be a positive integer between 0 and 150
```

## Definition

A **`Proxy`** is an exotic wrapper that intercepts fundamental operations (property lookup, assignment, enumeration, invocation, construction) through handler functions called **traps**. **`Reflect`** is a built-in namespace exposing each interceptable operation as a function, so traps can forward work to the underlying target with correct receiver bindings.

> **Textbook Definition:** A proxy mediates selected internal operations on a target through handler traps, subject to language invariants. `Reflect` exposes corresponding operations as functions so a trap can forward an operation with an explicit receiver.

## First Principles

Every object operation is defined in terms of spec-level internal methods (`[[Get]]`, `[[Set]]`, `[[Delete]]`, `[[Call]]`) — `Proxy` hooks developer code directly into those primitives. A proxy does not copy the target's properties, but the distinct wrapper and its handler still use memory and retain references. Operations without a custom trap forward to the target. And to keep metaprogramming from corrupting runtime guarantees, the engine enforces **invariants** — traps must obey the specific constraints imposed by target descriptors and extensibility; a non-configurable writable property has different constraints from a fully locked one.

## 1. Step-by-Step Assignment Interception

Assigning `proxyUser.age = 31` flows through a pipeline:

```text
proxyUser.age = 31
       │
       ▼
1. JavaScript engine invokes the handler's set() trap:
   set(target, prop, value, receiver)
       │
       ▼
2. Custom Validation Logic runs:
   Verifies that 31 is an integer between 0 and 150
       │
       ▼
3. Reflect.set(target, prop, value, receiver) forwards the operation:
   Applies the write to user.age and returns true
       │
       ▼
4. Assignment completes successfully!
```

## 2. Preserve the Receiver When Forwarding

A raw `target[prop]` read evaluates getters with the target as receiver. `Reflect.get(target, prop, receiver)` can preserve the caller's receiver, which matters when nested getter reads must also pass through the proxy:

```javascript
// WRONG: Breaks inheritance and getter and setter reactivity!
const badHandler = {
  get(target, prop, receiver) {
    return target[prop]; // Loses 'receiver'!
  }
};

// CORRECT: Uses Reflect to preserve the calling receiver
const goodHandler = {
  get(target, prop, receiver) {
    return Reflect.get(target, prop, receiver); // 'this' points to proxy!
  }
};
```

With an inherited getter, the difference is observable:

```javascript
const parent = {
  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  }
};

const child = { firstName: 'Alice', lastName: 'Smith' };
Object.setPrototypeOf(child, parent);

const childProxy = new Proxy(child, {
  get(target, prop, receiver) {
    // target[prop] would bind this to child, not parent.
    // Reflect.get preserves childProxy, so nested reads can also be trapped.
    console.log('read', String(prop));
    return Reflect.get(target, prop, receiver);
  }
});

console.log(childProxy.fullName); // 'Alice Smith'
// Traces read fullName, read firstName, read lastName.
// With target[prop], only read fullName is trapped; the string is still Alice Smith.
```

Without `receiver`, inherited getters bind `this` to the static target instead of the calling proxy — silently breaking reactivity.

## 3. The 13 Proxy Traps (The Complete Metaprogramming Surface)

The 13 handler traps correspond to the fundamental internal operations a proxy can intercept:

| Category | Traps | Triggered By |
| :------------------------ | :------------------------------------------------------ | :-------------------------------------------------------------------------- |
| **Property Operations** | `get`, `set`, `has`, `deleteProperty` | `obj.x`, `obj.x = 1`, `'x' in obj`, `delete obj.x` |
| **Descriptor Operations** | `getOwnPropertyDescriptor`, `defineProperty`, `ownKeys` | `Object.getOwnPropertyDescriptor`, `Object.defineProperty`, `Object.keys()` |
| **Prototype Operations** | `getPrototypeOf`, `setPrototypeOf` | `Object.getPrototypeOf`, `Object.setPrototypeOf`, `instanceof` |
| **Extensibility** | `isExtensible`, `preventExtensions` | `Object.isExtensible`, `Object.preventExtensions`, `Object.freeze` |
| **Function Invocations** | `apply`, `construct` | `fn(...args)`, `new Constructor(...args)` |

## 4. Engine Invariants: Protected Target Rules

The engine rejects traps that contradict locked target state. If `target.id` is non-configurable and non-writable with value `42`, a `get` trap **must** return `42` — anything else throws `TypeError`. If `Object.preventExtensions(target)` ran, the `isExtensible` trap must return `false`:

```javascript
const locked = {};
Object.defineProperty(locked, 'secret', {
  value: 42,
  writable: false,
  configurable: false
});

const invalidProxy = new Proxy(locked, {
  get() { return 999; } // Invariant violation!
});

try {
  invalidProxy.secret;
} catch (e) {
  console.log(e instanceof TypeError); // true: Invariant violation throws TypeError
}
```

A `set` trap must also return a boolean indicating whether the assignment succeeded: returning `false` in strict mode throws `TypeError`, whereas in sloppy mode the assignment fails silently:

```javascript
const readOnly = new Proxy({ count: 1 }, {
  set() { return false; }
});

(() => {
  'use strict';
  try {
    readOnly.count = 2;
  } catch (e) {
    console.log(e instanceof TypeError); // true: strict assignment rejects falsy set trap
  }
})();
```

## 5. Production Architectural Use Cases

1. **Reactivity engines (Vue 3)** — the `get` trap registers the rendering computed expression or template as a subscriber (`track(target, prop)`); the `set` trap detects changes and schedules re-renders (`trigger(target, prop)`).
2. **Dynamic Remote Procedure Call (RPC) clients** — a recursive proxy builds URLs instead of a hundred-line SDK:
   ```javascript
   function createApiClient(baseUrl) {
     return new Proxy({}, {
       get(target, prop) {
         return (id = '') => fetch(`${baseUrl}/${String(prop)}/${id}`);
       }
     });
   }
   const api = createApiClient('https://api.example.com');
   // api.users(123) automatically calls fetch('https://api.example.com/users/123')
   ```
3. **Revocable proxies (`Proxy.revocable`)** — an owner can disable further operations through this wrapper. It is not a sandbox: retained raw-target references and values already returned remain usable:
   ```javascript
   const sensitiveData = { token: 'xyz123' };
   const { proxy, revoke } = Proxy.revocable(sensitiveData, {});

   console.log(proxy.token); // 'xyz123': a returned primitive cannot be revoked
   revoke();                 // Immediately cuts off access!

   try {
     console.log(proxy.token);
   } catch (e) {
     console.log(e instanceof TypeError); // true: Cannot perform 'get' on a proxy that has been revoked
   }
   ```

## 6. Senior Gotchas: Internal Slots and Identity Transparency

- **Internal slot failures (`Map`, `Set`, `Date`, and private `#fields`)** — built-ins store native state in internal slots like `[[MapData]]`. Calling `mapProxy.get('a')` throws `TypeError: Method Map.prototype.get called on incompatible receiver` because `this` inside `Map.prototype.get` is the proxy wrapper rather than the raw `Map`. ES private class fields (`#secret`) perform an analogous brand check on `this` and fail for the same reason. Re-bind native or private-access methods to `target` in the `get` trap:

```javascript
'use strict';

const brokenMap = new Proxy(new Map([['a', 1]]), {});
try {
  brokenMap.get('a');
} catch (e) {
  console.log(e instanceof TypeError); // true: missing [[MapData]] internal slot
}

const safeMap = new Proxy(new Map([['a', 1]]), {
  get(target, prop) {
    const val = Reflect.get(target, prop, target);
    return typeof val === 'function' ? val.bind(target) : val;
  }
});
console.log(safeMap.get('a')); // 1

class Vault {
  #secret = 'top-secret';
  readSecret() { return this.#secret; }
}
const proxiedVault = new Proxy(new Vault(), {});
try {
  proxiedVault.readSecret();
} catch (e) {
  console.log(e instanceof TypeError); // true: proxy fails #secret brand check
}
```

- **Shallow traps and lazy nested wrapping** — `new Proxy(root, handler)` intercepts only direct operations on `root`. Reading `proxy.nested` returns the raw inner object, so `proxy.nested.count = 2` bypasses `root`'s `set` trap. Deep reactive frameworks wrap nested objects lazily inside `get` and cache wrappers in a `WeakMap` so repeated reads preserve object identity (`proxy.nested === proxy.nested`):

```javascript
'use strict';

const proxyCache = new WeakMap();

function reactiveRead(target, onRead) {
  if (typeof target !== 'object' || target === null) return target;
  if (proxyCache.has(target)) return proxyCache.get(target);

  const proxy = new Proxy(target, {
    get(t, prop, receiver) {
      onRead(t, prop);
      const value = Reflect.get(t, prop, receiver);
      return reactiveRead(value, onRead);
    }
  });
  proxyCache.set(target, proxy);
  return proxy;
}

const reads = [];
const state = reactiveRead({ user: { name: 'Alice' } }, (_, k) => reads.push(k));
console.log(state.user === state.user); // true (WeakMap preserves wrapper identity)
console.log(state.user.name, reads);    // 'Alice' [ 'user', 'user', 'user', 'name' ]
```

- **Identity mismatch (`proxy !== target`)** — a proxy is a distinct object, so `Map` keys, `Set` membership, or `===` checks must consistently use either the proxy or the target, never a mix.

## Summary

`Proxy` intercepts internal operations through 13 traps for validation, reactivity, dynamic RPC, and revocable wrapper access. `Reflect` forwards each trapped operation with the correct receiver, which inherited getters depend on. Engines enforce invariants that forbid contradicting locked target state. Watch for internal-slot and private-field brand failures with built-ins like `Map` and `#fields`, wrap nested objects lazily via a `WeakMap` cache to keep identity consistent, and remember proxies never equal their targets.

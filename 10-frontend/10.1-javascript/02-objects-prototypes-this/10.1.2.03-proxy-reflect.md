# Proxy & Reflect

Suppose an API exposes an account object and must reject an invalid age whenever clients assign `user.age`. Replacing property access with a `setAge()` method would change every caller; a proxy can intercept the existing assignment. Forwarding must still preserve the receiver and the target's guarantees.

## Definition

A **Proxy** is a distinct object that intercepts selected operations on a target object through handler functions called **traps**. A callable or constructible function can also be a target, allowing call or construction operations to be intercepted. **Reflect** provides functions for performing corresponding object operations explicitly, often forwarding a trap to its target. Only operations that go through the proxy are intercepted; code holding the target can bypass it.

> **Textbook Definition:** A proxy mediates selected internal operations on a target through handler traps, subject to language invariants. Reflect exposes corresponding operations as functions so a trap can forward an operation with an explicit receiver.

## First Principles

1. Property reads, writes, calls and other object interactions are defined as operations, not special syntax that only direct methods can observe.
2. A proxy can replace selected operations with handler code; omitted traps forward to the target.
3. Because handlers can run arbitrary code, the engine checks that their results still honor protected target properties and object invariants.

## Follow one assignment

```text
user.age = 31
  → set trap receives target, key, value and receiver
  → validate the value
  → Reflect.set forwards the write with that receiver
  → the trap reports whether the operation succeeded
```

```js
'use strict';
const target = { name: 'Alice', age: 30 };
const user = new Proxy(target, {
  get(object, key, receiver) {
    return Reflect.get(object, key, receiver);
  },
  set(object, key, value, receiver) {
    if (key === 'age' && (!Number.isInteger(value) || value < 0 || value > 150)) {
      throw new TypeError('age must be an integer from 0 to 150');
    }
    return Reflect.set(object, key, value, receiver);
  }
});

console.log(user.age = 31); // 31: assignment evaluates to the right-hand side
console.log(target.age);    // 31: forwarding changed the target
try { user.age = -1; } catch (error) { console.log(error.name); } // TypeError
```

The `receiver` is the object through which the operation was requested. It matters when lookup reaches an inherited accessor: the accessor's `this` should usually be the receiver, not the target where the accessor was found. `Reflect.get` and `Reflect.set` preserve that relationship; direct `target[key]` operations may not.

A `set` trap returns a success boolean, not the assigned value. Returning `false` makes this strict-mode assignment throw. The engine also enforces **invariants**: a trap cannot claim a write succeeded if it contradicts a protected non-configurable, non-writable target property. A `get` trap must return the actual value of such a property. These rules keep a proxy from contradicting target guarantees the language exposes.

This proxy validates writes that pass through it. It does not validate the initial object, direct writes through `target`, property definition, deletion or nested objects. Validate external input at the boundary with a runtime schema.

## The trap follows the operation

| Operation | Trap | Important boundary |
| -------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------- |
| Read, write, delete, test property | `get`, `set`, `deleteProperty`, `has` | `in` invokes `has`; ordinary property reads invoke `get`. |
| List keys or inspect/define a property | `ownKeys`, `getOwnPropertyDescriptor`, `defineProperty` | Invariants constrain reported keys and descriptors. |
| Read or change the prototype | `getPrototypeOf`, `setPrototypeOf` | The reported chain must respect target extensibility. |
| Inspect or prevent extensions | `isExtensible`, `preventExtensions` | A proxy cannot report a state inconsistent with the target. |
| Call or construct | `apply`, `construct` | The target must itself be callable or constructible. |

An omitted trap forwards its operation. `Reflect.ownKeys` includes symbols and non-enumerable properties; `Object.keys` filters to own enumerable string keys, so those APIs are not interchangeable.

## Reactivity is dependency tracking around these operations

A reactive runtime can use `get` to record that the active computation read a `(target, key)` pair, then use a successful `set` to notify computations subscribed to that pair when the value changes. It must also remove stale dependencies when a computation takes a different branch and define how updates are scheduled. This is the connection between Proxy and systems such as [Vue reactivity](https://vuejs.org/guide/extras/reactivity-in-depth.html).

That model is synchronous and incomplete by design. Production runtimes also need rules for nested objects, collections, deletion, batching, effects that throw, re-entry and reads after `await`. A `get`/`set` sketch does not provide those lifecycle guarantees.

## Revocation stops access through one wrapper

```js
const target = { message: 'hello' };
const { proxy, revoke } = Proxy.revocable(target, {});
console.log(proxy.message); // hello
revoke();
try { console.log(proxy.message); }
catch (error) { console.log(error.name); } // TypeError
console.log(target.message); // hello: the target remains usable
```

Revocation makes later operations through that proxy throw. It does not destroy the target, revoke other proxies or retract references already returned. A proxy also has its own identity, so it is not automatically transparent: methods on `Map` and other built-ins can reject a proxy receiver because it lacks the target's internal slots. Binding every method to the target can bypass interception and change the API contract. Test the operations callers actually use.

Traps can affect hot-path cost. Measure representative operations in the target runtime instead of assuming a fixed slowdown.

## Summary

Identify the operation being trapped, preserve its receiver when forwarding, and respect invariants on the target. A proxy mediates only access through that wrapper; raw references, nested values, built-in internal slots and lifecycle remain separate design concerns.

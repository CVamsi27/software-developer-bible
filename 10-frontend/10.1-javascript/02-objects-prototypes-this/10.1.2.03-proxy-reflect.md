# Proxy & Reflect

Suppose you need to enforce runtime schema validation whenever someone assigns `user.age = -5`, or build a fine-grained reactivity system like Vue 3 that detects property reads and writes. How can you intercept native JavaScript property access without forcing callers to replace dot-syntax with getter and setter helper functions?

```javascript
'use strict';

const user = { name: 'Alice', age: 30 };

const validator = {
  set(target, prop, value, receiver) {
    if (prop === 'age' && (!Number.isInteger(value) || value < 0 || value > 150)) {
      throw new TypeError('age must be a positive integer between 0 and 150');
    }
    return Reflect.set(target, prop, value, receiver);
  }
};

const proxyUser = new Proxy(user, validator);
proxyUser.age = 31; // Works seamlessly!
// proxyUser.age = -1; // Throws TypeError: age must be a positive integer between 0 and 150
```

## Definition

A **`Proxy`** is an exotic JavaScript wrapper object that intercepts fundamental internal language operations (such as property lookup, assignment, enumeration, function invocation, and construction) through custom handler functions called **traps**. **`Reflect`** is a built-in static object that provides matching methods for every interceptable internal operation, allowing traps to delegate execution back to the underlying target while preserving correct receiver bindings.

> **Textbook Definition:** A proxy mediates selected internal operations on a target through handler traps, subject to language invariants. Reflect exposes corresponding operations as functions so a trap can forward an operation with an explicit receiver.

## First Principles

1. **Metaprogramming via Internal Methods**: In ECMAScript, all object manipulations compile to internal methods on the specification level (like `[[Get]]`, `[[Set]]`, `[[Delete]]`, and `[[Call]]`). `Proxy` allows developer code to hook directly into these internal virtual machine primitives.
2. **Transparent Delegation**: A proxy does not duplicate object memory. It acts as an inline mediator: any operation without a custom trap falls through directly to the underlying target object.
3. **Invariable Language Integrity**: To prevent metaprogramming from corrupting core runtime guarantees, the engine strictly enforces **invariants**: traps are mathematically forbidden from contradicting non-configurable or non-writable property states on the target.

## How It Works

### 1. Step-by-Step Assignment Interception

When code assigns `proxyUser.age = 31`, execution flows through a structured pipeline:

```text
proxyUser.age = 31
       │
       ▼
1. JavaScript engine invokes the handler's set() trap:
   set(target, prop, value, receiver)
       │
       ▼
2. Custom Validation Logic runs:
   Verifies that 31 is an integer between 0 and 150
       │
       ▼
3. Reflect.set(target, prop, value, receiver) forwards the operation:
   Applies the write to user.age and returns true
       │
       ▼
4. Assignment completes successfully!
```

### 2. Why `Reflect` is Mandatory: The Receiver Argument

A common anti-pattern among novice developers is forwarding operations inside a trap using raw property assignment (`target[prop] = value`):

```javascript
// WRONG: Breaks inheritance and getter/setter reactivity!
const badHandler = {
  get(target, prop, receiver) {
    return target[prop]; // Loses 'receiver'!
  }
};

// CORRECT: Uses Reflect to preserve the calling receiver
const goodHandler = {
  get(target, prop, receiver) {
    return Reflect.get(target, prop, receiver); // 'this' points to proxy!
  }
};
```

#### Why does `receiver` matter?
Consider an object with an inherited getter:

```javascript
const parent = {
  get fullName() {
    return `${this.firstName} ${this.lastName}`;
  }
};

const child = { firstName: 'Alice', lastName: 'Smith' };
Object.setPrototypeOf(child, parent);

const childProxy = new Proxy(child, {
  get(target, prop, receiver) {
    // If you return target[prop], 'this' inside fullName binds to parent (missing child fields!)
    // Using Reflect.get(target, prop, receiver) ensures 'this' inside fullName binds to childProxy!
    return Reflect.get(target, prop, receiver);
  }
});

console.log(childProxy.fullName); // 'Alice Smith'
```

Without passing `receiver` to `Reflect.get`, inherited getters bind `this` to the static target where the getter was declared rather than the dynamic calling proxy, silently breaking reactivity and inheritance.

### 3. The 13 Proxy Traps (The Complete Metaprogramming Surface)

`Proxy` supports exactly 13 traps corresponding directly to the 13 internal ECMAScript methods:

| Category | Traps | Triggered By |
| :------------------------ | :------------------------------------------------------ | :-------------------------------------------------------------------------- |
| **Property Operations** | `get`, `set`, `has`, `deleteProperty` | `obj.x`, `obj.x = 1`, `'x' in obj`, `delete obj.x` |
| **Descriptor Operations** | `getOwnPropertyDescriptor`, `defineProperty`, `ownKeys` | `Object.getOwnPropertyDescriptor`, `Object.defineProperty`, `Object.keys()` |
| **Prototype Operations** | `getPrototypeOf`, `setPrototypeOf` | `Object.getPrototypeOf`, `Object.setPrototypeOf`, `instanceof` |
| **Extensibility** | `isExtensible`, `preventExtensions` | `Object.isExtensible`, `Object.preventExtensions`, `Object.freeze` |
| **Function Invocations** | `apply`, `construct` | `fn(...args)`, `new Constructor(...args)` |

### 4. Engine Invariants: Protected Target Rules

JavaScript engines strictly enforce invariants to preserve memory safety:
- **Non-Configurable, Non-Writable Properties**: If `target.id` is `{ writable: false, configurable: false }` with value `42`, a `get` trap **must** return `42`. Returning any other value throws a fatal `TypeError`.
- **Non-Extensible Targets**: If `Object.preventExtensions(target)` has been called, `isExtensible()` trap must return `false`.

```javascript
const locked = {};
Object.defineProperty(locked, 'secret', {
  value: 42,
  writable: false,
  configurable: false
});

const invalidProxy = new Proxy(locked, {
  get() { return 999; } // Invariant violation!
});

try {
  invalidProxy.secret;
} catch (e) {
  console.log(e instanceof TypeError); // true: Invariant violation throws TypeError
}
```

### 5. Production Architectural Use Cases

1. **Reactivity Engines (Vue 3)**:
   - `get` trap: Identifies which computed property or component template is currently rendering and registers it as a subscriber (`track(target, prop)`).
   - `set` trap: Detects value changes and schedules reactive re-renders (`trigger(target, prop)`).
2. **Dynamic RPC / Virtual HTTP Clients**:
   Instead of writing hundred-line client SDKs, a recursive proxy builds URLs dynamically:
   ```javascript
   function createApiClient(baseUrl) {
     return new Proxy({}, {
       get(target, prop) {
         return (id = '') => fetch(`${baseUrl}/${String(prop)}/${id}`);
       }
     });
   }
   const api = createApiClient('https://api.example.com');
   // api.users(123) automatically calls fetch('https://api.example.com/users/123')
   ```
3. **Revocable Proxies (`Proxy.revocable`)**:
   Used in security sandboxes to provide temporary object access to untrusted third-party plugins:
   ```javascript
   const sensitiveData = { token: 'xyz123' };
   const { proxy, revoke } = Proxy.revocable(sensitiveData, {});

   console.log(proxy.token); // 'xyz123'
   revoke();                 // Immediately cuts off access!

   try {
     console.log(proxy.token);
   } catch (e) {
     console.log(e instanceof TypeError); // true: Cannot perform 'get' on a proxy that has been revoked
   }
   ```

### 6. Senior Gotchas: Internal Slots and Identity Transparency

- **Internal Slot Failures (`Map`, `Set`, `Date`, `#private`)**:
  Built-in objects store native C++ pointers in internal slots (e.g., `[[MapData]]`, `[[DateValue]]`). When you invoke `mapProxy.get('key')`, the native C++ method checks `this` for the `[[MapData]]` slot. Because `this === mapProxy`, the check fails and throws `TypeError: Method Map.prototype.get called on incompatible receiver`.
  *Fix*: Re-bind methods to the underlying target when accessing built-in collection methods.
- **Identity Mismatch (`proxy !== target`)**:
  Because a proxy is a distinct object in memory, checking `proxy === target` evaluates to `false`. Code relying on `Map` keys or object identity must consistently reference either the proxy or the target, never a mixture of both.

## Summary

`Proxy` provides native metaprogramming capabilities by intercepting internal object methods through 13 specialized traps. `Reflect` mirrors these traps, providing safe standard implementations that properly forward dynamic receiver contexts for inherited getters and setters. While engines guarantee language integrity through invariant validation, senior engineers must account for internal slot incompatibilities with built-ins like `Map` and `Date`, and leverage `Proxy.revocable` for secure plugin boundaries.

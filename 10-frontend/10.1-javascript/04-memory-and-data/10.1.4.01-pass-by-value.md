# Pass by Value vs Pass by Reference

## Definition

JavaScript passes arguments by value: a parameter receives the argument's value in its own binding. An object value identifies a shared object; passing it does not duplicate that object's contents or give the function access to the caller's variable binding. This is also described as **call by sharing**.

## First Principles

1. **The caller and callee have distinct bindings.** Assigning a parameter changes that parameter's binding. To change the caller's binding, the caller must assign a returned value or another explicit result.
2. **An object has identity beyond any one binding.** Several variables can identify the same object. A property write changes that shared object, so every alias can observe it.
3. **Ownership determines whether sharing is useful.** Sharing a mutable buffer can avoid copying; sharing a supposedly immutable React snapshot can hide changes. The passing rule does not choose a mutation policy for an API.

## One call can mutate an object without replacing the caller's value

Run this as JavaScript in Node or a browser console:

```javascript
const original = { count: 1 };
function update(record) {
  record.count = 2;
  record = { count: 3 };
  return record;
}
const replacement = update(original);
console.log(original.count);       // 2
console.log(replacement.count);    // 3
console.log(original === replacement); // false
```

At the call, both `original` and the parameter `record` identify the first object. The property write changes its count to 2. Reassigning `record` then makes only that local binding identify a second object. Returning it lets the caller deliberately keep that replacement.

```text
at call:        original ─┐
                         ├→ object A {count: 1}
                record ──┘
after property write:       object A {count: 2}
after rebinding: original → object A; record → object B {count: 3}
```

The diagram describes identity, not a guaranteed physical heap/stack layout. Engines may optimize storage without changing these observable results.

## Primitives, arrays and destructuring follow the same rule

Primitives—string, number, bigint, boolean, symbol, null and undefined—do not expose mutable object properties. Reassigning a primitive parameter therefore cannot change an earlier binding. String methods produce values rather than changing the existing string:

```javascript
let name = "alice";
function uppercase(value) { value = value.toUpperCase(); return value; }
console.log(uppercase(name)); // ALICE
console.log(name);            // alice
name = uppercase(name);
console.log(name);            // ALICE
```

Arrays, functions, dates, maps and sets are objects. Their mutation methods operate on shared identity:

```javascript
const rows = [{ name: "Alice" }];
const alias = rows;
const [row] = rows;
let { name } = row;
name = "Local";           // Rebinds the destructured primitive.
row.name = "Bob";         // Changes the shared nested object.
alias.push({ name: "Cara" });
console.log(rows.length, rows[0].name, name); // 2 Bob Local
```

Destructuring reads property values into bindings; it is not a deep clone. `const` protects a binding from reassignment, while the object it identifies may still be mutable.

## Make mutation part of the function contract

Both APIs below are valid, but callers need to know which one they receive:

```typescript
function appendInPlace(values: number[], value: number): number[] {
  values.push(value);
  return values;
}
function appended(values: readonly number[], value: number): number[] {
  return [...values, value];
}
const source = [1, 2];
const next = appended(source, 3);
console.log(source, next); // [1, 2] [1, 2, 3]
console.log(appendInPlace(source, 4) === source); // true
```

A `readonly` parameter prevents writes through that typed view; another alias may still mutate the object at runtime. `Object.freeze` protects an object's own properties at runtime and is shallow. Neither creates a deep clone. Their exact boundaries and copying methods belong in [Shallow vs Deep Copy](10.1.4.03-shallow-vs-deep-copy.md).

For a pure numeric sort, `values.toSorted((a, b) => a - b)` returns another array; `values.sort(...)` mutates the original. A shallow copy still shares object elements, so sorting a copy does not make nested records independently mutable.

## Replace React state along the changed path

A state update should describe a new snapshot. This typed reducer changes the top-level value and shares the unchanged nested preferences:

```typescript
type State = { count: number; preferences: { theme: string } };
type Action = { type: "set-count"; count: number };
function reducer(state: State, action: Action): State {
  if (state.count === action.count) return state;
  return { ...state, count: action.count };
}
const previous: State = { count: 0, preferences: { theme: "dark" } };
const next = reducer(previous, { type: "set-count", count: 1 });
console.log(previous.count, next.count); // 0 1
console.log(previous.preferences === next.preferences); // true
```

If a nested preference changes, replace that nested object and each parent on its path. Avoid cloning an entire large graph when only one branch changes. Redux Toolkit can expose mutation-like syntax through Immer while producing immutable results; that is a library mechanism, not a different JavaScript argument-passing rule.

## Keep binding, receiver and closure questions separate

A callback losing `this` is a **receiver-selection** problem, explained in [This](../02-objects-prototypes-this/10.1.2.01-this.md). A returned function retaining an outer variable is a **lexical-binding** problem, explained in [Closures](../01-execution-and-scope/10.1.1.06-closures.md). Closures retain access to bindings rather than taking a universal by-value snapshot of each captured variable. Neither changes how arguments are passed.

## Decide whether copying pays for independence

Passing an object does not recursively copy its graph. A shallow object/array copy visits the selected top-level properties/elements; a deep clone traverses the supported reachable graph and preserves its internal cycles and aliases according to the clone protocol. Actual representation and timing are engine dependent; a reference argument is not guaranteed to have exactly the same machine cost as a number argument.

Use sharing when ownership is clear, structural sharing for immutable updates, and a deep clone when independent supported data is required. Persistent immutable collections can share unchanged branches; they are useful for appropriate workloads, with their own representation and interoperability costs.

## Summary

A function receives a value in its own parameter binding. Object values may identify the same object, so mutation is visible through aliases; rebinding a parameter does not replace the caller's value. State the mutation contract, and copy only the data that needs an independent identity.

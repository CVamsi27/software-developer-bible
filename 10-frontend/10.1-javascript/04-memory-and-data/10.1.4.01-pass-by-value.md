# Pass by Value vs Pass by Reference

Inside a function, `record.count = 2` mutates the caller's object — but the very next line, `record = { count: 3 }`, affects nothing outside. Same parameter, opposite outcomes. JavaScript passes everything strictly by value; the difference is *what* gets copied.

```javascript
const original = { count: 1 };

function update(record) {
  record.count = 2;      // Mutates the shared heap object
  record = { count: 3 }; // Rebinds only the local parameter
  return record;
}

const replacement = update(original);
console.log(original.count);            // 2 (shared object was mutated)
console.log(replacement.count);         // 3 (new allocation returned)
console.log(original === replacement);  // false (different addresses)
```

## Definition

JavaScript uses **pass-by-value** for all arguments — specialized as **call-by-sharing** for objects. Each argument expression evaluates fully, and the resulting value copies into the callee's parameter slot. Primitives copy the raw value; objects copy the **heap pointer**. Reassigning the parameter rebinds the local pointer; dereferencing it (`.`) mutates the shared heap allocation.

> **Textbook Definition:** JavaScript strictly evaluates all function arguments using pass-by-value semantics. When passing an object, the value copied into the callee's parameter binding is the reference pointer addressing the heap object; parameter reassignment re-binds the local pointer without altering the caller's variable, whereas property dereferencing mutates the shared heap allocation.

## First Principles

Each call creates fresh parameter slots in its own environment record, and argument values copy into them bit-for-bit. Objects live only on the heap, so the "value" copied is a memory address — caller and callee slots end up holding identical pointers to one allocation. From there the rule is mechanical: `=` rewrites the address *in the slot*, while `.` follows the address *to the heap*.

```text
At Function Invocation:
Caller Scope: [ original ] ───▶ (0x7FFF) ───▶ Heap Object: { count: 1 }
                                  ▲
Callee Scope: [ record   ] ───────┘ (Pointer copied by value)

After `record.count = 2` (Dereference & Mutate):
Caller Scope: [ original ] ───▶ (0x7FFF) ───▶ Heap Object: { count: 2 }
                                  ▲
Callee Scope: [ record   ] ───────┘

After `record = { count: 3 }` (Local Reassignment):
Caller Scope: [ original ] ───▶ (0x7FFF) ───▶ Heap Object: { count: 2 }
Callee Scope: [ record   ] ───▶ (0x9AAA) ───▶ Heap Object: { count: 3 }
```

## 1. The Core Senior Distinction: Reassignment vs. Mutation

In the hook example, `update(original)` copies address `0x7FFF` into `record`. `record.count = 2` follows that pointer and writes into the shared allocation — visible via `original`. Then `record = { count: 3 }` allocates `0x9AAA` and stores it in the *local* slot only; `original` still points at `0x7FFF`. True pass-by-reference (C++ `&`, C# `ref`) passes the *binding's* address, so reassignment would rewrite the caller's variable — impossible in ECMAScript, which never exposes binding addresses.

## 2. Memory Internals: Stack Frames vs. V8 Garbage Collected Heap

| Value Type | Engine Representation | Storage Location | Copy Mechanism |
| :------------------------------ | :------------------------------ | :------------------------ | :------------------------------------------------------------------- |
| **Small Integer (Smi)** | 31-bit or 32-bit tagged integer | Call Stack / CPU Register | Raw value copied inline; zero heap allocation |
| **Primitives (String, BigInt)** | Immutable heap structure | V8 Heap | Immutable pointer copied; deduplicated via internalized string table |
| **Objects & Arrays** | Mutable `JSObject` structure | V8 Garbage Collected Heap | 32-bit compressed pointer copied into parameter slot |

## 3. Destructuring and Spread: What Actually Copies?

Spread and destructuring copy the outer shell only — nested references stay shared:

```javascript
const state = {
  user: { name: 'Alice' },
  roles: ['admin', 'editor'],
};

// Spread shallow-copies the outer object:
const stateClone = { ...state };

// The outer containers have distinct identities:
console.log(state === stateClone); // false

// BUT nested objects share identical reference addresses:
console.log(state.user === stateClone.user);   // true
console.log(state.roles === stateClone.roles); // true

// Mutating a nested reference affects BOTH copies:
stateClone.user.name = 'Bob';
console.log(state.user.name); // "Bob" (Inadvertent mutation!)
```

Destructuring behaves identically — `const { user } = state` binds the same heap pointer, so `user.name = 'Charlie'` mutates `state.user.name`.

## 4. Contract Design: Pure Functions vs. In-Place Mutation

Reliable APIs declare their contract up front — mutating in place or returning a defensive copy:

```typescript
// MUTATING IN-PLACE (Impure Contract)
function appendInPlace<T>(list: T[], item: T): T[] {
  list.push(item);
  return list;
}

// PURE TRANSFORMATION (Defensive Copy Contract)
function appendImmutable<T>(list: readonly T[], item: T): T[] {
  return [...list, item];
}
```

ES2023 added non-mutating counterparts for the historic in-place array methods:

| In-Place Mutating Method | Non-Mutating Pure Counterpart | Returned Output |
| :------------------------- | :---------------------------- | :--------------------------- |
| `arr.sort(compareFn)` | `arr.toSorted(compareFn)` | New sorted array instance |
| `arr.reverse()` | `arr.toReversed()` | New reversed array instance |
| `arr.splice(start, count)` | `arr.toSpliced(start, count)` | New spliced array instance |
| `arr[i] = value` | `arr.with(i, value)` | New array with updated index |

```javascript
const numbers = [3, 1, 2];

// Historic method mutates original array:
// numbers.sort(); // Mutates numbers to [1, 2, 3]

// Modern ES2023 pure method:
const sorted = numbers.toSorted();
console.log(numbers); // [3, 1, 2] (Preserved untouched)
console.log(sorted);  // [1, 2, 3] (New array instance)
```

## Summary

Every argument copies by value: primitives copy bits, objects copy heap pointers (call-by-sharing). Dereferencing a copied pointer mutates shared heap state; reassigning the parameter only rebinds the local slot. Spread and destructuring are shallow — nested references stay aliased. Prefer pure contracts (`toSorted`, defensive copies) where aliasing mutations would surprise callers.

# Map, Set, WeakMap, and WeakSet

Need object keys without string coercion, duplicate-free values, or metadata attached to DOM nodes that vanishes when the node is removed? The four built-in collections differ on exactly three axes: key equality, iteration exposure, and reference strength.

```javascript
const cache = new Map();
const key = { id: 1 };
cache.set(key, 'admin');
console.log(cache.get({ id: 1 })); // undefined — different reference!

const seen = new Set([1, 2, 3, 2, 1]);
console.log([...seen]); // [1, 2, 3] — duplicates dropped, order kept
```

## Definition

**`Map`** and **`Set`** are general-purpose collections with **strong references**: any-value keys, `SameValueZero` equality, and guaranteed insertion-order iteration. **`WeakMap`** and **`WeakSet`** hold object-only keys **weakly**: entries vanish when the key loses all strong references, and the contents can never be enumerated — which is precisely what makes them leak-proof metadata stores.

| Collection | Key Type | Value Uniqueness | Iteration Order | Garbage Collection |
| :------------------------ | :---------------------------- | :------------------------ | :------------------------ | :-------------------------------------------------------- |
| **`Map`** | Any value (including objects) | Unique keys | Insertion order | Strong references; keys and values retained |
| **`Set`** | Any value (including objects) | Unique values | Insertion order | Strong references; items retained |
| **`WeakMap`** | Objects only (no primitives) | Unique keys | Insertion order | **Weak** references; keys GC'd when no strong refs exist |
| **`WeakSet`** | Objects only (no primitives) | Unique values | Insertion order | **Weak** references; items GC'd when no strong refs exist |

> **Textbook Definition:** `Map` and `Set` are collections that track insertion order and allow any value as a key (Map) or value (Set) using the SameValueZero equality algorithm. `WeakMap` and `WeakSet` are collections where keys are weakly referenced, allowing garbage collection when no strong references exist, making them ideal for private data attachment without memory leaks.

## First Principles

Plain objects coerce keys to strings, so a keyed store needs a structure with **identity-based equality** — `SameValueZero`, where `NaN` equals `NaN` and `+0` equals `-0`. Insertion order must survive deletion and re-insertion for predictable iteration. And metadata attached to ephemeral objects (DOM nodes, class instances) must not *keep those objects alive* — hence weak references with no enumeration surface, so the engine can reclaim entries invisibly.

## How It Works

### 1. Map: Keyed Collections with Any-Keys

- **SameValueZero equality** — `NaN` keys match each other; `+0` and `-0` are identical. Subtly different from both `==` and `===`.
- **Insertion-order iteration** — guaranteed even after deletion and re-insertion.
- **Any-type keys** — objects, functions, primitives. DOM nodes or class instances work as keys with no collision risk:

```javascript
const user = { id: 1 };
const organizer = new Map();
organizer.set(user, 'admin');

// Object key lookup works even with identical structure:
const duplicate = { id: 1 };
organizer.get(duplicate); // undefined — different reference
```

### 2. Set: Unique Value Collection

Same equality and ordering guarantees as `Map`, applied to membership: adding a present value is a no-op and `size` stays put.

```javascript
const unique = new Set([1, 2, 3, 2, 1]);
console.log(unique.size); // 2 — duplicates ignored
console.log([...unique]); // [1, 2] — insertion order preserved
```

### 3. WeakMap: Private Data Without Memory Leaks

- **Object-only keys** — primitives throw `TypeError`.
- **Weak references** — drop the last strong reference to a key and its entry is GC'd, even while the `WeakMap` lives on.
- **No iteration surface** — no `size`, `clear`, or enumeration. This is the enforcement mechanism for the private-data pattern:

```javascript
const privateData = new WeakMap();

const element = document.createElement('div');
privateData.set(element, { initialized: true });

// When element is removed from DOM and has no other refs:
// { initialized: pair is GC'd automatically — no memory leak!
```

### 4. WeakSet: Object Membership Testing

Object-only members, weakly held, with no `size` or iteration — the membership-test counterpart: "is this element currently animating?" without retaining it:

```javascript
const animatingObjects = new WeakSet();

function animateIfVisible(element) {
  if (animatingObjects.has(element)) {
    element.animate([...]);
  }
}

// When element is no longer needed and strong refs dropped:
// It's automatically removed from animatingObjects — no leak
```

### 5. Choosing Between Them

| Scenario | Recommended Collection |
| :-------------------------------------- | :------------------------ |
| Caching function results by ID | `Map` |
| Tracking unique strings/primitives | `Set` |
| Attaching private config to DOM nodes | `WeakMap` |
| Set of elements being observed/animated | `WeakSet` |
| Object keys that must persist | `Map` (strong) |
| Object keys for temporary tracking | `WeakMap` (weak) |

Compared head-to-head: `Map`/`Set` accept any value, expose `size`/`clear`/iteration, and retain entries strongly. `WeakMap`/`WeakSet` accept objects only, expose nothing enumerable, and release entries with their keys. **Rule**: default to `Map`/`Set` for data storage; reach for weak variants when associating data with objects you must not keep alive.

## Summary

- **`Map`**: any-type keys, strong references, insertion order — general keyed storage.
- **`Set`**: unique values under the same guarantees — deduplication and membership.
- **`WeakMap`**: object-only weak keys, no enumeration — leak-proof private metadata.
- **`WeakSet`**: object-only weak members, no enumeration — leak-proof membership tracking.

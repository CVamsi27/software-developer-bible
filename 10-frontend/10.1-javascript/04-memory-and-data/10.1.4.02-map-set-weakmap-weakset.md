# Map, Set, WeakMap, and WeakSet

Need object keys without string coercion, duplicate-free values, or metadata whose collection need not keep a DOM node alive? The four built-in collections differ on exactly three axes: key equality, iteration exposure, and reference strength.

```javascript
const cache = new Map();
const key = { id: 1 };
cache.set(key, 'admin');
console.log(cache.get({ id: 1 })); // undefined — different reference!

const seen = new Set([1, 2, 3, 2, 1]);
console.log([...seen]); // [1, 2, 3] — duplicates dropped, order kept
```

## Definition

**`Map`** and **`Set`** are general-purpose collections with **strong references**: any-value keys, `SameValueZero` equality, and guaranteed insertion-order iteration. **`WeakMap`** and **`WeakSet`** hold eligible keys/members **weakly**: objects and non-registered symbols. They do not retain those keys by themselves and expose no enumeration or observable collection deadline. They can support metadata ownership; they do not make the whole application leak-proof.

| Collection | Key Type | Value Uniqueness | Iteration Order | Garbage Collection |
| :------------------------ | :--------------------------------- | :------------------------ | :------------------------ | :--------------------------------------------------------------------------------- |
| **`Map`** | Any value (including objects) | Unique keys | Insertion order | Strong references; keys and values retained |
| **`Set`** | Any value (including objects) | Unique values | Insertion order | Strong references; items retained |
| **`WeakMap`** | Objects and non-registered symbols | Unique keys | Not iterable | **Weak** references; eligible keys may be collected without a promised deadline |
| **`WeakSet`** | Objects and non-registered symbols | Unique values | Not iterable | **Weak** references; eligible members may be collected without a promised deadline |

> **Textbook Definition:** `Map` and `Set` are collections that track insertion order and allow any value as a key (Map) or value (Set) using the SameValueZero equality algorithm. `WeakMap` and `WeakSet` are collections where keys are weakly referenced, allowing garbage collection when no strong references exist, supporting metadata whose owner should follow the key's external lifetime; this supplies no deterministic cleanup guarantee.

## First Principles

Plain object property keys are strings or symbols; other key values are converted, so a keyed store needs a structure with **identity-based equality** — `SameValueZero`, where `NaN` equals `NaN` and `+0` equals `-0`. Updating an existing Map key preserves its position; deleting and reinserting it moves it to the end. And metadata attached to ephemeral objects (DOM nodes, class instances) must not *keep those objects alive* — hence weak references with no enumeration surface, so the engine can reclaim entries invisibly.

## 1. Map: Keyed Collections with Any-Keys

- **SameValueZero equality** — `NaN` keys match each other; `+0` and `-0` are identical. Subtly different from both `==` and `===`.
- **Insertion-order iteration** — guaranteed even after deletion and re-insertion.
- **Any-type keys** — objects, functions, primitives. DOM nodes or class instances work as keys without key-coercion collisions:

```javascript
const user = { id: 1 };
const organizer = new Map();
organizer.set(user, 'admin');

// Structural similarity does not preserve object identity:
const duplicate = { id: 1 };
organizer.get(duplicate); // undefined — different reference
```

## 2. Set: Unique Value Collection

Same equality and ordering guarantees as `Map`, applied to membership: adding a present value is a no-op and `size` stays put.

```javascript
const unique = new Set([1, 2, 3, 2, 1]);
console.log(unique.size); // 3 — duplicates ignored
console.log([...unique]); // [1, 2, 3] — insertion order preserved
```

## 3. WeakMap: Metadata Without Owning the Key

- **Eligible keys** — objects and non-registered symbols work; registered `Symbol.for` values and other primitives cannot be keys. Check older runtime compatibility for symbol support.
- **Weak references** — the map alone does not keep a key alive. When no external strong path retains it, collection becomes possible; timing is not promised.
- **No iteration surface** — no `size`, `clear`, or enumeration. This is the enforcement mechanism for the private-data pattern:

```javascript
const privateData = new WeakMap();

const element = document.createElement('div');
privateData.set(element, { initialized: true });

// When element is removed from DOM and has no other refs:
// The key and its metadata may become collectible; no deadline is observable.
```

## 4. WeakSet: Object Membership Testing

Objects and non-registered symbols, weakly held, with no `size` or iteration — the membership-test counterpart: "is this element currently animating?" without retaining it:

```javascript
const animatingObjects = new WeakSet();

function animateIfTracked(element) {
  if (animatingObjects.has(element)) {
    element.animate([{ opacity: 0 }, { opacity: 1 }], { duration: 200 });
  }
}

// When element is no longer needed and strong refs dropped:
// Its weak membership does not keep it alive; collection timing is unspecified.
```

## 5. Choosing Between Them

| Scenario | Recommended Collection |
| :-------------------------------------- | :------------------------ |
| Caching function results by ID | `Map` |
| Tracking unique strings/primitives | `Set` |
| Attaching private config to DOM nodes | `WeakMap` |
| Set of elements being observed/animated | `WeakSet` |
| Object keys that must persist | `Map` (strong) |
| Object keys for temporary tracking | `WeakMap` (weak) |

Compared head-to-head: `Map`/`Set` accept any value, expose `size`/`clear`/iteration, and retain entries strongly. `WeakMap`/`WeakSet` accept objects and non-registered symbols, expose no iteration, and do not independently retain their keys/members. **Rule**: default to `Map`/`Set` for data storage; reach for weak variants when associating data with objects you must not keep alive.

A WeakMap uses conditional (ephemeron) reachability: a value pointing back to its own key does not by itself keep that key alive through this entry. A separate global reference to the value can still retain the key. Weak collections are not an eviction policy for externally live keys.

For conversion, Map entries are explicit iterable pairs; `JSON.stringify(new Map(...))` does not serialize those entries. Choose a wire schema deliberately. Use the [canonical bounded LRU wrapper](../05-functional-patterns/10.1.5.02-memoization.md) when enumeration and deterministic capacity are required.

## Summary

- **`Map`**: any-type keys, strong references, insertion order — general keyed storage.
- **`Set`**: unique values under the same guarantees — deduplication and membership.
- **`WeakMap`**: eligible weak keys, no enumeration — metadata that need not own a key.
- **`WeakSet`**: eligible weak members, no enumeration — non-owning membership tracking.

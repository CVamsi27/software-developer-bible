# Map, Set, WeakMap, WeakSet

## Definition

`Map` stores key–value pairs; `Set` stores unique values. `WeakMap` and `WeakSet` track eligible keys or members without keeping them alive solely because they are in the collection. Use the strong collections when you need to enumerate entries, count them, or control their lifetime explicitly. Use weak collections for metadata whose lifetime should follow an object.

> **Textbook Definition:** A `Map` is an insertion-ordered collection of unique key–value pairs, and a `Set` is an insertion-ordered collection of unique values; both use SameValueZero equality. A `WeakMap` associates values with weakly held object or eligible symbol keys, while a `WeakSet` weakly holds eligible objects or symbols. Weak collections expose no enumeration or size because garbage-collection timing is nondeterministic.

## First Principles

An ordinary object is a record: its property keys are strings or symbols. When another value is used as a property key, JavaScript converts it. Two different objects can therefore collide after conversion:

```js
const record = {};
const first = { id: 1 };
const second = { id: 2 };

record[first] = 'first';
record[second] = 'second';
console.log(record[first]); // 'second' — both keys became "[object Object]"
```

`Map` preserves the keys themselves, so object identity remains meaningful. `Set` provides the same direct membership test without a value. Weak collections add a different lifetime rule: membership alone does not keep an eligible key alive. These are separate choices—key behavior, enumeration, and ownership—not a ranking of collection types.

## Choose by key and lifetime

| Collection | Stores | Keys/members | Iterable and countable? | Typical use |
| ---------- | ----------- | ----------------------------------- | ----------------------- | -------------------------------------------------- |
| `Map` | key → value | Any value; object keys use identity | Yes; `.size` | Dynamic lookup table, cache with explicit eviction |
| `Set` | values | Any value; objects use identity | Yes; `.size` | Deduplication, visited values, membership |
| `WeakMap` | key → value | Objects and eligible symbols | No | Per-object metadata or memoized data |
| `WeakSet` | values | Objects and eligible symbols | No | Marking objects as visited or currently handled |

The standard permits object and eligible symbol keys in weak collections. Global-registry symbols such as `Symbol.for('shared')` are not eligible; check the runtime versions you support if weak symbol keys matter. A weak collection is not an expiry mechanism: it cannot tell you when an entry disappears or run cleanup at a predictable time.

## Equality and order

`Map` keys and `Set` members use **SameValueZero**. `NaN` matches itself, positive and negative zero are equivalent, and objects match only when they are the same object:

```js
const a = { id: 1 };
const b = { id: 1 };
const keys = new Map([[a, 'stored']]);

console.log(keys.get(a)); // 'stored'
console.log(keys.get(b)); // undefined: same shape, different identity
console.log(new Set([NaN, NaN, 0, -0]).size); // 2
```

Iteration follows insertion order. Setting an existing key changes its value without moving it; deleting and setting it again moves it to the end. This small contract supports patterns such as an LRU cache, but it does not make every Map a cache—capacity and eviction still belong to the application.

## Attach metadata without retaining the subject

A `WeakMap` is useful when a module needs metadata associated with objects it does not own. Keep the WeakMap private to the module when that metadata is an implementation detail:

```js
const measurements = new WeakMap();

export function measure(element) {
  let result = measurements.get(element);
  if (result === undefined) {
    result = calculateMeasurement(element);
    measurements.set(element, result);
  }
  return result;
}
```

If the element becomes unreachable elsewhere, the WeakMap entry does not keep it alive. If the element remains reachable, its cached value remains reachable too; large values attached to long-lived keys still need an invalidation or size policy. Removing a DOM node is not enough if application code still holds a reference to it.

A WeakMap is not a pool or an enumerable cache. A pool must strongly retain reusable objects in bounded storage. A cache that needs size, expiry, inspection, or deterministic eviction should use a `Map` plus an explicit policy. For example, an LRU cache can treat insertion order as recency by deleting and reinserting on every successful read; it must also validate capacity and define whether a stored `undefined` differs from a miss.

```typescript
class LruCache<K, V> {
  private entries = new Map<K, V>();

  constructor(private readonly capacity: number) {
    if (!Number.isInteger(capacity) || capacity < 1) {
      throw new RangeError('capacity must be a positive integer');
    }
  }

  get(key: K): { found: false } | { found: true; value: V } {
    if (!this.entries.has(key)) return { found: false };
    const value = this.entries.get(key)!;
    this.entries.delete(key);
    this.entries.set(key, value); // Move this key to most-recently-used position.
    return { found: true, value };
  }

  set(key: K, value: V): void {
    if (this.entries.has(key)) {
      this.entries.delete(key);
    } else if (this.entries.size === this.capacity) {
      this.entries.delete(this.entries.keys().next().value!); // Oldest key.
    }
    this.entries.set(key, value);
  }
}
```

This bounds the number of entries, not their total size. Expiration, byte limits, and persistence need separate policies.

## Convert only at a boundary

Use objects for fixed records and JSON-shaped configuration. Use Maps when arbitrary keys or collection operations are part of the data model. Converting a Map to an object can change meaning: object keys are coerced to property keys, numeric `1` and string `'1'` collide, and JSON does not serialize Map entries by default.

```js
const map = new Map([[1, 'number'], ['1', 'string']]);
const object = Object.fromEntries(map);

console.log(map.size); // 2
console.log(object);   // { '1': 'string' } — conversion collapsed the keys
```

For a JSON API, define an explicit representation such as an array of entry pairs and validate it on input. Do not assume that `JSON.stringify(new Map(...))` preserves its contents.

## Complexity and implementation boundary

The ECMAScript specification requires average sublinear access for Map and Set; it does not promise a particular hash-table layout or guarantee worst-case constant time. Engines choose their own representation. Treat collection choice as a semantic decision first, then benchmark the workload that matters.

## Summary

Choose `Map` for enumerable key–value data, `Set` for enumerable membership, and weak collections when membership should not retain eligible subjects. Object identity and SameValueZero determine matches. Conversion can change keys, while weak collections cannot provide enumeration, expiry, or deterministic cleanup.

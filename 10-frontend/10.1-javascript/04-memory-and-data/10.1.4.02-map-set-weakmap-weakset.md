# Map, Set, WeakMap, and WeakSet

JavaScript's built-in collection types provide keyed data structures with distinct semantics for value equality, reference identity, and garbage collection. Understanding when to use each type is essential for writing predictable, memory-efficient code.

## Definition

| Collection | Key Type | Value Uniqueness | Iteration Order | Garbage Collection |
| :------------------------ | :------------------------ | :------------------------ | :------------------------ | :------------------------ |
| **`Map`** | Any value (including objects) | Unique keys | Insertion order | Strong references; keys and values retained |
| **`Set`** | Any value (including objects) | Unique values | Insertion order | Strong references; items retained |
| **`WeakMap`** | Objects only (no primitives) | Unique keys | Insertion order | **Weak** references; keys GC'd when no strong refs exist |
| **`WeakSet`** | Objects only (no primitives) | Unique values | Insertion order | **Weak** references; items GC'd when no strong refs exist |

> **Textbook Definition:** `Map` and `Set` are collections that track insertion order and allow any value as a key (Map) or value (Set) using the SameValueZero equality algorithm. `WeakMap` and `WeakSet` are collections where keys are weakly referenced, allowing garbage collection when no strong references exist, making them ideal for private data attachment without memory leaks.

## First Principles

### Map: Keyed Collections with Any-Keys

1. **SameValueZero Equality:** Map uses the SameValueZero algorithm for key equality—`NaN` keys are equal to each other, and `+0` and `-0` are treated as identical. This differs from the `==` and `===` operators in subtle ways.

2. **Insertion Order Iteration:** The iteration order of a Map is the order in which keys were inserted. This is guaranteed even after deletion and re-insertion.

3. **Any-Type Keys:** Unlike plain objects, Map keys can be objects, functions, or any primitive. This enables using DOM nodes, class instances, or other objects as lookup keys without risking name collisions.

```javascript
const user = { id: 1 };
const organizer = new Map();
organizer.set(user, 'admin');

// Object key lookup works even with identical structure:
const duplicate = { id: 1 };
organizer.get(duplicate); // undefined — different reference
```

### Set: Unique Value Collection

1. **SameValueZero Equality:** Set uses the SameValueZero algorithm for value equality, matching Map's behavior with `NaN` and `+0`/`−0` handling.

2. **Duplicate Prevention:** Adding a value already present in the Set is a no-op; the Set size does not increase.

3. **Insertion Order:** Iteration order follows insertion order, preserved even after removing and re-adding elements.

```javascript
const unique = new Set([1, 2, 3, 2, 1]);
console.log(unique.size); // 2 — duplicates ignored
console.log([...unique]); // [1, 2] — insertion order preserved
```

### WeakMap: Private Data without Memory Leaks

1. **Object-Only Keys:** WeakMap keys must be objects. Primitives cause a TypeError.

2. **Weak References:** Keys are weakly referenced. If the only strong reference to a WeakMap key is removed, the key-value pair is automatically GC'd, even if the WeakMap itself still exists.

3. **No Iteration:** WeakMap does not support `size`, `clear`, iteration, or any method that exposes its contents. This enforces the private-data pattern.

4. **Typical Use Case:** Attaching private metadata to objects without preventing garbage collection.

```javascript
const privateData = new WeakMap();

const element = document.createElement('div');
privateData.set(element, { initialized: true });

// When element is removed from DOM and has no other refs:
// { initialized: pair is GC'd automatically — no memory leak!
```

### WeakSet: Object Membership Testing

1. **Object-Only Members:** WeakSet contains only object references.

2. **Weak References:** Members are weakly referenced. If all strong references to a WeakSet member are removed, the member is automatically GC'd.

3. **No Size or Iteration:** Like WeakMap, WeakSet does not expose `size`, `clear`, or iteration.

4. **Typical Use Case:** Tracking object membership (e.g., "is this element currently being animated?") without memory leaks.

```javascript
const animatingObjects = new WeakSet();

function animateIfVisible(element) {
  if (animatingObjects.has(element)) {
    element.animate([...]);
  }
}

// When element is no longer needed and strong refs dropped:
// It's automatically removed from animatingObjects — no leak
```

## Memory Comparison: Map/Set vs. WeakMap/WeakSet

| Aspect | Map / Set | WeakMap / WeakSet |
| :------------------------ | :------------------------ | :------------------------ |
| **Key/Value Type** | Any value (primitives + objects) | Objects only |
| **Reference Strength** | Strong — items retained indefinitely | Weak — GC'd when no strong refs exist |
| **`size` Property** | Yes | No (throws error) |
| **`clear()` Method** | Yes | No (does not exist) |
| **Iteration (`forEach`, spread)** | Supported | Not supported |
| **Primary Use Case** | General-purpose keyed data | Private attachment / memory-safe tracking |
| **GC Behavior** | Prevents GC of keys/values | Allows GC of keys/values when unreachable |

## When to Use Which

| Scenario | Recommended Collection |
| :------------------------ | :------------------------ |
| Caching function results by ID | `Map` |
| Tracking unique strings/primitives | `Set` |
| Attaching private config to DOM nodes | `WeakMap` |
| Set of elements being observed/animated | `WeakSet` |
| Object keys that must persist | `Map` (strong) |
| Object keys for temporary tracking | `WeakMap` (weak) |

## Summary

- **`Map`**: General-purpose keyed collection; any key type; strong references; preserves insertion order.
- **`Set`**: Unique value collection; any value type; strong references; preserves insertion order.
- **`WeakMap`**: Private metadata attachment to objects; keys GC'd when unreachable; no iteration/exposure.
- **`WeakSet`**: Object membership tracking; members GC'd when unreachable; no iteration/exposure.

Choose Map/Set for general data storage. Choose WeakMap/WeakSet when you need to associate data with objects without preventing garbage collection.

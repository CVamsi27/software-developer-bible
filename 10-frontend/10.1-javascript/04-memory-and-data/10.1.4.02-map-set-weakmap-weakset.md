# Map, Set, WeakMap, WeakSet

Using a plain JavaScript object `{}` as a cache keyed by DOM elements or composite objects silently converts every key into the string `"[object Object]"`, collapsing distinct entries into a single overwritten slot. JavaScript provides four specialized keyed collections designed for distinct identity, iteration, and memory lifecycle requirements.

## Definition

`Map`, `Set`, `WeakMap`, and `WeakSet` are ECMAScript standard keyed collections. `Map` and `Set` provide insertion-ordered, enumerable storage for arbitrary keys and unique values. `WeakMap` and `WeakSet` maintain non-enumerable, weak references to object keys, permitting unreferenced objects to be reclaimed by the garbage collector without manual collection pruning.

> **Textbook Definition:** `Map` and `Set` are enumerable keyed collections governed by SameValueZero equality, guaranteeing deterministic insertion-order iteration and sublinear lookup complexity. `WeakMap` and `WeakSet` are ephemeron-based collections that hold weak references to object or non-registered symbol keys, exposing neither size nor iteration to prevent user-space observation of nondeterministic garbage collector sweeps.

## First Principles

1. **Key Coercion Decoupling:** Plain JavaScript objects strictly require string or Symbol keys, coercing all other types via `ToString()`. `Map` and `Set` preserve original object references and primitive types without coercion.
2. **SameValueZero Equality:** Key identity in `Map` and `Set` is evaluated using `SameValueZero`. Unlike `===`, `NaN` matches `NaN`. Unlike `Object.is()`, `+0` and `-0` are treated as identical keys.
3. **Ephemeron Reachability:** In `WeakMap`, an entry's value remains reachable only as long as its corresponding key object remains reachable through external strong references. The collection itself does not prevent key reclamation.
4. **Nondeterministic GC Invariance:** Because garbage collection timing is an implementation-dependent engine behavior, weak collections intentionally omit `.size`, `.keys()`, and iteration methods to prevent application logic from depending on GC cycles.

```text
Strong Collections (Map / Set):
Collection Root ──(Strong Reference)──▶ Key Object ──▶ Value Object
(Key object cannot be garbage collected while collection is alive)

Weak Collections (WeakMap / WeakSet - Ephemeron Table):
Collection Root ──(Weak Table Handle)
                                     │
External Pointer ──(Strong Ref)──▶ Key Object ──(Ephemeron)──▶ Value Object
(If External Pointer drops, Key Object and Value are reclaimed together)
```

## Architectural Matrix of Keyed Collections

Selecting the appropriate collection depends on key typing, iteration needs, and memory lifecycle ownership:

| Collection | Key Types Allowed | Value Types | Iterable? | Size Property | Memory Lifecycle | Primary Use Case |
| :------------ | :----------------------------- | :---------- | :-------------------------------------- | :------------ | :-------------------- | :-------------------------------------------- |
| **`Map`** | Any type (primitives, objects) | Any type | Yes (`keys()`, `values()`, `entries()`) | `.size` | Strong references | High-performance lookups, LRU caches |
| **`Set`** | Any type (primitives, objects) | Same as key | Yes (`values()`, `entries()`) | `.size` | Strong references | Value deduplication, fast membership tests |
| **`WeakMap`** | Objects and unique Symbols | Any type | No | None | Weak keys (Ephemeron) | Private state, DOM metadata associations |
| **`WeakSet`** | Objects and unique Symbols | Same as key | No | None | Weak members | Object tagging, circular graph visit tracking |

## Plain Object vs. Map: The Key Coercion Trap

Plain objects fail as general-purpose dictionary structures when keys are non-strings:

```javascript
const registry = {};
const btnSubmit = document.createElement('button');
const btnCancel = document.createElement('button');

// Plain object coercions:
registry[btnSubmit] = 'submit-action';
registry[btnCancel] = 'cancel-action';

// Both buttons stringified to "[object HTMLButtonElement]":
console.log(registry[btnSubmit]); // "cancel-action" (Overwritten!)
console.log(Object.keys(registry)); // ["[object HTMLButtonElement]"]

// Map preserves object identity:
const buttonMap = new Map();
buttonMap.set(btnSubmit, 'submit-action');
buttonMap.set(btnCancel, 'cancel-action');

console.log(buttonMap.get(btnSubmit)); // "submit-action" (Preserved)
console.log(buttonMap.size);            // 2
```

Furthermore, plain objects coerce numeric keys to strings:
```javascript
const map = new Map();
map.set(1, 'number-one');
map.set('1', 'string-one');
console.log(map.size); // 2 (Distinct types preserved)

const obj = {};
obj[1] = 'number-one';
obj['1'] = 'string-one';
console.log(Object.keys(obj).length); // 1 (Coerced to string "1")
```

## Equality Semantics: SameValueZero

`Map` keys and `Set` elements are compared using the ECMAScript `SameValueZero` specification algorithm:

```javascript
const testSet = new Set();

// 1. NaN equals NaN (differs from === where NaN !== NaN)
testSet.add(NaN);
testSet.add(NaN);
console.log(testSet.size); // 1

// 2. +0 and -0 are treated as identical (differs from Object.is)
testSet.add(+0);
testSet.add(-0);
console.log(testSet.size); // 2 (Holds NaN and 0)

// 3. Object identity: distinct references never collide
testSet.add({ id: 1 });
testSet.add({ id: 1 });
console.log(testSet.size); // 4 (Structural duplicates are distinct objects)
```

## WeakMap Ephemerons and Memory Leak Prevention

When associating metadata with objects whose lifecycle is managed externally (such as DOM nodes, third-party library handles, or request contexts), storing them in a `Map` creates a memory leak because the Map retains a strong reference to the key.

A `WeakMap` holds its keys weakly via ephemeron pairs:

```javascript
// Metadata association without memory leaks
const elementMetadata = new WeakMap();

export function trackElementClick(domElement, metadata) {
  elementMetadata.set(domElement, metadata);
}

export function getElementMetadata(domElement) {
  return elementMetadata.get(domElement);
}

// When domElement is removed from the DOM and all application variables drop it:
// The WeakMap entry is automatically reclaimed during subsequent GC cycles.
```

### Eligible Keys in Weak Collections

The ECMAScript specification restricts WeakMap and WeakSet keys to:
- Non-null Objects (`typeof key === 'object'` or functions).
- Non-registered Symbols (symbols created via `Symbol('desc')`).
- **Forbidden:** Primitives (numbers, strings, booleans) and global registry symbols (`Symbol.for('key')`) are disallowed because they are permanently interned or cannot be garbage collected.

## Production Pattern: LRU Cache via Map Insertion Order

The ECMAScript specification guarantees that `Map` iterates keys strictly in **insertion order**. When a key is deleted and re-inserted, it moves to the end of the iteration sequence. This enables an $O(1)$ Least Recently Used (LRU) cache:

```typescript
export class LruCache<K, V> {
  private readonly entries = new Map<K, V>();

  constructor(private readonly capacity: number) {
    if (!Number.isInteger(capacity) || capacity < 1) {
      throw new RangeError('Capacity must be a positive integer >= 1');
    }
  }

  get(key: K): V | undefined {
    if (!this.entries.has(key)) return undefined;

    const value = this.entries.get(key)!;
    // Refresh recency: delete and re-insert at end of Map
    this.entries.delete(key);
    this.entries.set(key, value);
    return value;
  }

  set(key: K, value: V): void {
    if (this.entries.has(key)) {
      this.entries.delete(key);
    } else if (this.entries.size >= this.capacity) {
      // Evict oldest entry (the first key in iteration order)
      const oldestKey = this.entries.keys().next().value;
      if (oldestKey !== undefined) {
        this.entries.delete(oldestKey);
      }
    }
    this.entries.set(key, value);
  }

  get size(): number {
    return this.entries.size;
  }
}
```

## Modern Set Methods (ES2024 / ES2025 Standard)

Modern JavaScript standardizes native mathematical set operations:

```javascript
const admins = new Set(['alice', 'bob', 'charlie']);
const editors = new Set(['bob', 'david']);

// 1. Union: Elements present in either set
const allStaff = admins.union(editors);
// Set(4) { 'alice', 'bob', 'charlie', 'david' }

// 2. Intersection: Elements present in both sets
const adminEditors = admins.intersection(editors);
// Set(1) { 'bob' }

// 3. Difference: Elements in admins but not in editors
const pureAdmins = admins.difference(editors);
// Set(2) { 'alice', 'charlie' }

// 4. Symmetric Difference: Elements in one set but not both
const exclusiveRoles = admins.symmetricDifference(editors);
// Set(3) { 'alice', 'charlie', 'david' }

// 5. Predicates:
console.log(adminEditors.isSubsetOf(admins));     // true
console.log(admins.isSupersetOf(adminEditors));   // true
console.log(pureAdmins.isDisjointFrom(editors));  // true
```

## Summary

`Map` and `Set` provide enumerable, insertion-ordered storage that respects arbitrary types and object identity under SameValueZero equality. `WeakMap` and `WeakSet` provide non-enumerable ephemeron associations whose entries disappear automatically when key objects become unreachable. Plain objects should be reserved for fixed records and JSON data, while `Map` and `WeakMap` should be selected whenever dynamic keys, object identity, or lifecycle-bound metadata are required.

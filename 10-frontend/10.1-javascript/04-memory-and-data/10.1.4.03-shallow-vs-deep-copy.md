# Shallow Copy vs Deep Copy

## Definition

A **shallow copy** creates a new outer object but reuses the references stored in it. A **deep copy** creates a separate version of a supported object graph. “Deep” describes the relationships the copy preserves, not a promise that every JavaScript value or behavior can be duplicated.

> **Textbook Definition:** A shallow copy duplicates one container level, leaving referenced child objects shared. A deep copy traverses a supported object graph to create corresponding nodes, while preserving cycles and aliases within the copied graph when the cloning algorithm supports them.

## First Principles

Objects are graphs: a property may point to another object, and multiple properties may point to the same child. Copying therefore requires an ownership decision: which identities should be new, which may remain shared, and which values the chosen operation can represent. The right copy is the smallest one that makes the intended mutation safe.

## Follow the reference

Suppose two screens display a user profile and one screen changes a nested preference. A shallow copy separates only the profile object; its `preferences` object is still shared:

```js
const original = {
  name: 'Sam',
  preferences: { theme: 'light' },
};

const shallow = { ...original };
shallow.name = 'Rae';
shallow.preferences.theme = 'dark';

console.log(original.name);                 // 'Sam'
console.log(original.preferences.theme);    // 'dark' — nested object was shared
```

The same rule applies to array spread, `slice()`, `Array.from()`, and `Object.assign()`: they make a new outer container, not a recursive copy. Shallow copies are useful when shared children are treated as immutable. If a nested value changes, copy each container along the path to that value and keep unrelated branches shared.

## Choose a clone contract

For supported values, `structuredClone()` copies a graph, preserving cycles and repeated references within the clone:

```js
const shared = { enabled: true };
const original = { first: shared, second: shared };
original.self = original;

const clone = structuredClone(original);

console.log(clone !== original);                    // true
console.log(clone.first === clone.second);           // true: alias preserved
console.log(clone.self === clone);                   // true: cycle preserved
console.log(clone.first !== original.first);         // true: graph separated
```

`structuredClone()` supports common data such as arrays, plain data objects, `BigInt`, `Date`, `Map`, `Set`, typed data, and cycles. It does not preserve arbitrary prototypes, methods, private fields, property descriptors, or symbol-keyed properties. Function and symbol values are not cloneable; weak collections and many host objects also fail. Test the exact types used by the application.

Two buffer cases change the ownership story. A `SharedArrayBuffer` clone gives another wrapper over the same shared memory. Passing an `ArrayBuffer` in a transfer list moves its backing memory and detaches the original. A clone is not always an isolated snapshot.

## JSON is a serialization format

`JSON.parse(JSON.stringify(value))` is appropriate only when JSON’s value model is the intended contract. It transforms data while serializing:

```js
const source = {
  created: new Date('2025-01-01T00:00:00.000Z'),
  missing: undefined,
  score: NaN,
};

const copy = JSON.parse(JSON.stringify(source));
console.log(copy); // { created: '2025-01-01T00:00:00.000Z', score: null }
```

Object properties whose values are `undefined`, functions, or symbols are omitted; array slots with those values become `null`. Dates normally serialize as strings, `NaN` and infinities become `null`, and `Map`/`Set` do not retain their entries by default. Cycles and unhandled `BigInt` values throw. This can be a valid wire-format conversion, but it is not a general-purpose clone.

## Copying objects can run code

Object spread and `Object.assign()` copy enumerable own string and symbol properties. They read source properties, so getters can run. `structuredClone()` also reads enumerable own properties of ordinary objects, so a getter can run during cloning. The target behavior of the shallow operations differs: spread defines data properties on a fresh object; `Object.assign()` writes to the target and may invoke a setter. None preserves ordinary property descriptors or makes shallow operations recursive. Treat copying untrusted objects as an operation that may execute user-defined accessors.

## Prefer path copying for immutable updates

For application state, copying the changed path usually gives a clearer contract than cloning the entire state tree:

```js
function changeTheme(state, theme) {
  return {
    ...state,
    user: {
      ...state.user,
      preferences: {
        ...state.user.preferences,
        theme,
      },
    },
  };
}
```

The result has new identities along the edited path while unchanged branches remain shared. This is efficient when consumers treat state as immutable; mutating a shared child breaks that assumption. Libraries such as Immer can express these updates with mutation-like syntax while producing immutable results, but they do not make arbitrary external objects safe to clone.

Copying and freezing solve different problems. `Object.freeze()` is shallow, and a copy remains mutable unless it is separately protected. For caches and undo history, define cloneability, capacity, expiration, and behavior on clone failure; deep copies can retain large graphs and allocate substantial memory.

## Cost and decision rule

A shallow copy costs work proportional to the entries it copies. A deep clone must visit the supported graph and copy relevant byte data; it can consume memory proportional to that graph. If unchanged branches can safely be shared, path copying is usually cheaper. Measure before optimizing, and avoid cloning merely to make an API appear immutable.

## Summary

Shallow copies create a new outer object and share nested references. Deep cloning creates a separate supported graph under a specific API’s rules. Use JSON only for a JSON contract, `structuredClone()` for supported data graphs, and path copying when immutable updates need to replace only changed branches. Document transfer, shared-memory, mutation, failure, and retention behavior at the boundary.

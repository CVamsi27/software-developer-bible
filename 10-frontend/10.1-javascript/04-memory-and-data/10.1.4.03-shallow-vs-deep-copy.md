# Shallow Copy vs Deep Copy

After using the spread operator to duplicate a user profile and updating `profileCopy.preferences.theme = 'dark'`, the original user's screen theme mutates simultaneously. While the outer container was duplicated, all nested object properties remained pointing to identical heap addresses. Choosing between shallow copies, structured deep clones, and immutable structural sharing is a foundational architectural decision.

## Definition

A **shallow copy** duplicates an object's root-level properties into a new container while copying references to any nested composite structures. A **deep copy** recursively traverses an object graph, creating newly allocated clones for every descendant node while preserving internal graph relationships and circular references.

> **Textbook Definition:** A shallow copy creates a new top-level object instance populated with the primitive values and reference pointers of the source, leaving nested heap structures shared across both instances. A deep copy recursively duplicates every reachable node in a supported object graph, isolating mutations within the new graph while preserving internal aliasing and cycle topologies.

## First Principles

1. **Object Graph Representation:** In JavaScript memory, nested objects are directed graphs where properties hold pointer references to independent heap allocations.
2. **Single-Level Duplication:** Operations like `{ ...obj }`, `Object.assign()`, and `arr.slice()` allocate exactly one new memory container at the root level ($O(1)$ depth). All internal pointer values are copied verbatim.
3. **Graph Topology Preservation:** A true deep-cloning algorithm must record visited nodes (typically via an internal WeakMap or identity table) to avoid infinite recursion on circular structures and preserve shared references within the copied graph.
4. **Serialization Lossiness:** JSON serialization (`JSON.stringify`) converts data into a textual transport representation rather than cloning an engine memory graph, discarding prototypes, functions, undefined values, and special numeric formats.

```text
Source Object Graph:
[ User Profile (0x100) ]
  ├── name: "Alice" (Primitive Smi/String)
  └── preferences ──────────▶ [ Prefs Object (0x200) ]
                                └── theme: "light"

Shallow Copy ({ ...user }):
[ Shallow Copy (0x300) ] (New outer container)
  ├── name: "Alice" (Copied value)
  └── preferences ──────────▶ [ Prefs Object (0x200) ] (SHARED REFERENCE!)

Deep Copy (structuredClone):
[ Deep Clone   (0x400) ] (New outer container)
  ├── name: "Alice" (Copied value)
  └── preferences ──────────▶ [ Cloned Prefs (0x500) ] (ISOLATED ALLOCATION!)
                                └── theme: "light"
```

## Shallow Copy Techniques and Their Traps

Common shallow copying mechanisms include object spread (`{ ...obj }`), `Object.assign()`, `Array.prototype.slice()`, and `Array.from()`.

```javascript
const source = {
  id: 101,
  metadata: { version: 1 },
  get timestamp() { return Date.now(); }
};

// 1. Object spread creates a shallow copy:
const spreadCopy = { ...source };

// 2. Object.assign creates a shallow copy into target:
const assignCopy = Object.assign({}, source);

// Trap A: Nested mutations leak to source:
spreadCopy.metadata.version = 2;
console.log(source.metadata.version); // 2 (Mutated!)

// Trap B: Getters are executed and flattened into static data properties:
console.log(spreadCopy.timestamp); // 1713000000000 (Static number, no longer a getter)

// Trap C: Prototype chains are NOT copied:
class CustomEntity {}
const entity = new CustomEntity();
const entityClone = { ...entity };
console.log(entityClone instanceof CustomEntity); // false (Inherits from Object.prototype)
```

### Spread vs. `Object.assign` Under the Hood

| Mechanism | Internal Operation | Target Side Effects | Handles Symbols? |
| :---------------------------------- | :---------------------- | :-------------------------------------------------- | :--------------------------- |
| **Object Spread (`{ ...source }`)** | `[[DefineOwnProperty]]` | Creates fresh own properties; never invokes setters | Yes (enumerable own symbols) |
| **`Object.assign(target, source)`** | `[[Set]]` | Invokes existing setters on the target object | Yes (enumerable own symbols) |

## The Modern Deep Clone Standard: `structuredClone()`

JavaScript provides native, platform-standard deep cloning via `structuredClone()` (standardized in HTML and ECMAScript runtimes):

```javascript
const sharedNode = { active: true };
const graph = {
  title: 'Network Graph',
  primary: sharedNode,
  secondary: sharedNode,
  created: new Date(),
  flags: new Set(['alpha', 'beta']),
  cache: new Map([['k1', new Uint8Array([1, 2, 3])]]),
};
graph.self = graph; // Circular reference!

const cloned = structuredClone(graph);

// 1. Deep isolation:
console.log(cloned.created !== graph.created); // true
console.log(cloned.cache.get('k1') !== graph.cache.get('k1')); // true

// 2. Internal aliasing preserved:
console.log(cloned.primary === cloned.secondary); // true

// 3. Circular references handled without stack overflow:
console.log(cloned.self === cloned); // true
```

### Limitations of `structuredClone()`

`structuredClone()` throws a `DataCloneError` DOMException or drops properties when encountering unsupported types:

| Supported by `structuredClone()` | Throws `DataCloneError` / Unsupported |
| :-------------------------------------- | :---------------------------------------------------------- |
| Primitives, `BigInt`, `Date`, `RegExp` | **Functions and Methods** |
| `Array`, plain `Object`, `Map`, `Set` | **DOM Nodes** (`HTMLElement`) |
| `ArrayBuffer`, `TypedArray`, `DataView` | **Symbols** (as keys or values) |
| `Error` objects (`TypeError`, etc.) | **WeakMap** and **WeakSet** |
| Circular references | **Property Descriptors** (getters, setters, non-enumerable) |

## The `JSON.parse(JSON.stringify(obj))` Pitfall Matrix

Using JSON serialization as a deep-clone mechanism is an anti-pattern in production systems due to silent data corruption:

```javascript
const complexPayload = {
  date: new Date('2025-01-01T00:00:00.000Z'),
  fn: () => console.log('hello'),
  undef: undefined,
  notANumber: NaN,
  infinity: Infinity,
  symbolKey: Symbol('id'),
  map: new Map([['key', 'val']]),
  big: 100n, // Throws TypeError!
};

// JSON cloning drops and mutates types silently:
const jsonClone = JSON.parse(JSON.stringify({
  date: complexPayload.date,
  fn: complexPayload.fn,
  undef: complexPayload.undef,
  notANumber: complexPayload.notANumber,
  map: complexPayload.map,
}));

console.log(jsonClone);
// {
//   date: "2025-01-01T00:00:00.000Z",  <-- Converted to String!
//   notANumber: null,                  <-- NaN converted to null!
//   map: {},                           <-- Map converted to empty object!
//   (fn and undef are completely omitted!)
// }
```

> [!WARNING]
> Never use `JSON.parse(JSON.stringify())` for objects containing `Date`, `BigInt`, `Map`, `Set`, `NaN`, `undefined`, functions, or circular references. Use `structuredClone()` instead.

## Production Pattern: Structural Sharing for Immutable State

In modern UI architectures (React, Redux, Zustand), deep-cloning large state trees on every user action incurs severe $O(N)$ CPU and memory overhead and breaks memoization checks (`prevProps === nextProps`).

Senior engineers employ **structural sharing**, duplicating only the ancestors along the path of mutation while preserving shared references for all untouched sibling branches:

```javascript
const initialAppState = {
  user: {
    id: 101,
    preferences: { theme: 'light', fontSize: 14 },
    profile: { bio: 'Engineer', avatarUrl: 'https://cdn.example.com/pic.png' }
  },
  catalog: {
    items: [/* 10,000 product objects */],
    lastFetched: 1713000000
  }
};

// Structural Sharing: Only path [state -> user -> preferences] is duplicated:
function updateTheme(state, newTheme) {
  return {
    ...state, // Level 1 duplicated
    user: {
      ...state.user, // Level 2 duplicated
      preferences: {
        ...state.user.preferences, // Level 3 duplicated
        theme: newTheme // Leaf value updated
      }
    }
  };
}

const updatedState = updateTheme(initialAppState, 'dark');

// 1. Path of mutation has new references:
console.log(initialAppState.user.preferences !== updatedState.user.preferences); // true

// 2. Untouched branches retain identical references (O(1) memory & React.memo safe):
console.log(initialAppState.catalog === updatedState.catalog); // true (ZERO re-allocation!)
console.log(initialAppState.user.profile === updatedState.user.profile); // true
```

## Summary

Shallow copying duplicates an object's root-level properties while retaining shared references to nested heap objects. Native `structuredClone()` provides robust deep copying for standard data structures, preserving circular graphs and typed collections without data loss. JSON serialization is a lossy transport protocol that corrupts specialized types. For high-throughput state management, structural sharing provides optimal memory efficiency by copying only the ancestors of mutated nodes.

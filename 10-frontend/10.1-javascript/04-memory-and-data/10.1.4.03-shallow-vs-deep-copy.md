# Shallow vs Deep Copy

A copied settings object still changes the original when its nested preferences are edited. The outer objects differ, but both properties refer to one child. Choose which identities must separate before choosing a copy API.

```javascript
const original = { a: 1, b: { c: 2 } };
const shallow = { ...original };
console.log(shallow.b === original.b); // true
shallow.b.c = 99;
console.log(original.b.c); // 99
```

## Definition

A **shallow copy** creates a new outer container while retaining nested object values. A **deep clone** separates a supported graph of objects while preserving relationships such as repeated references and cycles inside the new graph. The chosen API defines which types, properties and resources it supports.

> **Textbook Definition:** Shallow copying copies top-level values into a new container, retaining nested object identity. Deep cloning recursively constructs a supported object graph and maintains an original-to-copy identity mapping. It need not preserve arbitrary prototypes, descriptors, host resources or shared-memory isolation.

## First Principles

An object value denotes an identity. Copying a property value does not recursively copy the object it denotes. To separate a nested graph, a clone must visit supported children and record each copy before visiting its children: otherwise cycles recurse forever and two aliases can incorrectly become two different children. Copying is also a data contract, not a promise that any JavaScript value can become an independent duplicate.

## 1. Copy the Outer Container

Object spread and `Object.assign` copy own enumerable string and symbol property values. Reading a getter can execute code. Spread creates data properties; assigning into an existing target can invoke target setters. Neither preserves a custom source prototype or its property descriptors.

```javascript
const state = { nested: { count: 1 } };
const copy = Object.assign({}, state);
copy.nested.count = 2;
console.log(state.nested.count); // 2

const rows = [{ id: 1 }, { id: 2 }];
const sliced = rows.slice();
const concatenated = rows.concat();
console.log(sliced !== rows, sliced[0] === rows[0]); // true, true
console.log(concatenated[0] === rows[0]); // true
```

Array slice/concat create another array under their own species/sparse-array rules. The useful common boundary is retained nested values, not universal preservation of every top-level type.

## 2. Structured Clone Has a Supported-Type Contract

`structuredClone` is a **host API**, not an ES2022 language addition. It handles supported values such as plain data, Date, Map, Set, typed arrays and cycles. Functions, symbol values, DOM nodes and weak collections cannot simply be cloned; unsupported values can throw `DataCloneError`. Custom prototypes, private fields and descriptors are not generally preserved.

```javascript
const child = { count: 1 };
const graph = { left: child, right: child };
graph.self = graph;
const cloned = structuredClone(graph);
console.log(cloned !== graph); // true
console.log(cloned.left === cloned.right); // true: internal alias preserved
console.log(cloned.left !== child); // true: original child separated
console.log(cloned.self === cloned); // true: cycle preserved

try { structuredClone({ run() {} }); } catch (error) {
  console.log(error.name); // DataCloneError
}
```

A transferred ordinary ArrayBuffer moves usable ownership and detaches the sender's buffer. Cloning a SharedArrayBuffer instead creates another wrapper over **shared bytes**; that is not isolated memory. Browser availability of shared memory has additional isolation requirements.

```javascript
const bytes = new Uint8Array([10, 20, 30]);
const moved = structuredClone(bytes, { transfer: [bytes.buffer] });
console.log(bytes.byteLength, moved.byteLength); // 0, 3
```

## 3. JSON Round-Trips Are Serialization

JSON is appropriate when the wire schema is JSON, not as a universal clone. Dates normally serialize to strings; Map/Set/RegExp typically become empty objects without a custom encoding. Object properties holding undefined, functions or symbols are omitted, while corresponding array positions become null. NaN/infinities become null, and cycles or unhandled BigInts throw. A `toJSON` method or getter can run application code.

Choose a documented encoder/decoder for domain types. A successful JSON round-trip means the serialized representation survived; it does not mean the original JavaScript type or identity graph did.

## 4. A Restricted Recursive Copier

A custom copier is justified only when its supported domain is explicit. This teaching example accepts primitive data except symbols/functions, arrays, and same-realm plain/null-prototype objects. It copies **own enumerable string data properties**, rejects accessors/symbol keys and unsupported instances, and preserves aliases/cycles. It is not a replacement for structured cloning or a hostile-object sandbox; reflection on a Proxy can execute traps, and untrusted depth can overflow recursion.

```javascript
function clonePlainData(value, seen = new WeakMap()) {
  if (typeof value === 'function' || typeof value === 'symbol') {
    throw new TypeError('Unsupported function or symbol');
  }
  if (value === null || typeof value !== 'object') return value;
  if (seen.has(value)) return seen.get(value);

  const prototype = Object.getPrototypeOf(value);
  if (!Array.isArray(value) && prototype !== Object.prototype && prototype !== null) {
    throw new TypeError('Expected plain data or an array');
  }
  if (Object.getOwnPropertySymbols(value).length) throw new TypeError('Unsupported symbol key');
  const copy = Array.isArray(value) ? new Array(value.length) : Object.create(prototype);
  seen.set(value, copy);
  for (const key of Object.keys(value)) {
    const descriptor = Object.getOwnPropertyDescriptor(value, key);
    if (!descriptor || !('value' in descriptor)) throw new TypeError('Unsupported accessor');
    Object.defineProperty(copy, key, {
      value: clonePlainData(descriptor.value, seen),
      enumerable: true, writable: true, configurable: true,
    });
  }
  return copy;
}
```

Defining an own data property avoids accidentally invoking the inherited `__proto__` setter. Constructor-name tests cannot safely distinguish every supported type; this copier never invokes an input's constructor. Date/Map/Set or application classes need a different explicit contract.

## 5. Choose Isolation, Structural Sharing and Retention

| Requirement | Decision and boundary |
| -------------------------------------- | ------------------------------------------------------------------------------------------ |
| Change one field in immutable UI state | Copy only the changed path and retain unchanged branches |
| Snapshot supported mutable data | Structured clone, with clone failures handled before replacing current state |
| Cross a worker boundary | Let messaging clone/transfer a designed payload; a prior clone is usually unnecessary |
| Preserve behavior/private class state | Use a domain-specific constructor/serializer, not a generic deep clone |
| Hot path | Measure graph size, getter work, allocation and retained bytes; no API is uniformly faster |

```javascript
const previous = { user: { name: 'Alice' }, settings: { theme: 'dark' } };
const next = { ...previous, user: { ...previous.user, name: 'Bob' } };
console.log(previous.user.name, next.settings === previous.settings); // Alice, true
```

If a shallow copy retains a nested child, that child remains reachable. It does **not** necessarily retain the original outer container unless a child/back-reference leads back to it. Dropping the last reference only makes an object eligible for collection; it never promises a GC deadline. Deep cloning may increase total retained data, while SharedArrayBuffer and transferable resources require separate ownership rules.

## Summary

A shallow copy separates the outer container while sharing nested identities. A supported deep clone separates a graph and preserves its internal aliases/cycles under an API-specific type contract. Structured cloning rejects some values and does not universally preserve behavior or isolate shared bytes. Use path copying for immutable updates, explicit serialization for domain types, and measured retention rather than assuming every copy is safe or cheap.

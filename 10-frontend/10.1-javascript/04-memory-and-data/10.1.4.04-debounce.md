# Debounce

## Definition

**Debouncing** is a technique that delays the execution of a function until after a specified period of inactivity. Each time the function is called, the timer resets. The function only executes when there's a pause in calls.

> **Textbook Definition:** Debouncing coalesces a burst of invocations by using a quiet-time threshold to select when a callback runs. Leading execution, trailing execution and a maximum wait are policy choices layered on that timing rule.


## First Principles

Debounce is deducible from one observation about events:

1. **Some work only needs the latest value after an input burst.** For search, resize handling or autosave, a pause can be the signal to act. Reset a timer on every call, then run the work when the timer expires.
2. **Reducing repeated work adds delay.** The debounced operation waits N milliseconds after the latest call. A long wait feels slow; a short wait may run in the middle of a burst. Choose N for the interaction rather than expecting one universal value.
3. **Choose whether to act at the beginning or end.** A **leading** invocation runs when the burst starts. A **trailing** invocation runs after the quiet period. Both policies use the timer to track the burst; the examples below define their exact behavior.

If you can state "act after the pause," you can implement debounce from scratch — which is the interview point.


## Why It Matters

A timer belongs to each created debounced wrapper. Sharing that wrapper also shares its timer; creating a new wrapper for every event defeats debounce. In React, keep a wrapper stable for its intended lifetime and dispose its pending work when that lifetime ends. `useDebouncedValue` patterns in React are just `useEffect` + `setTimeout`. Common interview gotcha: using `setTimeout` directly in render — must be in `useEffect`.

## Code Examples

### One wrapper owns one burst

This teaching implementation exposes leading/trailing policy, cancellation and flushing in one place. `wait` is a nonnegative delay in milliseconds. It returns `void`: it schedules side effects and does not give each caller a promise for a result. Async callbacks must handle their own rejection.

```typescript
function debounce<T extends (...args: any[]) => any>(
  func: T,
  wait: number,
  { leading = false, trailing = true } = {}
): ((...args: Parameters<T>) => void) & { cancel: () => void; flush: () => void } {
  if (!Number.isFinite(wait) || wait < 0) throw new RangeError('Invalid wait');
  let timer: ReturnType<typeof setTimeout> | null = null;
  let args: Parameters<T> | null = null;
  let receiver: any;

  function invoke() {
    if (args === null) return;
    const savedArgs = args;
    const savedReceiver = receiver;
    args = null;
    receiver = undefined; // Clear before calling; callback may call the wrapper again.
    func.apply(savedReceiver, savedArgs);
  }

  const wrapped = function(this: any, ...nextArgs: Parameters<T>) {
    const atStart = timer === null;
    args = nextArgs;
    receiver = this;
    if (timer !== null) clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (trailing) invoke();
      else { args = null; receiver = undefined; }
    }, wait);
    if (atStart && leading) invoke();
  };

  wrapped.cancel = () => {
    if (timer !== null) clearTimeout(timer);
    timer = null;
    args = null;
    receiver = undefined;
  };
  wrapped.flush = () => {
    if (timer !== null) clearTimeout(timer);
    timer = null;
    if (trailing) invoke();
    else { args = null; receiver = undefined; }
  };
  return wrapped;
}

const search = debounce((query: string) => console.log(query), 300);
search('H');
search('He');
search('Hello'); // If these calls occur within one burst, only Hello is printed.
```

Suppose calls arrive at 0, 100 and 200ms. Trailing-only execution prints the last value at about 500ms: each call moves the quiet-time deadline. With `leading: true`, the 0ms call also runs immediately. With both edges enabled, a lone call runs only once; a second call during the burst supplies a pending trailing value. With both edges disabled, no callback runs. `cancel` drops that pending value; `flush` runs it early and ends the burst. Neither stops a callback or request that has already started.

A timeout becomes eligible after the delay; other work or a background tab can postpone it. Continuous input can postpone the trailing call forever. A **maximum wait** places an additional deadline measured from the start of the burst; this small implementation omits it. Use a tested library when that policy or return-value caching is required.

### React Hook

```typescript
import { useEffect, useMemo, useRef } from 'react';

function useDebounce<T extends (...args: any[]) => any>(func: T, wait: number) {
  const latest = useRef(func);
  useEffect(() => { latest.current = func; }, [func]);
  const wrapped = useMemo(
    () => debounce((...args: Parameters<T>) => latest.current(...args), wait),
    [wait]
  );
  useEffect(() => () => wrapped.cancel(), [wrapped]);
  return wrapped;
}

function SearchComponent() {
  const debouncedSearch = useDebounce((query: string) => {
    console.log('Latest query:', query);
  }, 300);
  return <input onChange={e => debouncedSearch(e.target.value)} />;
}
```

The wrapper remains stable while `wait` is unchanged. An effect updates the callback reference after a committed render, and cleanup cancels work on unmount or a wait change. Calls come from events after mounting; this is not a render-time scheduling API. It uses the latest committed callback with the latest event arguments. That policy differs from freezing the callback captured when a burst began.

## Real-World Use Cases

### 1. Search Input

This is a scheduling sketch: assume React imports, an endpoint returning `{ results: Array<{ id: string; title: string }> }`, and application response validation/error display. Debounce reduces request starts; it does not order responses. An older request can finish after a newer one. Use the generation-and-cancellation policy in [Abort and cancellation](../03-async-concurrency/10.1.3.05-abort-and-cancellation.md) through its category path below before applying it to real search.

```typescript
function SearchInput() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState<Array<{ id: string; title: string }>>([]);

  const debouncedSearch = useDebounce(async (searchQuery: string) => {
    if (searchQuery.length < 2) {
      setResults([]);
      return;
    }

    const response = await fetch(`/api/search?q=${encodeURIComponent(searchQuery)}`);
    const data = await response.json();
    setResults(data.results);
  }, 300);

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value;
    setQuery(value);
    debouncedSearch(value);
  };

  return (
    <div>
      <input value={query} onChange={handleChange} />
      <ul>
        {results.map(result => (
          <li key={result.id}>{result.title}</li>
        ))}
      </ul>
    </div>
  );
}

```

### 2. Window Resize Handler

The examples reading `window` during state initialization are browser-only. For server rendering, start with a server-safe size and read the viewport in an effect after hydration. Debouncing resize means the displayed size deliberately lags until the user stops resizing.

```typescript
function useWindowSize() {
  const [size, setSize] = useState({
    width: window.innerWidth,
    height: window.innerHeight
  });

  useEffect(() => {
    const handleResize = debounce(() => {
      setSize({
        width: window.innerWidth,
        height: window.innerHeight
      });
    }, 250);

    window.addEventListener('resize', handleResize);
    return () => {
      window.removeEventListener('resize', handleResize);
      handleResize.cancel();
    };
  }, []);

  return size;
}

```

### 3. Form Validation

The remote result must also be associated with the current field value, as in search. Clearing an old error on a valid response is necessary, but does not prevent an obsolete response from replacing a newer one. Server validation remains authoritative when the form submits.

```typescript
function Form() {
  const [email, setEmail] = useState('');
  const [error, setError] = useState('');

  const validateEmail = useDebounce(async (value: string) => {
    if (!value) {
      setError('');
      return;
    }

    const response = await fetch(`/api/validate-email?email=${encodeURIComponent(value)}`);
    const data = await response.json();

    setError(data.valid ? '' : 'Invalid email address');
  }, 500);

  const handleChange = (e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value;
    setEmail(value);
    validateEmail(value);
  };

  return (
    <div>
      <input value={email} onChange={handleChange} />
      {error && <span className="error">{error}</span>}
    </div>
  );
}

```

### 4. Scroll Event Handler

```typescript
function useScrollPosition() {
  const [scrollY, setScrollY] = useState(0);

  useEffect(() => {
    const handleScroll = debounce(() => {
      setScrollY(window.scrollY);
    }, 100);

    window.addEventListener('scroll', handleScroll);
    return () => {
      window.removeEventListener('scroll', handleScroll);
      handleScroll.cancel();
    };
  }, []);

  return scrollY;
}

```

### 5. Button Click Handler

A trailing debounce delays submission until clicks stop. The disabled state begins only when work starts, and debounce alone cannot prevent concurrent requests lasting longer than its wait. If the contract is “one submission until completion”, use an in-flight guard and server idempotency instead. `submitForm` below represents application work with its own error reporting; it must not leave an unhandled rejection.

```typescript
function SubmitButton() {
  const [isSubmitting, setIsSubmitting] = useState(false);

  const handleSubmit = useDebounce(async () => {
    setIsSubmitting(true);
    try {
      await submitForm();
    } finally {
      setIsSubmitting(false);
    }
  }, 1000);

  return (
    <button onClick={handleSubmit} disabled={isSubmitting}>
      {isSubmitting ? 'Submitting...' : 'Submit'}
    </button>
  );
}

```

## Common Mistakes

### 1. Not Cleaning Up

```typescript
// Bad: No cleanup
useEffect(() => {
  const handleResize = debounce(() => {
    setWidth(window.innerWidth);
  }, 250);

  window.addEventListener('resize', handleResize);
  // Missing cleanup!
}, []);

// Good: Proper cleanup
useEffect(() => {
  const handleResize = debounce(() => {
    setWidth(window.innerWidth);
  }, 250);

  window.addEventListener('resize', handleResize);
  return () => {
    handleResize.cancel();
    window.removeEventListener('resize', handleResize);
  };
}, []);

```

### 2. Using Debounce Everywhere

```typescript
// Bad: Debouncing scroll for animation
const handleScroll = debounce(() => {
  updateAnimation(); // Needs immediate response
}, 100);

// Good: Use requestAnimationFrame for animations
let frame: number | null = null;
const handleScroll = () => {
  if (frame !== null) return;
  frame = requestAnimationFrame(() => {
    frame = null;
    updateAnimation();
  });
};
// Teardown also removes the listener and cancels any pending frame.

```

### 3. Wrong Wait Time

```typescript
// Too short: Still causes excessive calls
const search = debounce(fetchResults, 50);

// Too long: Feels unresponsive
const search = debounce(fetchResults, 2000);

// Good: Balance based on use case
const search = debounce(fetchResults, 300);

```

### 4. Leading feedback is an optional policy

```typescript
// Trailing-only is appropriate when only the final value should run
const search = debounce(fetchResults, 300);
// First keystroke waits 300ms

// Choose leading mode only when immediate execution is desired
const search = debounce(fetchResults, 300, { leading: true });

```

## Best Practices

### 1. Choose Appropriate Wait Time

```typescript
// Search: 300ms (user typing speed)
const search = debounce(fetchResults, 300);

// Form validation: 500ms (less frequent)
const validate = debounce(validateField, 500);

// Resize: 100ms (responsive but not too frequent)
const resize = debounce(handleResize, 100);

```

### 2. Clean Up Debounced Functions

```typescript
useEffect(() => {
  const debouncedFn = debounce(fn, wait);

  // Store reference for cleanup
  debouncedFnRef.current = debouncedFn;

  return () => {
    debouncedFn.cancel();

}, [fn, wait]);
```

## Performance Considerations

### Memory Usage

```typescript
// Weak: a brand-new debounced function on every render.
// The abandoned ones are garbage, not a leak — the real costs are an
// unstable identity (re-fires effect deps, breaks memoized children) and a
// timer left over from a render whose state has since been superseded.
const Component = () => {
  const debouncedFn = debounce(fn, 300);
  return <button onClick={debouncedFn}>Click</button>;
};

// Better: keep ONE debounced function per stable `fn`.
// useCallback evaluates its argument every render, but hands back the first
// result for as long as the deps don't change, so identity stays constant.
const Component = () => {
  const debouncedFn = useCallback(debounce(fn, 300), [fn]);
  return <button onClick={debouncedFn}>Click</button>;
};

// Stable identity still requires cleanup when this wrapper is replaced/unmounted:
// useEffect(() => () => debouncedFn.cancel(), [debouncedFn]);
const Component = () => {
  const debouncedFn = useMemo(() => debounce(fn, 300), [fn]);
  return <button onClick={debouncedFn}>Click</button>;
};
```

### Timer Precision

```typescript
// setTimeout is not precise
// Delay is a minimum eligibility threshold; busy/background pages can run much later.

// For precise timing, use:
// - requestAnimationFrame for animations
// - performance.now() for elapsed-time measurement, not scheduling

```

## Summary

Debouncing is essential for performance:

1. **Definition**: Delays execution until pause in calls

2. **Use cases**: Search, resize, form validation

3. **Implementation**: setTimeout with clearTimeout

4. **Options**: Leading, trailing, cancel, flush

5. **Performance**: Prevents excessive function calls

6. **Cleanup**: Always clean up timers

7. **Testing**: Use fake timers

# Debounce

When a user types at 80 words per minute into an autocomplete input, dispatching an HTTP request on every keystroke floods the network with dozens of ephemeral, rapidly obsolete queries. Debouncing postpones callback invocation until user activity ceases for a designated quiet period, coalescing rapid bursts of events into a single consolidated execution.

## Definition

**Debouncing** is a higher-order rate-limiting technique that delays the execution of a target function until a specified period of inactivity (`wait` milliseconds) has elapsed since its most recent invocation. Each incoming call during the active window resets the timer, capturing the latest arguments and `this` context while discarding intermediate evaluations.

> **Textbook Definition:** Debouncing is a temporal coalescing pattern that buffers bursts of high-frequency events, scheduling callback execution only after input event intervals exceed a configured quiet-time threshold. Debounce implementations support leading-edge execution, trailing-edge resolution, maximum wait deadlines, and explicit lifecycle cancellation.

## First Principles

1. **Temporal Clustering:** High-frequency event streams (keystrokes, mouse moves, window resizes) exhibit natural clustering. The vast majority of intermediate states are superseded by the terminal event.
2. **Timer Reset Invariant:** In trailing debounce, every invocation cancels the existing pending timer and schedules a new timeout for $T_{\text{now}} + \text{wait}$. Execution occurs only when no new event arrives before the timer expires.
3. **Execution Edge Decoupling:** Debouncing supports two distinct execution edges: the **leading edge** (invoked immediately on the first event of a quiet burst) and the **trailing edge** (invoked after the quiet period expires).
4. **Context and Argument Preservation:** Because the callback executes in a future event loop turn, the wrapper closure must retain the latest arguments and `this` receiver, releasing them upon settlement to avoid memory leaks.

```text
Incoming Calls:   --C1--C2----C3-------------------------C4----C5-------->
Timer State:        [---Reset---][-------wait-------]      [---Reset---]
Trailing Edge:   -----------------------------------(Fn)----------------->
                                                    (args of C3)

Leading Edge:     --(Fn)---------------------------------(Fn)------------>
                    (args of C1)                           (args of C4)
```

## Production Implementation: Comprehensive Debounce Utility

A robust production debounce utility must support `leading`, `trailing`, `maxWait` (to prevent starvation during continuous input), `cancel`, and `flush`:

```typescript
export interface DebounceOptions {
  leading?: boolean;
  trailing?: boolean;
  maxWait?: number;
}

export interface DebouncedFunction<Args extends unknown[], R> {
  (...args: Args): R | undefined;
  cancel(): void;
  flush(): R | undefined;
}

export function debounce<Args extends unknown[], R>(
  func: (...args: Args) => R,
  wait: number,
  options: DebounceOptions = {}
): DebouncedFunction<Args, R> {
  if (!Number.isFinite(wait) || wait < 0) {
    throw new RangeError('Wait must be a non-negative number');
  }

  const leading = options.leading ?? false;
  const trailing = options.trailing ?? true;
  const maxWait = options.maxWait;

  let timerId: ReturnType<typeof setTimeout> | undefined;
  let lastCallTime: number | undefined;
  let lastInvokeTime = 0;
  let lastArgs: Args | undefined;
  let lastThis: unknown;
  let result: R | undefined;

  function invoke(time: number): R | undefined {
    const args = lastArgs!;
    const thisArg = lastThis;

    lastArgs = undefined;
    lastThis = undefined;
    lastInvokeTime = time;

    result = func.apply(thisArg, args);
    return result;
  }

  function shouldInvoke(time: number): boolean {
    if (lastCallTime === undefined) return false;
    const timeSinceLastCall = time - lastCallTime;
    const timeSinceLastInvoke = time - lastInvokeTime;

    return (
      timeSinceLastCall >= wait ||
      timeSinceLastCall < 0 ||
      (maxWait !== undefined && timeSinceLastInvoke >= maxWait)
    );
  }

  function timerExpired(): void {
    const time = Date.now();
    if (shouldInvoke(time)) {
      trailingEdge(time);
      return;
    }

    // Reschedule timer for remaining wait budget
    const timeSinceLastCall = time - lastCallTime!;
    const remainingWait = wait - timeSinceLastCall;
    const remainingMax = maxWait !== undefined ? maxWait - (time - lastInvokeTime) : Infinity;
    const nextWait = Math.min(remainingWait, remainingMax);

    timerId = setTimeout(timerExpired, nextWait);
  }

  function trailingEdge(time: number): R | undefined {
    timerId = undefined;
    if (trailing && lastArgs) {
      return invoke(time);
    }
    lastArgs = undefined;
    lastThis = undefined;
    return result;
  }

  const debounced = function (this: unknown, ...args: Args): R | undefined {
    const time = Date.now();
    const isInvoking = shouldInvoke(time);

    lastArgs = args;
    lastThis = this;
    lastCallTime = time;

    if (isInvoking) {
      if (timerId === undefined) {
        lastInvokeTime = time;
        timerId = setTimeout(timerExpired, wait);
        return leading ? invoke(time) : result;
      }
      if (maxWait !== undefined) {
        // Enforce maxWait deadline during continuous input
        timerId = setTimeout(timerExpired, wait);
        return invoke(time);
      }
    }

    if (timerId === undefined) {
      timerId = setTimeout(timerExpired, wait);
    }
    return result;
  } as DebouncedFunction<Args, R>;

  debounced.cancel = () => {
    if (timerId !== undefined) clearTimeout(timerId);
    timerId = undefined;
    lastCallTime = undefined;
    lastInvokeTime = 0;
    lastArgs = undefined;
    lastThis = undefined;
  };

  debounced.flush = () => {
    if (timerId === undefined) return result;
    clearTimeout(timerId);
    return trailingEdge(Date.now());
  };

  return debounced;
}
```

## Execution Edge Configurations

| Configuration | First Call Behavior | Subsequent Rapid Calls | Idle Expiration Behavior | Primary Production Use Case |
| :--------------------------------------------------- | :------------------- | :--------------------------- | :------------------------------------- | :---------------------------------------- |
| **Trailing Only** (`leading: false, trailing: true`) | Silent buffer | Extends delay timer | Executes once with latest arguments | Search inputs, auto-save drafts |
| **Leading Only** (`leading: true, trailing: false`) | Executes immediately | Ignored during active window | Timer clears quietly without execution | Prevent double-submit button clicks |
| **Both Edges** (`leading: true, trailing: true`) | Executes immediately | Buffers latest arguments | Executes once with latest arguments | Responsive UI with guaranteed final state |

## Debouncing vs. Throttling vs. Microtask Coalescing

Engineers frequently conflate rate-limiting patterns:

```text
Input Stream:     |---C1---C2---C3---C4---C5---C6---C7---C8---(pause)--->
Debounce (300ms): ---------------------------------------------(Exec C8)->
Throttle (300ms): |---(Exec C1)---------▶(Exec C4)---------▶(Exec C7)---->
Microtask:        |---(All in same tick)---▶ [Microtask Checkpoint (Exec)]
```

- **Debounce:** Resets on every call; executes only when input *pauses*.
- **Throttle:** Guarantees periodic execution at fixed intervals during continuous input.
- **Microtask (`queueMicrotask`):** Coalesces synchronous calls within the *exact same turn* of the event loop; does not span wall-clock time.

## React Integration and the Re-Render Leak Trap

A critical pitfall in React components is instantiating `debounce()` directly in the render body:

```javascript
// DANGEROUS ANTIPATTERN: Recreated on every render!
function SearchBar() {
  const [query, setQuery] = useState('');

  // BUG: A new debounce instance is created every keystroke!
  // The internal timer is never shared; every keystroke fires independently!
  const debouncedSearch = debounce((q) => fetchResults(q), 300);

  return <input onChange={(e) => debouncedSearch(e.target.value)} />;
}
```

### The Production Hook Pattern (`useDebouncedCallback`)

To preserve timer state across renders and prevent memory leaks, memoize the wrapper and maintain a mutable reference to the latest callback:

```typescript
import { useEffect, useMemo, useRef } from 'react';

export function useDebouncedCallback<Args extends unknown[], R>(
  callback: (...args: Args) => R,
  wait: number,
  options?: DebounceOptions
): DebouncedFunction<Args, R> {
  const callbackRef = useRef(callback);
  callbackRef.current = callback; // Always references latest props/state

  const debounced = useMemo(() => {
    return debounce((...args: Args) => callbackRef.current(...args), wait, options);
  }, [wait, options?.leading, options?.trailing, options?.maxWait]);

  // Guaranteed cleanup on unmount:
  useEffect(() => {
    return () => debounced.cancel();
  }, [debounced]);

  return debounced;
}
```

## Summary

Debouncing coalesces high-frequency event bursts by delaying callback execution until a quiet period of inactivity elapses. Leading-edge execution delivers immediate responsiveness for action triggers, while trailing-edge execution captures final settled input states. Adding `maxWait` eliminates starvation during infinite input streams. Component integrations must memoize the debounced instance across renders and invoke `.cancel()` during unmounting to prevent stranded timers and closure leaks.

# Debounce

Typing at 80 WPM into autocomplete fires a request per keystroke — dozens of obsolete queries flooding the network. Debouncing waits for a quiet period and runs once with the latest input.

```javascript
const search = debounce((q) => fetchResults(q), 300);

input.addEventListener('input', (e) => search(e.target.value));
// 10 keystrokes in 200ms → 1 network call with the final query
```

## Definition

**Debouncing** delays a function's execution until `wait` milliseconds of inactivity have passed since its last call. Each new call resets the timer, keeping the latest arguments and `this` while discarding intermediate invocations.

> **Textbook Definition:** Debouncing is a temporal coalescing pattern that buffers bursts of high-frequency events, scheduling callback execution only after input event intervals exceed a configured quiet-time threshold. Debounce implementations support leading-edge execution, trailing-edge resolution, maximum wait deadlines, and explicit lifecycle cancellation.

## First Principles

High-frequency streams (keystrokes, resizes, mouse moves) arrive in clusters where every intermediate state is obsolete before it renders. The **timer-reset invariant** exploits this: each call cancels the pending timer and rearms for `now + wait`, so execution happens only in true silence. Two **edges** decouple responsiveness from finality — leading (run on the burst's first event) vs. trailing (run after quiet returns). And the wrapper closure retains the latest arguments and receiver, releasing them at settlement to avoid leaks.

```text
Incoming Calls:   --C1--C2----C3-------------------------C4----C5-------->
Timer State:        [---Reset---][-------wait-------]      [---Reset---]
Trailing Edge:   -----------------------------------(Fn)----------------->
                                                     (args of C3)

Leading Edge:     --(Fn)---------------------------------(Fn)----------->
                     (args of C1)                           (args of C4)
```

## 1. Production Implementation

This implementation supports `leading`, `trailing`, `maxWait` (anti-starvation during endless input), `cancel`, and `flush`:

```typescript
export interface DebounceOptions {
  leading?: boolean;
  trailing?: boolean;
  maxWait?: number;
}

export interface DebouncedFunction<Args extends unknown[], R> {
  (...args: Args): R | undefined;
  cancel(): void;
  flush(): R | undefined;
}

export function debounce<Args extends unknown[], R>(
  func: (...args: Args) => R,
  wait: number,
  options: DebounceOptions = {}
): DebouncedFunction<Args, R> {
  if (!Number.isFinite(wait) || wait < 0) {
    throw new RangeError('Wait must be a non-negative number');
  }

  const leading = options.leading ?? false;
  const trailing = options.trailing ?? true;
  if (options.maxWait !== undefined && (!Number.isFinite(options.maxWait) || options.maxWait < 0)) {
    throw new RangeError('maxWait must be a non-negative number');
  }
  const maxWait = options.maxWait === undefined ? undefined : Math.max(wait, options.maxWait);

  let timerId: ReturnType<typeof setTimeout> | undefined;
  let lastCallTime: number | undefined;
  let lastInvokeTime = 0;
  let lastArgs: Args | undefined;
  let lastThis: unknown;
  let result: R | undefined;

  function invoke(time: number): R | undefined {
    const args = lastArgs!;
    const thisArg = lastThis;

    lastArgs = undefined;
    lastThis = undefined;
    lastInvokeTime = time;

    result = func.apply(thisArg, args);
    return result;
  }

  function shouldInvoke(time: number): boolean {
    if (lastCallTime === undefined) return true;
    const timeSinceLastCall = time - lastCallTime;
    const timeSinceLastInvoke = time - lastInvokeTime;

    return (
      timeSinceLastCall >= wait ||
      timeSinceLastCall < 0 ||
      (maxWait !== undefined && timeSinceLastInvoke >= maxWait)
    );
  }

  function timerExpired(): void {
    const time = Date.now();
    if (shouldInvoke(time)) {
      trailingEdge(time);
      return;
    }

    // Reschedule timer for remaining wait budget
    const timeSinceLastCall = time - lastCallTime!;
    const remainingWait = wait - timeSinceLastCall;
    const remainingMax = maxWait !== undefined ? maxWait - (time - lastInvokeTime) : Infinity;
    const nextWait = Math.min(remainingWait, remainingMax);

    timerId = setTimeout(timerExpired, nextWait);
  }

  function trailingEdge(time: number): R | undefined {
    timerId = undefined;
    if (trailing && lastArgs) {
      return invoke(time);
    }
    lastArgs = undefined;
    lastThis = undefined;
    return result;
  }

  const debounced = function (this: unknown, ...args: Args): R | undefined {
    if (!leading && !trailing) return result; // Disabled: retain no arguments/timer.
    const time = Date.now();
    const isInvoking = shouldInvoke(time);

    lastArgs = args;
    lastThis = this;
    lastCallTime = time;

    if (isInvoking) {
      if (timerId === undefined) {
        lastInvokeTime = time;
        timerId = setTimeout(timerExpired, wait);
        return leading ? invoke(time) : result;
      }
      if (maxWait !== undefined) {
        // Replace the one pending timer before a forced invocation.
        clearTimeout(timerId);
        timerId = setTimeout(timerExpired, wait);
        return invoke(time);
      }
    }

    if (timerId === undefined) {
      timerId = setTimeout(timerExpired, wait);
    }
    return result;
  } as DebouncedFunction<Args, R>;

  debounced.cancel = () => {
    if (timerId !== undefined) clearTimeout(timerId);
    timerId = undefined;
    lastCallTime = undefined;
    lastInvokeTime = 0;
    lastArgs = undefined;
    lastThis = undefined;
  };

  debounced.flush = () => {
    if (timerId === undefined) return result;
    clearTimeout(timerId);
    return trailingEdge(Date.now());
  };

  return debounced;
}
```

## 2. Execution Edge Configurations

| Configuration | First Call Behavior | Subsequent Rapid Calls | Idle Expiration Behavior | Primary Production Use Case |
| :--------------------------------------------------- | :------------------- | :--------------------------- | :----------------------------------------------------------- | :---------------------------------------------------------------------------- |
| **Trailing Only** (`leading: false, trailing: true`) | Silent buffer | Extends delay timer | Executes once with latest arguments | Search inputs, auto-save drafts |
| **Leading Only** (`leading: true, trailing: false`) | Executes immediately | Ignored during active window | Timer clears quietly without execution | Short UI burst suppression; writes still need an in-flight/idempotency policy |
| **Both Edges** (`leading: true, trailing: true`) | Executes immediately | Buffers latest arguments | Executes only if another call arrived after the leading call | Responsive UI with the last buffered invocation |

## 3. Debouncing vs. Throttling vs. Microtask Coalescing

```text
Input Stream:     |---C1---C2---C3---C4---C5---C6---C7---C8---(pause)--->

Debounce (300ms): ---------------------------------------------(Exec C8)->
Throttle (300ms): |---(Exec C1)---------▶(Exec C4)---------▶(Exec C7)---->
Microtask:        |---(All in same tick)---▶ [Microtask Checkpoint (Exec)]
```

- **Debounce** resets per call — runs only when input *pauses*.
- **Throttle** bounds ordinary starts under continuous input; host delays mean it cannot guarantee exact periodic execution.
- **Microtask (`queueMicrotask`)** coalesces only synchronous calls within the *same turn* — it spans no wall-clock time.

## 4. React Integration and the Re-Render Leak Trap

Creating `debounce()` in the render body rebuilds the timer every keystroke — each keystroke then fires independently:

```javascript
// DANGEROUS ANTIPATTERN: Recreated on every render!
function SearchBar() {
  const [query, setQuery] = useState('');

  // BUG: A new debounce instance is created every keystroke!
  // The internal timer is never shared; every keystroke fires independently!
  const debouncedSearch = debounce((q) => fetchResults(q), 300);

  return <input value={query} onChange={(e) => {
    setQuery(e.target.value); // Causes the next render to create another wrapper.
    debouncedSearch(e.target.value);
  }} />;
}
```

Keep the wrapper stable for its intended mounted lifetime, publish the callback ref **after commit**, and cancel pending work during cleanup. A render may be abandoned, so writing a shared callback ref during render can expose uncommitted props/state:

```typescript
import { useEffect, useLayoutEffect, useMemo, useRef } from 'react';

export function useDebouncedCallback<Args extends unknown[], R>(
  callback: (...args: Args) => R,
  wait: number,
  options?: DebounceOptions
): DebouncedFunction<Args, R> {
  const callbackRef = useRef(callback);
  useLayoutEffect(() => { callbackRef.current = callback; }, [callback]);

  const debounced = useMemo(() => {
    return debounce((...args: Args) => callbackRef.current(...args), wait, options);
  }, [wait, options?.leading, options?.trailing, options?.maxWait]);

  // Cleanup on replacement and ordinary unmount
  useEffect(() => {
    return () => debounced.cancel();
  }, [debounced]);

  return debounced;
}
```

The numeric delays are scheduling thresholds, not exact deadlines. `maxWait` is normalized to at least `wait`; both edges false disables work. The wrapper returns the last callback result, not a separate completion promise per queued call. Callback exceptions follow the invocation path, and callback-created promises need an owner for rejection. Cancel stops pending invocation only.

For search, invalidate the previous result **when input changes**, then debounce the replacement start. Waiting until that start to invalidate leaves an old request able to publish during the quiet gap. Use the canonical [search manager](../03-async-concurrency/10.1.3.05-abort-and-cancellation.md) for result-generation and abort ownership; debounce alone neither cancels I/O nor serializes writes.

## Summary

Debounce coalesces event bursts by running only after a quiet period, capturing the latest arguments and receiver. Leading edge buys responsiveness, trailing edge captures final state, and `maxWait` prevents starvation under endless input. In components, memoize the wrapper across renders and `cancel()` on unmount to avoid stranded timers.

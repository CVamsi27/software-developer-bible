# Throttle

Hundreds of scroll events per second, each triggering DOM measurement, means main-thread jank and dropped frames. Throttling spaces ordinary callback starts and can retain the latest suppressed input; a busy host can delay scheduled work.

```javascript
const onScroll = throttle(() => {
  updateStickyHeader(window.scrollY);
}, 100);

window.addEventListener('scroll', onScroll);
// 500 events/sec → at most 10 executions/sec
```

## Definition

**Throttling** enforces a maximum invocation frequency over time: at most one execution per `interval` milliseconds, sampling the input stream. Where debounce resets its quiet-time deadline per event, a throttle admits work during a sustained stream. Timers cannot guarantee exact deadlines, and explicit flush/cancel policies can change spacing.

> **Textbook Definition:** Throttling is a temporal rate-limiting technique that bounds ordinary invocation starts under an interval policy, admitting an initial leading invocation and scheduling a trailing execution for the most recent arguments received during the throttled window while discarding intermediate calls.

## First Principles

Under continuous input (dragging, scrolling), debounce would defer forever — throttle instead admits work during the stream under an interval budget; it cannot force an exact cadence. Window expiry is measured with a monotonic clock (`performance.now()`), immune to wall-clock drift. If input stops mid-window, the final state must still land — so a hybrid throttle arms a trailing timer for the latest arguments. For visual work, `requestAnimationFrame` can coalesce work at a rendering opportunity; it does not guarantee a paint or replace a slower rate limit when less frequent work is desired.

```text
Continuous Input:  --E1--E2--E3--E4--E5--E6--E7--E8--E9--E10-------->
Time Intervals:    [--- Window 1 ---][--- Window 2 ---][--- Window 3 ---]
Throttled Output:  --(Fn: E1)--------▶(Fn: E5)--------▶(Fn: E10)------>
                   (Leading)          (Trailing W1)   (Trailing W2)
```

## 1. Production Implementation: Hybrid Timestamp & Timer Throttle

Timestamp-only throttles drop the final event when input stops mid-window. The robust form pairs monotonic timestamps (leading edge) with a trailing timeout:

```typescript
export interface ThrottleOptions {
  leading?: boolean;
  trailing?: boolean;
}

export interface ThrottledFunction<Args extends unknown[], R> {
  (...args: Args): R | undefined;
  cancel(): void;
  flush(): R | undefined;
}

export function throttle<Args extends unknown[], R>(
  func: (...args: Args) => R,
  interval: number,
  options: ThrottleOptions = {}
): ThrottledFunction<Args, R> {
  if (!Number.isFinite(interval) || interval < 0) {
    throw new RangeError('Interval must be a non-negative number');
  }

  const leading = options.leading ?? true;
  const trailing = options.trailing ?? true;

  let lastRunTime: number | undefined;
  let timerId: ReturnType<typeof setTimeout> | undefined;
  let lastArgs: Args | undefined;
  let lastThis: unknown;
  let result: R | undefined;

  function invoke(time: number): R | undefined {
    const args = lastArgs!;
    const thisArg = lastThis;

    lastArgs = undefined;
    lastThis = undefined;
    lastRunTime = time;

    result = func.apply(thisArg, args);
    return result;
  }

  const throttled = function (this: unknown, ...args: Args): R | undefined {
    if (!leading && !trailing) return result;
    const now = performance.now();
    lastArgs = args;
    lastThis = this;

    // First invocation handling
    if (lastRunTime === undefined) {
      if (leading) {
        return invoke(now);
      }
      lastRunTime = now;
    }

    const elapsed = now - lastRunTime;
    // A fresh trailing-only burst waits rather than invoking immediately.
    if (!leading && timerId === undefined && elapsed >= interval) lastRunTime = now;
    const remaining = interval - (now - lastRunTime);

    if ((remaining <= 0 || remaining > interval) && (leading || timerId !== undefined)) {
      // Window has expired: execute immediately
      if (timerId !== undefined) {
        clearTimeout(timerId);
        timerId = undefined;
      }
      return invoke(now);
    }

    // Schedule trailing execution if not already waiting
    if (trailing && timerId === undefined) {
      timerId = setTimeout(() => {
        timerId = undefined;
        invoke(performance.now());
      }, remaining);
    }

    if (!trailing) { lastArgs = undefined; lastThis = undefined; }
    return result;
  } as ThrottledFunction<Args, R>;

  throttled.cancel = () => {
    if (timerId !== undefined) clearTimeout(timerId);
    timerId = undefined;
    lastRunTime = undefined;
    lastArgs = undefined;
    lastThis = undefined;
  };

  throttled.flush = () => {
    if (timerId === undefined) return result;
    clearTimeout(timerId);
    timerId = undefined;
    return invoke(performance.now());
  };

  return throttled;
}
```

## 2. Architectural Edge Policies

| Configuration | First Call of Burst | Continuous Activity | Termination of Activity | Primary Use Case |
| :------------------------------------------------------- | :------------------ | :---------------------------------------------- | :----------------------------------------- | :------------------------------------------------- |
| **Leading & Trailing** (`leading: true, trailing: true`) | Runs immediately | Starts are ordinarily at least `interval` apart | Fires once with final arguments | Scroll position meters, volume sliders |
| **Leading Only** (`leading: true, trailing: false`) | Runs immediately | Starts are ordinarily at least `interval` apart | Discards any calls made inside last window | Rate-limiting game fire buttons, telemetry pings |
| **Trailing Only** (`leading: false, trailing: true`) | Silent buffer | Starts are ordinarily at least `interval` apart | Fires with final arguments after interval | Background telemetry batches, auto-refresh polling |

## 3. Throttle vs. `requestAnimationFrame` for Visual Scrolling

A fixed 16 ms timer is independent of the display's rendering schedule and can perform redundant work or miss useful presentation opportunities. It does not by itself cause screen tearing:

```text
Timer Throttle (setTimeout 16ms):
[ Tick (16ms) ]      [ Tick (16ms) ]      [ Tick (16ms) ] (Decoupled from VSync)
       ▲                    ▲                    ▲
[ Display Frame 1 ]  [ Display Frame 2 ]  [ Display Frame 3 ] (VSync 60Hz / 120Hz)
Result: Can schedule redundant work or miss the desired rendering opportunity.

rAF Throttle:
[ rAF Callback ] ──▶ [ Recalculate Layout ] ──▶ [ Paint ] (Synchronized with VSync)
```

For animations, sticky headers, and canvas redraws, an rAF gate keeps at most one callback pending for a rendering opportunity. Its owner must remove the event listener and cancel pending work during teardown:

```javascript
export function rafThrottle(callback) {
  let frameId;
  let lastArgs;
  let lastThis;
  const wrapped = function (...args) {
    lastArgs = args;
    lastThis = this;
    if (frameId !== undefined) return;
    frameId = requestAnimationFrame(() => {
      frameId = undefined;
      const args = lastArgs;
      const receiver = lastThis;
      lastArgs = lastThis = undefined;
      callback.apply(receiver, args);
    });
  };
  wrapped.cancel = () => {
    if (frameId !== undefined) cancelAnimationFrame(frameId);
    frameId = lastArgs = lastThis = undefined;
  };
  return wrapped;
}
```

## 4. React Integration Pattern

Building `throttle()` in the render body recreates the closure per update, wiping `lastRunTime` and timer handles. Stabilize with a hook:

```typescript
import { useEffect, useLayoutEffect, useMemo, useRef } from 'react';

export function useThrottledCallback<Args extends unknown[], R>(
  callback: (...args: Args) => R,
  interval: number,
  options?: ThrottleOptions
): ThrottledFunction<Args, R> {
  const callbackRef = useRef(callback);
  useLayoutEffect(() => { callbackRef.current = callback; }, [callback]);

  const throttled = useMemo(() => {
    return throttle((...args: Args) => callbackRef.current(...args), interval, options);
  }, [interval, options?.leading, options?.trailing]);

  useEffect(() => {
    return () => throttled.cancel();
  }, [throttled]);

  return throttled;
}
```

Publish callback refs after commit, so an abandoned render cannot expose an uncommitted callback. Create scheduled work from events/effects, then cancel it on wrapper replacement/unmount.

`interval: 0` supplies no positive spacing, both edges false disables work, and `flush()` deliberately runs pending work early. A callback may return a promise, but this helper does not await it: starts can overlap, so write serialization and server quotas need their own owner.

## Summary

Throttle bounds invocation frequency for sustained streams where debounce would starve. Pair monotonic timestamps (leading edge) with a trailing timer so final state survives input end. Prefer `requestAnimationFrame` gating for visual updates to stay VSync-aligned, and memoize throttled callbacks in React to preserve timer state.

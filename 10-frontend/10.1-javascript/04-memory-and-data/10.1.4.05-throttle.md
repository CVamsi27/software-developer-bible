# Throttle

Hundreds of scroll events per second, each triggering DOM measurement, means main-thread jank and dropped frames. Throttling caps the callback at a fixed frequency so work arrives at regular intervals no matter the input volume.

```javascript
const onScroll = throttle(() => {
  updateStickyHeader(window.scrollY);
}, 100);

window.addEventListener('scroll', onScroll);
// 500 events/sec → at most 10 executions/sec
```

## Definition

**Throttling** enforces a maximum invocation frequency over time: at most one execution per `interval` milliseconds, sampling the input stream. Where debounce resets its timer per event, throttle guarantees periodic execution even under endless input.

> **Textbook Definition:** Throttling is a temporal rate-limiting technique that bounds function execution frequency to a deterministic period, admitting an initial leading invocation and scheduling a trailing execution for the most recent arguments received during the throttled window while discarding intermediate calls.

## First Principles

Under continuous input (dragging, scrolling), debounce would defer forever — throttle instead guarantees a cadence of `1 / interval`. Window expiry is measured with a monotonic clock (`performance.now()`), immune to wall-clock drift. If input stops mid-window, the final state must still land — so a hybrid throttle arms a trailing timer for the latest arguments. And for visual work, VSync-aligned `requestAnimationFrame` beats wall-clock timers, which drift against the compositor.

```text
Continuous Input:  --E1--E2--E3--E4--E5--E6--E7--E8--E9--E10-------->
Time Intervals:    [--- Window 1 ---][--- Window 2 ---][--- Window 3 ---]
Throttled Output:  --(Fn: E1)--------▶(Fn: E5)--------▶(Fn: E10)------>
                   (Leading)          (Trailing W1)   (Trailing W2)
```

## How It Works

### 1. Production Implementation: Hybrid Timestamp & Timer Throttle

Timestamp-only throttles drop the final event when input stops mid-window. The robust form pairs monotonic timestamps (leading edge) with a trailing timeout:

```typescript
export interface ThrottleOptions {
  leading?: boolean;
  trailing?: boolean;
}

export interface ThrottledFunction<Args extends unknown[], R> {
  (...args: Args): R | undefined;
  cancel(): void;
  flush(): R | undefined;
}

export function throttle<Args extends unknown[], R>(
  func: (...args: Args) => R,
  interval: number,
  options: ThrottleOptions = {}
): ThrottledFunction<Args, R> {
  if (!Number.isFinite(interval) || interval < 0) {
    throw new RangeError('Interval must be a non-negative number');
  }

  const leading = options.leading ?? true;
  const trailing = options.trailing ?? true;

  let lastRunTime: number | undefined;
  let timerId: ReturnType<typeof setTimeout> | undefined;
  let lastArgs: Args | undefined;
  let lastThis: unknown;
  let result: R | undefined;

  function invoke(time: number): R | undefined {
    const args = lastArgs!;
    const thisArg = lastThis;

    lastArgs = undefined;
    lastThis = undefined;
    lastRunTime = time;

    result = func.apply(thisArg, args);
    return result;
  }

  const throttled = function (this: unknown, ...args: Args): R | undefined {
    const now = performance.now();
    lastArgs = args;
    lastThis = this;

    // First invocation handling
    if (lastRunTime === undefined) {
      if (leading) {
        return invoke(now);
      }
      lastRunTime = now;
    }

    const elapsed = now - lastRunTime;
    const remaining = interval - elapsed;

    if (remaining <= 0 || remaining > interval) {
      // Window has expired: execute immediately
      if (timerId !== undefined) {
        clearTimeout(timerId);
        timerId = undefined;
      }
      return invoke(now);
    }

    // Schedule trailing execution if not already waiting
    if (trailing && timerId === undefined) {
      timerId = setTimeout(() => {
        timerId = undefined;
        invoke(performance.now());
      }, remaining);
    }

    return result;
  } as ThrottledFunction<Args, R>;

  throttled.cancel = () => {
    if (timerId !== undefined) clearTimeout(timerId);
    timerId = undefined;
    lastRunTime = undefined;
    lastArgs = undefined;
    lastThis = undefined;
  };

  throttled.flush = () => {
    if (timerId === undefined) return result;
    clearTimeout(timerId);
    timerId = undefined;
    return invoke(performance.now());
  };

  return throttled;
}
```

### 2. Architectural Edge Policies

| Configuration | First Call of Burst | Continuous Activity | Termination of Activity | Primary Use Case |
| :------------------------------------------------------- | :------------------ | :------------------------ | :----------------------------------------- | :------------------------------------------------- |
| **Leading & Trailing** (`leading: true, trailing: true`) | Runs immediately | Fires every `interval` ms | Fires once with final arguments | Scroll position meters, volume sliders |
| **Leading Only** (`leading: true, trailing: false`) | Runs immediately | Fires every `interval` ms | Discards any calls made inside last window | Rate-limiting game fire buttons, telemetry pings |
| **Trailing Only** (`leading: false, trailing: true`) | Silent buffer | Fires every `interval` ms | Fires with final arguments after interval | Background telemetry batches, auto-refresh polling |

### 3. Throttle vs. `requestAnimationFrame` for Visual Scrolling

A 16ms timer drifts against the display's VSync, causing jitter, tearing, or duplicate work inside one frame:

```text
Timer Throttle (setTimeout 16ms):
[ Tick (16ms) ]      [ Tick (16ms) ]      [ Tick (16ms) ] (Decoupled from VSync)
       ▲                    ▲                    ▲
[ Display Frame 1 ]  [ Display Frame 2 ]  [ Display Frame 3 ] (VSync 60Hz / 120Hz)
Result: Can cause frame jitter, tearing, or redundant calculations within the same frame.

rAF Throttle:
[ rAF Callback ] ──▶ [ Recalculate Layout ] ──▶ [ Paint ] (Synchronized with VSync)
```

For animations, sticky headers, and canvas redraws, an rAF gate runs at most once per frame in lockstep with the compositor:

```javascript
export function rafThrottle(callback) {
  let isQueued = false;
  let lastArgs;

  return function (...args) {
    lastArgs = args;
    if (isQueued) return;

    isQueued = true;
    requestAnimationFrame(() => {
      isQueued = false;
      callback(...lastArgs);
    });
  };
}
```

### 4. React Integration Pattern

Building `throttle()` in the render body recreates the closure per update, wiping `lastRunTime` and timer handles. Stabilize with a hook:

```typescript
import { useEffect, useMemo, useRef } from 'react';

export function useThrottledCallback<Args extends unknown[], R>(
  callback: (...args: Args) => R,
  interval: number,
  options?: ThrottleOptions
): ThrottledFunction<Args, R> {
  const callbackRef = useRef(callback);
  callbackRef.current = callback;

  const throttled = useMemo(() => {
    return throttle((...args: Args) => callbackRef.current(...args), interval, options);
  }, [interval, options?.leading, options?.trailing]);

  useEffect(() => {
    return () => throttled.cancel();
  }, [throttled]);

  return throttled;
}
```

## Summary

Throttle bounds invocation frequency for sustained streams where debounce would starve. Pair monotonic timestamps (leading edge) with a trailing timer so final state survives input end. Prefer `requestAnimationFrame` gating for visual updates to stay VSync-aligned, and memoize throttled callbacks in React to preserve timer state.

# Throttle

When a user scrolls continuously down an infinite feed, the browser generates hundreds of scroll events per second. Running expensive DOM measurements or layout queries on every raw event causes main-thread jank and dropped frames. Throttling restricts callback execution to a fixed maximum frequency, admitting work at regular intervals regardless of input volume.

## Definition

**Throttling** is a rate-control mechanism that enforces a maximum invocation frequency on a target function over time. Unlike debouncing—which resets its timer on every incoming event—throttling guarantees that a function executes at most once per configured time interval (`limit` milliseconds), sampling the continuous stream of inputs.

> **Textbook Definition:** Throttling is a temporal rate-limiting technique that bounds function execution frequency to a deterministic period, admitting an initial leading invocation and scheduling a trailing execution for the most recent arguments received during the throttled window while discarding intermediate calls.

## First Principles

1. **Guaranteed Execution Cadence:** During continuous, non-pausing input streams (e.g. mouse dragging, scrolling, window resizing), debouncing would postpone execution indefinitely. Throttling guarantees steady periodic execution ($1 / \text{interval}$).
2. **Monotonic Elapsed Timing:** Determining when a throttled window expires requires measuring elapsed wall-clock time from the last invocation using a monotonic clock (`performance.now()`), preventing clock drift errors.
3. **Trailing State Preservation:** If input ceases midway through an active throttled window, the final state must not be lost. A hybrid throttle schedules a trailing timer to process the latest received arguments upon window expiration.
4. **Display Pipeline Alignment:** For visual animations and layout recalculations, timer-based throttling (`setTimeout`) is inferior to display VSync alignment (`requestAnimationFrame`), which synchronizes work with the browser compositor.

```text
Continuous Input:  --E1--E2--E3--E4--E5--E6--E7--E8--E9--E10--------->
Time Intervals:    [--- Window 1 ---][--- Window 2 ---][--- Window 3 ---]
Throttled Output:  --(Fn: E1)--------▶(Fn: E5)--------▶(Fn: E10)------>
                   (Leading)          (Trailing W1)   (Trailing W2)
```

## Production Implementation: Hybrid Timestamp & Timer Throttle

A naive throttle based purely on timestamps misses the final trailing event when input stops. A robust production throttle combines monotonic timestamps with a trailing timeout:

```typescript
export interface ThrottleOptions {
  leading?: boolean;
  trailing?: boolean;
}

export interface ThrottledFunction<Args extends unknown[], R> {
  (...args: Args): R | undefined;
  cancel(): void;
  flush(): R | undefined;
}

export function throttle<Args extends unknown[], R>(
  func: (...args: Args) => R,
  interval: number,
  options: ThrottleOptions = {}
): ThrottledFunction<Args, R> {
  if (!Number.isFinite(interval) || interval < 0) {
    throw new RangeError('Interval must be a non-negative number');
  }

  const leading = options.leading ?? true;
  const trailing = options.trailing ?? true;

  let lastRunTime: number | undefined;
  let timerId: ReturnType<typeof setTimeout> | undefined;
  let lastArgs: Args | undefined;
  let lastThis: unknown;
  let result: R | undefined;

  function invoke(time: number): R | undefined {
    const args = lastArgs!;
    const thisArg = lastThis;

    lastArgs = undefined;
    lastThis = undefined;
    lastRunTime = time;

    result = func.apply(thisArg, args);
    return result;
  }

  const throttled = function (this: unknown, ...args: Args): R | undefined {
    const now = performance.now();
    lastArgs = args;
    lastThis = this;

    // First invocation handling
    if (lastRunTime === undefined) {
      if (leading) {
        return invoke(now);
      }
      lastRunTime = now;
    }

    const elapsed = now - lastRunTime;
    const remaining = interval - elapsed;

    if (remaining <= 0 || remaining > interval) {
      // Window has expired: execute immediately
      if (timerId !== undefined) {
        clearTimeout(timerId);
        timerId = undefined;
      }
      return invoke(now);
    }

    // Schedule trailing execution if not already waiting
    if (trailing && timerId === undefined) {
      timerId = setTimeout(() => {
        timerId = undefined;
        invoke(performance.now());
      }, remaining);
    }

    return result;
  } as ThrottledFunction<Args, R>;

  throttled.cancel = () => {
    if (timerId !== undefined) clearTimeout(timerId);
    timerId = undefined;
    lastRunTime = undefined;
    lastArgs = undefined;
    lastThis = undefined;
  };

  throttled.flush = () => {
    if (timerId === undefined) return result;
    clearTimeout(timerId);
    timerId = undefined;
    return invoke(performance.now());
  };

  return throttled;
}
```

## Architectural Edge Policies

| Configuration | First Call of Burst | Continuous Activity | Termination of Activity | Primary Use Case |
| :------------------------------------------------------- | :------------------ | :------------------------ | :----------------------------------------- | :------------------------------------------------- |
| **Leading & Trailing** (`leading: true, trailing: true`) | Runs immediately | Fires every `interval` ms | Fires once more with final arguments | Scroll position meters, volume sliders |
| **Leading Only** (`leading: true, trailing: false`) | Runs immediately | Fires every `interval` ms | Discards any calls made inside last window | Rate-limiting game fire buttons, telemetry pings |
| **Trailing Only** (`leading: false, trailing: true`) | Silent buffer | Fires every `interval` ms | Fires with final arguments after interval | Background telemetry batches, auto-refresh polling |

## Throttle vs. `requestAnimationFrame` for Visual Scrolling

A common senior engineering dilemma is whether to throttle scroll and resize listeners using time intervals (e.g. 16ms) or `requestAnimationFrame`:

```text
Timer Throttle (setTimeout 16ms):
[ Tick (16ms) ]      [ Tick (16ms) ]      [ Tick (16ms) ] (Decoupled from VSync)
       ▲                    ▲                    ▲
[ Display Frame 1 ]  [ Display Frame 2 ]  [ Display Frame 3 ] (VSync 60Hz / 120Hz)
Result: Can cause frame jitter, tearing, or redundant calculations within the same frame.

rAF Throttle:
[ rAF Callback ] ──▶ [ Recalculate Layout ] ──▶ [ Paint ] (Synchronized with VSync)
```

For DOM operations affecting visual rendering (animations, sticky headers, canvas redraws), **rAF Throttling** delivers superior fluidity:

```javascript
export function rafThrottle(callback) {
  let isQueued = false;
  let lastArgs;

  return function (...args) {
    lastArgs = args;
    if (isQueued) return;

    isQueued = true;
    requestAnimationFrame(() => {
      isQueued = false;
      callback(...lastArgs);
    });
  };
}
```

## React Integration Pattern

Instantiating `throttle()` inside the render body recreates the closure on every update, wiping out `lastRunTime` and timer handles. A production hook encapsulates stable references and automatic unmount cleanup:

```typescript
import { useEffect, useMemo, useRef } from 'react';

export function useThrottledCallback<Args extends unknown[], R>(
  callback: (...args: Args) => R,
  interval: number,
  options?: ThrottleOptions
): ThrottledFunction<Args, R> {
  const callbackRef = useRef(callback);
  callbackRef.current = callback;

  const throttled = useMemo(() => {
    return throttle((...args: Args) => callbackRef.current(...args), interval, options);
  }, [interval, options?.leading, options?.trailing]);

  useEffect(() => {
    return () => throttled.cancel();
  }, [throttled]);

  return throttled;
}
```

## Summary

Throttling enforces an upper bound on invocation frequency, guaranteeing periodic execution during sustained input streams. The hybrid implementation pairs monotonic timestamp checks for instantaneous leading execution with a timeout for trailing edge capture. For visual rendering and layout updates, `requestAnimationFrame` provides optimal alignment with the browser's refresh pipeline, while React integrations require hook memoization to preserve timer state across re-renders.

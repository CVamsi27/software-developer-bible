# Equality & Type Coercion

An empty array runs inside `if ([])`, yet `[] == false` is also true. There is no contradiction: the condition and loose equality use different rules.

## Definition

**Type coercion** is a conversion JavaScript performs when an operation requires a different kind of value. Equality, arithmetic, relational operators, and Boolean conditions each apply different rules; understanding which operation is running is more useful than memorizing a list of surprising expressions.

> **Textbook Definition:** Type coercion applies language-defined conversions when an operator or context requires a different value representation. JavaScript's equality algorithms specify whether those conversions occur and how values such as `NaN`, signed zero, objects, and BigInts compare.

## First Principles

Start by asking what question the code is asking. `if ([])` checks truthiness, so it runs because arrays are objects and ordinary objects are truthy. `[] == false` converts `false` to `0`, then converts the array to `''` and that string to `0`. The two expressions use different algorithms.

## Pick the equality relation deliberately

| Operation | Coercion | `NaN` with itself | `0` and `-0` | Objects |
| ------------------ | -------------- | ----------------- | ------------ | ----------------------------------------- |
| `===` | No | Not equal | Equal | Same identity only |
| `Object.is()` | No | Equal | Different | Same identity only |
| Map/Set membership | No | Equal | Equal | Same identity only |
| `==` | Type-dependent | Not equal | Equal | Identity unless compared with a primitive |

Use strict equality as the default. `Object.is()` implements SameValue, which distinguishes signed zero and equates `NaN` with itself. Map and Set use SameValueZero: both zeros are equivalent, and `NaN` matches itself. None of these compares object structure.

## Derive loose equality from the operand types

The common cases of `==` can be derived in this order:

1. Same type: compare as that type (`NaN` is still unequal to itself; objects use identity).
2. `null` and `undefined`: they compare equal to each other. The legacy browser object `document.all` is an additional historical exception.
3. Boolean: convert the Boolean to `0` or `1`, then compare again.
4. Number and string: convert the string to a Number. An invalid numeric string becomes `NaN`, which compares unequal.
5. BigInt and string: parse the string as a BigInt; if it is not a valid integer representation, the comparison is false.
6. Object and primitive: convert the object with `ToPrimitive`, then compare the results again. Two objects do not get converted merely because they are compared with each other.
7. Number and BigInt: compare their mathematical numeric values without first rounding the BigInt through Number.

For example, `[10] == 10` is true because the array becomes the primitive string `'10'`, then the string becomes Number `10`. `Number()` is not blindly applied to both operands: `null == 0` is false, even though `Number(null)` is zero.

### Object conversion can execute code

`ToPrimitive` first calls `Symbol.toPrimitive` when present. Otherwise, ordinary conversion tries `valueOf()` and `toString()` in an order selected by the hint; `Date` has special default-hint behavior. A hook must return a primitive or JavaScript throws. Conversion can have side effects, so equality and arithmetic on user-defined objects are not always pure reads.

```js
const value = {
  [Symbol.toPrimitive](hint) {
    return hint === 'string' ? 'value' : 42;
  },
};

value == 42; // true: default hint produces 42
`${value}`;  // 'value': string hint produces a string
```

### Relational comparison is a different algorithm

`<`, `>`, `<=`, and `>=` do not reuse loose equality. They convert objects to primitives and compare two strings lexicographically; otherwise they compare numeric values. This explains the often-tested boundary:

```js
null == 0; // false: null only loosely equals undefined (plus legacy document.all)
null >= 0; // true: relational comparison converts null to numeric 0
```

The relational result can be undefined for `NaN`, which makes all four ordered comparisons false. Do not infer a numeric ordering from an equality result.

### `+` can concatenate or add

`+` first converts operands to primitives. If either primitive is a string, it concatenates; otherwise it performs numeric addition. BigInt arithmetic only combines with BigInt, so `1n + 1` throws. Other arithmetic operators are numeric, which can produce `NaN` rather than an error:

```js
1 + '2';      // '12'
[1, 2] + [3]; // '1,23'
'6' - 1;      // 5
true + true;  // 2
1n + 1n;      // 2n
```

Avoid ambiguous mixed-type expressions in application code. Make parsing and validation explicit at the input boundary.

## Parse input according to its contract

HTML input values, URL parameters, and storage values are strings. `Number('')` and `Number('  ')` return `0`; `Number('42px')` returns `NaN`, while `parseInt('42px', 10)` returns `42`. Choose whole-string conversion or prefix parsing according to the field's grammar, then validate range and finiteness. Conversion alone is not validation.

```js
function parseQuantity(input) {
  if (input.trim() === '') return { ok: false, reason: 'required' };
  const quantity = Number(input);
  if (!Number.isSafeInteger(quantity) || quantity < 0) {
    return { ok: false, reason: 'invalid quantity' };
  }
  return { ok: true, value: quantity };
}
```

Use `??` when only `null` and `undefined` mean “missing”; use `||` when every falsy value is invalid. For example, `0 || 50` returns 50, while `0 ?? 50` preserves zero. Empty arrays and objects are truthy, so test their length or keys when emptiness matters. Default `Array.prototype.sort()` compares string representations; supply a comparator for numeric ordering.

## Summary

Choose an equality relation based on its exact contract: strict comparison by default, `Object.is()` for SameValue, SameValueZero for Map/Set, and loose equality only when its conversions are intentional. Truthiness, relational comparison, `+`, and equality are separate algorithms. Parse and validate external strings at the boundary, then compare values in their intended domain.

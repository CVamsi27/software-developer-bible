# Equality & Type Coercion

`if ([])` is `true` — arrays are objects. Yet `[] == false` is *also* `true`. No contradiction: the first runs `ToBoolean`, the second runs `IsLooselyEqual`. Two different algorithms, two predictable answers.

```javascript
console.log(Boolean([]));  // true  (ToBoolean: all objects are truthy)
console.log([] == false);  // true  (IsLooselyEqual: reduces to 0 == 0)
console.log([] === false); // false (Strict: no coercion, different types)
```

## Definition

**Type coercion** is the implicit or explicit conversion of a value between types, driven by operators and abstract operations. JavaScript ships four equality algorithms — **`==`** (`IsLooselyEqual`), **`===`** (`IsStrictlyEqual`), **`Object.is`** (`SameValue`), and **`SameValueZero`** (`Map`/`Set`/`includes`) — each with fixed coercion and identity rules.

> **Textbook Definition:** Type coercion is the automatic or explicit transformation of a value between data types governed by ECMAScript abstract operations. Equality evaluation depends on the designated algorithm: strict equality rejects cross-type coercion, loose equality executes multi-step primitive reductions, and specialized operations evaluate signed zeroes and `NaN` equivalence.

## First Principles

Each syntactic context invokes its own abstract operation: `if (x)` runs `ToBoolean`, `x == y` runs `IsLooselyEqual`, `x + y` first converts to primitives and may concatenate strings, while relational comparison has its own primitive/numeric rules — never interchange them. Objects reduce to primitives via `ToPrimitive(input, hint)`, trying `[Symbol.toPrimitive]` before `valueOf()`/`toString()`. Loose equality prefers numbers (booleans become 0/1, strings parse numerically). Under ordinary ECMAScript rules, `null` and `undefined` loosely equal each other, not `0` or `false`. Browsers retain a legacy `document.all` exception to truthiness and nullish loose equality; avoid using that special object as a general model.

```text
Evaluating: [] == false
      │
      ▼ (Rule 1: Boolean operand coerces to Number)
      [] == 0
      │
      ▼ (Rule 2: Object operand undergoes ToPrimitive(hint: 'default'))
      [].toString() produces ""
      "" == 0
      │
      ▼ (Rule 3: String operand coerces to Number)
      ToNumber("") produces 0
      0 == 0
      │
      ▼ (Rule 4: Identical Number types compare directly)
      true
```

## 1. The Four Equality Algorithms

| Equality Relation | Operator / API | Cross-Type Coercion? | `NaN` vs `NaN` | `+0` vs `-0` | Object Comparison |
| :------------------------ | :------------------------ | :------------------------------ | :---------------------- | :------------------------------------- | :-------------------------------------- |
| **Strict Equality** | `===` | No | `false` (`NaN !== NaN`) | `true` (`+0 === -0`) | Reference identity only |
| **Loose Equality** | `==` | Yes (`ToPrimitive`, `ToNumber`) | `false` | `true` | Coerces object if paired with primitive |
| **`SameValue`** | `Object.is()` | No | `true` | `false` (`Object.is(+0, -0)` is false) | Reference identity only |
| **`SameValueZero`** | `Map`, `Set`, `.includes` | No | `true` | `true` (`+0` equals `-0`) | Reference identity only |

```javascript
// Demonstrating the four equality algorithms:
console.log(NaN === NaN);                 // false (Strict)
console.log(Object.is(NaN, NaN));         // true  (SameValue)
console.log(new Set([NaN, NaN]).size);    // 1     (SameValueZero)

console.log(+0 === -0);                   // true  (Strict)
console.log(Object.is(+0, -0));           // false (SameValue distinguishes signs)
console.log(new Map([[+0, 'zero']]).get(-0)); // "zero" (SameValueZero equates zeroes)
```

## 2. Abstract Equality (`==`) Evaluation Pipeline

`IsLooselyEqual` walks a fixed decision tree: (1) **same type** → compare via `===` (objects by identity); (2) **`null`/`undefined`** → equal only to each other; (3) **number vs string** → `ToNumber` the string (garbage becomes `NaN` → `false`); (4) **boolean operand** → `ToNumber` it first (`true`→1, `false`→0); (5) **object vs primitive** → `ToPrimitive` the object, then re-evaluate; (6) **BigInt vs string/number** → compare mathematical integer value; (7) otherwise `false`.

The classic `[] == ![]` traces exactly this path: `![]` is `false` (objects are truthy, negated) → `[] == 0` → `[].toString()` gives `""` → `"" == 0` → `0 == 0` → `true`.

```javascript
console.log([] == ![]); // true
```

## 3. The `ToPrimitive` Conversion Hook

Whenever an object must become a primitive (template literals, arithmetic, loose equality), `ToPrimitive(input, hint)` runs — honoring an explicit hook first:

```javascript
const account = {
  id: 42,
  name: 'Trading Account',

  // ES6 explicit conversion hook:
  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return this.id;
    if (hint === 'string') return this.name;
    return this.id; // 'default' hint (used by + and ==)
  }
};

console.log(+account);          // 42       (hint: 'number')
console.log(`${account}`);       // "Trading Account" (hint: 'string')
console.log(account + 10);       // 52       (hint: 'default')
console.log(account == 42);      // true     (hint: 'default')
```

Without the hook, the fallback order depends on hint: **string hint** tries `toString()` then `valueOf()`; **number/default hint** tries `valueOf()` then `toString()`. If neither yields a primitive, the engine throws `TypeError`.

## 4. Binary Arithmetic (`+`) vs. Relational Operators

`+` and `<` coerce differently. `+` applies `ToPrimitive` with the default hint — if either result is a string, it concatenates:

```javascript
1 + '2';       // "12"  (If either is a string after ToPrimitive, concatenate)
[1, 2] + [3];  // "1,23" ("1,2" + "3")
'6' - 1;       // 5     (numeric subtraction; BigInt has separate same-type rules)
true + true;   // 2     (1 + 1)
```

Relational operators (`<`, `>`, `<=`, `>=`) reduce both sides with the *number* hint; two remaining strings compare lexicographically, otherwise numeric comparison includes Number/BigInt rules rather than indiscriminately converting both to Number. Hence the null conundrum:

```javascript
console.log(null > 0);  // false (Number(null) is 0; 0 > 0 is false)
console.log(null == 0); // false (null only loosely equals undefined)
console.log(null >= 0); // true  (Evaluated as !(null < 0); 0 < 0 is false, so true!)
```

## 5. Safe Boundary Conversion in Production

External input (URL params, forms, env vars) arrives as strings, and naive conversion invents zeroes — `Number("")` and `Number(" ")` both yield `0`. Guard the boundary:

```typescript
// DANGEROUS: Accidental zero conversion
function parsePort(input: string): number {
  return Number(input); // Number("") produces 0! Number(" ") produces 0!
}

// SAFE: Robust input parsing boundary
export function parseIntegerStrict(value: string): number | null {
  const trimmed = value.trim();
  if (!/^[+-]?\d+$/.test(trimmed)) return null; // Decimal integer grammar only

  const parsed = Number(trimmed);
  if (!Number.isSafeInteger(parsed)) return null;

  return parsed;
}
```

The integer parser accepts signed decimal syntax and checks Number safe-integer range; callers still enforce a domain range such as a valid port or nonnegative limit. Hexadecimal and exponent spellings are deliberately rejected.

And prefer nullish coalescing over logical OR for defaults — `||` discards every falsy value, `??` only `null`/`undefined`:

```javascript
const defaultLimit = 50;

// Logical OR: Treats 0, "", false, NaN as falsy!
const limitA = 0 || defaultLimit; // 50 (BUG: User's chosen zero was overridden!)

// Nullish Coalescing: Replaces ONLY null or undefined:
const limitB = 0 ?? defaultLimit; // 0 (CORRECT: User's explicit value preserved)
```

## Summary

Four algorithms govern equality: `===` without coercion, `==` through systematic primitive reduction, `Object.is` distinguishing signed zeroes, and `SameValueZero` for collections. Objects reduce via `ToPrimitive` (`Symbol.toPrimitive` → `valueOf`/`toString`), `+` concatenates on any string while relationals prefer numbers, and ordinary nullish loose equality has its own boundary (with a legacy browser exception). Default to `===`, use `??` for defaults, and validate string input at system boundaries.

# Equality & Type Coercion

The expression `if ([])` evaluates to `true` because arrays are objects, yet the comparison `[] == false` also evaluates to `true`. This apparent paradox is not random language inconsistency; it is the predictable output of two distinct ECMAScript algorithms: `ToBoolean` and `IsLooselyEqual`. Mastering type coercion requires understanding internal specification conversion pipelines rather than memorizing quirk tables.

## Definition

**Type coercion** is the implicit or explicit conversion of a value from its original primitive or composite type to another type as mandated by an operator, control structure, or abstract operation. JavaScript defines four foundational equality algorithms—`IsLooselyEqual` (`==`), `IsStrictlyEqual` (`===`), `SameValue` (`Object.is`), and `SameValueZero` (`Map`, `Set`, `Array.includes`)—each enforcing specific coercion and identity behaviors.

> **Textbook Definition:** Type coercion is the automatic or explicit transformation of a value between data types governed by ECMAScript abstract operations. Equality evaluation depends on the designated algorithm: strict equality rejects cross-type coercion, loose equality executes multi-step primitive reductions, and specialized operations evaluate signed zeroes and `NaN` equivalence.

## First Principles

1. **Algorithm Context Separation:** A boolean condition (`if (x)`), a loose equality check (`x == y`), an addition (`x + y`), and a relational comparison (`x < y`) invoke entirely different abstract operations (`ToBoolean`, `IsLooselyEqual`, `ToNumeric`, and `ToPrimitive`).

2. **Deterministic Primitive Reduction:** When an operation demands a primitive value from an object, the runtime executes `ToPrimitive(input, hint)`, checking `[Symbol.toPrimitive]` before falling back to `valueOf()` and `toString()`.

3. **Numeric Preference in Loose Equality:** When comparing numbers against strings or booleans, `IsLooselyEqual` converts non-numeric operands toward IEEE-754 numbers (`0` and `1` for booleans; numeric parsing for strings).

4. **Null and Undefined Quarantine:** In loose equality, `null` and `undefined` loosely equal each other and nothing else (except legacy `document.all`). They never coerce to `0` or `false` in `==` evaluations.

```text
Evaluating: [] == false
      │
      ▼ (Rule 1: Boolean operand coerces to Number)
      [] == 0
      │
      ▼ (Rule 2: Object operand undergoes ToPrimitive(hint: 'default'))
      [].toString() produces ""
      "" == 0
      │
      ▼ (Rule 3: String operand coerces to Number)
      ToNumber("") produces 0
      0 == 0
      │
      ▼ (Rule 4: Identical Number types compare directly)
      true
```

## The Four Equality Algorithms

| Equality Relation | Operator / API | Cross-Type Coercion? | `NaN` vs `NaN` | `+0` vs `-0` | Object Comparison |
| :------------------------ | :------------------------ | :------------------------------ | :---------------------- | :------------------------------------- | :-------------------------------------- |
| **Strict Equality** | `===` | No | `false` (`NaN !== NaN`) | `true` (`+0 === -0`) | Reference identity only |
| **Loose Equality** | `==` | Yes (`ToPrimitive`, `ToNumber`) | `false` | `true` | Coerces object if paired with primitive |
| **`SameValue`** | `Object.is()` | No | `true` | `false` (`Object.is(+0, -0)` is false) | Reference identity only |
| **`SameValueZero`** | `Map`, `Set`, `.includes` | No | `true` | `true` (`+0` equals `-0`) | Reference identity only |

```javascript
// Demonstrating the four equality algorithms:
console.log(NaN === NaN);                 // false (Strict)
console.log(Object.is(NaN, NaN));         // true  (SameValue)
console.log(new Set([NaN, NaN]).size);    // 1     (SameValueZero)

console.log(+0 === -0);                   // true  (Strict)
console.log(Object.is(+0, -0));           // false (SameValue distinguishes signs)
console.log(new Map([[+0, 'zero']]).get(-0)); // "zero" (SameValueZero equates zeroes)
```

## Abstract Equality (`==`) Evaluation Pipeline

When `x == y` is evaluated, the engine traverses the ECMAScript `IsLooselyEqual` decision tree in strict sequence:

1. **Same Type:** Compare via `===` (e.g. `NaN == NaN` is false; objects compare by reference identity).
2. **`null` and `undefined`:** `null == undefined` is `true`. Neither loosely equals any other value.
3. **Number vs. String:** Convert the string to a Number: `x == ToNumber(y)`. If string is invalid, it becomes `NaN`, yielding `false`.
4. **Boolean Operand:** Convert the boolean to a Number (`true` → `1`, `false` → `0`), then re-evaluate: `x == ToNumber(bool)`.
5. **Object vs. Primitive:** Convert the object via `ToPrimitive(obj)`, then re-evaluate the result against the primitive.
6. **BigInt vs. String / Number:** Parse string to BigInt; compare mathematical integer value without precision loss.
7. **Default:** Return `false`.

### Why `[] == ![]` is True

A classic senior interview question evaluates:

```javascript
console.log([] == ![]); // true
```

1. `![]` is evaluated first. Because `[]` is an object, `ToBoolean([])` is `true`. Negating it yields `false`.
2. The expression simplifies to `[] == false`.
3. Boolean `false` converts to Number `0`: `[] == 0`.
4. Object `[]` undergoes `ToPrimitive`: `[].toString()` yields `""`: `"" == 0`.
5. String `""` converts to Number `0`: `0 == 0`.
6. Result: `true`.

## The `ToPrimitive` Conversion Hook

When an object must be converted to a primitive (during string template literals, arithmetic, or loose equality), the engine calls `ToPrimitive(input, preferredType)`:

```javascript
const account = {
  id: 42,
  name: 'Trading Account',

  // ES6 explicit conversion hook:
  [Symbol.toPrimitive](hint) {
    if (hint === 'number') return this.id;
    if (hint === 'string') return this.name;
    return this.id; // 'default' hint (used by + and ==)
  }
};

console.log(+account);          // 42       (hint: 'number')
console.log(`${account}`);       // "Trading Account" (hint: 'string')
console.log(account + 10);       // 52       (hint: 'default')
console.log(account == 42);      // true     (hint: 'default')
```

If `Symbol.toPrimitive` is absent:

- **String Hint:** Calls `toString()`. If it returns an object, calls `valueOf()`.
- **Number / Default Hint:** Calls `valueOf()`. If it returns an object, calls `toString()`.
- If neither returns a primitive value, a `TypeError` is thrown.

## Binary Arithmetic (`+`) vs. Relational Operators

Binary addition and relational comparisons follow distinct operational rules:

### Binary Addition (`+`)

```javascript
1 + '2';       // "12"  (If either is a string after ToPrimitive, concatenate)
[1, 2] + [3];  // "1,23" ("1,2" + "3")
'6' - 1;       // 5     (- strictly coerces to Number)
true + true;   // 2     (1 + 1)
```

### Relational Comparison (`<`, `>`, `<=`, `>=`)

Relational operators convert both operands to primitives via `ToPrimitive(hint: 'number')`. If both are strings, they undergo lexicographical comparison. Otherwise, both are coerced to Numbers.

This explains the classic null comparison conundrum:

```javascript
console.log(null > 0);  // false (Number(null) is 0; 0 > 0 is false)
console.log(null == 0); // false (null only loosely equals undefined)
console.log(null >= 0); // true  (Evaluated as !(null < 0); 0 < 0 is false, so true!)
```

## Safe Boundary Conversion in Production

External inputs (URL params, HTML forms, environment variables) are always strings. Naive conversions introduce critical bugs:

```typescript
// DANGEROUS: Accidental zero conversion
function parsePort(input: string): number {
  return Number(input); // Number("") produces 0! Number(" ") produces 0!
}

// SAFE: Robust input parsing boundary
export function parseIntegerStrict(value: string): number | null {
  const trimmed = value.trim();
  if (trimmed === '') return null;

  const parsed = Number(trimmed);
  if (!Number.isSafeInteger(parsed)) return null;

  return parsed;
}
```

### Nullish Coalescing (`??`) vs. Logical OR (`||`)

```javascript
const defaultLimit = 50;

// Logical OR: Treats 0, "", false, NaN as falsy!
const limitA = 0 || defaultLimit; // 50 (BUG: User's chosen zero was overridden!)

// Nullish Coalescing: Replaces ONLY null or undefined:
const limitB = 0 ?? defaultLimit; // 0 (CORRECT: User's explicit value preserved)
```

## Summary

JavaScript equality and type coercion operate through explicit, deterministic specification algorithms rather than capricious quirks. Strict equality (`===`) evaluates types and values without coercion, while loose equality (`==`) executes systematic primitive reductions. Objects reduce to primitives via `ToPrimitive` using `Symbol.toPrimitive`, `valueOf`, and `toString`. Production architectures enforce strict equality by default, use nullish coalescing (`??`) to avoid falsy traps, and validate raw external string inputs at system boundaries.

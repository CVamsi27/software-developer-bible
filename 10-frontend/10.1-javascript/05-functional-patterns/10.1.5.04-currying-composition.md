# Currying and Function Composition

A request pipeline often reuses a tenant, role, or output format across calls. Decide which values belong to setup and which should vary per request. Currying and partial application stage arguments; composition connects the value produced by one function to the next.

```js
const add = (a, b, c) => a + b + c;
const curriedAdd = a => b => c => a + b + c;

curriedAdd(1)(2)(3); // 6
```

## Definition

**Currying** transforms a function that accepts several arguments into nested functions that each accept one argument. **Partial application** fixes selected arguments and returns a function for the rest. **Function composition** connects functions so one function's output becomes the next function's input.

> **Textbook Definition:** Currying transforms an n-ary function into a sequence of unary functions. Partial application binds a subset of arguments to produce a function over the remaining arguments. Composition constructs a new function from functions whose input and output types align.

## First Principles

Functions are values and can return other functions, so an outer call can capture configuration for a later call. Composition uses a different relationship: the return value of one function is passed as the input to another. The distinction matters because staged calls preserve arguments, while a pipeline passes intermediate results. Neither pattern defines error handling, mutation, or asynchronous scheduling.

## How It Works

### 1. Fix Setup Once, Then Pass Data Through

A manual curry makes each stage visible. `addTax(rate)` captures the rate and returns a function that accepts one amount. A partial application may fix several arguments at once; `bind` does this for leading arguments and also fixes `this`.

```js
function greet(greeting, name) {
  return `${greeting}, ${name}`;
}
const greetSam = greet.bind(null, 'Hello');
greetSam('Sam'); // 'Hello, Sam'
```

`bind` does not create unary stages; it fixes selected arguments and leaves the remaining call shape intact. Generic `curry` helpers often infer arity from `Function.length`, but default and rest parameters make that an unreliable contract. Use explicit arity or a documented library helper when a generic curry is truly useful.

### 2. Compose Functions When Values Line Up

Mathematical composition `f ∘ g` means `f(g(x))`; `compose(f, g)` therefore runs right to left. A pipe reads in the order data flows, which is often easier to scan:

```js
const pipe = (...steps) => value => steps.reduce((result, step) => step(result), value);

const normalize = text => text.trim().toLowerCase();
const words = text => text.split(/\s+/);
const longWords = list => list.filter(word => word.length > 3);

pipe(normalize, words, longWords)('  Hello World JavaScript  ');
// ['hello', 'world', 'javascript']
```

Each step here is synchronous and accepts the previous result. If a step returns a promise, the next step receives that promise unless the pipeline explicitly awaits it. Composition also preserves call order; it does not recover from exceptions or undo side effects. Use an async-aware pipeline when every stage must await.

### 3. Framework Factories Are Not Always Unary Pipelines

A factory can fix configuration and return a handler with a framework-defined multi-argument signature. Express calls middleware with `(req, res, next)` and sequences it through `next()`; ordinary `pipe` would pass the previous return value as the next function's only argument.

```js
const requireRole = role => (req, res, next) => {
  if (req.user?.role !== role) return res.status(403).json({ error: 'Forbidden' });
  return next();
};

router.post('/admin', requireRole('admin'), handleAdminRequest);
```

This is a configured handler factory, not a unary transformation pipeline. Authentication must establish `req.user` before the role check, and authorization must still be enforced at the resource operation. The middleware example illustrates argument staging; the full request boundary belongs in the [Express and API security chapters](../../../20-backend/20.1-node.js/INDEX.md).

### 4. Keep the Public Call Shape Readable

Currying is useful when callers repeatedly provide setup values before data. Partial application is simpler when only a few leading arguments need fixing. Composition is useful when intermediate types align and the order reads clearly. Prefer named intermediate functions when point-free expressions hide what each step receives.

## Summary

Currying supplies one argument at a time; partial application fixes selected arguments; composition passes results between functions. Choose the form that makes setup and data flow clear. Keep framework callback protocols, asynchronous behavior, and side-effect ordering explicit because these helpers do not define them.

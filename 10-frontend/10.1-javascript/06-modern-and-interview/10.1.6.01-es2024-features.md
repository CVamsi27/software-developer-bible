# Recent ECMAScript Features (ES2022–ES2026)

## Definition

The ECMAScript language specification evolves through yearly editions. Each edition standardizes syntax and built-in behavior after the TC39 proposal process. This chapter selects additions from ES2022 through ES2026 that affect everyday data handling, iteration, promises, binary data, and error handling. Host APIs such as `structuredClone` have separate specifications and support timelines.

> **Textbook Definition:** An ECMAScript edition specifies the language syntax, semantics and standard built-in objects adopted for that release. Edition membership is distinct from implementation support and from browser or server host APIs.


## First Principles

New APIs have to preserve observable language behavior and work within their host's capabilities. Those constraints lead to three practical checks:

1. **Existing source must retain its specified meaning.** A new API cannot silently change how older programs evaluate; compatibility constrains the design and its edge cases.
2. **The language and its host are separate contracts.** ECMAScript may define a method while browsers, Node.js, and embedded engines adopt it at different times. A host may also add facilities outside the language specification.
3. **Every convenience method still has observable costs and semantics.** Mutation, object identity, scheduling, resource ownership, and failure behavior come from the API contract, not from how short its call looks.

These checks explain why release year, runtime support, and API behavior must be evaluated separately.


## Why It Matters

Modern APIs make common contracts explicit: `toSorted` returns a sorted copy, `Promise.withResolvers` exposes promise settlement functions, and grouping helpers build keyed collections. Choose by the required behavior and supported runtime. A copying array method preserves the previous outer array but still allocates and shares nested objects; it does not guarantee a performance win.

**Concretely:**

1. **Less boilerplate** — `Promise.withResolvers()` removes the `let resolve, reject` dance for hand-rolled promises
2. **Explicit copying** — `toSorted`, `toReversed`, `toSpliced`, and `with` (ES2023) return a new outer array, useful when a state update must preserve the previous array
3. **Native grouping** — `Object.groupBy`/`Map.groupBy` (ES2024) replace `_.groupBy` and reduce loops
4. **Host-supported deep cloning** — `structuredClone` handles Dates, Maps, Sets, RegExps, ArrayBuffers, and cycles
5. **Better ergonomics** — `findLast`, `findLastIndex`, `Symbol.description` remove common papercuts

## Choose the operation before the release year

A dashboard needs an independent sorted array, grouped records, and a handoff of binary upload data. The important questions are ownership and timing: does the operation mutate the original, preserve nested identity, start work, or detach another owner's buffer? Release years organize the API list below; runtime support must be checked per feature, and TypeScript's lib declarations do not install missing runtime methods.


### Modern Syntax Foundations (ES2020–2021): `?.` and `??`

These two operators predate this file's ES2022+ focus, but they're load-bearing in every modern codebase — and the two gotchas (`?.` short-circuits the whole chain; `??` only guards `null`/`undefined`, not `0` or `''`) are perennial interview traps.

```typescript
// Optional chaining (?.) — short-circuits to undefined at the FIRST nullish link
const city = user?.address?.city;          // undefined if user OR address is nullish
const first = list?.[0];                    // works for arrays/indexed access
const result = maybeFn?.(arg);              // skips a nullish function, not a non-callable value

// Optional chaining does NOT short-circuit assignments — and the left side
// of `=` must not be optional-chained (SyntaxError):
// user?.name = 'x'; // SyntaxError

// Nullish coalescing (??) — falls back ONLY on null/undefined
const port = config.port ?? 3000;           // 0, '', false all pass through
const name = input.name ?? 'anonymous';

// The classic || vs ?? bug:
const volume = 0;
volume || 50;   // 50  ← WRONG if 0 is a valid volume
volume ?? 50;   // 0   ← correct: 0 is not nullish

// Combined (?. + ??): the idiomatic default-from-deep-property line
const theme = prefs?.appearance?.theme ?? 'system';
```

Senior-level note: `a?.b` evaluates to `undefined` when `a` is nullish — so
`a?.b ?? 'default'` and `a?.b || 'default'` differ exactly when the property is
`0`, `''`, or `false`. Choosing deliberately (and being able to say which and
why) is the interview signal.

### ES2022 language features and the separate structured-clone host API

Run independent snippets in a supporting runtime; the deliberately throwing line must not precede later examples in one uninterrupted script. structuredClone is a host API, not an ES2022 language addition. Its supported graph/prototype/cycle contract is taught in the [copying chapter](../04-memory-and-data/10.1.4.03-shallow-vs-deep-copy.md); this section contrasts that host operation with class-field and module syntax.

```typescript
// structuredClone — deep clone with cycle and type support
const original = {
  date: new Date(),
  map: new Map([['k', 'v']]),
  set: new Set([1, 2, 3]),
  regex: /foo/g,
};
const clone = structuredClone(original);
// clone.date instanceof Date === true
// clone.map instanceof Map === true
// structuredClone can even clone cycles
const a: { self: unknown } = { self: null };
a.self = a;
const c = structuredClone(a); // works! JSON.parse(JSON.stringify(a)) throws instead

// Old way (lossy + unsafe)
// JSON.parse(JSON.stringify(a)); // Intentionally throws on cycle; run separately.

// Class fields (public/private)
class Counter {
  count = 0; // public field
  #privateField = 'secret'; // truly private (hard private)
  static instances = 0; // static field
}
// Hard privacy is engine-enforced, not a naming promise: outside the class
// `counter.#privateField` is a SyntaxError and `counter['#privateField']` is undefined,
// where the old `_underscore` convention relied on everyone playing along.

// Top-level await in ESM — no IIFE wrapper needed for async init
const config = await fetch('/api/config').then(r => r.json());
```

### ES2023: Immutable Array Methods

Each copying method makes one independent outer array. Sorting reorders copied entries; reversing changes their order; toSpliced removes/inserts a range; with replaces one index and throws RangeError if the index is outside the array. findLast and findLastIndex scan backward without first making a reversed copy; worst-case search remains O(n). None freezes nested objects. For multi-digit numbers, default sorting compares strings, so supply a numeric comparator. These methods read sparse holes as `undefined` and write dense results; some `slice`/`splice` alternatives preserve holes, while spread-copying also turns them into `undefined`.

```typescript
const nums = [3, 1, 4, 1, 5, 9, 2, 6];

// .toSorted() — returns new sorted array, original untouched
const sorted = nums.toSorted(); // [1, 1, 2, 3, 4, 5, 6, 9]
const desc = nums.toSorted((a, b) => b - a); // [9, 6, 5, 4, 3, 2, 1, 1]

// .toReversed() — returns new reversed array
const reversed = nums.toReversed();

// .toSpliced() — returns new spliced array
const withoutFirst = nums.toSpliced(0, 1); // [1, 4, 1, 5, 9, 2, 6]

// .with() — returns new array with one element replaced
const replaced = nums.with(2, 99); // [3, 1, 99, 1, 5, 9, 2, 6]

// .findLast() and .findLastIndex() (ES2023) — search from end
const lastEven = nums.findLast(n => n % 2 === 0); // 6
const lastEvenI = nums.findLastIndex(n => n % 2 === 0); // 7

// In React/Redux, an in-place sort can mutate the previous state snapshot and keep the same array identity.
// These methods copy the outer array; nested object references are shared.
```

### ES2024: Grouping, Promises, ArrayBuffer, RegExp `v` Flag

Grouping computes one key per input item and appends that original item to the key's array. Object.groupBy converts keys to property keys and returns an object without Object.prototype; call Object.hasOwn rather than expecting grouped.hasOwnProperty. Map.groupBy retains key identity, so distinct object keys can represent distinct groups. Both share the original item objects.

Promise.withResolvers creates a pending promise and the functions that settle it; it does not start a task or cancel one. The timeout wrapper below rejects its returned promise if the deadline wins, clears its timer when the input settles, and still leaves underlying work running. Buffer transfer instead changes data ownership: all sender-side views of the original buffer are affected by detachment.

```typescript
// Object.groupBy() — group by string/symbol key, returns a null-prototype object
const inventory = [
  { name: 'asparagus', type: 'vegetables' },
  { name: 'bananas', type: 'fruit' },
  { name: 'goat', type: 'meat' },
  { name: 'cherries', type: 'fruit' },
  { name: 'fish', type: 'meat' },
];

const grouped = Object.groupBy(inventory, item => item.type);
// {
// vegetables: [{ name: 'asparagus', type: 'vegetables' }],
// fruit: [{ name: 'bananas', type: 'fruit' }, { name: 'cherries', type: 'fruit' }],
// meat: [{ name: 'goat', type: 'meat' }, { name: 'fish', type: 'meat' }],
// }

// Map.groupBy() — same but returns a Map (preserves insertion order, any key type)
const byType = Map.groupBy(inventory, item => item.type);

// Promise.withResolvers() — no more "let resolve, reject" boilerplate
const { promise, resolve, reject } = Promise.withResolvers();

// Use case: deadline on the returned result, not operation cancellation
function withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
  if (!Number.isFinite(ms) || ms < 0) throw new RangeError('Invalid timeout');
  const { promise, resolve, reject } = Promise.withResolvers<T>(); // all three!
  const timer = setTimeout(() => reject(new Error('Timeout')), ms);
  p.then(v => { clearTimeout(timer); resolve(v); },
         e => { clearTimeout(timer); reject(e); });
  return promise;
}

// ArrayBuffer.prototype.transfer() / transferToFixedLength()
// Detach the original buffer and return a new one with the same byte contents.
// This is an in-agent ownership transfer; postMessage(value, [buffer]) is the worker-transfer operation. Physical zero-copy behavior is not a JavaScript guarantee.
const source = new Uint8Array([1, 2, 3, 4]).buffer;
const dest = source.transfer(); // source is now detached (byteLength 0)

// RegExp `v` flag (unicodeSets) — set notation inside character classes:
// subtraction, intersection, and multi-code-point properties in one class.
/^[\w--\d]+$/v.test('abc'); // true  — alphanumerics MINUS digits
/^[\w--\d]+$/v.test('a1');  // false — the \d half is subtracted away
/^[\w--\d]+$/.test('a1');   // true  — WITHOUT v, `--` are literal hyphens
                             //          and \d still applies: same text,
                             //          different language
```

Other ES2024 additions matter at specific boundaries: resizable `ArrayBuffer`s and growable `SharedArrayBuffer`s let an owner change capacity under their API rules; `Atomics.waitAsync` waits without blocking the calling agent; `String.prototype.isWellFormed()` and `toWellFormed()` detect or replace lone UTF-16 surrogates. Resizing a buffer can invalidate fixed-length views or change length-tracking views, and `waitAsync` still needs an atomic state protocol. These are not implied by the array-grouping or transfer methods above.

### ES2025: Iterator Helpers, Set Methods, RegExp Utilities, Promise.try and Binary16

Iterator helpers wrap a synchronous iterator lazily: next pulls values through map/filter until take's limit is met. They do not add these methods to every arbitrary object with next; use Iterator.from for a compatible plain iterator when necessary. In the example, source values 0, 1, 2, 3, 4 become 0, 2, 4, 6, 8; the filter passes 0, 4, 8, and take stops after those three. Reusing the same consumed iterator continues/ends its state rather than restarting it.

Set union collects membership from either input, intersection from both, difference from the left only and symmetricDifference from exactly one. The result is a new Set; subset testing instead returns a Boolean. Equality remains SameValueZero, so different object identities are not merged just because their fields match. RegExp inline modifiers affect only a group, while duplicate named groups are permitted on appropriate disjoint alternatives; they do not authorize two participating captures with the same name in one alternative.

```typescript
// Iterator helpers — lazy transformations on supported synchronous iterator objects
function* numbers(n: number) {
  for (let i = 0; i < n; i++) yield i;
}

const evens = numbers(10)
  .map(x => x * 2)
  .filter(x => x % 4 === 0)
  .take(3); // Lazy: nothing runs until iteration
console.log([...evens]); // [0, 4, 8]

// New Set methods — set algebra without manual loops
const a = new Set([1, 2, 3]);
const b = new Set([3, 4]);
a.union(b);        // Set {1, 2, 3, 4}
a.intersection(b); // Set {3}
a.difference(b);   // Set {1, 2}
a.symmetricDifference(b); // Set {1, 2, 4}
a.isSubsetOf(b);   // false

// Inline pattern modifiers — scope flags to part of a pattern (ES2025)
/(?i:hello)/.test('HELLO'); // true — case-insensitive only inside the group
/(?i:hello)/.test('hello'); // true
/(?-i:abc)/i.test('ABC');   // false — this section OPTS OUT of the /i flag
/(?-i:abc)/i.test('abc');   // true
// No need to rebuild from `re.source` + re.flags — the scope is written
// into the pattern itself.

// Duplicate named capture groups — reuse the same name on alternatives
const locale = /(?<year>\d{4})-(?<month>\d{2})|(?<month>\d{2})\/(?<year>\d{4})/;
const m = '03/2026'.match(locale);
m?.groups?.year; // '2026'
m?.groups?.month; // '03'

// RegExp.escape protects literal input when constructing a pattern.
const prefix = 'a.b';
const startsWithLiteral = new RegExp(`^${RegExp.escape(prefix)}`);
startsWithLiteral.test('a.b result'); // true; the dot is literal

// Promise.try converts a synchronous return/throw to a promise result.
// The callback itself is called immediately; promise reactions remain asynchronous.
const parsed = Promise.try(() => JSON.parse('{"ok":true}'));
const failed = Promise.try(() => { throw new Error('sync failure'); });
void failed.catch(error => console.log(error.message)); // handle the rejection

// Float16Array stores IEEE 754 binary16 values in platform byte order.
const half = new Float16Array([1.5, 0.1]);
Math.f16round(0.1); // rounds to the nearest representable binary16 value
```

ES2025 standardizes import-attribute syntax; the host defines how a module type such as JSON is loaded. In a supporting host, `import data from './data.json' with { type: 'json' }` makes the requested type explicit, while loader support and bundler configuration still matter. Float16 APIs are useful when an interchange format or graphics/ML workload needs binary16; they can lose precision and do not promise faster arithmetic.

The methods and syntax above have independent compatibility timelines. Check each API's browser/Node matrix and test the deployed runtime; syntax support must be checked at parse/build time rather than by executing a guarded unsupported literal.

### ES2026: Async Collection, Iterator Composition, and Safer Data Boundaries

ES2026 adds several useful standard-library operations. `Array.fromAsync` consumes an async or sync iterable into an array and returns a promise. With a mapping callback, it awaits each mapped result. A custom async iterator may return a promise as its value, which Array.fromAsync retains when there is no mapper. Async generators adopt a yielded promise at their own yield boundary; that value is already fulfilled before Array.fromAsync receives it. With a mapper, each mapper result is awaited. `Iterator.concat` lazily yields values from its input iterables in order; it does not collect them into an array.

```javascript
async function* asyncSource() {
  yield 1;
  yield 2;
}
const values = await Array.fromAsync(asyncSource(), value => value * 2);
console.log(values); // [2, 4]

const combined = Iterator.concat([1, 2], new Set([3, 4]));
combined.next(); // { value: 1, done: false }; later sources are consumed on demand
```

Other additions address narrower boundaries:

| API | Contract | Boundary to remember |
| ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| `Map`/`WeakMap.getOrInsert` and `getOrInsertComputed` | Return an existing value or insert a default when the key is absent. | A present `undefined` is still present; the computed form avoids building an unused default. |
| `JSON.parse` reviver context and `JSON.rawJSON` | An unmodified primitive can expose its original source text to a reviver; `JSON.rawJSON` wraps valid JSON primitive text for raw insertion by `JSON.stringify`. | The parsed Number may already have lost precision; use `context.source` to reconstruct large integers. `rawJSON` rejects arrays and objects. |
| `Uint8Array` base64/hex methods | Convert between byte arrays and encoded strings. | These operate on bytes; choose the right alphabet, padding, and validation policy for the wire format. |
| `Math.sumPrecise` | Sum an iterable of Numbers with less rounding error than a naive left-to-right sum. | It still returns a Number, not an exact decimal or arbitrary-precision result. |
| `Error.isError` | Identify Error objects across realms. | `instanceof Error` can fail when an error comes from another realm, such as an iframe. |

```javascript
const cache = new Map([['present-but-undefined', undefined]]);
cache.getOrInsert('present-but-undefined', 0); // undefined: the key exists
cache.getOrInsertComputed('items', () => []); // compute only if absent

const record = JSON.parse('{"id":9007199254740993}', (key, value, context) =>
  key === 'id' && /^\d+$/.test(context.source) ? BigInt(context.source) : value
);
record.id; // 9007199254740993n, before Number precision loss is accepted

const encoded = JSON.stringify({ id: JSON.rawJSON(record.id.toString()) });
encoded; // '{"id":9007199254740993}' — the digits stay a JSON number token

Math.sumPrecise([1e16, 1, -1e16]); // 1; a Number, not a decimal-money type
Uint8Array.fromBase64('SGk=').toHex(); // '4869'
Error.isError(new TypeError('bad input')); // true
```

Treat the feature list as an API map, not a compatibility promise. Check the runtime and type declarations actually deployed by the application.

### Hashbang belongs at the start of source; Symbol.description predates it

```javascript
#!/usr/bin/env node
console.log('runs as a CLI');
```

Save that as a separate file: the hashbang comment belongs at the start of script or module source, before ordinary comments and statements. Hashbang grammar was standardized in ES2023. `Symbol.description` arrived in ES2019:

```javascript
const sym = Symbol('my description');
console.log(sym.description); // my description
```

## Code Examples

### A React array update keeps the previous snapshot intact

```tsx
import { useState } from "react";
export function SortedNumbers() {
  const [items, setItems] = useState([3, 1, 2]);
  return <section>
    <button onClick={() => setItems(previous => previous.toSorted((a, b) => a - b))}>
      Sort ascending
    </button>
    <p>{items.join(", ")}</p>
  </section>;
}
```

The returned array is new; nested object elements would still be shared. A non-mutating array method is not a deep immutable update system.

### Cancellation already belongs to fetch's signal contract

`Promise.withResolvers` creates a promise plus its resolving functions; it does not make work cancellable. Forward the caller's signal directly to an abort-aware API:

```typescript
function fetchWithCancel(url: string, signal: AbortSignal): Promise<Response> {
  return fetch(url, { signal });
}
```

Wrapping this fetch in another resolver pair adds an abort listener, an already-aborted race and cleanup responsibilities without adding cancellation. See [Web Workers](10.1.6.02-web-workers.md) for worker lifetimes, and the [canonical cancellation chapter](../03-async-concurrency/10.1.3.05-abort-and-cancellation.md) for request ownership and custom reasons.

### Real-World: Group Orders by Status

```typescript
type Order = { id: string; status: 'pending' | 'shipped' | 'delivered'; amount: number };
const orders: Order[] = [
  { id: "a", status: "pending", amount: 20 },
  { id: "b", status: "shipped", amount: 15 },
  { id: "c", status: "pending", amount: 30 },
];

// ES2024: native grouping, no lodash needed
const byStatus = Map.groupBy(orders, o => o.status);

const pending = byStatus.get('pending') ?? [];
const totalPending = pending.reduce((sum, o) => sum + o.amount, 0);
console.log(totalPending); // 50
```

## Adopt by contract and runtime

Before using a new feature, ask whether it mutates or copies, whether nested values remain shared, whether it starts or cancels work, and what happens at failure or ownership boundaries. Then verify method support in the deployed runtime and syntax support in the build target. Measure the full workload when a claim is about performance; a shorter call is not evidence of faster code.

## Summary

Recent editions provide copying array methods, grouping and Set helpers, synchronous iterator composition, async collection, `RegExp.escape`, promise utilities, import attributes, and binary16 typed arrays. ES2026 also adds safer default insertion, loss-aware JSON reviver context, byte-string conversion, more accurate numeric summation, and cross-realm error detection. Host APIs such as `structuredClone` have their own support boundary. Select an API for its contract and check that specific syntax or method in the deployed runtime. A shallow array copy, graph clone, async collection, and buffer transfer have different identity, scheduling, and ownership consequences.

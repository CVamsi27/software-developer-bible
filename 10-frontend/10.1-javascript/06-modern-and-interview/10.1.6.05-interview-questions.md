# JavaScript Interview Questions

Use this bank after the learning chapters and [separate revision](REVISION.md). Answer with a rule, a short trace and a changed condition; use the source groups below to resolve uncertainty.

## First Principles

This set probes the JS engine's contract with the developer (→ 10.1.1–10.1.4):

1. **The senior tells are mental-model answers**: predicting event-loop order, explaining closure captures, reasoning about coercion outcomes from the rules (→ 10.1.4.09) — deriving behavior, not recalling trivia.
2. **Modern-surface questions** test whether the model distinguishes language editions, host APIs, and runtime support (→ 10.1.6.01–04).

## Why It Matters

Senior JavaScript interviews test deep understanding, not surface recall. Knowing the difference between "this is a closure" and being able to trace the call stack, predict the output of async code, or explain why `Promise.all` is preferred over sequential awaits is what separates senior from mid-level.

## 62 JavaScript Interview Questions

### Modern API Questions (12 Questions — ES2022–ES2026 and React)

Sources: [Modern Features](10.1.6.01-es2024-features.md).

**Q51: Why can a TypeScript build accept a standard method that is missing in production?**

A: Type declarations describe what a target should provide; they do not install the runtime method. Check syntax support in the build target and built-in support in every deployed runtime, then ship a tested fallback or raise the supported floor.

**Q52: Name three things ES2025's iterator helpers let you do that classic array methods don't.**

A: (1) **Lazy evaluation** — `numbers(1e9).map(f).filter(p).take(3)` never materializes intermediate arrays and can stop early (`take`/`every` short-circuit); array methods would process all billion items first. (2) **Infinite sequences** — a generator producing primes, IDs, or a synchronous generated sequence composes with `map`/`filter`/`take` without ever holding everything in memory. (3) **Non-array iterables** — Map/Set iterators and generators support the pipeline; wrap a compatible plain iterator with `Iterator.from` rather than assuming every iterable exposes helper methods. Helpers are synchronous, not an async event-stream API.

**Q53: When is `Object.groupBy` the wrong choice over `Map.groupBy`?**

A: Use `Map.groupBy` when key identity or type must survive grouping. `Object.groupBy` converts callback results to string or symbol property keys, so numeric `1` and string `'1'` share a group, and ordinary object keys can collide through string conversion. `Map.groupBy` preserves distinct object identities and iterates keys in insertion order. Symbol keys are valid in `Object.groupBy`; a non-string result alone is not a reason to reject it.

**Q54: What problem does `Promise.withResolvers()` solve, and when would you still hand-roll?**

A: It returns the promise and its settlement functions together, so a callback owner can settle work awaited elsewhere. It neither starts work nor cancels it. Exposure across modules is an ownership/API choice possible with either construction form; use the executor form when setup naturally belongs inside the executor or when the runtime lacks `withResolvers`.

**Q55: What changed about `ref` in React 19, and what does that mean for `forwardRef`?**

A: React 19 lets a function component receive `ref` as a prop and pass it to a DOM element or use `useImperativeHandle`, so new function components do not need `forwardRef` for that purpose. Older React versions still need it; class-component refs have their own instance behavior. `forwardRef` remains available, so compatibility requirements decide whether to retain a wrapper. See [React's guidance](https://react.dev/reference/react/forwardRef).

**Q56: When does `Array.fromAsync` await values from its input, and when does it await the mapper?**

A: It returns a promise that consumes an async or sync iterable in order. For a sync iterable, each yielded value is awaited; for an async iterable, a yielded promise is retained as a value when no mapper is supplied. If a mapper is supplied, its result is awaited. Use an async generator or an explicit mapper when the desired promise-unwrapping behavior needs to be clear.

**Q57: What does `Iterator.concat` do lazily, and how is it different from array concatenation?**

A: It creates a synchronous iterator that yields from each supplied iterable in order as the consumer requests values. It does not materialize an array or accept an async stream; source iterators can remain untouched until iteration reaches them. Use array concatenation when eager array values and indexing are required.

**Q58: How do `Map.getOrInsert` and `getOrInsertComputed` treat a key mapped to `undefined`?**

A: They treat the key as present and return its `undefined` value; absence is determined by membership, not by the result of `get`. `getOrInsert` receives an already-evaluated default expression, while `getOrInsertComputed` invokes its callback only when insertion is needed. Use the computed form for expensive defaults.

**Q59: How can a JSON reviver recover an integer that `JSON.parse` cannot represent exactly as a Number?**

A: For a primitive reviver value, ES2026 supplies a third context argument whose `source` property contains that value's original JSON text. A reviver can pass a digit-only source to `BigInt` before the rounded Number is used. This preserves the token's integer value, but the application must define which fields and formats are accepted; it does not make every JSON number an arbitrary-precision value.

**Q60: What does `Math.sumPrecise` improve, and what limitation remains?**

A: It sums an iterable of Numbers with one correctly rounded result instead of accumulating each intermediate floating-point rounding error. The result is still a Number, so it does not provide decimal arithmetic for money or arbitrary precision; use an integer minor-unit or decimal representation when that is the domain contract.

**Q61: Why use `Error.isError` instead of `value instanceof Error` at a cross-realm boundary?**

A: `instanceof` follows a realm-specific prototype chain, so an Error created in another iframe or VM may fail the check. `Error.isError` checks the built-in Error brand across realms; it does not establish that the error is trusted or safe to display.

**Q62: What do the `Uint8Array` base64 and hex methods add over `atob`/`btoa`?**

A: They convert between a byte array and an encoded string directly, avoiding the Latin-1 string bridge used by `atob`/`btoa`. Base64 methods support standard or URL-safe alphabets and explicit decoding policies; choose options that match the wire format and reject malformed data as required.

### Beginner Level (10 Questions)

Sources: [Execution & Scope](../01-execution-and-scope/INDEX.md).

**Q1: What is JavaScript?**

A: JavaScript is the language used to express computations in engines embedded in browsers, Node and other hosts. Engines can interpret and compile it. One JavaScript agent runs one active synchronous evaluation at a time; workers and host I/O add concurrency. The host supplies APIs such as the DOM or filesystem.

**Q2: What are the different data types in JavaScript?**

A: The language types are Undefined, Null, Boolean, String, Symbol, Number, BigInt and Object. Arrays, callable functions, Dates and Maps are object kinds, not additional primitive types. Copying an object value preserves the same object identity.

**Q3: What is the difference between `let`, `const`, and `var`?**

A:

- `var`: Function-scoped, hoisted and initialized to `undefined`, reassignable
- `let`: Block-scoped, hoisted but uninitialized (TDZ), reassignable
- `const`: Block-scoped, hoisted but uninitialized (TDZ), not reassignable

**Q4: What is hoisting?**

A: Hoisting is a shorthand for declaration setup before statements in the applicable scope; source code does not move. Function entry, block entry and module linking perform different setup steps. A block binding is created when entering its block, not universally when the outer function starts. `var` bindings are created and initialized to `undefined`, function declarations are created with their complete body (so they can be called before their line appears), and `let`/`const`/`class` bindings are created but left uninitialized behind the Temporal Dead Zone, so reading one early throws a ReferenceError.

**Q5: What is the difference between `==` and `===`?**

A: `===` rejects mismatched types and compares matching values under strict equality. `==` applies type-dependent rules, not a universal conversion of both sides: `null == undefined` is true, while neither equals zero. Distinct objects compare by identity even with `==`; `NaN` is unequal to itself with either operator.

**Q6: What are closures?**

A: A closure is a function that retains access to its outer scope's variables even after the outer function has returned. Closures are created every time a function is created.

**Q7: What is `this` in JavaScript?**

A: For an ordinary function, the way it is called supplies `this`, often the object a method should operate on. A plain strict call uses `undefined`; a property call such as `obj.method()` uses `obj`; `call`, `apply` and `bind` can supply an explicit value. Construction has its own rules. An arrow uses the surrounding `this` rather than getting one from its call. The value need not be an object.

**Q8: What is the event loop?**

A: The event loop schedules work in the surrounding runtime. It runs eligible tasks and reaches checkpoints for queued microtasks such as promise callbacks. Browser loops also coordinate rendering opportunities. Tasks cannot interrupt active synchronous JavaScript, and browser and Node scheduling rules differ.

**Q9: What is the difference between synchronous and asynchronous code?**

A: Synchronous evaluation runs until it returns or throws; queued callbacks cannot interrupt it. An async operation can complete later through a callback or promise, allowing the current caller to continue. Promise executors and an async function's pre-await work still execute synchronously.

**Q10: What are Promises?**

A: A promise represents an eventual result with pending, fulfilled and rejected states. Settlement happens once, but resolving to another pending promise can adopt its eventual result. `.then` creates a new promise; return/throw in its handler determines that downstream result. A promise alone provides no cancellation.

### Intermediate Level (10 Questions)

Sources: [Objects and receivers](../02-objects-prototypes-this/INDEX.md), [DOM Events](10.1.6.03-dom-events-delegation.md).

**Q11: How are primitive values and object values passed to a function?**

A: JavaScript passes every argument by value. For an object, that value identifies the same object, so the callee can mutate it and the caller observes the mutation; assigning the parameter to a different object does not reassign the caller's variable. “Pass by reference” is therefore misleading for JavaScript parameters.

**Q12: What is prototypal inheritance?**

A: Ordinary objects can use a **prototype chain** for property lookup. If the object does not own a property, lookup follows its internal `[[Prototype]]` link to another object. A `null` link ends the chain. This internal link is different from a constructor function's `.prototype` property.

**Q13: What is the difference between `map`, `filter`, and `reduce`?**

A:

- `map`: Transforms each element, returns new array
- `filter`: Selects elements based on condition, returns new array
- `reduce`: Accumulates elements into a single value

**Q14: What is destructuring?**

A: Destructuring is a syntax that unpacks values from arrays or properties from objects into distinct variables: `const { name, age } = person;`

**Q15: What are template literals?**

A: Template literals use backticks and `${expression}` syntax for string interpolation: `` `Hello, ${name}!` ``

**Q16: What is the spread operator?**

A: Array/call spread consumes an iterable, such as `[...set]`. Object spread instead copies own enumerable properties, including symbols, into a new object; it does not require an iterable or copy its prototype. Both preserve nested object identities, so neither is a general deep copy.

**Q17: What is async/await?**

A: An `async` function returns a promise. `await` pauses that function, then resumes it with a fulfilled value or throws the rejection reason inside it. The calling thread can continue other work while the function waits. It does not move an expensive calculation to another thread.

**Q18: What are the different ways to create objects?**

A: Object literals `{}`, constructor functions `new Func()`, `Object.create()`, class syntax `class Foo {}`, and factory functions.

**Q19: What is event delegation?**

A: A stable ancestor routes a propagating event by inspecting its target and finding a matching descendant. Bubbling works for clicks; non-bubbling events require capture or a bubbling alternative. Guard target shape, containment and action data, and remove the ancestor listener when its owner ends.

**Q20: What is the difference between `null` and `undefined`?**

A: `undefined` can be a default initialized value, a missing property result or an explicit value. `null` is another primitive commonly used for intentional absence. An uninitialized lexical binding throws rather than returning `undefined`; the application schema decides which absence representation is valid.

### Senior Level (15 Questions)

Sources: [Async](../03-async-concurrency/INDEX.md), [Memory](../04-memory-and-data/INDEX.md), [Functional Patterns](../05-functional-patterns/INDEX.md).

**Q21: Explain the execution context and scope chain.**

A: An execution context tracks an active or resumable evaluation. Its `LexicalEnvironment` (LE) starts identifier lookup; its `VariableEnvironment` (VE) supplies the applicable `var` declaration boundary. These are record references, not two separate memory buckets. A block can change LE while VE stays at the function boundary, and name reads still follow the same outer-record lookup chain.

Record kinds describe where bindings come from: Declarative records model declared names; Function and Module records specialize that model; Object records resolve eligible names through properties; Global records combine object-backed and declarative bindings. They are different models, not five stores inside every context. Default parameter initializers can capture a parameter binding distinct from a same-named body `var`; trace that case in [Execution Context](../01-execution-and-scope/10.1.1.01-execution-context.md#parameter-and-body-bindings-can-differ), then review the record roles in [Lexical Environment](../01-execution-and-scope/10.1.1.05-lexical-environment.md).

**Q22: What is the difference between call, apply, and bind?**

A:

- `call`: Invokes function with specific `this` and individual arguments
- `apply`: Invokes function with specific `this` and arguments array
- `bind`: Returns new function with `this` permanently bound

When a bound function is called with `new`, construction creates the new instance and ignores the bound `this`; bound arguments still precede call-time arguments.

**Q23: How does garbage collection work in JavaScript?**

A: Collection is an engine policy, not one language-mandated algorithm. Reachability tracing starts at roots and finds live objects; an unreachable cycle is collectible. Generational collectors exploit typical short lifetimes, while barriers record references relevant to partial collections. Collection timing and finalizers are not deterministic cleanup.

**Q24: What is the difference between debouncing and throttling?**

A: Debouncing delays execution until a pause in calls. Throttling limits execution to once per interval. Debounce for search, throttle for scroll.

**Q25: How do you prevent memory leaks?**

A: Find the owning root and dispose resources when that owner ends: remove listeners, clear timers and bound caches. Compare heap snapshots after repeating the same completed lifecycle; inspect retaining paths. Weak references fit optional cache/metadata contracts, not guaranteed cleanup or essential ownership.

**Q26: What is the difference between shallow and deep copy?**

A: A shallow copy creates a new outer container while retaining nested identities. A graph clone creates independent supported objects and must preserve cycles and internal alias relationships. `structuredClone` supports many built-ins but rejects functions; JSON serialization has a different, lossy contract.

**Q27: Explain the module system (CommonJS vs ES Modules).**

A: CommonJS typically evaluates a required module synchronously and returns its exports value; destructured properties are ordinary copied values. ESM links static imports to live exported bindings before evaluation. Loading and top-level await are host/graph dependent; static import is not equivalent to an async function call. Bundler tree shaking depends on analyzable usage and side effects.

**Q28: What are generators and their use cases?**

A: A synchronous generator can pause at `yield` and resume when its iterator is advanced. It supports lazy synchronous sequences and state machines. An `async function*` is a separate async-generator form for values produced over time; a synchronous iterator helper is not an async stream pipeline.

**Q29: How does `this` work in arrow functions vs regular functions?**

A: Arrow functions don't have their own `this` - they inherit from the enclosing lexical scope. Regular functions have `this` based on how they're called.

**Q30: What is memoization and when should you use it?**

A: Memoization reuses a result for an equivalent input key. Require purity or include every changing dependency (tenant, locale, version) in the key. Bound retention and choose result ownership; caching a mutable result shares it. Promise/API caching needs separate rejection, freshness and authorization policies.

**Q31: Explain the event loop phases in Node.js.**

A: Node coordinates timers, pending callbacks, internal idle/prepare, poll, check (`setImmediate`) and close callbacks. Promise microtasks and next-tick callbacks are not separate loop phases. In ordinary CommonJS scheduling a next-tick queue is drained before promise microtasks; ES module evaluation already runs through microtasks, so the same top-level snippet can differ. Timer/check ordering also depends on I/O context and runtime version.

**Q32: What is the difference between iteration and recursion?**

A: Iteration stores progress explicitly in loop state; recursive calls store progress in call frames and can hit stack limits at deep input sizes. Recursion can mirror tree or divide-and-conquer structure more directly, but use an explicit stack or queue when depth is unbounded. Do not rely on portable tail-call optimization to prevent overflow.

**Q33: How do you implement immutability in JavaScript?**

A: Establish ownership first. Copy each changed path without mutating shared state; unchanged paths can retain identity. `Object.freeze` protects only that object's own surface, not nested objects or a Map's internal entries. A readonly TypeScript type is also not runtime enforcement.

**Q34: What is currying and when is it useful?**

A: Currying transforms a function with multiple arguments into a series of functions each taking one argument. Useful for partial application and function composition.

**Q35: Explain the difference between microtasks and macrotasks.**

A: Browser task queues schedule timers and events. At a microtask checkpoint, promise reactions and `queueMicrotask` callbacks drain, including newly queued microtasks, before later tasks can run. Recursive microtasks can starve rendering/tasks. A task boundary creates an opportunity to handle other work, not a guaranteed paint; Node has additional ordering rules.

### FAANG-style (10 Questions)

Sources: [Memory patterns](../04-memory-and-data/INDEX.md), [Bounded Concurrency](../03-async-concurrency/10.1.3.06-bounded-concurrency.md).

**Q36: Design a debounce function from scratch.**

A: Reset a pending timer on each call, retain the latest arguments/receiver, and invoke after the quiet period. Specify leading/trailing, cancellation and flush behavior before implementing. With calls at 0/30/90 ms and wait 100 ms, trailing-only invokes at 190 ms. Use the [canonical implementation and edge trace](../04-memory-and-data/10.1.4.04-debounce.md); an async callback still owns its rejection.

**Q37: Implement a memoization function with LRU cache.**

A: Use an explicit key function and a capacity-bounded Map. A hit, including an `undefined` value, moves its key to the recent end; insertion evicts the oldest when needed. At capacity two, A/B/A/C leaves A and C. Validate capacity and the input-equivalence contract. Use [Memoization](../05-functional-patterns/10.1.5.02-memoization.md) for the canonical implementation; JSON stringification is not a universal key.

**Q38: Design an event emitter class.**

A: Implement `on`, `off`, `emit` methods using a Map to store listeners by event name.

```typescript
class EventEmitter {
  private listeners = new Map<string, Set<(...args: unknown[]) => void>>();

  on(event: string, callback: (...args: unknown[]) => void) {
    if (!this.listeners.has(event)) {
      this.listeners.set(event, new Set());
    }
    this.listeners.get(event)!.add(callback);
    return () => this.off(event, callback);
  }

  off(event: string, callback: (...args: unknown[]) => void) {
    const group = this.listeners.get(event);
    group?.delete(callback);
    if (group?.size === 0) this.listeners.delete(event);
  }

  emit(event: string, ...args: unknown[]) {
    for (const cb of [...(this.listeners.get(event) ?? [])]) cb(...args);
  }
}

```

Register A and B on `saved`, emit once, unsubscribe A, then emit again: the callbacks run A/B then B. This implementation snapshots listeners; removal during dispatch affects the next emission. Duplicate function registration is deduplicated by Set. A synchronous callback error stops the current emission and propagates; async callbacks need their own rejection handling.

**Q39: Implement a deep clone function.**

A: Define the supported object graph before coding. `structuredClone` is the usual platform option for supported data. A custom plain-record/array clone must remember each original before visiting children so cycles and aliases resolve to the same cloned node; reject unsupported native objects/accessors under that contract. Use the [canonical constrained clone](../04-memory-and-data/10.1.4.03-shallow-vs-deep-copy.md).

**Q40: Design a promise-based task scheduler with concurrency control.**

A: Use a queue, track running tasks, process queue when slots available.

```typescript
class TaskScheduler {
  private queue: (() => Promise<any>)[] = [];
  private running = 0;

  constructor(private maxConcurrent: number = 5) {
    if (!Number.isSafeInteger(maxConcurrent) || maxConcurrent < 1) {
      throw new RangeError("positive concurrency required");
    }
  }

  async add<T>(task: () => Promise<T>): Promise<T> {
    return new Promise((resolve, reject) => {
      this.queue.push(async () => {
        try {
          this.running++;
          resolve(await task());
        } catch (e) {
          reject(e);
        } finally {
          this.running--;
          this.processQueue();
        }
      });
      this.processQueue();
    });
  }

  private processQueue() {
    while (this.running < this.maxConcurrent && this.queue.length) {
      this.queue.shift()!();
    }
  }
}

```

At capacity two, enqueue tasks A/B/C: A and B increment `running` synchronously before awaiting, so C waits until one finishes. Each returned promise settles with its own task result; one failure does not stop other tasks. This pedagogical queue has no queue-size bound, cancellation or whole-batch failure policy. Those contracts belong to [Bounded Concurrency](../03-async-concurrency/10.1.3.06-bounded-concurrency.md).

**Q41: Implement a reactive state management system.**

A: While an effect reads properties, associate it with the keys read. A write notifies those dependencies; before rerunning, remove old dependencies so conditional branches stop observing obsolete keys. Schedule/deduplicate effects, avoid recursive feedback, and expose disposal. A retained raw target can bypass proxy tracking.

**Q42: Design a custom React hook for data fetching.**

A: Start the request in an effect, decode successful responses and represent loading/data/error explicitly. Cleanup aborts owned I/O and prevents an obsolete request publishing after inputs change. Abort is cooperative; guard stale publication even if a server or helper ignores it. Handle the rejection in the launched async function.

**Q43: Implement a pub/sub system with wildcard support.**

A: Specify whether a wildcard matches one segment or an entire suffix before writing the matcher. Emit against a subscription snapshot so unsubscribe/add-during-dispatch has defined behavior. Define duplicate registration, callback failures and ordering; return an unsubscribe handle and delete empty groups.

**Q44: Design a rate limiter.**

A: A sliding window counts attempts within a defined recent interval; a token bucket replenishes credits at a fixed rate up to capacity, allowing a bounded burst. Use a monotonic time source where possible and define which attempts consume credit. Multiple processes need shared atomic accounting; a per-tab map cannot enforce a global user quota.

**Q45: Implement a dependency injection container.**

A: Register providers by token, recursively resolve their dependencies, and track the active resolution path to report cycles. Decide singleton, request or transient ownership and disposal before caching instances. A missing registration is a clear error; asynchronous factories require a separate promise-aware resolution contract.

### Follow-up Questions (5 Questions)

Sources: [Memory Leaks](../04-memory-and-data/10.1.4.06-memory-leaks.md), [Cross-Tab Communication](10.1.6.04-cross-tab-communication.md).

**Q46: How would you optimize a React application that's re-rendering too much?**

A: Profile the slow interaction first, then distinguish expensive computation, broad state/context updates and large DOM lists. Keep state close to its users; virtualize long lists; cache measured expensive pure work. Stable props can let `memo` skip work, but inline functions are not automatically a problem and caching cannot guarantee rendering never occurs. Code splitting addresses loading cost rather than every update. Recheck the same interaction after the change.

**Q47: Explain how you would debug a memory leak in a production application.**

A: Repeat one completed lifecycle, allow equivalent idle/collection conditions, and compare heap snapshots. Find growing retained objects and follow paths back to roots such as a window listener or global cache. Remove the owning reference and repeat the lifecycle. A detached node alone is not proof of a leak, and nonstandard `performance.memory` is neither portable nor a retaining-path diagnosis. See [Memory Leaks](../04-memory-and-data/10.1.4.06-memory-leaks.md).

**Q48: How would you implement optimistic UI updates?**

A: Apply a predicted result and attach it to a mutation identity/version. When the server confirms, reconcile with its authoritative response. If it fails, undo only that mutation: restoring an old whole-state snapshot can erase a later successful edit. Retries need the server's idempotency contract.

**Q49: Design a caching strategy for a web application.**

A: Define the key, owner, freshness requirement, capacity and invalidation rule for each layer. HTTP headers govern browser/CDN reuse; a client query cache handles view data; a service worker can provide offline response policy; a server cache reduces upstream work. Include authorization/tenant dependencies and avoid caching private responses as public. A TTL limits age, not memory or correctness during permission changes.

**Q50: How would you handle authentication in a single-page application?**

A: Start with the authoritative server session and protected-operation checks. Choose a session/credential model, then implement expiry, refresh or rotation if that model needs them, logout invalidation and safe startup revalidation. HttpOnly cookies prevent direct script reads but cookie-authenticated operations need CSRF defenses; bearer-token models have different storage/exposure risks. Cross-tab messages invalidate UI and never grant access. Inactivity logout and multi-factor challenges are product/security requirements, not automatic consequences of using a JWT. See [Cross-Tab Communication](10.1.6.04-cross-tab-communication.md) for session-generation-aware invalidation.

# Keyof & Typeof

## Definition

- **`keyof`** produces a type describing the permitted property keys of an object type. The result is often a union: a set of alternatives, such as `"name" | "age"`. Keys can also be numbers or symbols.
- **`typeof`** can refer to the static type of an existing variable or property. Here it appears where TypeScript expects a type, such as after a type alias's `=`. This differs from JavaScript's runtime `typeof` expression. Type queries cannot contain arbitrary function calls.

> **Textbook Definition:** `keyof` derives the allowed property-key type from another type. Type-position `typeof` derives a type from a value declaration; runtime `typeof` instead evaluates to a string describing a value's runtime category.

```text
value declaration settings = { port: 3000, host: "localhost" }
  typeof settings               -> { port: number; host: string }
  keyof typeof settings         -> "port" | "host"
  (typeof settings)["port"]      -> number
```

The first step queries the compiler's description of a value; the second selects legal names; the third looks up one property's value type. None enumerates or reads the object at runtime. `settings.port` is the actual runtime property read.

## First Principles

A generic accessor needs one relationship to survive type checking: the selected key must constrain the returned property type. If every key is widened to `string`, the checker cannot connect a particular choice to its value type. Likewise, a type that describes a runtime configuration can be derived from that value's declared shape, but a separately authored schema may be the real source of truth instead.

1. **Keep the key and result correlated.** Constrain a key to the object's known keys, then index the object type by that specific key. A misspelling fails statically; optional or unchecked indexed reads can still yield `undefined` at runtime.
2. **Choose the right source of truth.** Query a value's static type when the value is canonical. Keep an independently authored type or runtime schema when it intentionally defines the contract instead.
3. **Do not confuse type relations with runtime work.** These operators do not enumerate object properties, prove ownership or validate input. TypeScript erases the relation; JavaScript still performs any actual property read or runtime check.

A key union describes a static contract, not a runtime enumeration. For a string index signature, `keyof { [key: string]: number }` includes `string | number`; a unique-symbol property contributes that symbol's type. For a union, `keyof` describes keys safely present across its alternatives rather than every possible alternative key. An index signature permits an arbitrary key but does not prove that the particular key is stored. `noUncheckedIndexedAccess` helps direct reads, but a generic accessor returning `T[K]` can still overstate a missing dictionary value.

## Why It Matters

For a closed, named shape, `keyof` supports a type-safe accessor (`function get<T, K extends keyof T>(obj: T, key: K): T[K]`) that connects a chosen key to its declared value type. An index-signature dictionary needs a missing-result type because the key constraint does not prove storage. Type-position `typeof` can derive a type from a runtime constant when that value is the intended source of truth.

## How a key determines its value type

Check each independent example as a TypeScript module with strict checking (see the [compiler setup](10.2.1.04-tsconfig-compiler-options.md)). Browser navigation examples need an actual page. Lines annotated `@ts-expect-error` demonstrate intentional rejected calls.

### Derive the legal keys before indexing a value

```typescript
// Extract keys as union
interface User {
  name: string;
  age: number;
  email: string;
}

type UserKeys = keyof User;
// "name" | "age" | "email"

// Use in generic functions
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user: User = { name: "Alice", age: 30, email: "a@b.com" };
const userName = getProperty(user, "name"); // string
const age = getProperty(user, "age"); // number

```

This signature is useful for a closed named shape. A dictionary lookup needs an absence result because its index signature does not prove presence:

```typescript
function getDictionaryValue<V>(dictionary: Readonly<Record<string, V>>, key: string): V | undefined {
  if (!Object.hasOwn(dictionary, key)) return undefined;
  return dictionary[key]; // noUncheckedIndexedAccess also reflects possible absence here
}
```

`keyof Record<string, V>` includes arbitrary strings; it does not turn dynamic storage into an exhaustive object. If inherited entries are part of the contract, use an explicit `in` check and document that boundary instead of claiming own-property lookup.

### Query a value's static type rather than repeating its shape

```typescript
// Extract type of a value
const config = {
  host: "localhost",
  port: 3000,
  debug: true
};

type Config = typeof config;
// {
// host: string;
// port: number;
// debug: boolean;
// }

// Use with class instances
class User {
  constructor(
    public name: string,
    public email: string
  ) {}
}

const user = new User("Alice", "a@b.com");
type UserType = typeof user; // User

// Use with functions
function createUser(name: string) {
  return { name, createdAt: new Date() };
}

type CreateUserReturn = ReturnType<typeof createUser>;
// { name: string; createdAt: Date }

```

### Each legal key can drive a derived property

A mapped type visits the key alternatives and creates a member per key. For User, the name step adds `name: boolean`, age adds `age: boolean`, and email adds `email: boolean`. An indexed access such as User[K] instead preserves that key's original value type. [Mapped Types](../03-type-transformations/10.2.3.03-mapped-types.md) owns the complete modifier/remapping mechanism.

```typescript
// Create type with all properties set to a specific type
type KeyedValues<K extends PropertyKey, T> = {
  [P in K]: T;
};

interface User {
  name: string;
  age: number;
  email: string;
}

// All properties as booleans
type UserFlags = KeyedValues<keyof User, boolean>;
// {
// name: boolean;
// age: boolean;
// email: boolean;
// }

// All properties as optional
type PartialUser = {
  [K in keyof User]?: User[K];
};

```

### A derived name can keep, rename or remove a key

Here string keys become getter names: name becomes getName and retains the original string result type. `string & K` drops number/symbol keys from the template expression; it does not convert their runtime values to strings. The nullable filter retains a property when null is assignable to its value type, which requires strict null checking for the intended distinction.

```typescript
// Transform keys using `as`
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

interface User {
  name: string;
  age: number;
}

type UserGetters = Getters<User>;
// {
// getName: () => string;
// getAge: () => number;
// }

// Filter keys
type NullableKeys<T> = {
  [K in keyof T as null extends T[K] ? K : never]: T[K];
};

interface Mixed {
  name: string;
  age: number;
  phone: string | null;
}

type Nullable = NullableKeys<Mixed>;
// { phone: string | null }

```

### typeof with keyof

```typescript
// Combine typeof and keyof for type-safe property access
const routes = {
  home: "/",
  about: "/about",
  contact: "/contact"
} as const;

type Route = keyof typeof routes;
// "home" | "about" | "contact"

function navigate(route: Route): void {
  window.location.href = routes[route];
}

navigate("home"); // ok
navigate("about"); // ok
// @ts-expect-error A name outside the route key union is rejected.
navigate("missing");

```

## Code Examples

### Practical Patterns

```typescript
// ─── Type-safe object manipulation ────────────────────────────
function pick<T extends object, K extends keyof T>(obj: T, keys: readonly K[]): Pick<T, K> {
  const result = {} as Pick<T, K>;
  for (const key of keys) {
    if (key in obj) {
      Object.defineProperty(result, key, {
        value: obj[key], enumerable: true, writable: true, configurable: true,
      });
    }
  }
  return result;
}

const user = { name: "Alice", age: 30, email: "a@b.com" };
const preview = pick(user, ["name", "email"]);
// { name: string; email: string }

// An event map correlates one selected name with its payload type.
interface AppEvents {
  "user:created": { userId: string };
  "order:placed": { orderId: string; amount: number };
}
function logEvent<K extends keyof AppEvents>(event: K, payload: AppEvents[K]): void {
  console.log(event, payload);
}
logEvent("user:created", { userId: "123" });
// @ts-expect-error The selected event requires a userId.
logEvent("user:created", { orderId: "o1", amount: 10 });

// ─── Type-safe configuration ──────────────────────────────────
const defaultConfig = {
  host: "localhost",
  port: 3000,
  debug: false,
  logLevel: "info"
} as const;

type ConfigKey = keyof typeof defaultConfig;
type ConfigValue = typeof defaultConfig[ConfigKey];

function getConfig<K extends ConfigKey>(key: K): (typeof defaultConfig)[K] {
  return defaultConfig[key];
}

// `as const` preserves these literal values, so ConfigValue is the
// literal union — a plain (non-const) object would give string/number/boolean.
const host = getConfig("host"); // "localhost"
const port = getConfig("port"); // 3000

```

The pick helper copies only keys present on the source, including inherited keys, and defines each result as an own data property; a missing optional key stays absent. A key named `__proto__` is copied as data. Its assertion is an internal construction claim: only requested, present keys are populated. Reads can invoke getters or proxy traps; the helper does not preserve descriptors/prototypes or validate untrusted data. A wider union-valued event name needs its correlated payload checked as a discriminated message, rather than assuming the generic call itself validates pairing. [Advanced Patterns](../04-advanced-patterns/10.2.4.05-advanced-patterns.md) owns the emitter implementation.

### Advanced Patterns

```typescript
// ─── Type-safe property accessor ──────────────────────────────
type PropertyAccessor<T> = {
  [K in keyof T]: {
    get: () => T[K];
    set: (value: T[K]) => void;
  };
};

// Object.keys cannot prove it has every keyof T: optional, symbol,
// inherited or non-enumerable properties have different runtime rules.
// Access one explicit key without claiming an exhaustive runtime registry.
function createAccessor<T extends object, K extends keyof T>(obj: T, key: K) {
  return {
    get: (): T[K] => obj[key],
    set: (value: T[K]): void => { obj[key] = value; },
  };
}
const editable = { count: 1 };
const countAccessor = createAccessor(editable, "count");
countAccessor.set(2);
console.log(countAccessor.get()); // 2
// This API intentionally permits writes; use a getter-only API for readonly data. Types do not prove a runtime property is writable: a frozen object or setter can reject or transform assignment.

// ─── Type-safe enum-like objects ──────────────────────────────
const Status = {
  Active: "ACTIVE",
  Inactive: "INACTIVE",
  Pending: "PENDING"
} as const;

type StatusValue = typeof Status[keyof typeof Status];
// "ACTIVE" | "INACTIVE" | "PENDING"

function isValidStatus(value: string): value is StatusValue {
  return Object.values(Status).includes(value as StatusValue);
}

// Route parameter construction belongs to the template-literal chapter.
// A cast cannot manufacture a params object that the implementation never created.
```

## Real-World Use Cases

- **Typed config objects** — `keyof typeof CONFIG` gives you a literal union of config keys; typo a key and the compiler catches it before the env var is ever read (→ 20.2.4.01).
- **Event/route name registries** — `typeof handlers` maps names to payload types; `keyof typeof handlers` is the event union (the `TypedEventEmitter` backbone, → 10.2.4.05).
- **Record-building helpers** — `Record<keyof Settings, string>` forces new config fields to update every derived map at compile time.

## Common Mistakes

### 1. Using keyof Where It Produces Noise

```typescript
// `keyof string` compiles — but it returns the entire method surface
type Bad = keyof string;
// "toString" | "charAt" | "concat" | "indexOf" | ... (never what you want)

// Correct: keyof the object type you actually own
interface User { name: string; age: number; }
type Keys = keyof User; // "name" | "age"

```

### 2. Not Constraining Generic Keys

```typescript
// Bad: No constraint on K
function getProp<T, K>(obj: T, key: K) {
  // @ts-expect-error K might not be a key of T.
  return obj[key];
}

// Good: Constrain K
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

```

### 3. Forgetting typeof Returns the Value Type

```typescript
// Confusion: typeof returns the type of the VALUE
const str = "hello";
type T1 = typeof str; // "hello" (the literal type), not string

// To get the primitive type, use string directly
type T2 = string; // string

```

## Best Practices

1. **Derive when the value is the source of truth** — use `keyof` and `typeof` to avoid maintaining a parallel description; use an explicit type when it represents a broader contract than one particular value.
2. **Constrain generic keys** — `K extends keyof T` turns a typo'd key into a compile error and yields the precise `T[K]` return type.
3. **Distinguish keys from values** — `keyof typeof` already preserves literal property names on an ordinary object. `as const` preserves literal values and readonly properties in the type system; it does not freeze the object at runtime.
4. **Remap with `as`** — key remapping (`[K in keyof T as ...]`) renames, prefixes, and filters keys in one pass; combine with conditional types for "keys whose value matches X".
5. **Mind the union size** — `keyof` on a very large or deeply-chained type produces a large union; prefer the narrowed key set you actually index (`keyof Pick<T, …>`) when only a subset matters.

## Performance Considerations

- Both operators resolve entirely at compile time — there is no runtime cost, and no emitted code differs.
- Checker cost depends on the whole type graph, including union size, repeated mapped/conditional operations and instantiation depth; the keyword alone is not a useful performance diagnosis. Reduce unnecessary complexity, then profile with compiler diagnostics or a trace.
- A named alias (`type Config = typeof defaultConfig`) can keep error output readable; `typeof` alone does not establish that a large derived type is cheap to check.

## Summary

`keyof` derives a type's permitted keys; type-position `typeof` captures the static type of a value declaration. Together, they support enum-like literal unions, type-safe accessors (`obj[K]`) and mapped transformations without duplicating a shape when the value is its source of truth. Runtime input still needs validation, and a readonly type does not freeze the runtime object.

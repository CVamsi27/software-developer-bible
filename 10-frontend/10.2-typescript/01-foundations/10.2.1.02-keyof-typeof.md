# Keyof & Typeof

A settings panel reads values by a selected key. If the key is misspelled, the call should fail during type checking; if the key comes from user input, the program must still check that it exists at runtime. `keyof` and type-position `typeof` connect a value's declared shape to its legal keys without confusing that static relationship with a runtime lookup.

```typescript
function get<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}

const user = { name: "Ada", age: 30 };
get(user, "name"); // string
// get(user, "emali"); // rejected: key outside the contract
```

## Definition

**`keyof T`** produces the property-key type described by `T` — often a union like `"host" | "port"`. **Type-position `typeof value`** asks TypeScript for the static type of an existing value declaration, distinct from JavaScript's runtime `typeof`, which evaluates to a string. Neither performs runtime enumeration, access, or validation.

> **Textbook Definition:** `keyof` derives the permitted property-key type from another type, while a type-position `typeof` query derives a static type from a value declaration. Neither performs runtime enumeration, access or validation.

```text
const settings = { host: "localhost", port: 3000 } as const
  typeof settings           -> { readonly host: "localhost"; readonly port: 3000 }
  keyof typeof settings     -> "host" | "port"
  (typeof settings)["port"] -> 3000
```

## First Principles

Preserve the key-to-value relationship: constrain the key, then index the object type with that specific key. Query a runtime value with `typeof` only when that value is the intended source of truth — a broader API contract or runtime schema may intentionally live elsewhere. And remember that static keys prove nothing about untrusted input at runtime: TypeScript erases these relations, so JavaScript must still perform the read and its validation.

## 1. Derive a Legal Key and Its Value Type

```typescript
export {};
interface User {
  name: string;
  age: number;
  email?: string;
}

function get<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}

const user: User = { name: "Ada", age: 30 };
const name = get(user, "name"); // string
const email = get(user, "email"); // string | undefined
// @ts-expect-error A key outside User's contract is rejected.
get(user, "emali");
```

The optional property contributes `undefined` to the read type. For a union, `keyof` gives the keys safe to use on every member; alternative-only fields become available after narrowing by a discriminant. A string index signature admits broad keys, and `keyof Record<string, V>` includes both `string` and `number` because JavaScript coerces numeric property access to strings.

A dictionary's key type does not prove that an entry is stored. Model absence in the return type and check the runtime contract:

```typescript
function readLabel(labels: Readonly<Record<string, string>>, key: string): string | undefined {
  if (!Object.hasOwn(labels, key)) return undefined;
  return labels[key];
}
```

`noUncheckedIndexedAccess` also makes direct indexed reads reflect possible absence, but a generic `T[K]` accessor can still describe only the declared type. Use an absence-aware API for sparse dictionaries rather than treating an index signature as proof of presence.

## 2. Derive a Union from a Value That Is the Source of Truth

```typescript
export {};
const routes = {
  home: "/",
  users: "/users",
  settings: "/settings",
} as const;

type RouteName = keyof typeof routes;
type RoutePath = (typeof routes)[RouteName];
// RouteName: "home" | "users" | "settings"
// RoutePath: "/" | "/users" | "/settings"

function pathFor(route: RouteName): RoutePath {
  return routes[route];
}
pathFor("users");
// @ts-expect-error A name not in the route object is rejected.
pathFor("missing");

function isRouteName(value: unknown): value is RouteName {
  return typeof value === "string" && Object.hasOwn(routes, value);
}
```

`as const` preserves literal values and readonly types for the checker; it does not freeze the object at runtime. An ordinary `keyof typeof routes` still preserves the keys, but mutable string values widen to `string`. Runtime configuration should be validated separately if it comes from a file, environment or request.

Type-position `typeof` refers to a declaration or its property; it cannot query the result of an arbitrary call. Runtime `typeof routes` instead evaluates to `"object"`. Use `ReturnType<typeof makeRoute>` when the intended type is a function's return, or define a schema/type at the source that owns that contract.

## 3. Let the Key Set Drive a Transformation

A mapped type visits a key union and produces a property for each key. The `as` clause can rename or filter those keys; the full transformation rules belong in [Mapped Types](../03-type-transformations/10.2.3.03-mapped-types.md).

```typescript
export {};
type NullableKeys<T> = {
  [K in keyof T as null extends T[K] ? K : never]: T[K]
};

interface Account {
  id: string;
  nickname: string | null;
}
type NullableAccountFields = NullableKeys<Account>;
// { nickname: string | null }
```

This filter asks whether `null` is assignable to the property's type, so `strictNullChecks` must be enabled for nullability to have its intended meaning. `keyof` and `typeof` create type relationships; a runtime `Object.keys()` call is different: it returns enumerable own string keys and may omit symbols, inherited properties and non-enumerable properties.

## Summary

`keyof` derives permitted keys, type-position `typeof` derives a static type from a value declaration, and indexed access (`T[K]`) connects one selected key to its value type. Use these relations to avoid duplicated contracts when one value is canonical. Validate dynamic keys and external data at runtime; a type query does not read or prove the object.

# Type Narrowing

## TL;DR

Type narrowing is the process of refining a type based on control flow: `typeof` guards, `instanceof` checks, `in` operator, discriminated unions, type predicates (`x is T`), and assertion functions. It is what makes TypeScript feel like a runtime-checked language.

## First Principles

Narrowing exists because a union's safety depends on *proving* which member you hold:

1. **The compiler tracks control flow, not just declarations** — an `if (typeof x === 'string')` re-types `x` in the branch: the type is a function of the path, which is what makes unions (→ 10.2.1.01) usable at all.
2. **Every narrowing mechanism is a runtime check the compiler understands** — `typeof`, `in`, `instanceof`, discriminants (→ 10.2.2.03), predicates — write the check you'd write anyway and the type follows.
3. **Assertions (`as`) are the escape hatch that *disables* the proof** — use them only where the human knows something the checker can't; every `as` is an unverified claim.

## Why It Matters

Senior engineers design discriminated unions (`type Shape = { kind: 'circle'; r: number } | { kind: 'square'; s: number }`) to enable exhaustive narrowing with `switch`/`never`. They write type predicates (`function isUser(x: unknown): x is User`) to validate external data (API responses, JSON.parse).

## Definition

**Type narrowing** is the process of refining a broader type into a more specific type through control flow analysis, type guards, and other TypeScript mechanisms. It allows you to safely work with specific types within conditional blocks.

## How It Works

### typeof

```typescript
// Narrow primitive types
function processValue(value: string | number | boolean): string {
  if (typeof value === "string") {
    return value.toUpperCase(); // string methods available
  } else if (typeof value === "number") {
    return value.toFixed(2); // number methods available
  } else {
    return value ? "true" : "false"; // boolean
  }
}

```

### instanceof

```typescript
// Narrow class instances
class HttpError {
  constructor(public status: number, public message: string) {}
}

class NetworkError {
  constructor(public message: string, public code: string) {}
}

function handleError(error: HttpError | NetworkError): string {
  if (error instanceof HttpError) {
    return `HTTP ${error.status}: ${error.message}`;
  } else {
    return `Network ${error.code}: ${error.message}`;
  }
}

```

### in Operator

```typescript
// Check for property existence
interface Bird {
  fly(): void;
  layEggs(): void;
}

interface Fish {
  swim(): void;
  layEggs(): void;
}

function move(animal: Bird | Fish): void {
  if ("fly" in animal) {
    animal.fly(); // Bird
  } else {
    animal.swim(); // Fish
  }
}

```

### User-Defined Type Guards

```typescript
// Type guard function
interface Cat {
  meow(): void;
  purr(): void;
}

interface Dog {
  bark(): void;
  fetch(): void;
}

function isCat(animal: Cat | Dog): animal is Cat {
  return "meow" in animal;
}

function interact(animal: Cat | Dog): void {
  if (isCat(animal)) {
    animal.meow(); // Cat
    animal.purr(); // Cat
  } else {
    animal.bark(); // Dog
    animal.fetch(); // Dog
  }
}

```

### Discriminated Unions

```typescript
// Union with common discriminant
type Shape =

  | { kind: "circle"; radius: number }
  | { kind: "rectangle"; width: number; height: number }
  | { kind: "triangle"; base: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "rectangle":
      return shape.width * shape.height;
    case "triangle":
      return (shape.base * shape.height) / 2;
  }
}

// Exhaustive check
function assertNever(x: never): never {
  throw new Error("Unexpected value: " + x);
}

function areaExhaustive(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "rectangle":
      return shape.width * shape.height;
    case "triangle":
      return (shape.base * shape.height) / 2;
    default:
      return assertNever(shape); // Compile error if missing case
  }
}

```

### The never Type

```typescript
// never represents values that never occur
function throwError(message: string): never {
  throw new Error(message);
}

function infiniteLoop(): never {
  while (true) {}
}

// Use with exhaustive checking
function processShape(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "rectangle":
      return shape.width * shape.height;
    case "triangle":
      return (shape.base * shape.height) / 2;
    default:
      // shape is never here — every case handled
      const _exhaustive: never = shape;
      return _exhaustive;
  }
}

```

## Code Examples

### Practical Examples

```typescript
// ─── API Response handling ────────────────────────────────────
type ApiResponse<T> =

  | { status: "success"; data: T }
  | { status: "error"; error: string }
  | { status: "loading" };

function handleResponse<T>(response: ApiResponse<T>): string {
  switch (response.status) {
    case "success":
      return `Data: ${JSON.stringify(response.data)}`;
    case "error":
      return `Error: ${response.error}`;
    case "loading":
      return "Loading...";
  }
}

// ─── Type-safe event handling ─────────────────────────────────
type Event =

  | { type: "click"; x: number; y: number }
  | { type: "keypress"; key: string }
  | { type: "scroll"; top: number };

function handleEvent(event: Event): void {
  switch (event.type) {
    case "click":
      console.log(`Click at (${event.x}, ${event.y})`);
      break;
    case "keypress":
      console.log(`Key pressed: ${event.key}`);
      break;
    case "scroll":
      console.log(`Scrolled to ${event.top}`);
      break;
  }
}

// ─── Type-safe parsing ────────────────────────────────────────
function parseJSON<T>(json: string): T | null {
  try {
    return JSON.parse(json) as T;
  } catch {
    return null;
  }
}

function processUser(json: string): void {
  const user = parseJSON<User>(json);
  if (user && typeof user === "object" && "name" in user) {
    console.log(user.name); // TypeScript knows user has name
  }
}

```

### Advanced Patterns

```typescript
// ─── Type-safe reducer ────────────────────────────────────────
type Action =

  | { type: "INCREMENT"; amount: number }
  | { type: "DECREMENT"; amount: number }
  | { type: "RESET" };

interface State {
  count: number;
}

function reducer(state: State, action: Action): State {
  switch (action.type) {
    case "INCREMENT":
      return { count: state.count + action.amount };
    case "DECREMENT":
      return { count: state.count - action.amount };
    case "RESET":
      return { count: 0 };
  }
}

// ─── Type-safe validation ─────────────────────────────────────
interface ValidationSuccess<T> {
  valid: true;
  value: T;
}

interface ValidationFailure {
  valid: false;
  errors: string[];
}

type ValidationResult<T> = ValidationSuccess<T> | ValidationFailure;

function validate(input: unknown): ValidationResult<string> {
  if (typeof input === "string") {
    return { valid: true, value: input };
  }
  return { valid: false, errors: ["Expected string"] };
}

function processInput(input: unknown): void {
  const result = validate(input);
  if (result.valid) {
    console.log(result.value.toUpperCase()); // string
  } else {
    console.error(result.errors); // string[]
  }
}

// ─── Type-safe optional chaining ──────────────────────────────
function getNestedValue(
  obj: Record<string, any>,
  path: string
): string | undefined {
  const keys = path.split(".");
  let current: any = obj;

  for (const key of keys) {
    if (current === null || current === undefined) {
      return undefined;
    }
    current = current[key];
  }

  return typeof current === "string" ? current : undefined;
}

```

## Real-World Use Cases

- **Discriminated API responses** — `if ('error' in res)` / `res.status === 'ok'` narrows before data access; the backbone of every API client (→ 20.3.3.02's error shape).
- **Form field validation** — `typeof value === 'string'` per field drives both runtime checks and the compiled types.
- **Exhaustive switch over state machines** — `default: x satisfies never` turns a missed checkout step into a compile error instead of a dead screen (→ 10.2.4.01).

## Common Mistakes

### 1. Forgetting Exhaustive Checking

```typescript
// Bad: a void handler missing a case compiles — the branch never runs.
// (Value-returning functions at least fail with TS2366 "Function lacks
// ending return statement"; void handlers fail silently.)
function handle(action: Action): void {
  switch (action.type) {
    case "INCREMENT":
      console.log("up");
      break;
    case "RESET":
      console.log("reset");
      break;
    // DECREMENT missing — no error, the event just vanishes
  }
}

// Good: route the now-impossible remainder through assertNever, so
// adding a union member later puts a compile error on this switch.
function handleAll(action: Action): void {
  switch (action.type) {
    case "INCREMENT":
      console.log("up");
      break;
    case "RESET":
      console.log("reset");
      break;
    default:
      assertNever(action); // (from How It Works)
  }
}

```

### 2. Forgetting `typeof null === "object"`

```typescript
interface User {
  name: string;
  email: string;
}

// Bad: `typeof null` is "object", so the guard keeps null in the type
function printUser(user: User | null) {
  if (typeof user === "object") {
    console.log(user.name); // Error: user is possibly null
  }
}

// Good: check the value directly
function printUser(user: User | null) {
  if (user !== null) {
    console.log(user.name); // user: User
  }
}

```

### 3. Not Using Type Guards

```typescript
// Bad: a boolean helper narrows nothing — the call stays `unknown`,
// so the branch needs an assertion to do anything with it
function isString(value: unknown): boolean {
  return typeof value === "string";
}

function handle(value: unknown) {
  if (isString(value)) {
    (value as string).toUpperCase(); // Unsafe!
  }
}
```

```typescript
// Good: declare the claim in the signature (`value is string`) and the
// branch narrows automatically
function isString(value: unknown): value is string {
  return typeof value === "string";
}

function handle(value: unknown) {
  if (isString(value)) {
    value.toUpperCase(); // value: string
  }
}
```

## Best Practices

1. **Model variants as discriminated unions** — one literal `kind`/`status`/`type` field makes every `switch` branch provable and every missed branch visible.
2. **Make exhaustiveness explicit** — route the impossible `default` through `assertNever` (or `x satisfies never`) so a new union member errors on the switch itself, not somewhere downstream.
3. **Prefer guards to assertions** — `typeof`/`instanceof`/`in`/predicates prove the narrowing; `as` only silences the check. Reach for assertions only at boundaries you have verified by hand.
4. **Write validators as predicates** — `function isUser(x: unknown): x is User` makes the check reusable at every call site instead of re-asserting inline.
5. **Mind where narrowing dies** — it is path-sensitive: any reassignment of the variable (even one that seems safe) resets the analysis to the declared type, so a guard followed by a mutation must re-prove the type before the next use.

## Performance Considerations

- Narrowing itself is erased — guards compile to the plain JS check you wrote (`typeof`, `in`, `instanceof`, `===`), so the only runtime cost is that check.
- Control-flow analysis is per-function and re-run at each branch point; extremely long functions with deeply nested guards are the case where the checker slows down, not the guard keyword.
- Exhaustiveness checks (`never` assignments, `satisfies`) are compile-time only — zero bytes, zero cycles.

## Summary

Type narrowing is control flow re-typing: every guard the compiler understands (`typeof`, `instanceof`, `in`, discriminants, predicates) converts a broad union into the member you have just proved. Discriminated unions give you the shape to switch on, `never` makes missing branches a compile error, and assertions are the explicit "I know better" escape — the goal is to need them rarely.

## Revision Questions

**Definition**

1. **Q:** What does it mean to "narrow" a value, and where does the refinement live?
   **A:** You replace a union with the member(s) still possible on the current control-flow path; the refinement exists only in the checker's model of that branch — the runtime value never changes.

2. **Q:** Which everyday operators double as type guards?
   **A:** `typeof` (primitives), `instanceof` (classes), `in` (property presence), and equality against a literal discriminant (`x.status === "ok"`), plus user-defined predicates (`x is T`).

**How It Works**

3. **Q:** Why does `if (typeof user === "object")` still allow `null`?
   **A:** `typeof null` is `"object"`, so the null branch survives the guard — check `user !== null` (or `!= null`) explicitly instead.

4. **Q:** What must a function return for `if (isCat(x))` to narrow `x`?
   **A:** A type predicate — `x is Cat` in the signature — not a plain `boolean`; the boolean version only says yes/no, it claims nothing about the type.

**Code Examples**

5. **Q:** In `default: assertNever(shape)`, what breaks when a new union member is added?
   **A:** The `shape` in that branch is no longer `never`, so the call fails to type-check and the error lands directly on the switch that is missing a case.

**Common Mistakes**

6. **Q:** Why is a `void` handler with an uncovered union member dangerous compared to a value-returning one?
   **A:** The value-returning function fails with `TS2366 Function lacks ending return statement`, but the `void` handler compiles cleanly and silently drops the event.

7. **Q:** After `x = x.trim()` inside a branch that had already narrowed `x`, is the narrowed type kept?
   **A:** No — reassignment resets control-flow analysis to the declared type (`string | null`), so you must re-narrow before using `x` again.

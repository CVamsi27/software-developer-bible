# Infer

A function returns `Promise<User>`, but a caller needs the `User` inside it. A conditional type can match the promise shape and name the inner type with `infer`; the same pattern works for function returns, tuple positions and other known structures.

## Definition

**`infer`** introduces a type variable inside the `extends` pattern of a conditional type. When the checked type matches, the inferred type is available in the true branch.

> **Textbook Definition:** In a conditional type, `infer` binds a type variable to a position that matches part of the checked type. The branch can then return or transform that captured type; a nonmatching type follows the false branch.

## First Principles

A conditional type first tests whether an input has a particular structure. If the result needs one part of that structure, `infer` names it at the point where it matches. Choose the false branch deliberately: preserve a nonmatch, discard it with `never`, or return another fallback.

`infer` is different from call-site inference in [Generics](10.2.2.01-generics.md). Call-site inference chooses a generic argument from function arguments; `infer` captures a slot while a conditional type matches another type. It can be introduced only in the conditional's `extends` pattern, not first in the true branch. Capturing all of `T` is legal but adds no information; capturing one part is useful.

## Capture a part from the matched structure

`Promise<infer Value>` captures the promise's inner type. Returning `T` on a nonmatch makes this helper pass unrelated types through; returning `never` would make it a promise-only extractor.

```typescript
type UnwrapPromise<T> = T extends Promise<infer Value> ? Value : T;

type UserValue = UnwrapPromise<Promise<{ id: string }>>;
// { id: string }
type PlainValue = UnwrapPromise<number>; // number: pass through

type PromisePayload<T> = T extends Promise<infer Value> ? Value : never;
type PayloadOrNothing = PromisePayload<number>; // never
```

The match checks a static type. It does not await, inspect or validate a runtime value. A conditional with a naked type parameter also distributes over unions, so each union member gets its own match and false-branch result.

## Read function and constructor types

The same technique can capture a function's return type, its ordered parameter tuple or the instance produced by a constructor signature.

```typescript
type ReturnValue<T> = T extends (...args: never[]) => infer Result ? Result : never;
type ParametersOf<T> = T extends (...args: infer Params) => unknown ? Params : never;
type FirstParameter<T> =
  T extends (...args: infer Params) => unknown
    ? Params extends [infer First, ...unknown[]] ? First : never
    : never;
type InstanceOf<T> = T extends new (...args: never[]) => infer Instance ? Instance : never;

type Result = ReturnValue<(name: string) => Promise<number>>; // Promise<number>
type Args = ParametersOf<(name: string, age: number) => void>;
// [name: string, age: number]
type Name = FirstParameter<(name: string, age: number) => void>; // string
type NoFirst = FirstParameter<() => void>; // never

class UserModel { constructor(readonly name: string) {} }
type UserInstance = InstanceOf<typeof UserModel>; // UserModel
```

The first-parameter pattern requires a statically present first argument; an optional first tuple member does not match that required position. For overloaded functions, inference utilities generally use the last declared signature rather than selecting an overload from hypothetical call arguments. Use built-in `ReturnType`, `Parameters`, `InstanceType` and `Awaited` when their standard behavior is the desired contract.

## Capture tuple positions explicitly

A tuple pattern can name the head, tail or final item. The required head and tail patterns return `never` for an empty tuple or an open array that cannot guarantee that position.

```typescript
type Head<T extends readonly unknown[]> =
  T extends readonly [infer First, ...unknown[]] ? First : never;
type Tail<T extends readonly unknown[]> =
  T extends readonly [unknown, ...infer Rest] ? Rest : never;
type Last<T extends readonly unknown[]> =
  T extends readonly [...unknown[], infer Final] ? Final : never;

type FirstField = Head<[string, number, boolean]>; // string
type Remaining = Tail<[string, number, boolean]>; // [number, boolean]
type FinalField = Last<readonly [string, number, boolean]>; // boolean
```

The inferred `Tail` is a mutable tuple even when the source is readonly. Preserve modifiers explicitly if the API requires them.

## Extract from a generic wrapper

An API response wraps its data in a generic property. Matching `ApiResponse<infer Data>` recovers the payload type from an existing response contract.

```typescript
type ApiResponse<T> = { data: T; status: number; timestamp: Date };
type DataOf<T> = T extends ApiResponse<infer Data> ? Data : never;

interface User { id: string; name: string; email: string }
const response: ApiResponse<User> = {
  data: { id: '1', name: 'Ada', email: 'a@example.com' },
  status: 200,
  timestamp: new Date(),
};

type UserData = DataOf<typeof response>; // User
```

This recovers the declared type, not the validity of a received JSON object. A runtime decoder must establish that the data really is a `User`. The route-parameter example in [Template Literal Types](../03-type-transformations/10.2.3.04-template-literal-types.md) applies the same capture idea to string segments. Nested property reads and writes belong to [Advanced Generics](10.2.2.03-advanced-generics.md), where their path contract is developed once.

## Recurse only while a match remains

A recursive helper captures the next inner promise and calls itself until the input no longer matches. Returning that terminal input makes the recursion stop; `never` would instead discard it.

```typescript
type DeepUnwrap<T> = T extends Promise<infer Value> ? DeepUnwrap<Value> : T;

type Nested = DeepUnwrap<Promise<Promise<Promise<string>>>>; // string
type Terminal = DeepUnwrap<number>; // number
```

This helper handles `Promise`, not every thenable and nullish edge. Use the built-in `Awaited<T>` when the runtime `await` contract is intended. Keep recursive conditionals shallow enough for the consuming project; very deep nesting or large distributed unions can increase checker work or reach instantiation limits.


## Summary

`infer` names a slot inside a conditional match. Use the capture that represents the part the caller needs, choose a deliberate nonmatch result, and give recursive patterns a terminal case. These types describe structure; runtime code still validates and transforms values.

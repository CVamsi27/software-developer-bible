# Advanced Generics

A pipeline can turn a number into a string and then into a length. Its type must carry each stage's output into the next stage's input. Advanced generics are useful when an API needs to preserve relationships across several types or transformations like this.

## Definition

**Advanced generics** compose type parameters with constraints, inference, conditional types, mapped types, tuples and recursion to express relationships that span an API. They describe static contracts; runtime code still performs the operations.

> **Textbook Definition:** An advanced generic is a parameterized type or operation whose result is computed from constraints and relationships among its type arguments. Its design must preserve the intended relationships while keeping inference, diagnostics and compiler cost manageable.

## First Principles

A type parameter by itself only names an unknown type. A useful generic adds a relationship: an output depends on an input, a property path depends on each key before it, or a function stage must accept the preceding stage's result. Every such promise must match the runtime operation and stop at a defined boundary.

## Represent a family of containers

A generic type constructor such as `Array<T>` accepts another type. TypeScript lets a generic function accept a type parameter, but it does not let you apply an arbitrary parameter `F` as `F<T>`. A keyed type table can represent a known family instead: the key chooses the container while the second parameter supplies its element type.

```typescript
interface URItoKind<A> {
  array: A[];
  promise: Promise<A>;
}

type URI = keyof URItoKind<unknown>;
type Kind<U extends URI, A> = URItoKind<A>[U];

interface Functor<U extends URI> {
  map<A, B>(value: Kind<U, A>, transform: (item: A) => B): Kind<U, B>;
}

const arrayMap: Functor<'array'> = {
  map: (items, transform) => items.map(transform),
};
const promiseMap: Functor<'promise'> = {
  map: (value, transform) => value.then(transform),
};

const names = arrayMap.map([1, 2], String); // string[]
const label = promiseMap.map(Promise.resolve(1), String); // Promise<string>
```

The selected key preserves the outer structure: the array mapping returns an array, and the promise mapping runs after fulfillment and returns a promise. Adding a key requires an implementation. This table is a compile-time encoding, not a runtime constructor or dispatcher. Libraries use this pattern when an operation such as `map` needs a known set of container kinds.

## Follow a path through a nested type

A dot path is a sequence of keys. At each step, check that the next name belongs to the current object, then recurse into that property's type. The same structure can rebuild a type with a changed value, but neither alias reads or writes an object at runtime.

```typescript
type DeepPropertyAccess<T, Path extends string> =
  Path extends `${infer Head}.${infer Rest}`
    ? Head extends keyof T
      ? DeepPropertyAccess<T[Head], Rest>
      : never
    : Path extends keyof T
      ? T[Path]
      : never;

type SetProperty<T, Path extends string, Value> =
  Path extends `${infer Head}.${infer Rest}`
    ? Head extends keyof T
      ? { [K in keyof T]: K extends Head ? SetProperty<T[K], Rest, Value> : T[K] }
      : T
    : Path extends keyof T
      ? { [K in keyof T]: K extends Path ? Value : T[K] }
      : T;

interface Config {
  database: {
    host: string;
    port: number;
    credentials: { user: string; password: string };
  };
}

type Host = DeepPropertyAccess<Config, 'database.host'>; // string
type User = DeepPropertyAccess<Config, 'database.credentials.user'>; // string
type Redacted = SetProperty<Config, 'database.credentials.password', '[redacted]'>;
```

For `database.credentials.user`, the first match selects `database`, the second selects `credentials`, and the final key yields `string`. `SetProperty` reconstructs the containing object types and replaces only the terminal field. These sketches assume required object properties and literal paths; optional children, arrays, missing keys and dots in property names need separate policies. The template-literal chapter derives allowed paths from an object shape; this example answers what one path reads or changes in the type.

## Carry a tuple of function stages through a pipeline

A variadic tuple represents an ordered list of function types. To validate a pipeline, compare adjacent stages: each return type must fit the next parameter. The final result comes from the last function, not from repeatedly checking every stage against the first input.

```typescript
type Unary = (value: any) => any;
type Compatible<Fns extends readonly Unary[]> =
  Fns extends readonly [infer First extends Unary, infer Second extends Unary, ...infer Rest extends Unary[]]
    ? ReturnType<First> extends Parameters<Second>[0]
      ? readonly [First, ...Compatible<readonly [Second, ...Rest]>]
      : never
    : Fns;
type LastResult<Fns extends readonly Unary[]> =
  Fns extends readonly [...Unary[], infer Last extends Unary] ? ReturnType<Last> : never;

function pipe<Fns extends readonly [Unary, ...Unary[]]>(
  ...functions: Fns & Compatible<Fns>
): (value: Parameters<Fns[0]>[0]) => LastResult<Fns> {
  const apply = (value: unknown): unknown =>
    functions.reduce<unknown>((result, fn) => fn(result), value);
  return apply as (value: Parameters<Fns[0]>[0]) => LastResult<Fns>;
}

const formatLength = pipe(
  (value: number) => value + 1,
  (value: number) => String(value),
  (value: string) => value.length,
);
formatLength(9); // 2: 9 -> 10 -> '10' -> 2
// @ts-expect-error The first stage returns number, not string.
pipe((value: number) => value + 1, (value: string) => value.length);
```

The check accepts number → string → number because each stage matches its neighbor. The runtime is an ordinary synchronous unary `reduce`, and the final assertion connects that implementation to the public tuple proof; assertions cannot repair a caller that uses `any`. This example excludes empty pipelines, promises, overloads, optional/rest parameters and multi-argument stages. Runtime currying and its arity rules belong to [Currying and Composition](../../10.1-javascript/05-functional-patterns/10.1.5.04-currying-composition.md).

A curry type is another tuple-to-callable transformation: one required tuple element becomes one unary call stage.

```typescript
type Curry<Args extends unknown[], Result> =
  Args extends [infer First, ...infer Rest]
    ? Rest extends [] ? (arg: First) => Result : (arg: First) => Curry<Rest, Result>
    : () => Result;

const add: Curry<[number, number, number], number> = a => b => c => a + b + c;
add(1)(2)(3); // 6
```

This type covers a fixed tuple of required unary stages. Empty, optional, rest and defaulted arguments need their own contract; `function.length` is not a universal measure of application arity. See the linked runtime chapter for complete currying behavior.

## Recurse through data with an explicit leaf policy

Recursive object types are resolved through a structural position such as a property or array member. A bare alias cycle has no such position and is rejected. A recursive transformation needs both a rule for each supported container and explicit leaves for types whose methods should remain usable.

```typescript
// @ts-expect-error A bare self-reference has no structural position.
type Invalid<T> = Invalid<T> | T;
type LinkedList<T> = { value: T; next: LinkedList<T> } | null;

type DeepReadonly<T> =
  T extends ((...args: any[]) => any) | Date | RegExp ? T :
  T extends readonly unknown[] ? { readonly [K in keyof T]: DeepReadonly<T[K]> } :
  T extends Map<infer K, infer V> ? ReadonlyMap<DeepReadonly<K>, DeepReadonly<V>> :
  T extends Set<infer U> ? ReadonlySet<DeepReadonly<U>> :
  T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> } : T;

type DeepPartial<T> =
  T extends ((...args: any[]) => any) | Date | RegExp ? T :
  T extends readonly (infer U)[] ? DeepPartial<U>[] :
  T extends Map<infer K, infer V> ? Map<K, DeepPartial<V>> :
  T extends Set<infer U> ? Set<DeepPartial<U>> :
  T extends object ? { [K in keyof T]?: DeepPartial<T[K]> } : T;

type DeepFlatten<T> = T extends readonly (infer U)[] ? DeepFlatten<U> : T;
type FlatNumbers = DeepFlatten<readonly number[][]>; // number
```

`DeepReadonly` preserves tuple positions and exposes readonly Map/Set views, but an existing mutable alias can still change the data; a readonly `Date` can still call `setTime`. `DeepPartial` deliberately turns readonly arrays and tuples into mutable arrays of partial elements, so it is not a general immutable patch protocol. These examples support plain data and the listed containers, not every host class. Recursive values can be finite or cyclic; recursive type evaluation still needs a terminating conditional and manageable expansion.

## Check runtime values before trusting static keys

Structural typing permits a value to carry more fields than a narrower view exposes. `keyof` describes that static view; `Object.keys` enumerates own enumerable string keys from the actual object.

```typescript
const actual = { name: 'Ada', extra: 1 };
const view: { name: string } = actual;
Object.keys(view); // ['name', 'extra']
```

An assertion cannot make runtime keys match `keyof` or remove extras. Symbols, non-enumerable properties and inherited names also differ between the two. For runtime grouping, `Map.get` correctly admits a missing group; modern runtimes also provide [Map.groupBy](../../10.1-javascript/06-modern-and-interview/10.1.6.01-es2024-features.md).

## Name shared contracts and keep the computation bounded

Use a named constraint when it expresses a reusable capability; avoid repeating a long inline intersection. A default such as `T = unknown` is useful when callers may omit the type argument without losing safety. Recursive type calculations need a base case, and large unions or deep object graphs can increase editor and compiler work.

```typescript
interface HasId { id: string }
interface User extends HasId { name: string; email: string }

function processUser<T extends User>(value: T): T { return value; }
function keepId<T extends HasId>(value: T): T { return value; }

type Envelope<T = unknown> = { data: T; status: number };
const response: Envelope = { data: null, status: 200 };
```

The body of `keepId` may safely use `id`, while its return type preserves any extra fields in the caller's type. `Envelope` defaults to `unknown`, not `any`, so an omitted payload type still requires narrowing before use. Measure costly types in the consuming project with `tsc --extendedDiagnostics`; simplify them when measurements show material checker or editor work. All these relationships erase from JavaScript, so the runtime implementation must still validate external input, authorize operations and perform the advertised work.

## Summary

Advanced generics preserve relationships across containers, property paths, tuple stages and recursive data. Give each relationship a concrete boundary, check adjacent transitions and define base cases and leaf policies. The type calculation guides callers; runtime code remains responsible for values.

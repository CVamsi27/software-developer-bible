# Conditional Types

## Definition

**Conditional types** are TypeScript types that select types based on conditions, similar to the ternary operator (`? :`) in JavaScript. They enable creating types that depend on type relationships.

> **Textbook Definition:** A conditional type selects a type expression according to an assignability test. When the tested expression is a naked type parameter, union arguments distribute across the branches unless distribution is explicitly suppressed.

```text
ToArray<string | number>
  test string -> string[]
  test number -> number[]
  join results -> string[] | number[]

ToArrayNonDist<string | number>
  one whole-type test -> (string | number)[]
```

The first result describes homogeneous alternatives; the second permits a single mixed array such as ["one",2]. These are different contracts, even though both were derived from the same input union.

## First Principles

Conditional types are the type-level `if`:

1. **A conditional can test union members separately.** In `T extends B ? X : Y`, this happens when the checked side is the type parameter `T` itself, with no wrapper. This is called a naked type parameter. For a union input, TypeScript runs the test on each member and joins the results. `Diff<T, U> = T extends U ? never : T` uses that behavior to remove members assignable to `U`.
2. **`never` contributes no members to a union.** A branch returning `never` therefore removes that member from the result, which is how `Exclude` filters a union. To test the entire input together instead, wrap the checked parameter in a tuple: `[T] extends [B]`.

## Why It Matters

Senior engineers use conditional types to build type-level functions: discriminating payload shapes, extracting Promise inner types, mapping API responses to UI models. The mental model is: `T extends U ? X : Y` is type-level `if/else`. Distributive behavior over unions is the key gotcha.



## How It Works

Check independent snippets in a strict TypeScript module. A conditional tests static assignability, not an actual value's runtime type; implementations and external decoders still need their own correct checks.

### Basic Syntax

```typescript
// Simple conditional type
type IsString<T> = T extends string ? true : false;

type A = IsString<string>; // true
type B = IsString<number>; // false
type C = IsString<"hello">; // true (string literal extends string)

```

### Distributing Over Unions

```typescript
// The naked checked type parameter T makes this conditional distributive
type ToArray<T> = T extends unknown ? T[] : never;

type StrArr = ToArray<string | number>;
// string[] | number[] (distributed)

// To prevent distribution, wrap in tuple
type ToArrayNonDist<T> = [T] extends [unknown] ? T[] : never;
type Result = ToArrayNonDist<string | number>;
// (string | number)[]

```

The special input never has no members to distribute, so ToArray<never> returns never; a wrapped whole-input test can take a true branch. unknown is not assignable to string, while any bypasses normal certainty and can yield both branch alternatives. Avoid using any when a conditional result should prove a relationship.

### Nested Conditionals

```typescript
// Multiple conditions
// Illustrative classifier: its fallback label covers all omitted cases too.
type TypeName<T> =
  T extends string ? "string" :
  T extends number ? "number" :
  T extends boolean ? "boolean" :
  T extends undefined ? "undefined" :
  T extends (...args: any[]) => unknown ? "function" :
  "object";

type A = TypeName<string>; // "string"
type B = TypeName<() => void>; // "function"
type C = TypeName<string[]>; // "object"

```

### The `infer` Keyword

`infer` names a type captured by the assignability pattern for use in the true branch. Inferring a whole parameter tuple distinguishes an empty argument list from an unconstrained first argument: a zero-argument function can satisfy a one-argument function pattern, so the older direct `first: infer F` test yields `unknown` rather than `never`.

```typescript
// Extract type using infer
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

type Fn = () => string;
type Result = MyReturnType<Fn>; // string

// More complex inference
type UnpackPromise<T> = T extends Promise<infer U> ? U : T;

type A = UnpackPromise<Promise<string>>; // string
type B = UnpackPromise<number>; // number

```

## Code Examples

### Practical Examples

```typescript
// ─── Type-safe event handling ─────────────────────────────────
type EventMap = {
  click: { x: number; y: number };
  scroll: { top: number };
  keypress: { key: string };
};

type EventHandler<T extends keyof EventMap> =
  (event: EventMap[T]) => void;

const handleClick: EventHandler<"click"> = (event) => {
  console.log(event.x, event.y); // TypeScript knows event has x, y
};

// ─── Conditional API response ─────────────────────────────────
type ApiResponse<T> =
  T extends "user" ? { name: string; email: string } :
  T extends "post" ? { title: string; content: string } :
  T extends "comment" ? { text: string; author: string } :
  never;

async function fetchData<T extends "user" | "post" | "comment">(
  type: T, parse: (data: unknown) => ApiResponse<T>
): Promise<ApiResponse<T>> {
  const response = await fetch(`/api/${type}`);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const data: unknown = await response.json();
  return parse(data);
}

declare function parseUser(data: unknown): ApiResponse<"user">;
const user = await fetchData("user", parseUser);
// { name: string; email: string }

// Recursive conditional + mapped transforms are implemented in the
// Mapped Types chapter, Code Examples — Advanced Patterns.

// The required-first argument extractor is canonical in Infer.
// Recursive collection flattening is canonical in Advanced Generics.
```

FirstParam and DeepFlatten have their complete implementations and empty/readonly/nonmatch conditions in [Infer](../02-generics-and-inference/10.2.2.02-infer.md) and [Advanced Generics](../02-generics-and-inference/10.2.2.03-advanced-generics.md). The conditional here supplies their branch mechanism.

### Complex Patterns

A computed return type must match the operation: uppercasing a literal string cannot promise the original literal. The `Match` type below reflects that transformation. Removing `?` in the nullable-key map also prevents optional mapped properties from injecting `undefined` into the indexed key union.

```typescript
// ─── Type-safe switch statement ────────────────────────────────
type Match<T, U> = T extends U ? Uppercase<T & string> : U;

function processValue<T extends string | number>(value: T): Match<T, string> {
  if (typeof value === "string") {
    return value.toUpperCase() as Match<T, string>;
  }
  return String(value) as Match<T, string>;
}

// ─── Conditional mapped type ──────────────────────────────────
type NullableKeys<T> = {
  [K in keyof T]-?: null extends T[K] ? K : undefined extends T[K] ? K : never
}[keyof T];

interface User {
  name: string;
  email: string;
  phone: string | null;
  address?: string;
}

type OptionalAndNullableKeys = NullableKeys<User>;
// "phone" | "address"

// ─── Type-safe discriminated union helper ─────────────────────
type Discriminate<U, K extends string, V> =
  U extends { [P in K]: V } ? U : never;

type Shape =

  | { kind: "circle"; radius: number }
  | { kind: "rectangle"; width: number; height: number };

type Circle = Discriminate<Shape, "kind", "circle">;
// { kind: "circle"; radius: number }

type Rectangle = Discriminate<Shape, "kind", "rectangle">;
// { kind: "rectangle"; width: number; height: number }

```

processValue("ada") returns ADA, matching Uppercase<"ada">; a number returns its string form. The implementation assertions connect the declared computed return to those runtime branches, rather than proving them automatically. Validate the branch behavior and keep this helper's string-or-number domain explicit. The nullable-key map selects phone/address under strict null checking, while -? removes incidental optional-read undefined from the resulting key union.

## Real-World Use Cases

- **Response mappers** — `ApiResponse<T extends Resource>` conditional maps a resource name to its payload type; the type-level version of the adapter pattern.
- **Async plumbing** — `Awaited<T>`, `UnwrapPromise<T>` utilities keep promise chains typed through helpers (→ 10.1.3.02's combinators).
- **Fallbacks at type level** — `T extends string ? T : never` narrows generated unions from codegen before they reach public APIs.

## Common Mistakes

### 1. Forgetting Distribution

```typescript
// Unexpected distribution
type IsNever<T> = T extends never ? true : false;
type A = IsNever<never>; // never (not true!)

// Fix: Wrap in tuple to prevent distribution
type IsNeverWhole<T> = [T] extends [never] ? true : false;
type B = IsNeverWhole<never>; // true

```

### 2. Discarding Inferred Return Information

```typescript
// Bad: `any` bypasses type checking
type BadReturnType<T> = T extends (...args: any[]) => any ? any : never;

// Good: Preserve type information
type GoodReturnType<T> = T extends (...args: any[]) => infer R ? R : never;

```

### 3. Overcomplicating Conditionals

```typescript
// Bad: Too many nested ternaries
type Complex<T> =
  T extends string ? "str" :
  T extends number ? "num" :
  T extends boolean ? "bool" :
  T extends null ? "null" :
  T extends undefined ? "undef" :
  T extends (...args: any[]) => unknown ? "func" :
  T extends any[] ? "arr" :
  "obj";

// A smaller helper is valid only when its domain is intentionally restricted
type GetPrimitiveType<T extends string | number | boolean> =
  T extends string ? "str" : T extends number ? "num" : "bool";

```

## Best Practices

```typescript
// 1. Use conditional types for type-safe APIs
type EventHandler<T> = T extends keyof WindowEventMap
  ? (event: WindowEventMap[T]) => void
  : never;

// 2. Combine with mapped types for powerful transformations
type OptionalExcept<T, K extends keyof T> =
  Partial<Omit<T, K>> & Required<Pick<T, K>>;

// 3. Use `infer` to extract types
type ElementOf<T> = T extends readonly (infer E)[] ? E : never;

// 4. Compute a classification; a runtime guard is a separate function
type IsString<T> = T extends string ? true : false;

// 5. Document complex conditional types with comments
/**

 - Extracts the resolved type of a Promise or returns the type itself.
 */
type Resolve<T> = T extends Promise<infer U> ? Resolve<U> : T;

```

## Performance Considerations

Distribution over large unions and deep recursive conditionals can increase checker and editor work or reach compiler limits. The cost depends on the inputs and surrounding types; do not assume a fixed cost per conditional or rely on undocumented caching behavior. Measure with the consuming project’s compiler diagnostics, then reduce the expanded union or recursion depth if it is costly.

## Summary

Conditional types select and compute types through assignability tests. Naked type parameters distribute over unions, tuple wrapping suppresses that behavior, and inference captures pieces of the matched structure; runtime implementations must still fulfill the computed contract.

# Conditional Types

A function that accepts a resource name such as `user` or `post` should return the matching data shape. Conditional types let TypeScript describe that relationship; they do not inspect or validate the response at runtime.

## Definition

**Conditional types** select one type expression when another type is assignable to a tested type, and a second expression otherwise. Their syntax, `T extends U ? X : Y`, resembles a ternary operator, but it runs in the type system and emits no JavaScript.

> **Textbook Definition:** A conditional type evaluates an assignability relation and resolves to one of two type expressions. When its checked side is a naked type parameter, a union argument is evaluated member by member and the branch results are combined.

## First Principles

A generic API often needs to preserve a relationship between an input type and its output. An assignability test gives the type system a way to choose that output. If the input is a union, the author must decide whether each member gets its own result or the union is treated as one whole type.

## Choose a result from an assignability test

In `T extends string ? 'text' : 'other'`, TypeScript checks the relationship between types, not the value passed to a JavaScript function. The result for a literal such as `'Ada'` follows from the fact that the literal type is assignable to `string`.

```typescript
type Label<T> = T extends string ? 'text' : 'other';

type TextLabel = Label<'Ada'>; // 'text'
type NumberLabel = Label<42>; // 'other'
```

This simple branch is enough for a single type. A union introduces a second question: should the branch run once for the whole union or once for each member?

## Decide how a union should be tested

A conditional distributes when its checked side is a naked type parameter. `ToArray<string | number>` therefore means either an array of strings or an array of numbers. Wrapping the parameter in a tuple tests the union as one value and permits a mixed array.

```typescript
type ToArray<T> = T extends unknown ? T[] : never;
type SeparateArrays = ToArray<string | number>;
// string[] | number[]

type ToArrayWhole<T> = [T] extends [unknown] ? T[] : never;
type MixedArray = ToArrayWhole<string | number>;
// (string | number)[]
```

This rule explains two common edge cases. `never` has no union members to visit, so a distributive test of `never` produces `never`; tuple wrapping lets a whole-type test recognize it. `any` can produce both conditional branches, while `unknown` follows ordinary assignability rules. Avoid `any` when the result is meant to prove a precise relationship.

```typescript
type IsNever<T> = [T] extends [never] ? true : false;
type NeverResult = IsNever<never>; // true

type IsString<T> = T extends string ? true : false;
type AnyResult = IsString<any>; // true | false
```

`Exclude<T, U>` uses the same member-by-member behavior: members assignable to `U` become `never`, which removes them from the resulting union. Tuple wrapping is the choice when the question concerns the union as a whole.

## Capture the part that matched

Inside the true branch, `infer` can name a type that matched a pattern. Here it captures the payload field, or the return type of a function, without requiring the caller to repeat that type.

```typescript
type PayloadOf<T> = T extends { payload: infer Payload } ? Payload : never;
type Message = PayloadOf<{ payload: { id: string; text: string } }>;
// { id: string; text: string }

type ReturnValue<T> = T extends (...args: never[]) => infer Result ? Result : never;
type Loaded = ReturnValue<() => Promise<{ id: string }>>;
// Promise<{ id: string }>
```

This return helper captures the declared return type; it does not unwrap a promise. The separate [Infer](../02-generics-and-inference/10.2.2.02-infer.md) chapter develops argument-tuple inference and explains overloaded functions, where utility types such as `ReturnType` use the last declared signature.

## Keep an input and its result connected

A resource-to-response map can make a caller that requests a user receive the user shape, while a post request receives the post shape. The `never` fallback rejects an unsupported resource if the constraint is later widened.

```typescript
type Resource = 'user' | 'post' | 'comment';
type ApiResponse<T extends Resource> =
  T extends 'user' ? { name: string; email: string } :
  T extends 'post' ? { title: string; content: string } :
  T extends 'comment' ? { text: string; author: string } :
  never;

type UserResponse = ApiResponse<'user'>;
// { name: string; email: string }
type PostResponse = ApiResponse<'post'>;
// { title: string; content: string }

type Decoder<T> = (value: unknown) => T;
async function fetchResource<T extends Resource>(
  resource: T,
  decode: Decoder<ApiResponse<T>>,
): Promise<ApiResponse<T>> {
  const response = await fetch(`/api/${resource}`);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const body: unknown = await response.json();
  return decode(body);
}

declare function decodeUser(value: unknown): ApiResponse<'user'>;
const user = fetchResource('user', decodeUser);
// Promise<{ name: string; email: string }>
```

The decoder must check the actual unknown value before returning the declared shape; its signature alone cannot prove its implementation is correct. This is why `fetchResource` takes a decoder instead of asserting that a URL determines the response data. For a complete decoder-based `fetch` contract, see [Generics](../02-generics-and-inference/10.2.2.01-generics.md).

## Filter a discriminated union

A conditional can retain only union members whose discriminant matches a requested value. Because `U` is naked, each member is tested independently and nonmatches disappear as `never`.

```typescript
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'rectangle'; width: number; height: number };

type OfKind<U, K extends PropertyKey, V> =
  U extends { [P in K]: V } ? U : never;

type Circle = OfKind<Shape, 'kind', 'circle'>;
// { kind: 'circle'; radius: number }
```

This computes a static subtype. Runtime code still needs to inspect `kind` before reading variant-specific fields.

## Find keys whose values admit null or undefined

Conditional checks can also be embedded in mapped types. Under `strictNullChecks`, the following keeps keys whose values include `null` or `undefined`. Removing the optional modifier with `-?` matters: otherwise indexing the mapped type can add an unrelated `undefined` to the key union.

```typescript
type NullableKeys<T> = {
  [K in keyof T]-?: null extends T[K]
    ? K
    : undefined extends T[K]
      ? K
      : never
}[keyof T];

interface User {
  name: string;
  phone: string | null;
  address?: string;
}

type OptionalOrNullable = NullableKeys<User>;
// 'phone' | 'address'
```

## Keep type computation readable and bounded

Nested branches are useful when they express a small, stable mapping such as `ApiResponse`. If the conditions classify unrelated cases or grow into a long ladder, split them into named helpers or use a lookup map when it makes the relationship clearer.

Distributing over a large union and recursing through deeply nested types can increase compile and editor work or reach compiler limits. Measure with the consuming project's `tsc --extendedDiagnostics` output before optimizing; the cost depends on the inputs and surrounding types. Runtime guards and decoders remain separate because conditional types do not execute against values.

## Summary

Conditional types select a result by testing assignability. A naked checked type parameter distributes over union members; tuple wrapping tests the whole input. `infer` captures parts of a matching type, but runtime code must still validate values and honor the resulting contract.

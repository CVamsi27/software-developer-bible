# Mapped Types

Suppose every field in a form needs a value, an error and a touched flag. Writing each field by hand repeats the source shape and can drift when a field is added. A mapped type visits the keys of that shape and constructs the related type one property at a time.

```typescript
type FormFieldState<T> = {
  [K in keyof T]: { value: T[K]; error: string | null; touched: boolean };
};

interface LoginForm { email: string; password: string }
type LoginState = FormFieldState<LoginForm>;
// email: { value: string; error: string | null; touched: boolean }
// password: { value: string; error: string | null; touched: boolean }
```

## Definition

**Mapped types** build a new object type by iterating over a set of property keys. For each key, the author chooses its output name, value type and modifiers.

> **Textbook Definition:** A mapped type applies a type transformation to each key in a key set, producing corresponding properties. When mapped from `keyof T`, it can retain source modifiers, replace them, or remap keys with an `as` clause.

## First Principles

A record is a set of key/value relationships. To derive a related record, visit each key, look up its source value with `T[K]`, and decide what the corresponding property should mean. A mapping over `keyof T` starts from an existing shape; a mapping over an independent key union can create a new one.

## 1. Carry Each Source Field into a New Shape

The key variable `K` moves through `keyof T`. `T[K]` retrieves the value type for that key, so each generated field stays connected to its source field.

```typescript
interface LoginForm {
  email: string;
  password: string;
  rememberMe: boolean;
}

type FormFieldState<T> = {
  [K in keyof T]: {
    value: T[K];
    error: string | null;
    touched: boolean;
  };
};

type LoginState = FormFieldState<LoginForm>;
// email: { value: string; error: string | null; touched: boolean }
// password: { value: string; error: string | null; touched: boolean }
// rememberMe: { value: boolean; error: string | null; touched: boolean }

type Feature = 'darkMode' | 'exports';
type FeatureFlags = { [K in Feature]: boolean };
// { darkMode: boolean; exports: boolean }
```

The first map follows an existing object; the second creates properties from a separate finite union. The built-in `Record<Feature, boolean>` expresses the latter contract; the standard utilities and their runtime limits are covered in [Utility Types](10.2.3.01-utility-types.md).

## 2. Change Modifiers While Retaining Keys

A direct map over `keyof T` retains the source's optional and readonly modifiers unless the mapping changes them. A `?` adds optionality, `-?` removes it, and `-readonly` removes the readonly modifier. These operators affect the static contract only.

```typescript
type MutableRequired<T> = {
  -readonly [K in keyof T]-?: T[K];
};

interface SourceConfig {
  readonly host: string;
  port?: number;
}

type EditableConfig = MutableRequired<SourceConfig>;
// { host: string; port: number }
```

Adding `undefined` to a property's value type does not make the property optional. Likewise, `Readonly<T>` does not freeze an object or prevent another mutable alias from changing it.

## 3. Rename or Filter Keys with `as`

An `as` clause can create a new property name or map a key to `never` to omit it. This getter example carries each original value type into its new function. The second map keeps properties that are not wholly callable.

```typescript
type Getters<T> = {
  [K in keyof T as K extends string ? `get${Capitalize<K>}` : never]: () => T[K];
};

interface User {
  name: string;
  age: number;
  greet: () => void;
  maybeLabel: string | (() => string);
}

type UserGetters = Getters<User>;
// getName: () => string; getAge: () => number;
// getGreet: () => () => void; getMaybeLabel: () => string | (() => string)

type NonCallableProperties<T> = {
  [K in keyof T as T[K] extends (...args: never[]) => unknown ? never : K]: T[K];
};

type DataFields = NonCallableProperties<User>;
// name, age, and maybeLabel
```

The `maybeLabel` property remains because the full union is not assignable to a function type. A remapping that uses string templates drops numeric and symbol keys unless it handles them separately. The mapped type also does not install getters or remove a runtime method.

## 4. Build the Mapped Result at Runtime

A type can promise that every source key has a transformed value, but JavaScript must still enumerate and construct those properties. This `mapValues` implementation is valid under a narrow contract: the input is a closed plain record whose required declared fields are own properties.

```typescript
function mapValues<T extends object, U>(
  obj: T,
  fn: (value: T[keyof T], key: string | symbol) => U,
): { [K in keyof T]: U } {
  const result = {} as { [K in keyof T]: U };
  for (const key of Reflect.ownKeys(obj)) {
    Object.defineProperty(result, key, {
      value: fn(obj[key as keyof T], key),
      enumerable: true,
      writable: true,
      configurable: true,
    });
  }
  return result;
}

const user = { name: 'Alice', age: 30, email: 'a@example.com' };
const lengths = mapValues(user, (value) =>
  typeof value === 'string' ? value.length : value,
);
// { name: number; age: number; email: number }
```

`Reflect.ownKeys` includes symbols and non-enumerable fields, and returns numeric property keys as strings. This implementation recreates each found property as enumerable, writable and configurable; it does not preserve descriptors, and reading a getter runs it. `DefineProperty` keeps a key such as `__proto__` as data. Extra runtime keys, missing optional properties or inherited class members can break the claimed result shape, so do not generalize the assertion beyond the stated record contract.

## 5. Combine Mapped and Conditional Types Deliberately

A conditional inside the mapped body can make a decision for each field. This example adds `null` only to string-valued fields. The test checks the whole property type: `string | number` does not wholly extend `string`, so it remains unchanged.

```typescript
type NullableStrings<T> = {
  [K in keyof T]: T[K] extends string ? T[K] | null : T[K];
};

interface Config {
  host: string;
  port: number;
  label: string | number;
}

type NullableConfig = NullableStrings<Config>;
// host: string | null; port: number; label: string | number
```

Recursive mapped types add a separate question: which values should recursion treat as leaves? The [Advanced Generics](../02-generics-and-inference/10.2.2.03-advanced-generics.md) chapter owns the full `DeepPartial` and `DeepReadonly` implementations, including their Date, function, tuple, Map and Set boundaries. Keep a recursive policy domain-specific; a static deep partial is not a runtime merge or a PATCH protocol.

## Summary

A mapped type visits a key set, retrieves or replaces each value type, and can change modifiers or remap names. Trace the source key to its result. Runtime enumeration and construction must satisfy the same assumptions as the static shape.

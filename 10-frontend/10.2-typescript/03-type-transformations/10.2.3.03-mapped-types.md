# Mapped Types

## Definition

**Mapped types** are types that transform existing types by iterating over their keys using `[K in keyof T]` syntax. They allow you to create new types by mapping over every property in a type.

> **Textbook Definition:** A mapped type iterates over a key type to construct properties and their value types. It can preserve or change property modifiers and remap keys, deriving a new object contract from existing structure.

```text
source: { name: string; age: number }
Stringify<T>: visit name -> name:string; visit age -> age:string
Getters<T>:   name -> getName:()=>string; age -> getAge:()=>number
```

The map builds a static property contract one key at a time. The first replaces value types; the second changes names while retrieving the original value type. It does not convert an object's stored values or add getter functions at runtime.

## First Principles

Mapped types are the type-level `for` loop over keys:

1. **Visit each key and choose its value type.** In `{ [K in keyof T]: F<T[K]> }`, `K` is the current key and `T[K]` is its source value type. A mapping that preserves this source structure is called homomorphic. Such maps normally keep optional and readonly modifiers unless the mapping explicitly changes them. `Partial` and `Readonly` change those modifiers.
2. **Change the keys with an `as` clause.** Key remapping can rename a property, omit it by producing `never`, or build a new name using a template literal type. This lets one map control both the property names and their value types.

## Why It Matters

Senior engineers use mapped types to build project-specific utilities: `Getters<T>` (turn values into functions), `Nullable<T>` (describe permitted explicit null values), `DeepReadonly<T>` (recursive readonly views). A PATCH endpoint still needs a separately defined omission/null/merge protocol. The interview signal is being able to author a custom mapped type from scratch.



## How It Works

Check independent snippets with strict null checking. Maps over keyof T preserve its relevant structure/modifiers unless the map explicitly changes them. Runtime examples assume closed plain records whose declared fields are own data; the assertions do not verify that assumption.

### Basic Syntax

```typescript
// Make all properties optional
type Optional<T> = {
  [K in keyof T]?: T[K];
};

interface User {
  name: string;
  age: number;
  email: string;
}

type OptionalUser = Optional<User>;
// {
// name?: string;
// age?: number;
// email?: string;
// }

// Make all properties required
type MyRequired<T> = {
  [K in keyof T]-?: T[K];
};

// Make all properties readonly
type MyReadonly<T> = {
  readonly [K in keyof T]: T[K];
};

```

### Iteration Syntax

```typescript
// Basic iteration
type Stringify<T> = {
  [K in keyof T]: string;
};

interface User {
  name: string;
  age: number;
  email: string;
}

type StringUser = Stringify<User>;
// {
// name: string;
// age: string;
// email: string;
// }

// With constraints
type MyPick<T, K extends keyof T> = {
  [P in K]: T[P];
};

type UserPreview = MyPick<User, "name" | "email">;
// {
// name: string;
// email: string;
// }

```

### Key Remapping with `as`

```typescript
// Transform keys
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

interface User {
  name: string;
  age: number;
}

type UserGetters = Getters<User>;
// {
// getName: () => string;
// getAge: () => number;
// }

// Filter keys
type KeysNotWhollyCallable<T> = {
  [K in keyof T as T[K] extends (...args: any[]) => unknown ? never : K]: T[K];
};

interface Mixed {
  name: string;
  age: number;
  greet: () => void;
}

type Filtered = KeysNotWhollyCallable<Mixed>;
// {
// name: string;
// age: number;
// }

// Rename keys
type Renamed<T> = {
  [K in keyof T as `${string & K}Key`]: T[K];
};

```

### Adding Modifiers

A homomorphic map over `keyof T` retains source optional and readonly modifiers unless changed explicitly. `-?` removes optionality; adding `undefined` to a value type does not let the property be omitted. With key remapping, string-only templates drop numeric and symbol keys rather than converting them automatically.

```typescript
// Remove readonly
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

// Remove optional
type Concrete<T> = {
  [K in keyof T]-?: T[K];
};

// Make all properties optional and nullable
type Weak<T> = {
  [K in keyof T]?: T[K] | null;
};

interface User {
  name: string;
  age: number;
}

type WeakUser = Weak<User>;
// {
// name?: string | null;
// age?: number | null;
// }

```

## Code Examples

### Practical Examples

`mapValues` assumes a plain record whose declared fields are own properties. `Reflect.ownKeys` includes symbol and non-enumerable keys; numeric TypeScript keys appear as strings at runtime, so the callback accepts the reflected `string | symbol` key. The result assertion bridges dynamic enumeration to static keys, but inherited class members or extra runtime keys can violate that assumption.

```typescript
// ─── Type-safe object manipulation ────────────────────────────
function mapValues<T extends object, U>(
  obj: T,
  fn: (value: T[keyof T], key: string | symbol) => U
): { [K in keyof T]: U } {
  const result = {} as { [K in keyof T]: U };
  for (const key of Reflect.ownKeys(obj)) {
    Object.defineProperty(result, key, {
      value: fn(obj[key as keyof T], key), enumerable: true, writable: true, configurable: true,
    });
  }
  return result;
}

const user = { name: "Alice", age: 30, email: "a@b.com" };
const lengths = mapValues(user, (value) =>
  typeof value === "string" ? value.length : value
);
// { name: number; age: number; email: number }

// ─── Type-safe API response transformation ────────────────────
type ApiResponse<T> = {
  [K in keyof T]: {
    data: T[K];
    status: number;
    timestamp: Date;
  };
};

interface User { id: string; name: string }
interface Post { id: string; title: string }
interface CommentRecord { text: string }
interface UserData {
  user: User;
  posts: Post[];
  comments: CommentRecord[];
}

type UserResponses = ApiResponse<UserData>;
// {
// user: { data: User; status: number; timestamp: Date };
// posts: { data: Post[]; status: number; timestamp: Date };
// comments: { data: CommentRecord[]; status: number; timestamp: Date };
// }

// ─── Type-safe form state ─────────────────────────────────────
type FormState<T> = {
  [K in keyof T]: {
    value: T[K];
    error: string | null;
    touched: boolean;
    dirty: boolean;
  };
};

interface LoginForm {
  email: string;
  password: string;
  rememberMe: boolean;
}

type LoginFormState = FormState<LoginForm>;
// {
// email: { value: string; error: string | null; touched: boolean; dirty: boolean };
// password: { value: string; error: string | null; touched: boolean; dirty: boolean };
// rememberMe: { value: boolean; error: string | null; touched: boolean; dirty: boolean };
// }

function createFormState<T extends object>(defaults: T): FormState<T> {
  const state = {} as FormState<T>;
  for (const rawKey of Reflect.ownKeys(defaults)) {
    const key = rawKey as keyof T;
    Object.defineProperty(state, key, {
      value: { value: defaults[key], error: null, touched: false, dirty: false },
      enumerable: true, writable: true, configurable: true,
    });
  }
  return state;
}

const form = createFormState({
  email: "",
  password: "",
  rememberMe: false
});

```

For the closed user record, mapValues reads Alice/30/a@b.com and stores their lengths-or-number under the same own keys. DefineProperty keeps __proto__ as data rather than invoking a setter. Reflect.ownKeys includes symbols/nonenumerables and returns numeric keys as strings; getters still run during reads and descriptors are not preserved. createFormState applies the same own-key construction to field wrappers; it initializes data, not UI wiring or validation. Input/default object values remain shared references.

`KeysNotWhollyCallable` filters a key only when its entire property type is assignable to a callable signature. A property typed as `(() => void) | string` remains in the result because the union as a whole is not callable.

### Advanced Patterns

```typescript
// ─── Deep mapped type ─────────────────────────────────────────
type DeepPartial<T> =
  T extends Date | ((...args: any[]) => any) ? T :
  T extends object ? { [K in keyof T]?: DeepPartial<T[K]> } : T;

type DeepReadonly<T> =
  T extends Date | ((...args: any[]) => any) ? T :
  T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> } : T;
// Conditional checks use naked T, so optional-object unions recurse per member.
// Homomorphic mapping preserves tuples; Date/function leaves retain their APIs.
// A readonly Date field still permits date.setTime(...): it is not frozen.

// ─── Conditional mapped type ──────────────────────────────────
type NullableStrings<T> = {
  [K in keyof T]: T[K] extends string ? T[K] | null : T[K];
};

interface Config {
  host: string;
  port: number;
  debug: boolean;
}

type NullableConfig = NullableStrings<Config>;
// {
// host: string | null;
// port: number;
// debug: boolean;
// }

// ─── Type-safe event emitter ──────────────────────────────────
type EventMap = {
  "user:created": { userId: string };
  "user:deleted": { userId: string };
  "order:placed": { orderId: string; amount: number };
};

type EventHandler<T> = (payload: T) => void;

type TypedEventHandlers<Events> = {
  [K in keyof Events as `${string & K}`]: EventHandler<Events[K]>;
};

type Handlers = TypedEventHandlers<EventMap>;
// {
// "user:created": EventHandler<{ userId: string }>;
// "user:deleted": EventHandler<{ userId: string }>;
// "order:placed": EventHandler<{ orderId: string; amount: number }>;
// }

// Route parameter capture has its canonical grammar and runtime builder
// in Template Literal Types; a mapped type alone does not replace placeholders.
```

### Utility Type Implementations

`Optional`, `MyRequired`, `MyReadonly` and `MyPick` above implement the property modifiers and key selection used by the corresponding built-ins in [Utility Types](10.2.3.01-utility-types.md). `Record` maps a supplied key union rather than deriving one from an existing object:

```typescript
type MyRecord<K extends PropertyKey, Value> = { [P in K]: Value };
```

These recursive helpers support plain data objects/arrays/tuples with Date/function leaves. A Date remains mutable; Map/Set/native classes need deliberate leaf rules or readonly-container views from [Advanced Generics](../02-generics-and-inference/10.2.2.03-advanced-generics.md). A NullableStrings test examines the whole property type: string|number does not wholly extend string, so it is retained rather than automatically distributing. [Template Literal Types](10.2.3.04-template-literal-types.md) owns route extraction.

## Real-World Use Cases

- **Update payloads** — `DeepPartial<Appointment>` for PATCH bodies; the mapped type describes a static partial view; decoding, authorization and patch-merge semantics remain runtime work (→ 20.3.2.04's conditional requests).
- **Selector maps** — `{ [K in keyof State]: (s: State) => State[K] }` generates selectors typed per key; Redux/Zustand selectors stay in sync with the store shape.
- **Permission matrices** — remapping a role enum to capability booleans with `as` re-keying keeps the authz table checked by the compiler (→ 20.5.1.10).

## Common Mistakes

### 1. Forgetting to Use T[K]

`Stringify` in **How It Works** deliberately replaces every value type with `string`; an identity or modifier-only transformation should instead index the source as `T[K]`. Decide whether values are being preserved or converted before writing the mapped body.

### 2. Not Handling Nested Objects

```typescript
interface Config { database: { host: string; port: number } }
type PartialConfig = Optional<Config>;
// database may be omitted; if supplied, host and port are both required.
type DeepPartialConfig = DeepPartial<Config>;
// database and its nested fields may all be omitted.
```

Use the recursive transform in **Code Examples — Advanced Patterns** when that is the intended contract. Optional nested objects need a distributive helper; testing `T[K] extends object` directly can stop recursion on the `undefined` branch.

### 3. Overusing Mapped Types

```typescript
// Bad: Unnecessary mapped type
type StringUser = {
  [K in "name" | "age"]: string;
};

// Better: Simple object type
type ExplicitStringUser = {
  name: string;
  age: string;
};

```

## Best Practices

```typescript
// Combine with conditional types: allow explicit undefined for string fields
// This changes value types, not optional modifiers
type UndefinedAllowedStrings<T> = {
  [K in keyof T]: T[K] extends string ? T[K] | undefined : T[K];
};

// Use key remapping for transformations
type PrefixKeys<T> = {
  [K in keyof T as `prefix_${string & K}`]: T[K];
};

// Use helper types for complex transformations
type NullableKeys<T> = {
  [K in keyof T]-?: null extends T[K] ? K : never
}[keyof T];

```

## Performance Considerations

Mapped types are erased, but large key unions and recursive compositions can increase checker and editor work. The cost depends on the mapped body and input type; avoid assuming a fixed cost per property or relying on undocumented caching behavior. Measure against the consuming project and simplify only where the diagnostics show meaningful cost.

## Summary

A mapped type selects each key, retrieves or replaces its value type, and optionally changes the key or modifiers. Trace those choices separately. Runtime enumeration and construction must fulfill that contract; readonly, nullable and partial views do not perform freezing, validation or patching.

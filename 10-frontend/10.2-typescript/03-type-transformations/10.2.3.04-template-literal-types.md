# Template Literal Types

A route builder should require `userId` and `postId` when given `/users/:userId/posts/:postId`, then encode each value as one path segment. Template literal types let TypeScript derive that contract from the route pattern; the runtime function still has to build and validate the actual URL.

## Definition

**Template literal types** build string types using backticks and string literal types, such as the exact type `'user'`. They combine literal text with other types to describe permitted strings. Introduced in TypeScript 4.1, they can check CSS values and event names. Paired with conditional types and `infer`, they can also parse and transform known string types during checking. They do not manipulate runtime strings.

> **Textbook Definition:** A template literal type forms a string type by interpolating types into literal text. Union members at interpolation positions expand into combinations; with conditional types and `infer`, a matching pattern can also extract parts of a string type.


## First Principles

Template literal types bring string construction to the type world:

1. **Many APIs identify things by strings.** Event handlers, CSS properties and route patterns all use names. Template literal types generate permitted names from known parts, such as `on${Capitalize<E>}` for an event union `E`. The checker can then reject a misspelled name.
2. **Patterns can also extract parts of a string type.** Built-in transformations such as `Uppercase` and `Capitalize` change literal types. Inside a conditional type, a pattern such as `` `${infer Head}/${infer Rest}` `` can capture the pieces around a slash. Combining these operations can describe a small, deliberate naming grammar. Complex grammars increase checking work and can make errors hard to read.

## Construct names from known pieces

Each interpolation accepts a type. If that type is a union, TypeScript combines every member with the other literal pieces; two unions therefore form their Cartesian product. This is useful for a small whitelist, while a broad `string` describes a pattern and does not enumerate allowed values.

```typescript
type Event = 'click' | 'focus' | 'blur';
type Handler = `on${Capitalize<Event>}`;
// "onClick" | "onFocus" | "onBlur"

type Horizontal = 'left' | 'center' | 'right';
type Vertical = 'top' | 'middle' | 'bottom';
type Position = `${Vertical}-${Horizontal}`;
// 3 × 3 = 9 permitted strings, such as "top-left" and "bottom-right"
```

Built-in transforms such as `Capitalize`, `Uppercase` and `Uncapitalize` operate on literal types. Pattern matching can also capture a piece with `infer`. The route example uses both ideas: it extracts names from `:userId` and requires those names in the parameter object.

Check type-only snippets in a strict TypeScript project; aliases do not execute. A static name contract does not install an event handler, CSS rule or translated message.

## Derive route parameters from a path

The type-level route list keeps colon placeholders literal, so TypeScript can extract their names. The runtime builder then substitutes complete path segments and encodes each value. This small grammar omits optional and wildcard parameters; supporting them requires matching type-level parsing and runtime behavior.

### Build a path from named segments

The conditional pattern `:${infer Name}` captures one parameter name. Recursion visits the remaining slash-separated segments, and the mapped result requires one string for each distinct name. The type list restricts which patterns the function accepts; it is not a runtime route registry.

```typescript
// Route definitions
type RoutePattern =
  | '/users'
  | '/users/:id'
  | '/users/:userId/posts'
  | '/users/:userId/posts/:postId'
  | '/products'
  | '/products/:id';

// Route params extractor
type SegmentParam<S extends string> = S extends `:${infer Name}` ? Name : never;
type ParamNames<T extends string> =
  T extends `${infer Head}/${infer Rest}`
    ? SegmentParam<Head> | ParamNames<Rest> : SegmentParam<T>;
type ExtractParams<T extends string> = Record<ParamNames<T>, string>;

type UserParams = ExtractParams<'/users/:id'>;
// { id: string }

type PostParams = ExtractParams<'/users/:userId/posts/:postId'>;
// { userId: string; postId: string }

// Type-safe route builder
function buildPath<T extends RoutePattern>(
  pattern: T,
  params: ExtractParams<T>
): string {
  return pattern.split("/").map(segment => {
    if (!segment.startsWith(":")) return segment;
    const name = segment.slice(1);
    const value = (params as Record<string, unknown>)[name];
    if (!Object.prototype.hasOwnProperty.call(params, name) || typeof value !== "string") {
      throw new Error(`Missing string parameter: ${name}`);
    }
    return encodeURIComponent(value);
  }).join("/");
}

const path1 = buildPath('/users/:id', { id: '42' });
// Result: "/users/42"
const path2 = buildPath('/users/:userId/posts/:postId', {
  userId: 'abc',
  postId: '123',
});
// Result: "/users/abc/posts/123"
```

For `/users/:userId/posts/:postId`, parsing collects `userId` and `postId`; building visits the same segments and replaces only complete colon-prefixed segments. A value `a/b` becomes `a%2Fb` inside one segment, so `:id` cannot accidentally replace part of `:id2`. Repeated names reuse one value. The grammar supports required `:name` segments only; it does not parse optional, wildcard or query-string syntax. Since JavaScript callers can bypass static checking, the function still throws for a missing or non-string parameter.

## Apply the same patterns to application contracts

### Event names carry their payload type

The event map already pairs each event name with its payload. A template pattern can split `resource:action`, then a mapped type can derive handler names without losing that payload relationship.

```typescript
type EventMap = {
  'user:created': { userId: string; timestamp: number };
  'user:updated': { userId: string; changes: string[] };
  'user:deleted': { userId: string; reason: string };
  'order:placed': { orderId: string; amount: number };
  'order:shipped': { orderId: string; trackingNumber: string };
};

// Derive event names from the map
type EventName = keyof EventMap;
// "user:created" | "user:updated" | "user:deleted" | "order:placed" | "order:shipped"

// Derive handler names
type HandlerName<T extends EventName> =
  T extends `${infer Resource}:${infer Action}`
    ? `on${Capitalize<Resource>}${Capitalize<Action>}`
    : never;

type UserCreatedHandler = HandlerName<'user:created'>;
// "onUserCreated"

type HandlerRegistry = {
  [E in EventName as HandlerName<E>]: (payload: EventMap[E]) => void;
};
// Example member: onUserCreated:(payload:{userId:string;timestamp:number})=>void
// This is a registry type, not a no-op class pretending to emit events.
```

For `user:created`, the pattern captures `user` and `created`, capitalizes both and builds `onUserCreated`. The mapped registry retains that event's payload. A runtime [event emitter](../04-advanced-patterns/10.2.4.05-advanced-patterns.md) still has to own subscriptions, delivery and cleanup. Distinct source names can collide after capitalization; define a unique naming grammar or reject collisions before generating a real registry.

### CSS values use a deliberately small grammar

Some CSS-in-JS APIs accept a restricted number-and-unit grammar. Template literals can reject missing units, but they do not parse the full CSS language or validate a value for every property.

```typescript
// CSS property types
type CSSUnit = 'px' | 'rem' | 'em' | '%' | 'vw' | 'vh' | 'pt';
type CSSValue = `${number}${CSSUnit}`;

type Width = CSSValue; // "10px" | "2rem" | "50%" | ...
type Margin = `${CSSValue} ${CSSValue}`; // "10px 20px"
type Padding = `${CSSValue} ${CSSValue} ${CSSValue} ${CSSValue}`;

// Type-safe CSS-in-JS
interface CSSProperties {
  width?: CSSValue;
  height?: CSSValue;
  margin?: CSSValue | Margin;
  padding?: CSSValue | Padding;
  fontSize?: CSSValue;
  gap?: CSSValue;
  borderRadius?: CSSValue;
}

const styles: CSSProperties = {
  width: '100px', // Valid
  height: '50%', // Valid
  // width: 'abc', // Type error!
  // height: '10', // Missing unit
  margin: '10px 20px', // Valid
  padding: '10px 15px 10px 15px', // Valid
};
```

CSSValue expresses a deliberately limited number-plus-unit subset, not all CSS: auto, zero without units, calc and two/three-value padding are outside this example. It also admits values a specific CSS property might reject, such as negative width. The types neither parse complete CSS nor install a stylesheet.

### CSS classes combine finite token sets

When an API accepts only a known set of utility tokens, finite unions can make misspellings visible at compile time.

```typescript
type Spacing = '0' | '1' | '2' | '4';
type Edge = '' | 'x' | 'y' | 't' | 'b';
type MarginClass = `m${Edge}-${Spacing}`;
// "m-0" | "mx-1" | "my-2" | "mt-4" | "mb-4" | ...

type Color = 'red' | 'blue';
type Shade = '400' | '600';
type TextColorClass = `text-${Color}-${Shade}`;
// "text-red-400" | "text-red-600" | "text-blue-400" | "text-blue-600"
```

These types describe a small custom whitelist. They neither resolve conflicting classes nor cause a CSS framework to generate styles.

### String transformations alter types, not runtime keys

The camel-to-kebab helper is intended for lower-camel ASCII names with ordinary letter transitions. Digits and punctuation also satisfy `T extends Uppercase<T>`, and acronym runs need a more nuanced boundary rule; the type does not convert any runtime keys or detect key collisions.

```typescript
// Convert lowercase words separated by one underscore.
type SnakeToCamel<S extends string> =
  S extends `${infer T}_${infer U}`
    ? `${T}${Capitalize<SnakeToCamel<U>>}`
    : S;

type CamelCase1 = SnakeToCamel<'user_name'>;
// "userName"

// Convert lower-camel ASCII identifiers with no digits or acronym runs.
type CamelToKebab<S extends string> =
  S extends `${infer T}${infer U}`
    ? T extends Uppercase<T>
      ? `-${Lowercase<T>}${CamelToKebab<U>}`
      : `${T}${CamelToKebab<U>}`
    : S;

type Kebab1 = CamelToKebab<'backgroundColor'>;
// "background-color"

// Apply a known converter to each string key in the mapped type.
type CamelKeys<T> = {
  [K in keyof T as K extends string ? SnakeToCamel<K> : K]: T[K];
};

interface ApiResponse {
  user_name: string;
  user_email: string;
  created_at: Date;
}

type FrontendResponse = CamelKeys<ApiResponse>;
// {
// userName: string;
// userEmail: string;
// createdAt: Date;
// }
```

`SnakeToCamel` assumes lowercase words and single separators. `CamelToKebab` assumes ordinary letter transitions: digits satisfy `T extends Uppercase<T>`, while acronym runs need a different boundary rule. Neither helper changes runtime object keys; key collisions also need a runtime policy when transforming real objects.

### Deep paths depend on the input shape

To offer completions for paths such as `database.credentials.user`, recursively visit object-valued fields, prefix each child with its parent key, and stop at leaf values.

```typescript
// Type-safe object path access
type PathImpl<T, K extends keyof T> =
  K extends string
    ? T[K] extends readonly unknown[]
      ? K
      : T[K] extends object
        ? `${K}.${PathImpl<T[K], keyof T[K]> & string}`
        : K
    : never;

type Path<T> = PathImpl<T, keyof T> & string;

interface NestedConfig {
  database: {
    host: string;
    port: number;
    credentials: {
      user: string;
      password: string;
    };
  };
  cache: {
    ttl: number;
    redis: {
      host: string;
      port: number;
    };
  };
}

type ConfigPaths = Path<NestedConfig>;
// "database.host" | "database.port" | "database.credentials.user"
// | "database.credentials.password" | "cache.ttl" | "cache.redis.host"
// | "cache.redis.port"

type DeepSelect<T> = Partial<Record<Path<T>, boolean>>;
type ConfigSelection = DeepSelect<NestedConfig>;
const selection: ConfigSelection = { "database.host": true };
```

For `database.credentials.user`, the type visits each record field, prefixes parent names and returns terminal paths; `selection` therefore accepts `database.host`. This sketch assumes required finite plain records; arrays, native classes, optional children and cycles need separate rules or a depth limit. It constrains a static selection shape, but cannot authorize a field or change a database query. The related [Advanced Generics](../02-generics-and-inference/10.2.2.03-advanced-generics.md) example answers the next question: given one path, what value type does it select?

### Translation key types do not guarantee messages exist

Combine a finite set of message IDs with a finite set of locales to describe allowed dictionary keys. The dictionary itself is runtime data, so the application still needs a missing-message policy.

```typescript
type Locale = 'en' | 'es' | 'fr' | 'de';

type TranslationKeys = {
  'welcome': `welcome.${Locale}`;
  'goodbye': `goodbye.${Locale}`;
  'error.not_found': `error.not_found.${Locale}`;
  'error.server': `error.server.${Locale}`;
};

type TranslationKey = TranslationKeys[keyof TranslationKeys];
// "welcome.en" | "welcome.es" | ... | "error.server.de"

// Permitted message keys are static; dictionary availability is a runtime concern.
// Recover a message ID from one of its localized keys.
type MessageIdFromKey<T extends string> =
  T extends `${infer Key}.${Locale}` ? Key : never;

type WelcomeMessageId = MessageIdFromKey<'welcome.en'>;
// "welcome"

const dictionary: Partial<Record<TranslationKey, string>> = {
  'welcome.en': 'Welcome, {{name}}!'
};
function getTranslation(key: TranslationKey): string {
  const value = dictionary[key];
  if (value === undefined) throw new Error(`Missing translation: ${key}`);
  return value;
}

function translate(key: TranslationKey, params: Record<string, string> = {}): string {
  const value = getTranslation(key);
  return value.replace(/\{\{([A-Za-z][A-Za-z0-9_]*)\}\}/g, (_match, name: string) => {
    const replacement = params[name];
    if (!Object.prototype.hasOwnProperty.call(params, name) || typeof replacement !== "string") {
      throw new Error(`Missing translation parameter: ${name}`);
    }
    return replacement; // callback result inserts literal $ characters too
  });
}

const greeting = translate('welcome.en', { name: 'Alice' }); // Welcome, Alice!
```

The partial dictionary has only `welcome.en`, so another permitted key throws until its message exists. The replacement grammar handles repeated `{{name}}` tokens and throws for missing string values; a callback inserts `$&` literally instead of treating it as replacement syntax. The type does not derive message-specific parameter names. This is plain text substitution, not pluralization, rich HTML or locale fallback. Render the result as text or apply the escaping required by its output context.

### Join and Split preserve literals only for known inputs

`Join` preserves literal output for fixed-length mutable or readonly tuples and widens an open-ended array to `string`. Optional or rest tuples need another contract. `Split` uses a deliberate simplified policy: empty input yields an empty tuple and a trailing delimiter contributes no final empty field, unlike JavaScript `String.split`; this helper also excludes an empty delimiter.

```typescript
// Join array of strings
type Join<T extends readonly string[], Separator extends string = ','> =
  number extends T['length'] ? string :
  T extends readonly [infer F, ...infer R]
    ? F extends string
      ? R extends readonly string[]
        ? R['length'] extends 0
          ? F
          : `${F}${Separator}${Join<R, Separator>}`
        : never
      : never
    : '';

type Joined1 = Join<['a', 'b', 'c']>;
// "a,b,c"
type Joined2 = Join<['a', 'b', 'c'], '-'>;
// "a-b-c"
type Joined3 = Join<['hello'], '.'>;
// "hello"
type JoinedReadonly = Join<readonly ['users', '42'], '/'>;
// "users/42"
type JoinedArray = Join<string[], '/'>;
// string: the element sequence is not known at compile time

// Split string into tuple
type Split<S extends string, D extends string = ','> =
  string extends S ? string[] :
  S extends '' ? [] :
  S extends `${infer T}${D}${infer U}`
    ? [T, ...Split<U, D>]
    : [S];

type Split1 = Split<'a,b,c'>;
// ["a", "b", "c"]
type Split2 = Split<'hello world', ' '>;
// ["hello", "world"]
type Split3 = Split<'user:42:active', ':'>;
// ["user", "42", "active"]
```

### Prefix keys while preserving their values

Key remapping changes the static property contract while retaining each property's value type. This form intentionally handles string keys; numeric and symbol keys do not fit the template and are omitted.

```typescript
type PrefixedKeys<T, Prefix extends string> = {
  [K in keyof T as K extends string
    ? `${Prefix}${Capitalize<K>}`
    : never]: T[K];
};

type User = { name: string; age: number };
type ApiUser = PrefixedKeys<User, 'user'>;
// { userName: string; userAge: number }
```

### Recursive helpers need explicit input limits

These helpers define specific grammars: `Trim` recognizes space, newline and tab, not every JavaScript whitespace character. Pass `Repeat` a small nonnegative integer literal; a negative or fractional count cannot reach the base case and can exceed the checker's recursion budget, while broad `number` matches zero immediately.

```typescript
// Trim whitespace
type TrimLeft<S extends string> =
  S extends `${' ' | '\n' | '\t'}${infer Rest}`
    ? TrimLeft<Rest>
    : S;

type TrimRight<S extends string> =
  S extends `${infer Rest}${' ' | '\n' | '\t'}`
    ? TrimRight<Rest>
    : S;

type Trim<S extends string> = TrimLeft<TrimRight<S>>;

type Trimmed1 = Trim<' hello '>; // "hello"
type Trimmed2 = Trim<'\n\t world \n'>; // "world"

// Repeat string N times (using array accumulator for type-level length tracking)
type Repeat<S extends string, N extends number, Acc extends never[] = []> =
  Acc['length'] extends N ? '' : `${S}${Repeat<S, N, [...Acc, never]>}`;

type Dashes = Repeat<'-', 5>; // "-----"
type Dots = Repeat<'.', 3>; // "..."

// Replace all occurrences
type ReplaceAll<S extends string, From extends string, To extends string> =
  From extends '' ? S :
  S extends `${infer Head}${From}${infer Tail}`
    ? `${Head}${To}${ReplaceAll<Tail, From, To>}`
    : S;

type Replaced1 = ReplaceAll<'a-b-c-d', '-', '_'>;
// "a_b_c_d"
type Replaced2 = ReplaceAll<'user@example.com', '@', '[at]'>;
// "user[at]example.com"
```

`ReplaceAll` treats an empty search string as no change so each recursive match consumes input. A recursive type can also use a bounded approximation when full precision is unnecessary:

```typescript
type TakePrefix<S extends string, Budget extends number = 10, Seen extends unknown[] = []> =
  Seen['length'] extends Budget ? '' :
  S extends `${infer First}${infer Rest}`
    ? `${First}${TakePrefix<Rest, Budget, [...Seen, unknown]>}` : '';
type Prefix = TakePrefix<'hello-world', 5>; // "hello"
```

`Budget` must be a small nonnegative integer literal, and the helper is intended for ASCII literals. Its truncated result is a stated approximation, not a full string transformation.

## Know where the type contract ends

Template literal types constrain static values; they do not install handlers, generate CSS, load translations, validate outside data or transform runtime keys. Treat the type and its runtime implementation as two parts of one contract.

### Expansion size grows with each union

```typescript
type WrapString<T> = T extends string ? `~${T}~` : T;
type Result = WrapString<'a' | 'b'>; // "~a~" | "~b~"
type Wrapped = `~${'a' | 'b'}~`; // Also "~a~" | "~b~"
type Combinations = `${'red' | 'blue'}-${'sm' | 'lg'}`;
// "red-sm" | "red-lg" | "blue-sm" | "blue-lg"
```

The conditional distributes because its checked side is a naked type parameter. Template interpolation expands unions independently. Tuple wrapping changes conditional distribution, but it does not stop a template literal from expanding interpolated unions.

Every independent union position multiplies the alternatives. Keep a whitelist small, define unsupported inputs, and measure a production type with `tsc --extendedDiagnostics`; compiler version, surrounding types and caching affect checker cost.

The path generator above also needs a finite input shape: arrays, optional records and recursive models require additional cases or a depth bound before it can serve as a general library utility.

## Summary

Template literals construct permitted string patterns; unions multiply alternatives, and infer extracts parts of a matched literal. Define a small grammar and trace its terminal cases. Runtime route substitution, key conversion and translation delivery must implement that same contract rather than assuming a type alias performs the work.

# Template Literal Types

A route builder should require `userId` and `postId` when given `/users/:userId/posts/:postId`, then encode each value as one path segment. Template literal types let TypeScript derive that contract from the route pattern; the runtime function still has to build and validate the actual URL.

```typescript
type Event = 'click' | 'focus' | 'blur';
type Handler = `on${Capitalize<Event>}`;
// "onClick" | "onFocus" | "onBlur"
```

## Definition

**Template literal types** build string types using backticks and string literal types, such as the exact type `'user'`. They combine literal text with other types to describe permitted strings. Introduced in TypeScript 4.1, they can check CSS values and event names. Paired with conditional types and `infer`, they can also parse and transform known string types during checking. They do not manipulate runtime strings.

> **Textbook Definition:** A template literal type forms a string type by interpolating types into literal text. Union members at interpolation positions expand into combinations; with conditional types and `infer`, a matching pattern can also extract parts of a string type.

## First Principles

Choose one of two jobs: construct names from known literal parts, or match an existing literal and capture its pieces. Construction can multiply union members; parsing depends on a precise pattern and a recursive rule that makes progress. Both operations affect only what the checker accepts.

## How It Works

### 1. Construct Names from Known Pieces

Each interpolation contributes its possible strings. If two positions are unions, TypeScript combines every member with every member of the other union. This is useful for small finite APIs and limited grammars; a broad `string` pattern does not whitelist known values.

```typescript
type Event = 'click' | 'focus' | 'blur';
type Handler = `on${Capitalize<Event>}`;
// "onClick" | "onFocus" | "onBlur"

type CSSLength = `${number}px` | `${number}rem`;
const gap: CSSLength = '1.5rem';
```

The event type permits only names derived from the finite source union. `CSSLength` describes a small number-and-unit grammar, not CSS as a whole; it can still admit a negative width that the property rejects. Neither type installs a handler or validates a runtime string.

### 2. Derive Route Parameters from a Path

The type-level route list keeps colon placeholders literal, so TypeScript can extract their names. The runtime builder then substitutes complete path segments and encodes each value. This small grammar omits optional and wildcard parameters; supporting them requires matching type-level parsing and runtime behavior.

The conditional pattern `:${infer Name}` captures one parameter name. Recursion visits the remaining slash-separated segments, and the mapped result requires one string for each distinct name. The type list restricts which patterns the function accepts; it is not a runtime route registry.

```typescript
// Route definitions
type RoutePattern =
  | '/users'
  | '/users/:id'
  | '/users/:userId/posts'
  | '/users/:userId/posts/:postId'
  | '/products'
  | '/products/:id';

// Route params extractor
type SegmentParam<S extends string> = S extends `:${infer Name}` ? Name : never;
type ParamNames<T extends string> =
  T extends `${infer Head}/${infer Rest}`
    ? SegmentParam<Head> | ParamNames<Rest> : SegmentParam<T>;
type ExtractParams<T extends string> = Record<ParamNames<T>, string>;

type UserParams = ExtractParams<'/users/:id'>;
// { id: string }

type PostParams = ExtractParams<'/users/:userId/posts/:postId'>;
// { userId: string; postId: string }

// Type-safe route builder
function buildPath<T extends RoutePattern>(
  pattern: T,
  params: ExtractParams<T>
): string {
  return pattern.split("/").map(segment => {
    if (!segment.startsWith(":")) return segment;
    const name = segment.slice(1);
    const value = (params as Record<string, unknown>)[name];
    if (!Object.prototype.hasOwnProperty.call(params, name) || typeof value !== "string") {
      throw new Error(`Missing string parameter: ${name}`);
    }
    return encodeURIComponent(value);
  }).join("/");
}

const path1 = buildPath('/users/:id', { id: '42' });
// Result: "/users/42"
const path2 = buildPath('/users/:userId/posts/:postId', {
  userId: 'abc',
  postId: '123',
});
// Result: "/users/abc/posts/123"
```

For `/users/:userId/posts/:postId`, parsing collects `userId` and `postId`; building visits the same segments and replaces only complete colon-prefixed segments. A value `a/b` becomes `a%2Fb` inside one segment, so `:id` cannot accidentally replace part of `:id2`. Repeated names reuse one value. The grammar supports required `:name` segments only; it does not parse optional, wildcard or query-string syntax. Since JavaScript callers can bypass static checking, the function still throws for a missing or non-string parameter.

### 3. Apply Generated Names to Event and Key Contracts

An event map ties each name to its payload. A template pattern can derive a handler name, and a mapped type can carry the matching payload into that handler.

```typescript
type EventMap = {
  'user:created': { userId: string; timestamp: number };
  'user:updated': { userId: string; changes: string[] };
  'order:placed': { orderId: string; amount: number };
};

type EventName = keyof EventMap;
type HandlerName<T extends EventName> =
  T extends `${infer Resource}:${infer Action}`
    ? `on${Capitalize<Resource>}${Capitalize<Action>}`
    : never;

type HandlerRegistry = {
  [E in EventName as HandlerName<E>]: (payload: EventMap[E]) => void;
};
// onUserCreated: (payload: { userId: string; timestamp: number }) => void
```

For `user:created`, the pattern captures `user` and `created`, then builds `onUserCreated` with that event's payload. A runtime emitter still owns subscriptions, delivery and cleanup. Different source names can collide after capitalization, so define a unique naming grammar before generating a real registry.

A converter can also remap string keys while preserving each property's value type. This helper assumes lower-case words separated by single underscores; it does not convert runtime objects or detect collisions.

```typescript
type SnakeToCamel<S extends string> =
  S extends `${infer Head}_${infer Tail}`
    ? `${Head}${Capitalize<SnakeToCamel<Tail>>}`
    : S;

type CamelKeys<T> = {
  [K in keyof T as K extends string ? SnakeToCamel<K> : K]: T[K];
};

interface ApiResponse {
  user_name: string;
  user_email: string;
  created_at: Date;
}
type FrontendResponse = CamelKeys<ApiResponse>;
// { userName: string; userEmail: string; createdAt: Date }
```

Non-string keys pass through unchanged. If two source names map to the same output key, the mapped result combines them; transforming a real object needs an explicit collision policy. For more complex remapping, see [Mapped Types](10.2.3.03-mapped-types.md).

### 4. Derive Deep Paths from the Input Shape

To offer completions for paths such as `database.credentials.user`, recursively visit object-valued fields, prefix each child with its parent key, and stop at leaf values.

```typescript
// Type-safe object path access
type PathImpl<T, K extends keyof T> =
  K extends string
    ? T[K] extends readonly unknown[]
      ? K
      : T[K] extends object
        ? `${K}.${PathImpl<T[K], keyof T[K]> & string}`
        : K
    : never;

type Path<T> = PathImpl<T, keyof T> & string;

interface NestedConfig {
  database: {
    host: string;
    port: number;
    credentials: {
      user: string;
      password: string;
    };
  };
  cache: {
    ttl: number;
    redis: {
      host: string;
      port: number;
    };
  };
}

type ConfigPaths = Path<NestedConfig>;
// "database.host" | "database.port" | "database.credentials.user"
// | "database.credentials.password" | "cache.ttl" | "cache.redis.host"
// | "cache.redis.port"

type DeepSelect<T> = Partial<Record<Path<T>, boolean>>;
type ConfigSelection = DeepSelect<NestedConfig>;
const selection: ConfigSelection = { "database.host": true };
```

For `database.credentials.user`, the type visits each record field, prefixes parent names and returns terminal paths; `selection` therefore accepts `database.host`. This sketch assumes required finite plain records; arrays, native classes, optional children and cycles need separate rules or a depth limit. It constrains a static selection shape, but cannot authorize a field or change a database query. The related [Advanced Generics](../02-generics-and-inference/10.2.2.03-advanced-generics.md) example answers the next question: given one path, what value type does it select?

### 5. Join, Split, and Replace Known String Tuples

A fixed tuple preserves exact output; an open-ended array has unknown length and therefore widens to `string`. Optional and rest tuples need an explicit policy. The split helper states its edge cases: empty input becomes an empty tuple, a trailing delimiter adds no final empty part, and an empty delimiter is unsupported.

```typescript
type Join<T extends readonly string[], Separator extends string = ','> =
  number extends T['length'] ? string :
  T extends readonly [infer Head, ...infer Rest]
    ? Head extends string
      ? Rest extends readonly string[]
        ? Rest['length'] extends 0 ? Head : `${Head}${Separator}${Join<Rest, Separator>}`
        : never
      : never
    : '';

type Split<S extends string, Delimiter extends string = ','> =
  Delimiter extends '' ? never :
  string extends S ? string[] :
  S extends '' ? [] :
  S extends `${infer Head}${Delimiter}${infer Tail}`
    ? [Head, ...Split<Tail, Delimiter>]
    : [S];

type Route = Join<readonly ['users', '42'], '/'>; // "users/42"
type UnknownRoute = Join<string[], '/'>; // string
type Parts = Split<'users,42,active'>; // ["users", "42", "active"]
type TrailingDelimiter = Split<'a,'>; // ["a"]
type EmptyDelimiter = Split<'abc', ''>; // never
```

A recursive string helper needs a terminal case and a rule that makes progress. An empty search value could match without consuming input, so the helper returns the original string for that case.

```typescript
type ReplaceAll<S extends string, From extends string, To extends string> =
  From extends '' ? S :
  S extends `${infer Head}${From}${infer Tail}`
    ? `${Head}${To}${ReplaceAll<Tail, From, To>}`
    : S;

type Replaced = ReplaceAll<'a-b-c-d', '-', '_'>; // "a_b_c_d"
type EmptySearch = ReplaceAll<'abc', '', 'x'>; // "abc"
```

The result is a type, not a runtime string replacement. Broad inputs and long literal strings can increase checker work; use runtime code when the value is not a small compile-time literal.

### 6. Bound Generated Unions and Runtime Expectations

Each independent union position multiplies possible strings. Conditional types distribute only when a naked type parameter is checked; interpolations expand independently. Tuple wrapping changes conditional distribution but does not stop interpolation expansion.

```typescript
type ConditionalResult<T> = T extends string ? `~${T}~` : never;
type Distributed = ConditionalResult<'a' | 'b'>; // "~a~" | "~b~"
type Interpolated = `~${'a' | 'b'}~`; // Also "~a~" | "~b~"
type Combinations = `${'red' | 'blue'}-${'sm' | 'lg'}`;
// "red-sm" | "red-lg" | "blue-sm" | "blue-lg"
```

Use finite unions for small supported sets and define what unsupported inputs mean. Route and path helpers above assume known finite shapes; arrays, optional records and cycles need additional policies or a depth bound. Measure large types with `tsc --extendedDiagnostics` using realistic inputs.

Template literal types constrain static strings; they do not build URLs, install handlers, convert runtime keys, validate external input or transform runtime strings. The runtime implementation must enforce the same contract.

## Summary

Template literals construct permitted string patterns; unions multiply alternatives, and infer extracts parts of a matched literal. Define a small grammar and trace its terminal cases. Runtime route construction, key conversion and parsing must implement that same contract rather than assuming a type alias performs the work.

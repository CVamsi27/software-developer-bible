# Branded Types

A function that accepts a user ID should not accidentally receive an order ID. Both values may be strings at runtime, so ordinary structural typing treats them as interchangeable. A brand lets the checker distinguish them after validation.

## Definition

A branded type combines a value's ordinary representation with a type-only marker. The marker changes TypeScript assignability while leaving the runtime value unchanged. A constructor must establish the invariant the brand claims.

> **Textbook Definition:** A branded type is an intersection between a base type and a required phantom member used to simulate nominal distinctions in a structural type system. The member is erased at runtime; only a trusted construction boundary can establish the represented invariant.

## First Principles

TypeScript compares type members, not their names. Two aliases of `string` therefore describe the same values. Add a required marker keyed by a module-private `unique symbol` and the checker can distinguish the aliases.

```typescript
declare const brand: unique symbol;
type Branded<Value, Name extends string> =
  Value & { readonly [brand]: Name };

type UserId = Branded<string, 'UserId'>;
type OrderId = Branded<string, 'OrderId'>;

function parseUserId(input: unknown): UserId {
  if (typeof input !== 'string' || !/^user_[a-z0-9]+$/i.test(input)) {
    throw new TypeError('Invalid user ID');
  }
  return input as UserId; // The check justifies this local assertion.
}

declare function loadUser(id: UserId): void;
const id = parseUserId('user_42');
loadUser(id);

// @ts-expect-error — an ordinary string has not crossed the constructor
loadUser('user_42');

// @ts-expect-error — distinct brands are not interchangeable
const orderId: OrderId = id;
```

The assertion does not validate; the preceding condition does. Keeping the brand key private and exporting a constructor gives callers a checked path. A caller can still bypass it with `as` or `any`, so a brand records that code followed a convention rather than proving the value trustworthy.

## Validate again after serialization

Branded strings serialize as ordinary strings. Validate JSON or database values again before returning `UserId`. A phantom marker adds no property, wrapper or immutability.

Use brands when two values share a representation but have different meanings. Do not brand every primitive: the extra type can cost more than the mistake it prevents.

## Units need dimension-specific operations

```typescript
declare const unit: unique symbol;
type Quantity<Name extends string> = number & { readonly [unit]: Name };
type Meters = Quantity<'Meters'>;
type Seconds = Quantity<'Seconds'>;

function meters(value: number): Meters {
  if (!Number.isFinite(value)) throw new RangeError('Expected finite meters');
  return value as Meters;
}
function addMeters(left: Meters, right: Meters): Meters {
  return meters(left + right);
}

const distance = addMeters(meters(3), meters(4));
const duration: Seconds = 2 as Seconds;
// @ts-expect-error — a duration cannot be added to a distance
addMeters(distance, duration);
```

The brand prevents a seconds value from entering an operation that requires meters. It does not derive dimensions through arbitrary arithmetic: multiplication and division need domain-specific operations and result brands. Constructors and operations must also check overflow and other numeric invariants.

## Currency is a stronger domain boundary

```typescript
declare const moneyBrand: unique symbol;
type Currency = 'USD' | 'EUR';
type Money<C extends Currency> = {
  readonly cents: number;
  readonly currency: C;
  readonly [moneyBrand]: C;
};

function money<C extends Currency>(currency: C, cents: number): Money<C> {
  if (!Number.isSafeInteger(cents) || cents < 0) {
    throw new RangeError('Expected nonnegative safe integer cents');
  }
  return { currency, cents } as Money<C>;
}

function addMoney<C extends Currency>(
  left: Money<C>,
  right: Money<NoInfer<C>>
): Money<C> {
  if (left.currency !== right.currency) throw new TypeError('Currency mismatch');
  return money(left.currency, left.cents + right.cents);
}

const total = addMoney(money('USD', 500), money('USD', 250));
// @ts-expect-error — the first argument fixes C as USD
addMoney(money('USD', 500), money('EUR', 250));
```

The currency field is real data; the unique-symbol member exists only in the type. The constructor checks the numeric rule, and the operation checks the actual currency fields. `NoInfer` prevents the second argument from widening the generic currency to a union. Conversion still needs an exchange-rate source and a rounding policy.

## Keep different claims distinct

A date-only string identifies a calendar day; an instant identifies a point on the UTC timeline. For a canonical YYYY-MM-DD value, parse it as UTC and require formatting it back to produce the same string; that round trip rejects dates such as 2024-02-30. Do not derive someone's local day by slicing an arbitrary instant in UTC.

A JWT-shaped string is not an authenticated identity. Verify its signature and issuer, audience and expiry claims before constructing trusted claims. Branding the text before verification only hides an untrusted boundary.

A flavor uses an optional marker, such as `type Flavor<T, Name> = T & { readonly [brand]?: Name }`. Because that marker is optional, raw values still satisfy the type. Flavoring documents intent with less friction but does not block accidental inputs.

A discriminated union usually needs no brand: its stored `kind` field already lets runtime code choose a branch. Use runtime tags for behavior and phantom markers for distinctions with no runtime representation.

## Summary

Brands distinguish same-shaped values for checked callers. A validated constructor establishes the claimed invariant; assertions, `any` and serialization bypass or erase the marker. Use domain-specific operations for units and currencies, and validate external values before branding them.

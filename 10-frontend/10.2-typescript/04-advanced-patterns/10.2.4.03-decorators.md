# Decorators

## Definition

**Decorators** are functions that can observe or alter a class or class member at definition time. The legacy and Stage 3 APIs use different arguments, return values and metadata facilities. The diagram below shows legacy targets; Stage 3 includes fields and auto-accessors but does not include parameter decorators or support legacy `emitDecoratorMetadata`.

```text
┌────────────────────────────────────────────────────────────┐
│ DECORATOR TYPES                                            │
├────────────────────────────────────────────────────────────┤
│                                                            │
│ @ClassDecorator                                            │
│ class MyClass {                                            │
│ @PropertyDecorator                                         │
│ myProperty: string;                                        │
│                                                            │
│ @MethodDecorator                                           │
│ myMethod(@ParameterDecorator arg: string): void {}         │
│ }                                                          │
│                                                            │
│ ┌──────────────────┬─────────────────────────────────────┐ │
│ │ Decorator Type │ Applies To │                            │
│ ├──────────────────┼─────────────────────────────────────┤ │
│ │ Class │ Class declaration │                              │
│ │ Method │ Class method │                                  │
│ │ Property │ Class property │                              │
│ │ Parameter │ Method/function parameter │                  │
│ └──────────────────┴─────────────────────────────────────┘ │
│                                                            │
└────────────────────────────────────────────────────────────┘

```


## First Principles

Decorators are metadata + behavior attachment at declaration sites:

1. **A decorator is a function invoked for its side effect on the class** — wrapping methods (logging, auth checks), registering routes/controllers (→ 20.2.1's Nest DI reads them), annotating schema — a metaprogramming hook evaluated when the class is defined, with instance work deferred through initializers.
2. **The cost is indirection**: behavior appears from outside the method body — powerful for cross-cutting concerns, dangerous when overused (the "where does this come from" debugging tax).

## Why It Matters

Senior engineers see decorators in: NestJS (`@Controller`, `@Get`, `@Injectable`), TypeORM (`@Entity`, `@Column`), class-validator (`@IsEmail`, `@MinLength`). The interview signal is understanding the decorator factory pattern, metadata reflection, and the difference between legacy experimental and Stage 3 syntax.

**Concretely:**

1. **Metaprogramming**: Add behavior to classes and methods

2. **Code reuse**: Implement cross-cutting concerns (logging, validation)

3. **Declarative syntax**: Express intent through annotations

4. **Framework support**: Used by Angular, NestJS, TypeORM, etc.

5. **Aspect-oriented programming**: Separate concerns from business logic

## How It Works

### Experimental Decorators (TypeScript legacy)

These examples require `experimentalDecorators`; the metadata examples also require the installed `reflect-metadata` package and its runtime import. Metadata registration alone does not run validation or inject a service: a consumer must read it and act.

```typescript
import "reflect-metadata";

// Enable in tsconfig.json:
// { "experimentalDecorators": true }

// ─── Class Decorator ──────────────────────────────────────────
function Sealed(constructor: Function) {
  Object.seal(constructor);
  Object.seal(constructor.prototype);
}

@Sealed
class Greeter {
  greeting: string;
  constructor(message: string) {
    this.greeting = message;
  }
  greet() {
    return "Hello, " + this.greeting;
  }
}

// ─── Method Decorator ─────────────────────────────────────────
function Log(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  const originalMethod = descriptor.value;

  descriptor.value = function (...args: any[]) {
    console.log(`Calling ${propertyKey} with`, args);
    const result = originalMethod.apply(this, args);
    console.log(`Result:`, result);
    return result;
  };
}

class Calculator {
  @Log
  add(a: number, b: number): number {
    return a + b;
  }
}

// ─── Property Decorator: register metadata, do not intercept fields ──
function Required(target: object, propertyKey: string) {
  const fields: string[] = Reflect.getOwnMetadata("requiredFields", target) ?? [];
  Reflect.defineMetadata("requiredFields", [...fields, propertyKey], target);
}

class User {
  @Required
  name!: string;
}
// A validator must inspect requiredFields and the actual instance values.

// ─── Parameter Decorator ──────────────────────────────────────
function Validate(
  target: any,
  propertyKey: string,
  parameterIndex: number
) {
  const existingRequiredParameters: number[] =
    Reflect.getOwnMetadata("required", target, propertyKey) || [];
  existingRequiredParameters.push(parameterIndex);
  Reflect.defineMetadata(
    "required",
    existingRequiredParameters,
    target,
    propertyKey
  );
}

class UserService {
  createUser(@Validate name: string, @Validate email: string): void {
    // Implementation
  }
}

```

### Stage 3 Decorators (TC39 proposal)

```typescript
// TS 5.0+: leave experimentalDecorators disabled for this API

// ─── Class Decorator ──────────────────────────────────────────
function sealed(originalClass: new (...args: any[]) => any, context: ClassDecoratorContext) {
  Object.seal(originalClass);
  Object.seal(originalClass.prototype);
  return originalClass;
}

@sealed
class Greeter {
  greeting: string;
  constructor(message: string) {
    this.greeting = message;
  }
  greet() {
    return "Hello, " + this.greeting;
  }
}

// ─── Method Decorator ─────────────────────────────────────────
function log(originalMethod: any, context: ClassMethodDecoratorContext) {
  const methodName = String(context.name);

  return function (this: any, ...args: any[]) {
    console.log(`Calling ${methodName} with`, args);
    const result = originalMethod.call(this, ...args);
    console.log(`Result:`, result);
    return result;
  };
}

class Calculator {
  @log
  add(a: number, b: number): number {
    return a + b;
  }
}

// ─── Method binding through an instance initializer ──────────
function bound<This, Args extends unknown[], Result>(
  _method: (this: This, ...args: Args) => Result,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Result>
) {
  if (context.private || context.static) throw new Error("Expected a public instance method");
  context.addInitializer(function (this: This) {
    Object.defineProperty(this, context.name, {
      value: _method.bind(this), writable: true, configurable: true
    });
  });
}

class Button {
  label = "Click me";
  @bound
  handleClick() { return this.label; }
}
const button = new Button();
const detached = button.handleClick;
console.log(detached()); // "Click me"

// A field decorator instead receives undefined as its first argument and
// may return an initializer: (this: This, initialValue: Value) => Value.

```

## Code Examples

### Practical Examples

The following decorators use the legacy API. `Min` decorates an accessor, because a legacy property decorator cannot observe a field initializer; defining a setter on the prototype can be bypassed by emitted class fields.

```typescript
// ─── Validation Decorators ────────────────────────────────────
function Min(length: number) {
  return function (_target: object, propertyKey: string, descriptor: PropertyDescriptor) {
    const originalSetter = descriptor.set;
    if (!originalSetter) throw new Error(`${propertyKey} needs a setter`);
    descriptor.set = function (value: string) {
      if (value.length < length) throw new Error(`${propertyKey} needs ${length} characters`);
      originalSetter.call(this, value);
    };
  };
}

class Form {
  private _username = "";
  private _password = "";

  @Min(3)
  set username(value: string) { this._username = value; }
  get username() { return this._username; }

  @Min(8)
  set password(value: string) { this._password = value; }
  get password() { return this._password; }
}

// ─── Caching Decorator ────────────────────────────────────────
function Cache(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  const originalMethod = descriptor.value;
  const caches = new WeakMap<object, Map<string, any>>();

  descriptor.value = function (...args: any[]) {
    const key = JSON.stringify(args);
    let cache = caches.get(this);
    if (!cache) { cache = new Map(); caches.set(this, cache); }

    if (cache.has(key)) {
      console.log(`Cache hit for ${propertyKey}`);
      return cache.get(key);
    }

    const result = originalMethod.apply(this, args);
    cache.set(key, result);
    // Retry rejected async work on a later call instead of caching failure forever.
    if (result instanceof Promise) {
      void result.catch(() => { if (cache!.get(key) === result) cache!.delete(key); });
    }
    return result;
  };
}

class DataService {
  @Cache
  getUser(id: string): Promise<User> {
    console.log(`Fetching user ${id}`);
    return fetch(`/api/users/${id}`).then(r => r.json());
  }
}

// ─── Retry Decorator ──────────────────────────────────────────
function Retry(maxRetries: number = 3) {
  return function (
    target: any,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ) {
    if (!Number.isInteger(maxRetries) || maxRetries < 0) throw new Error("Invalid retry count");
    const originalMethod = descriptor.value;

    descriptor.value = async function (...args: any[]) {
      let lastError: unknown;

      for (let i = 0; i <= maxRetries; i++) {
        try {
          return await originalMethod.apply(this, args);
        } catch (error) {
          lastError = error;
          console.log(`Attempt ${i + 1}/${maxRetries + 1} failed`);
          if (i < maxRetries) {
            await new Promise(resolve =>
              setTimeout(resolve, 1000 * (i + 1))
            );
          }
        }
      }

      throw lastError;
    };
  };
}

class ApiClient {
  @Retry(3)
  async fetchData(url: string): Promise<any> {
    const response = await fetch(url);
    if (!response.ok) throw new Error("Request failed");
    return response.json();
  }
}

```

### Advanced Patterns

This minimal DI example registers no-argument services and stores constructor parameter tokens; `resolve` is the missing consumer that turns metadata into arguments. It is intentionally smaller than a framework container (no scopes or cycle detection).

```typescript
// ─── Dependency Injection ─────────────────────────────────────
const dependencies = new Map<string, any>();

function Injectable(constructor: new () => object) {
  dependencies.set(constructor.name, new constructor());
}

function Inject(dependency: string) {
  return function (target: object, propertyKey: string | symbol | undefined, parameterIndex: number) {
    const existingDependencies: string[] =
      Reflect.getOwnMetadata("dependencies", target, propertyKey) || [];
    existingDependencies[parameterIndex] = dependency;
    Reflect.defineMetadata("dependencies", existingDependencies, target, propertyKey);
  };
}

function resolve<T>(constructor: new (...args: any[]) => T): T {
  const tokens: string[] = Reflect.getOwnMetadata("dependencies", constructor) ?? [];
  const args = tokens.map(token => {
    if (!dependencies.has(token)) throw new Error(`Missing dependency: ${token}`);
    return dependencies.get(token);
  });
  return new constructor(...args);
}

@Injectable
class DatabaseService {
  // Parameterized queries only — never interpolate values into SQL strings
  query(sql: string, params: unknown[] = []): any[] {
    return [];
  }
}

class UserService {
  constructor(
    @Inject("DatabaseService") private db: DatabaseService
  ) {}

  getUser(id: string): any {
    return this.db.query('SELECT * FROM users WHERE id = $1', [id]);
  }
}

const userService = resolve(UserService);

// ─── Event Emitter Decorator ──────────────────────────────────
function OnEvent(event: string) {
  return function (
    target: any,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ) {
    const originalMethod = descriptor.value;

    if (!target.constructor._eventHandlers) {
      target.constructor._eventHandlers = {};
    }

    target.constructor._eventHandlers[event] = originalMethod;
  };
}

class EventHandler {
  @OnEvent("user:created")
  handleUserCreated(payload: { userId: string }): void {
    console.log(`User ${payload.userId} created`);
  }

  @OnEvent("order:placed")
  handleOrderPlaced(payload: { orderId: string }): void {
    console.log(`Order ${payload.orderId} placed`);
  }
}

// ─── Auto-bind Decorator ──────────────────────────────────────
function AutoBind(
  target: any,
  propertyKey: string,
  descriptor: PropertyDescriptor
) {
  const originalMethod = descriptor.value;

  return {
    configurable: true,
    get() {
      const bound = originalMethod.bind(this);
      Object.defineProperty(this, propertyKey, {
        value: bound,
        configurable: true,
        writable: true
      });
      return bound;
    }
  };
}

class Button {
  label = "Click me";

  @AutoBind
  handleClick() {
    console.log(this.label);
  }
}

```

## Real-World Use Cases

- **NestJS DI** — `@Injectable()` + parameter decorators + `emitDecoratorMetadata` are the framework (→ 20.2.1.04); understanding them demystifies every Nest interview question.
- **Custom request context** — a `@CurrentUser()` parameter decorator reading from the request (the exact code in 10.2.4.05) is a real first-week task.
- **Validation/serialization hooks** — class decorators registering metadata that validators read at runtime (class-validator's whole model).

## Common Mistakes

### 1. Not Preserving `this` Context

Calling a saved method as `originalMethod(...args)` drops its receiver. The wrapper in **How It Works** uses `originalMethod.apply(this, args)` to preserve the caller's instance; binding at construction time is the separate concern demonstrated by Stage 3 `bound`.

### 2. Confusing Mutation with Replacement

A legacy method decorator may mutate the supplied descriptor and return nothing; the `Log` example in **How It Works** does exactly this. Return a descriptor when replacing it. A Stage 3 method decorator instead returns a replacement function, or nothing to keep the original; returning an unchanged original method is valid.

### 3. Mixing the Two APIs

A legacy method decorator receives `(target, key, descriptor)`; a Stage 3 method decorator receives `(value, context)`. Compiler mode and function signature must agree. Parameter decorators and legacy design-type metadata require legacy mode; Stage 3 does not bridge those APIs automatically.

## Best Practices

- Choose the decorator API required by the framework and document its compiler flags.
- Keep each decorator focused; prefer ordinary functions when declaration-site registration is unnecessary.
- Stacked decorator expressions evaluate top to bottom, then apply bottom to top. Wrapper nesting follows that application order, so the outer decorator runs first when the method is called.
- Metadata only describes a declaration: document which validator, router or container consumes it.
- Define cache keys and eviction policy for the domain. The example isolates instances and evicts rejected promises, but JSON keys cannot represent cycles, functions or every object distinction.
- Retry only operations for which repeated execution is acceptable, and distinguish retries from the initial attempt.

## Performance Considerations

- **Runtime overhead**: Decorators add runtime cost
- **Memory**: Cached decorators consume memory
- **Startup time**: Many decorators slow application startup
- **Tree shaking**: Decorators may prevent tree shaking
- **Debugging**: Decorators can make debugging harder

## Summary

Decorators enable metaprogramming in TypeScript, allowing you to add behavior to classes and methods declaratively. They're essential for frameworks like Angular and NestJS. Understand both experimental and stage 3 decorator APIs.

# Decorators

## Definition

**Decorators** are functions applied while defining a class or a supported member. They can replace a method, arrange initialization, or register information for another part of the application. That registered information is **metadata**: a description of a declaration which a router, validator or dependency container can read later. Recording metadata does not itself run the described behavior.

> **Textbook Definition:** A decorator is an evaluation-time function applied to a class or supported class element to customize its definition or initialization. Standard decorators and TypeScript's legacy experimental decorators have different signatures and capabilities.

## First Principles

A method shared on a prototype cannot know which future instance will call it. A decorator can wrap that method once at class definition, but preserving the caller still requires forwarding `this`. Work which depends on a particular instance needs an initializer or a later invocation. These three times explain most decorator behavior:

```text
class definition → evaluate decorators → wrap method or save metadata
new instance    → initialize fields and any registered instance hooks
method call     → wrapper runs, or framework reads metadata and dispatches
```

A class annotation looks local, while its behavior may live in a separate consumer. Follow both pieces to explain a request: which decorator records a route, which router resolves it, and which instance supplies the receiver.

## Why It Matters

Frameworks use declaration-site registration to connect controllers, validators and services without repeating a registration call beside each class. Wrappers also share logging and other call behavior. The benefit comes with an extra debugging step: inspect the decorator's API, its application order and the consumer of its metadata.

## How It Works

### Choose one calling convention for a project

| Target | Legacy `experimentalDecorators: true` | Standard convention, flag disabled |
| ---------------------------- | -------------------------------------------------------- | ------------------------------------------------------- |
| Class | Constructor; may return replacement constructor | Constructor and class context; may return replacement |
| Method/getter/setter | Target, key and descriptor | Member function and context; may return replacement |
| Field | Target and key; no initializer interception | Undefined and context; may return an initializer |
| Auto-accessor (`accessor x`) | No standard auto-accessor protocol | Get/set functions and context; may replace get/set/init |
| Constructor/method parameter | Target, member key or undefined, argument index | Unavailable |
| Design-type metadata | Optional `emitDecoratorMetadata` with a runtime consumer | Incompatible with legacy `emitDecoratorMetadata` |

These are separate compiler modes, not two interchangeable signatures. Use TypeScript 5.0+ and `strict: true` for the independent files below. Compile standard examples with `experimentalDecorators` disabled; compile legacy examples with it enabled. Metadata examples also need the installed `reflect-metadata` package and its runtime import. A full legacy configuration has flags inside `compilerOptions`:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "strict": true,
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true
  }
}
```

Explicit metadata below uses `Reflect.defineMetadata`; it does not need the compiler to infer design types. `emitDecoratorMetadata` helps frameworks read some runtime constructor information, but erased interfaces, generics and type-only imports are not complete runtime validators or dependency tokens.

### A legacy wrapper preserves the original call

```typescript
function Log(_target: object, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  descriptor.value = function (this: object, ...args: unknown[]) {
    console.log(`Calling ${key} with`, args);
    const result = original.apply(this, args);
    console.log('Result:', result);
    return result;
  };
}
class Calculator {
  @Log
  add(a: number, b: number): number { return a + b; }
}
const calculator = new Calculator();
console.log(calculator.add(2, 3));
// Calling add with [2, 3]; Result: 5; then the caller prints 5.
```

At class definition, `Log` replaces the descriptor's method. At the later call, the wrapper forwards the receiver and both arguments, calls the saved method, and returns the same result. If the original throws, the result log is skipped and the exception propagates. If it returns a promise, this wrapper logs that promise immediately, not its eventual fulfillment. `PropertyDescriptor.value` is permissively typed; the runtime assumption here is that this decorator is used on a method.

### Standard replacement and instance binding are separate

```typescript
function log<This, Args extends unknown[], Result>(
  original: (this: This, ...args: Args) => Result,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Result>
) {
  return function (this: This, ...args: Args): Result {
    console.log(`Calling ${String(context.name)}`);
    return original.apply(this, args);
  };
}
function bound<This extends object, Args extends unknown[], Result>(
  _method: (this: This, ...args: Args) => Result,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Result>
) {
  if (context.private || context.static) throw new Error('Expected a public instance method');
  context.addInitializer(function () {
    // Read the final decorated method, including replacements from other decorators.
    const finalMethod = Reflect.get(this, context.name);
    if (typeof finalMethod !== 'function') throw new Error('Expected method');
    Object.defineProperty(this, context.name, {
      value: finalMethod.bind(this), writable: true, configurable: true
    });
  });
}
class Button {
  label = 'Click me';
  @log
  @bound
  handleClick() { return this.label; }
}
const button = new Button();
const detached = button.handleClick;
console.log(detached()); // Calling handleClick; Click me.
```

`bound` schedules work rather than replacing the method at definition time. Its initializer reads the final method from the instance, so an outer `log` replacement is preserved. Binding the captured `_method` instead would bypass that outer wrapper. The initializer runs before instance fields; it binds a function but does not read `label` until the later call. Each instance receives its own stable bound function. This helper intentionally rejects private and static members rather than pretending their access rules are identical.

### Fields initialize once; accessors can intercept later writes

```typescript
function trimField<This>(
  _value: undefined, _context: ClassFieldDecoratorContext<This, string>
) {
  return function (initial: string) { return initial.trim(); };
}
function nonnegative<This>(
  target: ClassAccessorDecoratorTarget<This, number>,
  _context: ClassAccessorDecoratorContext<This, number>
): ClassAccessorDecoratorResult<This, number> {
  function check(value: number) {
    if (!Number.isFinite(value) || value < 0) throw new Error('Expected finite nonnegative value');
    return value;
  }
  return {
    init: check,
    set(value) { target.set.call(this, check(value)); }
  };
}
class Profile {
  @trimField name = ' Ada ';
  @nonnegative accessor visits = 0;
}
const profile = new Profile();
console.log(profile.name); // Ada
profile.name = ' Grace '; // A plain field write; it is not trimmed.
profile.visits = 2; // Setter validates; assigning -1 would throw.
```

A field initializer changes the initial value only. An auto-accessor provides hidden storage plus get/set operations; the replacement setter can validate every subsequent assignment, while `init` checks the first value. Decorating a plain field is not equivalent to intercepting all writes.

## Code Examples

### Sealing a class does not seal its instances

```typescript
function Sealed(constructor: Function) {
  Object.seal(constructor);
  Object.seal(constructor.prototype);
}
@Sealed
class Greeter {
  constructor(public greeting: string) {}
  greet() { return this.greeting; }
}
const greeter = new Greeter('Hello');
console.log(Object.isSealed(Greeter), Object.isSealed(greeter)); // true, false
```

This legacy class decorator prevents adding or removing properties on the constructor and prototype. Existing writable members can still change, and new instances remain unsealed. In standard mode a class decorator receives the constructor and context instead; it can perform the same operations and return the original constructor or a compatible replacement.

### Metadata needs a validator to read it

This legacy file requires `reflect-metadata`. It deliberately reads only the immediate class prototype; supporting inherited required fields would need an explicit merge policy.

```typescript
import 'reflect-metadata';
function Required(target: object, key: string) {
  const fields: string[] = Reflect.getOwnMetadata('requiredFields', target) ?? [];
  Reflect.defineMetadata('requiredFields', [...fields, key], target);
}
function missingRequired(instance: object): string[] {
  const prototype = Object.getPrototypeOf(instance);
  const fields: string[] = Reflect.getOwnMetadata('requiredFields', prototype) ?? [];
  return fields.filter(key => {
    const value: unknown = Reflect.get(instance, key);
    return typeof value !== 'string' || value.trim().length === 0;
  });
}
class User {
  @Required name = '';
}
const user = new User();
console.log(missingRequired(user)); // ['name']
user.name = 'Ada';
console.log(missingRequired(user)); // []
```

`Required` stores the name while defining the class. `new User()` still sets an empty field. Only `missingRequired(user)` reads the saved list and checks actual values. A legacy parameter decorator similarly stores an argument index; a method wrapper or framework must read that index and validate the corresponding invocation argument.

### An accessor wrapper checks assignments in legacy mode

```typescript
function Min(length: number) {
  if (!Number.isSafeInteger(length) || length < 0) throw new Error('Invalid minimum');
  return function (_target: object, key: string, descriptor: PropertyDescriptor) {
    const originalSetter = descriptor.set;
    if (!originalSetter) throw new Error(`${key} needs a setter`);
    descriptor.set = function (value: unknown) {
      if (typeof value !== 'string' || value.length < length) {
        throw new Error(`${key} needs ${length} characters`);
      }
      originalSetter.call(this, value);
    };
  };
}
class Form {
  private _username = '';
  @Min(3)
  set username(value: string) { this._username = value; }
  get username() { return this._username; }
}
const form = new Form();
form.username = 'Ada';
console.log(form.username); // Ada; assigning 'ab' throws before changing storage.
```

The descriptor exposes the setter receiving each assignment. A legacy property decorator receives only the prototype and key, so it cannot observe a field initializer. Installing a prototype setter for a field can also be bypassed by emitted own class fields. This accessor example avoids that mismatch.

### Caching requires receiver identity and a bounded policy

A cache wrapper must forward `this` and isolate receivers: the same ID can produce different results from two service instances. Keep the cache algorithm in [Memoization](../../10.1-javascript/05-functional-patterns/10.1.5.02-memoization.md); an adapter can keep a `WeakMap<instance, memoizedFunction>`, binding each function to its instance and choosing a capacity there. The receiver map permits unused instances to become collectible; it does not bound a live instance's cached entries.

Use string IDs or a domain-defined key contract rather than assuming `JSON.stringify(args)` preserves every distinction. Define how cached promises fail, expire or become invalid when instance state changes. Decorating a method does not make it pure or turn unchecked response JSON into a typed user.

### Retries count attempts and need a failure policy

This independent legacy example accepts asynchronous methods only. Its default zero delay makes the trace quick; a real network policy can supply a delay and select transient failures.

```typescript
function Retry(
  maxRetries = 3,
  shouldRetry: (error: unknown) => boolean = () => true,
  delayMs = 0
) {
  if (!Number.isSafeInteger(maxRetries) || maxRetries < 0 ||
      !Number.isFinite(delayMs) || delayMs < 0) throw new Error('Invalid retry policy');
  return function (_target: object, _key: string, descriptor: PropertyDescriptor) {
    const original = descriptor.value;
    descriptor.value = async function (this: object, ...args: unknown[]) {
      for (let attempt = 0; ; attempt++) {
        try { return await original.apply(this, args); }
        catch (error) {
          if (attempt === maxRetries || !shouldRetry(error)) throw error;
          if (delayMs > 0) await new Promise(resolve => setTimeout(resolve, delayMs));
        }
      }
    };
  };
}
class ExampleService {
  attempts = 0;
  @Retry(3)
  async read() {
    if (++this.attempts < 3) throw new Error('temporary');
    return 'ready';
  }
}
const service = new ExampleService();
void service.read().then(value => console.log(value, service.attempts)); // ready 3
```

`Retry(3)` allows four attempts: one initial call plus three retries. A permanent failure predicate can stop after one. Repeated execution must be acceptable for the operation; retrying a write can duplicate its effects. The wrapper always returns a promise and does not cancel a pending attempt or enforce a deadline. A never-settling attempt prevents the loop from advancing.

### Constructor parameter tokens need a container

This legacy file requires `reflect-metadata`. Symbols avoid collisions between class names or names altered by minification. The container eagerly creates no-argument singleton services and requires an explicit token for each required constructor argument. It omits optional/default/rest arguments, scopes and dependency cycles.

```typescript
import 'reflect-metadata';
const dependencies = new Map<symbol, object>();
function Injectable(token: symbol) {
  return function (constructor: new () => object) {
    if (dependencies.has(token)) throw new Error('Duplicate token');
    dependencies.set(token, new constructor());
  };
}
function Inject(token: symbol) {
  return function (target: object, key: string | symbol | undefined, index: number) {
    if (key !== undefined) throw new Error('Inject supports constructor parameters only');
    const tokens: symbol[] = Reflect.getOwnMetadata('dependencies', target) ?? [];
    const copy = tokens.slice();
    copy[index] = token;
    Reflect.defineMetadata('dependencies', copy, target);
  };
}
function resolve<T>(constructor: new (...args: any[]) => T): T {
  const tokens: symbol[] = Reflect.getOwnMetadata('dependencies', constructor) ?? [];
  const args = Array.from({ length: constructor.length }, (_, index) => {
    const token = tokens[index];
    if (!token || !dependencies.has(token)) throw new Error(`Missing dependency at ${index}`);
    return dependencies.get(token);
  });
  return new constructor(...args);
}
const DATABASE = Symbol('database');
@Injectable(DATABASE)
class DatabaseService {
  private names = new Map([['u1', 'Ada']]);
  findName(id: string) { return this.names.get(id); }
}
class UserService {
  constructor(@Inject(DATABASE) private database: DatabaseService) {}
  getName(id: string) { return this.database.findName(id); }
}
const userService = resolve(UserService);
console.log(userService.getName('u1')); // Ada
```

Class decoration installs the singleton under `DATABASE`. Parameter decoration records that token at index zero. `resolve` reads the constructor metadata, looks up the object and calls `new UserService(database)`. A missing token fails before constructing the consumer. This small container assumes every required parameter participates; `constructor.length` stops before defaults and does not represent optional/rest policy. A full framework resolves dependency graphs, lifetimes, cycles and explicit registration rules as well as metadata.

### Event registration and legacy autobinding have different consumers

An `@OnEvent('user:created')` decorator can record an event name and method key. A subscriber must later resolve the instance, attach a bound method to a bus, and keep the unsubscribe function for cleanup. Store registrations per class in a `WeakMap` or own metadata and define how inheritance combines them; mutating an inherited `_eventHandlers` object can change the base class's registry. [Advanced Patterns](10.2.4.05-advanced-patterns.md) owns the typed bus and its dispatch policy.

A legacy autobinder can defer creation of the bound function until first instance access:

```typescript
function AutoBind(_target: object, key: string, descriptor: PropertyDescriptor) {
  const original = descriptor.value;
  return {
    configurable: true,
    get(this: object) {
      const bound = original.bind(this);
      Object.defineProperty(this, key, { value: bound, configurable: true, writable: true });
      return bound;
    }
  };
}
class Button {
  label = 'Click me';
  @AutoBind handleClick() { return this.label; }
}
const button = new Button();
const first = button.handleClick;
console.log(first === button.handleClick, first()); // true, Click me
```

The first instance read uses the prototype getter and installs an own method. Later reads reuse that function, preserving callback identity. Different instances get different bound functions. This implementation is intended for instance reads; reading the getter through `Button.prototype` would bind to that prototype and install a property there.

### Trace stacked evaluation, application and calls separately

Standard mode, independent file:

```typescript
const trace: string[] = [];
function mark(label: string) {
  trace.push(`evaluate ${label}`);
  return function <This, Args extends unknown[], Result>(
    method: (this: This, ...args: Args) => Result,
    _context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Result>
  ) {
    trace.push(`apply ${label}`);
    return function (this: This, ...args: Args): Result {
      trace.push(`call ${label}`);
      return method.apply(this, args);
    };
  };
}
class Example {
  @mark('A')
  @mark('B')
  run() { trace.push('body'); return 5; }
}
new Example().run();
console.log(trace);
// evaluate A, evaluate B, apply B, apply A, call A, call B, body
```

Expressions evaluate top to bottom, then decorators apply bottom to top. B wraps the body first; A wraps B. At invocation A therefore runs first. If wrappers depend on each other's return type, metadata or side effects, swapping annotations can change behavior.

## Real-World Decisions

Use metadata when a framework owns a lifecycle such as routing or dependency resolution. Use a wrapper when behavior must surround each invocation, and an initializer when work needs an instance. An ordinary higher-order function is often easier to inspect when declaration-site registration offers no benefit. For framework decorators, follow its supported compiler mode and registration conventions; decorators alone are not the entire DI or routing system.

## Common Mistakes

- Calling a saved method without `.apply(this, args)` loses its receiver. Binding once is a separate choice from forwarding the current receiver.
- Returning a legacy descriptor is optional after mutating it; return a descriptor when supplying a replacement. Standard method decorators instead return a replacement function or nothing.
- A field decorator, class seal or metadata record does not automatically validate future instance writes.
- An outer wrapper can be skipped if a binding initializer captures the earlier undecorated method.
- Parameter metadata and compiler design types are incomplete without a consumer, dependency registration and runtime checks where needed.

## Best Practices

Document compiler flags, initialization timing, supported targets and the metadata consumer. Preserve argument and result types in standard wrappers. Define inheritance, cleanup and failure behavior for registration. Keep cache, retry and DI policies explicit instead of hiding them behind an annotation name. Check stacked call traces when order changes.

## Performance Considerations

Definition-time registration, per-instance binding, per-call wrappers and cache retention have different costs. Measure the phase that matters for the application. Binding allocates one function per instance, a wrapper adds work to each call, and cache entries remain while their owner retains them. Decorators with observable registration also affect what a bundler can remove.

## Summary

A decorator can replace behavior, schedule initialization or register metadata. Explain which phase it acts in and who consumes its result. Legacy and standard APIs have distinct signatures and compiler modes; instance state, invocation receiver, composition order and cleanup remain ordinary runtime responsibilities.

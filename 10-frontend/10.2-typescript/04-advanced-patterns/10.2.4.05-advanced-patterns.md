# Composing Advanced TypeScript Patterns

A producer emits `appointment:created` and a listener expects an appointment payload. A stringly typed bus can pair that event with a cancellation payload by mistake. This chapter follows one typed event bus from its static contract through runtime dispatch and cleanup.

```typescript
type EventMap = {
  'appointment:created': { appointmentId: string; clinicId: string };
  'appointment:cancelled': { appointmentId: string; reason: string };
};

const emitter = new TypedEventEmitter<EventMap>();
emitter.on('appointment:created', (event) => console.log(event.appointmentId));
emitter.emit('appointment:created', { appointmentId: 'a1', clinicId: 'c1' }); // logs a1
// emitter.emit('appointment:created', { appointmentId: 'a3', reason: 'x' }); // rejected
```

## Definition

Advanced TypeScript patterns compose existing type features to preserve relationships across an API. Here, generics, mapped types and indexed access keep each event name paired with its payload. Runtime code must still implement the relationship and validate real values.

> **Textbook Definition:** Type-level composition derives a contract by combining generic parameters, mapped properties, conditional branches or string transformations. The derived type constrains static callers; runtime code remains responsible for implementing the relationship and validating external data.

## First Principles

For each event key, derive a tuple containing that key and its payload. Form a union of those complete tuples. Do not make a union of names and a separate union of payloads; doing so loses which values belong together.

## 1. Pair Each Event Name with Its Payload

The mapped type builds one `[event, payload]` tuple per key, then indexes into the union of all of them — so each name stays correlated with its own payload:

```typescript
type EventMap = {
  'appointment:created': { appointmentId: string; clinicId: string };
  'appointment:cancelled': { appointmentId: string; reason: string };
};

type EventArgs<Events extends object> = {
  [K in keyof Events]: [event: K, payload: Events[K]]
}[keyof Events];

class TypedEventEmitter<Events extends object> {
  private listeners = new Map<keyof Events, Set<(payload: unknown) => void>>();

  on<K extends keyof Events>(
    event: K,
    listener: (payload: Events[K]) => void
  ): () => void {
    const entry = (payload: unknown) => listener(payload as Events[K]);
    let group = this.listeners.get(event);

    if (!group) {
      group = new Set();
      this.listeners.set(event, group);
    }
    group.add(entry);

    return () => {
      group.delete(entry);
      if (group.size === 0 && this.listeners.get(event) === group) {
        this.listeners.delete(event);
      }
    };
  }

  emit(...[event, payload]: EventArgs<Events>): void {
    const group = this.listeners.get(event);
    if (!group) return;

    // Snapshot: subscription changes affect the next emit.
    for (const listener of [...group]) listener(payload);
  }
}

const emitter = new TypedEventEmitter<EventMap>();
const unsubscribe = emitter.on('appointment:created', event => {
  console.log(event.appointmentId);
});

emitter.emit('appointment:created', {
  appointmentId: 'a1',
  clinicId: 'c1'
}); // Listener logs a1.

unsubscribe();
emitter.emit('appointment:created', {
  appointmentId: 'a2',
  clinicId: 'c1'
}); // No log.

// @ts-expect-error — the cancellation payload belongs to a different event
emitter.emit('appointment:created', { appointmentId: 'a3', reason: 'conflict' });
```

The generic constraint is `object`, not `Record<string, unknown>`, so an interface event map need not claim that every possible string key exists. The one assertion is inside storage, where the map has erased the callback's payload type. Registration fixes the event key and listener parameter; the tuple union checks the same pairing at dispatch. The assertion is justified by that invariant. An untrusted message or `any` can bypass it, so decode the payload before emitting it.

## Dispatch policy is part of the API

This implementation is synchronous and calls listeners in registration order. A thrown error propagates and stops later listeners. A promise returned by a listener is not awaited. Subscription changes during an emit affect the next emit because the current listener set was copied first; recursive emits take a new snapshot immediately.

The disposer removes its own registration and is safe to call repeatedly. Owners must retain and call it to release listener closures. If consumers need asynchronous delivery, isolated listener failures or queued events, define those as runtime policies rather than changing the type signature alone.

## Summary

Compose type features only when they protect a real API relationship. The event map couples each name to its payload; the runtime bus supplies ordering, error, cleanup and validation behavior that types cannot provide.

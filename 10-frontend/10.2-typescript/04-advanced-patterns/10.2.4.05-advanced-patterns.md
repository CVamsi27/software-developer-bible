# TypeScript Advanced Patterns — Decorators, Middleware, Advanced Generics

## TL;DR

The composition layer: decorators (class/parameter/property metadata — the mechanics behind NestJS), the type-level toolkit composing (conditional + mapped + template-literal types), and branded types for nominal identity in a structural system. Rule of thumb: reach for these when types must *describe behavior* (DI, event maps, route params) — and stop when the type is harder to read than the code it constrains.

## First Principles

The advanced patterns are compositions of the primitives — none are new machinery:

1. **Builder/fluent APIs via `this` types**, exhaustive switches via `never`, module augmentation via declaration merging, deep transforms via recursive conditionals — each is derivable from (→ 10.2.2, → 10.2.3); knowing the primitives means you can *reinvent* the pattern when needed.
2. **Complexity is the budget**: every clever type shows up in error messages and onboarding time — the senior skill is spending it where runtime correctness actually benefits (→ 10.2.4.02's domain-safety rule).

## Definition

**Advanced TS patterns** are the idioms built by composing the type system's primitives: decorators (metadata over classes/parameters), conditional types (`T extends U ? X : Y`), mapped types (`[P in keyof T]`), template literal types (string-level parsing), and branded types (intersection-based nominal tags). Each chapter file covers one primitive; this file shows them composed.

## Why It Matters

Real codebases don't use these patterns one at a time — `TypedEventEmitter` needs mapped+conditional+generics together, NestJS needs decorators+reflection together, API layers need branded IDs + discriminated unions together. The interview signal is *composition*: can you glue three primitives into one ergonomic, type-safe API — and do you know when not to?

## Class Decorators

```typescript
// Controller decorator (NestJS-style)
function Controller(path: string) {
  return function (target: Function) {
    Reflect.defineMetadata('path', path, target);
  };
}

// Method decorator
function Get(path: string) {
  return function (target: any, propertyKey: string, descriptor: PropertyDescriptor) {
    const existingMetadata = Reflect.getMetadata('routes', target.constructor) || [];
    existingMetadata.push({
      method: 'GET',
      path,
      handler: propertyKey
    });
    Reflect.defineMetadata('routes', existingMetadata, target.constructor);
  };
}

// Usage
@Controller('appointments')
class AppointmentController {
  @Get(':id')
  findOne(@Param('id') id: string) {
    return { id, status: 'booked' };
  }
}
```

## Parameter Decorators

```typescript
// Custom parameter decorator
function CurrentUser() {
  return function (target: any, propertyKey: string, parameterIndex: number) {
    const existingMetadata = Reflect.getMetadata('params', target.constructor, propertyKey) || [];
    existingMetadata.push({
      index: parameterIndex,
      type: 'user'
    });
    Reflect.defineMetadata('params', existingMetadata, target.constructor, propertyKey);
  };
}

// Usage
class AppointmentController {
  create(@CurrentUser() user: User, @Body() data: CreateAppointmentDto) {
    // user is injected from request context
  }
}
```

## Advanced Generics

```typescript
// Type-safe event emitter
type EventMap = {
  'appointment:created': { appointmentId: string; clinicId: string };
  'appointment:cancelled': { appointmentId: string; reason: string };
  'user:login': { userId: string; timestamp: Date };
};

class TypedEventEmitter<Events extends Record<string, any>> {
  private listeners: Map<string, Function[]> = new Map();

  on<K extends keyof Events>(
    event: K,
    listener: (data: Events[K]) => void
  ): void {
    const existing = this.listeners.get(event as string) || [];
    existing.push(listener);
    this.listeners.set(event as string, existing);
  }

  emit<K extends keyof Events>(event: K, data: Events[K]): void {
    const listeners = this.listeners.get(event as string) || [];
    listeners.forEach(listener => listener(data));
  }
}

// Usage
const emitter = new TypedEventEmitter<EventMap>();
emitter.on('appointment:created', (data) => {
  // data is typed as { appointmentId: string; clinicId: string }
  console.log(data.appointmentId);
});
```

## Conditional Types

```typescript
// Extract return type of async function
type AsyncReturnType<T extends (...args: any) => Promise<any>> =
  T extends (...args: any) => Promise<infer R> ? R : never;

// Usage
async function getUser() {
  return { id: '1', name: 'John' };
}

type User = AsyncReturnType<typeof getUser>; // { id: string; name: string }

// Conditional type for API responses
type ApiResponse<T> = T extends 'user'
  ? { id: string; name: string; email: string }
  : T extends 'appointment'
  ? { id: string; scheduledAt: Date; status: string }
  : never;

// Usage
function getData<T extends 'user' | 'appointment'>(type: T): Promise<ApiResponse<T>> {
  // Implementation
}
```

## Mapped Types

```typescript
// Make all properties optional recursively
type DeepPartial<T> = {
  [P in keyof T]?: T[P] extends object ? DeepPartial<T[P]> : T[P];
};

// Make all properties required
type DeepRequired<T> = {
  [P in keyof T]-?: T[P] extends object ? DeepRequired<T[P]> : T[P];
};

// Pick properties by value type
type PickByType<T, ValueType> = {
  [P in keyof T as T[P] extends ValueType ? P : never]: T[P];
};

// Usage
interface Appointment {
  id: string;
  status: string;
  scheduledAt: Date;
  notes?: string;
}

type AppointmentUpdate = DeepPartial<Appointment>; // All fields optional
type AppointmentRequired = DeepRequired<Appointment>; // All fields required
type StringFields = PickByType<Appointment, string>; // { id: string; status: string }
```

## Template Literal Types

```typescript
// Type-safe route parameters
type RouteParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof RouteParams<Rest>]: string }
    : T extends `${string}:${infer Param}`
    ? { [K in Param]: string }
    : {};

// Usage
type Params = RouteParams<'/appointments/:clinicId/patients/:patientId'>;
// { clinicId: string; patientId: string }

// Type-safe event names
type DomainEvent = `${'appointment' | 'patient' | 'clinician'}.${'created' | 'updated' | 'deleted'}`;

// Usage
function onEvent(event: DomainEvent, handler: () => void) {}
onEvent('appointment.created', () => {}); //
onEvent('appointment.invalid', () => {}); // Type error
```

## Branded Types

```typescript
// Prevent mixing of similar types
type UserId = string & { readonly __brand: 'UserId' };
type AppointmentId = string & { readonly __brand: 'AppointmentId' };

function createUserId(id: string): UserId {
  return id as UserId;
}

function createAppointmentId(id: string): AppointmentId {
  return id as AppointmentId;
}

// Usage
const userId = createUserId('user-123');
const appointmentId = createAppointmentId('apt-456');

function getUser(id: UserId) { /* ... */ }
function getAppointment(id: AppointmentId) { /* ... */ }

getUser(userId); //
getUser(appointmentId); // Type error
```

## Utility Type Combinations

```typescript
// API response types
type SuccessResponse<T> = {
  success: true;
  data: T;
  timestamp: Date;
};

type ErrorResponse = {
  success: false;
  error: {
    type: string;
    title: string;
    status: number;
    detail: string;
  };
};

type ApiResponse<T> = SuccessResponse<T> | ErrorResponse;

// Type guard
function isSuccessResponse<T>(response: ApiResponse<T>): response is SuccessResponse<T> {
  return response.success === true;
}

// Usage
const response: ApiResponse<User> = await fetchUser(userId);
if (isSuccessResponse(response)) {
  // response.data is typed as User
  console.log(response.data.name);
} else {
  // response.error is typed as error object
  console.error(response.error.detail);
}
```

## Real-World Use Cases

- **NestJS controllers/services** — decorators + `emitDecoratorMetadata` + `reflect-metadata` are the entire DI story (→ 20.2.1.04); the parameter decorator here is the `@CurrentUser()` you'll write on the job.
- **Typed event buses** — the `TypedEventEmitter` pattern above is how clinic events flow in Docita; the `EventMap` is the single source of truth for producers and consumers.
- **API layer typing** — branded IDs + `SuccessResponse<T> | ErrorResponse` discriminated union + type guard: the shape every REST client should have (→ 20.3.3.02).
- **Form/route parsing** — `RouteParams` turns a path string into a typed params object; the same trick types feature flags and query strings.

## Common Mistakes

1. **Type-level heroics over runtime validation** — a `DeepPartial` proves nothing about the bytes arriving over the wire; validate at boundaries (zod, → 10.5.02) and *then* trust types internally.
2. **Brands without constructors** — `id as UserId` everywhere means the brand proves nothing; create branded values only through functions that own the invariant.
3. **Decorators without `experimentalDecorators`/`emitDecoratorMetadata` alignment** — the tcconfig and the framework must agree (legacy vs ES decorators, → 10.2.4.03); the mismatch is the classic "decorator silently does nothing" bug.
4. **Conditional-type explosion** — nested conditionals over unions grow combinatorially; distribute only when needed (`[T] extends [U]` to disable distribution) or the error messages become unreadable.
5. **`any` smuggled through generic constraints** — `Events extends Record<string, any>` accepts everything; prefer `Record<string, unknown>` or a specific payload map.

## Best Practices

- **Compose two primitives, not five** — most real utilities are conditional + mapped; if you need more, reconsider the API.
- **Name the type, export the factory** — `createUserId` owns the invariant; callers never see the raw `as`.
- **Test types, not just code** — `expectTypeOf`/`tsd` assertions keep the composed types honest across refactors.
- **Keep decorators side-effect-light** — metadata registration, not behavior; behavior belongs in the framework's execution path.

## Cheat Sheet

```text
DECORATORS   @Injectable/@Get (class/method) · @Body/@Param (parameter)
             need experimentalDecorators + emitDecoratorMetadata
CONDITIONAL  T extends U ? X : Y        distributive over naked unions
MAPPED       { [P in K]-?: ... }        -? removes optionality, as renames
TEMPLATE     `${Prefix}-${infer Rest}`  parse strings at type level
BRAND        type UserId = string & { __brand: 'UserId' } · create via factory
COMPOSE      EventEmitter<K extends keyof E> · ApiResponse<T> union + guard
STOP WHEN    the type is harder to read than the code it constrains
```

## Summary

1. **Decorators modify classes declaratively** — NestJS's `@Injectable`, `@Get`, `@Body` are decorators over DI and routing
2. **Parameter decorators feed metadata** — the mechanism behind constructor injection
3. **Advanced generics (conditional + mapped + template literal) compose** — most real utility types are two of these glued together
4. **Branded types make invalid states unrepresentable** — `type UserId = string & { __brand: 'UserId' }`
5. **Know when to stop** — unreadable type-level code fails review; runtime validation at boundaries beats heroics in the type system

# Virtual DOM

A search box can render again on every keystroke without replacing its input node. That distinction explains what React’s “Virtual DOM” describes — and what the phrase does not mean.

```jsx
function SearchBox({ query, onChange }) {
  return <input value={query} onChange={onChange} />;
}
// Every keystroke creates a NEW element object —
// but React keeps the SAME browser <input> node and updates its value.
```

## Definition

The Virtual DOM (VDOM) is an informal name for the in-memory UI descriptions React uses when it calculates an update. JSX creates React elements that describe component or host-element types, props, keys and children. React compares the new description with its retained tree, then commits the host changes required to display the accepted result.

> **Textbook Definition:** A virtual DOM is an in-memory representation of a desired user interface that a renderer reconciles with its retained tree before applying changes to the host environment. In React, the term is shorthand rather than a public API or one persistent clone of the browser DOM.

## First Principles

The visible interface must reflect the state React has committed — imperative code has to coordinate every DOM mutation with that state by hand. Instead, a component describes its desired output as a function of props and state, and React compares descriptions before touching the host. A new description is not a new DOM node: React uses type and identity to decide which existing host nodes survive.

## 1. JSX Creates Descriptions, Not Nodes

Consider an input rendered at the same position with the same type. Each render creates a new React element object, but React can retain the existing browser input and update only the properties that changed. The object describing the input and the input node are different things.

## 2. Three Layers: Element, Fiber, DOM Node

| Layer | What it represents |
| ------------- | --------------------------------------------------------------------------- |
| React element | A description produced by JSX |
| Fiber | React’s internal work record for component identity, state and pending work |
| DOM node | A browser-owned node in the committed document |

Fiber is described in the next chapter. Neither the React element nor the fiber is the browser node.

## 3. The Useful Boundary

A virtual description does not make every update faster than carefully written DOM code. React still spends CPU evaluating components and reconciling output; the browser still performs style, layout, paint and compositing. Declarative rendering mainly gives the application one consistent way to describe the UI and lets the renderer coordinate host changes.

React Native and other renderers also show why “Virtual DOM” should not mean “a copy of the browser DOM”: React can reconcile descriptions into different host environments.

## Summary

React elements describe desired output; they are not DOM nodes and are not a literal, persistent clone of the page. React reconciles descriptions against retained identity and commits the necessary host changes. Measure component work, commit work and browser rendering separately when performance matters.

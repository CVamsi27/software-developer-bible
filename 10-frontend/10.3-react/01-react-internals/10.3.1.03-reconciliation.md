# Reconciliation

You edit a note in Ben’s row, then sort the patient list. If the note follows the row’s position instead of Ben, the screen can show the right names with the wrong state. Reconciliation is where React’s identity rules decide whether that row continues or is replaced.

```tsx
{patients.map(patient => (
  <PatientRow key={patient.id} patient={patient} />
))}
// Sort the list: each row's draft follows its patient — not its position.
```

## Definition

Reconciliation is the process React uses to match newly rendered elements with the existing component and host tree. A match determines which component state can continue and which host changes React needs to commit.

> **Textbook Definition:** Reconciliation compares a newly described element tree with a previously retained tree to determine component continuity, state preservation and host updates. Element type and position establish identity; keys distinguish sibling elements when their order or membership changes.

## First Principles

State belongs to a component identity, not to the value currently printed on screen. React therefore needs a rule for deciding whether a new element represents the same component as before — and for list siblings, that rule is the key.

## 1. Stable Keys Keep State with the Record

For siblings in a list, a stable key gives React a record-specific identity:

```tsx
{patients.map(patient => (
  <PatientRow key={patient.id} patient={patient} />
))}
```

If the rows reorder under the same parent and keep the same component type and key, React can preserve each row’s local state with its patient. An array index instead identifies a position. After a reorder, React may preserve the state at that position and pass it a different patient.

## 2. When Identity Changes

React resets local state when the component type changes or when its key changes. A matching key cannot preserve state across different parents or different component types. Choose keys to express the lifetime the product needs:

- Keep a stable domain key when a record moves among siblings and its draft should follow it.
- Change the key when selecting another record should start a fresh editing session.
- Store state above a component when it must survive that component’s removal.

Identity answers which state continues. It does not guarantee that React skips rendering or that the resulting update is cheap. Parent renders, component calculations and browser layout have separate costs.

## 3. Keys Are Scoped, Not Storage

A key is scoped to siblings; it is not a global identifier or a storage system. If a row is removed, its local state is destroyed. If it must survive filtering or navigation, keep the draft in an owner that outlives the row, keyed by the patient ID.

## Summary

Reconciliation uses type, tree position and sibling keys to match new elements with retained identities. Stable keys keep row state with the correct record; changing identity resets state. A key does not preserve state after unmount, work across parents or act as a performance switch.

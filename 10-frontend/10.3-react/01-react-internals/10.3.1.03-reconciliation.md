# Reconciliation

You edit a note in Ben's row, then sort the patient list. If the note follows the row's position instead of Ben, the screen shows the right names paired with the wrong draft. Reconciliation is where React's identity rules decide whether each row continues or resets.

```tsx
// excerpt
// Anti-pattern: position key leaves Ben's local draft attached to slot 0 after sorting
patients.map((patient, index) => <PatientRow key={index} patient={patient} />);
```

## Definition

Reconciliation is the process React uses to match newly rendered elements with the existing component and host tree. A match determines which component state can continue and which host changes React needs to commit.

> **Textbook Definition:** Reconciliation compares a newly described element tree with a previously retained tree to determine component continuity, state preservation, and host updates. Element type and position establish identity; a `key` distinguishes sibling elements when their order or membership changes.

## First Principles

State belongs to a component identity, not to the value currently printed on screen. A general optimal tree-edit algorithm takes cubic time, so React uses a practical heuristic: match by element type at the same tree position, and use an explicit sibling `key` when children move.

```text
key={index} (position identity) after reversing [Ben, Ada]:
  slot 0: key=0 -> reused old slot 0 fiber (Ben's draft!) now renders name="Ada"
  slot 1: key=1 -> reused old slot 1 fiber (Ada's draft!) now renders name="Ben"

key={patient.id} (record identity) after reversing [Ben, Ada]:
  slot 0: key="p-ada" -> matches Ada's old fiber (Ada's draft moves to slot 0)
  slot 1: key="p-ben" -> matches Ben's old fiber (Ben's draft moves to slot 1)
```

## 1. Stable `key`s Keep State With the Record

For siblings in a list, a stable domain `key` gives React a record-specific identity:

```tsx
function PatientList({ patients }: { patients: { id: string; name: string }[] }) {
  return (
    <ul>
      {patients.map((patient) => (
        <PatientRow key={patient.id} patient={patient} />
      ))}
    </ul>
  );
}
```

When rows reorder under the same parent and keep the same element type and `key`, React matches each fiber to its domain record and moves both its DOM node and local state together. When you pass an array index as `key`, React matches index `0` to index `0` and feeds Ada's props into Ben's retained state — a state-identity bug, not merely an extra render. Using unstable values like `key={Math.random()}` is even worse because every render forces a full unmount and remount (destroying DOM focus and state), while duplicate sibling keys cause skipped or misrouted updates.

## 2. When Identity Changes (Type vs. `key`)

React preserves state only when **both** element type and `key` match within the same parent:

- **Same `key`, different type:** React still marks the old fiber for deletion at commit and mounts a brand-new fiber with fresh state (for example, switching `<EditableRow key={id} />` to `<ReadOnlyRow key={id} />`).
- **Inline component or `React.memo` wrapper inside render:** declaring `const Row = memo(...)` inside a parent function creates a brand-new component type on every render, destroying child state and defeating memoization. Always define components and `React.memo` wrappers at module scope.
- **Deliberate state reset:** changing `key={selectedPatient.id}` on a detail panel intentionally unmounts the old instance and mounts a fresh one, clearing drafts, scroll positions, and uncontrolled inputs without manual Effect resets.

Conditional rendering keeps state intact when JSX preserves the child's slot position under the same parent. In `Page` below, JSX compiles `{showBanner && <Banner />}` to slot `0` holding either `false` or the banner element, so `<CheckoutForm />` stays at slot `1` across toggles instead of resetting; switching the outer wrapper tag (`<div>` vs. `<section>`) changes the parent type and unmounts `<CheckoutForm />`:

```tsx
// excerpt — conditional slot 0 keeps CheckoutForm at slot 1 across toggles
function Page({ showBanner }: { showBanner: boolean }) {
  return (
    <main>
      {showBanner && <Banner />}
      <CheckoutForm />
    </main>
  );
}
```

## 3. `key`s Are Scoped, Not Storage

A `key` is scoped to siblings under one parent; matching `key` values never transfer state across different parent branches. If a filtered row leaves the list and later returns with the same `key`, its unmounted local state is gone — store drafts that must survive filtering or navigation in a keyed owner above the list.

Likewise, React's linear heuristic does not bound total interaction cost: component calculations, list sorting, repeated concurrent renders, and browser layout or paint often dominate render time. Identity keeps state accurate; profiling and memoization manage cost.

### When React Bails Out of Re-rendering

Matching a fiber lets React reuse state, and React can skip re-rendering that fiber's subtree altogether when three conditions hold: the element `type` matches, there are no pending state updates or changed consumed Context values on the fiber, and either the new element object keeps the same reference (`oldProps === newProps`, as with `{children}` passed from above) or `React.memo` shallow prop equality passes. Calling `setState` with an identical value under `Object.is` similarly triggers a bailout before descending into children.

## Summary

Reconciliation matches elements by type, parent position, and sibling `key`. Keep component and `React.memo` definitions at module scope, use stable record IDs as list `key`s so state follows items across reorders, change `key` intentionally to reset local state, and lift state above rows when it must survive unmounts.

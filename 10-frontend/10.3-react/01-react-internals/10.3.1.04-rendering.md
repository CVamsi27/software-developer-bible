# Rendering

A render log can show a component running while the visible page barely changes. To understand the cost, follow the update through calculation, commit and browser paint; those are different pieces of work.

```jsx
function Row({ patient }) {
  console.log('render', patient.id); // runs on every parent render…
  return <tr><td>{patient.name}</td></tr>;
}
// …even when the committed <tr> is byte-identical to before.
```

## Definition

Rendering is React calling components to calculate the next UI from their current props, state and context. React reconciles that output with the retained tree. Commit applies accepted changes to the host environment, such as the browser DOM. A render can finish without changing a DOM node.

> **Textbook Definition:** The render phase computes a prospective interface and reconciles it with retained identity. The commit phase publishes the accepted result to the host environment. Render work may be repeated or discarded, so component rendering must remain pure.

## First Principles

A state update requests another UI calculation; it does not directly mutate the DOM. React calls the relevant component, compares its output with the retained tree and commits the accepted changes. The browser then performs its own style, layout, paint and compositing work. If a parent renders, ordinary descendants are usually evaluated too — and any of that work may be repeated or discarded, so render must stay pure.

## 1. One Update, Three Costs

1. **Render:** React evaluates components and prepares the next tree.
2. **Commit:** React applies the accepted host changes and runs commit-phase work. DOM mutations are synchronous.
3. **Browser work:** The browser calculates styles and layout, then paints and composites as needed.

React’s render phase can yield between work units, but it cannot interrupt a component function halfway through. Passive Effects usually run after commit, but their timing relative to paint can vary; useLayoutEffect only when work must run after DOM mutation and before paint.

## 2. Purity: Render May Repeat or Discard Work

Render must be a pure calculation: given the same inputs, it should return the same description without changing external state. React may repeat or abandon render work, especially with concurrent features — so side effects in render can fire for work that is never committed.

Memo can let React skip a parent-driven render when props compare equal, but the child’s own state or consumed context can still require an update. In development, Strict Mode may repeat render-related work to expose impure components. A render count is not a count of visible DOM updates. Use the React Profiler and browser performance tools to locate whether component calculation, commit, layout or paint dominates an interaction.

## 3. Flush Only for an Immediate DOM Dependency

If a third-party integration must read the updated DOM in the same callback, React DOM’s flushSync can force pending work to commit before the next line. It can flush more work than the wrapped update and can reveal a Suspense fallback, so treat it as an integration escape hatch rather than a batching or performance tool.

## Summary

Rendering calculates a candidate UI; commit applies its accepted host changes; the browser performs layout and paint. A component can run without changing the DOM, and render work may be repeated or discarded. Keep rendering pure and measure each stage before optimizing.

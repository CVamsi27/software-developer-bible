# Lifecycle

Every user interface element experiences a temporal lifecycle: it is born, updates over time, and eventually leaves the screen. It mounts into the document, reacts to user gestures and state changes, and unmounts when navigation shifts or dialogs close.

Historically, React structured this lifecycle through class methods: `componentDidMount`, `componentDidUpdate`, and `componentWillUnmount`. Developers conceptualized their code chronologically: *“Do this on appearance, do this on update, and tear down on destruction.”*

However, that paradigm suffered from a fundamental flaw: cohesive business logic was scattered across disconnected methods (starting a timer in `componentDidMount` and clearing it in `componentWillUnmount`), while unrelated concerns (data fetching, document title updates, and event listeners) were forced into the same monolithic lifecycle block.

Modern React shifts the paradigm from chronological milestones to **declarative synchronization**.

Instead of asking *“Which lifecycle method is firing?”*, modern components ask: *“Which external system am I synchronizing with, and which reactive inputs govern that synchronization?”*

Mastering component lifecycles means understanding how mounting, updates, and unmounting map to Fiber reconciliation, how `useLayoutEffect` and `useEffect` coordinate with browser paint deadlines, and why React's development Strict Mode intentionally mounts, unmounts, and re-mounts effects to expose dangling resources.

## Definition

A component's **lifecycle** covers mounting, updates and unmounting. Mounting adds the component to the UI; updates prepare and apply its next state; unmounting removes it. Class components have methods for particular lifecycle phases. Function components use `useEffect` and `useLayoutEffect` to manage synchronization with external systems after a commit and to clean it up. Effects are not one-to-one replacements for every class lifecycle method.

> **Textbook Definition:** A component lifecycle comprises mounting, updating and unmounting of a retained component identity. Effect setup and cleanup synchronize external resources with committed state rather than making each render a distinct lifecycle event.

Understanding lifecycle boundaries helps you attach subscriptions, DOM measurements and resource cleanup to committed UI. Prefer a framework or data layer for server data when it provides caching and request coordination; an Effect is one option for client-only synchronization, not a required home for every fetch.

## First Principles

1. **A component identity can be created, updated, and removed independently of individual render calls.** Render may be retried or abandoned, so external resources must attach to committed lifetimes rather than every function invocation.
2. **An external resource has a setup and a corresponding teardown.** A changed effect dependency ends the old synchronization before starting the new one, while unmount ends the remaining synchronization. Cleanup must target the exact subscription, timer or request acquired by that setup.
3. **Different work needs different DOM timing.** Class snapshots read before an update, layout effects work after DOM mutation before paint, and passive effects generally run later. Class lifecycle methods and Hooks overlap in purpose but do not provide interchangeable timing or a one-to-one migration.

## Why It Matters

Use `useLayoutEffect` for measurements that must affect the UI before paint. Passive effects run after commit and usually after paint, with interaction-related exceptions. Development Strict Mode rehearses setup → cleanup → setup to reveal missing teardown; this is not a new React 19 cleanup-on-remount API.

## The Problem It Solves

### The Problem

Components need to perform actions at specific points in their existence:

1. **On mount**: Fetch data, set up subscriptions, initialize DOM

2. **On update**: Respond to prop/state changes, re-fetch data

3. **On unmount**: Clean up subscriptions, cancel API calls, release resources

Without lifecycle hooks, developers would need manual tracking systems, leading to memory leaks and bugs.

### Function Component Lifecycle with useEffect

The diagrams show a common paint order, not a guarantee for passive effects. Updates run cleanup and setup only for effects whose dependencies changed; layout cleanup belongs to commit before the replacement setup. Effects do not execute for an abandoned render or on the server.

```text
Function Component Lifecycle:
═══════════════════════════════════════════════════════════════

MOUNTING:
┌─────────────────────────────────────────────────────────────┐
│ Component function called                                   │
│ render() → Virtual DOM created                              │
│ DOM updated (commit phase)                                  │
│ useLayoutEffect(() => { ... }, []) runs                     │
│ Browser paints                                              │
│ useEffect(() => { ... }, []) runs                           │
└─────────────────────────────────────────────────────────────┘

UPDATING:
┌─────────────────────────────────────────────────────────────┐
│ Component function called (new props/state)                 │
│ render() → New Virtual DOM                                  │
│ Commit: layout cleanup and DOM updates                      │
│ New useLayoutEffect setup runs                              │
│ Browser paints                                              │
│ useEffect cleanup → useEffect run                           │
└─────────────────────────────────────────────────────────────┘

UNMOUNTING:
┌─────────────────────────────────────────────────────────────┐
│ Component removed from tree                                 │
│ useLayoutEffect cleanup runs                                │
│ useEffect cleanup runs (passive phase)                      │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│ useEffect(() => {                                           │

│ };                                                          │
│ }, [deps]);                                                 │
│                                                             │

│ 1. Before the effect re-runs (deps changed)                 │

```

### Lifecycle Method Mapping

This table groups similar responsibilities, not exact timing equivalents. A dependency-based effect runs on mount too, whereas `componentDidUpdate` does not. `getSnapshotBeforeUpdate` reads the old DOM before mutations; `useLayoutEffect` reads the updated DOM, so a layout effect is not a drop-in replacement for preserving an old scroll snapshot.

```text
Class → Function Component Mapping:
═══════════════════════════════════════════════════════════════

Class Component Function Component
───────────────────────────────────────────────────────────────
constructor() → useState(initialValue)
componentDidMount() → useEffect(() => {}, [])
componentDidUpdate() → useEffect(() => {}, [deps])
componentWillUnmount() → useEffect(() => { return cleanup }, [])
shouldComponentUpdate() → React.memo() + useMemo/useCallback
getDerivedStateFromProps() → derive state during render
getSnapshotBeforeUpdate() → No direct Hook equivalent
componentDidCatch() → Error Boundary component

```

## Code Examples

### Class Component Lifecycle

```typescript
import React, { Component } from 'react';

interface Props {
  userId: string;
}

interface State {
  user: User | null;
  loading: boolean;
}

class UserProfile extends Component<Props, State> {
  private controller: AbortController | null = null;
  private requestVersion = 0;
  constructor(props: Props) {
    super(props);
    this.state = { user: null, loading: true };
    console.log('1. constructor');
  }

  static getDerivedStateFromProps(props: Props, state: State): Partial<State> | null {
    console.log('2. getDerivedStateFromProps');
    // Sync state from props if needed
    return null;
  }

  componentDidMount() {
    console.log('4. componentDidMount');
    // Set up subscriptions, fetch data
    this.fetchUser();
  }

  async fetchUser() {
    this.controller?.abort();
    const controller = new AbortController();
    this.controller = controller;
    const version = ++this.requestVersion;
    this.setState({ loading: true });
    try {
      const user = await fetchUser(this.props.userId, { signal: controller.signal });
      if (version === this.requestVersion) this.setState({ user, loading: false });
    } catch (error) {
      if (version === this.requestVersion && !controller.signal.aborted) {
        console.error(error);
        this.setState({ user: null, loading: false });
      }
    }
  }

  componentDidUpdate(prevProps: Props) {
    console.log('5. componentDidUpdate');
    // Respond to prop changes
    if (prevProps.userId !== this.props.userId) {
      this.fetchUser();
    }
  }

  componentWillUnmount() {
    console.log('6. componentWillUnmount');
    ++this.requestVersion; // Suppress result publication after unmount.
    this.controller?.abort();
  }

  render() {
    console.log('3. render');
    const { user, loading } = this.state;

    if (loading) return <div>Loading...</div>;
    return <div>{user?.name}</div>;
  }
}

```

### Function Component with useEffect

```typescript
import React, { useState, useEffect } from 'react';

const UserProfile = ({ userId }: { userId: string }) => {
  const [user, setUser] = useState<User | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    setLoading(true);
    setError(null);
    fetchUser(userId, { signal: controller.signal })
      .then(data => { if (active) setUser(data); })
      .catch(err => { if (active) setError(err instanceof Error ? err.message : String(err)); })
      .finally(() => { if (active) setLoading(false); });
    return () => {
      active = false;
      controller.abort();
    };
  }, [userId]); // Setup on mount and resynchronize when userId changes.

  if (loading) return <div>Loading...</div>;
  if (error) return <div>{error}</div>;
  return <div>{user?.name}</div>;
};
```

Trace `userId` from Ada to Ben: React first commits the new prop; the previous effect cleanup then sets its own `active` flag to false and aborts its controller. The Ben setup starts another request. If Ada resolves afterward, its callback cannot publish because it closes over the old false flag. Aborting reduces unnecessary work; the publication guard protects the UI even when a transport cannot cancel in time.

This minimal example keeps the previous `user` until the new effect sets loading. That can briefly display old data under new props. For sensitive records, key the profile by user ID to reset local state, or store the requested ID with each result and render it only when it matches the current ID. The class example needs the same display-identity rule.

One effect owns one fetch lifecycle. Separate “mount”, “update” and “unmount” fetching effects would issue multiple requests on the initial mount because all effects are set up then.

### Cleanup Function Patterns

```typescript
// Pattern 1: Subscription with cleanup
const useSubscription = (channel: string) => {
  useEffect(() => {
    const subscription = subscribe(channel);

    return () => {
      subscription.unsubscribe(); // Cleanup
    };
  }, [channel]);
};

// Pattern 2: Event listener with cleanup
const useEventListener = (event: string, handler: EventListener) => {
  useEffect(() => {
    window.addEventListener(event, handler);

    return () => {
      window.removeEventListener(event, handler); // Cleanup
    };
  }, [event, handler]);
};

// Pattern 3: Timer with cleanup
const useInterval = (callback: () => void, delay: number) => {
  useEffect(() => {
    const id = setInterval(callback, delay);

    return () => {
      clearInterval(id); // Cleanup
    };
  }, [callback, delay]);
};

// This minimal version restarts when callback identity changes. An inline
// callback can therefore reset the timer after each render. A production Hook
// may keep the latest callback in a ref or use an Effect Event where supported,
// while tying the interval lifecycle to delay.

// Pattern 4: Abort controller for fetch
const useFetch = (url: string) => {
  const [data, setData] = useState<unknown>(null);

  useEffect(() => {
    const controller = new AbortController();

    fetch(url, { signal: controller.signal })
      .then(res => res.json())
      .then(result => { if (!controller.signal.aborted) setData(result); })
      .catch(error => { if (!controller.signal.aborted) console.error(error); });

    return () => {
      controller.abort(); // Cleanup
    };
  }, [url]);

  return data;
};

```

### Conditional Lifecycle

```typescript
// Class: conditional componentDidUpdate
class MyComponent extends Component<Props, State> {
  componentDidUpdate(prevProps: Props) {
    // Only fetch when specific prop changes
    if (prevProps.userId !== this.props.userId) {
      this.fetchData(this.props.userId);
    }
  }
}

// Function: equivalent with useEffect
const MyComponent = ({ userId }: Props) => {
  useEffect(() => {
    fetchData(userId);
  }, [userId]); // Setup on mount and again when userId changes
};

// Multiple effects for different concerns
const MyComponent = ({ userId, theme }: Props) => {
  // Effect 1: Fetch user data
  useEffect(() => {
    fetchUser(userId);
  }, [userId]);

  // Effect 2: Apply theme
  useEffect(() => {
    const previousClassName = document.body.className;
    document.body.className = theme;
    return () => {
      document.body.className = previousClassName; // Restore the state this setup replaced.
    };
  }, [theme]);

  // Effect 3: Set up analytics
  useEffect(() => {
    const tracker = trackPageView(userId);
    return () => tracker.stop();
  }, [userId]);
};

```

## Real-World Use Cases

### 1. Data Fetching with Cleanup

> [Function Component with useEffect](#function-component-with-useeffect) handles prop changes, cancellation, errors and loading in one synchronization cycle. The generic reusable hook is in [useEffect — Fetch with Abort Controller](../02-core-hooks/10.3.2.02-useeffect.md#fetch-with-abort-controller).

### 2. WebSocket Connection Management

```typescript
const useWebSocket = (url: string) => {
  const [messages, setMessages] = useState<Message[]>([]);

  useEffect(() => {
    const ws = new WebSocket(url);

    ws.onmessage = (event) => {
      const message = JSON.parse(event.data);
      setMessages(prev => [...prev, message]);
    };

    ws.onerror = (error) => {
      console.error('WebSocket error:', error);
    };

    return () => {
      ws.close(); // Cleanup: close WebSocket on unmount
    };
  }, [url]);

  return messages;
};

```

> See [useEffect — Document Title Sync](../02-core-hooks/10.3.2.02-useeffect.md#document-title-sync) for setup and restoration. A title is synchronized to a changing value rather than to a class lifecycle label.

### 4. Intersection Observer for Lazy Loading

```typescript
const useIntersectionObserver = (
  ref: React.RefObject<HTMLElement>,
  options?: IntersectionObserverInit
) => {
  const [isVisible, setIsVisible] = useState(false);

  useEffect(() => {
    const element = ref.current;
    if (!element) return;

    const observer = new IntersectionObserver(([entry]) => {
      setIsVisible(entry.isIntersecting);
    }, options);

    observer.observe(element);

    return () => {
      observer.disconnect(); // Cleanup
    };
  }, [ref, options]);

  return isVisible;
};

```

### 5. Window Resize Handler

```typescript
// Browser-only: server rendering cannot read window during initialization.
const useWindowSize = () => {
  const [size, setSize] = useState({
    width: window.innerWidth,
    height: window.innerHeight,
  });

  useEffect(() => {
    const handleResize = () => {
      setSize({
        width: window.innerWidth,
        height: window.innerHeight,
      });
    };

    window.addEventListener('resize', handleResize);

    return () => {
      window.removeEventListener('resize', handleResize); // Cleanup
    };
  }, []);

  return size;
};

```

## Common Mistakes

### 1. Missing Cleanup Functions

```typescript
// BAD: No cleanup - memory leak
const BadComponent = () => {
  useEffect(() => {
    const interval = setInterval(() => {
      console.log('tick');
    }, 1000);

    // No cleanup! Interval continues after unmount
  }, []);
};

// GOOD: Proper cleanup
const GoodComponent = () => {
  useEffect(() => {
    const interval = setInterval(() => {
      console.log('tick');
    }, 1000);

    return () => clearInterval(interval); // Cleanup
  }, []);
};

```

### 2. Using useEffect for Derived State

Deriving state in an effect forces a second render. The BAD/GOOD pair — and the render-phase fix with `useMemo` — is owned by [useEffect — Common Mistakes](../02-core-hooks/10.3.2.02-useeffect.md), where the hook's contract is defined.

### 3. Incorrect Dependency Arrays

```typescript
// BAD: Missing dependency
const BadComponent = ({ userId }: { userId: string }) => {
  useEffect(() => {
    fetchUser(userId); // userId not in deps!
  }, []); // Will always fetch with initial userId
};

// BAD: Unnecessary dependencies
const BadComponent = ({ data }: { data: Data }) => {
  const processed = processData(data);

  useEffect(() => {
    saveToDatabase(processed);
  }, [data, processed]); // processed changes on every render

  return <div>{processed}</div>;
};

// GOOD: Correct dependencies
const GoodComponent = ({ userId }: { userId: string }) => {
  useEffect(() => {
    fetchUser(userId);
  }, [userId]); // Setup on mount and again when userId changes
};

```

### 4. Calling setState Without Condition

```typescript
// BAD: Infinite loop
const InfiniteLoop = () => {
  const [count, setCount] = useState(0);

  useEffect(() => {
    setCount(count + 1); // Causes re-render, triggers effect again
  }); // No dependency array - runs every render

  return <div>{count}</div>;
};

// GOOD: Conditional update
const GoodComponent = () => {
  const [count, setCount] = useState(0);

  useEffect(() => {
    if (count < 10) {
      setCount(count + 1);
    }
  }, [count]);

  return <div>{count}</div>;
};

```

## Best Practices

1. **Release acquired resources**: Subscriptions, timers, listeners and requests need matching teardown. An effect that acquires no lasting resource may need no cleanup.

2. **Use dependency arrays correctly**: Include all reactive values the effect reads; module constants are not render-reactive dependencies.

3. **Compute derived state during render**: Don't use `useEffect` for data transformation.

4. **Split effects by concern**: One effect per side effect.

5. **Use `useLayoutEffect` for DOM measurements**: When you need to measure before paint.

6. **Use `useEffect` for passive external synchronization**: Subscriptions, client-only data synchronization and logging. Do not use it for derived state or work that belongs in an event handler.

7. **Avoid async functions in useEffect**: Use inner async function or `.then()`.

## Performance Considerations

### Lifecycle Timing

| Method | Timing | Use Case |
| -------------------- | -------------------------------------- | ---------------------------- |
| constructor | Before first render | Initialize state |
| render | During render phase | Return JSX |
| componentDidMount | After initial DOM commit, before paint | Setup side effects |
| componentDidUpdate | After update commit; not on mount | Respond to changes |
| componentWillUnmount | Before unmount | Cleanup |
| useEffect | After commit, usually after paint | Synchronize external systems |
| useLayoutEffect | After DOM mutation (sync) | DOM measurements |

### Effect Frequency

| Dependency Array | When It Runs | Use Case |
| ---------------- | ------------------------------------------- | ------------------- |
| `[]` | Setup on mount; extra dev Strict Mode cycle | Initial setup |
| `[dep1, dep2]` | Mount, then changed dependencies | Conditional effects |
| No array | Every committed render | Rarely used |

## Summary

The component lifecycle in React manages the series of events from mounting to unmounting. Class components use lifecycle methods (`componentDidMount`, `componentDidUpdate`, `componentWillUnmount`). Function components use `useEffect` and `useLayoutEffect`. Understanding lifecycle is crucial for managing side effects, subscriptions, and resource cleanup.

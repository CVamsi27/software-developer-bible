# useState

A click handler can request a new count and still log the old one. That is expected: the handler belongs to the render that created it, while the update belongs to a later render.

```tsx
const [count, setCount] = useState(0);

function addOne() {
  setCount(count + 1);
  console.log(count); // logs the OLD count — this handler's snapshot
}
```

## Definition

The React Hook useState gives a component a value that React remembers between renders and a setter that queues its next value. Each render receives a snapshot; calling the setter does not change variables in the currently running component or handler.

> **Textbook Definition:** useState associates local state with a mounted component identity and returns its current render snapshot together with a stable update function. React queues updates for a later render; object values are replaced rather than merged.

## First Principles

A component function re-runs to calculate new UI, so its locals cannot persist across calls — React retains state per component identity and feeds it back as input to each render. A handler closes over its own render's snapshot: calling the setter queues another render without rewriting that closure, and queued updates process in order before commit.

## 1. Follow One Click into the Next Render

```tsx
import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  function addOne() {
    setCount(count + 1);
    console.log(count); // This handler still sees its render snapshot.
  }

  function addThree() {
    setCount(current => current + 1);
    setCount(current => current + 1);
    setCount(current => current + 1);
  }

  return (
    <>
      <p>Count: {count}</p>
      <button onClick={addOne}>Add one</button>
      <button onClick={addThree}>Add three</button>
    </>
  );
}
```

After Add one, that handler still reads the old count. React later renders with the queued value and commits the new text. Add three uses updater functions, so each receives the pending result of the previous updater.

A direct replacement such as setCount(count + 1) is correct when the next value comes from this event’s snapshot. Use an updater when multiple queued changes must compose or when the calculation depends on pending state. A setter returns nothing; it is not a promise for the next render. React batches updates before committing, and Object.is equality can let it skip an unchanged value.

## 2. Replace Collections Immutably

A Hook setter replaces its value. It does not shallow-merge objects as class setState does. Copy each level that changes and preserve the rest:

```tsx
setProfile(current => ({
  ...current,
  preferences: {
    ...current.preferences,
    theme: 'dark',
  },
}));
```

Do the same for arrays with map, filter and spread. Mutating the existing object and passing the same reference can make React skip an update while also corrupting the previous snapshot.

## 3. Store Only State the Interface Needs

If a value can be calculated from current props and state, derive it during render instead of storing a second copy and synchronizing it with an Effect. Store the source values that users can change; use a reducer when several values participate in a complex transition or must change together. Put shared state at the nearest owner that needs to coordinate its readers.

An initializer function, such as useState(() => loadInitialDraft()), avoids repeating an expensive initial calculation on ordinary updates. Initializers and updater functions must be pure; development Strict Mode may call them twice to expose side effects. The initial value is ignored after the first render for that component identity. A new key deliberately creates a new identity and resets its local state.

Call Hooks at the top level and in the same order on every render. React associates each Hook call with the component identity and call position; conditional Hook calls break that mapping.

## Summary

State is a render snapshot associated with a component identity. A setter queues a replacement or an updater for a later render; it does not mutate the current handler’s values. Use immutable updates, derive redundant values during render, and choose state ownership from the transitions the interface must support.

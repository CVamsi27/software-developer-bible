# useEffect

A profile page switches from Ada to Ben, but Ada’s slower request finishes last. If that response is allowed to update the page, Ben’s screen can show Ada’s data. An Effect must own both the external work it starts and the rule for which result may be published.

```tsx
useEffect(() => {
  const controller = new AbortController();
  let current = true;
  fetch('/api/users/' + userId, { signal: controller.signal })
    .then((res) => res.json())
    .then((profile) => { if (current) setProfile(profile); });
  return () => { current = false; controller.abort(); };
}, [userId]);
```

## Definition

useEffect synchronizes a committed component with an external system, such as a subscription, browser API or network request. Its setup starts synchronization; the optional cleanup stops or invalidates that setup.

> **Textbook Definition:** useEffect declares post-commit synchronization with an external system. React runs cleanup before replacing an Effect whose dependencies changed and when the component is removed. Effect execution follows commit, but its timing relative to browser paint is not fixed.

## First Principles

Rendering calculates UI from props, state and context — and must stay pure because React may repeat or discard render work. An Effect runs only after a commit, when its synchronization corresponds to UI React actually accepted. Think of one Effect as a start/stop process, not a lifecycle callback: setup connects, cleanup releases exactly what that setup acquired.

## 1. Dependencies Define When Setup Becomes Obsolete

The dependency list includes every reactive value read by setup: props, state and values calculated in the component body. React compares entries with Object.is after commits.

| Dependency argument | Synchronization behavior |
| ----------------------- | ------------------------------------------------------------------------- |
| Omitted | Setup runs after every commit |
| Empty array | Setup runs on initial commit; cleanup runs on removal |
| Values such as [roomId] | Setup runs initially and is replaced after a commit where a value changed |

Do not omit a dependency to force a preferred frequency. If an object or function is created during render only for the Effect, move it inside setup or depend on its primitive inputs. A fresh object reference otherwise makes the previous setup obsolete every time.

In development, Strict Mode may run setup, cleanup, then setup again before the first real cycle. Correct cleanup makes this check harmless. A ref that merely suppresses the second setup hides a missing cleanup rather than fixing it.

## Protect asynchronous result ownership

Suppose the user navigates from Ada’s profile to Ben’s. The render for Ben can happen before the Effect starts the new request, so associate each result with its requested identity. Abort supported work to reduce waste, and separately prevent a superseded request from publishing its data or error.

```tsx
import { useEffect, useState } from 'react';

type Profile = { id: string; name: string };
type ProfileResult =
  | { userId: string; status: 'loading' }
  | { userId: string; status: 'ready'; profile: Profile }
  | { userId: string; status: 'error'; message: string };

function ProfilePage({
  userId,
  parseProfile,
}: {
  userId: string;
  parseProfile: (value: unknown) => Profile;
}) {
  const [result, setResult] = useState<ProfileResult | null>(null);

  useEffect(() => {
    const controller = new AbortController();
    let current = true;
    setResult({ userId, status: 'loading' });

    async function load() {
      try {
        const response = await fetch(
          '/api/users/' + encodeURIComponent(userId),
          { signal: controller.signal },
        );
        if (!response.ok) throw new Error('Request failed: ' + response.status);

        const payload: unknown = await response.json();
        const profile = parseProfile(payload); // Runtime validation, not a type assertion.
        if (profile.id !== userId) throw new Error('Response identity mismatch');

        if (current) setResult({ userId, status: 'ready', profile });
      } catch (error) {
        if (current && !controller.signal.aborted) {
          setResult({
            userId,
            status: 'error',
            message: error instanceof Error ? error.message : String(error),
          });
        }
      }
    }

    void load();
    return () => {
      current = false;
      controller.abort();
    };
  }, [userId, parseProfile]);

  const visible = result?.userId === userId ? result : null;
  if (!visible || visible.status === 'loading') return <p>Loading profile…</p>;
  if (visible.status === 'error') return <p role="alert">{visible.message}</p>;
  return <h1>{visible.profile.name}</h1>;
}
```

The identity check prevents the prior profile from appearing under new props before the Effect runs. The cleanup flag blocks late data and errors; aborting stops supported fetch work. If cleanup only aborts, a transport that cannot cancel or a response already completed can still race. Debouncing search delays request starts but does not order their completions, so stale-result protection still matters.

This example also assumes parseProfile has stable identity, such as an imported module function. If it is recreated on every render, it is a dependency change and the request will restart; move it outside the component or otherwise give it an appropriate stable owner. For production server data, a route loader or server-state library may provide caching, deduplication and navigation coordination.

## 2. Choose the Right Place for the Work

- Derive display values during render; do not use an Effect to copy one state value into another.
- Run work caused by a specific user action in its event handler, such as submitting a form.
- Use an Effect when the committed UI must stay synchronized with an external system.
- Use useLayoutEffect only when a DOM measurement or correction must complete before paint. It blocks painting while it runs.
- Effects run only on the client. Keep server-rendered output independent of browser-only values.

Passive Effects run after commit, but React may let the browser paint first or may run an interaction-related Effect before paint. Their JavaScript still runs synchronously when invoked, so expensive work can block the main thread.

## Summary

Use one Effect for one external synchronization process. Its dependencies describe the committed inputs that make setup valid; cleanup releases the old resource before replacement and on removal. For async work, cancellation limits waste while identity guards prevent stale results from changing the UI.

# useMemo & useCallback

A directory rerenders when its search query changes. Filtering and sorting several thousand records may be measurable work; a memoized row may also rerender because it receives a new callback reference. These are separate costs. `useMemo` can reuse a calculation result, while `useCallback` can preserve a function identity for a consumer that compares it.

```tsx
const visibleUsers = useMemo(() => {
  return users.filter((u) => u.name.includes(query)).sort(byName);
}, [users, query]); // recompute only when an input actually changes
```

## Definition

`useMemo` and `useCallback` are React Hooks for memoization. `useMemo` can reuse a value computed during render; `useCallback` can reuse a function reference. Each compares its dependencies with `Object.is` during ordinary renders.

> **Textbook Definition:** `useMemo` caches a render-time calculation result and `useCallback` caches a function definition across renders while the declared dependencies compare equal. Both provide performance optimizations, not semantic guarantees that application correctness may depend on.

## First Principles

A render can repeat work and mint new identities: re-running an expensive pure calculation costs time, and a fresh object or function defeats identity-sensitive consumers. A cache stays valid only for the inputs it tracks — include every reactive value, or stale data (or hidden mutations) slips through. And the cache itself costs comparison plus memory, and React may discard it — so durable state belongs in state, a ref, or its owner, never in a memo hook.

## How It Works

### 1. Cache a Calculation with useMemo

```tsx
import { useMemo, useState } from 'react';

type User = { id: string; name: string };

function Directory({ users }: { users: User[] }) {
  const [query, setQuery] = useState('');
  const normalizedQuery = query.trim().toLowerCase();

  const visibleUsers = useMemo(() => {
    return users
      .filter((user) => user.name.toLowerCase().includes(normalizedQuery))
      .sort((left, right) => left.name.localeCompare(right.name));
  }, [users, normalizedQuery]);

  return (
    <>
      <label>
        Search users
        <input value={query} onChange={(event) => setQuery(event.target.value)} />
      </label>
      <ul>{visibleUsers.map((user) => <li key={user.id}>{user.name}</li>)}</ul>
    </>
  );
}
```

The result can be reused while both inputs keep their identities/values. `useMemo` does not make the initial calculation faster, and it is useful only if avoiding the work or preserving this result's identity matters. Keep the calculation pure; use immutable updates so a changed list receives a changed identity. If the list is small, direct calculation is often clearer.

### 2. Preserve a Callback Identity with useCallback

A memoized child can skip a parent-driven render when its props remain equal. The callback's identity is one of those props:

```tsx
import { memo, useCallback, useState } from 'react';

type User = { id: string; name: string };

const UserRows = memo(function UserRows({
  users,
  onOpen,
}: {
  users: User[];
  onOpen: (id: string) => void;
}) {
  return <ul>{users.map((user) => (
    <li key={user.id}>
      <button onClick={() => onOpen(user.id)}>{user.name}</button>
    </li>
  ))}</ul>;
});

function UserPanel({ users }: { users: User[] }) {
  const [selectedId, setSelectedId] = useState<string | null>(null);
  const [showDetails, setShowDetails] = useState(false);
  const openUser = useCallback((id: string) => setSelectedId(id), []);

  return (
    <>
      <button onClick={() => setShowDetails((visible) => !visible)}>
        Toggle details
      </button>
      {showDetails && <p>Selected: {selectedId ?? 'none'}</p>}
      <UserRows users={users} onOpen={openUser} />
    </>
  );
}
```

When `showDetails` changes, `UserRows` can skip the parent-driven render if `users` is also unchanged. `memo` only compares props for that parent-driven render: the child still renders when its own state or a context it reads changes. An ordinary child still renders with its parent. `useCallback` returns a cached function reference when dependencies match; JavaScript still evaluates the function expression passed to the Hook, and the Hook does not cache the callback's return value.

### 3. Keep Dependencies Honest and Work Measurable

Dependencies must include every reactive value read by a calculation or callback. If an object is created during render and passed as a dependency, its fresh identity invalidates the cache each time. When an object exists only to configure an Effect, creating it inside that Effect is usually simpler than memoizing the object. Do not omit a dependency to force a cache hit; that trades visible work for stale behavior.

`useCallback` is useful when a memoized child, another Hook, or an external subscription observes function identity. It usually adds no value to a handler used only by a native button. `useMemo` can help even without a memoized child when a pure calculation is expensive. Neither Hook prevents the component itself from rendering, and memoization cannot fix excessive state updates, an N+1 request pattern, or slow work outside React.

Before adding or removing manual memoization, profile the interaction that feels slow with React Developer Tools. Compare the work that was skipped with dependency checking and retained memory; production measurements are more informative than development render counts, which Strict Mode may intentionally repeat.

### 4. React Compiler Changes the Default Choice

React Compiler 1.0 is a stable build-time compiler that can automatically memoize components and Hooks when enabled and when code follows the Rules of React. For new code, prefer the compiler's analysis over adding `useMemo`, `useCallback`, and `memo` everywhere. Keep a manual Hook when profiling or an explicit identity boundary justifies it. In an existing compiled codebase, do not remove manual memoization mechanically: first verify the compiled result and test behavior that depends on Effect timing or identity.

The compiler does not make memoization a correctness mechanism. Effects must still synchronize correctly if a cache is dropped or changes, and invalid Hook patterns must be fixed rather than hidden behind a compiler setting.

## Summary

`useMemo` can reuse a calculated value; `useCallback` can reuse a function reference. Both are disposable performance caches whose dependencies must describe the real inputs. Profile the consumer, prefer React Compiler when the project enables it, and use manual memoization only where avoiding measured work or stabilizing an observed identity is valuable.

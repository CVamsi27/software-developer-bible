# useRef

Clicking Focus should move the browser cursor into an input without changing the rendered UI. Storing the input node in state would add an unnecessary render; a local variable would be lost when the component runs again.

```tsx
function SearchField() {
  const input = useRef<HTMLInputElement>(null);

  return (
    <>
      <input ref={input} aria-label="Search" />
      <button type="button" onClick={() => input.current?.focus()}>
        Focus
      </button>
    </>
  );
}
```

## Definition

useRef returns a stable object with a mutable current property that survives renders for one component identity. React also assigns a DOM node to an object ref after commit. Changing current does not schedule a render.

> **Textbook Definition:** A ref is a mutable cell retained for the lifetime of a component identity. It stores an imperative handle or other non-rendered value; React does not subscribe to mutations of the cell.

## First Principles

Use state when a change must produce new UI. Use a ref when an event handler or Effect needs a handle that persists but does not itself affect the UI. React attaches the DOM node during commit and clears current when that node is removed.

## 1. Refs for DOM Nodes and Focus

```tsx
import { useRef } from 'react';

function SearchField() {
  const input = useRef<HTMLInputElement>(null);

  return (
    <>
      <input ref={input} aria-label="Search" />
      <button type="button" onClick={() => input.current?.focus()}>
        Focus
      </button>
    </>
  );
}
```

The input reference is available to the click handler, while the button label remains ordinary rendered output.

## 2. Retain a Nonvisual Handle

A timer ID must survive renders so the same timer can be stopped later. It should not itself update the screen, so it belongs in a ref; any visible elapsed count belongs in state.

```tsx
import { useEffect, useRef } from 'react';

function TimerControl() {
  const timer = useRef<ReturnType<typeof setInterval> | null>(null);

  function start() {
    if (timer.current !== null) return;
    timer.current = setInterval(() => console.log('tick'), 1000);
  }

  function stop() {
    if (timer.current === null) return;
    clearInterval(timer.current);
    timer.current = null;
  }

  useEffect(() => () => {
    if (timer.current !== null) clearInterval(timer.current);
  }, []);

  return (
    <>
      <button onClick={start}>Start</button>
      <button onClick={stop}>Stop</button>
    </>
  );
}
```

The guard prevents a second Start from overwriting the only stored ID while the first interval remains active. Cleanup releases the resource when the component is removed.

A ref is mutable shared storage, not part of a render snapshot. Do not read or write current during ordinary render: a restarted render could observe a mutation from work React does not commit. Read or write refs in event handlers, Effects and callback refs. Predictable one-time initialization guarded by current === null is the narrow documented render-time exception.

The initial argument is ignored after mount, but JavaScript still evaluates it on every render. For an expensive object, use a null ref and initialize it once behind the predictable guard rather than calling useRef(createExpensiveThing()).

## 3. Ref Callbacks and Component Boundaries

An object ref is convenient when one stable node owns the handle. When the actual node can change, a callback ref makes attach and detach explicit. React 19 callback refs can return cleanup for the attached node:

```tsx
import { useCallback } from 'react';

function ObservedBox() {
  const attach = useCallback((node: HTMLDivElement | null) => {
    if (!node) return;
    const observer = new ResizeObserver(entries => {
      console.log(entries[0]?.contentRect.width);
    });
    observer.observe(node);
    return () => observer.disconnect();
  }, []);

  return <div ref={attach}>Resize this element</div>;
}
```

Keep the callback identity stable when possible; a different callback causes React to detach the previous ref and attach the next one. React 18 does not use returned callback-ref cleanup; its callback receives null on detach, so release resources through that path when supporting React 18.

In React 19, a function component can receive ref as a prop. React 18 requires forwardRef for that boundary; it remains compatible but is no longer necessary for new React 19 components. Use useImperativeHandle to expose a small parent-facing API instead of the entire DOM node:

```tsx
import { useImperativeHandle, useRef, type Ref } from 'react';

type SearchFieldHandle = { focus: () => void };

function SearchFieldWithHandle({
  ref,
}: {
  ref?: Ref<SearchFieldHandle>;
}) {
  const input = useRef<HTMLInputElement>(null);
  useImperativeHandle(ref, () => ({
    focus: () => input.current?.focus(),
  }), []);

  return <input ref={input} aria-label="Search" />;
}
```

An imperative handle does not make a controlled input uncontrolled. The component that owns the displayed value must still update that value through state. For media controls, use a ref to request play or pause, then let media events update the displayed playback state: playback can fail, and a user can also operate native controls.

## Summary

A ref is a retained mutable handle whose changes do not render UI. Use object refs for stable DOM nodes and non-visual bookkeeping, callback refs for node-specific attachment, and state for displayed values. Keep mutable access out of ordinary render and expose only the imperative methods a parent needs.

# Suspense

A dashboard can show the account summary immediately while its large chart is still loading. Put both behind one boundary and the summary waits too; put a spinner around every small widget and the screen becomes noisy. A Suspense boundary defines which region should appear together and what users see while that region is not ready.

## Definition

**Suspense** is a React boundary that displays fallback UI when a supported child cannot finish rendering because required code or data is pending. When that resource becomes available, React retries the suspended work and reveals the content.

> **Textbook Definition:** A Suspense boundary is a component-tree boundary that coordinates the reveal of descendants whose render depends on supported asynchronous resources. The nearest boundary supplies fallback UI while the suspended region is pending; nested boundaries can reveal independent regions separately.

## First Principles

Rendering calculates the next UI. Some React integrations can signal during render that a required resource is still pending. React then uses the nearest Suspense boundary to choose what remains visible. This signal is specific to supported sources; an ordinary fetch in an Effect does not activate Suspense.

A boundary is therefore a user-facing loading decision. Descendants under one boundary reveal together; a nested boundary can let a slower chart wait without hiding the summary. During an initial suspended mount, React retries the subtree from its beginning rather than preserving state from an uncommitted render. Keep resource creation in a loader, server component or cache that survives that retry.

## Let one boundary match one loading decision

For code splitting, declare each lazy component outside the rendering component so it keeps a stable component identity. Put the boundary around the region whose loading state belongs together:

```tsx
import { lazy, Suspense } from 'react';

const RevenueChart = lazy(() => import('./RevenueChart.tsx'));

export function AnalyticsPanel() {
  return (
    <section aria-labelledby="analytics-title">
      <h2 id="analytics-title">Analytics</h2>
      <Suspense fallback={<p role="status">Loading chart…</p>}>
        <RevenueChart />
      </Suspense>
    </section>
  );
}
```

`lazy` asks the bundler to load the module when React first renders that component. Split routes, editors or charts when the smaller initial bundle is worth the extra chunk and first-use wait. If the lazy component is declared inside `AnalyticsPanel`, each parent render creates a new component type and can reset the child's state. The module system generally caches imported modules; declaring `lazy` at module scope preserves React's component identity.

Place boundaries at the loading sequence the interface should communicate, not mechanically around every component. A single boundary coordinates its descendants; nested boundaries permit progressive reveal. If a user changes a tab or route and already-visible content suspends again, React may replace it with the fallback. Marking the navigation update as a Transition can keep that revealed content visible while the next tree is prepared.

```tsx
import { Suspense, useState, useTransition } from 'react';

export function ReportTabs() {
  const [tab, setTab] = useState<'summary' | 'details'>('summary');
  const [isPending, startTransition] = useTransition();

  function select(next: 'summary' | 'details') {
    startTransition(() => setTab(next));
  }

  return (
    <>
      <button onClick={() => select('summary')}>Summary</button>
      <button onClick={() => select('details')}>Details</button>
      {isPending && <span role="status">Updating…</span>}
      <Suspense fallback={<p role="status">Loading report…</p>}>
        {tab === 'summary' ? <Summary /> : <Details />}
      </Suspense>
    </>
  );
}
```

A Transition changes the priority of the state update; it does not make the network or render work faster. React can keep already revealed content during that update, while a newly mounted nested boundary can still show its own fallback. Keep controlled input state urgent; use a separate deferred value when an expensive result should lag behind typing.

## Read data through a Suspense-enabled source

React 19's `use(promise)` reads a Promise during render. The Promise must come from an owner that reuses the same instance across retries, such as a route loader, Server Component or Suspense-enabled cache:

```tsx
import { Suspense, use } from 'react';

type Profile = { name: string; role: string };

function ProfileCard({ profile }: { profile: Promise<Profile> }) {
  const value = use(profile);
  return <p>{value.name} — {value.role}</p>;
}

export function ProfileRegion({ profile }: { profile: Promise<Profile> }) {
  return (
    <Suspense fallback={<p role="status">Loading profile…</p>}>
      <ProfileCard profile={profile} />
    </Suspense>
  );
}
```

Do not create a new Promise with `fetch()` in the rendering component and pass it straight to `use`: a retry can create another pending Promise and suspend again. A cache or framework must own request reuse, invalidation and error policy. `use` may be called conditionally, unlike ordinary Hooks, but a pending read is not handled with `try/catch`; its nearest Suspense boundary owns the pending state. An Effect-based fetch remains a valid design when the component itself owns loading and error state.

## Keep pending and failed states separate

Suspense handles pending supported work. It does not catch a rejected lazy import, a rejected Promise read with `use`, or an ordinary render exception. Those failures reach an Error Boundary. Pair the loading boundary with a recoverable error boundary where a failed chunk or data resource should not take down the surrounding screen; resetting the boundary alone may not reset the resource that failed.

On the server, React's streaming renderers can send a shell containing Suspense fallbacks, then stream completed boundary content as it becomes ready. Frameworks use these boundaries to coordinate server output and selective hydration. This behavior depends on the renderer and framework configuration; adding `<Suspense>` to a client-only app does not by itself enable streaming SSR.

## Summary

Suspense coordinates pending work from supported React sources. The nearest boundary controls the loading region, nested boundaries control progressive reveal, and Transitions can preserve already revealed content during a non-urgent update. Keep Promise ownership in a stable loader or cache, and use an Error Boundary for rejected work.

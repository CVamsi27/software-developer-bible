# Custom Hooks

## TL;DR

Custom hooks are reusable functions that call other hooks (`useState`, `useEffect`, etc.). They extract component logic into composable units, enabling reuse without HOCs or render props. Naming convention: `use*` (e.g., `useDebounce`, `useLocalStorage`, `useFetch`).

## First Principles

1. **Render calls are temporary; state must survive between calls.** React owns each component's Hook records. A custom hook calls built-in Hooks while that component renders, so it can package state and synchronization without adding a wrapper component.
2. **Reusing logic does not imply sharing storage.** Two callers execute the same function but receive separate Hook records. Shared sessions or caches need a common provider or external store; extracting a function alone does not connect those callers.
3. **Effects have lifetimes; ordinary calls do not provide automatic cleanup.** JavaScript functions can maintain state in closures or modules. To connect reusable logic to React's commit and cleanup lifecycle, call Hooks in a custom hook and keep their order stable. `renderHook` provides a focused test harness, while component tests remain useful for checking the user-visible integration; neither requires a full application tree.

## Why It Matters

Extract a custom hook when repeated stateful behavior has a useful, focused interface. They know hooks compose (`useDebounce(useLocalStorage(...))`), and they encapsulate complex logic (`useAuth`, `usePagination`) so components stay declarative.

**Concretely:**

1. **Reusability** — Extract and share stateful logic between components without duplication
2. **Separation of concerns** — Keep components focused on UI, move logic to hooks
3. **Composability** — Combine multiple hooks to build complex behaviors
4. **Testability** — Isolate and test logic independently of component rendering
5. **Cleaner components** — Reduce boilerplate and improve readability

## Definition

**Custom Hooks** are JavaScript functions that reuse stateful logic across React components. They start with `use` by convention, call other React Hooks inside them, and return a value, an array, or an object. Custom Hooks let you extract component logic into reusable functions — enabling composition, separation of concerns, and sharing of stateful behavior without higher-order components or render props.

Names beginning with `use` followed by an uppercase letter or digit let Hook tooling recognize custom hooks and check their callers. Naming alone does not grant access to React state: runtime Hook calls require React's active dispatcher and consistent call order. Removing the prefix does not bypass those runtime constraints.

## How It Works

### Custom Hook Convention

```text
├── Only call hooks at top level (not inside loops/conditions)
```

### Data Flow

A component calls `useFetch(url)` during render and reads its current result. After commit, the hook's effect starts a request. A completed request updates the caller's state, which schedules another render. When the URL changes or the component unmounts, cleanup aborts the old request and prevents its eventual completion from replacing the newer result. The complete example below includes these lifetime boundaries.

## Code Examples

### 1. useCounter

```typescript
import { useState, useCallback } from 'react';

interface UseCounterProps {
  initialValue?: number;
  min?: number;
  max?: number;
  step?: number;
}

interface UseCounterReturn {
  count: number;
  increment: () => void;
  decrement: () => void;
  reset: () => void;
  setCount: (value: number) => void;
}

function useCounter({
  initialValue = 0,
  min = -Infinity,
  max = Infinity,
  step = 1,
}: UseCounterProps = {}): UseCounterReturn {
  const [count, setCount] = useState(initialValue);

  const increment = useCallback(() => {
    setCount(prev => Math.min(prev + step, max));
  }, [step, max]);

  const decrement = useCallback(() => {
    setCount(prev => Math.max(prev - step, min));
  }, [step, min]);

  const reset = useCallback(() => {
    setCount(initialValue);
  }, [initialValue]);

  return { count, increment, decrement, reset, setCount };
}

// Usage
const CounterComponent = () => {
  const { count, increment, decrement, reset } = useCounter({
    initialValue: 10,
    min: 0,
    max: 100,
  });

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={decrement}>-</button>
      <button onClick={increment}>+</button>
      <button onClick={reset}>Reset</button>
    </div>
  );
};
```

### 2. useLocalStorage

This browser-only hook accepts JSON-serializable values. Keep `key` stable for one mounted instance (remount with a new React key when switching storage slots). It does not subscribe to writes from other tabs or other hook instances; SSR needs a deterministic server snapshot instead of reading storage during hydration.

```typescript
import { useState, useCallback, useEffect } from 'react';

function useLocalStorage<T>(
  key: string,
  initialValue: T
): [T, (value: T | ((prev: T) => T)) => void, () => void] {
  const [state, setState] = useState(() => {
    try {
      const item = window.localStorage.getItem(key);
      return { value: item === null ? initialValue : JSON.parse(item) as T, removed: false };
    } catch {
      return { value: initialValue, removed: false };
    }
  });

  // Commit external writes here; state updater functions must stay pure.
  useEffect(() => {
    try {
      if (state.removed) window.localStorage.removeItem(key);
      else window.localStorage.setItem(key, JSON.stringify(state.value));
    } catch (error) {
      console.error('Storage write failed', error);
    }
  }, [key, state]);

  const setValue = useCallback((value: T | ((prev: T) => T)) => {
    setState(prev => ({
      value: typeof value === 'function' ? (value as (prev: T) => T)(prev.value) : value,
      removed: false,
    }));
  }, []);
  const remove = useCallback(() => {
    setState({ value: initialValue, removed: true });
  }, [initialValue]);

  return [state.value, setValue, remove];
}

function ThemeToggle() {
  const [theme, setTheme] = useLocalStorage<'light' | 'dark'>('theme', 'light');
  return (
    <button onClick={() => setTheme(prev => prev === 'light' ? 'dark' : 'light')}>
      Current: {theme}
    </button>
  );
}
```

### 4. useMediaQuery

```typescript
import { useState, useEffect } from 'react';

function useMediaQuery(query: string): boolean {
  // Deterministic first render on server and client; update after commit.
  const [matches, setMatches] = useState(false);

  useEffect(() => {
    const mediaQuery = window.matchMedia(query);
    setMatches(mediaQuery.matches); // Also refresh when query changes.

    const handleChange = (event: MediaQueryListEvent) => {
      setMatches(event.matches);
    };

    mediaQuery.addEventListener('change', handleChange);
    return () => mediaQuery.removeEventListener('change', handleChange);
  }, [query]);

  return matches;
}

// Usage

  const isTablet = useMediaQuery('(min-width: 769px) and (max-width: 1024px)');
  const isDesktop = useMediaQuery('(min-width: 1025px)');

  return (
    <div>
      {isMobile && <MobileLayout />}
      {isTablet && <TabletLayout />}
      {isDesktop && <DesktopLayout />}
    </div>
  );
};
```

### 5. useToggle

```typescript
import { useState, useCallback } from 'react';

function useToggle(
  initialValue: boolean = false
```

### 6. useFetch

Keep a nonempty `options` object stable with `useMemo`, or define it outside the component when it is constant. Changes in request options are meaningful dependencies; hiding them in a render-written ref would keep an obsolete request alive. This hook owns cancellation through its internal signal.

```typescript
import { useState, useEffect, useCallback } from 'react';

interface UseFetchResult<T> {
  data: T | null;
  loading: boolean;
  error: Error | null;
  refetch: () => void;
}

function useFetch<T = unknown>(url: string, options?: Omit<RequestInit, 'signal'>): UseFetchResult<T> {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);
  const [revision, setRevision] = useState(0);
  const refetch = useCallback(() => setRevision(prev => prev + 1), []);

  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    setLoading(true);
    setError(null);
    setData(null);
    async function load() {
      try {
        const response = await fetch(url, { ...options, signal: controller.signal });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const result = await response.json() as T;
        if (active) setData(result);
      } catch (error) {
        if (active) setError(error instanceof Error ? error : new Error(String(error)));
      } finally {
        if (active) setLoading(false);
      }
    }
    void load();
    return () => { active = false; controller.abort(); };
  }, [url, options, revision]);

  return { data, loading, error, refetch };
}
```

### 7. useIntersectionObserver

```typescript
import { useState, useEffect, useRef, RefObject } from 'react';

interface UseIntersectionObserverOptions {
  threshold?: number;
  root?: Element | null;
  rootMargin?: string;
  enabled?: boolean;
}

function useIntersectionObserver<T extends HTMLElement = HTMLDivElement>(
  options: UseIntersectionObserverOptions = {}
): { ref: RefObject<T | null>; isIntersecting: boolean; entry: IntersectionObserverEntry | null } {
  const ref = useRef<T | null>(null);
  const [isIntersecting, setIsIntersecting] = useState(false);
  const [entry, setEntry] = useState<IntersectionObserverEntry | null>(null);

  const { threshold = 0, root = null, rootMargin = '0px', enabled = true } = options;

  useEffect(() => {
    if (!enabled || !ref.current) return;

    const observer = new IntersectionObserver(
      ([entry]) => {
        setIsIntersecting(entry.isIntersecting);
        setEntry(entry);
      },
      { threshold, root, rootMargin }
    );

    observer.observe(ref.current);

    return () => observer.disconnect();
  }, [threshold, root, rootMargin, enabled]);

  return { ref, isIntersecting, entry };
}

// Usage — Infinite scroll + lazy loading
const LazyImage = ({ src, alt }: { src: string; alt: string }) => {
  const { ref, isIntersecting } = useIntersectionObserver({
    threshold: 0.1,
    rootMargin: '100px',
  });

  return (
    <div ref={ref} style={{ minHeight: 200 }}>
      {isIntersecting ? (
        <img src={src} alt={alt} loading="lazy" />
      ) : (
        <div className="skeleton">Loading...</div>
      )}
    </div>
  );
};
```

### 8. useEventListener

```typescript
import { useEffect, useRef, RefObject } from 'react';

function useEventListener<K extends keyof WindowEventMap>(
  eventName: K,
  handler: (event: WindowEventMap[K]) => void,
  element?: Window | HTMLElement | RefObject<HTMLElement | null>,
  options?: boolean | AddEventListenerOptions
): void;

function useEventListener<
  K extends keyof HTMLElementEventMap,
  T extends HTMLElement = HTMLDivElement
>(
  eventName: K,
  handler: (event: HTMLElementEventMap[K]) => void,
  element: RefObject<T | null>,
  options?: boolean | AddEventListenerOptions
): void;

function useEventListener(
  eventName: string,
  handler: EventListener,
  element?: Window | HTMLElement | RefObject<HTMLElement | null>,
  options?: boolean | AddEventListenerOptions
): void {
  const savedHandler = useRef(handler);

  useEffect(() => {
    savedHandler.current = handler;
  }, [handler]);

  useEffect(() => {
    const targetElement: Window | HTMLElement | null =
      element && 'current' in element
        ? element.current
        : (element as HTMLElement) ?? window;

    if (!targetElement?.addEventListener) return;

    const eventListener = (event: Event) => savedHandler.current(event);
    targetElement.addEventListener(eventName, eventListener, options);

    return () => {
      targetElement.removeEventListener(eventName, eventListener, options);
    };
  }, [eventName, element, options]);
}

// Usage
const DocumentClick = () => {
  const [clickCount, setClickCount] = useState(0);

  useEventListener('click', () => {
    setClickCount(prev => prev + 1);
  });

  return <p>Document clicked {clickCount} times</p>;
};
```

### 9. useForm

This small form example handles string and boolean inputs with synchronous validation. Parse numbers explicitly, and use a form library for complex schemas or asynchronous field validation. Avoid overlapping submissions with the disabled submit button; a production form also needs an operation/version policy if it can reset or submit through another entry point while a request is pending.

```typescript
import { useState, useCallback, useMemo } from 'react';

interface UseFormProps<T extends Record<string, any>> {
  initialValues: T;
  validate?: (values: T) => Partial<Record<keyof T, string>>;
  onSubmit: (values: T) => void | Promise<void>;
}

interface UseFormReturn<T> {
  values: T;
  errors: Partial<Record<keyof T, string>>;
  touched: Partial<Record<keyof T, boolean>>;
  dirty: boolean;
  isSubmitting: boolean;
  submitError: string | null;
  handleChange: (field: keyof T) => (event: React.ChangeEvent<HTMLInputElement>) => void;
  handleBlur: (field: keyof T) => () => void;
  handleSubmit: (event: React.FormEvent) => void;
  setFieldValue: (field: keyof T, value: any) => void;
  resetForm: () => void;
}

function useForm<T extends Record<string, any>>({
  initialValues,
  validate,
  onSubmit,
}: UseFormProps<T>): UseFormReturn<T> {
  const [values, setValues] = useState<T>(initialValues);
  const [errors, setErrors] = useState<Partial<Record<keyof T, string>>>({});
  const [touched, setTouched] = useState<Partial<Record<keyof T, boolean>>>({});
  const [isSubmitting, setIsSubmitting] = useState(false);
  const [submitError, setSubmitError] = useState<string | null>(null);

  const dirty = useMemo(
    () => JSON.stringify(values) !== JSON.stringify(initialValues),
    [values, initialValues]
  );

  const validateForm = useCallback(
    (currentValues: T) => {
      if (validate) {
        const validationErrors = validate(currentValues);
        setErrors(validationErrors);
        return Object.keys(validationErrors).length === 0;
      }
      return true;
    },
    [validate]
  );

  const handleChange = useCallback(
    (field: keyof T) => (event: React.ChangeEvent<HTMLInputElement>) => {
      const newValue = event.target.type === 'checkbox'
        ? event.target.checked
        : event.target.value;

      setValues(prev => ({ ...prev, [field]: newValue }));

      // Validate on change if field has been touched
      if (touched[field] && validate) {
        const newValues = { ...values, [field]: newValue };
        const validationErrors = validate(newValues);
        setErrors(prev => ({
          ...prev,
          [field]: validationErrors[field] || undefined,
        }));
      }
    },
    [values, touched, validate]
  );

  const handleBlur = useCallback(
    (field: keyof T) => () => {
      setTouched(prev => ({ ...prev, [field]: true }));
      if (validate) {
        const validationErrors = validate(values);
        setErrors(prev => ({
          ...prev,
          [field]: validationErrors[field] || undefined,
        }));
      }
    },
    [values, validate]
  );

  const handleSubmit = useCallback(
    async (event: React.FormEvent) => {
      event.preventDefault();

      // Mark all fields as touched
      const allTouched = Object.keys(values).reduce(
        (acc, key) => ({ ...acc, [key]: true }),
        {} as Partial<Record<keyof T, boolean>>
      );
      setTouched(allTouched);

      if (!validateForm(values)) return;

      setIsSubmitting(true);
      setSubmitError(null);
      try {
        await onSubmit(values);
      } catch (error) {
        setSubmitError(error instanceof Error ? error.message : String(error));
      } finally {
        setIsSubmitting(false);
      }
    },
    [values, onSubmit, validateForm]
  );

  const setFieldValue = useCallback((field: keyof T, value: any) => {
    setValues(prev => ({ ...prev, [field]: value }));
  }, []);

  const resetForm = useCallback(() => {
    setValues(initialValues);
    setErrors({});
    setTouched({});
    setSubmitError(null);
    setIsSubmitting(false);
  }, [initialValues]);

  return {
    values,
    errors,
    touched,
    dirty,
    isSubmitting,
    submitError,
    handleChange,
    handleBlur,
    handleSubmit,
    setFieldValue,
    resetForm,
  };
}

// Usage
const LoginForm = () => {
  const {
    values,
    errors,
    touched,
    isSubmitting,
    submitError,
    handleChange,
    handleBlur,
    handleSubmit,
  } = useForm({
    initialValues: { email: '', password: '' },
    validate: (values) => {
      const errors: Record<string, string> = {};
      if (!values.email) errors.email = 'Required';
      if (!values.password) errors.password = 'Required';
      return errors;
    },
    onSubmit: async (values) => {
      await api.login(values);
    },
  });

  return (
    <form onSubmit={handleSubmit}>
      <input
        name="email"
        value={values.email}
        onChange={handleChange('email')}
        onBlur={handleBlur('email')}
      />
      {touched.email && errors.email && <span>{errors.email}</span>}
      <input type="password" name="password" value={values.password}
        onChange={handleChange('password')} onBlur={handleBlur('password')} />
      {touched.password && errors.password && <span>{errors.password}</span>}
      {submitError && <p role="alert">{submitError}</p>}
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Logging in...' : 'Login'}
      </button>
    </form>
  );
};
```

### 10. useAsync

This hook executes on demand. The caller can start it in an effect using a stable callback, as below. A request sequence protects against out-of-order completion, reset, dependency changes, and Strict Mode's development cleanup/replay. It suppresses obsolete state updates; cancel the underlying operation separately when its API supports cancellation.

```typescript
import { useState, useCallback, useRef, useEffect } from 'react';

type AsyncState<T> = { data: T | null; loading: boolean; error: Error | null };

function useAsync<T, Args extends unknown[]>(asyncFunction: (...args: Args) => Promise<T>) {
  const [state, setState] = useState<AsyncState<T>>({ data: null, loading: false, error: null });
  const requestVersion = useRef(0);
  useEffect(() => () => { requestVersion.current++; }, [asyncFunction]);

  const execute = useCallback(async (...args: Args): Promise<T | undefined> => {
    const version = ++requestVersion.current;
    setState(prev => ({ ...prev, loading: true, error: null }));
    try {
      const result = await asyncFunction(...args);
      if (version === requestVersion.current) {
        setState({ data: result, loading: false, error: null });
      }
      return result;
    } catch (error) {
      if (version === requestVersion.current) {
        setState({ data: null, loading: false,
          error: error instanceof Error ? error : new Error(String(error)) });
      }
      return undefined;
    }
  }, [asyncFunction]);

  const reset = useCallback(() => {
    requestVersion.current++;
    setState({ data: null, loading: false, error: null });
  }, []);
  return { ...state, execute, reset };
}

function UserProfile({ userId }: { userId: string }) {
  const loadUser = useCallback(() => fetchUser(userId), [userId]);
  const { data: user, loading, error, execute } = useAsync(loadUser);
  useEffect(() => { void execute(); }, [execute]);
  if (loading) return <Spinner />;
  if (error) return <ErrorMessage message={error.message} />;
  return <div>{user?.name}</div>;
}
```

## Real-World Use Cases

### 1. useAuth — Authentication Hook

The [authentication context example](../02-core-hooks/10.3.2.05-context-api.md#1-authentication-context) owns a shared session in one provider, exposes `useAuth`, and protects initial loading from superseding a later login/logout. Calling a stateful `useAuth` implementation independently in each component would create separate sessions. Extract the consuming hook for reuse, while keeping shared storage in the provider.

### 2. useWebSocket — Real-Time Connection

The effect owns one connection session and its reconnect timer. Cleanup marks that session stopped before closing the socket, so its close event cannot resurrect it. `onMessage` changes update a callback ref after commit without reopening the connection. The example assumes JSON messages; malformed payloads are reported separately from connection failures.

```typescript
import { useState, useEffect, useRef, useCallback } from 'react';

interface UseWebSocketOptions {
  url: string;
  onMessage?: (data: unknown) => void;
  reconnect?: boolean;
  reconnectInterval?: number;
  maxReconnects?: number;
}

function useWebSocket({ url, onMessage, reconnect = true,
  reconnectInterval = 3000, maxReconnects = 5 }: UseWebSocketOptions) {
  const [isConnected, setIsConnected] = useState(false);
  const wsRef = useRef<WebSocket | null>(null);
  const messageRef = useRef(onMessage);
  const stopRef = useRef<(() => void) | null>(null);
  useEffect(() => { messageRef.current = onMessage; }, [onMessage]);

  useEffect(() => {
    let stopped = false;
    let attempts = 0;
    let socket: WebSocket | null = null;
    let timer: ReturnType<typeof setTimeout> | null = null;
    function connect() {
      if (stopped) return;
      const ws = new WebSocket(url);
      socket = ws;
      wsRef.current = ws;
      ws.onopen = () => { if (!stopped) { attempts = 0; setIsConnected(true); } };
      ws.onmessage = event => {
        if (stopped) return;
        let data: unknown;
        try { data = JSON.parse(event.data); }
        catch (error) { console.error('Invalid socket JSON', error); return; }
        messageRef.current?.(data);
      };
      ws.onclose = () => {
        if (stopped) return;
        if (wsRef.current === ws) wsRef.current = null;
        setIsConnected(false);
        if (reconnect && attempts < maxReconnects) {
          attempts++;
          timer = setTimeout(connect, reconnectInterval);
        }
      };
      ws.onerror = () => ws.close();
    }
    function stop() {
      stopped = true;
      if (timer !== null) clearTimeout(timer);
      if (socket) {
        socket.onopen = socket.onmessage = socket.onclose = socket.onerror = null;
        if (wsRef.current === socket) wsRef.current = null;
        socket.close();
      }
    }
    stopRef.current = stop;
    setIsConnected(false);
    connect();
    return () => { stop(); stopRef.current = null; };
  }, [url, reconnect, reconnectInterval, maxReconnects]);

  const send = useCallback((data: unknown): boolean => {
    const ws = wsRef.current;
    if (!ws || ws.readyState !== WebSocket.OPEN) return false;
    ws.send(JSON.stringify(data));
    return true;
  }, []);
  const disconnect = useCallback(() => {
    stopRef.current?.();
    setIsConnected(false);
  }, []);
  return { isConnected, send, disconnect };
}
```

## Common Mistakes

### 1. Breaking the Rules of Hooks

```typescript
// BAD: Hook inside condition
function useBadHook(condition: boolean) {
  if (condition) {
    useState(0); // Conditional hook call
  }
}

// BAD: Hook inside loop
function useBadHook(items: any[]) {
  items.forEach(() => {
    useEffect(() => {}); // Hook inside loop
  });
}

// GOOD: Always at top level
function useGoodHook(condition: boolean) {
  const [value] = useState(0);

  useEffect(() => {
    if (condition) {
      // Logic inside effect is fine
    }
  }, [condition]);
}
```

### 2. Not Memoizing Return Values

A fresh return object does not itself schedule a render. It matters when the object is an effect dependency, a context value, or a prop passed across a memoized boundary. Memoize that object when preserving identity helps a measured consumer; callers destructuring primitive fields do not automatically need it. See [useMemo / useCallback](../02-core-hooks/10.3.2.03-usememo-usecallback.md) for the complete dependency and caching examples.

### 3. Creating Stale Closures

An interval effect with `[delay]` that closes over `callback` keeps the callback from its installation render. Either make callback changes restart the timer, or [store the committed callback separately from the timer lifetime](../02-core-hooks/10.3.2.02-useeffect.md#timer-with-cleanup). The latter changes which behavior the next tick sees while preserving the timer cadence.

### 4. Over-Abstracting

```typescript
// BAD: One-line custom hook adds no value
function useDouble(value: number) {
  return value * 2; // Just use `value * 2` inline!
}

// GOOD: Custom hook encapsulates lifecycle-bound logic
function useDocumentTitle(title: string) {
  useEffect(() => {
    const previous = document.title;
    document.title = title;
    // Restore on unmount — this cleanup is the lifecycle part
    // a plain helper function could never own
    return () => {
      document.title = previous;
    };
  }, [title]);
}

// Instead of a helper that would be called (and forgotten) in every component:
//   useEffect(() => { document.title = title; }, [title]);
```

## Best Practices

1. **Start with `use`** — Make custom hooks recognizable to Hook linting and readers

2. **Return a single object** — Named properties are easier to destructure

3. **Preserve identity when needed** — Memoize values used by identity-sensitive consumers

4. **Accept arguments sparingly** — Use an options object for multiple params

5. **Clean up side effects** — Always return cleanup functions from `useEffect`

6. **Handle errors gracefully** — Return error state from async hooks

7. **Separate lifetimes carefully** — A committed callback ref can keep subscriptions stable; reactive request inputs still belong in dependencies

8. **Test in isolation** — Use `renderHook` from `@testing-library/react`

9. **Keep hooks focused** — Each hook should do one thing well

10. **Compose hooks** — Build complex hooks from simpler ones

## Performance Considerations

Custom hooks add function calls and the work performed by their built-in hooks. A fresh return identity can invalidate a memoized prop or effect dependency, but it does not independently schedule an update. First measure expensive computations, subscription churn, and state updates; add identity caching only where a consumer benefits.
| Aspect | Impact | Mitigation |
| -------------------- | ------------------------ | -------------------------------------------------------- |
| Over-memoization | Wasted render cycles | Memoize for measured identity-sensitive consumers |
| Stale closures | Buggy behavior | Use `useRef` for callbacks |
| State isolation | Clean per-instance state | Use a provider/store when shared state is required |
| Large return objects | Memory overhead | Return only what's needed |
| Frequent re-creation | Performance degradation | `useCallback` for returned functions |

## Testing Custom Hooks

```typescript
import { renderHook, act } from '@testing-library/react';

// Test useCounter
test('should increment counter', () => {
  const { result } = renderHook(() => useCounter({ initialValue: 0 }));

  act(() => {
    result.current.increment();
  });

  expect(result.current.count).toBe(1);
});

// Test useDebounce
test('should debounce value changes', async () => {
  jest.useFakeTimers();

  const { result, rerender, unmount } = renderHook(
    ({ value }) => useDebounce(value, 500),
    { initialProps: { value: 'hello' } }
  );

  expect(result.current).toBe('hello');

  rerender({ value: 'world' });
  expect(result.current).toBe('hello'); // Not updated yet

  act(() => { jest.advanceTimersByTime(500); });
  expect(result.current).toBe('world'); // Updated after delay
  unmount();
  jest.useRealTimers();
});

// Test useLocalStorage
test('should persist value to localStorage', () => {
  const key = 'test-key';
  localStorage.removeItem(key);
  const { result } = renderHook(() => useLocalStorage(key, 'default'));

  act(() => {
    result.current[1]('updated');
  });

  expect(localStorage.getItem(key)).toBe('"updated"');
  act(() => { result.current[2](); });
  expect(localStorage.getItem(key)).toBeNull();
});
```

## Summary

Custom Hooks are the primary mechanism for reusing stateful logic in React. They follow the Hook rules (top-level only, React-only, `use` prefix) and can encapsulate any combination of built-in hooks. Well-designed custom hooks improve code organization, testability, and reusability across components.

## Revision Questions

**First Principles**

1. **Q:** What connects extracted stateful logic to React's render lifecycle?
   **A:** JavaScript functions can maintain closure or module state. A custom hook specifically calls React Hooks during a component render, which ties its state and effects to that caller's Hook records and cleanup lifecycle. Each independent caller receives its own records.

2. **Q:** How do custom hooks escape "wrapper hell" where HOCs and render props don't?
   **A:** They share the logic without inserting nodes into the component tree: the caller receives return values instead of a wrapped component, so the hierarchy in JSX and DevTools stays exactly what you wrote — no nesting, no prop-injection collisions, no renamed `displayName`.

3. **Q:** Why does extraction also create a test boundary?
   **A:** `renderHook` mounts a small harness that calls the hook, allowing direct assertions on its returned behavior. It isolates reusable logic from markup; component tests still verify that UI interactions use the hook correctly, and provider-dependent hooks need an appropriate wrapper.

**How It Works**

4. **Q:** What does the `use` prefix actually buy you?
   **A:** The prefix followed by an uppercase letter or digit tells tooling and readers that callers must follow the Hook rules. Runtime access still depends on React's active dispatcher and stable Hook ordering; renaming a function cannot bypass those checks.

5. **Q:** Is state shared between two components that call the same `useCounter`?
   **A:** No. The hook function is ordinary module-scope code; each call site gets its own `useState` slot, so state is isolated per component instance — that isolation is what lets you drop the same hook anywhere without cross-talk.

**Code Examples**

6. **Q:** Why does `useDebounce` return `clearTimeout(timer)` from its effect?
   **A:** Every new `value` re-runs the effect; without the cleanup the previous timer would still fire and commit a stale value after a newer one. Clearing guarantees only the final change's timer survives, so rapid typing settles on the last query.

7. **Q:** Why keep fetch options as dependencies but an event handler in a committed ref?
   **A:** A URL or request-option change should cancel the old request and start a new one, so use stable options and list them as dependencies. A handler change can update what an existing event listener calls without reinstalling that listener; updating the handler ref after commit separates callback behavior from subscription lifetime.

**Common Mistakes**

8. **Q:** Why is a `useDouble` built on `useState` + `useEffect` a worse hook than `value * 2`?
   **A:** Storing a derived product in state renders once with the old derived value, then schedules another render from the effect. Compute the product during render. A custom hook is useful when it organizes reusable Hook behavior; a pure helper is sufficient for arithmetic alone.

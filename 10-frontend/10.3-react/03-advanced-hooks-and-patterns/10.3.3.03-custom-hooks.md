# Custom Hooks

A search box should respond to every keystroke immediately, but it should not send a request for every character. A custom Hook can package the delay once and let each search field use it with its own value.

## Definition

A **custom Hook** is a function, named with the `use` prefix, that calls built-in or other custom Hooks to package reusable component behavior.

> **Textbook Definition:** A custom Hook composes React Hooks so a component can reuse stateful behavior while each call remains associated with the state and effect lifecycle of the component that called it.

Calling the same custom Hook from two components reuses its logic, not its state. Shared state needs a shared owner, such as a parent component, Context provider, or external store.

## First Principles

React associates Hook state with a component render. That creates three rules for extraction:

1. **A custom Hook runs as part of its caller.** It does not create another component or an independent state boundary.
2. **Each call has its own Hook state.** Two callers run the same function separately and get separate state unless the Hook subscribes to a shared owner.
3. **Call order must stay stable.** Call Hooks at the top level of a component or custom Hook, not inside a condition, loop, callback, or after an early return. React's linter checks these rules; the `use` name signals that a function follows them.

## Reuse a behavior with a small contract

This Hook returns the latest value only after it has stayed unchanged for the requested delay:

```tsx
import { useEffect, useState } from 'react';

export function useDebouncedValue<T>(value: T, delayMs = 300): T {
  const [settledValue, setSettledValue] = useState(value);

  useEffect(() => {
    const timer = window.setTimeout(() => setSettledValue(value), delayMs);
    return () => window.clearTimeout(timer);
  }, [value, delayMs]);

  return settledValue;
}
```

When `value` or `delayMs` changes, React runs the previous cleanup before scheduling the next timer. That prevents an older timer from publishing an outdated value. The Hook delays a value; it does not cancel a network request or protect the server from excess traffic by itself.

Use it at the point where the debounced value becomes a query key:

```tsx
import { useState } from 'react';
import { useQuery } from '@tanstack/react-query';
import { useDebouncedValue } from './use-debounced-value';

type CatalogItem = { id: string; name: string };
declare function searchCatalog(
  query: string,
  options: { signal: AbortSignal },
): Promise<CatalogItem[]>;

function CatalogSearch() {
  const [input, setInput] = useState('');
  const query = useDebouncedValue(input.trim(), 250);
  const results = useQuery({
    queryKey: ['catalog-search', query],
    queryFn: ({ signal }) => searchCatalog(query, { signal }),
    enabled: query.length > 0,
  });

  return (
    <>
      <label>
        Search catalog
        <input value={input} onChange={(event) => setInput(event.target.value)} />
      </label>
      {results.isLoading && <p>Searching…</p>}
      {results.isError && <p role="alert">Search failed. Try again.</p>}
      {results.data?.map((item) => <p key={item.id}>{item.name}</p>)}
    </>
  );
}
```

`searchCatalog` should check HTTP failures and validate the response shape. Passing TanStack Query's `signal` lets an obsolete request be cancelled when the query is no longer needed. The backend still needs its own validation, authorization, and rate limits.

## Extract only a behavior worth naming

Some duplicated logic deserves a Hook: subscribing to an external system, managing a reusable input contract, or coordinating a timer with cleanup. A pure calculation such as `value * 2` is clearer as a normal function. A Hook that combines unrelated screen state becomes a hard-to-reuse “god hook”; prefer small names that describe one behavior, such as `useOnlineStatus` or `useDebouncedValue`.

Effects inside custom Hooks still synchronize with external systems. Keep their reactive inputs in the dependency list when a change should resubscribe or restart the work. React 19.2+ provides `useEffectEvent` for logic called by an Effect that needs the latest committed values without re-synchronizing that Effect. It is restricted to Effect logic; do not use it to hide a dependency that should restart the synchronization. On earlier React versions, include the dependency or use a carefully designed committed-ref pattern when avoiding resubscription is a real requirement.

## Test the behavior at its useful boundary

For a focused stateful Hook, React Testing Library's `renderHook` can verify its public result. A component test is still needed when the important behavior includes user interaction, providers, or rendered loading and error states.

```tsx
import { act, renderHook } from '@testing-library/react';
import { afterEach, expect, it, vi } from 'vitest';
import { useDebouncedValue } from './use-debounced-value';

afterEach(() => vi.useRealTimers());

it('publishes only the latest value after the delay', async () => {
  vi.useFakeTimers();
  const { result, rerender } = renderHook(
    ({ value }) => useDebouncedValue(value, 300),
    { initialProps: { value: 'first' } },
  );

  rerender({ value: 'second' });
  expect(result.current).toBe('first');

  await act(async () => { await vi.advanceTimersByTimeAsync(299); });
  expect(result.current).toBe('first');
  await act(async () => { await vi.advanceTimersByTimeAsync(1); });
  expect(result.current).toBe('second');
});
```

The test proves the visible timing contract and that the latest scheduled value wins. It does not prove request cancellation, caching, or server rate limiting; test those at the query and API boundaries that own them.

## Summary

Custom Hooks package behavior inside the calling component's render and lifecycle. Each call keeps its own state, so share state through an explicit owner. Extract Hooks when they give repeated behavior a clear contract, keep Effect dependencies honest, and test the behavior users can observe.

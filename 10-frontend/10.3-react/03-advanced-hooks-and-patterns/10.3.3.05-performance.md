# React Performance Optimization

## TL;DR

React performance optimization involves: profiling with React DevTools (find what actually re-renders), memoization (`React.memo`, `useMemo`, `useCallback`), virtualization for long lists (`react-window`, `react-virtuoso`), code splitting (`React.lazy`, `Suspense`), and avoiding reconciliation thrash with stable keys.

## First Principles

React performance is *scheduling and commit cost management*, measured before optimized:

1. **Profile first (Profiler API, why-did-you-render)**: the cost is either too-wide renders (many components re-rendering) or too-expensive commits (DOM churn) — different diseases, different cures (memoization vs virtualization, → 10.3.1.03).
2. **The toolbox maps to causes**: memo/useMemo for referential stability (→ 10.3.2.03), list virtualization for size (only visible rows exist), transitions for interruptibility (→ 10.3.1.02), code-splitting for load (→ 40.5.1.01) — each fixes one measured cause.

## Why It Matters

Senior engineers measure before optimizing: `Profiler` API in production, `why-did-you-render` in dev. They know that `React.memo` is wasted work if the component re-renders for other reasons, and that `useMemo` doesn't memoize across component instances. The biggest perf wins usually come from reducing work, not memoizing existing work.

**Concretely:**

React applications can become slow due to unnecessary re-renders, large bundle sizes, expensive computations, poor state management, and missing memoization.

## Definition

React performance optimization is the practice of improving the speed, responsiveness, and efficiency of React applications. It involves reducing unnecessary re-renders, minimizing bundle size, optimizing rendering cycles, and improving user experience metrics like First Contentful Paint (FCP) and Time to Interactive (TTI).


## How It Works

### Performance Optimization Hierarchy

```text
Level 1: Component Optimization
├── React.memo: Prevent unnecessary re-renders
├── useMemo: Memoize expensive computations
├── useCallback: Memoize function references
└── State colocation: Keep state close to usage

Level 2: Bundle Optimization
├── Code splitting: Lazy load components
├── Tree shaking: Remove unused code
├── Dynamic imports: Load on demand
└── Compression: gzip, brotli

Level 3: Rendering Optimization
├── Virtualization: Render only visible items
├── Concurrent features: Prioritize updates
├── useTransition: Defer non-urgent updates
└── useDeferredValue: Lag behind source value

```

## Code Examples

### React.memo

```typescript
import React, { memo, useState, useCallback } from 'react';

const MemoizedChild = memo(({ data, onClick }: { data: Data; onClick: () => void }) => {
  console.log('MemoizedChild rendered');
  return <div onClick={onClick}><p>{data.text}</p></div>;
});

const Parent = () => {
  const [count, setCount] = useState(0);
  const [data] = useState({ text: 'Hello' });
  const handleClick = useCallback(() => console.log('clicked'), []);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(c => c + 1)}>+1</button>
      <MemoizedChild data={data} onClick={handleClick} />
    </div>
  );
};

```

### useMemo for Expensive Computations

```typescript
const DataVisualization = ({ rawData }: { rawData: RawDataPoint[] }) => {
  const [timeRange, setTimeRange] = useState('all');

  const processedData = useMemo(() => {
    const filtered = rawData.filter(d =>
      timeRange === 'all' || d.timestamp >= Date.now() - timeRangeToMs(timeRange)
    );
    return filtered.sort((a, b) => a.value - b.value);
  }, [rawData, timeRange]);

  return (
    <div>
      <TimeRangeSelector value={timeRange} onChange={setTimeRange} />
      <Chart data={processedData} />
    </div>
  );
};

```

### Virtualization

```typescript
import { useVirtualizer } from '@tanstack/react-virtual';

const VirtualList = ({ items }: { items: Item[] }) => {
  const parentRef = useRef<HTMLDivElement>(null);

  const virtualizer = useVirtualizer({
    count: items.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 50,
    overscan: 10,
  });

  return (
    <div ref={parentRef} style={{ height: '600px', overflow: 'auto' }}>
      <div style={{ height: virtualizer.getTotalSize(), position: 'relative' }}>
        {virtualizer.getVirtualItems().map(virtualRow => (
          <div key={virtualRow.key} style={ {
            position: 'absolute', top: 0, left: 0, width: '100%',
            height: virtualRow.size, transform: `translateY(${virtualRow.start}px)`,
          }}>
            <ListItem item={items[virtualRow.index]} />
          </div>
        ))}
      </div>
    </div>
  );
};

```

### Code Splitting

```typescript
import { lazy, Suspense } from 'react';

const Dashboard = lazy(() => import('./Dashboard'));
const Settings = lazy(() => import('./Settings'));

const App = () => {
  const [currentPage, setCurrentPage] = useState('home');

  return (
    <div>
      <Suspense fallback={<div>Loading...</div>}>
        {currentPage === 'dashboard' && <Dashboard />}
        {currentPage === 'settings' && <Settings />}
      </Suspense>
    </div>
  );
};

```

### Concurrent Features (useTransition & useDeferredValue)

```typescript
import { useState, useTransition, useDeferredValue } from 'react';

// 1. useTransition for deferring heavy UI transitions
export const TabSwitcher = () => {
  const [tab, setTab] = useState<'overview' | 'analytics'>('overview');
  const [isPending, startTransition] = useTransition();

  const handleSelectTab = (nextTab: 'overview' | 'analytics') => {
    // Non-urgent transition: input/clicks remain interactive while Analytics renders
    startTransition(() => {
      setTab(nextTab);
    });
  };

  return (
    <div>
      <div className="tab-buttons">
        <button onClick={() => handleSelectTab('overview')}>Overview</button>
        <button onClick={() => handleSelectTab('analytics')}>Analytics</button>
      </div>
      {isPending && <span className="loading-badge">Transitioning views...</span>}
      {tab === 'overview' ? <OverviewView /> : <AnalyticsView />}
    </div>
  );
};

// 2. useDeferredValue for responsive search-as-you-type
export const SearchBox = ({ data }: { data: string[] }) => {
  const [query, setQuery] = useState('');
  // Input typing remains 60fps; deferredQuery lags behind until CPU is idle
  const deferredQuery = useDeferredValue(query);
  const isStale = query !== deferredQuery;

  const filteredItems = data.filter((item) =>
    item.toLowerCase().includes(deferredQuery.toLowerCase())
  );

  return (
    <div>
      <input
        type="search"
        value={query}
        onChange={(e) => setQuery(e.target.value)}
        placeholder="Type to filter immediately..."
      />
      <div style={{ opacity: isStale ? 0.6 : 1, transition: 'opacity 0.2s' }}>
        <FilteredItemList items={filteredItems} />
      </div>
    </div>
  );
};
```

## Real-World Use Cases

- **Dashboards with 50+ live widgets** — virtualize the grid + memoize each widget; measure first or you'll memoize the wrong 50.
- **Feeds/tables with thousands of rows** — `react-virtuoso` renders only visible rows; pair with stable keys (→ 10.3.1.03's reconciliation) or virtualization gains vanish.
- **Search-as-you-type over large datasets** — `useDeferredValue`/`useTransition` keep typing responsive while the heavy list re-renders (→ 10.3.4.01).
- **Bundle bloat after feature creep** — `React.lazy` route-level splitting; the win shows up in FCP/TTI (→ 50.3.1.01), not in component benchmarks.

## Common Mistakes

| Mistake | Root Cause | Fix |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Wrapping every callback in `useCallback` | Premature optimization allocates extra closures; useless without memoized child components | Only wrap functions passed to `React.memo` components or hook dependency arrays |
| Passing inline objects or array literals to memoized children | `{ ...style }` or `[a, b]` creates a new heap reference every render, breaking equality | Hoist static values outside the component or wrap dynamic objects in `useMemo` |
| Using array index as JSX `key` in dynamic lists | Reconciliation fails to map identity when items reorder or delete, causing remount thrash | Always use stable, unique domain IDs (`item.id`) |
| Monolithic Context providers triggering cascading renders | Any value update in a Context forces all consumers to re-render, even if slice is unused | Split contexts into independent providers or migrate to `useSyncExternalStore` |
| Returning fresh object literals from custom hooks | Hook callers receive new references every render, triggering downstream `useEffect` loops | Memoize the returned object using `useMemo` inside custom hooks |
| Assuming `useMemo` caches across component instances | `useMemo` cache is instance-scoped; 1,000 instances compute the value 1,000 times | Use module-level LRU cache or server-state cache (TanStack Query) for cross-instance sharing |

## Best Practices

1. **Profile before optimizing** — use React DevTools Profiler ("Highlight updates" + flamegraph) to identify actual render bottlenecks before adding memoization
2. **Colocate state** — keep state as close as possible to the components that read and write it; parent state triggers child re-renders
3. **Stabilize props selectively** — pair `useCallback` and `useMemo` strictly with `React.memo` boundary components
4. **Virtualize long collections** — use `@tanstack/react-virtual` or `react-virtuoso` for lists with >100 elements
5. **Route-level code splitting** — load non-critical routes and heavy dependencies (charts, rich-text editors) via `React.lazy()` and `Suspense`
6. **Embrace Concurrent Transitions** — use `useTransition` for non-urgent route or tab changes to preserve main-thread input responsiveness
7. **React Compiler Readiness** — write idiomatic React following the Rules of Hooks and pure functions so the React Compiler can automate memoization cleanly

## Performance Considerations

| Metric | Target | Tool | Primary Lever |
| ------------------------ | ------ | ---------- | --------------------------------------- |
| First Contentful Paint | < 1.8s | Lighthouse | Route code-splitting, critical CSS |
| Largest Contentful Paint | < 2.5s | Lighthouse | Image optimization, SSR / Edge delivery |
| Time to Interactive | < 3.8s | Lighthouse | Defer non-critical JS, tree shaking |
| Cumulative Layout Shift | < 0.1 | Lighthouse | Explicit image/element dimensions |

## Summary

React performance optimization is the measured reduction of unnecessary re-renders, bundle size, and commit overhead. Key strategies include targeted memoization (`React.memo`, `useMemo`, `useCallback`), virtualization for collection rendering, route code-splitting, and concurrent features (`useTransition`, `useDeferredValue`). Always profile in production mode before introducing memoization layers.

## Cheat Sheet
```text
REACT PERFORMANCE OPTIMIZATION CHEAT SHEET
============================================================

DIAGNOSTIC WORKFLOW:
  1. React DevTools Profiler: Record user interaction -> inspect flamegraph
  2. "Why Did This Render?": Check props changed vs parent re-rendered
  3. Chrome Performance: Identify long tasks (>50ms) blocking the main thread

MEMOIZATION TRIO:
  • React.memo(Component)     -> Shallow props compare; skips re-render if props equal
  • useMemo(() => fn(), deps) -> Caches return value across renders of THIS instance
  • useCallback(fn, deps)     -> Caches function reference across renders of THIS instance

VIRTUALIZATION (@tanstack/react-virtual):
  • Render only visible items in viewport + overscan buffer
  • Essential for collections > 100 DOM elements

CONCURRENT FEATURES (React 18/19):
  • useTransition()     -> Marks state update as interruptible (UI doesn't freeze)
  • useDeferredValue(v) -> Lags non-critical value until high-priority work completes

INTERVIEW TRAPS:
  • Does useMemo speed up initial mount? No, it adds overhead on first render.
  • Does React.memo do deep comparison? No, shallow equality (Object.is) by default.
  • When does useCallback hurt? When wrapping small functions passed to native DOM elements (<button onClick={...}>).
```

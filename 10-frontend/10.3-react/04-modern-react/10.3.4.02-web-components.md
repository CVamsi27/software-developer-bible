# Web Components

> **Custom Elements, Shadow DOM, and HTML Templates — native browser component system.**

## TL;DR

- Web Components are the **platform's own component model**: custom elements (new HTML tags with lifecycle), shadow DOM (scoped styles/DOM), slots/templates — zero runtime, framework-agnostic.
- The win is **encapsulation and portability** (design systems, embeddable widgets); the cost is manual re-rendering and awkward React interop — React 19 improved props/children handling, but custom *events* still need ref wiring.
- Decision rule: React for the app, Web Components for the pieces other stacks must consume.

## First Principles

Web components are the browser's native component model:

1. **The platform primitives (custom elements, shadow DOM, templates) give encapsulation without a framework** — shadow DOM scopes styles (→ 10.7.06's global-cascade problem, solved natively); custom elements give lifecycle and registration.
2. **The interop trade**: framework-agnostic and durable, but React interop (events, props, SSR) stays awkward (→ 10.3.4.03's ecosystem for apps) — they shine for design systems and micro-frontends boundaries, less for app state.

## Definition

**Web Components** are a set of native browser features — Custom Elements, Shadow DOM, and HTML templates/slots — that together let you define reusable, encapsulated HTML elements with their own behavior and styling, usable in any framework or none.

## Why It Matters

Unlike React components (framework-specific), Web Components work everywhere — React, Vue, Angular, or plain HTML. The encapsulation is enforced by the platform, not by tooling: shadow DOM scoping is a browser boundary (→ 10.7.06's global-cascade problem, solved natively), so a component's styles can't leak and host styles can't reach in (except through CSS custom properties, → 10.7.07). That makes them the natural boundary technology where one codebase's UI must run inside another's page.

```
Web Components = Custom Elements + Shadow DOM + HTML Templates
```

| Feature | What It Does | Browser Support |
| ------------------- | --------------------------- | ------------------- |
| **Custom Elements** | Define new HTML tags | All modern browsers |
| **Shadow DOM** | Encapsulated DOM and styles | All modern browsers |
| **HTML Templates** | Reusable markup fragments | All modern browsers |

## Custom Elements

```typescript
// Define a custom element
class PatientCard extends HTMLElement {
  constructor() {
    super();
    // Attach shadow DOM for encapsulation
    this.attachShadow({ mode: 'open' });
  }

  connectedCallback() {
    const name = this.getAttribute('name') || 'Unknown';
    const email = this.getAttribute('email') || '';

    this.shadowRoot!.innerHTML = `
      <style>
        .card {
          border: 1px solid #e0e0e0;
          border-radius: 8px;
          padding: 16px;
          font-family: system-ui;
        }
        .name { font-weight: 600; font-size: 1.1rem; }
        .email { color: #666; }
      </style>
      <div class="card">
        <div class="name">${name}</div>
        <div class="email">${email}</div>
        <slot></slot>
      </div>
    `;
  }

  // React to attribute changes
  static get observedAttributes() {
    return ['name', 'email'];
  }

  attributeChangedCallback(name: string, oldVal: string, newVal: string) {
    if (oldVal !== newVal) {
      this.connectedCallback(); // Re-render
    }
  }
}

// Register the custom element
customElements.define('patient-card', PatientCard);
```

```html
<!-- Use in HTML -->
<patient-card name="Maria Schmidt" email="maria@example.com">
  <p>Appointment: 2026-08-25</p>
</patient-card>
```

## Shadow DOM

Shadow DOM provides style and DOM encapsulation — styles inside don't leak out, and external styles don't affect the inside.

```typescript
class StyledButton extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }

  connectedCallback() {
    this.shadowRoot!.innerHTML = `
      <style>
        /* This style ONLY affects this component */
        button {
          background: var(--btn-bg, #3b82f6);
          color: white;
          border: none;
          padding: 8px 16px;
          border-radius: 4px;
          cursor: pointer;
        }
        button:hover {
          background: var(--btn-hover, #2563eb);
        }
      </style>
      <button><slot></slot></button>
    `;
  }
}

customElements.define('styled-button', StyledButton);
```

### Shadow DOM Encapsulation

```css
/* External styles DON'T affect shadow DOM */
styled-button button {
  background: red; /* This won't work! */
}

/* Use CSS custom properties (they DO pierce shadow DOM) */
styled-button {
  --btn-bg: #10b981; /* This works! */
}
```

## HTML Templates

```html
<template id="patient-row">
  <tr>
    <td class="name"></td>
    <td class="email"></td>
    <td class="status"></td>
  </tr>
</template>

<script>
  const template = document.getElementById('patient-row');
  const clone = template.content.cloneNode(true);

  clone.querySelector('.name').textContent = 'Maria Schmidt';
  clone.querySelector('.email').textContent = 'maria@example.com';
  clone.querySelector('.status').textContent = 'Active';

  document.querySelector('tbody').appendChild(clone);
</script>
```

## Web Components vs React

| Feature | Web Components | React |
| -------------------- | --------------------------------- | ------------------------ |
| **Encapsulation** | Shadow DOM (native) | Scoped CSS (tools) |
| **Re-rendering** | Manual (attributeChangedCallback) | Automatic (state change) |
| **Framework** | Framework-agnostic | React-specific |
| **Bundle size** | 0KB (native) | ~40KB (React runtime) |
| **Server rendering** | Custom Elements API | SSR/SSG |
| **Ecosystem** | Limited | Vast |

## Code Examples

### Using a custom element from React (React 19 interop)

React 19 sets non-primitive props as *properties* and primitives as *attributes* — but custom events still need manual wiring via a ref:

```tsx
// React 19: props flow naturally
function BookingWidget({ clinicId, onBooked }: { clinicId: string; onBooked: (id: string) => void }) {
  const ref = useRef<HTMLElement>(null);

  useEffect(() => {
    const el = ref.current;
    if (!el) return;
    // Custom events are NOT auto-handled — attach/detach via ref
    const handler = (e: Event) => onBooked((e as CustomEvent<string>).detail);
    el.addEventListener('booked', handler);
    return () => el.removeEventListener('booked', handler);
  }, [onBooked]);

  // primitives → attributes; objects/functions → properties (React 19)
  return <booking-widget ref={ref} clinic-id={clinicId} config={{ theme: 'dark' }} />;
}
```

The attribute-vs-property trap is the interview probe: `<booking-widget config={{...}} />` works in React 19 (property), but in React ≤18 it serialized to the *string* `"[object Object]"` as an attribute — the classic broken-interop story.

## Interview Questions

**Q: "When would you use Web Components over React?"**

> Web Components when: (1) building a design system used by multiple frameworks (React + Vue + Angular teams), (2) creating embeddable widgets for third-party sites (payment form, chat widget), (3) need zero-dependency components (no React runtime). React when: (1) building a full application with complex state management, (2) need hot module replacement, (3) want access to the React ecosystem. For Docita: React for the main app, Web Components for the embeddable appointment booking widget that clinics can add to their websites.

## Common Mistakes

1. **Expecting React re-renders to update the element** — only attributes/properties you pass change it; `attributeChangedCallback` re-renders only observed attributes. Passing an object prop that the element doesn't read silently does nothing.
2. **Styling across the boundary with regular selectors** — shadow DOM blocks them. Use CSS custom properties (they pierce), `::part()`, or constructable stylesheets.
3. **Forgetting `observedAttributes`** — without it, `attributeChangedCallback` never fires and props look "broken" in every framework.
4. **Using Web Components for app state** — they have no state model; the interop cost buys nothing inside a single-framework app.
5. **Listening for custom events with `onClick`-style props** — React doesn't attach listeners for custom event names; use `addEventListener` in a ref effect.

## Best Practices

- **Ship design systems and embeddable widgets as Web Components**; keep app UI in React.
- **Emit CustomEvents with `detail`** for a clean host-facing API; document them like props.
- **Prefer `type: 'module'` custom element files** and lazy-register (`customElements.get` check) to avoid double-registration errors in HMR.
- **Pass data down as properties, receive events up via CustomEvent** — one-way flow, same mental model as React.

## Summary

1. **Web Components = custom elements + shadow DOM + slots** — framework-agnostic encapsulation at the platform level
2. **React 19 interop improved** — custom elements accept props/children more naturally; attribute vs property handling is still the trap
3. **Shadow DOM boundaries affect styling and events** — composed/retargeted events, `:host` styling, constructable stylesheets
4. **Right tool for embeddable widgets and design systems** — one widget consumed by React/Vue/plain-HTML hosts
5. **Docita-style decision rule** — main app in React; ship the embeddable booking widget as a Web Component

## Cheat Sheet

```text
DEFINE      class X extends HTMLElement · customElements.define('x-tag', X)
LIFECYCLE   connectedCallback · disconnectedCallback · attributeChangedCallback
OBSERVE     static get observedAttributes() { return ['name'] }
ENCAPE      this.attachShadow({ mode: 'open' }) → this.shadowRoot
STYLE       styles inside shadow DOM are scoped · CSS custom properties pierce
SLOTS       <slot></slot> renders host children (light DOM)
EVENTS      dispatchEvent(new CustomEvent('booked', { detail }))
REACT 19    primitives→attributes · objects/functions→properties · events via ref
USE FOR     design systems · embeddable widgets · micro-frontend boundaries
SKIP FOR    single-framework apps with complex state
```

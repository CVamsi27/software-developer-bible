# Web Components

Suppose a booking widget must work in a React application today and a plain HTML partner portal tomorrow. A React component alone cannot cross that boundary; a custom element can, if its attributes, properties and events form a clear public contract.

```html
<booking-card status="confirmed">
  <span slot="title">Flight BA249</span>
  Seat 14A · Boarding 18:40
</booking-card>
```

## Definition

**Practical definition:** Web Components are browser standards for building reusable HTML elements with a registered lifecycle and public attributes, properties and events, plus optional DOM and style encapsulation. Independent frameworks can use the same browser-level contract.

> **Textbook Definition:** Web Components combine Custom Elements, Shadow DOM and HTML templates or slots to define reusable browser-native interfaces. These features are independent: a custom element does not need a shadow root, and a shadow root does not provide a security sandbox.

## First Principles

A component shared across frameworks needs three things: a browser-recognized element name, a predictable way to receive data, and a way to report user actions. Custom Elements supply the name and lifecycle; attributes and properties carry data in; events carry outcomes out. Shadow DOM and templates solve separate composition and styling problems.

## How It Works

### 1. Give the Element a Lifecycle and a Contract

A custom element name must contain a hyphen, such as **booking-card**. The browser calls **connectedCallback** when the element joins a document and **disconnectedCallback** when it leaves. If an observed attribute changes, **attributeChangedCallback** runs. Treat these callbacks as lifecycle events: attach listeners and observers once, update from changed inputs, and clean up resources on disconnection.

```js
const template = document.createElement("template");
template.innerHTML =
  "<style>" +
  ":host { display: block; color: var(--booking-text, #222); }" +
  "article { border: 1px solid #aaa; padding: 1rem; }" +
  "</style>" +
  "<article part='card'>" +
  "<h2><slot name='title'></slot></h2>" +
  "<slot></slot>" +
  "</article>";

class BookingCard extends HTMLElement {
  static observedAttributes = ["status"];

  constructor() {
    super();
    // React 19 checks that this own property exists on the constructed element.
    this.config = undefined;
    const root = this.attachShadow({ mode: "open" });
    root.append(template.content.cloneNode(true));
  }

  connectedCallback() {
    this.render();
  }

  attributeChangedCallback() {
    this.render();
  }

  render() {
    // Attribute values are text, not trusted HTML.
    this.dataset.state = this.getAttribute("status") ?? "pending";
    this.dataset.theme = this.config?.theme ?? "light";
  }
}

customElements.define("booking-card", BookingCard);
```

The template stores inert markup; cloning its fragment puts that markup in the shadow tree. Named slots place host-provided children into specific locations. Here, text is supplied through a slot, while the status attribute updates a host-facing state marker. Do not interpolate untrusted values into innerHTML; a shadow root does not make HTML safe.

The custom-element registry is page-wide, so a name can be defined only once. Hot reload must account for an existing definition. A shadow tree scopes ordinary CSS selectors, but inherited properties and CSS custom properties still cross the boundary. **::part()** exposes selected internals for deliberate styling. An open shadow root is accessible through JavaScript; a closed root is not a security boundary.

### 2. Make Events Cross the Boundary Deliberately

An event dispatched inside a shadow tree is retargeted for outside listeners. If it must bubble through the shadow boundary, dispatch it with both **bubbles: true** and **composed: true**. A public event dispatched directly on the custom-element host can bubble to page ancestors with `bubbles: true`; it does not need `composed` because it did not originate inside the shadow tree.

```js
// Add this method to BookingCard; bookingId comes from the confirmed action.
confirmBooking(bookingId) {
  this.dispatchEvent(
    new CustomEvent("booking-confirmed", {
      detail: { bookingId },
      bubbles: true,
    }),
  );
}
```

The event name and detail shape are part of the component’s API. Document them as carefully as a function’s parameters and return value.

### 3. Bridge Framework Data Without Losing Its Type

HTML attributes represent strings. JavaScript properties can hold objects and functions. React 19’s client renderer assigns a JSX value as a property when that property already exists on the custom-element instance during construction; otherwise it uses an attribute. The server renderer emits primitive values as attributes and omits non-primitive values, so the element must tolerate an object property that is unavailable until hydration.

```tsx
function BookingAdapter({
  settings,
  onBooked,
}: {
  settings: { theme: string };
  onBooked: (bookingId: string) => void;
}) {
  return (
    <booking-card
      config={settings}
      onbooking-confirmed={(event: CustomEvent<{ bookingId: string }>) =>
        onBooked(event.detail.bookingId)
      }
    />
  );
}
```

The custom element must initialize `config` in its constructor for React 19 to recognize it as a property. The example renders its initial value from `connectedCallback`; if the property can change later, add a setter or update method that rerenders the element. The JSX tag also needs a TypeScript `JSX.IntrinsicElements` declaration; runtime interoperability does not add compile-time tag types. React 19’s on-prefixed event props preserve the event name’s case and dashes. For React 18, use a ref-based adapter to assign object properties and subscribe to custom events.

Choose this boundary when a widget must be consumed by multiple frameworks or by an independently deployed host. In a React-only application, ordinary React components usually provide simpler state, testing and server-rendering integration.

## Summary

Custom Elements provide browser-level behavior; Shadow DOM scopes selectors; templates and slots compose markup. Their public API is the attributes, properties and events that cross the element boundary. React 19 improves that interoperability, but server rendering, event propagation, accessibility and state ownership still require deliberate design.

# React Router Data Mode

A URL such as /projects/42 should load the project, preserve the surrounding navigation, work with browser Back, and show a useful failure if the request is denied. A route tree gives one place to coordinate those behaviors.

```tsx
const router = createBrowserRouter([
  {
    path: "/",
    Component: RootLayout,          // nav + <Outlet /> stays mounted
    children: [
      { path: "projects/:projectId", loader: projectLoader, Component: ProjectPage },
    ],
  },
]);
```

## Definition

**Practical definition:** React Router matches the current URL to nested route components. Data Mode extends that route tree with loaders, actions, navigation state, error handling and revalidation; the server still owns authorization.

> **Textbook Definition:** A client-side router maps a location to a configured UI branch and manages navigation between branches. React Router Data Mode extends route matching with data handlers and state transitions; it does not itself authorize access to server resources.

## First Principles

A navigation changes more than the visible component: it selects a route branch, starts that branch’s data work, exposes pending state, and chooses where failures render. Starting unrelated fetch Effects inside each component makes cancellation, stale responses and shared layout behavior harder to coordinate. A data router places those lifecycle decisions beside the route that owns them. In Data Mode that coordination still runs in the browser, so server authorization remains an API responsibility.

**Version boundary:** This chapter uses React Router v8.4.0, released September 15, 2026. V8 requires Node 22.22+ and React/React DOM 19.2.7+; Framework Mode also requires Vite 7+. V8 removes the react-router-dom re-export package: use react-router for route APIs and react-router/dom for the DOM-aware RouterProvider. Check the official upgrade guide when migrating a v7 app.

## How It Works

### 1. Let the URL Select a Nested Branch

A route tree ties each URL to a page and its layout. A matched child renders where its parent places Outlet. For /projects/42, the project page can keep the root navigation while it loads:

```tsx
import { createBrowserRouter, Link, Outlet } from "react-router";
import { RouterProvider } from "react-router/dom";

// RootLayout, Home, ProjectPage and the error boundaries are app components.
const router = createBrowserRouter([
  {
    path: "/",
    Component: RootLayout,
    ErrorBoundary: RootError,
    children: [
      { index: true, Component: Home },
      {
        path: "projects/:projectId",
        loader: projectLoader,
        action: projectAction,
        Component: ProjectPage,
        ErrorBoundary: ProjectError,
      },
    ],
  },
]);

function RootLayout() {
  return (
    <>
      <nav aria-label="Main"><Link to="/projects/42">Project</Link></nav>
      <main><Outlet /></main>
    </>
  );
}

export function App() {
  return <RouterProvider router={router} />;
}
```

Declarative Mode is enough when an app needs URL matching and navigation. Data Mode adds route loaders, actions and pending state while the application still owns its build and server integration. Framework Mode adds route-module conventions, generated route types, code splitting and server rendering options. Choose based on who should own those responsibilities.

### 2. Load Route Data with Navigation

A loader supplies the data required by its route before that route commits. In Data Mode, loaders run in the browser, so use them to call an API rather than to access server secrets or a database directly:

```ts
import type { LoaderFunctionArgs } from "react-router";
import { ProjectSchema } from "./project-schema";

async function projectLoader({ params, request }: LoaderFunctionArgs) {
  const projectId = params.projectId;
  if (!projectId) throw new Response("Not found", { status: 404 });

  const response = await fetch(
    "/api/projects/" + encodeURIComponent(projectId),
    { credentials: "same-origin", signal: request.signal },
  );

  if (!response.ok) throw response;
  const payload: unknown = await response.json();
  return ProjectSchema.parse(payload);
}
```

`ProjectSchema` is an application runtime schema. A TypeScript assertion alone cannot validate data received over the network. The API must authenticate the session, enforce tenant and project permissions, and return an appropriate status. A client loader redirect improves navigation flow; it does not protect the data endpoint.

For a large route, route.lazy can import implementation fields such as Component, loader and action while keeping matching fields like path in the initial route tree. Lazy loading can reduce initial JavaScript, at the cost of a later module request; split routes when bundle measurements justify it.

The router starts loaders for matched routes concurrently by default. A child loader cannot wait for a parent loader’s result, and a parent loader redirect does not prevent the child loader from starting. Put dependent work in one loader or coordinate it explicitly. Pass the navigation’s AbortSignal to fetch so obsolete reads can stop; aborting the browser request does not undo work the server already accepted.

React Router v8 also provides route middleware. In Data Mode it runs in the browser in a parent-to-child chain before route handlers, then unwinds afterward. It can check session state once for the route branch and pass data through router context, but it remains client code: every API must authorize its own operation. Framework Mode server middleware runs on the server for document and data requests, which is a different trust boundary.

```ts
import { createContext, redirect, type MiddlewareFunction } from "react-router";

const sessionContext = createContext<Session | null>(null);
const requireSession: MiddlewareFunction = async ({ context }, next) => {
  const session = await api.getCurrentSession();
  if (!session) throw redirect("/login");

  context.set(sessionContext, session);
  await next();
};
```

Attach it to a protected branch so the check runs once before that branch’s loaders:

```ts
{
  path: "projects",
  middleware: [requireSession],
  children: projectRoutes,
}
```

This can stop client loaders after a missing session is found. Keep resource-level checks on the API, including tenant ownership and write permissions. A branch middleware check only coordinates browser navigation.

### 3. Submit Changes and Show Their State

Use a route action for a mutation associated with navigation. A React Router Form submits to that action; after a successful submission, active loader data is revalidated so the view can reflect the server’s confirmed result.

Use a fetcher for an inline operation, such as renaming a row, when the URL should stay put. Both approaches expose pending state. A typical interface disables duplicate submission, marks the pending row for assistive technology, and reports field errors next to the relevant controls:

```tsx
import { useFetcher } from "react-router";

function RenameProject({ projectId, name }: { projectId: string; name: string }) {
  const fetcher = useFetcher<typeof projectAction>();
  const pending = fetcher.state !== "idle";

  return (
    <fetcher.Form method="post" action={`/projects/${encodeURIComponent(projectId)}`}>
      <label>Project name <input name="name" defaultValue={name} /></label>
      <button disabled={pending}>{pending ? "Saving…" : "Save"}</button>
      <span role="status" aria-live="polite">{pending ? "Saving project" : ""}</span>
      {fetcher.data?.error && <p role="alert">{fetcher.data.error}</p>}
    </fetcher.Form>
  );
}
```

The route action receives the project ID from the matched URL and validates the submitted name before calling the API:

```ts
import type { ActionFunctionArgs } from "react-router";

async function projectAction({ params, request }: ActionFunctionArgs) {
  const projectId = params.projectId;
  if (!projectId) throw new Response("Not found", { status: 404 });

  const formData = await request.formData();
  const name = formData.get("name");
  if (typeof name !== "string" || !name.trim()) {
    return { error: "Enter a project name." };
  }

  const response = await fetch(`/api/projects/${encodeURIComponent(projectId)}`, {
    method: "PATCH",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ name: name.trim() }),
  });
  if (!response.ok) throw response;
  return null;
}
```

The validation object above has a successful response status, so default loader revalidation still runs. Return an appropriate 4xx status when a failed submission should skip it. The API still authenticates the request and authorizes the project; client-side route validation improves feedback but is not a security boundary.

In Data Mode, actions run in the browser and usually call an API. In Framework Mode, route actions run on the server; a clientAction runs in the browser. A client-side Data Mode Form depends on JavaScript. No-JavaScript form behavior needs a server endpoint or a Framework Mode server action.

V8 Data Mode revalidates loaders after a successful action by default. A failed 4xx/5xx action response skips that default revalidation; returning an error object with a successful status does not. Use shouldRevalidate only when a route’s data is unaffected, and return defaultShouldRevalidate for cases the route does not handle. Skipping necessary revalidation can leave stale data on screen.

### 4. Reveal Non-Critical Data Progressively

Await data needed for the page before returning from the loader. A slower, optional panel can remain a promise and render under Suspense:

```tsx
import { Suspense } from "react";
import { Await, useLoaderData } from "react-router";

async function dashboardLoader() {
  return {
    summary: await getSummary(),
    activity: getRecentActivity(),
  };
}

function Dashboard() {
  const { summary, activity } = useLoaderData<typeof dashboardLoader>();

  return (
    <>
      <SummaryCard data={summary} />
      <Suspense fallback={<p role="status">Loading activity…</p>}>
        <Await resolve={activity} errorElement={<ActivityError />}>
          {(items) => <ActivityList items={items} />}
        </Await>
      </Suspense>
    </>
  );
}
```

The router waits for summary before committing the route; activity can appear when its promise resolves. Give rejected deferred data an error UI. Returning a promise in Data Mode does not configure server HTML streaming; Framework Mode or a custom server integration must coordinate streamed data and rendered HTML.

### 5. Keep Links, Errors and Navigation Understandable

Use route-level error boundaries near the part of the screen that can recover. A project-specific 404 can stay inside the project layout; an unexpected root failure can use the root boundary. A loader or action can throw a status-bearing Response or redirect.

The common hooks answer different questions: useParams reads path segments; useSearchParams reads or changes URL query state; useNavigation exposes the current navigation or submission; useFetcher tracks an independent load or mutation; useNavigate performs a programmatic navigation. Keep shareable filters in the URL and transient presentation state in the component that owns it.

Relative links resolve against the route hierarchy by default. A link to .. leaves one path-contributing route, which may contain multiple URL segments. Set relative="path" when the intended step is exactly one URL segment. A leading slash starts at the application root.

## Summary

The route tree connects URL, layout, data and failure behavior. Loaders prepare route data; actions handle mutations; pending state and errors belong beside the route they affect. In Data Mode those handlers run in the browser and rely on an authorized API. Use middleware for client navigation coordination, never as the server’s access-control boundary.

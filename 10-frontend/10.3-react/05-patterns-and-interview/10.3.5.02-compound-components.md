# Compound Components

## Definition

Consider how native HTML designs form controls: you write `<select>` and `<option>`. You do not configure a select box by passing a massive configuration object with fifty props (`<Select options={[...]} renderItem={...} headerClassName={...} />`). The browser provides a cohesive family of declarative tags that communicate implicit state behind the scenes while giving the developer complete control over layout and styling.

In React, monolithic component design often leads to a **prop apocalypse**: an initial `<Modal title="..." content="..." />` rapidly balloons into dozens of boolean flags, custom render props, and style overrides. The **Compound Components Pattern** solves this by decomposing a complex widget into a family of cooperating subcomponents (such as `<Tabs>`, `<Tabs.List>`, `<Tabs.Trigger>`, and `<Tabs.Content>`). The parent component encapsulates state management and keyboard accessibility, sharing context implicitly with its descendants while granting callers complete layout flexibility without prop drilling.

> **Textbook Definition:** Compound components express one coordinated interface through cooperating child components. Shared state and explicit child contracts allow callers to arrange the parts while the implementation retains ownership of their behavior.


## First Principles

A tab's trigger and panel must agree on one selected value even when a caller wraps them in layout elements. Separate local state can let them disagree; passing every coordination prop through each wrapper couples layout to behavior. A common owner keeps one selection while leaving the caller room to arrange the parts.

That freedom still needs rules: related children require their matching owner, identities must remain stable, and keyboard/label relationships must connect the parts. Context supplies transport; it does not validate arbitrary nesting or implement accessible widget behavior.

## The trade-off is flexible markup for a stricter composition contract

Use this pattern when related parts need shared behavior and callers benefit from choosing their arrangement. The parent must still define which parts are valid, what happens when a part is missing or repeated, and whether child identity is stable. Context carries state; it does not validate the tree or implement widget accessibility.

`React.Children` and `cloneElement` solve a narrower problem: they inspect or transform elements passed directly in `children`. They do not inspect the rendered output of a child component or traverse into fragments. They can inject props, but that direct-child contract is fragile when arbitrary wrappers are allowed. Use them only when direct children are intentionally part of the API.

## How It Works

### State Sharing via Context

```text
Tabs (owns activeIndex and setActiveIndex)
└── TabsContext.Provider
    ├── TabList
    │   └── Tab (reads selection; changes activeIndex)
    └── TabPanels
        └── TabPanel (renders the selected content)
```

Wrappers between these components do not block context. A changed provider value notifies consumers that read that context; Context does not select updates by individual field. The sketches below teach composition and state contracts, not complete accessible widgets.

## Code Examples

### 1. Tabs state-sharing sketch

This abbreviated example demonstrates shared state and composition. Its buttons have no tab-widget semantics; a production tab widget also needs linked tab/panel IDs, roving focus, arrow-key behavior, and a defined activation policy.

```typescript
import type { ReactNode } from 'react';
import { createContext, useContext, useState, useMemo } from 'react';

// ─── Context ─────────────────────────────────────────────────

interface TabsContextType {
  activeIndex: number;
  setActiveIndex: (index: number) => void;
}

const TabsContext = createContext<TabsContextType | null>(null);

const useTabsContext = () => {
  const context = useContext(TabsContext);
  if (!context) throw new Error('Tabs compound components must be used within Tabs');
  return context;
};

// ─── Tabs Parent ─────────────────────────────────────────────

interface TabsProps {
  defaultIndex?: number;
  children: ReactNode;
}

const TabsRoot = ({ defaultIndex = 0, children }: TabsProps) => {
  const [activeIndex, setActiveIndex] = useState(defaultIndex);

  const value = useMemo(
    () => ({ activeIndex, setActiveIndex }),
    [activeIndex]
  );

  return (
    <TabsContext.Provider value={value}>
      <div className="tabs">{children}</div>
    </TabsContext.Provider>
  );
};

// ─── TabList ─────────────────────────────────────────────────

const TabList = ({ children }: { children: ReactNode }) => (
  <div className="tab-list">{children}</div>
);

// ─── Tab ─────────────────────────────────────────────────────

interface TabProps {
  index: number;
  children: ReactNode;
}

const Tab = ({ index, children }: TabProps) => {
  const { activeIndex, setActiveIndex } = useTabsContext();

  return (
    <button
      type="button"
      className={activeIndex === index ? 'tab tab--active' : 'tab'}
      onClick={() => setActiveIndex(index)}
    >
      {children}
    </button>
  );
};

// ─── TabPanels ───────────────────────────────────────────────

const TabPanels = ({ children }: { children: ReactNode }) => (
  <div className="tab-panels">{children}</div>
);

// ─── TabPanel ────────────────────────────────────────────────

interface TabPanelProps {
  index: number;
  children: ReactNode;
}

const TabPanel = ({ index, children }: TabPanelProps) => {
  const { activeIndex } = useTabsContext();

  if (activeIndex !== index) return null;

  return (
    <div className="tab-panel">
      {children}
    </div>
  );
};

const Tabs = Object.assign(TabsRoot, { TabList, Tab, TabPanels, TabPanel });

// ─── Usage ───────────────────────────────────────────────────

const App = () => (
  <Tabs defaultIndex={0}>
    <Tabs.TabList>
      <Tabs.Tab index={0}>Profile</Tabs.Tab>
      <Tabs.Tab index={1}>Settings</Tabs.Tab>
      <Tabs.Tab index={2}>Security</Tabs.Tab>
    </Tabs.TabList>

    <Tabs.TabPanels>
      <Tabs.TabPanel index={0}>
        <ProfileForm />
      </Tabs.TabPanel>
      <Tabs.TabPanel index={1}>
        <SettingsForm />
      </Tabs.TabPanel>
      <Tabs.TabPanel index={2}>
        <SecuritySettings />
      </Tabs.TabPanel>
    </Tabs.TabPanels>
  </Tabs>
);
```

Trace selecting Settings: its Tab reads the shared setter, queues index 1, and every subscribed trigger/panel reads the new provider value. Profile's inner content unmounts because its panel returns null; Settings mounts. A form draft inside Profile therefore does not survive a tab switch unless its owner stays mounted or stores it above the panel. An additional nested Tabs provides a distinct nearest selection owner.

The numeric indices in this compact example assume a stable tab order. For dynamic tabs, use stable domain values and define what happens if the selected tab is removed. A controlled variant must accept its selected value and emit changes to the parent; do not silently mix a controlled prop with an independent internal state copy.

### 2. Accordion Compound Component

Each panel below stays mounted while closed and is hidden with the native `hidden` attribute. This preserves its component state, but its effects remain active; choose an explicit unmount policy if that work should stop while closed. The markup demonstrates the expanded-state relationship; a production accordion should place each trigger inside the heading level appropriate to the page.

```typescript
import type { ReactNode } from 'react';
import { createContext, useContext, useState, useCallback, useMemo, useId } from 'react';

// ─── Context ─────────────────────────────────────────────────

interface AccordionContextType {
  openItems: Set<number>;
  toggleItem: (index: number) => void;
  allowMultiple: boolean;
}

const AccordionContext = createContext<AccordionContextType | null>(null);

const useAccordionContext = () => {
  const context = useContext(AccordionContext);
  if (!context) throw new Error('Must be inside Accordion');
  return context;
};

// ─── Accordion Parent ────────────────────────────────────────

interface AccordionProps {
  allowMultiple?: boolean;
  children: ReactNode;
}

const AccordionRoot = ({ allowMultiple = false, children }: AccordionProps) => {
  const [openItems, setOpenItems] = useState<Set<number>>(new Set());

  const toggleItem = useCallback((index: number) => {
    setOpenItems(prev => {
      const next = new Set(prev);
      if (next.has(index)) {
        next.delete(index);
      } else {
        if (!allowMultiple) next.clear();
        next.add(index);
      }
      return next;
    });
  }, [allowMultiple]);

  const value = useMemo(
    () => ({ openItems, toggleItem, allowMultiple }),
    [openItems, toggleItem, allowMultiple]
  );

  return (
    <AccordionContext.Provider value={value}>
      <div className="accordion">{children}</div>
    </AccordionContext.Provider>
  );
};

// ─── AccordionItem ───────────────────────────────────────────

interface AccordionItemProps {
  index: number;
  title: string;
  children: ReactNode;
}

const AccordionItem = ({ index, title, children }: AccordionItemProps) => {
  const { openItems, toggleItem } = useAccordionContext();
  const isOpen = openItems.has(index);
  const panelId = useId();

  return (
    <div className="accordion-item">
      <button
        type="button"
        className="accordion-header"
        onClick={() => toggleItem(index)}
        aria-expanded={isOpen}
        aria-controls={panelId}
      >
        {title}
        <span aria-hidden="true" className={`chevron ${isOpen ? 'chevron--open' : ''}`}>▼</span>
      </button>
      <div id={panelId} className="accordion-body" hidden={!isOpen}>{children}</div>
    </div>
  );
};

const Accordion = Object.assign(AccordionRoot, { Item: AccordionItem });

// ─── Usage ───────────────────────────────────────────────────

const FaqSection = () => (
  <Accordion allowMultiple>
    <Accordion.Item index={0} title="What is React?">
      <p>React is a JavaScript library for building user interfaces.</p>
    </Accordion.Item>
    <Accordion.Item index={1} title="What are hooks?">
      <p>Hooks let you use state and other React features without writing a class.</p>
    </Accordion.Item>
    <Accordion.Item index={2} title="What is TypeScript?">
      <p>TypeScript is a typed superset of JavaScript that compiles to plain JavaScript.</p>
    </Accordion.Item>
  </Accordion>
);
```

### 3. Choice Popover Compound Component

```typescript
import type { ReactNode } from 'react';
import { createContext, useContext, useState, useRef, useEffect, useMemo, useCallback, useId } from 'react';

// ─── Context ─────────────────────────────────────────────────

interface SelectContextType {
  isOpen: boolean;
  selectedValue: string | null;
  selectedLabel: string | null;
  label: string;
  placeholder: string;
  toggle: () => void;
  select: (value: string) => void;
  registerOption: (value: string, label: string) => void;
  unregisterOption: (value: string, label: string) => void;
  optionsId: string;
}

const SelectContext = createContext<SelectContextType | null>(null);

const useSelectContext = () => {
  const context = useContext(SelectContext);
  if (!context) throw new Error('Must be inside Select');
  return context;
};

// ─── Select Parent ───────────────────────────────────────────

interface SelectProps {
  value: string | null;
  onChange: (value: string) => void;
  label: string;
  placeholder?: string;
  children: ReactNode;
}

const SelectRoot = ({ value, onChange, label, placeholder = 'Select...', children }: SelectProps) => {
  const [isOpen, setIsOpen] = useState(false);
  const [options, setOptions] = useState(() => new Map<string, string>());
  const ref = useRef<HTMLDivElement>(null);
  const optionsId = useId();

  const selectedLabel = value === null ? null : options.get(value) ?? null;

  const toggle = useCallback(() => setIsOpen(prev => !prev), []);
  const select = useCallback((val: string) => {
    onChange(val);
    setIsOpen(false);
  }, [onChange]);

  const registerOption = useCallback((val: string, label: string) => {
    setOptions(previous => {
      if (previous.get(val) === label) return previous;
      const next = new Map(previous);
      next.set(val, label);
      return next;
    });
  }, []);

  const unregisterOption = useCallback((val: string, label: string) => {
    setOptions(previous => {
      if (previous.get(val) !== label) return previous;
      const next = new Map(previous);
      next.delete(val);
      return next;
    });
  }, []);

  // Close on outside click
  useEffect(() => {
    if (!isOpen) return;
    const handleClick = (e: MouseEvent) => {
      if (ref.current && !ref.current.contains(e.target as Node)) {
        setIsOpen(false);
      }
    };
    document.addEventListener('mousedown', handleClick);
    return () => document.removeEventListener('mousedown', handleClick);
  }, [isOpen]);

  const ctx = useMemo(() => ({
    isOpen, selectedValue: value, selectedLabel, label, placeholder, toggle, select,
    registerOption, unregisterOption, optionsId,
  }), [isOpen, value, selectedLabel, label, placeholder, toggle, select, registerOption, unregisterOption, optionsId]);

  return (
    <SelectContext.Provider value={ctx}>
      <div ref={ref} className="custom-select">{children}</div>
    </SelectContext.Provider>
  );
};

// ─── SelectOption ────────────────────────────────────────────

interface SelectOptionProps {
  value: string;
  label?: string;
  children: ReactNode;
}

const SelectOption = ({ value, label: providedLabel, children }: SelectOptionProps) => {
  const { selectedValue, select, registerOption, unregisterOption } = useSelectContext();
  const label = providedLabel ?? (typeof children === 'string' ? children : value);

  useEffect(() => {
    registerOption(value, label);
    return () => unregisterOption(value, label);
  }, [value, label, registerOption, unregisterOption]);

  return (
    <button
      type="button"
      className={`select-option ${selectedValue === value ? 'select-option--selected' : ''}`}
      onClick={() => select(value)}
      aria-pressed={selectedValue === value}
    >
      {children}
    </button>
  );
};

// ─── SelectTrigger ───────────────────────────────────────────

const SelectTrigger = () => {
  const { selectedLabel, placeholder, toggle, isOpen, optionsId } = useSelectContext();
  return (
    <button type="button" className="select-trigger" onClick={toggle} aria-expanded={isOpen} aria-controls={optionsId}>
      {selectedLabel ?? placeholder}
      <span aria-hidden="true">▼</span>
    </button>
  );
};

const SelectOptions = ({ children }: { children: ReactNode }) => {
  const { isOpen, optionsId, label } = useSelectContext();
  // Keep options mounted so initial/changed labels can register.
  return <div id={optionsId} className="select-dropdown" role="group" aria-label={label} hidden={!isOpen}>{children}</div>;
};

const Select = Object.assign(SelectRoot, {
  Trigger: SelectTrigger,
  Option: SelectOption,
  Options: SelectOptions,
});
```

This is a controlled choice-popover sketch with a named group of toggle buttons, not a native `<select>` replacement, menu, or listbox. Production behavior still needs a deliberate focus/Escape policy and a visual positioning strategy. Values must be unique. Registration cleanup prevents removed options from leaving stale labels. Because options register in an Effect, a non-null initial value can briefly show the placeholder; derive the initial label from the state owner or use a native control when that behavior is not acceptable.

```tsx
function StatusPicker() {
  const [status, setStatus] = useState<string | null>(null);
  return (
    <Select value={status} onChange={setStatus} label="Status">
      <Select.Trigger />
      <Select.Options>
        <Select.Option value="open">Open</Select.Option>
        <Select.Option value="closed">Closed</Select.Option>
      </Select.Options>
    </Select>
  );
}
```

### 4. Form Field Compound Component

```typescript
import type { InputHTMLAttributes, ReactNode } from 'react';
import { createContext, useContext, useId, useMemo } from 'react';

// ─── Context ─────────────────────────────────────────────────

interface FormFieldContextType {
  id: string;
  name: string;
  label: string;
  error: string | undefined;
  isRequired: boolean;
}

const FormFieldContext = createContext<FormFieldContextType | null>(null);

const useFormField = () => {
  const context = useContext(FormFieldContext);
  if (!context) throw new Error('Must be inside FormField');
  return context;
};

// ─── FormField Parent ────────────────────────────────────────

interface FormFieldProps {
  name: string;
  label: string;
  error?: string | undefined;
  required?: boolean;
  children: ReactNode;
}

const FormFieldRoot = ({ name, label, error, required = false, children }: FormFieldProps) => {
  const id = useId();

  const value = useMemo(() => ({
    id,
    name,
    label,
    error,
    isRequired: required,
  }), [id, name, label, error, required]);

  return (
    <FormFieldContext.Provider value={value}>
      <div className="form-field">
        {children}
      </div>
    </FormFieldContext.Provider>
  );
};

// ─── FormField.Label ─────────────────────────────────────────

const Label = ({ children }: { children?: ReactNode }) => {
  const { id, label, isRequired } = useFormField();
  return (
    <label htmlFor={id} className="form-label">
      {children ?? label}
      {isRequired && <span className="required">*</span>}
    </label>
  );
};

// ─── FormField.Input ─────────────────────────────────────────

type InputProps = InputHTMLAttributes<HTMLInputElement>;

const Input = (props: InputProps) => {
  const { id, name, error, isRequired } = useFormField();
  const describedBy = [props['aria-describedby'], error ? `${id}-error` : undefined]
    .filter(Boolean)
    .join(' ') || undefined;
  return (
    <input
      {...props}
      id={id}
      required={isRequired}
      name={name}
      className={['form-input', error ? 'form-input--error' : '', props.className].filter(Boolean).join(' ')}
      aria-invalid={error ? true : props['aria-invalid']}
      aria-describedby={describedBy}
    />
  );
};

// ─── FormField.Error ─────────────────────────────────────────

const ErrorMessage = () => {
  const { id, error } = useFormField();
  if (!error) return null;

  return (
    <p id={`${id}-error`} className="form-error" role="alert">
      {error}
    </p>
  );
};

const FormField = Object.assign(FormFieldRoot, {
  Label,
  Input,
  Error: ErrorMessage,
});

// ─── Usage ───────────────────────────────────────────────────

const SignupForm = () => (
  <form>
    <FormField name="email" label="Email" required error={errors.email}>
      <FormField.Label />
      <FormField.Input type="email" placeholder="Enter email" />
      <FormField.Error />
    </FormField>

    <FormField name="password" label="Password" required>
      <FormField.Label />
      <FormField.Input type="password" />
      <FormField.Error />
    </FormField>
  </form>
);
```

### 5. TypeScript Generics with Compound Components

A global `createContext<ListContextType<any>>` erases the item type: `<List<User>>` does not specialize `<List.Items>` through JSX. A factory fixes the type before creating the parent/child API:

```tsx
import type { Key, ReactNode } from 'react';
import { createContext, useContext, useState, useMemo } from 'react';

function createList<T>() {
  type State = {
    items: T[];
    selected: T | null;
    select: (item: T) => void;
    renderItem: (item: T) => ReactNode;
    getKey: (item: T) => Key;
  };
  const Context = createContext<State | null>(null);
  const useList = () => {
    const value = useContext(Context);
    if (!value) throw new Error('List children require their matching List parent');
    return value;
  };

  function Root({ children, items, renderItem, getKey }: {
    children: ReactNode;
    items: T[];
    renderItem: State['renderItem'];
    getKey: State['getKey'];
  }) {
    const [selected, select] = useState<T | null>(null);
    const value = useMemo(
      () => ({ items, selected, select, renderItem, getKey }),
      [items, selected, renderItem, getKey]
    );
    return <Context.Provider value={value}>{children}</Context.Provider>;
  }

  function Items() {
    const { items, select, renderItem, getKey } = useList();
    return <ul>{items.map(item => (
      <li key={getKey(item)}><button type="button" onClick={() => select(item)}>
        {renderItem(item)}
      </button></li>
    ))}</ul>;
  }

  function Selected() {
    const { selected, renderItem } = useList();
    return selected !== null ? <div>{renderItem(selected)}</div> : null;
  }

  return Object.assign(Root, { Items, Selected });
}

// Create once at module scope, not during render (which would reset identity).
const NumberList = createList<number>();
```

`selected !== null` deliberately keeps a selected value of `0` visible. For replaceable object items, retaining the object itself can leave a stale or removed selection; store its stable key and derive the current item when that is the required lifetime policy. Each factory call creates a distinct context, while each mounted parent has its own selection state.

## Where this pattern fits

Tabs, accordions, menus, and form fields are natural candidates when their parts coordinate through shared state. A native `<select>` is often better than a custom compound select when the product does not need custom interaction or layout; a custom choice control must implement its own keyboard, focus, and selection contract.

## Common Mistakes

### 1. Not Providing Error Messages for Missing Context

```tsx
import { createContext, useContext } from 'react';

const TabsContext = createContext<{ activeIndex: number } | null>(null);

// BAD: silently returns null outside the matching provider
const useTabsUnsafe = () => useContext(TabsContext);

// GOOD: Throw descriptive error
const useTabs = () => {
  const ctx = useContext(TabsContext);
  if (!ctx) throw new Error('Tabs.* components must be rendered inside a <Tabs> component');
  return ctx;
};
```

### 2. Assuming Child Cloning Is Transparent

```tsx
import { Children, cloneElement, isValidElement, type ReactNode } from 'react';

// Fragile for an API that promises arbitrary wrapper composition
const Tabs = ({ children }: { children: ReactNode }) => (
  <div>
    {Children.map(children, (child, index) => {
      if (!isValidElement<{ index?: number }>(child)) return child;
      return cloneElement(child, { index });
    })}
  </div>
);

// For context-based sharing, reuse the Tabs parent in example 1.
```

### 3. Treating memoization as a correctness requirement

```tsx
import type { ReactNode } from 'react';
import { createContext, useMemo } from 'react';

interface TabsContextValue {
  activeIndex: number;
  setActiveIndex: (index: number) => void;
}

const TabsContext = createContext<TabsContextValue | null>(null);

function UnmemoizedProvider({ activeIndex, setActiveIndex, children }: TabsContextValue & { children: ReactNode }) {
  return (
    <TabsContext.Provider value={{ activeIndex, setActiveIndex }}>
      {children}
    </TabsContext.Provider>
  );
}

function StableProvider({ activeIndex, setActiveIndex, children }: TabsContextValue & { children: ReactNode }) {
  // Stable identity avoids a context notification when dependencies are unchanged.
  const value = useMemo(() => ({ activeIndex, setActiveIndex }), [activeIndex, setActiveIndex]);
  return <TabsContext.Provider value={value}>{children}</TabsContext.Provider>;
}
```

## Best Practices

1. **Guard the owner contract** — Throw a clear error when a child is outside its matching parent
2. **Define child rules** — Specify required parts, duplicate behavior, ordering, and what removal does to selection
3. **Keep Context focused** — Share only the state and actions the parts need; split unrelated update domains
4. **Type the public API** — Use `Object.assign(Root, { Child })` so TypeScript exposes namespaced children; use a factory when a generic family needs a fixed item type
5. **Keep identity stable** — Prefer stable domain IDs when children can be reordered or removed
6. **Document accessibility behavior** — State which keyboard, focus, label, and error relationships are implemented
7. **Memoize only for observed identity** — A stable provider value avoids redundant context notifications; changed shared state still notifies consumers

## Performance Considerations

| Aspect | Impact | Mitigation |
| ---------------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Context updates | Subscribed consumers observe the changed value | Split independent contexts; prop memoization cannot block consumed context |
| Many compound children | Render and DOM work depend on workload | Measure first; virtualize only with a valid focus/accessibility policy |
| Deeply nested context | Provider scope controls which owner a child reads | Choose props or context by the needed public composition contract |
| `React.Children` | Direct-child assumptions and injected props | `cloneElement` returns a new element and preserves the existing ref unless a replacement ref is supplied |

## Summary

Compound components trade an explicit data prop for a coordinated set of children that share a state contract. They fit when callers need structural flexibility; simple data-driven or native controls are often easier to maintain. Define selection and unmount behavior, preserve label/control relationships, and implement the promised keyboard and focus behavior.

# Web Components

> **Custom Elements, Shadow DOM, and HTML Templates — native browser component system.**

---

## What Are Web Components?

Web Components are native browser features that let you create reusable, encapsulated HTML elements. Unlike React components (framework-specific), Web Components work everywhere — React, Vue, Angular, or plain HTML.

```
Web Components = Custom Elements + Shadow DOM + HTML Templates
```

| Feature | What It Does | Browser Support |
|---------|--------------|-----------------|
| **Custom Elements** | Define new HTML tags | All modern browsers |
| **Shadow DOM** | Encapsulated DOM and styles | All modern browsers |
| **HTML Templates** | Reusable markup fragments | All modern browsers |

## Custom Elements

```typescript
// Define a custom element
class PatientCard extends HTMLElement {
  constructor() {
    super();
    // Attach shadow DOM for encapsulation
    this.attachShadow({ mode: 'open' });
  }

  connectedCallback() {
    const name = this.getAttribute('name') || 'Unknown';
    const email = this.getAttribute('email') || '';

    this.shadowRoot!.innerHTML = `
      <style>
        .card {
          border: 1px solid #e0e0e0;
          border-radius: 8px;
          padding: 16px;
          font-family: system-ui;
        }
        .name { font-weight: 600; font-size: 1.1rem; }
        .email { color: #666; }
      </style>
      <div class="card">
        <div class="name">${name}</div>
        <div class="email">${email}</div>
        <slot></slot>
      </div>
    `;
  }

  // React to attribute changes
  static get observedAttributes() {
    return ['name', 'email'];
  }

  attributeChangedCallback(name: string, oldVal: string, newVal: string) {
    if (oldVal !== newVal) {
      this.connectedCallback(); // Re-render
    }
  }
}

// Register the custom element
customElements.define('patient-card', PatientCard);
```

```html
<!-- Use in HTML -->
<patient-card name="Maria Schmidt" email="maria@example.com">
  <p>Appointment: 2026-08-25</p>
</patient-card>
```

## Shadow DOM

Shadow DOM provides style and DOM encapsulation — styles inside don't leak out, and external styles don't affect the inside.

```typescript
class StyledButton extends HTMLElement {
  constructor() {
    super();
    this.attachShadow({ mode: 'open' });
  }

  connectedCallback() {
    this.shadowRoot!.innerHTML = `
      <style>
        /* This style ONLY affects this component */
        button {
          background: var(--btn-bg, #3b82f6);
          color: white;
          border: none;
          padding: 8px 16px;
          border-radius: 4px;
          cursor: pointer;
        }
        button:hover {
          background: var(--btn-hover, #2563eb);
        }
      </style>
      <button><slot></slot></button>
    `;
  }
}

customElements.define('styled-button', StyledButton);
```

### Shadow DOM Encapsulation

```css
/* External styles DON'T affect shadow DOM */
styled-button button {
  background: red; /* This won't work! */
}

/* Use CSS custom properties (they DO pierce shadow DOM) */
styled-button {
  --btn-bg: #10b981; /* This works! */
}
```

## HTML Templates

```html
<template id="patient-row">
  <tr>
    <td class="name"></td>
    <td class="email"></td>
    <td class="status"></td>
  </tr>
</template>

<script>
  const template = document.getElementById('patient-row');
  const clone = template.content.cloneNode(true);

  clone.querySelector('.name').textContent = 'Maria Schmidt';
  clone.querySelector('.email').textContent = 'maria@example.com';
  clone.querySelector('.status').textContent = 'Active';

  document.querySelector('tbody').appendChild(clone);
</script>
```

## Web Components vs React

| Feature | Web Components | React |
|---------|---------------|-------|
| **Encapsulation** | Shadow DOM (native) | Scoped CSS (tools) |
| **Re-rendering** | Manual (attributeChangedCallback) | Automatic (state change) |
| **Framework** | Framework-agnostic | React-specific |
| **Bundle size** | 0KB (native) | ~40KB (React runtime) |
| **Server rendering** | Custom Elements API | SSR/SSG |
| **Ecosystem** | Limited | Vast |

## When to Use Web Components

| Scenario | Recommendation |
|----------|---------------|
| **Design system shared across frameworks** | Web Components |
| **Widget embedded in third-party sites** | Web Components |
| **React-only application** | Use React components |
| **Need hot module replacement** | Use React components |
| **Healthcare app (Docita)** | React for app, Web Components for embeddable widgets |

---

## Interview Questions

**Q: "When would you use Web Components over React?"**

> Web Components when: (1) building a design system used by multiple frameworks (React + Vue + Angular teams), (2) creating embeddable widgets for third-party sites (payment form, chat widget), (3) need zero-dependency components (no React runtime). React when: (1) building a full application with complex state management, (2) need hot module replacement, (3) want access to the React ecosystem. For Docita: React for the main app, Web Components for the embeddable appointment booking widget that clinics can add to their websites.

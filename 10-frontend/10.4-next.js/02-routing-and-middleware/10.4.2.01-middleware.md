# Proxy (formerly Middleware) in Next.js

## Definition

In Next.js 16, **Proxy** is a request-interception function that runs before route rendering. It can redirect, rewrite, modify request or response headers, set cookies, or return a response. Next.js 15 uses the `middleware.ts` convention; the function is renamed and the convention deprecated in Next.js 16.

> **Textbook Definition:** Proxy is a pre-route request boundary that can continue, redirect, rewrite, or answer a request before its destination runs. It can make an early routing decision, but it does not replace authorization at the protected data read or mutation.


## First Principles

Proxy exists for decisions that must happen before the destination route runs:

1. **A matched request waits for the decision:** Proxy adds work before the route. Keep it bounded; slow data access belongs in the route or service that owns it.
2. **It cannot inspect rendered page output:** return a redirect, rewrite, response or continue signal. Work that depends on the completed response belongs after rendering or at the hosting layer.

## Why It Matters

Use Proxy for cheap request routing such as a redirect, rewrite, locale choice, or experiment assignment. A cookie check may improve navigation, but every protected operation still verifies the session and resource permission. Next.js 15 Middleware defaults to Edge and can opt into Node.js from 15.5; Next.js 16 Proxy defaults to Node.js and rejects a `runtime` setting. Neither a runtime label nor a nearby deployment guarantees low latency.

## How It Works

**Version scope:** Code examples use the current Next.js 16 `proxy.ts` / `export function proxy` convention. Next.js 15 uses `middleware.ts` / `export function middleware`, defaults to Edge, and supports Node.js with `config.runtime: 'nodejs'` from 15.5. In Next.js 16 the old convention is deprecated; Proxy defaults to Node.js and has no `runtime` option. Runtime support and actual geographic placement are separate choices.

Match static literal paths in `config.matcher`; it is analyzed at build time. Match path segments (`pathname === route || pathname.startsWith(route + '/')`) rather than raw prefixes so `/admin-tools` does not accidentally match `/admin`. Forwarded headers are trustworthy only when trusted ingress overwrites caller-supplied values. `NextRequest.geo` was removed in Next.js 15; use your hosting provider's documented location headers.

Next.js applies configured headers and redirects before Proxy, then evaluates Proxy before filesystem routes and later rewrite phases. Prefer `next.config` redirects for fixed path maps; use Proxy when the decision needs request data. This ordering does not make a Proxy check authoritative for a later data read or mutation.

The in-memory rate-limit example is a single-process demonstration: instances do not share its counters and entries need eviction. Production enforcement needs a shared atomic store and a trusted, normalized client-IP source.

### Trace routing before the destination runs

```text
Request / → matcher → assign variant b → rewrite to /variant-b
Browser address stays /; returned rewrite response also sets variant cookie
Next request / → saved b → same destination (unless the experiment changes)
```

A **redirect** tells the browser to request another URL; its address changes. A **rewrite** selects a different internal destination while preserving the visible URL. `NextResponse.next()` continues the current route. Response headers go to the browser; forwarded request headers go to the destination handler. An early gate cannot inspect HTML that has not rendered yet.

These decisions add work before the matched destination. Geographic placement and cold-start latency depend on the host and runtime; Edge is not a universal speed guarantee. API handlers own bodies and response semantics, while Server Components own UI output.

## Code Examples

### Basic Proxy

```typescript
// proxy.ts (at the same level as app/ or pages/)
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  // Add custom header
  const response = NextResponse.next()
  response.headers.set('x-custom-header', 'my-value')

  return response
}

// Only run on specific paths
export const config = {
  matcher: '/dashboard/:path*',
}

```

### Authentication Redirects

> The full cookie-presence redirect example lives in [Authentication](../04-production/10.4.4.01-authentication.md#1-proxy-for-early-redirects). It is an optimistic UX gate: validate session signature/expiry and resource permissions at the data-access layer. A forged or expired cookie must not grant access or create a login/dashboard redirect loop.

### Role-Based Access Control

> JWT validation and route-role checks live in [Authentication](../04-production/10.4.4.01-authentication.md#6-role-based-access-control). If you pass verified identity downstream, clone `request.headers`, overwrite the identity fields, and pass them through `NextResponse.next({ request: { headers } })`; setting `response.headers` only sends them to the browser. Routes must still enforce authorization themselves.

### A/B Testing Proxy

```typescript
// proxy.ts — Next.js 16 (Next.js 15 used middleware.ts / middleware)
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const saved = request.cookies.get('ab-variant')?.value
  const variant = saved === 'a' || saved === 'b' ? saved : Math.random() > 0.5 ? 'a' : 'b'
  const response = request.nextUrl.pathname === '/'
    ? NextResponse.rewrite(new URL(`/variant-${variant}`, request.url))
    : NextResponse.next()

  response.cookies.set('ab-variant', variant, {
    httpOnly: true, secure: true, sameSite: 'lax', path: '/',
    maxAge: 60 * 60 * 24 * 30,
  })
  return response
}
```

The cookie must be attached to the actual rewrite response. Setting it on one response and returning a newly created response discards the cookie; validating the saved variant also prevents a visitor from selecting an unintended rewrite target.

### Geographic Routing

```typescript
// proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  // Vercel supplies these headers; other hosts require their own trusted source.
  const country = request.headers.get('x-vercel-ip-country') || 'US'
  const city = request.headers.get('x-vercel-ip-city') || 'Unknown'

  const { pathname } = request.nextUrl
  const locale = country === 'DE' ? 'de' : country === 'JP' ? 'ja' : null
  const localized = /^\/(de|ja)(?:\/|$)/.test(pathname)
  const destination = request.nextUrl.clone()
  if (locale && !localized) destination.pathname = `/${locale}${pathname}`

  // Set headers on the response that will actually be returned.
  const response = locale && !localized
    ? NextResponse.redirect(destination)
    : NextResponse.next()
  response.headers.set('x-country', country)
  response.headers.set('x-city', city)

  return response
}

```

### URL Rewriting

```typescript
// proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl

  // Rewrite /blog/:slug to /posts/:slug
  if (pathname.startsWith('/blog/')) {
    const slug = pathname.replace('/blog/', '')
    const rewriteUrl = request.nextUrl.clone()
    rewriteUrl.pathname = `/posts/${slug}`
    return NextResponse.rewrite(rewriteUrl)
  }

  // Rewrite API versioning
  if (pathname.startsWith('/api/v1/')) {
    const newPath = pathname.replace('/api/v1/', '/api/')
    const rewriteUrl = request.nextUrl.clone()
    rewriteUrl.pathname = newPath
    return NextResponse.rewrite(rewriteUrl)
  }

  return NextResponse.next()
}

```

Cloning the URL preserves query parameters such as pagination; constructing a path-only URL would discard them. Define whether the destination expects an encoded segment or a nested path before rewriting arbitrary user input.

### Bot Detection

```typescript
// proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const userAgent = request.headers.get('user-agent') || ''

  const botPatterns = [
    /googlebot/i,
    /bingbot/i,
    /slurp/i,
    /duckduckbot/i,
    /baiduspider/i,
  ]

  const isBot = botPatterns.some(pattern => pattern.test(userAgent))

  const response = NextResponse.next()

  if (isBot) {
    // Mark the response for diagnostics; this does not change rendering
    response.headers.set('x-is-bot', 'true')
  } else {
    response.headers.set('x-is-bot', 'false')
  }

  return response
}

```

User-agent strings are caller-controlled. These patterns are diagnostic hints, not verified crawler identity or an authorization decision.

### Rate Limiting Boundary

The in-memory sketch below illustrates fixed-window decisions only. It is not a production limiter: process restarts and replicas reset or split counters, and high-cardinality keys need eviction. Next recommends using Proxy sparingly; enforce limits at a gateway or an atomic shared store, with a host-verified client identity and an explicit failure policy. `trustedClientIp` is an application adapter, not a Next.js API.

```typescript
// proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

const rateLimit = new Map<string, { count: number; timestamp: number }>()

const WINDOW_MS = 60 * 1000 // 1 minute
const MAX_REQUESTS = 100

export function proxy(request: NextRequest) {
  const ip = trustedClientIp(request) // Host-specific adapter; overwrites untrusted input
  const now = Date.now()

  const record = rateLimit.get(ip)

  if (!record || now - record.timestamp >= WINDOW_MS) {
    rateLimit.set(ip, { count: 1, timestamp: now })
    return NextResponse.next()
  }

  if (record.count >= MAX_REQUESTS) {
    return NextResponse.json(
      { error: 'Too many requests' },
      { status: 429, headers: { 'Retry-After': String(Math.ceil((WINDOW_MS - (now - record.timestamp)) / 1000)) } }
    )
  }

  record.count++
  return NextResponse.next()
}

```

Requests 1–100 within one window pass; request 101 returns 429 without incrementing the count. At the window boundary, the first request starts a new record. This fixed-window scheme can permit a burst across adjacent windows; the shared-store implementation must preserve atomic increments and expiry. `trustedClientIp` must define the host trust boundary—using an arbitrary forwarded-header string lets callers evade limits, while one `unknown` key unfairly groups users.

### Header Manipulation

```typescript
// proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  const response = NextResponse.next()

  // Security headers
  response.headers.set('X-Frame-Options', 'DENY')
  response.headers.set('X-Content-Type-Options', 'nosniff')
  response.headers.set('Referrer-Policy', 'origin-when-cross-origin')
  response.headers.set(
    'Permissions-Policy',
    'camera=(), microphone=(), geolocation=()'
  )

  // Only use immutable caching for content-versioned assets
  if (request.nextUrl.pathname.startsWith('/static/versioned/')) {
    response.headers.set(
      'Cache-Control',
      'public, max-age=31536000, immutable'
    )
  }

  // CORS headers for API routes
  if (request.nextUrl.pathname.startsWith('/api/')) {
    response.headers.set('Access-Control-Allow-Origin', '*')
    response.headers.set('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE')
  }

  return response
}

```

The CORS header sketch is for public non-credentialed responses only. It does not answer preflight requests or authorize mutations; use the [Route Handler CORS example](10.4.2.02-route-handlers.md#5-not-handling-cors) for the endpoint policy. Set caching only on truly content-versioned public assets, and verify whether the host overwrites these headers.

### Cookie Handling

```typescript
// proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  // Read cookies
  const session = request.cookies.get('session')?.value
  const preferences = request.cookies.get('preferences')?.value

  const response = NextResponse.next()

  // Set cookies
  response.cookies.set('last-visit', new Date().toISOString(), {
    httpOnly: true,
    secure: true,
    sameSite: 'lax',
    maxAge: 60 * 60 * 24 * 365, // 1 year
  })

  // Delete cookies
  if (request.nextUrl.pathname === '/logout') {
    response.cookies.delete('session')
    response.cookies.delete('preferences')
  }

  // Treat cookie JSON as untrusted input; retain only the expected preference.
  if (preferences && preferences.length <= 1024) {
    try {
      const parsed = JSON.parse(preferences)
      if (parsed && (parsed.theme === 'light' || parsed.theme === 'dark')) {
        response.cookies.set('preferences', JSON.stringify({
          theme: parsed.theme, lastPage: request.nextUrl.pathname,
        }), { httpOnly: true, secure: true, sameSite: 'lax', path: '/' })
      }
    } catch { /* Ignore a malformed preference rather than breaking the route. */ }
  }

  return response
}

```

### Conditional Proxy Logic

```typescript
// proxy.ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'

export function proxy(request: NextRequest) {
  // Skip middleware for static files
  if (request.nextUrl.pathname === '/_next' || request.nextUrl.pathname.startsWith('/_next/')) {
    return NextResponse.next()
  }

  // Skip for API routes
  if (request.nextUrl.pathname === '/api' || request.nextUrl.pathname.startsWith('/api/')) {
    return NextResponse.next()
  }

  // Only run in production
  if (process.env.NODE_ENV === 'development') {
    return NextResponse.next()
  }

  // Production middleware logic
  return NextResponse.next()
}

export const config = {
  matcher: [
    // Match all paths except:
    '/((?!_next/static|_next/image|favicon.ico).*)',
  ],
}

```

### Composing Proxy Helpers

Compose one entry point from small helpers. A helper can return `null` to continue or a complete response to stop, avoiding brittle tests such as `status !== 200` for `NextResponse.next()`. Preserve accumulated headers/cookies on the final response; the [rate-limit example](#rate-limiting-boundary) shows only the fixed-window decision, not a production storage design.

```typescript
// proxy.ts — helpers return a response or null to continue
export async function proxy(request: NextRequest) {
  const blocked = await enforceRateLimit(request)
  if (blocked) return blocked
  const authFailure = await enforceSessionForProtectedPath(request)
  if (authFailure) return authFailure
  return NextResponse.next()
}
```

## Real-World Use Cases

| Use Case | Implementation |
| ------------------ | --------------------------------------------------------------------------------------- |
| Authentication UX | Redirect a likely unauthenticated visitor; authorize again at the protected operation |
| A/B Testing | Assign variants via cookies |
| Geographic routing | Redirect based on country |
| Bot detection | Classify user agents; headers alone do not change content |
| Rate limiting | Prefer a gateway or shared atomic limiter; process-local counters are illustrative only |
| Redirects | URL-based redirects |
| Rewrites | Internal URL mapping |
| Security headers | Set selected response headers; centralize policy where possible |
| Feature flags | Enable/disable features by path |
| Maintenance mode | Redirect all traffic during maintenance |

## Common Mistakes

### 1. Assuming the runtime is the same across versions

```typescript
// Next.js 15 middleware.ts defaults to Edge; Node APIs are unavailable there.
import fs from 'fs'
import { db } from './database'

export function middleware(request: NextRequest) {
  const data = fs.readFileSync('file.txt') // Error!
  const user = db.user.findFirst() // Driver compatibility depends on runtime
  return NextResponse.next()
}

// Next.js 16 proxy.ts defaults to Node.js; its `runtime` option is not supported.
export function proxy(request: NextRequest) {
  const token = request.cookies.get('token') // OK
  const country = request.headers.get('x-vercel-ip-country') // Vercel-specific
  return NextResponse.next()
}

```

### 2. Not Matching All Required Paths

```typescript
// BAD: Only matches the exact /dashboard path.
export const config = {
  matcher: '/dashboard',
}

// GOOD: Match /dashboard and its nested paths.
export const config = {
  matcher: '/dashboard/:path*',
}

```

### 3. Infinite Redirects

```typescript
// BAD: Redirect loop
export function proxy(request: NextRequest) {
  if (!request.cookies.get('token')) {
    return NextResponse.redirect(new URL('/login', request.url))
  }
  // Login page might also trigger middleware
  return NextResponse.next()
}

// GOOD: Exclude auth pages from middleware
export const config = {
  matcher: ['/dashboard/:path*', '/settings/:path*'],
}

```

### 4. Treating a Token Check as the Whole Authorization Boundary

JWT verification needs the appropriate runtime-compatible library, a configured key and allowed algorithms, issuer/audience checks and expiry handling. A missing or invalid token can produce an early login redirect; valid identity still needs resource authorization in the route or data layer. Use the [canonical authentication example](../04-production/10.4.4.01-authentication.md#6-role-based-access-control), and verify the protected operation directly as well as through the normal page flow.

### 5. Modifying Request Body

`Request.body` is a readable stream, not an assignable property. Middleware can inspect a cloned request body when supported, but consuming the original stream may prevent the endpoint from reading it and large uploads add memory/latency. Parse, validate, and transform payloads in the [Route Handler](10.4.2.02-route-handlers.md) that owns them.

## Best Practices

1. **Use Proxy sparingly.** Prefer static `next.config` redirects and route-local logic when they fit.
2. **Match dependencies to the versioned runtime.** Next.js 15 Edge Middleware and Next.js 16 Node Proxy have different constraints.
3. **Keep matchers narrow and test the boundaries.** Include prefetch, API, data, static and direct-navigation cases that matter.
4. **Keep authorization authoritative at the data boundary.** Proxy may improve navigation but cannot protect a service called another way.
5. **Forward only trusted context.** Overwrite caller-supplied headers and never send secrets to the browser.
6. **Measure pre-route latency and failure behavior.** A slow shared-store lookup or unavailable dependency affects every matched request.

## Performance Considerations

Proxy adds work before matched routes. Measure its latency on the actual host, especially cold starts and shared-store calls. Fixed redirects belong in `next.config`; specific matchers reduce unnecessary invocation. A module-global variable is not shared state across processes and cannot provide durable assignments or rate limits.

## Summary

| Feature | Proxy (Next.js 16) |
| ------------- | --------------------------------------------------------------------------- |
| Location | `proxy.ts` beside `app/` or `pages/` |
| Runtime | Node.js by default; `runtime` config is unsupported |
| Previous name | Next.js 15 `middleware.ts`; Edge by default, Node stable from 15.5 |
| When | Before page rendering |
| Can do | Redirect, rewrite, headers, cookies |
| Constraints | Do not rely on shared render globals; body handling belongs at its endpoint |
| Use case | Cheap routing decisions, not authoritative authorization |
| Performance | Adds pre-route work to matched requests; measure on the chosen host |

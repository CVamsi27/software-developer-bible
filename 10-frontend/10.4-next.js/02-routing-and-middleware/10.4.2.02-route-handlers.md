# Route Handlers in Next.js

When a payment provider sends a webhook, the server must verify the exact request body and return an HTTP status the provider can act on. A Next.js App Router **Route Handler** gives that request a method-specific owner; the same mechanism can serve an API, file upload or event stream.

```typescript
// app/api/users/[id]/route.ts
import { NextResponse } from 'next/server';

export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  await requireUserReadAccess(request, id); // authorize first
  const user = await db.user.findUnique({ where: { id }, select: { id: true, name: true } });
  if (!user) return NextResponse.json({ error: 'User not found' }, { status: 404 });
  return NextResponse.json(user, { headers: { 'Cache-Control': 'private, no-store' } });
}
```

## Definition

**Route Handlers** expose HTTP methods from `route.ts` files in the App Router. They use the Web `Request` and `Response` APIs to return JSON, streams, files or other non-UI responses. Pages Router API Routes remain a separate, supported `req`/`res` interface.

> **Textbook Definition:** A Route Handler implements an HTTP method at a filesystem route using request and response APIs. It owns status, headers and body semantics and must enforce validation, authorization and caching policy for its endpoint.

## First Principles

Route Handlers are the application's HTTP surface inside the framework. **The handler owns its HTTP contract**: Next selects the method and route, but the application owns status, headers, body validation, and authorization. **Caching is a policy decision**: a GET response is never automatically safe to share — cache only data whose identity, freshness, and invalidation rules are explicit. Reach for a Route Handler when an external caller needs an HTTP contract; use a Server Function for a server mutation owned by your React UI.

## 1. Follow the Request into Its HTTP Response

**Version scope:** Examples use Next.js 16 and Promise-based `params`. Recommended `create-next-app` defaults enable Cache Components and Partial Prefetching; in existing or manual apps, enable `cacheComponents: true` and `partialPrefetching: true` explicitly.

Without Cache Components, a `GET` handler is uncached by default; a safe public response can opt into the previous route-cache model. With Cache Components, a `GET` handler can be prerendered when it needs no request-time data, and reusable external or database reads belong in a `use cache` helper. Request-specific values stay dynamic.

`Cache-Control` independently controls browser and CDN reuse; personalized responses should usually be `private, no-store`. Cache Components requires Node.js.

A `route.ts` can sit in any app segment, but cannot share the same route with `page.tsx`. A request body is a one-use stream: verify webhook signatures against raw text before parsing. Bound the query pagination and validate it before using an ORM offset; use cursors for deep result sets.

Cookie-authenticated handlers should set or clear cookies on the response they return, revoke the server-side session on logout, and apply a CSRF policy to mutations. `HttpOnly`, `Secure`, and `SameSite` reduce exposure but do not replace session validation or resource authorization. For browser requests, same-origin defaults are simplest; cross-origin credentials require an explicit origin and credential policy.

```text
GET /api/users/42 → app/api/users/[id]/route.ts → GET export
                 → await params → authorize read → load user → JSON + status
```

The segment supplies `id="42"`; it does not prove that the visitor may read user 42. The handler can return 404 for a missing user, use the application's disclosure policy for denied access, and treat an upstream failure as a different outcome. Exporting `GET` does not make a response cacheable or make a POST valid.

App Router handlers use Web request/response APIs. Pages Router API routes use `req`/`res`; both remain supported, and both depend on their chosen host's runtime, duration and streaming capabilities.

Next.js generates a `RouteContext<'/api/users/[id]'>` helper for typed route params during development, build or type generation. The explicit Promise type below makes the runtime shape visible; the generated helper keeps a larger app's signature aligned with its route.

## 2. Dynamic Routes and Query Params

```typescript
// app/api/users/[id]/route.ts
import { NextRequest, NextResponse } from 'next/server'

export async function GET(
  request: NextRequest,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params

  await requireUserReadAccess(request, id) // Application adapter; map denial to HTTP policy
  const user = await db.user.findUnique({
    where: { id },
    select: { id: true, name: true }, // Only fields safe for this caller
  })

  if (!user) {
    return NextResponse.json(
      { error: 'User not found' },
      { status: 404, headers: { 'Cache-Control': 'private, no-store' } }
    )
  }

  return NextResponse.json(user, {
    headers: { 'Cache-Control': 'private, no-store' },
  })
}

```

For a protected update, parse a narrow schema into an allowlist of editable fields, authorize the session against this user, and handle missing/concurrent records explicitly. Never pass the whole request JSON to `db.user.update`: a visitor could supply fields such as roles or tenant IDs. Deletes need the same resource authorization; define whether repeated deletion is a successful no-op or a 404. The database module and access checks are application adapters.

```typescript
// app/api/search/route.ts
import { NextRequest, NextResponse } from 'next/server'

export async function GET(request: NextRequest) {
  const searchParams = request.nextUrl.searchParams
  const query = searchParams.get('q')?.trim()
  const page = Number(searchParams.get('page') ?? '1')
  const limit = Number(searchParams.get('limit') ?? '10')
  if (!Number.isSafeInteger(page) || page < 1 || !Number.isSafeInteger(limit) || limit < 1 || limit > 100 ||
      !Number.isSafeInteger((page - 1) * limit)) {
    return NextResponse.json({ error: 'Invalid pagination' }, { status: 400 })
  }

  if (!query || query.length > 200) {
    return NextResponse.json(
      { error: 'Query must contain 1–200 characters' },
      { status: 400 }
    )
  }

  const results = await db.post.findMany({
    where: {
      title: { contains: query },
    },
    skip: (page - 1) * limit,
    take: limit,
  })

  return NextResponse.json({
    results,
    page,
    limit,
    total: await db.post.count({
      where: { title: { contains: query } },
    }),
  })
}

```

This search sketch assumes public posts. Add tenant/publication filters where required. A bounded page size does not bound a very large offset or the count query cost; enforce a product-specific maximum page or use cursor pagination for deep result sets. The count and rows are separate reads and may reflect different concurrent snapshots.

Map malformed input to a client error and unexpected failures to a stable server error; log details server-side without returning stack traces. Parse into an allowlist before calling the ORM, then authorize the requested resource as well as the caller's identity.

## 3. Streaming Responses

```typescript
// app/api/stream/route.ts
export async function GET() {
  const encoder = new TextEncoder()

  let count = 0
  let timer: ReturnType<typeof setInterval> | undefined
  const stop = () => { if (timer !== undefined) clearInterval(timer) }
  const stream = new ReadableStream<Uint8Array>({
    start(controller) {
      timer = setInterval(() => {
        controller.enqueue(encoder.encode(`data: ${JSON.stringify({ count })}\n\n`))
        count += 1
        if (count === 10) { stop(); controller.close() }
      }, 1000)
    },
    cancel() { stop() }, // A disconnected consumer must not keep the producer running.
  })

  return new Response(stream, {
    headers: {
      'Content-Type': 'text/event-stream',
      'Cache-Control': 'no-cache',
    },
  })
}

```

These frames use the Server-Sent Events protocol, but the sketch has no durable IDs/replay, heartbeat or upstream error mapping. Cancellation stops the local producer; buffering and connection duration depend on the proxy/host. A cookie-authenticated stream still needs access checks before returning its body.

## 4. Webhooks: Verify Before Parsing

```typescript
// app/api/webhooks/stripe/route.ts
import { NextRequest, NextResponse } from 'next/server'
import Stripe from 'stripe'

const stripe = new Stripe(process.env.STRIPE_SECRET_KEY!)

export async function POST(request: NextRequest) {
  const body = await request.text()
  const sig = request.headers.get('stripe-signature')
  if (!sig) {
    return NextResponse.json({ error: 'Missing signature' }, { status: 400 })
  }

  let event: Stripe.Event

  try {
    event = stripe.webhooks.constructEvent(
      body,
      sig,
      process.env.STRIPE_WEBHOOK_SECRET!
    )
  } catch {
    return NextResponse.json(
      { error: 'Webhook signature verification failed' },
      { status: 400 }
    )
  }

  switch (event.type) {
    case 'payment_intent.succeeded':
      const paymentIntent = event.data.object as Stripe.PaymentIntent
      await handlePaymentSuccess(paymentIntent)
      break
    case 'payment_intent.payment_failed':
      const failedPayment = event.data.object as Stripe.PaymentIntent
      await handlePaymentFailure(failedPayment)
      break
  }

  return NextResponse.json({ received: true })
}

```

Successful signature verification does not make event delivery unique or ordered. `handlePaymentSuccess` and `handlePaymentFailure` must durably deduplicate event IDs and apply state transitions transactionally. Return success after durable acceptance; retryable processing failures must not be acknowledged as completed.

## 5. File Uploads

```typescript
// app/api/upload/route.ts
import { NextRequest, NextResponse } from 'next/server'
import { put } from '@vercel/blob'

export async function POST(request: NextRequest) {
  await requireUploadPermission(request) // Authenticate/authorize before buffering
  const formData = await request.formData()
  const file = formData.get('file')

  if (!(file instanceof File)) {
    return NextResponse.json(
      { error: 'No file provided' },
      { status: 400 }
    )
  }

  if (file.size > 5 * 1024 * 1024 || !['image/png', 'image/jpeg'].includes(file.type)) {
    return NextResponse.json({ error: 'Unsupported image or size' }, { status: 400 })
  }
  // Extension/MIME are hints; inspect/re-encode bytes before publishing in production.
  const blob = await put(`uploads/${crypto.randomUUID()}`, file, {
    access: 'public',
  })

  return NextResponse.json({
    url: blob.url,
    pathname: blob.pathname,
  })
}

```

This upload publishes a public URL, so it is unsuitable for private documents. `requireUploadPermission` is an application adapter; size checks after `formData()` do not stop an oversized body from being buffered. Enforce request limits at the host and use direct-to-storage upload flows for large files. Inspect bytes, avoid caller-controlled object paths and apply quota/cleanup policy.

## 6. Cache Policy and Revalidation

The canonical model and authenticated, allowlisted invalidation policy live in [Data and Caching](../03-data-and-caching/10.4.3.03-caching.md). In Next.js 16, `revalidateTag(tag, 'max')` marks tagged data for stale-while-revalidate behavior; a one-argument call is deprecated. Invalidating a cache is separate from regenerating it and does not instantly update every visitor's screen.

```typescript
// app/api/products/route.ts — Cache Components disabled
export const dynamic = 'force-static'
export const revalidate = 60

export async function GET() {
  const products = await db.product.findMany({ where: { published: true } })
  return Response.json(products)
}
```

With Cache Components enabled, put reusable public data in a cached helper instead:

```typescript
// lib/products.ts
import { cacheLife } from 'next/cache'

export async function getPublicProducts() {
  'use cache'
  cacheLife('hours')
  return db.product.findMany({ where: { published: true } })
}

// app/api/products/route.ts
import { getPublicProducts } from '@/lib/products'

export async function GET() {
  return Response.json(await getPublicProducts())
}
```

With Cache Components disabled, Route Handlers are uncached by default; route-segment configuration can opt a safe public `GET` into static caching and revalidation. With Cache Components enabled, static work is prerendered and reusable database work belongs in a cached helper; request-specific data stays dynamic. HTTP `Cache-Control` is a separate browser/CDN policy: use `private, no-store` when an intermediary must not reuse a personalized response. Test invalidation at every cache layer.

## 7. Method and Browser Boundaries

Export only the methods your endpoint supports. Next.js returns `405 Method Not Allowed` for an unsupported method and supplies `OPTIONS` automatically when you do not define it. Adding unrestricted POST/PUT/DELETE handlers to a read-only route unnecessarily expands its write surface.

For a public, non-credentialed cross-origin endpoint, return the same CORS headers on the response and its preflight. Cookie-bearing APIs need an explicit allowed origin and `Access-Control-Allow-Credentials`, rather than `*`; if the allowed origin is selected dynamically, include `Vary: Origin`. CORS controls browser access to a response; it does not authenticate callers or stop direct HTTP clients.

```typescript
const corsHeaders = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Methods': 'GET, OPTIONS',
  'Access-Control-Allow-Headers': 'Content-Type, Authorization',
}
export async function OPTIONS() {
  return new Response(null, { status: 204, headers: corsHeaders })
}
export async function GET() {
  return Response.json({ data: [] }, { headers: corsHeaders })
}
```

## Summary

A Route Handler owns an HTTP method's validation, authorization, status, headers and body. Choose it when a caller needs an HTTP contract; make caching, streaming, webhook retries and cross-origin access explicit at the boundary.

# Metadata API in Next.js

## Definition

The **Metadata API** in Next.js provides a systematic way to define and manage metadata for your pages, including titles, descriptions, Open Graph images and Twitter cards. It supports both static metadata via `metadata` export and dynamic metadata via `generateMetadata`. Structured data in JSON-LD is rendered separately in a script element; it is not a field of the `Metadata` object.

> **Textbook Definition:** Route metadata describes document information such as titles, canonical URLs and social previews. Next.js resolves static or computed metadata across route segments and emits the corresponding document-head representation.


## First Principles

A browser tab, a search result and a shared link need different descriptions of the same page. They cannot infer all of that from its visual layout.

1. **A URL needs a document identity.** A useful title describes this page, while the site supplies shared branding. A canonical URL identifies the preferred version when multiple URLs show equivalent content.
2. **Different consumers need explicit fields.** Open Graph describes a sharing preview; JSON-LD describes entities in structured data. Neither replaces visible page content or guarantees a search result format.
3. **Nested routes share defaults but need specific overrides.** Resolve parent values before page values and define how conflicts behave. Deriving a post's title and description from the same source as its body reduces disagreement, but their cache policy still controls freshness.

## Why It Matters

Senior engineers use `generateMetadata` for dynamic titles/descriptions based on route params (e.g., product pages). They know the precedence rules: layout metadata merges down, page metadata overrides, and `metadataBase` supplies the origin/base for relative URL fields; a canonical URL requires `alternates.canonical`.

## How It Works

Metadata is resolved from root to leaf with a **shallow merge**: a page that defines `openGraph` replaces that nested object, so explicitly carry forward parent images with the `parent` argument when necessary. Export either `metadata` or `generateMetadata` from a server layout/page, never both in one segment.

`generateMetadata` is not necessarily a per-request operation: prerenderable pages can resolve it during build. Next.js 15.2+ can stream request-dependent metadata for capable clients, while HTML-limited bots receive blocking metadata. For JSON-LD containing user/CMS text, escape `<` before injecting JSON into a script so a literal closing script tag cannot terminate it.

### Follow a page override through the hierarchy

```text
Root layout: title template "%s | My App", default Open Graph image /site.png
About page: title "About" → final document title "About | My App"
Blog page: supplies its own openGraph object → replaces parent's nested object
```

If the blog object supplies only a title, the parent's image does not survive automatically. Read the resolved `parent` metadata and explicitly preserve wanted fields. `metadataBase` resolves relative URLs against a known origin; it does not create a canonical link by itself. Declare that link through `alternates.canonical`.

| Consumer | Fields or representation | Purpose |
| ------------------------ | ------------------------------------- | --------------------------------------- |
| Browser/search | Title, description, canonical, robots | Document identity and crawl/index hints |
| Sharing platform | Open Graph and Twitter card fields | Preview text/image |
| Structured-data consumer | Escaped JSON-LD script | Facts about an entity or page |
| Crawler discovery | Sitemap and robots files | Discovery and crawl directives |

## Code Examples

### Basic Static Metadata

```typescript
// app/layout.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'My Application',
  description: 'A modern web application built with Next.js',
  keywords: ['nextjs', 'react', 'webapp'],
  authors: [{ name: 'John Doe' }],
  robots: {
    index: true,
    follow: true,
  },
}

export default function RootLayout({ children }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}

```

// app/about/page.tsx
import type { Metadata } from 'next'

### Dynamic Metadata with generateMetadata

```typescript
// app/blog/[slug]/page.tsx
import type { Metadata, ResolvingMetadata } from 'next'
import { notFound } from 'next/navigation'

interface Post {
  title: string
  excerpt: string
  coverImage: string
  publishedAt: string
  author: string
}

async function getPost(slug: string): Promise<Post> {
  const res = await fetch(`https://api.example.com/posts/${encodeURIComponent(slug)}`)
  if (res.status === 404) notFound()
  if (!res.ok) throw new Error('Failed to fetch post')
  return res.json()
}

export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>
}, parent: ResolvingMetadata): Promise<Metadata> {
  const { slug } = await params
  const post = await getPost(slug)
  const previousImages = (await parent).openGraph?.images ?? []

  return {
    title: post.title,
    description: post.excerpt,
    openGraph: {
      title: post.title,
      description: post.excerpt,
      images: [post.coverImage, ...previousImages],
      type: 'article',
      publishedTime: post.publishedAt,
      authors: [post.author],
    },
    twitter: {
      card: 'summary_large_image',
      title: post.title,
      description: post.excerpt,
      images: [post.coverImage],
    },
  }
}

export default async function BlogPost({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.excerpt}</p>
    </article>
  )
}

```

The helper handles 404 separately from a failed service. Both metadata and page call it; identical GET fetches can be memoized within rendering, which is different from persistent caching across requests. The parent image merge above intentionally retains site previews after the post image. Keep the merge only if that is the desired sharing policy.

### Template Titles

```typescript
// app/layout.tsx
import type { Metadata } from 'next'
export const metadata: Metadata = {
  title: { default: 'My Application', template: '%s | My Application' },
}

// app/about/page.tsx (separate file)
export const metadata: Metadata = { title: 'About' }
// About | My Application

// To bypass an inherited template on a particular page:
// export const metadata: Metadata = { title: { absolute: 'Independent Title' } }
```

A layout template applies to descendants, not the title in the same segment. `title.absolute` bypasses inherited formatting; it is an alternative to using the ordinary title value.

### Canonical URLs

```typescript
// app/blog/[slug]/page.tsx
export async function generateMetadata({ params }): Promise<Metadata> {
  const { slug } = await params
  const post = await getPost(slug)

  return {
    title: post.title,
    alternates: {
      canonical: `https://example.com/blog/${encodeURIComponent(slug)}`,
    },
  }
}

```

### Multi-Language Metadata

```typescript
// app/[locale]/layout.tsx
export async function generateMetadata({
  params,
}: {
  params: Promise<{ locale: string }>
}): Promise<Metadata> {
  const { locale } = await params

  return {
    title: locale === 'en' ? 'Home' : locale === 'es' ? 'Inicio' : 'Accueil',
    description:
      locale === 'en'
        ? 'Welcome to our app'
        : locale === 'es'
        ? 'Bienvenido a nuestra aplicación'
        : 'Bienvenue dans notre application',
    alternates: {
      languages: {
        'en': '/en',
        'es': '/es',
        'fr': '/fr',
      },
    },
  }
}

```

### Structured Data (JSON-LD)

```typescript
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'BlogPosting',
    headline: post.title,
    description: post.excerpt,
    image: post.coverImage,
    datePublished: post.publishedAt,
    author: {
      '@type': 'Person',
      name: post.author,
    },
  }

  return (
    <article>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }}
      />
      <h1>{post.title}</h1>
      <p>{post.excerpt}</p>
    </article>
  )
}

```

### Product Structured Data

```typescript
// app/products/[id]/page.tsx
export default async function ProductPage({ params }) {
  const { id } = await params
  const product = await getProduct(id)

  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'Product',
    name: product.name,
    description: product.description,
    image: product.images,
    sku: product.sku,
    brand: {
      '@type': 'Brand',
      name: product.brand,
    },
    offers: {
      '@type': 'Offer',
      url: `https://example.com/products/${encodeURIComponent(product.id)}`,
      priceCurrency: 'USD',
      price: product.price,
      availability: product.inStock ? 'https://schema.org/InStock' : 'https://schema.org/OutOfStock',
    },
  }

  return (
    <div>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }}
      />
      <h1>{product.name}</h1>
      <p>${product.price}</p>
    </div>
  )
}

```

Product structured data must match visible facts such as stock, currency and price. This sketch assumes the product adapter supplies `inStock` and USD pricing; it does not override checkout verification or guarantee a rich result.

### Breadcrumb Structured Data

```typescript
// components/breadcrumb.tsx
interface BreadcrumbItem {
  name: string
  url: string
}

export function Breadcrumb({ items }: { items: BreadcrumbItem[] }) {
  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'BreadcrumbList',
    itemListElement: items.map((item, index) => ({
      '@type': 'ListItem',
      position: index + 1,
      name: item.name,
      item: item.url,
    })),
  }

  return (
    <>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }}
      />
      <nav aria-label="Breadcrumb">
        <ol>
          {items.map((item, index) => (
            <li key={item.url}>
              {index < items.length - 1 ? (
                <a href={item.url}>{item.name}</a>
              ) : (
                <span>{item.name}</span>
              )}
            </li>
          ))}
        </ol>
      </nav>
    </>
  )
}

```

### robots.txt Generation

```typescript
// app/robots.ts
import type { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      {
        userAgent: '*',
        allow: '/',
        disallow: ['/admin', '/api'],
      },
    ],
    sitemap: 'https://example.com/sitemap.xml',
  }
}

```

Robots directives are instructions to cooperating crawlers, not access control. Protect private routes with authorization. Blocking crawling also prevents a crawler from reading a page-level `noindex`, so choose crawl and indexing policy deliberately.

### Sitemap Generation

```typescript
// app/sitemap.ts
import type { MetadataRoute } from 'next'

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const response = await fetch('https://api.example.com/posts')
  if (!response.ok) throw new Error('Failed to fetch sitemap entries')
  const posts = await response.json()

  const postEntries = posts.map(post => ({
    url: `https://example.com/blog/${encodeURIComponent(post.slug)}`,
    lastModified: post.updatedAt,
    changeFrequency: 'weekly' as const,
    priority: 0.8,
  }))

  return [
    {
      url: 'https://example.com',
      changeFrequency: 'daily',
      priority: 1,
    },
    {
      url: 'https://example.com/about',
      changeFrequency: 'monthly',
      priority: 0.5,
    },
    ...postEntries,
  ]
}

```

Use the actual content modification time for `lastModified`; regenerating the sitemap does not mean every page changed. This sketch assumes the posts feed includes only canonical, public, indexable entries. Large collections need bounded batches and the sitemap format limits, not one unbounded database read.

## Common Mistakes

### 1. Not Using metadataBase

```typescript
// A relative image needs a reliable base; deployment fallbacks may be unsuitable
export const metadata: Metadata = {
  openGraph: {
    images: ['/og-image.png'], // Which origin will the deployment use?
  },
}

// GOOD: Use metadataBase
export const metadata: Metadata = {
  metadataBase: new URL('https://example.com'),
  openGraph: {
    images: ['/og-image.png'], // Resolves to full URL
  },
}

```

### 2. Duplicate Titles

A layout title and page title do not produce duplicate `<title>` tags: the more specific value overrides. Duplication occurs when a page already appends the brand and an inherited template appends it again; use the [title-template example](#template-titles) and supply only the unique page title.

### 3. Missing OG Images

```typescript
// BAD: No OG image defined
export const metadata: Metadata = {
  title: 'My Page',
  openGraph: {
    title: 'My Page',
    // No image defined!
  },
}

// GOOD: Always include OG image
export const metadata: Metadata = {
  title: 'My Page',
  openGraph: {
    title: 'My Page',
    images: [
      {
        url: 'https://example.com/og-image.png',
        width: 1200,
        height: 630,
        alt: 'My Page',
      },
    ],
  },
}

```

### 4. Not Generating Dynamic Metadata

```typescript
// BAD: Static metadata for dynamic content
// app/blog/[slug]/page.tsx
export const metadata: Metadata = {
  title: 'Blog Post', // Same for every post!
  description: 'Read our blog post',
}

// GOOD: Generate metadata dynamically
export async function generateMetadata({ params }) {
  const { slug } = await params
  const post = await getPost(slug)
  return {
    title: post.title,
    description: post.excerpt,
  }
}

```

### 5. Ignoring Mobile Metadata

An Open Graph image is a sharing preview, not the responsive image displayed in your page. Supplying a desktop and mobile OG image does not make Next select by viewport; social platforms decide which preview to use. Supply a correctly sized preview with dimensions and alt text, and use [responsive `next/image`](../04-production/10.4.4.02-image-optimization.md#responsive-images) for on-page images.

## Best Practices

1. **Use metadataBase** — Always define for proper URL resolution

2. **Use templates** — Consistent title formatting across pages

3. **Generate dynamic metadata** — For dynamic content pages

4. **Include OG images** — Essential for social sharing

5. **Add accurate structured data** — Follow the supported schema and search guidelines; eligibility does not guarantee display

6. **Generate sitemaps** — Help search engines discover pages

7. **Define robots.txt** — Control crawling behavior

8. **Test metadata** — Use Open Graph debugger tools

9. **Describe the specific page concisely** — Search engines can truncate or rewrite snippets; there is no universal optimal length
10. **Update metadata** — Keep metadata fresh with content changes

## Performance Considerations

A static object avoids an extra runtime data read, but its emitted tags still have delivery cost. Generated metadata can reuse rendering fetches; slow request-dependent metadata may delay HTML-limited bots even when other clients receive it through streaming. Keep reads bounded, choose an explicit cache policy and inspect both the rendered page and the sharing/crawler response. JSON-LD size and unnecessary duplicate images add payload; metadata does not make the underlying content indexable by itself.

# Metadata API in Next.js

A shared product link can show the site name instead of the product even when the page body is correct. Its document metadata describes only the site. Next.js lets a route resolve a page-specific title, canonical URL and sharing preview from the same data that renders the page.

## Definition

The **Metadata API** defines document information such as a title, description, canonical URL and social preview. A Server Component exports static `metadata` or computes it with `generateMetadata`; Next.js resolves those values across layouts and pages and emits the corresponding HTML tags. JSON-LD is rendered separately in a script element, not as a `Metadata` field.

> **Textbook Definition:** Route metadata describes document information such as titles, canonical URLs and social previews. Next.js resolves static or computed values across route segments and emits the corresponding document metadata in the response.


## First Principles

The browser tab, search result and shared link read different metadata fields from the same document; they cannot infer all of them from its visual layout.

1. **A URL needs a document identity.** A useful title describes this page, while the site supplies shared branding. A canonical URL identifies the preferred version when multiple URLs show equivalent content.
2. **Different consumers need explicit fields.** Open Graph describes a sharing preview; JSON-LD describes entities in structured data. Neither replaces visible page content or guarantees a search result format.
3. **Nested routes share defaults but need specific overrides.** Resolve parent values before page values and define how conflicts behave. Deriving a post's title and description from the same source as its body reduces disagreement, but their cache policy still controls freshness.

## Choose static or generated metadata

Use `generateMetadata` when a page's title or preview depends on route data; otherwise prefer a static `metadata` export. Metadata cascades from layouts to pages, while a page can override inherited fields. Set `metadataBase` when relative URL fields need a stable public origin, and declare canonical identity through `alternates.canonical`. Metadata can guide crawlers and sharing clients, but it cannot guarantee a ranking or a particular search result.

## Resolve inherited values and generated resources

Metadata exports are supported in Server Components. A segment exports either `metadata` or `generateMetadata`, never both. Metadata is resolved from root layout to leaf page with a **shallow merge**: if a page defines `openGraph`, that nested object replaces the parent's object. Use the `parent` argument when the page should extend inherited values.

File-based metadata conventions such as `opengraph-image.png`, `icon.png`, `robots.ts`, and `sitemap.ts` generate or serve those resources directly and are static by default unless they depend on request-time data. For the same field, a file-based convention takes priority over the `metadata` export. Viewport settings are exported separately as `viewport` or `generateViewport`; they are not part of the current `Metadata` shape.

`generateMetadata` is not necessarily per-request: prerenderable pages can resolve it during build, and identical `fetch` calls are memoized during a render. Next.js can stream request-dependent metadata to clients that execute JavaScript; HTML-limited bots wait for tags in the document head. With Cache Components, metadata that reads request data or uncached data defers to request time. If the rest of the page can prerender, explicitly cache safe data or place the deferred work behind the intended dynamic/Suspense boundary.

| Consumer | Fields or representation | Purpose |
| ------------------------ | ------------------------------------- | --------------------------------------- |
| Browser/search | Title, description, canonical, robots | Document identity and crawl/index hints |
| Sharing platform | Open Graph and Twitter card fields | Preview text/image |
| Structured-data consumer | Escaped JSON-LD script | Facts about an entity or page |
| Crawler discovery | Sitemap and robots files | Discovery and crawl directives |

## Set defaults, then describe one page

Put the public origin and site-wide defaults in the root layout. A child page can add its own title, description and canonical path; the title template supplies consistent branding.

```typescript
// app/layout.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  metadataBase: new URL('https://example.com'),
  title: { default: 'Acme Store', template: '%s | Acme Store' },
  description: 'Tools and supplies for the home workshop.',
  openGraph: {
    type: 'website',
    siteName: 'Acme Store',
    images: [{ url: '/og-default.png', width: 1200, height: 630, alt: 'Acme Store workshop tools' }],
  },
}
```

```typescript
// app/about/page.tsx
import type { Metadata } from 'next'

export const metadata: Metadata = {
  title: 'About', // Resolves to "About | Acme Store"
  description: 'How Acme Store helps people build and repair.',
  alternates: { canonical: '/about' },
}
```

`metadataBase` makes relative URL fields absolute; it does not create a canonical link. A layout title template applies to descendants, not to the layout's own title. Use `title.absolute` only when a page must bypass that template.

## Derive metadata from the page's data

```typescript
// app/blog/[slug]/page.tsx
import type { Metadata, ResolvingMetadata } from 'next'
import { notFound } from 'next/navigation'
import { z } from 'zod'

const postSchema = z.object({
  title: z.string(),
  excerpt: z.string(),
  coverImage: z.url(), // This API returns an absolute image URL.
  publishedAt: z.string(),
  author: z.string(),
})
type Post = z.infer<typeof postSchema>

async function getPost(slug: string): Promise<Post> {
  const res = await fetch(`https://api.example.com/posts/${encodeURIComponent(slug)}`)
  if (res.status === 404) notFound()
  if (!res.ok) throw new Error('Failed to fetch post')
  return postSchema.parse(await res.json())
}

export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>
}, parent: ResolvingMetadata): Promise<Metadata> {
  const { slug } = await params
  const post = await getPost(slug)
  const previousImages = (await parent).openGraph?.images ?? []

  return {
    title: post.title,
    description: post.excerpt,
    alternates: { canonical: `/blog/${encodeURIComponent(slug)}` },
    openGraph: {
      title: post.title,
      description: post.excerpt,
      url: `/blog/${encodeURIComponent(slug)}`,
      images: [
        { url: post.coverImage, width: 1200, height: 630, alt: post.title },
        ...previousImages,
      ],
      type: 'article',
      publishedTime: post.publishedAt,
      authors: [post.author],
    },
    twitter: {
      card: 'summary_large_image',
      title: post.title,
      description: post.excerpt,
      images: [post.coverImage],
    },
  }
}

export default async function BlogPost({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.excerpt}</p>
    </article>
  )
}

```

The helper distinguishes a missing post from an upstream failure and validates remote JSON before using it. Metadata and page call the same helper; identical GETs can be memoized within rendering, which is separate from persistent caching across requests. The nested Open Graph object replaces the parent's, so this example deliberately carries the inherited image forward after the post image. URL syntax validation does not approve an origin; if the API response is untrusted, enforce an allowed image host before emitting the URL.

Beyond page identity and sharing previews, routes can publish language alternatives, structured facts and crawler instructions. Keep each one derived from canonical public content.

## Publish related page and crawler metadata

### Link equivalent language versions

```typescript
// Add to the route's metadata when these URLs serve equivalent translations.
import type { Metadata } from 'next'

export const metadata: Metadata = {
  alternates: {
    languages: {
      en: '/en/products/hammer',
      de: '/de/products/hammer',
      fr: '/fr/products/hammer',
    },
  },
}

```

### Icons and app manifest

Prefer file-based conventions such as `icon.png`, `apple-icon.png` and `manifest.json`; Next.js derives the corresponding tags from the files. Use the Metadata API's `icons` field only when explicit paths or relationships are needed. File-based metadata has higher priority for the field it defines.

### Structured Data (JSON-LD)

Inside the page component above, render public structured data in a script element and escape `<` so content cannot close the script early:

```typescript
// Inside BlogPost, using the validated `post` already loaded for the page.
  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'BlogPosting',
    headline: post.title,
    description: post.excerpt,
    image: post.coverImage,
    datePublished: post.publishedAt,
    author: {
      '@type': 'Person',
      name: post.author,
    },
  }

  return (
    <article>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }}
      />
      <h1>{post.title}</h1>
      <p>{post.excerpt}</p>
    </article>
  )

```

For other schema types, use the same safe serialization pattern and derive values from the public page data. A product's price, currency, and availability must match what a visitor can see; a `BreadcrumbList` should match the visible breadcrumb path. Structured data describes the page but does not replace its content or guarantee a rich search result.

### robots.txt Generation

```typescript
// app/robots.ts
import type { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      {
        userAgent: '*',
        allow: '/',
        disallow: ['/admin', '/api'],
      },
    ],
    sitemap: 'https://example.com/sitemap.xml',
  }
}

```

Robots directives are instructions to cooperating crawlers, not access control. Protect private routes with authorization. Blocking crawling also prevents a crawler from reading a page-level `noindex`, so choose crawl and indexing policy deliberately.

### Generate a sitemap from canonical public content

```typescript
// app/sitemap.ts
import type { MetadataRoute } from 'next'

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const posts = await getCanonicalPublicPosts() // Validates the API response and excludes drafts.
  return [
    { url: 'https://example.com' },
    { url: 'https://example.com/about' },
    ...posts.map(post => ({
      url: `https://example.com/blog/${encodeURIComponent(post.slug)}`,
      lastModified: post.updatedAt,
    })),
  ]
}

```

Use the actual significant content modification time for `lastModified`; generating a sitemap does not mean every page changed. Google ignores `priority` and `changefreq`, and each sitemap is limited to 50,000 URLs. For larger collections, use `generateSitemaps` to produce bounded files rather than loading every record at once.

### Social previews and page images

An Open Graph image is a sharing preview, not the responsive image displayed in your page. Supplying a desktop and mobile OG image does not make Next select by viewport; social platforms decide which preview to use. Supply a correctly sized preview with dimensions and alt text, and use [responsive `next/image`](../04-production/10.4.4.02-image-optimization.md#follow-the-image-to-the-browser) for on-page images.

## Check the emitted document

Use a static object unless route data changes the description; when it does, share the same validated data helper with the page. Keep titles, canonical and language URLs, social previews, JSON-LD and sitemap entries consistent with visible public content. Inspect the rendered head and crawler responses in production; none of these fields guarantees a ranking or replaces authorization.

## Keep metadata work within the render budget

A static object avoids an extra runtime data read, but its emitted tags still have delivery cost. Generated metadata can reuse rendering fetches; slow request-dependent metadata may delay HTML-limited bots even when other clients receive it through streaming. Keep reads bounded, choose an explicit cache policy and inspect both the rendered page and the sharing/crawler response. JSON-LD size and unnecessary duplicate images add payload; metadata does not make the underlying content indexable by itself.

## Summary

Describe the document that the route actually renders: set shared defaults in a layout, derive page-specific values from validated route data, and keep canonical, sharing and crawler output aligned. Treat metadata as public, cache-aware output—not as content or access control.

# Metadata API in Next.js

## Definition

The **Metadata API** defines document metadata such as a page title, description, canonical URL, and social preview. A route can export static `metadata` or compute it with `generateMetadata`; Next.js resolves these values across layouts and pages and emits the document head. Structured data such as JSON-LD is rendered separately in a script element; it is not a field of the `Metadata` object.

> **Textbook Definition:** Route metadata describes document information such as titles, canonical URLs and social previews. Next.js resolves static or computed metadata across route segments and emits the corresponding document-head representation.


## First Principles

A browser tab, a search result and a shared link need different descriptions of the same page. They cannot infer all of that from its visual layout.

1. **A URL needs a document identity.** A useful title describes this page, while the site supplies shared branding. A canonical URL identifies the preferred version when multiple URLs show equivalent content.
2. **Different consumers need explicit fields.** Open Graph describes a sharing preview; JSON-LD describes entities in structured data. Neither replaces visible page content or guarantees a search result format.
3. **Nested routes share defaults but need specific overrides.** Resolve parent values before page values and define how conflicts behave. Deriving a post's title and description from the same source as its body reduces disagreement, but their cache policy still controls freshness.

## Choose static or generated metadata

Use `generateMetadata` when a page's title or preview depends on route data; otherwise prefer a static `metadata` export. Metadata cascades from layouts to pages, while a page can override inherited fields. Set `metadataBase` when relative URL fields need a stable public origin, and declare canonical identity through `alternates.canonical`. Metadata can guide crawlers and sharing clients, but it cannot guarantee a ranking or a particular search result.

## Resolve inherited values and generated resources

Metadata exports are supported in Server Components. A segment exports either `metadata` or `generateMetadata`, never both. Metadata is resolved from root layout to leaf page with a **shallow merge**: if a page defines `openGraph`, that nested object replaces the parent's object. Use the `parent` argument when the page should extend inherited values.

File-based metadata conventions such as `opengraph-image.png`, `icon.png`, `robots.ts`, and `sitemap.ts` generate or serve those resources directly and are cached by default unless they depend on request-time data. For the same field, a file-based convention takes priority over the `metadata` export. When Proxy uses a broad matcher, exclude metadata files unless they need request interception. Viewport settings are exported separately as `viewport` or `generateViewport`; they are not part of the current `Metadata` shape.

`generateMetadata` is not necessarily a per-request operation: prerenderable pages can resolve it during build, and identical `fetch` calls are memoized during a render. Next.js 15.2+ can stream request-dependent metadata for capable clients, while HTML-limited bots wait for metadata in the document head. With Cache Components enabled, request-dependent or uncached metadata must follow the same cache or Suspense boundary rules as other route work. For JSON-LD containing user/CMS text, escape `<` before injecting JSON into a script so a literal closing script tag cannot terminate it.

### Follow a page override through the hierarchy

```text
Root layout: title template "%s | My App", default Open Graph image /site.png
About page: title "About" → final document title "About | My App"
Blog page: supplies its own openGraph object → replaces parent's nested object
```

If the blog object supplies only a title, the parent's image does not survive automatically. Read the resolved `parent` metadata and explicitly preserve wanted fields. `metadataBase` resolves relative URLs against a known origin; it does not create a canonical link by itself. Declare that link through `alternates.canonical`.

| Consumer | Fields or representation | Purpose |
| ------------------------ | ------------------------------------- | --------------------------------------- |
| Browser/search | Title, description, canonical, robots | Document identity and crawl/index hints |
| Sharing platform | Open Graph and Twitter card fields | Preview text/image |
| Structured-data consumer | Escaped JSON-LD script | Facts about an entity or page |
| Crawler discovery | Sitemap and robots files | Discovery and crawl directives |

## Describe each consumer's view of the page

### Set shared defaults once, then add page identity

```typescript
// app/layout.tsx
import type { Metadata } from 'next'
import type { ReactNode } from 'react'

export const metadata: Metadata = {
  title: 'My Application',
  description: 'A concise description of the application.',
}

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  )
}

```

Each page should add a distinct title and description when it has a distinct identity. The browser and search engine can still choose different display text, so write metadata that accurately describes the visible page rather than treating it as a ranking guarantee.

### Dynamic Metadata with generateMetadata

```typescript
// app/blog/[slug]/page.tsx
import type { Metadata, ResolvingMetadata } from 'next'
import { notFound } from 'next/navigation'

interface Post {
  title: string
  excerpt: string
  coverImage: string
  publishedAt: string
  author: string
}

async function getPost(slug: string): Promise<Post> {
  const res = await fetch(`https://api.example.com/posts/${encodeURIComponent(slug)}`)
  if (res.status === 404) notFound()
  if (!res.ok) throw new Error('Failed to fetch post')
  const payload: unknown = await res.json()
  if (typeof payload !== 'object' || payload === null ||
      !('title' in payload) || typeof payload.title !== 'string' ||
      !('excerpt' in payload) || typeof payload.excerpt !== 'string' ||
      !('coverImage' in payload) || typeof payload.coverImage !== 'string' ||
      !('publishedAt' in payload) || typeof payload.publishedAt !== 'string' ||
      !('author' in payload) || typeof payload.author !== 'string') {
    throw new Error('Unexpected post response')
  }
  return {
    title: payload.title,
    excerpt: payload.excerpt,
    coverImage: payload.coverImage,
    publishedAt: payload.publishedAt,
    author: payload.author,
  }
}

export async function generateMetadata({
  params,
}: {
  params: Promise<{ slug: string }>
}, parent: ResolvingMetadata): Promise<Metadata> {
  const { slug } = await params
  const post = await getPost(slug)
  const previousImages = (await parent).openGraph?.images ?? []

  return {
    title: post.title,
    description: post.excerpt,
    openGraph: {
      title: post.title,
      description: post.excerpt,
      images: [post.coverImage, ...previousImages],
      type: 'article',
      publishedTime: post.publishedAt,
      authors: [post.author],
    },
    twitter: {
      card: 'summary_large_image',
      title: post.title,
      description: post.excerpt,
      images: [post.coverImage],
    },
  }
}

export default async function BlogPost({ params }: { params: Promise<{ slug: string }> }) {
  const { slug } = await params
  const post = await getPost(slug)

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.excerpt}</p>
    </article>
  )
}

```

The helper handles 404 separately from a failed service. Both metadata and page call it; identical GET fetches can be memoized within rendering, which is different from persistent caching across requests. The parent image merge above intentionally retains site previews after the post image. Keep the merge only if that is the desired sharing policy.

### Template Titles

```typescript
// app/layout.tsx
import type { Metadata } from 'next'
export const metadata: Metadata = {
  title: { default: 'My Application', template: '%s | My Application' },
}

// app/about/page.tsx (separate file)
export const metadata: Metadata = { title: 'About' }
// About | My Application

// To bypass an inherited template on a particular page:
// export const metadata: Metadata = { title: { absolute: 'Independent Title' } }
```

A layout template applies to descendants, not the title in the same segment. `title.absolute` bypasses inherited formatting; it is an alternative to using the ordinary title value.

### Canonical URLs

```typescript
// app/blog/[slug]/page.tsx
export async function generateMetadata({ params }): Promise<Metadata> {
  const { slug } = await params
  const post = await getPost(slug)

  return {
    title: post.title,
    alternates: {
      canonical: `https://example.com/blog/${encodeURIComponent(slug)}`,
    },
  }
}

```

### Multi-Language Metadata

```typescript
// app/[locale]/layout.tsx
export async function generateMetadata({
  params,
}: {
  params: Promise<{ locale: string }>
}): Promise<Metadata> {
  const { locale } = await params

  return {
    title: locale === 'en' ? 'Home' : locale === 'es' ? 'Inicio' : 'Accueil',
    description:
      locale === 'en'
        ? 'Welcome to our app'
        : locale === 'es'
        ? 'Bienvenido a nuestra aplicación'
        : 'Bienvenue dans notre application',
    alternates: {
      languages: {
        'en': '/en',
        'es': '/es',
        'fr': '/fr',
      },
    },
  }
}

```

### Structured Data (JSON-LD)

```typescript
// app/blog/[slug]/page.tsx
export default async function BlogPost({ params }) {
  const { slug } = await params
  const post = await getPost(slug)

  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'BlogPosting',
    headline: post.title,
    description: post.excerpt,
    image: post.coverImage,
    datePublished: post.publishedAt,
    author: {
      '@type': 'Person',
      name: post.author,
    },
  }

  return (
    <article>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd).replace(/</g, '\\u003c') }}
      />
      <h1>{post.title}</h1>
      <p>{post.excerpt}</p>
    </article>
  )
}

```

For other schema types, use the same safe serialization pattern and derive values from the public page data. A product's price, currency, and availability must match what a visitor can see; a `BreadcrumbList` should match the visible breadcrumb path. Structured data describes the page but does not replace its content or guarantee a rich search result.

### robots.txt Generation

```typescript
// app/robots.ts
import type { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      {
        userAgent: '*',
        allow: '/',
        disallow: ['/admin', '/api'],
      },
    ],
    sitemap: 'https://example.com/sitemap.xml',
  }
}

```

Robots directives are instructions to cooperating crawlers, not access control. Protect private routes with authorization. Blocking crawling also prevents a crawler from reading a page-level `noindex`, so choose crawl and indexing policy deliberately.

### Sitemap Generation

```typescript
// app/sitemap.ts
import type { MetadataRoute } from 'next'

interface SitemapPost {
  slug: string
  updatedAt: string
}

function isSitemapPost(value: unknown): value is SitemapPost {
  return typeof value === 'object' && value !== null &&
    'slug' in value && typeof value.slug === 'string' &&
    'updatedAt' in value && typeof value.updatedAt === 'string' &&
    Number.isFinite(Date.parse(value.updatedAt))
}

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  const response = await fetch('https://api.example.com/posts')
  if (!response.ok) throw new Error('Failed to fetch sitemap entries')
  const payload: unknown = await response.json()
  if (!Array.isArray(payload) || !payload.every(isSitemapPost)) {
    throw new Error('Unexpected sitemap response')
  }
  const posts: SitemapPost[] = payload

  const postEntries = posts.map(post => ({
    url: `https://example.com/blog/${encodeURIComponent(post.slug)}`,
    lastModified: post.updatedAt,
  }))

  return [
    {
      url: 'https://example.com',
    },
    {
      url: 'https://example.com/about',
    },
    ...postEntries,
  ]
}

```

Use the actual significant content modification time for `lastModified`; regenerating the sitemap does not mean every page changed. This sketch assumes the feed includes only canonical, public, indexable entries. Google ignores sitemap `priority` and `changefreq` values, and each sitemap is limited to 50,000 URLs. For a larger collection, use `generateSitemaps` to query one bounded range per file instead of loading every record at once.

### Metadata Base URL

```typescript
// app/layout.tsx
export const metadata: Metadata = {
  metadataBase: new URL('https://example.com'),
  title: 'My Application',
  openGraph: {
    title: 'My Application',
    images: ['/og-image.png'], // Resolves to https://example.com/og-image.png
  },
}

```

## Social previews and page images

An Open Graph image is a sharing preview, not the responsive image displayed in your page. Supplying a desktop and mobile OG image does not make Next select by viewport; social platforms decide which preview to use. Supply a correctly sized preview with dimensions and alt text, and use [responsive `next/image`](../04-production/10.4.4.02-image-optimization.md#responsive-images) for on-page images.

## Keep public descriptions consistent

1. Prefer a static `metadata` object; use `generateMetadata` only when route data changes the page description. Share the page's data helper so the body and head describe the same record.
2. Set the public origin in `metadataBase`, then declare `alternates.canonical` for pages that need a canonical URL. Keep canonical, language alternatives, and sitemap entries consistent.
3. Define a title template at a layout boundary and provide concise, distinct titles in child pages. Check the resolved title so the brand is not appended twice.
4. Keep previews, JSON-LD, and sitemap entries aligned with public visible content. Treat all of them as public output; never include secrets or private customer facts.
5. Inspect the emitted head and crawler responses in production. Verify inherited fields, canonical URLs, social images, robot directives, and the actual sitemap.

## Keep metadata work within the render budget

A static object avoids an extra runtime data read, but its emitted tags still have delivery cost. Generated metadata can reuse rendering fetches; slow request-dependent metadata may delay HTML-limited bots even when other clients receive it through streaming. Keep reads bounded, choose an explicit cache policy and inspect both the rendered page and the sharing/crawler response. JSON-LD size and unnecessary duplicate images add payload; metadata does not make the underlying content indexable by itself.

## Summary

| Feature | Metadata API |
| ---------- | ------------------------------------------ |
| Static | `export const metadata = {...}` |
| Dynamic | `export async function generateMetadata()` |
| Open Graph | og:title, og:description, og:image |
| Twitter | twitter:card, twitter:title, twitter:image |
| Structured | JSON-LD in script tags |
| Sitemap | `sitemap.ts` export |
| Robots | `robots.ts` export |

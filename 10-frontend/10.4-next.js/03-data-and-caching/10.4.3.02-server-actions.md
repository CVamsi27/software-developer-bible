# Server Actions in Next.js

## TL;DR

Server Actions are async functions that run on the server, callable from Client or Server Components. Marked with `'use server'`. They integrate with forms (`<form action={action}>`), enable mutations without API routes, and support progressive enhancement.

## First Principles

Server Actions make mutations POSTs with a typed RPC skin:

1. **An action is a server function the client can call** — the framework generates the endpoint, serializes args, and returns a serializable result; what you *don't* get is secrecy: the code ships server-side but the *interface* is public HTTP (validate authz inside, → 20.5.1.02).
2. **Progressive enhancement falls out**: `<form action={fn}>` works before hydration — the mutation is a form POST at heart; client-side niceties (useActionState, optimistic updates) layer on top.
3. **Revalidation is the coupling point**: a mutation that changes cached data must invalidate it (→ 10.4.3.03's revalidateTag) — the action is the natural place where write and cache meet.

## Why It Matters

Senior engineers use Server Actions for: form submissions, mutations from client components, revalidation triggers. They know the security model (always re-validate auth server-side), the `revalidatePath`/`revalidateTag` integration, and the difference between Server Actions and Route Handlers (Actions are mutations, Handlers are full HTTP endpoints).

## Definition

**Server Actions** are asynchronous functions that run on the server and can be called from Client Components or Server Components. They use the `'use server'` directive and enable form handling, data mutations, and progressive enhancement without creating API routes.


## How It Works

**Version scope:** Next.js 15/16 use React 19's `useActionState` from `react` (the earlier `useFormState` API is deprecated). Form actions rendered by Server Components support submission without client JavaScript; client-rendered forms have hydration/queuing behavior, so do not assume every arbitrary event handler is progressively enhanced.

Actions are public mutation endpoints: use a session check and resource ownership in each action, and validate runtime inputs. A TypeScript cast cannot validate `FormData`, which can contain `null` or a `File`. Next checks action origins against the host; deployment proxy/allowed-origin configuration must retain that check.

`redirect()` throws control-flow machinery; call it outside a catch that would turn that redirect into an error state. `useFormStatus` reads its nearest parent form, so the submit button must be a descendant, not the component creating the form. The upload example permits 5 MiB, which requires raising the default 1 MiB Server Action body limit to an appropriate bounded value in `experimental.serverActions.bodySizeLimit` or uploading directly to storage.

## Code Examples

### Basic Server Action

```typescript
// app/actions/post.ts
'use server'

import { revalidatePath } from 'next/cache'
import { redirect } from 'next/navigation'
import { db } from '@/lib/database'
import { auth } from '@/auth'
import { z } from 'zod'

export async function createPost(formData: FormData) {
  const session = await auth()
  if (!session?.user?.id) throw new Error('Unauthorized')
  const { title, content } = z.object({
    title: z.string().min(1), content: z.string().min(1),
  }).parse({ title: formData.get('title'), content: formData.get('content') })

  await db.post.create({
    data: { title, content, authorId: session.user.id },
  })

  revalidatePath('/posts')
  redirect('/posts')
}

```

### Server Action with Validation

```typescript
// app/actions/user.ts
'use server'

import { z } from 'zod'
import { revalidatePath } from 'next/cache'

const userSchema = z.object({
  name: z.string().min(2).max(50),
  email: z.string().email(),
  age: z.number().min(18).max(120),
})

interface ActionState {
  errors?: Record<string, string[]>
  success?: boolean
}

export async function createUser(
  prevState: ActionState,
  formData: FormData
): Promise<ActionState> {
  const rawData = {
    name: formData.get('name') as string,
    email: formData.get('email') as string,
    age: Number(formData.get('age')),
  }

  const validated = userSchema.safeParse(rawData)

  if (!validated.success) {
    return {
      errors: validated.error.flatten().fieldErrors,
    }
  }

  await db.user.create({
    data: validated.data,
  })

  revalidatePath('/users')
  return { success: true }
}

```

### Using useActionState Hook

```typescript
// app/users/new/page.tsx
'use client'

import { useActionState } from 'react'
import { createUser } from '@/app/actions/user'

export default function NewUserPage() {
  const [state, formAction] = useActionState(createUser, {})

  return (
    <div>
      <h1>Create User</h1>
      <form action={formAction}>
        <div>
          <label htmlFor="name">Name</label>
          <input type="text" id="name" name="name" required />

            <p className="error">{state.errors.name[0]}</p>
          )}
        </div>
        <div>
          <label htmlFor="email">Email</label>
          <input type="email" id="email" name="email" required />
          {state.errors?.email && (
            <p className="error">{state.errors.email[0]}</p>
          )}
        </div>
        <div>
          <label htmlFor="age">Age</label>
          <input type="number" id="age" name="age" required />
          {state.errors?.age && (
            <p className="error">{state.errors.age[0]}</p>
          )}
        </div>
        <button type="submit">Create</button>
        {state.success && <p className="success">User created!</p>}
      </form>
    </div>
  )
}
```

### Server Action with useTransition

```typescript
// app/actions/like.ts
'use server'

import { revalidatePath } from 'next/cache'

export async function toggleLike(postId: string) {
  const session = await auth() // Import the configured session helper in this action file
  if (!session?.user?.id) throw new Error('Unauthorized')
  const currentUserId = session.user.id
  const existingLike = await db.like.findFirst({
    where: { postId, userId: currentUserId },
  })

  if (existingLike) {
    await db.like.delete({ where: { id: existingLike.id } })
  } else {
    await db.like.create({
      data: { postId, userId: currentUserId },
    })
  }

  revalidatePath('/posts')
}

```

```typescript
}
```

### Server Action with Optimistic Updates

```typescript
// components/todo-list.tsx
'use client'

import { useOptimistic } from 'react'
import { addTodo } from '@/app/actions/todo'

interface Todo {
  id: string
  text: string
  completed: boolean
}

export function TodoList({ initialTodos }: { initialTodos: Todo[] }) {
  const [optimisticTodos, addOptimisticTodo] = useOptimistic(
    initialTodos,
    (state, newTodo: Omit<Todo, 'id'>) => [
      ...state,
      { ...newTodo, id: 'temp-' + Date.now() },
    ]
  )

  async function handleSubmit(formData: FormData) {
    const text = formData.get('text') as string

    addOptimisticTodo({ text, completed: false })
    await addTodo(formData)
  }

  return (
    <div>
      <form action={handleSubmit}>
        <input name="text" required />
        <button type="submit">Add</button>
      </form>
      <ul>
        {optimisticTodos.map(todo => (
          <li key={todo.id} className={todo.completed ? 'done' : ''}>
            {todo.text}
          </li>
        ))}
      </ul>
    </div>
  )
}

```

### Server Action with Cookies

```typescript
// app/actions/preferences.ts
'use server'

import { cookies } from 'next/headers'
import { revalidatePath } from 'next/cache'

export async function updatePreferences(formData: FormData) {
  const theme = formData.get('theme') as string
  const language = formData.get('language') as string

  const cookieStore = await cookies()

  cookieStore.set('preferences', JSON.stringify({ theme, language }), {
    httpOnly: true,
    secure: true,
    sameSite: 'lax',
    maxAge: 60 * 60 * 24 * 365, // 1 year
  })

  revalidatePath('/')
}

```

### Server Action with Error Handling

```typescript
// app/actions/upload.ts
'use server'

import { revalidatePath } from 'next/cache'

interface UploadState {
  error?: string
  success?: boolean
  fileUrl?: string
}

export async function uploadFile(
  prevState: UploadState,
  formData: FormData
): Promise<UploadState> {
  const file = formData.get('file') as File

  if (!file) {
    return { error: 'No file provided' }
  }

  if (file.size > 5 * 1024 * 1024) {
    return { error: 'File size must be less than 5MB' }
  }

  const allowedTypes = ['image/jpeg', 'image/png', 'image/webp']
  if (!allowedTypes.includes(file.type)) {
    return { error: 'File type not allowed' }
  }

  try {
    const buffer = Buffer.from(await file.arrayBuffer())
    const filename = `${Date.now()}-${file.name}`

    // Upload to storage (e.g., S3, Cloudflare R2)
    const url = await uploadToStorage(buffer, filename)

    revalidatePath('/gallery')
    return { success: true, fileUrl: url }
  } catch (error) {
    return { error: 'Upload failed. Please try again.' }
  }
}

```

### Server Action with File Upload

```typescript
// app/actions/upload-document.ts
'use server'

import { put } from '@vercel/blob'
import { revalidatePath } from 'next/cache'

export async function uploadDocument(formData: FormData) {
  const file = formData.get('file') as File

  if (!file) {
    throw new Error('No file provided')
  }

  const blob = await put(file.name, file, {
    access: 'public',
  })

  await db.document.create({
    data: {
      name: file.name,
      url: blob.url,
      size: file.size,
    },
  })

  revalidatePath('/documents')
}

```

### Server Action with Search Params

```typescript
// app/actions/search.ts
'use server'

import { redirect } from 'next/navigation'

export async function searchProducts(formData: FormData) {
  const query = formData.get('query') as string
  const category = formData.get('category') as string

  const params = new URLSearchParams()
  if (query) params.set('q', query)
  if (category) params.set('category', category)

  redirect(`/products?${params.toString()}`)
}
```

## Common Mistakes

### 1. Not Using 'use server' Directive

```typescript
// BAD: Missing directive
export async function createPost(formData: FormData) {
  await db.post.create({ data: { title: formData.get('title') } })
  // This won't work as a Server Action!
}

// GOOD: Add directive
'use server'

export async function createPost(formData: FormData) {
  await db.post.create({ data: { title: formData.get('title') } })
}

```

### 2. Returning Non-Serializable Data

```typescript
// BAD: Returning non-serializable data
'use server'

export async function getData() {
  return {
    date: new Date(), // Native Date is supported by React serialization
    fn: () => {}, // Ordinary callbacks are not supported
  }
}

// GOOD: Return serializable data
'use server'

export async function getData() {
  return {
    date: new Date().toISOString(), // String
    value: 42, // Primitive
  }
}

```

### 3. Not Handling Errors

```typescript
// BAD: No error handling
'use server'

export async function updateUser(formData: FormData) {
  await db.user.update({
    where: { id: formData.get('id') },
    data: { name: formData.get('name') },
  })
  // What if it fails?
}

// GOOD: Proper error handling
'use server'

export async function updateUser(
  prevState: any,
  formData: FormData
) {
  try {
    await db.user.update({
      where: { id: formData.get('id') },
      data: { name: formData.get('name') },
    })
    revalidatePath('/users')
    return { success: true }
  } catch (error) {
    return { error: 'Failed to update user' }
  }
}

```

### 4. Not Using Revalidation

```typescript
// BAD: No revalidation after mutation
'use server'

export async function createPost(formData: FormData) {
  await db.post.create({
    data: { title: formData.get('title') },
  })
  // Page won't show new post!
}

// GOOD: Revalidate after mutation
'use server'

export async function createPost(formData: FormData) {
  await db.post.create({
    data: { title: formData.get('title') },
  })
  revalidatePath('/posts') // Refresh /posts page
  revalidateTag('posts') // Refresh all pages with 'posts' tag
}

```

### 5. Calling Server Action from Server Component

A Server Component may call a Server Function directly, but reads should generally use a server-only data helper rather than exposing a new client-callable action. Never perform a mutation during rendering: prerendering, retries, or navigation may render more than once. Keep the mutation in a form/action invocation.

## Best Practices

1. **Use 'use server' directive** — Always at the top of the file or function

2. **Return React-serializable data** — Built-ins such as Date/Map are supported; ordinary callbacks/class instances are not

3. **Handle errors gracefully** — Return error states to client

4. **Use revalidation** — Call `revalidatePath` or `revalidateTag` after mutations

5. **Validate inputs** — Use Zod or similar for server-side validation

6. **Keep actions focused** — One action per operation

7. **Use useActionState for forms** — For error handling and state management

8. **Use useFormStatus for loading** — Show pending state during submission

9. **Test server actions** — Unit test the action logic separately
10. **Document action contracts** — Define clear input/output types

## Performance Considerations

```text
Server Actions Performance:

- Execute on server (no client JS overhead)
- Explicit revalidation can update the UI without a full page reload
- Progressive enhancement works without JS
- Type safety reduces runtime errors

Optimization:

- Keep actions focused and fast
- Invalidate only the paths/tags affected by the completed write
- Implement proper error handling
- Cache frequently accessed data

```

## Revision Questions

**Definition**

1. **Q:** Why is a server-only action still an externally reachable security boundary?
   **A:** Next creates a client-callable POST interface for it. Keep identity, ownership, and runtime input validation inside the action.


**How It Works**

2. **Q:** Which hook now owns returned form state in the React 19 stack?
   **A:** useActionState from react pairs the previous state with the next submission. The older react-dom useFormState API is deprecated.


**Code Examples**

3. **Q:** Why must a useFormStatus submit button be below the form it observes?
   **A:** The hook reads the nearest parent form context. Calling it in the component that creates the form cannot observe that future child form.

4. **Q:** What infrastructure setting must match a form that accepts a five-MiB upload?
   **A:** The Server Action request-body limit must be raised from its default one MiB to a bounded suitable value, or the file should upload directly to storage.


**Common Mistakes**

5. **Q:** Why should redirect be outside a broad action catch block?
   **A:** Redirect throws a framework control-flow signal. A catch can intercept it and incorrectly report a successful redirect as a failed mutation.

6. **Q:** Which returned values prove that React serialization is broader than JSON?
   **A:** Native Date, Map, and Set can be supported values. Ordinary functions and arbitrary class instances still cannot be returned across the boundary.

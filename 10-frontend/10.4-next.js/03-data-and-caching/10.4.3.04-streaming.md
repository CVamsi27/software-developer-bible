# Streaming in Next.js

A dashboard can render its title quickly while a chart query takes seconds. If the route waits for the chart, ready content waits too; a Suspense boundary can let the useful shell arrive while that region is pending.

```tsx
export default function DashboardPage() {
  const chart = getChartData(); // start now, await later
  const stats = getStats();

  return (
    <main>
      <h1>Dashboard</h1>
      <Suspense fallback={<ChartSkeleton />}>
        <Chart result={chart} />
      </Suspense>
      <Suspense fallback={<StatsSkeleton />}>
        <Stats result={stats} />
      </Suspense>
    </main>
  );
}
```

## Definition

**Streaming** sends a rendered response in parts. A useful shell can reach the browser while a slower region is still waiting; that region replaces its fallback when its work is ready.

> **Textbook Definition:** Streaming is incremental delivery of a response as independent portions become available. In React, Suspense boundaries define pending UI regions; the server and transport determine when their completed output can reach the client.

## First Principles

A fallback gives the renderer a useful place to pause while the slow region is unresolved. Streaming helps only when the shell is useful and the slow work can proceed separately: if a recommendation query needs the user ID, it must wait for the user read. A Suspense boundary controls when UI reveals — never data dependencies, and never automatic request parallelization.

## 1. Place the Boundary Where Waiting Begins

Start independent work before awaiting it, then place a boundary around each region whose delay should not block the rest:

```tsx
import { Suspense } from 'react';
import { Activity, Chart, Stats } from './dashboard-sections';
import { ActivitySkeleton, ChartSkeleton, StatsSkeleton } from './skeletons';
import { getActivity, getChartData, getStats } from './data';

export default function DashboardPage() {
  // These application reads begin before any result is awaited.
  const activity = getActivity();
  const chart = getChartData();
  const stats = getStats();

  return (
    <main>
      <h1>Dashboard</h1>
      <section aria-label="Activity">
        <Suspense fallback={<ActivitySkeleton />}>
          <Activity result={activity} />
        </Suspense>
      </section>
      <section aria-label="Statistics">
        <Suspense fallback={<StatsSkeleton />}>
          <Stats result={stats} />
        </Suspense>
      </section>
      <section aria-label="Analytics">
        <Suspense fallback={<ChartSkeleton />}>
          <Chart result={chart} />
        </Suspense>
      </section>
    </main>
  );
}
```

Each async section awaits its own promise and renders the result. The three reads can finish in any order, regardless of their position in the JSX. They must still be authorized and scoped to the signed-in user. If a later read depends on an earlier result, start it after that input exists and put its fallback around the dependent region.

## 2. Pick Route-Wide or Local Loading by Scope

`loading.tsx` gives a route segment an automatic Suspense fallback around its page and descendants beneath that segment's layout. It is useful for navigation-level feedback. A local `<Suspense>` gives finer control when a page has several regions with different waiting and reveal behavior.

A fallback must be useful, accessible, and close to the final region's geometry. Replacing a small label with a full-page spinner hides ready content; a skeleton with the wrong height can shift content when replaced. An awaited request in a parent layout is outside that segment's `loading.tsx`; move it below the boundary or wrap it in a nearer Suspense boundary.

## 3. Keep HTTP Decisions Ahead of the First Bytes

When streaming begins, the response status and headers are already committed. A later `notFound()`, redirect, or exception can update the streamed UI protocol, but it cannot rewrite the HTTP status that was sent. Authenticate and perform checks that must produce a real 401, 404, or redirect before sending the relevant shell. Do not place private or misleading output in that shell while an authorization decision is pending.

Suspense means “still waiting,” not “failed.” A thrown error is handled by the nearest React/Next error boundary; route-level `error.tsx` is a Client Component with a reset action. Return a safe message and log diagnostic details on the server rather than rendering raw exception text. Add a narrower error boundary only when a region has a distinct recovery path.

## 4. Account for Crawlers and the Production Path

Streaming metadata differs by crawler capability. Next.js waits for `generateMetadata` when an HTML-limited bot needs metadata in the initial `<head>`; full browsers and DOM-capable crawlers can receive metadata as a streamed update. With Cache Components, HTML-limited bots render the page dynamically rather than using the prerendered shell so metadata is available in the head. Ensure data needed by that rendering path is available at request time.

The framework can emit progressive output, but a reverse proxy, CDN, serverless adapter, or compression layer may buffer it. HTTP/1.1 and HTTP/2 frame streamed responses differently; the application-level behavior is progressive delivery around Suspense boundaries. Verify the production path, not only the development server. In browser tools inspect document timing and when useful content appears; a fast first byte does not prove that the largest visible content arrived sooner.

## 5. Decide What Streams Separately

Use separate boundaries for independently useful dashboard panels, product information and optional reviews, or an article and its comments. Keep authentication, the title, or any content needed to understand the page outside a slow optional boundary when those values are ready sooner. Keep sections together when revealing them separately would mislead, break a task, or cause disruptive layout movement.

Measure the user-visible result. Streaming may improve time to first byte and first paint when the shell is useful, but Largest Contentful Paint still depends on the largest content element. Reserve space for fallbacks and watch layout shift as sections resolve.

## Summary

Streaming lets ready UI arrive before slower work, while Suspense boundaries define which region waits. Start independent reads together, keep true dependencies intact, and choose boundaries around meaningful content. Make status and access decisions before sending bytes, handle failures separately from pending states, and verify that production infrastructure forwards the stream.

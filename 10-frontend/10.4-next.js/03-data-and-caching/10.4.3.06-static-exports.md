# Static Exports in Next.js

## Definition

A **static export** runs `next build` with `output: 'export'` and emits route HTML, JavaScript, styles, and other files into `out/`. A plain web server or CDN serves those files; no Next.js application server runs for each request.

> **Textbook Definition:** Static export is build-time generation of deployable route documents and assets. It replaces request-time framework execution with file serving, so routes and data must be known during the build or loaded by browser code from another service.

## First Principles

A file server can return a file that exists. It cannot run a page handler, inspect a visitor's session, regenerate a route, or perform a Server Action. The export is therefore a contract between the build and the host:

1. Every page that the host should serve must have output before deployment.
2. Personalized or changing data needs a separate service or a deliberate browser-fetch path.
3. Deep links, not-found responses, redirects, and cache headers depend on the host's URL-to-file rules.

## Build the pages the host will serve

Use `output: 'export'`; since Next.js 14, `next export` is no longer a separate command. The normal `next build` writes the static output:

```typescript
// next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  output: 'export',
  trailingSlash: true,
};

export default nextConfig;
```

```bash
npm run build
# or: npx next build
# Static files are written to ./out/
```

Server Components still run, but they run during the build. Their rendered HTML and static navigation payload become public output, so do not render private records or embed secrets there. If a path is dynamic, enumerate every route the export must contain with `generateStaticParams` and disable unknown params:

```tsx
// app/products/[id]/page.tsx
export const dynamicParams = false;

export async function generateStaticParams() {
  const response = await fetch('https://catalog.example.com/products');
  if (!response.ok) throw new Error('Product list unavailable during build');
  const products = parseProductIndex(await response.json());
  return products.map((product) => ({ id: product.id }));
}

export default async function ProductPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const response = await fetch(
    `https://catalog.example.com/products/${encodeURIComponent(id)}`,
  );
  if (!response.ok) throw new Error(`Build could not read product ${id}`);
  const product = parseProduct(await response.json());

  return <main><h1>{product.name}</h1><p>{product.description}</p></main>;
}
```

The parsers represent runtime validation of the build-time API responses. If a product is missing during build, fail the build or intentionally omit it; do not ship a page containing a fabricated fallback as if it were real data. A product created after deployment has no exported page until the next build. Pages Router applications use `getStaticPaths` with `fallback: false`; `fallback: true` and `'blocking'` require runtime generation and do not fit a static export.

### Move request-time work to an explicit runtime

An App Router Route Handler can emit a static file only when it is a request-independent `GET` and is marked `dynamic = 'force-static'`:

```typescript
// app/catalog.json/route.ts
export const dynamic = 'force-static';

export async function GET() {
  const catalog = await loadCatalogAtBuildTime();
  return Response.json(catalog);
}
```

The generated `catalog.json` cannot vary by cookie, incoming header, or query parameter. A handler that reads `Request` data, uses a mutation method, or accesses a session needs a runtime and cannot be exported. Pages Router API routes also require a server.

For data that should change without rebuilding a public shell, the browser can call an external API or load a JSON snapshot emitted by the build. The external API must perform authentication and resource authorization; hiding a control in client code is not access control. Never put credentials in the bundle or a public JSON file.

If the build should create a JSON snapshot, finish that work before `next build` and fail the build if the source is unavailable:

```typescript
// scripts/generate-data.ts
import { mkdir, writeFile } from 'node:fs/promises';
import { resolve } from 'node:path';

const response = await fetch('https://catalog.example.com/products');
if (!response.ok) throw new Error('Catalog unavailable during build');
const products = parseProductIndex(await response.json());

const directory = resolve('public/data');
await mkdir(directory, { recursive: true });
await writeFile(
  resolve(directory, 'products.json'),
  JSON.stringify(products),
  'utf8',
);
```

Run it in the same build command: `tsx scripts/generate-data.ts && next build`. This file represents the last deployed build snapshot; a later browser fetch does not make it live.

## Check the unsupported capabilities

| Capability | Static-export behavior | Design choice |
| ---------------------------------------------------- | ------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Dynamic App Router route | Build every permitted path; set `dynamicParams = false` | Rebuild when the route set changes |
| Request-dependent Route Handler, cookies, or headers | No request-time Next.js runtime | Use an external backend/API |
| Server Actions, Proxy, ISR, or rewrites | Cannot execute after deployment | Use an application server or host-level configuration |
| Default `next/image` optimizer | Requires a Next.js runtime | Use `unoptimized` or a custom loader for an image CDN |
| Client Component browser API | Component is still prerendered during build | Read `window`, `localStorage`, or `navigator` after mount, not during render |
| Page not found, redirects, and response headers | Owned by the static host | Configure and test host routing and headers |

Client Components still render to HTML during the build. Keep their first render deterministic and access browser-only APIs in an effect or after mount, so build HTML and the first browser render agree. For `next/image`, set intrinsic dimensions or a stable aspect ratio even when optimization is disabled. In Next.js 16, `preload` replaces the deprecated `priority` prop when the image should be preloaded; do not preload several competing images by default.

## Make host routing part of the release

The host must map a URL such as `/products/42/` to the emitted file (for example, `out/products/42/index.html` with `trailingSlash: true`) and return the intended 404 for unknown files. A minimal Nginx configuration is:

```nginx
server {
    listen 80;
    root /var/www/out;

    location / {
        try_files $uri $uri.html $uri/ =404;
    }

    error_page 404 /404.html;
}
```

For a site hosted under a project prefix such as `/repo`, set Next.js `basePath` and verify that links, scripts, images, direct visits, and client navigation all include that prefix. Test the actual provider's custom 404 status, redirects, cache headers, HTTPS, and subpath behavior; serving `out/` locally does not verify those host rules.

## Real-world decisions

Static export fits documentation, marketing, and portfolio sites when content changes through a controlled build and the pages are public. It can also serve a static shell for a client-rendered interface, but any session, private data, mutation, or live update still needs a real backend. If the app needs per-request authorization, preview mode, unbounded dynamic routes, webhook-driven regeneration, or Server Actions, deploy a Next.js runtime instead of trying to simulate one with static files.

## Summary

Static export moves Server Component execution to build time and deploys the resulting files without a Next.js request server. Generate every route the host must serve, keep private data out of emitted output, and move request-specific work to an authorized service. The host's file mapping and error behavior are part of the application contract and must be tested at the deployed URL shape.

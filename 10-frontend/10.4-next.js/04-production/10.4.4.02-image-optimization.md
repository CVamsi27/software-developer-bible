# Image Optimization in Next.js

## Definition

Next.js provides an **Image component** (`next/image`) that automatically optimizes images through lazy loading, format conversion (WebP/AVIF), responsive sizing, and blur placeholders. It prevents layout shift and improves Core Web Vitals.


## First Principles

The image optimizer trades CPU at delivery for bandwidth and LCP:

1. **Serve the smallest format/size the client can use** — AVIF/WebP negotiation, responsive `srcset`, lazy-by-default: each is a decision the framework encodes so pages don't hand-roll it wrong (→ 50.3.1.01's LCP is image-dominated).
2. **Optimization is on-demand and cacheable** — first request pays transform cost, the result caches at the CDN (→ 30.3.4.03); `unoptimized` opts out when images are pre-processed at build (the build-time vs request-time transform trade).

## Why It Matters

Senior engineers use `next/image` for LCP wins. They preload only the likely LCP image (`priority` in Next.js 15; `preload` in 16), use `sizes` for responsive images, configure `remotePatterns` for external CDNs, and customize the loader for non-Next-image backends. The interview question is: how does Next.js decide image dimensions? Answer: `width`/`height` props or parent's `fill`.

## How It Works

The default optimizer transforms requested image variants at request time, not during `next build`. `formats` defaults to WebP; AVIF needs explicit opt-in and the proxy must forward `Accept` for format negotiation. Byte sizes in the comparison below are illustrative, not measured guarantees.

`width`/`height` supply intrinsic aspect ratio; CSS determines displayed size. `sizes` tells the browser which candidate to request from `srcset`, so it must describe the actual layout, not simply copy breakpoints. `fill` requires a positioned parent with a defined size; `sizes` is particularly important there. Static image imports can supply dimensions and supported blur data automatically.

**Version scope:** Priority examples target Next.js 15; Next.js 16 deprecates `priority` in favor of `preload`. For 16 choose `preload`, eager loading, or `fetchPriority` deliberately rather than combining all hints. Long `minimumCacheTTL` values retain old image variants: there is no tag-based image invalidation API, so update the source URL/version when content changes.

### Image Optimization Pipeline

```text
┌─────────────────────────────────────────────────────────┐
│ NEXT.JS IMAGE OPTIMIZATION                              │
├─────────────────────────────────────────────────────────┤
│                                                         │
│ 1. Image Request                                        │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ <Image src="/photo.jpg" width={800} height={600} /> │ │
│ └─────────────────────────────────────────────────────┘ │
│ │                                                       │
│ ▼                                                       │
│ 2. Default optimization (on demand)                     │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ - Resize to requested dimensions                    │ │
│ │ - Convert to optimal format (WebP/AVIF)             │ │
│ │ - Compress for web delivery                         │ │
│ │ - Generate responsive variants                      │ │
│ └─────────────────────────────────────────────────────┘ │
│ │                                                       │
│ ▼                                                       │
│ 3. Caching                                              │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ - Cache optimized image on CDN                      │ │
│ │ - Serve from cache on subsequent requests           │ │
│ └─────────────────────────────────────────────────────┘ │
│ │                                                       │
│ ▼                                                       │
│ 4. Delivery                                             │
│ ┌─────────────────────────────────────────────────────┐ │
│ │ - Serve optimized image to browser                  │ │
│ │ - Use appropriate format for browser                │ │
│ │ - Lazy load if below fold                           │ │
│ └─────────────────────────────────────────────────────┘ │
│                                                         │
└─────────────────────────────────────────────────────────┘

```

## Code Examples

### Basic Image Usage

```typescript
// app/page.tsx
import Image from 'next/image'

export default function Page() {
  return (
    <div>
      <h1>My Page</h1>
      <Image
        src="/hero.jpg"
        alt="Hero image"
        width={1200}
        height={600}
        priority
      />
    </div>
  )
}

```

### Auto Blur Placeholder

```typescript
// app/page.tsx
import Image from 'next/image'
import heroImg from '@/public/hero.jpg'

export default function Page() {
  return <Image src={heroImg} alt="Hero with auto blur" placeholder="blur" />
}
```

Blur metadata is generated from supported static imports, not enabled by `minimumCacheTTL`. A string path or remote URL needs its own small `blurDataURL`; a placeholder is optional and does not alter downloaded image quality.

### Avatar Component

```typescript
// components/avatar.tsx
import Image from 'next/image'

interface AvatarProps {
  src: string
  alt: string
  size?: 'sm' | 'md' | 'lg'
}

const sizeMap = {
  sm: 32,
  md: 48,
  lg: 64,
}

export function Avatar({ src, alt, size = 'md' }: AvatarProps) {
  const pixelSize = sizeMap[size]

  return (
    <div
      className="relative rounded-full overflow-hidden"
      style={{ width: pixelSize, height: pixelSize }}
    >
      <Image
        src={src}
        alt={alt}
        fill
        sizes={`${pixelSize}px`}
        style={{ objectFit: 'cover' }}
        className="rounded-full"
      />
    </div>
  )
}

```

### Product Image with Zoom

```typescript
// components/product-image.tsx
'use client'

import { useState } from 'react'
import Image from 'next/image'

export function ProductImage({ src, alt }: { src: string; alt: string }) {
  const [isZoomed, setIsZoomed] = useState(false)

  return (
    <div
      className="relative cursor-zoom-in"
      onMouseEnter={() => setIsZoomed(true)}
      onMouseLeave={() => setIsZoomed(false)}
    >
      <Image
        src={src}
        alt={alt}
        width={isZoomed ? 1600 : 800}
        height={isZoomed ? 1200 : 600}

          transition: 'transform 0.3s',
          transform: isZoomed ? 'scale(1.5)' : 'scale(1)',
        }}
        priority
      />
    </div>
  )
}
```

### Image with Loading States

```typescript
// components/image-with-loading.tsx
'use client'

import { useState } from 'react'
import Image from 'next/image'

export function ImageWithLoading({
  src,
  alt,
  width,
  height,
}: {
  src: string
  alt: string
  width: number
  height: number
}) {
  const [isLoading, setIsLoading] = useState(true)

  return (
    <div className="relative">
      {isLoading && (
        <div
          className="absolute inset-0 bg-gray-200 animate-pulse"
          style={{ width, height }}
        />
      )}
      <Image
        src={src}
        alt={alt}
        width={width}
        height={height}
        onLoad={() => setIsLoading(false)}
        onError={() => setIsLoading(false)}
        className={isLoading ? 'opacity-0' : 'opacity-100'}
      />
    </div>
  )
}

```

### Next.js Image Configuration

```typescript
// next.config.js
module.exports = {
  images: {
    // Device sizes for responsive images
    deviceSizes: [640, 750, 828, 1080, 1200, 1920, 2048, 3840],

    // Image sizes for srcset
    imageSizes: [16, 32, 48, 64, 96, 128, 256, 384],

    // Allowed remote patterns
    remotePatterns: [
      {
        protocol: 'https',
        hostname: '**.example.com',
      },
    ],

    // Formats to use
    formats: ['image/avif', 'image/webp'],

    // Minimum cache TTL (seconds)
    minimumCacheTTL: 60 * 60 * 24 * 30, // 30 days

    // Disable static imports
    disableStaticImages: false,

    // Content security policy
    contentSecurityPolicy: "default-src 'self'; script-src 'none'; sandbox;",
  },
}

```

## Common Mistakes

### 1. Not Setting Width and Height

```typescript
// BAD: String src without dimensions or fill fails component validation
<Image src="/photo.jpg" alt="Photo" />

// GOOD: Give dimensions (or use a static import/sized fill parent)
<Image src="/photo.jpg" alt="Photo" width={800} height={600} />

```

### 2. Using Priority on All Images

```typescript
// BAD: All images marked as priority
<Image src="/photo1.jpg" alt="1" width={800} height={600} priority />
<Image src="/photo2.jpg" alt="2" width={800} height={600} priority />
<Image src="/photo3.jpg" alt="3" width={800} height={600} priority />

// GOOD: Only above-the-fold images get priority
<Image src="/hero.jpg" alt="Hero" width={1200} height={600} priority />
<Image src="/content.jpg" alt="Content" width={800} height={600} />

```

### 3. Not Using Remote Patterns

```typescript
// BAD: Remote image not configured
<Image src="https://example.com/photo.jpg" alt="Photo" width={800} height={600} />
// Error: Invalid src prop

// GOOD: Configure remote patterns
// next.config.js
module.exports = {
  images: {
    remotePatterns: [
      { protocol: 'https', hostname: 'example.com' },
    ],
  },
}

```

### 4. Ignoring Aspect Ratio

```typescript
// BAD: Incorrect aspect ratio
<Image src="/photo.jpg" alt="Photo" width={800} height={800} />
// Image will be stretched if original is not square

// GOOD: Match aspect ratio or use fill
<Image
  src="/photo.jpg"
  alt="Photo"
  width={800}
  height={600}
  style={{ objectFit: 'cover' }}
/>

```

### 5. Not Using Blur Placeholder

```typescript
// BAD: No loading placeholder
<Image src="/photo.jpg" alt="Photo" width={800} height={600} />
// Shows nothing while loading

// GOOD: Use blur placeholder
<Image
  src="/photo.jpg"
  alt="Photo"
  width={800}
  height={600}
  placeholder="blur"
  blurDataURL="data:image/jpeg;base64,..."
/>

```

## Best Practices

1. **Reserve the image area** — Use intrinsic dimensions, static imports, or a sized fill parent

2. **Preload selectively** — Use priority on 15, preload on 16 for the likely LCP image

3. **Implement blur placeholders** — Better loading experience

4. **Configure remote patterns** — For external images

5. **Use responsive sizes** — Serve appropriate sizes

6. **Lazy load below-the-fold images** — Save bandwidth

7. **Use fill mode for backgrounds** — For flexible layouts

8. **Optimize image formats** — Enable WebP/AVIF

9. **Test on different devices** — Verify responsive behavior
10. **Monitor image performance** — Track loading metrics

## Performance Considerations

```text
Image Optimization Benefits:

- File size: savings depend on the source, codec, output dimensions, and quality setting
- Lazy loading: Saves bandwidth for below-fold images
- Responsive sizing: Smaller images on mobile
- Blur placeholders: Better perceived performance
- CDN caching: Fast subsequent loads

Core Web Vitals Impact:

- LCP: Improved with priority loading
- CLS: Prevented with width/height
- FCP: Improved with lazy loading

```

# Image Optimization in Next.js

A product card may occupy 400 CSS pixels while its source photo is 4,000 pixels wide. Sending the original wastes bandwidth; choosing a candidate that is too small looks soft on a high-density display.

```text
400px CSS card × 2x Retina display ─► needs ~800px variant (not 4,000px original)
```

## Definition

The Next.js `Image` component (`next/image`) adds responsive source selection and, with the default loader, on-demand resizing and encoding. Its benefit depends on accurate layout hints, a suitable loading policy, trusted sources, and a cache policy that fits how images change.

> **Textbook Definition:** Image optimization selects and delivers an encoded image variant suited to the rendered dimensions and supported format. Responsive sizing, loading policy, cache identity, and layout reservation govern bandwidth, processing cost, and visual stability.

## First Principles

Three facts govern image delivery:

- **The rendered slot determines useful pixels:** The browser combines CSS width, device density, and the `sizes` hint to choose a `srcset` candidate.
- **The layout must exist before the image arrives:** Intrinsic dimensions or a sized `fill` parent reserve space and prevent layout shift.
- **Each transformed variant costs work and storage:** Reuse needs stable source identity, and changed content needs a refresh path.

## Follow the image to the browser

```text
CSS slot + device density
  → browser selects a srcset candidate using sizes
  → Next.js loader resizes and encodes on a cache miss
  → browser decodes bytes inside the reserved layout box
```

For a card that is full width on small screens, half width on medium screens, and one-third width on wide screens, describe those widths in `sizes`:

```tsx
import Image from 'next/image';

export function ProductCardImage({ src, alt }: { src: string; alt: string }) {
  return (
    <Image
      src={src}
      alt={alt}
      width={1200}
      height={900}
      sizes="(max-width: 767px) 100vw, (max-width: 1279px) 50vw, 33vw"
      style={{ width: '100%', height: 'auto' }}
    />
  );
}
```

The browser uses `sizes` to choose a candidate; the optimizer does not infer the card's CSS width. Inspect `currentSrc` and transferred bytes at representative viewport widths and pixel densities. Use meaningful `alt` text for informative images and `alt=""` when a decorative image adds no information beyond nearby content.

When the parent owns the crop, use `fill` and give that parent a position and stable aspect ratio:

```tsx
// excerpt — fill mode requires a positioned parent with an explicit aspect ratio or size
<div className="relative aspect-[4/3]">
  <Image
    src={src}
    alt={alt}
    fill
    sizes="(max-width: 767px) 100vw, 50vw"
    style={{ objectFit: 'cover' }}
  />
</div>
```

`fill` does not set the parent's height. A zero-height or unbounded parent can still collapse the layout.

## 1. Limit Source and Cache Work

Remote images must match `remotePatterns`. Restrict protocol, host, path, and query string to sources the application intends to fetch. Local images can also be limited with `localPatterns`.

```typescript
// next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'images.example.com',
        pathname: '/catalog/**',
        search: '',
      },
    ],
    localPatterns: [{ pathname: '/assets/images/**', search: '' }],
    qualities: [75, 90],
    formats: ['image/avif', 'image/webp'],
    minimumCacheTTL: 3600,
    maximumRedirects: 1,
    maximumResponseBody: 5_000_000,
    dangerouslyAllowLocalIP: false,
  },
};

export default nextConfig;
```

In Next.js 16, configure the `qualities` allowlist; the default optimized quality is `75`. WebP is the default output format, while AVIF is opt-in and can cut transfer size at the cost of extra encoding CPU and cached variants.

If a proxy or CDN sits in front of Next.js, forward the `Accept` header so format negotiation works.

The default optimizer does not forward `Authorization` headers, so do not use it for private sources that require caller credentials — use an explicitly authorized image service or an unoptimized path instead.

Redirect targets are not rechecked against `remotePatterns`, so allow only trusted sources and cap `maximumRedirects`. Keep `dangerouslyAllowLocalIP` disabled unless a reviewed private-network design requires it.

The optimizer caches by source URL and transformation parameters, with no tag-based invalidation; a longer upstream `Cache-Control` lifetime can also outlast `minimumCacheTTL`.

Version the source URL when replacing content because route revalidation does not purge transformed images. Next.js 16.1.2+ can cap upstream response bytes with `maximumResponseBody`.

## 2. Choose Loading Behavior and Runtime

Images are lazy-loaded by default; keep that behavior below the fold. For a measured above-the-fold Largest Contentful Paint (LCP) image, choose one hint — usually `loading="eager"` or `fetchPriority="high"`.

In Next.js 16, `priority` is deprecated. Use `preload` only when the LCP image is unambiguous, and never combine `preload` with `loading` or `fetchPriority`.

A supported static image import can provide intrinsic dimensions and blur metadata. A remote URL or string path needs its own `blurDataURL` for a blur placeholder. The placeholder is optional feedback, not layout reservation; dimensions or the parent aspect ratio reserve the box.

When a remote image can fail, present a deliberate fallback and keep loading/error state tied to the current source. A late load event from an old source must not hide an error for its replacement.

The default optimizer runs on the Next.js server on first request for a variant, then caches the output — which requires a runtime capable of serving the image endpoint.

Static export has no Next.js image optimizer, so use `unoptimized` or a custom loader pointing to an external image service. Managed hosts and self-hosted setups differ in cache persistence, cost, and transformation limits.

Measure LCP contribution, transferred bytes, request priority, and layout shift on the deployed page. Intrinsic geometry reduces image-related Cumulative Layout Shift (CLS), but it does not guarantee faster LCP; selected bytes, connection, decode, and host cache still matter.

## Summary

Match `sizes` to the actual layout, reserve geometry before loading, and restrict sources and variants the optimizer may fetch. Choose one loading hint from measured LCP behavior, version URLs when content changes, and verify the runtime and cache policy serving the image.

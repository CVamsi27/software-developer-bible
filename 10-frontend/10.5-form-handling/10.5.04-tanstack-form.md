# TanStack Form

In a large editor, a change to one field should update that field and the displays that depend on it. The design question is which parts of the form subscribe to each change.

```tsx
<form.Field
  name="quantity"
  children={(field) => (
    <div>
      <label htmlFor={field.name}>Quantity</label>
      <input
        id={field.name}
        value={field.state.value}
        onChange={(e) => field.handleChange(e.target.value)}
        onBlur={field.handleBlur}
      />
    </div>
  )}
/>
```

## Definition

**TanStack Form** manages form values, validation and submission without supplying visual input components. This is called a **headless** library. Its framework adapters connect the model to the UI; these examples use the React adapter and the v1 API. Inference starts from typed `defaultValues`, so ordinary forms do not need manually repeated generic arguments.

> **Textbook Definition:** TanStack Form is a headless form-state system with typed field access and reactive subscriptions. Validation and submission operate on its model, while framework adapters connect that model to independently chosen UI components.

## First Principles

A form needs an owner for shared values, but each display needs only part of that model — so a field or selector subscribes to relevant state, and an email edit never updates unrelated subscribers. Static field types catch mismatched paths during development, while network and user input still need runtime validation. And a valid model never proves its server operation committed — subscription, validation, and submission stay separate lifecycle boundaries.

## 1. Follow a Change Through Submission

```text
input change → field.handleChange → shared form model
                                      ↓
                         field/store subscriptions → relevant display
                                      ↓
submit → validate complete model → await application service → settle feedback
```

A field subscribes to its value and metadata. In React, `form.Subscribe` can select state for a UI fragment, while `useSelector(form.store, selector)` makes selected state available in component logic. A direct read of `form.state` is a snapshot, not a subscription. Narrow selectors limit form-driven updates; parent renders and other React state can still render a component.

## 2. Follow a Derived Value Through the Form

An invoice editor can let each input own its displayed value while a subtotal subscribes only to the fields it uses. The input model stays textual so an empty field remains a valid editing state; submission parses it into integer quantities and cents.

```typescript
import { useForm } from '@tanstack/react-form';
import { z } from 'zod';

const invoiceSchema = z.object({
  quantity: z.string().trim().regex(/^[1-9]\d*$/, { error: 'Enter a whole quantity above zero' })
    .transform(Number).pipe(z.number().int().max(10_000)),
  unitPriceCents: z.string().trim().regex(/^\d+$/, { error: 'Enter a non-negative amount in cents' })
    .transform(Number).pipe(z.number().int().max(1_000_000)),
  description: z.string().trim().min(1, { error: 'Enter a description' }),
});
type InvoiceInput = z.input<typeof invoiceSchema>;
type Invoice = z.output<typeof invoiceSchema>;
const usd = new Intl.NumberFormat('en-US', { style: 'currency', currency: 'USD' });

function wholeNumber(text: string): number | undefined {
  if (!/^\d+$/.test(text)) return undefined;
  const value = Number(text);
  return Number.isSafeInteger(value) ? value : undefined;
}

export function InvoiceForm({ save }: { save: (invoice: Invoice) => Promise<void> }) {
  const form = useForm({
    defaultValues: { quantity: '1', unitPriceCents: '0', description: '' } satisfies InvoiceInput,
    validators: { onSubmit: invoiceSchema },
    onSubmit: async ({ value }) => {
      // Standard Schema validates this input; parsing supplies transformed output.
      await save(invoiceSchema.parse(value));
    },
  });

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        e.stopPropagation();
        void form.handleSubmit();
      }}
    >
      <form.Field name="description" children={(field) => <div>
        <label htmlFor={field.name}>Description</label>
        <input id={field.name} name={field.name} value={field.state.value}
          onChange={(event) => field.handleChange(event.target.value)} onBlur={field.handleBlur}
          aria-invalid={field.state.meta.errors.length > 0}
          aria-describedby={field.state.meta.errors.length ? `${field.name}-error` : undefined} />
        {field.state.meta.errors.length > 0 && <p id={`${field.name}-error`}>
          {field.state.meta.errors.map((error) => error?.message).join(', ')}
        </p>}
      </div>} />
      <form.Field name="quantity" children={(field) => <div>
        <label htmlFor={field.name}>Quantity</label>
        <input id={field.name} name={field.name} inputMode="numeric" value={field.state.value}
          onChange={(event) => field.handleChange(event.target.value)} onBlur={field.handleBlur}
          aria-invalid={field.state.meta.errors.length > 0}
          aria-describedby={field.state.meta.errors.length ? `${field.name}-error` : undefined} />
        {field.state.meta.errors.length > 0 && <p id={`${field.name}-error`}>
          {field.state.meta.errors.map((error) => error?.message).join(', ')}
        </p>}
      </div>} />
      <form.Field name="unitPriceCents" children={(field) => <div>
        <label htmlFor={field.name}>Unit price in cents</label>
        <input id={field.name} name={field.name} inputMode="numeric" value={field.state.value}
          onChange={(event) => field.handleChange(event.target.value)} onBlur={field.handleBlur}
          aria-invalid={field.state.meta.errors.length > 0}
          aria-describedby={field.state.meta.errors.length ? `${field.name}-error` : undefined} />
        {field.state.meta.errors.length > 0 && <p id={`${field.name}-error`}>
          {field.state.meta.errors.map((error) => error?.message).join(', ')}
        </p>}
      </div>} />
      <form.Subscribe selector={(state) => {
        const quantity = wholeNumber(state.values.quantity);
        const unitPrice = wholeNumber(state.values.unitPriceCents);
        const subtotal = quantity === undefined || unitPrice === undefined ? undefined : quantity * unitPrice;
        return subtotal !== undefined && Number.isSafeInteger(subtotal) ? subtotal : undefined;
      }}>
        {(cents) => <output aria-label="Invoice subtotal">
          {cents === undefined ? 'Enter valid whole-number values to see the subtotal.' : `Subtotal: ${usd.format(cents / 100)}`}
        </output>}
      </form.Subscribe>
      <form.Subscribe selector={(s) => s.isSubmitting}>
        {(isSubmitting) => (
          <button type="submit" disabled={isSubmitting}>
            {isSubmitting ? 'Saving…' : 'Save invoice'}
          </button>
        )}
      </form.Subscribe>
    </form>
  );
}
```

## 3. Make Remote Validation Advisory

```typescript
const form = useForm({
  defaultValues: { username: '' },
  validators: {
    onChangeAsyncDebounceMs: 500,
    onChangeAsync: async ({ value, signal }) => {
      try {
        const res = await fetch(`/api/check-username?u=${encodeURIComponent(value.username)}`, { signal });
        if (!res.ok) return 'Username check unavailable; try again';
        const result = z.object({ exists: z.boolean() }).safeParse(await res.json());
        if (!result.success) return 'Username check unavailable; try again';
        return result.data.exists ? { fields: { username: 'Username is taken' } } : undefined;
      } catch {
        return signal.aborted ? undefined : 'Username check unavailable; try again';
      }
    },
  },
  onSubmit: async ({ value }) => {
    // Await the application mutation; do not log submitted values.
  },
});
```

Form-level validators receive the complete values object; field-level validators receive that field's value. A schema transform validates but does not replace the submitted values: explicitly parse in `onSubmit` when normalized output is needed. Abort stale checks using the provided signal and keep the server-side uniqueness constraint authoritative.

## 4. Preserve Identity in a Field Array

```tsx
// The form's typed defaults include items: { id: string; name: string; qty: number; price: number }[].
<form.Field
  name="items"
  mode="array"
  children={(field) => (
    <div>
      {field.state.value.map((item, i) => (
        <form.Field
          key={item.id}
          name={`items[${i}].name`}
          children={(sub) => (
            <>
              <label htmlFor={`item-${item.id}`}>Item name</label>
              <input id={`item-${item.id}`} name={sub.name} value={sub.state.value}
                onBlur={sub.handleBlur} onChange={(e) => sub.handleChange(e.target.value)} />
            </>
          )}
        />
      ))}
      <button type="button" onClick={() => field.pushValue({ id: crypto.randomUUID(), name: '', qty: 1, price: 0 })}>
        Add
      </button>
    </div>
  )}
/>
```

The array fragment assumes typed items containing stable IDs, a default empty array and imported form helpers. Generate IDs when adding/loading a row, not during render. Indexed paths change after removal; stable keys preserve row UI identity. A production field also connects validation feedback and its accessible description.

Other framework adapters include Preact, Vue, Angular, Solid, Svelte and Lit, each with its own integration API. The React examples above are not copy-paste examples for those frameworks.

## 5. Choose Between Form Models

| Question | React Hook Form | TanStack Form |
| --------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Editable values | Native registration or controlled-widget adapters | Controlled form model |
| Reactive UI | Subscribe to the form values/state a component reads | Select field or store state with subscriptions |
| Schema output | A compatible resolver can provide parsed output | Validation checks input; parse explicitly to obtain transformed output |
| Useful starting point | Existing RHF integrations or native inputs | Typed shared primitives and selected subscriptions |

TanStack is useful when typed shared field components, framework adapters or granular subscriptions solve a real need. RHF fits existing native registration and resolver contracts; keep Formik when controlled fields and its integrations already work. Compare accessibility and rendered behavior on the representative form before migrating.

## Summary

TanStack Form keeps typed values in a form model and updates React views through field and store subscriptions. Standard Schema validators check the editable input but do not replace it with transformed output; parse at submission when the mutation needs normalized data. Choose it from the form's interaction and integration needs, then measure the real component tree.

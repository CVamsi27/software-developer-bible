# TanStack Form

> TanStack Form is a framework-agnostic, headless form library from the TanStack team. It ships first-class TypeScript inference, granular subscriptions, async validation, and a small bundle — the modern alternative to RHF and Formik when type-safety and dynamic schemas matter.

## Definition

**TanStack Form** manages form values, validation and submission without supplying the visual input components. This is called a **headless** library. Its types check field names and values, and framework adapters support React, Vue, Solid, Svelte and Lit. In React, `useForm()` returns helpers for field state, validation and submission. These examples target v1. Let typed `defaultValues` supply the inferred value type rather than passing an incomplete list of generic type arguments.

## First Principles

TanStack Form is type-safety-first form state:

1. **The form is a typed state machine** — field values, errors, and validators are checked against the schema *at the API level* (no `any` field names), which is the increment over RHF for TS-heavy teams.
2. **Framework adapters over React lock-in** — the core is adapter-agnostic (→ 10.3.4.02's interop instinct): the same form model across React/Solid/Vue.

## Why It Matters

- **Framework-agnostic** — same API in React, Vue, Solid, Svelte, Lit
- **Type-first** — typed `defaultValues` infer field names and value types
- **Granular subscriptions** — components only re-render for their slice of state
- **Schema validators** — Standard Schema support (for example Zod, Valibot, ArkType and Effect/Schema; check the installed version)
- **Built for dynamic forms** — array fields, conditional fields, complex deps

## RHF vs TanStack Form

| Dimension | React Hook Form | TanStack Form |
| ---------------- | ----------------------------------------- | ---------------------------------------------- |
| Architecture | Uncontrolled, refs | Controlled + granular subscriptions |
| Framework | React only | React, Vue, Solid, Svelte, Lit |
| Type inference | Typed field paths and resolver output | Typed defaults, field paths and validators |
| Re-renders | Refs avoid most | Subscription-based, fine-grained |
| Bundle | Measure the chosen build and imports | Measure core plus adapter and validators |
| Dynamic forms | `useFieldArray` | Array-mode fields and typed nested paths |
| Async validation | Async rules/resolvers; debounce as needed | Async validator lifecycle and debounce options |
| Schema | Resolver pattern | Standard Schema (no resolver needed) |
| Maturity | High (2019) | Newer (2024), rapidly maturing |

## Code Examples

### 1. Basic Form (React)

```typescript
import { useForm } from '@tanstack/react-form';
import { z } from 'zod';

const loginSchema = z.object({
  email: z.string().email('Invalid email'),
  password: z.string().min(8, 'Min 8 characters'),
});

type LoginValues = z.infer<typeof loginSchema>;

function LoginForm() {
  const form = useForm({
    defaultValues: { email: '', password: '' } as LoginValues,
    validators: { onChange: loginSchema },
    onSubmit: async ({ value }) => {
      await api.login(value);
    },
  });

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        e.stopPropagation();
        form.handleSubmit();
      }}
    >
      <form.Field
        name="email"
        children={(field) => (
          <div>
            <label htmlFor={field.name}>Email</label>
            <input
              id={field.name}
              type="email"
              value={field.state.value}
              onChange={(e) => field.handleChange(e.target.value)}
              onBlur={field.handleBlur}
            />
            {field.state.meta.errors.length > 0 && (
              <span role="alert">{field.state.meta.errors.map((error) => error?.message).join(', ')}</span>
            )}
          </div>
        )}
      />
      {/* password similar */}
      <form.Subscribe selector={(s) => [s.canSubmit, s.isSubmitting]}>
        {([canSubmit, isSubmitting]) => (
          <button type="submit" disabled={!canSubmit}>
            {isSubmitting ? 'Logging in…' : 'Login'}
          </button>
        )}
      </form.Subscribe>
    </form>
  );
}
```

### 2. Granular Subscription (No Unnecessary Re-renders)

```typescript
// Only this component re-renders when email value or error changes
<form.Field
  name="email"
  children={(field) => {
    // form.Field subscribes to this field's state
    return <EmailInput {...field} />;
  }}
/>

// Subscribe to specific state with form.Subscribe
<form.Subscribe
  selector={(state) => [state.values.email, state.fieldMeta.email?.errors] as const}
  children={([email, errors]) => <EmailStatus value={email} errors={errors} />}
/>
```

### 3. Async Validation with Debounce

```typescript
const form = useForm({
  defaultValues: { username: '' },
  validators: {
    onChangeAsyncDebounceMs: 500,
    onChangeAsync: async ({ value, signal }) => {
      const res = await fetch(`/api/check-username?u=${encodeURIComponent(value.username)}`, { signal });
      if (!res.ok) return 'Username check unavailable; try again';
      const { exists } = await res.json();
      return exists ? { fields: { username: 'Username is taken' } } : undefined;
    },
  },
  onSubmit: async ({ value }) => console.log(value),
});
```

Form-level validators receive the complete values object; field-level validators receive that field's value. A schema transform validates but does not replace the submitted values: explicitly parse in `onSubmit` when normalized output is needed. Abort stale checks using the provided signal and keep the server-side uniqueness constraint authoritative.

### 4. Dynamic Field Arrays

```typescript
<form.Field
  name="items"
  mode="array"
  children={(field) => (
    <div>
      {field.state.value.map((_, i) => (
        <form.Field
          key={i}
          name={`items[${i}].name`}
          children={(sub) => (
            <input
              value={sub.state.value}
              onChange={(e) => sub.handleChange(e.target.value)}
            />
          )}
        />
      ))}
      <button type="button" onClick={() => field.pushValue({ name: '', qty: 1, price: 0 })}>
        Add
      </button>
    </div>
  )}
/>
```

### 5. Framework-Agnostic Usage (Vue)

```typescript
// In a Vue component — same `useForm` API
import { useForm } from '@tanstack/vue-form';

const form = useForm({
  defaultValues: { email: '' },
  onSubmit: async ({ value }) => console.log(value),
});
```

## When to Choose TanStack Form

| Use TanStack Form | Stick with RHF |
| ------------------------------------------ | ------------------------------ |
| Multi-framework team (React + Vue + Solid) | React-only project |
| Need maximum type-safety from schemas | RHF is "good enough" on types |
| Building a UI kit / design system | Single-app form library needs |
| Standard Schema support is required | Yup / Zod via resolver is fine |
| Complex dynamic forms (form builder) | Mostly static forms |
| Want to invest in a 2026+ library | Prefer the most-mature option |

## Real-World Use Cases

- **Type-critical design systems** — form primitives whose field types flow from schema to submit payload without `any`; the inference-first pitch in practice.
- **High-frequency forms** — per-field subscriptions keep a 40-field config panel re-rendering one input per keystroke, not the page.

## Common Mistakes

| Mistake | Fix |
| ---------------------------------------------------------- | -------------------------------------------------------------------------- |
| Mixing controlled `<input value={...}>` without `onChange` | Use `field.state.value` + `field.handleChange(e.target.value)` together |
| Reading `form.state` without subscribing | Use `form.Subscribe` or the documented store selector hook for reactive UI |
| Not subscribing to submit state | Use `form.Subscribe` to read `canSubmit` and `isSubmitting` |
| Assuming RHF patterns apply | TanStack Form is subscription-based, not ref-based |

## Best Practices

1. **Pair with Standard Schema** (Zod / Valibot) — no resolver needed
2. **Use `form.Field` and `form.Subscribe` for granular updates** — select only the state the UI needs
3. **Validate per lifecycle** — `onChange`, `onBlur`, `onSubmit`, or async
4. **Debounce async validators** — `onChangeAsyncDebounceMs: 500`
5. **Adopt for UI libraries** — framework-agnostic = single investment
6. **Wrap in a custom `<Form>` component** — encapsulates the boilerplate

## Summary

- TanStack Form is the framework-agnostic, type-first form library for 2026
- First-class React, Vue, Solid, Svelte, Lit support — same API across all
- Granular subscriptions bound which views react to a state change; profile the actual form
- Standard Schema support avoids a resolver adapter; use a compatible validator version
- Best for: multi-framework teams, UI libraries, dynamic forms

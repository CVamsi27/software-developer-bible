# TanStack Form

In a large editor, a change to one field should update that field and the displays that depend on it. The design question is which parts of the form subscribe to each change.

## Definition

**TanStack Form** manages form values, validation and submission without supplying the visual input components. This is called a **headless** library. Its types check field names and values, and adapters are available for React, Preact, Vue, Angular, Solid, Svelte and Lit. In React, `useForm()` returns helpers for field state, validation and submission. These examples target v1. Let typed `defaultValues` supply the inferred value type rather than passing an incomplete list of generic type arguments.

> **Textbook Definition:** TanStack Form is a headless form-state system with typed field access and reactive subscriptions. Validation and submission operate on its model, while framework adapters connect that model to independently chosen UI components.

## First Principles

A form needs an owner for shared values, but each display needs only part of that model. A field or selector subscribes to relevant state so an email edit need not update unrelated subscribers.

Static field types catch mismatched paths/values during development. Network and user input still need runtime validation. A valid model also does not establish that its server operation committed, so subscription, validation and submission are separate lifecycle boundaries.

## Follow a change through submission

```text
input change → field.handleChange → shared form model
                                      ↓
                         field/store subscriptions → relevant display
                                      ↓
submit → validate complete model → await application service → settle feedback
```

A field subscribes to its value and metadata. In React, `form.Subscribe` can select state for a UI fragment, while `useSelector(form.store, selector)` makes selected state available in component logic. A direct read of `form.state` is a snapshot, not a subscription. Narrow selectors limit form-driven updates; parent renders and other React state can still render a component.


## RHF vs TanStack Form

| Question | React Hook Form | TanStack Form |
| --------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Editable values | Native registration or controlled-widget adapters | Controlled form model |
| Reactive UI | Subscribe to the form values/state a component reads | Select field or store state with subscriptions |
| Schema output | A compatible resolver can provide parsed output | Validation checks input; parse explicitly to obtain transformed output |
| Useful starting point | Existing RHF integrations or native inputs | Typed shared primitives and selected subscriptions |

Both libraries support field arrays, asynchronous validation and schema integration. Compare the contracts your form needs and measure representative behavior rather than treating the library name as a performance result.

## Code Examples

The validation examples use the Zod 4 API.

### 1. Basic Form (React)

```typescript
import { useState } from 'react';
import { useForm } from '@tanstack/react-form';
import { z } from 'zod';

const loginSchema = z.object({
  email: z.email({ error: 'Enter a valid email' }),
  password: z.string().min(1, { error: 'Enter your password' }),
});

type LoginValues = z.infer<typeof loginSchema>;

export function LoginForm({ login }: { login: (values: LoginValues) => Promise<void> }) {
  const [submitError, setSubmitError] = useState<string | null>(null);
  const form = useForm({
    defaultValues: { email: '', password: '' },
    validators: { onChange: loginSchema },
    onSubmit: async ({ value }) => {
      setSubmitError(null);
      try { await login(loginSchema.parse(value)); }
      catch { setSubmitError('Could not sign in. Check the result before retrying.'); }
    },
  });

  return (
    <form
      onSubmit={(e) => {
        e.preventDefault();
        e.stopPropagation();
        void form.handleSubmit();
      }}
    >
      <form.Field
        name="email"
        children={(field) => (
          <div>
            <label htmlFor={field.name}>Email</label>
            <input
              id={field.name}
              name={field.name}
              type="email"
              autoComplete="username"
              value={field.state.value}
              onChange={(e) => field.handleChange(e.target.value)}
              onBlur={field.handleBlur}
              aria-invalid={field.state.meta.errors.length > 0}
              aria-describedby={field.state.meta.errors.length ? 'login-email-error' : undefined}
            />
            {field.state.meta.errors.length > 0 && (
              <p id="login-email-error" role="alert">
                {field.state.meta.errors.map((error) => error?.message).join(', ')}
              </p>
            )}
          </div>
        )}
      />
      <form.Field name="password" children={field => <div>
        <label htmlFor="login-password">Password</label>
        <input id="login-password" name={field.name} type="password" autoComplete="current-password"
          value={field.state.value} onChange={event => field.handleChange(event.target.value)}
          onBlur={field.handleBlur} aria-describedby="login-password-error"
          aria-invalid={field.state.meta.errors.length > 0} />
        <p id="login-password-error" role="alert">
          {field.state.meta.errors.map(error => error?.message).join(', ')}
        </p>
      </div>} />
      {submitError && <p role="alert">{submitError}</p>}
      <form.Subscribe selector={(s) => s.isSubmitting}>
        {(isSubmitting) => (
          <button type="submit" disabled={isSubmitting}>
            {isSubmitting ? 'Logging in…' : 'Login'}
          </button>
        )}
      </form.Subscribe>
    </form>
  );
}
```

### 2. Async validation with debounce

```typescript
const form = useForm({
  defaultValues: { username: '' },
  validators: {
    onChangeAsyncDebounceMs: 500,
    onChangeAsync: async ({ value, signal }) => {
      try {
        const res = await fetch(`/api/check-username?u=${encodeURIComponent(value.username)}`, { signal });
        if (!res.ok) return 'Username check unavailable; try again';
        const result = z.object({ exists: z.boolean() }).safeParse(await res.json());
        if (!result.success) return 'Username check unavailable; try again';
        return result.data.exists ? { fields: { username: 'Username is taken' } } : undefined;
      } catch {
        return signal.aborted ? undefined : 'Username check unavailable; try again';
      }
    },
  },
  onSubmit: async ({ value }) => {
    // Await the application mutation; do not log submitted values.
  },
});
```

Form-level validators receive the complete values object; field-level validators receive that field's value. A schema transform validates but does not replace the submitted values: explicitly parse in `onSubmit` when normalized output is needed. Abort stale checks using the provided signal and keep the server-side uniqueness constraint authoritative.

### 3. Dynamic field arrays

```tsx
// The form's typed defaults include items: { id: string; name: string; qty: number; price: number }[].
<form.Field
  name="items"
  mode="array"
  children={(field) => (
    <div>
      {field.state.value.map((item, i) => (
        <form.Field
          key={item.id}
          name={`items[${i}].name`}
          children={(sub) => (
            <>
              <label htmlFor={`item-${item.id}`}>Item name</label>
              <input id={`item-${item.id}`} name={sub.name} value={sub.state.value}
                onBlur={sub.handleBlur} onChange={(e) => sub.handleChange(e.target.value)} />
            </>
          )}
        />
      ))}
      <button type="button" onClick={() => field.pushValue({ id: crypto.randomUUID(), name: '', qty: 1, price: 0 })}>
        Add
      </button>
    </div>
  )}
/>
```

The array fragment assumes typed items containing stable IDs, a default empty array and imported form helpers. Generate IDs when adding/loading a row, not during render. Indexed paths change after removal; stable keys preserve row UI identity. A production field also connects validation feedback and its accessible description.

Other framework adapters include Preact, Vue, Angular, Solid, Svelte and Lit, each with its own integration API. The React examples above are not copy-paste examples for those frameworks.

## Choose it by the interaction contract

TanStack Form fits teams that want typed shared field primitives, framework adapters or explicit subscriptions in a dynamic form. RHF may fit an existing React codebase built around native registration and resolver integrations; retaining a tested Formik form may cost less than migration. Compare the actual form, accessibility behavior, installed validator support and production bundle before choosing.

## Summary

TanStack Form keeps typed values in a form model and updates React views through field and store subscriptions. Standard Schema validators check the editable input but do not replace it with transformed output; parse at submission when the mutation needs normalized data. Choose it from the form's interaction and integration needs, then measure the real component tree.

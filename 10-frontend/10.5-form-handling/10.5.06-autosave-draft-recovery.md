# Autosave & Draft Recovery

> Long forms lose users when a tab crashes, a session expires, or a laptop dies mid-entry. This file covers the full draft-recovery stack: debounced autosave, localStorage vs IndexedDB trade-offs, multi-step form resume, dirty-state guards, versioned draft migrations, and conflict resolution when the server copy moved on.

## Definition

**Autosave** persists form state continuously (debounced) so work survives interruptions without an explicit submit. **Draft recovery** restores that state on return — including schema migrations for drafts saved by older app versions, dirty-state guards that prevent accidental navigation away, and conflict resolution when a newer server copy exists alongside the local draft.

```text
┌─────────────────────────────────────────────────────────────────────┐
│ AUTOSAVE PIPELINE                                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│ keystroke ──▶ RHF watch() ──▶ debounce(800ms) ──▶ serialize         │
│                                                                  │    │
│                                     ┌───────────────┴────────────┐  │
│                                     ▼                            │    │
│                              { v: 2, updatedAt,                     │
│                                step, values }                       │
│                                                                  │    │
│                    ┌────────────────┴────────────────┐              │
│                    ▼                                 ▼              │
│             localStorage                      IndexedDB             │
│             (small, sync)                     (large, async)        │
│                    └────────────────┬────────────────┘              │
│                                     ▼                               │
│                          optional: POST /drafts (server copy)       │
│                                                                     │
│ RECOVERY: mount ──▶ load draft ──▶ migrate(v1→v2) ──▶ reset(values) │
│           ──▶ if server.updatedAt > local.updatedAt ──▶ prompt      │
└─────────────────────────────────────────────────────────────────────┘
```

## Why It Matters (TL;DR)

- **Data loss is churn** — abandonment spikes when a long application form wipes out on refresh
- **Multi-step forms need memory** — users return days later; step position + values must survive
- **Senior signal** — autosave touches debouncing, storage APIs, schema versioning, and offline UX in one feature
- **Conflict edge cases** — two tabs, stale drafts, and server-side edits are classic interview follow-ups
- **Pairs with Server Actions** — the same Zod schema validates drafts and final submits

## How It Works

### 1. Debounced autosave loop

Write on a timer, not on every keystroke. The debounce window trades durability against I/O churn:

| Debounce | Writes/min (typing) | Worst-case loss |
| -------- | ------------------: | --------------- |
| 200 ms   | ~30                 | negligible      |
| 800 ms   | ~7                  | half a field    |
| 3 s      | ~2                  | a few fields    |

Flush immediately on three lifecycle moments regardless of the timer: `beforeunload`/`pagehide`, tab becoming hidden (`visibilitychange`), and successful submit (then delete the draft).

### 2. Where to persist

| localStorage       | IndexedDB                       |                                                                                    |
| ------------------ | ------------------------------- | ---------------------------------------------------------------------------------- |
| Capacity           | ~5 MB per origin                | hundreds of MB+, quota-managed                                                     |
| API                | synchronous                     | async (promises via `idb`)                                                         |
| Blocks main thread | yes, on every read/write        | no                                                                                 |
| Structured data    | strings only (`JSON.stringify`) | structured clone (objects, Blobs, File)                                            |
| Eviction           | never evicted (best-effort)     | can be evicted under storage pressure unless `navigator.storage.persist()` granted |
| Worker access      | no                              | yes                                                                                |

Rules of thumb: small settings-shaped drafts (< 100 KB, written rarely) fit localStorage; large forms, attachments, image blobs, or anything written every few hundred milliseconds belongs in IndexedDB.

### 3. Draft envelope

Always store a wrapper, never raw values:

```typescript
interface DraftEnvelope<T> {
  v: number;            // schema version — enables migrations
  formId: string;       // which form this belongs to
  updatedAt: number;    // epoch ms — conflict resolution
  step?: number;        // wizard progress
  values: T;            // payload validated by the same Zod schema
}
```

### 4. Conflict resolution model

Compare `updatedAt` clocks when both a local draft and a server copy exist:

- Local strictly newer → restore local silently, offer "discard server changes" undo toast
- Server strictly newer (user edited on another device/tab) → show both, ask
- Equal or ambiguous (same second) → prompt, defaulting to the newer timestamp

## Code Examples

### 1. Debounced autosave hook (storage-agnostic)

```typescript
import { useEffect, useRef } from 'react';
import type { FieldValues, UseFormWatch } from 'react-hook-form';

interface DraftStore {
  load(formId: string): Promise<DraftEnvelope<unknown> | null>;
  save(envelope: DraftEnvelope<unknown>): Promise<void>;
  clear(formId: string): Promise<void>;
}

export function useAutosave<T extends FieldValues>(opts: {
  formId: string;
  watch: UseFormWatch<T>;
  store: DraftStore;
  delay?: number;
}) {
  const { formId, watch, store, delay = 800 } = opts;
  const timer = useRef<ReturnType<typeof setTimeout>>();
  const latest = useRef<T>();

  // Track latest values without re-rendering on each keystroke.
  useEffect(() => {
    const sub = watch((values) => { latest.current = values; });
    return () => sub.unsubscribe();
  }, [watch]);

  // Schedule debounced writes whenever values change.
  useEffect(() => {
    const flush = () => {
      if (!latest.current) return;
      void store.save({
        v: SCHEMA_VERSION,
        formId,
        updatedAt: Date.now(),
        values: latest.current,
      });
    };

    const schedule = () => {
      clearTimeout(timer.current);
      timer.current = setTimeout(flush, delay);
    };

    const sub = watch(schedule);

    const flushNow = () => { clearTimeout(timer.current); flush(); };
    // pagehide covers mobile Safari where beforeunload is unreliable.
    window.addEventListener('pagehide', flushNow);
    document.addEventListener('visibilitychange', flushNow);

    return () => {
      sub.unsubscribe();
      clearTimeout(timer.current);
      window.removeEventListener('pagehide', flushNow);
      document.removeEventListener('visibilitychange', flushNow);
      flushNow(); // flush pending edits on unmount
    };
  }, [formId, watch, store, delay]);

  return {
    discard: () => store.clear(formId),
  };
}
```

### 2. localStorage adapter

```typescript
export function createLocalDraftStore(): DraftStore {
  const key = (id: string) => `draft:${id}`;
  return {
    async load(formId) {
      const raw = localStorage.getItem(key(formId));
      if (!raw) return null;
      try {
        return JSON.parse(raw) as DraftEnvelope<unknown>;
      } catch {
        localStorage.removeItem(key(formId)); // corrupted — drop it
        return null;
      }
    },
    async save(envelope) {
      try {
        localStorage.setItem(key(envelope.formId), JSON.stringify(envelope));
      } catch {
        // QuotaExceededError — fall back to IndexedDB or trim fields
      }
    },
    async clear(formId) {
      localStorage.removeItem(key(formId));
    },
  };
}
```

### 3. IndexedDB adapter (async, large payloads)

```typescript
const DB_NAME = 'drafts';
const STORE = 'form-drafts';

function openDb(): Promise<IDBDatabase> {
  return new Promise((resolve, reject) => {
    const req = indexedDB.open(DB_NAME, 1);
    req.onupgradeneeded = () => {
      req.result.createObjectStore(STORE, { keyPath: 'formId' });
    };
    req.onsuccess = () => resolve(req.result);
    req.onerror = () => reject(req.error);
  });
}

export function createIndexedDraftStore(): DraftStore {
  return {
    async load(formId) {
      const db = await openDb();
      return new Promise((resolve, reject) => {
        const tx = db.transaction(STORE, 'readonly').objectStore(STORE);
        const req = tx.get(formId);
        req.onsuccess = () => resolve(req.result ?? null);
        req.onerror = () => reject(req.error);
      });
    },
    async save(envelope) {
      const db = await openDb();
      return new Promise((resolve, reject) => {
        const tx = db.transaction(STORE, 'readwrite').objectStore(STORE);
        const req = tx.put(envelope);
        req.onsuccess = () => resolve();
        req.onerror = () => reject(req.error);
      });
    },
    async clear(formId) {
      const db = await openDb();
      return new Promise((resolve, reject) => {
        const tx = db.transaction(STORE, 'readwrite').objectStore(STORE);
        const req = tx.delete(formId);
        req.onsuccess = () => resolve();
        req.onerror = () => reject(req.error);
      });
    },
  };
}
```

### 4. React Hook Form integration: restore then autosave

```tsx
'use client';

import { useEffect, useState } from 'react';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const schema = z.object({
  fullName: z.string().min(2),
  motivation: z.string().max(2000),
});
type Values = z.infer<typeof schema>;

const SCHEMA_VERSION = 2;
const store = createLocalDraftStore();

export function Application() {
  const [restored, setRestored] = useState(false);
  const form = useForm<Values>({
    resolver: zodResolver(schema),
    defaultValues: { fullName: '', motivation: '' },
  });

  // Restore once on mount, BEFORE wiring autosave below.
  useEffect(() => {
    store.load('application').then(async (draft) => {
      if (!draft) return;
      const migrated = migrate(draft);          // example 6
      const parsed = schema.safeParse(migrated.values);
      if (parsed.success) {
        form.reset(parsed.data);                // resets dirty state too
        setRestored(true);
      }
    });
  }, [form]);

  useAutosave({ formId: 'application', watch: form.watch, store });

  const onSubmit = form.handleSubmit(async (values) => {
    await submitApplication(values);
    await store.clear('application');           // submitted → drop draft
  });

  return (
    <form onSubmit={onSubmit}>
      {restored && (
        <p role="status">Draft restored. <button onClick={() => {
          store.clear('application');
          form.reset();
          setRestored(false);
        }}>Start over</button></p>
      )}
      <input {...form.register('fullName')} />
      <textarea {...form.register('motivation')} />
      <button type="submit">Submit</button>
    </form>
  );
}
```

Key RHF detail: call `reset(values)` to restore — never `setValue` per field in a loop. `reset` replaces the baseline so `isDirty`, `dirtyFields`, and validation state all become correct relative to the restored values.

### 5. Dirty-state guards: unload + route change

```tsx
// 1. Tab close / reload — the native prompt
useEffect(() => {
  const handler = (e: BeforeUnloadEvent) => {
    if (!form.formState.isDirty) return;
    e.preventDefault();
    e.returnValue = ''; // Chrome requires returnValue to be set
  };
  window.addEventListener('beforeunload', handler);
  return () => window.removeEventListener('beforeunload', handler);
}, [form.formState.isDirty]);

// 2. In-app navigation — confirm with react-router
import { useBlocker } from 'react-router-dom';

function RouteGuard({ blocked }: { blocked: boolean }) {
  const blocker = useBlocker(blocked);
  if (blocker.state !== 'blocked') return null;
  return (
    <div role="dialog">
      <p>You have unsaved changes. Leave anyway?</p>
      <button onClick={blocker.proceed}>Leave</button>
      <button onClick={blocker.reset}>Stay</button>
    </div>
  );
}

// Usage inside the form component:
<RouteGuard blocked={form.formState.isDirty} />
```

Note: because autosave runs, "unsaved" means *not yet persisted*, not *not yet submitted*. If the draft is safely stored you may allow navigation freely — decide which contract your product promises and keep guard + autosave consistent.

### 6. Versioned schema migration

```typescript
type AnyDraft = Record<string, unknown> & { v: number };

const migrations: Record<number, (d: AnyDraft) => AnyDraft> = {
  // v1 stored { name, coverLetter } → v2 renames fields
  1: (d) => ({
    ...d,
    values: {
      fullName: d.values.name,
      motivation: d.values.coverLetter,
    },
    v: 2,
  }),
};

export function migrate(draft: DraftEnvelope<unknown>): DraftEnvelope<unknown> {
  let current = draft as AnyDraft;
  while (current.v < SCHEMA_VERSION) {
    const step = migrations[current.v];
    if (!step) break; // unknown future version — surface an error instead
    current = step(current);
  }
  return current as DraftEnvelope<unknown>;
}
```

This is the same mental model as DB migrations: never mutate old records in place; apply ordered forward steps until the record matches the current version.

### 7. Multi-step (wizard) resume

```typescript
interface WizardState {
  step: number;
  visitedSteps: number[];
}

export function useWizardResume(steps: string[]) {
  const [state, setState] = useState<WizardState>({ step: 0, visitedSteps: [] });

  useEffect(() => {
    store.load('visa-wizard').then((draft) => {
      if (!draft || typeof draft.step !== 'number') return;
      if (draft.step >= steps.length) return;
      setState({ step: draft.step, visitedSteps: draft.visitedSteps ?? [] });
    });
  }, [steps.length]);

  const goTo = (step: number) => {
    setState((prev) => ({
      step,
      visitedSteps: [...new Set([...prev.visitedSteps, prev.step])],
    }));
  };

  return { ...state, goTo };
}
```

Persist `step` inside the same envelope as the values (one atomic write), so values and progress can never drift apart.

### 8. Conflict resolution against a fresher server copy

```typescript
async function reconcile(formId: string, serverUpdatedAt: number) {
  const local = await store.load(formId);
  if (!local) return null;

  if (local.updatedAt > serverUpdatedAt) {
    return { action: 'restore-local' as const, draft: local };
  }
  if (local.updatedAt < serverUpdatedAt) {
    return { action: 'prompt' as const, local, reason: 'server-newer' };
  }
  return { action: 'keep-server' as const };
}
```

```text
LOCAL NEWER                 SERVER NEWER                 AMBIGUOUS/TIE
┌────────────────────────────────────────────────────────────────────────┐
│ restore local │           │ show chooser: │            │ keep server                  │
│ silently +    │           │  • keep mine  │            │ + undo toast                 │
│ undo toast    │           │  • take server│            │ (server wins)                │
└────────────────────────────────────────────────────────────────────────┘
```

## Common Mistakes

| Mistake                                       | Fix                                                                 |
| --------------------------------------------- | ------------------------------------------------------------------- |
| Saving on every keystroke                     | Debounce 500–1000 ms; flush on `pagehide`/`visibilitychange`        |
| Restoring with per-field `setValue`           | Use `reset(values)` so `isDirty`/baseline stay correct              |
| Storing raw values without `{ v, updatedAt }` | Wrap in a versioned envelope from day one                           |
| Trusting `beforeunload` alone                 | It does not fire reliably on mobile — also listen to `pagehide`     |
| JSON-blobbing huge files into localStorage    | Attachments/images go to IndexedDB (structured clone, bigger quota) |
| Deleting the draft before submit succeeds     | Clear only after the submit resolves, or you lose data on failure   |

## Best Practices

1. **One envelope, atomically written** — values, step, version, and timestamp live together
2. **Validate restored drafts with the same Zod schema** — a failed parse means discard, not crash
3. **Migrate forward only**, with pure functions per version, unit-tested like DB migrations
4. **Make recovery visible and reversible** — "Draft restored · Start over", never silent mutation
5. **Scope keys by form id + user id** — shared machines must not leak drafts across accounts
6. **Cap draft size** — trim or move heavy fields (files) to IndexedDB/object storage
7. **Decide the guard contract explicitly** — autosave-on means navigation may be free; say it in code review

## Performance Considerations

- `JSON.stringify` on every keystroke shows up in profiles for big forms — debounce and serialize only changed forms
- localStorage writes are synchronous: 1 ms for small drafts, tens of ms past ~1 MB — enough to drop frames while typing
- IndexedDB opens a transaction per operation; reuse the connection instead of calling `openDb()` per write
- On low-end Android, prefer one IndexedDB write per pause (`visibilitychange`) over aggressive timers

## Summary

- Autosave = debounced persistence + lifecycle flushes (`pagehide`, `visibilitychange`, unmount)
- localStorage for small synchronous drafts; IndexedDB for large or high-frequency ones
- Store a versioned envelope (`v`, `formId`, `updatedAt`, `step`, `values`) — never bare values
- Restore through `reset()`, validate with the production Zod schema, migrate old versions forward
- Guard navigation consistently with the autosave contract; resolve conflicts by comparing timestamps and always leaving the user an undo path

## Cheat Sheet

```text
AUTOSAVE & DRAFT RECOVERY CHEAT SHEET
════════════════════════════════════════════════════════════════

STORAGE CHOICE:
  localStorage → < 100 KB, sync OK, strings only, ~5 MB cap
  IndexedDB    → large/high-frequency, async, blobs, workers
  server copy  → cross-device; needs updatedAt conflict checks

ENVELOPE:
  { v, formId, updatedAt, step?, values }

LIFECYCLE FLUSHES:
  debounce(800ms) + pagehide + visibilitychange + unmount
  clear AFTER submit resolves — never before

RHF INTEGRATION:
  restore → form.reset(values)   (not setValue loops)
  track   → watch(cb) subscription, ref for latest
  guard   → isDirty drives beforeunload + router blocker

CONFLICTS:
  local.updatedAt > server → restore local + undo toast
  server newer             → prompt (mine vs theirs)
  tie                      → server wins by default

MIGRATIONS:
  v1 → v2 → … pure steps, tested, forward-only
  unknown version → error path, never silent loss
```

# CSS Animations

A button can respond to hover with a transition; a loading indicator can follow keyframes. Choose the state change first, then check what work the browser must repeat for each frame.

```css
.button {
  transition: background-color 0.3s ease, transform 0.2s ease;
}

.button:hover,
.button:focus-visible {
  background-color: darkblue;
  transform: translateY(-2px);
}
```

## Definition

CSS lets you describe motion and have the browser calculate the intermediate values. A **transition** moves a property from its old value to a new value after a change, such as `:hover`. **`@keyframes`** describe several stages and can loop or start after a delay. Eligible `transform` and `opacity` effects can run in the browser's **compositor**, which assembles visual layers without repeating layout and paint for every frame. Other properties may still need main-thread layout or painting.

> **Textbook Definition:** CSS transitions interpolate a changed property between states, while CSS animations evaluate named keyframes over a timeline. Interpolation, timing and composition determine the effect; the property and browser determine its rendering cost.

## First Principles

Animation changes displayed values repeatedly, so the rendering work matters. **Rendering cost depends on the property**: eligible transform/opacity animations can avoid repeated layout and paint (→ 10.7.03) — though layer allocation, rasterization, and device load still affect smoothness, and geometry changes cost more. **Transitions and keyframes answer different control needs**: a transition interpolates a changed value, while keyframes specify intermediate stages, delays, and repetition. **Motion preference is part of behavior**: replace nonessential movement with an immediate or quieter state under `prefers-reduced-motion` (→ 50.2.02).

## 1. Let a Transition Follow the Interface State

```text
hover/class change → old/new property values → transition interpolation
keyframes + timing → progress → evaluated property values
                                  ↓
                property/browser → layout, paint or composition
```

For the button below, hover changes translateY from 0 to −2px. At the midpoint of an eased transition, the timing function chooses the progress; it need not be exactly halfway in distance. Releasing hover targets the base state again. A transform moves the painted button without reserving a different normal-flow position.

```css
.button {
  background-color: blue;
  color: white;
  padding: 10px 20px;
  border: none;
  border-radius: 4px;
  cursor: pointer;
  /* transition: <property> <duration> <timing-function> <delay> */
  transition: background-color 0.3s ease, transform 0.2s ease;
}

.button:hover,
.button:focus-visible {
  background-color: darkblue;
  transform: translateY(-2px);
}

.button:active {
  transform: translateY(0);
}
```

The button needs semantic `<button>` markup and a visible focus indicator. The focus state above gives keyboard users the same feedback; reduced-motion rules below keep the operation available.

**Choose how progress moves between the states:**

```css
.ease { transition-timing-function: ease; }
.ease-in { transition-timing-function: ease-in; }
.ease-out { transition-timing-function: ease-out; }
.ease-in-out { transition-timing-function: ease-in-out; }
.linear { transition-timing-function: linear; }
.bounce { transition-timing-function: cubic-bezier(0.68, -0.55, 0.265, 1.55); }

/* Material Design easing */
.material { transition-timing-function: cubic-bezier(0.4, 0, 0.2, 1); }
```

## 2. Use Keyframes When the Effect Has Authored Stages

```css
@keyframes fadeIn {
  from { opacity: 0; transform: translateY(20px); }
  to { opacity: 1; transform: translateY(0); }
}

.fade-in {
  animation: fadeIn 0.5s ease-out forwards;
}

@keyframes pulse {
  0%, 100% { transform: scale(1); opacity: 1; }
  50% { transform: scale(1.1); opacity: 0.8; }
}

.pulse {
  animation: pulse 2s ease-in-out infinite;
}

@keyframes shimmer {
  0% { background-position: -200% 0; }
  100% { background-position: 200% 0; }
}

.skeleton {
  background: linear-gradient(90deg, #f0f0f0 25%, #e0e0e0 50%, #f0f0f0 75%);
  background-size: 200% 100%;
  animation: shimmer 1.5s infinite;
}
```

**Know what the animation shorthand sets:**

```css
/* Shorthand: name duration timing-function delay iteration-count direction fill-mode play-state */
.animated {
  animation: slideIn 0.5s ease-out 0.2s 1 normal forwards;
}

/* Longhand */
.animated {
  animation-name: slideIn;
  animation-duration: 0.5s;
  animation-timing-function: ease-out;
  animation-delay: 0.2s;
  animation-iteration-count: 1;
  animation-direction: normal; /* normal | reverse | alternate | alternate-reverse */
  animation-fill-mode: forwards; /* none | forwards | backwards | both */
  animation-play-state: running; /* running | paused */
}
```

`animation-fill-mode` controls the effect outside its active interval; it does not rewrite the underlying CSS. `backwards` applies the first relevant keyframe during the delay, which is `to` for reverse playback. `forwards` retains the final sampled state: reverse playback ends at `from`, and a fractional iteration can end between keyframes. Direction and iteration count therefore matter when choosing the persistent interface state. [Fill semantics](https://developer.mozilla.org/en-US/docs/Web/CSS/animation-fill-mode).

## 3. Add a Rendering Hint Only When Measurements Justify It

```css
/* Hint about a forthcoming change; layer promotion is not guaranteed */
.animated {
  will-change: transform, opacity;
}

/* Remove the hint after the animation completes */
.animated.done {
  will-change: auto;
}

```

`will-change` can allocate resources and create a stacking context before the visible change. Applying it to every element or adding `translateZ(0)` indiscriminately can increase memory and rendering cost. Confirm the bottleneck, add a scoped hint before the interaction and remove it afterward.

## 4. Keep the Interaction Useful with Reduced Motion

```css
/* Apply this class to nonessential animated decoration. */
@media (prefers-reduced-motion: reduce) {
  .decorative-motion,
  .decorative-motion::before,
  .decorative-motion::after {
    animation: none !important;
    transition: none !important;
  }

  html { scroll-behavior: auto; }
}

/* Provide a non-animated fallback */
.no-motion {
  animation: none;
  transition: none;
}
```

The `infinite` pulse and shimmer examples also need a stopping policy. For automatically moving content that lasts more than five seconds alongside other content, provide a pause, stop or hide mechanism unless the movement is essential. Reduced motion is a separate preference; it does not replace that control. A CSS pause button can toggle a class that sets `animation-play-state: paused`. [WCAG pause/stop/hide conditions](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html).

Target the effect, not every element on the page. A broad zero-duration rule can leave content in a keyframe-dependent state and does not reliably stop scroll-timeline motion. Keep essential content visible in its base styles, and make application code that waits for animation events handle the no-animation and cancellation paths. `transitionend`/`animationend` are not guaranteed after an effect is removed or canceled; keep the interface state authoritative instead of waiting forever for an end event.

## 5. Compare the Rendering Work Each Property Changes

| Property | Work to investigate |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `transform`, `opacity` | Eligible effects may reuse rasterized layers; verify composition and layer size |
| `width`, `height`, margins, padding, `font-size`, `line-height` | Geometry can change, requiring layout and subsequent visual work |
| `background-color`, `background-position`, blurred `box-shadow` | Usually changes painted content even when geometry remains unchanged |
| `filter`, `clip-path` | Cost and compositing support depend on the effect, browser and affected area |

Scaling a box changes its visual size without making its siblings reflow. Animating width changes layout geometry. These are different behaviors, so a transform is not a correct replacement for every layout animation. Use a transform when only the visual position or size should change; animate layout dimensions when neighboring content must reflow. Name properties in `transition` rather than using `all`, and keep the underlying state usable if motion is disabled. A skeleton shimmer that changes `background-position`, for example, may repaint; use a static placeholder when that is clearer or cheaper.

To find a missed frame, record the interaction in a real browser and separate JavaScript, layout, paint, rasterization and composition. A 60 Hz display has roughly 16.7 ms between refreshes, and the browser shares that interval with other work. Property choice helps, but does not guarantee a frame rate. Use the [browser-rendering chapter](../10.7-html-css/10.7.03-browser-rendering.md) to identify the stage that misses the deadline.

## Summary

Use transitions for changed states and keyframes for authored stages. Property choice determines rendering work; it does not promise a frame rate. Keep a visible nonanimated state, honor reduced motion, and measure before adding rendering hints.

# Framer Motion

## Definition

Motion for React, previously Framer Motion, connects React components to animated visual states. The current package is `motion`, imported from `motion/react`. React decides what should exist and where it belongs; Motion interpolates its visual changes and coordinates entering, leaving and layout movement.

## First Principles

An expanding help panel exposes three separate problems. React can add it instantly, but opening should communicate where the content came from. Closing removes the DOM node before an ordinary exit effect can finish. The panel also pushes its neighbours into new positions. These require different mechanisms: animate a target, retain a departing node, and measure changing layout.

## What happens when a panel opens and closes?

```text
click → React changes open
      → panel enters → initial values move towards animate values
close → React removes its child from the desired tree
      → AnimatePresence retains the departing DOM temporarily
      → exit completes → retained DOM is removed
```

A `motion` component adds animation props to an HTML or SVG element. `AnimatePresence` sits above conditional children and watches their identities. It must remain mounted long enough to observe their departure; removing the whole wrapper removes that opportunity. [Presence documentation](https://motion.dev/docs/react-animate-presence).

```tsx
import { useState } from 'react';
import { AnimatePresence, motion, useReducedMotion } from 'motion/react';

export function HelpPanel() {
  const [open, setOpen] = useState(false);
  const reduced = useReducedMotion();
  const offset = reduced ? 0 : 12;

  return (
    <section>
      <button
        type="button"
        aria-expanded={open}
        aria-controls="help-panel"
        onClick={() => setOpen(value => !value)}
      >
        {open ? 'Hide help' : 'Show help'}
      </button>
      <AnimatePresence initial={false}>
        {open && (
          <motion.div
            key="help"
            id="help-panel"
            initial={{ opacity: 0, y: offset }}
            animate={{ opacity: 1, y: 0 }}
            exit={{ opacity: 0, y: offset }}
            transition={{ duration: reduced ? 0 : 0.2 }}
          >
            Choose a delivery address before paying.
          </motion.div>
        )}
      </AnimatePresence>
    </section>
  );
}
```

1. Opening mounts `help`. Its opacity and translation approach their targets.
2. Closing removes `help` from React's desired children. The surviving presence wrapper retains it for the exit.
3. A reduced-motion preference makes these changes immediate while preserving the same message and button behavior.

The panel contains plain text, so no focus transfer is needed. An interactive departing panel needs an explicit policy for disabling its controls and moving focus out before dismissal. A dialog additionally needs dialog semantics, focus management and keyboard dismissal; animation does not provide them.

## How does movement differ from changing layout?

`animate={{ x: 20 }}` changes a visual transform; surrounding layout does not move with it. With `layout`, React/CSS first establishes a new layout. Motion measures old and new bounds and uses transforms to interpolate between them. A stable React `key` identifies a list item across reorders. A `layoutId` relates separately rendered elements for a shared visual transition. `LayoutGroup` coordinates related measurements; it does not virtualize a large list. [Layout documentation](https://motion.dev/docs/react-layout-animations).

A page wrapper keyed by pathname can animate local children only when the router preserves that wrapper and gives it outgoing content. Placing one wrapper in a Next.js App Router root layout does not guarantee complete route exits: router segment lifecycles matter. Use the [view-transition chapter](10.6.06-view-transitions-and-scroll-driven-animations.md) for router/platform integration.

## Which controls belong inside this mechanism?

| Need | Control | What it contributes |
| ------------------------------------- | -------------- | ------------------------------------------------------------------------------------------ |
| Several elements share named states | `variants` | Parent labels select coordinated descendant targets |
| Respond to hover, press or drag | Gesture props | Temporary targets and gesture tracking; retain semantic controls and keyboard alternatives |
| Observe continuous scroll/drag values | Motion values | Update animated styles without a React state update for every sample |
| Derive an opacity from distance | `useTransform` | Map one changing value into another |
| Run a deliberate sequence | `useAnimate` | Scoped imperative playback and sequencing |

These controls extend the same target-and-lifecycle model. Introduce them when the interaction requires them, rather than replacing every CSS hover transition with a library.

## Where does the rendering work happen?

Motion has native browser animation paths and JavaScript paths. Continuous gesture tracking, measurements and some interpolation require JavaScript; a library cannot move all its work off the main thread. Eligible transform/opacity animations can avoid repeated layout and paint. Actual compositing depends on the property, element and browser. Background color and shadows can animate too, with different rendering costs.

Measure a representative interaction in a browser performance recording: look for layout work, painting, long tasks and large layers. Neither a `requestAnimationFrame` callback count nor a library choice proves every frame reached the display. Bundle cost depends on version, imports and build; use the production bundle rather than a fixed size quoted in a chapter.

## Reduced motion needs an explicit policy

`MotionConfig reducedMotion="user"` disables transform and layout motion for descendants according to the user's preference; other effects such as opacity remain possible. Use `useReducedMotion` when the effect needs a tailored alternative, as in the panel above. It does not suppress unrelated CSS animation, video or Canvas loops. [Accessibility guide](https://motion.dev/docs/react-accessibility).

SSR can produce markup and initial styles. Browser measurements and interactions start on the client. In a Server Component application, put interactive Motion code behind a client boundary; ordinary React SSR does not use `'use client'` as a universal directive. Keep essential content readable before hydration and when an optional effect fails.

## Summary

React owns the desired UI; Motion supplies interpolation, layout projection and controlled exit retention. Choose each mechanism for the lifecycle it solves, keep accessibility behavior explicit, and verify rendering cost in the actual interaction.

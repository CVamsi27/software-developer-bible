# GSAP (GreenSock Animation Platform)

> When several animations must overlap, pause or reverse together, a timeline makes their timing explicit. GSAP supplies that control along with plugins for scrolling, paths and text.

## Definition

**GSAP** is a JavaScript animation library controlled through function calls. A **tween** changes supported property values over time; `gsap.to()`, `gsap.from()` and `gsap.fromTo()` create tweens. A **timeline**, created with `gsap.timeline()`, coordinates several animations. Plugins add capabilities: ScrollTrigger connects animation to scrolling, SplitText supports text reveals, MorphSVG animates shapes and MotionPath moves objects along paths.

> **Textbook Definition:** GSAP schedules imperative property interpolation through tweens and coordinated timelines. Timeline position, easing and repeat rules determine motion; integration code must scope targets and release animation resources when their owner is removed.

## First Principles

GSAP is a *timeline* engine — imperative control is the feature:

1. **A timeline lets you control when each step happens.** You can sequence animations, pause, reverse or seek to a time. **Scrubbing** makes scroll progress control that time. This is useful for scroll-driven stories and coordinated sequences; target-based tools (→ 10.6.02) instead emphasize the visual state to reach.
2. **The application owns that timeline's lifetime.** Create and control imperative animations outside React's render calculation, then clean them up when the component unmounts (→ 10.3.2.02). That ownership is the cost of direct playback control.

## How It Works

```text
targets + end values + duration → tweens
                                ↓
                  timeline positions + one playhead
                                ↓
                    evaluated values → target writes
```

A timeline schedules child animations; it does not automatically grant them independent DOM ownership. Scope targets to their interface and keep the timeline alive only while that interface owns it. Plugins extend target/playback capabilities; they do not remove property rendering cost.


## Code Examples

### 1. Basic Tweens

These are independent alternatives. Import `gsap`, provide an existing `.box`, and choose one; running them all simultaneously creates competing writes.

```javascript
// Animate to a state
gsap.to('.box', { x: 300, rotation: 360, duration: 1, ease: 'power2.out' });

// Animate from the supplied state to the current state
gsap.from('.box', { opacity: 0, y: 50, duration: 1 });

// Animate from one state to another
gsap.fromTo('.box', { opacity: 0, scale: 0 }, { opacity: 1, scale: 1, duration: 0.8 });

// Set immediately (no animation)
gsap.set('.box', { x: 100 });

// Chain multiple properties
gsap.to('.box', { x: 300, y: 100, scale: 1.5, rotation: 180, backgroundColor: 'red', duration: 1 });
```

### 2. Timelines (Sequenced Animations)

```javascript
const tl = gsap.timeline({ defaults: { duration: 0.5, ease: 'power2.out' } });

tl.from('.title', { y: -50, opacity: 0 })
  .from('.subtitle', { y: -30, opacity: 0 }, '-=0.2') // start 0.2s before previous ends
  .from('.button', { scale: 0 }, '-=0.1')
  .to('.button', { scale: 1.1, repeat: 1, yoyo: true, duration: 0.3 }, '+=0.2');

// Position parameters:
// '-=0.5' → start 0.5s before previous ends
// '+=0.5' → start 0.5s after previous ends
// '<0.2' → start 0.2s after previous starts
// '>0.5' → start 0.5s after the previous animation ends
// 'label' → start at the labeled point

// Control
tl.play();
tl.pause();
tl.reverse();
tl.seek(2);
tl.timeScale(2); // 2x speed
```

With the stated 0.5-second defaults, title runs 0–0.5s, subtitle starts at 0.3s and ends at 0.8s, button entry starts at 0.7s and ends at 1.2s, then its 0.3s forward/return pulse starts at 1.4s and ends at 2s. Position strings affect scheduling; ease affects progress inside each scheduled interval.

### 3. ScrollTrigger Plugin

```javascript
import { gsap } from 'gsap';
import { ScrollTrigger } from 'gsap/ScrollTrigger';
gsap.registerPlugin(ScrollTrigger);

// Basic reveal
gsap.from('.reveal', {
  scrollTrigger: '.reveal',
  y: 100,
  opacity: 0,
  duration: 1,
});

// Scrub — animation tied to scroll position
gsap.to('.parallax', {
  y: () => -window.innerHeight * 0.5,
  ease: 'none',
  scrollTrigger: {
    trigger: '.parallax',
    start: 'top top',
    end: 'bottom top',
    scrub: true, // tie to scroll, no smoothing
    // scrub: 0.5 // tie to scroll with 0.5s smoothing
  },
});

// Pin an element while animating
gsap.to('.pinned-section', {
  scale: 1.5,
  scrollTrigger: {
    trigger: '.pinned-section',
    start: 'top top',
    end: '+=500', // pin for 500px of scroll
    pin: true,
    scrub: 1,
  },
});

// Batch — animate many elements as they enter
ScrollTrigger.batch('.card', {
  onEnter: (els) => gsap.to(els, { opacity: 1, y: 0, stagger: 0.1 }),
  start: 'top 80%',
});
```

### 4. Easing Functions

```javascript
// Built-in eases
gsap.to('.box', { x: 100, ease: 'power1.out' });
gsap.to('.box', { x: 100, ease: 'power2.out' });
gsap.to('.box', { x: 100, ease: 'power3.out' });
gsap.to('.box', { x: 100, ease: 'power4.out' });
gsap.to('.box', { x: 100, ease: 'back.out(1.7)' });
gsap.to('.box', { x: 100, ease: 'elastic.out(1, 0.3)' });
gsap.to('.box', { x: 100, ease: 'bounce.out' });

// Custom cubic-bezier: register a CustomEase instead of a raw CSS ease string
import { CustomEase } from 'gsap/CustomEase';
gsap.registerPlugin(CustomEase);
CustomEase.create('standard', '0.4,0,0.2,1');
gsap.to('.box', { x: 100, ease: 'standard' });
```

### 5. React Integration (via `@gsap/react`)

```tsx
import { useRef } from 'react';
import { useGSAP } from '@gsap/react';
import { gsap } from 'gsap';

gsap.registerPlugin(useGSAP);

function FadeIn() {
  const container = useRef(null);

  useGSAP(() => {
    gsap.from('.box', { opacity: 0, y: 30, duration: 0.6, stagger: 0.1 });
  }, { scope: container });

  return (
    <div ref={container}>
      <div className="box">1</div>
      <div className="box">2</div>
      <div className="box">3</div>
    </div>
  );
}
```

`scope` limits selector matching to this component. The Hook reverts work recorded by its context when the owner ends. Animations created later by event handlers need `contextSafe`; manually installed listeners, timers and unrelated resources still need their own cleanup. When dependency changes should rebuild the animation, use an explicit dependency list and `revertOnUpdate: true`.

### 6. Timeline Markers and Labels

```javascript
const tl = gsap.timeline();

tl.addLabel('start')
  .from('.a', { x: -100, opacity: 0 })
  .addLabel('middle')
  .to('.a', { x: 0, opacity: 1 })
  .from('.b', { x: 100, opacity: 0 })
  .addLabel('end');

tl.play('start'); // play from the label
tl.seek('middle'); // jump to the label
```

### 7. Real-World: Hero Animation Sequence

```javascript
import { gsap } from 'gsap';
import { SplitText } from 'gsap/SplitText';

gsap.registerPlugin(SplitText);

function playHero() {
  const context = gsap.context(() => {
    const tl = gsap.timeline();

    // Split the title into characters
    const title = new SplitText('.hero-title', { type: 'chars' });
    const subtitle = new SplitText('.hero-subtitle', { type: 'lines' });

    tl.from(title.chars, {
      opacity: 0,
      y: 50,
      rotateX: -90,
      stagger: 0.03,
      duration: 0.8,
      ease: 'power4.out',
    })
    .from(subtitle.lines, {
      opacity: 0,
      y: 20,
      stagger: 0.1,
      duration: 0.6,
      ease: 'power2.out',
    }, '-=0.4')
    .from('.hero-cta', { scale: 0, ease: 'back.out(1.7)' }, '-=0.3')
    .from('.hero-image', { x: 100, opacity: 0, duration: 1 }, '-=0.8');
    return () => { title.revert(); subtitle.revert(); };
  });
  return () => context.revert(); // owner calls this when the hero is removed
}
```

Keep the unanimated hero readable, and create this sequence only when the user's motion preference allows it. A short demonstration with global selectors assumes one hero; use a scoped container when several instances can exist.

## Common Mistakes

| Mistake | Fix |
| ------------------------------------------ | ----------------------------------------------------------------------------------------- |
| Assuming the library guarantees smoothness | Prefer transforms/opacity when suitable; profile JavaScript, paint and layer cost |
| Not registering plugins | `gsap.registerPlugin(ScrollTrigger)` once at app start |
| Forgetting to clean up | Revert the owned context; individual trigger instances expose `kill()` |
| Heavy main-thread work during animation | Reduce callbacks and visual work; offload suitable computation rather than DOM changes |
| Animating during `prefers-reduced-motion` | Detect and skip the animation, or use `gsap.matchMedia()` |

## Performance Considerations

GSAP's ticker updates JavaScript work; it does not move all animation logic off the main thread. A cheap transform can still be interrupted by a costly callback or oversized layer. Measure the complete interaction on representative devices.

Import the plugins actually used and inspect the built bundle rather than relying on fixed compressed-size estimates. Use `gsap.set()` for an immediate change. `overwrite: 'auto'` can resolve conflicting property tweens, but it is not a substitute for explicit ownership and teardown.

## Summary

- GSAP coordinates imperative tweens through controllable timelines
- Use `gsap.to/from/fromTo` for tweens; `gsap.timeline()` for sequences
- ScrollTrigger plugin enables pin, scrub, batch, parallax for scroll-linked animations
- Scoped `useGSAP` tracks animation cleanup; later callbacks and other resources require explicit integration
- Prefer suitable transforms/opacity and measure actual rendering cost

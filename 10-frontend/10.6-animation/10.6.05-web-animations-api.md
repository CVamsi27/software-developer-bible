# Web Animations API (WAAPI)

A menu opens, but a second input arrives before its entrance finishes. The Web Animations API (WAAPI) gives the interaction an animation object that can be reversed or canceled; the component still owns the menu state and the browser still determines rendering cost.

```javascript
const animation = panel.animate(
  [
    { transform: 'translateX(-100%)', opacity: 0 },
    { transform: 'translateX(0)', opacity: 1 },
  ],
  { duration: 240, easing: 'ease-in-out', fill: 'both' }
);

closeButton.addEventListener('click', () => animation.reverse());
```

## Definition

The **Web Animations API (WAAPI)** lets JavaScript create and control browser animations. Call `element.animate(keyframes, options)` to create an `Animation` object. That object supports play, pause, reverse, finish, cancel and changing `currentTime` to seek. Eligible `transform` and `opacity` effects can update through the compositor without repeated layout. Animating width, height or properties that require painting still needs main-thread work. Using WAAPI alone does not guarantee compositor execution.

> **Textbook Definition:** The Web Animations API associates keyframe effects with timelines through controllable animation objects. Playback state, timing and seeking govern effect evaluation; compositor eligibility depends on the animated properties and implementation.

## First Principles

An animation combines an effect (keyframes and timing) with a timeline that advances it. CSS and WAAPI share the browser's Web Animations model; WAAPI adds JavaScript control over an animation object. Libraries may use browser animations, a JavaScript ticker, or both.

## 1. Create an Effect That Responds to New Input

```text
keyframes + timing → KeyframeEffect → Animation + timeline
                                            ↓
                              play / pause / seek / reverse
                                            ↓
                         layout, paint or composite as properties require
```

`element.animate()` starts playing immediately. `animation.ready` resolves when a pending play or pause operation is ready. `animation.finished` resolves at the end of that playback and rejects if the animation is canceled before it settles. Restarting creates a new `finished` promise. An indefinitely repeating animation has no natural end, so do not await its `finished` promise as a completion signal.

```javascript
const panel = document.querySelector('.panel');
const closeButton = document.querySelector('.close');
if (!panel || !closeButton) throw new Error('Menu controls are missing');

const animation = panel.animate(
  [
    { transform: 'translateX(-100%)', opacity: 0 },
    { transform: 'translateX(0)', opacity: 1 },
  ],
  {
    duration: 240,
    easing: 'ease-in-out',
    fill: 'both',
  }
);

closeButton.addEventListener('click', () => animation.reverse());
```

## 2. Await a Finite Effect and Release Its Retained Style

```javascript
const finite = el.animate([{ opacity: 0 }, { opacity: 1 }], { duration: 200, fill: 'forwards' });
try {
  await finite.finished;
  finite.commitStyles(); // move the final result into inline styles if desired
  finite.cancel();       // release the filled effect after committing
} catch (error) {
  if (!(error instanceof DOMException && error.name === 'AbortError')) throw error;
}
```

For an interruptible interaction, call `pause()`, set `currentTime` to seek, change `playbackRate`, or call `reverse()` on the same object. `cancel()` stops playback and removes its effect; it does not reverse application state. Keep the persistent final state in the DOM or commit the finished effect with `commitStyles()` before canceling it.

## 3. Configure Timing, Offsets, and Inspection

```javascript
el.animate(keyframes, {
  duration: 1000, // ms
  delay: 200, // ms before start
  endDelay: 0, // ms after end (before finished resolves)
  easing: 'ease-in-out', // or 'cubic-bezier(0.4, 0, 0.2, 1)'
  iterations: 1, // or Infinity
  iterationStart: 0, // non-negative iteration offset (may exceed 1)
  direction: 'normal', // 'normal' | 'reverse' | 'alternate' | 'alternate-reverse'
  fill: 'none', // 'none' | 'forwards' | 'backwards' | 'both' | 'auto'
  composite: 'replace', // 'replace' | 'add' | 'accumulate'
  iterationComposite: 'replace', // limited browser support; detect before relying on it
});
```

`composite` controls how an effect combines with the underlying value. `iterationComposite` controls accumulation between iterations and has limited browser support. An unsupported dictionary option can be ignored without throwing, so successful `animate()` creation does not prove it worked; check `'iterationComposite' in animation.effect` and test the intended effect before relying on accumulation. [Iteration composition](https://developer.mozilla.org/en-US/docs/Web/API/KeyframeEffect/iterationComposite).

Custom offsets divide an effect into authored stages. Multiple values can be animated at their own offsets, but their ending value still needs an application-owned state if it must persist after the animation object is removed.

```javascript
const anim = el.animate(
  [
    { transform: 'scale(1)', opacity: 1, offset: 0 },
    { transform: 'scale(1.2)', opacity: 0.8, offset: 0.5 },
    { transform: 'scale(1)', opacity: 1, offset: 1 },
  ],
  { duration: 1500, iterations: 3, direction: 'alternate' }
);
```

To inspect live effects, `getAnimations()` returns the current animation objects for an element:

```javascript
const running = element.getAnimations();
console.log(running.map(({ currentTime, playState }) => ({ currentTime, playState })));
```

`document.getAnimations()` is useful for diagnostics or deliberately page-wide controls, not as a substitute for clear ownership.

## 4. Cancel Work When a React Owner Goes Away

```typescript
import { useEffect, useRef } from 'react';

export function useReveal(trigger: unknown) {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    const element = ref.current;
    if (!element || !element.animate) return;
    const reduced = matchMedia('(prefers-reduced-motion: reduce)');
    if (reduced.matches) return;
    const animation = element.animate(
      [{ opacity: 0, transform: 'translateY(20px)' }, { opacity: 1, transform: 'none' }],
      { duration: 300, easing: 'ease-out' },
    );
    const stopForPreference = () => { if (reduced.matches) animation.cancel(); };
    reduced.addEventListener('change', stopForPreference);
    return () => {
      reduced.removeEventListener('change', stopForPreference);
      animation.cancel();
    };
  }, [trigger]);
  return ref;
}

function MyComponent({ identity }: { identity: string }) {
  const ref = useReveal(identity);
  return <div ref={ref}>Hello</div>;
}
```

The preference listener cancels active motion when reduced motion is enabled; the visible base state remains. The cleanup removes that listener and cancels the animation if the component unmounts or `trigger` changes. In React Strict Mode, setup can be repeated in development, so cleanup must fully release each object it creates.

## 5. Reveal Content Without Depending on Motion

```javascript
export function revealContent(skeleton, content) {
  let active = true;
  let reveal;
  const show = () => {
    skeleton.hidden = true;
    content.hidden = false;
  };
  if (!skeleton.animate || matchMedia('(prefers-reduced-motion: reduce)').matches) {
    show();
    return () => {};
  }
  const fade = skeleton.animate([{ opacity: 1 }, { opacity: 0 }], { duration: 200 });
  void fade.finished.then(() => {
    if (!active) return;
    show();
    reveal = content.animate(
      [{ opacity: 0, transform: 'translateY(8px)' }, { opacity: 1, transform: 'none' }],
      { duration: 300, easing: 'ease-out' },
    );
  }).catch(error => {
    if (active) show(); // Content must remain usable when optional animation fails.
    if (error?.name !== 'AbortError') console.error('Reveal failed', error);
  });
  return () => { active = false; fade.cancel(); reveal?.cancel(); };
}
```

Keep gesture ownership outside the animation object: animating scale on pointerdown is feedback, not a complete drag implementation. Capture the active pointer so releasing outside the element is observed; handle pointerup, pointercancel and lost capture. Cancel the owned effect on completion/removal and clean up listeners. Provide keyboard alternatives for the underlying move operation. The browser's animation object does not supply those interaction semantics.

CSS and WAAPI use the same browser animation model; WAAPI adds a JavaScript playback object. Use it when code needs to pause, seek, reverse, inspect or cancel an effect. Use `requestAnimationFrame` when each frame depends on application state or custom drawing. Timers are for coarse scheduling, not frame-by-frame visuals. For either API, measure the animated property in the target browser and preserve a nonanimated path.

## Summary

WAAPI is useful when an interaction needs programmatic playback control that CSS alone does not provide. Give each animation a clear owner, handle cancellation of `finished`, persist the final interface state deliberately, and provide a reduced-motion path.

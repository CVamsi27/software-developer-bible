# Web Animations API (WAAPI)

> The Web Animations API (WAAPI) lets JavaScript create and control browser animation effects. Its playback object exposes timing and lifecycle controls; the animated properties still determine much of the rendering work.

## Definition

The **Web Animations API (WAAPI)** lets JavaScript create and control browser animations. Call `element.animate(keyframes, options)` to create an `Animation` object. That object supports play, pause, reverse, finish, cancel and changing `currentTime` to seek. Eligible `transform` and `opacity` effects can update through the compositor without repeated layout. Animating width, height or properties that require painting still needs main-thread work. Using WAAPI alone does not guarantee compositor execution.

> **Textbook Definition:** The Web Animations API associates keyframe effects with timelines through controllable animation objects. Playback state, timing and seeking govern effect evaluation; compositor eligibility depends on the animated properties and implementation.

## First Principles

An animation combines an effect (keyframes and timing) with a timeline that advances it. CSS and WAAPI share the browser's Web Animations model; WAAPI adds JavaScript control over an animation object. Libraries may use browser animations, a JavaScript ticker, or both.

## Why It Matters

- **Browser scheduling** — eligible effects can be composited; frame rate still depends on properties, layers and device load
- **Programmatic control** — start, pause, reverse, seek, set playback rate
- **No library dependency** — suitable when a small controlled effect does not need a broader animation system
- **CSS integration** — can read/write CSS animation properties
- **Element inspection** — `element.getAnimations()` and `document.getAnimations()` for global control

## How It Works

```text
keyframes + timing → KeyframeEffect → Animation + timeline
                                            ↓
                              play / pause / seek / reverse
                                            ↓
                         layout, paint or composite as properties require
```

`element.animate()` starts playing immediately. `animation.ready` resolves when a pending play or pause operation is ready. `animation.finished` resolves at the end of that playback and rejects if the animation is canceled before it settles. Restarting creates a new `finished` promise. An indefinitely repeating animation has no natural end.

## Code Examples

### 1. Basic Animation

```javascript
const el = document.querySelector('.box');

const animation = el.animate(
  [
    { transform: 'translateX(0px)', opacity: 1 },
    { transform: 'translateX(300px)', opacity: 0.5 },
  ],
  {
    duration: 1000,
    easing: 'ease-in-out',
    iterations: Infinity,
    direction: 'alternate',
  }
);
```

### 2. Animation Control

```javascript
// Playback controls operate on this Animation object.
animation.pause();
animation.currentTime = 500;
animation.playbackRate = 2;
animation.play();
animation.reverse();
animation.cancel(); // stop playback and remove this animation's effect

// Use finished with a finite animation. Cancellation before completion rejects.
const finite = el.animate([{ opacity: 0 }, { opacity: 1 }], { duration: 200, fill: 'forwards' });
try {
  await finite.finished;
  finite.commitStyles(); // move the final result into inline styles if desired
  finite.cancel();       // release the filled effect after committing
} catch (error) {
  if (!(error instanceof DOMException && error.name === 'AbortError')) throw error;
}
```

### 3. Animation Options Reference

```javascript
el.animate(keyframes, {
  duration: 1000, // ms
  delay: 200, // ms before start
  endDelay: 0, // ms after end (before finished resolves)
  easing: 'ease-in-out', // or 'cubic-bezier(0.4, 0, 0.2, 1)'
  iterations: 1, // or Infinity
  iterationStart: 0, // non-negative iteration offset (may exceed 1)
  direction: 'normal', // 'normal' | 'reverse' | 'alternate' | 'alternate-reverse'
  fill: 'none', // 'none' | 'forwards' | 'backwards' | 'both' | 'auto'
  composite: 'replace', // 'replace' | 'add' | 'accumulate'
  iterationComposite: 'replace',
});
```

### 4. Complex Keyframes

```javascript
const anim = el.animate(
  [
    { transform: 'scale(1)', opacity: 1, offset: 0 },
    { transform: 'scale(1.2)', opacity: 0.8, offset: 0.5 },
    { transform: 'scale(1)', opacity: 1, offset: 1 },
  ],
  { duration: 1500, iterations: 3, direction: 'alternate' }
);
```

### 5. Reading CSS Animations

```javascript
const el = document.querySelector('.fade-in');
const running = el.getAnimations();
console.log(running[0]?.currentTime, running[0]?.playState);

// Pause all animations on the page
document.getAnimations().forEach((a) => a.pause());
```

### 6. Replacing CSS Animations Programmatically

```javascript
// Apply a CSS class, then take over with WAAPI
el.classList.add('fade-in');
const animations = el.getAnimations();
const fade = animations[0];

// Wait for the animation to start, then customize
fade.ready.then(() => {
  fade.currentTime = 0;
  fade.pause();
  // Custom logic
});
```

### 7. Effect: Spring-like with WAAPI (Not Native, But Possible)

```javascript
function springify(el, keyframes, duration = 1000) {
  // Use a custom cubic-bezier approximation of a spring
  return el.animate(keyframes, {
    duration,
    easing: 'cubic-bezier(0.34, 1.56, 0.64, 1)', // slight overshoot
  });
}
```

### 8. Combining Multiple Animations

```javascript
const moveX = el.animate(
  [{ transform: 'translateX(0)' }, { transform: 'translateX(300px)' }],
  { duration: 500, fill: 'forwards' }
);

const fade = el.animate(
  [{ opacity: 0 }, { opacity: 1 }],
  { duration: 500, fill: 'forwards' }
);

// Both run in parallel on the same element
await Promise.all([moveX.finished, fade.finished]);
```

### 9. React Hook for WAAPI

```typescript
import { useEffect, useRef } from 'react';

export function useReveal(trigger: unknown) {
  const ref = useRef<HTMLDivElement>(null);
  useEffect(() => {
    const element = ref.current;
    if (!element || !element.animate ||
        matchMedia('(prefers-reduced-motion: reduce)').matches) return;
    const animation = element.animate(
      [{ opacity: 0, transform: 'translateY(20px)' }, { opacity: 1, transform: 'none' }],
      { duration: 300, easing: 'ease-out' },
    );
    return () => animation.cancel();
  }, [trigger]);
  return ref;
}

function MyComponent({ identity }: { identity: string }) {
  const ref = useReveal(identity);
  return <div ref={ref}>Hello</div>;
}
```

## Real-World Use Cases

### 1. Skeleton → Content Reveal

```javascript
export function revealContent(skeleton, content) {
  let active = true;
  let reveal;
  const show = () => {
    skeleton.hidden = true;
    content.hidden = false;
  };
  if (!skeleton.animate || matchMedia('(prefers-reduced-motion: reduce)').matches) {
    show();
    return () => {};
  }
  const fade = skeleton.animate([{ opacity: 1 }, { opacity: 0 }], { duration: 200 });
  void fade.finished.then(() => {
    if (!active) return;
    show();
    reveal = content.animate(
      [{ opacity: 0, transform: 'translateY(8px)' }, { opacity: 1, transform: 'none' }],
      { duration: 300, easing: 'ease-out' },
    );
  }).catch(error => {
    if (active) show(); // Content must remain usable when optional animation fails.
    if (error?.name !== 'AbortError') console.error('Reveal failed', error);
  });
  return () => { active = false; fade.cancel(); reveal?.cancel(); };
}
```

### Drag feedback still needs a gesture owner

Animating scale on pointerdown is feedback, not a complete drag implementation. Capture the active pointer so releasing outside the element is observed; handle pointerup, pointercancel and lost capture. Cancel the owned effect on completion/removal and clean up listeners. Provide keyboard alternatives for the underlying move operation. The browser's animation object does not supply those interaction semantics.

## Common Mistakes

| Mistake | Fix |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Animating layout properties via WAAPI | Prefer them when they express the behavior; measure required layout effects |
| Not awaiting `animation.finished` | Use `.finished` Promise for sequential animations |
| Depending on `fill: 'forwards'` indefinitely | Render the final application state or commit it with `commitStyles()` and cancel the finished animation |
| Not cancelling animations on unmount | `return () => animation.cancel()` in `useEffect` |
| Re-creating animations on every render | Create it in an effect with fixed dependencies; keep its ownership local |

## Best Practices

1. **Choose suitable properties** — avoid repeated layout when visual transforms meet the requirement
2. **Use `.finished` for sequenced animations** — chain via Promises
3. **Cancel on unmount** — prevent leaked animations in SPAs
4. **Commit or render the final state deliberately** — forwards fill retains an effect; `commitStyles()` plus cancel can release it
5. **Compose multiple animations** on the same element for parallel effects
6. **Read animations with `getAnimations()`** for global control
7. **Test reduced-motion** — manually check `matchMedia('(prefers-reduced-motion: reduce)')`

## Performance Considerations

CSS and WAAPI both use the browser's animation model; WAAPI adds a JavaScript playback object. Use `requestAnimationFrame` when each frame depends on application state or custom drawing. Timers are useful for coarse scheduling, not for per-frame visuals. Choose WAAPI when code needs to pause, seek, reverse, inspect or cancel an effect, and still measure the animated property in the target browser.

## Summary

- WAAPI exposes browser keyframes and playback control; eligible properties can be composited
- Use `element.animate(keyframes, options)` to start; control via `.play()`, `.pause()`, `.reverse()`, `.currentTime`
- Prefer `transform` and `opacity` for frame-sensitive effects; implement reduced-motion behavior explicitly
- Use `.finished` Promise for sequenced animations; cancel on unmount
- Reach for it when you need control beyond what CSS provides, without pulling in a library

# Canvas & SVG Animation

Choose a rendering owner, follow one frame, and measure the scene before changing technologies. Canvas keeps pixels you redraw; SVG keeps shapes you restyle — and removing per-shape DOM nodes also removes their native events, focus, and accessibility.

```typescript
function frame(now: number): void {
  const seconds = Math.min((now - last) / 1000, 0.05); // clamp pause gaps
  last = now;
  distance += 200 * seconds;
  draw(); // clear + redraw the bitmap at the new position
  frameId = requestAnimationFrame(frame);
}
```

## Definition

**Canvas** stores pixels in a bitmap. Drawing commands change those pixels, which remain until cleared or drawn over. **SVG** keeps shapes as vector elements in a document tree. To animate Canvas, application code usually redraws the changing pixels. To animate SVG, it changes the shapes' attributes or styles. Both can handle complex scenes. Choose based on the work each frame requires and the interactions the scene needs.

> **Textbook Definition:** Canvas is an immediate drawing surface whose bitmap is changed by drawing commands. SVG retains a vector-element tree; animation updates either the Canvas drawing output or the attributes and styles of retained SVG elements.

## First Principles

A moving ball needs position, elapsed time and a rendering owner. With SVG, a node retains the ball's geometry and receives updated properties. With Canvas, your state retains the position and drawing commands update the bitmap. Removing per-shape DOM nodes also removes their native event, focus and accessibility behavior, so Canvas transfers those responsibilities to the application.

## 1. Trace One Canvas Frame

```typescript
export function startBall(canvas: HTMLCanvasElement): () => void {
  const ctx = canvas.getContext('2d');
  if (!ctx) throw new Error('Canvas 2D is unavailable');
  const radius = 12;
  let width = 0, height = 0, distance = 0;
  let last: number | undefined;
  let frameId = 0;
  const reduced = matchMedia('(prefers-reduced-motion: reduce)');

  function draw(): void {
    const travel = Math.max(0, width - radius * 2);
    const phase = travel === 0 ? 0 : distance % (travel * 2);
    const x = travel === 0 ? width / 2 : radius + (phase <= travel ? phase : travel * 2 - phase);
    ctx!.clearRect(0, 0, width, height);
    ctx!.fillStyle = '#c33';
    ctx!.beginPath();
    ctx!.arc(x, height / 2, radius, 0, Math.PI * 2);
    ctx!.fill();
  }
  function resize(): void {
    width = canvas.clientWidth; height = canvas.clientHeight;
    const dpr = Math.min(devicePixelRatio || 1, 2); // deliberate memory/quality cap
    canvas.width = Math.round(width * dpr);
    canvas.height = Math.round(height * dpr);
    ctx!.setTransform(dpr, 0, 0, dpr, 0, 0);
    draw();
  }
  function frame(now: number): void {
    const seconds = last === undefined ? 0 : Math.min((now - last) / 1000, 0.05);
    last = now;
    distance += 200 * seconds;
    draw();
    frameId = requestAnimationFrame(frame);
  }
  function applyPreference(): void {
    cancelAnimationFrame(frameId);
    last = undefined;
    draw();
    if (!reduced.matches) frameId = requestAnimationFrame(frame);
  }
  const observer = new ResizeObserver(resize);
  observer.observe(canvas);
  reduced.addEventListener('change', applyPreference);
  resize();
  applyPreference();
  return () => {
    cancelAnimationFrame(frameId);
    observer.disconnect();
    reduced.removeEventListener('change', applyPreference);
  };
}
```

Set the canvas's CSS size separately, for example `width: 100%; height: 240px`. The backing store uses physical pixels while the transform lets drawing use CSS-pixel coordinates. Resizing the backing store clears pixels and resets context state, so reapply the transform and redraw. The observer handles CSS-size changes; if a window can move between displays with different pixel ratios, also recheck `devicePixelRatio` because the CSS box may stay the same.

The DPR cap limits density, not total allocation: a 1920 × 1080 CSS box at DPR 2 needs about 31.6 MiB for one 4-byte-per-pixel buffer, before extra surfaces. Bound both backing dimensions and total pixels for an unbounded scene; browser/device limits differ, and exceeding them can make drawing fail. This example assumes the constrained CSS box above. [Canvas size limits](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/canvas).

One frame reads its timestamp → computes elapsed seconds → advances distance → folds that distance into a bounce position → clears/redraws → schedules the next frame. The clamp deliberately drops simulation time after a long pause rather than teleporting the ball. A simulation that must track real elapsed time needs a different catch-up policy.

```text
application state + elapsed time → new position → Canvas commands → changed bitmap
```

The returned function owns cleanup. For this endless nonessential demo, a visible Stop control can call it; alternatively start the demo only after an explicit user request. Apply the [pause/stop/hide policy](10.6.01-css-animations.md#4-keep-the-interaction-useful-with-reduced-motion) when placing automatic motion beside other content. Return it from a React effect; development Strict Mode's extra setup/cleanup cycle helps expose missing cleanup. `requestAnimationFrame` provides a rendering opportunity, not proof that a frame was painted or a fixed 60 FPS guarantee.

## 2. SVG Keeps the Shape as a Node

```html
<svg viewBox="0 0 300 100" aria-hidden="true">
  <path class="signature" d="M10,80 Q75,10 150,80 T290,80"
        pathLength="100" fill="none" stroke="currentColor" stroke-width="4" />
</svg>
```

```css
.signature { stroke-dasharray: 100; stroke-dashoffset: 0; }
@media (prefers-reduced-motion: no-preference) {
  .signature { animation: draw 2s ease backwards; }
  @keyframes draw { from { stroke-dashoffset: 100; } }
}
```

`pathLength` normalizes the path's distance to 100. A dash and gap of that length let the offset hide or reveal the stroke. The visible base state prevents unsupported or reduced-motion environments from receiving hidden content. For a purely decorative image, omit unnecessary announced text and hide it from assistive technology; meaningful graphics need useful descriptions and interaction semantics.

To trigger only on entry, initially leave the visible base state and apply an animation class from an IntersectionObserver. The observer must have a matching CSS rule and an owner that disconnects it. Adding an unused class does not delay an already-running animation.

## 3. Native SVG Animation Remains an Option

SVG `<animate>` and `<animateTransform>` are supported native animation mechanisms, often called SMIL animation. A historical proposed removal is not a current blanket deprecation. They can be controlled through SVG animation APIs such as `beginElement`; CSS or WAAPI may fit a particular application's tooling better. Changing an `x` attribute and alternating an eased transform do not produce identical timing or geometry by default.

## 4. What a Worker Changes

OffscreenCanvas can transfer rendering ownership to a worker, moving eligible simulation/drawing work off the main JavaScript thread. Feature-detect transfer, context and worker scheduling support before transferring; a transferred canvas cannot simply be reused as an ordinary main-thread canvas. Plan dimensions, device-pixel ratio, input messages, failure recovery and worker termination.

A worker does not guarantee responsive input at any load. CPU/GPU contention, message volume, memory and compositing still affect the application. Define the fallback before transfer and profile both threads. Keep visible DOM controls/descriptions when Canvas carries meaningful interactive information.

## 5. Choose by Ownership and Measured Work

| Need | Reason to consider |
| ------------------------------------------------------- | ---------------------------------------- |
| Individual shape styling, focus or DOM events | SVG's retained nodes |
| Many changing pixels or application-managed hit testing | Canvas 2D |
| GPU batching or shader-based scenes | WebGL/WebGPU with their own complexity |
| Main-thread simulation contention | Worker + OffscreenCanvas where supported |

There is no universal hundreds-versus-thousands node threshold. Canvas cost includes commands, paths, effects, area and transfers; SVG cost includes node/style/paint work. A single bitmap does not make all drawing free. Multiple rAF callbacks can coexist; use a shared ticker when it simplifies coordination, not because callbacks inherently fight for frames.

## Summary

Identify who retains the scene, who draws updates and who owns interaction. Trace elapsed time through one frame, preserve pixels deliberately, scale and clean up correctly, then choose SVG, Canvas or worker rendering from measured workload rather than fixed object counts.

# Canvas & SVG Animation

> When element counts climb past what DOM animation can handle, you leave the DOM: **Canvas 2D** for pixel-level imperative rendering, **SVG** for resolution-independent vector motion (including the stroke-draw-on effect). This file covers the rAF loop with delta time, HiDPI canvas scaling, `stroke-dashoffset` draw-ons, the SMIL deprecation story, performance envelopes, OffscreenCanvas in workers, and correct rAF cleanup in React.

## TL;DR

Canvas and SVG: immediate-mode pixel drawing vs retained-mode vector scenes — the performance and interaction trade-offs for data-viz and games.

## First Principles

Canvas and SVG answer "who rasterizes?":

1. **SVG is retained-mode vector DOM** — elements are nodes you style/animate (→ 10.7.03's rendering pipeline applies, with paint cost per node); right for hundreds of interactive shapes, wrong for thousands (DOM cost scales).
2. **Canvas is immediate-mode raster** — you redraw every frame; the browser forgets between frames: right for thousands of particles/games, and you own everything (hit-testing, a11y — the DOM-free cost, → 50.2.02).
3. **WebGL/OffscreenCanvas push further**: GPU batches and worker threads for the extreme end — the same "who owns the pixels" question at each scale.

## Definition

**Canvas** is an immediate-mode bitmap surface: each frame you clear and redraw everything from scratch — nothing persists between frames. **SVG** is retained-mode vector graphics: you animate declarative attributes/CSS and the browser owns the scene graph. Both are driven by `requestAnimationFrame` (rAF), which syncs callbacks to the display refresh cycle (~60/120 fps).

## Why It Matters

- **Performance envelope** — interviews probe "when does DOM animation break down?" Canvas answers ~1000s of elements, SVG hundreds
- **Delta-time loops** — frame-rate-independent animation is a core senior skill
- **Draw-on effects** — `stroke-dasharray`/`stroke-dashoffset` is the canonical SVG interview trick
- **SMIL is legacy** — knowing it exists, and why to avoid it, is a 2026-era signal
- **OffscreenCanvas** — moving render loops off the main thread is the modern scaling answer

## How It Works

### The rAF loop with delta time

```text
┌──────────────────────────────────────────────────────────────┐
│ FRAME LOOP                                                   │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  t0 ──▶ rAF cb(t1) ──▶ dt = t1 - last                        │
│                          │                                   │
│          update(dt): x += speed * dt   ← seconds, not frames │
│                          │                                   │
│          render(): clear ─▶ draw everything                  │
│                          │                                   │
│          rAF(cb) ◀──── schedule next                         │
│                                                              │
│  At 60fps dt ≈ 16.7ms; at 120fps dt ≈ 8.3ms                  │
│  → same visual speed on both                                 │
└──────────────────────────────────────────────────────────────┘
```

Never write `x += 5` inside a rAF callback — that ties speed to refresh rate and doubles it on 120 Hz displays. Multiply by elapsed time.

### Performance envelope by technology

| Element count | Best fit | Why |
| -------------------------------------------- | ----------------------------------------- | --------------------------------------------------- |
| 1–10 animated nodes | CSS / WAAPI / Framer Motion | compositor handles it; cheapest authoring |
| 10–500 nodes, interactive hover/focus needed | SVG | retained mode, hit-testing free, styleable with CSS |
| 500–5,000 shapes redrawn per frame | Canvas 2D | immediate mode beats style recalculation |
| 10,000+ particles / pixels | Canvas + OffscreenCanvas worker, or WebGL | main thread isolation / GPU |

The crossover logic: DOM/SVG pay layout + paint + style recalc per mutation; Canvas pays only your JS plus one composite of a single bitmap. Past roughly a thousand simultaneously animating nodes, JS redraw of a bitmap wins because the browser stops doing bookkeeping you no longer need.

### SMIL: deprecated in spirit

SMIL (`<animate>`, `<animateTransform>` as XML markup) still renders in browsers but was slated for deprecation in Chrome years ago (the removal was paused), is unsupported in IE11 historically, cannot be driven from JS timelines, and composes poorly with modern tooling. Treat it as read-only knowledge: recognize it in old codebases, migrate to CSS animations or WAAPI.

## Code Examples

### 1. Delta-time canvas loop with devicePixelRatio scaling

```typescript
function startBounce(canvas: HTMLCanvasElement) {
  const ctx = canvas.getContext('2d')!;
  const dpr = Math.min(window.devicePixelRatio || 1, 2);
  let width = 0;
  let height = 0;

  const resize = () => {
    // Backing store sized in physical px, styled in CSS px.
    width = canvas.clientWidth;
    height = canvas.clientHeight;
    canvas.width = Math.round(width * dpr);
    canvas.height = Math.round(height * dpr);
    ctx.setTransform(dpr, 0, 0, dpr, 0, 0); // draw in CSS px afterwards
  };
  resize();
  const observer = new ResizeObserver(resize);
  observer.observe(canvas);

  let x = 20;
  const SPEED = 200; // px per second — not per frame
  let direction = 1;
  let last = performance.now();
  let raf = 0;

  const frame = (now: number) => {
    const dt = Math.min((now - last) / 1000, 0.05); // clamp tab-switch jumps
    last = now;

    // update
    x += SPEED * direction * dt;
    if (x > width - 20 || x < 0) direction *= -1;

    // render: clear then redraw EVERYTHING (immediate mode)
    ctx.clearRect(0, 0, width, height);
    ctx.fillStyle = '#ff6b6b';
    ctx.beginPath();
    ctx.arc(x, height / 2, 12, 0, Math.PI * 2);
    ctx.fill();

    raf = requestAnimationFrame(frame);
  };
  raf = requestAnimationFrame(frame);

  return () => {
    cancelAnimationFrame(raf);
    observer.disconnect();
  };
}
```

Without the `setTransform(dpr, ...)` step, canvas output looks blurry on Retina displays: the backing store must hold physical pixels while you reason in CSS pixels.

### 2. React cleanup: the useEffect return contract

```tsx
import { useEffect, useRef } from 'react';

export function BouncingBall() {
  const ref = useRef<HTMLCanvasElement>(null);

  useEffect(() => {
    const canvas = ref.current!;
    return startBounce(canvas); // cancelAnimationFrame runs on unmount
  }, []);

  return <canvas ref={ref} style={{ width: '100%', height: 240 }} />;
}
```

Skipping cleanup leaks a loop that mutates detached state every frame after navigation — visible in profiles as runaway rAF callbacks and battery drain. Strict Mode double-mounting will expose it immediately in dev.

### 3. SVG draw-on via stroke-dashoffset

```html
<svg viewBox="0 0 300 100" class="signature">
  <!-- pathLength normalizes math: total "length" becomes exactly 100 -->
  <path d="M10,80 Q75,10 150,80 T290,80"
        pathLength="100"
        fill="none" stroke="#333" stroke-width="4" />
</svg>
```

```css
.signature path {
  /* dash pattern = one gap as long as the whole path */
  stroke-dasharray: 100;
  stroke-dashoffset: 100; /* fully hidden */
  animation: draw 2s ease forwards;
}

@keyframes draw {
  to { stroke-dashoffset: 0; } /* revealed tip-to-tail */
}
```

Mechanics: `stroke-dasharray` chops the stroke into dashes/gaps; setting both dash length and offset to the path's normalized length hides it, and animating the offset to 0 slides the visible portion along the path — the "handwriting" effect. With `pathLength="100"` you never measure real geometry in JS.

Trigger on scroll entry by combining with `animation-play-state` or an IntersectionObserver toggling a class:

```typescript
const io = new IntersectionObserver(([entry]) => {
  if (entry.isIntersecting) {
    entry.target.classList.add('draw');
    io.disconnect();
  }
});
io.observe(document.querySelector('.signature')!);
```

### 4. SMIL vs the modern equivalents

```xml
<!-- LEGACY: SMIL — do not author new code like this -->
<rect x="0" y="0" width="40" height="40" fill="#333">
  <animate attributeName="x" from="0" to="260" dur="2s" repeatCount="indefinite" />
</rect>
```

```css
/* MODERN: identical result, CSS-driven, debuggable in DevTools */
@keyframes slide { to { transform: translateX(260px); } }
rect { animation: slide 2s infinite alternate ease-in-out; }
```

### 5. OffscreenCanvas: render loop in a Web Worker

```typescript
// main.ts
const canvas = document.querySelector('canvas')!;
if ('transferControlToOffscreen' in canvas && typeof Worker !== 'undefined') {
  const offscreen = canvas.transferControlToOffscreen();
  const worker = new Worker(new URL('./render-worker.ts', import.meta.url));
  worker.postMessage({ canvas: offscreen }, [offscreen]); // transfer ownership
}
```

```typescript
// render-worker.ts
self.onmessage = (e: MessageEvent<{ canvas: OffscreenCanvas }>) => {
  const { canvas } = e.data;
  const ctx = canvas.getContext('2d')!;
  let last = performance.now();

  const frame = (now: number) => {
    const dt = (now - last) / 1000;
    last = now;
    // heavy particle simulation + drawing happens off main thread:
    // input handlers and scrolling stay responsive at any load
    simulateAndDraw(ctx, canvas.width, canvas.height, dt);
    requestAnimationFrame(frame); // also available inside workers
  };
  requestAnimationFrame(frame);
};
```

`OffscreenCanvas` detaches the bitmap from the DOM (`transferControlToOffscreen()`), so the simulation cost never lands on the thread that handles typing, scrolling, and React renders. Feature-detect: Safari shipped it in 16.4; fall back to a main-thread loop otherwise.

### 6. Choosing per scenario

```text
Need interactivity per shape (hover/click/a11y)? ──▶ SVG
Thousands of nodes or pixel manipulation?        ──▶ Canvas (+worker)
UI micro-interaction?                            ──▶ CSS/WAAPI/Framer Motion
Data-viz axes, labels, tooltips?                 ──▶ SVG (D3) — text stays crisp/selectable
Heatmaps, particle systems, image filters?       ──▶ Canvas/WebGL
```

## Real-World Use Cases

- **Data-viz dashboards** — SVG for interactive charts (retained DOM, per-node events); canvas when nodes exceed ~1k and interaction moves to hit-testing.
- **Signature/annotation layers** — canvas capture of freehand input; export as image, overlay on PDF/document views.

## Common Mistakes

| Mistake | Fix |
| -------------------------------------------------- | --------------------------------------------------------------- |
| `x += 5` per frame (frame-rate dependent) | Track `dt = now - last`, multiply speeds by seconds |
| Blurry canvas on Retina | Scale backing store by `devicePixelRatio` + `ctx.setTransform` |
| Forgetting `cancelAnimationFrame` on unmount | Return the canceler from `useEffect`; Strict Mode catches leaks |
| Drawing before fonts/layout settle | Observe `ResizeObserver` and re-size backing store on changes |
| Animating SVG position via `x`/`y` attrs per frame | Use `transform` (CSS) so the compositor can help |
| Reaching for WebGL for 50 circles | Canvas 2D or SVG already covers it; WebGL adds complexity |

## Best Practices

1. **Clamp delta time** (`Math.min(dt, 0.05)`) so background-tab resumption doesn't teleport objects
2. **Pause loops when invisible** — IntersectionObserver / `visibilitychange` instead of burning rAF off-screen
3. **Batch canvas state changes** — set `fillStyle` once per group; `save()`/`restore()` sparingly
4. **Prefer CSS/WAAPI first**, SVG second, Canvas only past the element-count envelope
5. **Keep SVG accessible** — real `<title>`, focusable interactive nodes; Canvas needs explicit ARIA fallback content
6. **Respect `prefers-reduced-motion`** — render final states, skip loops
7. **Move to OffscreenCanvas only when profiling shows main-thread contention** — it costs messaging complexity

## Performance Considerations

- Canvas clear/draw cost scales with area drawn, not object count — full-screen clears are cheap; avoid per-shape clip regions
- SVG performance dies on attribute mutations that trigger layout (`cx`, `width`) — animate `transform` and `opacity`
- One rAF loop per app, not per component: multiple loops fight for frames; fan out updates from a shared ticker
- Profile with the Performance panel: long "Animation Frame" tasks in the main thread = move work off-thread or reduce draw calls

## Summary

- Drive all programmatic animation from one rAF loop using delta time in seconds
- Canvas = immediate mode (clear/redraw, HiDPI via `devicePixelRatio` scaling); SVG = retained mode (styleable, accessible, hit-tested)
- The draw-on effect is `stroke-dasharray` + animated `stroke-dashoffset`, simplified by `pathLength`
- SMIL is legacy: recognize it, replace it with CSS animations or WAAPI
- Envelope: CSS/WAAPI for UI, SVG up to a few hundred live nodes, Canvas into thousands, OffscreenCanvas workers beyond that
- Always cancel rAF on unmount — the `useEffect` return is part of the animation's API

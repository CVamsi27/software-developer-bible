# Animation Interview Questions

> 30+ curated questions on animation in web development — from CSS basics to React animation patterns, performance, and accessibility.

## Definition

This guide covers the questions a senior full-stack engineer should be able to answer about web animation — CSS transitions/keyframes, Web Animations API, React animation libraries, performance, and accessibility. Grouped by difficulty.

## First Principles

This set probes the threading model (→ 10.6.01) and tool selection (→ 10.6.02–07):

1. **The senior tell is compositor fluency**: when transform/opacity can avoid repeated layout and paint, what forces layout per frame, how to read a performance profile of jank.
2. **Selection questions** (declarative vs timeline vs physics vs platform) test matching the tool to the *control* needed, not the trend.

## Why It Matters

- **UX skill** — animation is a key differentiator in product quality
- **Performance** — animations impact perceived and actual performance
- **Accessibility** — must be inclusive (vestibular disorders, screen readers)
- **Library fluency** — interviewers expect knowledge of Framer Motion, GSAP, etc.

## Answer Framework

```text
ANSWER STRUCTURE:
  1. Definition (CSS / WAAPI / library)
  2. How it works (compositor, transform/opacity)
  3. Implementation (code example)
  4. Performance (GPU vs CPU, jank, will-change)
  5. Accessibility (prefers-reduced-motion, focus)
```

## Beginner

**Q1: What is the difference between CSS transitions and `@keyframes` animations?**

A: A **transition** animates between two states (start → end) when something changes (e.g., `:hover`, class change, JS). A **`@keyframes`** animation is multi-step, can loop, delay, and play without any state change. Transitions are for two-state reactions; `@keyframes` are for declarative sequences.

**Q2: What is the `transform` property and which values are GPU-accelerated?**

A: `transform` changes visual translation, scale, rotation or skew without changing normal-flow geometry. Eligible transform animations can be composited without repainting each frame. No transform value promises a GPU path or a fixed frame rate; measure layer size, painting and main-thread work.

**Q3: How do you create a hover effect?**

A: Use `transition` to interpolate a property and change it on `:hover`:

```css
.button {
  background: blue;
  transition: transform 0.3s ease, background 0.3s ease;
}
.button:hover {
  background: darkblue;
  transform: translateY(-2px);
}
```

**Q4: What is hardware acceleration?**

A: Hardware acceleration means some rendering work uses GPU resources. Compositing an existing layer can be cheaper than rerunning layout and paint, but promotion, rasterization and memory still cost work. Choosing transform/opacity makes efficient paths possible; it does not guarantee them.

**Q5: What is `will-change`?**

A: A CSS hint that tells the browser which properties will animate, so it can pre-optimize (create a compositor layer, allocate GPU memory). Use sparingly — overuse consumes GPU memory and slows down the page. Remove after the animation completes.

**Q6: What are CSS animation properties?**

A: `animation-name`, `animation-duration`, `animation-timing-function`, `animation-delay`, `animation-iteration-count`, `animation-direction`, `animation-fill-mode`, `animation-play-state`. Combined into the shorthand: `animation: name duration timing delay iter dir fill state`.

## Intermediate

**Q7: How do you create a CSS keyframe animation?**

A: Define keyframes with `@keyframes`, then apply via `animation` property:

```css
@keyframes fadeIn {
  from { opacity: 0; }
  to { opacity: 1; }
}
.fade-in {
  animation: fadeIn 0.5s ease-out forwards;
}
```

**Q8: What is `animation-fill-mode`?**

A: Defines how styles apply before and after the animation:
- `none` — element reverts to its base state when not animating
- `forwards` — element retains the final state after the animation
- `backwards` — element gets the first keyframe styles during delay
- `both` — applies both forwards and backwards

**Q9: How do you optimize CSS animations for performance?**

A: Start with the recording: identify layout, paint, JavaScript or raster cost. Prefer transform/opacity when they express the effect; reserve layout animation for effects that need changing geometry. Apply `will-change` only when measurement justifies it. Containment can constrain particular work, with layout/paint effects on descendants; `contain: paint` is not a general layout-thrashing fix. Reduced motion is a separate user preference.

**Q10: What is the FLIP technique?**

A: First, Last, Invert, Play — a technique for animating between two layout states smoothly: (1) capture initial position (`First`), (2) apply the new layout, capture final position (`Last`), (3) compute the delta, apply `transform: translate(dx, dy)` to revert to the initial position (`Invert`), (4) remove the transform with a transition to animate to the natural position (`Play`). Framer Motion's `layout` prop does this automatically.

**Q11: How do you handle animations in responsive design?**

A: (1) Use `clamp()` for fluid sizing in keyframes. (2) Use media queries to reduce animation distance/duration on small screens. (3) Always respect `prefers-reduced-motion`. (4) Test on touch devices — gestures change animation needs.

**Q12: What is the Web Animations API (WAAPI)?**

A: WAAPI creates browser-managed `Animation` objects through `element.animate()`. Playback controls include play, pause, reverse and cancel, and completion has a promise that can reject on cancellation. Rendering still depends on the animated properties and browser; native playback does not promise 60fps or compositor-only execution.

## Senior

**Q13: What is Framer Motion and when do you reach for it?**

A: A React animation library with declarative API (`<motion.div>`), built-in gestures (`whileHover`, `whileTap`, `drag`), `<AnimatePresence>` for exit animations, `layout` prop for FLIP transitions, `useScroll` for scroll-linked animations. Reach for it when: React app, complex state-driven animations, gesture support needed, layout transitions, or scroll-linked motion.

**Q14: How does Framer Motion achieve good performance?**

A: Motion can update motion values and styles without a React render for every sample, and can use native browser playback where supported. Layout measurement and gesture handling still need main-thread work. Profile the exact effect; do not describe the entire engine as compositor-only or rely on automatic layer promotion as a performance guarantee.

**Q15: Framer Motion vs React Spring?**

A: Compare the interaction's control needs. Motion combines presence, layout projection, gestures and animated targets. React Spring emphasizes spring values, interruption and adapters, while also supporting duration/easing and decay. Both can express spring motion. Choose by the interaction, platform adapter and integration cost rather than claiming one owns all natural motion.

**Q16: How do you implement page transitions in React?**

A: A surviving `AnimatePresence` wrapper can retain a keyed outgoing child until its exit completes. `mode="wait"` sequences a single incoming child after its predecessor exits. The router must expose and preserve that lifecycle; adding a wrapper to a Next.js App Router root layout alone does not guarantee it. Use a supported router view-transition integration or a tested local transition, and handle focus and reduced motion. See the Motion and view-transition chapters for the canonical mechanisms.

**Q17: How do you make animations accessible?**

A: Preserve readable states, keyboard operation and focus while an effect runs. Honor reduced motion with immediate changes or an appropriate quieter alternative. Avoid unsafe flashing and provide required pause/stop/hide controls for moving content. Feedback can animate when its meaning remains accessible; a universal 400ms cutoff or a rule forbidding all essential UI animation is not an accessibility standard.

**Q18: What causes animation jank and how do you fix it?**

A: Find the bottleneck before choosing a fix. Repeated layout reads after writes, expensive painting, long JavaScript tasks and excessive layers can all cause jank. Batch reads/writes, reduce visual cost or split/offload suitable computation. `requestAnimationFrame` aligns callbacks with rendering opportunities but does not make expensive work cheap; workers cannot directly manipulate the DOM or guarantee smooth display.

**Q19: How do you create scroll-triggered animations?**

A: Separate threshold-triggered effects from continuously linked progress. Intersection Observer suits an element entering view; CSS `scroll()`/`view()` timelines or library scroll values link animation progress to scrolling. A scroll listener can schedule bounded work, but wrapping each event in rAF does not automatically reduce callback frequency. Provide a usable unsupported-browser and reduced-motion state.

**Q20: How do you test animations?**

A: Test behavior (open/closed state, cancellation, cleanup and focus), capture representative visual states deterministically, and record real browser performance on representative devices. rAF timing measures callback opportunities, not displayed frames. Lighthouse and INP can reveal related loading/interaction issues but are not complete animation smoothness tests.

**Q21: How do you handle animations in SSR (Next.js, Remix)?**

A: Server-render useful markup and stable initial styles. Run browser-dependent animation code after a client boundary/hydration. `'use client'` applies to React Server Component boundaries, not every SSR framework. Load optional heavy effects when justified, preserve a readable nonanimated fallback, and avoid hiding essential content until JavaScript runs.

**Q22: How do you animate complex sequences?**

A: Use delays/keyframes for simple declarative sequences, variants for coordinated component targets, a timeline for explicit overlapping tracks, or await WAAPI playback completion for a controlled sequence. `commitStyles()` writes the current animated styles to inline styles; it does not itself sequence animations. Handle cancellation and the final base state.

## FAANG-style

**Q23: Design an animation system for a design system.**

A: Define which state changes deserve motion, then shared durations/easings/distances and reusable controls. Establish component-specific reduced-motion and focus behavior, cancellation rules and browser fallbacks. Document representative states and measure critical interactions. Duration and performance budgets are product decisions verified with users and devices, not universal 200/400ms laws.

**Q24: How would you optimize animations for low-end devices?**

A: Reduce costly effects and simultaneous work based on measured interactions and user preferences. Hardware concurrency and device-memory values are coarse, sometimes unavailable or privacy-limited hints; they do not classify a device's animation performance. Test representative hardware and graceful degradation rather than disabling features at a fixed core or RAM threshold.

**Q25: Explain animation performance monitoring.**

A: Use a performance trace to separate JavaScript, layout, paint, raster and compositing work. At 60Hz a refresh interval is roughly 16.7ms; higher-refresh displays have less time, and callbacks do not measure actual presentation. Long-task entries detect sufficiently long main-thread tasks, not all dropped frames. Field INP tracks interaction latency; complement it with targeted recordings and visual review.

**Q26: How do you handle animations in micro-frontends?**

A: Agree on motion tokens and cross-boundary lifecycle/focus behavior, then decide whether sharing a compatible library actually reduces total cost. Module Federation can share dependencies but needs version/lifecycle coordination. CSS scoping reduces selector collisions; it does not isolate main-thread or GPU resource use. Measure the composed page as well as each application.

**Q27: Design a page transition system for a multi-page app.**

A: For actual cross-document navigation, start with supported View Transitions opt-in on both eligible documents and a usable ordinary navigation fallback. An SPA route transition has a different lifecycle and needs router integration. Keep loading/error states, cancellation, title/focus updates and reduced motion explicit. Announcing an entire page with one `aria-live` region can be noisy; use targeted navigation announcements where needed.

## Follow-ups

**Q28: How do you handle animations in React Server Components?**

A: A Server Component can emit markup/classes for CSS effects and pass serializable initial data to a client component. Interactive Motion hooks belong on the client. Preserve essential content and meaning during server render; animation does not convert browser events into server behavior.

**Q29: How do you handle animations with third-party libraries?**

A: (1) Check if they expose `data-` attributes or CSS classes for animation hooks. (2) Wrap them in a client component with Framer Motion. (3) Use `useReducedMotion` to disable for accessibility. (4) Test that the library's internal animations also respect the motion preference (not all do).

**Q30: How do you handle animation performance at scale?**

A: Inventory important interactions, track field responsiveness and profile expensive flows. CI can enforce selected bundle/loading/interaction budgets, but Lighthouse alone cannot prove animation smoothness. Review property cost, cleanup, cancellation, reduced motion and focus for the specific effect; 'GPU-only properties' is not a universal requirement.

**Q31: How do you handle animations in different browsers?**

A: Set a supported-browser policy, detect optional CSS/API features, and keep a readable nonanimated fallback. Test real engines and critical effects. Modern target browsers support keyframes; vendor prefixes and transition fallbacks are not the primary solution for optional View Transitions, scroll timelines or engine bugs. `@supports` tests recognized syntax, not bug-free behavior.

**Q32: How do you handle animations with content changes?**

A: Give list items stable identities so layout projection can relate old and new positions; use presence retention for actual removals. React `useTransition` marks state updates as nonurgent and can preserve an existing UI during a suspending update; it does not animate interpolation or universally keep every outgoing view. Same-document and cross-document View Transitions have distinct integration paths.

## Summary

Explain an animation through the state change, DOM lifecycle and rendering work it causes. Choose control APIs for that behavior, then test cancellation, focus, reduced motion and cost on representative browsers/devices.

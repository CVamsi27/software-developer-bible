# HTML Fundamentals — Semantic HTML, Forms, Accessibility

> HTML is the backbone of every web page. This covers semantic elements, forms, accessibility attributes, meta tags, and document structure.

## Semantic Elements

| Element | Use Case | Replaces |
| --------------------------- | ---------------------- | ----------------------- |
| `<header>` | Page/section header | `<div class="header">` |
| `<nav>` | Navigation links | `<div class="nav">` |
| `<main>` | Primary content | `<div class="main">` |
| `<article>` | Self-contained content | `<div class="post">` |
| `<section>` | Thematic grouping | `<div class="section">` |
| `<aside>` | Sidebar content | `<div class="sidebar">` |
| `<footer>` | Page/section footer | `<div class="footer">` |
| `<figure>` + `<figcaption>` | Image with caption | `<div>` wrapper |
| `<details>` + `<summary>` | Expandable content | Custom JS accordion |
| `<time datetime="...">` | Machine-readable date | `<span>` |

### Why Semantics Matter
- **Accessibility:** Screen readers use semantics to convey structure
- **SEO:** Search engines use semantics to understand content hierarchy
- **Maintainability:** Code is self-documenting

## Forms

### Key Attributes
| Attribute | Purpose | Example |
| ------------------------- | ---------------------------------- | ----------------------------- |
| `required` | Field must have a value | `<input required>` |
| `pattern` | Regex validation | `pattern="[A-Za-z]{3}"` |
| `minlength` / `maxlength` | String length limits | `minlength="2"` |
| `min` / `max` | Numeric/date limits | `min="0" max="100"` |
| `type` | Input type + validation + keyboard | `type="email"`, `type="tel"` |
| `aria-describedby` | Links to error/help text | `aria-describedby="error-id"` |
| `aria-invalid` | Validation state | `aria-invalid="true"` |

### Input Types
| Type | Mobile Keyboard | Validation |
| -------- | --------------- | ------------- |
| `email` | Email keyboard | Email format |
| `tel` | Phone keyboard | None |
| `number` | Number keyboard | Number format |
| `date` | Date picker | Date format |
| `url` | URL keyboard | URL format |
| `search` | Search keyboard | None |

## Meta Tags

```html
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Patient Dashboard — Docita</title>
  <meta name="description" content="Manage patient appointments securely." />
  <meta name="robots" content="index, follow" />
  <link rel="canonical" href="https://docita.work/dashboard" />
  <meta property="og:title" content="Patient Dashboard — Docita" />
  <meta property="og:description" content="Manage patient appointments securely." />
  <meta property="og:image" content="/og-image.png" />
  <meta name="twitter:card" content="summary_large_image" />
  <meta name="theme-color" content="#1a73e8" />
</head>
```

| Tag | Purpose | Best Practice |
| -------------------- | --------------------------- | ---------------------------- |
| `<title>` | Browser tab / search result | 50-60 chars, primary keyword |
| `<meta description>` | Search snippet | 150-160 chars, compelling |
| `<link canonical>` | Preferred URL | Self-referencing |
| `og:*` | Social sharing | Title, description, image |

## Accessibility (HTML Level)

### ARIA Attributes
| Attribute | Purpose | Example |
| ------------------ | --------------------------------- | --------------------------------- |
| `aria-label` | Accessible name (no visible text) | `<button aria-label="Close">` |
| `aria-labelledby` | References visible label | `<div aria-labelledby="title">` |
| `aria-describedby` | References description | `<input aria-describedby="help">` |
| `aria-live` | Dynamic changes announced | `aria-live="polite"` |
| `aria-hidden` | Hides from screen readers | `aria-hidden="true"` for icons |
| `role` | Explicit role | `role="alert"`, `role="status"` |

### Keyboard Navigation
- Use `<button>`, `<a>`, `<input>` — not `<div onclick>`
- Tab order: logical, no positive `tabindex`
- Focus must be visible (don't remove `:focus` outline)
- Skip links: `<a href="#main" class="skip-link">Skip to content</a>`

## Interview Tips
- Explain why `<div>` is not semantic
- Know `aria-label` vs `aria-labelledby` vs `aria-describedby`
- Explain `preload` vs `prefetch` vs `preconnect`
- Know why `<button>` beats `<div onclick>` (keyboard, focus, semantics)

## Summary

1. **Semantic HTML is the accessibility and SEO foundation** — pick elements by meaning, never by default styling
2. **Forms are state machines** — inputs, labels, validation attributes, and error semantics (`aria-describedby`, `role="alert"`)
3. **Meta tags control the platform** — viewport for responsive behavior, description/OG for sharing, `theme-color` for polish
4. **`<button>` beats `<div onclick>`** every time: keyboard focus, screen-reader role, and form submission for free
5. **Resource hints (`preload`/`prefetch`/`preconnect`) are performance levers** declared in plain HTML

# SEO — Meta Tags, Structured Data, Core Web Vitals

> **Technical SEO fundamentals for frontend developers — what crawlers see, what users experience.**

---

## TL;DR

SEO is (1) crawlable structure, (2) semantic HTML, (3) metadata, (4) performance — and for React apps, server-rendered content, because crawlers historically under-execute JS. Framework choice (SSR/SSG, → 10.4.1.01) is now an SEO decision.

## First Principles

SEO is making content machine-consumable — crawlers are users with constraints:

1. **Crawl → render → index → rank, each stage has failure modes**: robots/noindex gates discovery, SSR/hydration gates rendering (→ 10.4.1.01's why-SSR exists), canonical/structured-data gates identity and meaning.
2. **The ranking signal is relevance × experience**: Core Web Vitals (→ 50.3.1.01) and mobile-friendliness are *table-stakes filters*, not winners — content relevance still dominates; performance keeps you out of the penalty box.
3. **Metadata is the contract**: title/hreflang/canonical/JSON-LD — each answers a crawler question; duplicate or conflicting answers split ranking across URLs.

## Definition

**SEO** (Search Engine Optimization) is the practice of making content discoverable, crawlable, and understandable by search engines: technical (rendering, indexing, canonicals), on-page (semantics, headings, metadata), and experiential (speed, Core Web Vitals → 50.3.1.01).

## Why It Matters

Most frontend interviews treat SEO as "meta tags," but the senior conversation is rendering strategy: a client-only SPA is invisible until the crawler executes JS; SSG/SSR/ISR (→ 10.4.1.01, → 10.4.3.05) ship the content in the HTML. Metadata, structured data, and canonicals are the mechanical half.


## On-Page SEO

| Element | Best Practice | Example |
| -------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `<title>` | 50-60 chars, primary keyword first | `<title>Docita — Clinic Management Software</title>` |
| `<meta description>` | 150-160 chars, compelling, includes CTA | `<meta name="description" content="Manage appointments, patients, and prescriptions with Docita. Free trial.">` |
| `<h1>` | One per page, describes main topic | `<h1>Clinic Management Dashboard</h1>` |
| `<h2>`-`<h6>` | Logical hierarchy, keywords | Use for section headings |
| `<img alt>` | Descriptive, includes keywords naturally | `<img alt="Docita appointment calendar view">` |
| `<a href>` | Descriptive anchor text, not "click here" | `<a href="/features">View Features</a>` |
| `<link canonical>` | Self-referencing for duplicate prevention | `<link rel="canonical" href="https://docita.work/features">` |
| `<meta viewport>` | Mobile-first responsive | `<meta name="viewport" content="width=device-width, initial-scale=1">` |

## Core Web Vitals

Google's three metrics that measure user experience:

| Metric | What It Measures | Good Threshold | How to Improve |
| ----------------------------------- | ------------------- | -------------- | ---------------------------------------------------- |
| **LCP** (Largest Contentful Paint) | Loading performance | < 2.5 seconds | Optimize images, use CDN, preload critical resources |
| **INP** (Interaction to Next Paint) | Interactivity | < 200ms | Reduce JS execution, break up long tasks |
| **CLS** (Cumulative Layout Shift) | Visual stability | < 0.1 | Set image dimensions, use font-display: swap |

### LCP Optimization

```html
<!-- Preload critical resources -->
<link rel="preload" href="/hero-image.webp" as="image">
<link rel="preload" href="/fonts/inter.woff2" as="font" crossorigin>
<link rel="preconnect" href="https://fonts.googleapis.com">

<!-- Use modern image formats -->
<picture>
  <source srcset="/hero.webp" type="image/webp">
  <img src="/hero.jpg" alt="Hero" width="1200" height="600">
</picture>
```

### CLS Prevention

```css
/* Always set dimensions for images and embeds */
img, video, iframe {
  max-width: 100%;
  height: auto;
  aspect-ratio: 16/9; /* Maintain ratio */
}

/* Prevent layout shift from fonts */
@font-face {
  font-family: 'Inter';
  font-display: swap; /* Show fallback immediately */
  src: url('/fonts/inter.woff2') format('woff2');
}

/* Reserve space for dynamic content */
.ad-slot {
  min-height: 250px; /* Prevents shift when ad loads */
}
```

### INP Optimization

```typescript
// Break up long tasks
function processLargeDataset(items: any[]) {
  const CHUNK_SIZE = 100;
  let index = 0;

  function processChunk(deadline: IdleDeadline) {
    while (index < items.length && deadline.timeRemaining() > 0) {
      processItem(items[index]);
      index++;
    }

    if (index < items.length) {
      requestIdleCallback(processChunk);
    }
  }

  requestIdleCallback(processChunk);
}

// Use scheduler.yield() for yielding to main thread
async function heavyComputation() {
  for (let i = 0; i < 1000000; i++) {
    if (i % 10000 === 0) {
      await new Promise((resolve) => setTimeout(resolve, 0));
    }
    doWork(i);
  }
}
```

## Technical SEO Checklist

| Category | Item | How to Check |
| ---------------- | ----------------------------- | ----------------------------------------------------- |
| **Crawlability** | robots.txt allows crawling | `curl https://site.com/robots.txt` |
| **Crawlability** | XML sitemap exists | `curl https://site.com/sitemap.xml` |
| **Crawlability** | No orphan pages | Screaming Frog crawl |
| **Indexability** | No noindex on important pages | `<meta name="robots" content="index, follow">` |
| **Indexability** | Canonical tags correct | Self-referencing for primary pages |
| **Performance** | LCP < 2.5s | Lighthouse, PageSpeed Insights |
| **Performance** | INP < 200ms | Chrome DevTools Performance |
| **Performance** | CLS < 0.1 | Lighthouse, Web Vitals library |
| **Mobile** | Responsive design | Mobile-Friendly Test |
| **Mobile** | Viewport meta tag | `<meta name="viewport" content="width=device-width">` |
| **Security** | HTTPS everywhere | Certificate valid, no mixed content |
| **Security** | HSTS header | `Strict-Transport-Security: max-age=31536000` |

## SSR vs CSR vs SSG for SEO

| Rendering | How It Works | SEO | Performance | Use Case |
| ---------------------------- | ------------------------------- | --------------------------- | ---------------- | ------------------------- |
| **CSR** (Client-Side) | JS renders in browser | Bad (crawlable but delayed) | After first load | Dashboards (behind auth) |
| **SSR** (Server-Side) | Server renders HTML per request | Excellent | Server load | Public pages, marketing |
| **SSG** (Static Generation) | Build-time HTML generation | Excellent | Fastest | Blog, docs, landing pages |
| **ISR** (Incremental Static) | SSG + revalidation | Excellent | Fast | E-commerce, news |

```typescript
// Next.js App Router: SSG/ISR for public pages, SSR for dynamic content

// app/features/page.tsx — static + hourly ISR (great for SEO)
export const revalidate = 3600; // ISR: revalidate hourly

export default async function FeaturesPage() {
  const features = await fetchFeatures();
  return <FeatureList features={features} />;
}

// app/dashboard/[id]/page.tsx — SSR (dynamic, behind auth)
import { cookies } from 'next/headers';
import { redirect } from 'next/navigation';

export default async function DashboardPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  const session = await getSession(await cookies());
  if (!session) redirect('/login');
  const data = await fetchDashboardData(id, { cache: 'no-store' });
  return <Dashboard data={data} />;
}

// Legacy note: in the Pages Router these were getStaticProps/getServerSideProps —
// same strategies, different API. New code should use the App Router.
```

## Crawl Budget Optimization

| Issue | Problem | Fix |
| ---------------------- | ------------------------------ | ------------------------------ |
| **Duplicate content** | Same page at multiple URLs | Canonical tags, 301 redirects |
| **Faceted navigation** | Infinite URL combinations | robots.txt, noindex, canonical |
| **Orphan pages** | Pages not linked from anywhere | Internal linking strategy |
| **Thin pages** | Pages with little content | Merge or noindex |
| **Redirect chains** | Multiple redirects in sequence | Flatten to single redirect |

## Interview Questions

**Q: "How do you handle SEO for a SPA?"**

> For public-facing pages (marketing, blog): use SSG (Next.js static export) or SSR (server-side rendering). For pages behind authentication (dashboard): CSR is fine — search engines don't need to index private data. Use Next.js: SSG for `/features`, `/pricing`, `/blog`; SSR for `/dashboard/[id]`; API routes for `/api/*`. Implement structured data (JSON-LD) for rich snippets. Set canonical tags to prevent duplicate content. Monitor Core Web Vitals via CrUX data.

**Q: "What are Core Web Vitals and why do they matter for SEO?"**

> Core Web Vitals are three metrics Google uses to measure user experience: LCP (loading speed — < 2.5s), INP (interactivity — < 200ms), CLS (visual stability — < 0.1). They're ranking factors — sites with poor CWV rank lower. For Docita: LCP optimization via image preloading and CDN, INP via breaking up long tasks, CLS via setting image dimensions and font-display: swap. Use Lighthouse in CI/CD to catch regressions.

## Real-World Use Cases

- **Migrating CRA-style SPA → Next.js** — the SEO payoff (content in HTML) is usually the business justification; ISR keeps it fresh (→ 10.4.3.05).
- **E-commerce category pages** — canonical tags for filtered variants, structured data (`Product` schema) for rich results, `generateMetadata` per route (→ 10.4.2.03).
- **Content sites** — sitemap.xml + robots.txt + per-page OG tags; social preview cards are SEO-adjacent UX.

## Common Mistakes

1. **Client-only rendering for content pages** — crawler sees an empty shell; if content matters, prerender it.
2. **Duplicate content via query params** — missing `rel=canonical` splits ranking across URL variants.
3. **Metadata as an afterthought** — same title on every page wastes the primary ranking surface; per-route titles/descriptions are table stakes.
4. **Ignoring structured data** — schema.org markup (`Article`, `Product`, `FAQ`) drives rich results; pure-tag SEO leaves that surface unused.

## Best Practices

- **One `<h1>`, logical heading nesting** — the outline machines read (→ 10.7.01).
- **Per-route metadata** (framework-managed, → 10.4.2.03) + OG/Twitter cards.
- **Measure LCP/CLS/INP** — Core Web Vitals are a ranking input, not just UX (→ 50.3.1.01).
- **Verify with the crawler's eyes**: Google Search Console's URL inspection, not your browser.

## Summary

1. **Crawl → render → index → rank** — JavaScript rendering is a second-class path; SSR/SSG for content that must rank
2. **Canonicals and redirects consolidate signals** — duplicate content is a self-inflicted wound
3. **Structured data (JSON-LD) buys rich results** — schema.org types map to your domain entities
4. **Core Web Vitals are a ranking input** — LCP/INP/CLS tie SEO to performance work
5. **Sitemaps and robots directives steer the crawler** — `noindex` beats disallow for removal

## Cheat Sheet

```text
CRAWLABLE   SSR/SSG/ISR for content · robots.txt · sitemap.xml
SEMANTIC    one h1 · landmarks · alt text (→ 10.7.01)
META        unique title/description per route · canonical · OG tags
STRUCTURED  schema.org JSON-LD (Article/Product/FAQ) → rich results
SPEED       LCP < 2.5s · CLS < 0.1 · INP < 200ms (→ 50.3.1.01)
VERIFY      Search Console URL inspection · rendered HTML, not dev tools
```

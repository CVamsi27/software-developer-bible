# SEO — Meta Tags, Structured Data, Core Web Vitals

> **Technical SEO fundamentals for frontend developers — what crawlers see, what users experience.**

---

## Definition

Technical SEO helps search systems discover, fetch, render and understand intended public content. Metadata, crawl controls, URL identity and useful content work together. Successful rendering or a perfect performance score does not guarantee indexing or ranking.

> **Textbook Definition:** Technical search-engine optimization makes intended public resources discoverable, renderable and identifiable to search systems. Crawl policy, canonical identity and structured metadata guide processing without guaranteeing inclusion or ranking.

## First Principles

A search system cannot evaluate content it never discovers or cannot retrieve. If a URL returns an empty application shell, the system must also execute the necessary JavaScript before understanding the page. Each boundary has different evidence: a crawlable link, HTTP response, rendered content, index eligibility and a chosen canonical identity.

## Follow one public product page

```text
internal link → fetch /products/42 → meaningful HTTP response
                                    ↓
                         content + metadata/rendered result
                                    ↓
                         indexing/canonical decisions → possible search result
```

A valid product returns public content and an accurate title. A missing product returns a meaningful missing-page response rather than an empty shell with status 200. The page links to related public URLs through real anchor elements. Its declared canonical points to the preferred equivalent URL, while internal links and sitemap entries agree.

Google can execute JavaScript, but rendering has constraints and other crawlers may not execute it. SSR/SSG can make content available in the response and simplify retrieval; CSR is not inherently unindexable. Inspect the fetched and rendered evidence instead of assigning a universal "bad/excellent" grade to each rendering strategy. [Google's JavaScript SEO guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).

Private dashboards require access control. `noindex` and robots directives do not protect confidential content, and their rendering strategy is not the security boundary.

## Metadata describes content; it does not enforce identity

```html
<title>Compact Desk — Example Store</title>
<meta name="description" content="Dimensions, materials and delivery options for the Compact Desk.">
<link rel="canonical" href="https://example.com/products/42">
<meta property="og:title" content="Compact Desk — Example Store">
<meta property="og:image" content="https://example.com/images/compact-desk.jpg">
```

Use distinct descriptive titles, accurate summaries and meaningful headings. Search systems can rewrite titles/snippets; fixed character counts are editorial heuristics rather than hard limits. Image descriptions serve their content/accessibility purpose instead of keyword stuffing.

Canonical declarations are signals, not commands. They do not redirect a user or remove duplicate URLs. Use consistent canonical signals for genuinely equivalent content and redirects for an intentional permanent move. A filter producing a substantially different useful page may need its own indexable identity rather than a blanket canonical to its parent.

## Crawling and indexing controls have different effects

| Mechanism | Job and limitation |
| --------------------- | ------------------------------------------------------------------------------- |
| Crawlable links | Help discover URLs; avoid relying only on click handlers |
| Sitemap | Suggest preferred URLs for discovery; not an indexing guarantee |
| `robots.txt` disallow | Restrict crawling; a known blocked URL may still appear without fetched content |
| `noindex` meta/header | Request exclusion when the crawler can fetch and observe it |
| Redirect | Move retrieval to another URL with the appropriate status |

Do not block crawling and expect the crawler to discover a newly added `noindex` in that blocked response. Keep pagination/faceted navigation bounded and intentional. Inspect responses, robots/header directives and rendered content with Search Console and appropriate fetches.

## Structured data describes supported meaning

JSON-LD can describe visible content using an applicable schema. Validate required properties and the search system's feature eligibility; valid schema alone does not guarantee a rich result. Keep product price, availability and identity consistent with what users can actually see.

Google stopped showing FAQ rich results from May 7, 2026 and removed that feature's documentation in June. `FAQPage` remains a vocabulary concept, but must not be taught as a current Google rich-result opportunity. Check feature support against the current [Search documentation changelog](https://developers.google.com/search/updates).

## Performance is user evidence, not a rank guarantee

| Core Web Vital | Good threshold | What it observes |
| -------------- | ------------------ | ----------------------------------------------- |
| LCP | ≤ 2.5 seconds | Loading of the largest eligible visible content |
| INP | ≤ 200 milliseconds | Responsiveness across user interactions |
| CLS | ≤ 0.1 | Unexpected layout movement |

Assess the 75th percentile of page visits, separating mobile and desktop. Lab tests help reproduce problems; Lighthouse's navigation run does not itself measure real-user INP because it has no representative user interaction. Use field data and interaction traces alongside lab evidence. [Web Vitals measurement guidance](https://web.dev/articles/vitals).

Dimensions and suitable fallback-font metrics can reduce shifts; `font-display: swap` alone does not guarantee zero CLS. Optimize the measured loading/interaction path, and preserve semantic content. Good page experience is one part of search quality, not a substitute for relevance or guaranteed ranking improvement.

## Summary

Trace discovery, retrieval, rendered content and index eligibility before changing tags. Keep URL signals consistent, distinguish crawl restrictions from exclusion and validate current structured-data support. Measure user experience while treating indexing and ranking as separate outcomes.

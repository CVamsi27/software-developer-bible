# SEO — Meta Tags, Structured Data, SSR Benefits

## On-Page SEO
| Element | Best Practice |
|---------|---------------|
| `<title>` | 50-60 chars, primary keyword first |
| `<meta description>` | 150-160 chars, compelling, includes CTA |
| `<h1>` | One per page, describes main topic |
| `<h2>`-`<h6>` | Logical hierarchy, keywords |
| `<img alt>` | Descriptive, includes keywords naturally |
| `<a href>` | Descriptive anchor text, not "click here" |
| `<link canonical>` | Self-referencing for duplicate prevention |

## Structured Data (JSON-LD)

```json
{

  "address": {
    "@type": "PostalAddress",
    "addressCountry": "DE"
  }

```

## Technical SEO
- **Sitemap:** `sitemap.xml` listing all pages
- **Robots.txt:** `User-agent: * Allow: / Disallow: /api/`
- **Page speed:** Core Web Vitals (LCP, INP, CLS)
- **Mobile-first:** Responsive design, viewport meta tag
- **Internal linking:** Logical hierarchy, breadcrumbs
- **URL structure:** Clean, descriptive, no query params for content

## SSR vs SPA for SEO
| Aspect | SPA (Vite) | SSR (Next.js) |
|--------|-----------|---------------|
| SEO | Client-rendered (bad for crawlers) | Server-rendered (good for SEO) |
| Initial load | Faster after first load | Faster first paint |
| Use case | Dashboard (behind auth) | Public pages, marketing |

## Interview Tips
- Know SSR vs CSR vs SSG for SEO
- Explain structured data and rich snippets
- Know Core Web Vitals and their thresholds
- Understand crawler behavior and rendering

# Browser Rendering — Critical Rendering Path, Reflow, Paint

## Critical Rendering Path
1. **HTML parsing** → DOM tree
2. **CSS parsing** → CSSOM tree
3. **Render tree** = DOM + CSSOM (only visible elements)
4. **Layout** (reflow): calculate geometry (position, size)
5. **Paint**: fill pixels (colors, text, shadows)
6. **Composite**: combine layers into final image

## Reflow vs Repaint vs Composite
| Operation | Trigger | Cost |
|-----------|---------|------|
| **Reflow** | Layout change (width, height, position) | Expensive |
| **Repaint** | Visual change (color, shadow) | Moderate |
| **Composite** | Transform, opacity, filter | Cheapest |

## Performance Best Practices
| Do | Don't |
|----|-------|
| Use `transform` for animations | Animate `width`, `height`, `top`, `left` |
| Use `opacity` for fade | Use `visibility` + `display` |
| Batch DOM reads/writes | Read between writes (forces reflow) |
| Use `will-change` for animations | Animate too many properties |
| Use `content-visibility: auto` | Render off-screen content |

## CSS Containment
```css
.card {
  contain: layout style paint; /* Isolates reflow/repaint */
}
```

## Browser Rendering Pipeline
```
HTML → DOM → Render Tree → Layout → Paint → Composite
  ↓       ↓
CSS → CSSOM
```

## Key Concepts
- **Critical CSS:** Inline above-the-fold CSS, defer rest
- **Layout Thrashing:** Reading layout properties forces synchronous reflow
- **GPU acceleration:** `transform`, `opacity`, `filter` are composited on GPU
- **Layer promotion:** `will-change: transform` creates a new compositing layer

## Interview Tips
- Explain the critical rendering path
- Know reflow vs repaint vs composite
- Explain why `transform: translateX(100px)` is better than `left: 100px`
- Know `content-visibility: auto` for off-screen optimization

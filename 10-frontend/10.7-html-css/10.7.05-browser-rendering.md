# Browser Rendering — Critical Rendering Path, Reflow, Paint

> **How browsers turn HTML/CSS/JS into pixels — and how to avoid performance pitfalls.**

---

## Critical Rendering Path

The Critical Rendering Path (CRP) is the sequence of steps the browser takes to convert HTML, CSS, and JavaScript into pixels on screen.

```
1. HTML Parsing → DOM Tree
2. CSS Parsing → CSSOM Tree
3. Render Tree = DOM + CSSOM (only visible elements)
4. Layout (Reflow) → calculate geometry (position, size)
5. Paint → fill pixels (colors, text, shadows, borders)
6. Composite → combine layers into final image
```

```
┌──────────────────────────────────────────────────────────┐
│ Critical Rendering Path │
│ │
│ HTML ──→ DOM ──┐ │
│ ├──→ Render Tree ──→ Layout ──→ Paint ──→ Composite ──→ Screen│
│ CSS ──→ CSSOM ─┘ │
│ │
│ JS ──→ Can modify DOM ──→ Triggers re-render ──────────│
└──────────────────────────────────────────────────────────┘
```

### What Happens During Each Step

| Step | What Happens | Cost | What Slows It Down |
|------|--------------|------|-------------------|
| **DOM Construction** | Parse HTML tags into tree | Low | Large HTML, deep nesting |
| **CSSOM Construction** | Parse CSS into tree | Low | Complex selectors, large stylesheets |
| **Render Tree** | Combine DOM + CSSOM, compute styles | Low | `display: none` elements skipped |
| **Layout** | Calculate position, size of every element | **High** | Deep DOM, frequent reflows |
| **Paint** | Fill pixels (text, shadows, gradients) | Medium | Complex visual effects |
| **Composite** | Combine layers into final image | Low | Too many layers |

## Reflow vs Repaint vs Composite

| Operation | What Changes | Triggers | Cost | How to Avoid |
|-----------|--------------|----------|------|--------------|
| **Reflow** | Layout (position, size) | `width`, `height`, `top`, `left`, `margin`, `padding`, `font-size`, DOM insertion/removal | **Expensive** — affects entire layout tree | Batch DOM reads/writes, use `transform` |
| **Repaint** | Visual (color, visibility) | `color`, `background`, `box-shadow`, `visibility`, `border-style` | Moderate — only affects specific area | Minimize visual changes |
| **Composite** | Layer combination | `transform`, `opacity`, `filter` | **Cheapest** — GPU-accelerated | Use these for animations |

### Animation Cost Comparison

```css
/* EXPENSIVE: triggers reflow */
.animate-left {
  animation: moveLeft 1s ease-in-out;
}
@keyframes moveLeft {
  from { left: 0; }
  to { left: 100px; }
}

/* CHEAP: triggers composite only */
.animate-transform {
  animation: moveRight 1s ease-in-out;
}
@keyframes moveRight {
  from { transform: translateX(0); }
  to { transform: translateX(100px); }
}

/* EXPENSIVE: triggers reflow */
.animate-size {
  animation: grow 1s ease-in-out;
}
@keyframes grow {
  from { width: 100px; }
  to { width: 200px; }
}

/* CHEAP: triggers composite */
.animate-scale {
  animation: scaleUp 1s ease-in-out;
}
@keyframes scaleUp {
  from { transform: scaleX(1); }
  to { transform: scaleX(2); }
}
```

## Layout Thrashing

Layout thrashing occurs when you read a layout property (e.g., `offsetHeight`) after writing a style change. The browser must synchronously recalculate layout before returning the value.

```typescript
// LAYOUT THRASHING: read between writes
function badAnimation() {
  const elements = document.querySelectorAll('.item');

  for (const el of elements) {
    // Write: change style
    el.style.height = `${el.offsetHeight + 10}px`;
    // Read: forces synchronous layout reflow
  }
}

// BATCHED: read first, then write
function goodAnimation() {
  const elements = document.querySelectorAll('.item');

  // Phase 1: Read all layout properties
  const heights = Array.from(elements).map((el) => el.offsetHeight);

  // Phase 2: Write all changes
  elements.forEach((el, i) => {
    el.style.height = `${heights[i] + 10}px`;
  });
}

// BEST: use transform (no reflow at all)
function bestAnimation() {
  const elements = document.querySelectorAll('.item');
  elements.forEach((el) => {
    el.style.transform = 'translateY(10px)';
  });
}
```

### Properties That Trigger Reflow

| Read Properties (Force Layout) | Write Properties (Trigger Layout) |
|-------------------------------|-----------------------------------|
| `offsetHeight`, `offsetWidth` | `width`, `height` |
| `clientHeight`, `clientWidth` | `top`, `left`, `right`, `bottom` |
| `scrollTop`, `scrollLeft` | `margin`, `padding` |
| `getComputedStyle()` | `border-width`, `display` |
| `getBoundingClientRect()` | `font-size`, `position` |

## GPU Acceleration

The browser composites layers on the GPU. Certain CSS properties are GPU-accelerated:

```css
/* GPU-accelerated (composite only) */
.gpu-accelerated {
  transform: translateX(100px);
  transform: scale(1.5);
  transform: rotate(45deg);
  opacity: 0.5;
  filter: blur(5px);
  will-change: transform; /* Promote to new layer */
}

/* NOT GPU-accelerated (triggers reflow/repaint) */
.not-gpu {
  width: 200px;
  height: 200px;
  top: 10px;
  left: 10px;
  box-shadow: 0 0 10px rgba(0,0,0,0.5);
}
```

### Layer Promotion

```css
/* Create a new compositing layer */
.animated-element {
  will-change: transform; /* Hints to browser */
  transform: translateZ(0); /* Force layer promotion */
}

/* Don't overuse will-change — each layer uses GPU memory */
.complex-layout {
  /* Only promote elements that actually animate */
  will-change: transform, opacity;
}
```

## CSS Containment

CSS containment isolates elements so changes inside don't affect the outside.

```css
/* Containment types */
.card {
  contain: layout style paint;
  /* layout: internal layout doesn't affect outside */
  /* style: counters, quotes don't leak */
  /* paint: content is clipped to border box */
}

.list-item {
  contain: content; /* Shorthand for layout + style + paint */
}

/* content-visibility: skip rendering off-screen content */
.below-fold {
  content-visibility: auto;
  contain-intrinsic-size: 0 500px; /* Estimated size before render */
}
```

## Script Loading Strategies

| Strategy | Behavior | Use Case |
|----------|----------|----------|
| `<script>` | Blocks HTML parsing until downloaded | Legacy, avoid |
| `<script defer>` | Downloads in parallel, executes after DOM | Analytics, non-critical |
| `<script async>` | Downloads in parallel, executes immediately | Ads, third-party widgets |
| `<script type="module">` | Deferred by default, ES modules | Modern applications |

```html
<!-- Critical: inline in <head> -->
<script>
  // Critical path JS (e.g., theme detection)
  if (localStorage.theme === 'dark') document.documentElement.classList.add('dark');
</script>

<!-- Non-critical: defer -->
<script defer src="/app.js"></script>

<!-- Third-party: async -->
<script async src="https://analytics.example.com/script.js"></script>
```

## Interview Questions

**Q: "Why is `transform: translateX(100px)` faster than `left: 100px`?"**

> `left` triggers layout reflow — the browser must recalculate the position of the element and potentially all surrounding elements. `transform` only triggers compositing — the GPU moves the pre-rendered layer without recalculating layout. Compositing is 10-100x faster than reflow. For animations: always use `transform` (translate, scale, rotate) and `opacity` instead of layout properties (`left`, `top`, `width`, `height`).

**Q: "What is layout thrashing and how do you prevent it?"**

> Layout thrashing happens when you interleave DOM reads and writes. Reading `offsetHeight` after a style change forces a synchronous layout reflow to get the accurate value. If you do this in a loop, the browser reflows on every iteration. Prevention: (1) Batch reads first, then writes, (2) Use `requestAnimationFrame` for animations, (3) Use `ResizeObserver` instead of reading layout properties, (4) Use `transform` instead of layout properties.

## 30-Second Interview Version

> Browser rendering has 6 steps: HTML→DOM, CSS→CSSOM, Render Tree, Layout, Paint, Composite. Reflow (layout) is expensive — triggered by `width`, `top`, `display`. Composite is cheap — triggered by `transform`, `opacity`. Layout thrashing: interleaving DOM reads and writes forces synchronous reflow on every iteration — prevent by batching reads then writes. GPU acceleration: use `transform` and `opacity` for animations. CSS containment and `content-visibility: auto` skip rendering off-screen content.

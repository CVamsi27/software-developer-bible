# Tailwind CSS: Utility-First Styling with Design Tokens

A status button looks correct in development, but its red state disappears in the production build. The component constructed `bg-${color}-500` at runtime; the CSS build never saw a complete class name. To diagnose the result, trace the source scan, the token definition and the browser's cascade separately.

## Definition

**Tailwind CSS** generates CSS utilities from detected class candidates and theme values. Components compose those utilities for layout, typography, colors and interaction states. A utility can emit several declarations or nested rules; it is not necessarily one class for one declaration.

> **Textbook Definition:** A utility-first styling system expresses presentation through composable classes with narrow responsibilities. Tailwind generates those classes at build time from source candidates, configured theme values and supported variants; normal CSS cascade rules still determine the rendered result.

## First Principles

The browser needs concrete CSS rules, not the application's intention to create a class later. A build tool can generate a rule only when it has a candidate and knows how that candidate maps to CSS. Named tokens make the mapping reusable, while source detection bounds the candidate set. More detected values and variants can produce more CSS; the framework does not guarantee a constant bundle size as a product grows.

## 1. Use the configuration model for the installed major

Tailwind 4 uses CSS-first configuration. For example, a CSS entry can import the framework and define brand tokens with `@theme`:

```css
@import "tailwindcss";

@theme {
  --color-brand-600: #1d4ed8;
  --color-brand-700: #1e40af;
}
```

```html
<button class="rounded bg-brand-600 px-4 py-2 text-white hover:bg-brand-700 focus-visible:outline-2 focus-visible:outline-offset-2">
  Save changes
</button>
```

The color namespace supplies the brand utilities; spacing and radius use the framework's configured/default scales. Token names alone do not establish readable contrast, keyboard usability or a sufficient hit area. Test the rendered button in every required state and theme.

Tailwind 3 commonly uses a JavaScript configuration with `theme.extend`, `content` and `safelist`. Version 4 can load compatible JavaScript configuration explicitly with `@config`, but does not automatically discover it and does not support every old option. For example, old `corePlugins` and JavaScript `safelist` settings are not the v4 control surface. Check the upgrade guide before copying a repository's historical setup.

## 2. Detect complete class candidates

The scanner reads source as text; it does not evaluate JavaScript expressions. Map bounded variants to complete strings instead of constructing partial class names:

```typescript
const statusClasses = {
  success: 'bg-green-700 text-white',
  error: 'bg-red-700 text-white',
} as const;

function classesFor(status: keyof typeof statusClasses) {
  return statusClasses[status];
}
```

Version 4 automatically detects normal project sources subject to its documented exclusions. Register external UI-package sources with `@source` when needed, or use `@source inline(...)` for a deliberately generated set of candidates. Version 3 uses its configured content paths/safelist. Avoid scanning a giant dependency tree as a substitute for declaring the actual shared package source.

For unbounded runtime values such as a user-selected color, use a validated CSS custom property or inline style rather than synthesizing unlimited utility names. Keep validation separate from source detection: generating a style does not make untrusted input safe.

## 3. Variants are selectors and conditions

Responsive, hover, focus-visible, dark, group and peer variants change when a rule applies. Breakpoints ordinarily use viewport conditions; container-query variants have a different ancestor relationship. Choose those conditions from the component's real layout rather than assuming a device label.

Dark mode may follow a media query or an explicitly configured selector. Tokens expressed through custom properties can change under that selector without changing every class list. Keep the stored preference, effective theme and CSS selector aligned. The cascade, inheritance, layer ordering and selector matching still matter when utilities coexist with authored CSS.

## 4. Extract repeated behavior without hiding ownership

A shared button component can own its variants, semantics and focus behavior while retaining utility classes. A CSS module may still be appropriate for a complex local selector or animation. Coexistence is valid when ownership and layer precedence are clear; a migration need not delete every existing selector.

Use `@apply` for a specific authoring need rather than assuming it is either mandatory or forbidden. Check the generated rules and dependency direction. Arbitrary values are also valid escape hatches, but repeated unexplained values usually deserve a shared token. Measure the output rather than assuming utility-first automatically means smaller CSS.

## 5. Verify the built artifact and interaction

Build a fixture containing both complete status strings, then confirm both rules exist in the generated CSS. Remove one source candidate and rebuild to observe the detection boundary. Repeat from the production working directory so monorepo path assumptions are exercised.

In the browser, activate the control using a keyboard, inspect focus visibility, change themes and resize the container. A compiler check proves that CSS was emitted; it does not prove contrast, layout or accessible behavior. For migration, compare computed styles and supported-browser behavior before and after changing the integration/plugin.

## Summary

Tailwind generates utilities from detected source candidates and theme values; the browser still applies normal CSS semantics. Use the installed major's configuration model, expose complete classes to detection, declare external sources deliberately and verify the production CSS. Components, authored CSS and tokens can coexist when their responsibilities and precedence are explicit.

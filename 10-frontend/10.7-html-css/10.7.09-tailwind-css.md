# Tailwind CSS: Utility-First Styling with Design Tokens

Changing one brand color touches ten files; a component's class list grows until no one dares delete anything. Utility-first styling inverts the model: instead of inventing component names, you compose tiny single-purpose classes that map directly to design tokens, and a JIT compiler emits only the CSS your markup actually uses.

```html
<button class="px-4 py-2 bg-brand-600 text-white rounded hover:bg-brand-700 focus-visible:ring-2 focus-visible:ring-brand-400">
  Save changes
</button>
```

## Definition

**Tailwind CSS** is a utility-first CSS framework: classes such as `flex`, `pt-4`, `text-red-600` and `md:hidden` each map to one CSS declaration, and a Just-in-Time (JIT) engine scans your templates to generate only the used utilities. A `tailwind.config.ts` file maps semantic roles (brand, surface, error) to design-token values, so changing a token updates every element that references it.

> **Textbook Definition:** Tailwind CSS compiles a constrained utility vocabulary into atomic CSS at build time, driven by a design-token configuration file and a content scan that tree-shakes unused utilities out of the shipped stylesheet.

## First Principles

Design tokens come first: spacing, color, typography and radius are named values, not magic numbers. Utilities compose those tokens into layouts, and the compiler removes anything unused. The trade-off is explicit: HTML becomes more verbose, but stylesheets stop growing forever and there are no invented component names to maintain.

## 1. JIT compilation and content scanning

Styling a page in Tailwind is a compile-time pipeline:

The JIT engine scans your HTML, JSX and template files for class strings and emits exactly those utilities. A class you never write (`pb-96`) never ships. Dynamic or concatenated classes (`bg-${color}-500`) are not detected unless listed in `content` or safelisted, so runtime-generated class names can silently produce missing styles.

## 2. Design token mapping (spacing, colors, typography)

`tailwind.config.ts` extends the default theme: `colors.brand` maps to your palette, `spacing` keeps multiples of 8px, and `fontSize` ties each size to a line-height. Components reference `bg-surface` or `text-error` instead of hex values, so a rebrand is one config change plus a rebuild.

## 3. Variants: responsive, hover, dark, group, peer

Prefixes compose: `md:flex-row` applies above the medium breakpoint, `hover:opacity-75` on interaction, `dark:bg-neutral-900` under a dark theme, and `group-hover:text-brand` styles a child when its parent is hovered. Variants multiply output, so the config's `safelist` and `corePlugins` keep the bundle bounded.

## 4. Bundle-size control and dead-code elimination

Unused utilities are never emitted, so the shipped CSS stays small regardless of how many classes exist in the library. The risk is the opposite direction: unrestricted arbitrary values (`w-[437px]`, `margin-[calc(100%-2rem)]`) bypass the token system and ship one-off CSS. Reserve arbitrary values for genuine one-offs, not routine layout.

## 5. Component abstraction trade-offs

Pure utility HTML repeats the same class list everywhere. Extract repeated surfaces into components (`<PrimaryButton>`) or template partials rather than into `@apply` utilities, which hide the token chain and make the compiled output harder to audit. The rule: keep tokens visible in markup; hide repetition in components, not in CSS.

## 6. Migration pitfalls

Moving from CSS modules or scoped styles to Tailwind means deleting global selectors, not adding a new layer on top. Keep one file for genuinely global rules (reset, font loading, document-level dark-mode class) and route everything else through utilities. Do not mix scoped class names and utilities for the same element — specificity surprises follow.

## Summary

Tailwind CSS maps design tokens to utility classes and compiles only the markup-proven subset into atomic CSS. The result is a stylesheet that does not grow with the feature list: tokens live in config, variants express responsive and interactive states, and repetition is abstracted into components rather than one-off classes.

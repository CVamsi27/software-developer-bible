# React Native & Cross-Platform

## TL;DR

React Native renders **real native widgets** (UIKit on iOS, Android View hierarchy on Android) driven by your TypeScript codebase. The legacy asynchronous JSON bridge has been superseded by the New Architecture: **JSI** (direct synchronous C++ bindings), **Fabric** (concurrent native rendering engine), and **TurboModules** (lazy-loaded native modules). Choose React Native when a TypeScript engineering team must ship high-quality apps to both app stores from a shared monorepo; choose pure native (Swift/Kotlin) for deep OS integration, background compute, or hardware sensors; choose PWA for instant reach without app store review.

---

## First Principles

React Native's core trade-off follows from two fundamental architectural choices:

1. **JS Drives, Native Renders**: Rather than running inside an embedded webview (like Cordova or Capacitor), React Native executes business logic in a dedicated JavaScript engine (Hermes) while instantiating actual host UI views. The trade is maintaining a communication boundary—formerly an asynchronous JSON-serialized bridge, now synchronous C++ bindings through JSI.
2. **Native Widgets, Not DOM Elements**: You write JSX using primitive components (`<View>`, `<Text>`, `<ScrollView>`) mapped directly to platform primitives (`UIView`, `UITextView`, `android.view.ViewGroup`). Web CSS and DOM APIs do not exist; layout is calculated across platforms by Meta's C++ flexbox engine, **Yoga**.

---

## Definition

**React Native** is a cross-platform mobile application framework that brings the React declarative component model to native mobile development. Applications run JavaScript/TypeScript code inside the lightweight Hermes runtime and communicate with native iOS and Android APIs and UI components via the JavaScript Interface (JSI), delivering native performance and appearance from a unified codebase.

---

## Why Do We Need It?

1. **Single Codebase, Both App Stores**: Drastically reduces engineering overhead and prevents feature drift between iOS and Android engineering teams.
2. **Web Monorepo Synergy**: Allows sharing domain models, Zod validation schemas, API client SDKs, state machines, and business logic hooks between web and mobile applications.
3. **Over-The-Air (OTA) Updates**: Services like Expo EAS Update allow pushing critical bug fixes and asset changes directly to end users without waiting for App Store or Google Play review queues.
4. **Hermes Engine Optimization**: Ahead-of-time (AOT) bytecode compilation delivers fast startup times, low memory footprints, and reduced binary sizes on mobile devices.

## How It Works

### The Architectural Shift: Bridge vs New Architecture (JSI + Fabric)

```text
LEGACY ARCHITECTURE (Bridge):
┌────────────────────────────────────────────────────────────────────┐          JSON Serialization          ┌──────────────┐
│  JS Thread   │ ───────▶ (Batched / Async) ────────▶ │Native Thread │
│ (React code) │ ◀─────── (Bottleneck / Jank) ─────── │ (UIKit/View) │
└────────────────────────────────────────────────────────────────────┘                                      └──────────────┘

NEW ARCHITECTURE (JSI + Fabric + TurboModules):
┌────────────────────────────────────────────────────────────────────┐          Direct C++ Memory           ┌──────────────┐
│  JS Thread   │ ◀══════════════════════════════════▶ │Native Thread │
│   (Hermes)   │         Synchronous Calls (JSI)      │   (Fabric)   │
└────────────────────────────────────────────────────────────────────┘                                      └──────────────┘
```

1. **JavaScript Interface (JSI)**: A lightweight, general-purpose C++ abstraction layer that lets JavaScript hold direct references to host C++ objects and call native methods synchronously without JSON stringification.
2. **Fabric Renderer**: React Native's modern rendering engine. It unifies layout calculation via Yoga in C++, enables concurrent React 18+ features (like `useTransition` and Suspense), and allows synchronous UI measurements on the main thread, eliminating layout pop-in and scroll jank.
3. **TurboModules**: Replaces eager native module initialization. Native modules are registered lazily on first access, significantly improving application cold-start time.
4. **Codegen**: Automated build-time tool that converts TypeScript type definitions into C++ interfaces, guaranteeing strict type safety across the JS-native boundary.

### Expo Managed Workflow vs Bare React Native

| Factor | Expo Managed Workflow | Bare React Native |
| ---------------------------------- | ---------------------------------------------------- | --------------------------------------------------------- |
| **Setup & Tooling** | Instant, zero Xcode/Android Studio config required | Manual native project setup and toolchain management |
| **Native Modules** | Extensive ecosystem (`expo-*`) + Config Plugins | Direct editing of native `AppDelegate` and `build.gradle` |
| **Custom Native Code** | Supported seamlessly via Expo Prebuild & Dev Clients | Full access to arbitrary Swift/Objective-C/Kotlin code |
| **CI/CD & Cloud Builds** | Managed via EAS Build and EAS Submit | Self-hosted Fastlane pipelines or custom build runners |
| **Recommended Stance** | **Default choice today** for 95% of applications | Reserved for specialized hardware/exotic native SDKs |

## Code Examples

### UI Thread Animations with React Native Reanimated

Animations must run directly on the UI thread at 60/120 fps without crossing the JS thread boundary:

```typescript
import React from 'react';
import { StyleSheet, View, Button } from 'react-native';
import Animated, {
  useSharedValue,
  useAnimatedStyle,
  withSpring,
  withTiming,
} from 'react-native-reanimated';

export function AnimatedCard() {
  const scale = useSharedValue(1);
  const opacity = useSharedValue(1);

  // Executed on the native UI thread (Worklet)
  const animatedStyle = useAnimatedStyle(() => {
    return {
      transform: [{ scale: scale.value }],
      opacity: opacity.value,
    };
  });

  const handlePressIn = () => {
    scale.value = withSpring(0.95);
    opacity.value = withTiming(0.8, { duration: 150 });
  };

  const handlePressOut = () => {
    scale.value = withSpring(1);
    opacity.value = withTiming(1, { duration: 150 });
  };

  return (
    <View style={styles.container}>
      <Animated.View style={[styles.card, animatedStyle]} />
      <Button
        title="Toggle Scale"
        onPress={() => {
          scale.value = withSpring(scale.value === 1 ? 1.1 : 1);
        }}
      />
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center' },
  card: { width: 200, height: 120, backgroundColor: '#2563eb', borderRadius: 12 },
});
```

### Offline-First Local Storage (SQLite with expo-sqlite)

Mobile applications require resilient local state persistence that operates seamlessly offline:

```typescript
import * as SQLite from 'expo-sqlite';

interface PatientRecord {
  id: string;
  name: string;
  updatedAt: number;
}

export class LocalPatientDatabase {
  private db: SQLite.SQLiteDatabase;

  constructor() {
    this.db = SQLite.openDatabaseSync('clinic_offline.db');
    this.init();
  }

  private init() {
    this.db.execSync(`
      PRAGMA journal_mode = WAL;
      CREATE TABLE IF NOT EXISTS patients (
        id TEXT PRIMARY KEY NOT NULL,
        name TEXT NOT NULL,
        updated_at INTEGER NOT NULL
      );
    `);
  }

  savePatient(patient: PatientRecord) {
    this.db.runSync(
      'INSERT OR REPLACE INTO patients (id, name, updated_at) VALUES (?, ?, ?)',
      [patient.id, patient.name, patient.updatedAt]
    );
  }

  getPatients(): PatientRecord[] {
    return this.db.getAllSync<PatientRecord>(
      'SELECT id, name, updated_at as updatedAt FROM patients ORDER BY updated_at DESC'
    );
  }
}
```

## The Decision Matrix

| Factor | React Native | Native (Swift/Kotlin) | PWA (Progressive Web App) |
| ------------------------------------------------ | --------------------------------------- | ------------------------------------------ | ---------------------------------------- |
| **Team Skillset** | High (JavaScript / TypeScript / React) | Specialized (Swift, Kotlin, Xcode) | High (Standard web technologies) |
| **Time to Both Stores** | Fast (single cross-platform codebase) | Slow (two distinct codebase streams) | Fastest (no app store submission) |
| **Hardware & Sensor Access** | Broad (via Expo plugins/native modules) | Complete (direct SDK access on day 1) | Restricted (browser sandbox constraints) |
| **Complex Gesture / 120fps UI** | Strong (via Reanimated worklets) | Flawless (native CoreAnimation/RenderNode) | Constrained by DOM reflow limits |
| **Offline-First Resilience** | High (SQLite, MMKV, WatermelonDB) | High (CoreData, SwiftData, Room) | Moderate (IndexedDB quota limits) |
| **Store Release Burden** | Softened (EAS OTA updates for JS code) | Full (every bug fix requires review) | None (instant server-driven deploy) |
| **Push Notifications & Background Tasks** | Full support (APNs, FCM via plugins) | Full support (unrestricted lifecycle) | Variable (iOS Safari push limitations) |

## Real-World Use Cases

1. **Healthcare Clinic Mobile Companion**: Enabling doctors and staff to view schedules, check patient records offline via local SQLite, and receive push notifications on consultation updates.
2. **Fintech Consumer Apps**: Fast, unified mobile deployment featuring biometric authentication (`LocalAuthentication`), secure encrypted key-value storage (`expo-secure-store`), and shared Zod validation schemas from the backend monorepo.
3. **E-Commerce & Retail Marketplaces**: Smooth 60fps product list scrolling with `FlashList`, deep link routing via `expo-router`, and instant promotional layout adjustments via OTA updates.

## Common Mistakes

| Mistake | Impact | Correct Practice |
| ------------------------------------------------------ | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Running heavy animations across the JS boundary | Visible frame drops and UI stutter | Use `react-native-reanimated` worklets running directly on the native UI thread |
| Rendering long lists with basic `ScrollView` | High memory footprint and app crashes on low-end Android | Use Shopify's `@shopify/flash-list` with recycling and fixed item heights |
| Treating mobile layout like web CSS | Unexpected wrapping and broken responsive containers | Understand Yoga's defaults: `flexDirection: column` is default; absolute positioning works relative to immediate parent |
| Storing sensitive tokens in unencrypted `AsyncStorage` | Data vulnerability on jailbroken devices | Use `expo-secure-store` or Keychain/Keystore wrappers |
| Neglecting low-end device testing | Regressions in cold-start and memory leaks | Profile on budget Android hardware using Hermes heap sampling and Flipper/DevTools |

## Best Practices

1. **Start with Expo and Config Plugins**: Avoid creating bare native projects unless an unsupported proprietary SDK strictly demands manual native workspace modification.
2. **Share Monorepo Packages**: Re-use types, API client classes, business logic hooks, and validation rules from shared packages; keep mobile screens as thin presentation layers.
3. **Adopt FlashList for Data Views**: Replace legacy `FlatList` with `@shopify/flash-list` to eliminate white flashes during rapid scrolling.
4. **Use Hermes Engine**: Ensure Hermes is enabled to maximize execution speed, reduce app download size, and benefit from ahead-of-time bytecode compilation.
5. **Establish OTA Update Channels**: Maintain separated `development`, `staging`, and `production` runtime channels in Expo EAS Update to prevent shipping breaking native changes across incompatible binary versions.

---

## Performance Considerations

- **List Recycling**: Use `@shopify/flash-list` rather than `FlatList` to recycle native views and avoid garbage-collection spikes during high-speed fling gestures.
- **Hermes Bytecode**: Compiles JS to bytecode ahead of time during the build phase; eliminates runtime parsing and JIT compilation overhead at app launch.
- **Image Optimization**: Serve WebP images scaled to device screen resolution; avoid embedding massive inline base64 image strings.
- **Thread Segregation**: Keep heavy business logic or JSON parsing asynchronous; avoid blocking the single JavaScript event loop.

---

## Summary

React Native unites the React component model with genuine platform-native rendering. With the New Architecture (JSI, Fabric, and TurboModules) replacing the asynchronous JSON bridge, React Native closes the performance gap with native development while preserving cross-platform velocity. Combined with Expo's modern tooling ecosystem and shared monorepo contracts, it provides an optimal foundation for multi-platform products.

## Cheat Sheet

```text
REACT NATIVE & MOBILE ARCHITECTURE CHEAT SHEET
═══════════════════════════════════════════════════════════════════════════════

ARCHITECTURE:
  • Legacy: JS Thread ⇄ async JSON bridge (serialization bottleneck) ⇄ Native
  • Modern: Hermes ⇄ JSI (direct C++ memory pointers) ⇄ Fabric (UI) + TurboModules

CORE PRIMITIVES:
  • <View> → UIView (iOS) / android.view.ViewGroup (Android)
  • <Text> → UITextView / TextView (all text MUST be wrapped in <Text>)
  • Styling: Yoga C++ flexbox engine (default: flexDirection: 'column')

PERFORMANCE ESSENTIALS:
  • Lists: @shopify/flash-list (recycles views; FlatList re-instantiates)
  • Animations: react-native-reanimated worklets (run on UI thread at 60/120fps)
  • Storage: MMKV (synchronous binary KV) or SQLite (relational offline)
  • Engine: Hermes AOT bytecode compilation (faster TTIB, smaller heap)

EXPO WORKFLOW:
  • Managed workflow + Expo Prebuild = standard for modern mobile development
  • EAS Build: Cloud build pipelines for iOS IPA and Android AAB
  • EAS Update: OTA updates for JS bundle without App Store review delay

DECISION RULES:
  • Choose React Native: Web/TS team, simultaneous iOS+Android launch, shared monorepo
  • Choose Pure Native: Low-level Bluetooth/audio drivers, background OS services
  • Choose PWA: Content/booking web apps with zero store commission or review
```

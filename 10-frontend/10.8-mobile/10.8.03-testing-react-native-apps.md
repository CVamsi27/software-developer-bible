# Testing React Native Apps

> RN testing is a pyramid like web's — Jest units, React Native Testing Library components, and a thin device-level E2E layer — plus two mobile-only problems: native modules that must be mocked, and CI that needs real simulators (including macOS runners for iOS builds). This file covers the stack, the Detox vs Maestro decision, debugging tools, and visual regression options.

## TL;DR

Testing RN apps: Jest + RNTL for components, Detox/Maestro for E2E on devices — unit the logic, integration the navigation, E2E the critical flows.

## First Principles

RN testing layers map to the rendering host split (→ 10.8.01):

1. **Jest + RNTL tests the React layer** (mocking native modules — the boundary is where mocks live); E2E (Detox/Maestro) tests the *native* result on device/simulator: each layer tests one side of the JS↔native boundary.
2. **The pyramid still applies, but the top is expensive**: device farms and CI simulators are slow/flaky — push confidence down the stack (→ 50.1.1.01's test economics) and reserve E2E for critical journeys.

## Definition

A production-grade RN test setup layers:

1. **Unit tests** (Jest) — pure logic, hooks, reducers, API mappers
2. **Component tests** (React Native Testing Library) — render components against a fake native runtime and assert by *role/text*, not implementation
3. **E2E tests** (Detox or Maestro) — drive real apps on simulators/devices through flows
4. **Visual regression** — screenshot diffs to catch layout drift

```text
┌──────────────────────────────────────────────────────────────────┐
│ RN TEST PYRAMID                                                  │
├──────────────────────────────────────────────────────────────────┤
│                        ▲  E2E (Detox/Maestro)                    │
│                       ▲▲  critical flows only · minutes · flaky  │
│                     ▲▲▲▲▲                                        │
│                   ▲▲▲▲▲▲▲  Component (RNTL)                      │
│                 ▲▲▲▲▲▲▲▲▲  interactions · a11y queries · seconds │

│         ▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲  domain logic · ms-fast · run on push  │
└──────────────────────────────────────────────────────────────────┘
```

## Why It Matters

- **Mobile breakage is expensive** — a broken release needs a store review cycle (days), not a hotfix deploy
- **Native boundary is the new risk** — web testing skills transfer, but modules like `react-native-fs` crash differently under mocks than reality
- **CI needs hardware** — iOS builds require macOS runners; this shapes pipeline cost and design
- **Detox vs Maestro** is a common senior-level "pick your tooling and justify it" question

## How It Works

### Layer-by-layer

| Layer | Tool | Speed | Runs where |
| --------- | ------------------------------------------------------------------ | ----------------- | -------------------------------------------------------- |
| Unit | Jest + ts-jest/babel | milliseconds | any CI machine |
| Component | React Native Testing Library | ~100 ms/node tree | Node (jsdom-like RN preset) |
| E2E | Detox (builds app w/ test hooks) or Maestro (drives installed app) | minutes | macOS/Linux runners + simulators/emulators, device farms |
| Visual | Detox screenshots / Maestro screenshot + diff tool | minutes | same as E2E |

## Code Examples

### 1. Jest config for a bare RN workspace

```javascript
// jest.config.js
module.exports = {
  preset: 'react-native',
  setupFilesAfterEnv: ['@testing-library/jest-native/extend-expect', './jest.setup.ts'],
  transformIgnorePatterns: [
    // RN ships untranspiled ESM in node_modules — whitelist what Jest must parse
    'node_modules/(?!(react-native|@react-native|@expo|react-native-reanimated|react-native-gesture-handler)/)',
  ],
  moduleNameMapper: {
    '\\.(png|jpg)$': '<rootDir>/__mocks__/fileMock.js',
  },
};
```

The `transformIgnorePatterns` allowlist is the single most common RN/Jest integration fight: libraries shipping modern JS must be transformed, everything else should not be (speed).

### 2. Unit test of shared domain logic

```typescript
// pricing.test.ts
import { computeTotal } from './pricing';

describe('computeTotal', () => {
  it('applies percentage discounts before tax', () => {
    expect(computeTotal({ items: [1000, 500], discountPct: 10, taxPct: 20 }))
      .toBe(1296); // (1500 - 150) * 1.2 in minor units
  });

  it('never returns negative totals after clamping', () => {
    expect(computeTotal({ items: [100], discountPct: 150 })).toBe(0);
  });
});
```

Keep business rules in plain TS modules (your shared monorepo packages) so they test without any RN runtime at all.

### 3. Component test with React Native Testing Library

```tsx
import { render, screen, fireEvent } from '@testing-library/react-native';
import { LoginForm } from './LoginForm';

jest.mock('@react-native-async-storage/async-storage', () => ({
  getItem: jest.fn().mockResolvedValue(null),
  setItem: jest.fn().mockResolvedValue(undefined),
}));

test('shows validation error and calls onSubmit', async () => {
  const onSubmit = jest.fn();
  render(<LoginForm onSubmit={onSubmit} />);

  fireEvent.press(screen.getByRole('button', { name: /sign in/i }));

  expect(await screen.findByText(/email is required/i)).toBeTruthy();
  expect(onSubmit).not.toHaveBeenCalled();

  fireEvent.changeText(screen.getByLabelText('Email'), 'a@b.co');
  fireEvent.changeText(screen.getByLabelText('Password'), 'hunter22');
  fireEvent.press(screen.getByRole('button', { name: /sign in/i }));

  expect(await screen.findByRole('button', { name: /signing in/i })).toBeDisabled();
});
```

RNTL principles carried over from web: query by accessibility role/label (`getByRole`, `getByLabelText`) — which doubles as an a11y audit — never by `testID` internals unless necessary.

### 4. Mocking native modules (the RN-specific skill)

Anything touching Objective-C/Kotlin does not exist in Jest's Node world:

```typescript
// __mocks__/react-native-fs.ts — hand-rolled mock for a native module
export const readFile = jest.fn().mockResolvedValue('{"version":2}');
export const writeFile = jest.fn().mockResolvedValue(undefined);
export const exists = jest.fn().mockResolvedValue(true);
```

```typescript
// jest.setup.ts — silence the rest globally
jest.mock('react-native-fs', () => require('./__mocks__/react-native-fs'));
jest.mock('react-native-haptic-feedback', () => ({ trigger: jest.fn() }));
jest.mock('react-native-permissions', () => ({
  PERMISSIONS: { IOS: {}, ANDROID: {} },
  request: jest.fn().mockResolvedValue('granted'),
  RESULTS: { GRANTED: 'granted' },
}));
```

Rules that keep mocks honest: mock the module's *interface*, not its behavior; prefer `jest.spyOn` over reimplementation when the JS wrapper has logic worth exercising; and if a library offers official mocks (AsyncStorage, Reanimated), use them.

### 5. Detox vs Maestro

| Dimension | Detox | Maestro |
| ------------ | ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Model | grey-box: links app against test harness (`detox` build), syncs with app via native APIs | black-box: drives ANY installed app by YAML flows + id/accessibility selectors |
| Language | TypeScript (Jest/Mocha runner) | declarative YAML (`runFlow`, `runScript` escape hatch in JS) |
| Setup weight | high — per-platform build configs, Xcode/Gradle hooks | low — install CLI, point at simulator/app binary |
| Speed/flake | fast once built; synchronization reduces sleeps | slightly slower per step; no build coupling but more retry-prone waits |
| CI fit | needs the same mac toolchain as your builds | trivially scriptable anywhere with simulators |
| Best fit | teams owning the app binary wanting tight control & speed | quick coverage, cross-app flows, QA-authored tests |

```yaml
# .maestro/login.yaml — Maestro flow
appId: com.example.app
---
- launchApp
- tapOn: "Email"
- inputText: "a@b.co"
- tapOn: "Sign In"
- assertVisible: "Welcome back"
```

```typescript
// Detox equivalent
await device.launchApp({ newInstance: true });
await element(by.id('email')).typeText('a@b.co');
await element(by.text('Sign In')).tap();
await expect(element(by.text('Welcome back'))).toBeVisible();
```

Answer template: *"Expo-managed product needing QA-maintainable smoke suites → Maestro; performance-critical app with engineers owning E2E → Detox."*

### 6. Visual regression options

| Option | How it works | Notes |
| --------------------------------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------- |
| Detox `.takeScreenshot()` + Jest image snapshot | captures simulator screenshots, diffs committed baselines | free, tied to Detox runs |
| Maestro `takeScreenshot` + external differ (e.g., reg-suit) | upload artifacts, comment diffs on PRs | works with black-box flows |
| Storybook (web) for shared UI packages | visual-test RN components rendered on web | only valid for truly platform-agnostic components |
| Cloud device farms (Firebase Test Lab, AWS Device Farm, BrowserStack) | run suites across many OS/device combos | catches device-specific layout breaks |

Pin simulator model + OS version or diffs become noise; treat font-rendering differences across devices as expected variance.

### 7. CI: simulators, emulators, macOS runners

```yaml
# GitHub Actions sketch — iOS needs macOS
jobs:
  unit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: yarn }
      - run: yarn install --frozen-lockfile
      - run: yarn test --ci
  e2e-ios:
    runs-on: macos-14          # Apple silicon runner
    steps:
      - uses: actions/checkout@v4
      - run: yarn install --frozen-lockfile
      - run: pod install --project-directory ios
      - run: detox build --configuration ios.sim.debug
      - run: detox test --configuration ios.sim.debug --headless
```

Practical notes: macOS runners are ~10x the cost of Linux per minute — keep them for E2E/build jobs only; cache Pods/CocoaPods and Gradle aggressively; Android E2E can run on Linux with KVM-enabled emulators; for broad device matrices, offload to Firebase Test Lab/BrowserStack instead of growing self-hosted fleets.

### 8. Debugging toolchain

```text
React Native DevTools (RN 0.76+): Chrome-DevTools-style debugger,
  React component inspector, Hermes console — replaces Flipper.
Flipper: legacy desktop debugger (network, layout, redux plugins);
  still present in older codebases but deprecated in current RN —
  recognize it in interviews, don't propose it for new setups.
```

Day-to-day: `npx react-native log-android` / Console.app for native logs, Metro bundler errors for JS, and DevTools breakpoints for logic. Debug builds ship `localhost` network stubbing via MSW or fetch mocks mirroring your web setup.

## Real-World Use Cases

- **Navigation regression safety** — E2E smoke over the 5 critical flows (auth → core action → sync) catches the deep-link/dark-mode regressions unit tests can't see.
- **Offline-mode testing** — Detox/Maestro device controls simulate airplane mode; queue-and-sync logic only proves itself on-device.

## Common Mistakes

| Mistake | Fix |
| ----------------------------------------- | --------------------------------------------------------------------------- |
| Querying by `testID` everywhere | Prefer role/label queries; keep `testID` for E2E only |
| Mocking native modules with fake behavior | Mock interfaces minimally; test wrappers' logic separately |
| E2E suite covering everything | Keep E2E to money paths (auth, checkout, deep links); push down the pyramid |
| Unpinned simulators in visual tests | Pin device model + OS version in CI config |
| Skipping `transformIgnorePatterns` tuning | Maintain the explicit allowlist or Jest chokes/fails mysteriously |
| Running iOS E2E on Linux runners | iOS requires macOS runners (or cloud Macs); plan budget accordingly |

## Best Practices

1. **Share tests with web** — monorepo packages holding domain logic reuse their Jest suites unchanged on mobile
2. **One mock directory per native module**, registered in `jest.setup.ts`, reviewed like source code
3. **Smoke-first E2E**: login → core action → logout on both platforms; expand only when flake budget allows
4. **Run units + components on every PR** (Linux, cheap); E2E nightly or pre-release
5. **Name accessibility labels deliberately** — they power RNTL queries, Maestro/Detox selectors, and screen readers simultaneously
6. **Adopt React Native DevTools**; mention Flipper only as legacy context
7. **Quarantine flaky tests immediately** — mobile flakes compound into ignored red pipelines

## Performance Considerations

- Jest transforms dominate unit-test wall time — narrow `transformIgnorePatterns` and consider `jest-light-runner` style runners for large repos
- Simulator E2E is CPU-bound; parallelize by splitting Detox workers per simulator instance
- Visual diffs are storage-heavy: retain baselines per platform branch, prune old artifact buckets regularly

## Summary

- The RN pyramid mirrors web: Jest units, RNTL component tests, thin Detox/Maestro E2E, visual snapshots on top
- The mobile-specific skills are mocking native modules honestly and wiring CI with macOS runners for iOS
- Detox = grey-box, fast, engineer-owned; Maestro = black-box YAML, low setup, QA-friendly — choose per team ownership
- Query components by role and label: better tests, better accessibility, shared selectors with E2E
- Debug with React Native DevTools; treat Flipper as historical context
- Keep E2E small and pinned to critical flows — store-review cycles make regressions too expensive to risk on a flaky mega-suite

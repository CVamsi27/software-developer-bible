# Node.js Buffers

Character counts differ from byte counts. const text = 'hé😀';

## Definition

Why can `hé😀` occupy four JavaScript code units but seven bytes on the wire?

A Buffer is Node's fixed-length, mutable array of bytes. It extends `Uint8Array` with helpers for text encoding and binary reads and writes. The bytes count toward external/ArrayBuffer memory; V8, Node's JavaScript engine, manages the JavaScript wrapper and its lifetime through garbage collection (GC).
External memory still uses RAM and can put pressure on garbage collection.

> **Textbook Definition:** A Buffer is a fixed-length, mutable sequence of bytes exposed through Node.js APIs for binary data manipulation and encoding conversion. Its byte storage contributes to process memory independently of ordinary JavaScript heap objects.

## First Principles

1. A network transports bytes; a JavaScript string contains UTF-16 code units. The encoding boundary must specify how one becomes the other.
2. A byte view can share storage. Ownership determines whether mutation is safe and whether retaining a tiny view keeps a large allocation alive.
3. An untrusted length is an allocation request. Validate bounds before copying, reading a field, or reserving memory; a signature alone does not establish a valid file.

## How It Works


### 1. Character counts differ from byte counts

```javascript
const text = 'hé😀';
console.log(text.length);                 // 4 UTF-16 code units
console.log(Buffer.byteLength(text));     // 7 UTF-8 bytes
const bytes = Buffer.from(text, 'utf8');
console.log(bytes.toString('hex'));        // 68c3a9f09f9880
```

Use byte lengths for network framing and file offsets. A chunk can split a multi-byte character; use a streaming decoder as in [Streams](20.1.2.01-streams.md). Invalid UTF-8 is replaced by default; use a fatal decoder when rejecting malformed text is the protocol requirement.

| Encoding | Purpose | Size / limitation |
| --------------- | -------------------------- | ------------------------------------------------------------------------------------- |
| UTF-8 | Unicode text | Variable byte length |
| Base64 | Bytes represented as text | `4 * ceil(n / 3)` characters with padding; about 33% expansion for large inputs |
| Base64url | URL-safe representation | Different alphabet, often unpadded; not encryption |
| Hex | Byte debugging and digests | Two characters per byte |
| ASCII / Latin-1 | Specific legacy encodings | Cannot preserve arbitrary Unicode; browser charset labels can have different mappings |

Buffer's hex/base64 decoders can accept inputs more leniently than a protocol allows. Validate canonical syntax and length when they are part of a security or framing contract.

### 2. How allocation affects ownership

| Operation | Copies or shares? | Important consequence |
| --------------------------------------------- | ------------------------ | ---------------------------------------------------------------- |
| `Buffer.alloc(n)` | Fresh zero-filled bytes | Safe initial contents; no blanket guarantee about later secrets |
| `Buffer.allocUnsafe(n)` | Contents unspecified | Initialize every exposed byte before reading, sending or hashing |
| `Buffer.from(string)` / `Buffer.from(buffer)` | Copies | Encode text or establish independent storage |
| `buf.subarray(start, end)` | Shares | Mutation affects the original; view can retain its allocation |
| `Buffer.from(arrayBuffer, offset, length)` | Shares | Specify the actual byte range |
| `Buffer.concat(parts)` | Copies into a new result | Temporarily holds inputs plus output; not streaming |

`Buffer.slice` also shares memory, unlike `Uint8Array.slice`; prefer the explicit `subarray` spelling for views. The Buffer wrapper's length is fixed, while its bytes remain mutable.

```javascript
const original = Buffer.from('Hello');
const view = original.subarray(0, 2);
view[0] = 0x4a;
console.log(original.toString()); // Jello
const copy = Buffer.from(view);
copy[0] = 0x48;
console.log(original.toString()); // still Jello
```

Small allocations from certain APIs use Node's shared internal pool; `Buffer.alloc` does not use that pool. Inspect `Buffer.poolSize` and the versioned API contract rather than assuming every small Buffer is pooled. A long-lived tiny view can retain the entire backing slab.
A custom pool reset cannot safely reuse bytes while old views remain live.

`buf.write(text)` stops at the available space, so compare its returned byte count with `Buffer.byteLength(text)`. A zero-filled buffer still contains its unused NUL bytes; decode only the range actually written. Overwriting may reduce one retained secret copy, but cannot erase copies in strings, logs, native code, or swap.

Copying a scratch Buffer into a growing result array still retains all result bytes, and `Buffer.concat` already copies its inputs into a new allocation. Neither pattern is streaming; for a required bounded result, allocate the known final size once when possible.

### 3. Choose the wire bytes explicitly

```javascript
const values = new Uint16Array([0x1234, 0xabcd]);
const numericCopy = Buffer.from(values); // converts elements to bytes: [0x34, 0xcd]
const rawView = Buffer.from(values.buffer, values.byteOffset, values.byteLength);
// rawView shares the host-endian representation; it is not a portable wire format.
const wire = Buffer.alloc(4);
wire.writeUInt16BE(values[0], 0);
wire.writeUInt16BE(values[1], 2);
console.log(wire.toString('hex')); // 1234abcd
```

Converting typed-array elements and sharing their raw bytes are different operations. Choose the protocol's byte order explicitly: endianness specifies which byte of a multi-byte number comes first. The host computer's order may differ.
Numeric field reads and writes check their bounds; they do not overflow into adjacent memory.

### 4. Read a file header without mistaking it for validation

```typescript
function inspectPngHeader(buffer: Buffer): { width: number; height: number; bitDepth: number } {
  if (buffer.length < 33) throw new RangeError('Truncated PNG header');
  if (!buffer.subarray(0, 8).equals(Buffer.from('89504e470d0a1a0a', 'hex'))) {
    throw new Error('Wrong PNG signature');
  }
  if (buffer.readUInt32BE(8) !== 13 || buffer.toString('ascii', 12, 16) !== 'IHDR') {
    throw new Error('Missing initial IHDR');
  }
  const width = buffer.readUInt32BE(16);
  const height = buffer.readUInt32BE(20);
  if (width === 0 || height === 0) throw new Error('Invalid dimensions');
  return { width, height, bitDepth: buffer.readUInt8(24) };
}
```

This reads fields from a Portable Network Graphics (PNG) header, but does not validate CRCs, color-type/bit-depth combinations, later chunks, or actual decompression. Use a maintained decoder and a pixel limit before accepting an image. For a 24-bit bitmap (BMP) sketch, rows require `ceil(width * 3 / 4) * 4` bytes and total storage includes the headers; validate dimensions, multiplication, and protocol field limits before allocating it.

### 5. Follow a bounded binary frame

This illustrative protocol is `uint32 BE frame length → uint8 type → payload`. The length includes the type byte; each frame is bounded to 64 KiB. Input chunk sizes need a separate bound at the source.

```typescript
async function* parseFrames(
  source: AsyncIterable<Uint8Array>,
): AsyncGenerator<{ type: number; payload: Buffer }> {
  const maxFrame = 64 * 1024;
  let pending = Buffer.alloc(0);
  for await (const bytes of source) {
    pending = Buffer.concat([pending, bytes]);
    while (pending.length >= 4) {
      const size = pending.readUInt32BE(0);
      if (size < 1 || size > maxFrame) throw new RangeError('Invalid frame size');
      if (pending.length < 4 + size) break;
      const type = pending[4];
      // Copy payload ownership before retaining/reusing the remaining input.
      const payload = Buffer.from(pending.subarray(5, 4 + size));
      pending = pending.subarray(4 + size);
      yield { type, payload };
    }
  }
  if (pending.length !== 0) throw new Error('Truncated final frame');
}

function createMessage(type: number, payload: Buffer): Buffer {
  if (!Number.isInteger(type) || type < 0 || type > 255) throw new RangeError('Invalid type');
  if (payload.length + 1 > 64 * 1024) throw new RangeError('Payload too large');
  const output = Buffer.alloc(5 + payload.length);
  output.writeUInt32BE(payload.length + 1, 0);
  output.writeUInt8(type, 4);
  payload.copy(output, 5);
  return output;
}
```

For type 7 and UTF-8 payload hé, createMessage emits a four-byte length of 4, one type byte and three payload bytes. Splitting those bytes after the second length byte and inside the payload still yields one {type:7,payload:hé} result. A zero length is rejected; ending with only three header bytes raises the truncated-tail error.
The copied payload remains owned by the consumer rather than aliasing the retained input.

Transport chunks can split the header or combine many messages. Validate the advertised length before waiting for it, and fail on an unfinished tail. Yielding each parsed frame preserves downstream demand.
Repeated concat on fragmented input copies retained bytes repeatedly; a bounded segment queue can reduce that cost after correctness is established.

### 6. Serialization needs a field contract

An illustrative record layout might contain `uint32 id`, `uint16 UTF-8 name length`, `int64 timestamp`, `uint16 value count`, then name bytes and Float32 values. A correct decoder checks the minimum header, derives and validates the exact remaining byte length, and decides whether trailing bytes are allowed.

Use `bigint` for a full signed 64-bit value. Converting it to Number loses precision outside the safe-integer range. Float32 serialization can round JavaScript Numbers; reject or explicitly permit NaN/infinity according to the format.
A name's UTF-8 byte length and a value count must fit their 16-bit fields before writing.

#### Assemble an upload only after admission

```typescript
function assembleUpload(chunks: readonly { index: number; buffer: Buffer }[], totalSize: number): Buffer {
  const limit = 10 * 1024 * 1024;
  if (!Number.isSafeInteger(totalSize) || totalSize < 0 || totalSize > limit) {
    throw new RangeError('Invalid total size');
  }
  const ordered = [...chunks].sort((a, b) => a.index - b.index);
  let measured = 0;
  for (const [index, chunk] of ordered.entries()) {
    if (chunk.index !== index || !Buffer.isBuffer(chunk.buffer)) {
      throw new Error('Missing, duplicate, or invalid chunk');
    }
    measured += chunk.buffer.length;
    if (measured > limit) throw new RangeError('Upload too large');
  }
  if (measured !== totalSize) throw new Error('Total size mismatch');
  return Buffer.concat(ordered.map(chunk => chunk.buffer), totalSize);
}
```

This is an in-memory assembly helper, not a complete upload service. Admission must cap the number of chunks and received bytes before storing them, bind them to an authorized upload/tenant, and use a durable disk/object-store assembly for larger files. Filename extensions alone do not validate content.
SHA-256 content names can assist deduplication but do not authorize cross-tenant access or prove a file safe.

### 7. Apply the same byte contract to crypto and images

Use `randomBytes` for unpredictable token bytes and base64url for their transport representation. A digest checks content identity; an HMAC authenticates content only when the key is protected and verification follows the protocol. Neither hashing nor Base64 encrypts the original bytes.

For images, a whole-image Buffer is an explicit memory choice; Sharp can decode many more pixels than the compressed input length suggests. Bound pixels and concurrent processing. Select the encoder once: calling `.jpeg()` after a generic `.toFormat()` selects JPEG, regardless of the earlier requested format.
See the [streaming image example](20.1.2.01-streams.md) for one processor per image.

## Summary

Buffers represent bytes with mutable ownership. Correct binary code specifies encoding, byte order, length bounds, and storage lifetime; stream and protocol boundaries determine when those bytes are complete enough to interpret. Make copying versus sharing explicit, validate lengths before allocation, and observe RSS/external memory along with heap usage.

# HTTP Module

## Definition

`node:http` implements HTTP/1 server and client messages over network sockets. A server reads a request through `IncomingMessage` and writes a response through `ServerResponse`. An `Agent` manages client sockets for reuse. `node:https` adds Transport Layer Security (TLS), which encrypts the connection. `node:http2` provides HTTP/2 sessions that can carry several message streams.

> **Textbook Definition:** Node's HTTP APIs implement client and server message exchange over network connections, exposing message bodies as streams. HTTP/1, HTTPS and HTTP/2 provide distinct connection, security and multiplexing contracts.

## First Principles

1. HTTP bodies arrive incrementally. A parser must bound bytes and validate a complete application value before using it.
2. A response has one lifecycle. Once headers or the body have been sent, an error handler cannot safely restart it with another status/body.
3. A socket is shared across message lifetimes under keep-alive. Header/body timeouts, application deadlines and idle-connection expiry are different limits.

## Why a try/catch misses a failed handler

```text
connection → HTTP parser → request event → handler returns promise
                                      → promise rejects later
```

The raw server does not automatically await a handler's promise and turn its rejection into an HTTP error response. Attach a rejection path yourself. Common frameworks wrap this boundary in different ways; the framework's version still determines its error behavior.

One keep-alive connection can carry multiple requests, so `connection → request → response → close` is not a required one-request sequence. `res.end()` marks message completion; it does not prove a remote client consumed the bytes.

## Code: bound JSON and catch the whole async route

This example is a parsing/routing exercise with no authentication or persistence. It accepts one name field and avoids letting an input body overwrite server-owned fields. Save as `server.cjs`.

```javascript
const http = require('node:http');

class HttpError extends Error {
  constructor(status, message) { super(message); this.status = status; }
}

async function readJson(req, limit = 1024) {
  if (!/^application\/json(?:\s*;|$)/i.test(req.headers['content-type'] ?? '')) {
    throw new HttpError(415, 'Expected application/json');
  }
  const chunks = [];
  let bytes = 0;
  // Preserve the request on early iteration exit so an error response can be sent.
  for await (const chunk of req.iterator({ destroyOnReturn: false })) {
    bytes += chunk.length;
    if (bytes > limit) throw new HttpError(413, 'Body too large');
    chunks.push(chunk);
  }
  try {
    const body = JSON.parse(Buffer.concat(chunks).toString('utf8'));
    if (body === null || typeof body !== 'object' || Array.isArray(body)) {
      throw new Error('Expected object');
    }
    return body;
  } catch { throw new HttpError(400, 'Invalid JSON object'); }
}

function sendJson(res, status, value) {
  const body = JSON.stringify(value);
  res.writeHead(status, {
    'Content-Type': 'application/json; charset=utf-8',
    'Content-Length': Buffer.byteLength(body),
  });
  res.end(body);
}

async function route(req, res) {
  // Fixed parsing base: the attacker-controlled Host header is not authority.
  const url = new URL(req.url ?? '/', 'http://local.invalid');
  if (req.method === 'GET' && url.pathname === '/health') {
    sendJson(res, 200, { status: 'ok' });
    return;
  }
  if (req.method === 'POST' && url.pathname === '/api/users') {
    const body = await readJson(req);
    if (typeof body.name !== 'string' || body.name.length < 1 || body.name.length > 80) {
      throw new HttpError(400, 'Invalid name');
    }
    sendJson(res, 200, { name: body.name }); // echo, not a created database entity
    return;
  }
  throw new HttpError(404, 'Not found');
}

const server = http.createServer((req, res) => {
  res.on('error', error => console.error('response failed', error));
  void route(req, res).catch(error => {
    if (res.headersSent || res.destroyed) {
      res.destroy(error);
      return;
    }
    // Reject admission and close this connection instead of preserving a partial body.
    res.setHeader('Connection', 'close');
    req.resume(); // discard remaining bytes without accumulating them
    sendJson(res, error instanceof HttpError ? error.status : 500,
      { error: error instanceof HttpError ? error.message : 'Internal server error' });
  });
});
server.requestTimeout = 30_000;
server.headersTimeout = 10_000;
server.keepAliveTimeout = 5_000;
server.on('error', error => console.error('server failed', error));
server.listen(3000, '127.0.0.1');
```

The receive limits are examples, not a production policy. Bound request count, header/body sizes, and application work too. Malformed UTF-8 is replaced by the default decode; add fatal validation if the JSON protocol requires it. A Content-Length header is untrusted: enforce the bytes actually received even when its advertised value is small or absent.

The fixed URL base avoids deriving an origin from Host. If an application needs to generate absolute URLs, use configured trusted origins and a deliberately configured proxy policy. Repeated query parameters may have meaning; `Object.fromEntries(searchParams)` silently keeps only the last value.

## How response streaming finishes

```javascript
const { Readable } = require('node:stream');
const { pipeline } = require('node:stream/promises');
const { setTimeout: delay } = require('node:timers/promises');

async function streamChunks(res) {
  const controller = new AbortController();
  const onClose = () => {
    if (!res.writableFinished) controller.abort();
  };
  res.on('close', onClose);
  try {
    res.setHeader('Content-Type', 'text/plain; charset=utf-8');
    await pipeline(Readable.from((async function* () {
      for (let count = 1; count <= 10; count++) {
        await delay(100, undefined, { signal: controller.signal });
        yield `Chunk ${count}\n`;
      }
    })()), res, { signal: controller.signal });
  } finally { res.off('close', onClose); }
}
```

Pipeline carries pressure from the response upstream and rejects on failure. The caller must catch that rejection without attempting a second body after headers. Do not manually force `Transfer-Encoding: chunked`; Node chooses appropriate HTTP/1 framing when no Content-Length is supplied. A file download similarly uses a fresh source and `pipeline`; determine missing-file/content metadata before committing success headers where possible.

## Code: bound an outbound JSON response

```javascript
async function getJson(url) {
  // The URL must already satisfy the application's destination/SSRF policy.
  const response = await fetch(url, { signal: AbortSignal.timeout(5000), redirect: 'error' });
  if (!response.ok) {
    await response.body?.cancel();
    throw new Error(`Upstream HTTP ${response.status}`);
  }
  if (!response.body) throw new Error('No upstream body');
  const chunks = [];
  let bytes = 0;
  for await (const chunk of response.body) {
    bytes += chunk.length;
    if (bytes > 1024 * 1024) throw new RangeError('Upstream response too large');
    chunks.push(Buffer.from(chunk));
  }
  return JSON.parse(Buffer.concat(chunks).toString('utf8'));
}
```

This buffers at most the chosen response allowance plus an arriving chunk; use record streaming for larger data. Parsing happens synchronously after reading. The URL, redirect, DNS and private-network policies belong at the egress boundary; HTTPS alone does not prevent SSRF.

With `http.request`, register request and response error/aborted paths, call `end()`, and destroy/abort the request on the chosen deadline. `request.setTimeout()` alone emits a timeout notification; it does not abort. Catch JSON parse errors inside the response callback or propagate them through an awaited wrapper.

## Pool and timeout decisions

| Limit | What it controls | What it does not establish |
| --------------------------------- | --------------------------------------------------------- | ----------------------------------------------------------------- |
| `headersTimeout` | Time to receive complete request headers | Business-operation deadline |
| `requestTimeout` | Time to receive the complete request | Database/API processing time |
| `server.timeout` / socket timeout | Socket inactivity and notification policy | Automatic application cancellation in all listener configurations |
| `keepAliveTimeout` | Idle time after a response while awaiting another request | Limit on in-flight work |
| Agent `maxSockets` | Client sockets per origin | Bound on all queued requests or all origins |

For Node HTTP clients, an owned keep-alive Agent can cap per-origin sockets; `maxTotalSockets` and application admission limit wider concurrency. Destroy an owned Agent when its lifetime ends. Built-in `fetch` uses Undici's dispatcher, not `http.Agent`; configuring one does not configure the other.

TLS may terminate at Node or a trusted reverse proxy. Trust forwarding headers only from configured proxies, and validate request syntax/body limits at consistent boundaries to reduce parser discrepancies and smuggling risk.

## Real-world: proxies and health

A reverse proxy must handle request/response errors, both disconnect directions, backpressure, deadlines, upgrades, and hop-by-hop headers (including headers nominated by `Connection`). Copying all client headers to an upstream and piping both sides is only a sketch. Prefer a maintained proxy implementation when those semantics are required.

A public health response should be minimal. Separate liveness (process can respond) from readiness (admission is appropriate) and keep detailed memory/configuration diagnostics behind operator access. Follow [Process & Environment](../03-processes-and-concurrency/20.1.3.03-process-environment.md) for graceful shutdown; upgraded WebSockets require separate tracking.

## Common mistakes

An async function does not offload CPU, a timeout notification does not necessarily cancel work, and response completion does not prove remote receipt. Wildcard CORS may be appropriate for public unauthenticated data, but it is not authorization and cannot be combined with credentialed access as a general policy. Implement CORS deliberately for the selected browser-client contract rather than adding it to every server example.

## Best Practices

Make admission, byte bounds, processing deadlines, and error ownership explicit. Match trusted origins and proxy assumptions to deployment, and test aborted uploads, slow receivers, malformed bodies, oversized responses, and keep-alive reuse.

## Summary

Raw HTTP exposes streaming message lifetimes. Correct handlers own their promises and responses, enforce limits as data arrives, and distinguish transport deadlines from the work performed after parsing.

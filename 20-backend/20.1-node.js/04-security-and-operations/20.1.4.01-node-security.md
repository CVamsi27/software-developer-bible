# Node.js Security

## Definition

Node.js security controls the authority and resources a server process gives to requests, dependencies and operators. The process can hold database credentials, open files, start subprocesses and send network requests; each exposed operation needs a defined input contract and an authorization boundary.

## First Principles

1. **Input becomes dangerous at an interpreter.** A string used as a value differs from a string parsed as SQL, a shell command, a regular expression or a template. Preserve that distinction at the receiving API.
2. **Valid data can still request forbidden work.** A well-formed user ID does not prove the caller may read that user's record. Validation checks shape; authorization checks the permitted action and resource.
3. **Every accepted request spends finite capacity.** Bound bytes, execution time, concurrent work and stored state before expensive operations. A timer cannot interrupt synchronous JavaScript already blocking the loop.
4. **Loaded code executes with process authority.** A vulnerable or malicious dependency may reach credentials and files. Dependency review and OS isolation protect different parts of that exposure.

## Follow a request across its trust boundaries

Consider `POST /reports` with a JSON body selecting an export format:

```text
connection → limit bytes/time → parse → validate format
                                      ↓
                           authenticate caller
                                      ↓
                         authorize report/tenant
                                      ↓
                        build fixed operation arguments
                                      ↓
                      bounded job → explicit response DTO
```

Parsing is already work, so a schema alone cannot stop a huge body. A valid format alone cannot authorize an export. A shell-free subprocess alone cannot prevent reading an unauthorized file. Keep the checks at the boundary they actually protect.

## Build values rather than accepting query structure

Avoid passing a client-supplied object directly to MongoDB or spreading it into an update. A field named `username` must contain a string, rather than an object such as `{ "$ne": null }` that MongoDB interprets as an operator.

```javascript
function readUsername(body) {
  if (body === null || typeof body !== 'object' || Array.isArray(body)) {
    throw new TypeError('Expected an object');
  }
  if (typeof body.username !== 'string' ||
      body.username.length < 1 || body.username.length > 80) {
    throw new TypeError('Invalid username');
  }
  return body.username;
}

function userLookup(body, authenticatedTenantId) {
  if (typeof authenticatedTenantId !== 'string' || !authenticatedTenantId) {
    throw new TypeError('Tenant context required');
  }
  return { tenantId: authenticatedTenantId, username: readUsername(body) };
}
// db.users.findOne(userLookup(req.body, authenticatedUser.tenantId));
```

The tenant comes from verified server context. This lookup is one application policy, not a password-verification implementation. Do not silently stringify unexpected objects into plausible input.

For SQL, bind values with parameters; allowlist identifiers that cannot be bound. For HTML, encode for the output context using the template engine. HTML encoding does not sanitize a shell argument, and stripping `$` keys recursively is not a complete MongoDB policy.

## Give a subprocess one defined operation

If a report requires a native program, fix the executable and permitted arguments. Prefer a library when it provides the needed operation. This illustration permits only two fixed modes and accepts no client path or arbitrary command string:

```javascript
const { execFile } = require('node:child_process');
const { promisify } = require('node:util');
const executeFile = promisify(execFile);

async function runtimeInfo(mode) {
  const options = new Map([
    ['version', '--version'],
    ['help', '--help'],
  ]);
  if (!options.has(mode)) throw new TypeError('Unsupported operation');
  return executeFile(process.execPath, [options.get(mode)], {
    shell: false,
    timeout: 2000,
    maxBuffer: 64 * 1024,
    env: { PATH: process.env.PATH },
  });
}
```

`execFile` bypasses shell parsing; the executable still interprets its arguments. Real export commands also need resource authorization, controlled working directories and privileges, plus bounded inputs/outputs. An allowlist of commands such as `cat` with arbitrary filenames would still expose files.

For file access, see [filesystem containment](../02-io-and-data/20.1.2.03-file-system.md): a resolved path prefix is insufficient, and lexical containment alone does not prevent symlink races. For outbound URLs, use destination allowlists and egress policy; account for DNS resolution and redirects rather than treating an `https:` prefix as SSRF protection.

## Treat configuration as data with a narrow schema

Prototype pollution occurs when a write uses attacker-controlled property paths to alter an object's prototype or a shared prototype. Avoid recursive merging of request data into configuration. Build only the known settings:

```javascript
function readPreferences(input) {
  if (input === null || typeof input !== 'object' || Array.isArray(input)) {
    throw new TypeError('Expected preferences');
  }
  const allowed = new Set(['theme', 'pageSize']);
  if (Object.keys(input).some(key => !allowed.has(key))) {
    throw new TypeError('Unknown preference');
  }
  const theme = input.theme ?? 'light';
  const pageSize = input.pageSize ?? 20;
  if (!['light', 'dark'].includes(theme) ||
      !Number.isSafeInteger(pageSize) || pageSize < 1 || pageSize > 100) {
    throw new TypeError('Invalid preference');
  }
  return Object.freeze({ theme, pageSize });
}
```

A `Map` or null-prototype object avoids inherited-property behavior for a dictionary. It does not make later deep merges, property lookups on other objects or privileged operations safe. Restrict request size/depth before validation, and test nested `constructor`/`prototype` input when any generic merge remains.

## Bound work before it reaches the event loop

Use [the bounded HTTP parser](../02-io-and-data/20.1.2.04-http-module.md) or the framework's configured body limit, rather than trusting `Content-Length`. Chunked requests can omit it. Also limit decompressed payloads, multipart fields/files, upload duration and simultaneous uploads.

A public login path typically needs both per-account and per-source controls. A process-local limiter resets on restart and differs across workers; an unbounded IP-to-array map is itself a memory exhaustion target. For shared enforcement, study [the atomic Redis token bucket](../../20.8-caching/20.8.03-advanced-redis-patterns.md), choose a bounded key lifetime and define the Redis failure policy. A limiter cannot replace a concurrency cap for expensive accepted work.

Only trust forwarded client IP headers from configured proxies. Otherwise attackers can spoof the key, or every request may be counted against the load balancer's address.

Regular expressions and JSON parsing run synchronously. Bound input length, avoid ambiguous patterns, and use a compatible linear-time regex engine where appropriate; RE2 does not support every JavaScript regex feature. Password hashes deliberately consume CPU or memory: choose a password hashing algorithm and parameters from the [security chapters](../../20.5-security/INDEX.md), then bound authentication concurrency. A plain SHA-256 hash is not a password hashing scheme.

## Let headers enforce a deliberate browser policy

For an Express application, install and configure Helmet for the pages you actually serve:

```javascript
const express = require('express');
const helmet = require('helmet');
const app = express();
app.disable('x-powered-by');
app.use(helmet());
app.use(express.json({ limit: '100kb' }));
app.get('/health', (_req, res) => res.json({ status: 'ok' }));
module.exports = app;
```

Inspect the locked Helmet release's output instead of copying a stale defaults table. Current Helmet disables the legacy `X-XSS-Protection` filter (`0`); it does not enable `Cross-Origin-Embedder-Policy` by default and does not set the retired `Expect-CT` header.

CSP restricts browser resource execution; output encoding is still necessary. `frame-ancestors` controls embedding. HSTS tells browsers to prefer HTTPS after receiving the header over HTTPS; include subdomains only when they support it. Test policies with the application rather than assuming every default fits.

CORS controls which browser origins may read a response. It does not authenticate callers, block non-browser clients or replace CSRF protection. A public non-credentialed endpoint may deliberately use `*`; credentialed responses need an explicit allowed origin and the proper credential policy.

## Reduce dependency and process authority

- Commit the lockfile and use `npm ci` for a consistent dependency graph. A lockfile does not prove code is benign; install scripts can execute with build credentials.
- Run `npm audit` to detect known advisory matches and review fixes. `--audit-level=high` changes the exit threshold, not which findings appear. Do not automatically accept breaking upgrades or treat a clean report as proof against supply-chain attacks.
- Review new dependencies, package provenance and install scripts. Use `--ignore-scripts` only when compatible with the build, then deliberately authorize required tooling.
- Run as a non-root user with restricted filesystem/network access. Keep secrets out of image layers, logs, traces and error payloads. Environment variables are a delivery mechanism, not encryption or access control.
- Node's permission model helps trusted code avoid unintended resource access. Its official threat model does not promise isolation from malicious loaded code; OS boundaries remain necessary for untrusted execution.

The strict configuration example belongs in [Process & Environment](../03-processes-and-concurrency/20.1.3.03-process-environment.md). Load configuration before serving requests; avoid a homemade asynchronous `.env` reader that races startup or silently overwrites values.

## Check failures at the receiving boundary

| Boundary | Useful negative probe | Expected behavior |
| ----------------- | ----------------------------------------------- | ----------------------------------------- |
| Query building | `username` supplied as an operator object | Reject before the driver receives a query |
| Resource access | Valid record ID from another tenant | Deny even though validation succeeds |
| Subprocess | Unsupported mode or oversized output | Reject mode; enforce output/time limits |
| Parsing/admission | Chunked oversized JSON, many expensive requests | Enforce bytes and accepted-work caps |
| Configuration | Unknown/nested prototype keys | Reject without mutating shared state |
| Browser response | Stored markup in a rendered field | Contextual encoding plus tested CSP |

## Summary

Trace each untrusted value into the API that receives it. Construct narrow query/command/DTO shapes, authorize resources independently, and bound work before expensive operations. Headers, dependency controls and process privileges cover additional boundaries; none turns a generic sanitizer into a complete security policy.

# NestJS Guards

## Definition

A guard decides whether processing may continue to a selected handler. Its ExecutionContext exposes the controller, method and transport arguments, so it can enforce handler metadata against verified caller identity before pipes and business work.

> **Textbook Definition:** A NestJS guard implements CanActivate to admit or reject handler execution. A boolean, promise or observable decision controls continuation; an exception can express a deliberate transport failure.

## First Principles

A valid-looking request can still ask for another tenant's record. Input parsing cannot prove that the caller has permission. Access policy needs verified identity plus the action/resource being requested, and the decision must precede protected work. Handler metadata makes a declared route policy visible to that decision.

A decorator records policy; it does not enforce it. A public marker likewise changes a guard only if that guard reads it. Establish identity before any guard consumes its roles or tenant; sorting solely by the cheapest rejection would violate that dependency.

## Trace authentication and inherited role policy

Save this complete Nest 11 loopback fixture as `guards.ts` and compile with the [core setup](../01-core-architecture/20.2.1.02-controllers.md#run-one-createread-fixture). Fixture tokens stand in for an injected credential verifier; they are not JWT verification.

```typescript
import 'reflect-metadata';
import {
  CanActivate, Controller, ExecutionContext, Get, Inject, Injectable,
  Module, SetMetadata, UnauthorizedException, UseGuards,
} from '@nestjs/common';
import { APP_GUARD, NestFactory, Reflector } from '@nestjs/core';
const PUBLIC = Symbol('PUBLIC');
const ROLES = Symbol('ROLES');
const VERIFY = Symbol('VERIFY');
const Public = () => SetMetadata(PUBLIC, true);
const Roles = (...roles: string[]) => SetMetadata(ROLES, roles);
interface Principal { id: string; tenantId: string; roles: string[] }
type Verify = (token: string) => Promise<Principal | null>;
interface RequestShape { headers: { authorization?: string }; principal?: Principal }
@Injectable()
class AuthenticationGuard implements CanActivate {
  constructor(@Inject(VERIFY) private readonly verify: Verify,
    @Inject(Reflector) private readonly reflector: Reflector) {}
  async canActivate(context: ExecutionContext) {
    if (this.reflector.getAllAndOverride<boolean>(PUBLIC,
      [context.getHandler(), context.getClass()]) === true) return true;
    const req = context.switchToHttp().getRequest<RequestShape>();
    const match = /^Bearer ([^\s]+)$/.exec(req.headers.authorization ?? '');
    if (!match) throw new UnauthorizedException();
    const principal = await this.verify(match[1]);
    if (!principal) throw new UnauthorizedException();
    req.principal = principal;
    return true;
  }
}
@Injectable()
class RolesGuard implements CanActivate {
  constructor(@Inject(Reflector) private readonly reflector: Reflector) {}
  canActivate(context: ExecutionContext) {
    const roles = this.reflector.getAllAndOverride<string[]>(ROLES,
      [context.getHandler(), context.getClass()]);
    const principal = context.switchToHttp().getRequest<RequestShape>().principal;
    return !!principal && !!roles?.length && roles.some(role => principal.roles.includes(role));
  }
}
@Controller('reports')
@Roles('admin')
@UseGuards(RolesGuard)
class ReportsController {
  @Get() get() { return { report: 'fixture' }; }
  @Get('read') @Roles('reader') read() { return { report: 'reader-fixture' }; }
}
@Controller('health')
class HealthController { @Get() @Public() get() { return { status: 'ok' }; } }
@Module({
  controllers: [ReportsController, HealthController],
  providers: [RolesGuard,
    { provide: VERIFY, useValue: async (token: string): Promise<Principal | null> =>
      token === 'fixture-admin' ? { id: 'u1', tenantId: 'clinic-a', roles: ['admin'] } :
      token === 'fixture-reader' ? { id: 'u2', tenantId: 'clinic-a', roles: ['reader'] } : null },
    { provide: APP_GUARD, useClass: AuthenticationGuard }],
})
class AppModule {}
async function main() {
  const app = await NestFactory.create(AppModule, { logger: false });
  try {
    await app.listen(0, '127.0.0.1');
    const origin = await app.getUrl();
    for (const [path, token] of [
      ['/health', ''], ['/reports', ''], ['/reports', 'fixture-reader'],
      ['/reports', 'fixture-admin'], ['/reports/read', 'fixture-reader'],
    ]) {
      const response = await fetch(origin + path, {
        headers: token ? { authorization: `Bearer ${token}` } : {},
      });
      console.log(response.status);
    }
  } finally { await app.close(); }
}
main().catch(error => { console.error(error); process.exitCode = 1; });
```

The statuses are `200, 401, 403, 200, 200`. Public health skips the authentication guard. Missing credentials on reports fail with 401 before RolesGuard. A verified reader lacks the controller's admin role, so false becomes Nest's default 403. The admin is admitted. The read handler's metadata overrides the controller's roles, so a reader is admitted there. `getAllAndOverride` chooses the first defined metadata in the listed order; `getAllAndMerge` would combine them and requires a deliberately different policy.

The role check means **any** listed role. A permission policy can require **every** named permission; changing some to every changes the contract. This fixture fails closed when reports have no roles metadata or no principal. Other applications can deliberately allow authenticated routes without role metadata, but that default must be explicit and tested.

## Register with the correct dependency and transport scope

`APP_GUARD` registers a globally applied guard through module DI, including the verifier and Reflector above. Controller/method `@UseGuards(Class)` lets Nest construct the guard. `app.useGlobalGuards(new Guard())` is manual construction: supply its required dependencies or retrieve a container-managed instance; an empty constructor call is not a DI shortcut. Hybrid transports have their own inheritance configuration.

Global guards run before controller then route guards, respecting binding order within each scope. A denial stops downstream processing, while a deliberate UnauthorizedException distinguishes absent/invalid authentication from an authenticated forbidden action. Returning false is a valid 403 policy, not intrinsically a mistake. Throw only safe public details; do not disclose private resource existence accidentally.

ExecutionContext is transport-specific. `switchToHttp` does not extract GraphQL, WebSocket or RPC identity by magic. Use the appropriate transport context and error mapping; a shared policy service can evaluate a normalized verified principal/action/resource after each transport verifies its credential.

## A route role does not authorize a resource

For `/orders/:id`, an admin role may still be limited to one tenant. Carry the verified tenant into the service query and enforce resource membership. Guards run before handler pipes, so a guard reading raw route/body fields must validate the small portion it needs itself; it cannot assume ParseUUIDPipe already ran. Prefer an atomic scoped query/update for permission-sensitive mutations. A guard's earlier check and later mutation can race with revocation or resource changes; choose the transaction/consistency boundary.

JWT verification must constrain the intended signature algorithm/key, issuer, audience and time claims, then validate the usable principal shape. Decoding is not verification. Authentication libraries, sessions, key rotation/revocation and API-key timing-safe comparison/rotation/rate limits live in [security](../../20.5-security/INDEX.md). Do not let unknown verifier infrastructure failures silently grant access or become a fake invalid-password signal; return the chosen safe availability failure.

## Compare additional admission policies

| Policy | Decision inputs | Changed-condition boundary |
| ------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Permission or OAuth scope | Verified principal grants and declared action | Route access is not object/field ownership |
| Subscription tier | Server-owned current entitlement | Cached entitlement needs revocation/staleness policy; unknown tiers must not compare as valid |
| Feature flag | Server-owned subject/tenant and rule snapshot | Enablement does not grant permission; dependency failure needs a fallback |
| Rate limit | Trusted identity, bounded atomic state and time | Process-local Maps differ across workers and need eviction; quota is not a concurrent-work cap |

A public marker must not unintentionally skip resource authorization on a private endpoint. Keep public metadata narrowly placed and test overrides. Permission caching needs bounded keys, relevant authorization context and a revocation policy; an unconditional long TTL can preserve revoked access. Use [atomic Redis limiting](../../20.8-caching/20.8.03-advanced-redis-patterns.md) for that mechanism rather than duplicating an unbounded Map here.

## Mistakes and working decisions

Compose policies in dependency order, keep expensive asynchronous lookups bounded, and authorize effects again at their actual data boundary when concurrent state can change. Unit-test the guard decision, then use HTTP/transport tests to prove registration, metadata override, error status and that denied requests do not call business code. Headers naming roles, internal origin or tenants are untrusted input; a guard must not accept them as established authority.

## Summary

A guard evaluates a selected handler's policy before protected work. Trace verified identity, metadata selection and the allow/deny result. Registration determines DI and scope; transport determines how identity and errors are represented. Roles, flags and quotas still need resource, concurrency, staleness and failure boundaries.

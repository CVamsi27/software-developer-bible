# NestJS Interceptors

Trace two wrappers around one result. Save this complete Nest/RxJS fixture as `interceptors.ts` and use the [core compiler setup](../01-core-architecture/20.2.1.02-controllers.md#run-one-createread-fixture).

## Definition

An interceptor wraps the remaining handler execution. It can establish before-work, transform emitted results, observe errors or replace the continuation. `next.handle()` supplies an RxJS Observable: a sequence that can emit values, fail, complete or be unsubscribed.

> **Textbook Definition:** A NestJS interceptor composes handler behavior through an Observable continuation, with scope and ordering determined by its binding. Its operators affect observed execution/results, not automatically the underlying operation's transaction or cancellation semantics.

## First Principles

A guard answers whether execution may start; a pipe establishes an input argument. Timing a call or mapping its result needs an owner surrounding execution. Wrappers nest, so outer before-work runs first and outer result mapping runs after the inner wrapper.
This makes order part of the response contract.

Observation and effect are different. A result emitted by a handler does not prove its response reached the client. Unsubscribing a promise-backed Observable does not cancel the promise's database mutation.
An interceptor must state what boundary it observes or controls.

## 1. Trace two wrappers around one result

Save this complete Nest/RxJS fixture as `interceptors.ts` and use the [core compiler setup](../01-core-architecture/20.2.1.02-controllers.md#run-one-createread-fixture). The empty execution context is an isolated fixture: these wrappers deliberately read no transport state.

```typescript
import 'reflect-metadata';
import { CallHandler, ExecutionContext, NestInterceptor } from '@nestjs/common';
import { defer, finalize, firstValueFrom, map, of } from 'rxjs';
const events: string[] = [];
class TraceInterceptor implements NestInterceptor<number, number> {
  constructor(private readonly name: string) {}
  intercept(_context: ExecutionContext, next: CallHandler<number>) {
    events.push(`${this.name}:before`);
    return next.handle().pipe(
      map(value => { events.push(`${this.name}:map`); return value + 1; }),
      finalize(() => events.push(`${this.name}:finalize`)),
    );
  }
}
async function main() {
  const context = {} as ExecutionContext;
  const outer = new TraceInterceptor('outer');
  const inner = new TraceInterceptor('inner');
  const handler: CallHandler<number> = { handle: () => defer(() => {
    events.push('handler');
    return of(1);
  }) };
  const result = await firstValueFrom(outer.intercept(context, {
    handle: () => inner.intercept(context, handler),
  }));
  console.log(result);
  console.log(events);
}
main().catch(error => { console.error(error); process.exitCode = 1; });
```

The result is 3: handler 1 → inner map 2 → outer map 3. The trace begins `outer:before, inner:before, handler, inner:map, outer:map`. Finalizers execute when their subscriptions terminate; they are not successful-client-receipt callbacks.
In an application, global → controller → route bindings produce nested before-work and reverse result processing. Returning an Observable without calling `next.handle()` can intentionally bypass downstream pipes/handler, for example a valid cache hit.

## 2. Choose the operator for the contract

| Operator | What it does | Boundary |
| -------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| map | Replaces each emitted value synchronously | An envelope is not field authorization or serialization exclusion |
| tap | Observes next/error/complete notifications | A throwing observer can fail the stream; an async callback's promise is not automatically awaited |
| finalize | Runs cleanup on completion/error/unsubscribe | Does not mean an HTTP response completed successfully |
| catchError | Replaces/rethrows a failure | Returning a success value changes the error contract and can conceal a failed effect |
| mergeMap / concatMap | Owns async inner work; concatMap serializes emissions | Bound concurrency and queues; effects must still be retry-safe |
| switchMap | Replaces observation of a previous inner stream | Unsubscription may not cancel a promise's side effect |
| timeout | Stops waiting under its emission rule | Must separately cancel cooperative underlying work |
| retry | Resubscribes after an error | Can rerun handler work; a committed mutation is not undone |

Keep response mapping separate from byte streaming. Native `@Res()` sends bypass Nest's standard returned-value mapping; streams, 204s, files and SSE need suitable policies rather than a global JSON envelope. A class-transformer projection needs configured decorators/exclusion and the intended serializer; merely instantiating a DTO does not erase secrets.

## 3. Observe a timeout without inventing cancellation

This standalone RxJS continuation demonstrates the changed condition. Save as `timeout.ts` with the same compiler setup:

```typescript
import { defer, firstValueFrom, from, timeout, TimeoutError } from 'rxjs';
import { setTimeout as wait } from 'node:timers/promises';
async function main() {
  let effects = 0;
  const work = defer(() => from(wait(40).then(() => { effects += 1; return 'committed'; })));
  try { await firstValueFrom(work.pipe(timeout({ first: 5 }))); }
  catch (error) {
    if (!(error instanceof TimeoutError)) throw error;
    console.log('stopped waiting');
  }
  await wait(60);
  console.log(effects);
}
main().catch(error => { console.error(error); process.exitCode = 1; });
```

It prints stopped waiting, then 1. The first emission missed its deadline, so the observer unsubscribed; the promise still incremented the fixture effect. A mutation may similarly commit after the caller gets a timeout.
Propagate an AbortSignal/deadline to APIs that cooperate, own release/cleanup, and reconcile an uncertain commit through durable operation identity. A timer cannot interrupt synchronous JavaScript already blocking the loop. For multi-emission SSE, a first-value timeout differs from an `each` inactivity deadline.

A service waiting on a downstream deadline may deliberately use 504, while other overload/deadline situations need their documented error contract. Do not select 408 solely because the RxJS error is named TimeoutError. Do not blanket-retry every Observable: repeated database charges, enqueue calls or email effects need transaction/idempotency/reconciliation boundaries.

## 4. Cache only an eligible representation

A GET method and raw URL alone do not establish shared cache eligibility. Two tenants can request the same URL and need different bytes. Include the verified tenant/user/projection and relevant negotiated representation, or explicitly restrict the cache to public invariant data.
Preserve intended status/headers, avoid private/Set-Cookie responses, bound entry count/size/TTL and define invalidation/failure behavior.

A response shortcut happens after guards but can skip pipes and handler work; permission checks that only happen in the handler may therefore be bypassed. Ensure eligibility/policy before cache lookup. Concurrent fills and writes can leave stale entries even when a writer deletes a key.
Process-local cache state differs across replicas. The full mechanism lives in [caching](../../20.8-caching/INDEX.md).

## 5. Timing, metrics and serialization need their actual owners

`tap(next)` can miss failures and record several results for a multi-emission stream. Use deliberate outcome/error tracking plus finalization for handler lifetime, and response finish/close instrumentation for transport completion. Do not double count those two boundaries or classify an aborted response as delivered.
Use monotonic elapsed time and bounded method/route-template labels; raw paths, request IDs and user IDs cause metric cardinality growth.

An injected telemetry exporter needs bounded buffering and a failure posture. Logging failures must not unexpectedly replace the application's result, and `tap(async ...)` is not durable audit delivery. Strip secrets in the producer and control artifact access/retention.

Compression should use an adapter-compatible streaming/negotiated facility that handles Accept-Encoding, Vary, no-body responses, content type and pressure. Applying gzipSync(JSON.stringify(data)) to every result blocks the loop, may cause adapter reserialization, ignores negotiation and corrupts streams. Upload interceptors must use the adapter's compatible parser and its limits before file validation; that mechanism lives in [upload APIs](../../20.3-rest-apis/03-payloads-errors-integration/20.3.3.04-file-upload-apis.md).

## 6. Registration and failures

`@UseInterceptors(Class)` and module `APP_INTERCEPTOR` registration let Nest inject dependencies; manually constructed instances need their collaborators supplied. Use SetMetadata/Reflector to select an intended DTO policy rather than writing metadata to the wrong class/property/handler target. Handler exceptions propagate unless deliberately replaced; every interceptor need not catch/log the same error.
Filters own final uncaught transport mapping.

Test operator behavior in isolation, then test real status/headers/bytes, denied requests, streams, errors and cancellation. Async operators compose promises; they do not move CPU work to another thread. Measure middleware, handler, transport and queue time separately when selecting a performance change.

## Summary

Interceptors wrap a continuation and compose its observed results and failures. Trace nesting and operator effects before applying mapping, caching, timeouts or retries. Subscription lifetime is not client delivery or mutation cancellation.
Authorization, durable effects, resource bounds and response bytes retain their own explicit owners.

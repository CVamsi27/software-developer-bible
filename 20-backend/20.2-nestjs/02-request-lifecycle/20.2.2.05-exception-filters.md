# NestJS Exception Filters

Trace one safe HTTP mapper. Save this complete Nest 11 fixture as `filters.ts` and use the [core compiler setup](../01-core-architecture/20.2.1.02-controllers.md#run-one-createread-fixture).

## Definition

An exception filter maps an uncaught failure from a supported Nest execution context into its transport error response. HTTP filters choose status and public error shape; RPC, GraphQL and WebSocket contexts need their own compatible failure representation.

> **Textbook Definition:** A NestJS exception filter handles selected uncaught exceptions within its binding and execution context. It controls transport-specific failure mapping, not automatic recovery of detached work or rollback of previously committed effects.

## First Principles

A missing record and a database outage have different meanings to a client. Returning both as 500 loses useful policy; returning an internal driver message can disclose query text or credentials. The failure boundary needs a stable public representation and separately owned private diagnostics.

The response also has a state. Before headers, a filter can send its error envelope. After bytes have begun, it cannot replace an earlier 200 with a new complete JSON 500.
The stream/adapter needs a compatible close/error policy instead. Mapping an error does not undo its underlying effect.

## 1. Trace one safe HTTP mapper

Save this complete Nest 11 fixture as `filters.ts` and use the [core compiler setup](../01-core-architecture/20.2.1.02-controllers.md#run-one-createread-fixture). It demonstrates adapter-neutral writing through HttpAdapterHost and safe fixed messages; it does not export raw exception details.

```typescript
import 'reflect-metadata';
import {
  ArgumentsHost, BadRequestException, Catch, Controller, Get,
  HttpException, Inject, Module, NotFoundException,
} from '@nestjs/common';
import { APP_FILTER, BaseExceptionFilter, HttpAdapterHost, NestFactory } from '@nestjs/core';
@Catch()
class SafeHttpFilter extends BaseExceptionFilter {
  constructor(@Inject(HttpAdapterHost) private readonly adapters: HttpAdapterHost) {
    super(adapters.httpAdapter);
  }
  catch(exception: unknown, host: ArgumentsHost) {
    const adapter = this.adapters.httpAdapter;
    const response = host.switchToHttp().getResponse();
    if (adapter.isHeadersSent(response)) {
      super.catch(exception, host); // adapter-compatible existing-response handling
      return;
    }
    const messages = new Map([
      [400, 'Invalid request'], [401, 'Unauthorized'], [403, 'Forbidden'],
      [404, 'Not found'], [409, 'Conflict'], [413, 'Payload too large'],
      [415, 'Unsupported media type'], [422, 'Invalid input'],
      [429, 'Too many requests'], [503, 'Service unavailable'],
      [504, 'Gateway timeout'],
    ]);
    const proposed = exception instanceof HttpException ? exception.getStatus() : 500;
    const status = messages.has(proposed) ? proposed : 500;
    adapter.reply(response, { statusCode: status,
      message: messages.get(status) ?? 'Internal server error' }, status);
  }
}
@Controller('probe')
class ProbeController {
  @Get('missing') missing() { throw new NotFoundException('private resource detail'); }
  @Get('invalid') invalid() { throw new BadRequestException('private validation detail'); }
  @Get('unexpected') unexpected() { throw new Error('database password=fixture-secret'); }
}
@Module({ controllers: [ProbeController],
  providers: [{ provide: APP_FILTER, useClass: SafeHttpFilter }] })
class AppModule {}
async function main() {
  const app = await NestFactory.create(AppModule, { logger: false });
  try {
    await app.listen(0, '127.0.0.1');
    const origin = await app.getUrl();
    for (const path of ['missing', 'invalid', 'unexpected']) {
      const response = await fetch(origin + '/probe/' + path);
      console.log(response.status, await response.json());
    }
  } finally { await app.close(); }
}
main().catch(error => { console.error(error); process.exitCode = 1; });
```

The outputs are 404 Not found, 400 Invalid request and 500 Internal server error in the same `{ statusCode, message }` shape. No private text reaches the response. The status allowlist is the fixture's contract; add another known status/message deliberately rather than silently treating all valid HTTP statuses as identical.
A real filter also uses the server-owned correlation ID and bounded, redacted diagnostics; the fixture avoids a fake no-op monitoring client.

Changing the thrown value to a non-Error still follows the generic 500 path. An HttpException's class/status alone does not prove its message/details are safe: a dependency can construct one with internal data. A deliberate domain error can instead carry a reviewed public code/schema that the mapper recognizes.
Preserve protocol-required headers such as the intended WWW-Authenticate challenge or Retry-After when those apply; this narrow fixture does not implement those policies.

## 2. Know when the built-in layer is enough

Nest's built-in HTTP exception layer handles HttpException status/response and gives unknown failures a generic 500. A custom filter is useful for a deliberate envelope/domain mapping, not a requirement to duplicate framework behavior. `getResponse()` may be a string or object, including a validation message array; `exception.message` alone is not the complete HttpException payload.

If exposing validation details, construct a bounded allowlisted field/code array and omit rejected values, credentials and arbitrary driver text. Keep a stable schema across known errors. Do not serialize stacks or simply pass every exception response object through because its status is below 500.

## 3. Selection and registration are not an error middleware chain

`@Catch(Type)` selects specified exception classes; `@Catch()` catches all. A route-scoped filter has precedence over controller then global filters. Once an applicable filter handles an exception, it is not automatically passed onward through every higher-scoped filter.
Middleware runs before Nest selects a route, so an exception thrown there can reach only a global filter. Caught exceptions do not reach the filter layer at all. Do not rely on “log here, format globally” unless the chosen implementation explicitly delegates that behavior.
[Request lifecycle](https://docs.nestjs.com/faq/request-lifecycle)

`APP_FILTER` registers a DI-managed global filter. Manually calling `app.useGlobalFilters(new Filter())` requires supplying constructor collaborators yourself. Controller/route scoped filters are valid for a specific local contract; they are not inherently a mistake because a global filter also exists.
Filters needing the underlying platform can use HttpAdapterHost; Express `.status().json()` is not automatically a Fastify interface.

The default implementation is BaseExceptionFilter, not an exported `ExceptionsFilter` to instantiate indiscriminately. Extending it is useful when delegating framework behavior, with the correct adapter supplied. Keep catch-all and specific registrations unambiguous and test precedence with the real application.

## 4. Recoverability belongs to the operation

A unique-constraint violation can map to a conflict only when its constraint/operation has the intended business meaning. A foreign-key failure is not always a client 400: it might reveal a concurrent deletion or an internal bug. Map known database failures in a domain-aware boundary and preserve unexpected failures for investigation.
Never return raw detail containing another tenant's record.

A pre-checked account balance is not an atomic funds constraint. The service transaction must enforce it under concurrency. A filter producing “insufficient funds” cannot repair a partial debit or undo a charge already accepted by a provider.
Unknown commit outcomes need reconciliation/idempotency before retry; do not blindly convert every driver failure into a retriable response.

Log unexpected failures with controlled context and redaction, classify expected errors for appropriate levels/metrics, and avoid repeatedly logging the same failure in service/interceptor/filter. Async transport logging still spends capacity and may block, overflow or lose events. Define bounded buffering and a sink failure policy; a promise that nobody awaits is not durable monitoring.

## 5. Respect failures outside the HTTP path

An awaited/returned handler failure can reach the applicable filter; an unrelated timer throw or detached promise is not automatically owned by that completed request. Queue workers need their own acknowledgment/retry/dead-letter boundary. Process-level fatal failures need bounded shutdown/exit policy rather than attempting another HTTP response.

GraphQL filters implement the supported GqlExceptionFilter contract and return compatible GraphQLError/public extension codes; do not import a fictional GraphQLException or treat GraphQL errors as ordinary response.status writes. RPC handlers use their transport exception/observable convention, and WebSockets require their connection/message policy. Hybrid applications need deliberate global-filter inheritance/configuration.

For an already-started response, the fixture delegates the framework's existing-response behavior. A streaming source failure needs the stream owner's teardown/error signaling and may truncate the earlier response; test actual bytes/connection behavior. Do not promise a new complete JSON envelope or retry a streamed mutation at that point.

## Summary

A filter selects and maps an uncaught transport failure to a deliberate public contract. Distinguish known domain/status cases from unexpected details, preserve response-state and protocol requirements, and test scope precedence. Error mapping does not establish rollback, cancellation, delivery or ownership of detached work.

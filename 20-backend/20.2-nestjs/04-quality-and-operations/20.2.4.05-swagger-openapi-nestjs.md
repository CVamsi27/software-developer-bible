# Swagger & OpenAPI in NestJS


A generated client can compile against a schema that the server never enforces. Generate a reviewable description, then compare its statuses, payloads and access requirements with actual responses.

## Definition

**OpenAPI** describes an HTTP API in a format that programming languages can share: paths, operations, data schemas, and security requirements. **Swagger** is the tooling around that format, including Swagger UI and code generators. In NestJS, `@nestjs/swagger` reads decorators to generate an OpenAPI document and can serve Swagger UI at `/docs`. It can infer many schema details when data transfer objects (DTOs) are decorated or the CLI plugin supplies their metadata.

> **Textbook Definition:** NestJS OpenAPI tooling derives an HTTP API description from controller and data-model metadata. Swagger UI renders that description for exploration; runtime validation and authorization remain separate application responsibilities.

## First Principles

Generated OpenAPI follows from the single-source-of-truth principle (→ 20.3.1.05), applied at the code level:

1. **Decorators provide metadata for the specification.** `@ApiProperty` and `@ApiOperation` describe DTOs and handlers. Generating OpenAPI from them reduces duplicate documentation, but the metadata must still match runtime behavior.
2. **A DTO can support validation and documentation.** Keeping both near the same declaration reduces disagreement between them (→ 20.2.2.03). Fastify's schema-based serialization applies a similar idea (→ 20.1.4.03).
3. **Generation leaves details for the author.** Response types, error codes, and examples need explicit attention. A generated document can still be incomplete or promise behavior the handler does not provide.

## Why Do We Need It?

1. **Less duplicated contract data** — controllers and DTO metadata can generate much of the specification; tests still compare it with real status codes and payloads.
2. **Client codegen** — frontend/mobile teams generate typed SDKs (`openapi-typescript`, `openapi-generator`) from `/docs-json` instead of hand-writing fetch wrappers.
3. **Auth documentation** — declare security schemes, then attach operation requirements. Swagger UI displays them; a guard separately enforces access.
4. **Contract testing in CI** — a committed spec snapshot makes any accidental breaking change a visible diff at PR time.
5. **Interview signal** — "How do you keep docs from lying?" tests whether you treat the spec as a build artifact rather than a chore.

## How It Works

### Generation Pipeline

```text
┌─────────────────────────────────────────────────────────────┐
│ SPEC GENERATION PIPELINE                                    │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│ Controllers (@Controller/@Get/@Post)                        │
│      │  path + method + status codes                        │
│      ▼                                                      │
│ DTOs (@ApiProperty / CLI plugin inference)                  │
│      │  request/response schemas                            │
│      ▼                                                      │
│ DocumentBuilder                                             │
│      │  info/servers/tags/securitySchemes                   │
│      ▼                                                      │
│ SwaggerModule.createDocument(app, config)                   │
│      │                                                      │
│      ├──► SwaggerModule.setup('/docs')   Swagger UI         │
│      └──► writeFileSync('openapi.json')  artifact for CI    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### Decorator Layering per Route

```text
@Post()                    ← operation exists
@ApiBearerAuth('jwt')      ← security requirement (scheme ref)
@ApiOperation({summary})   ← human summary
@ApiCreatedResponse({type}) ← 201 success schema (default POST)
@ApiBadRequestResponse()   ← error schemas
@ApiParam/@ApiQuery        ← parameter metadata
Handler(dto: CreateXDto)   ← body schema from @ApiProperty
```

## Code Examples

### Setup and DocumentBuilder Composition

```typescript
// main.ts
import { NestFactory } from '@nestjs/core';
import { ValidationPipe } from '@nestjs/common';
import { SwaggerModule, DocumentBuilder } from '@nestjs/swagger';
import { AppModule } from './app.module';
import * as fs from 'node:fs';

async function bootstrap(): Promise<void> {
  const app = await NestFactory.create(AppModule);
  app.useGlobalPipes(new ValidationPipe({
    transform: true, whitelist: true, forbidNonWhitelisted: true,
  }));

  const config = new DocumentBuilder()
    .setTitle('Orders API')
    .setDescription('Order management for the storefront platform')
    .setVersion('2.1')
    .setContact('API Team', 'https://example.com', 'api@example.com')
    .setLicense('MIT', 'https://opensource.org/licenses/MIT')
    .addServer('https://api.example.com', 'Production')
    .addServer('https://staging-api.example.com', 'Staging')
    .addTag('orders', 'Order lifecycle endpoints')
    .addTag('health', 'Liveness and readiness')
    // Security schemes:
    .addBearerAuth({ type: 'http', scheme: 'bearer', bearerFormat: 'JWT' }, 'jwt')
    .addApiKey({ type: 'apiKey', name: 'X-API-Key', in: 'header' }, 'apiKey')
    .addCookieAuth('session_cookie', { type: 'apiKey', in: 'cookie' }, 'cookie')
    .build();

  const document = SwaggerModule.createDocument(app, config);

  // Metadata does not enforce access: protect routes with guards and validate DTOs.
  // Artifact for client codegen + CI contract diff
  if (process.env.NODE_ENV !== 'production') {
    fs.writeFileSync('./openapi.json', JSON.stringify(document, null, 2));
  }

  SwaggerModule.setup('docs', app, document, {
    swaggerOptions: { persistAuthorization: false }, // avoid retaining credentials by default
    customSiteTitle: 'Orders API Docs',
  });

  await app.listen(3000);
}
bootstrap().catch(error => { console.error(error); process.exitCode = 1; });
```

### DTO Mapping with @ApiProperty

```typescript
// create-order.dto.ts
import { ApiProperty, ApiPropertyOptional } from '@nestjs/swagger';
import {
  ArrayMaxSize, ArrayMinSize, IsArray, IsIn, IsInt, IsOptional, IsUUID, Max, Min, ValidateNested,
} from 'class-validator';
import { Type } from 'class-transformer';

class OrderItemDto {
  @ApiProperty({ format: 'uuid', description: 'Product identifier' })
  @IsUUID()
  productId!: string;

  @ApiProperty({ minimum: 1, maximum: 100, example: 2 })
  @IsInt()
  @Min(1)
  @Max(100)
  quantity!: number;
}

export class CreateOrderDto {
  @ApiProperty({
    enum: ['standard', 'express'],
    example: 'standard',
    description: 'Shipping speed',
  })
  @IsIn(['standard', 'express'])
  shippingMethod!: 'standard' | 'express';

  @ApiProperty({
    type: () => [OrderItemDto],
    minItems: 1, maxItems: 100,
    description: 'Items being purchased',
  })
  @IsArray()
  @ArrayMinSize(1)
  @ArrayMaxSize(100)
  @ValidateNested({ each: true })
  @Type(() => OrderItemDto)
  items!: OrderItemDto[];

  @ApiPropertyOptional({ format: 'uuid', nullable: true })
  @IsOptional()
  @IsUUID()
  couponId?: string | null;
}
```

These quantity/item limits are example product policy, documented and validated consistently. The service still derives trusted prices and checks inventory/ownership atomically; a valid product ID does not authorize a purchase. `@ApiProperty` alone performs no validation.

The snippets use the usual OpenAPI 3.0 schema shape, including `nullable`. OpenAPI 3.1 represents null through JSON Schema types/composition instead; match the generator output and client tools to the declared document version.

### Generic Envelope Schemas via @ApiExtraModels

```typescript
// api-envelope.ts — one generic shape reused by every endpoint
import { applyDecorators, Type } from '@nestjs/common';
import {
  ApiExtraModels, ApiOkResponse, ApiProperty, getSchemaPath,
} from '@nestjs/swagger';

export class ApiResponseDto<T> {
  data!: T;
  requestId!: string;
}

/** Documents `{ data: T, requestId }` responses for one item type. */
export function ApiOkEnvelope(itemType: Type, description = 'OK'): MethodDecorator {
  return applyDecorators(
    ApiExtraModels(itemType),
    ApiOkResponse({
      description,
      schema: {
        type: 'object',
        required: ['data', 'requestId'],
        properties: {
          data: { $ref: getSchemaPath(itemType) },
          requestId: { type: 'string', description: 'Correlation identifier' },
        },
      },
    }),
  );
}
```

```typescript
// orders.controller.ts — using response decorators + generics
import { Body, Controller, Get, Param, Post, UseGuards } from '@nestjs/common';
import {
  ApiBearerAuth, ApiCreatedResponse, ApiOperation, ApiTags,
} from '@nestjs/swagger';
import { OrderDto } from './order.dto';
import { JwtAuthGuard } from './jwt-auth.guard';

@ApiTags('orders')
@ApiBearerAuth('jwt')
@UseGuards(JwtAuthGuard) // application verifier; metadata alone does not protect routes
@Controller('orders')
export class OrdersController {
  constructor(private readonly orders: OrdersService) {}

  @Post()
  @ApiOperation({ summary: 'Create an order from items' })
  @ApiCreatedResponse({ type: OrderDto, description: 'Order created' })
  async create(@Body() dto: CreateOrderDto): Promise<OrderDto> {
    return this.orders.create(dto);
  }

  @Get(':id')
  @ApiOperation({ summary: 'Fetch one order' })
  @ApiOkEnvelope(OrderDto, 'The order wrapped in the standard envelope')
  async getById(@Param('id') id: string): Promise<ApiResponseDto<OrderDto>> {
    return { data: await this.orders.getById(id), requestId: crypto.randomUUID() }; // prefer propagated request ID
  }
}
```

### Auth Security Schemes in Practice

```typescript
// Per-route scheme selection — matches addBearerAuth/addApiKey/addCookieAuth keys
import { applyDecorators, UseGuards } from '@nestjs/common';
import { ApiBearerAuth, ApiCookieAuth, ApiSecurity } from '@nestjs/swagger';
import { JwtAuthGuard } from './jwt-auth.guard';
import { ApiKeyGuard } from './api-key.guard';

/** End-user JWT routes */
export function JwtProtected(): MethodDecorator {
  return applyDecorators(UseGuards(JwtAuthGuard), ApiBearerAuth('jwt'));
}

/** Machine-to-machine routes authenticated by header key */
export function ApiKeyProtected(): MethodDecorator {
  return applyDecorators(UseGuards(ApiKeyGuard), ApiSecurity('apiKey'));
}
```

### Serving Spec JSON for Client Codegen

```typescript
// scripts/dump-openapi.ts — build-time artifact for codegen + CI diff
// Run headless: node dist/scripts/dump-openapi.js openapi.current.json
import { NestFactory } from '@nestjs/core';
import { SwaggerModule, DocumentBuilder } from '@nestjs/swagger';
import { AppModule } from '../app.module';
import * as fs from 'node:fs';

async function dump(): Promise<void> {
  const app = await NestFactory.create(AppModule, { logger: false });
  const config = new DocumentBuilder().setTitle('Orders API').setVersion('2.1').build();
  try {
    const doc = SwaggerModule.createDocument(app, config);
    fs.writeFileSync(process.argv[2] ?? 'openapi.current.json', JSON.stringify(doc, null, 2) + '\n');
  } finally { await app.close(); }
}
dump().catch(error => { console.error(error); process.exitCode = 1; });
```

> Note: once `SwaggerModule.setup('docs', app, document)` runs, Nest also
> serves machine-readable JSON automatically at `/docs-json`.

```bash
# Client generation from the served spec
npx openapi-typescript http://localhost:3000/docs-json -o src/types/api.d.ts

# Full SDK (TS axios):
npx @openapitools/openapi-generator-cli generate \
  -i http://localhost:3000/docs-json \
  -g typescript-axios -o ../frontend/src/api-client
```

### CI Contract Check

Use a pinned, installed `oasdiff` CLI and the same spec-generation configuration as the application. The dump command writes a named file; redirecting stdout would create an empty artifact while potentially overwriting the committed baseline.

```bash
npm run build
node dist/scripts/dump-openapi.js openapi.current.json
oasdiff breaking openapi.json openapi.current.json --fail-on ERR
cmp openapi.json openapi.current.json
```

The breaking-change check compares the committed contract with the generated one. `cmp` separately checks whether the committed artifact is current: an additive change can pass compatibility but still require regeneration. To evaluate compatibility after a PR updates both code and its spec, compare the base branch's spec with the new one too. A textual diff cannot discover which deployed consumers still use a removed field; maintain consumer evidence separately.

Boot-time specification generation can run constructors and initialization code. Keep the generation application safe without production credentials and avoid migrations or external side effects in its startup. These commands assume the application's build and generator paths; they are not a complete CI workflow.

## Real-World Use Cases

1. **Frontend typed SDK** — Next.js team imports generated types from `docs-json`; code that consumes a renamed field can fail after client regeneration/type-checking. An already deployed client still needs a compatibility and rollout policy.
2. **Public partner API** — versioned spec published at `/v2/docs-json` with bearer + apiKey schemes documented; partners self-serve integration through Swagger UI.
3. **Microservice gateway aggregation** — each service exposes its spec; the BFF merges documents into one catalog for internal discovery.
4. **Mobile offline clients** — codegen produces Kotlin/Swift models from the same spec, keeping three platforms aligned to one contract.
5. **Deprecation workflow** — `@ApiOperation({ deprecated: true })` marks sunset endpoints; the spec diff flags contract removal; consumer usage requires telemetry or contract tests.

## Common Mistakes

| Mistake | Fix |
| --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Undecorated DTOs produce empty schemas `{}` | Add `@ApiProperty` per field, or enable the Swagger CLI plugin (`introspectComments`, `classValidatorShim`) to infer from types. |
| Using concrete classes in `@ApiResponse({ type })` for generics | Generics erase at runtime; use `@ApiExtraModels` + `getSchemaPath` composition. |
| Security scheme added but not referenced | `addBearerAuth(..., 'jwt')` must pair with `@ApiBearerAuth('jwt')` per route/controller. |
| Serving interactive UI publicly in production | Disable `SwaggerModule.setup` behind env flag or protect with basic auth/IP allowlist. |
| Spec and server drift | Choose code-first generation or contract-first implementation, then compare the published artifact with actual response and access behavior. |
| `nullable` mismatches between TS and schema | Set `nullable: true` in `@ApiProperty` whenever the TS type includes `null` — strictNullChecks will not save the spec. |

## Best Practices

1. **Enable the CLI plugin** — `plugins: ['@nestjs/swagger']` in `nest-cli.json` infers properties from types/comments and slashes decorator boilerplate.
2. **Compose reusable response helpers** — wrap `applyDecorators(ApiExtraModels..., ApiOkResponse...)` so envelopes stay consistent everywhere.
3. **Name schemes explicitly** ('jwt', 'apiKey', 'cookie') — operations reference their intended requirements. Separate security requirement objects mean alternatives (OR); multiple scheme keys in one object mean all are required (AND).
4. **Commit `openapi.json`** — it becomes reviewable in PRs and the anchor for `oasdiff` contract checks.
5. **Choose token persistence deliberately** — `persistAuthorization` retains credentials in the browser; leave it off on shared machines or sensitive environments.
6. **Tag controllers by domain** — grouped navigation beats a 200-operation flat list.
7. **Document error shapes too** — `@ApiUnauthorizedResponse` etc. make client error handling implementable without reading source.

## Performance Considerations

- **Spec generation walks every controller at boot** — measure cost on the actual application; skip `createDocument` entirely in production when docs are disabled.
- **Serve pre-built specs in prod** — dump `openapi.json` at build time and serve statically instead of reflecting at runtime.
- **The UI bundle is loaded by documentation clients, not ordinary API responses** — but gate it anyway; public API surfaces should minimize attack/recon surface.
- **Codegen output grows with spec size** — keep shared schemas `$ref`-ed (default) so generated clients stay small; avoid inline object duplication.

## Summary

- `@nestjs/swagger` turns controllers + decorated DTOs into an OpenAPI 3 document; `DocumentBuilder` composes title/servers/tags/security schemes globally.
- Precise payload docs come from `@ApiProperty`/`@ApiPropertyOptional`; generic envelopes need `@ApiExtraModels` + `getSchemaPath` because TypeScript generics vanish at runtime.
- Security schemes (bearer JWT, header API key, cookie session) are declared once in the builder and attached per route with matching keys.
- Treat the spec as a build artifact: expose `/docs-json`, generate clients from it, and run `oasdiff` against the committed copy in CI to block breaking changes.
- The same artifact links the NestJS stack to the REST stack's contract testing practices — one source of truth, many consumers.

# File Upload APIs

>
> **Why it matters:** File upload is where naive backends leak: memory exhaustion from buffering a 4 GB body, RCE via crafted filenames, malware hosting on your CDN. Senior interviews love the presigned-URL flow because it tests whether you understand who owns which responsibility.

## Definition

A **file upload API** moves binary payloads from clients into durable storage while enforcing size, type, provenance, and lifecycle policies. The two canonical flows:

```text
1. PROXY UPLOAD (small files, ≤ tens of MB)
Client ──multipart/form-data──► API ──stream──► Object Storage ──► metadata row

2. PRESIGNED / DIRECT UPLOAD (large files)
Client ──POST /uploads {filename,size,type}──► API (validates policy,
          ◄──── presigned PUT + final URL ────  issues signed grant)
Client ──PUT bytes────────────────────────────► S3 (server never touches data)
        ──POST /uploads/{id}/complete─────────► API confirms, scans, publishes
```

**Resumable uploads** extend flow 2 with offset tracking so interrupted transfers continue instead of restarting.

## First Principles

File uploads are governed by where bytes can and cannot flow:

1. **App servers are the wrong place for large bytes.** They're sized for request handling, not throughput; streaming 2GB through one ties a worker for minutes. The scalable shape routes bytes *around* the app: presigned URLs direct-to-object-storage, server only brokers authorization.
2. **Integrity needs both directions.** Client → server needs checksums (hash before upload, verify after) because TCP checksums don't catch application-level corruption; server → client needs Content-Length/Range so partial transfers are detectable and resumable.
3. **Upload size must be a designed limit**, not an accident of framework defaults — body-size caps, storage quotas, and virus scanning are boundary controls. Every "unlimited" upload endpoint becomes an attacker's free storage.

## Why Do We Need It?

1. **Bandwidth economics** — Proxying a 2 GB video through your API costs egress + ingress twice and pins Node event-loop sockets; direct-to-S3 makes storage the data plane and your API the control plane.
2. **Reliability on bad networks** — Mobile clients die mid-upload constantly; resumable protocols turn a restart-from-zero into a restart-from-offset.
3. **Memory safety** — Naive multer usage buffers entire files in RAM; streaming keeps constant memory under concurrency.
4. **Security surface reduction** — Signed, scoped, short-TTL grants replace long-lived bucket credentials on clients; filename/MIME gates stop path traversal and polyglot-file attacks.
5. **Compliance gates** — Virus scanning, PII detection, and license checks must run *before* an object is publicly reachable, not after.
6. **Post-processing pipeline** — Thumbnails, transcodes, EXIF stripping, OCR all hang naturally off an upload-complete event.

## How It Works

### Multipart/form-data mechanics

`multipart/form-data` splits the body into parts separated by a boundary; each part carries its own headers:

```text
Content-Type: multipart/form-data; boundary=X-BOUNDARY
──X-BOUNDARY
Content-Disposition: form-data; name="file"; filename="report.pdf"
Content-Type: application/pdf
<bytes...>
──X-BOUNDARY
Content-Disposition: form-data; name="documentId"

12345
──X-BOUNDARY--
```

Server-side rules that matter:

- Enforce a **max body/part size** at every layer (nginx `client_max_body_size`, Express `limits.fileSize` in busboy/multer) — reject with `413 Payload Too Large`.
- Treat `filename` as attacker-controlled text (it may contain `../../`, nulls, unicode confusables).
- Never trust part `Content-Type`; sniff magic bytes.
- Stream: parse → transform → sink (storage/HTTP) without whole-file buffering.

### Presigned URL flow (client → S3 direct)

```text
Client                          API                              S3
  │ POST /uploads                │                                │
  │ {name,size,mime,checksum}    │ validate policy (size≤2GB,     │
  │─────────────────────────────►│ mime allow-list, quota, authz) │
  │◄──201 {uploadId,             │ create metadata row (pending)  │
  │   putUrl(signed,TTL=15m)}    │                                │
  │ PUT bytes ──── putUrl ───────────────────────────────────────► │
  │      (optionally x-amz-checksum-sha256 header)                │
  │ POST /uploads/{id}/complete  │ headObject: verify exists,     │
  │─────────────────────────────►│ size+checksum match            │
  │                              │ enqueue virus scan             │
  │◄──202 {status:"scanning"}────│                                │
```

Presigning options worth naming: presigned `PUT` (single op, no policy conditions), presigned `POST` policy (can constrain content-length-range, key prefix), and S3 multipart (initiate/upload-part/complete) for files over ~100 MB or when parallelism is needed.

### Resumable uploads (tus ideas + Content-Range)

```text
POST   /files            Upload-Length: 1073741824        → 201, Location: /files/24d5...
HEAD   /files/24d5                                        → 200, Upload-Offset: 52428800
PATCH  /files/24d5       Content-Type: application/offset+octet-stream
                         Upload-Offset: 52428800
                         <remaining bytes>                 → 204, Upload-Offset: 1073741824
```

The same shape works without tus libraries using plain HTTP range semantics: client asks `HEAD` for received offset, sends the next chunk with `Content-Range: bytes 52428800-.../*`, server appends durably and returns the new offset. S3 exposes this natively as **multipart upload**: `CreateMultipartUpload` → N × `UploadPart` (each independently retryable) → `CompleteMultipartUpload`.

### Security gates pipeline

```text
bytes ──► [1] size cap ──► [2] MIME sniff ──► [3] sanitize name/key
              │                  │                     │
           413 early      allow-list only         random uuid.ext
                                                    │
        [6] publish (flip tag/acl) ◄── [5] scan OK ◄┴── [4] store to quarantine prefix
              │                       │
        public CDN domain        [infected] → delete/quarantine + audit event
```

Objects live under a **quarantine prefix** (or private ACL) until the scanner marks them clean; serving happens from a cookie-less CDN domain so a stored HTML/SVG can never ride your app's session cookies.

## Code Examples

### Streaming proxy upload (NestJS + multer memory-safe limits)

```typescript
// uploads/proxy-uploads.controller.ts
import { BadRequestException, Controller, Post, UploadedFile, UseInterceptors } from '@nestjs/common';
import { FileInterceptor } from '@nestjs/platform-express';
import { createReadStream } from 'node:fs';

const MAX_BYTES = 25 * 1024 * 1024; // 25 MB
const ALLOWED = new Map([
  ['image/png', 'png'], ['image/jpeg', 'jpg'], ['application/pdf', 'pdf'],
]);

@Controller('attachments')
export class ProxyUploadsController {
  constructor(private readonly storage: StorageService, private readonly sniff: SniffService) {}

  @Post()
  @UseInterceptors(FileInterceptor('file', {
    limits: { fileSize: MAX_BYTES },        // hard cap inside the parser
    // storage: DiskStorage with streaming sink in real code — never default memory for big files
  }))
  async upload(@UploadedFile() file: Express.Multer.File, /* @CurrentUser() user */) {
    if (!file) throw new BadRequestException('file part missing');

    // 1) MIME sniffing — trust bytes, not headers
    const sniffed = await this.sniff.magicBytes(file.path);
    const ext = ALLOWED.get(sniffed);
    if (!ext) throw new BadRequestException(`unsupported type ${sniffed}`);

    // 2) Filename sanitization — we generate the key, original name is metadata ONLY
    const key = `q/${crypto.randomUUID()}.${ext}`;               // quarantine prefix
    await this.storage.putStream(createReadStream(file.path), key, {
      contentLength: file.size,                                  // assert ≤ cap again
      metadata: { originalName: sanitizeName(file.originalname) },
    });

    // 3) Row + scan job; object is NOT public yet
    const record = await this.uploads.create({
      key, bytes: file.size, mimeSniffed: sniffed, status: 'scanning',
      originalName: sanitizeName(file.originalname),
    });
    await this.scanQueue.enqueue({ uploadId: record.id });
    return { id: record.id, status: record.status };
  }
}

function sanitizeName(name: string): string {
  return name.replace(/[^\w.\- ]+/g, '_').slice(0, 180);         // strip traversal/control chars
}
```

### Presigned URL issuance + completion (AWS SDK v3)

```typescript
// uploads/presign.service.ts
import { S3Client, PutObjectCommand, HeadObjectCommand } from '@aws-sdk/client-s3';
import { getSignedUrl } from '@aws-sdk/s3-request-presigner';
import { createHash } from 'node:crypto';

@Injectable()
export class PresignService {
  private s3 = new S3Client({});
  private static TTL_SECONDS = 900;
  private static MAX_BYTES = 2 * 1024 * 1024 * 1024;

  async issue(input: { name: string; size: number; mime: string }) {
    const ext = extensionFor(input.mime);
    const key = `u/${new Date().toISOString().slice(0, 10)}/${crypto.randomUUID()}.${ext}`;
    if (input.size > PresignService.MAX_BYTES) throw new BadRequestException413();

    const cmd = new PutObjectCommand({
      Bucket: BUCKET, Key: key,
      ContentType: input.mime,                                    // advisory; sniffed again later
      ChecksumSHA256: undefined,                                  // client may set via header
    });
    const putUrl = await getSignedUrl(this.s3, cmd, {
      expiresIn: PresignService.TTL_SECONDS,
    });

    const upload = await this.repo.createPending({ key, declaredSize: input.size, declaredMime: input.mime });
    return { id: upload.id, key, putUrl, method: 'PUT', expiresInSeconds: PresignService.TTL_SECONDS };
  }

  /** Idempotent completion — safe to retry */
  async complete(uploadId: string, expectedChecksum?: string) {
    const rec = await this.repo.mustFind(uploadId);
    if (rec.status === 'published' || rec.status === 'scanning') return rec;

    const head = await this.s3.send(new HeadObjectCommand({ Bucket: BUCKET, Key: rec.key }));
    if ((head.ContentLength ?? 0) !== rec.declaredSize) {
      await this.repo.fail(rec.id, 'size-mismatch');
      throw new ConflictException('declared size does not match uploaded object');
    }
    if (expectedChecksum && head.ChecksumSHA256 &&
        head.ChecksumSHA256 !== b64(expectedChecksum)) {
      await this.repo.fail(rec.id, 'checksum-mismatch');
      throw new UnprocessableEntityException('checksum mismatch');
    }
    return this.repo.markScanning(rec.id);                        // gate before publish
  }
}
function extensionFor(mime: string): string { /* map allow-listed mime → ext */ return 'bin'; }
function b64(hex: string): string { return createHash('sha256').update(hex).digest('base64'); }
```

### Resumable chunk endpoint with Content-Range

```typescript
@Put('uploads/:id/chunks')
async chunk(
  @Param('id') id: string,
  @Headers('content-range') contentRange: string,   // "bytes START-END/TOTAL"
  @Req() req: Request,
) {
  const m = /^bytes (\d+)-(\d+)\/(\d+)$/.exec(contentRange ?? '');
  if (!m) throw new BadRequestException('invalid Content-Range');
  const [, startS, endS, totalS] = m.map(Number) as unknown as number[];

  const rec = await this.uploads.mustFind(id);
  if (startS !== rec.receivedBytes) return { receivedBytes: rec.receivedBytes }; // client resyncs

  await pipeline(req, this.storage.appendStream(rec.key, startS)); // durable append at offset
  const received = endS + 1;
  await this.uploads.setReceived(id, received, totalS);

  if (received === totalS) await this.scanQueue.enqueue({ uploadId: id }); // last byte → scan
  return { receivedBytes: received };
}
```

### Scan gate + image post-processing hooks

```typescript
// workers/scan-and-process.worker.ts
export async function onUploaded({ uploadId }: { uploadId: string }) {
  const rec = await uploads.mustFind(uploadId);

  const verdict = await clamScan.stream(await storage.getStream(rec.key));
  if (!verdict.clean) {
    await storage.delete(rec.key);
    await uploads.mark(rec.id, 'rejected', { reason: 'malware' });
    await audit.emit('upload.rejected', { uploadId, verdict });
    return;
  }

  if (rec.mimeSniffed.startsWith('image/')) {
    const img = sharp(await storage.getBuffer(rec.key))
      .rotate()                                   // honor EXIF orientation
      .withoutExif();                             // strip GPS/camera PII
    await Promise.all([
      storage.put(img.clone().resize(256, 256).webp(), thumbKey(rec.key)),
      storage.put(img.clone().webp({ quality: 80 }), derivedKey(rec.key)),
    ]);
  }

  await storage.tagObject(rec.key, { scan: 'clean' });   // publish gate flips here
  await uploads.mark(rec.id, 'published');
  await cdnQueue.enqueue({ key: rec.key });              // warm cache / invalidate
}
```

### Metadata sidecar table

```sql
CREATE TABLE uploads (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  owner_id      UUID NOT NULL REFERENCES users(id),
  key           TEXT NOT NULL UNIQUE,          -- storage path (random, no user input)
  original_name TEXT NOT NULL,                 -- sanitized display name
  mime_declared TEXT NOT NULL,
  mime_sniffed  TEXT,
  bytes         BIGINT NOT NULL CHECK (bytes >= 0),
  sha256        CHAR(64),
  status        TEXT NOT NULL DEFAULT 'pending'
                CHECK (status IN ('pending','receiving','scanning','published','rejected','failed')),
  reject_reason TEXT,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  published_at  TIMESTAMPTZ
);
CREATE INDEX uploads_owner_created_idx ON uploads (owner_id, created_at DESC);
CREATE UNIQUE INDEX uploads_pending_dedupe_idx ON uploads (owner_id, sha256)
  WHERE status = 'published';                   -- optional dedupe of identical blobs
```

## Real-World Use Cases

1. **Avatar/profile images** — Small proxy uploads with immediate sniffing; thumbnails generated synchronously (<300 ms) so the UI can show them right away.
2. **CSV/ERP bulk imports** — Direct-to-S3 presigned PUT of a 200 MB export, then an operation resource tracks parsing progress (pairs with long-running operations).
3. **Video platforms** — S3 multipart with per-part retries plus resumable offsets; each finished part triggers progressive transcode.
4. **Healthcare document intake** — Quarantine prefix until ClamAV + DLP pass; PHI stays in-region with SSE-KMS and access logged per read.
5. **Support ticket attachments** — Strict caps (10 MB), PDF/image allow-list only, served via short-lived signed GETs so URLs expire.

## Common Mistakes

| Mistake | Fix |
| -------------------------------------------------- | -------------------------------------------------------------------------------------- |
| Trusting `Content-Type`/extension | Sniff magic bytes server-side; allow-list |
| Using client `filename` in the storage path | Generate random keys; keep original name as sanitized metadata |
| No size limit until multer's default | Cap at proxy (`client_max_body_size`), framework (`limits.fileSize`), and policy check |
| Buffering whole file in RAM (`memoryStorage`) | Stream to disk/object store; constant memory under load |
| Public-write buckets or wildcard presign (`key=*`) | Scope every signature to one key + short TTL |
| Publishing before virus scan completes | Quarantine prefix/tag-gated publish; flip only after clean verdict |
| Serving uploads from the app's cookie domain | Serve from a separate CDN domain; `Content-Disposition: attachment` for user content |
| Inline synchronous AV scan blocking the request | Async scan worker + `202`/status field; request returns after receipt |
| Ignoring EXIF (orientation, GPS) | Rotate per EXIF then strip metadata on publish |

## Best Practices

1. **Choose by size, not fashion** — ≤ ~20 MB proxy multipart; above that presigned direct; unreliable networks add resumability.
2. **Validate three times** — declared metadata at issuance, actual bytes at completion (head + checksum), and content sniffing before publish.
3. **Random keys everywhere** — UUIDv4 paths prevent enumeration and collisions; never derive keys from usernames/timestamps alone.
4. **Quarantine → scan → publish** as an explicit state machine persisted in the sidecar table.
5. **Short-lived signatures** (5–15 min) and one-time use where possible; log issuance with actor identity for audit.
6. **Checksums end-to-end** — accept client SHA-256, verify against S3's computed checksum at completion.
7. **Lifecycle rules** — abort incomplete multipart uploads after 7 days; expire quarantined rejects; tier old objects to infrequent access.
8. **Idempotent completion** — completing twice must not double-publish or double-enqueue scans.
9. **Observability** — metrics for bytes in/out, scan verdict rates, presign→complete conversion, and time-to-first-byte of uploads.
10. **Document limits in OpenAPI** — max bytes, allowed MIME list, required headers; return `413`/`415` with machine-readable codes.

## Performance Considerations

- Direct-to-S3 removes the API from the data path — API cost scales with *number* of uploads, not *size*.
- Parallel multipart parts (8–16 concurrent) saturate consumer links; tune part size ≈ 8–64 MB so retries are cheap.
- Streaming transforms (sharp pipelines, gzip) should run on workers near the storage region, not on API pods.
- Signed GETs are cheap but not free at high QPS — front the CDN with longer-TTL signed cookies/URLs for hot assets.
- Watch GIN-free metadata queries: the sidecar table needs indexes on `(owner_id, created_at)` and `status` for cleanup jobs.

## Summary

- Two flows: proxy multipart for small files, presigned direct-to-S3 for large ones; resumable offsets for hostile networks.
- The API is the control plane: policy, signatures, metadata, and gates — never a dumb byte pipe.
- Security gates are sequential: size → sniff → sanitize → quarantine → scan → publish; each state persists in a sidecar table.
- Post-processing (thumbnails, transcodes, EXIF strip) hangs off upload-complete events asynchronously.
- Limits and error codes (413, 415, 409 on mismatch) are part of the contract; document them.

# PostgreSQL Window Functions

>
> **Why it matters:** Window functions are one of the most tested SQL topics in senior interviews. They demonstrate you can write complex analytical queries that go beyond simple aggregations.

## Definition

A window function performs a calculation across a set of table rows that are somehow related to the current row. Unlike aggregate functions, window functions do not collapse rows — they return a value for each row.

```sql
-- Aggregate: collapses rows
SELECT department, AVG(salary) FROM employees GROUP BY department;
-- Returns 1 row per department

-- Window function: preserves rows
SELECT name, department, salary, AVG(salary) OVER (PARTITION BY department) FROM employees;
-- Returns ALL rows, with AVG added to each
```

## First Principles

Running totals, rankings, moving averages are all one primitive, derivable from what GROUP BY cannot do:

1. **Aggregate-without-collapsing requires a new kind of function.** GROUP BY destroys rows to make one output row per group; but "share of total per row" needs every row *kept* and a computation over its peers. Window functions are that: a partition-wise computation exposed alongside each row.
2. **Partition + order + frame = the whole grammar.** PARTITION BY defines the peer group, ORDER BY sequences within it, the frame clause bounds which rows contribute (running vs moving). Every window need decomposes into these three choices — memorizing functions is unnecessary once the grammar is held.
3. **They execute after joins/where/having, before ORDER BY** — which is why you can't filter windows in WHERE and why the subquery-with-window-outer-filter pattern exists.

## Why Do We Need It?

| Problem | Solution |
| ---------------------------- | ----------------------------------------------------------------- |
| **Rank employees by salary** | ROW_NUMBER, RANK, DENSE_RANK |
| **Compare to previous row** | LAG, LEAD |
| **Running total** | SUM OVER (ORDER BY date ROWS UNBOUNDED PRECEDING) |
| **Moving average** | AVG OVER (ORDER BY date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW) |
| **Percent of total** | SUM(salary) / SUM(SUM(salary)) OVER () |
| **Top N per group** | ROW_NUMBER() OVER (PARTITION BY group ORDER BY value DESC) |

## How It Works

### Window Function Syntax

```text
FUNCTION() OVER (
    PARTITION BY column -- Optional: divide rows into groups
    ORDER BY column -- Optional: define row order within partition
    FRAME_clause -- Optional: define which rows in the window
)

FRAME_clause:
    ROWS BETWEEN frame_start AND frame_end
    RANGE BETWEEN frame_start AND frame_end

frame_start/frame_end:
    UNBOUNDED PRECEDING -- First row of partition
    N PRECEDING -- N rows before current
    CURRENT ROW -- Current row
    N FOLLOWING -- N rows after current
    UNBOUNDED FOLLOWING -- Last row of partition
```

### Ranking Functions

```sql
-- Sample data
CREATE TABLE employees (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100),
    department VARCHAR(50),
    salary INT,
    hire_date DATE
);

INSERT INTO employees (name, department, salary, hire_date) VALUES
('Alice', 'Engineering', 120000, '2020-01-15'),
('Bob', 'Engineering', 110000, '2021-03-20'),
('Charlie', 'Engineering', 130000, '2019-06-10'),
('Diana', 'Marketing', 95000, '2020-08-01'),
('Eve', 'Marketing', 105000, '2021-01-15'),
('Frank', 'Sales', 85000, '2020-11-20'),
('Grace', 'Sales', 90000, '2019-04-05'),
('Henry', 'Sales', 85000, '2021-06-01');

-- ROW_NUMBER: Unique sequential number (no ties)
SELECT name, department, salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) as row_num
FROM employees;

-- Result:
-- Charlie | Engineering | 130000 | 1
-- Alice | Engineering | 120000 | 2
-- Bob | Engineering | 110000 | 3
-- Eve | Marketing | 105000 | 4
-- Diana | Marketing | 95000 | 5
-- Grace | Sales | 90000 | 6
-- Frank | Sales | 85000 | 7
-- Henry | Sales | 85000 | 8

-- RANK: Ties get same rank, gaps in sequence
SELECT name, department, salary,
    RANK() OVER (ORDER BY salary DESC) as rank
FROM employees;

-- Result:
-- Charlie | 130000 | 1
-- Alice | 120000 | 2
-- Bob | 110000 | 3
-- Eve | 105000 | 4
-- Diana | 95000 | 5
-- Grace | 90000 | 6
-- Frank | 85000 | 7 ← Tie!
-- Henry | 85000 | 7 ← Same rank

-- DENSE_RANK: Ties get same rank, no gaps
SELECT name, department, salary,
    DENSE_RANK() OVER (ORDER BY salary DESC) as dense_rank
FROM employees;

-- Result:
-- Charlie | 130000 | 1
-- Alice | 120000 | 2
-- Bob | 110000 | 3
-- Eve | 105000 | 4
-- Diana | 95000 | 5
-- Grace | 90000 | 6
-- Frank | 85000 | 7 ← Tie!
-- Henry | 85000 | 7 ← Same rank (no gap)
```

### PARTITION BY (Grouping Within Windows)

```sql
-- Top 2 earners per department
SELECT name, department, salary,
    ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) as rank_in_dept
FROM employees
WHERE ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) <= 2;

-- Better approach with CTE:
WITH ranked AS (
    SELECT name, department, salary,
        ROW_NUMBER() OVER (PARTITION BY department ORDER BY salary DESC) as rank_in_dept
    FROM employees
)
SELECT * FROM ranked WHERE rank_in_dept <= 2;

-- Result:
-- Charlie | Engineering | 130000 | 1
-- Alice | Engineering | 120000 | 2
-- Eve | Marketing | 105000 | 1
-- Diana | Marketing | 95000 | 2
-- Grace | Sales | 90000 | 1
-- Frank | Sales | 85000 | 2
```

### Navigation Functions (LAG/LEAD)

```sql
-- Compare salary to previous employee (by hire date)
SELECT name, department, salary, hire_date,
    LAG(salary, 1) OVER (ORDER BY hire_date) as prev_salary,
    LEAD(salary, 1) OVER (ORDER BY hire_date) as next_salary
FROM employees;

-- Result:
-- Alice | 120000 | 2020-01-15 | NULL | 105000
-- Eve | 105000 | 2021-01-15 | 120000 | 110000
-- Bob | 110000 | 2021-03-20 | 105000 | 90000
-- Grace | 90000 | 2019-04-05 | NULL | 130000
-- ...

-- Calculate salary difference from previous hire
SELECT name, salary, hire_date,
    salary - LAG(salary, 1) OVER (ORDER BY hire_date) as salary_diff
FROM employees;

-- Compare to previous employee in same department
SELECT name, department, salary,
    LAG(salary, 1) OVER (PARTITION BY department ORDER BY hire_date) as prev_dept_salary
FROM employees;
```

### Aggregate Window Functions

```sql
-- Running total of salary by hire date
SELECT name, salary, hire_date,
    SUM(salary) OVER (ORDER BY hire_date ROWS UNBOUNDED PRECEDING) as running_total
FROM employees;

-- Result:
-- Alice | 120000 | 2020-01-15 | 120000
-- Eve | 105000 | 2021-01-15 | 225000
-- Bob | 110000 | 2021-03-20 | 335000
-- ...

-- Moving average (3-row window)
SELECT name, salary, hire_date,
    AVG(salary) OVER (ORDER BY hire_date ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING) as moving_avg
FROM employees;

-- Salary as percentage of department total
SELECT name, department, salary,
    ROUND(salary * 100.0 / SUM(salary) OVER (PARTITION BY department), 2) as pct_of_dept
FROM employees;

-- Result:
-- Alice | Engineering | 120000 | 34.29
-- Bob | Engineering | 110000 | 31.43
-- Charlie | Engineering | 130000 | 37.14
-- ...

-- Cumulative count
SELECT name, hire_date,
    COUNT(*) OVER (ORDER BY hire_date ROWS UNBOUNDED PRECEDING) as cumulative_count
FROM employees;
```

### FIRST_VALUE, LAST_VALUE, NTH_VALUE

```sql
-- Get highest salary in each department
SELECT name, department, salary,
    FIRST_VALUE(salary) OVER (PARTITION BY department ORDER BY salary DESC) as highest_salary
FROM employees;

-- Get lowest salary in each department
SELECT name, department, salary,
    LAST_VALUE(salary) OVER (
        PARTITION BY department
        ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) as lowest_salary
FROM employees;

-- Get 2nd highest salary in each department
SELECT name, department, salary,
    NTH_VALUE(salary, 2) OVER (
        PARTITION BY department
        ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) as second_highest
FROM employees;
```

## Code Examples

### 1. Top N Per Group (Common Interview Question)

```sql
-- Find top 3 earners in each department
WITH ranked AS (
    SELECT
        name,
        department,
        salary,
        ROW_NUMBER() OVER (
            PARTITION BY department
            ORDER BY salary DESC
        ) as rn
    FROM employees
)
SELECT name, department, salary, rn
FROM ranked
WHERE rn <= 3
ORDER BY department, rn;
```

### 2. Running Total and Moving Average

```sql
-- Daily sales with running total and 7-day moving average
SELECT
    date,
    sales,
    SUM(sales) OVER (ORDER BY date ROWS UNBOUNDED PRECEDING) as running_total,
    AVG(sales) OVER (
        ORDER BY date
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) as moving_avg_7day
FROM daily_sales
ORDER BY date;
```

### 3. Year-over-Year Comparison

```sql
-- Compare each month's revenue to previous month
SELECT
    month,
    revenue,
    LAG(revenue, 1) OVER (ORDER BY month) as prev_month,
    revenue - LAG(revenue, 1) OVER (ORDER BY month) as month_over_month,
    ROUND(
        (revenue - LAG(revenue, 1) OVER (ORDER BY month)) * 100.0 /
        NULLIF(LAG(revenue, 1) OVER (ORDER BY month), 0),
        2
    ) as pct_change
FROM monthly_revenue
ORDER BY month;
```

### 4. Percentile and Distribution

```sql
-- Calculate salary percentiles
SELECT
    name,
    department,
    salary,
    NTILE(4) OVER (ORDER BY salary) as quartile,
    PERCENT_RANK() OVER (ORDER BY salary) as percentile_rank,
    CUME_DIST() OVER (ORDER BY salary) as cumulative_distribution
FROM employees;

-- NTILE: Divides rows into N equal groups
-- PERCENT_RANK: (rank - 1) / (total_rows - 1)
-- CUME_DIST: rank / total_rows
```

### 5. Gap and Island Analysis

```sql
-- Find consecutive date ranges (islands)
WITH daily_data AS (
    SELECT DISTINCT date::date as day FROM events
),
grouped AS (
    SELECT
        day,
        day - INTERVAL '1 day' * ROW_NUMBER() OVER (ORDER BY day) as grp
    FROM daily_data
)
SELECT
    MIN(day) as start_date,
    MAX(day) as end_date,
    COUNT(*) as consecutive_days
FROM grouped
GROUP BY grp
ORDER BY start_date;
```

### 6. Session Analysis

```sql
-- Identify user sessions (gap > 30 minutes = new session)
WITH events_with_lag AS (
    SELECT
        user_id,
        event_time,
        LAG(event_time) OVER (PARTITION BY user_id ORDER BY event_time) as prev_event
    FROM user_events
),
session_boundaries AS (
    SELECT
        user_id,
        event_time,
        CASE
            WHEN prev_event IS NULL THEN 1
            WHEN event_time - prev_event > INTERVAL '30 minutes' THEN 1
            ELSE 0
        END as new_session
    FROM events_with_lag
)
SELECT
    user_id,
    MIN(event_time) as session_start,
    MAX(event_time) as session_end,
    COUNT(*) as events_in_session
FROM session_boundaries
GROUP BY user_id, SUM(new_session) OVER (PARTITION BY user_id ORDER BY event_time)
ORDER BY user_id, session_start;
```

## Common Mistakes

### 1. Using WHERE Instead of QUALIFY

```sql
-- Bad: Can't filter on window function in WHERE
SELECT name, salary,
    ROW_NUMBER() OVER (ORDER BY salary DESC) as rn
FROM employees
WHERE rn <= 3; -- ERROR!

-- Good: Use CTE or subquery
WITH ranked AS (
    SELECT name, salary,
        ROW_NUMBER() OVER (ORDER BY salary DESC) as rn
    FROM employees
)
SELECT * FROM ranked WHERE rn <= 3;
```

### 2. Forgetting Frame Clause

```sql
-- Bad: LAST_VALUE without frame gives wrong result
SELECT name, salary,
    LAST_VALUE(salary) OVER (ORDER BY salary DESC) as last_val
FROM employees;
-- Returns CURRENT ROW only (default frame is RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)

-- Good: Specify frame explicitly
SELECT name, salary,
    LAST_VALUE(salary) OVER (
        ORDER BY salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) as last_val
FROM employees;
```

### 3. Mixing Aggregate and Window Functions

```sql
-- Bad: Can't use aggregate in WHERE after GROUP BY
SELECT department, AVG(salary)
FROM employees
GROUP BY department
HAVING AVG(salary) > 100000; -- This works

-- But window functions can't be used in WHERE
SELECT name, salary,
    AVG(salary) OVER () as avg_salary
FROM employees
WHERE salary > avg_salary; -- ERROR!
```

## Performance Considerations

| Operation | Complexity | Notes |
| ----------------- | ---------- | ----------------- |
| ROW_NUMBER | O(N log N) | Sort required |
| RANK / DENSE_RANK | O(N log N) | Sort required |
| LAG / LEAD | O(N) | Sequential access |
| SUM / AVG | O(N) | Sequential access |
| NTILE | O(N log N) | Sort required |

### Indexing for Window Functions

```sql
-- Index for ORDER BY in window function
CREATE INDEX idx_employees_salary ON employees(salary);
CREATE INDEX idx_employees_hire_date ON employees(hire_date);
CREATE INDEX idx_employees_dept_salary ON employees(department, salary);

-- Composite index for PARTITION BY + ORDER BY
CREATE INDEX idx_employees_dept_salary ON employees(department, salary DESC);
```

## Summary

| Function | Use Case | Returns |
| ------------- | ------------------------------- | ----------------------- |
| ROW_NUMBER | Unique ranking | 1, 2, 3, 4, ... |
| RANK | Ranking with ties | 1, 2, 2, 4, ... |
| DENSE_RANK | Ranking without gaps | 1, 2, 2, 3, ... |
| LAG | Previous row value | Value from N rows back |
| LEAD | Next row value | Value from N rows ahead |
| SUM/AVG/COUNT | Running totals, moving averages | Aggregated value |
| FIRST_VALUE | First row in window | Value |
| LAST_VALUE | Last row in window | Value |
| NTH_VALUE | Nth row in window | Value |
| NTILE | Divide into N groups | Group number (1-N) |
| PERCENT_RANK | Percentile rank | 0.0 to 1.0 |
| CUME_DIST | Cumulative distribution | 0.0 to 1.0 |

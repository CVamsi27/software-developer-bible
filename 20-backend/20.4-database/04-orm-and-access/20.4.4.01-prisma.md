# Prisma ORM

A TypeScript endpoint can compile while production rejects a write: the generated client and the database enforce separate contracts, and concurrent writers test a third. Follow one model from schema to query to see where each guarantee comes from.

## Definition

Prisma supplies a schema/model contract, client tooling and database access APIs. An ORM call translates application values into database operations; it does not replace the database's constraints, query planner or concurrency rules.

> **Textbook Definition:** Prisma is a database toolkit that derives typed application access from a declared model and coordinates schema migrations. Its client operations execute under the database's constraint, transaction and concurrency rules.

## First Principles

1. **Application objects and database rows have different contracts.** Generated types catch many mismatched queries, while the database enforces constraints against all writers. Neither validates an untrusted HTTP body automatically.
2. **A change has two consumers.** The database needs reviewed DDL; the application needs a client generated for the compatible schema/API. Generating the client does not apply the migration.
3. **The database executes the final operation.** Indexes, joins, locks and isolation still determine cost and correctness. Inspect emitted SQL and test concurrent behavior instead of inferring it from an API name.
4. **An API example needs a version.** A valid client call in one major version may not exist in another. Pin CLI/client together and follow documentation for that major.

## How It Works


### 1. Choose the version contract before copying code

The executable examples in this chapter and [Prisma Advanced](20.4.4.02-prisma-advanced.md) use **Prisma CLI and Client 7.10.0 with PostgreSQL**, the `prisma-client` generator and the `pg` driver adapter. As of 12 October 2026, Prisma's official [release-status page](https://www.prisma.io/docs/orm/release-status) still labels Prisma ORM 8 a release candidate; v7 is the current stable line. Use the stable, supported client contract for these examples, then recheck release status before upgrading.

Prisma ORM 7 requires a driver adapter for the application client, moves the database URL to `prisma.config.ts`, and uses the `prisma-client` generator with an explicit output path. Prisma ORM 8 is a distinct, still-changing contract with a different runtime and query API; do not mix its examples with the v7 schema and client below.

```text
schema.prisma ──generate──→ typed PrismaClient ──pg adapter──→ PostgreSQL
      │                         │                               │
prisma.config.ts        migration SQL                  planner + locks + constraints
```

The adapter passes connection work to the `pg` driver, so its pool limits and timeouts are part of the application's capacity plan. Database portability is limited by the provider's actual features: PostgreSQL arrays, UUID types or locking SQL do not become portable merely because CRUD uses an ORM.

### 2. Generate one client from a complete schema

Use this small schema for the chapter examples. Related models and indexed fields are defined explicitly; no preview features or PostgreSQL extensions are needed for client-generated `uuid()` IDs.

```prisma
// prisma/schema.prisma — Prisma ORM 7.10.0, PostgreSQL
generator client {
  provider = "prisma-client"
  output   = "../src/generated/prisma"
}

datasource db {
  provider = "postgresql"
}

model User {
  id        String   @id @default(uuid()) @db.Uuid
  email     String   @unique
  name      String?
  posts     Post[]
  profile   Profile?
  createdAt DateTime @default(now()) @map("created_at")
  @@map("users")
}

model Post {
  id        String   @id @default(uuid()) @db.Uuid
  title     String
  content   String?  @db.Text
  published Boolean  @default(false)
  authorId  String   @db.Uuid @map("author_id")
  author    User     @relation(fields: [authorId], references: [id])
  tags      String[] @default([])
  metadata  Json     @default("{}")
  createdAt DateTime @default(now()) @map("created_at")
  @@index([authorId])
  @@index([published, createdAt, id])
  @@map("posts")
}

model Profile {
  id     String  @id @default(uuid()) @db.Uuid
  bio    String? @db.Text
  userId String  @unique @db.Uuid @map("user_id")
  user   User    @relation(fields: [userId], references: [id])
  @@map("profiles")
}

model Account {
  id           String @id @default(uuid()) @db.Uuid
  tenantId     String @db.Uuid @map("tenant_id")
  balanceCents BigInt @default(0) @map("balance_cents")
  version      Int    @default(0)
  @@index([tenantId])
  @@map("accounts")
}

model Product {
  id       String @id @default(uuid()) @db.Uuid
  tenantId String @db.Uuid @map("tenant_id")
  stock    Int    @default(0)
  @@index([tenantId])
  @@map("products")
}

model OutboxEvent {
  id            String   @id @default(uuid()) @db.Uuid
  tenantId      String   @db.Uuid @map("tenant_id")
  aggregateId   String   @db.Uuid @map("aggregate_id")
  eventType     String   @map("event_type")
  schemaVersion Int      @default(1) @map("schema_version")
  payload       Json
  createdAt     DateTime @default(now()) @db.Timestamptz(3) @map("created_at")
  @@index([tenantId, aggregateId, createdAt])
  @@map("outbox_events")
}

model Appointment {
  id          String   @id @default(uuid()) @db.Uuid
  tenantId    String   @db.Uuid @map("tenant_id")
  patientId   String   @db.Uuid @map("patient_id")
  doctorId    String   @db.Uuid @map("doctor_id")
  scheduledAt DateTime @db.Timestamptz(3) @map("scheduled_at")
  @@index([tenantId, scheduledAt])
  @@map("appointments")
}
```

`prisma-client` generates TypeScript into the configured `output`; application imports below use that generated module. `prisma.config.ts` owns the CLI connection URL in Prisma 7:

```typescript
// prisma.config.ts
import 'dotenv/config';
import { defineConfig, env } from 'prisma/config';

export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: { path: 'prisma/migrations' },
  datasource: { url: env('DATABASE_URL') },
});
```

The index on a foreign-key field is a workload decision, not automatically created by PostgreSQL's foreign key. `uuid()` is a Prisma-side default; raw database writers must provide an ID or use an explicit database default. A Prisma JSON type does not establish the business schema of arbitrary JSON values.

For an isolated learning database:

```bash
npm install --save-exact @prisma/client@7.10.0 @prisma/adapter-pg@7.10.0 pg dotenv
npm install --save-dev --save-exact prisma@7.10.0
npx prisma@7.10.0 validate
npx prisma@7.10.0 migrate dev --name initial --create-only
# Review/edit the generated migration SQL, then apply in development:
npx prisma@7.10.0 migrate dev
npx prisma@7.10.0 generate
```

Add database invariants to the reviewed migration:

```sql
ALTER TABLE accounts ADD CONSTRAINT accounts_nonnegative CHECK (balance_cents >= 0);
ALTER TABLE products ADD CONSTRAINT products_nonnegative CHECK (stock >= 0);
```

For deployment, use `migrate deploy` on reviewed migration history. It does not generate your client or perform the development shadow-database workflow. `db push` changes the database without creating migration history; keep it for deliberate prototyping. Studio is a data browser that needs appropriate access, not a production authorization layer.

### 3. Shape one write and its returned fields

Create `client.ts` once per long-running application process and close the client during the owned shutdown lifecycle, rather than connecting/disconnecting after each request. Prisma 7 needs the driver adapter at construction. This sample sets a per-process pool limit and a bounded connection wait; choose `max` from the total database connection budget across every app and worker replica:

```typescript
// src/client.ts — Prisma ORM 7.10 with node-postgres
import 'dotenv/config';
import { PrismaClient } from './generated/prisma/client';
import { PrismaPg } from '@prisma/adapter-pg';

const connectionString = process.env.DATABASE_URL;
if (!connectionString) throw new Error('DATABASE_URL is required');

const adapter = new PrismaPg({
  connectionString,
  max: 5,
  connectionTimeoutMillis: 5_000,
});
export const prisma = new PrismaClient({ adapter });
```

A nested write groups related records atomically; `select` chooses the returned projection:

```typescript
import { prisma } from './client';

export async function createAuthor(email: string, name: string) {
  return prisma.user.create({
    data: {
      email, name,
      profile: { create: { bio: 'New author' } },
      posts: { create: [{ title: 'First draft' }] },
    },
    select: { id: true, email: true, posts: { select: { id: true, title: true } } },
  });
}
```

Validate request input before calling this function. A pre-check for duplicate email cannot replace the unique constraint under concurrency; handle the resulting `P2002` conflict deliberately. `update`/`delete` can fail when the record is absent, and deleting this author's related records needs an explicit referential-action or transaction policy. `upsert` can express create-or-update, but its concurrency behavior depends on whether the operation can become a database-native upsert; test conflicts.

### 4. Page a relation with deterministic ordering

```typescript
import { prisma } from './client';

export async function publishedPage(afterId?: string, size = 20) {
  if (!Number.isSafeInteger(size) || size < 1 || size > 100) {
    throw new RangeError('Invalid page size');
  }
  return prisma.post.findMany({
    where: { published: true },
    orderBy: [{ createdAt: 'asc' }, { id: 'asc' }],
    ...(afterId ? { cursor: { id: afterId }, skip: 1 } : {}),
    take: size,
    select: { id: true, title: true, createdAt: true, author: { select: { name: true } } },
  });
}
```

The ID cursor is unique, while the timestamp-plus-ID order breaks ties. `skip: 1` excludes the cursor row. Define what a deleted/missing cursor and concurrent inserts mean for the API; cursor pagination alone does not give a snapshot across requests. Offset pagination remains useful for small bounded pages, but large offsets need more work.

An `include` relation does not itself prove a single SQL statement or rule out N+1 behavior in surrounding application code. Prisma 7's `relationJoins` strategy remains preview-gated; query count and join strategy depend on the generated operation and configuration. The automatic dataloader batches certain `findUnique` calls, not arbitrary `findMany` calls.
Inspect emitted SQL, selected fields and relation cardinality. Avoid loading every child simply to count or aggregate it.

### 5. Keep raw SQL parameterized and results honest

```typescript
import { prisma } from './client';

export async function authorPostCounts(email: string) {
  return prisma.$queryRaw<Array<{ id: string; post_count: bigint }>>`
    SELECT u.id, COUNT(p.id) AS post_count
    FROM users AS u LEFT JOIN posts AS p ON p.author_id = u.id
    WHERE u.email = ${email}
    GROUP BY u.id
  `;
}
```

Tagged-template values are parameters here; table/column identifiers cannot be replaced with value parameters. Keep identifiers static or allowlisted. `$queryRaw<T>` describes the expected result to TypeScript; it does not validate returned rows. PostgreSQL `COUNT` is a bigint, and native JavaScript `JSON.stringify` needs an explicit conversion policy for bigint values.

Unsafe raw APIs can still bind separate value parameters, but building SQL by string concatenation is dangerous. Interpolating `Prisma.raw(untrustedText)` into an otherwise tagged template also defeats the protection. For important row contracts, validate results or test them against the real schema.

### 6. Move read-modify-write logic to its database boundary

A transaction makes its writes commit/rollback together; it does not automatically make a preceding application read safe from another transaction. Two transfers can both observe enough funds before either decrements. Use an atomic condition or appropriate locks/isolation, and let constraints reject invalid state.
The complete [transfer/stock examples](20.4.4.02-prisma-advanced.md) show the boundary rather than duplicating an unsafe check-then-decrement here.

For independent Prisma client operations, `$transaction([...])` executes them in sequence atomically. Dependent ID creation is usually a nested write or interactive callback. Inside the callback use `tx` for every participating query; calls on the root client use another transaction/connection.
Network calls and external effects are outside database rollback, so record an outbox event in the transaction instead.

### 7. Account for pool ownership and query cost

With the PostgreSQL adapter, `PrismaPg` uses `pg` pool options such as `max`, `connectionTimeoutMillis` and `idleTimeoutMillis`. In Prisma 7, `max` defaults to 10 and `connectionTimeoutMillis` to 0 (no timeout); these defaults differ from Prisma 6. A limit of five per process means up to 40 connections across eight replicas, before workers, migrations and administration are counted.
Review [connection pooling](../05-operations-and-scaling/20.4.5.01-connection-pooling.md) with the chosen runtime and adapter.

Use query logs in a controlled environment to inspect SQL and duration without leaking sensitive parameter values. Measure pool acquisition, database work and result shaping separately. Type-safe CRUD does not automatically create an appropriate index or choose a good execution plan.

## Summary

Pin the Prisma contract, generate the matching client and review migrations independently. Construct bounded projections and relations, parameterize raw values and test result shapes. Transactions group database effects, while constraints, conditional writes and isolation protect concurrent invariants; the ORM's types do not establish authorization or replace those mechanisms.

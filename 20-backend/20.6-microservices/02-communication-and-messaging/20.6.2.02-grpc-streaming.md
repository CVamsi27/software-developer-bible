# gRPC Streaming

A feed produces several values over time. Returning an ever-growing array delays the first result and retains all results in memory. A stream can send values incrementally, but must also define how a slow or disconnected reader stops production.

## Definition

**gRPC streaming** sends a sequence of messages within one RPC. Server streaming has one request and many responses; client streaming has many requests and one response; bidirectional streaming allows independent sequences in both directions. Unary RPC remains one request and one response.

> **Textbook Definition:** gRPC streaming exchanges ordered message sequences within a call through server, client or bidirectional streams. Flow control bounds transport pressure, while deadlines, cancellation and application buffering determine resource lifetime.

## First Principles

The producer and consumer can run at different rates. If the producer ignores pressure, application buffers grow even when HTTP/2 limits network flow. If a consumer leaves, continuing work wastes resources.
Streaming therefore needs bounded production, cooperative cancellation and an explicit terminal outcome.

Message order within one direction is defined; cross-direction interaction and reconnect replay are application contracts. Finishing the client's input does not necessarily finish the server's output.

## 1. Choose the shape from the interaction

| Shape | Example | Completion contract |
| ------------- | ---------------------------------- | --------------------------------------------------------------------- |
| Server stream | Read a finite page or watch a feed | Server ends with final status; a watch needs cancellation/deadline |
| Client stream | Submit a bounded batch | Client half-closes; server returns one result through the callback |
| Bidirectional | Exchange live control messages | Each direction can progress independently; define shutdown and errors |

A native Node client-streaming result is supplied through its callback, not by treating it as a server response `data` event. A server-streaming handler receives `ServerWritableStream`, not a duplex handler with arbitrary client input. Browser adapters may not support all native modes.

## 2. Stream a bounded range and release it on cancellation

Save this complete contract as `range.proto`:

```protobuf
syntax = "proto3";
package demo.v1;
service RangeService { rpc List (RangeRequest) returns (stream Item); }
message RangeRequest { uint32 count = 1; }
message Item { uint32 value = 1; }
```

This complete CommonJS module uses the same two Node packages as the unary chapter. It implements a finite server stream, observing writable backpressure and cancellation. Transport credentials are loopback-only and insecure for the local fixture.

```javascript
const grpc = require('@grpc/grpc-js');
const loader = require('@grpc/proto-loader');
const path = require('node:path');
const { once } = require('node:events');
const { setTimeout: delay } = require('node:timers/promises');
const definition = loader.loadSync(path.join(__dirname, 'range.proto'), { defaults: true });
const proto = grpc.loadPackageDefinition(definition).demo.v1;
async function localRangeService(observe = () => {}) {
  const server = new grpc.Server();
  server.addService(proto.RangeService.service, {
    list(call) {
      const controller = new AbortController();
      const stop = () => controller.abort();
      call.once('cancelled', stop);
      void (async () => {
        const count = call.request.count;
        if (!Number.isInteger(count) || count < 1 || count > 100) {
          throw Object.assign(new Error('count must be 1..100'), { code: grpc.status.INVALID_ARGUMENT });
        }
        for (let value = 0; value < count; value++) {
          await delay(5, undefined, { signal: controller.signal });
          if (controller.signal.aborted || call.cancelled) break;
          observe(value);
          if (!call.write({ value })) await once(call, 'drain', { signal: controller.signal });
        }
        if (!controller.signal.aborted) call.end();
      })().catch(error => {
        if (!controller.signal.aborted) call.emit('error', error);
      }).finally(() => { call.off('cancelled', stop); observe('released'); });
    },
  });
  const port = await new Promise((resolve, reject) => server.bindAsync(
    '127.0.0.1:0', grpc.ServerCredentials.createInsecure(),
    (error, port) => error ? reject(error) : resolve(port),
  ));
  const client = new proto.RangeService(`127.0.0.1:${port}`, grpc.credentials.createInsecure());
  return { server, client };
}
module.exports = { localRangeService };
```

A request for three emits 0, 1, 2 then completes. A request above 100 returns `INVALID_ARGUMENT`. A client cancellation interrupts the local delay/pressure wait and releases the producer.
This finite fixture does not implement authentication, reconnect/resume, a database feed or durability; test those contracts separately when replacing the source.

## 3. Transport flow control is not a complete buffer budget

A writable `false` tells this producer to pause until `drain`. It does not promise the peer has processed the item. An event source that cannot pause needs its own bounded queue and overflow policy: drop only where the domain permits, disconnect with a resumable cursor, or persist pending work.
Async event callbacks can run concurrently unless the application serializes them.

Clients consuming slowly must also bound local processing. Authorization belongs to the logical resource and can change during a watch; establish how revocation/credential expiry closes or rechecks the stream. Avoid trusting a client-supplied tenant/user field as identity.

## 4. Define reconnect and terminal outcomes

A failure after item 42 does not automatically resume at 43. If resumability is required, define a stable cursor, retained source, ordering and duplicate policy. Reauthorize on reconnect, apply jittered bounded retries and distinguish a completed finite range from a interrupted watch.
Replaying a command stream must not repeat external effects without idempotency.

A deadline or cancellation closes the RPC, but application work already committed remains committed. Stop source subscriptions, timers and downstream work cooperatively; monitor active streams, oldest lifetime, queue bytes and cancellation cleanup. Decide whether an idle stream should be closed independently of its total lifetime.

## Summary

Streaming sends ordered sequences within a call. Choose its direction from the interaction, honor application and transport pressure, and release source work on termination. Resume, authority changes and durable effects need explicit contracts beyond the transport.

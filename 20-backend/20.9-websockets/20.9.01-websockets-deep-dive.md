# WebSockets — Connection Lifecycle, Scaling, Rooms, Namespaces

## WebSocket Protocol
- **HTTP upgrade:** Client sends `Upgrade: websocket` header
- **Full-duplex:** Both client and server can send messages at any time
- **Persistent connection:** Stays open until explicitly closed
- **Binary or text:** Supports both `ws.send("text")` and `ws.send(buffer)`

## Connection Lifecycle
1. Client connects: `new WebSocket("ws://server")`
2. Server handles upgrade: `wss.on("connection", (ws) => {...})`
3. Bidirectional messaging
4. Client or server closes: `ws.close()` or `ws.terminate()`

## Socket.IO (most common in NestJS)
```typescript
// Server
@WebSocketGateway({ cors: { origin: "*" } })
export class ClinicGateway implements OnGatewayConnection {
  @WebSocketServer() server: Server;

  handleConnection(client: Socket) {
    const token = client.handshake.auth.token;
    const user = verifyJwt(token);
    client.join(`clinic:${user.clinicId}`);
  }

  @SubscribeMessage("appointment:update")
  handleAppointmentUpdate(@MessageBody() data: AppointmentUpdate) {
    this.server.to(`clinic:${data.clinicId}`).emit("appointment:changed", data);
  }
}
```

// Client
const socket = io("wss://api.docita.work", { auth: { token: jwt } });

## Scaling WebSockets
| Challenge | Solution |
|-----------|----------|
| Single server limit | Sticky sessions or Redis adapter |
| Room broadcast | Redis pub/sub between instances |
| Connection state | External store (Redis) |
| Load balancing | L4 (TCP) or L7 with session affinity |

### Redis Adapter (Socket.IO)
```typescript
// Server
import { createAdapter } from "@socket.io/redis-adapter";
import { createClient } from "redis";

const pubClient = createClient({ url: "redis://localhost:6379" });
const subClient = pubClient.duplicate();
io.adapter(createAdapter(pubClient, subClient));
```

## Failure Modes
| Failure | Handling |
|---------|----------|
| Client disconnect | Reconnect with exponential backoff |
| Server restart | Client reconnects, misses events → use event sourcing |
| Network partition | Fallback to polling |
| Message loss | Persist critical events in database |

## Interview Tips
- Explain WebSocket vs SSE vs polling
- Know Socket.IO rooms and namespaces
- Explain how to scale WebSockets across multiple instances
- Know the reconnection strategy (exponential backoff)

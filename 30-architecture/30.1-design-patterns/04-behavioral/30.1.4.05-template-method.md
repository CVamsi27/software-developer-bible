# Template Method Pattern

Two exporters must trim records before formatting them, but one produces JSON and another CSV. Copying the sequence into each class lets the ordering drift.

## Definition

The Template Method pattern puts a stable algorithm sequence in a base-class method and delegates selected steps to subclasses. The sequence stays under one owner; the overridden operations are its variation points.

> **Textbook Definition:** “Define the skeleton of an algorithm in an operation, deferring some steps to subclasses.” The GoF definition describes a base method that controls the order while subclasses supply selected operations without replacing that structure.

## First Principles

Keep invariant steps in the template and expose only deliberate variation points. Each step still needs a contract: its inputs, outputs, side effects and failure behavior must fit the sequence that calls it.

## Trace a JSON export

```typescript
abstract class Exporter {
  // Template method: subclasses are expected to preserve this sequence.
  export(records: readonly string[]): string {
    const normalized = records.map(record => record.trim());
    const output = this.format(normalized);
    this.afterExport(output);
    return output;
  }

  protected abstract format(records: readonly string[]): string;
  protected afterExport(_output: string): void {}
}

class JsonExporter extends Exporter {
  protected format(records: readonly string[]): string {
    return JSON.stringify(records);
  }
}

console.log(new JsonExporter().export([' first ', ' second ']));
// ["first","second"]
```

`export` trims each record, dispatches to the subclass's `format`, calls the optional hook and returns the result. `JsonExporter` supplies only formatting. If formatting throws, the success hook is not called. If the hook throws, the whole call fails despite having produced output; that behavior must be intentional.

```text
base: normalize → format → afterExport? → result
                  ↑           ↑
            required step   optional hook
```

A comment does not enforce the sequence. TypeScript has no `final` method modifier, and even a `protected` template method can be overridden by subclasses. If the sequence must not be replaceable, put it in a coordinator and inject the varying steps instead of relying on inheritance.

## Resource cleanup needs an explicit rule

A database export may add connect, extract, transform, load and disconnect steps. Once connected, use `try/finally` so cleanup runs on both success and failure. If cleanup also fails, a throw from `finally` can replace the original error; catch both failures and define whether to preserve the original, aggregate them or give cleanup precedence. If an asynchronous step affects success, make the template asynchronous and await it. A synchronous `void` hook cannot express that contract; document fire-and-forget notifications and their error handling separately.

The TypeScript checker requires a concrete subclass to implement abstract operations; that requirement is erased from emitted JavaScript. It does not prove that the implementation respects units, ownership or error semantics. Document those contracts and test representative subclasses against the base workflow.

## Composition is the alternative

Pass `format` and optional hooks into an ordinary coordinating function when you need to mix steps at runtime. This uses Strategy-like composition while keeping the same sequencing idea. It avoids an inheritance hierarchy but moves validation of compatible steps to the composition boundary.

Frameworks often own lifecycle sequencing, but not every callback API is an instance of GoF Template Method. Express middleware is principally an ordered chain; calling `next()` does not await downstream response completion. Test runners commonly use registered callbacks rather than user subclasses. React may invoke render work more than once, so its lifecycle must not be reduced to an unconditional single-pass template.

## Compare the variation

| Pattern | Variation point |
| --------------- | ----------------------------------------------------------------- |
| Template Method | Selected inherited steps inside a base sequence |
| Strategy | An interchangeable behavior supplied to a client |
| Factory Method | An overridable creation operation, which may be one template step |
| Builder | Incremental construction; a director may prescribe an order |

Factory Method can participate in a Template Method; it does not require an entire fixed algorithm. Builder does not guarantee that all step orders are legal.

## Common mistakes

- Overriding the whole template and bypassing its invariant steps.
- Adding hooks for every imaginable future variation. Each hook becomes a contract to maintain.
- Using no-op hooks to silently omit required validation or cleanup.
- Choosing inheritance solely to share a few unrelated utility methods.
- Assuming a new template step is automatically compatible with every subclass.

## Summary

Keep a genuinely shared sequence in one base algorithm and expose deliberate variation points. Trace failures as carefully as success, preserve resource cleanup and use composition when independently supplied steps fit better than inheritance.

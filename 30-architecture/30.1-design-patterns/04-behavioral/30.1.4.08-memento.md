# Memento Pattern


## Definition

Memento lets an object capture and restore its state while keeping representation details out of the code that manages history. The originator owns capture and restoration; the caretaker holds opaque snapshot tokens.

## First Principles

An undo manager needs to remember an editor's prior state, but should not know every private field. Let the editor produce a token that only it can restore. Capturing a mutable reference is insufficient: later edits would also change the supposed snapshot. Preserve the state through immutable values, intentional copies or persistent data structures.

## Follow one undo

```typescript
class Editor {
  #text = '';
  #snapshots = new WeakMap<object, string>();

  setText(text: string): void { this.#text = text; }
  getText(): string { return this.#text; }

  save(): object {
    const token = Object.freeze({});
    this.#snapshots.set(token, this.#text);
    return token;
  }

  restore(token: object): void {
    const text = this.#snapshots.get(token);
    if (text === undefined) throw new Error('Unknown snapshot');
    this.#text = text;
  }
}

const editor = new Editor();
const history: object[] = [];
editor.setText('first');
history.push(editor.save());
editor.setText('second');
editor.restore(history.pop()!);
console.log(editor.getText()); // first
```

The caretaker stores a token before the edit. The editor privately associates that token with the immutable string `first`. Restoration looks up the token; a token from another editor is rejected. WeakMap prevents the editor's lookup table from retaining tokens after their owners release them; the history array deliberately retains tokens that are still undoable.

```text
editor state → save → opaque token → caretaker history
editor state ← restore(token) ←──── caretaker chooses prior token
```

This example saves text only. A real editor must define whether selection, cursor, formatting and document version are part of the restored state. The token design is in-memory and cannot simply be serialized for another process.

## Redo and history limits

Before undoing, capture the current state into a redo stack. Restore the selected prior state and remove it from undo history. Redo performs the reverse. A fresh edit after undo normally clears redo because it creates a new history branch. Bound history by retained size as well as entry count; one large snapshot can outweigh thousands of small ones.

Immutable state can still support mementos: retain earlier immutable versions rather than deep-cloning everything. For mutable nested data, select a copy strategy compatible with its types. `structuredClone` handles many built-in data structures but does not preserve arbitrary class prototypes or private fields and cannot clone functions or DOM nodes. Serialization is a possible mechanism, not a requirement of Memento.

## Restoration is not distributed rollback

Restoring a local object does not undo an email, a payment or another user's concurrent edit. Define the boundary at which restoration is safe. Persistent snapshots need schema versions, runtime validation and migration rules. A checksum can detect some corruption; it is not authenticity protection against a malicious writer.

Editors may use inverse operations, persistent structures, snapshots or combinations; do not claim every editor uses full-state Memento. Jest snapshots are comparison fixtures, not restored hidden object state. Database savepoints use database transaction machinery rather than this object protocol. Git commits describe committed trees and metadata, excluding untracked files, and their contents are inspectable.

## Compare what is saved

| Pattern | Saved information |
| -------------- | ---------------------------------------------------------------- |
| Memento | A recoverable state representation |
| Command | A requested operation; optional inverse or prior state |
| Prototype | An object's copy for independently usable construction |
| Event sourcing | Accepted domain events from which authoritative state is derived |

Neither commands nor event logs are always smaller than snapshots. A patch is not automatically an executable Command, and replaying changes requires ordering, compatibility and effect rules.

## Summary

Let the originator define complete, safe capture and restoration, while the caretaker manages history through tokens. Trace snapshot ownership and aliasing, bound retained history and distinguish local restoration from external compensation.

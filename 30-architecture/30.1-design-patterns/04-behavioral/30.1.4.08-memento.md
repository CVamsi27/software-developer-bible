# Memento Pattern

A user presses Undo after editing a document. If the history manager copies the editor's private fields itself, every change to the editor's representation also changes the history code. Memento lets the editor create a restorable snapshot while history holds only a token:

```typescript
editor.setText('second');
editor.restore(undoHistory.pop()!); // back to 'first'
```

## Definition

**Memento** lets the state-owning object — the **originator** — capture and restore its state without exposing the representation to the **caretaker**. The caretaker manages the snapshot tokens and their order without inspecting their contents.

> **Textbook Definition:** "Without violating encapsulation, capture and externalize an object's internal state so that the object can be restored to this state later." — GoF intent, quoted in [*Java Design Patterns*](https://www.oreilly.com/library/view/java-design-patterns/9781484218020/9781484218013_Ch13.xhtml)

## First Principles

Without this boundary, history code must read and copy the editor's private fields. With it, the editor defines what to capture and how to restore it; history only retains and selects a token. That token must preserve a point-in-time state. If it aliases mutable nested data, later edits also change the supposed snapshot. Use immutable values, intentional copies, or persistent data structures.

## How It Works

### 1. Save an opaque token, restore from it

```typescript
class Editor {
  #text = '';
  #snapshots = new WeakMap<object, string>();

  setText(text: string): void { this.#text = text; }
  getText(): string { return this.#text; }

  save(): object {
    const token = Object.freeze({});
    this.#snapshots.set(token, this.#text);
    return token;
  }

  restore(token: object): void {
    const text = this.#snapshots.get(token);
    if (text === undefined) throw new Error('Unknown snapshot');
    this.#text = text;
  }
}

const editor = new Editor();
const undoHistory: object[] = [];
editor.setText('first');
undoHistory.push(editor.save());
editor.setText('second');
editor.restore(undoHistory.pop()!);
console.log(editor.getText()); // first
```

The caretaker stores a token before the edit. The editor privately associates that token with the immutable string `first`. Restoration looks up the token; a token from another editor is rejected. WeakMap keeps the editor's lookup table from retaining tokens after their owners release them; the history array deliberately retains tokens that are still undoable.

```text
editor state → save → opaque token → caretaker history
editor state ← restore(token) ←──── caretaker chooses prior token
```

This example saves text only. A real editor must define whether selection, cursor, formatting, and document version belong to the restored state. The token design is in-memory and cannot simply be serialized for another process.

### 2. Bound undo and redo history deliberately

Before undoing, capture the current state into a redo stack. Restore the selected prior state and remove it from undo history. Redo performs the reverse. A fresh edit after undo normally clears redo because it creates a new history branch. Bound history by retained size as well as entry count — one large snapshot can outweigh thousands of small ones.

Immutable state can still support mementos: retain earlier immutable versions rather than deep-cloning everything. For mutable nested data, select a copy strategy compatible with its types. [`structuredClone`](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm) handles many built-in data types but preserves no arbitrary class prototypes or private fields, and clones no functions or DOM nodes. Serialization is a possible mechanism, never a requirement of Memento.

### 3. Distinguish restoration from distributed rollback

Restoring a local object never undoes an email, a payment, or another user's concurrent edit. Define the boundary at which restoration is safe. Persistent snapshots need schema versions, runtime validation, and migration rules. A checksum can detect some corruption; it is not authenticity protection against a malicious writer.

Editors may use inverse operations, persistent structures, snapshots, or combinations — never claim every editor uses full-state Memento. Jest snapshots are comparison fixtures, not restored hidden object state. Database savepoints use database transaction machinery rather than this object protocol. Git commits describe committed trees and metadata, excluding untracked files, and their contents are inspectable.

### 4. Compare what is saved

| Pattern | Saved information |
| -------------- | ---------------------------------------------------------------- |
| Memento | A recoverable state representation |
| Command | A requested operation; optional inverse or prior state |
| Prototype | An object's copy for independently usable construction |
| Event sourcing | Accepted domain events from which authoritative state is derived |

Neither commands nor event logs are always smaller than snapshots. A patch is not automatically an executable Command, and replaying changes requires ordering, compatibility, and effect rules.

## Summary

Let the originator define complete, safe capture and restoration, while the caretaker manages history through tokens. Check who owns each snapshot and whether any references still point to mutable state. Limit the memory retained by history and distinguish local restoration from actions that compensate for external effects.

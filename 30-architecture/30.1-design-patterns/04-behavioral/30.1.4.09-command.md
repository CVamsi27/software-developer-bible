# Command Pattern


## Definition

Command represents an operation request as a value that an invoker can execute. It separates request creation from execution. Queuing, metadata and undo are possible extensions, not guarantees of every command.

> **Textbook Definition:** Command is a behavioral pattern that encapsulates an operation request and its required context as an object or value, separating the requester from the component that executes it.

## First Principles

A toolbar, shortcut and macro may all trigger the same operation. The receiver is the object that performs that operation; the invoker is the object that decides when to run the request. If each trigger knows how the receiver works, execution rules become scattered. Give each trigger a request value instead. The invoker can choose when to execute it and how to record the outcome. Delayed execution raises new questions: are the parameters captured now, who authorizes later and can the operation safely repeat?

## Trace an undoable command

```typescript
interface Command { execute(): void }
interface UndoableCommand extends Command { undo(): void }

class Light {
  on = false;
}

class SetLight implements UndoableCommand {
  private previous: boolean | undefined;
  constructor(private readonly light: Light, private readonly desired: boolean) {}

  execute(): void {
    if (this.previous !== undefined) throw new Error('Command already executed');
    this.previous = this.light.on;
    this.light.on = this.desired;
  }

  undo(): void {
    if (this.previous === undefined) throw new Error('Command not executed');
    this.light.on = this.previous;
    this.previous = undefined;
  }
}

const light = new Light();
const turnOn = new SetLight(light, true);
turnOn.execute();
console.log(light.on); // true
turnOn.undo();
console.log(light.on); // false
```

The client creates `SetLight` with the target and desired value. Execution captures the preceding value, then applies the change. Undo restores that captured value rather than assuming the inverse of "on" is always the original state. The guards allow redo after undo but reject another execution without undo.

```text
client creates request → invoker executes → receiver changes
                              │
                        records prior state → optional undo
```

This example assumes one owner changes the light and history is undone in order. If another actor changes it between execution and undo, blindly restoring an old value can erase their work. Concurrent systems require versions, conflict rules or a domain compensation operation.

## A queued command must be data

A closure such as `() => light.on = true` can represent a local command. A class holding a live receiver reference is not automatically serializable either. For durable jobs, store validated operation data such as `{ operationId, type, targetId, desired }` and let a worker resolve the receiver through approved handlers.

Persist request identity before relying on retries. Authorize against the applicable execution-time policy, keep secrets out of job payloads, define deadlines and retain outcomes. A durable queue may redeliver after a worker fails; the Command pattern does not supply idempotency or exactly-once effects.

Commands express intent; events describe accepted facts. A CQRS write request may use a command object, but CQRS itself does not require one class per operation. Redux actions are data messages to state logic and may represent events rather than imperative commands.

## Undo, compensation and transactions

Expose `undo` only when it is meaningful. A no-op undo method falsely suggests reversibility. An email cannot be unsent by restoring local state. A refund or follow-up message is a compensating business action with its own failures.

Running several commands and invoking inverses on failure is not equivalent to an atomic database transaction. Earlier effects may already be visible, compensation can fail and irreversible effects may remain. Use a database transaction for local atomic changes and a recoverable saga when distributed compensation is the intended contract.

Bound command history explicitly. Weak references can make required undo information disappear nondeterministically, so they are not a substitute for a history retention policy.

## Summary

Capture a request so execution policy can be separated from its trigger. Trace what is captured, when it runs and what happens on repeat or failure. Add undo only for a defined reversible boundary, and give durable commands identity, validation and recovery rules.

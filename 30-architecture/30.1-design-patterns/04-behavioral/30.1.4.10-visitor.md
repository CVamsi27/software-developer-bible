# Visitor Pattern


## Definition

Visitor separates operations from a relatively stable set of element types. Elements expose an `accept` operation that dispatches to the visitor method for their type; each new visitor implements another operation over that same structure.

## First Principles

A document can need plain-text extraction, validation and rendering. Putting all three operations inside each element class mixes unrelated reasons to change. Keep the structure stable and give each operation its own visitor. This favors adding operations: adding an element type generally requires updating the visitor contract and implementations.

## Follow an operation through two element types

```typescript
interface DocumentVisitor<T> {
  paragraph(node: Paragraph): T;
  heading(node: Heading): T;
}
interface DocumentNode {
  accept<T>(visitor: DocumentVisitor<T>): T;
}
class Paragraph implements DocumentNode {
  constructor(readonly text: string) {}
  accept<T>(visitor: DocumentVisitor<T>): T { return visitor.paragraph(this); }
}
class Heading implements DocumentNode {
  constructor(readonly text: string, readonly level: number) {}
  accept<T>(visitor: DocumentVisitor<T>): T { return visitor.heading(this); }
}
const plainText: DocumentVisitor<string> = {
  paragraph: node => node.text,
  heading: node => node.text
};
const outline: DocumentVisitor<string> = {
  paragraph: () => '',
  heading: node => `${'  '.repeat(node.level - 1)}${node.text}`
};
const document: DocumentNode[] = [new Heading('Start', 1), new Paragraph('Body')];
console.log(document.map(node => node.accept(plainText)).join('\n'));
// Start
// Body
console.log(document.map(node => node.accept(outline)).filter(Boolean).join('\n'));
// Start
```

The caller holds only `DocumentNode`. A heading's `accept` selects `visitor.heading`; the supplied visitor determines which operation that method performs. `plainText` returns the text, while `outline` excludes paragraphs. Adding the outline operation did not change either node class.

```text
node.accept(visitor) → node chooses heading/paragraph method
                     → visitor supplies that operation's behavior
```

This is the Visitor form of double dispatch. JavaScript/TypeScript does not select overload implementations from runtime argument types: explicitly named methods make the node choice visible. Multiple dispatch, tagged-union matching and other dispatch techniques are alternatives, so Visitor is not the only way to obtain type-dependent behavior.

## Traversal is a separate responsibility

This example traverses an array before visiting each element. For a tree, a traversal driver or a visitor can choose DFS/BFS and whether to descend. State which owns recursion to avoid visiting children twice or not at all. Graphs need a cycle/identity policy; a global visited set prevents repeat visits but can also suppress a shared node that should be counted once per path.

A visitor can return values, accumulate results, mutate nodes or produce a transformed structure. Reuse a stateful visitor only when its reset and concurrency behavior are explicit. Untrusted node data still needs validation; the sample's heading level must be a supported positive integer before calling `repeat` in a production boundary.

## Choose the axis that changes

| Approach | What stays stable | What is easy to add |
| -------------------------------- | ------------------------------------- | ---------------------------- |
| Methods on node classes | Operations | Node types |
| Classic Visitor | Node types and their visitor contract | Operations |
| Tagged union + exhaustive switch | Closed union of node types | Separate operation functions |
| Generic iterator | Traversal protocol | Collection implementations |

A union reduces ceremony but retains the same tradeoff: adding a union member requires updating exhaustive operations. Neither form makes both axes independently extensible without costs. Visitor can be adapted around third-party objects through wrappers or an external dispatch layer; it need not be inserted into objects you cannot edit.

## How this fits a language pipeline

A parser constructs an AST from input. An interpreter evaluates its meaning. Visitors may then implement type checking, formatting, optimization or evaluation over that AST. Interpreter is not the parser; the same structure can support multiple operations.

ESLint's node-type callbacks are visitor-like operations driven by its AST traversal, rather than proof that every AST class exposes the exact GoF `accept` method. Explain the dispatch mechanism used by the actual framework.

## Summary

Keep a stable structure's operations separate when operations change more often than element types. Trace both dispatch choices, assign traversal to one owner and account for the cost of adding a new node type.

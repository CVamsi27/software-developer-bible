# Anti-Corruption Layer (ACL)


## Definition

An Anti-Corruption Layer protects one context's model from the meaning and conventions of another system. It translates at an integration boundary so vendor status codes, units and failure semantics do not become scattered domain assumptions.

## First Principles

A vendor's `A` may mean an active billing relationship; your domain's "active customer" may mean something different. Renaming a field is insufficient if its meaning differs. Define the contract your domain needs, then make the translation and its unsupported cases explicit at the boundary.

## Trace one vendor record

```typescript
type BillingStatus = 'active' | 'inactive' | 'suspended';
type BillingAccount = Readonly<{ id: string; name: string; status: BillingStatus }>;

function translateAccount(input: unknown): BillingAccount {
  if (typeof input !== 'object' || input === null) throw new Error('Invalid record');
  const record = input as Record<string, unknown>;
  if (typeof record.cust_id !== 'string' || !/^CU-[0-9]{6}$/.test(record.cust_id) ||
      typeof record.cust_nm !== 'string' || record.cust_nm.trim() === '') {
    throw new Error('Invalid account identity');
  }
  let status: BillingStatus;
  switch (record.cust_sts) {
    case 'A': status = 'active'; break;
    case 'I': status = 'inactive'; break;
    case 'S': status = 'suspended'; break;
    default: throw new Error('Unknown billing status');
  }
  return Object.freeze({
    id: record.cust_id.slice(3), // preserve leading zeros: identity is not a number
    name: record.cust_nm.trim(),
    status
  });
}
console.log(translateAccount({ cust_id: 'CU-000123', cust_nm: ' Clinic ', cust_sts: 'A' }));
// { id: '000123', name: 'Clinic', status: 'active' }
```

The adapter receives untrusted data → the translator validates its shape and identity → it maps an approved status → the domain receives its own record. An unknown status is visible as a translation failure rather than silently becoming inactive. Type assertions alone would not validate an external payload.

```text
foreign protocol/DTO → adapter → validated semantic translation → your port/model
```

A port states what your application expects. An adapter implements it using the foreign client. A translator owns representation and meaning conversion. A facade can simplify multi-call choreography. These are cooperating roles, not a requirement for three classes in every ACL.

## Translation must preserve meaning

Document units, currency, time zone, identifier formatting, enum versions, defaults and null semantics. If a vendor date is a local calendar date, converting it to UTC midnight without a business rule changes meaning. A numeric date constructor can normalize invalid dates; validate a calendar date before accepting it. Decimal money conversion needs agreed precision and rounding instead of a casual multiply-and-round for every currency.

If null means unlimited credit in one documented contract, represent unlimited explicitly. If null means unknown, do not translate it to unlimited. Validate outbound requests with equal care, including idempotency keys and the original vendor identity required by its endpoint.

A separate credit-limit read followed by a charge does not atomically enforce a credit limit. An ACL can faithfully translate a protocol; it cannot manufacture concurrency guarantees absent from the upstream system. Require the authoritative atomic operation or accept a defined reservation/reconciliation model.

## Keep failures and ownership visible

Map legitimate not-found outcomes separately from timeouts, unavailable service and invalid data. Retry only under an operation's duplicate-effect contract. Keep deadlines, cancellation, rate limits and pagination in the integration owner, with transport helpers shared where useful.

Own domain translation in the consuming context. Shared protocol clients can be appropriate, but forcing several contexts to share one compromise domain model recreates coupling. Contexts may intentionally share vocabulary; an ACL protects meaning where models differ rather than forbidding all shared names.

Recorded payload fixtures test known translation cases; they do not detect a vendor change until new evidence reaches the tests. Combine them with schema/contract checks and anomaly monitoring. Use representative redacted fixtures and reject unexpected cases deliberately.

## Is the layer worth keeping?

A long-lived foreign model that conflicts with yours benefits from an explicit translation boundary. A simple aligned API may need only a thin adapter. Owning both systems does not eliminate the need if they represent different contexts or migrate on different timelines. Measure maintenance cost instead of deciding by team size.

Replacing a vendor can reuse a port when meanings still match; it does not guarantee one binding change and zero domain work. Delete retired mappings after consumers and migration dependencies have been checked.

## Summary

Translate meaning at a deliberate boundary, then trace one real payload through validation and mapping. Keep unsupported data and infrastructure failures distinct, preserve operation semantics and scope the layer to the context it protects.

# Anti-Corruption Layer (ACL)

Suppose a billing vendor returns `cust_sts: "A"`. A local handler turns it into `active` and grants a product entitlement. The vendor meant only “billing profile is open”; local eligibility also depends on whether an invoice is settled. The bug is the meaning crossing the boundary, not the field spelling.

## Definition

An **Anti-Corruption Layer (ACL)** sits on the consumer side of an integration: the **upstream** system provides data or operations, and the **downstream** application consumes them. The layer translates between their contracts, including outbound requests when needed, so raw vendor fields, codes and failure conventions do not become assumptions throughout the domain.

> **Textbook Definition:** In Eric Evans's context-mapping pattern, a downstream client isolates its model from an upstream model by expressing the upstream capabilities in its own terms. The layer uses the upstream interface and translates between the models in one or both directions. [Evans's DDD Reference, “Anticorruption Layer”](https://www.domainlanguage.com/wp-content/uploads/2016/05/DDD_Reference_2015-03.pdf)

## First Principles

If callers inspect `cust_sts` directly, each can make a different assumption and the vendor schema becomes part of the local API. One owned translator centralizes that mapping. It can preserve a vendor fact, but it cannot infer the consuming domain's eligibility rules from a label such as “active.”

## Translate one vendor record

```typescript
type BillingProfileState = 'open' | 'closed' | 'suspended';
type BillingAccount = Readonly<{ id: string; name: string; profileState: BillingProfileState }>;

function translateAccount(input: unknown): BillingAccount {
  if (typeof input !== 'object' || input === null) throw new Error('Invalid record');
  const record = input as Record<string, unknown>;
  if (typeof record.cust_id !== 'string' || !/^CU-[0-9]{6}$/.test(record.cust_id) ||
      typeof record.cust_nm !== 'string' || record.cust_nm.trim() === '') {
    throw new Error('Invalid account identity');
  }
  let profileState: BillingProfileState;
  switch (record.cust_sts) {
    case 'A': profileState = 'open'; break;
    case 'I': profileState = 'closed'; break;
    case 'S': profileState = 'suspended'; break;
    default: throw new Error('Unknown billing status');
  }
  return Object.freeze({
    id: record.cust_id.slice(3), // preserve leading zeros: identity is not a number
    name: record.cust_nm.trim(),
    profileState
  });
}
console.log(translateAccount({ cust_id: 'CU-000123', cust_nm: ' Clinic ', cust_sts: 'A' }));
// { id: '000123', name: 'Clinic', profileState: 'open' }
```

These fields and codes define an illustrative vendor contract, not a real provider API. Here, `open` means only that the vendor's billing profile is open; it does not prove that a product invoice is paid. The local subscription policy must check its own eligibility rules. The ID is unique within the vendor's namespace, so combining records from several vendors requires retaining the source or maintaining an explicit identity map. Type assertions alone would not validate this external payload.

The function above is the pure translator inside the ACL. A surrounding adapter calls the vendor client and returns the local type through a **port**, the interface owned by the consuming application. The adapter and translator can be one small in-process component; an ACL is a boundary role, not a requirement for three classes. Reject an unknown status instead of silently treating it as closed. For bulk ingestion, quarantine the payload with enough context to investigate it without exposing sensitive data in logs.

For an outbound operation, the same boundary maps a local request into the vendor's protocol. A facade can simplify a multi-call workflow, but domain rules and workflow recovery keep their own owners.

## Translation must preserve meaning

Document units, currency and precision, calendar dates versus instants, identifier scope, enum versions, defaults, and the difference between missing and `null`. If a vendor date is a local calendar date, converting it to UTC midnight changes its meaning. Validate calendar fields before accepting a date because some date constructors normalize invalid values. Money conversion needs an agreed precision and rounding rule for each currency.

If `null` means unlimited credit in one documented contract, represent unlimited explicitly. If it means unknown, do not translate it to unlimited. Validate outbound requests too, including idempotency keys and any vendor identity required by the endpoint.

A credit-limit read followed by a separate charge does not enforce the limit atomically. An ACL can translate a protocol; it cannot add concurrency guarantees the upstream system does not provide. Require an authoritative atomic operation or define a reservation and reconciliation model.

## Keep failures and ownership visible

Keep legitimate not-found results, invalid or unknown data, throttling, timeouts and service failures distinct. Retry only when the operation's duplicate-effect contract is clear—for example, when a stable idempotency key makes repeating a charge safe. Put deadlines, cancellation, rate limits and pagination in the integration owner; share transport helpers without sharing a compromise domain model.

Own each translation in the consuming context. Shared protocol clients can be appropriate, but making several contexts share one compromise domain model recreates coupling. Contexts may intentionally share vocabulary; an ACL protects meaning where models differ rather than forbidding shared names.

Recorded payload fixtures test known translations, but they cannot detect a vendor change until new evidence reaches the tests. Combine them with schema or contract checks and monitor translation failures by vendor operation and schema version. Use representative redacted fixtures and reject unexpected cases deliberately.

## Is the layer worth keeping?

A long-lived foreign model that conflicts with yours benefits from an explicit translation boundary. If the models already share the needed meaning, a thin adapter may be enough; keep domain rules and orchestration out of it. An in-process boundary avoids an extra network hop. Deploy a separate ACL service only when independent ownership, scaling or release needs justify its added latency, operating cost and availability risk.

During a strangler migration, route only the capabilities already moved to the new model and keep the remaining behavior on the old system. Treat the ACL as migration code when that is its role: track its consumers and remove it after the old system has none. Replacing a vendor can reuse a port when meanings still match, but it may still require domain changes.

## Summary

Keep foreign protocol and meaning at one owned boundary. Validate and translate both directions, keep local policy and cross-system consistency separate, and choose an in-process or deployed boundary based on its operational cost. Retire migration glue when no consumers remain.

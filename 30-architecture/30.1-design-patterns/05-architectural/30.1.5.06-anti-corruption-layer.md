# Anti-Corruption Layer (ACL)

> **TL;DR:** An Anti-Corruption Layer isolates your domain model from a legacy or external system's model. It sits at the boundary of a bounded context and speaks **your language inward, theirs outward** — implemented as a trio of Facade + Adapter + Translator. Build one when the foreign model is valuable-but-messy and you cannot change it; skip it when you own both sides.

<!-- section: Design Patterns | category: Architecture | subcategory: Architectural | tags: concept, ddd -->

## Definition

An **Anti-Corruption Layer** is an intermediary boundary that prevents a foreign model — a legacy database schema, a third-party vendor's API semantics, another team's microservice contract — from leaking into and degrading ("corrupting") your domain model.

The name is Eric Evans': without protection, foreign concepts colonize your model. You end up with `CustMst` records, status codes like `"R"`, and null-semantics quirks woven through clean code. The ACL makes the translation explicit, tested, and located in exactly one place.

```text
┌───────────────────────────────────────────────────────────────┐
│  YOUR BOUNDED CONTEXT (clean model)                           │
│                                                               │
│   Customer, Invoice, BillingCycle  ← pure domain types        │
└──────────────┬────────────────────────────────────────────────┘
               │ depends on ports (interfaces YOU define)
┌──────────────▼───────────────────────────────────────────────┐
│  ANTI-CORRUPTION LAYER                                        │
│                                                               │
│  ┌─────────┐    ┌───────────┐    ┌───────────────────────┐     │
│  │ Facade  │───▶│ Adapter   │───▶│ Translator / Mapper   │     │
│  │ simple  │    │ implements│   │ TheirDTO ↔ YourModel  │     │
│  │ entry   │    │ your port │   │ (both directions)     │     │
│  └─────────┘    └──────────┘    └───────────┬───────────┘     │
└──────────────────────────────────────────────┼─────────────────┘
                                               │ their protocol
                                 ┌─────────────▼───────────────┐
                                 │ LEGACY / EXTERNAL SYSTEM    │
                                 │ SOAP RPC, CustMst table,    │
                                 │ vendor SDK, partner REST    │
                                 └─────────────────────────────┘
```

Three cooperating roles:

1. **Facade** — a simplified, intention-revealing entry point hiding the awkward call choreography (retries, pagination, session tokens) the foreign system demands.
2. **Adapter** — implements YOUR port interface in terms of the foreign client. The rest of your app sees only the port.
3. **Translator** — pure functions converting between foreign DTOs and your domain objects, both directions. Where validation and semantic repair live (`"R"` → `BillingStatus.Refunded`, epoch-seconds → `Date`, money-as-cents → `Money`).

## Why Do We Need It?

1. **Models encode assumptions.** A legacy `Customer` with mandatory `custType` codes and implicit "deleted = flag" semantics will fight your `Customer` aggregate. Direct coupling imports those fights forever.
2. **Foreign systems change on their schedule**, not yours. Vendors deprecate fields, partners ship breaking versions. Without an ACL every change ripples into domain logic.
3. **Strangler migrations need seams.** Replacing a monolith incrementally requires a stable seam where new code meets old code — the ACL is that seam.
4. **Testing becomes possible.** With translation isolated, you can test your domain against translated fixtures and test the translator against recorded foreign payloads.
5. **Bounded-context integrity.** In DDD terms, each context keeps its own ubiquitous language; the ACL enforces "no shared vocabulary" across contexts.

## How It Works

1. Define a **port** in your context: an interface named in YOUR language (`LegacyBillingGateway` returning `Invoice[]`).
2. Implement the port with an **adapter** that owns the foreign client (SOAP stub, HTTP client, DB connection).
3. Write **translators** as pure, exhaustively-tested functions for every field mapping — including defaults, sentinel values, and error semantics.
4. Wrap it all in a **facade** exposing the handful of operations your domain actually needs.
5. Register the adapter in your DI container. Domain services depend only on the port; the ACL is swappable, mockable, and eventually deletable when the legacy system dies.

Placement rule: the ACL lives **inside the downstream bounded context that consumes the foreign system** — never shared as a "common integration library" by multiple contexts, or the corruption just re-enters through the back door.

## Code Examples

### The foreign model (what we are protecting against)

```typescript
// Legacy billing vendor: SOAP-era DTOs, stringly-typed enums, local dates
interface LegacyCustomerRecord {
  cust_id: string;          // "CU-000123"
  cust_nm: string;          // "ACME Corp"
  cust_sts: 'A' | 'I' | 'S'; // Active | Inactive | Suspended
  credit_lmt_amt: number | null; // null means UNLIMITED (!)
  bill_freq: 'W' | 'M' | 'Q';
  last_bill_dte: string;    // 'YYYYMMDD'
}
```

### Step 1 — Your port (domain-side interface)

```typescript
import { Money } from './money';

type BillingStatus = 'Active' | 'Inactive' | 'Suspended';

interface BillingAccount {
  id: string;
  legalName: string;
  status: BillingStatus;
  creditLimit: Money | 'unlimited';
  billingCycle: 'Weekly' | 'Monthly' | 'Quarterly';
}

interface BillingGateway {
  findAccount(customerId: string): Promise<BillingAccount | null>;
  charge(accountId: string, amount: Money): Promise<void>;
}
```

### Step 2 — Translators (pure functions, exhaustively testable)

```typescript
function parseLegacyDate(yyyymmdd: string): Date {
  if (!/^\d{8}$/.test(yyyymmdd)) throw new Error(`Bad legacy date: ${yyyymmdd}`);
  const y = Number(yyyymmdd.slice(0, 4));
  const m = Number(yyyymmdd.slice(4, 6));
  const d = Number(yyyymmdd.slice(6, 8));
  return new Date(Date.UTC(y, m - 1, d));
}

function toBillingStatus(code: LegacyCustomerRecord['cust_sts']): BillingStatus {
  switch (code) {
    case 'A': return 'Active';
    case 'I': return 'Inactive';
    case 'S': return 'Suspended';
  }
}

export function translateLegacyCustomer(rec: LegacyCustomerRecord): BillingAccount {
  return {
    id: rec.cust_id.replace(/^CU-0*/, ''),
    legalName: rec.cust_nm.trim(),
    status: toBillingStatus(rec.cust_sts),
    // Semantic repair: legacy null means unlimited, not unknown!
    creditLimit: rec.credit_lmt_amt === null
      ? 'unlimited'
      : Money.of(Math.round(rec.credit_lmt_amt * 100), 'USD'),
    billingCycle: { W: 'Weekly', M: 'Monthly', Q: 'Quarterly' }[rec.bill_freq],
  };
}
```

Every quirk — prefix stripping, sentinel-null meaning, date format, enum decoding — has exactly one home.

### Step 3 — Adapter implementing the port

```typescript
class LegacyBillingAdapter implements BillingGateway {
  constructor(private readonly soapClient: LegacySoapClient) {}

  async findAccount(customerId: string): Promise<BillingAccount | null> {
    let record: LegacyCustomerRecord;
    try {
      record = await this.soapClient.getCustomer(`CU-${customerId.padStart(6, '0')}`);
    } catch (err) {
      if ((err as SoapError).code === 'NOT_FOUND') return null;
      throw err; // infrastructure failures stay loud
    }
    return translateLegacyCustomer(record);
  }

  async charge(accountId: string, amount: Money): Promise<void> {
    await this.soapClient.postCharge({
      acct_id: accountId,
      amt: amount.amountCents / 100,
      cur: amount.currency,
    });
  }
}
```

### Step 4 — Facade for the domain's actual vocabulary

```typescript
class BillingFacade {
  constructor(private readonly gateway: BillingGateway) {}

  async canAcceptOrder(customerId: string, orderTotal: Money): Promise<boolean> {
    const account = await this.gateway.findAccount(customerId);
    if (!account || account.status !== 'Active') return false;
    if (account.creditLimit === 'unlimited') return true;
    const outstanding = await this.gateway.outstandingFor(account.id);
    return outstanding.add(orderTotal).amountCents <= account.creditLimit.amountCents;
  }
}
```

Domain services call `billing.canAcceptOrder(...)` — no SOAP, no `'A'` codes, no padded IDs anywhere else in the codebase.

### Wiring

```typescript
container.bind<BillingGateway>('BillingGateway')
  .to(LegacyBillingAdapter)
  .inSingletonScope();
// Swapping vendors later = one binding change, zero domain edits.
```

## Real-World Use Cases

1. **Vendor payment/ERP integration** — SAP/NetSuite semantics behind a clean `LedgerGateway`.
2. **Strangler-fig migration** — new service reads old monolith's tables through an ACL until cutover deletes it whole.
3. **Partner APIs with alien contracts** — airline GDS responses, hotel-channel-manager XML, insurance ACORD formats.
4. **Cross-team microservice boundaries** — another team's user service models "user" differently than yours does; translate rather than adopt.
5. **IoT/legacy device protocols** — binary register maps translated into typed readings once, at the edge.

## When NOT to Build One

Honest cost/benefit matters in interviews:

| Factor | Favors ACL | Against ACL |
| ------------- | ------------------------------------------- | ------------------------------------ |
| Ownership | You don't control the other model | Same team/codebase owns both |
| Model quality | Foreign model actively conflicts with yours | Foreign model ≈ yours anyway |
| Lifespan | Integration outlives many releases | One-off script, short-lived campaign |
| Blast radius | Many consumers of the foreign system | Single call site |
| Team cost | Can afford translator maintenance | 2-person startup building CRUD |

Skip the ACL when: you own both sides (just refactor the model), the integration is trivial CRUD over a well-designed API, or the project's lifespan is shorter than the layer's build time. A thin repository or plain HTTP client is then the honest answer — patterns applied where unnecessary are their own form of corruption (of the codebase's simplicity).

## Common Mistakes

### 1. Leaking DTOs past the layer

```typescript
// BAD: domain service receives LegacyCustomerRecord directly
const rec = await legacyClient.getCustomer(id);
order.applyCustomer(rec); // corruption complete
```

Translation must happen inside the adapter; nothing foreign crosses the port.

### 2. Bidirectional laziness

Teams translate inbound carefully but let outbound requests construct foreign payloads ad hoc. Outbound translation deserves the same rigor (and tests) — malformed outbound writes poison the legacy system's data too.

### 3. ACL without contract tests

The legacy team changes `cust_sts` values silently. Record real payloads and replay them against translators in CI (consumer-driven contract testing) so drift fails a build, not production.

### 4. Building a general-purpose integration framework

The ACL should expose only what THIS context needs. Exposing everything "for reuse" recreates the legacy model, one abstraction higher.

### 5. Sharing one ACL library across bounded contexts

Context A's `Customer` ≠ Context B's `Customer`. Shared translation layers force compromise models. Each consuming context gets its own ACL.

### 6. Ignoring error semantics

Legacy timeouts, partial-success responses, and idempotency quirks are part of the foreign model. Translate them into your error taxonomy explicitly (retryable vs permanent), or they leak as mystery 500s.

## Best Practices

1. Define ports in domain language FIRST; write adapters second (dependency inversion).
2. Keep translators pure and total — no I/O, no clock, no randomness; snapshot-test them against captured payload fixtures.
3. Make the ACL own ALL protocol concerns: auth, retries, pagination, rate limits.
4. Log translation anomalies (unknown enum value arrived) as structured events — that is your early-warning system for upstream drift.
5. Version the facade operations so multiple legacy versions can coexist during migration windows.
6. Delete aggressively: every retired foreign operation loses its translator the same sprint.

## Summary

The Anti-Corruption Layer buys your domain model diplomatic immunity from foreign systems: Facade simplifies, Adapter implements your port, Translator purifies semantics — and all three live in exactly one place per consuming context. It is not free; build it when the foreign model is messy, long-lived, and outside your control, and resist it when you own both ends.

**Interview-ready one-liner:** "An ACL is a boundary translation module — facade plus adapter plus pure translators — that keeps legacy/vendor concepts like status codes and sentinel nulls out of my domain model. I scope it per bounded context, contract-test the translators against recorded payloads, and delete it with the legacy system during strangler migrations."

## Cheat Sheet

| Aspect | Detail |
| -------------- | ------------------------------------------------------------------------------------ |
| **Purpose** | Isolate your model from legacy/external models |
| **Trio** | Facade (simple entry) + Adapter (implements your port) + Translator (DTO <-> domain) |
| **Lives in** | The consuming bounded context — never shared between contexts |
| **Build when** | Foreign model is messy, long-lived, not under your control |
| **Skip when** | You own both sides; integration is trivial; lifespan too short |
| **Key risk** | DTO leakage past the port; untested translators drifting |
| **Pairs with** | Repository, Strangler Fig, Ports & Adapters (hexagonal), Saga |

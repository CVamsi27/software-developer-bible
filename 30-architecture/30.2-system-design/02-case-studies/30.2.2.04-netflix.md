# Netflix System Design

A viewer taps Play on a phone whose network varies from segment to segment. One high-bitrate segment arrives quickly; the next stalls as bandwidth falls. The player must lower quality before its buffer empties, while the service separately checks whether this profile may watch the title. That trace separates playback authorization from media delivery and adaptation.

## Definition

A Netflix-like service helps viewers find content available under current rights, verifies that an account may play it and delivers encoded media suited to the device and network. The catalog/playback application programming interface (API) handles decisions; media caches and a content delivery network (CDN) carry most transferred bytes.

> **Textbook Definition:** An on-demand video service manages content discovery, playback authorization, and adaptive delivery of encoded media, separating control operations from the high-volume media delivery path.

This is an interview design, not a verified description of Netflix's deployment. The [YouTube case](30.2.2.17-youtube.md) owns the focused encoding/publication example. Here the additional reasoning concerns licensed playback, adaptive quality, profiles and recovery.

## First Principles

A video is too large to retransmit through the account API for every viewer. Publish immutable encoded segments, let a player choose compatible renditions and place those objects near demand. A catalog outage and a media-origin outage affect different paths: an existing player may continue from cached segments while new authorization cannot complete.

A paid account does not imply every title is playable on every device or in every territory. Subscription, profile maturity policy, device capability, concurrent-stream policy and content-rights windows need separate checks. Cached metadata cannot replace the current entitlement decision.

The player must choose quality before knowing the next download's actual speed. A bandwidth estimate is uncertain, so buffer occupancy, safety margin and switching stability matter as well as nominal bitrate.

## Requirements and consistent capacity

Support accounts/profiles, search, discovery, subtitles/audio tracks, watch history, resume, parental controls, compatible renditions and authorized playback. Offline downloads introduce separately provisioned digital rights management (DRM) licenses and expiration rules. Choose explicit objectives for playback start, failed starts, rebuffering and API availability; a blanket global 50 ms target ignores device and network conditions.

For an illustrative peak, 15 million concurrent streams at 5 Mbit/s require 75 Tbit/s of payload egress. This is a concurrency calculation, not a subscriber count. If 200 million users each watch two hours/day at 5 Mbit/s, transfer is 900 PB/day: 200 million ×2 ×3,600 ×5 million /8. The mean simultaneous viewing would be about 16.7 million, so it cannot coexist with a 15 million peak. Choose one coherent workload; for example, 100 million daily viewers at one hour/day implies about 4.17 million average concurrent streams and 225 PB/day at that bitrate. Use decimal byte units consistently for these estimates.

A 100,000-hour library at an assumed 1 GB/hour contains 100 TB before additional renditions, audio, subtitles and replicas. That storage assumption is distinct from a 5 Mbit/s viewing rendition, which consumes 2.25 GB/hour in decimal units. Sum actual encoded bitrate-hours rather than mixing title count, source hours and arbitrary 50 GB copies. Measure compute-hours per source-hour for each codec/rendition; parallelism reduces elapsed time within capacity, not total required compute.

## How the components fit

```text
Catalog ingest → reviewed metadata / rights / source media
                         ↓                   ↓
                 discovery/search      encode/package/validate
                         ↓                   ↓
Profile → playback authorization → immutable rendition manifests
                         ↓                   ↓
                short-lived grant      media CDN → player
                         ↓                   ↓
                  DRM key/license service   segment choice + quality-of-experience (QoE) events

Viewing events → durable progress → recommendation features/ranking
```

A **manifest** describes media segments and rendition choices using a protocol such as HTTP Live Streaming (HLS) or Dynamic Adaptive Streaming over HTTP (DASH, standardized as MPEG-DASH). A Python dictionary naming quality levels is not an HLS playlist or DASH Media Presentation Description (MPD). Segment boundaries and independent decode points must support safe switching; bitrate names alone do not establish compatibility.

## Trace an authorized playback start

1. Resolve account/profile from the authenticated session. Verify current content rights, subscription, maturity restrictions, device limits and requested territory under the product's policy.
2. Atomically create or renew a bounded playback lease if simultaneous-stream limits matter. Two independent count-then-create requests can exceed the limit.
3. Select a compatible package and return session identity, short-lived scoped media authorization and the data needed to begin a device-specific DRM-license exchange. Keep raw bearer secrets out of logs and URLs where possible.
4. The player obtains a DRM license when required, then downloads the manifest and requests segments directly from the media CDN. The account API does not proxy every media byte.
5. The player records useful playback events and renews authorization under policy. A copied manifest URL must not permanently bypass entitlement checks.

A DRM license authorizes technical decryption on a supported device. The entitlement service separately checks contractual title rights, account subscription and profile policy. DRM reduces unauthorized playback under a specified device/trust model; it does not make piracy impossible or replace application permissions. A signed media URL and a DRM license solve different boundaries.

## Example: a conservative quality shortlist

This complete Python function selects the highest listed nominal bitrate below a safety-adjusted bandwidth estimate and under a device-height limit. It does not model codec or DRM compatibility, buffer state, or segment availability; it demonstrates a bound, not a production adaptive-bitrate controller.

```python
import math

RENDITIONS = (("360p", 1_000_000, 360),
              ("720p", 3_000_000, 720),
              ("1080p", 6_000_000, 1080))

def choose_rendition(bandwidth_bps, max_height, safety=0.75):
    if not math.isfinite(bandwidth_bps) or bandwidth_bps < 0:
        raise ValueError("Bandwidth must be finite and nonnegative")
    if not isinstance(max_height, int) or max_height <= 0 or not (0 < safety <= 1):
        raise ValueError("Invalid device capability or safety margin")
    budget = bandwidth_bps * safety
    eligible = [r for r in RENDITIONS
                if r[1] <= budget and r[2] <= max_height]
    return max(eligible, key=lambda r: r[1])[0] if eligible else None

print(choose_rendition(8_000_000, 1080))  # 1080p
print(choose_rendition(500_000, 1080))    # None
```

At 8 Mbit/s measured bandwidth and a 0.75 margin, the budget is 6 Mbit/s. At 0.5 Mbit/s, even the lowest rendition does not fit: blindly returning 360p would conceal the shortage. A real player considers buffered seconds, recent segment variability, codec capability, startup strategy and hysteresis to avoid repeated quality oscillation. Lowering quality may reduce rebuffering, but cannot solve a complete connectivity loss.

## Immutable media and controlled cache access

Publish a processing version only after required media, manifests, audio and subtitle assets are validated. Jobs need stable identities, retry-safe output paths and a version check so an old encode cannot publish over a newer package. The [YouTube publication trace](30.2.2.17-youtube.md) demonstrates this boundary.

Media objects can be immutable and widely cached while access remains conditional. Authorize at the chosen edge/origin boundary before serving protected bytes; a cache hit must not skip that check. Scope grants to the allowed content/session and expire them deliberately. Rights withdrawal may require invalidation and refusing grant renewal; already downloaded licensed content follows its own contract.

A cache miss should fetch the authorized object through the CDN's normal origin path. Returning a raw origin URL to clients as a fallback may bypass policy and overwhelm origin capacity. Multi-CDN steering requires valid grants, equivalent packages, origin shielding and measured failover. The geographically nearest edge is not always the fastest or healthy one.

## Profiles, history and recommendations

Identify every playable item, including episodes, unambiguously. Store progress per profile/item, with session identity and update sequence; a delayed update from an old session must not overwrite a newer chosen resume state. Taking the maximum position is insufficient because a viewer may deliberately rewind. Define how concurrent devices choose the authoritative resume session or conflict policy.

Recommendation candidates can be computed offline, with bounded online retrieval/ranking. The serving path may run inference; it should not train a model synchronously for every browse request. Apply current territory, maturity and availability filters after retrieving candidates. A cached personalized list must be scoped to the profile and policy version, and fallback popular titles must obey the same restrictions.

Keep watch events separate from canonical progress. Deduplicate event IDs when consuming them, and avoid counting retries as additional watches. Search results, totals and personalized rows can reveal profile behavior; enforce account/profile permissions and appropriate telemetry retention.

## Recovery must preserve the requested intent

| Failure | Controlled behavior |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Recommendation unavailable | Show authorized nonpersonalized discovery rows. |
| Requested title metadata unavailable | Use suitably bounded authorized metadata or report failure; do not silently play another title. |
| CDN failure | Try a compatible healthy delivery path within retry/time budget; avoid a synchronized origin stampede. |
| Origin failure | Cached segments may remain playable, but uncached objects still fail. |
| DRM license service failure | Already provisioned DRM licenses may work under their existing policy; do not invent a license after failure. |
| Entitlement authority unavailable | Apply the explicitly allowed cached/grace policy or reject new starts; a stale read replica is not automatically safe. |
| Progress write failure | Buffer bounded retry-safe updates and expose sync delay without blocking media unnecessarily. |

Offline downloads require advance DRM-license provisioning, authorized encrypted assets, storage limits, expiry and revocation policy. They are not a universal emergency fallback. Server response success also does not prove a player rendered its first frame.

## Real-world decisions

Start with the actual device matrix and content rights. Choose HLS or MPEG-DASH packaging, codecs, encryption and CDN integration from supported clients. Their manifests, packaging constraints and client support differ; neither name alone determines which codecs or DRM systems will work. More codecs improve some bandwidth/device outcomes but add encoding, storage and quality-validation cost.

Separate read-mostly catalog storage, authoritative account/lease decisions, high-volume viewing telemetry and search indexes. A list of PostgreSQL/Cassandra/Elasticsearch names is not evidence that their query and failure contracts fit. Regional serving needs explicit consistency boundaries for current rights and concurrent stream counts.

Measure first-frame time, start failures, rebuffer duration divided by viewing duration, bitrate changes, license latency, bytes/segment-cache misses and origin saturation. Segment by device, network and region. Define denominators and windows before stating a 1% rebuffer objective; averages alone can hide an unusable device cohort.

## Test the playback contract

Race two starts against the simultaneous-stream limit; revoke a title between catalog display and authorization; test an unsupported device, a missing segment, an expired DRM license and a cold-CDN failover. Publish only a package whose required assets are all present, and confirm that every cached delivery path still enforces its grant. Use real player/network measurements for adaptive-quality claims; a local selection function cannot establish end-to-end playback reliability.

## Summary

A licensed video service separates discovery and playback authorization from high-volume immutable media delivery. Adaptive quality balances device compatibility, uncertain bandwidth and buffer state. Rights, concurrent streams, licenses, publication versions and progress conflicts each need an explicit authority; controlled degradation preserves the viewer's intent without bypassing those boundaries.

# Workflow Engine — System Design Case Study

> **Company-adjacent:** n8n, sennder, Hostaway. Design a workflow automation platform that executes user-defined workflows with triggers, actions, and error handling.

---


## Requirements

**What are we building?** A workflow automation platform (like n8n or Zapier) where users create workflows — chains of connected steps (nodes) that execute in order. Each node performs an action: HTTP request, database query, send email, conditional branch. Workflows are triggered by events (webhook, schedule, manual). The system must handle 100K executions/day, support retries on failure, and log every step for debugging. This is the core of n8n's product and a common system design question at workflow/data companies.


### Functional
- Users create workflows (DAG of nodes)
- Each node is an action (HTTP request, database query, email, etc.)
- Workflows are triggered by events (webhook, schedule, manual)
- Each execution is logged with step-by-step results
- Workflows can be paused, resumed, cancelled
- Retries with configurable policy per node

### Non-Functional
- 100K workflow executions/day
- Each workflow has 5-20 nodes
- Execution latency: <30s for simple workflows, <5min for complex
- 99.9% execution success rate
- Execution history retained for 30 days

## Data Model

```sql
-- Workflow definition
CREATE TABLE workflows (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name VARCHAR(200) NOT NULL,
  description TEXT,
  nodes JSONB NOT NULL, -- DAG definition
  edges JSONB NOT NULL, -- Connections between nodes
  active BOOLEAN DEFAULT false,
  clinic_id UUID NOT NULL,
  created_by UUID NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Workflow execution
CREATE TABLE executions (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  workflow_id UUID NOT NULL REFERENCES workflows(id),
  status VARCHAR(20) DEFAULT 'queued', -- queued, running, completed, failed, cancelled
  triggered_by VARCHAR(20), -- manual, webhook, schedule
  input JSONB,
  output JSONB,
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  error TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Execution step (each node execution)
CREATE TABLE execution_steps (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  execution_id UUID NOT NULL REFERENCES executions(id),
  node_id VARCHAR(100) NOT NULL,
  node_type VARCHAR(100) NOT NULL,
  status VARCHAR(20) DEFAULT 'pending', -- pending, running, completed, failed, skipped
  input JSONB,
  output JSONB,
  error TEXT,
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  retry_count INT DEFAULT 0
);

-- Indexes
CREATE INDEX idx_workflows_clinic ON workflows (clinic_id);
CREATE INDEX idx_executions_workflow ON executions (workflow_id, created_at DESC);
CREATE INDEX idx_executions_status ON executions (status) WHERE status IN ('queued', 'running');
CREATE INDEX idx_execution_steps_execution ON execution_steps (execution_id, node_id);
```

## Execution Engine

```typescript
class ExecutionEngine {
  async execute(executionId: string): Promise<void> {
    // 1. Load workflow definition
    const execution = await this.loadExecution(executionId);
    const workflow = await this.loadWorkflow(execution.workflowId);

    // 2. Parse DAG
    const dag = this.parseDAG(workflow.nodes, workflow.edges);

    // 3. Execute in topological order
    for (const node of dag.topologicalSort()) {
      // Check if execution is cancelled
      if (await this.isCancelled(executionId)) {
        break;
      }

      // Check if all parent nodes completed
      if (!this.allParentsCompleted(node, dag)) {
        await this.skipNode(executionId, node.id);
        continue;
      }

      // Execute node
      try {
        await this.executeNode(executionId, node);
      } catch (error) {
        // Handle retry
        if (await this.shouldRetry(executionId, node.id)) {
          await this.retryNode(executionId, node);
        } else {
          await this.failNode(executionId, node, error);
          break;
        }
      }
    }

    // 4. Mark execution as completed
    await this.completeExecution(executionId);
  }

  private async executeNode(executionId: string, node: WorkflowNode): Promise<void> {
    // 1. Get input from parent nodes
    const input = await this.getNodeInput(executionId, node.id);

    // 2. Execute based on node type
    let output;
    switch (node.type) {
      case 'http':
        output = await this.executeHTTP(node.config, input);
        break;
      case 'database':
        output = await this.executeDatabase(node.config, input);
        break;
      case 'email':
        output = await this.executeEmail(node.config, input);
        break;
      case 'condition':
        output = await this.evaluateCondition(node.config, input);
        break;
    }

    // 3. Store output
    await this.storeOutput(executionId, node.id, output);
  }
}
```

## Worker Implementation

```typescript
// BullMQ worker for workflow execution
import { Worker, Queue, QueueScheduler } from 'bullmq';

const executionQueue = new Queue('workflow-execution', {
  connection: redis,
  defaultJobOptions: {
    attempts: 3,
    backoff: {
      type: 'exponential',
      delay: 2000
    }
  }
});

const worker = new Worker('workflow-execution', async (job) => {
  const { executionId } = job.data;
  
  // Update status to running
  await prisma.execution.update({
    where: { id: executionId },
    data: { status: 'running', startedAt: new Date() }
  });

  // Execute workflow
  const engine = new ExecutionEngine();
  await engine.execute(executionId);

}, {
  connection: redis,
  concurrency: 10, // Process 10 workflows in parallel
  limiter: {
    max: 100,
    duration: 1000 // Max 100 executions per second
  }
});

// Handle failed jobs
worker.on('failed', async (job, error) => {
  console.error(`Execution ${job.data.executionId} failed:`, error);
  
  await prisma.execution.update({
    where: { id: job.data.executionId },
    data: { 
      status: 'failed', 
      error: error.message,
      completedAt: new Date()
    }
  });
});
```

## Retry Strategy

```typescript
const retryConfig = {
  // Default retry policy
  default: {
    maxRetries: 3,
    backoff: 'exponential',
    baseDelay: 2000, // 2 seconds
    maxDelay: 30000, // 30 seconds
    retryableErrors: ['ECONNRESET', 'ETIMEDOUT', '503', '429']
  },

  // Node-specific retry policies
  nodeTypes: {
    http: {
      maxRetries: 3,
      retryableErrors: ['ECONNRESET', 'ETIMEDOUT', '503']
    },
    email: {
      maxRetries: 5, // Email providers are flaky
      retryableErrors: ['503', '429', 'ECONNRESET']
    },
    database: {
      maxRetries: 2,
      retryableErrors: ['40001'] // Serialization failure
    }
  }
};
```

## Idempotency

```typescript
// Idempotency per node execution
async function executeNodeWithIdempotency(
  executionId: string,
  nodeId: string,
  config: any,
  input: any
): Promise<any> {
  // Check if already executed
  const existing = await prisma.executionStep.findFirst({
    where: {
      executionId,
      nodeId,
      status: 'completed'
    }
  });

  if (existing) {
    return existing.output; // Return cached result
  }

  // Execute
  const output = await executeNode(config, input);

  // Store result
  await prisma.executionStep.upsert({
    where: {
      executionId_nodeId: { executionId, nodeId }
    },
    update: {
      status: 'completed',
      output,
      completedAt: new Date()
    },
    create: {
      executionId,
      nodeId,
      nodeType: config.type,
      status: 'completed',
      input,
      output,
      startedAt: new Date(),
      completedAt: new Date()
    }
  });

  return output;
}
```

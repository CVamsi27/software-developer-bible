# Real-Time Collaboration — System Design Case Study

> **Company-adjacent:** Pitch, Contentful, n8n. Design a real-time collaborative editor where multiple users edit the same document simultaneously.

---


## Requirements

**What are we building?** A real-time collaborative editor (like Google Docs or Figma) where multiple users edit the same document simultaneously. Changes must appear in <100ms, all users must converge to the same final state (conflict-free), and offline edits must sync when reconnected. This is a classic distributed systems problem: two users editing the same line simultaneously must not corrupt the document. The two main approaches are Operational Transformation (OT, used by Google Docs) and CRDTs (Conflict-free Replicated Data Types, used by Figma).


### Functional
- Multiple users edit same document simultaneously
- Changes appear in real-time (< 100ms latency)
- Show who is editing what (cursors, selections)
- Version history with ability to revert
- Conflict resolution (last-write-wins or OT/CRDT)
- Offline support with sync on reconnect

### Non-Functional
- 10K concurrent editors
- < 100ms latency for change propagation
- 99.99% availability
- Conflict-free convergence (all users see same final state)
- Graceful degradation when WebSocket fails

## Conflict Resolution Strategies

### Operational Transformation (OT)
```typescript
// OT: Transform operations against concurrent operations
interface Operation {
  type: 'insert' | 'delete' | 'replace';
  position: number;
  content?: string;
  length?: number;
}

function transform(op1: Operation, op2: Operation): [Operation, Operation] {
  // Transform op1 against op2
  // Both operations are applied, resulting in same state
  
  if (op1.type === 'insert' && op2.type === 'insert') {
    if (op1.position <= op2.position) {
      return [op1, { ...op2, position: op2.position + op1.content!.length }];
    } else {
      return [{ ...op1, position: op1.position + op2.content!.length }, op2];
    }
  }
  
  // Handle other combinations...
}
```

### CRDT (Conflict-free Replicated Data Type)
```typescript
// CRDT: Each character has unique ID, no conflicts
interface CRDTChar {
  id: string; // Unique: userId + timestamp
  value: string;
  parent: string; // ID of character before this one
}

class CRDTDocument {
  private chars: CRDTChar[] = [];

  insert(position: number, value: string, userId: string): void {
    const id = `${userId}-${Date.now()}-${Math.random()}`;
    const parent = position > 0 ? this.chars[position - 1].id : 'root';
    
    this.chars.splice(position, 0, { id, value, parent });
  }

  delete(position: number): void {
    this.chars.splice(position, 1);
  }

  merge(remoteChars: CRDTChar[]): void {
    // Merge remote changes, maintaining order by parent IDs
    // No conflicts possible - operations are commutative
  }
}
```

## WebSocket Protocol

```typescript
// Message types
enum MessageType {
  // Client → Server
  JOIN_DOCUMENT = 'join_document',
  LEAVE_DOCUMENT = 'leave_document',
  OPERATIONS = 'operations',
  CURSOR_UPDATE = 'cursor_update',
  
  // Server → Client
  DOCUMENT_STATE = 'document_state',
  OPERATIONS_BROADCAST = 'operations_broadcast',
  USER_JOINED = 'user_joined',
  USER_LEFT = 'user_left',
  CURSOR_BROADCAST = 'cursor_broadcast'
}

// Client sends operations
interface OperationsMessage {
  type: MessageType.OPERATIONS;
  documentId: string;
  operations: Operation[];
  version: number; // Client's last known version
}

// Server broadcasts to all clients
interface BroadcastMessage {
  type: MessageType.OPERATIONS_BROADCAST;
  documentId: string;
  operations: Operation[];
  version: number; // New version after applying operations
  userId: string; // Who made the change
}
```

## Scaling Collaboration

```typescript
// Redis Pub/Sub for multi-instance scaling
class CollaborationServer {
  private redis: Redis;
  private pubClient: Redis;
  private subClient: Redis;

  constructor() {
    this.pubClient = new Redis();
    this.subClient = new Redis();
    
    // Subscribe to document channels
    this.subClient.on('message', (channel, message) => {
      const { documentId, data } = JSON.parse(message);
      this.broadcastToLocalClients(documentId, data);
    });
  }

  async broadcast(documentId: string, data: any): Promise<void> {
    // Publish to Redis (all instances receive)
    await this.pubClient.publish(
      `document:${documentId}`,
      JSON.stringify({ documentId, data })
    );
  }

  // Each instance only sends to its local WebSocket connections
  private broadcastToLocalClients(documentId: string, data: any): void {
    const clients = this.documentClients.get(documentId) || [];
    clients.forEach(client => client.send(JSON.stringify(data)));
  }
}
```

## Offline Support

```typescript
// Client-side offline handling
class OfflineManager {
  private pendingOps: Operation[] = [];
  private isOnline: boolean = true;

  addOperation(op: Operation): void {
    if (this.isOnline) {
      this.sendToServer(op);
    } else {
      // Queue for later
      this.pendingOps.push(op);
      // Apply locally immediately
      this.applyLocally(op);
    }
  }

  async onReconnect(): Promise<void> {
    // 1. Get current server version
    const serverVersion = await this.getServerVersion();
    
    // 2. Get operations since last sync
    const missedOps = await this.getOperationsSince(this.lastSyncVersion);
    
    // 3. Transform pending ops against missed ops
    const transformedOps = this.transformPendingOps(missedOps);
    
    // 4. Send transformed ops to server
    await this.sendToServer(transformedOps);
    
    // 5. Update local state
    this.lastSyncVersion = serverVersion;
    this.pendingOps = [];
  }
}
```

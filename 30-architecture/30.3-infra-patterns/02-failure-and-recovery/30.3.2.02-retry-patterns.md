# Retry Patterns

> **Exponential backoff, jitter, retry budgets, and when NOT to retry.**

---

## Why Retry Matters

Networks are unreliable. A single HTTP call to an external service (payment gateway, email provider, WhatsApp API) will fail ~0.1-1% of the time due to transient issues. Without retry, every 1000 requests lose 1-10. With retry, you recover most failures.

```
Without Retry:
Request → External Service → Timeout → Lost

With Retry:
Request → External Service → Timeout → Retry 1 → Timeout → Retry 2 → Success 
```

## Retry Strategies

### Strategy 1: Fixed Delay

```typescript
async function retryFixed<T>(fn: () => Promise<T>, retries = 3, delayMs = 1000): Promise<T> {
  for (let i = 0; i <= retries; i++) {
    try {
      return await fn();
    } catch (error) {
      if (i === retries) throw error;
      await sleep(delayMs); // Always 1 second
    }
  }
  throw new Error('Unreachable');
}
```

**Problem:** If the service is down for 30 seconds, all retries hit within 3 seconds — then give up.

### Strategy 2: Exponential Backoff (Recommended)

```typescript
async function retryExponential<T>(
  fn: () => Promise<T>,
  retries = 3,
  baseDelayMs = 1000,
  maxDelayMs = 30000
): Promise<T> {
  for (let i = 0; i <= retries; i++) {
    try {
      return await fn();
    } catch (error) {
      if (i === retries) throw error;

      // Exponential backoff: 1s, 2s, 4s, 8s...
      const delay = Math.min(baseDelayMs * Math.pow(2, i), maxDelayMs);
      console.log(`Attempt ${i + 1} failed, retrying in ${delay}ms...`);
      await sleep(delay);
    }
  }
  throw new Error('Unreachable');
}
```

### Strategy 3: Exponential Backoff + Jitter (Best)

```typescript
async function retryWithJitter<T>(
  fn: () => Promise<T>,
  retries = 3,
  baseDelayMs = 1000,
  maxDelayMs = 30000
): Promise<T> {
  for (let i = 0; i <= retries; i++) {
    try {
      return await fn();
    } catch (error) {
      if (i === retries) throw error;

      // Add jitter to prevent thundering herd
      const delay = Math.min(baseDelayMs * Math.pow(2, i), maxDelayMs);
      const jitter = Math.random() * delay * 0.3; // 0-30% jitter
      const finalDelay = delay + jitter;

      console.log(`Attempt ${i + 1} failed, retrying in ${finalDelay.toFixed(0)}ms...`);
      await sleep(finalDelay);
    }
  }
  throw new Error('Unreachable');
}
```

**Why jitter?** Without jitter, 1000 clients all retry at the same times (1s, 2s, 4s), creating synchronized thundering herds. Jitter randomizes retry times.

## Retry Budgets

A retry budget limits the total number of retries within a time window. This prevents retry storms from overwhelming a failing service.

```typescript
class RetryBudget {
  private retryCount = 0;
  private windowStart = Date.now();
  private readonly maxRetries: number;
  private readonly windowMs: number;

  constructor(maxRetries = 10, windowMs = 60000) {
    this.maxRetries = maxRetries;
    this.windowMs = windowMs;
  }

  canRetry(): boolean {
    const now = Date.now();
    if (now - this.windowStart > this.windowMs) {
      this.windowStart = now;
      this.retryCount = 0;
    }
    return this.retryCount < this.maxRetries;
  }

  recordRetry(): void {
    this.retryCount++;
  }
}

// Usage
const budget = new RetryBudget(10, 60000); // 10 retries per minute

async function resilientCall<T>(fn: () => Promise<T>): Promise<T> {
  for (let i = 0; i <= 3; i++) {
    try {
      return await fn();
    } catch (error) {
      if (i === 3 || !budget.canRetry()) throw error;
      budget.recordRetry();
      await sleep(1000 * Math.pow(2, i));
    }
  }
  throw new Error('Unreachable');
}
```

## When NOT to Retry

| Error Type | Retry? | Why |
| --------------------------- | ------ | ------------------------------------ |
| **400 Bad Request** | No | Client error — retrying won't fix it |
| **401 Unauthorized** | No | Auth failure — need new token |
| **403 Forbidden** | No | Permission denied — won't change |
| **404 Not Found** | No | Resource doesn't exist |
| **422 Unprocessable** | No | Validation error — won't change |
| **429 Too Many Requests** | Maybe | Respect Retry-After header |
| **500 Internal Error** | Yes | Server might recover |
| **502 Bad Gateway** | Yes | Transient proxy error |
| **503 Service Unavailable** | Yes | Server overloaded, may recover |
| **504 Gateway Timeout** | Yes | Transient timeout |
| **ECONNREFUSED** | Yes | Server might be restarting |
| **ECONNRESET** | Yes | Network hiccup |

```typescript
function isRetryable(error: any): boolean {
  // HTTP errors
  if (error.response?.status) {
    const status = error.response.status;
    return status === 429 || status >= 500;
  }

  // Network errors
  if (error.code) {
    return ['ECONNREFUSED', 'ECONNRESET', 'ETIMEDOUT'].includes(error.code);
  }

  return false;
}
```

### Retry with Axios

```typescript
import axios from 'axios';
import RetryAxios from 'retry-axios';

const client = axios.create({
  timeout: 5000,
});

client.interceptors.request.use((config) => {
  config.raxConfig = {
    retry: 3,
    backoffType: 'exponential',
    retryDelay: 1000,
    maxRetries: 3,
    onRetryAttempt: (err) => {
      const cfg = RetryAxios.getConfig(err);
      console.log(`Retry attempt #${cfg.currentRetryAttempt}`);
    },
  };
  return config;
});

RetryAxios.attach(client);
```

## Common Mistakes

| Mistake | Problem | Fix |
| --------------------------------------- | ----------------------------------------- | --------------------------------- |
| **No jitter** | Thundering herd on recovery | Add 30% random jitter |
| **Retrying non-retryable errors** | Wasted resources, longer response | Check status code first |
| **No retry budget** | Retry storm overwhelms recovering service | Limit retries per time window |
| **No timeout** | Retries hang forever | Set per-attempt timeout |
| **Retrying idempotent operations only** | Non-idempotent retries cause duplicates | Use idempotency keys for POST/PUT |

## Interview Questions

**Q: "How do you implement retry with exponential backoff?"**

> Multiply delay by 2 after each failure: 1s, 2s, 4s, 8s. Cap at maxDelay (30s). Add jitter (0-30% random) to prevent thundering herds. Only retry on 5xx or network errors — never on 4xx client errors. Implement a retry budget (max 10 retries per minute) to prevent retry storms from overwhelming a recovering service.

**Q: "When should you NOT retry?"**

> Never retry: 400/401/403/404/422 (client errors — retrying won't fix them), non-idempotent operations without idempotency keys (retry causes duplicates), circuit breaker open (service is confirmed down), or when the retry budget is exhausted. Always retry: 500/502/503/504, ECONNREFUSED/ECONNRESET, and 429 with Retry-After header.

---

## 30-Second Interview Version

> Retry with exponential backoff (1s, 2s, 4s) + jitter (30% random) prevents thundering herds. Only retry on 5xx and network errors — never on 4xx. Implement a retry budget (10 retries/minute) to prevent retry storms. For non-idempotent operations, use idempotency keys before retrying. The formula: delay = min(baseDelay × 2^attempt + random(0, baseDelay × 0.3), maxDelay). Three retries is usually sufficient — if three retries fail, the service is likely down.

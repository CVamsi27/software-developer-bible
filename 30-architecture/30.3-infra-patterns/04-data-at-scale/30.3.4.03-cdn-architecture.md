# CDN Architecture — Edge Caching, Geographic Distribution, Cache Invalidation

> **TL;DR:** **A CDN is a programmable caching layer plus edge compute plus a DDoS shield — not a place static files go.** Correctness lives in the cache key (which query params, headers and cookies vary the response) and the invalidation strategy; hit ratio and origin shielding are the economics; and the senior conversation is always what may be cached, for how long, and how a purge propagates.

---

## First Principles

(→ 40.10 covers operations; the architecture axioms:)

1. **The CDN is a distributed cache with proximity as the product** (→ 20.8.01's axioms at geographic scale): edge caches cut RTT by serving from nearby — the physics argument (→ 30.2.1.20 axiom 1) made into infrastructure.
2. **Cache keys and TTLs are the entire control surface**: versioned URLs for deploys, signed URLs for auth, stale-while-revalidate for freshness-with-speed. Getting keys right is the difference between 95% hit ratio and an origin-killing miss storm.
3. **Origin protection is structural**: request coalescing (one origin fetch per concurrent miss), origin shields, and rate limits — because every cache miss at the edge is an origin request, and popular content's miss storm is the classic outage.

---

## Definition

A **CDN** is a globally distributed caching and delivery layer that terminates client connections at an edge location and serves content from cache, falling back to an **origin** — it exists because the speed of light and origin capacity, not software, bound delivery.

Its behaviour is defined by four mechanisms:

```text
DNS/Anycast ─▶ nearest edge ─▶ cache lookup ─┬─ HIT  ─▶ serve (µs)
                                             └─ MISS ─▶ fetch origin ─▶ store ─▶ serve
                                             (Tier-2: another edge/tier; shielded so the
                                              origin sees 1 request, not N)
Invalidation: TTL expiry │ explicit purge │ versioned/surrogate keys (instant, deterministic)
```

1. **The cache key** is the real design surface — host + path + selected headers/query params (`Vary`). Too narrow a key (cookies, session headers included) makes hit ratio collapse; too wide a key leaks one user's response to another (the classic cache-poisoning bug).
2. **Origin shielding** collapses concurrent misses for the same object into a single origin fetch, protecting the origin during a thundering herd (e.g. a homepage cache expiry).
3. **Invalidation** is where the CDN meets correctness: TTL is eventually-correct, purge is immediate but global and rate-limited, and **versioned or surrogate-keyed URLs** are instant and deterministic — which is why deploying static assets with content hashes in the filename is the default modern practice.
4. **Dynamic content** is handled by tiered caching (micro-cache of a few hundred ms absorbs traffic spikes without serving stale business data) rather than by caching personalization.

## CDN Concepts

**What is a CDN?** A Content Delivery Network is a distributed network of servers (called edge locations) placed close to users worldwide. When a user in Berlin requests your website, instead of the request traveling to your server in the US, it's served from a CDN edge location in Frankfurt — 10ms instead of 150ms. CDNs cache static assets (JS, CSS, images) at the edge. For healthcare apps like Docita, CDNs serve the SPA shell and static assets, but never cache PHI (patient data) at the edge.


| Concept | Description |
| ----------------- | --------------------------------------------------------------------- |
| **Edge Location** | CDN server closest to user (e.g., CloudFront has 400+ edge locations) |
| **Origin** | Your original server (API, S3 bucket, etc.) |
| **Cache Hit** | Request served from edge (fast, ~1-50ms) |
| **Cache Miss** | Request forwarded to origin (slower, ~100-500ms) |
| **TTL** | Time-to-live for cached content |

## CDN Caching Strategies

### Static Assets (JS, CSS, Images)
```typescript
// CloudFront behavior for static assets
const staticAssetsConfig = {
  pathPattern: '/assets/*',
  ttl: {
    minTTL: 86400, // 1 day minimum
    defaultTTL: 31536000, // 1 year (fingerprinted files)
    maxTTL: 31536000
  },
  compress: true,
  viewerProtocolPolicy: 'redirect-to-https'
};

// Vite fingerprinted files
// dist/assets/index-a1b2c3d4.js → long TTL (filename changes on build)
// dist/assets/index-e5f6g7h8.css → long TTL
```

### API Responses
```typescript
// Cache-Control headers for API
const cacheHeaders = {
  // Public data (clinic info, public pages)
  public: 'public, max-age=300, s-maxage=3600',

  // Private data (patient records, appointments)
  private: 'private, no-cache, no-store',

  // Static API responses (lookups, configs)
  static: 'public, max-age=3600, stale-while-revalidate=86400',

  // Never cache (authentication, writes)
  noStore: 'no-store, no-cache, must-revalidate'
};

// Middleware to set cache headers
function setCacheHeaders(req: Request, res: Response, next: NextFunction) {
  const path = req.path;

  if (path.startsWith('/api/public/')) {
    res.setHeader('Cache-Control', cacheHeaders.public);
  } else if (path.startsWith('/api/patients/') || path.startsWith('/api/appointments/')) {
    res.setHeader('Cache-Control', cacheHeaders.private);
  } else if (path.startsWith('/api/config/')) {
    res.setHeader('Cache-Control', cacheHeaders.static);
  } else {
    res.setHeader('Cache-Control', cacheHeaders.noStore);
  }

  next();
}
```

### HTML Pages (SSR/SSG)
```typescript
// Next.js App Router: cache headers live on the response (Route Handlers)
import { NextResponse } from 'next/server';

export async function GET() {
  const data = await getData();
  return NextResponse.json(data, {
    headers: {
      // Cache for 5 minutes, stale-while-revalidate for 1 hour
      'Cache-Control': 'public, s-maxage=300, stale-while-revalidate=3600',
    },
  });
}

// Or for static pages: ISR via the route segment config
// app/products/page.tsx
export const revalidate = 3600; // ISR: revalidate every hour
```

## Cache Invalidation

### Versioned URLs (Best Practice)
```typescript
// Fingerprinted filenames (Vite does this automatically)
// Before: /assets/app.js
// After: /assets/app-a1b2c3d4.js

// HTML references new filename on each build
// CDN caches old version until it expires (long TTL)
// New version has new filename → automatic cache miss → fresh content
```

### Cache Invalidation API
```typescript
// CloudFront invalidation
import { CloudFrontClient, CreateInvalidationCommand } from '@aws-sdk/client-cloudfront';

async function invalidateCDN(patterns: string[]): Promise<void> {
  const client = new CloudFrontClient({ region: 'us-east-1' });

  const command = new CreateInvalidationCommand({
    DistributionId: process.env.CLOUDFRONT_DISTRIBUTION_ID,
    InvalidationBatch: {
      CallerReference: Date.now().toString(),
      Paths: {
        Quantity: patterns.length,
        Items: patterns // e.g., ['/index.html', '/assets/*']
      }
    }
  });

  await client.send(command);
}

// When to invalidate:
// - After deploying new HTML (not needed for fingerprinted assets)
// - After updating static content
// - Emergency cache purge
```

### Stale-While-Revalidate
```typescript
// Serve stale content while refreshing in background
res.setHeader(
  'Cache-Control',
  'public, max-age=60, stale-while-revalidate=300'
);

// Flow:
// 1. User requests content at T+0
// 2. CDN caches for 60 seconds
// 3. At T+61, CDN serves stale content (fast)
// 4. CDN fetches fresh content in background
// 5. Next request gets fresh content
```

## Edge Computing

### Cloudflare Workers
```typescript
// Edge function for A/B testing
addEventListener('fetch', event => {
  event.respondWith(handleRequest(event.request));
});

async function handleRequest(request: Request): Promise<Response> {
  const url = new URL(request.url);

  // A/B test at edge
  const userId = request.headers.get('cf-connecting-ip');
  const bucket = hashCode(userId) % 2;

  if (bucket === 0) {
    // Version A
    return fetch(`https://origin.example.com${url.pathname}`, request);
  } else {
    // Version B
    return fetch(`https://origin-b.example.com${url.pathname}`, request);
  }
}
```

### Vercel Edge Functions
```typescript
// Edge middleware for geo-based routing
export const config = {
  matcher: '/api/:path*'
};

export function middleware(request: NextRequest) {
  const country = request.geo?.country || 'US';

  // Route to nearest API
  const apiEndpoints = {
    EU: 'https://api-eu.docita.work',
    US: 'https://api-us.docita.work',
    DEFAULT: 'https://api.docita.work'
  };

  const endpoint = apiEndpoints[country] || apiEndpoints.DEFAULT;

  return NextResponse.rewrite(new URL(`${endpoint}${request.nextUrl.pathname}`));
}
```

## CDN Performance Metrics

```typescript
const cdnMetrics = {
  // Hit ratio
  hitRatio: 'cache_hits / (cache_hits + cache_misses)',

  // Latency
  edgeLatency: 'p95 latency at edge location',
  originLatency: 'p95 latency at origin',

  // Bandwidth
  bandwidthSaved: 'bytes_served_from_edge / total_bytes',

  // Cost
  costSavings: 'bandwidth_saved * cost_per_gb'
};

// Monitoring queries
const cdnMonitoring = {
  hitRatio: `
    SELECT
      DATE(timestamp) as date,
      SUM(hits) / (SUM(hits) + SUM(misses)) as hit_ratio
    FROM cdn_metrics
    WHERE timestamp > NOW() - INTERVAL '7 days'
    GROUP BY DATE(timestamp)
  `,

  slowOrigins: `
    SELECT
      origin,
      AVG(origin_latency_ms) as avg_latency,
      COUNT(CASE WHEN cache_miss THEN 1 END) as misses
    FROM cdn_requests
    WHERE timestamp > NOW() - INTERVAL '24 hours'
    GROUP BY origin
    HAVING AVG(origin_latency_ms) > 500
  `
};
```

---
## Summary

1. **CDNs are cache + edge compute + DDoS shield** — the caching rules you know (Cache-Control, ETags) apply with new knobs
2. **Origin shield prevents request amplification** — without it, every PoP miss is an origin hit
3. **Invalidation is the hard part** — surrogate keys / cache tags beat path purges for correctness at scale
4. **Stale-while-revalidate is the uptime lever** — serve slightly-stale content rather than an origin outage
5. **Edge functions move personalization to the PoP** — at the cost of new state-management constraints

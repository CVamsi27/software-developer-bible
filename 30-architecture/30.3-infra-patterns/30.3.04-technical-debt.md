# Technical Debt — Identification, Prioritization, Remediation

## Types of Technical Debt

| Type | Description | Example |
|------|-------------|---------|
| **Deliberate/Prudent** | Known trade-off for speed | "We'll clean this up after launch" |
| **Deliberate/Reckless** | No plan to fix | "We don't have time for tests" |
| **Inadvertent/Prudent** | Discovered later | "Now we know the right pattern" |
| **Inadvertent/Reckless** | Didn't know better | "What's dependency injection?" |

### Debt Scoring
```typescript
interface TechnicalDebt {
  id: string;
  description: string;
  type: 'code' | 'architecture' | 'process' | 'documentation';
  
  // Impact (1-5)
  maintainability: number;  // How hard to work around
  reliability: number;      // How likely to cause bugs
  developerExperience: number; // How much it slows development
  
  // Effort (1-5)
  estimatedHours: number;
  requiredSkills: string[];
  dependencies: string[];
  
  // Metadata
  createdBy: string;
  discoveredAt: Date;
  lastModified: Date;
  affectedModules: string[];
}

function calculateDebtScore(debt: TechnicalDebt): number {
  const impact = (debt.maintainability + debt.reliability + debt.developerExperience) / 3;
  const effort = debt.estimatedHours / 40; // Normalize to ~1 week
  
  // Higher score = prioritize first
  return (impact * 2) / (effort + 1);
}
```

## Remediation Strategies

#
## Strangler Fig Pattern

**What is it?** Named after a fig tree that grows around a host tree and eventually replaces it, the strangler fig pattern is a migration strategy: you gradually replace parts of a legacy system with new code, route traffic to the new code for specific features, and eventually the old code has no traffic and can be deleted. Unlike a "big bang" rewrite (which is risky and often fails), this approach is incremental — each small migration is low-risk and independently deployable.

```typescript
// Gradually replace legacy system
class StranglerFig {
  private legacySystem: LegacySystem;
  private newSystem: NewSystem;

  async processRequest(request: Request): Promise<Response> {
    // Check if new system handles this
    if (this.newSystem.canHandle(request)) {
      return this.newSystem.handle(request);
    }
    
    // Fallback to legacy
    return this.legacySystem.handle(request);
  }

  // Gradually move routes to new system
  async migrateRoute(route: string): Promise<void> {
    console.log(`Migrating ${route} to new system`);
    
    // Test new system
    const testResult = await this.testRoute(route);
    if (testResult.success) {
      // Update routing
      this.newSystem.addRoute(route);
      this.legacySystem.removeRoute(route);
    }
  }
}
```

## Branch by Abstraction

**What is it?** When you need to replace an internal implementation (e.g., old payment provider → Stripe), you create an abstract interface, implement both the old and new providers behind it, and use a feature flag to switch between them. This lets you deploy the new code without affecting users, then gradually migrate traffic, then remove the old code. The key: the abstraction layer means you can swap implementations without changing any caller code.

```typescript
// Create abstraction layer
interface PaymentProcessor {
  process(payment: Payment): Promise<PaymentResult>;
}

// Legacy implementation
class LegacyPaymentProcessor implements PaymentProcessor {
  async process(payment: Payment): Promise<PaymentResult> {
    // Old payment logic
  }
}

// New implementation
class StripePaymentProcessor implements PaymentProcessor {
  async process(payment: Payment): Promise<PaymentResult> {
    // New Stripe logic
  }
}

// Feature flag for gradual rollout
class PaymentService {
  constructor(
    private legacy: PaymentProcessor,
    private modern: PaymentProcessor,
    private featureFlags: FeatureFlags
  ) {}

  async processPayment(payment: Payment): Promise<PaymentResult> {
    if (this.featureFlags.isEnabled('use-stripe-payments')) {
      return this.modern.process(payment);
    }
    return this.legacy.process(payment);
  }
}
```

### Parallel Running
```typescript
// Run both old and new systems, compare results
class ParallelRunner {
  async processWithComparison(request: Request): Promise<Response> {
    const [legacyResult, newResult] = await Promise.all([
      this.legacySystem.handle(request),
      this.newSystem.handle(request)
    ]);
    
    // Compare results
    if (!this.resultsMatch(legacyResult, newResult)) {
      console.error('Results mismatch', { legacyResult, newResult });
      this.metrics.increment('parallel_run_mismatch');
    }
    
    // Return legacy result (safe default)
    return legacyResult;
  }
}
```

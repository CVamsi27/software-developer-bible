# Event Sourcing & CQRS — Patterns, Implementation, Trade-offs

## What is Event Sourcing?

Event Sourcing stores state as a sequence of events rather than the current state. Instead of updating a row, you append an event to an event log.

### Traditional vs Event Sourcing

```
Traditional (Current State):
  appointments table:
    id: 1, status: 'confirmed', patient_id: 'abc'
  
  UPDATE appointments SET status = 'cancelled' WHERE id = 1;
  -- Old state is LOST

Event Sourcing (Event Log):
  events table:
    1. { type: 'APPOINTMENT_CREATED', data: { patient_id: 'abc' } }
    2. { type: 'APPOINTMENT_CONFIRMED', data: {} }
    3. { type: 'APPOINTMENT_CANCELLED', data: { reason: 'patient request' } }
  
  -- Full history is PRESERVED
  -- Current state is derived by replaying events
```

### When to Use Event Sourcing

| Use Case | Why Event Sourcing |
|----------|-------------------|
| **Audit trail** | Full history of changes (healthcare, finance) |
| **Temporal queries** | "What was the state at time T?" |
| **Debugging** | Replay events to reproduce bugs |
| **CQRS** | Separate read/write models |
| **Collaboration** | Resolve conflicts via event ordering |

### When NOT to Use Event Sourcing

| Use Case | Why Not |
|----------|---------|
| **Simple CRUD** | Overhead not justified |
| **High write volume** | Event store becomes bottleneck |
| **Simple queries** | Projection overhead unnecessary |

## What is CQRS?

CQRS (Command Query Responsibility Segregation) separates read and write models.

### Traditional vs CQRS

```
Traditional:
  Client → API → Database (same model for reads and writes)
  
CQRS:
  Client → API → Write Model → Events → Read Model → API → Client
  
  Write side: Optimized for writes (normalized, indexed)
  Read side: Optimized for reads (denormalized, cached)
```

### CQRS Architecture

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Command    │────▶│  Write DB   │────▶│   Events    │
│   Handler    │     │ (PostgreSQL)│     │   (Kafka)   │
└─────────────┘     └─────────────┘     └──────┬──────┘
                                                │
                                                ▼
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   Query     │◀────│  Read DB    │◀────│  Projector  │
│   Handler   │     │  (Redis)    │     │  (Worker)   │
└─────────────┘     └─────────────┘     └─────────────┘
```

## Implementation Example

### Event Store

```sql
CREATE TABLE events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  aggregate_id UUID NOT NULL,  -- Which entity this event belongs to
  aggregate_type VARCHAR(50) NOT NULL,  -- 'Appointment', 'Patient', etc.
  event_type VARCHAR(100) NOT NULL,  -- 'APPOINTMENT_CREATED', etc.
  payload JSONB NOT NULL,  -- Event data
  metadata JSONB,  -- Correlation ID, causation ID, user ID
  version INT NOT NULL,  -- Optimistic concurrency
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  
  -- Optimistic concurrency: one event per version per aggregate
  UNIQUE(aggregate_id, version)
);

-- Query events for an aggregate
SELECT * FROM events 
WHERE aggregate_id = 'appointment-123' 
ORDER BY version ASC;
```

### Event Types

```typescript
interface AppointmentCreated {
  type: 'APPOINTMENT_CREATED';
  aggregateId: string;
  payload: {
    patientId: string;
    practitionerId: string;
    clinicId: string;
    slotStart: Date;
    slotEnd: Date;
  };
}

interface AppointmentConfirmed {
  type: 'APPOINTMENT_CONFIRMED';
  aggregateId: string;
  payload: {};
}

interface AppointmentCancelled {
  type: 'APPOINTMENT_CANCELLED';
  aggregateId: string;
  payload: {
    reason: string;
    cancelledBy: string;
  };
}

type AppointmentEvent = AppointmentCreated | AppointmentConfirmed | AppointmentCancelled;
```

### Aggregate (Event Sourced)

```typescript
class Appointment {
  private events: AppointmentEvent[] = [];
  
  // Command: create appointment
  create(dto: CreateAppointmentDto): void {
    this.apply({
      type: 'APPOINTMENT_CREATED',
      aggregateId: this.id,
      payload: dto,
    });
  }
  
  // Command: confirm appointment
  confirm(): void {
    if (this.status !== 'created') {
      throw new Error('Can only confirm created appointments');
    }
    this.apply({
      type: 'APPOINTMENT_CONFIRMED',
      aggregateId: this.id,
      payload: {},
    });
  }
  
  // Command: cancel appointment
  cancel(reason: string, cancelledBy: string): void {
    if (this.status === 'cancelled') {
      throw new Error('Already cancelled');
    }
    this.apply({
      type: 'APPOINTMENT_CANCELLED',
      aggregateId: this.id,
      payload: { reason, cancelledBy },
    });
  }
  
  // Apply event to state
  private apply(event: AppointmentEvent): void {
    this.events.push(event);
    this.applyEvent(event);
  }
  
  // Rebuild state from events
  private applyEvent(event: AppointmentEvent): void {
    switch (event.type) {
      case 'APPOINTMENT_CREATED':
        this.status = 'created';
        this.patientId = event.payload.patientId;
        break;
      case 'APPOINTMENT_CONFIRMED':
        this.status = 'confirmed';
        break;
      case 'APPOINTMENT_CANCELLED':
        this.status = 'cancelled';
        break;
    }
  }
  
  // Rebuild from event history
  static fromEvents(events: AppointmentEvent[]): Appointment {
    const appointment = new Appointment();
    events.forEach(event => appointment.applyEvent(event));
    return appointment;
  }
}
```

### Projector (Read Model)

```typescript
class AppointmentProjector {
  async project(event: AppointmentEvent): Promise<void> {
    switch (event.type) {
      case 'APPOINTMENT_CREATED':
        await prisma.appointmentReadModel.create({
          data: {
            id: event.aggregateId,
            patientId: event.payload.patientId,
            status: 'created',
            slotStart: event.payload.slotStart,
            version: 1,
          },
        });
        break;
      
      case 'APPOINTMENT_CONFIRMED':
        await prisma.appointmentReadModel.update({
          where: { id: event.aggregateId },
          data: { status: 'confirmed' },
        });
        break;
      
      case 'APPOINTMENT_CANCELLED':
        await prisma.appointmentReadModel.update({
          where: { id: event.aggregateId },
          data: { status: 'cancelled' },
        });
        break;
    }
  }
}
```

## Trade-offs

| Aspect | Traditional | Event Sourcing |
|--------|-------------|----------------|
| **Complexity** | Low | High |
| **Audit trail** | Manual (audit logs) | Automatic (event log) |
| **Temporal queries** | Hard (need history table) | Easy (replay events) |
| **Storage** | Current state only | All history |
| **Query performance** | Good | Requires projections |
| **Debugging** | Hard | Easy (replay events) |
| **Migration** | Schema changes | Event versioning |

## Interview Tips

- **Q: When would you use Event Sourcing?**
  - Audit trail required (healthcare, finance)
  - Temporal queries needed ("what was the state at time T?")
  - Complex domain with many state transitions
  - CQRS pattern for read/write optimization

- **Q: How do you handle event versioning?**
  - Upcasting: transform old events to new schema
  - Weak schema: use JSONB for flexible payload
  - Event migration: backfill new fields

- **Q: How do you handle eventual consistency?**
  - Read-your-writes: check version after write
  - Causal consistency: pass version in context
  - UI feedback: show "processing" state

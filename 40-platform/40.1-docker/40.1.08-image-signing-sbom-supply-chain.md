# Image Signing, SBOM & Supply Chain Security

## TL;DR

Everything your container runs was produced by someone else: base images, dependencies, CI runners, registries. **Supply chain security** makes that chain verifiable — **cosign** signs images (and attestations), **SBOMs** (syft / BuildKit attestations) inventory what is inside, **SLSA** grades how tamper-resistant the build was, and admission policies enforce all of it at deploy time.

**Why it matters:** Senior interviews increasingly include "how do you know the image you deployed is the one your CI built?" Answers that mention signing, provenance, SBOM gating, and registry policy signal production-grade thinking beyond CVE scanning.

## Definition

**Container supply chain security** is the set of controls that lets a cluster answer three questions before running an image:

- **Integrity/authenticity** — Who built and published this digest, and has anything changed since? → cryptographic signatures (**cosign/Sigstore**).
- **Composition** — What exactly is in this image (packages, libraries, licenses)? → **SBOM** (Software Bill of Materials) via **syft**, **Trivy**, or BuildKit **attestations**.
- **Process** — Was it built by a trustworthy pipeline from the declared source at the declared commit? → **provenance** attestations graded by **SLSA levels**.

```text
THREAT MODEL: WHERE IMAGES GET COMPROMISED
═══════════════════════════════════════════
 [source repo]──build CI──push──registry──pull/admit──runtime
      │            │         │        │          │
   malicious     runner    stolen   tag       unsigned/
   PR or dep     hijack    creds    mutated /  spoofed
   injected      or dirty  or weak  digest     image pulled
                 cache     ACLs     rewritten  by cluster
```

## Why Do We Need It?

| Problem                                                        | Solution                                                              |
| -------------------------------------------------------------- | --------------------------------------------------------------------- |
| Attacker pushes a backdoored tag to your registry              | Sign at build; verify signature before admission                      |
| `latest` mutable tags make "what is running?" unanswerable     | Deploy by immutable digest; sign the digest                           |
| Compromised CI produces a valid-looking image                  | Provenance attestation ties image to source commit + builder identity |
| Zero-day drops; you must find every service using log4j/xz     | SBOM query answers "where is X?" in minutes, not weeks                |
| Compliance (EO 14028, PCI, SOC2) demands software transparency | SLSA level + SBOM + signatures are auditable evidence                 |
| Developers pull random public images                           | Registry allowlist + pull-through cache + signature verification      |

## How It Works

### Sigstore Keyless Signing Model

Cosign's keyless mode removes long-lived keys from developers/CI:

```text
┌──────────────────────────────────────────────┐
│ CI   │                             │                  │
│ job  │ ◀────────────────────────── │ (CA)             │
└──────────────────────────────────────────────┘
   │ 2. push signature + cert to OCI registry (attached to digest)
   ▼
┌───────────────────────────────────────────────┐
│ Rekor    │ ◀──record signed entry── │ cosign           │
│ (log)    │                          │ sign             │
└───────────────────────────────────────────────┘

Verify = check sig against cert + cert against OIDC identity +
         entry exists in tamper-evident Rekor log.
```

### What Gets Signed — Digests, Not Tags

```text
WRONG:  cosign sign myregistry/myapp:latest
        → latest moves; signature verifies whatever lands there next.

RIGHT:  myregistry/myapp@sha256:abc123...   ← content address
        Tag → digest resolution happens ONCE at build/push;
        deployments and admission policies pin the digest.
```

### SBOM Generation Paths

```text
Option A: post-build scan (works with any existing image)
   syft myregistry/myapp:1.4.2 -o spdx-json > sbom.spdx.json

Option B: build-time attestation (BuildKit ≥ 0.11, docker buildx)
   docker buildx build --sbom=true --provenance=mode=max \
     --push -t myregistry/myapp:1.4.2 .
   → SBOM + provenance stored IN the registry as OCI artifacts,
     attached to the image manifest — no separate storage to leak.

Formats: SPDX (ISO standard, ecosystem-wide) vs CycloneDX
         (security-tooling friendly). Both readable by Grype/Trivy.
```

### SLSA Provenance Levels

SLSA (Supply-chain Levels for Software Artifacts) grades build integrity:

| Level              | Guarantee                                           | Example                                    |
| ------------------ | --------------------------------------------------- | ------------------------------------------ |
| L0                 | No guarantees                                       | Laptop builds, curl pipe-to-shell installs |
| L1                 | Provenance EXISTS (documents how it was built)      | CI emits attestation, but may be forgeable |
| L2                 | Hosted build platform generates signed provenance   | GitHub Actions + BuildKit attestations     |
| L3                 | Hardened, isolated builds; provenance non-forgeable | Isolated ephemeral builders, sealed caches |
| L4+ (v1.0 roadmap) | Two-person review, reproducible builds              | Org-level process requirements             |

Most orgs realistically target **L2/L3 for tier-1 services**: signed provenance from a hosted builder, verified at admission.

### Enforcement Points

```text
1. ADMISSION (cluster): Kyverno/Gatekeeper verify signature +
   provenance issuer + SBOM present BEFORE pod creation.

2. REGISTRY POLICY: Harbor/ECR/GAR rules — immutable tags,
   deny unsigned pushes, allowlisted upstream mirrors only.

3. CI GATE: verify base-image signature + scan SBOM against
   policy (fail on critical CVEs / banned licenses) pre-push.

4. RUNTIME DRIFT CHECK: periodic re-verify of what actually runs
   vs what was admitted (detects out-of-band changes).
```

## Code Examples

### Signing and Verifying With Cosign

```bash
# Install cosign, then sign keyless (CI identity via OIDC)
COSIGN_EXPERIMENTAL=1 cosign sign --yes \
  myregistry.io/team/myapp@sha256:9f86d081884c7d65...

# Verify: identity + issuer + optional transparency log check
cosign verify \
  --certificate-identity-regexp 'https://github.com/org/myapp/.github/workflows/release.yml@refs/tags/v.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  myregistry.io/team/myapp@sha256:9f86d081884c7d65...

# Attach an SBOM as an attestation
syft myregistry.io/team/myapp@sha256:9f86... -o cyclonedx-json > sbom.json
cosign attest --yes --predicate sbom.json --type cyclonedx \
  myregistry.io/team/myapp@sha256:9f86...

# Verify the attestation too
cosign verify-attestation --type cyclonedx \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  myregistry.io/team/myapp@sha256:9f86...
```

### Generating SBOMs

```bash
# Syft: catalog any image, dir, or lockfile set
syft packages myregistry.io/team/myapp:1.4.2 -o spdx-json > app.sbom.json
syft packages dir:. -o cyclonedx-json > src.sbom.json   # even without Docker

# Query it: are we exposed to a specific component?
jq '.packages[] | select(.name | test("xz|log4j")) | {name, versionInfo}' app.sbom.json

# Vulnerability-match the SBOM with Grype
grype sbom:app.sbom.json --fail-on high
```

### BuildKit Attestations at Build Time

```bash
docker buildx create --use --name secure-builder
docker buildx build \
  --provenance=mode=max \        # full recipe: source ref, commit, materials
  --sbom=true \                  # generated from the final image contents
  --push -t myregistry.io/team/myapp:1.4.2 .

# Inspect attestations attached in-registry
docker buildx imagetools inspect myregistry.io/team/myapp:1.4.2
# → attestation-manifest entries: provenance, sbom
```

The resulting provenance document includes: `builder.id`, `source` (repo + commit), `materials` (base image digests), invocation parameters — machine-checkable claims about *how* the artifact came to be.

### Kubernetes Admission Enforcement (Kyverno)

```yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: verify-images
spec:
  validationFailureAction: Enforce
  webhookTimeoutSeconds: 30
  rules:
    - name: check-signature-sbom-provenance
      match:
        any:
          - resources:
              kinds: [Pod]
              namespaces: ["prod"]
      verifyImages:
        - imageReferences: ["myregistry.io/team/*"]
          mutateDigest: true                      # rewrite tag → digest
          verifyDigest: true
          requiredAnnotations:
            vendor.example.com/approved: "true"
          attestors:
            - entries:
                - keyless:
                    subject: "https://github.com/org/myapp/*"
                    issuer: "https://token.actions.githubusercontent.com"
                    rekor:
                      url: https://rekor.sigstore.dev
          attestations:
            - type: https://slsa.dev/provenance/v0.2
              conditions:
                - all:
                    - key: "{{ builder.id }}"
                      operator: Equals
                      value: "https://github.com/slsa-framework/slsa-github-generator/.github/workflows/generator_container_slsa3.yml@refs/tags/v1.9.0"
```

### Verifying in CI Before Deploy

```yaml
# .github/workflows/deploy.yml — gate deployment on verification
jobs:
  verify-supply-chain:
    runs-on: ubuntu-latest
    permissions:
      id-token: write        # OIDC for keyless verification
      contents: read
    steps:
      - uses: actions/checkout@v4

      - name: Resolve immutable digest
        id: img
        run: |
          DIGEST=$(docker buildx imagetools inspect "$REGISTRY/$IMAGE:$TAG" \
            --format '{{json .Manifest.Digest}}' | tr -d '"')
          echo "ref=$REGISTRY/$IMAGE@$DIGEST" >> "$GITHUB_OUTPUT"

      - name: Verify signature
        run: |
          cosign verify \
            --certificate-identity-regexp "^https://github.com/org/repo/" \
            --certificate-oidc-issuer https://token.actions.githubusercontent.com \
            "${{ steps.img.outputs.ref }}"

      - name: Require SBOM + provenance attestations
        run: |
          cosign verify-attestation --type sbom/cyclonedx "${{ steps.img.outputs.ref }}"
          cosign verify-attestation --type slsa/provenance  "${{ steps.img.outputs.ref }}"

      - name: Fail on critical vulnerabilities
        run: grype "${{ steps.img.outputs.ref }}" --fail-on critical

      - name: Deploy pinned digest
        run: kubectl set image deploy/myapp \
          myapp="${{ steps.img.outputs.ref }}"
```

### Registry-Side Policy (Harbor Example)

```bash
# Harbor project settings enforced server-side:
#   Content trust: require signed images for pull
#   Tag immutability: v* patterns immutable once pushed
#   Quota + vulnerability policy: block pull when severity >= High
# AWS ECR equivalent: ECR basic scanning + enhanced scanning,
#   plus immutable tags per repository configuration.
aws ecr put-image-tag-mutability \
  --repository-name team/myapp \
  --image-tag-mutability IMMUTABLE
```

## Real-World Use Cases

### 1. The xz-Style Backdoor Scenario

A compromised dependency ships subtly malicious code. Without SBOMs you audit by memory and grep. With them:

```bash
for ns in prod staging; do
  kubectl get pods -n $ns -o json | jq -r '..|.image? // empty' | sort -u
done > deployed-images.txt
while read -r img; do syft "$img" -o json | jq -r '.artifacts[].name'; done \
  < deployed-images.txt | sort -u | grep -n xz
```

### 2. Multi-Team Platform With a Private Registry

Platform team configures Harbor: pulls from Docker Hub only via an allowlisted pull-through mirror, requires signatures for `prod/*` projects, blocks unsigned pushes. Application teams inherit enforcement without touching their pipelines — the registry becomes the choke point.

### 3. Auditable Releases for Regulated Workloads

Each release produces: signed digest + provenance attestation (builder, commit, base image digests) + SPDX SBOM archived with the release. An auditor can reconstruct exactly what shipped and how, months later, without trusting anyone's memory.

### 4. Blocking a Stolen CI Credential From Shipping Malware

Even with leaked tokens, an attacker cannot produce a valid SLSA L3 provenance attestation from outside the hardened builder, so admission verification rejects their push regardless of a valid registry credential.

## Common Mistakes

| Mistake                                                 | Fix                                                                     |
| ------------------------------------------------------- | ----------------------------------------------------------------------- |
| Signing a mutable tag (`:latest`)                       | Sign digests; resolve tag→digest once and pin everywhere                |
| Verifying only locally/manually ("we ran cosign once")  | Enforce at admission (Kyverno/Gatekeeper) — humans forget               |
| SBOM generated but never queried or gated               | Wire SBOM into CI gates (grype --fail-on) and incident playbooks        |
| Treating CVE scanning as supply-chain security complete | Scanning covers known vulns only; signatures/provenance cover tampering |
| Long-lived cosign keys pasted into CI secrets           | Use keyless OIDC signing or KMS-backed keys with rotation               |
| Allowing arbitrary public bases (`FROM anything`)       | Allowlist base images through a curated internal mirror                 |

## Best Practices

1. **Pin and deploy by digest** — tags are pointers, not identities; make admission rewrite tags to digests.
2. **Sign in the same trusted pipeline that builds** — the signer identity IS the guarantee; signing elsewhere adds no trust.
3. **Emit both SBOM and provenance as registry attestations** — they travel with the image and need no extra infrastructure.
4. **Start enforcement in audit mode** — run Kyverno policy as `Audit`, review violations, then flip to `Enforce`.
5. **Curate the bottom of the stack** — approved base images with automated rebuilds matter more than scanning your own code.
6. **Practice the recall drill** — given component X at version Y, produce the list of affected workloads in under 15 minutes; timebox it like a game day.

## Performance Considerations

| Aspect                                      | Cost                       | Mitigation                                                                |
| ------------------------------------------- | -------------------------- | ------------------------------------------------------------------------- |
| Admission webhook verifying signatures      | ~100-500ms per new pod     | Cache verification results per digest; batch rollouts                     |
| SBOM cataloging large images                | Seconds-minutes per image  | Build-time attestations amortize into the build                           |
| Registry storing attestations               | Small JSON manifests       | Negligible; keep mode=max provenance for release builds only if huge      |
| Keyless verification requiring Rekor lookup | Network round-trip         | Regional Rekor mirrors; tolerate brief unavailability via offline bundles |
| Policy complexity                           | Webhook latency under load | Scope match rules narrowly (namespace/image prefixes)                     |

## Summary

Supply chain security converts trust-in-people into trust-in-cryptography-and-process. Sign every production image with cosign (keyless where possible), attach SBOM and provenance as BuildKit attestations, grade your build integrity against SLSA (target L2-L3 for critical services), and enforce all of it where it counts — at admission and in CI gates — while deploying immutable digests. Scanners tell you what is broken inside an image; signatures, SBOMs, and provenance tell you whether you can trust the image at all.

## Cheat Sheet

```text
SUPPLY CHAIN CHEAT SHEET
════════════════════════

SIGN:
• cosign sign --yes REG/IMG@sha256:DIGEST     keyless sign
• cosign verify --certificate-identity-regexp '...' \
               --certificate-oidc-issuer '...' REG/IMG@DIGEST
• Never sign :tags — sign digests only

SBOM:
• syft IMG -o spdx-json > sbom.json           post-build
• docker buildx build --sbom=true --provenance=mode=max \
    --push ...                                in-registry attestations
• grype sbom:sbom.json --fail-on high         gate on vulns

PROVENANCE / SLSA:
• L1 provenance exists · L2 hosted+signed · L3 hardened builder
• Verify: cosign verify-attestation --type slsa/provenance ...

ENFORCE:
• Kyverno verifyImages (mutateDigest + keyless attestors)
• Registry: immutable tags, unsigned-push deny, allowlist mirrors
• CI: verify → attest-check → grype gate → deploy @digest

INCIDENT RECALL:
• syft each deployed image → grep component name
• kubectl get pods -o json | jq -r '..|.image? // empty'

ORDER OF TRUST:  digest → signature → provenance → SBOM → scan
```

# Media Optimization at the Edge

If a page always sends a 4000-pixel source for a 400 CSS-pixel card, the browser downloads pixels that the layout will usually downscale. If the transform service accepts arbitrary widths, the same card can create many distinct misses. Media delivery has to choose a useful representation, bound variants and keep access checks separate from byte reuse.

## Definition

**Media optimization at the edge** selects, transforms or delivers suitable image and video representations through a distributed delivery layer. The original source remains authoritative; derived representations may be generated during a build, on upload, on demand at an origin, or through a provider's image service. They do not have to be encoded in every edge location.

> **Textbook Definition:** Media optimization transforms and delivers representations selected for consumer capabilities, dimensions, quality and bandwidth, with caching and access policies that preserve representation identity and authorization.

A **rendition** is one encoded representation. An **adaptive bitrate (ABR) ladder** offers several video renditions so a player can change its choice as bandwidth and buffer state change. A **manifest** describes available tracks/segments. **HLS** (HTTP Live Streaming) and **DASH** (Dynamic Adaptive Streaming over HTTP) are streaming delivery formats.

## First Principles

A source image can be much larger than the slot that displays it, while aggressive compression can destroy visible detail. Choose dimensions and encoding from visual quality, device support, transferred bytes and decode cost; a format name does not guarantee a universal saving.

A transformed output depends on the source revision, transformation policy and request inputs. Reusing it is correct only when those inputs resolve to the same bytes. Include source and policy versions in the key, then normalize dimensions, quality, crop and format before both rendering and lookup. Unbounded combinations create unbounded work and cache identities.

Private bytes create an independent boundary: possession of a cache entry is not permission to return it. Verify authorization before every protected hit as well as a miss. Removing credentials from an internal content key is safe only if the enforcement path cannot be bypassed.

## Choose and identify an image variant

For responsive images, `srcset` lists candidate files and their intrinsic widths; `sizes` describes the rendered slot. The browser chooses a candidate using those hints, viewport and display density. Explicit dimensions reserve layout space while the image loads.

```html
<img
  src="/media/cover-960.jpg"
  srcset="/media/cover-480.jpg 480w, /media/cover-960.jpg 960w"
  sizes="(max-width: 600px) 100vw, 50vw"
  width="960" height="640" alt="Product cover"
>
```

An image service may instead transform a source on demand. Its pipeline should make the representation choice explicit:

```text
source identity + validated dimensions/quality + selected supported format
   → representation key
   → eligible hit: return stored bytes with matching metadata
   → miss: transform, validate successful output, store under that key
```

The selected format must respect the consumer's capabilities and `Accept` preferences, including `q=0`, which means the format is not acceptable. A substring search for `image/avif` is not complete HTTP negotiation. Keep the resolved format in the provider key and send the appropriate `Vary: Accept` response policy for downstream caches. `Vary` alone does not make every custom CDN key respect that dimension; verify the CDN's configured key as well. See [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-accept).

### Normalize a small public variant policy

This standalone TypeScript helper normalizes a deliberately narrow public-image policy for one configured source origin. The catalog maps each allowed path to a source revision; the key also includes a transform-policy version. The caller supplies an already-negotiated format. This is not a Worker, image renderer, arbitrary-source fetcher or full `Accept` parser. For multiple origins, use a stable source ID that includes the origin rather than keying by path alone.

```typescript
export function imageVariant(
  url: URL, format: 'avif' | 'webp' | 'jpeg', sources: ReadonlyMap<string, string>,
): { key: string; width: number; quality: number; format: string } {
  if (url.origin !== 'https://images.example.com') throw new Error('Unexpected source origin');
  const sourceRevision = sources.get(url.pathname);
  if (!sourceRevision) throw new Error('Unknown source');
  if (!['avif', 'webp', 'jpeg'].includes(format)) throw new Error('Unsupported format');
  for (const name of url.searchParams.keys()) {
    if (!['w', 'quality', 'utm_source'].includes(name)) throw new Error('Unknown parameter');
    if (url.searchParams.getAll(name).length !== 1) throw new Error('Repeated parameter');
  }
  const widthText = url.searchParams.get('w') ?? '960';
  const qualityText = url.searchParams.get('quality') ?? '80';
  if (!/^\d+$/.test(widthText) || !/^\d+$/.test(qualityText)) throw new Error('Invalid number');
  const requested = Number(widthText);
  const quality = Number(qualityText);
  if (!Number.isSafeInteger(requested) || requested <= 0 || requested > 1920) {
    throw new Error('Width outside policy');
  }
  if (![60, 80].includes(quality)) throw new Error('Quality outside policy');
  const width = [320, 480, 640, 960, 1280, 1920].find(value => value >= requested)!;
  return {
    key: JSON.stringify([url.pathname, sourceRevision, 'image-policy-v1', width, quality, format]),
    width, quality, format,
  };
}
```

For an allowed `/img/hero.a1b2.jpg`, `?w=420&quality=80` resolves to width 480. Changing parameter order or `utm_source` preserves the key; changing the source revision, policy version or selected format changes it. The renderer must use exactly the normalized values in the key—it must not render width 420 while storing under width 480. The bucket set and quality choices are an example policy, not universal defaults.

The catalog establishes the source boundary for this example. A multi-tenant design needs its own tenant and access identity. Only mark an output immutable when the source and transform policy guarantee that its bytes cannot change. Do not cache a renderer error, wrong content type or incomplete body as a successful immutable image. Cloudflare's [image transformation parameters](https://developers.cloudflare.com/images/optimization/features/) illustrate one provider's supported options and limits.

## Signed Access Is Separate from Content Identity

A signed URL is a bearer capability: anyone holding it can use its granted scope until policy or expiry rejects it. Expiry limits replay time; it does not prevent sharing or prove a user's current entitlement. Protect signing keys, URLs/logs and direct-origin access. Removing a signing key revokes tokens made with it; revoking one token earlier requires an online policy check or a revocation list.

The following Node.js primitive signs one cataloged path and expiry. Issue it only after entitlement checks. The verifier receives parsed canonical fields and must run before **every** protected cache lookup. It is not a complete CDN deployment or a one-use token protocol.

```typescript
import { createHmac, timingSafeEqual } from 'node:crypto';

export function mediaSignature(path: string, expires: number, key: Buffer): string {
  if (key.length < 32) throw new Error('Use a securely generated signing key');
  if (!Number.isSafeInteger(expires) || expires <= 0) throw new Error('Invalid expiry');
  return createHmac('sha256', key).update(JSON.stringify([path, expires])).digest('hex');
}

export function verifyMedia(
  path: string, expires: number, signature: string, key: Buffer,
  allowedPaths: ReadonlySet<string>, nowSeconds: number,
): boolean {
  if (!Number.isFinite(nowSeconds) || !allowedPaths.has(path)) return false;
  if (!Number.isSafeInteger(expires) || expires <= nowSeconds) return false;
  if (!/^[0-9a-f]{64}$/.test(signature)) return false;
  const supplied = Buffer.from(signature, 'hex');
  const expected = Buffer.from(mediaSignature(path, expires, key), 'hex');
  return timingSafeEqual(supplied, expected); // equal-length byte buffers
}
```

An altered path or expiry must fail. An expired or malformed signature returns false. Invalid server key configuration is an operational error. Bind any additional grant fields—tenant, allowed transformation, disposition or scope—into a canonical signed payload when they affect authorization. Parse duplicate/ambiguous URL fields consistently before invoking the primitive.

After verification, an internal content key may omit expiry/signature when authorized callers receive exactly the same bytes. The public delivery path must still verify every request before returning that shared entry, including a cache hit. Set browser cache lifetime within the access policy or use `no-store` when local reuse after expiry is not allowed. Changing token expiry does not recall bytes already downloaded. Cross-Origin Resource Sharing (CORS) and Referer checks do not establish entitlement.

## Video Delivery Uses a Different Pipeline

Video follows a separate pipeline. Encode a suitable source into supported resolution/bitrate renditions, then package them as a manifest and media segments. The manifest declares available tracks; the player estimates bandwidth and buffer health, chooses a rendition, fetches segments and adapts. Encoding usually happens before delivery; the CDN distributes the resulting objects rather than performing the full video encode at each edge. Apple's [HLS authoring specification](https://developer.apple.com/documentation/http-live-streaming/hls-authoring-specification-for-apple-devices/) gives current device and playlist constraints.

The ladder, codec support, segment duration and startup choice affect quality and buffering. Common Media Application Format (CMAF) can let compatible HLS/DASH configurations share media segments; Apple's [CMAF guidance](https://developer.apple.com/documentation/http-live-streaming/about-the-common-media-application-format-with-http-live-streaming-hls/) describes its use with HLS. Verify codec, encryption and manifest requirements before reusing segments.

On-demand versioned segments can have a long eligible cache policy. A live manifest changes as segments appear and needs a different freshness policy. Low-latency delivery introduces parts and protocol/player requirements; there is no universal two-second end-to-end latency. Apply the access and freshness policy to each protected manifest, segment and Digital Rights Management (DRM) license; they are separate resources.

A browser can use native HLS where supported or a compatible library such as [hls.js](https://github.com/video-dev/hls.js/blob/master/docs/API.md). Handle unsupported playback, errors and token renewal; destroy a library instance when detaching it. Set a deliberate startup cap in bitrate or resolution terms—a raw ladder index has no stable meaning across different encodings.

## Place transformation work where it fits

Pre-generate build assets or predictable hot renditions when that reduces request-time work at acceptable storage cost. Transform on upload when content and likely sizes are known. Use bounded on-demand transformations for a measured long tail. None is universally best: compare transform cost, cache reuse, storage, deployment complexity and miss-path capacity.

Do not lazy-load the likely Largest Contentful Paint (LCP) image if that delays discovery; lazy loading can suit offscreen media. Measure transfer bytes, transform latency/cache hits, decode time, layout stability and visual quality. Smaller files alone do not prove a faster or better page.

Codec, quality and transfer savings depend on source content, device support and the encoder. Benchmark representative files and devices, and compare image/video quality, startup time, rebuffering and total delivery cost. A lab result on one codec or network is not a universal saving.

## Summary

Media delivery selects representations that fit the client and request. Bound transformation inputs and include source/policy versions in cache identity; authorize every protected hit. Treat image rendering, video manifests, segments and licenses as distinct resources with freshness and access rules that fit their role.

# Media Optimization at the Edge

Sending a 4000-pixel image into a 400-pixel card wastes bytes. Generating a new image for every arbitrary width can waste transform work instead. Media delivery balances suitable representations with a bounded set of outputs, correct cache identity and access decisions.

## Definition

**Media optimization at the edge** selects, transforms or delivers suitable image/video representations through a distributed delivery layer. The original source remains authoritative; derived representations may be generated during a build, on upload, on demand at an origin, or through a provider's image service. They do not have to be encoded in every edge location.

> **Textbook Definition:** Media optimization transforms and delivers representations selected for consumer capabilities, dimensions, quality and bandwidth, with caching and access policies that preserve representation identity and authorization.

A **rendition** is one encoded representation. An **adaptive bitrate (ABR) ladder** offers several video renditions so a player can change its choice as bandwidth and buffer state change. A **manifest** describes available tracks/segments. **HLS** (HTTP Live Streaming) and **DASH** (Dynamic Adaptive Streaming over HTTP) are streaming delivery formats.

## First Principles

A display cannot benefit equally from every source pixel, but compression can discard visible detail. Choose dimensions and encoding from visual quality, device support, transferred bytes and decode cost; a format name does not guarantee a universal saving.

A transformed output depends on its source version and transformation inputs. Reusing it for another request is correct only when those inputs resolve to the same representation. Unbounded dimensions/quality/crop combinations create unbounded work and cache identities, so validate and normalize a finite supported policy.

Private bytes create an independent boundary: possession of a cache entry is not permission to return it. Verify authorization before every protected hit as well as a miss. Removing credentials from an internal content key is safe only if the enforcement path cannot be bypassed.

## How Image Variants Work

```text
source identity + validated dimensions/quality + selected supported format
   → representation key
   → eligible hit: return stored bytes with matching metadata
   → miss: transform, validate successful output, store under that key
```

The selected format must respect the consumer's actual capabilities and Accept preferences, including `q=0` exclusions. A substring search for `image/avif` is not complete HTTP negotiation. Keep resolved format in the provider key and the appropriate `Vary` policy for downstream caches. `Vary` alone does not make every custom CDN key respect that dimension.

### Normalize a small public variant policy

This standalone TypeScript helper normalizes a deliberately narrow public-image policy. The caller supplies an already-negotiated supported format and an allowed, versioned source catalog. It does not implement a Worker, image renderer, arbitrary-source fetcher or full Accept parser.

```typescript
export function imageVariant(
  url: URL, format: 'avif' | 'webp' | 'jpeg', sources: ReadonlySet<string>,
): { key: string; width: number; quality: number; format: string } {
  if (!sources.has(url.pathname)) throw new Error('Unknown source');
  if (!['avif', 'webp', 'jpeg'].includes(format)) throw new Error('Unsupported format');
  for (const name of url.searchParams.keys()) {
    if (!['w', 'q', 'utm_source'].includes(name)) throw new Error('Unknown parameter');
    if (url.searchParams.getAll(name).length !== 1) throw new Error('Repeated parameter');
  }
  const widthText = url.searchParams.get('w') ?? '960';
  const qualityText = url.searchParams.get('q') ?? '80';
  if (!/^\d+$/.test(widthText) || !/^\d+$/.test(qualityText)) throw new Error('Invalid number');
  const requested = Number(widthText);
  const quality = Number(qualityText);
  if (!Number.isSafeInteger(requested) || requested <= 0 || requested > 1920) {
    throw new Error('Width outside policy');
  }
  if (![60, 80].includes(quality)) throw new Error('Quality outside policy');
  const width = [320, 480, 640, 960, 1280, 1920].find(value => value >= requested)!;
  return { key: JSON.stringify([url.pathname, width, quality, format]), width, quality, format };
}
```

For an allowed `/img/hero.a1b2.jpg`, `?w=420&q=80` resolves to width 480. Changing parameter order or `utm_source` preserves the key; choosing WebP instead of AVIF changes it. The renderer must use exactly these normalized values. It must not render width 420 while storing under width 480.

The catalog establishes the source boundary for this example. A multi-tenant/private design needs its own source/access identity. Only mark an output immutable if the source and transform-policy identity guarantee that its bytes will not change. A renderer error, wrong content type or incomplete body must not become a one-year successful image.

## Signed Access Is Separate from Content Identity

A signed URL is a bearer capability: anyone holding it can use its granted scope until policy/expiry rejects it. Expiry limits replay time; it does not prevent sharing or prove a user's current entitlement. Protect signing keys, URLs/logs and direct-origin access, and plan key rotation/revocation.

The following Node.js primitive signs one cataloged path and expiry. Issue it only after entitlement checks. The verifier receives parsed canonical fields and must run before **every** protected cache lookup. It is not a complete CDN deployment or a one-use token protocol.

```typescript
import { createHmac, timingSafeEqual } from 'node:crypto';

export function mediaSignature(path: string, expires: number, key: Buffer): string {
  if (key.length < 32) throw new Error('Use a securely generated signing key');
  if (!Number.isSafeInteger(expires) || expires <= 0) throw new Error('Invalid expiry');
  return createHmac('sha256', key).update(JSON.stringify([path, expires])).digest('hex');
}

export function verifyMedia(
  path: string, expires: number, signature: string, key: Buffer,
  allowedPaths: ReadonlySet<string>, nowSeconds: number,
): boolean {
  if (!Number.isFinite(nowSeconds) || !allowedPaths.has(path)) return false;
  if (!Number.isSafeInteger(expires) || expires <= nowSeconds) return false;
  if (!/^[0-9a-f]{64}$/.test(signature)) return false;
  const supplied = Buffer.from(signature, 'hex');
  const expected = Buffer.from(mediaSignature(path, expires, key), 'hex');
  return timingSafeEqual(supplied, expected); // equal-length byte buffers
}
```

An altered path or expiry must fail. An expired or malformed signature returns false. Invalid server key configuration is an operational error. Bind any additional grant fields—tenant, allowed transformation, disposition or scope—into a canonical signed payload when they affect authorization. Parse duplicate/ambiguous URL fields consistently before invoking the primitive.

After verification, an internal content key may omit expiry/signature when authorized callers receive exactly the same bytes. The public delivery path must still verify a fresh request before returning that shared entry. Browser response caching/expiry and download interruption need deliberate policy; changing expiry does not recall already-downloaded bytes. Cross-Origin Resource Sharing (CORS) and Referer checks do not establish entitlement.

## Video Delivery Uses a Different Pipeline

Encode a suitable high-quality source into supported resolution/bitrate tracks, then package them into manifests and segments. Encoding can happen before delivery; the CDN usually distributes the resulting objects rather than performing the complete video encode at each edge.

A player estimates bandwidth and buffer health, chooses a rendition, fetches segments and adapts. The ladder, codec support, segment duration, startup choice and network conditions affect quality and buffering. CMAF (Common Media Application Format) can let compatible HLS/DASH configurations share media segments; codec/encryption/manifest requirements still need verification.

On-demand versioned segments can have a long eligible cache policy. A live manifest changes as segments appear and needs a different freshness policy. Low-latency delivery introduces parts and protocol/player requirements; there is no universal two-second end-to-end latency. Digital rights management (DRM) licenses, access tokens and personalized manifests are separate access/freshness surfaces.

A browser player can use native HLS where supported or a compatible library such as hls.js. Handle unsupported playback, errors, token renewal and cleanup; destroy a library instance when detaching it. Starting at ladder index 1 is not universally conservative—the meaning depends on the authored ladder.

## Real-World Decisions

Pre-generate known build assets or predictable hot renditions when that improves deployment/runtime cost. Generate on upload when content and likely sizes are known. Use bounded on-demand transformations for a measured long tail. None is universally the best placement.

For HTML images, provide suitable `srcset`/`sizes`, explicit dimensions and alternatives. Avoid lazy-loading the likely largest-contentful-paint (LCP) hero when it delays its discovery; lazy loading can suit offscreen media. Test actual layout, visual quality, decode time and user-path latency alongside transferred bytes.

Shield/coalescing behavior depends on eligible same-object requests and supported provider policy. Warm-up cannot guarantee retention. Signed playback links do not prevent an authorized viewer sharing them. Treat claimed codec savings or egress improvements as measured workload results, not invented outcomes.

## Mistakes

- Negotiating by substring, accepting `q=0` formats or ignoring a source/transform version.
- Putting arbitrary quality/width values into keys without applying the same normalized renderer policy.
- Storing render failures under immutable image headers.
- Removing a signature before verification, or verifying only on a miss.
- Passing strings or unequal-length buffers to `timingSafeEqual`.
- Treating CORS, Referer or expiry as complete replay/sharing prevention.
- Giving live manifests and immutable on-demand segments the same cache lifetime.

## Best Practices

Define the finite representation policy and authorization boundary before optimizing. Test parameter normalization, tampering, expiry and hit-path enforcement, then measure rendering/playback quality and miss-path capacity. Verify provider storage, codec, encryption and access behavior separately from local helper correctness.

## Summary

Media delivery selects suitable representations under bounded transformation, cache identity and authorization policies. Images need normalized inputs and valid output; video needs compatible ladders, packaging and player behavior. Reusing bytes safely requires both the right representation and a current access decision.

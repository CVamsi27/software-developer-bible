# CI/CD Interview Questions

## First Principles

For each prompt, explain the mechanism, identify a concrete failure and state the condition that changes your decision. Use the learning chapters for implementation; preserve this bank as a separate drill. Avoid treating a memorized tool list or green YAML parse as operational evidence.

## Practice the Existing Interview Questions

---

### Question 1: What is CI/CD and why is it important?

**Answer:**

Continuous integration means integrating small changes frequently and validating the integrated result with automated builds/tests. Continuous delivery keeps a verified candidate releasable; continuous deployment also promotes eligible changes automatically. A workflow triggered by a push is only part of CI if teams leave branches divergent or routinely ignore failed integration.

---

### Question 2: What is the difference between Continuous Delivery and Continuous Deployment?

**Answer:**

Continuous delivery can leave production promotion as an explicit decision; continuous deployment automates that decision under policy. Both need trustworthy gates, identified artifacts and recovery. A manual button does not inherently lower risk, and automation need not expose every user immediately: flags and cohort routing can separate deployment from exposure.

---

### Question 3: What are the stages of a CI/CD pipeline?

**Answer:**

Draw the dependency graph for source validation, candidate build, artifact tests/scans, staging and protected promotion. Run independent checks together and require complete evidence for the exact candidate before production. Cheap checks can come early, but cost alone must not make an essential integration/security gate optional.

---

### Question 4: What is a Dockerfile and why use it?

**Answer:**

A Dockerfile declares build instructions and inputs; it does not guarantee determinism by itself. Use a lockfile, reviewed base digest, explicit runtime, small context and appropriate multi-stage separation. Native dependencies can differ across Alpine musl and glibc-based images. Test the final image’s real startup/user/filesystem separately from build-stage tests.

---

### Question 5: What is the difference between a Docker image and a container?

**Answer:**

An image supplies read-only content/configuration; a container is a running or stopped instance with runtime state and usually a writable layer. Images may live locally or in registries. Container-layer writes survive a stop/start but normally disappear when the container is removed; durable application data needs an explicit volume or external store with recovery policy.

---

### Question 6: What is Kubernetes and why use it?

**Answer:**

Kubernetes uses controllers to reconcile declared resources with observed cluster state. Scheduling, Services and rollout controllers can support a fleet, but they introduce control-plane, networking, storage and operational responsibilities. Choose it when those capabilities justify the cost; a managed platform or VM can meet simpler requirements.

---

### Question 7: What is a Kubernetes Deployment?

**Answer:**

A Deployment manages ReplicaSets and replacement of Pods according to the configured strategy. Its selector must match Pod-template labels. Retained revisions can restore a previous template, but cannot restore lost data or incompatible schema. Discuss maxSurge/maxUnavailable, readiness, capacity and rollout timeout; use StatefulSet, DaemonSet or Job when the workload contract differs.

---

### Question 8: What is Infrastructure as Code (IaC)?

**Answer:**

Infrastructure as code stores infrastructure intent in reviewed files and applies it through a tool. Terraform uses persistent state to map managed resources, whereas not all IaC tools share that model. Plan, refresh, provider behavior, access and locking matter. Current S3 Terraform backends support native lockfiles; DynamoDB locking is deprecated, so verify backend/version rather than copying a legacy default.

---

### Question 9: What is a CI/CD pipeline?

**Answer:**

A pipeline is a dependency graph whose checks and promotion policy act on a candidate. Identify event/ref, runtime, real scripts, output producer, artifact integrity and deployment authority. A sample that pushes latest without login, registry identity, tests or target configuration does not demonstrate a release. Use the complete platform chapters as provider syntax references.

---

### Question 10: What is version control and why is it important?

**Answer:**

Version control records reviewable source/configuration history and supports integration. Branch strategy affects feedback and merge risk: short-lived branches reduce divergence, while supported release branches may be necessary. Protected main and checks support releasability but do not prove all behavior; preserve required events and test the actual integrated ref.

---

### Question 11: What is a microservices architecture?

**Answer:**

Microservices divide a system into services with deliberate ownership and contracts. Independent deployment requires compatible APIs/events/data evolution, not merely separate pipelines. Contract tests provide useful evidence but do not replace runtime integration. A modular monolith can be simpler until scale, ownership or deployment boundaries justify distribution.

---

### Question 12: What is a container registry?

**Answer:**

A registry stores image manifests/layers and associated metadata. Select by authentication, availability, residency, policy and OCI feature support. Promote the verified digest, keep evidence and protect live/recovery references during retention. Use Google Artifact Registry for current GCP designs; legacy GCR terminology does not establish current support.

---

### Question 13: What is the difference between `docker build` and `docker compose`?

**Answer:**

Docker build creates an image from a build context; Compose defines and operates a multi-service application with networks/volumes and can also build images. Compose on a hosted CI runner is a temporary integration environment, not deployment to your production VM. A multi-platform build can produce an index plus several platform images.

---

### Question 14: What is a Kubernetes Service?

**Answer:**

A Service supplies stable selection/network access to matching endpoints. Readiness normally controls eligible endpoints, while headless and external-name cases have different behavior. ClusterIP, NodePort and LoadBalancer express different exposure contracts; the actual load balancer and data plane depend on cluster/controller configuration. Do not assume each Service maps to one billed cloud resource universally.

---

### Question 15: What is Helm?

**Answer:**

Helm renders chart templates with values and manages release history when used as a release client. Argo CD can use Helm only for rendering, with its own release ownership. Run lint/render/schema checks using the intended versions; helm diff is a separately installed plugin. A rollback changes manifests but does not reverse arbitrary database/external effects.

---

### Question 16: What is a webhook in CI/CD?

**Answer:**

A webhook delivers an event to a receiver that validates its signature, stores/deduplicates identity and schedules work. GitHub does not automatically redeliver failed webhook deliveries; configure supported manual/API reconciliation. Handle duplicate/out-of-order events and outages explicitly instead of promising retries supplied by every forge.

---

### Question 17: What is the difference between a build and a release?

**Answer:**

A build produces content; a release is the authorized publication/exposure of identified content and configuration. Promote the same candidate rather than rebuilding per environment. If build-time configuration requires variants, name and test them as separate artifacts instead of claiming identical bytes.

---

### Question 18: What is a staging environment?

**Answer:**

Staging tests chosen production-like contracts before release, but differs in data, load, permissions and external integrations. Record which differences limit evidence. Preview environments isolate changes but do not automatically establish production parity; bound credentials/cost and use synthetic or appropriately protected test data.

---

### Question 19: What is a canary deployment?

**Answer:**

A canary exposes a defined limited cohort to a candidate and evaluates valid user-facing outcomes against policy/baseline before ramping. Pod count is not request share. Explain routing, labels, minimum samples, missing telemetry, stop criteria and compatible recovery, including background-job effects and biased session cohorts.

---

### Question 20: What is blue-green deployment?

**Answer:**

Blue-green prepares replacement capacity and switches routing after validation while retaining a recovery target. Traffic propagation/draining and shared data constrain reversal; it is not inherently instant or zero downtime. Capacity cost depends on what is duplicated and retained. Rehearse schema compatibility and post-switch user checks.

---

### Question 21: What is feature flagging?

**Answer:**

Feature flags separate code deployment from exposure. Define assignment stability, default behavior, configuration freshness, authorization and cleanup. Both paths require appropriate tests, but every flag does not necessarily double the whole suite; prioritize consequential combinations. A flag service outage needs an explicit domain-safe fallback.

---

### Question 22: What is observability in CI/CD?

**Answer:**

Observe both pipeline execution and released behavior. Stage/queue durations, actual test reports and artifact provenance help diagnose delivery; user SLIs/logs/traces help diagnose the running system. Current DORA uses five service-level delivery measures including deployment rework rate; they complement rather than replace pipeline timings and user reliability.

---

### Question 23: What is GitOps?

**Answer:**

GitOps stores declarative desired state in versioned sources and uses reconciliation. CI may avoid direct cluster access, but a credential that changes production desired state remains powerful. Controllers can manage remote clusters, and manual cluster writes remain possible unless access policy forbids them. Define drift, hotfix authority, secret handling and compatible recovery.

---

### Question 24: What is a pipeline as code?

**Answer:**

Pipeline as code versions executable automation beside its contract. It still relies on external runner/tool/plugin/credential configuration. Reuse workflows or steps at a deliberate boundary, pin reviewed external code and test workflow changes. Configuration reuse alone does not enforce mandatory organizational policy.

---

### Question 25: What is artifact management?

**Answer:**

Artifact management stores content identity, producer/source/build evidence, access and retention. Promote verified content, distinguish mutable tags from digests and retain deployed/recovery references. An SBOM inventories components; a signature authenticates a statement; neither alone proves artifact correctness or a SLSA level.

---

### Question 26: What is the difference between a build agent and a runner?

**Answer:**

Agent and runner are platform-specific names for execution capacity. Either can be long-lived or ephemeral, self-hosted or managed according to the platform. Evaluate lifecycle, tool versions, host/network access and credential scope; a job container or new VM alone does not establish safe isolation.

---

### Question 27: What is a secrets manager?

**Answer:**

A secrets manager controls storage/access/rotation of sensitive material. Build-time secret access may be legitimate through nonpersistent BuildKit mounts, but commands can still copy or log it; never bake secrets into layers or arguments. Runtime injection and CI OIDC require narrow policy. Temporary tokens remain stealable until expiry.

---

### Question 28: What is a Kubernetes Ingress?

**Answer:**

Ingress declares HTTP routing that a compatible controller implements; no controller means no routing. Annotations are controller-specific. Community ingress-nginx is retired as of March 2026; distinguish it from other NGINX products and choose a maintained implementation. Gateway API supplies additional role/resource separation, with feature support still varying by implementation.

---

### Question 29: What is a service mesh?

**Answer:**

A service mesh supplies chosen communication policy/telemetry through its data plane, which may use sidecars or other deployment models. mTLS between internal services is distinct from ingress TLS termination. Assess routing, identity, retries and operational cost against actual needs; not every eBPF networking system provides every mesh feature.

---

### Question 30: What are the best practices for CI/CD?

**Answer:**

Keep small integrations, explicit dependencies, meaningful required evidence, identified artifacts, narrow authority and tested recovery. Measure feedback cost and flaky tests without hiding failures. Rehearse failed/missing checks, stale approvals, wrong targets, telemetry loss and incompatible state; a list of tools is weaker than one traced release decision.

---

## Summary

CI/CD interview questions cover:

- Core concepts (CI, CD, pipelines)
- Container technologies (Docker, Kubernetes)
- Deployment strategies (blue-green, canary)
- Infrastructure as Code
- Monitoring and observability
- Best practices

Focus on understanding the **why** behind each concept.

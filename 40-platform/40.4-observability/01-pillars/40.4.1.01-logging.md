# Logging

During a checkout incident, the API returns an error and a worker retries the payment. The team needs to know what happened without copying card details or passwords into a search index. A useful log records the event and safe correlation fields while making collection loss visible.

## Definition

Logging is the practice of recording discrete events that occur during software execution. Logs provide selected evidence about what happened in a system; metrics and traces answer related questions at different levels. They capture context about requests, errors, state changes, and business events in a format that humans and machines can parse.

> **Textbook Definition:** Logging records discrete software events with context for later inspection. Log reliability depends on timestamping, transport, retention, access controls, and an explicit policy for sensitive information.

A **log entry** records one event with a timestamp and context. Application logs are not automatically immutable or complete; tamper-evident audit requirements need separate controls. When collected, aggregated, and indexed, logs become a powerful tool for debugging, auditing, security analysis, and understanding system behavior over time.

## First Principles

Once a process has returned a response or crashed, its local execution state may be gone. Record selected events with enough context to distinguish one operation from another. Collection can fail and logs can expose sensitive data, so choose what to emit, how to bound it and what loss/access policy is acceptable.

## Follow an Event From Code to Investigation

```text
application emits structured event → stdout/transport → collector
                                  → storage/index → scoped query/retention
```

A record should describe an event, not dump arbitrary process state. Keep consistent timestamp, severity, service/version, operation and correlation fields. JSON makes fields parseable; it does not make them safe, truthful or durable. Request/trace IDs correlate work but are not authentication credentials.

A log can support aggregate queries if collection and sampling permit it. Metrics preaggregate chosen measurements more economically; traces connect operations. Select the signal from the question rather than claiming logs cannot calculate rates at all.

## A Logger With a Checkable Redaction Boundary

Install a reviewed `pino` version and save this ES module. The in-memory sink is only a local test; production needs a bounded transport/collector policy.

```javascript
// logging.mjs
import pino from 'pino';
import assert from 'node:assert/strict';
const records = [];
const logger = pino({
  level: 'info',
  base: { service: 'checkout' },
  redact: { paths: ['password', 'credentials.token'], censor: '[REDACTED]' },
}, { write(line) { records.push(JSON.parse(line)); } });
const requestLog = logger.child({ requestId: 'generated-request-1' });
requestLog.info({ operation: 'login', password: 'secret',
  credentials: { token: 'bearer-secret' } }, 'Login evaluated');
assert.equal(records[0].password, '[REDACTED]');
assert.equal(records[0].credentials.token, '[REDACTED]');
assert.equal(records[0].requestId, 'generated-request-1');
let expensiveCalls = 0;
if (logger.isLevelEnabled('debug')) {
  logger.debug({ detail: ++expensiveCalls }, 'Debug detail');
}
assert.equal(expensiveCalls, 0);
```

Redaction paths cover only the stated structure. If a developer writes the token inside `message`, a URL query or a differently named nested object, these paths do not protect it. Prefer an allowlisted event schema, omit raw bodies/headers/query strings and test secret-shaped input across the real schema. A child logger carries context; do not create one global child with a hard-coded request ID and reuse it for every request.

## Record Completion, Failure and Abort Correctly

For HTTP middleware, observe response `finish` for completed writes and `close` for premature termination. A patched `res.json` misses text, streams, redirects and end-only responses; registering both lifecycle listeners needs a once-only guard. “Finished writing” still does not prove the client received or acted on the response.

Use monotonic elapsed timing such as `performance.now()` for duration, and wall-clock timestamps for event correlation. Derive a trusted internal correlation ID or validate external IDs for length/format; never treat them as proof of user identity. Record bounded route names and safe status/error categories instead of raw URLs or bodies.

Serialize errors through the logger's supported error serializer. Error messages/stacks can also contain sensitive data, so decide what survives transport/storage. Do not log full orders, payment payloads or shipment addresses merely to provide “business context.”

## Bound Transport, Volume and Retention

Container applications commonly write structured events to stdout and delegate collection/rotation to the platform. File logging requires a writable directory, capacity monitoring and actual rotation/retention; a read-only image cannot write an assumed `logs/` path. Winston transports can be appropriate when those contracts are deliberate.

Async transport moves work; it does not make buffering free or prevent loss on crash. Choose bounded queues, backpressure/drop policy, dropped-event telemetry and graceful flush deadlines. Unbounded fire-and-forget writes can exhaust memory. Fatal/rejection handling must preserve process recovery policy rather than logging an unsafe process and continuing indefinitely.

Sampling can reduce routine request volume, but it changes completeness. Keep meaningful suppression counts and avoid dynamic unbounded sampler keys. Security audit records may need different durability, access and sampling rules from diagnostic logs. A fixed “100% errors” rule can still flood storage during an outage; preserve useful evidence while bounding failure modes.

## Real-World Decisions

**Incident diagnosis:** Search a safe request/trace ID, find the boundary failure and then inspect the matching trace. Clock skew and transport delay can make timestamp ordering misleading.

**Audit:** Define the actor/action/target/outcome, integrity and access requirements. Logging an event does not itself establish GDPR, SOC 2 or HIPAA compliance.

**Performance:** Benchmark the logger with actual serialization, transports and workload. A universal Pino-to-Winston speed ratio is not a production capacity estimate. Arguments are evaluated before the logging call, so disabled debug does not automatically avoid an expensive computation unless explicitly guarded.

## Summary

Logging preserves selected event context for later investigation. Structured records help querying, while safe schemas, lifecycle handling and bounded transport determine whether the evidence is useful. Correlation does not prove identity, and redaction does not protect values outside the fields it covers.

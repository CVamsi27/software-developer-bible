# Turbopack

## Definition

**Turbopack** is the Rust incremental bundler integrated into Next.js. It turns a module graph into the JavaScript, CSS, and assets needed by the application. **Turborepo** works one level higher: it schedules package tasks and restores their outputs from cache.

> **Textbook Definition:** Turbopack is an incremental JavaScript and TypeScript bundler that tracks fine-grained dependencies and reuses cached computation to update application output when inputs change.

For **Next.js 16**, Turbopack is the default for both `next dev` and `next build`. Next.js 15 stabilized development support, introduced experimental builds in 15.3, and moved builds to beta in 15.5. Specify the version before discussing readiness; older alpha benchmarks describe a different product.

## First Principles

1. A file edit changes only part of an application's dependency graph. Recording which computations depend on which inputs lets the bundler reuse unaffected results.
2. Reusing a result is correct only when its dependencies and configuration still match. Cache invalidation must include resolution, transforms, and environment-dependent decisions.
3. A framework builds several related graphs: browser, server, and React Server Components. Shared computation can reduce repeated work while keeping those targets distinct.

## Why It Matters

The useful question is whether your framework's supported bundler can reduce your actual edit-to-feedback and production-build times. A Rust implementation does not guarantee a fixed speedup, constant-time HMR, or compatibility with every Webpack extension.

## How It Works

```text
source/config change
  -> invalidate dependent computations
  -> resolve and transform requested modules
  -> recompute affected graph/output
  -> update the browser or write production artifacts
```

Lazy development compilation delays work until a route is requested. Incremental computation reuses work within the running process. Filesystem caching can reuse work across restarts; its availability and defaults depend on the Next.js version and dev/build mode. These are three different mechanisms.

## Code Examples

### Use the framework default

```bash
# Next.js 16
npx next dev
npx next build

# Opt into Webpack when a required integration depends on it
npx next dev --webpack
npx next build --webpack

# Collect a Turbopack development trace
NEXT_TURBOPACK_TRACING=1 npx next dev
```

The trace contains development paths and workload details; inspect it before sharing it publicly.

### Add a supported loader rule

```typescript
// next.config.ts
import type { NextConfig } from 'next';

const nextConfig: NextConfig = {
  turbopack: {
    rules: {
      '*.svg': {
        loaders: ['@svgr/webpack'],
        as: '*.js',
      },
    },
    resolveAlias: { '@components': './src/components' },
    resolveExtensions: ['.tsx', '.ts', '.jsx', '.js', '.mjs', '.json'],
  },
};

export default nextConfig;
```

Install the loader and import an SVG through this rule to check the emitted module. Rules support a subset of the Webpack loader API; Webpack plugins do not automatically run here. TypeScript `paths` is already supported, so use an explicit bundler alias only when it adds a deliberate resolution rule.

`experimental.turbo` was the configuration key through Next.js 15.2. Use `turbopack` in current configurations. Next.js 16 detects Babel configurations; a custom Babel requirement alone is no longer proof that Turbopack is unsuitable.

## Real-World Use Cases

- A Next.js monorepo can reduce repeated transforms of shared packages across routes and targets.
- An MDX site can inspect whether an article edit invalidates only relevant work rather than assuming that all loader chains have equivalent cost.
- A migration that depends on custom Webpack plugins can retain `--webpack` until equivalent supported integrations are verified.

## Common Mistakes

- Comparing a warm incremental rebuild against another tool's cold production build.
- Assuming Turbopack executes `webpack()` configuration or arbitrary Webpack plugins.
- Treating development success as evidence that every production route and asset builds correctly.
- Equating a cached computation with durable caching across process restarts.

## Best Practices

Measure cold startup, first-route compilation, repeated edits, production builds, memory, and emitted assets separately. Use the framework default when its integrations meet the application's needs. Keep a tested fallback while resolving unsupported extensions.

## Summary

Turbopack performs incremental module bundling inside Next.js; Turborepo orchestrates package tasks. Next.js 16 uses Turbopack for development and production by default. Choose compatibility and measured workload results over historical speed ratios.

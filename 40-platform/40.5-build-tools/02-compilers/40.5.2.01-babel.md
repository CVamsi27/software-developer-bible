# Babel

## Definition

Babel parses JavaScript and related syntax, applies configurable transformations and prints JavaScript. JSX and TypeScript presets can remove syntax a runtime does not understand; target presets can lower newer syntax for selected environments.

> **Textbook Definition:** Babel is a source-to-source compiler toolkit using an abstract syntax tree, plugin transformations and code generation to produce configured JavaScript output.

## First Principles

A runtime must understand the emitted syntax and provide the APIs that code calls. Rewriting an arrow function solves a syntax problem; it does not implement `fetch`. Transform configuration therefore has to distinguish language lowering, runtime support and type checking. A structural tree also permits binding-aware edits that text replacement cannot safely perform.

## Why It Matters

Babel remains useful for required proposal transforms, custom AST plugins and codemods. Adopt a proposal only with explicit semantics/version requirements; changing decorator modes can change runtime behavior. Do not assume Babel is a fixed percentage of every build or that another compiler always preserves its output semantics.

## How It Works

```text
source → parser → AST with scope/bindings → configured visitors → generated code/map
```

An AST is an abstract syntax tree. Visitors operate on syntax nodes and their paths, with scope information for safe binding edits. Plugins run before presets; plugins are ordered first to last and presets last to first. Individual transforms can still interact through traversal and passes, so inspect behavior rather than reducing a complex pipeline to one slogan.

Project-wide `babel.config.*` is rooted in Babel's configured working root. A nested workspace command does not automatically search every parent for it; `rootMode: 'upward'` can deliberately locate a monorepo root. File-relative `.babelrc` discovery has package boundaries and `babelrcRoots` rules. Resolve the actual config/caller before diagnosing differences between tests and bundling.

## Example: Lower Syntax Without Losing a Private Field

Install `@babel/core` and `@babel/preset-env` in a disposable Node project. Save `transform.cjs`:

```javascript
const assert = require('node:assert/strict');
const vm = require('node:vm');
const babel = require('@babel/core');
const source = `
class Counter {
  #value = 0;
  increment = () => ++this.#value;
}
globalThis.result = new Counter().increment();
`;
const { code, map } = babel.transformSync(source, {
  configFile: false,
  babelrc: false,
  presets: [[require.resolve('@babel/preset-env'), { targets: { ie: '11' } }]],
  sourceMaps: true,
  filename: 'counter.js',
});
const sandbox = {};
vm.runInNewContext(code, sandbox);
assert.equal(sandbox.result, 1);
assert(map.sources.includes('counter.js'));
console.log(code);
```

The printed output uses helper machinery for the private field. Replacing `#value` with a public `_value` property would change privacy semantics and is not an honest example of the normal transform. This test runs generated code in Node, not Internet Explorer; the legacy target illustrates syntax lowering only.

## Runtime APIs Need a Separate Strategy

`@babel/preset-env` can select core-js imports with `useBuiltIns: 'usage'` or `'entry'` when configured. Pin the installed core-js version including the required minor; `corejs: 3` alone describes 3.0 capabilities rather than every newer feature. Usage mode analyzes references, not every possible dynamically accessed API. Core-js does not supply all browser APIs such as fetch.

Helper deduplication through `@babel/plugin-transform-runtime` requires its runtime dependency. Its core-js options/version behavior differs across Babel majors; it is not an automatic privacy/security policy. Choose global application polyfills versus isolated library runtime imports deliberately. Deprecated `@babel/polyfill` is not the modern setup.

## Real-World Decisions

For a library, avoid unexpectedly mutating the consumer's globals and publish its required runtime/target contract. For an application, derive targets from actual audience requirements and inspect the resolved Browserslist set. A codemod is a one-time source migration, so validate representative binding and syntax cases rather than retaining it as an unnecessary build step.

## Mistakes and Best Practices

Babel strips TypeScript types without checking relationships or emitting public declarations. Keep explicit type/declaration gates. Configure plugins and runtime dependencies together, test class/decorator interoperability, and check original-line mappings. Cache transforms with their configuration inputs and profile the actual stage before replacing it.

## Summary

Babel's parse–transform–generate pipeline handles syntax, with explicit targets and extensions. Runtime polyfills, TypeScript correctness and deployment compatibility remain distinct responsibilities. Preserve semantics and source-map accuracy when changing compiler paths.

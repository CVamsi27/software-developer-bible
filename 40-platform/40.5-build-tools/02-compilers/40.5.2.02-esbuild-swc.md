# esbuild and SWC

Your TypeScript build can finish successfully and still ship `const count: number = 'not-a-number'`. A fast compiler may only erase the annotation; it has not necessarily checked the relationship between the value and its declared type.

## Definition

esbuild is a Go-based JavaScript bundler, transformer and minifier with command-line, JavaScript and Go APIs. SWC is a Rust-based compiler toolkit commonly embedded in framework and test pipelines. Both can remove supported TypeScript syntax without performing TypeScript's semantic type check.

> **Textbook Definition:** esbuild and SWC are source transformation toolchains that parse JavaScript-family syntax and emit configured JavaScript; esbuild also provides a standalone bundler, while SWC is commonly integrated as a compiler stage in a larger toolchain.

## First Principles

Build time depends on more than the compiler's parser: plugin work, module resolution, file I/O, bundling and minification all contribute. Replacing one transform can improve that stage without making the whole build equally faster. The output must still preserve required runtime behavior and satisfy separate type, API-compatibility and packaging checks.

## Compare the stage each tool owns

| Concern | esbuild | SWC |
| --------------- | ------------------------------------ | --------------------------------------------- |
| Main role | Bundles and transforms | Transforms; framework often bundles |
| Extensions | JS/Go build API plugins | Native/Wasm transform plugins |
| TypeScript | Erases syntax; no check/declarations | Erases syntax; no check/declarations |
| Syntax and APIs | Targeted syntax; no API polyfills | Targeted syntax; optional `core-js` injection |

The extension APIs are not interchangeable: esbuild plugins run through its JavaScript or Go **build** API, not its CLI or transform API. SWC plugins operate as native or WebAssembly transforms, so confirm compiler/plugin compatibility. The last row is another important boundary: esbuild's `target` only lowers supported syntax and cannot lower every newer feature to ES5; SWC's `env.mode` plus a pinned `env.coreJs` can inject selected `core-js` polyfills. Neither operation creates every missing Web API.

## See what a successful transform proves

Run this example in a disposable Node project with `esbuild` and `@swc/core` installed:

```javascript
import assert from 'node:assert/strict';
import vm from 'node:vm';
import * as esbuild from 'esbuild';
import { transformSync } from '@swc/core';

const source = `const count: number = 'not-a-number'; globalThis.value = count;`;
const outputs = [
  esbuild.transformSync(source, { loader: 'ts', target: 'es2020' }).code,
  transformSync(source, {
    jsc: { parser: { syntax: 'typescript' }, target: 'es2020' },
  }).code,
];

for (const code of outputs) {
  const sandbox = {};
  vm.runInNewContext(code, sandbox);
  assert.equal(sandbox.value, 'not-a-number');
  assert(!code.includes(': number'));
}
```

Both compilers emit runnable JavaScript and preserve the string at runtime. A TypeScript check such as `tsc --noEmit` rejects the assignment. Keep type checking, declaration generation, bundling and runtime tests as explicit build steps when the chosen compiler does not own them.

## Check integration before replacing a compiler

For esbuild, code splitting requires ESM output and an output directory; the official API documents a known ordering issue across split chunks. Test dynamic-import paths and initialization order in the deployed build. A target such as `es5` also does not guarantee every newer syntax form can be lowered that far. Browser bundles do not automatically gain Node built-ins, and a Node bundle does not automatically package native addons or dynamically loaded files.

For SWC, align parser syntax, JSX runtime, target and decorator semantics with the application. Legacy decorators and emitted metadata are separate options; `legacyDecorator` alone does not enable `decoratorMetadata`. If using `env.mode` with `coreJs`, pin the installed minor version: SWC treats an unspecified version as `3.0.0`, which may omit later polyfills.

Neither tool accepts every Babel plugin as a drop-in extension. Before migration, compare behavior for class fields, decorators, interop, source maps and native binaries, then measure both the changed transform and the full build on representative inputs. Vite 8 replaced its earlier esbuild/Rollup pipeline with Rolldown and Oxc, so inspect the installed Vite major rather than assuming it still delegates those stages to esbuild.

## Summary

esbuild can own a complete bundle, while SWC commonly supplies a compiler stage. Both can erase types without checking them. Choose by integration and semantic needs, then verify syntax targets, polyfills, type gates and final runtime output separately.

# esbuild and SWC

## Definition

esbuild is a Go-based bundler, transformer and minifier. SWC is a Rust compiler toolkit commonly embedded in framework and test pipelines. Both can transform supported TypeScript/JSX syntax into JavaScript without checking TypeScript relationships.

> **Textbook Definition:** esbuild and SWC are parsing and transformation toolchains with distinct bundling and extension capabilities; their emitted JavaScript is separate from type checking and declaration generation.

## First Principles

Transforming many files involves parsing, tree manipulation and code generation. Implementations can reduce allocations and parallelize independent work, but extensions, resolution and I/O still affect total time. Correct output requires the same runtime semantics and target support, so a faster transform is useful only when it fulfills that contract.

## Why It Matters

Use these tools for a supported compiler stage, a custom pipeline or a framework's integration. There is no universal 10–100x ratio. Vite 5–7 used esbuild prominently; Vite 8 changed to Rolldown/Oxc. Next.js can use SWC transforms while Turbopack bundles the graph: compiler and bundler are different roles.

## How the Capabilities Differ

| Concern | esbuild | SWC |
| --------------- | -------------------------------------------------- | -------------------------------------------------------------------------- |
| Standalone role | Bundle, transform, minify | Parse, transform, minify; bundling often belongs to an embedding tool |
| Extension | Resolution/loading hooks through JS/Go APIs | Native/Wasm transform plugins with version compatibility requirements |
| Types | Erase supported TS syntax | Erase supported TS syntax |
| Compatibility | No general ES5 lowering or automatic API polyfills | Supported lowering depends on target/config; API polyfills remain explicit |

An esbuild dev server serves built output. Watch/rebuild plus live reload is not framework state-preserving HMR. Full HMR needs application/framework integration and update acceptance boundaries.

## Example: Both Compilers Accept a Type Error

Install `esbuild` and `@swc/core` in a disposable Node project. Save `compare.cjs`:

```javascript
const assert = require('node:assert/strict');
const vm = require('node:vm');
const esbuild = require('esbuild');
const swc = require('@swc/core');
const source = `const count: number = 'not-a-number'; globalThis.value = count;`;
const outputs = [
  esbuild.transformSync(source, { loader: 'ts', target: 'es2020' }).code,
  swc.transformSync(source, {
    jsc: { parser: { syntax: 'typescript' }, target: 'es2020' },
  }).code,
];
for (const code of outputs) {
  const sandbox = {};
  vm.runInNewContext(code, sandbox);
  assert.equal(sandbox.value, 'not-a-number');
  assert(!code.includes(': number'));
}
```

Both transforms succeed and the runtime value is still a string. Running an explicit TypeScript checker on this assignment rejects it. Compilation output alone is not type correctness.

## Real-World Decisions

For esbuild ESM code splitting, use compatible ESM output and an output directory; verify lazy chunk paths and ordering. For a library, declare externals and conditional exports, then type-check and emit declarations separately. For a server bundle, a Node target does not guarantee native addons or dynamically loaded files were packaged.

For SWC, align parser syntax, JSX runtime, target and decorator semantics with the application. Legacy decorators and metadata are separate options; `legacyDecorator` alone does not enable `decoratorMetadata`. Validate the framework's metadata consumers and compiler version before replacing a TypeScript transform.

## Mistakes and Best Practices

Do not assume Babel plugins work unchanged in SWC or esbuild. Browser bundles do not automatically receive Node built-in polyfills; prefer browser-compatible packages or isolate server code before adding shims. Compare class fields, interop, decorators, maps and native-binary platform support during migration. Measure representative transforms and the full pipeline separately.

## Summary

esbuild combines bundling with transforms; SWC commonly supplies a compiler stage. Both erase supported type syntax without checking it. Choose their supported semantics and integration role, then prove output behavior and explicit correctness gates.

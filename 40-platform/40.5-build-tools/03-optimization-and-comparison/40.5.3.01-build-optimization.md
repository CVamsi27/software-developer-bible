# Build Optimization

## Definition

Build optimization improves measured compilation cost, emitted asset size or runtime loading behavior. A faster CI build and a faster first page are different goals; a smaller compressed bundle may still execute expensive work.

> **Textbook Definition:** Build optimization applies dependency analysis, transformations, caching and output policies to reduce measurable build or delivery costs while preserving required application behavior.

## First Principles

A user pays for downloaded bytes, dependency waterfalls, parsing and execution. A developer pays for repeated resolution and transforms. Reusing work helps only when its input identity is correct; removing work helps only when the application does not require its effects. Measure the expensive path before selecting a technique.

## Why It Matters

A large unused route in the entry bundle wastes initial loading work; a slow transform repeated in CI wastes feedback time. Splitting the route and caching the transform address different bottlenecks. Neither fixes a slow database call or a broken browser rendering path.

## How to Trace the Cost

1. Define the workload: cold build, warm edit, initial route or later navigation.
2. Record the pinned runtime/toolchain, cache state and emitted manifest.
3. Inspect the dependency graph for expensive transforms, large imports and duplicated versions.
4. Change one mechanism, compare the same workload and check runtime behavior.

### Export pruning and module effects are separate

Static ESM imports permit analysis of used exports. Minification can remove proven dead code. `sideEffects` declares whether evaluating a module is required: registration code and CSS imports may be essential even when no export is referenced. Incorrect metadata can make a smaller bundle that silently breaks the application. Keeping ESM through a compiler stage helps later analysis; CommonJS can obscure the graph.

### Splitting moves work and can add a waterfall

A dynamic import creates an asynchronous boundary when the bundler supports it. Split by meaningful route/feature needs, then verify shared dependencies and critical-route loading. A giant vendor chunk can download unused packages; hundreds of tiny chunks can add scheduling overhead. Prefetch is a speculative bandwidth tradeoff, not free work. Handle lazy-load failure when an old browser session requests an unavailable chunk after deployment.

## Example: Measure a Real Asset, Including Compression

Save `measure.cjs` and pass an actual emitted JavaScript filename. Missing output is a failed measurement, not a zero-byte success.

```javascript
const { readFileSync } = require('node:fs');
const { gzipSync, brotliCompressSync } = require('node:zlib');
const file = process.argv[2];
if (!file) throw new Error('Usage: node measure.cjs path/to/emitted.js');
const bytes = readFileSync(file);
if (!bytes.length) throw new Error('Emitted asset is empty');
console.log(JSON.stringify({
  file,
  raw: bytes.length,
  gzip: gzipSync(bytes).length,
  brotli: brotliCompressSync(bytes).length,
}));
```

These are file-level encoded sizes, not actual route transfer or execution time. A route budget should resolve its entry, imported chunks, CSS and required assets from a build manifest. Compare against a checked baseline and absolute cap; file-count changes and missing manifests must fail the gate rather than bypass it.

## Real-World Decisions

For slow builds, inspect transform scope and cache hit/miss reasons before migrating the toolchain. Include lockfiles, config and relevant environment inputs in cache identity; declared output hashes do not create correct cache keys by themselves. Native packages and platform-specific outputs may require separate caches.

For slow users, choose an explicit browser target, reduce critical imports, reserve image dimensions and prioritize the actual LCP resource. Code splitting can help interaction latency, but measure INP (Interaction to Next Paint) and long tasks rather than using retired FID as the current metric. Compression needs host `Content-Encoding` negotiation and `Vary: Accept-Encoding`; generating `.br` files alone does not make the host serve them.

## Mistakes and Best Practices

- Keep tool-specific configuration in the canonical chapters. Vite 8 uses Rolldown/Oxc; removed object-form `manualChunks` must not reappear in optimization snippets.
- Do not treat minifier output syntax settings as a complete transpilation or polyfill policy.
- Choose hidden/public source maps from the debugging and disclosure contract, not assumed byte savings.
- Serve content-identified immutable assets, refresh entry HTML/manifests appropriately, and retain old chunks through rollout.
- Validate optimization effects on real routes and device/network profiles. A universal compression percentage or promised load-time reduction is not evidence.

## Summary

Optimize the measured expensive path while preserving application effects. Separate build caching from browser caching, raw bytes from encoded transfer and chunk size from critical-route behavior. A meaningful budget fails on missing evidence and includes the assets the route actually needs.

# Build Optimization

A CI build becomes faster while users still wait for the first route. A page's JavaScript shrinks while the first interaction gets slower because a split chunk arrives late. Both outcomes are possible because build time, transfer cost, and browser work are different targets; optimize the one your evidence shows is expensive.

## Definition

Build optimization reduces a measured cost in compilation, emitted output, or runtime delivery while preserving the application's behavior. A faster build does not prove a faster page, and a smaller JavaScript file does not prove a better route experience.

> **Textbook Definition:** Build optimization applies dependency analysis, transformation, caching and output policies to reduce measured build or delivery cost without removing required behavior or invalidating the build's evidence.

## First Principles

A source change costs developers repeated resolution and transformation. A shipped route costs users downloaded bytes, request dependencies, parsing, execution, and rendering. Caching can avoid repeated compiler work; pruning can remove unused code; splitting can defer code. Each mechanism moves a different cost and is correct only when its inputs and required effects are preserved.

## How It Works

### Trace from the module graph to the route

Start with the route entry and inspect the modules that contribute to its output. Static ES module imports let a bundler determine which exports are used. Package-level `sideEffects` metadata answers a different question: whether a module must still be evaluated for registration, polyfills, or imported CSS. Incorrectly marking a package as side-effect-free can remove required styles even when the component's JavaScript remains.

Dynamic `import()` can create an asynchronous chunk boundary. A boundary helps when the code is not needed for the initial route; it can hurt when the route immediately needs that code and waits on an extra request. A very large shared chunk may include code the route never uses, while many tiny chunks can add request and browser-processing overhead. Measure the critical route and its dependency waterfall before changing split points or prefetch behavior.

### Measure what the route actually ships

This script measures one emitted JavaScript file in raw, gzip, and Brotli forms:

```javascript
const { readFileSync } = require('node:fs');
const { gzipSync, brotliCompressSync } = require('node:zlib');

const file = process.argv[2];
if (!file) throw new Error('Usage: node measure.cjs path/to/emitted.js');
const bytes = readFileSync(file);
if (!bytes.length) throw new Error('Emitted asset is empty');

console.log(JSON.stringify({
  file,
  raw: bytes.length,
  gzip: gzipSync(bytes).length,
  brotli: brotliCompressSync(bytes).length,
}));
```

These numbers are encoded file sizes, not what a route transfers or how long it takes to render. A route budget must follow the build manifest from its entry to required JavaScript, CSS, and other critical assets. Compare against both a checked baseline and an absolute cap. If the manifest is missing, fail the budget check; treating missing evidence as zero bytes creates a false pass.

### Match the technique to the measured cost

For a slow build, compare cold builds with warm edits under the same pinned toolchain and cache state. Inspect expensive transforms, duplicate dependency versions, and cache misses before switching bundlers. Cache identity must account for the lockfile, toolchain, build configuration, and relevant inputs; hashing an output does not make an incorrect cache key safe. Platform-specific native packages may need separate caches.

For slow page loads, trace the route's actual network and rendering path. Largest Contentful Paint (LCP) measures when the largest visible image or text block renders; Interaction to Next Paint (INP) measures responsiveness across user interactions. Use field data for real visits and lab traces to diagnose a change. INP requires interactions, so a static lab page load alone cannot establish it. Minification is also separate from browser compatibility: lowering syntax does not add missing Web APIs or polyfills, so set an explicit browser-support and polyfill policy.

Compression saves transfer bytes only when the serving layer negotiates it. The host or CDN must choose a gzip or Brotli representation the request accepts, return the corresponding `Content-Encoding`, and vary cache entries by `Accept-Encoding`. Generating `.br` files on disk alone does not configure this behavior.

### Deploy the output safely

Give content-hashed assets immutable URLs and keep each URL's bytes fixed. Entry HTML and manifests must revalidate so users discover the new hashes, while previous chunks remain available long enough for sessions that still reference them. A hidden source map can still be present in the output directory; upload it to the error tracker and exclude it from public hosting when source disclosure is not intended.

## Summary

Follow one route from its dependency graph to the assets the browser loads. Prune only unused work, split only where deferring work helps, and compare build time, encoded size, network behavior, and rendering separately. Make budgets fail when their evidence is missing, then verify both the optimization and the deployment that serves it.

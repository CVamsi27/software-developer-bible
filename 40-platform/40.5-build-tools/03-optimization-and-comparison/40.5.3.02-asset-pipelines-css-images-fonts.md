# Asset Pipelines — CSS, Images & Fonts

## Definition

A page references source styles, a large photograph and a font. An asset pipeline turns them into representations the deployed browser can load: compatible CSS, appropriately sized images, usable font subsets and a manifest connecting references to emitted files.

> **Textbook Definition:** An asset pipeline transforms stylesheets, images, fonts, and other resources into deployable representations with controlled references, cache identities, and output formats.

## First Principles

The browser loads the URLs emitted by the build, not the filenames in the source tree. Transforming bytes without updating references breaks the page. Changing bytes under a permanently cached URL creates another failure: an old browser can retain a different version. Emission must coordinate content identity, references and retention.

Compatibility and size are different constraints. Minified CSS can still use an unsupported feature; a small font subset can omit a user's script. Choose targets and required content before optimizing bytes, then test the actual rendered result.

## Follow the stages rather than install every tool

```text
source -> resolve references -> transform for targets -> optimize representations
       -> finalize bytes and identities -> manifest/HTML/CSS -> deploy together
source maps -> private diagnostic upload paired with the finalized release
```

CSS import resolution, syntax lowering, prefixing and minification perform separate jobs. PostCSS runs configured plugins; Lightning CSS can combine supported transformations and optimization. A required custom PostCSS plugin may still need its own stage. Align targets and order rather than applying two overlapping transformers blindly.

Tailwind generates utilities from detected class candidates. Dynamic string fragments such as `bg-${color}-500` do not describe complete candidates; map application choices to full class strings. Tailwind v4 uses CSS-first configuration and supports explicit sources and `@source inline(...)`; do not transfer v3's JavaScript safelist recipe without checking the installed version. Scanning does not determine which classes users actually exercise. [Tailwind source detection](https://tailwindcss.com/docs/detecting-classes-in-source-files).

Importing an image in a bundler normally establishes its URL and emission; it does not necessarily resize it or generate AVIF/WebP variants. Likewise, shipping a `.woff2` file does not prove a correct subset. Explicit processing supplies those transformations, while bundler output keeps their references consistent.

## Trace a responsive image choice

For an image displayed at 400 CSS pixels on a device with pixel ratio two, an 800-pixel candidate is a useful starting point. Its actual quality and byte budget still need measurement. Supply truthful `sizes` and width descriptors so the browser can select a candidate. Format fallback belongs in `<picture>`, not an unsupported `type` attribute on `<img>`.

This complete HTML example assumes the referenced variants exist. Their sizes and hashes are illustrative filenames; a real manifest supplies the emitted references.

```html
<picture>
  <source type="image/avif"
          srcset="/assets/hero-400.avif 400w, /assets/hero-800.avif 800w"
          sizes="(max-width: 600px) 100vw, 400px">
  <source type="image/webp"
          srcset="/assets/hero-400.webp 400w, /assets/hero-800.webp 800w"
          sizes="(max-width: 600px) 100vw, 400px">
  <img src="/assets/hero-800.jpg"
       srcset="/assets/hero-400.jpg 400w, /assets/hero-800.jpg 800w"
       sizes="(max-width: 600px) 100vw, 400px"
       width="800" height="600" alt="A mountain landscape"
       fetchpriority="high" decoding="async">
</picture>
```

Explicit dimensions reserve the aspect ratio. Do not lazy-load a likely largest-contentful-paint hero by default; below-fold images can use lazy loading. Choose alternative text from the content's purpose. Compression ratios and paint-time gains depend on the source and workload, so compare actual candidates rather than quote a universal percentage.

## Generate bounded image variants

Build-time transformation suits known static sources; a controlled CDN transformation service suits dynamic uploads and a large changing catalog. Both need limits and cache identities. The following complete ES module uses sharp in a disposable directory and writes one WebP variant; it does not implement the entire manifest or responsive set.

```javascript
// generate-image.mjs; install sharp, then supply input and output paths
import sharp from 'sharp';
const [input, output] = process.argv.slice(2);
if (!input || !output) throw new Error('input and output paths required');
const info = await sharp(input, { limitInputPixels: 25_000_000 })
  .rotate()
  .resize({ width: 800, withoutEnlargement: true })
  .webp({ quality: 75 })
  .toFile(output);
console.log(JSON.stringify({ width: info.width, height: info.height, bytes: info.size }));
```

Automatic orientation avoids ignoring camera orientation metadata. `withoutEnlargement` keeps smaller originals from being stretched. Limit concurrent conversions, input pixels and total artifact volume; a large product catalog can exhaust a build even when one conversion is small. Choose crop/aspect behavior explicitly and preserve required metadata under policy. [sharp resizing](https://sharp.pixelplumbing.com/api-resize/).

## Configure CSS deliberately

For a Vite installation supporting these options, this complete config selects Lightning CSS transformation and minification. Install `vite` and `lightningcss`; provide normal application sources separately. Browser target policy is intentionally omitted here so the example does not invent a universal supported browser set.

```javascript
// vite.config.mjs
import { defineConfig } from 'vite';
export default defineConfig({
  css: { transformer: 'lightningcss' },
  build: { cssMinify: 'lightningcss', sourcemap: 'hidden' },
});
```

`css.transformer` selects transformation; `build.cssMinify` controls build minification. `build.cssTransformer` is not the corresponding option. Configure supported targets explicitly for the application and installed major version. A hidden source map still exists as an output file: hiding its comment does not make that file private. [Vite shared options](https://vite.dev/config/shared-options.html), [build options](https://vite.dev/config/build-options.html).

Webpack's asset modules own imported resource emission; CSS extraction and transformation need their configured loaders/plugins. The [Webpack chapter](../01-bundlers/40.5.1.01-webpack.md) owns the bundler graph/runtime example. Do not copy a long webpack image-generation config unless its installed plugin version and emitted outputs have been checked.

## Fonts need coverage and layout checks

Subset to the scripts and glyphs actually required by static and dynamic content. A Latin-only subset does not cover all user names or translated text. Use `unicode-range` to help select applicable font resources, but keep a suitable fallback for omitted characters. Variable fonts can combine supported weight/axis ranges; they do not always yield the smallest required download.

`font-display: swap` displays fallback text while a font loads, but a later metric change can still shift layout. Compare fallback metrics and use compatible overrides where appropriate. Preload only fonts actually critical to the initial view, with matching URL/type/crossorigin settings; unused preloads consume bandwidth. Self-hosting and preloading do not guarantee zero flash or zero layout shift.

## Finalize bytes before publishing cache identities

Use immutable content identities for public assets whose URL always means the same bytes. HTML or a release manifest selects current identities and usually needs a different freshness policy. Deploy references and targets together, retain old lazy chunks for active sessions, and verify subpath/CDN URLs. Hashing alone does not supply those lifecycle guarantees.

If a source-map/debug-ID tool changes JavaScript after filenames were calculated, the filename no longer reflects those final bytes. Use a supported build integration at the correct stage, or recompute the identity and every reference. Upload source maps associated with the final artifact/release, verify an intentional error maps to the correct source, then remove maps from public artifacts if policy requires it. Preserve private copies for incident diagnosis. Public bundles still expose client behavior; removing maps does not hide secrets that were compiled into JavaScript.

## Decisions and failures

| Situation | Decision boundary |
| ------------------------ | ---------------------------------------------------------------------------------- |
| Static marketing images | Pre-generate measured variants; test real layout and hero loading. |
| Unbounded user uploads | Separate a bounded processing service from the application build. |
| Dynamic class choices | Map values to complete detected candidates or explicit supported source rules. |
| Multilingual fonts | Verify glyph coverage and fallback metrics, including newly entered content. |
| CSS imports dropped | Preserve stylesheet side effects and test emitted production styles. |
| Old tab requests a chunk | Retain compatible old artifacts or implement a tested recovery response. |
| Diagnostic upload fails | Follow release policy; do not falsely declare maps available to the error tracker. |

## Mistakes and best practices

Measure emitted and transferred bytes, critical-path requests and field rendering outcomes separately. Do not claim build-time work is free, CDN delivery compresses uploads automatically, hidden maps cannot be downloaded, or every image should cap pixel ratio at two. Pin transforms, account for cache inputs and run production route, font, image and error-mapping checks. Local generation verifies a representation; it does not establish browser quality or production performance.

## Summary

An asset pipeline preserves resource meaning while transforming bytes and references for deployment. CSS compatibility, image quality, font coverage, finalized content identities and diagnostic maps have separate contracts. Validate the emitted page and release lifecycle rather than infer correctness from a successful build or a fixed savings table.

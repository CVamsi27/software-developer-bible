# Asset Pipelines — CSS, Images & Fonts

> **JavaScript gets all the build-tool attention; the bytes that actually dominate your page weight are CSS, images, and fonts.** A senior-grade asset pipeline transforms CSS with PostCSS/Lightning CSS, compiles Tailwind from scanned sources, generates responsive image sets with sharp at build time, subsets and preloads fonts, fingerprints every artifact for immutable caching, and emits source maps that reach your error tracker — not your users. This file covers each stage of that pipeline, why it runs at build time rather than runtime, and concrete Vite/webpack configurations for all of it.

## TL;DR

- **CSS pipeline**: source (authoring syntax) -> imports/resolution -> vendor prefixing + downleveling (Autoprefixer or Lightning CSS) -> minification -> content-hashed filename.
- **Lightning CSS** (formerly Parcel CSS) does parsing/prefixing/minification in Rust — 100x faster than the PostJS chain and increasingly the default (Vite option, Tailwind v4 engine).
- **Tailwind compile path**: scan templates for class candidates -> generate only those utilities -> tree-shaken CSS output; v4 uses an Oxide/Lightning-based engine; `safelist` is the escape hatch for dynamic classes.
- **Images**: optimize AT BUILD TIME with sharp (or squoosh): AVIF/WebP variants, responsive `srcset` widths, lazy-loading attributes; never ship a 4 MB hero JPEG.
- **Fonts**: subset (unicode-range or glyph subsetting), WOFF2 only, self-host, `font-display: swap`, `<link rel="preload">` only for the critical one or two faces.
- **Fingerprinting**: content-hash every emitted asset (`app.a1b2c3.css`) so caches can be `immutable`; HTML references come from the generated manifest.
- **Source maps**: hidden/sentry strategy for production — upload to error tracker, never deploy publicly.
- **In interviews: "how do you ship fast CSS/images/fonts?" — pipeline stages + immutable hashing + format choices with fallbacks.**

---

## Definition

An **asset pipeline** is the set of build steps transforming non-JS resources — stylesheets, images, fonts, icons — into optimized, cacheable artifacts referenced by hashed URLs. It runs in bundlers (Vite/Rollup, webpack) via plugins/loaders, and its outputs are: transformed+minified CSS, responsive raster sets, subset fonts, fingerprinted filenames, and source maps.

Pipeline stages:

```text
source assets
                                                                │
   ├─ CSS ─────► resolve @import ─► prefix/downlevel ─► minify ─┐
   ├─ Tailwind ► scan classes ──► generate utilities ──────────┤
   ├─ images ───► decode (sharp) ─► encode avif/webp + resize ─┤
   ├─ fonts ────► subset ─► woff2 ─────────────────────────────┤
                                                                │                                                            ▼
                                                                │                                    emit dist/*.[hash].ext + manifest.json
   │                                                            │
   └─ sourcemaps ───────────────────────► upload to Sentry ─────┤
                                                                ▼
                                              HTML references hashed URLs
```

## Why Do We Need It?

1. **Bytes dominate performance budgets.** On a typical marketing page, images are 60-70% of weight and fonts 5-10%; JS optimization alone cannot fix that math.
2. **Browsers reward the right formats.** AVIF/WebP cut image bytes 30-90% vs JPEG/PNG; WOFF2 + subsetting cuts font files 50-80%. But support varies — pipelines generate fallbacks automatically.
3. **Caching needs immutability.** Long-lived caches require content that never changes under the same URL; content hashes make every asset permanently cacheable while remaining safe to redeploy.
4. **Runtime optimization is too late and too expensive.** Resizing images per-request burns server CPU; build-time generation costs nothing per user.
5. **Debuggability must survive minification.** Source maps routed to error trackers keep production stack traces meaningful without leaking source code publicly.

## How It Works

### 1. The CSS transformation chain

| Stage | Tool | Purpose |
| ------------------------ | --------------------------------------- | --------------------------------------------------------------------------- |
| Authoring | plain CSS / SCSS / PostCSS plugins | Nesting, variables, mixins |
| Import resolution | postcss-import / bundler | Inline `@import`s into one sheet |
| Prefixing + downleveling | Autoprefixer (postcss) or Lightning CSS | `-webkit-` prefixes, logical properties fallback, targets from browserslist |
| Minification | cssnano / Lightning CSS / esbuild | Whitespace, merge rules, shorten colors |
| Emission | MiniCssExtractPlugin / Vite built-in | Separate file + hash |

Two modern consolidation points:

- **Lightning CSS** replaces the whole chain (transform + prefix + minify) as a single Rust binary. In Vite: `build.cssTransformer: 'lightningcss'`. Standalone CLI also works for non-bundled flows.
- **Tailwind v4** embeds Lightning CSS internally — compiling utilities and optimizing output in one pass.

### 2. Tailwind's compilation path

```text
TEMPLATES                     COMPILER                    OUTPUT
*.tsx, *.html, *.vue  scan ──► candidate class set ──►  utilities.css
"flex items-center p-4         { flex, items-center,     (~10 KB, was 3 MB
 md:w-1/2 bg-slate-900..."       p-4, md\:w-1\/2, ... }    in v2 default)

v3: JIT engine, tailwind.config.ts content globs
v4: oxide scanner + lightningcss engine, config moves INTO css
    (@theme directive), zero-config content detection
```

Key behaviors:

- Only classes found in scanned files are emitted — the "tree shaking of CSS" effect.
- Variants (`md:`, `hover:`) expand into real media queries/pseudo-rules at build time.
- Dynamic class construction (`bg-${color}-500`) defeats scanning — use full literals or configure `safelist`.

### 3. Image optimization at build time

```text
hero.jpg (4000px, 4.2 MB)
  sharp resize(1920/1280/640)
      ├─ hero.avif        38 KB   <- best compression
      ├─ hero.webp        61 KB
      └─ hero.jpg        142 KB   <- universal fallback

HTML (generated):
<img src="/img/hero-1280.jpg"
     srcset="hero-640.avif 640w, hero-1280.avif 1280w, ..."
     sizes="(max-width: 768px) 100vw, 50vw"
     loading="lazy" decoding="async"
     type="image/avif">            <- via <picture> for real fallbacks
```

Build-time beats runtime: no request-time CPU, deterministic quality tuning, and the CDN serves static files forever.

### 4. Fonts: subsetting and loading strategy

| Technique | Effect |
| --------------------------------- | --------------------------------------------------- |
| Subset to used glyphs/scripts | Latin-only woff2 often < 25 KB |
| `unicode-range` splits | Browser downloads only needed ranges (CJK win huge) |
| Self-host + preload critical face | No third-party round trip, no FOUT flash |
| `font-display: swap` | Text renders immediately in fallback |
| Variable fonts | One file covers all weights |

Rule: preload at most 1-2 faces (the body-text regular + maybe a display bold); everything else loads lazily by usage.

### 5. Hashing/fingerprinting and caching

Content hashes turn cache policy into a one-liner: `Cache-Control: public, max-age=31536000, immutable`. Redeployments produce NEW hashes; old cached copies simply stop being referenced. The manifest maps logical names to hashed ones so HTML/CSS/SSR always point at current versions.

### 6. Source maps strategy

| Mode | Ships to browser? | Use when |
| ------------------- | ------------------------ | ------------------------------------------ |
| `hidden` | No (references stripped) | Production default with Sentry-like upload |
| `inline` | Yes, embedded | Debug builds only — huge payload |
| `nosources` partial | Names but not code | Middle ground for public sites |

Upload maps to the error tracker during CI (Sentry webpack plugin / Vite plugin), then DELETE them from `dist` before publishing.

## Code Examples

### Vite: complete asset configuration

```typescript
// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { vitePluginFaviconsInject } from "./plugins/favicon";

export default defineConfig({
  plugins: [react()],

  css: {
    transformer: "lightningcss", // replaces autoprefixer+cssnano in Rust
    lightningcss: {
      targets: { chrome: 100, firefox: 100, safari: 15 },
    },
    devSourcemap: true,
  },

  build: {
    sourcemap: true, // hidden-style handling done at deploy step
    assetsInlineLimit: 4096, // inline tiny assets as data URIs
    rollupOptions: {
      output: {
        entryFileNames: "assets/[name].[hash].js",
        chunkFileNames: "assets/[name].[hash].js",
        // Stable names + content hash for long-lived caching:
        assetFileNames: (info) =>
          info.names?.[0].endsWith(".css")
            ? "assets/[name].[hash].css"
            : "assets/[name].[hash][extname]",
      },
    },
  },
});
```

### Vite: Tailwind v4 wiring (CSS-first)

```css
/* src/index.css — Tailwind v4 style: no tailwind.config.js required */
@import "tailwindcss";

@theme {
  --color-brand: oklch(0.62 0.19 260);
  --font-display: "Inter var", system-ui, sans-serif;
}

@source "../**/*.tsx"; /* explicit globs beat magic scanning in monorepos */
```

```typescript
// vite.config.ts excerpt (v4 uses the official plugin, not postcss)
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
});
```

### webpack 5: asset modules + hashed extraction

```javascript
// webpack.config.js
const MiniCssExtractPlugin = require("mini-css-extract-plugin");
const ImageMinimizerPlugin = require("image-minimizer-webpack-plugin");

module.exports = {
  mode: "production",

  module: {
    rules: [
      {
        test: /\.css$/,
        use: [MiniCssExtractPlugin.loader, "css-loader", "postcss-loader"],
      },
      {
        // Asset modules replace file-loader/url-loader (webpack 5)
        test: /\.(png|jpe?g|gif|svg|woff2?)$/,
        type: "asset",
        parser: { dataUrlCondition: { maxSize: 4 * 1024 } },
        generator: {
          filename: "assets/[name].[contenthash][ext]",
        },
      },
    ],
  },

  plugins: [
    new MiniCssExtractPlugin({ filename: "assets/[name].[contenthash].css" }),
    new ImageMinimizerPlugin({
      minimizer: {
        implementation: ImageMinimizerPlugin.sharpMinify,
        options: { jpeg: { quality: 80 }, webp: { quality: 75 } },
      },
      generator: [
        {
          preset: "webp",
          implementation: ImageMinimizerPlugin.sharpGenerate,
          options: { encodeOptions: { webp: { quality: 75 } } },
        },
        {
          preset: "avif",
          implementation: ImageMinimizerPlugin.sharpGenerate,
          options: { encodeOptions: { avif: { quality: 65 } } },
        },
      ],
    }),
  ],

  devtool: "hidden-source-map",
};
```

### Build-time responsive sets with sharp

```typescript
// scripts/generate-images.ts
import sharp from "sharp";
import { readdirSync, mkdirSync } from "node:fs";
import { join } from "node:path";

const SRC = "src/assets/photos";
const OUT = "dist/img";
const WIDTHS = [320, 640, 960, 1280, 1920];

mkdirSync(OUT, { recursive: true });

for (const file of readdirSync(SRC).filter((f) => /\.(jpe?g|png)$/i.test(f))) {
  const base = file.replace(/\.(jpe?g|png)$/i, "");
  const input = join(SRC, file);

  await Promise.all(
    WIDTHS.flatMap((w) => [
      sharp(input)
        .resize(w)
        .avif({ quality: 65 })
        .toFile(join(OUT, `${base}-${w}.avif`)),
      sharp(input)
        .resize(w)
        .webp({ quality: 75 })
        .toFile(join(OUT, `${base}-${w}.webp`)),
      sharp(input)
        .resize(w)
        .jpeg({ quality: 80, mozjpeg: true })
        .toFile(join(OUT, `${base}-${w}.jpg`)),
    ]),
  );

  console.log(`generated ${WIDTHS.length * 3} variants for ${file}`);
}
```

### PostCSS setup when staying classic

```javascript
// postcss.config.mjs — the minimal defensible chain

```

```json

}
```

### Font-face with unicode-range + preload

```html
<!-- index.html -->
<link rel="preload"
      href="/fonts/inter-latin-var.woff2"
      as="font" type="font/woff2" crossorigin>

<style>
  @font-face {
    font-family: "Inter";
    src: url("/fonts/inter-latin-var.woff2") format("woff2-variations");
    font-weight: 100 900;
    font-display: swap;
    unicode-range: U+0000-00FF, U+2000-206F; /* latin + punctuation only */
  }
</style>
```

### Uploading hidden source maps in CI

```bash
# After vite build (dist contains *.map, HTML has no map references):
npx @sentry/cli sourcemaps inject ./dist
npx @sentry/cli sourcemaps upload --org acme --project web ./dist
find dist -name "*.map" -delete   # never publish maps publicly
```

## Real-World Use Cases

### 1. Marketing site rebuild cutting LCP by half

Hero images converted from a single 2.8 MB JPEG to a 96 KB AVIF `srcset`, fonts preloaded after subsetting, CSS switched to Lightning CSS. LCP drops 4.1s -> 1.9s with zero application-code changes — pure pipeline work.

### 2. Design-system package shipping compiled tokens

A component library publishes both Tailwind presets and precompiled Lightning CSS output; consuming apps choose their path, and the library enforces browserslist centrally instead of debugging per-app prefixes.

### 3. CJK-heavy product fixing font bloat

Full Noto Sans SC weighed 8 MB. Splitting into 120 unicode-range slices means users download ~300 KB covering their actual glyphs; preload stays reserved for the small Latin UI face.

### 4. Error triage with hidden maps

Production throws minified stack traces; Sentry de-obfuscates via uploaded maps within seconds of release. Public bundles contain no map references — competitors and attackers learn nothing from view-source.

### 5. Monorepo cache discipline

Hashed filenames plus a stable `[name]` scheme let the CI remote cache reuse unchanged asset chunks across branches; image regeneration (the slowest step) runs only when pixels actually change.

## Common Mistakes

| Mistake | Fix |
| -------------------------------------------------- | -------------------------------------------------------------------------- |
| Building dynamic Tailwind classes (`bg-${color}`) | Full literal strings; `safelist` only as last resort |
| Shipping source maps publicly | `hidden-source-map` + upload to tracker + delete from dist |
| Optimizing images per-request at the edge/server | Generate variant sets at build; serve static |
| Preloading every font face | Preload 1-2 critical faces max; lazy-load the rest |
| Double-prefixing (Autoprefixer AND Lightning CSS) | Pick one transformer; align browserslist everywhere |
| Hashing HTML itself or forgetting manifest updates | Only fingerprint leaf assets; HTML stays uncached |
| Committing `dist/` artifacts to git | Build in CI from source; artifacts live in registries/storage |
| One giant CSS bundle for MPA | Extract per-entry/per-route CSS; Vite/webpack do this with proper chunking |

---

## Best Practices

1. **Set browserslist once**, at the repo root, and derive prefixing/transpilation targets from it — mismatched targets are the top cause of double-transform bugs.
2. **Prefer one fast CSS transformer** (Lightning CSS) over stacked PostCSS plugins unless you need a specific plugin.
3. **Treat image variants as build artifacts**: AVIF primary, WebP fallback, JPEG last resort; wire `sizes=` honestly to layout columns.
4. **Subset and self-host fonts**; variable fonts for multi-weight needs; `font-display: swap` always.
5. **Fingerprint everything except HTML**, and serve hashed paths with `immutable` caching.
6. **Route source maps to tooling, never to users** — upload in CI, then delete.
7. **Keep asset steps in CI, measured**: log emitted bytes per release and alert on jumps (>10% CSS/image growth).
8. **Use `<picture>`/`type=` for AVIF adoption** until target browsers cover it fully.
9. **Scope Tailwind scanning explicitly** in monorepos (`@source` globs) to avoid both misses and accidental inclusion of vendored demos.
10. **Test the pipeline on slow 3G profiles** (Lighthouse CI) — the pipeline exists for the user on the bus, not the scorecard.

## Performance Considerations

| Asset | Typical saving from pipeline | Notes |
| ------------------------------- | ---------------------------------- | ----------------------------------------------- |
| JPEG/PNG -> AVIF/WebP sets | 30-70% bytes | Quality 65-75 usually indistinguishable |
| Full CSS -> minified + prefixed | 20-40% + fewer compat bugs | Lightning CSS also merges duplicate rules |
| Full font -> subset woff2 | 50-80% per script range | Biggest win on CJK/Arabic |
| Unhashed -> hashed + immutable | Eliminates revalidation RTTs | `immutable` skips conditional requests entirely |
| Single bundle -> per-route CSS | Removes render-blocking dead rules | Watch FOUC when splitting carelessly |

Budget rule of thumb: images should be optimized to the rendered pixel size times devicePixelRatio ceiling (cap at 2x), and total critical-path assets (CSS + fonts) under ~150 KB before JS enters the picture.

## Summary

- The asset pipeline is where most page-weight wins live: **CSS transform chains, Tailwind scanning, build-time image variants, font subsetting, hashing, and hidden source maps**.
- **Lightning CSS consolidates** the classic Autoprefixer/cssnano chain into one fast transformer; Tailwind v4 adopts it internally.
- **Tailwind emits only scanned classes** — dynamic class strings break scanning; design APIs accordingly.
- **Images: generate responsive AVIF/WebP/JPEG sets with sharp at build time**; reference via `srcset`/`<picture>`; cap DPR at 2x.
- **Fonts: subset, self-host, swap, preload sparingly.**
- **Content hashes enable `immutable` caching**; manifests keep references correct across deploys.
- **Source maps belong to your error tracker**, not your CDN.
- **In interviews: name the five stages, give the AVIF-vs-JPEG numbers, and explain why hashing makes deploys cache-safe.**

## Cheat Sheet

```text
ASSET PIPELINES CHEAT SHEET
════════════════════════════════════════════════════════════════

CSS CHAIN
  author -> @import resolve -> prefix/downlevel -> minify -> emit[hash]
  modern: Lightning CSS (one Rust pass) | classic: postcss-import +
          autoprefixer + cssnano | targets <- ONE browserslist

TAILWIND PATH
  scan templates -> candidate set -> emit ONLY those utilities
  v3: config.content globs + JIT | v4: @theme in CSS, lightning inside
  dynamic classnames break scanning -> literals or safelist

IMAGES (BUILD TIME, sharp)
  resize widths [320,640,960,1280,1920] x [avif q65 | webp q75 | jpg q80]
  ship: srcset + sizes + <picture> fallback | lazy-load below fold

FONTS
  subset (unicode-range) -> woff2 only -> self-host ->
  font-display: swap -> preload 1-2 faces MAX

HASHING & CACHING
  filename = [name].[contenthash].[ext]
  Cache-Control: public, max-age=31536000, immutable
  HTML: NO cache, references via manifest

SOURCE MAPS
  prod: hidden-source-map -> upload (Sentry CLI) -> delete *.map
  never: inline maps in production

VITE vs WEBPACK HOOKS
  Vite : css.transformer=lightningcss, assetFileNames[hash],
         @tailwindcss/vite plugin
  webpack: asset modules + [contenthash], MiniCssExtractPlugin,
           ImageMinimizerPlugin(sharp), devtool: hidden-source-map

INTERVIEW FORMULA
  5 stages -> format numbers (AVIF -50%, woff2 subset -70%) ->
  immutable caching story -> maps-to-Sentry -> measure with LH CI
```

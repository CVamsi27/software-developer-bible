# AWS Lambda

Traffic can fan one Lambda function out across many execution environments. A database client initialized at module load can be reused in that environment, but it is not one pool for the whole function: separate environments can open separate pools, and Managed Instances may share a client among concurrent handlers. If a payment commits just before a timeout, a retry can also repeat the command. The safe design depends on the compute mode and trigger, not just on the handler code.

## Definition

AWS Lambda is a managed compute service that runs function code in response to direct requests or events. AWS manages the execution infrastructure; the developer still configures the runtime, permissions, trigger, scaling limits, and failure behavior.

> **Textbook Definition:** AWS Lambda is an event-driven compute service that executes configured function code in isolated, provider-managed environments. Invocation semantics, environment concurrency, scaling, maximum duration, and retries depend on the selected compute mode and event source.

## First Principles

Lambda hides host allocation, but a function version is not a singleton process. The service can create several isolated execution environments and may reuse each one. Process-local state therefore belongs to one environment, not to the function as a whole. Reusable clients can be initialized outside the handler; durable business decisions cannot depend on which environment receives a request. More invocations create more downstream work, but they do not increase a database's connection budget — so the account quota, function concurrency cap, scaling rate, and dependency budget constrain different parts of the path. A caller can also retry after a lost response, so a committed side effect needs a stable operation ID.

## How It Works

### 1. Follow Default-Mode Invocation and Environment Lifecycle

```text
new environment -> runtime/application initialization -> invocation
                                                       -> possible reuse
                                                       -> reset/retirement
```

Each default-mode environment has its own process memory and temporary storage. Lambda may reuse it, freeze it between invocations, or discard it; `/tmp` and module caches are not shared durable storage. Keep request data inside the handler, validate reused connections, and finish essential work before returning because background work is not guaranteed to survive environment retirement. Managed Instances has a different lifecycle, described below.

The same function can receive different event contracts: API Gateway normally waits for a synchronous response, Amazon Simple Storage Service (S3) notifications use asynchronous invocation, and Amazon Simple Queue Service (SQS) is polled through an event-source mapping. Those paths differ in payload, acknowledgment, retry, and failure routing. A dead-letter destination for asynchronous invocation does not replace a queue redrive policy or a stream checkpoint policy.

### 2. Choose the Compute and Programming Model

Most examples below use Lambda's default compute mode, where each execution environment handles one invocation at a time. AWS also offers distinct modes with different assumptions:

- **Lambda Managed Instances** run functions on customer-owned Amazon Elastic Compute Cloud (EC2) capacity selected through a capacity provider; Lambda manages its operational lifecycle. One environment can handle multiple invocations concurrently, so shared state must be thread-safe and request context isolated. The capacity provider sets scaling and is also a trust boundary: assign only mutually trusted functions to it. Scaling reacts to capacity and processor utilization rather than creating a fresh on-demand environment for each invocation, so plan for traffic ramps.
- **Lambda Durable Functions** add checkpointed steps and waits for long-running workflows, currently documented for executions up to one year. A wait can release compute, then resume from saved progress; this is a different programming model from increasing a normal handler's timeout. Durable workflows still need idempotency around external effects.

Timeouts depend on both compute mode and trigger. A standard function invocation is limited to 15 minutes. A Durable Function can preserve workflow state for up to one year, but each handler invocation still has its own timeout; an event-source mapping also caps total execution (15 minutes on default capacity or up to 90 minutes on Managed Instances).

Managed Instances can use a 90-minute function timeout for asynchronous invocations and supported event-source mappings. Synchronous invocations, initialization, and Amazon MQ or DocumentDB mappings remain limited to 15 minutes. Verify the current contract for the exact source before designing around a longer limit. See [Durable Execution](40.7.07-durable-execution-temporal-inngest.md) for workflow trade-offs.

### 3. Validate an HTTP API Handler Against Its Contract

This complete handler targets **API Gateway HTTP API payload version 2.0**, not Representational State Transfer (REST) API payload version 1. It demonstrates path/method validation and response shape using synthetic data. Install `@types/aws-lambda` and compile with the selected Node runtime. A real authenticated user lookup also needs tenant authorization, database access, and AWS Identity and Access Management (IAM) permissions; the synthetic record supplies none of those.

```typescript
import type { APIGatewayProxyHandlerV2 } from 'aws-lambda';

const demoUsers = new Map([['demo-1', { id: 'demo-1', name: 'Example User' }]]);

export const handler: APIGatewayProxyHandlerV2 = async (event) => {
  const json = (statusCode: number, value: unknown) => ({
    statusCode,
    headers: { 'content-type': 'application/json', 'cache-control': 'no-store' },
    body: JSON.stringify(value),
  });
  if (event.requestContext.http.method !== 'GET') {
    return { ...json(405, { error: 'Method not allowed' }),
             headers: { 'content-type': 'application/json', allow: 'GET',
                        'cache-control': 'no-store' } };
  }
  const id = event.pathParameters?.id;
  if (!id || !/^[a-zA-Z0-9-]{1,64}$/.test(id)) return json(400, { error: 'Invalid id' });
  const user = demoUsers.get(id);
  return user ? json(200, user) : json(404, { error: 'Not found' });
};
```

Configure the route as `GET /users/{id}` with payload version 2.0. The code's map is immutable fixture data, not a persistence example. A real software development kit (SDK) client can be initialized outside the handler, with table names validated from deployment settings and request IDs kept inside the invocation.

### 4. Protect Different Boundaries with Concurrency Settings

For standard Lambda functions, **reserved concurrency** both reserves part of account capacity and caps the function's simultaneous invocations. **Provisioned concurrency** keeps initialized environments ready for a published version or alias; traffic beyond that configured capacity can use on-demand environments and encounter initialization. Reserved concurrency is a limit and reservation, not pre-warming. These settings do not describe Lambda Managed Instances, which use their own capacity-provider controls.

For standard on-demand functions, AWS currently documents a per-function rate of up to 1,000 additional execution environments per ten seconds. This is a scaling-rate limit, separate from the account concurrency quota; also check the trigger's limits. At 500 requests/s and 0.2 seconds mean duration, average concurrency is about 100 before tail latency and retries.

Set queue consumer maximum concurrency and database connection budgets together. Amazon Relational Database Service (RDS) Proxy can pool or multiplex supported connections, but transaction pinning and database capacity still matter. Aurora Serverless scales database resources; it does not automatically become a replacement connection proxy.

### 5. Retry with Batch Checkpoints, Not Blind Replays

For an SQS Standard queue, process independent records and report failed IDs using `ReportBatchItemFailures` on the **event-source mapping**. Without that mapping configuration, returning a partial-failure object does not establish the intended retry behavior. Successful writes still need durable business idempotency.

For first-in, first-out (FIFO) processing, stop after a failure and report failed plus unprocessed records so later records do not overtake earlier ones. Queue-side deduplication has a bounded window; it does not replace receiver-enforced command identity for external payments or durable writes. See [serverless patterns](40.7.05-serverless-patterns.md) for the focused batch example.

For streams, checkpoints, partial batch handling, record age, and retry limits govern how one bad record can block a partition. Configure supported failure destinations and rehearse replay. A Lambda async invocation destination is a separate mechanism from a queue's redrive policy.

On Managed Instances, an invocation timeout marks the request as failed but does not forcibly stop its handler code. It may keep using a runtime worker and commit side effects after the caller has received an error. Check the remaining time and stop at a safe boundary; never assume a timeout rolled the operation back.

### 6. Optimize Startup Without Hiding State Hazards

Measure initialization, handler central processing unit (CPU) time, I/O, and full request latency separately. Package size, initialization work, runtime/configuration, and load shape all affect startup; fixed runtime rankings and Elastic Network Interface (ENI) attachment penalties are not portable measurements. Current Amazon Virtual Private Cloud (VPC) networking uses managed Hyperplane ENIs rather than attaching a fresh ENI for every invocation. Private subnet egress, network address translation (NAT), endpoints, security groups, and DNS remain explicit design concerns.

SnapStart initializes a published version and restores environments from a snapshot. As verified on 2026-10-14, AWS lists Java 11+, Python 3.12+, and .NET 8+ as supported managed runtimes; Node.js is not supported. Confirm current regions, packaging, and compatibility restrictions before enabling it. SnapStart cannot be combined with provisioned concurrency under the current contract.

A random ID or expiring credential captured during initialization can be reused or stale after restoration. Generate per-operation uniqueness after restore and reconnect/refresh resources as required. SnapStart does not make `/tmp` universally read-only or remove the need for safe retries.

### 7. Package, Deploy, and Roll Back Deliberately

Choose a ZIP archive or a Lambda-compatible container image. A Lambda image is an invocation runtime image, not a long-running HTTP container service. Layers package shared dependencies under versioned references, but their extracted contents still count toward the function package-size quota.

Build for a currently supported runtime, architecture, and native dependency application binary interface (ABI). Publish a version, route production through an alias, and test a canary/rollback policy. Provisioned concurrency attaches to the version/alias configuration, not an arbitrary mutable source folder. IAM grants should cover only the resources and actions required by the handler.

An alias rollback changes code routing; it does not undo committed database writes or external effects. Use compatible schema changes and preserve business command IDs across rollout/retry boundaries.

## Code Examples

Operate the whole request path: track duration distributions, initialization/restore time, concurrent executions, throttles, downstream saturation, queue age, and failed-event backlog. Structured logs need correlation IDs and sensitive-data controls. Tracing does not automatically cover every asynchronous hop without context propagation.

Do not use `/tmp` as the authoritative store, decode binary images with `transformToString()`, or buffer an unbounded S3 object before processing. Validate object version and size, then stream binary data or hand large transformations to a suitable job service. Check the actual handler event shape instead of relying on a generic "Lambda" label.

## Summary

Lambda's compute modes define important runtime differences: default functions process isolated invocations, Managed Instances add per-environment concurrency, and Durable Functions add checkpointed workflow execution. For each, identify the event contract, bound pressure on dependencies, make retries safe, and deploy through versioned configuration. Measure the actual runtime and end-to-end path.

# AWS Lambda

## Definition

AWS Lambda is a serverless compute service that runs your code in response to events and automatically manages the underlying compute resources. You upload code as a Lambda function and the service manages execution environments under its trigger, runtime and capacity contracts.

> **Textbook Definition:** AWS Lambda is a managed event-driven compute service that executes functions in provider-managed environments, with invocation behavior governed by trigger type, concurrency, runtime limits, and retry configuration.

## First Principles

Lambda can create several execution environments for one function and reuse each environment for later invocations. Process-local state therefore belongs to a particular environment, not the function as a whole. Reusable clients can be hoisted; durable business decisions cannot depend on which environment receives a request.

Each additional concurrent invocation consumes capacity and may create downstream work. The account quota, function concurrency cap, scaling rate and database budget constrain different parts of that path. An event can also be retried after a lost acknowledgment, so a successful handler must have a recoverable side-effect contract.

## Invocation and environment lifecycles

```text
new environment -> runtime/application initialization -> invocation
                                                       -> possible reuse
                                                       -> reset/retirement
```

There is no promised three-minute idle shutdown. `/tmp` and module caches may survive reuse but are not shared durable storage. Clean up temporary/request-specific data and validate reused connections. Avoid starting essential unawaited work at handler return: the environment can be frozen or discarded.

API Gateway invokes synchronously; an S3 notification usually invokes asynchronously; SQS uses a polling event-source mapping. Their retries, dead-letter behavior and acknowledgments differ. A stream destination is not configured by simply adding the same async invocation dead-letter setting everywhere.

## A focused, validated HTTP API handler

This complete handler targets **API Gateway HTTP API payload version 2.0**, not REST API version 1. It demonstrates path/method validation and response shape using synthetic data. Install `@types/aws-lambda` and compile with the selected Node runtime. A real authenticated user lookup also needs tenant authorization, database access and IAM permissions; the synthetic record supplies none of those.

```typescript
import type { APIGatewayProxyHandlerV2 } from 'aws-lambda';

const demoUsers = new Map([['demo-1', { id: 'demo-1', name: 'Example User' }]]);

export const handler: APIGatewayProxyHandlerV2 = async (event) => {
  const json = (statusCode: number, value: unknown) => ({
    statusCode,
    headers: { 'content-type': 'application/json', 'cache-control': 'no-store' },
    body: JSON.stringify(value),
  });
  if (event.requestContext.http.method !== 'GET') {
    return { ...json(405, { error: 'Method not allowed' }),
             headers: { 'content-type': 'application/json', allow: 'GET',
                        'cache-control': 'no-store' } };
  }
  const id = event.pathParameters?.id;
  if (!id || !/^[a-zA-Z0-9-]{1,64}$/.test(id)) return json(400, { error: 'Invalid id' });
  const user = demoUsers.get(id);
  return user ? json(200, user) : json(404, { error: 'Not found' });
};
```

Configure the route as `GET /users/{id}` with payload version 2.0. The code's map is immutable fixture data, not a persistence example. A real SDK client can be initialized outside the handler, with table names validated from deployment settings and request IDs kept inside the invocation.

## Concurrency protects different boundaries

**Reserved concurrency** both reserves part of account capacity and caps this function's simultaneous invocations. **Provisioned concurrency** maintains initialized environments on a published version/alias; requests beyond that capacity may use on-demand environments and encounter initialization. Reserved capacity is not itself pre-warming.

AWS currently documents a per-function scaling rate of 1,000 additional environments per ten seconds. Read the current account quota and trigger-specific limits too; a historical region-wide “500–3,000 burst” table is not the current model. At 500 requests/s and 0.2 s mean duration, average concurrency is about 100 before tail latency and retries.

Set queue consumer maximum concurrency and database connection budgets together. RDS Proxy can pool/multiplex supported connections, but transaction pinning and database capacity still matter. Aurora Serverless scales database resources; it does not automatically become a replacement connection proxy.

## Retries and batch checkpoints

For an SQS Standard queue, process independent records and report failed IDs using `ReportBatchItemFailures` on the **event-source mapping**. Without that mapping configuration, returning a partial-failure object does not establish the intended retry behavior. Successful writes still need durable business idempotency.

For FIFO processing, stop after a failure and report failed plus unprocessed records so later records do not overtake earlier ones. Queue-side deduplication has a bounded window; it does not replace receiver-enforced command identity for external payments or durable writes. See [serverless patterns](40.7.05-serverless-patterns.md) for the focused batch example.

For streams, checkpoints, partial batch handling, record age and retry limits govern how one bad record can block a partition. Configure supported failure destinations and rehearse replay. A Lambda async invocation destination is a separate mechanism from a queue's redrive policy.

## Optimize startup without hiding state hazards

Measure initialization, handler CPU, I/O and full request latency separately. Package size, initialization work, runtime/configuration and load shape all affect startup; fixed runtime rankings and ENI-attachment penalties are not portable measurements. Current VPC networking uses managed Hyperplane ENIs rather than attaching a fresh ENI for every invocation. Private subnet egress, NAT/endpoints, security groups and DNS remain explicit design concerns.

SnapStart initializes a published version and restores environments from a snapshot. As verified on 2026-10-10, the official page lists Java 11+, Python 3.12+ and .NET 8+; Node.js is not supported. Confirm current regions, packaging and compatibility restrictions before enabling it. It cannot be combined with provisioned concurrency under the current contract.

A random ID or expiring credential captured during initialization can be reused or stale after restoration. Generate per-operation uniqueness after restore and reconnect/refresh resources as required. SnapStart does not make `/tmp` universally read-only or remove the need for safe retries.

## Packaging, deployment and rollback

Choose ZIP or a Lambda-compatible container image. A Lambda image is an invocation runtime image, not a long-running HTTP container service. Layers share packaged dependencies and version references; they do not remove those bytes from the function's total extracted-size budget.

Build for a currently supported runtime, architecture and native dependency ABI. Publish a version, route production through an alias and test a canary/rollback policy. Provisioned concurrency attaches to the version/alias configuration, not an arbitrary mutable source folder. IAM grants should cover only the resources and actions required by the handler.

An alias rollback changes code routing; it does not undo committed database writes or external effects. Use compatible schema changes and preserve business command IDs across rollout/retry boundaries.

## Operational decisions and common mistakes

Track duration distributions, initialization/restore time, concurrent executions, throttles, downstream saturation, queue age and failed-event backlog. Structured logs need correlation IDs and sensitive-data controls. Tracing does not automatically cover every asynchronous hop without propagation.

Avoid using `/tmp` as the authoritative store, decoding binary images with `transformToString()`, or buffering an unbounded S3 object before processing. Validate object version/size and stream binary data or hand large transformations to a suitable job service. Check the actual handler event shape instead of relying on a generic Lambda label.

## Summary

Lambda executes bounded, trigger-specific work in reusable provider environments. Hoisted clients improve efficiency while external authority preserves state. Concurrency controls, correct batch checkpoints, stable command identity and versioned deployment are distinct contracts. Measure startup and dependency behavior on the actual supported runtime rather than repeating old latency tables.

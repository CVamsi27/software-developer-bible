# Serverless & Edge Interview Questions

## First Principles

An answer must identify the lifetime, authority, delivery and capacity boundaries. Explain the mechanism, trace acknowledgment loss or overload, then choose a runtime/policy from that evidence. Use actual shipped evidence when available; label hypothetical designs honestly.

## Practice after revision

These 32 preserved prompts progress from service contracts to recovery and architecture. Each answer links to its canonical chapter; revisit that mechanism when you cannot explain a changed failure scenario.

## Foundations

**Q1: What is serverless computing?**

**Answer:** Serverless delegates execution-environment provisioning to a provider under explicit runtime, scaling and billing contracts. The application still owns authorization, data, downstream capacity and recovery. Scale-to-zero and GB-second pricing are service-specific, not universal properties.

Source: [Mechanism and boundaries](40.7.01-serverless-overview.md).

**Q2: What are the benefits of serverless?**

**Answer:** Provider-managed capacity can reduce host operations and idle compute for suitable workloads. Quotas, burst ramp-up, retries, startup, dependency capacity and total cost remain constraints. Compare a workload trace with container/VM alternatives before claiming lower cost or latency.

Source: [Mechanism and boundaries](40.7.01-serverless-overview.md).

**Q3: What is AWS Lambda?**

**Answer:** Lambda executes trigger-specific handlers in managed environments. HTTP, async invocations, queues and streams have different event and retry contracts. Select a supported runtime/package/architecture and test the actual trigger shape rather than treating every event as an HTTP request.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q4: What is a cold start?**

**Answer:** A new or restored environment may require runtime/application initialization before useful work. Scale-out and deployments can cause startup as well as inactivity. Measure the actual package and full request distribution; no fixed Node/Java range is portable.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q5: What are edge functions?**

**Answer:** Edge functions place suitable logic in distributed serving locations. Startup, APIs, CPU and elapsed limits differ by provider; remote database access can dominate despite nearby ingress. Current Workers support selected Node APIs, and current Next.js/Vercel runtime guidance must be checked by version.

Source: [Mechanism and boundaries](40.7.04-edge-functions.md).

**Q6: What is the difference between API Gateway HTTP API and REST API?**

**Answer:** HTTP API and REST API expose different gateway features and event formats. Choose from required authorization, transformations, validation, usage-plan/WAF integrations and current cost. A percentage price claim does not establish the best choice for every route or traffic model.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

## Runtime and delivery

**Q7: How do you reduce cold start latency?**

**Answer:** Measure initialization separately, trim unused packaged work, and reuse reconnectable clients. Provisioned concurrency maintains a bounded initialized capacity; SnapStart applies only to supported configurations and needs restore-safe uniqueness/credentials. Neither removes downstream latency or every startup case.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q8: How do you handle errors in serverless functions?**

**Answer:** Classify failure by trigger: caller/gateway policy for synchronous requests, async invocation settings, queue redrive/partial batches, and stream checkpoint policy. Retain stable business identity, alert on unresolved work and rehearse replay. A generic DLQ setting is not shared by every trigger.

Source: [Mechanism and boundaries](40.7.05-serverless-patterns.md).

**Q9: What is the maximum execution time for Lambda?**

**Answer:** Default-capacity invocations have a 15-minute maximum. Managed Instances permit up to 90 minutes for asynchronous invocations and supported event-source mappings; synchronous calls, Amazon MQ and DocumentDB mappings retain the 15-minute ceiling. Durable execution has a separate total timeout, and event-source mappings constrain that total as well. Queue visibility and long polling do not extend these limits.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q10: What is a Lambda layer?**

**Answer:** A layer packages shared dependencies under versioned references, normally extracted into /opt for ZIP-based functions. It still counts toward applicable extracted-size/layer limits and must match runtime/architecture. Sharing packaging does not automatically reduce total initialization work.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q11: What is the difference between SQS and SNS?**

**Answer:** SQS buffers work for competing consumers, while SNS fans out to independent subscriptions. Delivery/ordering/retention vary by queue/topic type and configuration, so no blanket no-retention rule fits every SNS mode. SNS-to-SQS gives each subscriber its own backlog and recovery policy.

Source: [Mechanism and boundaries](40.7.05-serverless-patterns.md).

**Q12: What is Lambda concurrency and how do you control it?**

**Answer:** Estimate average active concurrency from arrival rate × duration, then account for tails/retries. For default-capacity functions, reserved concurrency allocates and caps function capacity; provisioned concurrency maintains initialized capacity. Managed Instances use capacity-provider controls. Verify actual account/function/trigger quotas and scaling rate, and protect downstream budgets.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

## Senior decisions

**Q13: How do you handle long-running processes in serverless?**

**Answer:** Persist coordination through an engine when work needs durable waits and recovery. Split effect boundaries into idempotent tasks with timeouts, or choose a job/container for genuinely long continuous computation. Standard/Express Step Functions differ; neither queue leases nor a workflow definition overrides a task runtime limit.

Source: [Mechanism and boundaries](40.7.07-durable-execution-temporal-inngest.md).

**Q14: How do you implement connection pooling in Lambda?**

**Answer:** Reuse supported reconnectable clients and bound total function/consumer concurrency against usable database capacity. RDS Proxy can pool/multiplex supported connections, subject to pinning and database limits. Aurora Serverless scaling is not automatically a connection proxy.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q15: What is the impact of VPC on Lambda?**

**Answer:** Current Lambda VPC networking uses managed Hyperplane ENIs; old per-invocation attach delays and arbitrary memory penalties are misleading. Configure private routes, NAT/endpoints, DNS and security groups from actual dependency access. Measure connectivity and startup instead of assuming VPC is always harmful.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q16: How do you test serverless functions locally?**

**Answer:** Call pure handlers with the correct event fixtures, test generated infrastructure, and use local tools for fast feedback. SAM/Docker and offline emulators do not prove live IAM, routing, retries or quotas. Targeted staging integration tests establish those provider boundaries.

Source: [Mechanism and boundaries](40.7.06-serverless-frameworks.md).

**Q17: What is Lambda@Edge vs CloudFront Functions vs Cloudflare Workers?**

**Answer:** The three services have different trigger, runtime, API, deployment and resource contracts. Choose CloudFront request/response transforms, regional/origin processing, or Worker logic from the required mechanism and data path. Verify current quotas rather than mixing old memory/time numbers into one comparison.

Source: [Mechanism and boundaries](40.7.04-edge-functions.md).

**Q18: How do you handle authentication at the edge?**

**Answer:** Verify token signature under allowed algorithms/keys and validate issuer, audience, time constraints and tenant permissions. A replicated denylist can be stale; choose an authoritative revocation path or explicit expiry trade-off. Backend bypass protection and cache variation are part of the boundary.

Source: [Mechanism and boundaries](40.7.04-edge-functions.md).

**Q19: How do you implement idempotency in Lambda?**

**Answer:** Choose a stable business operation ID, compare its input identity, and commit a receipt with the database effect where possible. A check-then-write flag leaves crash/race windows; a claimed-but-unfinished operation also needs recovery. For external effects, use receiver-enforced identity or reconciliation; TTL expiration can reopen duplicates.

Source: [Mechanism and boundaries](40.7.05-serverless-patterns.md).

**Q20: How do you migrate from a monolith to serverless?**

**Answer:** Extract a bounded capability with a measurable contract, route controlled traffic, and preserve clear data ownership. Test failure/rollback and event publication before expanding scope. Falling back after a timed-out write can duplicate effects unless the old and new paths share an authoritative operation protocol.

Source: [Mechanism and boundaries](40.7.01-serverless-overview.md).

**Q21: What is Lambda SnapStart and when do you use it?**

**Answer:** SnapStart restores initialized snapshots for currently supported Java, Python and .NET configurations; check runtime, region and packaging restrictions. Captured random IDs, credentials and connections need restore-safe handling. It does not make /tmp universally read-only, and cannot currently combine with provisioned concurrency.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q22: How do you debug serverless in production?**

**Answer:** Correlate logs/traces with command IDs and measure errors, throttles, concurrency, dependency saturation and backlog age. Protect sensitive payloads and distinguish sampled evidence from complete audit. Replaying an event can repeat real effects; sanitize/isolate it and preserve business identity rather than blindly republishing production input.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

## Architecture scenarios

**Q23: Design a serverless architecture for a real-time chat application.**

**Answer:** Separate connection ownership, durable message acceptance, membership authorization and replay. API Gateway WebSocket integrations invoke handlers, while a bounded fan-out worker calls the management API and cleans stale connection IDs. SNS does not automatically invoke every connected client; sequence/cursor state and reconnect/offline behavior remain explicit.

Source: [Mechanism and boundaries](40.7.05-serverless-patterns.md).

**Q24: How would you implement CI/CD for a serverless application?**

**Answer:** Pin/build/test the artifact, inspect generated changes, verify staging provider boundaries, then promote identified versions under scoped credentials. Use current platform drift mechanisms, not an invented sam drift detect command. Rollback code routing separately from compatible schema and external effects.

Source: [Mechanism and boundaries](40.7.06-serverless-frameworks.md).

**Q25: Explain serverless at scale — what breaks first?**

**Answer:** The first limit depends on the workload: startup, ramp-up, account quota, database pool, queue age, log cost or payload size. Measure the full path under bursts and failures before increasing capacity. More function concurrency can make a saturated dependency fail faster.

Source: [Mechanism and boundaries](40.7.01-serverless-overview.md).

**Q26: How do you handle a 100x traffic spike in a serverless system?**

**Answer:** Admit bounded work, cache eligible public reads, queue retry-safe asynchronous commands and shed overload deliberately. Provision upstream and downstream budgets together; a raised Lambda quota alone is insufficient. Region failover must preserve authority and operation identity instead of multiplying uncertain writes.

Source: [Mechanism and boundaries](40.7.05-serverless-patterns.md).

**Q27: Design a serverless data pipeline for analytics.**

**Answer:** Choose ingestion delivery/ordering, event schemas and stable identities first. Persist bounded partitions, handle late/duplicate events and replay/rebuilds, then govern catalog/query access and scanned-data cost. A list of managed services does not define completeness, freshness, or recovery.

Source: [Mechanism and boundaries](40.7.05-serverless-patterns.md).

## Operational follow-ups

**Q28: How do you handle secrets in serverless?**

**Answer:** Use scoped runtime identity and a supported secret store/retrieval mechanism. Define caching, refresh, rotation and failure behavior; not every parameter store rotates values automatically or injects a live value into Lambda. Never place secret values in public build variables, telemetry or source.

Source: [Mechanism and boundaries](40.7.02-aws-lambda.md).

**Q29: What is the impact of serverless on database design?**

**Answer:** Short-lived/concurrent compute can amplify connection churn and retries. Select data authority, transaction/idempotency guarantees, pooling and locality before choosing a store. DocumentDB still has connection management; calling a database connectionless or serverless does not prove its suitability.

Source: [Mechanism and boundaries](40.7.01-serverless-overview.md).

**Q30: How do you handle rate limiting in serverless?**

**Answer:** Separate ingress shaping, tenant quotas, concurrent execution caps and business admission. A global/critical quota needs an atomic authority with explicit key and time-window policy; an eventually consistent KV increment is insufficient. Provider throttles/usage plans can be best-effort and vary by gateway type; verify current account quotas.

Source: [Mechanism and boundaries](40.7.04-edge-functions.md).

**Q31: What are the cost considerations for serverless?**

**Answer:** Budget the service’s actual request/compute/provisioned-capacity model plus transfer, storage, logs, queues and histories. Measure cost per successful operation including retries and idle minimums. Standard/Express workflows and Fluid Compute have distinct models; fixed generic prices are not a reliable estimate.

Source: [Mechanism and boundaries](40.7.01-serverless-overview.md).

**Q32: How do you secure serverless applications?**

**Answer:** Enforce tenant authorization and least-privilege runtime identity, validate bounded input, protect secret lifecycle and dependencies, and isolate untrusted builds/previews. VPC, encryption, WAF and code signing each address a specific threat; none proves an API’s application authorization or removes the need for tested recovery.

Source: [Mechanism and boundaries](40.7.04-edge-functions.md).

## Summary

- Choose function, container or edge execution from the workload and provider contract
- Master cold start mechanics, concurrency limits, and event-driven patterns
- Know the trade-offs: per-request cost, vendor lock-in, observability challenges
- Be ready to design: real-time chat, data pipelines, CI/CD, cost-optimized APIs

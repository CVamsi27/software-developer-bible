# Vite SPA on Cloudflare Workers

> Stage 10 of the [Serverless & Edge](INDEX.md) — prev: [Fly.io Deployment](40.7.09-flyio-deployment.md)

## Definition

A Vite SPA deployment on Cloudflare Workers combines **built static assets** with an optional **Worker script**. Static Assets serves the HTML, JavaScript, CSS and other build files. The script can handle selected API paths or other dynamic behavior. This chapter uses a same-origin HTTP API proxy; it does not replace the backend that owns authorization and persistence.

> **Textbook Definition:** A Vite single-page application deployment on Cloudflare Workers serves generated static assets and, when configured, executes Worker logic for dynamic routes under a shared deployment and routing configuration.

## First Principles

The browser needs an application shell for a client route that is not a physical file. API callers need an API response for a path that is also not a static file. A blanket HTML fallback cannot distinguish those contracts by path alone. Configure which requests reach the script before choosing how unknown navigation paths fall back to the SPA.

## Trace a Page Navigation and an API Read

1. A browser navigates to `/dashboard`: Static Assets returns the application shell for the client route.
2. The browser loads the emitted assets and the client router renders the page.
3. The app requests `/api/items?page=2`: Worker-first routing selects the script.
4. The proxy preserves method, path, query and body while selecting a configured backend origin.
5. The backend returns an authorized response; the Worker streams it to the caller.

```text
/dashboard ──> Static Assets ──> index.html + browser app
/api/items?page=2 ──> Worker ──> configured backend ──> API response
```

Static serving is usually asset-first. With modern compatibility dates, navigation requests can prefer SPA assets even for a path handled by the script. Explicit API Worker-first patterns prevent direct navigation to an API path from unexpectedly receiving `index.html`.

## Code Examples

### Keep Asset and API Routing Explicit

Assume `vite build` writes `dist/` next to this config. API_PROXY_TARGET is a trusted deployment setting containing an HTTPS origin, not a request parameter. Generate `Env` from Wrangler configuration; the ASSETS binding must be present when the code uses it.

```jsonc
// wrangler.jsonc
{
  "$schema": "./node_modules/wrangler/config-schema.json",
  "name": "spa-api-proxy",
  "main": "worker/index.ts",
  "compatibility_date": "2026-10-02",
  "compatibility_flags": ["nodejs_compat"],
  "assets": {
    "directory": "./dist",
    "binding": "ASSETS",
    "not_found_handling": "single-page-application",
    "run_worker_first": ["/api", "/api/*"]
  },
  "vars": { "API_PROXY_TARGET": "https://api.example.com" },
  "observability": { "enabled": true, "head_sampling_rate": 0.1 }
}
```

```typescript
// worker/index.ts
export default {
  async fetch(request, env) {
    const incoming = new URL(request.url);
    if (incoming.pathname !== "/api" && !incoming.pathname.startsWith("/api/")) {
      return env.ASSETS.fetch(request);
    }

    let target: URL;
    try {
      target = new URL(env.API_PROXY_TARGET);
    } catch {
      return new Response("Invalid proxy configuration", { status: 500 });
    }
    if (target.protocol !== "https:" || target.username || target.password ||
        target.pathname !== "/" || target.search || target.hash) {
      return new Response("Invalid proxy configuration", { status: 500 });
    }
    target.pathname = incoming.pathname;
    target.search = incoming.search;

    const outbound = new Request(target.toString(), request);
    // Do not pass arbitrary caller identity claims to a trusting backend.
    for (const header of ["forwarded", "x-forwarded-for", "x-real-ip", "x-user-id", "x-tenant-id"]) {
      outbound.headers.delete(header);
    }
    try {
      // Preserve the body stream; do not consume an unbounded upload into memory.
      // Manual redirects avoid silently following a backend redirect to another origin.
      return await fetch(outbound, { redirect: "manual" });
    } catch {
      return new Response("Upstream unavailable", { status: 502 });
    }
  },
} satisfies ExportedHandler<Env>;
```

This is a focused HTTP forwarding core. The backend must authenticate/authorize the forwarded cookies or token; deleting spoofable identity headers does not supply authentication. If it needs original client IP, define a vetted edge-address/trust contract separately. Validate the configured target per deployment and test forwarded Origin/Host policy. WebSockets, backend redirect rewriting, cookie Domain/Path rewriting and application deadlines require explicit additional behavior.

Hono is an optional framework for richer routing, not a requirement for serving static assets or this proxy. If using it, type all configured bindings and verify its proxy helper's current request/response behavior. Appending only `pathname` to the backend URL loses query parameters; the example above preserves `search` separately.

### Generate Types and Inspect the Build Before Deployment

```bash
npm install --save-dev wrangler typescript
npx vite build
npx wrangler types
npx tsc --noEmit
npx wrangler deploy --dry-run --outdir bundled
```

The TypeScript project must include the generated declaration file and target the Worker runtime; do not substitute broad DOM/Node declarations that hide binding mismatches. A dry run validates/builds locally and does not deploy the Worker. Pin the toolchain in the lockfile and test compatibility-date changes before promoting them.

## Measure the Correct Limit

As checked on 2026-10-02, Cloudflare's official limits page sets **64 MiB uncompressed Worker size** for both Free and Paid plans, with **no compressed-size limit**. Wrangler's `Total Upload` is the relevant uncompressed measurement; its gzip number is informational. The former 3 MB/10 MB gzip limits are obsolete.

Static Assets has separate file-count/file-size limits. The emitted browser bundles also have user-experience budgets distinct from the Worker bundle. Removing an unused dependency can help startup and maintainability even when the deployment size fits. Importing a roughly 70 KB library does not by itself exceed a 64 MiB Worker limit; fixed library sizes vary by version and tree-shaking.

## Choose Browser Performance and Deployment Policy Separately

A static application still has JavaScript download, parse, execution, hydration/client-render and data-fetch costs. “Served at the edge” does not establish a universal sub-50-ms latency or mean the shell can never be a bottleneck. Analyze the browser bundle and field experience using [bundle analysis](../../50-quality/50.3-performance-monitoring/03-optimization-and-governance/50.3.3.01-bundle-analysis.md) and the performance chapters.

Keep Vite configuration compatible with the installed major. Vite 8 uses Rolldown; do not copy an old Rollup manualChunks recipe as a version-independent default. Private source maps can support error diagnosis without being publicly served; turning all maps off is not a universal production requirement. Verify build output and upload/access policy.

## Real-World Decisions

### Keep a Same-Origin Browser API Without Hiding Backend Responsibilities

A Worker proxy lets a browser use `/api/*` on the app origin. That avoids the browser's cross-origin restriction on that particular request, but cookie scope, Secure/SameSite policy, CSRF protection and backend Origin checks still matter. Separate frontend/API origins can also work with deliberate CORS and credential policy; it is false that cookies can never work across them.

A proxy adds a hop and an operational dependency. Keep backend authorization, audit and persistence explicit. Static assets that bypass the script also bypass script-level middleware; to protect the app shell, use an applicable Access policy or deliberately run the Worker first for those paths too. An app shell is not itself the secret data boundary.

### Cache Immutable Assets Without Caching Personal API Data

Use content-hashed asset names for long-lived immutable caching; avoid applying that policy to `index.html`, mutable configuration, or private API responses. Static Assets has its own cache/header behavior, so a Worker `/assets/*` handler may not run under asset-first routing. Configure the appropriate asset header policy and verify response headers on the deployed path.

If changing headers on a fetched Response in script, create a mutable `new Response(response.body, response)` before mutation. Preserve streaming. Do not assume every fetched response has mutable headers or that missing custom headers means every asset invokes the Worker.

### Promote an Identified Build With Guarded Credentials

The deployment pipeline must account for shared source, lockfile, build/config changes and required checks, not only the app directory. A narrow path filter can skip a necessary rebuild. Use the canonical [GitHub Actions chapter](../40.3-ci-cd/01-ci-platforms/40.3.1.01-github-actions.md) for current actions, permissions, protected environments, scoped Cloudflare credentials and artifact promotion.

Preview/version URLs require the configured Cloudflare workflow; a PR does not automatically gain a preview just because a CLI deploy exists. Rehearse rollback of the Worker/assets and verify API compatibility with the separately deployed backend. Deployment rollback does not undo backend schema or external side effects.

## Common Mistakes

| Mistake | Consequence | Check |
| --------------------------------------------------------- | ------------------------------------------------- | --------------------------------------------------- |
| Old gzip budget presented as the current platform cap | False deployment failures or misleading diagnosis | Official plan limits and uncompressed Total Upload |
| SPA fallback without explicit API routing | API navigation can return HTML | Direct navigation and fetch on `/api` and `/api/*` |
| Proxy target built from path alone | Lost pagination/filter query | Compare backend request path and query |
| ASSETS used without its binding/type | Compile/runtime failure | Generated Env and config-schema validation |
| Immutable caching applied to private or mutable responses | Data leak or stale shell/config | Route-specific cache and response policy |
| A same-origin proxy treated as authorization | Untrusted caller reaches sensitive data | Backend tenant/identity enforcement and CSRF policy |

## Best Practices

Trace asset, API and authentication paths separately. Keep target origin controlled by deployment config, preserve request/response streams and test query/body/error behavior. Measure uncompressed Worker size and browser experience independently. Generate binding types, protect secrets and telemetry, and promote a tested build with a recoverable routing configuration.

## Summary

Static Assets serves the built SPA; selected Worker-first routes implement dynamic behavior such as an API proxy. Correctness depends on fallback order, request preservation and explicit backend trust/cookie policy. Use the current uncompressed Worker limit, generated bindings and deployed-path tests instead of copying obsolete budgets or assuming edge serving removes application costs.

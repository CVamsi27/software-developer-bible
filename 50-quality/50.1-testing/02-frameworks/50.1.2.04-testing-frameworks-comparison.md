# Testing Frameworks Comparison

> **Jest vs Vitest vs Playwright — choosing the right testing tool for each layer.**

---

## First Principles

Framework choice follows from app shape and runtime, not feature checklists:

1. **The decisive axes**: transform pipeline alignment (→ 50.1.2.02), DOM vs node targets, parallelism model, ecosystem weight — a Node API and a React SPA have different optima.
2. **Migration cost is API-surface-shaped**: Jest-compatible APIs (Vitest) make the switch mechanical; bespoke APIs are the lock-in (→ 40.5.3.03's portability axis, in tests).

## Testing Pyramid

```
          ╱╲
         ╱E2E╲ ← Playwright/Cypress (5%)
        ╱──────╲
       ╱Integration╲ ← Supertest + Prisma (15%)
      ╱──────────────╲
     ╱ Unit Tests ╲ ← Jest/Vitest (80%)
    ╱────────────────────╲
```

| Layer | Framework | What It Tests | Speed | Reliability |
| --------------- | ------------------ | ------------------------------ | ------- | ----------- |
| **Unit** | Jest / Vitest | Individual functions, services | < 100ms | High |
| **Integration** | Supertest + Prisma | API routes, database queries | < 1s | High |
| **E2E** | Playwright | Full user flows in browser | < 30s | Medium |

## Jest vs Vitest

| Feature | Jest | Vitest |
| --------------------- | ------------- | ---------------------- |
| **Speed** | Medium | **Fast** (2-5x faster) |
| **ESM Support** | Partial | Native |
| **Vite Integration** | Manual config | Automatic |
| **Config Complexity** | Medium | Low (zero-config) |
| **Watch Mode** | Good | Better (HMR-aware) |
| **Snapshot Testing** | Yes | Yes |
| **Mocking** | `jest.mock()` | `vi.mock()` |
| **Coverage** | Built-in | Built-in |
| **Community** | Large | Growing fast |

### Vitest (Recommended for Vite Projects)

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    globals: true,
    environment: 'node',
    coverage: {
      provider: 'v8',
      reporter: ['text', 'html'],
      exclude: ['node_modules/', 'test/'],
    },
    setupFiles: ['./test/setup.ts'],
  },
});

// test/appointment.service.test.ts
import { describe, it, expect, vi, beforeEach } from 'vitest';
import { AppointmentService } from '../src/appointment.service';

describe('AppointmentService', () => {
  let service: AppointmentService;

  beforeEach(() => {
    service = new AppointmentService();
  });

  it('should create an appointment', async () => {
    const appointment = await service.create({
      patientId: 'patient-1',
      clinicId: 'clinic-1',
      time: new Date('2026-08-25T10:00:00Z'),
    });

    expect(appointment).toBeDefined();
    expect(appointment.patientId).toBe('patient-1');
  });

  it('should reject double-booking', async () => {
    await service.create({
      patientId: 'patient-1',
      clinicId: 'clinic-1',
      time: new Date('2026-08-25T10:00:00Z'),
    });

    await expect(
      service.create({
        patientId: 'patient-2',
        clinicId: 'clinic-1',
        time: new Date('2026-08-25T10:00:00Z'),
      })
    ).rejects.toThrow('Time slot already booked');
  });
});
```

## Playwright (E2E Testing)

Playwright tests your application in real browsers — Chromium, Firefox, and WebKit.

```typescript
// tests/appointment-booking.spec.ts
import { test, expect } from '@playwright/test';

test.describe('Appointment Booking', () => {
  test.beforeEach(async ({ page }) => {
    await page.goto('/login');
    await page.fill('[data-testid="email"]', 'doctor@clinic.de');
    await page.fill('[data-testid="password"]', 'securepassword');
    await page.click('[data-testid="login-button"]');
    await expect(page).toHaveURL('/dashboard');
  });

  test('should book an appointment', async ({ page }) => {
    await page.click('[data-testid="new-appointment"]');
    await page.fill('[data-testid="patient-name"]', 'Maria Schmidt');
    await page.fill('[data-testid="appointment-time"]', '2026-08-25T10:00');
    await page.click('[data-testid="save-appointment"]');

    await expect(page.locator('[data-testid="success-message"]'))
      .toContainText('Appointment created');
  });

  test('should prevent double-booking', async ({ page }) => {
    // Book first appointment
    await page.click('[data-testid="new-appointment"]');
    await page.fill('[data-testid="patient-name"]', 'Patient 1');
    await page.fill('[data-testid="appointment-time"]', '2026-08-25T10:00');
    await page.click('[data-testid="save-appointment"]');

    // Try to book overlapping appointment
    await page.click('[data-testid="new-appointment"]');
    await page.fill('[data-testid="patient-name"]', 'Patient 2');
    await page.fill('[data-testid="appointment-time"]', '2026-08-25T10:00');
    await page.click('[data-testid="save-appointment"]');

    await expect(page.locator('[data-testid="error-message"]'))
      .toContainText('Time slot already booked');
  });
});
```

## Supertest (API Integration Testing)

```typescript
// test/appointments.e2e.test.ts
import { Test, TestingModule } from '@nestjs/testing';
import { INestApplication } from '@nestjs/common';
import * as request from 'supertest';
import { AppModule } from '../src/app.module';

describe('Appointments API (e2e)', () => {
  let app: INestApplication;

  beforeAll(async () => {
    const moduleFixture: TestingModule = await Test.createTestingModule({
      imports: [AppModule],
    }).compile();

    app = moduleFixture.createNestApplication();
    await app.init();
  });

  afterAll(async () => {
    await app.close();
  });

  it('/POST appointments', () => {
    return request(app.getHttpServer())
      .post('/api/appointments')
      .set('Authorization', `Bearer ${VALID_TOKEN}`)
      .send({
        patientId: 'patient-1',
        clinicId: 'clinic-1',
        time: '2026-08-25T10:00:00Z',
      })
      .expect(201)
      .then((response) => {
        expect(response.body).toHaveProperty('id');
        expect(response.body.patientId).toBe('patient-1');
      });
  });

  it('/GET appointments returns paginated results', () => {
    return request(app.getHttpServer())
      .get('/api/appointments?clinicId=clinic-1&limit=10')
      .set('Authorization', `Bearer ${VALID_TOKEN}`)
      .expect(200)
      .then((response) => {
        expect(response.body.data).toBeInstanceOf(Array);
        expect(response.body.meta).toHaveProperty('total');
      });
  });
});
```

## Choosing the Right Framework

| Need | Framework | Why |
| ---------------------------- | -------------------------------- | ---------------------------------- |
| **Unit tests (TypeScript)** | Vitest | Fast, native ESM, Vite integration |
| **Unit tests (established)** | Jest | Large ecosystem, familiar |
| **API integration tests** | Supertest + NestJS TestingModule | Real HTTP requests |
| **Database integration** | Vitest + Prisma + testcontainers | Real PostgreSQL in Docker |
| **E2E browser tests** | Playwright | Cross-browser, auto-wait |
| **Component tests** | Vitest + Testing Library | Render components in jsdom |

---

## Interview Questions

**Q: "How do you choose between Jest and Vitest?"**

> Vitest for new projects — it's faster (2-5x), has native ESM support, and integrates seamlessly with Vite. Jest for established projects — larger ecosystem, more plugins, more Stack Overflow answers. For Docita: Vitest (Vite-based frontend + NestJS backend). The key difference: Vitest uses Vite's transform pipeline, so it understands TypeScript, ESM, and CSS modules without configuration.

---

## 30-Second Interview Version

> Testing pyramid: 80% unit (Vitest/Jest), 15% integration (Supertest + Prisma), 5% E2E (Playwright). Vitest: faster, native ESM, zero-config with Vite. Jest: larger ecosystem, more plugins. Playwright: cross-browser E2E with auto-wait. Supertest: HTTP integration tests. For Docita: Vitest for unit tests, Supertest for API tests, Playwright for critical user flows (booking, prescription).

## Summary

1. **The pyramid is a cost-confidence trade** — many fast units, few expensive E2E; inverting it is the most common test-suite failure
2. **Vitest vs Jest is ecosystem vs speed** — native ESM and Vite-native config make Vitest the default for new projects; Jest's plugin ecosystem still matters for legacy
3. **Playwright owns the E2E tier** — cross-browser, auto-waiting, tracing; flaky selectors are a smell, not a nuisance
4. **Integration tests hit real dependencies** — Supertest + a real database in a transaction; mocks here test your assumptions, not the system
5. **Choose per layer, not per fashion** — Vitest unit, Supertest API, Playwright critical flows — and keep the ratio honest

# Playwright: End-to-End Browser Journeys

A checkout test clicks "Submit", then asserts an order confirmation — and fails because the navigation had not finished when the assertion ran. Flaky tests like this are the reason teams abandon E2E suites. Playwright removes the guesswork: its locators auto-wait until an element is actionable, assertions retry until the condition holds or times out, and the test runs against a real browser with network control at the boundary.

```typescript
await page.getByRole('button', { name: 'Submit order' }).click();
await expect(page.getByText('Order confirmed')).toBeVisible();
```

## Definition

**Playwright** is a browser automation library for end-to-end testing. It drives Chromium, Firefox and WebKit through a single API, with **locators** that describe how to find an element, **auto-waiting** that retries actions and assertions until the page settles, and **fixtures** that give each test an isolated browser context. Network interception lets tests stub APIs, and `storageState` reuses an authenticated session instead of logging in every test.

> **Textbook Definition:** Playwright is an out-of-process browser automation tool that executes tests against real browsers, waits for elements to be actionable before acting, retries assertions until they pass or time out, and isolates every test in its own browser context with optional network interception and session storage.

## First Principles

Test against a real browser, not a simulated DOM: layout, focus, popups and network timing are real in production and should be real in the test. Resilient selectors target user-visible roles and labels, not fragile class names or DOM position. Control the network at the boundary (stub slow third parties, assert on request payloads) rather than asserting only on rendered pixels.

## 1. Locators and auto-waiting (retry until actionable)

A Playwright test proves a user journey end to end:

`page.getByRole(...)`, `page.getByLabel(...)` and `page.locator(...)` resolve lazily: an action waits for the element to be visible, stable and enabled before acting. Assertions such as `expect(locator).toBeVisible()` retry on a polling interval until the condition holds or the timeout expires. This removes most `sleep()` and `waitFor()` calls.

## 2. Fixtures: one isolated context per test

Each test gets a fresh browser context (cookies, localStorage, permissions) by default, so tests never leak state into one another. `test.use()` configures fixtures globally; custom fixtures can spin up a test database seed or a logged-in page and tear it down after the test.

## 3. Network interception and mocking

`page.route('**/api/*', route => route.fulfill({ ... }))` stubs an API at the network layer, so tests run fast and deterministically. `page.request` can call real endpoints in setup, and `storageState` saves cookies/localStorage after one login so later tests skip the login flow entirely. Assert on the request payload (`route.request().postDataJSON()`) to verify what the client actually sends.

## 4. Page Object vs locator-first trade-offs

Locator-first tests (`page.getByRole(...)` inline) are fast to write and easy to read; Page Object models centralize selectors for large, churning UIs. Prefer locator-first for journey tests and Page Objects only when a dozen tests share the same complex form. Over-abstraction hides the very behavior the test is meant to prove.

## 5. Evidence on failure: tracing, video, screenshots

`trace: 'retain-on-failure'` records a trace Playwright can replay; video and screenshot on failure show exactly what the browser rendered. These artifacts are the difference between "test failed" and "I can see the modal never opened."

## 6. CI: sharding, retries, and visual regression limits

Shard tests across CI machines (`--shard=1/3`), retry flaky tests only on failure (`retries: 2`), and do not chase pixel-perfect visual regression for dynamic content — visual diffs break on anti-aliasing and fonts, so reserve them for stable design-token surfaces.

## Summary

Playwright drives real browsers with locators that auto-wait, assertions that retry, fixtures that isolate, and network interception that controls the boundary. It turns flaky E2E suites into deterministic journey tests: act on user-visible roles, stub slow third parties, keep evidence on failure, and shard in CI.

# Color & Contrast

A red "Invalid email" message may have enough contrast against its background while a red border alone fails to say what went wrong. Conversely, a clear text error can be too faint to read. Check both the signal's meaning and its visibility.

```typescript
console.log(contrastRatio('#767676', '#fff').toFixed(2)); // 4.54 — passes 4.5:1
console.log(contrastRatio('#777', '#fff') >= 4.5);         // false — rounds to 4.5, still fails
```

## Definition

**Color and contrast** in accessibility concern whether visual information remains distinguishable across different vision and viewing conditions. A readable **foreground/background pair** and a non-color explanation of important meaning solve related but different problems.

> **Textbook Definition:** Contrast ratio measures the relative luminance difference between two colors. Accessible visual communication also requires distinguishing information through labels, shapes or other cues when color alone would be ambiguous.

## First Principles

The eye needs sufficient distinction between a mark and its surroundings. Hue is not lightness: two different hues can share similar luminance, so if color alone distinguishes a status or series, someone who cannot perceive that distinction loses the information even when each mark is visible. Evaluate the rendered pair, never a color in isolation — backgrounds, transparency, images, themes and state changes all alter the pair, and a token called accessible-blue carries no universal guarantee.

## 1. Read the Requirement From the Content

For applicable text, WCAG's minimum contrast is **4.5:1**, or **3:1** for large text — at least 18 point, or 14 point bold (approximately 24 or 18.67 CSS px). Enhanced text contrast is 7:1 or 4.5:1 respectively. Conditions and exceptions, including incidental text and logos, belong to the criterion rather than an arbitrary project rule. [Text contrast requirements](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html).

**Non-text contrast** checks visual information needed to identify applicable controls and states and understand graphics, normally at least 3:1 against adjacent colors. It does not require every decorative border or every chart color to meet that ratio, and inactive components and unmodified user-agent appearance have specific exceptions. [Non-text contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). Never communicate required information through color alone: a status can include text, and chart series can combine direct labels with line patterns or markers — provided the added cue actually distinguishes the cases at the intended size. [Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html).

## 2. Calculate the Ratio on Rendered Pairs

WCAG contrast uses relative luminance: convert sRGB components to a linear-light scale, combine them with their specified weights, then divide the lighter-plus-0.05 by the darker-plus-0.05. Swapping foreground and background leaves the ratio unchanged. Black on white is 21:1; identical colors are 1:1.

```text
opaque sRGB pair → linear components → relative luminances
                                       ↓
                  (lighter + 0.05) / (darker + 0.05)
```

This calculation is a defined measurement, not a prediction of every individual's reading experience. Inspect the computed rendered colors in the actual UI: semi-transparent text requires compositing against its background, and an image or gradient creates several relevant locations. A contrast audit that checks only design-token pairs cannot see unexpected inherited styles or changing backgrounds.

## 3. Calculate a Real Pair With a Complete Input Contract

Save as `contrast.ts`. The parser rejects unsupported formats rather than silently treating an unknown value as black.

```typescript
export function luminance(hex: string): number {
  if (!/^#(?:[a-f\d]{3}|[a-f\d]{6})$/i.test(hex)) {
    throw new TypeError('Expected an opaque #RGB or #RRGGBB color');
  }
  const raw = hex.slice(1);
  const full = raw.length === 3 ? [...raw].map(c => c + c).join('') : raw;
  const linear = [0, 2, 4].map(offset => {
    const value = parseInt(full.slice(offset, offset + 2), 16) / 255;
    return value <= 0.04045 ? value / 12.92 : ((value + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * linear[0] + 0.7152 * linear[1] + 0.0722 * linear[2];
}

export function contrastRatio(first: string, second: string): number {
  const a = luminance(first);
  const b = luminance(second);
  return (Math.max(a, b) + 0.05) / (Math.min(a, b) + 0.05);
}

console.log(contrastRatio('#000', '#fff'));           // 21
console.log(contrastRatio('#767676', '#fff').toFixed(2)); // 4.54
console.log(contrastRatio('#999', '#fff').toFixed(2)); // 2.85
console.log(contrastRatio('#777', '#fff') >= 4.5);     // false
```

Use the unrounded ratio for threshold decisions: `#777` on white rounds to 4.5 at one decimal place but is below 4.5. Formatting is for display, not permission to pass. Resolve transparency and actual underlying backgrounds separately before applying this function.

## 4. Audit Combinations and States in Both Themes

These CSS tokens provide example pairs, not a claim that an entire product conforms. Apply them to the shown backgrounds; check focus next to any additional border or surface the component introduces.

```css
:root {
  color-scheme: light;
  --background: #ffffff;
  --surface: #f5f5f5;
  --text: #1a1a1a;
  --muted: #595959;
  --link: #1e40af;
  --focus: #005fcc;
}
@media (prefers-color-scheme: dark) {
  :root {
    color-scheme: dark;
    --background: #111827;
    --surface: #1f2937;
    --text: #f9fafb;
    --muted: #d1d5db;
    --link: #93c5fd;
    --focus: #fbbf24;
  }
}
body { color: var(--text); background: var(--background); }
.card { color: var(--text); background: var(--surface); }
.hint { color: var(--muted); }
a { color: var(--link); text-decoration: underline; }
:focus-visible { outline: 3px solid var(--focus); outline-offset: 3px; }
@media (forced-colors: active) {
  :focus-visible { outline-color: Highlight; }
}
```

For each theme, check text, muted text and links against both background and surface, then check the focus ring against its adjacent colors — plus hover, active, selected, invalid and disabled behavior separately. User-selected themes should resolve the same tokens explicitly; a dark media query does not by itself implement a persistent theme switch. A forced-color environment can replace author colors, so retain semantic elements and visible borders or outlines rather than depending on shadows or fills. [Forced-colors behavior](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/forced-colors).

For charts, categories need separable cues beyond a friendly palette; the [charts chapter](50.2.06-accessible-charts-data-viz.md) owns the complete equivalent-data and interaction treatment. For forms, text identifies the invalid condition and its correction while color reinforces it; the [forms chapter](50.2.05-forms-and-labels.md) owns error associations, validation and focus.

## Summary

Measure the actual foreground and background relationship and compare it with the applicable unrounded threshold. Color meaning and visual contrast are separate checks: verify states and themes, retain non-color cues, and treat token calculations as one part of the rendered interface evaluation.

# Accessible Charts & Data Visualization

## TL;DR

A chart rendered as a bare `<canvas>` or an unlabeled `<svg>` is a blank wall to a screen reader and often a color-guessing game for color-blind users. Make charts accessible by: exposing the container with `role="img"` plus a concise `aria-label` (or SVG `title`/`desc`), providing a **data table or download fallback** for the full dataset, encoding information redundantly (patterns, direct labels, shapes — never color alone), and testing the dashboard with a real screen reader. Library defaults (Recharts, Highcharts) get you maybe 60% of the way — the gaps are yours.

## Definition

**Accessible data visualization** presents quantitative information so that users can perceive it regardless of sensory modality: visually (color-independent encodings, sufficient contrast), non-visually (text alternatives via ARIA/SVG metadata or equivalent tables), and cognitively (predictable interactions, no hover-only content). The governing WCAG success criteria: **1.1.1 Non-text Content**, **1.4.1 Use of Color**, **1.4.11 Non-text Contrast**, **2.4.x navigability**, and **4.1.2 Name, Role, Value**.

```text
THE ACCESSIBLE CHART CONTRACT
┌─────────────────────────────────────────────────────────────┐
│  Visual layer      SVG/canvas pixels                        │
│  Semantic layer    role="img" + aria-label ("Bar chart:     │
│                    2025 revenue by quarter")                │
│  Detail layer      Data table / downloadable CSV            │
│                    (full values, keyboard reachable)        │
│  Redundant         Patterns + direct labels + shape,        │
│  encoding          not hue alone                            │
│  Interaction       Focusable points, visible focus ring,    │
│                    tooltips on focus AND hover              │
└─────────────────────────────────────────────────────────────┘
```

## Why it matters

Dashboards are where accessibility quietly dies. Teams nail forms and buttons, then ship a revenue analytics page that is one `<div id="chart">` with 40 KB of painted canvas — invisible, unoperable, and legally indefensible under ADA/EAA. Interviews increasingly include "how would you make this dashboard accessible?" because it tests three things at once: ARIA mechanics, progressive-enhancement judgment, and empathy for non-visual information consumption (a table is not a "fallback" — for many users it is the primary experience).

## Why Do We Need It?

- **WCAG conformance is contractual**: 1.1.1 requires a text alternative for every non-text content; an unlabeled chart fails AA outright.
- **Color independence**: ~8% of men have color vision deficiency; a red/green line chart without patterns communicates nothing to them.
- **Hover is not interaction**: tooltips that appear only on mouse hover are unreachable for keyboard and touch users.
- **Screen-reader users consume data too**: quarterly reports, health stats, election maps — excluding them excludes real customers and triggers lawsuits (domino's.com, beyonce.com precedent class).
- **Cognitive load**: cluttered dual-axis rainbow charts harm everyone; accessibility pressure produces clearer design generally (curb-cut effect).
- **Export parity**: CSV/data-download links serve analysts *and* assistive tech with one mechanism.

## How It Works

### Layer 1 — Name the chart

For a static chart, expose the whole figure as a single image-like object:

```html
<figure>
  <svg role="img" aria-labelledby="chart-title chart-desc" viewBox="0 0 600 400">
    <title id="chart-title">Quarterly revenue, 2025</title>
    <desc id="chart-desc">
      Bar chart of four quarters. Q1: 1.2M, Q2: 1.5M, Q3: 1.4M, Q4: 1.9M euros.
      Revenue grew 58 percent from Q1 to Q4.
    </desc>
    <!-- bars, axes, labels -->
  </svg>
  <figcaption>Quarterly revenue, 2025 (EUR)</figcaption>
</figure>
```

`role="img"` removes inner SVG nodes from the accessibility tree — intentional: reading 30 `<rect>` elements as "graphics symbol" spam is worse than one good description. The `desc` carries the *trend*, not just raw numbers; "grew 58%" is the insight a sighted user gets in two seconds.

### Layer 2 — Provide the data itself

The text alternative summarizes; the table delivers precision. Keep both in DOM, hide the table only if truly redundant, and offer machine-readable export:

```html
<div class="chart-with-data">
  <svg role="img" aria-labelledby="rev-title"> ... </svg>

  <details>
    <summary>View data as table</summary>
    <table>
      <caption>Quarterly revenue, 2025</caption>
      <thead><tr><th scope="col">Quarter</th><th scope="col">Revenue (EUR)</th></tr></thead>
      <tbody>
        <tr><td>Q1</td><td>1,200,000</td></tr>
        <tr><td>Q2</td><td>1,500,000</td></tr>
        <tr><td>Q3</td><td>1,400,000</td></tr>
        <tr><td>Q4</td><td>1,900,000</td></tr>
      </tbody>
    </table>
  </details>
  <a href="/api/revenue/2025.csv" download>Download CSV</a>
</div>
```

### Layer 3 — Color independence

Encode categories with more than hue:

```text
COLOR-INDEPENDENT ENCODINGS
• Line charts   -> dash patterns (solid/dashed/dotted) + distinct markers
• Bar charts    -> direct value labels on bars + texture fills if needed
• Status colors -> icon overlays (check/warning/x) alongside green/amber/red
• Heatmaps      -> luminance ramp (light->dark works for all CVD types)
                 plus numeric labels in cells when density allows
```

Direct labeling beats legends everywhere: label lines/bars at their endpoint so nobody cross-references a legend from working memory.

### Layer 4 — Interactive charts

If points are individually meaningful, make them focusable and give each a name:

```typescript
// Accessible scatter point: focusable, named, tooltip on focus AND hover
<g
  role="listitem"
  tabIndex={0}
  aria-label={`March: 342 orders, up 12% from February`}
  onFocus={() => showTooltip(datum)}
  onBlur={() => hideTooltip()}
  onMouseEnter={() => showTooltip(datum)}
  onMouseLeave={() => hideTooltip()}
/>
```

For dense charts (100+ points), do not create 100 tab stops — summarize in `desc`, keep the table as the precise source, and optionally add arrow-key roving focus within the chart.

### Sonification

Data sonification maps values to pitch/duration so trends are *heard* (rising pitch = rising line). It remains experimental — no browser-native standard, libraries like Highcharts sonification exist — but mentioning it shows senior depth: useful for trend-shape perception, useless for precise values, always paired with a table.

## Code Examples

### Recharts with accessibility patches

Recharts renders real SVG but ships no automatic text alternative; you must add figure semantics yourself:

```tsx
import {
  BarChart, Bar, XAxis, YAxis, Tooltip, AccessibilityLayer,
} from 'recharts';

const data = [
  { quarter: 'Q1', revenue: 1_200_000 },
  { quarter: 'Q2', revenue: 1_500_000 },
];

export function RevenueChart() {
  return (
    <figure role="figure" aria-label="Bar chart: 2025 quarterly revenue in euros. Q1 1.2 million, Q2 1.5 million.">
      <BarChart data={data} width={600} height={300}>
        {/* adds tabindex handling to the svg wrapper */}
        <AccessibilityLayer />
        <XAxis dataKey="quarter" />
        <YAxis />
        <Tooltip />
        <Bar dataKey="revenue" label={{ position: 'top' }} /> {/* direct labels */}
      </BarChart>
      <figcaption>2025 quarterly revenue (EUR)</figcaption>
    </figure>
  );
}
```

Gaps Recharts leaves even after this: pattern fills require custom `<defs>`; tooltip focus behavior needs manual wiring; multi-series legends remain color-only unless you customize legend rendering.

### Highcharts: use the built-in module, verify defaults

Highcharts is furthest ahead — its accessibility module generates hidden data tables and sonification support is built in:

```typescript
import Highcharts from 'highcharts';
import Accessibility from 'highcharts/modules/accessibility';
import Exporting from 'highcharts/modules/exporting';

Accessibility(Highcharts);
Exporting(Highcharts); // CSV export link comes free

Highcharts.chart('container', {
  chart: { type: 'line' },
  accessibility: {
    enabled: true,
    description: 'Monthly active users grew steadily through 2025.',
    point: {
      describeNull: false,
    },
  },
  series: [{
    name: 'Monthly active users',
    data: [1200, 1350, 1500 /* ... */],
    // color-independence still on you:
    dashStyle: 'Solid',
    marker: { symbol: 'circle' },
  }, {
    name: 'Churned users',
    data: [80, 95, 90],
    dashStyle: 'Dash',
    marker: { symbol: 'square' },
  }],
});
```

Audit what modules actually emit with the screen reader — default descriptions can be terse for complex multi-series charts, and the hidden table duplicates IDs if you render multiple charts per page carelessly.

## Real-World Use Cases

1. **Executive KPI dashboard** — twelve tiles each showing sparkline + number: each tile is a labeled region (`role="img"` + summary), plus one consolidated "view all data" table page; keyboard order follows visual layout.
2. **Financial trading view** — candlestick charts get axis-level description plus full OHLC table per instrument; real-time updates announce via `aria-live="polite"` region summarizing deltas, throttled (announcing every tick would be unusable).
3. **Public-sector open-data portal** — statutory AA requirement: every chart pairs with downloadable CSV and an HTML table; automated CI check fails builds where a `<canvas>` lacks an adjacent data table.
4. **Healthcare patient portal** — glucose trend charts for patients using VoiceOver: interactive focusable readings, high-contrast forced-colors support, and printable report fallback.
5. **Election results map** — choropleth uses luminance ramp (not red/blue party hues alone), map regions are focusable links with `aria-label="District 7: 54% Smith, 43% Jones"`, plus ranked table as canonical source.

## Common Mistakes

```typescript
// BAD: canvas pixel soup - nothing in accessibility tree
<canvas id="sales"></canvas>

// BAD: aria-label that names the type, not the content
<div role="img" aria-label="chart" />

// GOOD: content-bearing name + data path out
<figure role="img" aria-label="Line chart: monthly active users rose from 1,200 in January to 2,400 in June 2025. Full data in table below." />
```

```html
<!-- BAD: legend relies on color alone -->
<span style="color:#e33">&#9632;</span> Errors

<!-- GOOD: redundant encoding -->
<span aria-hidden="true" class="swatch swatch-errors"></span> Errors
<!-- .swatch-errors: red background AND diagonal-stripe pattern -->
```

More frequent failures:

- **`role="presentation"` on the SVG while expecting title to work** — presentation strips semantics; use `role="img"` with `aria-labelledby`.
- **Tooltip-only values** — data exists solely in mouse-hover popups; keyboard users get nothing.
- **Announcing every live update** — `aria-live` on a chart updating 10x/second makes the page unusable for screen readers; batch and throttle summaries.
- **Trusting library defaults blindly** — "we use Highcharts, so we're covered" until someone audits the multi-series combo chart whose generated description reads "chart with 3 series".
- **Decorative gridlines given roles** — every axis tick marked up as a landmark floods the rotor list; mark decoration `aria-hidden`.

## Best Practices

1. Every chart gets: container name (`role="img"` + label), insight-bearing description, and a precise data path (table or CSV).
2. Never encode meaning in hue alone — add dash patterns, markers, textures, or direct labels.
3. Meet 3:1 contrast for chart elements against background (WCAG 1.4.11), including focused states.
4. Tooltips respond to focus and hover; interactive points are keyboard reachable with visible focus indicators.
5. Throttle any `aria-live` announcements for streaming data; prefer periodic summaries.
6. Test dashboards with VoiceOver/NVDA end-to-end — navigate by landmarks, confirm every chart announces something coherent.
7. Wire axe-core/jest-axe checks into chart component unit tests; add custom rules asserting figures contain labels.

## Performance Considerations

Accessibility features cost little at runtime but watch scale: thousands of focusable SVG nodes tank both performance and screen-reader responsiveness — virtualize long series or aggregate before rendering. Hidden data tables double DOM size; render them inside collapsed `<details>` or generate on demand. Sonification synthesis is CPU-bound; trigger lazily on explicit user request, never autoplay. For streaming charts, updating `aria-label` strings every frame forces AT re-query — update on a cadence (every few seconds) instead.

## Summary

- Name every chart (`role="img"`, `aria-label` or SVG `title`/`desc`) with an insight-bearing description, not "chart".
- Always provide a precise non-visual data path: HTML table, details-disclosed table, or CSV download.
- Encode data redundantly — patterns, markers, direct labels, luminance ramps — so color vision deficiency never blocks comprehension.
- Keyboard operability means focusable points with focus-triggered tooltips, or deliberate summarization instead of hundreds of tab stops.
- Recharts gives structure but needs manual semantics; Highcharts' accessibility module goes further — either way, audit with real screen readers rather than trusting defaults.
- Sonification exists and is worth knowing; tables and good descriptions remain the dependable core.

## Cheat Sheet
```text
ACCESSIBLE CHARTS CHEAT SHEET
============================================================

EVERY CHART SHIPS WITH:
• role="img" + aria-label (or svg title/desc)
• Insight in the description ("grew 58%", not "bar chart")
• Table or CSV for exact values
• No color-alone encoding

WCAG HOOKS:
• 1.1.1  Non-text content  -> text alternative
• 1.4.1  Use of color      -> redundant encoding
• 1.4.11 Non-text contrast -> 3:1 chart vs background
• 4.1.2  Name/Role/Value   -> labeled widgets

ENCODING REDUNDANCY:
• Lines:   solid/dash/dot + distinct markers + endpoint labels
• Bars:    direct value labels
• Status:  icon + color
• Heatmap: luminance ramp + cell numbers

INTERACTION:
• Focusable points: tabIndex=0, aria-label per point
• Tooltip on focus AND hover
• Dense charts: summarize instead of N tab stops
• Live data: aria-live polite, throttled summaries

LIBRARY REALITY CHECK:
• Recharts:     structure yes, semantics manual (add AccessibilityLayer)
• Highcharts:   a11y module + hidden table + sonification built in
• Either way:   test with NVDA/VoiceOver, run axe-core in CI

INTERVIEW FORMULA:
• "Canvas chart = invisible to AT"
• "role=img collapses internals - write a GOOD desc"
• "Table is not a fallback, it IS the data"
• "Never color alone; 8% of men can't rely on hue"
```

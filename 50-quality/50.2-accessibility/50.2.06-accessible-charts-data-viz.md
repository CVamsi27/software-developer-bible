# Accessible Charts & Data Visualization

## Definition

**Accessible data visualization** makes a chart's information and interactions available through meaningful visual cues, text and structured data, and usable input paths. A chart title identifies the subject; it rarely supplies every value or relationship the task requires.

> **Textbook Definition:** Accessible data visualization provides equivalent access to a chart's information and interactions through perceptible encodings, text or structured data alternatives, and operable controls.

A revenue chart lets a sighted reader compare quarters quickly. Someone reading a table needs the values and units; someone listening may first need the main trend before choosing which values to inspect. Preserve both insight and precision.

## First Principles

A graphic compresses data into position, length, color and shape. The rendered pixels do not by themselves explain those relationships through a nonvisual path. Expose the same underlying information in an appropriate alternative and keep it consistent when data or filters change.

Static information and operable controls have different contracts. Treating the whole chart as one image-like object can be useful for a static summary, but can conceal independently operable descendants. Decide what the user needs to read or do before choosing roles or hundreds of focus targets.

## Connect summary, graphic and exact values

```text
                 one authoritative dataset
                 /          |           \
        trend summary    visual chart   exact table
                             |
                  any interaction has an equivalent operable path
```

A short alternative identifies the chart. A longer explanation supplies relevant relationships, units and caveats, while a table makes exact values available. Choose detail from the task: a table alone may leave an important trend hard to find, and a trend sentence alone cannot answer an exact-value question. [W3C complex-image guidance](https://www.w3.org/WAI/tutorials/images/complex/).

## Code Examples

### Generate a static chart and table from the same data

Save this complete fixture as revenue.html. It presents synthetic quarterly revenue in euros, using a zero-baseline bar chart. The SVG is one named static graphic; the HTML summary and data disclosure remain separately readable.

```html
<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Quarterly revenue and data</title>
<style>
  body { color: #1a1a1a; background: white; }
  svg { display: block; width: min(100%, 28rem); height: auto; }
  :focus-visible { outline: 3px solid #005fcc; outline-offset: 3px; }
  th, td { padding: .4rem; text-align: left; }
</style>
<main>
  <h1>Quarterly revenue, 2025</h1>
  <figure>
    <svg id="revenue-chart" role="img" aria-labelledby="revenue-title"
         aria-describedby="revenue-summary" viewBox="0 0 420 280">
      <title id="revenue-title">Bar chart of quarterly revenue in euros</title>
      <g id="revenue-bars" aria-hidden="true"></g>
    </svg>
    <figcaption>Quarterly revenue, 2025 (EUR)</figcaption>
  </figure>
  <p id="revenue-summary"></p>
  <details>
    <summary>View exact revenue data</summary>
    <table>
      <caption>Quarterly revenue, 2025, in euros</caption>
      <thead><tr><th scope="col">Quarter</th><th scope="col">Revenue (EUR)</th></tr></thead>
      <tbody id="revenue-rows"></tbody>
    </table>
  </details>
</main>
<script>
  const data = [
    { quarter: 'Q1', revenue: 1_200_000 },
    { quarter: 'Q2', revenue: 1_500_000 },
    { quarter: 'Q3', revenue: 1_400_000 },
    { quarter: 'Q4', revenue: 1_900_000 },
  ];
  const euros = new Intl.NumberFormat('en-IE');
  const bars = document.getElementById('revenue-bars');
  const rows = document.getElementById('revenue-rows');
  const ns = 'http://www.w3.org/2000/svg';
  const maximum = Math.max(...data.map(item => item.revenue));
  const graphic = (tag, attrs, text) => {
    const node = document.createElementNS(ns, tag);
    for (const [key, value] of Object.entries(attrs)) node.setAttribute(key, String(value));
    if (text !== undefined) node.textContent = text;
    bars.append(node);
  };
  data.forEach((item, index) => {
    const x = 20 + index * 100;
    const height = 190 * item.revenue / maximum;
    graphic('rect', { x, y: 230 - height, width: 65, height, fill: '#1e40af' });
    graphic('text', { x, y: 250, fill: '#1a1a1a' }, item.quarter);
    graphic('text', { x, y: 220 - height, fill: '#1a1a1a' }, `${item.revenue / 1_000_000}M`);
    const row = document.createElement('tr');
    const quarter = document.createElement('th');
    quarter.scope = 'row'; quarter.textContent = item.quarter;
    const value = document.createElement('td');
    value.textContent = euros.format(item.revenue);
    row.append(quarter, value); rows.append(row);
  });
  const growth = 100 * (data[3].revenue - data[0].revenue) / data[0].revenue;
  document.getElementById('revenue-summary').textContent =
    `Revenue increased ${growth.toFixed(1)}% from Q1 to Q4, with a dip in Q3. ` +
    'The data disclosure contains all four exact euro values. M means million euros.';
</script>
</html>
```

The same array supplies bar heights, visible labels and table cells. Q1→Q4 increases by 700,000/1,200,000, or approximately 58.3%; Q3 is lower than Q2. The summary exposes that relationship and explains the shortened unit. Enter or Space operates the native details disclosure; the table has column and row headers for inspecting exact values.

The fixture is deliberately fixed to four positive quarters. Empty data, negative values, other units, loading/failure states and changing filters need explicit rendering and summary rules. Its white theme and text/mark pairs also need evaluation before adapting them to another surface. A data alternative must not silently retain an old filter while the graphic changes.

## Preserve meaning when there is more than one series

For one series, bar height and labeled quarter carry the comparison; color is decoration. With several categories or statuses, hue alone may be the only distinguishing cue. Add useful direct labels, line dashes, markers or textures and check their clarity at the shown density.

A luminance ramp can convey ordered magnitude, but it does not make every heatmap or color-vision condition universally distinguishable. Include values or an equivalent structured path where needed. Measure the visual information required to interpret the graphic against relevant adjacent colors, using the [contrast chapter](50.2.04-color-and-contrast.md).

## Interaction must survive a different input path

A pointer-hover tooltip cannot be the only way to read a value. If points are interactive, define how keyboard focus reaches them, how values appear on focus and how the user exits the widget. Hover/focus content also needs an appropriate way to dismiss it, reach it where necessary and keep it visible while being used.

Dense datasets do not require one Tab stop per point. A scoped arrow-navigation model, table with usable sorting/filtering, or labeled selection control can supply a clearer path. Preserve equivalents for selecting a range, filtering, drilling into a point and resetting; an alternative that only lists values may omit the chart's actionable tasks.

If a point performs navigation or an action, give it the corresponding link/button semantics. role=listitem alone supplies neither action nor a complete chart interaction model. Do not expose such controls as children of an atomic role=img wrapper and expect them to remain independently discoverable.

For live data, retain a readable snapshot or pause mechanism where appropriate and offer useful summaries without announcing every sample. **Sonification** maps data to sound, such as pitch changing with magnitude; it can add a way to understand shape, but needs explained mappings, controls and an exact-data path. Avoid autoplay.

## Library behavior is versioned evidence

Recharts 3 enables its accessibilityLayer prop by default. It is a chart prop, not an exported component to insert as `<AccessibilityLayer />`. That support does not supply every application-specific summary, equivalent data path, category distinction or journey. Evaluate the actual rendered chart and pinned version. [Recharts accessibility documentation](https://github.com/recharts/recharts/blob/main/storybook/stories/API/Accessibility.mdx).

Highcharts supplies an accessibility module. Version 12 changed the UMD module-loading convention: modules initialize through import rather than the older function-call pattern. CSV/table export requires the data-export module in addition to relevant exporting support; importing exporting alone is not a guarantee of CSV behavior. Inspect the configured result and compatible module versions. [Version 12 guidance](https://www.highcharts.com/docs/getting-started/version-12), [accessibility module](https://www.highcharts.com/docs/accessibility/accessibility-module), [data-export support](https://www.highcharts.com/docs/export-module/export-module-overview).

## Real-World Decisions

Start with the information and tasks: exact comparison, trend, uncertainty, selection or live status. For a compact static graphic, a named summary and table can be enough. A complex financial dashboard may need several navigable views and a stable alternative to animated updates. Do not claim that a library, label or downloadable file alone establishes access to every task.

Downloads can help analysts, but an HTML alternative keeps the task within the page for people who cannot conveniently use the file format. Keep permissions, units and filter boundaries equivalent across both paths. Collapsing details changes visibility but does not remove its data nodes; generate on demand only with a tested loading/error and access path.

## Common Mistakes

- Naming a graphic only “chart” or presenting exact values without the needed relationship.
- Concealing interactive descendants within an image-like semantic wrapper.
- Requiring hover for data or giving every dense point an unexplained Tab stop.
- Keeping chart/table snapshots inconsistent after a filter or update.
- Copying outdated module APIs or assuming a library's defaults establish product conformance.

## Best Practices

Create graphic and alternatives from the same authoritative data and task model. Explain units, missing values and important trends, preserve equivalent interactions and evaluate the supported input/assistive-technology paths. Check states and library versions as well as the initial screenshot.

## Summary

A chart's alternative preserves the information and tasks it encodes. Combine an informative summary with precise structured data, non-color distinctions and usable interactions. Keep those views synchronized and evaluate actual library behavior rather than relying on a name or role alone.

# Accessibility Interview Questions

## First Principles

An interface must preserve meaning and task operation across supported ways of perceiving and entering information. A defensible answer therefore connects semantics, behavior, state and evaluation scope, rather than stopping at tool names or an acronym.

## Practice the original questions and changed conditions

Answer aloud before reading the model. Start from a real task, name the contract and explain how you would verify it. Use each probe to change one condition. Complete the [section revision](REVISION.md) first, and use verified personal contributions when discussing your own experience.

### Set the target and semantic contract

#### 1. What does it mean to claim WCAG conformance for a checkout?

**Answer:** Name the WCAG version and conformance level, identify the full pages and complete checkout process, and state the supported technology assumptions required by the standard. A component scan or score is evidence about a sample, not conformance of the full journey. Check the applicable contract or regulation before setting the release target.

**Probe:** What evidence is missing if the payment provider runs on a separate origin?

#### 2. When would you use native HTML instead of ARIA?

**Answer:** Use a native control when it expresses the task because the browser already supplies its semantics, focus behavior and activation. Use ARIA when native HTML cannot express a required relationship or widget pattern, then implement the behavior too. Treat the APG as pattern guidance and verify applicable normative requirements separately.

**Probe:** What remains broken if a div gets role=button but no keyboard handler?

#### 3. How do you name a custom control without hiding its visible label?

**Answer:** Prefer a visible label or referenced visible text, keep that wording in the computed accessible name, and use a description for secondary instructions. Check that every referenced ID exists and is unique when components repeat. An unrelated aria-label can make voice users unable to speak the label they see.

**Probe:** What changes if the visible text is replaced by an icon?

#### 4. How do you keep accessibility state aligned with component behavior?

**Answer:** Derive the DOM behavior and exposed state from the same state transition. An expanded button must reveal its panel; an aria-disabled action still needs activation blocked; aria-hidden must not leave focusable descendants unidentified. Test after repeated updates and removal, not only on the initial render.

**Probe:** What happens if a hidden error remains referenced by aria-describedby?

#### 5. How do you make page structure easy to navigate?

**Answer:** Use headings and native landmarks that describe the actual document regions, with distinct names for repeated navigation areas. A visible-on-focus skip link can bypass repeated content when it targets a useful main region. A header inside an article does not automatically create the page banner landmark.

**Probe:** How would you distinguish primary navigation from navigation inside an article?

#### 6. How do you evaluate color and contrast?

**Answer:** Check the unrounded ratio for the actual rendered foreground/background pair against the applicable criterion: normal text usually needs 4.5:1 at AA, large text 3:1, and required non-text information has separate rules. Test themes and states, and convey meaning through more than color alone.

**Probe:** Why can a passing token fail when it appears on a different surface?

### Check visual access at different sizes and themes

#### 7. How do you test reflow at high zoom?

**Answer:** At 400% zoom, check vertical content at a 320 CSS pixel width and horizontal content at a 256 CSS pixel height. Information and functionality should remain without two-dimensional scrolling, except content that genuinely needs it. A data table may need both axes, but ordinary page prose should not.

**Probe:** What parts of a wide table still need to reflow?

#### 8. What should a forced-colors theme preserve?

**Answer:** System colors can replace author colors. Keep focus, boundaries, selection and error states visible without relying only on background fills or shadows. Use system color values where needed and avoid broadly disabling forced-color adjustments; verify actual controls in the operating system's forced-color mode.

**Probe:** How would you detect a focus ring that disappeared with box-shadow?

### Preserve the user's interaction and recovery path

#### 9. How would you make a custom tablist keyboard-operable?

**Answer:** Follow the tab pattern: Tab enters the tablist at one tab stop, arrow keys move focus within it, and activation updates selected state and panel visibility together. Choose manual activation when panels are not immediate. Preserve normal text editing and define behavior for orientation, direction and disabled tabs.

**Probe:** What should happen when a focused tab is removed?

#### 10. How do you handle single-character keyboard shortcuts?

**Answer:** Under WCAG 2.1.4, a shortcut made only from printable characters must be turnable off, remappable to include a non-printable key, or active only while its component has focus. Avoid intercepting typing and composition; also account for speech input and assistive-technology commands.

**Probe:** Why can an input-only guard still interrupt someone dictating into an editor?

#### 11. What must a modal dialog do from opening through dismissal?

**Answer:** Choose a safe initial focus target, make background content inoperable while modal, support the expected dismissal action, and return focus to the trigger when it still exists. If the trigger was removed, restore focus to a useful next task target. aria-modal alone implements none of these behaviors.

**Probe:** Where does focus go if the dialog deletes the item that opened it?

#### 12. How do client-side route changes affect accessibility?

**Answer:** After intentional navigation, expose a useful page title and heading and move or announce context when the framework does not do so. Avoid focus changes on unrelated rerenders. Cancel or ignore stale asynchronous results so an earlier request cannot replace content for the newly selected route.

**Probe:** How would you handle a failed route transition without losing the user's place?

#### 13. How would you make form validation recoverable?

**Answer:** Provide persistent labels and instructions, associate each error with its field, preserve entered values, and choose one coherent focus or announcement strategy. Client checks improve feedback but do not confirm a server transaction. Support password managers and paste, and state honestly when a timeout leaves the outcome unknown.

**Probe:** What should the interface say after the server may have committed but the response timed out?

### Cover authentication and irreversible actions

#### 14. How do you make authentication accessible without weakening security?

**Answer:** WCAG 2.2 SC 3.3.8 requires an available path that does not depend on a cognitive function test, unless the criterion's stated exception applies. Support password-manager autofill and paste, and check every multifactor and account-recovery step; do not force users to transcribe codes.

**Probe:** What changes if a login is accessible but account recovery requires a puzzle?

#### 15. What error-prevention options apply to a financial or destructive action?

**Answer:** For actions covered by WCAG 2.2 SC 3.3.4, provide at least one of these: make the result reversible, check input and let the user correct it before submission, or let the user review, confirm and correct it. Scope the criterion; it does not require confirmation for every routine save.

**Probe:** Which option best fits an irreversible order submission with complex line items?

#### 16. When should an error use focus and when should it use a live region?

**Answer:** Use focus when the user needs a deliberate destination, such as a summary after failed submission; use a live region when useful status changes should be announced without moving focus. Avoid focusing the summary and firing several assertive alerts at once. Test the strategy with supported browser and screen-reader combinations.

**Probe:** How would your choice change for a non-blocking save confirmation?

#### 17. What makes a chart alternative useful?

**Answer:** Choose an image alternative from its purpose; for a complex chart, derive the short explanation and exact-value table from the same data. Include units and trends, then preserve tasks that filters or points enable. A title or downloadable CSV alone may omit needed information or action.

**Probe:** What defect appears if a filter updates the chart but not its table?

#### 18. How do you make a dense interactive chart operable?

**Answer:** Avoid a Tab stop for every point. Define a concise entry point and predictable internal navigation, expose each selected value, and provide another path to exact data and required actions. Evaluate the pinned chart-library version with actual browser and assistive-technology combinations; its defaults are only part of the implementation.

**Probe:** What additional path would you provide if arrow navigation conflicts with a screen reader command?

### Establish evidence and scale the fix

#### 19. What can an automated accessibility scan establish?

**Answer:** It can find failures covered by its selected rules in the rendered state it inspected. Preserve violations and incomplete results for review; neither an empty result nor a Lighthouse score evaluates every criterion, meaning or task. A passing component scan does not establish complete-page or process conformance.

**Probe:** What does an incomplete axe result require from the reviewer?

#### 20. What accessibility test strategy would you put in CI?

**Answer:** Define the revision, critical journeys, states, target criteria and supported environment. Run automated checks for inspectable rules and real browser input tests for interaction; retain reports and fail on the agreed blocking conditions. Schedule human keyboard, visual and assistive-technology evaluation for meaning and complete tasks.

**Probe:** How would a new payment integration change the test scope?

#### 21. How would you scale accessibility through a design system?

**Answer:** Assign behavior to primitives, theme pairs to tokens, composition rules to components and task content to consumers. Publish supported states and extension points, test representative compositions, and track releases until consumers adopt the fix. Re-evaluate each journey because an upgraded library cannot correct a missing title or broken page flow.

**Probe:** Who owns an empty dialog title that appears only in one product?

#### 22. How would you prioritize a large accessibility backlog?

**Answer:** Rank findings by blocked task, impact on users, affected states, applicable requirements and recurrence through shared components. Choose fixes that remove real barriers, not only easy high-count findings. Record a reproducible state, owner, acceptance evidence and any adoption dependency, then retest the same path.

**Probe:** When can a low-frequency defect outrank a widespread cosmetic issue?

#### 23. How do you evaluate third-party steps in a complete process?

**Answer:** Treat the provider transition, authentication, errors and return path as part of the user's process. Test what the product controls and obtain evidence or an explicit owner for what it cannot inspect. Record missing evidence instead of extending a component's pass to an untested provider journey.

**Probe:** What would you report if the provider's accessible error behavior cannot be verified?

#### 24. How do localization and right-to-left layouts affect accessibility?

**Answer:** Localize visible and accessible names together, declare language changes, and test longer text, reading order and keyboard conventions in the target locale. Mirroring the layout does not automatically reverse document order or every arrow-key rule. Verify the actual widget pattern and browser behavior rather than applying a global key reversal.

**Probe:** What breaks if a translated button keeps an unrelated English aria-label?

#### 25. How does progressive enhancement support accessibility?

**Answer:** Start with meaningful content and native controls that preserve the core task, then add richer interaction with explicit semantics and keyboard behavior. A fallback is useful only if it preserves the task; a static chart cannot replace interactive filtering without an equivalent way to choose and inspect data.

**Probe:** What alternative preserves the filtering task if the chart script fails?

## Summary

Explain the user's task, required semantics and behavior, state changes and evidence boundary. Conformance has a defined version and scope; automated scores, a library or a model answer cannot establish a complete usable journey by themselves.

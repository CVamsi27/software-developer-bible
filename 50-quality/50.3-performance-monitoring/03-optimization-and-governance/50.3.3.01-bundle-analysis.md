# Bundle Analysis

A feature used on one route adds a package that every visitor now downloads. The useful question is which import makes it reachable from the initial route, which output contains it, and when that output is requested.

```bash
node build.mjs  # emits dist/ bundles plus reports/eager.json and reports/lazy.json
```

## Definition

**Bundle analysis** inspects the contents, size and composition of JavaScript assets shipped to a browser. It connects output files to contributing **modules** so a team can find retained code, duplication and candidates for splitting.

> **Textbook Definition:** Bundle analysis attributes generated application assets to modules, dependencies and chunks to explain loading cost and evaluate changes in the shipped dependency graph.

## First Principles

A bundler starts at entry points and follows dependencies. It can omit unreachable code only where module semantics and optimization rules permit it. A **chunk** is a generated unit of code loaded as an asset: one route may require several chunks, and several routes may share a chunk. Changing an import changes this graph — a smaller individual chunk does not establish a smaller initial journey, since moving bytes to a shared chunk may preserve the total while a preload fetches a nominally lazy chunk immediately.

## How It Works

### 1. Connect Source, Output and Requests

```text
entry point → reachable imports → emitted chunks → requested assets
                    ↑                   ↑                ↑
            module/side-effect     analyzer metadata   browser waterfall
                 semantics
```

A **source map** relates generated code positions to original source. A bundler's metadata can instead record contributing input bytes and chunk imports directly. Neither report necessarily describes compressed transfer bytes. Pick one build, mode, compression method and route for comparisons.

| Measurement | Meaning | Boundary |
| ------------------- | ----------------------------------- | ---------------------------------------------------- |
| Emitted bytes | Generated file length | Does not include transport compression savings |
| Gzip/Brotli bytes | File size under a chosen compressor | Not total wire overhead or CPU cost |
| Input attribution | How modules contribute to an output | Attribution may leave runtime glue or unmapped bytes |
| Journey requests | Assets fetched for one navigation | Depends on cache, preloads, user action and build |
| Parse/evaluate work | Browser processing cost | Needs representative execution measurements |

### 2. Trace Eager and Lazy Imports in a Complete esbuild Fixture

Use an isolated directory, Node.js and an installed `esbuild` development dependency. Save these files, then run `node build.mjs`. Keep the resolved dependency version in the lockfile for reproducible comparisons.

```javascript
// src/report.js
export function renderReport(value) {
  return `Report: ${value}`;
}
export function unusedReport(value) {
  return `Unused: ${value}`;
}
```

```javascript
// src/eager.js
import { renderReport } from './report.js';
document.querySelector('#open').addEventListener('click', () => {
  document.querySelector('#result').textContent = renderReport('ready');
});
```

```javascript
// src/lazy.js
const button = document.querySelector('#open');
button.addEventListener('click', async () => {
  button.disabled = true;
  try {
    const { renderReport } = await import('./report.js');
    document.querySelector('#result').textContent = renderReport('ready');
  } catch {
    document.querySelector('#result').textContent = 'Report failed to load. Try again.';
  } finally {
    button.disabled = false;
  }
});
```

```javascript
// build.mjs
import { build, analyzeMetafile } from 'esbuild';
import { mkdir, writeFile } from 'node:fs/promises';

for (const variant of ['eager', 'lazy']) {
  const result = await build({
    entryPoints: [`src/${variant}.js`],
    outdir: `dist/${variant}`,
    bundle: true,
    format: 'esm',
    splitting: true,
    minify: true,
    metafile: true,
  });
  await mkdir('reports', { recursive: true });
  await writeFile(`reports/${variant}.json`, JSON.stringify(result.metafile, null, 2));
  console.log(variant, await analyzeMetafile(result.metafile));
}
```

```html
<!-- lazy.html; duplicate as eager.html and change the script path to eager/eager.js -->
<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Bundle loading trace</title>
<button id="open" type="button">Open report</button>
<p id="result" role="status"></p>
<script type="module" src="dist/lazy/lazy.js"></script>
</html>
```

The eager output contains the used report function in its entry asset and omits the unused export. The lazy entry references a generated dynamic chunk that the page need not fetch before clicking; clicking creates that dependency. In the tested esbuild fixture, the dynamic chunk retains both exports — destructuring the runtime module object does not guarantee export-level removal, so inspect the actual output. The tiny lazy version is larger in total because the module boundary and loading machinery have a cost: splitting helps when deferred work justifies that cost, not because every dynamic import saves bytes.

Serve both pages locally and inspect the Network panel before and after the click, comparing cold-cache and repeat visits separately. Keep a failure path: stale deployments or an unavailable chunk can reject the import. The fixture reports that failure and permits retry; a real app must define compatibility and deployment retention policies.

### 3. Use the Analyzer Already Supported by Your Build

Webpack's bundle analyzer consumes generated stats; source-map-explorer needs compatible source maps for source attribution; Rollup's visualizer consumes Rollup output. Those are separate integrations — enabling one is not a command that activates every tool. A Vite example must match the project's active bundler and plugin compatibility. For an existing Webpack build, merge this **configuration excerpt** into its production config:

```javascript
const { BundleAnalyzerPlugin } = require('webpack-bundle-analyzer');
module.exports = {
  plugins: [new BundleAnalyzerPlugin({
    analyzerMode: 'static',
    openAnalyzer: false,
    reportFilename: 'bundle-report.html',
    generateStatsFile: true,
    statsFilename: 'bundle-stats.json',
  })],
};
```

The excerpt enables analysis whenever that config runs — an `ANALYZE=true` environment variable has no effect unless the config reads it. Preserve existing entries, loaders and plugins when merging; this excerpt is not a complete application build.

### 4. Read Retained Code, Duplication and Side Effects

**Tree shaking** removes unused code where the bundler can establish that omission preserves behavior. A barrel re-export alone does not mean every export ships; CommonJS analysis, module evaluation side effects and inaccurate package metadata all change retention. `sideEffects: false` asserts that unused module evaluation is safe to omit — but CSS imports, registrations and global initialization may need retention, so mark them accurately instead of claiming every module is pure. Trace the report back to the import before editing metadata, and check behavior after the change.

When two versions of a dependency appear in the output, inspect their consumers and compatibility. Package-manager deduplication helps compatible ranges but cannot safely merge arbitrary versions, and overriding a transitive dependency requires functional verification rather than a smaller treemap. Deep imports help only where supported package exports and module structure allow them — measure the actual output instead of assigning universal byte counts to a library name.

### 5. Compare a Route Before and After a Dependency Change

An illustrative dashboard initially downloads a charting library for all visitors. A dynamic import removes it from the initial route, but opening the chart now waits for a fetch. Measure initial assets, chart-open latency, repeat navigation and error recovery. Prefetching can reduce the later wait while spending bytes before the feature is used — choose according to usage and target-device evidence.

Use package-size services as an estimate during selection. Your bundler, used exports, version, configuration and compression determine the actual shipped cost; a remote estimate cannot replace analysis of the release artifact.

## Summary

Attribute emitted assets to their inputs, then connect those assets to actual route requests. Tree shaking, sharing and lazy loading change different parts of the graph. Compare matching units and builds, preserve required behavior, and measure whether the new loading boundary helps users.

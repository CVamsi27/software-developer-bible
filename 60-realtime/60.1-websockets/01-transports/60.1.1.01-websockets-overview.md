# WebSockets Overview

## Definition

WebSockets provide full-duplex, bidirectional message exchange over a persistent connection. Both sides can send independently once the channel is established. For example, a browser can send a chat message while the server pushes another user's message without waiting for another poll.

> **Textbook Definition:** WebSocket is a framed, bidirectional communication protocol established through an opening handshake. Reliable transport delivery does not supply application-level persistence, acknowledgment, deduplication or replay.

The usual HTTP/1.1 path upgrades an existing HTTP connection. Supported HTTP/2 and HTTP/3 deployments can instead use extended CONNECT. `wss:` protects the connection with TLS; `ws:` is appropriate only for controlled local fixtures or equivalent trusted environments.

## First Principles

A request/response exchange couples a response to a request. Repeated polling must trade update delay against request cost. A long-lived bidirectional channel removes that coupling for application messages, but it introduces ownership: who holds the connection, detects failure and limits pending work?

The network can deliver bytes reliably while a process is alive, yet a disconnect can occur between accepting a command and reporting its outcome. Reconnecting creates a new channel; recovery needs a separate application contract. Connection reliability and business-operation reliability are different boundaries.

## When both peers need to send

Choose WebSocket when frequent two-way communication fits the product. HTTP already supports connection reuse, streaming responses and SSE; it does not create a new TCP handshake for every request. An occasional command plus server updates can use ordinary HTTP and SSE. Compare direction, recovery, payload and operational needs instead of assigning universal speed rankings.

## How handshake, frames and messages fit together

```text
existing HTTP/1.1 connection
  → upgrade request and server acceptance
  → WebSocket frames in either direction
  → application messages reconstructed and validated
  → close exchange or failed transport
```

The TCP connection exists before the upgrade request. In the HTTP/1.1 path, an accepted upgrade returns `101 Switching Protocols`. The client supplies a key and protocol version; the server returns the corresponding accept value. This demonstrates protocol participation, not user authentication.

A **frame** has fields describing whether it completes a message, its kind, length, masking and payload. A message can span several frames; ping/pong/close control frames can occur between fragments. Client-to-server masking is a protocol requirement intended to protect intermediaries; it is not encryption. Use a maintained implementation to parse frames rather than reproducing the wire protocol in application code.

The browser WebSocket API delivers reconstructed text or binary messages. A **text message** is UTF-8; it need not be JSON. A **binary message** can represent an application-defined format. JSON schema and binary version/length rules remain application responsibilities.

| State | What it means | Allowed application action |
| ---------- | -------------------------- | -------------------------------------------------- |
| CONNECTING | Opening handshake pending | Wait; sending now can throw |
| OPEN | Channel established | Send under the declared buffer policy |
| CLOSING | Close initiated | Stop accepting new work |
| CLOSED | Channel finished or failed | Dispose owned resources; decide whether to recover |

## Code Examples

### A complete bounded echo server

Use an isolated Node.js project with `ws` installed and locked. Save this as `server.mjs`, save the browser client below as `index.html`, then run `node server.mjs`. Open `http://127.0.0.1:18086`. This public loopback echo fixture has no user account or durable business write.

```javascript
import { createServer } from 'node:http';
import { readFile } from 'node:fs/promises';
import { pathToFileURL } from 'node:url';
import { WebSocketServer, WebSocket } from 'ws';

export function createDemo() {
  const server = createServer(async (req, res) => {
    if (req.method !== 'GET' || req.url !== '/') {
      res.writeHead(404).end('Not found'); return;
    }
    try {
      const html = await readFile(new URL('./index.html', import.meta.url));
      res.writeHead(200, { 'Content-Type': 'text/html; charset=utf-8' });
      res.end(html);
    } catch { res.writeHead(500).end('Client fixture unavailable'); }
  });
  const wss = new WebSocketServer({ noServer: true, maxPayload: 1024,
    perMessageDeflate: false });
  server.on('upgrade', (req, socket, head) => {
    socket.on('error', () => {});
    const allowedOrigin = `http://127.0.0.1:${server.address().port}`;
    if (req.url !== '/echo' || req.headers.origin !== allowedOrigin) {
      socket.end('HTTP/1.1 403 Forbidden\r\nConnection: close\r\n\r\n'); return;
    }
    if (wss.clients.size >= 32) {
      socket.end('HTTP/1.1 503 Service Unavailable\r\nConnection: close\r\n\r\n'); return;
    }
    wss.handleUpgrade(req, socket, head, ws => wss.emit('connection', ws));
  });
  wss.on('connection', ws => {
    let alive = true;
    let windowStart = performance.now();
    let received = 0;
    const heartbeat = setInterval(() => {
      if (!alive) { ws.terminate(); return; }
      alive = false;
      ws.ping();
    }, 15000);
    ws.on('pong', () => { alive = true; });
    ws.on('error', () => { ws.terminate(); });
    ws.once('close', () => clearInterval(heartbeat));
    ws.on('message', (data, isBinary) => {
      const now = performance.now();
      if (now - windowStart >= 1000) { windowStart = now; received = 0; }
      if (++received > 10) { ws.close(1008, 'Rate limit'); return; }
      if (isBinary) { ws.close(1003, 'Text required'); return; }
      let message;
      try { message = JSON.parse(data.toString()); }
      catch { ws.close(1008, 'Invalid JSON'); return; }
      if (!message || Array.isArray(message) || message.type !== 'echo' ||
          typeof message.text !== 'string' || message.text.length > 200) {
        ws.close(1008, 'Invalid message'); return;
      }
      const reply = JSON.stringify({ type: 'echo', text: message.text });
      if (ws.readyState !== WebSocket.OPEN) return;
      if (ws.bufferedAmount + Buffer.byteLength(reply) > 16384) {
        ws.terminate(); return;
      }
      ws.send(reply, error => { if (error) ws.terminate(); });
    });
  });
  return { server, connectionCount: () => wss.clients.size,
    close: () => {
      for (const ws of wss.clients) ws.terminate();
      wss.close(); server.close();
    } };
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  const demo = createDemo();
  demo.server.listen(18086, '127.0.0.1');
  for (const signal of ['SIGINT', 'SIGTERM']) process.once(signal, () => demo.close());
}
```

The server checks the path and browser origin before accepting the upgrade, caps connections and incoming messages, validates text JSON and bounds pending reply bytes. A socket owns its own heartbeat and rate counter; close releases the interval. This per-connection rate limit is a demonstration, not a distributed per-user abuse policy. Malformed JSON is an application-policy violation (1008); code 1007 is for invalid message data such as non-UTF-8 text. Closing is a cooperative exchange; use an appropriate deadline and termination policy where a peer does not complete it.

### A complete browser with explicit connection ownership

```html
<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>WebSocket echo fixture</title>
<button id="connect" type="button">Connect</button>
<button id="close" type="button">Disconnect</button>
<label for="text">Message</label>
<input id="text" maxlength="200" value="Hello">
<button id="send" type="button" disabled>Send</button>
<p id="status" role="status">Disconnected</p>
<output id="reply"></output>
<script>
  const status = document.querySelector('#status');
  const send = document.querySelector('#send');
  let current = null;
  document.querySelector('#connect').onclick = () => {
    if (current && current.readyState !== WebSocket.CLOSED) return;
    const scheme = location.protocol === 'https:' ? 'wss:' : 'ws:';
    const ws = new WebSocket(`${scheme}//${location.host}/echo`);
    current = ws;
    status.textContent = 'Connecting';
    ws.onopen = () => {
      if (current !== ws) return;
      send.disabled = false; status.textContent = 'Connected';
    };
    ws.onmessage = event => {
      if (current !== ws) return;
      try {
        const reply = JSON.parse(event.data);
        if (reply?.type !== 'echo' || typeof reply.text !== 'string' || reply.text.length > 200) {
          throw new Error('Invalid reply');
        }
        document.querySelector('#reply').textContent = reply.text;
      } catch { ws.close(1008, 'Invalid reply'); }
    };
    ws.onerror = () => { if (current === ws) status.textContent = 'Connection error'; };
    ws.onclose = event => {
      if (current !== ws) return;
      send.disabled = true; status.textContent = `Disconnected (${event.code})`;
    };
  };
  send.onclick = () => {
    const ws = current;
    if (!ws || ws.readyState !== WebSocket.OPEN) return;
    const body = JSON.stringify({ type: 'echo', text: document.querySelector('#text').value });
    if (ws.bufferedAmount + new TextEncoder().encode(body).byteLength > 16384) {
      status.textContent = 'Send buffer full. Try later.'; return;
    }
    ws.send(body);
  };
  document.querySelector('#close').onclick = () => {
    send.disabled = true;
    current?.close(1000, 'User disconnected');
  };
  window.addEventListener('pagehide', () => current?.close(1000, 'Page hidden'), { once: true });
</script>
</html>
```

Click Connect, then Send. The echo confirms that this server's handler produced a reply; it does not claim persistence. Disconnect deliberately ends the channel, and Connect opens a new one. The fixture queues no commands while disconnected. Old socket callbacks cannot update the new socket's UI because they check the captured connection identity.

An automatic reconnect policy would need one timer owner, bounded backoff with jitter, cancellation after explicit stop and a recovery handshake before releasing pending work. See the [scaling chapter](../02-architecture-and-scaling/60.1.2.02-scaling-patterns.md) for the wider recovery decision. A new socket alone does not restore rooms, missed messages or command outcomes.

## Real-World Decisions

### Authentication is separate from upgrade acceptance

An origin allowlist restricts browser-origin access; non-browser clients can supply an Origin header, so it is not user authentication. Production should authenticate through its session or another deliberately designed handshake flow and authorize every requested room/action against current user/tenant permissions. Native browser WebSocket cannot attach arbitrary Authorization headers. Avoid durable tokens in query strings; do not treat a client-supplied room or tenant ID as trusted identity.

Use secure transport, validate expiry/revocation policies and handle cross-site WebSocket hijacking where cookies authenticate the handshake. Bound work before and after authentication. Keep internal stack traces and secrets out of close reasons and responses.

### Heartbeats detect a transport boundary

The ws server sends protocol ping frames and observes protocol pong replies. Browsers handle these control frames without exposing a JavaScript ping method. An application text message named “ping” is a different protocol and needs an application-defined reply.

A missed pong can reveal an unreachable peer, but a received pong does not prove the database or business handler is healthy. Choose deadlines according to latency and intermediary behavior, and clear intervals on teardown. Track failed handshakes and recovery storms separately from message-processing health.

### Bound buffering and define what can be dropped

Browser `send()` enqueues data; `bufferedAmount` is local pending bytes, not a server acknowledgment. The API does not supply automatic application backpressure. Reject, coalesce or bound pending updates rather than accumulating an unlimited queue. A game position snapshot may replace an older one; a financial command cannot be dropped or retried blindly under the same policy.

A command can commit while its acknowledgment is lost. Use an operation identity and durable deduplication or reconcile authoritative state before retrying an effect. On reconnect, restore subscriptions and replay within a declared cursor/epoch domain. Reliable ordering on a live connection does not extend automatically across disconnected sessions.

### Scale the connection tier without inventing application guarantees

A live connection belongs to one backend after its handshake. New connections may land elsewhere. A shared broker can distribute room updates, but local room registries, authorization and replay remain owned responsibilities. Sticky routing is not universally necessary for raw WebSocket; polling-based fallback systems have a different affinity contract.

Compression is optional and consumes CPU/memory. Test it with the actual payload and concurrency rather than enabling it as an unconditional optimization. Collaborative editing additionally needs a conflict-resolution model, such as operational transformation or a convergent data type; broadcast alone does not establish convergence.

## Define the connection contract before shipping

Define the wire message schema, payload limits, connection owner and shutdown behavior. Validate both inbound data and application permissions. Test malformed messages, transport failure, explicit stop, slow-consumer policy and reconnect recovery. Measure memory, throughput and end-to-end applied updates for the actual workload; report each measurement's boundary.

## Summary

WebSocket establishes a persistent bidirectional message channel. The application still owns validation, permission, bounded work, lifecycle and recovery. Trace handshake, message handling and close separately from durable effects; then choose acknowledgment/replay policies for what the product must preserve.

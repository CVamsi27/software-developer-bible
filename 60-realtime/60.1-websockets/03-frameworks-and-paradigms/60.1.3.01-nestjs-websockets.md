# NestJS WebSockets

## Definition

NestJS handles persistent connection events through **gateways**: provider classes whose methods receive selected events and call application services. Its default Socket.IO adapter supplies the transport; a `ws` adapter or a custom adapter can provide a different platform.

> **Textbook Definition:** A NestJS WebSocket gateway adapts persistent connection events to application handlers through a transport adapter, with separate lifecycle, validation and authorization responsibilities.

A booking application can use HTTP controllers for ordinary requests and a gateway for live clinic updates. Both call the same business services. The gateway owns event handling; the service owns permissions and business state. A gateway is registered in a module's `providers`, not its `controllers`.

## First Principles

A live channel can carry many messages after its initial handshake. Each message has untrusted input and a requested action, while permissions can change during the connection. Business state can outlive the process that owns the socket.

Consequently, handshake acceptance, per-message access, payload validation and durable business behavior must be distinct. A framework can organize these stages and inject dependencies, but its decorators cannot infer the application's permissions or delivery contract.

## Why Use a Gateway?

Use a gateway when the application already benefits from Nest modules, dependency injection and its handler pipeline. Raw Socket.IO is also testable and can use injected dependencies through ordinary code. Nest adds a consistent organization; it does not uniquely provide type safety or make runtime input safe.

Choose the adapter deliberately. A plain WebSocket client cannot speak Socket.IO framing. Swapping adapters can change event envelopes, room APIs and acknowledgment behavior; it is not a guarantee that transport-specific handler code remains unchanged.

## How the Handler Pipeline Fits Together

```text
connection → adapter handshake/middleware → accepted live socket
message    → message guard → interceptor → body pipe → gateway method
                                                       ↓
                                                application service
                                                       ↓
                                        handler result / exception filter
```

A **guard** decides whether a handler may run. A **pipe** validates or converts its input. An **interceptor** surrounds handler execution and can observe or transform the returned value. An **exception filter** translates failures into the chosen WebSocket error contract. These components must use the WebSocket execution context rather than assuming an HTTP request and response.

A message guard is not automatically handshake authentication. Install appropriate connection middleware or adapter behavior as well. `handleConnection` and `handleDisconnect` observe lifecycle events; `afterInit` receives the initialized server or namespace. Gateways are long-lived providers, so do not treat their instance fields as per-user request state.

## Example: An Authorized Room Snapshot

This complete local fixture uses NestJS 11 with matching `common`, `core`, `platform-express`, `websockets` and `platform-socket.io` packages, Socket.IO 4, `reflect-metadata`, RxJS, `class-validator` and `class-transformer`. Save it as `main.ts` in a TypeScript project with `experimentalDecorators` and `emitDecoratorMetadata` enabled, compile it and run the result.

It demonstrates the framework pipeline through two events: join an authorized room, then request its current snapshot. The seeded snapshot and tokens are local fixtures. No durable writes, JWT verification, replay, distributed rate limiting or production network authentication are implemented.

```typescript
import 'reflect-metadata';
import {
  CanActivate, ExecutionContext, Injectable, Module,
  UseGuards, UsePipes, ValidationPipe,
} from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import {
  ConnectedSocket, MessageBody, OnGatewayInit, SubscribeMessage,
  WebSocketGateway, WsException,
} from '@nestjs/websockets';
import { Namespace, Socket } from 'socket.io';
import { IsString, Matches } from 'class-validator';

type User = { id: string; rooms: Set<string> };
@Injectable()
class Sessions {
  private readonly users = new Map<string, User>([
    ['alice-demo-token', { id: 'alice', rooms: new Set(['team:42']) }],
    ['eve-demo-token', { id: 'eve', rooms: new Set() }],
  ]);
  find(token: unknown): User | undefined {
    return typeof token === 'string' ? this.users.get(token) : undefined;
  }
}
@Injectable()
class MessageSessionGuard implements CanActivate {
  constructor(private readonly sessions: Sessions) {}
  canActivate(context: ExecutionContext): boolean {
    const client = context.switchToWs().getClient<Socket>();
    const user = this.sessions.find(client.handshake.auth.token);
    if (!user) throw new WsException('Authentication required');
    client.data.user = user;
    return true;
  }
}
class RoomRequest {
  @IsString()
  @Matches(/^team:[0-9]{1,8}$/)
  room!: string;
}
@Injectable()
class Snapshots {
  read(user: User, room: string) {
    if (!user.rooms.has(room)) throw new WsException('Forbidden room');
    return { room, revision: 1, items: ['demo booking'] };
  }
}
@UseGuards(MessageSessionGuard)
@UsePipes(new ValidationPipe({
  transform: true,
  whitelist: true,
  forbidNonWhitelisted: true,
  exceptionFactory: () => new WsException('Invalid payload'),
}))
@WebSocketGateway({
  namespace: '/study', transports: ['websocket'], maxHttpBufferSize: 16 * 1024,
})
class StudyGateway implements OnGatewayInit<Namespace> {
  constructor(private readonly sessions: Sessions, private readonly snapshots: Snapshots) {}
  afterInit(namespace: Namespace) {
    namespace.use((client, next) => {
      const user = this.sessions.find(client.handshake.auth.token);
      if (!user) return next(new Error('Authentication required'));
      client.data.user = user;
      next();
    });
  }
  @SubscribeMessage('room:join')
  async join(@ConnectedSocket() client: Socket, @MessageBody() input: RoomRequest) {
    const snapshot = this.snapshots.read(client.data.user, input.room);
    await client.join(input.room);
    return snapshot;
  }
  @SubscribeMessage('room:state')
  state(@ConnectedSocket() client: Socket, @MessageBody() input: RoomRequest) {
    if (!client.rooms.has(input.room)) throw new WsException('Join first');
    return this.snapshots.read(client.data.user, input.room);
  }
}
@Module({ providers: [Sessions, MessageSessionGuard, Snapshots, StudyGateway] })
class AppModule {}
async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.enableShutdownHooks();
  await app.listen(3000, '127.0.0.1');
}
bootstrap().catch((error) => { console.error(error); process.exitCode = 1; });
```

The namespace middleware rejects an invalid credential before accepting the Socket.IO connection. The guard checks the current fixture session for each subscribed message. The pipe rejects missing, malformed or unexpected payload fields. The service checks room permission before returning any data; being connected does not imply membership.

A namespaced gateway receives a Socket.IO `Namespace`, not a root `Server`, in its namespace server property/hook. Do not access root-only fields such as `engine` through a value merely annotated as `Server`.

### Client: observe both acknowledgments and exceptions

With `socket.io-client` installed, this integration snippet requests a room snapshot:

```javascript
import { io } from 'socket.io-client';
const socket = io('http://127.0.0.1:3000/study', {
  auth: { token: 'alice-demo-token' },
  transports: ['websocket'],
  autoConnect: false,
});
socket.on('exception', (error) => console.error('Event rejected:', error.message));
socket.on('connect_error', (error) => console.error('Connection rejected:', error.message));
socket.on('connect', async () => {
  try {
    const snapshot = await socket.timeout(2000).emitWithAck('room:join', { room: 'team:42' });
    console.log(snapshot);
  } catch {
    console.error('No acknowledgment before deadline');
  }
});
socket.connect();
// Owner cleanup when leaving this view: socket.disconnect();
```

With the default Socket.IO adapter, a handler's ordinary return value becomes the event acknowledgment when the sender provides a callback. A returned `{ event, data }` response instead expresses an emitted event. Direct `client.emit()` calls bypass return-value transformations in interceptors.

The default `WsException` path emits an `exception` event; it does not automatically reject the same acknowledgment callback. Consequently, a rejected event can also leave an acknowledgment deadline to expire. A production contract can add an explicit operation ID and uniform acknowledgment error envelope, but that behavior must be implemented and tested rather than assumed.

## Trace the Boundaries

Alice connects with a valid token and sends `room:join` with `team:42`. Middleware and guard establish her identity; the pipe validates the room field; the service permits it; the gateway joins the room and acknowledges the snapshot. Eve's valid token passes authentication but the service rejects that room. A malformed field fails the pipe before service execution.

A `room:state` request also checks that the live socket has joined and that the session still has access. If a real session expires or is revoked, the application must reject future messages and stop any server-driven private broadcasts as well. Message guards do not automatically re-check every outgoing event to previously joined rooms.

## Real-World Decisions

For durable chat or booking commands, call an application service that validates permissions and records the business change with duplicate-effect protection. Publish committed updates through the [outbox and recovery architecture](../02-architecture-and-scaling/60.1.2.01-real-time-architecture.md). Avoid duplicating the [Socket.IO delivery example](../01-transports/60.1.1.03-socket-io.md) with an incomplete second store here.

For presence, one user can own multiple sockets. Closing one tab must not mark the account offline while another remains connected. Socket.IO automatically leaves rooms on disconnect; separately clean up application timers, broker subscriptions and presence leases. A local user-to-socket map requires removal and bounds and does not route to other replicas.

For scaling, a Redis Socket.IO adapter handles cross-node events; a Nest Redis microservice transport serves a different message-handler role. They are not interchangeable. Polling still needs session affinity, while a WebSocket-only connection stays on its chosen node. Shared state and recovery remain explicit.

## Common Mistakes

- **Trusting `userId` in the event body.** Derive it from a verified session and reject or ignore impersonation fields deliberately.
- **Using string types as runtime validation.** DTO classes and their decorators must actually run through a configured pipe. String length uses length validators; numeric `Min`/`Max` do not validate text length.
- **Throwing an HTTP exception and assuming the client sees an HTTP response.** Use a WebSocket exception/filter contract and document whether it emits an error event or acknowledges an error.
- **Logging every token or payload.** Interceptor timing should describe handler execution, not network delivery or rendering. Use bounded event labels and redact sensitive data.
- **Applying a guard only at handshake.** Enforce current operation/object permissions and outgoing subscription revocation too.
- **Calling generated namespaces secure.** Each namespace needs its own appropriate policy; a separate URL is not an access-control boundary.

## Best Practices

Set payload, event-rate, subscription and queue limits. Account-based rate budgets are harder to bypass by reconnecting than socket-ID-only counters; expire storage and coordinate across replicas where the budget is global. Define finite acknowledgment waits and retry identities for durable commands.

Test the actual Nest application with its adapter, module registration, pipes and guards, as well as focused service tests. A direct method call cannot prove the transport pipeline works. During shutdown, stop new work, handle accepted commands under a deadline, close sockets and release owned resources; enabling shutdown hooks does not invent a durable drain policy.

## Summary

Nest gateways organize live event handling around modules and injected services. Authenticate connections, authorize each message, validate runtime payloads and define the actual acknowledgment/error contract. Keep durable business state and outgoing subscription policy independent of the socket lifecycle.

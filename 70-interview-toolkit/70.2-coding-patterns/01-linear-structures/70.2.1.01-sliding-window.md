# Sliding Window

## Definition

The sliding window pattern is a technique that uses a "window" (a subset of elements) that slides over a data structure to solve problems involving contiguous sequences. It maintains a window of elements and adjusts the window boundaries as it traverses the input, avoiding redundant recalculations.

> **Textbook Definition:** A sliding-window algorithm maintains a contiguous interval and updates its state as its boundaries move. Linear-time progress requires a valid invariant and bounded movement of each boundary.

## First Principles

Sliding window converts O(n²) subarray enumeration into O(n) by refusing to recompute:

1. **A subarray's property is often *monotonic* in its endpoints** — for constraints such as "at most K distinct values", expanding right can invalidate a window and shrinking left restores validity: that monotonicity means each endpoint moves forward at most n times total, which *is* the O(n) proof.
2. **The pattern is two pointers + a running state** (sum, counts, matches): maintain the state incrementally on enter/leave instead of recomputing per window — the general lesson: exploit incrementality when the measure is decomposable.

## Why It Matters

For a fixed-width sum, adjacent windows share nearly all their elements. Subtract the departing value and add the entering one. For a variable window, explain why discarding the leftmost candidate cannot lose a better answer: “contiguous” alone is insufficient. Positive-sum constraints and at-most-distinct constraints allow different shrinking rules; negative values can invalidate the usual sum rule.

## When to Use

- Finding a subarray/substring with a specific property (max sum, target sum)
- Problems involving contiguous sequences of elements
- When brute force would use nested loops (O(n²) or O(n³))
- Problems asking for maximum/minimum of a subarray of fixed or variable size
- String permutation or anagram problems

## How It Works

```text
Array: [2, 1, 5, 1, 3, 2], k = 3

Fixed Window (k=3):
Step 1: [2, 1, 5] 1, 3, 2 → sum = 8
Step 2: 2, [1, 5, 1] 3, 2 → sum = 7
Step 3: 2, 1, [5, 1, 3] 2 → sum = 9 ← max
Step 4: 2, 1, 5, [1, 3, 2] → sum = 6

Variable Window:
Target sum = 7
[2, 1, 5] 1, 3, 2 → sum = 8 (too big, shrink)
 2 [1, 5] 1, 3, 2 → sum = 6 (too small, expand)
 2, [1, 5, 1] 3, 2 → sum = 7 found!

```

The fixed example's state is the sum of exactly the current three elements. Moving from `[1,5,1]` to `[5,1,3]` subtracts 1 and adds 3: 7 becomes 9 without scanning the window again. Each endpoint moves only forward; constant-time state updates give linear total work.

For the target-sum illustration, all values are positive and the goal is an exact-sum window. Do not reuse its shrinking condition for minimum coverage: that problem shrinks while the window is valid to find a smaller valid result.

## Code Examples (TypeScript)

### Problem 1: Maximum Sum Subarray of Size K (Fixed Window)

```typescript
function maxSumSubarray(nums: number[], k: number): number {
  if (!Number.isInteger(k) || k < 1 || k > nums.length) throw new RangeError("invalid window size");
  let windowSum = 0;
  let maxSum = -Infinity;

  for (let i = 0; i < nums.length; i++) {
    windowSum += nums[i];

    if (i >= k) {
      windowSum -= nums[i - k];
    }

    if (i >= k - 1) {
      maxSum = Math.max(maxSum, windowSum);
    }
  }

  return maxSum;
}

// Example
console.log(maxSumSubarray([2, 1, 5, 1, 3, 2], 3)); // 9
// Explanation: [5, 1, 3] has the maximum sum

```

### Problem 2: Longest Substring Without Repeating Characters (Variable Window)

The indexed string examples below use ASCII input. For other text, choose code points or grapheme clusters consistently; a UTF-16 code unit is not always one user-visible character.

```typescript
function lengthOfLongestSubstring(s: string): number {
  const charMap = new Map<string, number>();
  let maxLength = 0;
  let left = 0;

  for (let right = 0; right < s.length; right++) {
    const char = s[right];

    if (charMap.has(char) && charMap.get(char)! >= left) {
      left = charMap.get(char)! + 1;
    }

    charMap.set(char, right);
    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
}

// Example
console.log(lengthOfLongestSubstring("abcabcbb")); // 3 ("abc")
console.log(lengthOfLongestSubstring("bbbbb")); // 1 ("b")
console.log(lengthOfLongestSubstring("pwwkew")); // 3 ("wke")

```

### Problem 3: Minimum Window Substring (Variable Window with Shrink)

```typescript
function minWindow(s: string, t: string): string {
  if (t.length === 0 || s.length < t.length) return "";

  const need = new Map<string, number>();
  const window = new Map<string, number>();

  for (const char of t) {
    need.set(char, (need.get(char) || 0) + 1);
  }

  let left = 0;
  let right = 0;
  let valid = 0;
  let minLen = Infinity;
  let minStart = 0;

  while (right < s.length) {
    const char = s[right];
    window.set(char, (window.get(char) || 0) + 1);

    if (need.has(char) && window.get(char) === need.get(char)) {
      valid++;
    }

    while (valid === need.size) {
      if (right - left + 1 < minLen) {
        minLen = right - left + 1;
        minStart = left;
      }

      const leftChar = s[left];
      window.set(leftChar, window.get(leftChar)! - 1);

      if (need.has(leftChar) && window.get(leftChar)! < need.get(leftChar)!) {
        valid--;
      }

      left++;
    }

    right++;
  }

  return minLen === Infinity ? "" : s.substring(minStart, minStart + minLen);
}

// Example
console.log(minWindow("ADOBECODEBANC", "ABC")); // "BANC"

```

### Problem 4: Longest Repeating Character Replacement

```typescript
function characterReplacement(s: string, k: number): number {
  if (!Number.isInteger(k) || k < 0) throw new RangeError("invalid replacement budget");
  const count = new Map<string, number>();
  let maxCount = 0; // historical maximum; deliberately does not decrease
  let left = 0;
  let maxLength = 0;

  for (let right = 0; right < s.length; right++) {
    const char = s[right];
    count.set(char, (count.get(char) || 0) + 1);
    maxCount = Math.max(maxCount, count.get(char)!);

    // Use the historical upper bound to limit growth; this is a length-only algorithm.
    while (right - left + 1 - maxCount > k) {
      const leftChar = s[left];
      count.set(leftChar, count.get(leftChar)! - 1);
      left++;
    }

    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
}

// Example
console.log(characterReplacement("AABABBA", 1)); // 4 ("AABA")

```

## Common Mistakes

1. **Off-by-one errors**: A window first has k elements at index k−1; its size is right−left+1.

2. **Not resetting window state**: When the problem requires independent windows

3. **Using the wrong shrink condition**: At-most constraints shrink when invalid; minimum-cover problems shrink while valid. State the invariant first.

4. **Using wrong data structure**: Use a Map or array for character frequency, not a Set

5. **Not handling edge cases**: Empty strings, single elements, k > array length

## Time/Space Complexity

| Complexity | Fixed Window | Variable Window |
| ---------- | ------------ | --------------- |
| Time | O(n) | O(n) |
| Space | O(1) | O(k) or O(n) |

- **Time O(n)**: Each element is visited at most twice (once by right pointer, once by left)
- **Space O(1)** for the running-sum fixed window: the input already holds the elements. Frequency maps use space proportional to the tracked alphabet/window.

The string examples index UTF-16 code units; use a consistent code-point or grapheme representation for Unicode text. The minimum-window example uses `for...of` for the target, so its stated contract is ASCII input. Sum-based shrinking additionally needs a monotone constraint: negative values can invalidate the usual positive-sum proof.

In character replacement, `maxCount` is a historical upper bound rather than the exact current frequency. The resulting window can temporarily be invalid, but cannot produce a larger unattainable optimum; recomputing the maximum on every shrink is unnecessary for the length-only answer.

## Summary

Maintain a contiguous interval and update its state as elements enter and leave. Linear time requires a correct shrinking invariant and bounded forward movement, not merely two indices. State input and character-unit assumptions before applying the pattern.

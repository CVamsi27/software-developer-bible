# Sliding Window

In `[2, 1, 5, 1, 3, 2]`, each length-three window shares two values with the next. The largest sum is 9 — and reusing the shared work instead of rescanning each window is what makes a linear scan possible.

```typescript
maxSumSubarray([2, 1, 5, 1, 3, 2], 3); // 9 — window [5, 1, 3]
```

## Definition

The **sliding-window pattern** maintains a contiguous **range** while its boundaries move through a sequence. It updates the range's **state** as elements enter or leave, avoiding redundant recalculation when the problem's invariant permits those movements.

> **Textbook Definition:** A sliding-window algorithm maintains a contiguous interval and updates its state as its boundaries move. Linear-time progress requires a valid invariant and bounded movement of each boundary.

## First Principles

Sliding window converts O(n²) subarray enumeration into O(n) by refusing to recompute. A subarray's property is often **monotonic** in its endpoints — for "at most K distinct values," expanding right can invalidate a window and shrinking left restores validity. That monotonicity means each endpoint moves forward at most n times total, which *is* the O(n) proof. The pattern is two pointers plus a running state (sum, counts, matches), maintained incrementally on enter and leave rather than recomputed per window.

## Why It Matters

For a fixed-width sum, adjacent windows share nearly all their elements: subtract the departing value and add the entering one. For a variable window, explain why discarding the leftmost candidate cannot lose a better answer — "contiguous" alone is insufficient. Positive-sum constraints and at-most-distinct constraints allow different shrinking rules, and negative values can invalidate the usual sum rule.

## How It Works

### 1. Move Two Boundaries With Running State

```text
Array: [2, 1, 5, 1, 3, 2], k = 3

Fixed Window (k=3):
Step 1: [2, 1, 5] 1, 3, 2 → sum = 8
Step 2: 2, [1, 5, 1] 3, 2 → sum = 7
Step 3: 2, 1, [5, 1, 3] 2 → sum = 9 ← max
Step 4: 2, 1, 5, [1, 3, 2] → sum = 6

Variable Window:
Target sum = 7
[2, 1, 5] 1, 3, 2 → sum = 8 (too big, shrink)
 2 [1, 5] 1, 3, 2 → sum = 6 (too small, expand)
 2, [1, 5, 1] 3, 2 → sum = 7 found!
```

The fixed example's state is the sum of exactly the current three elements. Moving from `[1,5,1]` to `[5,1,3]` subtracts 1 and adds 3: 7 becomes 9 without scanning the window again. Each endpoint moves only forward; constant-time state updates give linear total work. For the target-sum illustration, all values are positive and the goal is an exact-sum window — never reuse its shrinking condition for minimum coverage, which shrinks while the window is *valid* to find a smaller valid result.

### 2. Maximum Sum Subarray of Size K (Fixed Window)

```typescript
function maxSumSubarray(nums: number[], k: number): number {
  if (!Number.isInteger(k) || k < 1 || k > nums.length) throw new RangeError("invalid window size");
  let windowSum = 0;
  let maxSum = -Infinity;

  for (let i = 0; i < nums.length; i++) {
    windowSum += nums[i];

    if (i >= k) {
      windowSum -= nums[i - k];
    }

    if (i >= k - 1) {
      maxSum = Math.max(maxSum, windowSum);
    }
  }

  return maxSum;
}

// Example
console.log(maxSumSubarray([2, 1, 5, 1, 3, 2], 3)); // 9
// Explanation: [5, 1, 3] has the maximum sum
```

### 3. Longest Substring Without Repeating Characters (Variable Window)

The indexed string examples below use ASCII input. For other text, choose code points or grapheme clusters consistently; a UTF-16 code unit is not always one user-visible character.

```typescript
function lengthOfLongestSubstring(s: string): number {
  const charMap = new Map<string, number>();
  let maxLength = 0;
  let left = 0;

  for (let right = 0; right < s.length; right++) {
    const char = s[right];

    if (charMap.has(char) && charMap.get(char)! >= left) {
      left = charMap.get(char)! + 1;
    }

    charMap.set(char, right);
    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
}

// Example
console.log(lengthOfLongestSubstring("abcabcbb")); // 3 ("abc")
console.log(lengthOfLongestSubstring("bbbbb")); // 1 ("b")
console.log(lengthOfLongestSubstring("pwwkew")); // 3 ("wke")
```

### 4. Minimum Window Substring (Variable Window With Shrink)

```typescript
function minWindow(s: string, t: string): string {
  if (t.length === 0 || s.length < t.length) return "";

  const need = new Map<string, number>();
  const window = new Map<string, number>();

  for (const char of t) {
    need.set(char, (need.get(char) || 0) + 1);
  }

  let left = 0;
  let right = 0;
  let valid = 0;
  let minLen = Infinity;
  let minStart = 0;

  while (right < s.length) {
    const char = s[right];
    window.set(char, (window.get(char) || 0) + 1);

    if (need.has(char) && window.get(char) === need.get(char)) {
      valid++;
    }

    while (valid === need.size) {
      if (right - left + 1 < minLen) {
        minLen = right - left + 1;
        minStart = left;
      }

      const leftChar = s[left];
      window.set(leftChar, window.get(leftChar)! - 1);

      if (need.has(leftChar) && window.get(leftChar)! < need.get(leftChar)!) {
        valid--;
      }

      left++;
    }

    right++;
  }

  return minLen === Infinity ? "" : s.substring(minStart, minStart + minLen);
}

// Example
console.log(minWindow("ADOBECODEBANC", "ABC")); // "BANC"
```

### 5. Longest Repeating Character Replacement

```typescript
function characterReplacement(s: string, k: number): number {
  if (!Number.isInteger(k) || k < 0) throw new RangeError("invalid replacement budget");
  const count = new Map<string, number>();
  let maxCount = 0; // historical maximum; deliberately does not decrease
  let left = 0;
  let maxLength = 0;

  for (let right = 0; right < s.length; right++) {
    const char = s[right];
    count.set(char, (count.get(char) || 0) + 1);
    maxCount = Math.max(maxCount, count.get(char)!);

    // Use the historical upper bound to limit growth; this is a length-only algorithm.
    while (right - left + 1 - maxCount > k) {
      const leftChar = s[left];
      count.set(leftChar, count.get(leftChar)! - 1);
      left++;
    }

    maxLength = Math.max(maxLength, right - left + 1);
  }

  return maxLength;
}

// Example
console.log(characterReplacement("AABABBA", 1)); // 4 ("AABA")
```

In character replacement, `maxCount` is a historical upper bound rather than the exact current frequency. The resulting window can temporarily be invalid but cannot produce a larger unattainable optimum; recomputing the maximum on every shrink is unnecessary for the length-only answer.

## Real-World Use Cases

Reach for sliding window when brute force would use nested loops over contiguous sequences: finding a subarray or substring with a specific property (max sum, target sum), maximum or minimum over fixed or variable sizes, and string permutation or anagram problems.

- **Easy**: Maximum Average Subarray I (LeetCode 643) — max average of a size-k subarray; Best Time to Buy and Sell Stock (LeetCode 121) — max profit with one transaction; Contains Duplicate II (LeetCode 219) — bounded membership window.
- **Medium**: Longest Substring Without Repeating Characters (LeetCode 3); Longest Repeating Character Replacement (LeetCode 424); Minimum Size Subarray Sum (LeetCode 209); Permutation in String (LeetCode 567); Fruit Into Baskets (LeetCode 904).
- **Hard**: Minimum Window Substring (LeetCode 76); Substring with Concatenation of All Words (LeetCode 30); Sliding Window Maximum (LeetCode 239) — uses a deque; Longest Substring with At Most K Distinct Characters (LeetCode 340).

## Common Mistakes

1. **Off-by-one errors**: A window first has k elements at index k−1; its size is right−left+1.

2. **Not resetting window state**: When each candidate is independent, reset its counts and totals; otherwise state from an earlier candidate contaminates the result.

3. **Using the wrong shrink condition**: At-most constraints shrink when invalid; minimum-cover problems shrink while valid. State the invariant first.

4. **Using the wrong data structure**: Use a map or frequency array when counts matter; a set records membership only.

5. **Ignoring edge cases**: Check empty strings, single elements and invalid window sizes such as `k > nums.length`.

## Performance Considerations

| Complexity | Fixed Window | Variable Window |
| ---------- | ------------ | --------------- |
| Time | O(n) | O(n) |
| Space | O(1) | O(k) or O(n) |

- **Time O(n)**: Each element is visited at most twice (once by right pointer, once by left)
- **Space O(1)** for the running-sum fixed window: the input already holds the elements. Frequency maps use space proportional to the tracked alphabet/window.

The string examples index UTF-16 code units; use a consistent code-point or grapheme representation for Unicode text. The minimum-window example uses `for...of` for the target, so its stated contract is ASCII input. Sum-based shrinking additionally needs a monotone constraint: negative values can invalidate the usual positive-sum proof.

## Summary

Maintain a contiguous interval and update its state as elements enter and leave. Linear time requires a correct shrinking invariant and bounded forward movement, not merely two indices. State input and character-unit assumptions before applying the pattern.

# Two Pointers

In a sorted array, a pair-sum comparison can eliminate an entire group of candidates at once. Two pointers turn that ordering fact into a linear scan — provided each move has a proof.

```typescript
twoSumSorted([2, 7, 11, 15], 9); // [1, 2] — 1-indexed pair summing to 9
```

## Definition

**Two pointers** coordinate two positions in a data structure — from opposite ends or at different speeds — to reduce repeated search or comparison. Each advance follows an **invariant** that preserves candidate solutions.

> **Textbook Definition:** A two-pointer algorithm coordinates two positions in a data structure to reduce repeated search or comparison, advancing them according to an invariant that preserves candidate solutions.

## First Principles

Two pointers exploit **order** to avoid pairing enumeration. On sorted input, comparing the extremes yields usable information: if the smallest candidate plus the largest is too big, discard that largest candidate; if too small, discard the smallest. Each comparison eliminates a whole row or column of the pairing matrix — that is where O(n) vs O(n²) comes from. The pattern is a proof device: every step discards candidates *with justification* for why the discarded pair cannot be the answer.

## Why It Matters

Two pointers is a reusable building block foundational for the trickier patterns (3-sum, 4-sum, container-with-most-water). The senior signal is **knowing when input is sortable** — sometimes you sort first, losing O(n log n) but gaining O(n) traversal — and **handling duplicates** without infinite-looping. Expect to derive 3-sum, container-with-most-water and "sort colors" on the spot, and to explain why the slow/fast pointer trick detects cycles in O(1) space.

## How It Works

### 1. Eliminate Candidates With Ordering

For ascending `[2,7,11,15,20,25]` and target 22:

| Left/right | Sum | Safe elimination |
| ----------- | --- | ----------------------------------------------------------------------- |
| 0/5: 2 + 25 | 27 | Even the smallest remaining partner makes 25 too large; discard index 5 |
| 0/4: 2 + 20 | 22 | Found the pair |

When the sum is too small, the current left value fails even with the largest remaining partner, so no remaining pair using that left value can work — moving it preserves every possible answer. This proof needs sorted input. The container problem below uses another invariant: area is width times the shorter endpoint, so keeping the shorter endpoint while reducing width cannot improve the current area. Fast/slow list pointers use a different proof based on relative distance, explained in the canonical linked-list chapter.

The numeric examples assume finite inputs with every intermediate sum or area a safe integer in JavaScript. Heights are nonnegative. Two Sum requires ascending input; Three Sum sorts and mutates its input, so copy it when original order or indices matter.

### 2. Two Sum II on Sorted Input

```typescript
function twoSumSorted(numbers: number[], target: number): number[] {
  let left = 0;
  let right = numbers.length - 1;

  while (left < right) {
    const sum = numbers[left] + numbers[right];

    if (sum === target) {
      return [left + 1, right + 1]; // 1-indexed
    } else if (sum < target) {
      left++;
    } else {
      right--;
    }
  }

  return [-1, -1];
}

// Example
console.log(twoSumSorted([2, 7, 11, 15], 9)); // [1, 2]
```

### 3. Container With Most Water

```typescript
function maxArea(height: number[]): number {
  let left = 0;
  let right = height.length - 1;
  let maxArea = 0;

  while (left < right) {
    const width = right - left;
    const h = Math.min(height[left], height[right]);
    const area = width * h;

    maxArea = Math.max(maxArea, area);

    // Move the pointer with smaller height
    if (height[left] < height[right]) {
      left++;
    } else {
      right--;
    }
  }

  return maxArea;
}

// Example
console.log(maxArea([1, 8, 6, 2, 5, 4, 8, 3, 7])); // 49
// Container between index 1 (height 8) and index 8 (height 7)
```

### 4. Trapping Rain Water

```typescript
function trap(height: number[]): number {
  if (height.length === 0) return 0;

  let left = 0;
  let right = height.length - 1;
  let leftMax = height[left];
  let rightMax = height[right];
  let water = 0;

  while (left < right) {
    if (leftMax < rightMax) {
      left++;
      leftMax = Math.max(leftMax, height[left]);
      water += leftMax - height[left];
    } else {
      right--;
      rightMax = Math.max(rightMax, height[right]);
      water += rightMax - height[right];
    }
  }

  return water;
}

// Example
console.log(trap([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1])); // 6
```

### 5. Valid Palindrome

```typescript
function isPalindrome(s: string): boolean {
  const cleaned = s.toLowerCase().replace(/[^a-z0-9]/g, ''); // ASCII-alphanumeric contract

  let left = 0;
  let right = cleaned.length - 1;

  while (left < right) {
    if (cleaned[left] !== cleaned[right]) {
      return false;
    }
    left++;
    right--;
  }

  return true;
}

// Example
console.log(isPalindrome("A man, a plan, a canal: Panama")); // true
```

### 6. Detect Cycles Fast and Slow, Then Triple the Sum

Move one pointer one link and the other two links. In a finite cycle, their relative offset advances modulo cycle length until they meet; reaching null means no cycle. Compare node identity, not equal values. Use the [linked-list chapter's canonical Floyd implementation and cycle-entry derivation](70.2.1.04-linked-list-manipulation-patterns.md); boolean detection simply asks whether that implementation returns a node.

```typescript
function threeSum(nums: number[]): number[][] {
  nums.sort((a, b) => a - b);
  const result: number[][] = [];

  for (let i = 0; i < nums.length - 2; i++) {
    if (i > 0 && nums[i] === nums[i - 1]) continue; // skip duplicates

    let left = i + 1;
    let right = nums.length - 1;

    while (left < right) {
      const sum = nums[i] + nums[left] + nums[right];

      if (sum === 0) {
        result.push([nums[i], nums[left], nums[right]]);

        while (left < right && nums[left] === nums[left + 1]) left++;
        while (left < right && nums[right] === nums[right - 1]) right--;

        left++;
        right--;
      } else if (sum < 0) {
        left++;
      } else {
        right--;
      }
    }
  }

  return result;
}

// Example
console.log(threeSum([-1, 0, 1, 2, -1, -4]));
// [[-1, -1, 2], [-1, 0, 1]]
```

## Real-World Use Cases

Reach for two pointers for pairs in sorted arrays, comparisons from both ends, cycle detection in linked lists, comparisons of two sequences, and anywhere ordering, monotonicity or a traversal invariant proves candidates can be discarded.

- **Easy**: Valid Palindrome (LeetCode 125); Merge Sorted Array (LeetCode 88); Remove Duplicates from Sorted Array (LeetCode 26).
- **Medium**: Two Sum II - Input Array is Sorted (LeetCode 167); Container With Most Water (LeetCode 11); 3Sum (LeetCode 15); 3Sum Closest (LeetCode 16); 4Sum (LeetCode 18); Shortest Unsorted Continuous Subarray (LeetCode 581); 3Sum Smaller (LeetCode 259).
- **Hard**: Trapping Rain Water (LeetCode 42); Count of Range Sum (LeetCode 327).

## Common Mistakes

1. **Forgetting to check boundaries**: Always verify `left < right` before accessing elements

2. **Not handling duplicates**: In problems requiring unique results, skip duplicate values

3. **Moving the wrong pointer**: In the container problem, move a shorter boundary; when both heights are equal, moving either one is safe.

4. **Off-by-one with indices**: Remember array indexing when returning results

5. **Not considering all cases**: Empty arrays, single element, all same values

## Performance Considerations

| Complexity | Opposite Direction | Same Direction |
| ---------- | ------------------ | ----------------- |
| Time | O(n) for one scan | O(n) for one scan |
| Space | O(1) for the scan | O(1) for the scan |

- **Three Sum:** O(n²) after sorting; include the sort cost and output space, which can grow to O(n²). The traversal itself uses O(1) auxiliary state when sorting the input in place.
- **Space O(1)** describes pointer traversal only. Palindrome normalization allocates an O(n) string; include such allocations when describing the whole function.

The sorted-pair template requires ascending input. Discarding one endpoint eliminates a row or column of candidate pairs; it does not halve the remaining search space on every step.

## Summary

Move a pointer only when ordering or a maintained invariant proves that its discarded candidates cannot be the answer. Sorting can establish the needed order, but include its cost and any lost original indices.

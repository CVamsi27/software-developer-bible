# Binary Search

Suppose you need the smallest shipping capacity that finishes within five days. A larger capacity cannot make the schedule infeasible again — and that monotone boundary is what binary search needs.

```typescript
binarySearch([-1, 0, 3, 5, 9, 12], 9); // 4
```

## Definition

**Binary search** finds a target or a **boundary** in an ordered search space by repeatedly discarding a region that cannot contain the answer. A sorted array is one case; a monotone feasibility **predicate** over possible answers is another.

> **Textbook Definition:** Binary search repeatedly halves an ordered search interval using a monotone predicate, retaining the boundary that can still contain the requested element or transition.

## First Principles

Binary search needs one property: a **monotone predicate**. Any question shaped "find the boundary where P flips from false to true" is searchable — sorted arrays are just the canonical instance, and "minimum capacity to ship in D days" is the same structure with the *answer space* as the search space. The **invariant** is the whole implementation: one convention keeps `lo` where P is false and `hi` where P is true, while the exact-target examples below keep an inclusive interval `[left, right]` containing every remaining candidate. Halve while preserving the chosen invariant — off-by-one bugs are invariant violations, so write the invariant comment first.

## Why It Matters

Binary search appears in several disguises: classic sorted-array search, search-on-answer (parametric search), 2D matrix search, and rotated arrays. Senior interviews test **invariant reasoning** — what property holds true at every step? Strong candidates can derive the `left + (right - left) / 2` formula (rather than a sum that may overflow in fixed-width integer languages), handle **overflow** in typed languages, and know when to use the "exclusive right" vs "inclusive right" boundary convention. The "first bad version" and "find minimum in rotated sorted array" problems are canaries.

## 1. Halve an Ordered Interval While Preserving the Invariant

```text
Sorted Array: [2, 5, 8, 12, 16, 23, 38, 56, 72, 91], Target = 23

Step 1: left=0, right=9, mid=4
        [2, 5, 8, 12, |16|, 23, 38, 56, 72, 91]
                       mid
        16 < 23, so search right half

Step 2: left=5, right=9, mid=7
        [23, 38, |56|, 72, 91]
               mid
        56 > 23, so search left half

Step 3: left=5, right=6, mid=5
        [|23|, 38]
         mid
        23 = 23, found at index 5!
```

The array examples assume finite ordered values. For first occurrence, a matching mid is not enough — retain earlier candidates. For last occurrence, retain later candidates. A false-to-true answer-space predicate needs proven monotonicity plus bounds containing a feasible transition.

## 2. Search a Sorted Array and Its Left and Right Bounds

```typescript
function binarySearch(nums: number[], target: number): number {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) {
      return mid;
    } else if (nums[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return -1;
}

// Example
console.log(binarySearch([-1, 0, 3, 5, 9, 12], 9)); // 4
console.log(binarySearch([-1, 0, 3, 5, 9, 12], 2)); // -1
```

```typescript
function searchLeftBound(nums: number[], target: number): number {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) {
      right = mid - 1; // keep searching left
    } else if (nums[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return left < nums.length && nums[left] === target ? left : -1;
}

// Example
console.log(searchLeftBound([5, 7, 7, 8, 8, 10], 8)); // 3 (first 8)
console.log(searchLeftBound([5, 7, 7, 8, 8, 10], 6)); // -1
```

```typescript
function searchRightBound(nums: number[], target: number): number {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) {
      left = mid + 1; // keep searching right
    } else if (nums[mid] < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return right >= 0 && nums[right] === target ? right : -1;
}

// Example
console.log(searchRightBound([5, 7, 7, 8, 8, 10], 8)); // 4 (last 8)
console.log(searchRightBound([5, 7, 7, 8, 8, 10], 6)); // -1
```

## 3. Search an Answer Space for the First Feasible Value

If integer candidates are ordered and feasibility changes only from false to true, keep a known-feasible upper bound and move it left whenever the midpoint works. For shipping capacity, a candidate is feasible when a left-to-right packing uses at most the allowed number of days. The predicate must be monotone, and each evaluation's cost belongs in the total complexity.

```typescript
function firstFeasibleInteger(
  low: number,
  high: number,
  feasible: (candidate: number) => boolean
): number | null {
  if (!Number.isSafeInteger(low) || !Number.isSafeInteger(high) || !Number.isSafeInteger(high - low) || low > high) {
    throw new RangeError("invalid integer search bounds");
  }
  if (!feasible(high)) return null;

  let left = low;
  let right = high; // known feasible
  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    if (feasible(mid)) right = mid;
    else left = mid + 1;
  }
  return left;
}
```

This returns the smallest feasible integer in the inclusive bounds, or `null` when even `high` fails. It takes O(log(high − low + 1)) predicate calls; a shipping predicate scanning n packages makes the complete search O(n log(high − low + 1)).

## 4. Search Rotated Arrays and Find Their Minimum

Contract: the original sorted array contains distinct values. With duplicates, equal endpoints can hide the sorted side and require linear worst-case narrowing.

```typescript
function searchRotated(nums: number[], target: number): number {
  let left = 0;
  let right = nums.length - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] === target) return mid;

    // Left half is sorted
    if (nums[left] <= nums[mid]) {
      if (target >= nums[left] && target < nums[mid]) {
        right = mid - 1;
      } else {
        left = mid + 1;
      }
    }
    // Right half is sorted
    else {
      if (target > nums[mid] && target <= nums[right]) {
        left = mid + 1;
      } else {
        right = mid - 1;
      }
    }
  }

  return -1;
}

// Example
console.log(searchRotated([4, 5, 6, 7, 0, 1, 2], 0)); // 4
console.log(searchRotated([4, 5, 6, 7, 0, 1, 2], 3)); // -1
```

Contract: nonempty rotation of a strictly ascending array. At each step, the minimum remains in `[left,right]`; if `nums[mid] > nums[right]`, it lies after mid. Otherwise mid may itself be the minimum, so retain it with `right = mid`. Duplicates need an additional equality case and can cause linear worst-case work.

```typescript
function findMin(nums: number[]): number {
  if (nums.length === 0) throw new RangeError("nonempty input required");
  let left = 0;
  let right = nums.length - 1;

  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);

    if (nums[mid] > nums[right]) {
      left = mid + 1;
    } else {
      right = mid;
    }
  }

  return nums[left];
}

// Example
console.log(findMin([3, 4, 5, 1, 2])); // 1
console.log(findMin([4, 5, 6, 7, 0, 1, 2])); // 0
```

## 5. Search a 2D Matrix

Contract: the matrix is rectangular and its row-major flattened order is sorted; sorting each row and column independently is insufficient for this implementation.

```typescript
function searchMatrix(matrix: number[][], target: number): boolean {
  if (matrix.length === 0) return false;

  const m = matrix.length;
  const n = matrix[0].length;
  let left = 0;
  let right = m * n - 1;

  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2);
    const midValue = matrix[Math.floor(mid / n)][mid % n];

    if (midValue === target) {
      return true;
    } else if (midValue < target) {
      left = mid + 1;
    } else {
      right = mid - 1;
    }
  }

  return false;
}

// Example
const matrix = [
  [1, 3, 5, 7],
  [10, 11, 16, 20],
  [23, 30, 34, 60]
];
console.log(searchMatrix(matrix, 3)); // true
console.log(searchMatrix(matrix, 13)); // false
```

## Real-World Use Cases

Reach for binary search in sorted arrays, boundary conditions (first/last occurrence), sorted or monotonic functions, minimum or maximum values satisfying a condition, and search spaces where an answer can be guessed and verified.

- **Easy**: Binary Search (LeetCode 704); First Bad Version (LeetCode 278); Valid Perfect Square (LeetCode 367).
- **Medium**: Search in Rotated Sorted Array (LeetCode 33); Find First and Last Position of Element in Sorted Array (LeetCode 34); Search in Rotated Sorted Array II (LeetCode 81); Find Minimum in Rotated Sorted Array (LeetCode 153); Capacity To Ship Packages Within D Days (LeetCode 1011); Koko Eating Bananas (LeetCode 875); Search a 2D Matrix (LeetCode 74).
- **Hard**: Median of Two Sorted Arrays (LeetCode 4); Find in Mountain Array (LeetCode 1095); Split Array Largest Sum (LeetCode 410); Aggressive Cows (SPOJ).

## Common Mistakes

1. **Infinite loops**: Always ensure `left` and `right` move toward each other

2. **Off-by-one with mid**: Round the midpoint to an integer with `left + Math.floor((right - left) / 2)`

3. **Wrong boundary**: `left <= right` vs `left < right` depends on the problem

4. **Not handling duplicates**: When duplicates exist, you may need to handle them explicitly

5. **Integer overflow**: Use a difference-based midpoint with integer division in fixed-width languages; ordinary JavaScript array indices fit exactly in Number

## Performance Considerations

| Complexity | Standard | Left/Right Bound | Rotated Array with Distinct Values |
| ---------- | -------- | ---------------- | ------------------------------------- |
| Time | O(log n) | O(log n) | O(log n); duplicates can require O(n) |
| Space | O(1) | O(1) | O(1) |

- **Time O(log n)**: Each iteration halves the search space
- **Space O(1)**: Only using a few pointers

## Summary

State the ordered space, the predicate or comparison, and the interval invariant first. Correctly discarding half the candidates gives logarithmic iterations; total runtime also includes each predicate evaluation. Distinct rotated arrays and globally ordered matrices require their specific ordering contracts.

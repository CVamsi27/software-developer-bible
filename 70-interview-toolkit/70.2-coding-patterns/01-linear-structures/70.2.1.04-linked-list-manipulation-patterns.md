# Linked List Manipulation Patterns

When reversing `2 → 3 → 4`, changing `2.next` before saving it loses the rest of the list. Pointer order is the difference between a safe rewrite and a disconnected chain.

```typescript
while (curr !== null) {
  const next = curr.next;   // 1. save forward link
  curr.next = prev;         // 2. flip arrow
  prev = curr;              // 3. advance prev
  curr = next;              // 4. advance curr
}
return prev;                // new head (old tail)
```

## Definition

A **singly linked list** is a sequence of nodes, each storing a value and a `next` reference to its successor, with null marking the end. **Manipulation** changes those references while keeping the intended nodes reachable — iterative reversal, range reversal and reordering, without copying values into an array.

> **Textbook Definition:** Linked-list manipulation changes successor relationships between nodes while preserving reachability and the intended sequence. Dummy nodes and coordinated pointers simplify boundary handling without copying elements.

## First Principles

Linked-list algorithms replace indexed access with disciplined traversal and link changes. **Fast and slow pointers** advancing at different rates find a middle with a 2:1 ratio; in a cycle, fast gains one link per iteration until both meet, and resetting one pointer to the head then advancing both one link at a time reaches the cycle entry. **Reversal** grows a reversed prefix in place — recursion rewire similarly but costs stack space (see [backtracking and recursion](../03-recursion-and-optimization/70.2.3.01-backtracking.md). A **dummy node** gives the original head a predecessor, so head-changing operations use the same rewiring path as other nodes.

## Why It Matters

Linked-list questions test whether you preserve reachability while mutating references. Explain where each pointer is before changing links, then trace empty, single-node and boundary cases. State whether the operation mutates the input and whether the caller expects restoration. The acyclic-list operations assume a finite, acyclic list, and interleaving additionally requires disjoint inputs — shared nodes can create cycles when rewired.

## How It Works

### 1. Reverse With the Save-Flip-Advance Primitive

```typescript
class ListNode {
  val: number;
  next: ListNode | null;
  constructor(val = 0, next: ListNode | null = null) {
    this.val = val;
    this.next = next;
  }
}

// Primitive: full iterative reversal — THE pattern to memorize
function reverseList(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null;
  let curr = head;

  while (curr !== null) {
    const next = curr.next;   // 1. save forward link
    curr.next = prev;         // 2. flip arrow
    prev = curr;              // 3. advance prev
    curr = next;              // 4. advance curr
  }
  return prev;                // new head (old tail)
}
```

Trace `[1] → [2] → [3]`: save next `[2]`, flip `[1].next` to null; then flip `[2].next` to `[1]`; then flip `[3].next` to `[2]`; `curr` reaches null and `prev` (`[3]`) is the new head. Rewiring `curr.next` before saving it orphans the remainder — capture forward links first, always.

### 2. Kill Edge Cases With a Dummy and Land Fast/Slow Deliberately

Without a dummy, a null head and first-node handling need special cases and the return value varies. With `dummy.next = head`, every node has a predecessor: deletion is `prev.next = prev.next.next`, and the answer is always `dummy.next`. Operations always start from the dummy and never worry about the first node being special.

Where `slow` lands depends on the loop condition and list parity — never assume, draw lengths 4 and 5 first:

```text
Loop condition                         slow on [1,2,3,4]   slow on [1,2,3,4,5]
fast != null && fast.next != null       node 3              node 3
fast.next != null && fast.next.next     node 2              node 3
```

For splitting before reversal, the second form keeps `slow` at the first half's tail. Cut `slow.next` before merging the two halves.

### 3. Reverse Between Positions m..n

```typescript
function reverseBetween(
  head: ListNode | null, left: number, right: number
): ListNode | null {
  if (!Number.isInteger(left) || !Number.isInteger(right) || left < 1 || right < left) throw new RangeError("invalid positions");
  let check = head;
  for (let position = 1; position <= right; position++) {
    if (check === null) throw new RangeError("position exceeds list length");
    check = check.next;
  }
  const dummy = new ListNode(0, head);

  // step 1: node BEFORE the reversal window
  let before: ListNode = dummy;
  for (let i = 1; i < left; i++) before = before.next!;

  // step 2: standard in-place reversal inside the window
  let prev = before.next!;
  let curr = prev.next;
  for (let i = 0; i < right - left; i++) {
    const next = curr!.next;
    curr!.next = prev;
    prev = curr!;
    curr = next;
  }

  // step 3: reconnect window's old head to the tail remainder
  before.next!.next = curr;      // old window head → after-window
  before.next = prev;            // before-window → new window head

  return dummy.next;
}

// 1→2→3→4→5, left=2, right=4 ⇒ 1→4→3→2→5
const l = new ListNode(1, new ListNode(2,
  new ListNode(3, new ListNode(4, new ListNode(5)))));
console.log(JSON.stringify(reverseBetween(l, 2, 4))); // {"val":1,...} 1-4-3-2-5
```

The first node of the window becomes its last node — keep a reference to it for rewiring the remainder afterward. The dummy handles `left === 1`.

### 4. Reorder by Middle-Find, Reverse and Zip-Merge

```typescript
function reorderList(head: ListNode | null): void {
  if (!head || !head.next) return;

  // phase 1: find middle (slow ends at end of first half)
  let slow: ListNode = head;
  let fast: ListNode = head;
  while (fast.next !== null && fast.next.next !== null) {
    slow = slow.next!;
    fast = fast.next.next;
  }

  // phase 2: cut + reverse second half
  const second = reverseList(slow.next);
  slow.next = null;

  // phase 3: merge two halves, alternating
  let p1: ListNode | null = head;
  let p2: ListNode | null = second;
  while (p2 !== null) {
    const n1: ListNode | null = p1!.next;
    const n2: ListNode | null = p2.next;
    p1!.next = p2;
    p2.next = n1;
    p1 = n1;
    p2 = n2;
  }
}

// reverseList is the primitive defined above.

// 1→2→3→4→5 ⇒ 1→5→2→4→3
```

Three primitives compose: middle-find (the `fast.next?.next` condition keeps slow on the left half's tail, safe to cut), reverse, zip-merge.

### 5. Interleave Two Lists and Check Palindromes in Place

```typescript
function interleave(a: ListNode | null, b: ListNode | null): ListNode | null {
  if (!a) return b;
  if (!b) return a;

  const head = a;
  let currA: ListNode | null = a;
  let currB: ListNode | null = b;

  while (currA !== null && currB !== null) {
    const aNext: ListNode | null = currA.next;
    const bNext: ListNode | null = currB.next;

    if (aNext === null) {
      // last A node: attach the ENTIRE remaining B tail, stop
      currA.next = currB;
      break;
    }

    currA.next = currB;   // A node → B node
    currB.next = aNext;   // B node → next A node
    currA = aNext;
    currB = bNext;
  }
  return head;
}

// 1→2→3 + A→B ⇒ 1→A→2→B→3
// 1→2   + A→B→C ⇒ 1→A→2→B→C  (leftover tail preserved)
```

Save both successors *before* rewiring — losing either reference corrupts the list. Check for list exhaustion before splicing so leftovers stay attached.

```typescript
function isPalindrome(head: ListNode | null): boolean {
  if (!head || !head.next) return true;

  // find first-half tail; its next starts the second half
  let slow: ListNode = head;
  let fast: ListNode = head;
  while (fast.next !== null && fast.next.next !== null) {
    slow = slow.next!;
    fast = fast.next.next;
  }

  // reverse second half
  const reversedHead = reverseList(slow.next);
  let second: ListNode | null = reversedHead;
  let first: ListNode | null = head;

  // compare halves
  let ok = true;
  while (second !== null) {
    if (first!.val !== second.val) ok = false;
    first = first!.next;
    second = second.next;
  }
  slow.next = reverseList(reversedHead); // restore the original links
  return ok;
}

console.log(isPalindrome(
  new ListNode(1, new ListNode(2, new ListNode(2, new ListNode(1))))
)); // true
```

### 6. Remove the Nth Node From the End and Find Cycle Entry

```typescript
function removeNthFromEnd(
  head: ListNode | null, n: number
): ListNode | null {
  if (!Number.isInteger(n) || n < 1) throw new RangeError("invalid n");
  const dummy = new ListNode(0, head);
  let first: ListNode | null = dummy;
  let second: ListNode = dummy;

  // advance first n+1 steps → gap of n nodes
  for (let i = 0; i <= n; i++) {
    if (first === null) throw new RangeError("n exceeds list length");
    first = first.next;
  }

  // move together until first falls off; second sits on node BEFORE target
  while (first !== null) {
    first = first.next;
    second = second.next!;
  }

  second.next = second.next!.next;  // unlink target
  return dummy.next;                // dummy handles removing the real head
}
```

```typescript
function detectCycle(head: ListNode | null): ListNode | null {
  let slow: ListNode | null = head;
  let fast: ListNode | null = head;

  while (fast !== null && fast.next !== null) {
    slow = slow!.next;
    fast = fast.next.next;
    if (slow === fast) {                      // meeting point exists
      let p: ListNode | null = head;
      while (p !== slow) {                    // equidistant proof:
        p = p!.next;                          // head-to-entry distance
        slow = slow!.next;                    // == meet-to-entry distance
      }
      return p;                               // cycle entry
    }
  }
  return null;
}
```

At a meeting, slow has traveled `s` steps and fast `2s`, so their distance difference `s` is a multiple of cycle length `C`. If the entry is `d` steps from the head, the meeting offset is `(s - d) mod C`, equivalent to `-d mod C`. Advancing one pointer from the head and one from the meeting point by `d` steps therefore brings both to the entry — at equal speed, not another fast/slow phase.

## Real-World Use Cases

Reach for these patterns for sublist and range reversal, reordering and interleaving halves, one-pass middle-finding and cycle detection, O(1)-space palindrome checks via half-reversal, and anywhere recursion depth is a concern.

- **Easy**: Reverse Linked List (LeetCode 206) — the primitive; Merge Two Sorted Lists (LeetCode 21) — dummy node practice; Palindrome Linked List (LeetCode 234) — middle-find + reverse combo; Remove Duplicates from Sorted List (LeetCode 83) — simple rewiring.
- **Medium**: Reverse Linked List II (LeetCode 92) — windowed reversal; Reorder List (LeetCode 143) — three-primitive composition; Remove Nth Node From End of List (LeetCode 19) — gap pointers + dummy; Linked List Cycle II (LeetCode 142) — Floyd entry math; Swap Nodes in Pairs (LeetCode 24) — pairwise surgery with dummy; Rotate List (LeetCode 61) — close-the-loop trick, count length first; Copy List with Random Pointer (LeetCode 138) — interleave-with-clones surgery; Sort List (LeetCode 148) — merge sort adapted: middle-find + merge.
- **Hard**: Reverse Nodes in k-Group (LeetCode 25) — repeated windowed reversal + group counting.

## Common Mistakes

1. **Losing the rest of the list**: rewiring `curr.next` before saving `const next = curr.next`. Always capture forward links first.

2. **Skipping the dummy node**: hand-rolled `if (node === head)` branches multiply edge cases. One dummy line replaces them.

3. **Off-by-one on fast/slow landing position**: `while (fast && fast.next)` vs `while (fast.next && fast.next.next)` land slow differently on odd/even lists. Draw lists of length 4 and 5 before choosing.

4. **Forgetting to terminate the reversed section**: after reversing a window, the old window head must point to `null` or the remainder — dangling `next` pointers create accidental cycles that hang tests.

5. **Mutating input when the interviewer wants it preserved**: confirm upfront; palindrome problems often expect restoration (reverse the half back).

6. **Recursion for long lists**: recursive reversal is elegant but O(n) call-stack depth can exceed the runtime’s stack limit. Default to iteration unless asked for recursion explicitly.

7. **Comparing nodes instead of values** in palindrome checks (`first !== second` vs `.val` comparison).

## Performance Considerations

| Operation | Time | Space |
| --------------------------- | ----------------------------- | ----- |
| Full reversal | O(n) | O(1) |
| Reverse m..n window | O(n) traversal + O(n-m) flips | O(1) |
| Find middle (fast/slow) | O(n/2) → O(n) | O(1) |
| Reorder list | O(n) | O(1) |

| Operation | Time | Space |
| --------------------------- | ----------------------------- | ----- |
| Palindrome check (in-place) | O(n) | O(1) |
| Cycle detection (Floyd) | O(n) | O(1) |
| Remove nth from end | O(n) single pass | O(1) |

The implemented operations are linear in the traversed list and use constant auxiliary space. This does not describe every linked-list problem: sorting and cloning have their own bounds.

## Summary

Preserve the forward link before rewiring a node. Use a dummy predecessor when the head can change, and choose the fast/slow condition from where the split must land. Reversal, splitting and interleaving compose the implemented linear-time, constant-auxiliary-space operations. State acyclic/disjoint-input and restoration requirements explicitly.

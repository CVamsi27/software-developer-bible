# Linked List Manipulation Patterns

## TL;DR

Almost every linked-list manipulation reduces to three primitives:

1. **Reverse** — walk with `prev/curr` pointers, flip each arrow.
2. **Dummy head** — a fake node in front eliminates all "is this the first node?" special cases.
3. **Fast/slow pointers** — find middles (slow stops at mid) and detect cycles (fast laps slow).

Compose them and you get reverse-between-positions, reorder list, interleave, k-group reversal, and palindrome checks. The interview skill is drawing pointer states before writing code.

## First Principles

Linked-list patterns compensate for O(1)-index absence with *position discipline*:

1. **Fast/slow pointers turn position into physics**: speed ratio 2:1 finds middles and cycle starts (Floyd) — the math is invariant, not cleverness.
2. **Reversal is pointer rewiring in-place**: the iteratively-built reversed prefix is the accumulator; recursion does the same implicitly with stack space (→ 70.2.3.01's cost). Dummy-head nodes eliminate the empty-list special case — the general lesson: manufacture uniformity to kill edge cases.

## Definition

A family of **in-place pointer-surgery techniques** for singly linked lists: iterative reversal by rewiring `next` pointers, reversal of a sublist between positions, and reordering via the three-step decomposition (find middle with fast/slow pointers → reverse half → merge halves). No extra arrays, O(1) space.

## Why it matters

Linked-list questions are less about algorithms and more about **pointer hygiene under pressure** — interviewers watch whether you lose track of `next` references. They also test your ability to reason about in-place mutation without auxiliary structures. The senior signal: using a dummy node unprompted, walking through edge cases aloud (empty list, single node, m=1/n=end), and stating complexity without hesitation because everything here is O(n) time / O(1) space.

## When to Use

- "Reverse a linked list" or any sublist/range variant
- "Reorder" / "interleave" / "zip" two halves of one list
- Cycle detection or finding the middle in one pass
- Palindrome check with O(1) space (reverse second half)
- Any problem where recursion depth is a concern (iterative beats recursive on 10^5-node lists)

## Template

```typescript
class ListNode {
  val: number;
  next: ListNode | null;
  constructor(val = 0, next: ListNode | null = null) {
    this.val = val;
    this.next = next;
  }
}

// Primitive: full iterative reversal — THE pattern to memorize
function reverseList(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null;
  let curr = head;

  while (curr !== null) {
    const next = curr.next;   // 1. save forward link
    curr.next = prev;         // 2. flip arrow
    prev = curr;              // 3. advance prev
    curr = next;              // 4. advance curr
  }
  return prev;                // new head (old tail)
}
```

## How It Works

### Reversal as pointer surgery

```text
prev    curr    next
null ← [1]     [2] → [3]          save next = [2]
       flip: [1].next = null


       prev   curr
null ← [1]    [2] → [3]           flip: [2].next = [1]

             prev   curr
null ← [1] ← [2]    [3]           flip: [3].next = [2]

                    prev   curr=null → stop
null ← [1] ← [2] ← [3]
return prev = [3]  (new head)
```

### Dummy node kills edge cases

```text
WITHOUT dummy:                     WITH dummy:
head may be null                   dummy.next = head
first node needs special case      every node has a predecessor
deletion needs parent tracking     deletion: prev.next = prev.next.next
return value varies                always return dummy.next

[dm] → [n0] → [n1] → [n2]
  ↑ operations always start from dm,
    never worry about n0 being first
```

### Fast/slow pointer invariants

```text
Even length:  [1]→[2]→[3]→[4]→null
              s        f         slow ends at 2 (left-mid)

Odd length:   [1]→[2]→[3]→null
                 s     f→null    slow ends at 3? no:
              start both at head; loop while fast && fast.next
              → slow lands on middle [2]... verify per variant!

Cycle:        fast moves 2, slow moves 1
              gap shrinks by 1 each step → they MUST meet
              (no modular wraparound escape in finite list)
```

The subtle part: where exactly `slow` lands depends on the loop condition (`fast.next !== null` vs `fast !== null`) and list parity. Never assume — draw it for lengths 4 and 5 before coding.

## Code Examples (TypeScript)

### Problem 1: Reverse Linked List II (LeetCode 92) — reverse between positions m..n

```typescript
function reverseBetween(
  head: ListNode | null, left: number, right: number
): ListNode | null {
  const dummy = new ListNode(0, head);

  // step 1: node BEFORE the reversal window
  let before: ListNode = dummy;
  for (let i = 1; i < left; i++) before = before.next!;

  // step 2: standard in-place reversal inside the window
  let prev = before.next!;
  let curr = prev.next;
  for (let i = 0; i < right - left; i++) {
    const next = curr!.next;
    curr!.next = prev;
    prev = curr!;
    curr = next;
  }

  // step 3: reconnect window's old head to the tail remainder
  before.next!.next = curr;      // old window head → after-window
  before.next = prev;            // before-window → new window head

  return dummy.next;
}

// 1→2→3→4→5, left=2, right=4 ⇒ 1→4→3→2→5
const l = new ListNode(1, new ListNode(2,
  new ListNode(3, new ListNode(4, new ListNode(5)))));
console.log(JSON.stringify(reverseBetween(l, 2, 4))); // {"val":1,...} 1-4-3-2-5
```

Key insight: the first node of the window becomes its last node — keep a reference to it so you can wire the remainder afterward. The dummy handles `left === 1`.

### Problem 2: Reorder List (LeetCode 143) — L0→Ln→L1→Ln-1…

```typescript
function reorderList(head: ListNode | null): void {
  if (!head || !head.next) return;

  // phase 1: find middle (slow ends at end of first half)
  let slow: ListNode = head;
  let fast: ListNode = head;
  while (fast.next !== null && fast.next.next !== null) {
    slow = slow.next!;
    fast = fast.next.next;
  }

  // phase 2: cut + reverse second half
  const second = reverseList(slow.next);
  slow.next = null;

  // phase 3: merge two halves, alternating
  let p1: ListNode | null = head;
  let p2: ListNode | null = second;
  while (p2 !== null) {
    const n1 = p1!.next;
    const n2 = p2.next;
    p1!.next = p2;
    p2.next = n1;
    p1 = n1;
    p2 = n2;
  }
}

// helper from Template section
function reverseList(head: ListNode | null): ListNode | null {
  let prev: ListNode | null = null;
  let curr = head;
  while (curr !== null) {
    const next = curr.next;
    curr.next = prev;
    prev = curr;
    curr = next;
  }
  return prev;
}

// 1→2→3→4→5 ⇒ 1→5→2→4→3
```

Three primitives compose: middle-find (`fast.next?.next` condition keeps slow on the LEFT half's tail — safe to cut), reverse, zip-merge.

### Problem 3: Interleaving Two Lists (variant of merge, O(1) space)

```typescript
function interleave(a: ListNode | null, b: ListNode | null): ListNode | null {
  if (!a) return b;
  if (!b) return a;

  const head = a;
  let currA: ListNode | null = a;
  let currB: ListNode | null = b;

  while (currA !== null && currB !== null) {
    const aNext = currA.next;
    const bNext = currB.next;

    if (aNext === null) {
      // last A node: attach the ENTIRE remaining B tail, stop
      currA.next = currB;
      break;
    }

    currA.next = currB;   // A node → B node
    currB.next = aNext;   // B node → next A node
    currA = aNext;
    currB = bNext;
  }
  return head;
}

// 1→2→3 + A→B ⇒ 1→A→2→B→3
// 1→2   + A→B→C ⇒ 1→A→2→B→C  (leftover tail preserved)
```

Pattern: save both successors BEFORE rewiring — losing either reference corrupts the list. Check for list exhaustion before splicing so leftovers stay attached.

### Problem 4: Palindrome Linked List (LeetCode 234) — O(1) space

```typescript
function isPalindrome(head: ListNode | null): boolean {
  if (!head || !head.next) return true;

  // find middle (slow = start of second half)
  let slow: ListNode = head;
  let fast: ListNode = head;
  while (fast.next !== null && fast.next.next !== null) {
    slow = slow.next!;
    fast = fast.next.next;
  }

  // reverse second half
  let second: ListNode | null = reverseList(slow.next);
  let first: ListNode | null = head;

  // compare halves
  let ok = true;
  while (second !== null) {
    if (first!.val !== second.val) ok = false;
    first = first!.next;
    second = second.next;
  }
  // (optional: restore list by reversing second half again)
  return ok;
}

console.log(isPalindrome(
  new ListNode(1, new ListNode(2, new ListNode(2, new ListNode(1))))
)); // true
```

### Problem 5: Remove Nth Node From End (LeetCode 19) — two-pointer gap trick

```typescript
function removeNthFromEnd(
  head: ListNode | null, n: number
): ListNode | null {
  const dummy = new ListNode(0, head);
  let first: ListNode | null = dummy;
  let second: ListNode = dummy;

  // advance first n+1 steps → gap of n nodes
  for (let i = 0; i <= n; i++) first = first!.next;

  // move together until first falls off; second sits on node BEFORE target
  while (first !== null) {
    first = first.next;
    second = second.next!;
  }

  second.next = second.next!.next;  // unlink target
  return dummy.next;                // dummy handles removing the real head
}
```

### Problem 6: Linked List Cycle II (LeetCode 142) — find cycle entry

```typescript
function detectCycle(head: ListNode | null): ListNode | null {
  let slow: ListNode | null = head;
  let fast: ListNode | null = head;

  while (fast !== null && fast.next !== null) {
    slow = slow!.next;
    fast = fast.next.next;
    if (slow === fast) {                      // meeting point exists
      let p: ListNode | null = head;
      while (p !== slow) {                    // equidistant proof:
        p = p!.next;                          // head-to-entry distance
        slow = slow!.next;                    // == meet-to-entry distance
      }
      return p;                               // cycle entry
    }
  }
  return null;
}
```

The math (worth reciting): if slow traveled `s` steps and fast `2s`, and entry is `d` from head with cycle length `C`, they meet `d` steps into the cycle when `s ≡ 0 mod C` relationships hold — hence walking from head and from meet-point at equal speed collides exactly at entry.

## Common Mistakes

1. **Losing the rest of the list**: rewiring `curr.next` before saving `const next = curr.next`. Always capture forward links first.

2. **Skipping the dummy node**: hand-rolled `if (node === head)` branches multiply edge cases. One dummy line replaces them.

3. **Off-by-one on fast/slow landing position**: `while (fast && fast.next)` vs `while (fast.next && fast.next.next)` land slow differently on odd/even lists. Draw lists of length 4 and 5 before choosing.

4. **Forgetting to terminate the reversed section**: after reversing a window, the old window head must point to `null` or the remainder — dangling `next` pointers create accidental cycles that hang tests.

5. **Mutating input when the interviewer wants it preserved**: confirm upfront; palindrome problems often expect restoration (reverse the half back).

6. **Recursion for long lists**: recursive reversal is elegant but O(n) call-stack depth blows up around 10^4+ nodes. Default to iteration unless asked for recursion explicitly.

7. **Comparing nodes instead of values** in palindrome checks (`first !== second` vs `.val` comparison).

## Time/Space Complexity

| Operation | Time | Space |
| --------------------------- | ----------------------------- | ----- |
| Full reversal | O(n) | O(1) |
| Reverse m..n window | O(n) traversal + O(n-m) flips | O(1) |
| Find middle (fast/slow) | O(n/2) → O(n) | O(1) |
| Reorder list | O(n) | O(1) |
| Palindrome check (in-place) | O(n) | O(1) |
| Cycle detection (Floyd) | O(n) | O(1) |
| Remove nth from end | O(n) single pass | O(1) |

Everything in this chapter is linear time, constant extra space — say that sentence early; it frames the whole solution.

## Summary

Linked-list manipulation is pointer discipline, not algorithmics: master full reversal (save-flip-advance), reach for a dummy node whenever the head can change, use fast/slow for middles and cycles, and decompose complex reorders into find-middle → reverse-half → merge. Every technique is O(n)/O(1). Draw pointer states for lists of length ≤ 5 before coding, capture forward links before flipping them, and state the invariant you're maintaining as you go.

## Cheat Sheet

```text
LINKED LIST MANIPULATION — CHEAT SHEET
═════════════════════════════════════

FULL REVERSAL (memorize cold):
  let prev=null, curr=head
  while curr:
    const next = curr.next   ← SAVE FIRST
    curr.next = prev         ← FLIP
    prev = curr; curr = next ← ADVANCE
  return prev

DUMMY NODE:
  const dummy = new ListNode(0, head)
  ...operate...
  return dummy.next
  → kills "what if head changes" branches

FAST/SLOW LANDINGS:
  while fast && fast.next        → slow = ceil-mid
  while fast.next && fast.next.next
                                 → slow = left-half tail
                                   (safe to CUT before reverse)
  cycle: fast laps slow; entry found by
  advancing head & meet-point together

REVERSE WINDOW m..n:
  1. walk to node BEFORE m (use dummy)
  2. reverse n-m arrows
  3. old-window-head.next = remainder
     before.next = new head

REORDER LIST:
  mid(find, cut-safe) → reverse(second)
  → alternate-merge halves

REMOVE NTH FROM END:
  gap pointers: first walks n+1 first,
  then both walk; second.next skips target

TRAPS:
• save next BEFORE flipping
• terminate reversed section (avoid cycles)
• draw lengths 4 & 5 before picking loop cond.
• prefer iteration over recursion (stack depth)

EVERYTHING HERE: O(n) time · O(1) space
```

# Intervals

Two meetings `[1, 2)` and `[2, 3)` can use the same room, while closed ranges `[1, 2]` and `[2, 3]` share an endpoint. The endpoint convention changes the comparison — state it before merging or scheduling.

```typescript
merge([[1,3],[2,6],[8,10],[15,18]]); // [[1,6],[8,10],[15,18]]
```

## Definition

**Interval problems** work with ranges defined by **start and end** points: merging overlapping intervals, inserting new intervals, checking overlaps, and scheduling non-overlapping sets. Every operation depends on the defined **endpoint inclusion** and the required overlap relation.

> **Textbook Definition:** An interval represents a contiguous range with defined endpoint inclusion. Interval algorithms compare, merge or schedule ranges according to those endpoint rules and the required overlap relation.

## First Principles

Interval problems reduce to **event ordering**. Choose the ordering from the invariant: for merging, start order makes the next overlap a local comparison with the current maximum end; for scheduling, finish order supports an exchange argument. The objective determines the sort. The endpoints +1/−1 trick is the sweep formalized: a room becomes busy at start and free at end, and sorting events makes the running count the answer. For half-open meeting times, process ends before starts at a tie; for closed intervals, a shared endpoint counts as overlap.

## Why It Matters

Interval problems test whether you think in sorting-plus-sweep rather than nested loops. The senior-level question is when to sort by **start** (merge intervals) vs **end** (activity selection, meeting rooms) — the choice changes the algorithm. Discuss edge cases explicitly: empty input, single interval, touching intervals (`[1,2]` and `[2,3]` — overlap or not, depending on the problem), and off-by-one boundaries. In production: calendar scheduling, time-series compression, and resource allocation.

## How It Works

### 1. Sort by the Objective, Then Sweep Once

```text
Intervals: [[1,3], [2,6], [8,10], [15,18]]

Sort by start: [[1,3], [2,6], [8,10], [15,18]]

Step 1: current = [1,3]
        [2,6] overlaps (2 <= 3), merge to [1,6]

Step 2: current = [1,6]
        [8,10] doesn't overlap (8 > 6), add [1,6]

Step 3: current = [8,10]
        [15,18] doesn't overlap (15 > 10), add [8,10]

Step 4: Add [15,18]

Result: [[1,6], [8,10], [15,18]]
```

The same endpoints answer different questions. Closed ranges `[1,2]` and `[2,3]` merge; half-open calendar meetings `[1,2)` and `[2,3)` can reuse one room. State the convention before choosing `<` or `<=`. Assume each interval has two finite endpoints with start ≤ end. Merge, insert and balloon ranges are closed; meeting-room and non-overlap scheduling use half-open ranges with positive duration.

### 2. Merge Intervals and Insert Into a Sorted List

```typescript
function merge(intervals: number[][]): number[][] {
  if (intervals.length <= 1) return intervals.map(interval => [...interval]);

  intervals.sort((a, b) => a[0] - b[0]);
  const merged: number[][] = [];
  let current = [...intervals[0]];

  for (let i = 1; i < intervals.length; i++) {
    if (intervals[i][0] <= current[1]) {
      current[1] = Math.max(current[1], intervals[i][1]);
    } else {
      merged.push(current);
      current = [...intervals[i]];
    }
  }

  merged.push(current);
  return merged;
}

// Example
console.log(merge([[1,3],[2,6],[8,10],[15,18]]));
// [[1,6],[8,10],[15,18]]
console.log(merge([[1,4],[4,5]]));
// [[1,5]]
```

Contract: the insert input is already sorted by start and non-overlapping. This version mutates `newInterval`; clone it first when caller-owned data must remain unchanged.

```typescript
function insert(intervals: number[][], newInterval: number[]): number[][] {
  const result: number[][] = [];
  let i = 0;

  while (i < intervals.length && intervals[i][1] < newInterval[0]) {
    result.push(intervals[i]);
    i++;
  }

  while (i < intervals.length && intervals[i][0] <= newInterval[1]) {
    newInterval[0] = Math.min(newInterval[0], intervals[i][0]);
    newInterval[1] = Math.max(newInterval[1], intervals[i][1]);
    i++;
  }

  result.push(newInterval);

  while (i < intervals.length) {
    result.push(intervals[i]);
    i++;
  }

  return result;
}

// Example
console.log(insert([[1,3],[6,9]], [2,5]));
// [[1,5],[6,9]]
console.log(insert([[1,2],[3,5],[6,7],[8,10],[12,16]], [4,8]));
// [[1,2],[3,10],[12,16]]
```

### 3. Count Rooms With Endpoint Events

```typescript
// Contract: every meeting has start < end; times are half-open [start, end).
function minMeetingRooms(intervals: number[][]): number {
  const starts = intervals.map(([start]) => start).sort((a, b) => a - b);
  const ends = intervals.map(([, end]) => end).sort((a, b) => a - b);
  let endIndex = 0, active = 0, maximum = 0;
  for (const start of starts) {
    while (endIndex < ends.length && ends[endIndex] <= start) {
      active--;
      endIndex++;
    }
    active++;
    maximum = Math.max(maximum, active);
  }
  return maximum;
}

// Example
console.log(minMeetingRooms([[0,30],[5,10],[15,20]])); // 2
console.log(minMeetingRooms([[7,10],[2,4]])); // 1
```

The two sorted endpoint arrays give `O(n log n)` time and `O(n)` space. Repeatedly sorting an array after every insertion is not a heap and can take quadratic work.

### 4. Select the Largest Compatible Set Greedily

Choose the earliest-finishing compatible interval: replacing a chosen later-ending interval with it cannot reduce the room left for future intervals. That exchange argument justifies sorting by end here, while merging sorts by start. Contract: intervals are half-open, so an interval starting when the previous one ends is compatible.

```typescript
function eraseOverlapIntervals(intervals: number[][]): number {
  if (intervals.length === 0) return 0;

  intervals.sort((a, b) => a[1] - b[1]);
  let count = 0;
  let end = intervals[0][1];

  for (let i = 1; i < intervals.length; i++) {
    if (intervals[i][0] < end) {
      count++; // overlapping, remove this interval
    } else {
      end = intervals[i][1]; // no overlap, update end
    }
  }

  return count;
}

// Example
console.log(eraseOverlapIntervals([[1,2],[2,3],[3,4],[1,3]])); // 1
console.log(eraseOverlapIntervals([[1,2],[1,2],[1,2]])); // 2
```

```typescript
function findMinArrowShots(points: number[][]): number {
  if (points.length === 0) return 0;

  points.sort((a, b) => a[1] - b[1]);
  let arrows = 1;
  let end = points[0][1];

  for (let i = 1; i < points.length; i++) {
    if (points[i][0] > end) {
      arrows++;
      end = points[i][1];
    }
  }

  return arrows;
}

// Example
console.log(findMinArrowShots([[10,16],[2,8],[1,6],[7,12]])); // 2
console.log(findMinArrowShots([[1,2],[3,4],[5,6],[7,8]])); // 4
```

### 5. Collect Free Time From Merged Busy Ranges

Return only finite positive gaps between the union of busy intervals. This does not return the unbounded time before the first or after the last busy range, nor apply an office-hours boundary — supply such a boundary if the product requires it.

```typescript
function employeeFreeTime(schedule: number[][][]): number[][] {
  const allIntervals: number[][] = [];

  for (const employee of schedule) {
    for (const interval of employee) {
      allIntervals.push(interval);
    }
  }

  allIntervals.sort((a, b) => a[0] - b[0]);

  if (allIntervals.length === 0) return [];
  const merged: number[][] = [[...allIntervals[0]]];
  for (let i = 1; i < allIntervals.length; i++) {
    if (allIntervals[i][0] <= merged[merged.length - 1][1]) {
      merged[merged.length - 1][1] = Math.max(
        merged[merged.length - 1][1],
        allIntervals[i][1]
      );
    } else {
      merged.push([...allIntervals[i]]);
    }
  }

  const freeTime: number[][] = [];
  for (let i = 1; i < merged.length; i++) {
    freeTime.push([merged[i - 1][1], merged[i][0]]);
  }

  return freeTime;
}

// Example
const schedule = [
  [[1,2],[5,6]],
  [[1,3]],
  [[4,10]]
];
console.log(employeeFreeTime(schedule));
// [[3,4]]
```

## Real-World Use Cases

Reach for intervals for merging overlapping ranges, inserting into sorted lists, overlap checks, minimum removals for non-overlap, meeting-room allocation, and any time-range or number-line problem.

- **Easy**: Merge Sorted Array (LeetCode 88); Meeting Rooms (LeetCode 252).
- **Medium**: Merge Intervals (LeetCode 56); Insert Interval (LeetCode 57); Non-overlapping Intervals (LeetCode 435); Minimum Number of Arrows to Burst Balloons (LeetCode 452); Interval List Intersections (LeetCode 986); Meeting Rooms II (LeetCode 253).
- **Hard**: Employee Free Time (LeetCode 759); Data Stream as Disjoint Intervals (LeetCode 352).

## Common Mistakes

1. **Choosing the wrong order**: Start order supports merging; finish order supports activity selection

2. **Wrong comparison**: Use end time for greedy, start time for merging

3. **Off-by-one errors**: Be careful with strict vs non-strict comparisons

4. **Not handling empty input**: Check for empty arrays

5. **Modifying input**: Create copies when needed

## Performance Considerations

| Operation | Time | Space |
| --------------------- | ------------------------------ | ---------------------------------------------- |
| Merge / insert | O(n log n) / O(n) | O(n) result; sort workspace depends on runtime |
| Meeting Rooms II | O(n log n) | O(n) endpoint arrays |
| Non-overlap selection | O(n log n) | O(1) scan state, plus sort workspace |
| Arrow placement | O(n log n) | O(1) scan state, plus sort workspace |
| Employee free time | O(n log n) | O(n) for flattened intervals and result |

## Summary

Sort by start when merging ranges; sort by end when selecting the largest compatible set. Apply the endpoint convention consistently to overlap checks, event ties and free-time gaps.

# Shortest Paths: Dijkstra & Bellman-Ford

## Definition

**Dijkstra's Algorithm**: Computes shortest paths from a source to all nodes in a weighted graph with **non-negative edge weights**, using a priority queue to always settle the closest unsettled node next.

> **Textbook Definition:** A shortest-path algorithm minimizes path cost in a weighted graph. Dijkstra finalizes distances under nonnegative edge weights; Bellman-Ford uses repeated relaxation and can detect reachable negative cycles.

**Bellman-Ford**: Computes single-source shortest paths in **O(V·E)** by relaxing every edge V-1 times — and works with **negative weights**, detecting negative cycles as a bonus.

## First Principles

Dijkstra and Bellman-Ford differ exactly where their cost models differ:

1. **Dijkstra is greedy on edge weights**: with non-negative weights, the cheapest settled node is provably final (no negative detour exists) — the proof is the algorithm; negative edges break the proof, hence Bellman-Ford.
2. **Bellman-Ford buys correctness with brute force**: when no reachable negative cycle exists, n−1 rounds suffice because a shortest path can be chosen simple, with at most n−1 edges — it also *detects* negative cycles (still shrinking after n−1 rounds), which Dijkstra cannot even express.

## Why it matters

Shortest-path problems appear constantly disguised as non-graph problems: cheapest flight within K stops, network delay time, path with minimum effort, currency arbitrage (negative cycles!). Interviewers use them to test whether you know **why** Dijkstra fails on negative edges (greedy settlement becomes unsound) — not just that it does. Senior signal: choosing 0-1 BFS over Dijkstra when weights are binary, and reaching for Bellman-Ford when "at most K stops" turns into "at most K+1 relaxation rounds."

## When to Use

| Situation | Reach for |
| ------------------------------------------------------------- | -------------------------------------------------------- |
| Non-negative weights, need shortest from one source | Dijkstra + binary heap |
| Need all-pairs on dense-ish small graph | Floyd-Warshall (O(V³)) |
| Negative edges, or explicit negative-cycle/arbitrage question | Bellman-Ford |
| "At most K stops" / "at most K edges" constraints | Layered relaxation: K+1 / K rounds respectively |
| Unit/unweighted edges | Plain BFS |
| Weights only 0 and 1 | 0-1 BFS (deque) |

## How It Works

```text
Edges: A—B(1), A—D(3), B—C(5), C—E(1), D—E(9)

settle A at 0 → B=1, D=3
settle B at 1 → C=6
settle D at 3 → E=12
settle C at 6 → improve E to 7
settle E at 7 → the older heap entry E=12 is stale

Nonnegative edges ensure a future detour cannot lower a settled distance.
```

### Why negative edges break Dijkstra

```text
A --2--> B
A --4--> C
C --(-3)-> B

Truth: shortest A→B = 4 - 3 = 1.
Dijkstra settles B at distance 2 first (smaller than C=4),
so an implementation that permanently settles B returns the wrong answer.
The lazy heap example here allows reprocessing and may happen to correct
this graph; its Dijkstra correctness and complexity guarantees still do
not apply to negative weights, and a negative cycle can prevent termination.

Settlement is only safe if "future hops can't lower a settled
distance", which requires all weights ≥ 0.
```

### Bellman-Ford relaxation

```text
After round i, every reachable path using ≤ i edges has been considered.
With copied arrays the round represents that exact edge-count bound;
in-place standard Bellman-Ford may propagate more edges sooner.

After V-1 rounds every simple path (max V-1 edges) is correct.
Run round V: if ANY edge still relaxes → some shortest walk uses
≥ V edges → contains a cycle → that cycle must be negative.
```

## Template

The code assumes finite weights and valid integer node indices/source. Dijkstra requires nonnegative weights; its heap keeps old entries when a shorter route is found, and skips them when popped. `MinHeap` is defined in the network-delay example below. `Infinity` denotes unreachable vertices, not an input weight.

```typescript
// Dijkstra — adjacency list + min-heap of [dist, node]
function dijkstra(adj: number[][][], src: number): number[] {
  const dist = new Array(adj.length).fill(Infinity);
  dist[src] = 0;
  const heap = new MinHeap<[number, number]>(); // [dist, node]
  heap.push([0, src]);

  while (heap.size() > 0) {
    const [d, u] = heap.pop()!;
    if (d > dist[u]) continue;            // stale entry — skip

    for (const [v, w] of adj[u]) {
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        heap.push([dist[v], v]);
      }
    }
  }
  return dist;
}
```

## Code Examples (TypeScript)

### Problem 1: Network Delay Time (LeetCode 743) — Dijkstra

```typescript
function networkDelayTime(
  times: number[][], n: number, k: number
): number {
  const adj: number[][][] = Array.from({ length: n + 1 }, () => []);
  for (const [u, v, w] of times) adj[u].push([v, w]);

  const dist = dijkstra(adj, k);
  let max = 0;
  for (let i = 1; i <= n; i++) {
    if (dist[i] === Infinity) return -1; // unreachable node
    max = Math.max(max, dist[i]);
  }
  return max;
}

// Minimal array-based binary min-heap keyed on element[0]
class MinHeap<T extends number[]> {
  private a: T[] = [];
  size(): number { return this.a.length; }
  private less(i: number, j: number): boolean {
    return this.a[i][0] < this.a[j][0];
  }
  private swap(i: number, j: number): void {
    [this.a[i], this.a[j]] = [this.a[j], this.a[i]];
  }
  push(x: T): void {
    this.a.push(x);
    let i = this.a.length - 1;
    while (i > 0) {
      const p = (i - 1) >> 1;
      if (!this.less(i, p)) break;
      this.swap(i, p);
      i = p;
    }
  }
  pop(): T | undefined {
    const top = this.a[0];
    const last = this.a.pop()!;
    if (this.a.length > 0) {
      this.a[0] = last;
      let i = 0;
      for (;;) {
        const l = 2 * i + 1, r = l + 1;
        let m = i;
        if (l < this.a.length && this.less(l, m)) m = l;
        if (r < this.a.length && this.less(r, m)) m = r;
        if (m === i) break;
        this.swap(i, m);
        i = m;
      }
    }
    return top;
  }
}

console.log(networkDelayTime([[2,1,1],[2,3,1],[3,4,1]], 4, 2)); // 2
```

### Problem 2: Cheapest Flights Within K Stops (LeetCode 787) — Bellman-Ford variant

A stop is an intermediate airport: one allowed stop permits two edges. On flights 0→1→2 costing 100 each, the first round can reach 1, but cannot use its newly computed price to reach 2 in the same round. Reading the previous array and writing a copy enforces that bound. The contract uses a nonnegative integer stop limit.

```typescript
function findCheapestPrice(
  n: number, flights: number[][], src: number, dst: number, k: number
): number {
  // dp[v] = cheapest cost to reach v using at most i edges
  let dist = new Array(n).fill(Infinity);
  dist[src] = 0;

  for (let i = 0; i <= k; i++) {          // k+1 relaxation rounds
    const next = [...dist];               // copy: round reads only previous round
    for (const [u, v, w] of flights) {
      if (dist[u] !== Infinity && dist[u] + w < next[v]) {
        next[v] = dist[u] + w;
      }
    }
    dist = next;
  }
  return dist[dst] === Infinity ? -1 : dist[dst];
}

console.log(findCheapestPrice(
  4, [[0,1,100],[1,2,100],[2,0,100],[1,3,600],[2,3,200]], 0, 3, 1
)); // 700
```

### Problem 3: Standard Bellman-Ford With Negative Cycle Detection

**Relaxation** means replacing a tentative price with a cheaper route through an edge. A further improvement after all simple paths have been considered indicates a reachable negative cycle. When the returned flag is true, affected `dist` entries are tentative values, not finite shortest distances; this helper reports existence and does not identify every affected vertex.

```typescript
function bellmanFord(
  n: number, edges: number[][], src: number
): { dist: number[]; hasNegativeCycle: boolean } {
  const dist = new Array(n).fill(Infinity);
  dist[src] = 0;

  for (let i = 0; i < n - 1; i++) {
    let changed = false;                  // early-exit optimization
    for (const [u, v, w] of edges) {
      if (dist[u] !== Infinity && dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        changed = true;
      }
    }
    if (!changed) break;                  // already converged
  }

  // Round V: still relaxing ⇒ negative cycle reachable from src
  let hasNegativeCycle = false;
  for (const [u, v, w] of edges) {
    if (dist[u] !== Infinity && dist[u] + w < dist[v]) {
      hasNegativeCycle = true;
      break;
    }
  }

  return { dist, hasNegativeCycle };
}

console.log(bellmanFord(
  4,
  [[0,1,4],[0,2,5],[1,3,-3],[2,3,4],[3,1,-10]],
  0
).hasNegativeCycle); // true (3 → 1 → 3 sums to -13)
```

### Problem 4: Path With Minimum Effort (LeetCode 1631) — Dijkstra on a grid

For a rectangular grid of finite heights, minimize the largest adjacent height difference, not their sum. Extending a path cannot decrease its maximum, preserving the settlement argument. A route with differences 2 and 2 has effort 2, even though its total difference is 4.

```typescript
function minimumEffortPath(heights: number[][]): number {
  if (heights.length === 0 || heights[0].length === 0) return 0;
  const rows = heights.length, cols = heights[0].length;
  const dist: number[][] = Array.from({ length: rows }, () =>
    new Array(cols).fill(Infinity)
  );
  dist[0][0] = 0;
  const heap = new MinHeap<[number, number, number]>(); // [effort, r, c]
  heap.push([0, 0, 0]);
  const dirs = [[1,0],[-1,0],[0,1],[0,-1]];

  while (heap.size() > 0) {
    const [d, r, c] = heap.pop()!;
    if (r === rows - 1 && c === cols - 1) return d;
    if (d > dist[r][c]) continue;

    for (const [dr, dc] of dirs) {
      const nr = r + dr, nc = c + dc;
      if (nr < 0 || nr >= rows || nc < 0 || nc >= cols) continue;
      // Path effort = maximum edge difference seen so far
      const nd = Math.max(d, Math.abs(heights[nr][nc] - heights[r][c]));
      if (nd < dist[nr][nc]) {
        dist[nr][nc] = nd;
        heap.push([nd, nr, nc]);
      }
    }
  }
  return 0;
}

console.log(minimumEffortPath([[1,2,2],[3,8,2],[5,3,5]])); // 2
```

### Problem 5: 0-1 BFS (weights restricted to 0 and 1)

```typescript
function zeroOneBFS(
  adj: number[][][], src: number, n: number
): number[] {
  // adj[u] holds [v, w] where w ∈ {0, 1}
  const dist = new Array(n).fill(Infinity);
  dist[src] = 0;
  const dq = new Map<number, [number, number]>(); // indexed deque
  let head = 0, tail = 1;
  dq.set(0, [0, src]);

  while (head < tail) {
    const [queuedDistance, u] = dq.get(head)!;
    dq.delete(head++);
    if (queuedDistance !== dist[u]) continue;
    for (const [v, w] of adj[u]) {
      if (dist[u] + w < dist[v]) {
        dist[v] = dist[u] + w;
        if (w === 0) dq.set(--head, [dist[v], v]);
        else dq.set(tail++, [dist[v], v]);
      }
    }
  }
  return dist;
}

// No Array.shift/unshift: map-indexed pushes and pops are expected O(1).
// Contract: valid node indices, source and weights in {0, 1}.
```

Why it works: the deque maintains the invariant that its contents span at most two consecutive distance levels — 0-weight edges extend the current level (front), 1-weight edges open the next level (back). Same monotonicity argument as BFS, hence O(V + E).

## Common Mistakes

1. **Using Dijkstra with negative edges** — silently wrong answers; check the constraint before committing.

2. **Forgetting the stale-entry skip** (`if (d > dist[u]) continue`) — without it you reprocess nodes and degrade toward O(E²).

3. **Mutating `dist` mid-round in Bellman-Ford K-stops variants** — must read only the previous round's values (copy array), otherwise a chain of edges propagates within one round and violates the stop limit.

4. **Marking visited on push instead of pop** in lazy-deletion Dijkstra — a shorter distance found after pushing is then wrongly ignored. Either allow duplicate heap entries + skip stale ones, or use decrease-key semantics.

5. **Treating unreachable nodes as finite** — `Infinity` means "unreachable"; returning max over them produces Infinity/-wrong answers (guard like Problem 1 does).

6. **Negative cycle detection scoped wrong** — the helper detects cycles reachable from its source. A particular target has no finite shortest distance only if a reachable negative cycle can also reach that target.

## Time/Space Complexity

| Complexity | Dijkstra (binary heap) | Bellman-Ford | Bellman-Ford (early exit) | 0-1 BFS | BFS (unweighted) |
| ---------- | ------------------------------------ | ------------ | ------------------------------- | -------- | ---------------- |
| Time | O(V + E log(E+1)) for this lazy heap | O(V · E) | up to O(V · E), often much less | O(V + E) | O(V + E) |
| Space | O(V + E) | O(V) extra | O(V) extra | O(V + E) | O(V) |

Notes:

- The lazy heap can hold O(E) entries. For a simple graph, log E = O(log V), giving the usual O((V+E) log V) bound. Parallel edges require keeping the E-based heap bound.

- Dijkstra with an array-scan instead of a heap: O(V²), often a simpler choice for dense graphs (E ≈ V²).
- Floyd-Warshall all-pairs: O(V³) time, O(V²) space — choose it only when cubic work fits the runtime budget.
- Grids: V = rows × cols, E ≈ 4V, so Dijkstra on a grid is O(V log V).

## Choosing Between Them

```text
All weights ≥ 0, single source?          → Dijkstra (heap)
Weights ∈ {0, 1}?                        → 0-1 BFS (deque)
Unweighted?                              → BFS
Negative edges allowed / arbitrage?      → Bellman-Ford + cycle check
"At most K edges" constraint?            → copied relaxation, K rounds
"Exactly K edges" constraint?            → K rounds, each next array starts Infinity
"At most K stops" constraint?            → copied relaxation, K+1 rounds
Need all pairs, cubic work is feasible?  → Floyd-Warshall
Grid, minimize max edge weight?          → Dijkstra variant (Math.max merge)

                                           or threshold binary search + BFS
```

4. **Arbitrage-style currency problems** — Bellman-Ford negative cycle detection

## Summary

Dijkstra greedily settles nearest nodes and is correct exactly when weights are non-negative — the usual O((V+E) log V) bound on simple graphs with a binary heap and lazy deletion. Bellman-Ford trades speed for generality: V-1 relaxation rounds handle negative weights, a V-th round exposes negative cycles, and the same machinery solves "at most K edges" problems by capping rounds. When weights collapse to {0,1}, a deque replaces the heap entirely (0-1 BFS, linear time). Pick by asking one question: what are the edge weights?

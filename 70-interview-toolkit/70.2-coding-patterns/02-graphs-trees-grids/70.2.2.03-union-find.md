# Union-Find

If a service repeatedly adds connections and asks whether two nodes are now connected, rerunning a graph traversal for every query wastes work. Union-Find remembers which components have merged.

```typescript
const uf = new UnionFind(5);
uf.union(0, 1); uf.union(2, 3); uf.union(1, 3);
uf.connected(0, 3); // true — same merged component
uf.connected(0, 4); // false
```

## Definition

**Union-Find** (Disjoint Set Union, DSU) tracks elements partitioned into disjoint subsets. `find` determines an element's set; `union` merges two sets. Attaching the smaller tree below the larger limits lookup depth; compressing visited paths shortens later lookups.

> **Textbook Definition:** A disjoint-set data structure maintains a partition through representative lookup and set union. Union by rank or size with path compression provides near-constant amortized operations.

## First Principles

Adding an undirected connection can merge two groups but need not change either group if they are already connected. Store one representative per group so connectivity becomes a comparison of representatives. The invariant is representation: each set is a tree, and find walks to the root. Union by rank or size bounds height; path compression flattens visited paths. Together they give the near-constant amortized α(n) cost that makes large-scale connectivity queries practical. The pattern's real skill is recognition: "components that merge as you process" — connections coming online, accounts merging, redundant edges. If the data arrives as *links*, DSU is the first thought.

## Why It Matters

Union-Find serves connections added while components merge. The senior-level question is when to use union-find vs DFS/BFS for connected components: a DFS/BFS pass takes O(V+E), while processing all edges with optimized DSU takes O(V+E·α(V)). DSU gives roots for connectivity and can enumerate components by grouping nodes with the same root, as Accounts Merge below demonstrates. It supports interleaved edge additions and connectivity queries as well as offline batches — Kruskal's MST, accounts-merge, friend-circles, redundant-connection. Know both implementations (with rank and with size) and the path-compression one-liner.

## 1. Represent Sets as Trees With Rank and Compression

```text
Initial: [0, 1, 2, 3, 4] (5 separate sets)

Union(0, 1):
  0 ← 1 (1's root becomes 0)
  2 3 4

Union(2, 3):
  0 ← 1 2 ← 3
  4

Union(1, 3):
  roots 0 and 2 have equal rank: attach 2 to 0; 1 stays under 0, 3 under 2
  4

find(4) = 4
find(3) = 0 (with path compression)

connected(0, 3) = true
connected(0, 4) = false
```

A representative is an internal group identifier, not necessarily its smallest element. Rank is a merge-time bound, not the current height after compression: `find(3)` changes its parent from 2 to 0 without changing which nodes belong together. A failed union keeps the component count unchanged.

## 2. Carry the Reusable UnionFind Template

```typescript
class UnionFind {
  private parent: number[];
  private rank: number[];
  private components: number;

  constructor(n: number) {
    if (!Number.isInteger(n) || n < 0) throw new RangeError("invalid size");
    this.parent = new Array(n);
    this.rank = new Array(n).fill(0);
    this.components = n;

    for (let i = 0; i < n; i++) {
      this.parent[i] = i;
    }
  }

  find(x: number): number {
    if (!Number.isInteger(x) || x < 0 || x >= this.parent.length) throw new RangeError("invalid node");
    let root = x;
    while (this.parent[root] !== root) root = this.parent[root];
    while (this.parent[x] !== x) {
      const next = this.parent[x];
      this.parent[x] = root;
      x = next;
    }
    return root;
  }

  union(x: number, y: number): boolean {
    const rootX = this.find(x);
    const rootY = this.find(y);

    if (rootX === rootY) return false;

    // Union by rank
    if (this.rank[rootX] < this.rank[rootY]) {
      this.parent[rootX] = rootY;
    } else if (this.rank[rootX] > this.rank[rootY]) {
      this.parent[rootY] = rootX;
    } else {
      this.parent[rootY] = rootX;
      this.rank[rootX]++;
    }

    this.components--;
    return true;
  }

  connected(x: number, y: number): boolean {
    return this.find(x) === this.find(y);
  }

  getComponents(): number {
    return this.components;
  }
}
```

## 3. Grow Islands Incrementally and Merge Accounts

Contract: positive grid dimensions and valid cell coordinates. Count only activated land components: the general DSU also contains inactive grid cells, so its total component count is not the island count.

```typescript
function numIslands2(m: number, n: number, positions: number[][]): number[] {
  const uf = new UnionFind(m * n);
  let islandCount = 0;
  const grid = new Array(m * n).fill(0);
  const result: number[] = [];
  const directions = [[0, 1], [0, -1], [1, 0], [-1, 0]];

  for (const [r, c] of positions) {
    const id = r * n + c;

    if (grid[id] === 1) {
      result.push(islandCount);
      continue;
    }

    grid[id] = 1;
    islandCount++;

    for (const [dr, dc] of directions) {
      const nr = r + dr;
      const nc = c + dc;
      const nid = nr * n + nc;

      if (nr >= 0 && nr < m && nc >= 0 && nc < n && grid[nid] === 1) {
        if (uf.union(id, nid)) islandCount--;
      }
    }

    result.push(islandCount);
  }

  return result;
}

// Example
console.log(numIslands2(3, 3, [[0,0],[0,1],[1,2],[2,1]]));
// [1, 1, 2, 3]
```

Contract: each account contains a name and at least one email; accounts sharing an email represent the same person and have consistent names. Equal names alone do not merge accounts. Output groups have sorted emails; their group order is not an identity guarantee. This code does not resolve conflicting real-world identity records.

```typescript
function accountsMerge(accounts: string[][]): string[][] {
  const emailToId = new Map<string, number>();
  const emailToName = new Map<string, string>();
  let id = 0;

  for (const account of accounts) {
    const name = account[0];
    for (let i = 1; i < account.length; i++) {
      const email = account[i];
      emailToName.set(email, name);
      if (!emailToId.has(email)) {
        emailToId.set(email, id++);
      }
    }
  }

  const uf = new UnionFind(id);

  for (const account of accounts) {
    const firstEmailId = emailToId.get(account[1])!;
    for (let i = 2; i < account.length; i++) {
      const emailId = emailToId.get(account[i])!;
      uf.union(firstEmailId, emailId);
    }
  }

  const merged = new Map<number, string[]>();
  for (const [email] of emailToId) {
    const root = uf.find(emailToId.get(email)!);
    if (!merged.has(root)) {
      merged.set(root, []);
    }
    merged.get(root)!.push(email);
  }

  const result: string[][] = [];
  for (const [root, emails] of merged) {
    const name = emailToName.get(emails[0])!;
    result.push([name, ...emails.sort()]);
  }

  return result;
}

// Example
console.log(accountsMerge([
  ["John","johnsmith@mail.com","john_newyork@mail.com"],
  ["John","johnsmith@mail.com","john00@mail.com"],
  ["Mary","mary@mail.com"],
  ["John","johnnybravo@mail.com"]
]));
// [["John","john00@mail.com","john_newyork@mail.com","johnsmith@mail.com"],
// ["Mary","mary@mail.com"],
// ["John","johnnybravo@mail.com"]]
```

## 4. Detect Redundant Edges, Count Components and Fence Regions

Contract: an undirected tree on labels 1..n plus one extra edge. Adding an edge within an existing component closes a cycle. A directed graph needs a different argument: connectivity alone cannot detect directed cycles.

```typescript
function findRedundantConnection(edges: number[][]): number[] {
  const n = edges.length;
  const uf = new UnionFind(n + 1);

  for (const [u, v] of edges) {
    if (!uf.union(u, v)) {
      return [u, v];
    }
  }

  return [];
}

// Example
console.log(findRedundantConnection([[1,2],[1,3],[2,3]])); // [2,3]
console.log(findRedundantConnection([[1,2],[2,3],[3,4],[1,4],[1,5]])); // [1,4]
```

```typescript
function countComponents(n: number, edges: number[][]): number {
  const uf = new UnionFind(n);

  for (const [u, v] of edges) {
    uf.union(u, v);
  }

  return uf.getComponents();
}

// Example
console.log(countComponents(5, [[0,1],[1,2],[3,4]])); // 2
console.log(countComponents(5, [[0,1],[1,2],[2,3],[3,4]])); // 1
```

```typescript
function solve(board: string[][]): void {
  if (!board || board.length === 0) return;

  const rows = board.length;
  const cols = board[0].length;
  const uf = new UnionFind(rows * cols + 1);
  const dummy = rows * cols;

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (board[r][c] === 'O') {
        const id = r * cols + c;

        // Connect to dummy if on border
        if (r === 0 || r === rows - 1 || c === 0 || c === cols - 1) {
          uf.union(id, dummy);
        }

        // Connect to adjacent O's
        if (r > 0 && board[r - 1][c] === 'O') uf.union(id, (r - 1) * cols + c);
        if (c > 0 && board[r][c - 1] === 'O') uf.union(id, r * cols + (c - 1));
      }
    }
  }

  for (let r = 0; r < rows; r++) {
    for (let c = 0; c < cols; c++) {
      if (board[r][c] === 'O' && !uf.connected(r * cols + c, dummy)) {
        board[r][c] = 'X';
      }
    }
  }
}

// Example
const board = [
  ["X","X","X","X"],
  ["X","O","O","X"],
  ["X","X","O","X"],
  ["X","O","X","X"]
];
solve(board);
console.log(board);
// [["X","X","X","X"],["X","X","X","X"],["X","X","X","X"],["X","O","X","X"]]
```

## Real-World Use Cases

Reach for union-find for undirected cycle detection, connected components, incremental connectivity (adding edges and merging components — ordinary DSU supports no deletions or splits), Kruskal's minimum spanning tree, and merging groups and sets.

- **Static connectivity**: Number of Provinces (LeetCode 547); Max Area of Island (LeetCode 695).
- **Identity and cycle problems**: Accounts Merge (LeetCode 721); Number of Connected Components in an Undirected Graph (LeetCode 323); Redundant Connection (LeetCode 684); Redundant Connection II (LeetCode 685); Number of Islands II (LeetCode 305); Surrounded Regions (LeetCode 130).
- **Incremental and advanced practice**: Smallest String With Swaps (LeetCode 1202); Most Stones Removed with Same Row or Column (LeetCode 947); Satisfiability of Equality Equations (LeetCode 990).

## Common Mistakes

1. **Not using path compression**: Union by rank alone gives logarithmic height; adding compression improves amortized cost

2. **Not using union by rank**: Can lead to unbalanced trees

3. **Forgetting to check if already connected**: Union should return false if roots are same

4. **Wrong index handling**: Ensure 0-indexed or 1-indexed consistently

5. **Not updating component count**: Keep track of number of components

## Performance Considerations

| Operation | Time (with optimizations) | Space |
| --------- | ------------------------- | ----- |
| Find | O(α(n)) amortized | O(1) |
| Union | O(α(n)) amortized | O(1) |
| Connected | O(α(n)) amortized | O(1) |

- **α(n)**: Inverse Ackermann function (nearly constant, < 5 for all practical n)
- **Space**: O(n) for parent and rank arrays

## Summary

Union-Find is a powerful data structure for dynamic connectivity problems. With path compression and union by rank, it achieves nearly constant amortized time per operation. Keep domain counts, such as activated islands, separate from the DSU’s count of all allocated elements; ordinary DSU handles merging, not deletion.

# Topological Sort

If service A needs library B, B must build first. Repeatedly run tasks whose prerequisites are finished — and if tasks remain but none is ready, a dependency cycle is blocking progress.

```typescript
canFinish(2, [[1, 0]]);        // true — take 0, then 1
canFinish(2, [[1, 0], [0, 1]]); // false — cycle
```

## Definition

A **topological sort** is a linear ordering of a directed acyclic graph's (**DAG**) vertices where each prerequisite comes before the task depending on it. A directed **cycle** prevents such an ordering.

> **Textbook Definition:** A topological ordering arranges a directed acyclic graph's vertices so every directed edge points from an earlier vertex to a later one; a directed cycle prevents such an ordering.

## First Principles

A task can run only after its prerequisites are satisfied. Its **in-degree** counts incoming prerequisite edges; decrement that count as each prerequisite finishes. If unfinished tasks remain but none has in-degree zero, those tasks are blocked by a cycle or depend on one. Kahn's algorithm repeatedly removes in-degree-zero nodes (the currently available work); With prerequisite→dependent edges, DFS appends a node after its outgoing dependents finish, then reverses that finish order to put prerequisites first. Cycle detection falls out for free: unprocessed nodes with no in-degree-0 node means a dependency cycle.

## Why It Matters

Topological sort is the canonical pattern for **dependency resolution, build systems, course scheduling, task graphs and spreadsheet recalculation**. The senior-level questions are detecting **cycles** (impossible to sort → return empty or throw), handling **multiple valid orderings** (any is correct), and choosing **Kahn vs DFS** (Kahn gives natural cycle detection via in-degree; DFS gives the order with one final pass). A build task graph is a direct application. Package graphs can contain cycles, Kubernetes scheduling has placement constraints, and SQL join optimization considers costs — none is simply solved by a topological order. Interview examples include course prerequisites, an inferred alphabet order, and sequence reconstruction.

## 1. Drain In-Degree-Zero Tasks or Reverse DFS Finish Order

```text
Edges: 0→1, 0→2, 1→3, 2→3

Initial in-degrees: [0, 1, 1, 2]; available queue: [0]
Remove 0 → 1 and 2 become available.
Remove 1 → 3 still waits for 2.
Remove 2 → 3 becomes available.
Remove 3 → all four nodes processed.

Both [0,1,2,3] and [0,2,1,3] are valid.
[2,0,1,3] is invalid because it reverses edge 0→2.
```

The DFS alternative appends a node after its outgoing neighbors finish, then reverses the list once. A back-edge to a currently visiting node proves a cycle. Recursive DFS uses stack depth up to V — use Kahn's queue or an explicit DFS stack for deep graphs. The course helpers below take valid integer labels 0..numCourses−1 and pairs `[course, prerequisite]`, storing edges in the reverse reading direction prerequisite→course.

## 2. Carry Both Kahn and DFS Templates

```typescript
// Kahn's Algorithm (BFS-based)
function topologicalSortBFS(numCourses: number, prerequisites: number[][]): number[] {
  const inDegree = new Array(numCourses).fill(0);
  const graph: Map<number, number[]> = new Map();

  for (const [course, prereq] of prerequisites) {
    if (!graph.has(prereq)) graph.set(prereq, []);
    graph.get(prereq)!.push(course);
    inDegree[course]++;
  }

  const queue: number[] = [];
  for (let i = 0; i < numCourses; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }

  const result: number[] = [];

  let head = 0;
  while (head < queue.length) {
    const course = queue[head++];
    result.push(course);

    for (const next of graph.get(course) || []) {
      inDegree[next]--;
      if (inDegree[next] === 0) {
        queue.push(next);
      }
    }
  }

  return result.length === numCourses ? result : [];
}

// DFS-based
function topologicalSortDFS(numCourses: number, prerequisites: number[][]): number[] {
  const graph: Map<number, number[]> = new Map();
  for (const [course, prereq] of prerequisites) {
    if (!graph.has(prereq)) graph.set(prereq, []);
    graph.get(prereq)!.push(course);
  }

  const visited = new Array(numCourses).fill(0); // 0: unvisited, 1: visiting, 2: visited
  const result: number[] = [];

  function dfs(node: number): boolean {
    if (visited[node] === 1) return false; // cycle detected
    if (visited[node] === 2) return true;

    visited[node] = 1;

    for (const next of graph.get(node) || []) {
      if (!dfs(next)) return false;
    }

    visited[node] = 2;
    result.push(node); // record finish order
    return true;
  }

  for (let i = 0; i < numCourses; i++) {
    if (!dfs(i)) return []; // cycle detected
  }

  return result.reverse(); // reverse finish order once, not O(V²) unshift
}
```

DFS marks distinguish unvisited, currently active and finished nodes: an edge to an active node closes a cycle, while an edge to a finished node does not.

## 3. Schedule Courses and Infer an Alphabet

```typescript
function canFinish(numCourses: number, prerequisites: number[][]): boolean {
  return topologicalSortBFS(numCourses, prerequisites).length === numCourses;
}

// Example
console.log(canFinish(2, [[1,0]])); // true
console.log(canFinish(2, [[1,0],[0,1]])); // false (cycle)
```

```typescript
function findOrder(numCourses: number, prerequisites: number[][]): number[] {
  return topologicalSortBFS(numCourses, prerequisites);
}

// Example
console.log(findOrder(2, [[1,0]])); // [0, 1]
console.log(findOrder(4, [[1,0],[2,0],[3,1],[3,2]])); // [0, 1, 2, 3]
```

The alien-dictionary example assumes lowercase English letters, matching the problem's contract. Comparing only the first differing character of adjacent words yields a precedence edge. A longer word before its own prefix is invalid even without a graph cycle.

```typescript
function alienOrder(words: string[]): string {
  const graph = new Map<string, Set<string>>();
  const inDegree = new Map<string, number>();

  // Initialize
  for (const word of words) {
    for (const char of word) {
      if (!graph.has(char)) graph.set(char, new Set());
      if (!inDegree.has(char)) inDegree.set(char, 0);
    }
  }

  // Build graph
  for (let i = 0; i < words.length - 1; i++) {
    const word1 = words[i];
    const word2 = words[i + 1];

    // Check for invalid case: longer word comes before shorter
    if (word1.length > word2.length && word1.startsWith(word2)) {
      return '';
    }

    for (let j = 0; j < Math.min(word1.length, word2.length); j++) {
      const char1 = word1[j];
      const char2 = word2[j];

      if (char1 !== char2) {
        if (!graph.get(char1)!.has(char2)) {
          graph.get(char1)!.add(char2);
          inDegree.set(char2, (inDegree.get(char2) || 0) + 1);
        }
        break;
      }
    }
  }

  // Topological sort
  const queue: string[] = [];
  for (const [char, degree] of inDegree) {
    if (degree === 0) queue.push(char);
  }

  const result: string[] = [];

  let head = 0;
  while (head < queue.length) {
    const char = queue[head++];
    result.push(char);

    for (const next of graph.get(char) || []) {
      inDegree.set(next, inDegree.get(next)! - 1);
      if (inDegree.get(next) === 0) {
        queue.push(next);
      }
    }
  }

  return result.length === inDegree.size ? result.join('') : '';
}

// Example
console.log(alienOrder(["wrt","wrf","er","ett","rftt"]));
// "wertf"
console.log(alienOrder(["z","x"]));
// "zx"
console.log(alienOrder(["z","x","z"]));
// "" (cycle)
```

## 4. Count Semesters in Layers and Relax Longest DAG Paths

Contract: labels 1..n, each course takes one semester, and any number of available courses may run together. Count frozen queue layers, not individual removals. A limit on simultaneous courses or differing durations changes the scheduling problem.

```typescript
function minimumSemesters(n: number, relations: number[][]): number {
  const inDegree = new Array(n + 1).fill(0);
  const graph: Map<number, number[]> = new Map();

  for (const [prev, next] of relations) {
    if (!graph.has(prev)) graph.set(prev, []);
    graph.get(prev)!.push(next);
    inDegree[next]++;
  }

  const queue: number[] = [];
  for (let i = 1; i <= n; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }

  let semesters = 0;
  let count = 0;

  let head = 0;
  while (head < queue.length) {
    const size = queue.length - head;
    semesters++;

    for (let i = 0; i < size; i++) {
      const course = queue[head++];
      count++;

      for (const next of graph.get(course) || []) {
        inDegree[next]--;
        if (inDegree[next] === 0) {
          queue.push(next);
        }
      }
    }
  }

  return count === n ? semesters : -1;
}

// Example
console.log(minimumSemesters(3, [[1,3],[2,3]])); // 2
console.log(minimumSemesters(3, [[1,2],[2,3],[3,1]])); // -1 (cycle)
```

This version permits a path to start at any vertex and includes a zero-edge path of weight 0. Negative edges are allowed: choosing to start at a later vertex can beat including a negative predecessor edge. For a specified source instead, initialize other distances to negative infinity and guard unreachable predecessors.

```typescript
function longestPath(n: number, edges: number[][]): number[] {
  const graph: Map<number, [number, number][]> = new Map(); // node -> [(neighbor, weight)]
  const inDegree = new Array(n).fill(0);

  for (const [from, to, weight] of edges) {
    if (!graph.has(from)) graph.set(from, []);
    graph.get(from)!.push([to, weight]);
    inDegree[to]++;
  }

  const dist = new Array(n).fill(0);
  const queue: number[] = [];

  for (let i = 0; i < n; i++) {
    if (inDegree[i] === 0) queue.push(i);
  }

  let head = 0;
  while (head < queue.length) {
    const node = queue[head++];

    for (const [next, weight] of graph.get(node) || []) {
      dist[next] = Math.max(dist[next], dist[node] + weight);
      inDegree[next]--;
      if (inDegree[next] === 0) {
        queue.push(next);
      }
    }
  }

  if (head !== n) throw new Error("graph contains a cycle");
  return dist;
}

// Example
console.log(longestPath(5, [[0,1,3],[0,2,2],[1,3,1],[2,3,4],[1,4,2]]));
// [0, 3, 2, 6, 5]
```

## Real-World Use Cases

Reach for topological sort for task scheduling with dependencies, course prerequisites, build systems (make, webpack), spreadsheet cell dependencies, and any dependency-ordering problem.

- **Start with the state**: Course Schedule (LeetCode 207, Medium); Minimum Height Trees (LeetCode 310, Medium) — related undirected leaf peeling, not a DAG topological order.
- **Combine the mechanisms**: Course Schedule II (LeetCode 210); Alien Dictionary (LeetCode 269); Parallel Courses (LeetCode 1136); Longest Path in DAG (custom problem); Sort Items by Groups Respecting Dependencies (LeetCode 1203).
- **Extend the reasoning**: Largest Color Value in a Directed Graph (LeetCode 1857); Parallel Courses III (LeetCode 2050); Find All Possible Recipes from Given Supplies (LeetCode 2115, Medium).

## Common Mistakes

1. **Not detecting cycles**: Topological sort only works on DAGs

2. **Wrong edge direction**: Ensure edges represent dependencies correctly

3. **Not handling all nodes**: Some nodes may have no edges

4. **Forgetting to check if valid**: Result length must equal number of nodes

5. **Not initializing in-degree**: Set all nodes with no incoming edges to 0

## Performance Considerations

| Algorithm | Time | Space |
| ------------ | -------- | -------- |
| Kahn's (BFS) | O(V + E) | O(V + E) |
| DFS-based | O(V + E) | O(V + E) |

- **V**: Number of vertices
- **E**: Number of edges
- Both algorithms have the same complexity

## Summary

Represent each prerequisite as an edge to the task it blocks. A topological order exists only for a DAG; Kahn's algorithm detects a cycle when it emits fewer than V vertices. The result respects dependencies but does not decide resource-limited scheduling.

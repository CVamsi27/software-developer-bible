# Matrix Traversal & Simulation

## Definition

A family of **index-arithmetic patterns** for m×n grids where the challenge is not graph search but precise boundary management: spiral order via shrinking rectangles, in-place 90° rotation via transpose + row reversal, O(1)-space zero marking using first-row/column as flags, diagonal traversal via `(r+c)` / `(r-c)` index math, and simulation via direction vectors with turn logic.

## TL;DR

Matrix problems are 20% algorithm, 80% index discipline. The recurring toolkit:

1. **Direction vectors** `const dirs = [[0,1],[1,0],[0,-1],[-1,0]]` — replaces four copy-pasted branches.
2. **Boundary shrinking** — four walls (`top/bottom/left/right`) converge inward for spiral order.
3. **Transpose + reverse** — rotation becomes two array reversals instead of fragile single-pass math.
4. **First row/column as marker memory** — O(1) space Set Matrix Zeroes.
5. **Diagonal identity** — cells on the same anti-diagonal share `r+c`; same main diagonal share `r-c`.

If you can draw the matrix and annotate indices while talking, these problems become transcription exercises.

## Why it matters

Grid simulation questions (Spiral Matrix, Rotate Image, Set Matrix Zeroes) are FAANG staples because they expose candidates who code without a mental model of index state. They're also the base layer for island problems (70.2.2.01), shortest-path grids (70.2.2.02), and DP-on-grid problems (70.2.3.02). Senior signal: choosing the transpose trick over ad-hoc rotation loops, handling non-square matrices correctly, and knowing which problems allow input mutation.

## When to Use

| Signal in the problem | Pattern |
|----------------------|---------|
| "Print/traverse in spiral order" | Boundary shrinking |
| "Rotate image 90°, in place, O(1)" | Transpose + reverse rows |
| "Set entire row/col to zero, O(1) space" | First row/col as flag storage |
| "Traverse diagonally" | Group by `r+c` or step `r+1,c-1` |
| "Walk until obstacle then turn" | Direction vectors + turn cycle |
| "Flood fill / count regions" | DFS/BFS with visited handling (see 70.2.2.01) |

## How It Works

### Spiral order = peel rectangles

```text
┌──────────────────────┐
│ → → → → → → →        │   top row left→right,      top++
│ ┌──────────────────┐ │
│ │ ↓              ↓ │ │   right col top→bottom,    right--
│ │ ┌──────────────┐▼│ │
│ │ │ ← ← ← ← ← ← ←│ │   bottom row right→left,   bottom--
│ │ ▲┌────────────┐  │ │
│ │ └─↑ ↑ ↑ ↑ ↑ ↑──┘ │   left col bottom→top,     left++
│ └──────────────────┘ │
└──────────────────────┘
Loop while top <= bottom && left <= right.
After drawing top/right rows, RE-CHECK top<=bottom /
left<=right before drawing bottom/left (non-square guard).
```

### Rotate 90° clockwise = transpose + reverse each row

```text
Original      Transpose      Reverse rows
1 2 3         1 4 7          7 4 1
4 5 6   ───►  2 5 8    ───►  8 5 2
7 8 9         3 6 9          9 6 3

transpose: swap (i,j) ↔ (j,i) for j > i (upper triangle only!)
row reverse: two-pointer swap per row
Counter-clockwise variant: transpose + reverse COLUMNS
           (or reverse rows first, then transpose)
```

### Diagonal index math

```text
Anti-diagonals (↗): cells share r + c
  d=0: (0,0)
  d=1: (1,0) (0,1)
  d=2: (2,0) (1,1) (0,2)

Main diagonals (↘): cells share r - c
  k=0: (0,0) (1,1) (2,2)
  k=-1: (1,0) (2,1)

Diag-diff property (used in DP / game theory):
  moving right changes (r-c) by -1... moving down changes it by +1
```

## Code Examples (TypeScript)

### Problem 1: Spiral Matrix (LeetCode 54) — boundary shrinking

```typescript
function spiralOrder(matrix: number[][]): number[] {
  const result: number[] = [];
  if (matrix.length === 0) return result;

  let top = 0;
  let bottom = matrix.length - 1;
  let left = 0;
  let right = matrix[0].length - 1;

  while (top <= bottom && left <= right) {
    for (let c = left; c <= right; c++) result.push(matrix[top][c]); // →
    top++;

    for (let r = top; r <= bottom; r++) result.push(matrix[r][right]); // ↓
    right--;

    if (top <= bottom) {                                    // guard!
      for (let c = right; c >= left; c--) result.push(matrix[bottom][c]); // ←
      bottom--;
    }
    if (left <= right) {                                    // guard!
      for (let r = bottom; r >= top; r--) result.push(matrix[r][left]);   // ↑
      left++;
    }
  }
  return result;
}

console.log(spiralOrder([[1,2,3],[4,5,6],[7,8,9]]));
// [1,2,3,6,9,8,7,4,5]
```

The two inner guards are THE correctness point: without them, single-row/single-column remainders get printed twice.

### Problem 2: Rotate Image (LeetCode 48) — transpose + reverse

```typescript
function rotate(matrix: number[][]): void {
  const n = matrix.length;

  // transpose: upper-triangle swaps only
  for (let i = 0; i < n; i++) {
    for (let j = i + 1; j < n; j++) {
      [matrix[i][j], matrix[j][i]] = [matrix[j][i], matrix[i][j]];
    }
  }

  // reverse each row
  for (const row of matrix) {
    let l = 0, r = n - 1;
    while (l < r) {
      [row[l], row[r]] = [row[r], row[l]];
      l++; r--;
    }
  }
}

const img = [[1,2,3],[4,5,6],[7,8,9]];
rotate(img);
console.log(img); // [[7,4,1],[8,5,2],[9,6,3]]
```

Swapping over the FULL range in transpose would swap everything twice and restore the original — restrict to `j > i`. For counter-clockwise: reverse each row first, then transpose.

### Problem 3: Set Matrix Zeroes (LeetCode 73) — O(1) space

```typescript
function setZeroes(matrix: number[][]): void {
  const m = matrix.length;
  const n = matrix[0].length;
  let firstRowZero = false;
  let firstColZero = false;

  // 1. detect whether first row/col themselves need zeroing
  for (let c = 0; c < n; c++) if (matrix[0][c] === 0) firstRowZero = true;
  for (let r = 0; r < m; r++) if (matrix[r][0] === 0) firstColZero = true;

  // 2. use first row/col as marker memory for the rest
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      if (matrix[r][c] === 0) {
        matrix[r][0] = 0;   // mark this row
        matrix[0][c] = 0;   // mark this column
      }
    }
  }

  // 3. apply marks (skip markers themselves)
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      if (matrix[r][0] === 0 || matrix[0][c] === 0) matrix[r][c] = 0;
    }
  }

  // 4. finally handle the first row/col from saved booleans
  if (firstRowZero) for (let c = 0; c < n; c++) matrix[0][c] = 0;
  if (firstColZero) for (let r = 0; r < m; r++) matrix[r][0] = 0;
}

const g = [[1,1,1],[1,0,1],[1,1,1]];
setZeroes(g);
console.log(g); // [[1,0,1],[0,0,0],[1,0,1]]
```

Why booleans for row/col zero? If you zeroed `matrix[0][*]` during marking, step 3 could not distinguish "marker" from "genuinely zero" — order of operations is the whole problem.

### Problem 4: Diagonal Traverse (LeetCode 498)

```typescript
function findDiagonalOrder(mat: number[][]): number[] {
  const m = mat.length, n = mat[0].length;
  const result: number[] = [];
  let row = 0, col = 0;
  let goingUp = true;

  while (result.length < m * n) {
    result.push(mat[row][col]);

    if (goingUp) {
      if (col === n - 1)      { row++; goingUp = false; } // hit right wall
      else if (row === 0)     { col++; goingUp = false; } // hit top wall
      else                    { row--; col++; }           // ↗ continue
    } else {
      if (row === m - 1)      { col++; goingUp = true;  } // hit bottom wall
      else if (col === 0)     { row++; goingUp = true;  } // hit left wall
      else                    { row++; col--; }           // ↙ continue
    }
  }
  return result;
}

console.log(findDiagonalOrder([[1,2,3],[4,5,6],[7,8,9]]));
// [1,2,4,7,5,3,6,8,9]
```

Alternative formulation without walking: iterate diagonals `d = r+c` from 0..m+n-2, collect cells, reverse odd ones — same output, sometimes easier to reason about.

### Problem 5: Robot Bounded In Circle (LeetCode 1041) — direction-vector simulation

```typescript
function isRobotBounded(instructions: string): boolean {
  let x = 0, y = 0;
  let dirIdx = 0;                       // 0:N 1:E 2:S 3:W
  const dirs: [number, number][] = [[0,1],[1,0],[0,-1],[-1,0]];

  for (const ch of instructions) {
    if (ch === 'G') {
      x += dirs[dirIdx][0];
      y += dirs[dirIdx][1];
    } else if (ch === 'L') {
      dirIdx = (dirIdx + 3) % 4;        // counter-clockwise
    } else {
      dirIdx = (dirIdx + 1) % 4;        // clockwise
    }
  }
  // bounded iff back at origin OR facing a different direction
  // (any non-north heading self-repeats into a loop within 4 cycles)
  return (x === 0 && y === 0) || dirIdx !== 0;
}

console.log(isRobotBounded("GGLLGG")); // true
```

### Problem 6: Boundary following — island perimeter style walk

```typescript
// Count boundary edges of land in a grid without visiting water twice:
// each land cell contributes 4 minus its land neighbors.
function islandPerimeter(grid: number[][]): number {
  const m = grid.length, n = grid[0].length;
  let perimeter = 0;

  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (grid[r][c] !== 1) continue;
      perimeter += 4;
      if (r > 0 && grid[r-1][c] === 1) perimeter -= 2;  // shared edge above
      if (c > 0 && grid[r][c-1] === 1) perimeter -= 2;  // shared edge left
    }
  }
  return perimeter;
}

console.log(islandPerimeter([[0,1,0,0],[1,1,1,0],[0,1,0,0],[1,1,0,0]])); // 16
```

Counting only up/left neighbors subtracts every shared edge exactly once — no visited set needed.

## Common Mistakes

1. **Missing remainder guards in spiral** — printing bottom row/left col twice when the remaining strip is one row or one column thick. The `if (top <= bottom)` / `if (left <= right)` re-checks exist precisely for that.

2. **Full-range transpose** — swapping both triangles undoes itself. Restrict to `j > i` (or track with a `swapped` boolean).

3. **Marker corruption in Set Matrix Zeroes** — writing zeros into row/col markers before finishing detection, then misapplying them. Sequence strictly: detect originals → mark interior → apply interior → apply edges last.

4. **Assuming square matrices** — rotate is n×n only; spiral/diagonal code must handle m ≠ n. Test with a 1×k and k×1 matrix.

5. **Direction turn math errors** — `(idx + 1) % 4` vs `(idx + 3) % 4`; write N→E→S→W order down before coding turns.

6. **Off-by-one on wall checks in diagonal traverse** — checking `row === 0` before `col === n-1` (or vice versa) changes corner behavior; corners need explicit precedence decided once and tested.

## Time/Space Complexity

| Pattern | Time | Space |
|---------|------|-------|
| Spiral order | O(m·n) | O(1) extra (output aside) |
| Rotate 90° (transpose+reverse) | O(n²) | O(1) |
| Set Matrix Zeroes (marker trick) | O(m·n) | O(1) |
| Naive Set Matrix Zeroes (sets) | O(m·n) | O(m+n) |
| Diagonal traverse | O(m·n) | O(1) extra |
| Direction-vector simulation | O(steps) | O(1) |
| Island perimeter counting | O(m·n) | O(1) |

All are linear in cell count — interviewers probe the SPACE column, since O(1) variants are the actual test.

## Summary

Matrix simulation is index discipline: shrink four boundaries for spirals, compose transpose + row-reverse for rotation, spend the first row and column as free marker memory for zero-filling, exploit `r+c` / `r-c` identities for diagonals, and centralize movement in a direction vector with modular turn arithmetic. Every pattern is O(cells) time; the interview differentiator is achieving O(1) space and surviving non-square inputs. Draw the matrix, annotate boundaries, then transcribe.

## Cheat Sheet

```text
MATRIX TRAVERSAL & SIMULATION — CHEAT SHEET
═══════════════════════════════════════════

DIRECTION VECTORS (clockwise):
  [[0,1],[1,0],[0,-1],[-1,0]]
  turn CW:  idx=(idx+1)%4 · CCW: idx=(idx+3)%4

SPIRAL ORDER (4 shrinking walls):
  while top<=bottom && left<=right:
    → top row, top++
    ↓ right col, right--
    ← bottom row IF top<=bottom, bottom--   ← GUARD
    ↑ left col  IF left<=right, left++      ← GUARD
  guards prevent double-printing thin strips

ROTATE 90° CW IN PLACE:
  transpose (j>i upper triangle ONLY)
  + reverse each row
  CCW: reverse rows FIRST, then transpose

SET MATRIX ZEROES O(1):
  save firstRowZero/firstColZero bools
  mark interior zeros INTO row0/col0
  apply interior → apply row0 → apply col0 LAST
  (order preserves marker-vs-real-zero distinction)

DIAGONAL MATH:
  anti-diagonals share r+c · main share r-c
  diagonal traverse: walk ↗ until wall,
  corner precedence: right-wall BEFORE top-wall

SIMULATION:
  position + dirIdx + turn table;
  bounded-in-circle: return-to-origin OR turned

TRAPS:
• non-square inputs (test 1×k, k×1, 2×2)
• full-range transpose self-undoes
• spiral remainder strips printed twice
• marker writes racing detection in zeroes

ALL PATTERNS: O(m·n) time — fight for O(1) space
```

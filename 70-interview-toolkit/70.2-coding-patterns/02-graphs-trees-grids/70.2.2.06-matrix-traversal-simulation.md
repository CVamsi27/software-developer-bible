# Matrix Traversal & Simulation

A spiral scan of a `1 × 4` matrix consumes every cell on its first pass. If the algorithm does not re-check its remaining bounds, the later passes visit cells twice.

```typescript
spiralOrder([[1,2,3],[4,5,6],[7,8,9]]);
// [1,2,3,6,9,8,7,4,5]
```

## Definition

A **matrix algorithm** treats each cell as a row/column coordinate and changes or visits cells under explicit **boundary** and state rules. These examples focus on deterministic traversal and transformation; shortest paths and flood fill are graph problems over the same grid.

> **Textbook Definition:** Matrix traversal treats cells as positions with an explicit neighborhood relation; simulation updates state according to declared transition rules and whether changes take effect immediately or in a separate step.

## First Principles

A rectangular grid is a pair of bounded coordinates: after a spiral edge is consumed, exclude its row or column from the remaining rectangle, and recheck bounds to avoid consuming the same last strip twice. An in-place transformation destroys information unless it is saved or encoded elsewhere — rotation swaps values, while zero-filling stores marker bits in the first row and column and preserves their original status separately. Movement is state plus a transition: a robot needs position and heading, a diagonal walk needs coordinates and direction. Write how each boundary changes that state before turning the rule into code.

## Why It Matters

Matrix tasks expose boundary and mutation assumptions. Transpose-plus-row-reversal composes two simple transformations for an in-place square rotation; spiral traversal and zero-marker problems need different invariants. These coordinate rules also appear in [grid traversal](70.2.2.01-dfs-bfs.md), [weighted grid paths](70.2.2.02-shortest-paths-dijkstra-bellman-ford.md) and [grid dynamic programming](../03-recursion-and-optimization/70.2.3.02-dynamic-programming.md).

## 1. Peel Rectangles for Spiral Order

```text
┌──────────────────────┐
│ → → → → → → →        │   top row left→right,      top++
│ ┌──────────────────┐ │
│ │ ↓              ↓ │ │   right col top→bottom,    right--
│ │ ┌──────────────┐▼│ │
│ │ │ ← ← ← ← ← ← ←│   │   bottom row right→left,   bottom--
│ │ ▲┌────────────┐  │ │
│ │ └─↑ ↑ ↑ ↑ ↑ ↑──┘   │   left col bottom→top,     left++
│ └──────────────────┘ │
└──────────────────────┘
Loop while top <= bottom && left <= right.
After drawing top/right rows, RE-CHECK top<=bottom /
left<=right before drawing bottom/left (non-square guard).
```

## 2. Compose Transpose With Row Reversal for Rotation

```text
Original      Transpose      Reverse rows
1 2 3         1 4 7          7 4 1
4 5 6   ───►  2 5 8    ───►  8 5 2
7 8 9         3 6 9          9 6 3

transpose: swap (i,j) ↔ (j,i) for j > i (upper triangle only!)
row reverse: two-pointer swap per row
Counter-clockwise variant: transpose + reverse COLUMNS
           (or reverse rows first, then transpose)
```

## 3. Group Diagonals by Index Sums

```text
Anti-diagonals (↗): cells share r + c
  d=0: (0,0)
  d=1: (1,0) (0,1)
  d=2: (2,0) (1,1) (0,2)

Main diagonals (↘): cells share r - c
  k=0: (0,0) (1,1) (2,2)
  k=1: (1,0) (2,1)

Diag-diff property (used in DP / game theory):
  moving right changes (r-c) by -1... moving down changes it by +1
```

## 4. Shrink Boundaries, Rotate and Zero With Markers

Assume rectangular rows, including an empty matrix or zero columns. In a 2×3 matrix, consume the top row, then the last column — only the remaining bottom cells belong to the reverse pass, and the updated boundaries prevent revisiting corners. This helper preserves the input.

```typescript
function spiralOrder(matrix: number[][]): number[] {
  const result: number[] = [];
  if (matrix.length === 0) return result;

  let top = 0;
  let bottom = matrix.length - 1;
  let left = 0;
  let right = matrix[0].length - 1;

  while (top <= bottom && left <= right) {
    for (let c = left; c <= right; c++) result.push(matrix[top][c]); // →
    top++;

    for (let r = top; r <= bottom; r++) result.push(matrix[r][right]); // ↓
    right--;

    if (top <= bottom) {                                    // guard!
      for (let c = right; c >= left; c--) result.push(matrix[bottom][c]); // ←
      bottom--;
    }
    if (left <= right) {                                    // guard!
      for (let r = bottom; r >= top; r--) result.push(matrix[r][left]);   // ↑
      left++;
    }
  }
  return result;
}

console.log(spiralOrder([[1,2,3],[4,5,6],[7,8,9]]));
// [1,2,3,6,9,8,7,4,5]
```

The two inner guards are THE correctness point: without them, single-row and single-column remainders print twice.

```typescript
function rotate(matrix: number[][]): void {
  if (matrix.some(row => row.length !== matrix.length)) throw new RangeError("square matrix required");
  const n = matrix.length;

  // transpose: upper-triangle swaps only
  for (let i = 0; i < n; i++) {
    for (let j = i + 1; j < n; j++) {
      [matrix[i][j], matrix[j][i]] = [matrix[j][i], matrix[i][j]];
    }
  }

  // reverse each row
  for (const row of matrix) {
    let l = 0, r = n - 1;
    while (l < r) {
      [row[l], row[r]] = [row[r], row[l]];
      l++; r--;
    }
  }
}

const img = [[1,2,3],[4,5,6],[7,8,9]];
rotate(img);
console.log(img); // [[7,4,1],[8,5,2],[9,6,3]]
```

Swapping over the FULL range in transpose would swap everything twice and restore the original — restrict to `j > i`. For counter-clockwise: reverse each row first, then transpose.

```typescript
function setZeroes(matrix: number[][]): void {
  if (matrix.length === 0 || matrix[0].length === 0) return;
  const m = matrix.length;
  const n = matrix[0].length;
  let firstRowZero = false;
  let firstColZero = false;

  // 1. detect whether first row/col themselves need zeroing
  for (let c = 0; c < n; c++) if (matrix[0][c] === 0) firstRowZero = true;
  for (let r = 0; r < m; r++) if (matrix[r][0] === 0) firstColZero = true;

  // 2. use first row/col as marker memory for the rest
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      if (matrix[r][c] === 0) {
        matrix[r][0] = 0;   // mark this row
        matrix[0][c] = 0;   // mark this column
      }
    }
  }

  // 3. apply marks (skip markers themselves)
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      if (matrix[r][0] === 0 || matrix[0][c] === 0) matrix[r][c] = 0;
    }
  }

  // 4. finally handle the first row/col from saved booleans
  if (firstRowZero) for (let c = 0; c < n; c++) matrix[0][c] = 0;
  if (firstColZero) for (let r = 0; r < m; r++) matrix[r][0] = 0;
}

const g = [[1,1,1],[1,0,1],[1,1,1]];
setZeroes(g);
console.log(g); // [[1,0,1],[0,0,0],[1,0,1]]
```

The first row and column hold marker bits for other rows and columns. Save whether they originally contained a zero before writing new markers — otherwise a marker written for an interior zero could incorrectly clear the entire first row or column.

## 5. Walk Diagonals, Simulate Robots and Count Shared Edges

```typescript
function findDiagonalOrder(mat: number[][]): number[] {
  if (mat.length === 0 || mat[0].length === 0) return [];
  const m = mat.length, n = mat[0].length;
  const result: number[] = [];
  let row = 0, col = 0;
  let goingUp = true;

  while (result.length < m * n) {
    result.push(mat[row][col]);

    if (goingUp) {
      if (col === n - 1)      { row++; goingUp = false; } // hit right wall
      else if (row === 0)     { col++; goingUp = false; } // hit top wall
      else                    { row--; col++; }           // ↗ continue
    } else {
      if (row === m - 1)      { col++; goingUp = true;  } // hit bottom wall
      else if (col === 0)     { row++; goingUp = true;  } // hit left wall
      else                    { row++; col--; }           // ↙ continue
    }
  }
  return result;
}

console.log(findDiagonalOrder([[1,2,3],[4,5,6],[7,8,9]]));
// [1,2,4,7,5,3,6,8,9]
```

Alternative formulation without walking: iterate diagonals `d = r+c` from 0..m+n-2, collect cells with row increasing, then reverse even-numbered diagonals — same output, sometimes easier to reason about.

The same finite instruction string repeats indefinitely. If one pass returns to the origin, repetitions stay bounded. Otherwise a changed heading rotates the next displacement: after two or four passes the rotated displacements cancel. Returning with the original north heading and a nonzero displacement repeats that displacement forever.

```typescript
function isRobotBounded(instructions: string): boolean {
  let x = 0, y = 0;
  let dirIdx = 0;                       // 0:N 1:E 2:S 3:W
  const dirs: [number, number][] = [[0,1],[1,0],[0,-1],[-1,0]];

  for (const ch of instructions) {
    if (ch === 'G') {
      x += dirs[dirIdx][0];
      y += dirs[dirIdx][1];
    } else if (ch === 'L') {
      dirIdx = (dirIdx + 3) % 4;        // counter-clockwise
    } else if (ch === 'R') {
      dirIdx = (dirIdx + 1) % 4;        // clockwise
    } else {
      throw new Error("expected G, L or R");
    }
  }
  // bounded iff back at origin OR facing a different direction
  // (any non-north heading self-repeats into a loop within 4 cycles)
  return (x === 0 && y === 0) || dirIdx !== 0;
}

console.log(isRobotBounded("GGLLGG")); // true
```

```typescript
// Count boundary edges of land in a grid without visiting water twice:
// Start with 4 per land cell; remove both sides of each shared edge.
function islandPerimeter(grid: number[][]): number {
  if (grid.length === 0 || grid[0].length === 0) return 0;
  const m = grid.length, n = grid[0].length;
  let perimeter = 0;

  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (grid[r][c] !== 1) continue;
      perimeter += 4;
      if (r > 0 && grid[r-1][c] === 1) perimeter -= 2;  // shared edge above
      if (c > 0 && grid[r][c-1] === 1) perimeter -= 2;  // shared edge left
    }
  }
  return perimeter;
}

console.log(islandPerimeter([[0,1,0,0],[1,1,1,0],[0,1,0,0],[1,1,0,0]])); // 16
```

Inspecting only up and left counts each shared edge once, then subtracts 2 because both cells included that edge. This returns the total boundary of all land, including shores around holes, rather than only the outside coast.

## Real-World Use Cases

| Signal in the problem | Pattern |
| ---------------------------------------- | --------------------------------------------- |
| "Print/traverse in spiral order" | Boundary shrinking |
| "Rotate image 90°, in place, O(1)" | Transpose + reverse rows |
| "Set entire row/col to zero, O(1) space" | First row/col as flag storage |
| "Traverse diagonally" | Group by `r+c` or step `r+1,c-1` |
| "Walk until obstacle then turn" | Direction vectors + turn cycle |
| "Flood fill / count regions" | DFS/BFS with visited handling (see 70.2.2.01) |

- **Start with the state**: Island Perimeter (LeetCode 463) — edge-counting warm-up; Flipping an Image (LeetCode 832) — row reversal practice; Toeplitz Matrix (LeetCode 766) — diagonal identity `r-c`.
- **Combine the mechanisms**: Spiral Matrix (LeetCode 54) — boundary shrinking; Spiral Matrix II (LeetCode 59) — fill numbers spirally; Set Matrix Zeroes (LeetCode 73) — O(1) space markers; Diagonal Traverse (LeetCode 498) — wall-precedence logic; Robot Bounded In Circle (LeetCode 1041) — direction simulation; Transpose Matrix (LeetCode 867, Easy) — non-square indexing drill.
- **Extend the reasoning**: Rotate Image (LeetCode 48, Medium) — in-place O(1) rotation; Spiral Matrix IV (LeetCode 2326, Medium) — spiral + linked-list construction; Number of Islands II (LeetCode 305) — dynamic grid + union-find crossover.

## Common Mistakes

1. **Missing remainder guards in spiral** — printing bottom row/left col twice when the remaining strip is one row or one column thick. The `if (top <= bottom)` / `if (left <= right)` re-checks exist precisely for that.

2. **Full-range transpose** — swapping both triangles undoes itself. Restrict to `j > i` (or track with a `swapped` boolean).

3. **Marker corruption in Set Matrix Zeroes** — writing zeros into row/col markers before finishing detection, then misapplying them. Sequence strictly: detect originals → mark interior → apply interior → apply edges last.

4. **Assuming square matrices** — rotate is n×n only; spiral/diagonal code must handle m ≠ n. Test with a 1×k and k×1 matrix.

5. **Direction turn math errors** — `(idx + 1) % 4` vs `(idx + 3) % 4`; write N→E→S→W order down before coding turns.

6. **Off-by-one on wall checks in diagonal traverse** — checking `row === 0` before `col === n-1` (or vice versa) changes corner behavior; corners need explicit precedence decided once and tested.

## Performance Considerations

| Pattern | Time | Space |
| -------------------------------- | -------- | ----------------------------------- |
| Spiral order | O(m·n) | O(1) extra (output aside) |
| Rotate 90° (transpose+reverse) | O(n²) | O(1) |
| Set Matrix Zeroes (marker trick) | O(m·n) | O(1) |
| Naive Set Matrix Zeroes (sets) | O(m·n) | O(m+n) |

| Pattern | Time | Space |
| -------------------------------- | -------- | ----------------------------------- |
| Diagonal traverse | O(m·n) | O(1) extra, excluding O(m·n) output |
| Direction-vector simulation | O(steps) | O(1) |
| Island perimeter counting | O(m·n) | O(1) |

Grid scans are linear in cell count; robot simulation is linear in instruction count. Rectangular inputs are assumed for the traversal/zeroing examples. In-place rotation requires a square matrix; a rectangular 90° rotation changes dimensions and usually needs a new output matrix.

## Summary

Matrix simulation is index discipline: shrink four boundaries for spirals, compose transpose + row-reverse for rotation, spend the first row and column as free marker memory for zero-filling, exploit `r+c` / `r-c` identities for diagonals, and centralize movement in a direction vector with modular turn arithmetic. Grid scans take O(cells) time and the robot takes O(instructions). Keep output space separate from workspace and check whether mutation and rectangular inputs are allowed. Draw the matrix, annotate boundaries, then transcribe.

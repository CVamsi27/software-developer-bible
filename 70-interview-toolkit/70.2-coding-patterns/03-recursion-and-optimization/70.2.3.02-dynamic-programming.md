# Dynamic Programming

The naive Fibonacci recurrence solves `f(3)` more than once while computing `f(6)`. A state definition lets the algorithm store that result and reuse it.

```typescript
fibMemo(10); // 55 — each state computed once
fibTab(10);  // 55 — rolling pair, O(1) space
```

## Definition

**Dynamic Programming (DP)** solves optimization, counting or feasibility problems through a **recurrence** over subproblems, storing subproblem results to avoid redundant computation. It applies when problems have **overlapping subproblems**; optimization tasks also require that combining optimal subproblem answers preserves the global optimum.

> **Textbook Definition:** Dynamic programming evaluates a recurrence over overlapping subproblems and retains their results for reuse. The state must contain all information needed to determine subsequent transitions.

## First Principles

DP exists because naive recursion re-solves overlapping subproblems. Repeated states create reusable work — but a valid recurrence must retain enough information for later choices to depend only on the state. Optimization uses optimal substructure; counting combines contributions without double-counting. Caching each reachable state removes repeated evaluation, though an exponential number of states remains exponential. The state is the entire game: define it minimal (what the future needs to know about the past) and the transition writes itself. Memoization (top-down) and tabulation (bottom-up) are the same recurrence in different orders; their memory costs depend on stored states and traversal depth.

## Why It Matters

DP starts with a precise subproblem, not a familiar-looking loop. Define the **state**, **recurrence**, **base cases** and **answer location** before coding. Then estimate the number of states, transitions per state and retained memory. Common forms include sequence, grid, knapsack and string states.

## How It Works

### 1. Name the State, Recurrence and Evaluation Order

```text
State: f(i) = Fibonacci number at index i
Base:  f(0)=0, f(1)=1
Rule:  f(i)=f(i-1)+f(i-2)

Naive f(5) asks for f(3) through both f(4) and its own second branch.
Memoization computes f(3) once and reuses it.
Tabulation evaluates 0,1,2,3,4,5 so each dependency already exists.
A rolling pair retains only the two values needed by the next state.
```

```text
0/1 KNAPSACK PROBLEM:

Items: [(w=2, v=3), (w=3, v=4), (w=4, v=5)]
Capacity: 5

DP Table:
       Capacity
       0 1 2 3 4 5
Item 0 0 0 3 3 3 3
Item 1 0 0 3 4 4 7
Item 2 0 0 3 4 5 7

Each row uses the listed items up through that row.
At item 1/capacity 5, compare excluding it (3) with
including it (4 + earlier-row capacity 2 value 3 = 7).
Answer: 7 (items 0 and 1)
```

### 2. Build Fibonacci Both Ways

```typescript
// Memoization
function fibMemo(n: number): number {
  if (!Number.isInteger(n) || n < 0 || n > 78) throw new RangeError("Number implementation supports indices 0..78");
  const memo = new Map<number, number>();

  function dp(n: number): number {
    if (n <= 1) return n;
    if (memo.has(n)) return memo.get(n)!;

    memo.set(n, dp(n - 1) + dp(n - 2));
    return memo.get(n)!;
  }

  return dp(n);
}

// Tabulation
function fibTab(n: number): number {
  if (!Number.isInteger(n) || n < 0 || n > 78) throw new RangeError("Number implementation supports indices 0..78");
  if (n <= 1) return n;

  let prev = 0;
  let curr = 1;

  for (let i = 2; i <= n; i++) {
    const next = prev + curr;
    prev = curr;
    curr = next;
  }

  return curr;
}

// Example
console.log(fibMemo(10)); // 55
console.log(fibTab(10)); // 55
```

Fibonacci values after index 78 exceed JavaScript's exact integer range. Use BigInt for larger exact values; memoization does not correct numeric precision loss.

### 3. Fill Knapsack, LCS and LIS Tables

`dp[i][w]` is the best value using the first i items within capacity w. Values are finite Numbers with sums within the required precision; skipping every item is allowed. Zero-weight items are permitted once each. Reading only the previous item row prevents using an item twice. The same distinction matters in a 1D optimization: descending capacities enforce 0/1 use, while ascending capacities permit reuse.

```typescript
function knapsack(weights: number[], values: number[], capacity: number): number {
  if (!Number.isInteger(capacity) || capacity < 0 || weights.length !== values.length || weights.some(w => !Number.isInteger(w) || w < 0)) throw new RangeError("invalid knapsack inputs");
  const n = weights.length;
  const dp = Array(n + 1).fill(null).map(() => Array(capacity + 1).fill(0));

  for (let i = 1; i <= n; i++) {
    for (let w = 0; w <= capacity; w++) {
      if (weights[i - 1] <= w) {
        dp[i][w] = Math.max(
          dp[i - 1][w],
          dp[i - 1][w - weights[i - 1]] + values[i - 1]
        );
      } else {
        dp[i][w] = dp[i - 1][w];
      }
    }
  }

  return dp[n][capacity];
}

// Example
console.log(knapsack([2, 3, 4, 5], [3, 4, 5, 6], 5)); // 7
```

A subsequence preserves order but may skip characters. `dp[i][j]` is the best length for the first i and j code units of the two texts. Equal final units extend the smaller-prefix answer by one; unequal units require skipping one final unit and taking the better answer. Empty prefixes have length zero. This version returns the length, not the sequence.

```typescript
function longestCommonSubsequence(text1: string, text2: string): number {
  const m = text1.length;
  const n = text2.length;

  const dp = Array(m + 1).fill(null).map(() => Array(n + 1).fill(0));

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (text1[i - 1] === text2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1] + 1;
      } else {
        dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);
      }
    }
  }

  return dp[m][n];
}

// Example
console.log(longestCommonSubsequence("abcde", "ace")); // 3
console.log(longestCommonSubsequence("abc", "abc")); // 3
console.log(longestCommonSubsequence("abc", "def")); // 0
```

`dp[i]` means the best strictly increasing length **ending at i**, not the best length anywhere in the first i positions. Every smaller earlier value can precede it; take the best predecessor length plus one. Equality does not extend a strict sequence. Use finite numbers; the final answer is the maximum of all ending states.

```typescript
function lengthOfLIS(nums: number[]): number {
  const n = nums.length;
  if (n === 0) return 0;
  const dp = new Array(n).fill(1);

  for (let i = 1; i < n; i++) {
    for (let j = 0; j < i; j++) {
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }

  let longest = 0;
  for (const length of dp) longest = Math.max(longest, length);
  return longest;
}

// Example
console.log(lengthOfLIS([10, 9, 2, 5, 3, 7, 101, 18])); // 4 ([2,3,7,101])
```

### 4. Count Coins and Edits Minimally

`dp[i]` is the fewest coins needed for exactly i. Zero needs zero coins; other totals begin unreachable. For each available coin, a reachable i−coin offers one more coin. Reusing denominations is allowed, and positive integer coins ensure dependencies point to smaller totals. For [2] and target 3, no transition reaches 3, so return −1.

```typescript
function coinChange(coins: number[], amount: number): number {
  if (!Number.isInteger(amount) || amount < 0 || coins.some(c => !Number.isInteger(c) || c <= 0)) throw new RangeError("positive integer coins and nonnegative amount required");
  const dp = new Array(amount + 1).fill(Infinity);
  dp[0] = 0;

  for (let i = 1; i <= amount; i++) {
    for (const coin of coins) {
      if (i >= coin && dp[i - coin] !== Infinity) {
        dp[i] = Math.min(dp[i], dp[i - coin] + 1);
      }
    }
  }

  return dp[amount] === Infinity ? -1 : dp[amount];
}

// Example
console.log(coinChange([1, 2, 5], 11)); // 3 (5 + 5 + 1)
console.log(coinChange([2], 3)); // -1
```

`dp[i][j]` counts the fewest unit-cost insertions, deletions or replacements to turn the first i code units of word1 into the first j of word2. Empty-prefix costs are their lengths. Equal final units need no edit; otherwise compare removing the source unit, inserting the target unit or replacing one with the other. Transposition is not an operation in this recurrence.

```typescript
function minDistance(word1: string, word2: string): number {
  const m = word1.length;
  const n = word2.length;

  const dp = Array(m + 1).fill(null).map(() => Array(n + 1).fill(0));

  for (let i = 0; i <= m; i++) dp[i][0] = i;
  for (let j = 0; j <= n; j++) dp[0][j] = j;

  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        dp[i][j] = dp[i - 1][j - 1];
      } else {
        dp[i][j] = 1 + Math.min(
          dp[i - 1][j], // delete
          dp[i][j - 1], // insert
          dp[i - 1][j - 1] // replace
        );
      }
    }
  }

  return dp[m][n];
}

// Example
console.log(minDistance("horse", "ros")); // 3
console.log(minDistance("intention", "execution")); // 5
```

## Real-World Use Cases

Reach for DP for optimization problems (min/max), counting problems, overlapping subproblems, optimal substructure, and recurrences whose reusable states and transition costs fit the budget — exponential brute force alone does not prove DP will be efficient.

- **Establish the state**: Climbing Stairs (LeetCode 70); House Robber (LeetCode 198, Medium); Min Cost Climbing Stairs (LeetCode 746).
- **Combine choices and states**: Coin Change (LeetCode 322); Longest Increasing Subsequence (LeetCode 300); Word Break (LeetCode 139); Unique Paths (LeetCode 62); Maximum Product Subarray (LeetCode 152); Decode Ways (LeetCode 91); Longest Common Subsequence (LeetCode 1143).
- **Extend the constraints**: Edit Distance (LeetCode 72, Medium); Burst Balloons (LeetCode 312); Regular Expression Matching (LeetCode 10); Wildcard Matching (LeetCode 44); Longest Valid Parentheses (LeetCode 32).

## Common Mistakes

1. **Not identifying overlapping subproblems**: Use memoization to avoid redundant work

2. **Wrong recurrence relation**: Carefully define the relationship between subproblems

3. **Incorrect base case**: Always define base cases before recurrence

4. **Not considering all options**: In knapsack, consider both including and excluding items

5. **Discarding reconstruction data too early**: Rolling rows can preserve a length or cost but lose the decisions needed to reconstruct the answer. Choose storage according to the return contract.

## Performance Considerations

| Problem | Time | Space | Optimized Space |
| ------------- | ----------- | --------- | ------------------------------------------------------- |
| Fibonacci | O(n) | O(n) | O(1) |
| Knapsack | O(n×W) | O(n×W) | O(W) |
| LCS | O(m×n) | O(m×n) | O(min(m,n)) |
| LIS | O(n²) | O(n) | O(n); a different algorithm improves time to O(n log n) |
| Coin Change | O(n×amount) | O(amount) | O(amount) |
| Edit Distance | O(m×n) | O(m×n) | O(min(m,n)) |

Knapsack's O(n·W) bound depends on the numeric capacity W, making it pseudo-polynomial in the input's bit length. More generally, estimate state count × transitions per state, plus output and arithmetic costs. The string examples index UTF-16 code units; tokenize differently when the required symbol is a Unicode code point or grapheme.

## Summary

Define the state, valid transitions, base cases, evaluation order, and answer location. Reusing a computed state removes duplicate work, but total cost still depends on how many states exist. Reduce memory only after identifying which earlier states future transitions need.

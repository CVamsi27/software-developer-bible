# Heap

Suppose tasks arrive continuously and you need to run the highest-priority task next. Sorting after every arrival does extra work — a heap keeps only enough order to expose the next task efficiently.

```typescript
const kthLargest = new KthLargest(3, [4, 5, 8, 2]);
kthLargest.add(3); // 4 — root of the retained largest-3 set
```

## Definition

A **heap** is a tree-based structure satisfying the **heap property**: in a max-heap, every node is greater than or equal to its children; in a min-heap, less than or equal. Heaps implement **priority queues**. If an unsorted array is already available and only one rank is needed, compare with [Quick Select](70.2.4.05-quick-select-reservoir-sampling.md).

> **Textbook Definition:** A binary heap is a complete binary tree whose parent-child ordering keeps an extreme value at the root; array indexing encodes its shape and supports logarithmic insertion and removal.

## First Principles

A heap is a focused structure for *repeatedly extracting the extremum*. Sorted order is overkill when you only need the min or max: full sorting costs O(n log n) and answers all queries, while a heap maintains only the partial order needed for extract-min at O(log n). Pay for exactly the order you consume. The complete binary tree in an array is the cache-friendly encoding — parent and child by index arithmetic, no pointers.

## 1. Keep Only Enough Order for the Next Extremum

```text
Min-Heap:
        1
       / \
      3 2
     / \ / \
    7 4 5 6

Parent is no larger than its children.
Complete binary tree stored in array:
Index: 0 1 2 3 4 5 6
Value: 1 3 2 7 4 5 6

Max-Heap:
        7
       / \
      5 6
     / \ / \
    3 4 1 2

Parent is no smaller than its children.
```

```text
Original min-heap: [1,3,2,7,4,5,6]
Push 0 at index 7:
  swap with index 3 → [1,3,2,0,4,5,6,7]
  swap with index 1 → [1,0,2,3,4,5,6,7]
  swap with index 0 → [0,1,2,3,4,5,6,7]

Pop from the original heap:
  move last value 6 to root → [6,3,2,7,4,5]
  swap with smaller child 2 → [2,3,6,7,4,5]
  swap with child 5         → [2,3,5,7,4,6]
```

Each repair follows one root-to-leaf path, giving logarithmic work. Bottom-up heap construction is linear: most nodes are near leaves and need only a short repair. Repeatedly sorting after insertion maintains full order and loses this benefit.

## 2. Carry a Comparator-Driven Heap Template

Numeric examples assume finite values. `compare(a,b) < 0` gives a higher priority to a, and the comparison must remain consistent while values are queued. Mutating an item's priority without repairing its heap position invalidates the ordering.

```typescript
// compare(a,b) < 0 means a has higher priority than b.
class Heap<T> {
  private heap: T[];
  constructor(private compare: (a: T, b: T) => number, values: T[] = []) {
    this.heap = [...values];
    for (let i = Math.floor(this.heap.length / 2) - 1; i >= 0; i--) this.down(i);
  }
  size(): number { return this.heap.length; }
  peek(): T | undefined { return this.heap[0]; }
  push(value: T): void {
    this.heap.push(value);
    let index = this.heap.length - 1;
    while (index > 0) {
      const parent = Math.floor((index - 1) / 2);
      if (this.compare(this.heap[parent], this.heap[index]) <= 0) break;
      [this.heap[parent], this.heap[index]] = [this.heap[index], this.heap[parent]];
      index = parent;
    }
  }
  pop(): T | undefined {
    if (this.heap.length === 0) return undefined;
    const top = this.heap[0];
    const last = this.heap.pop()!;
    if (this.heap.length > 0) {
      this.heap[0] = last;
      this.down(0);
    }
    return top;
  }
  private down(index: number): void {
    for (;;) {
      const left = 2 * index + 1, right = left + 1;
      let best = index;
      if (left < this.heap.length && this.compare(this.heap[left], this.heap[best]) < 0) best = left;
      if (right < this.heap.length && this.compare(this.heap[right], this.heap[best]) < 0) best = right;
      if (best === index) return;
      [this.heap[index], this.heap[best]] = [this.heap[best], this.heap[index]];
      index = best;
    }
  }
}

class MinHeap extends Heap<number> {
  constructor(values: number[] = []) { super((a, b) => a - b, values); }
}
```

## 3. Retain Top-k Arrivals and Balance Two Halves

Retain the largest k arrivals in a min-heap. Its root is the smallest among those retained, hence the kth largest overall. An arrival no larger than that root cannot enter the retained set. Equal values count as separate arrivals; until k values exist, the answer is null.

```typescript
class KthLargest {
  private minHeap: MinHeap;
  private k: number;

  constructor(k: number, nums: number[]) {
    if (!Number.isInteger(k) || k < 1) throw new RangeError("positive k required");
    this.k = k;
    this.minHeap = new MinHeap();

    for (const num of nums) {
      this.add(num);
    }
  }

  add(val: number): number | null {
    if (this.minHeap.size() < this.k) {
      this.minHeap.push(val);
    } else if (val > this.minHeap.peek()!) {
      this.minHeap.pop();
      this.minHeap.push(val);
    }

    return this.minHeap.size() < this.k ? null : this.minHeap.peek()!;
  }
}

// Example
const kthLargest = new KthLargest(3, [4, 5, 8, 2]);
console.log(kthLargest.add(3)); // 4
console.log(kthLargest.add(5)); // 5
console.log(kthLargest.add(10)); // 5
console.log(kthLargest.add(9)); // 8
```

```typescript
class MedianFinder {
  private lower = new Heap<number>((a, b) => b - a); // actual max-heap
  private upper = new MinHeap();
  addNum(value: number): void {
    this.lower.push(value);
    this.upper.push(this.lower.pop()!);
    if (this.upper.size() > this.lower.size()) this.lower.push(this.upper.pop()!);
  }
  findMedian(): number {
    if (this.lower.size() === 0) throw new RangeError("empty stream");
    if (this.lower.size() > this.upper.size()) return this.lower.peek()!;
    return this.lower.peek()! / 2 + this.upper.peek()! / 2;
  }
}

// Example
const medianFinder = new MedianFinder();
medianFinder.addNum(1);
medianFinder.addNum(2);
console.log(medianFinder.findMedian()); // 1.5
medianFinder.addNum(3);
console.log(medianFinder.findMedian()); // 2
```

The lower heap contains the smaller half; every lower value is at most every upper value, and its size equals the upper size or exceeds it by one. Those two invariants make the roots sufficient to compute the median.

## 4. Rank Frequencies, Merge Lists and Cool Down Tasks

Count occurrences first, then keep k distinct values ranked by their counts. The min-heap root is the weakest retained count and is evicted when the heap grows. Ties at the cutoff permit several valid sets; add a secondary comparator if the product requires deterministic tie-breaking.

```typescript
function topKFrequent(nums: number[], k: number): number[] {
  const freq = new Map<number, number>();
  for (const num of nums) {
    freq.set(num, (freq.get(num) || 0) + 1);
  }

  if (!Number.isInteger(k) || k < 0 || k > freq.size) throw new RangeError("invalid k");
  if (k === 0) return [];
  const heap = new Heap<[number, number]>((a, b) => a[1] - b[1]);
  for (const [num, frequency] of freq) {
    heap.push([num, frequency]);
    if (heap.size() > k) heap.pop();
  }
  const result: number[] = [];
  while (heap.size() > 0) result.push(heap.pop()![0]);
  return result; // top-k set; ordering is not guaranteed
}

// Example
console.log(topKFrequent([1, 1, 1, 2, 2, 3], 2)); // values 1 and 2, in unspecified order
console.log(topKFrequent([1], 1)); // [1]
```

Contract: sorted, acyclic, disjoint input lists. The function reuses their nodes and rewires links. At most K current heads are queued, so N total nodes cost O(N log K) time and O(K) heap storage.

```typescript
class ListNode {
  val: number;
  next: ListNode | null;
  constructor(val?: number, next?: ListNode | null) {
    this.val = val ?? 0;
    this.next = next ?? null;
  }
}

function mergeKLists(lists: (ListNode | null)[]): ListNode | null {
  const heap = new Heap<ListNode>((a, b) => a.val - b.val);
  for (const node of lists) if (node) heap.push(node);
  const dummy = new ListNode();
  let current = dummy;
  while (heap.size() > 0) {
    const node = heap.pop()!;
    if (node.next) heap.push(node.next);
    current.next = node;
    current = node;
  }
  current.next = null;
  return dummy.next;
}
```

Contract: one CPU slot per task, identical task names need n intervening slots, and task order may be rearranged. One round has n+1 slots and takes each selected task type at most once. Hold unfinished counts outside the heap until the round ends; otherwise the same type could run again before its cooldown. Only a nonfinal round needs the remaining idle slots. This returns the minimum slot count, not an executable wall-clock schedule.

```typescript
function leastInterval(tasks: string[], n: number): number {
  const freq = new Map<string, number>();
  for (const task of tasks) {
    freq.set(task, (freq.get(task) || 0) + 1);
  }

  if (!Number.isInteger(n) || n < 0) throw new RangeError("nonnegative cooldown required");
  const heap = new Heap<number>((a, b) => b - a, [...freq.values()]);
  let time = 0;
  while (heap.size() > 0) {
    const remaining: number[] = [];
    let processed = 0;
    while (processed <= n && heap.size() > 0) {
      const frequency = heap.pop()!;
      if (frequency > 1) remaining.push(frequency - 1);
      processed++;
      time++;
    }
    for (const frequency of remaining) heap.push(frequency);
    if (heap.size() > 0) time += n + 1 - processed;
  }
  return time;
}

// Example
console.log(leastInterval(["A","A","A","B","B","B"], 2)); // 8
```

## Real-World Use Cases

Reach for heaps for kth largest and smallest elements, stream medians, priority task scheduling, merging k sorted lists and arrays, top-k frequent elements, and any problem needing efficient min/max access.

- **Establish the invariant**: Kth Largest Element in a Stream (LeetCode 703); Last Stone Weight (LeetCode 1046).
- **Combine the structures**: Top K Frequent Elements (LeetCode 347); Task Scheduler (LeetCode 621); Reorganize String (LeetCode 767); Kth Smallest Element in a Sorted Matrix (LeetCode 378); Find K Pairs with Smallest Sums (LeetCode 373).
- **Extend the constraints**: Find Median from Data Stream (LeetCode 295); Merge K Sorted Lists (LeetCode 23); Smallest Range Covering Elements from K Lists (LeetCode 632); IPO (LeetCode 502).

## Common Mistakes

1. **Wrong priority direction**: A bounded largest-k set uses a min-heap, while extracting the next largest uses a max-heap.

2. **Not maintaining heap after operations**: Always bubble up/down after push/pop

3. **Assuming equal-priority stability**: Heap order does not promise arrival order for ties; encode that requirement explicitly.

4. **Not handling edge cases**: Empty heap, single element, all same values

5. **Sorting after every operation**: Use sift-up/sift-down; heap order is partial, not a fully sorted array

These examples assume finite numeric values and a consistent comparator. The generic constructor copies input and heapifies bottom-up; a comparator must not depend on priorities that mutate invisibly while an item is queued. `KthLargest.add` returns null until k values have arrived, because a kth-largest value does not yet exist.

## Performance Considerations

| Operation | Time | Space |
| --------------------------------------- | ----------------------------------------------------- | ------------------------------------- |
| Insert | O(log n) repair; array growth can add allocation cost | O(1) repair state plus stored element |
| Remove root | O(log n) | O(1) repair state |
| Peek | O(1) | O(1) |
| Build Heap | O(n) | O(n) |
| In-place heap sort (separate algorithm) | O(n log n) | O(1) workspace |

The displayed constructor allocates a copy, so building it needs O(n) storage. Arbitrary deletion needs a way to locate the item plus repair; it is not the same operation as removing the root. Lazy deletion can retain stale items and needs a cleanup policy.

## Summary

Heaps maintain just enough order to extract the next extremum repeatedly: a bounded min-heap retains the largest k arrivals, two balanced halves locate a stream median, and a frequency or head-node heap merges ranked candidates. Use a min-heap for bounded largest-k sets and a max-heap for next-largest extraction, repair positions after every mutation, and never assume tie stability.

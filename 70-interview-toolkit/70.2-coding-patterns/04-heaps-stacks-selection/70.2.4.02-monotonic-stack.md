# Monotonic Stack

Given daily temperatures, find the next warmer day for every date. Comparing each day with every later day costs O(n²); a monotonic stack lets each unresolved day enter and leave once.

## Definition

A **monotonic stack** is a stack that maintains its elements in increasing or decreasing order, with equal-value handling chosen for the problem as you push and pop. It's the right pattern for "next greater/smaller element" problems, because when a new element arrives, you can resolve or discard each pending element at most once. A single arrival may pop many items, but total work across n arrivals remains O(n). The two flavors:

> **Textbook Definition:** A monotonic stack retains candidate elements in a chosen order, discarding candidates invalidated by new input. When each element is pushed and popped at most once, total stack work is linear.

- **Monotonic increasing stack** (bottom to top: increasing): the top has the **largest** value among the retained candidates; useful for "next smaller element"
- **Monotonic decreasing stack** (bottom to top: decreasing): the top has the **smallest** value among the retained candidates; useful for "next greater element"

## First Principles

Monotonic stacks answer "nearest smaller/greater element" by *amortizing discards*:

1. **Each candidate is handled once**: an index enters the stack once and leaves at most once. One input value may trigger many pops, but the total number of pops across the scan is at most n, so total work is O(n). This is an amortized bound.
2. **A pop has a reason**: in a left-to-right next-greater scan, the current value is the first greater value seen for every index it pops. In a histogram, a shorter bar fixes a popped bar’s right boundary; the new stack top supplies its nearest smaller left boundary. State whether equal values count, because that changes which candidates are popped.

## When to Use

- **"Next greater/smaller element"**: for each element, find the nearest element to its right that is greater/smaller
- **Largest rectangle in histogram**: for each bar, find the nearest smaller bar on each side (using monotonic stack)
- **Trapping rain water**: monotonic stack of bar heights, pop when current is taller, compute trapped water
- **Stock span**: for each day's price, count consecutive days with price ≤ today
- **Removing K digits**: discard larger earlier digits while deletion budget remains; asteroid collision is a related general stack simulation, not necessarily a monotonic stack
- **Look for:** per-element nearest greater/smaller neighbors where a quadratic scan repeats comparisons

## How It Works

```text
INPUT: [2, 1, 2, 4, 3] GOAL: next greater element for each index

Step-by-step with decreasing stack (top = index of "next greater" answer pending):

i=0, val=2 | stack=[] → push 0 | stack=[0]
            | No popped (stack empty)
i=1, val=1 | stack=[0], top has 2 → 2 < 1 ? NO (1 < 2, but we want next GREATER, so keep 0)
            | (we only pop if top's val < current val)
            | push 1 | stack=[0,1]
i=2, val=2 | stack=[0,1], top is 1 → 1 < 2? YES → pop 1, result[1] = 2
            | stack=[0], top is 0 → 2 < 2? NO (not strict)
            | push 2 | stack=[0,2]
i=3, val=4 | stack=[0,2] → 2 < 4? YES → pop 2, result[2] = 4
            | → value at index 0 is 2 < 4? YES → pop 0, result[0] = 4
            | push 3 | stack=[3]
i=4, val=3 | stack=[3], top is 3 → 4 < 3? NO
            | push 4 | stack=[3,4]
End: indices 3 and 4 still in stack → result[3] = -1, result[4] = -1

RESULT: [4, 2, 4, -1, -1]
```

Each element is **pushed exactly once** and **popped at most once** → O(2n) = O(n) total work.

## Template

These examples assume finite values and safe-integer area results. Use indices because duplicate values can have different distances and widths. The `-1` result in next-greater examples is a missing-value sentinel; use a separate presence flag if `-1` is a valid answer. For strictly greater queries, equal values remain pending; changing `<` to `<=` changes the question to greater-or-equal.

```typescript
// Next Greater Element (decreasing stack)
function nextGreaterElements(nums: number[]): number[] {
  const n = nums.length;
  const result = new Array(n).fill(-1);
  const stack: number[] = []; // stores INDICES of elements waiting for their "next greater"

  for (let i = 0; i < n; i++) {
    // Pop elements that have found their next greater element (current num)
    while (stack.length > 0 && nums[stack[stack.length - 1]] < nums[i]) {
      const idx = stack.pop()!;
      result[idx] = nums[i];
    }
    stack.push(i);
  }

  return result;
}


```

## Code Examples (TypeScript)

### Example 1: Daily Temperatures (LeetCode 739)

```typescript
/**
 * Given daily temperatures, return an array answer such that
 * answer[i] is the number of days until a warmer temperature.
 * If no future day is warmer, answer[i] = 0.
 */
function dailyTemperatures(temperatures: number[]): number[] {
  const n = temperatures.length;
  const result = new Array(n).fill(0);
  const stack: number[] = []; // indices of days waiting for a warmer day

  for (let i = 0; i < n; i++) {
    while (stack.length > 0 && temperatures[stack[stack.length - 1]] < temperatures[i]) {
      const prevDay = stack.pop()!;
      result[prevDay] = i - prevDay; // days until warmer
    }
    stack.push(i);
  }

  return result;
}

// Example
console.log(dailyTemperatures([73, 74, 75, 71, 69, 72, 76, 73]));
// [1, 1, 4, 2, 1, 1, 0, 0]
```

### Example 2: Largest Rectangle in Histogram (LeetCode 84)

Heights are nonnegative. When a shorter bar arrives at i, a popped bar cannot extend farther right at its own height. The new stack top gives its left boundary, so its width is i−left−1. Equal heights may remain; the earlier equal bar eventually accounts for the wider rectangle. A final −1 sentinel flushes all real heights.

```typescript
function largestRectangleArea(heights: number[]): number {
  const stack: number[] = []; // increasing stack of indices
  let maxArea = 0;

  for (let i = 0; i <= heights.length; i++) {
    // Nonnegative-height contract: sentinel -1 flushes all retained bars
    const h = i < heights.length ? heights[i] : -1;

    while (stack.length > 0 && heights[stack[stack.length - 1]] > h) {
      const height = heights[stack.pop()!];
      // Left boundary is the new top, or index -1 when the stack is empty
      const width = stack.length === 0 ? i : i - stack[stack.length - 1] - 1;
      maxArea = Math.max(maxArea, height * width);
    }

    if (i < heights.length) stack.push(i);
  }

  return maxArea;
}

// Example
console.log(largestRectangleArea([2, 1, 5, 6, 2, 3]));
// 10 (height 5 spans indices [2,3], giving 5*2)
```

### Example 3: Trapping Rain Water — One-Dimensional Stack

For nonnegative heights, popping a low bottom exposes a left wall while the incoming bar supplies a right wall. Water above that bottom reaches the lower wall; multiplying this depth by the interior width adds one layer. Without a left wall, that layer cannot hold water. The two-pointer alternative has its own canonical treatment in [Two Pointers](../01-linear-structures/70.2.1.02-two-pointers.md).

```typescript
function trap1D(height: number[]): number {
  const stack: number[] = [];
  let totalWater = 0;
  let i = 0;

  while (i < height.length) {
    while (stack.length > 0 && height[stack[stack.length - 1]] < height[i]) {
      const bottom = stack.pop()!;
      if (stack.length === 0) break;
      const left = stack[stack.length - 1];
      const width = i - left - 1;
      const boundedHeight = Math.min(height[left], height[i]) - height[bottom];
      totalWater += width * boundedHeight;
    }
    stack.push(i);
    i++;
  }

  return totalWater;
}

console.log(trap1D([0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]));
// 6
```

### Example 4: Next Greater Element in Circular Array (LeetCode 503)

The second pass offers earlier values to indices still waiting after the first pass. Push each original index only once, so wrapping does not create duplicate pending answers. Strictly greater prevents an index from satisfying itself.

```typescript
function nextGreaterElementsCircular(nums: number[]): number[] {
  const n = nums.length;
  const result = new Array(n).fill(-1);
  const stack: number[] = [];

  // Traverse twice to handle circular wrap-around
  for (let i = 0; i < 2 * n; i++) {
    const idx = i % n;

    while (stack.length > 0 && nums[stack[stack.length - 1]] < nums[idx]) {
      const prevIdx = stack.pop()!;
      result[prevIdx] = nums[idx];
    }

    // Only push the first n indices (avoid double-pushing)
    if (i < n) stack.push(idx);
  }

  return result;
}

console.log(nextGreaterElementsCircular([1, 2, 1]));
// [2, -1, 2]
```

## Common Mistakes

- **Leaving unresolved bars:** finish histogram processing with an explicit drain or a sentinel below the nonnegative input range.
- **Comparing indices as heights:** store indices for position-based answers, then compare their input values.
- **Changing the tie rule:** strict next-greater retains equals. Greater-or-equal resolves them. Contribution counting generally needs asymmetric strict/non-strict boundaries to avoid double-counting equal minima.
- **Discarding without a proof:** a pop must resolve the candidate or prove that another candidate dominates it for all later uses. Merely retaining sorted values is not sufficient.

| Operation | Time | Space |
| ------------------------------ | ---- | ----- |
| Next greater/smaller element | O(n) | O(n) |
| Largest rectangle in histogram | O(n) | O(n) |
| Trapping rain water (1D) | O(n) | O(n) |
| Stock span | O(n) | O(n) |
| Next greater in circular array | O(n) | O(n) |

The amortized O(n) bound comes from the fact that each element is pushed exactly once and popped at most once across the entire traversal.

## Summary

- Monotonic stack solves **"next greater/smaller"** problems in **O(n) total** by maintaining elements in sorted order
- Two flavors: **decreasing stack** for next greater; **increasing stack** for next smaller
- Each element is pushed once and popped at most once → amortized O(1) per element
- Canonical problems: **Daily Temperatures, Largest Rectangle in Histogram, Trapping Rain Water, Next Greater Element**
- For circular array: traverse **2n times** with `i % n`, only push the first n indices
- For histogram: use **sentinel below the allowed nonnegative heights** at the end to force the stack to flush
- Senior signal: explain why a popped candidate is resolved or dominated, and account for equal values explicitly
- **Avoid**: wrong direction (increasing vs. decreasing), strict vs. non-strict inequality, missing sentinel for histogram

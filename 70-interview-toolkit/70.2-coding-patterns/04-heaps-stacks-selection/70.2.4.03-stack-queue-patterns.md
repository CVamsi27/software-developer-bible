# Stack & Queue Patterns

A closing bracket must match the most recent unmatched opener, while a work queue should process the oldest accepted task. The required access order tells you whether the problem calls for a stack or a queue.

```typescript
isValid("()[]{}"); // true — every opener matched in LIFO order
isValid("([)]");   // false — counts alone would wrongly accept this
```

## Definition

**Stacks** (last in, first out; LIFO) and **queues** (first in, first out; FIFO) power interview problems well beyond basic push and pop: maintaining state (next greater, balanced brackets, sliding-window max) or simulating a process (BFS traversal, task scheduling, rate limiting).

> **Textbook Definition:** A stack removes the most recently inserted element, while a queue removes the earliest. These access disciplines encode nested computation or ordered processing; composite forms add further invariants.

## First Principles

Stacks and queues encode *processing order policies*. LIFO and FIFO encode different policies: undo, parsing and the [call stack](../../../10-frontend/10.1-javascript/01-execution-and-scope/10.1.1.03-call-stack.md) need most-recent-first; scheduling and [BFS](../02-graphs-trees-grids/70.2.2.01-dfs-bfs.md) need first-come-first-served. Emulation makes that order visible: a queue implemented with two stacks is amortized O(1) per operation because each item moves at most once into and once out of the output stack. Capacity, empty behavior, storage and concurrency remain separate parts of the implementation contract.

## How It Works

### 1. Match the Access Order to the Domain

- **Monotonic stack/deque** maintains elements in sorted order — covered in [Monotonic Stack](70.2.4.02-monotonic-stack.md).
- **Two-stack queue** implements a queue using two stacks (O(1) amortized).
- **Sliding window with deque** maintains max/min over a window in O(n).
- **BFS with queue** finds shortest paths in unweighted graphs.

Reach for a **stack** for balanced brackets (push opening, pop on closing), expression evaluation (operands and operators), next greater and smaller elements, iterative DFS (explicit stack avoids overflow), undo/redo operation stacks, and simulated call stacks. Reach for a **queue or deque** for BFS (shortest path, level-order), sliding window max/min via monotonic deque, producer-consumer handoffs, rate limiting with sliding timestamp logs, round-robin task scheduling, and LRU caches — where a hashmap plus doubly-linked list (a plain FIFO queue cannot move an arbitrary key efficiently) supplies the ordering. Tree traversal implementations belong in [DFS & BFS](../02-graphs-trees-grids/70.2.2.01-dfs-bfs.md); this chapter focuses on stateful structures: minimum stacks, two-stack queues, a deque, and an LRU ordering policy.

### 2. Trace Monotonic Deque and LRU Mechanics

```text
nums = [1, 3, -1, -3, 5, 3, 6, 7], k = 3

i=0, val=1: deque=[0] (values: [1])
i=1, val=3: pop 0 (1<3), deque=[1] (values: [3])
i=2, val=-1: deque=[1, 2] (values: [3, -1])
             i >= k-1, push nums[deque[0]]=3 to result
i=3, val=-3: deque=[1, 2, 3] (values: [3, -1, -3])
             shift if deque[0] <= 0 → 1>0, keep
             push nums[deque[0]]=3 to result
i=4, val=5: pop 3 (-3<5), pop 2 (-1<5), pop 1 (3<5)
             deque=[4] (values: [5])
             push 5 to result
i=5, val=3: deque=[4, 5] (values: [5, 3])
             shift if deque[0] <= 2 → 4>2, keep
             push 5 to result
i=6, val=6: pop 5 (3<6), pop 4 (5<6)
             deque=[6] (values: [6])
             push 6 to result
i=7, val=7: pop 6 (6<7)
             deque=[7] (values: [7])
             push 7 to result

Result: [3, 3, 5, 5, 6, 7]
```

```text
JavaScript Map preserves insertion order (Java HashMap does not; LinkedHashMap does)
So we can use Map as a combination of hashmap + insertion-order tracking

put(1, A): cache = {1: A}
put(2, B): cache = {1: A, 2: B}
put(3, C): cache = {1: A, 2: B, 3: C}
get(1): move 1 to end → cache = {2: B, 3: C, 1: A}
put(4, D): evict LRU (2) → cache = {3: C, 1: A, 4: D}
```

### 3. Validate Brackets, Track Minimums and Evaluate RPN

Contract: input contains only the six bracket characters. The latest unmatched opening must match the next closing; checking counts alone would wrongly accept ([)]. An empty stack at the end means every opening was matched.

```typescript
function isValid(s: string): boolean {
  const stack: string[] = [];
  const pairs: Record<string, string> = { ')': '(', ']': '[', '}': '{' };

  for (const c of s) {
    if (c in pairs) {
      if (stack.pop() !== pairs[c]) return false;
    } else {
      stack.push(c);
    }
  }
  return stack.length === 0;
}

console.log(isValid("()[]{}")); // true
console.log(isValid("([)]")); // false
```

Use finite numbers and call pop, top and getMin only on a nonempty stack, matching the exercise contract. Push a duplicate minimum onto the auxiliary stack too: after popping one copy, the other copy must still be available as the minimum.

```typescript
class MinStack {
  private stack: number[] = [];
  private minStack: number[] = []; // parallel stack tracking current min

  push(val: number): void {
    this.stack.push(val);
    if (this.minStack.length === 0 || val <= this.minStack[this.minStack.length - 1]) {
      this.minStack.push(val);
    }
  }

  pop(): void {
    const popped = this.stack.pop()!;
    if (popped === this.minStack[this.minStack.length - 1]) {
      this.minStack.pop();
    }
  }

  top(): number { return this.stack[this.stack.length - 1]; }
  getMin(): number { return this.minStack[this.minStack.length - 1]; }
}
```

**Reverse Polish notation** places each operator after its operands. Assume a well-formed expression of integer tokens and these four operators, no division by zero, and arithmetic within the required Number precision. Pop b before a so a−b and a/b preserve order; division truncates toward zero. This compact helper does not validate malformed expressions.

```typescript
function evalRPN(tokens: string[]): number {
  const stack: number[] = [];
  const ops: Record<string, (a: number, b: number) => number> = {
    '+': (a, b) => a + b,
    '-': (a, b) => a - b,
    '*': (a, b) => a * b,
    '/': (a, b) => Math.trunc(a / b),
  };

  for (const token of tokens) {
    if (token in ops) {
      const b = stack.pop()!;
      const a = stack.pop()!;
      stack.push(ops[token](a, b));
    } else {
      stack.push(Number(token));
    }
  }

  return stack[0];
}

console.log(evalRPN(["2", "1", "+", "3", "*"])); // 9
console.log(evalRPN(["4", "13", "5", "/", "+"])); // 6
```

### 4. Bound Windows, Rings and Two-Stack Queues

```typescript
function maxSlidingWindow(nums: number[], k: number): number[] {
  if (!Number.isInteger(k) || k < 1 || k > nums.length) {
    throw new RangeError("window must fit the input");
  }
  const result: number[] = [];
  const deque = new Map<number, number>(); // slot → input index
  let head = 0, tail = 0;
  for (let i = 0; i < nums.length; i++) {
    while (head < tail && deque.get(head)! <= i - k) deque.delete(head++);
    while (head < tail && nums[deque.get(tail - 1)!] < nums[i]) deque.delete(--tail);
    deque.set(tail++, i);
    if (i >= k - 1) result.push(nums[deque.get(head)!]);
  }
  return result;
}

console.log(maxSlidingWindow([1, 3, -1, -3, 5, 3, 6, 7], 3));
// [3, 3, 5, 5, 6, 7]
```

Head identifies the oldest item; tail identifies the next insertion slot. They can be equal in both empty and full states, so size distinguishes them. Modulo arithmetic wraps indices within the fixed array. Full insertion and empty removal return false; Front and Rear use the exercise's −1 empty sentinel.

```typescript
class MyCircularQueue {
  private data: number[];
  private head: number = 0;
  private tail: number = 0;
  private size: number = 0;
  private capacity: number;

  constructor(k: number) {
    if (!Number.isInteger(k) || k < 1) throw new RangeError("positive capacity required");
    this.capacity = k;
    this.data = new Array(k);
  }

  enQueue(value: number): boolean {
    if (this.isFull()) return false;
    this.data[this.tail] = value;
    this.tail = (this.tail + 1) % this.capacity;
    this.size++;
    return true;
  }

  deQueue(): boolean {
    if (this.isEmpty()) return false;
    this.head = (this.head + 1) % this.capacity;
    this.size--;
    return true;
  }

  Front(): number {
    return this.isEmpty() ? -1 : this.data[this.head];
  }

  Rear(): number {
    return this.isEmpty() ? -1 : this.data[(this.tail - 1 + this.capacity) % this.capacity];
  }

  isEmpty(): boolean { return this.size === 0; }
  isFull(): boolean { return this.size === this.capacity; }
}
```

Enqueue 1,2,3 into the input stack. Transferring all three into an empty output stack reverses them, leaving 1 on top. Never transfer again while older items remain there: enqueueing 4 must not place it ahead of 2 and 3. A transfer can take O(n), but each item crosses once, giving amortized constant work per operation.

```typescript
class MyQueue {
  private inStack: number[] = []; // for enqueue
  private outStack: number[] = []; // for dequeue/peek

  push(x: number): void {
    this.inStack.push(x);
  }

  pop(): number {
    this.peek();
    return this.outStack.pop()!;
  }

  peek(): number {
    if (this.empty()) throw new RangeError("empty queue");
    if (this.outStack.length === 0) {
      while (this.inStack.length > 0) {
        this.outStack.push(this.inStack.pop()!);
      }
    }
    return this.outStack[this.outStack.length - 1];
  }

  empty(): boolean {
    return this.inStack.length === 0 && this.outStack.length === 0;
  }
}

// Amortized O(1) per operation: each element is moved at most twice
```

### 5. Evict Least-Recently-Used Entries With Map Order

Deleting and reinserting a key moves it to the end of Map's insertion order. A separate doubly linked list is unnecessary for this JavaScript example. The `-1` miss sentinel follows the interview problem's contract; use a different API if `-1` can be a meaningful stored value.

```typescript
class LRUCache<K, V> {
  private capacity: number;
  private cache: Map<K, V>;

  constructor(capacity: number) {
    if (!Number.isInteger(capacity) || capacity < 1) throw new RangeError("positive capacity required");
    this.capacity = capacity;
    this.cache = new Map();
  }

  get(key: K): V | -1 {
    if (!this.cache.has(key)) return -1;
    const value = this.cache.get(key)!;
    // Move to end (most recently used)
    this.cache.delete(key);
    this.cache.set(key, value);
    return value;
  }

  put(key: K, value: V): void {
    if (this.cache.has(key)) this.cache.delete(key);
    else if (this.cache.size >= this.capacity) {
      // Evict the least recently used (first inserted)
      const oldest = this.cache.keys().next();
      if (!oldest.done) this.cache.delete(oldest.value);
    }
    this.cache.set(key, value);
  }
}
```

## Real-World Use Cases

- **Establish the invariant**: Valid Parentheses (LeetCode 20) — basic stack; Min Stack (LeetCode 155, Medium) — auxiliary stack; Implement Queue using Stacks (LeetCode 232) — two-stack trick; Implement Stack using Queues (LeetCode 225) — single-queue or two-queue; Design Circular Queue (LeetCode 622, Medium) — array with two pointers.
- **Combine the structures**: Evaluate Reverse Polish Notation (LeetCode 150) — stack with operators; Sliding Window Maximum (LeetCode 239, Hard) — monotonic deque; Daily Temperatures (LeetCode 739) — monotonic stack; LRU Cache (LeetCode 146) — hashmap + linked list; Binary Tree Level Order Traversal (LeetCode 102) — BFS; Decode String (LeetCode 394) — stack with count + string; Asteroid Collision (LeetCode 735) — stack with conditional pops.
- **Extend the constraints**: Maximal Rectangle (LeetCode 85) — stack of heights; Longest Valid Parentheses (LeetCode 32) — stack with sentinel; Basic Calculator (LeetCode 224) — stack of operators; LFU Cache (LeetCode 460) — doubly-linked list + frequency map; Shortest Subarray with Sum at Least K (LeetCode 862) — monotonic deque.

## Common Mistakes

- **Front-removing a dense array repeatedly:** repeated shift operations can move or reindex later entries. Use a head cursor, ring buffer or deque when the cost argument requires cheap front removal; reclaim processed storage if a queue lives indefinitely.
- **Mixing ring-buffer conventions:** tail is the next insertion slot, not the last stored element. Keep size to distinguish head=tail when empty versus full.
- **Forgetting indices in a window deque:** values alone cannot determine which duplicate occurrence has expired.
- **Confusing ordered storage with recency:** Map.set on an existing key does not move it to the end; delete then reinsert to record a cache hit or replacement as most recent.
- **Treating an in-memory queue as delivery infrastructure:** thread safety, durability, acknowledgment and repeated-effect handling are separate responsibilities.

## Performance Considerations

| Operation | Stack | Queue | Deque |
| ------------ | ----- | ----- | ----- |
| Push/Enqueue | O(1) | O(1) | O(1) |
| Pop/Dequeue | O(1) | O(1) | O(1) |
| Peek | O(1) | O(1) | O(1) |
| Search | O(n) | O(n) | O(n) |
| Build | O(n) | O(n) | O(n) |

| Pattern | Time | Space |
| ---------------------- | ---------------------------------------------------- | ----------- |
| Balanced brackets | O(n) | O(n) |
| Sliding window max/min | O(n) | O(k) |
| Min stack | O(1) per op | O(n) |
| BFS | O(V+E) | O(V) |
| Iterative DFS | O(V+E) | O(V) |
| LRU cache | Expected O(1) per op with common Map implementations | O(capacity) |

The abstract operation table assumes suitable storage. Array growth is amortized, a two-stack queue can have one linear transfer, and ECMAScript specifies average sublinear Map access rather than a universal O(1) implementation. A local queue also provides no cross-process durability, locking or retry protocol.

## Summary

Stacks serve nested, most-recent-first work — balanced brackets, expression evaluation, next-greater queries, undo histories and iterative DFS — while queues serve oldest-first work such as BFS, producer-consumer handoffs and scheduling. Deques add monotonic windowed max and min in amortized linear time, and Map insertion order supplies an LRU eviction policy without a separate linked list. Choose the structure from the domain's required access order, watch for shift costs and deque direction confusion, and never mistake an in-memory queue for delivery infrastructure.

# Quick Select & Reservoir Sampling

If you need the median of an unsorted array, sorting computes more order than one rank requires. If you need a sample from a stream whose final length is unknown, you cannot choose the sample positions in advance. Quickselect and reservoir sampling solve these distinct problems.

```typescript
findKthLargest([3, 2, 1, 5, 6, 4], 2); // 5 — one rank, no full sort
```

## Definition

**Quick Select** finds the **k-th smallest (or largest) element** in an unordered array in **expected O(n)** time with uniformly sampled pivots and **worst-case O(n²)** time. It uses QuickSort's partition step but continues only in the region containing the target rank. **Reservoir Sampling** selects a **uniform random sample of k items from a stream of unknown size n** in **O(n) time and O(k) space**: each new item replaces a random reservoir element with probability k/i for 1-based position i.

> **Textbook Definition:** Quickselect finds an order statistic by partitioning and retaining the relevant side. Reservoir sampling maintains a uniformly chosen fixed-size sample as items arrive without requiring the final stream length.

## First Principles

Both algorithms exploit *sampling without full order*. **Quickselect** partitions like quicksort but continues into one side only: once partitioning shows which region contains the target rank, the other regions need no more work. Independent uniformly sampled pivots give expected O(n); median-of-medians can guarantee O(n) worst-case time at the cost of a more involved pivot-selection algorithm. **Reservoir sampling** solves "uniform sample of unknown length": each item's final inclusion probability k/n is an exchange argument over stream position. Unknown length prevents choosing final indices in advance; the reservoir maintains a bounded sample as items arrive.

## How It Works

### 1. Retain Only the Region Containing the Target Rank

```text
Find rank k=3 in [3,2,1,5,4]; absolute target index is 2.

pivot 4 → smaller [3,2,1] | equal [4] | greater [5]
Target 2 is in the smaller region: retain [3,2,1].

pivot 1 → smaller [] | equal [1] | greater [3,2]
Target 2 is in the greater region: retain [3,2].

pivot 2 → smaller [] | equal [2] | greater [3]
Target 2 lies after the equal region: retain [3], then return 3.

The answer is 3; partitioned regions need not be internally sorted.
```

### 2. Keep Every Subset Equally Likely as the Stream Grows

```text
Goal: Pick k items from a stream of size n, each subset of size k equally likely.

Algorithm R:
  Fill reservoir with first k items
  For each i = k+1 to n:
    Pick random j in [0, i-1]
    If j < k, replace reservoir[j] with item[i]

Probability analysis (for any specific item m, m > k):
  P(item m is in reservoir) = P(m selected at step m) × P(not replaced in m+1..n)
                            = (k/m) × ((1 - 1/(m+1)) × ... × (1 - 1/n))
                            = (k/m) × (m/n)
                            = k/n

First-k items survive with product (1 - 1/(k+1)) ... (1 - 1/n) = k/n.
Algorithm R also maintains a uniform k-subset by induction: each new item
is admitted with probability k/i and replaces a uniformly chosen slot.
Equal individual inclusion probabilities alone would not prove uniform subsets.
```

### 3. Carry the Selection and Sampling Templates

The probability proofs assume independent uniform choices from each displayed integer range. Algorithm R returns a uniform sample after a finite stream ends; an unbounded stream needs a separate time window or population definition. `Math.random()` is a convenient demonstration source, not a security generator or an exact-uniformity guarantee from ECMAScript. Keep stream counters within exact Number integer range. Quickselect changes the input order; reservoir sampling selects arrival positions, so equal-valued items are still distinct candidates.

```typescript
// Quick Select: 1-based k; mutates nums; finite numeric values.
// Three-way partition groups equal values so duplicate-heavy input shrinks.
function quickSelect(nums: number[], k: number): number {
  if (!Number.isInteger(k) || k < 1 || k > nums.length) throw new RangeError("invalid k");
  const target = k - 1;
  let left = 0, right = nums.length - 1;
  while (left <= right) {
    const pivot = nums[left + Math.floor(Math.random() * (right - left + 1))];
    let smaller = left, scan = left, greater = right;
    while (scan <= greater) {
      if (nums[scan] < pivot) {
        [nums[scan], nums[smaller]] = [nums[smaller], nums[scan]];
        smaller++; scan++;
      } else if (nums[scan] > pivot) {
        [nums[scan], nums[greater]] = [nums[greater], nums[scan]];
        greater--;
      } else scan++;
    }
    if (target < smaller) right = smaller - 1;
    else if (target > greater) left = greater + 1;
    else return nums[target];
  }
  throw new Error("unreachable for valid numeric input");
}

// ==================== Reservoir Sampling (Algorithm R) ====================
function reservoirSample<T>(stream: Iterable<T>, k: number): T[] {
  if (!Number.isInteger(k) || k < 0) throw new RangeError("invalid sample size");
  const reservoir: T[] = [];
  let i = 0;

  for (const item of stream) {
    if (i < k) {
      reservoir.push(item); // fill the reservoir
    } else {
      // Replace a random element with probability k/(i+1)
      const j = Math.floor(Math.random() * (i + 1));
      if (j < k) {
        reservoir[j] = item;
      }
    }
    i++;
  }

  return reservoir;
}

// ==================== Fisher-Yates Shuffle ====================
function shuffle<T>(arr: T[]): T[] {
  const result = [...arr];
  for (let i = result.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [result[i], result[j]] = [result[j], result[i]];
  }
  return result;
}
```

### 4. Select Kth Largest and Top-k Frequent

```typescript
function findKthLargest(nums: number[], k: number): number {
  // Largest rank k corresponds to smallest rank n-k+1 (both 1-based)
  return quickSelect(nums, nums.length - k + 1);
}

console.log(findKthLargest([3, 2, 1, 5, 6, 4], 2)); // 5
```

```typescript
function topKFrequent(nums: number[], k: number): number[] {
  const count = new Map<number, number>();
  for (const n of nums) count.set(n, (count.get(n) || 0) + 1);

  if (!Number.isInteger(k) || k < 0 || k > count.size) throw new RangeError("invalid k");
  if (k === 0) return [];
  // Unique values, each with its count
  const unique = [...count.keys()];

  // Quick select by count (descending)
  return quickSelectByCount(unique, count, k);
}

function quickSelectByCount(unique: number[], count: Map<number, number>, k: number): number[] {
  let left = 0, right = unique.length - 1;
  const target = k - 1;
  while (left <= right) {
    const pivot = count.get(unique[left + Math.floor(Math.random() * (right - left + 1))])!;
    let higher = left, scan = left, lower = right;
    while (scan <= lower) {
      const frequency = count.get(unique[scan])!;
      if (frequency > pivot) {
        [unique[scan], unique[higher]] = [unique[higher], unique[scan]];
        higher++; scan++;
      } else if (frequency < pivot) {
        [unique[scan], unique[lower]] = [unique[lower], unique[scan]];
        lower--;
      } else scan++;
    }
    if (target < higher) right = higher - 1;
    else if (target > lower) left = lower + 1;
    else return unique.slice(0, k);
  }
  return unique.slice(0, k);
}

console.log(topKFrequent([1, 1, 1, 2, 2, 3], 2)); // [1, 2]
```

### 5. Sample Streams and Pick Random Indices

The class retains the same reservoir and arrival count across add calls. Its sample getter returns a copy so callers cannot alter stored positions. At k=2, the third arrival chooses j from 0,1,2: replace the corresponding slot for 0 or 1, and retain both previous items for 2. A stream shorter than k yields every available arrival.

```typescript
class StreamSampler<T> {
  private reservoir: T[];
  private k: number;
  private count: number = 0;

  constructor(k: number) {
    if (!Number.isInteger(k) || k < 0) throw new RangeError("invalid sample size");
    this.k = k;
    this.reservoir = [];
  }

  add(item: T): void {
    if (this.count < this.k) {
      this.reservoir.push(item);
    } else {
      const j = Math.floor(Math.random() * (this.count + 1));
      if (j < this.k) {
        this.reservoir[j] = item;
      }
    }
    this.count++;
  }

  getSample(): T[] {
    return [...this.reservoir];
  }
}

// Demonstrate processing 1M arrivals while retaining 100 positions
const sampler = new StreamSampler<number>(100);
for (let i = 0; i < 1_000_000; i++) {
  sampler.add(i);
}
console.log(sampler.getSample().length); // 100
console.log(sampler.getSample().slice(0, 5)); // e.g., [423801, 12734, ...]
```

Only matching positions enter the candidate stream. Increment the match count, then replace the chosen index with probability 1/count. A missing target returns −1. The constructor retains the original array reference; copy it if later caller mutation should not change the population.

```typescript
class Solution {
  private nums: number[];

  constructor(nums: number[]) {
    this.nums = nums;
  }

  pick(target: number): number {
    let count = 0;
    let result = -1;
    for (let i = 0; i < this.nums.length; i++) {
      if (this.nums[i] === target) {
        count++;
        // Reservoir with k=1: pick with probability 1/count
        if (Math.floor(Math.random() * count) === 0) {
          result = i;
        }
      }
    }
    return result;
  }
}
```

## Real-World Use Cases

Reach for **Quick Select** for kth smallest and largest elements in unsorted arrays, top-k elements where sorting can be avoided, and medians of available finite arrays (an ongoing stream usually needs a different structure). Reach for **Reservoir Sampling** for k random elements from unknown-size streams, uniform linked-list nodes without storing all nodes, random samples from database cursors, and weighted reservoirs (A-Res).

- **Select a rank**: Kth Largest Element in an Array (215) — partition an available array.
- **Select frequent values**: Top K Frequent Elements (347) — count, then partition by frequency.
- **Online rank maintenance**: Kth Largest Element in a Stream (703) — bounded heap, not repeated full selection.
- **Uniform matching index**: Random Pick Index (398) — reservoir of size one over matches.
- **Uniform list node**: Linked List Random Node (382) — reservoir of size one.
- **Uniform permutation**: Shuffle an Array (384) — Fisher–Yates, a separate operation.
- **Weighted single choice**: Random Pick with Weight (528) — prefix sums and binary search.

## Common Mistakes

- **Conflating absolute and relative ranks:** this quickselect keeps absolute target k−1 throughout. A recursive helper receiving a sliced region would need a different rank adjustment.
- **Treating randomization as a worst-case guarantee:** independent uniform pivots give expected linear work; a sequence of poor splits can still be quadratic. A three-way split handles equal values but does not eliminate that worst case on distinct inputs.
- **Using the previous stream length:** the ith zero-based arrival chooses j from 0..i, giving admission probability k/(i+1).
- **Promising uniform subsets from equal marginal probabilities alone:** verify the entire subset distribution or its induction invariant.
- **Rejecting sorting categorically:** sorting can be the clearer choice for small inputs or when later work needs full order. Compare that requirement with a single rank query.

## Performance Considerations

| Case | Time | Space |
| ------------------------------------- | ----- | ------------------------------ |
| Best | O(n) | O(1) iterative partition state |
| Expected (random pivot) | O(n) | O(1) iterative partition state |
| Worst (repeatedly poor pivots) | O(n²) | O(1) iterative partition state |

**With median-of-medians** pivot selection: guaranteed O(n) worst case, using a more involved pivot-selection procedure than this example.

| Algorithm | Time | Space | Notes |
| ---------------------------------- | -------------- | ----- | ------------------------------------ |
| Algorithm R (uniform) | O(n) | O(k) | Most common |
| Weighted reservoir with top-k keys | O(n log k) | O(k) | Different weighted sampling contract |

## Summary

Quickselect finds the k-th smallest element in expected O(n) time with uniformly sampled pivots by retaining only the region containing the target rank — not stable, with a possible quadratic worst case despite expected linearity. Reservoir sampling picks k uniform-random items from a stream in O(n) time and O(k) space, admitting each zero-based arrival i with probability k/(i+1). Recognize kth-element-in-an-available-array as quickselect, k-random-from-a-stream as reservoir sampling, and know both mathematical guarantees: expected linearity under uniform pivots, and uniform subsets by induction rather than marginal probabilities alone.

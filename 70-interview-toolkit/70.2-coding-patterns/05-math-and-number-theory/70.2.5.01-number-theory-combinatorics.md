# Number Theory & Combinatorics

A scheduler needs to count possible teams without listing every team, and the result may exceed a machine integer before the final modulo is applied. Number theory and combinatorics provide the counting argument and the arithmetic rules needed to keep that answer correct.

## Definition

Number theory studies divisibility, primes, and modular arithmetic. Combinatorics counts arrangements without enumerating each one. In coding problems, the difficult step is choosing a valid counting argument and an arithmetic representation that can hold every intermediate result.

> **Textbook Definition:** Number theory studies properties of integers, including divisibility and congruence; combinatorics studies discrete arrangements and their counts. Algorithmic use requires a valid counting argument and a suitable arithmetic representation.

If a problem requests an answer modulo a number, reduce additions and products as you go. Division requires an inverse only when that inverse exists. Reducing operands before multiplication **does not by itself prevent overflow**: the product of two residues may still exceed the language's integer range.

## First Principles

A divisor splits an integer into whole equal groups. If n has a nontrivial factor pair, at least one factor is no larger than its square root; testing beyond that point repeats the same pairs. Shared divisibility also survives replacing a number by its remainder, which is why Euclid's algorithm can shrink its inputs without losing their common divisors.

Counting starts with the outcomes that count as different. Choosing three ordered seats differs from choosing one unordered group of three. Derive how many choices remain at each step, then remove only the duplicated descriptions of the same outcome. A formula is useful only after those rules are fixed.


## Prime Numbers

A **prime** is an integer greater than 1 with no positive divisors other than 1 and itself. Trial division stops at i≤n/i, equivalent to i²≤n for positive integers but avoiding an overflowing multiplication. A sieve answers many primality questions together: once 2 is prime, cross out its multiples; after 3, cross out its remaining multiples. Start crossing out at p² because smaller multiples already have a smaller prime factor. Leave 0 and 1 unmarked as primes.

For a bound of 10, the prime positions are 2,3,5,7. `sieve(10)` includes position 10, while `countPrimes(10)` counts only values strictly below 10. Factorization repeatedly removes each divisor, so 12 becomes 2²×3; if a remainder above 1 survives the square-root search, it is itself prime.

The Java fragments below are instance methods in one class. Import `java.util.*`, put the fragments inside that class and call the desired method from a small harness. Sieve storage is proportional to the requested bound; a valid int is not automatically a practical allocation size.


```java
// Check if prime — O(√n)
boolean isPrime(int n) {
    if (n < 2) return false;
    for (int i = 2; i <= n / i; i++) {
        if (n % i == 0) return false;
    }
    return true;
}

// Sieve of Eratosthenes — O(n log log n)
boolean[] sieve(int n) {
    if (n < 0 || n == Integer.MAX_VALUE) throw new IllegalArgumentException();
    boolean[] isPrime = new boolean[n + 1];
    Arrays.fill(isPrime, true);
    isPrime[0] = false;
    if (n >= 1) isPrime[1] = false;

    for (int i = 2; i <= n / i; i++) {
        if (isPrime[i]) {
            for (long j = (long) i * i; j <= n; j += i) {
                isPrime[(int) j] = false;
            }
        }
    }
    return isPrime;
}

// Count primes strictly below n
int countPrimes(int n) {
    if (n < 0) throw new IllegalArgumentException();
    boolean[] isPrime = new boolean[n];
    Arrays.fill(isPrime, true);
    int count = 0;
    for (int i = 2; i < n; i++) {
        if (isPrime[i]) {
            count++;
            for (long j = (long) i * i; j < n; j += i) {
                isPrime[(int) j] = false;
            }
        }
    }
    return count;
}

// Prime Factorization
Map<Integer, Integer> primeFactorization(int n) {
    if (n < 1) throw new IllegalArgumentException();
    Map<Integer, Integer> factors = new HashMap<>();
    for (int i = 2; i <= n / i; i++) {
        while (n % i == 0) {
            factors.put(i, factors.getOrDefault(i, 0) + 1);
            n /= i;
        }
    }
    if (n > 1) factors.put(n, 1);
    return factors;
}

```

## GCD and LCM

The **greatest common divisor (GCD)** is the largest positive integer dividing both nonzero inputs. This helper convention returns 0 for gcd(0,0). The **least common multiple (LCM)** is the smallest positive multiple shared by two nonzero inputs, and the helper returns 0 if either input is zero.


For `gcd(48, 18)`, repeatedly replace the pair by `(b, a % b)`: `(48,18) → (18,12) → (12,6) → (6,0)`. Every common divisor survives the replacement, so the last nonzero remainder is the answer. The LCM formula divides before multiplying, but its result still needs a sufficiently wide type.


```java
// int inputs, nonnegative long result; handles Integer.MIN_VALUE safely.
long gcd(int first, int second) {
    long a = Math.abs((long) first), b = Math.abs((long) second);
    while (b != 0) {
        long remainder = a % b;
        a = b;
        b = remainder;
    }
    return a;
}

long lcm(int a, int b) {
    if (a == 0 || b == 0) return 0;
    // int magnitudes produce at most 2^62, which fits a long.
    return Math.abs(((long) a / gcd(a, b)) * b);
}

// Extended Euclidean: ax + by = gcd(a, b).
// Contract: 0 <= a, b <= Integer.MAX_VALUE; long intermediates.
long[] extendedGCD(long a, long b) {
    if (b == 0) return new long[]{a, 1, 0};
    long[] prev = extendedGCD(b, a % b);
    long gcd = prev[0];
    long x = prev[2];
    long y = prev[1] - (a / b) * prev[2];
    return new long[]{gcd, x, y};
}

```

## Modular Arithmetic

Modulo m groups integers by their remainder: 17 and 5 are **congruent modulo 12** because their difference is divisible by 12. Addition and multiplication preserve that relationship, so intermediate values can be reduced. Java's remainder operator can return a negative value; `floorMod` below normalizes a negative input into 0..MOD−1.

A **modular inverse** of a is a residue x such that a×x has remainder 1. Division by a modulo m means multiplication by this inverse, not integer division. For example, 3 has inverse 5 modulo 7 because 3×5=15 has remainder 1. By contrast, 2 has no inverse modulo 6 because its products always share the factor 2.

Repeated squaring computes an exponent without performing one multiplication per exponent unit. For 2¹³, start with result=1, base=2, exponent=13. An odd exponent multiplies result by base; then square base and halve the exponent. Repeat for exponents 6,3,1, reducing each product, until exponent 0. The invariant keeps result×base^exponent congruent to the requested power.


The Java examples deliberately use the fixed prime `1_000_000_007`: two reduced residues have a product below about `10^18`, within `long`. For arbitrary larger moduli use an overflow-safe multiplication algorithm or `BigInteger`. In JavaScript, integer products beyond `Number.MAX_SAFE_INTEGER` need `BigInt`. Fermat inversion requires a prime modulus and a nonzero residue; a general modulus needs `gcd(a, modulus) = 1`.

To choose r items from n distinct items without order, n!/(r!×(n−r)!) counts each group once. The denominator cancels permutations within the chosen and unchosen groups. Modulo the fixed prime below, multiply by its modular inverse. The factorial-based combination formula also requires `n < MOD`; otherwise factorials can become zero modulo `MOD` and the denominator may have no inverse. Large `n` requires a different method.


```java
final long MOD = 1_000_000_007L; // prime; residue products fit Java long

long residue(long value) {
    return Math.floorMod(value, MOD);
}

long addMod(long a, long b) {
    return (residue(a) + residue(b)) % MOD;
}

long mulMod(long a, long b) {
    return residue(a) * residue(b) % MOD;
}

long powerMod(long base, long exp) {
    if (exp < 0) throw new IllegalArgumentException("negative exponent");
    long result = 1;
    base = residue(base);
    while (exp > 0) {
        if ((exp & 1) != 0) result = result * base % MOD;
        exp >>= 1;
        base = base * base % MOD;
    }
    return result;
}

long modInverse(long a) {
    if (residue(a) == 0) throw new IllegalArgumentException("no inverse");
    return powerMod(a, MOD - 2); // nonzero residue, prime modulus
}

long nCr(int n, int r) {
    if (n < 0 || n >= MOD) throw new IllegalArgumentException();
    if (r < 0 || r > n) return 0;
    // O(n) memory/time: choose this only when n is feasible to allocate.
    long[] fact = new long[n + 1];
    fact[0] = 1;
    for (int i = 1; i <= n; i++) fact[i] = fact[i - 1] * i % MOD;
    long denominator = fact[r] * fact[n - r] % MOD;
    return fact[n] * modInverse(denominator) % MOD;
}

```

## Combinatorics and Probability

Choosing two ordered positions from four distinct candidates gives 4×3=12 outcomes. Choosing an unordered pair counts each pair twice, so divide by 2!: C(4,2)=6. Repetition would change that argument: two independent ordered choices with replacement give 4×4=16.

To distribute two identical items among three labeled bins, write two item marks and two separators. Choosing which two of the four positions hold the items gives C(4,2)=6 distributions. This **stars-and-bars** argument allows empty bins; requiring every bin to be nonempty first assigns one item to each and changes the remaining problem.

For a uniformly chosen unordered pair from four distinct candidates, one candidate appears with any of the other three. Its inclusion probability is 3/6=1/2. If two candidates are selected without replacement, their selections are dependent: after one is chosen, the chance of choosing another particular candidate in the next draw is 1/3, not 1/4. Use conditional probabilities or count the full equally likely sample space.

Enumeration is useful to check small formulas, but producing every arrangement still has output cost. Reuse the canonical [backtracking permutations and subsets](../03-recursion-and-optimization/70.2.3.01-backtracking.md) rather than treating a counting formula as an enumeration algorithm.

## Common Mistakes

- **Counting descriptions rather than outcomes:** decide whether order matters and whether choices can repeat before multiplying or dividing.
- **Dividing a residue directly:** use an inverse only when it exists; nonzero is not enough for a composite modulus.
- **Reducing after an overflowing product:** ensure the multiplication itself fits before applying the remainder.
- **Confusing a bound with a budget:** a sieve needs O(n) memory, and factorial tables rebuild O(n) work in this simple `nCr` helper.
- **Using uniform counts for biased outcomes:** favorable/total applies only to equally likely elementary outcomes. Independence is a separate condition.

## Cost and Numeric Boundaries

| Helper | Work | Retained storage |
| ----------------------------- | ------------------------------------ | ------------------------------------- |
| Trial primality/factorization | O(√n) trial steps | O(1) work state plus returned factors |
| Sieve/count-primes | O(n log log n) | O(n) |
| Euclid GCD | O(log max magnitude) remainder steps | O(1) iterative state |
| Modular power | O(log exponent) fixed-width products | O(1) |
| Factorial `nCr` shown | O(n + log MOD) | O(n) |

These are operation counts for the fixed-width types and stated bounds. Arbitrary-precision arithmetic adds operand-size costs. Extended Euclid uses logarithmic recursive depth and returns coefficients satisfying a×x+b×y=gcd(a,b); for coprime inputs, that identity supplies a general modular inverse after normalizing x.

## Summary

1. **Three templates carry most math problems** — sieve of Eratosthenes for primes, Euclid's algorithm for GCD/LCM, fast exponentiation for modular power
2. **Check intermediate ranges** — reducing residues helps, but the multiplication itself still needs a type or algorithm that can hold the product
3. **Counting without double-counting is the combinatorics game** — nCr via valid modular factorials, a multiplicative formula, or Pascal's row, complements ("total − invalid"), stars-and-bars for distributions
4. **Probability needs a sample space** — favorable/total for equally likely elementary outcomes; use conditional probabilities for dependent steps
5. **The skill being tested is recognition speed** — "primes up to N" → sieve, "pairs divisible by k" → modular buckets, "number of paths" → combinatorics, not simulation

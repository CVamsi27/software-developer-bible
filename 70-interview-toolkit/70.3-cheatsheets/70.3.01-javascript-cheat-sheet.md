# JavaScript Cheat Sheet

## Definition

JavaScript supplies the language rules for values, scope, objects, and functions. The host—such as a browser or Node.js—supplies scheduling, I/O, and other APIs. This reference follows one function call before comparing the features that affect it.

## First Principles

Code needs bindings to identify values, calls to execute work, and references to reach objects. Delayed work must resume through the host’s scheduling rules. Keeping those roles separate explains why a closure can retain a variable without retaining its original call stack, and why a promise does not create a worker thread.

## Trace a call and a delayed continuation

```javascript
function makeCounter() {
  let count = 0;
  return () => ++count;
}
const next = makeCounter();
console.log(next()); // 1
Promise.resolve().then(() => console.log(next()));
console.log(next()); // 2; the queued callback later logs 3
```

`makeCounter` returns, but the returned function still reaches the `count` binding. The promise callback queues a continuation; it does not interrupt the synchronous call that prints 2.

## Resolve names and choose the call receiver

| Role | Mechanism | Limit to remember |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Find a variable | Lexical environments link inner scope to outer scope; a closure retains access to those bindings | A `var` loop shares one binding; a `let` loop can create a binding per iteration |
| Create a binding | `var` is initialized to `undefined`; lexical `let`/`const` bindings remain inaccessible until initialization | Reading an uninitialized lexical binding throws, including `typeof` in its temporal dead zone |
| Choose `this` | Ordinary calls use their call form; `obj.method()` uses `obj`, while an extracted method loses that receiver | Strict plain calls have `undefined`; sloppy plain calls substitute the global object |
| Preserve lexical `this` | Arrows use the surrounding `this` | They cannot be constructors, rebound by `call`, or generator functions |
| Bind a receiver | `call`/`apply` invoke; `bind` creates a bound function | Calling a bound function with `new` uses construction semantics |
| Construct an instance | `new` creates a receiver and connects its prototype before calling the constructor | An explicit returned object can replace that receiver |
| Find an object property | Lookup follows `[[Prototype]]` until found or `null`; use `Object.getPrototypeOf` | Null-prototype objects lack inherited methods; not every function has a `.prototype` |
| Share class methods | Class instance methods live on the prototype; fields live on instances | Classes also have strict semantics, initialization rules, and private-field behavior |

Top-level `this` depends on the environment: a browser classic script uses its global object even when strict; an ES module uses `undefined`; Node.js CommonJS has its own wrapper. Do not substitute the strict-function rule for every top-level script.

## Resume asynchronous work

In a browser, a task runs synchronous code, then a microtask checkpoint drains queued promise reactions and `queueMicrotask` callbacks, including microtasks they enqueue. Rendering opportunities and later tasks follow host rules. A promise callback registered inside a later timer cannot run before that timer exists. An endless microtask chain can delay input and painting.

| Operation | What it supplies | What it does not supply |
| -------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| `async` / `await` | An async function returns a promise; `await` suspends that function’s continuation | Cancellation, a worker thread, or blocking of the whole event loop |
| `Promise.all` | Ordered results after all fulfill; rejection when one rejects | Cancellation of the other operations |
| `Promise.allSettled` | Ordered statuses after every input settles | A timeout for work that never settles |
| `Promise.race` | First observed settlement | Cancellation of losing work; an empty input stays pending |
| `Promise.any` | First fulfillment; `AggregateError` if all reject | Success from an empty input |
| Timers | A callback becomes eligible after a delay | An exact execution time or immediate execution at delay zero |
| Workers | Separate execution agents for suitable work | Automatic movement of arbitrary closures or shared mutable objects |

Node.js has host-specific phases and `process.nextTick` behavior. Use the [event-loop chapter](../../10-frontend/10.1-javascript/03-async-concurrency/10.1.3.01-event-loop.md) rather than one universal “macrotask tick” ranking.

## Choose value and lifetime semantics

| Need | Feature | Boundary |
| ------------------------ | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Exact comparison | `===` avoids coercion; `==` applies conversion rules | `NaN !== NaN`; Map/Set use SameValueZero, treating NaN as equal |
| Missing-value fallback | `?.` stops at nullish receivers; `??` defaults only null/undefined | Neither treats 0 or an empty string as missing |
| Identify a value | `typeof`, explicit null checks, and prototype checks | `typeof null` is `"object"`; `instanceof` can differ across realms |
| Unique property identity | `Symbol()` | A description is not its identity; `Symbol.for` uses a registry |
| Arbitrary keyed storage | `Map` and `Set` | Object keys compare by identity; storage is strongly reachable |
| Metadata with a weak key | `WeakMap` accepts objects and non-registered symbols | Weakness does not force immediate collection or provide enumerable keys |
| Weak reference | `WeakRef.deref()` may return an object or `undefined` | It is not deterministic resource cleanup |
| Copy structured data | `structuredClone` supports cycles, Date, Map, Set, and typed arrays | Functions are not cloneable; arbitrary prototypes and property descriptors are not preserved |
| Limit mutation | `Object.freeze`, immutable updates | Freeze and spread are shallow; spread does not clone nested objects |
| Binary view | `ArrayBuffer` plus typed-array/DataView views | A view and its buffer are distinct objects; endianness matters for multi-byte formats |
| Observe operations | `Proxy` handlers with `Reflect` forwarding | Proxy invariants still apply; checking direct assignments does not validate every mutation path |

Garbage collection follows reachability, not whether you intended an object to be useful. Clear timers, remove listeners, and bound caches when their lifetime ends. Weak collections can help with metadata; they do not make a cache automatically correct.

## Package behavior without repeating it

ES modules use static import/export bindings and allow dynamic `import()` for conditional loading. CommonJS uses `require` and `module.exports`; details of interoperability depend on the host. Static module structure helps tree shaking, but side effects and bundler analysis determine what is removable.

| Pattern | What is retained or transformed | Relevant contract |
| -------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| IIFE module | A closure retains private bindings | Use an ordinary identifier such as `count`; `private` is reserved in strict code |
| Currying | Several argument applications fill a parameter list | `fn.length` is not a reliable arity for default/rest parameters; state the expected arity |
| Composition | The output of `g` becomes the input of `f`: `f(g(x))` | Async and error behavior must also compose |
| Memoization | A cache associates a valid key with a result | JSON serialization is not a universal key: values can collide or fail to serialize |
| Debounce / throttle | A timer or interval suppresses repeated calls | Specify leading/trailing behavior, receiver preservation, and cancellation |
| Object pool | A bounded pool reuses objects | Reset the object in place and return the object itself; reset functions commonly return `undefined` |
| Iterator / generator | `next()` produces `{value, done}`; `yield` pauses a generator | Generators are lazy, but retained state and arithmetic still consume resources |
| Event delegation | A parent handles bubbling child events | Check the actual target and containment; shadow DOM can retarget events |

Destructuring extracts fields; rest collects values; spread expands them; template literals interpolate values or call a tag. These change expression shape, not deep-copy or ownership semantics.

## Keep an emitter’s keys separate from object prototypes

```javascript
class EventEmitter {
  constructor() { this.events = new Map(); }
  on(event, fn) {
    const list = this.events.get(event) ?? [];
    list.push(fn);
    this.events.set(event, list);
    return () => this.off(event, fn);
  }
  off(event, fn) {
    const remaining = (this.events.get(event) ?? []).filter(f => f !== fn);
    if (remaining.length) this.events.set(event, remaining);
    else this.events.delete(event);
  }
  emit(event, ...args) {
    // Snapshot: removal during dispatch affects later dispatches.
    for (const fn of [...(this.events.get(event) ?? [])]) fn(...args);
  }
}
```

This synchronous emitter permits duplicate subscriptions, removes all matching subscriptions with `off`, and propagates a handler’s thrown error. It neither awaits async handlers nor isolates their failures. A Map also permits names such as `__proto__` without colliding with inherited object properties.

## Generate an exact sequence lazily

```javascript
function* fibonacci() {
  let a = 0n, b = 1n;
  while (true) {
    yield a;
    [a, b] = [b, a + b];
  }
}
```

BigInt avoids Number’s eventual integer rounding, but the values grow and operations do not have constant cost forever. Stop consuming when the application no longer needs values.

## Summary

Resolve bindings and receivers first, then distinguish language behavior from host scheduling. For copying, caching, and delayed work, state the representation, lifetime, and cancellation contract rather than relying on the feature name.

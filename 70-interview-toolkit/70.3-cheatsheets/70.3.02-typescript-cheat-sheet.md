# TypeScript Cheat Sheet

## Definition

TypeScript checks static type relationships before execution. Most annotations are then erased when JavaScript is emitted. Types describe what code may assume during authoring; runtime validation establishes whether external data satisfies those assumptions.

> **Textbook Definition:** TypeScript extends JavaScript with a static type system that checks assignability and inferred relationships; its type declarations do not by themselves validate runtime values.

## First Principles

A static checker cannot observe future network responses. An assertion can change the checker’s view without changing the value. Safe boundary code therefore starts with `unknown`, checks the necessary facts, and only then exposes a typed result.

## Follow data from outside to a checked value

The examples use strict TypeScript in an ES module. External JSON starts as unknown; a shape check establishes only the fields it tests, not permissions or every application invariant.

```text
JSON / storage → unknown value → runtime checks → narrowed type → application use
```

```typescript
type User = { id: string; name: string };
function isUser(value: unknown): value is User {
  return typeof value === 'object' && value !== null
    && 'id' in value && typeof value.id === 'string'
    && 'name' in value && typeof value.name === 'string';
}
async function fetchUser(url: string): Promise<User> {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  const value: unknown = await response.json();
  if (!isUser(value)) throw new TypeError('Invalid user response');
  return value;
}
```

`fetchTyped<T>()` cannot verify arbitrary `T` merely by returning `response.json()`. Use a schema or a decoder supplied by the caller. A type predicate must check the fields it promises; the compiler does not prove that your predicate is truthful.

## Describe shape, alternatives, and impossible cases

| Need | Type feature | Limit |
| ---------------------- | ---------------------------------- | ---------------------------------------------------------------------------------------- |
| An object contract | `interface` or object `type` alias | A class can implement an eligible alias too; only interfaces support declaration merging |
| Several alternatives | Union: `string \| number` | Narrow before using operations that require one member |
| Combined requirements | Intersection: `A & B` | Conflicting property requirements can produce an impossible type |
| A finite state | Literal or discriminated union | A discriminator makes each branch’s required fields explicit |
| Untrusted input | `unknown` | It requires narrowing before most use; `any` suppresses checks where it flows |
| An unreachable branch | `never` | An exhaustiveness check can expose a newly added union member |
| An ignored return | A callback type returning `void` | It may accept an implementation returning a value; the caller does not use that value |
| A checked precondition | `asserts value is T` | The function must throw or otherwise not return when the precondition fails |

```typescript
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: T }
  | { status: 'error'; error: Error };
function assertNever(value: never): never {
  throw new Error(`Unexpected state: ${JSON.stringify(value)}`);
}
function describe<T>(state: RequestState<T>): string {
  switch (state.status) {
    case 'idle': return 'Not started';
    case 'loading': return 'Loading';
    case 'success': return 'Loaded';
    case 'error': return state.error.message;
    default: return assertNever(state);
  }
}
```

Control-flow narrowing uses runtime tests such as `typeof`, `instanceof`, property presence, equality, and discriminator checks. The tests run; their type annotations are erased. A non-null assertion `!` or `as T` adds no runtime test.

## Preserve relationships with generics

```typescript
function pluck<T, K extends keyof T>(object: T, key: K): T[K] {
  return object[key];
}
const name = pluck({ id: 1, name: 'Ada' }, 'name'); // string
```

The generic records a relationship between input and output. `extends` constrains accepted types; a default such as `<T = unknown>` supplies a type when inference or explicit arguments do not. Variadic tuples preserve argument-list relationships: `T extends unknown[]` can describe a tuple captured by `...args: T`.

| Transformation | Use |
| --------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `keyof T`, type-position `typeof value`, `T[K]` | Obtain keys, a value’s static type, and a property type |
| `Partial<T>`, `Required<T>`, `Readonly<T>` | Change top-level optionality or readonly modifiers |
| `Pick<T, K>`, `Omit<T, K>` | Select or remove declared properties |
| `Record<K, V>` | Describe a keyed object; it does not guarantee every arbitrary string exists at runtime |
| `ReturnType<F>`, `Parameters<F>`, `InstanceType<C>` | Extract callable or constructible relationships |
| `Extract<T, U>`, `Exclude<T, U>`, `NonNullable<T>` | Filter union members |
| `Awaited<T>` | Model recursively awaited results |
| Mapped types | Transform each key, for example `{ readonly [K in keyof T]: T[K] }` |
| Conditional types and `infer` | Select a type branch and extract part of a matching structure |
| Template literal types | Describe string combinations such as HTTP method plus endpoint |

A conditional type distributes only when the checked side is a naked type parameter. Wrapping it as `[T] extends [U]` checks the union as a whole. Readonly types are static constraints; they do not freeze runtime objects. A recursive DeepReadonly needs explicit handling of functions, arrays, Maps, and other special objects.

## Keep a checked shape without replacing it

```typescript
const palette = {
  red: '#ff0000',
  green: '#00ff00',
} as const satisfies Record<'red' | 'green', string>;
type Color = keyof typeof palette; // 'red' | 'green'
```

`satisfies` checks assignability while retaining the expression’s resulting type. It is not a blanket promise to keep every literal unchanged; contextual typing can affect inference. `as const` supplies literal/readonly inference for this example and still does not deep-freeze the object at runtime.

## Distinguish IDs after validating them

```typescript
type UserId = string & { readonly __brand: 'UserId' };
type OrderId = string & { readonly __brand: 'OrderId' };
function createUserId(value: string): UserId {
  if (!/^usr_[a-z0-9]+$/.test(value)) throw new TypeError('Invalid user ID');
  return value as UserId; // Brand construction after this domain check.
}
function getOrder(userId: UserId, orderId: OrderId): string {
  return `${userId}/${orderId}`;
}
```

Brands prevent accidental interchange in checked code. They do not add a runtime property, grant authorization, or validate serialized input on re-entry. The example’s ID syntax is illustrative, not a universal ID standard.

## Decode stored values too

```typescript
function readStored<T>(
  storage: Pick<Storage, 'getItem'>,
  key: string,
  decode: (value: unknown) => T,
): T | null {
  const raw = storage.getItem(key);
  if (raw === null) return null;
  const value: unknown = JSON.parse(raw);
  return decode(value);
}
```

This helper propagates malformed JSON, decoder errors, and storage-access failures. Choose error policy at the application boundary. Declaring a storage schema alone cannot stop old, corrupted, or hostile values from being stored. Avoid treating localStorage as a protected credential store.

## Check compiler and decorator modes separately

Enable `strict` for a new project; also consider checks outside that umbrella, such as `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`. Compiler options must match the runtime, module loader, and emit pipeline. `declare` describes an existing runtime value; it does not create one. Module augmentation and declaration merging extend type contracts without implementing behavior.

Standard decorators supported since TypeScript 5.0 and legacy `experimentalDecorators` have different signatures. The standard model is incompatible with `emitDecoratorMetadata` and does not support parameter decorators; a framework requiring legacy parameter injection cannot be migrated by simply deleting that flag. `reflect-metadata` is associated with the legacy emit mode, not automatic full runtime type information.

Most type syntax erases. Enums, decorators, namespaces with values, and downlevel transformations can emit JavaScript. String unions add no runtime object; ordinary enums do. Const-enum inlining depends on the build pipeline and can create publication/versioning problems.

## Summary

Use types to preserve known relationships and runtime checks to establish new facts. Explain the shape, narrowing rule, and generic relationship before using transformations; confirm the compiler and decorator mode before applying a version-specific example.

# React & Next.js Cheat Sheet

## Definition

React computes UI from props, state, and context. Next.js adds routing and server/client boundaries around that UI. A hook manages one part of React’s work; a route file determines where that work enters the application.

## First Principles

A render may be repeated or discarded, so it must not cause external effects. The committed UI needs browser event handling, while privileged data access needs a server boundary. Caching and streaming decide when results are reused or revealed; neither supplies authorization.

## Trace a request to an interactive screen

```text
request → route + layout → server data/render → HTML + component payload
        → browser hydration of client components → event → authorized mutation
```

Server Components do not ship their component implementation to the browser. The page still needs framework/client JavaScript where it contains interactive components. Client Components can be server-prerendered initially; their directive defines a client module graph, not “execute only in a browser.”

A state update starts React rendering. Reconciliation compares element identity; commit applies the resulting DOM changes. Effects synchronize a committed UI with external systems. Transitions can interrupt React render work, but cannot preempt a long synchronous JavaScript function or move it to a worker.

## Choose the API by Its Role

| Concept | Key Point | Code/Example |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Component | Function that returns JSX; re-renders on state/prop change | `function Button({ label }) { return <button>{label}</button>; }` |
| JSX | Syntax extension transformed to JSX-runtime calls; older transforms use `createElement` | `<div className="x">` → `createElement('div', {className: 'x'})` |
| Virtual DOM | In-memory representation; diffing compares old vs new trees | Enables efficient DOM updates |
| Reconciliation | Matches element type, position, and keys; a type change resets that subtree | Keys help identify which items changed |
| Fiber | Reconciler architecture; work units with priority; enables scheduling | Allows pausing, resuming, aborting work |
| Concurrent Features | `useTransition`, `useDeferredValue`, Suspense — non-blocking rendering | Keep UI responsive during heavy updates |
| `useState` | State hook; returns `[value, setter]`; setter triggers re-render | `const [count, setCount] = useState(0);` |
| `useEffect` | Synchronize after commit; cleanup before a changed-dependency setup and on unmount | `useEffect(() => { fetchData(); return cleanup; }, [dep])` |
| `useContext` | Consume context without nesting consumers | `const value = useContext(MyContext);` |
| `useRef` | Mutable ref object; persists across renders; DOM element access | `const inputRef = useRef(null);` |
| `useMemo` | Cache a computation by dependencies; a performance aid, not a correctness guarantee | `const sorted = useMemo(() => [...items].sort(), [items]);` |
| `useCallback` | Cache function identity; can help a memoized child skip renders | `const fn = useCallback(() => doSomething(a), [a]);` |
| `useReducer` | Complex state logic; `(state, action) => newState` | `const [state, dispatch] = useReducer(reducer, init);` |
| `useLayoutEffect` | Fires synchronously after DOM mutations, before paint | Use for measuring DOM elements |
| `useImperativeHandle` | Customize ref value exposed to parent | `useImperativeHandle(ref, () => ({ focus: () => ... }));` |
| `useTransition` | Mark state update as non-urgent; allows interruption | `const [isPending, startTransition] = useTransition();` |
| `useDeferredValue` | Defer re-render of non-urgent part; shows stale value while pending | `const deferredQuery = useDeferredValue(query);` |
| `useId` | Generate unique, stable ID for accessibility | `const id = useId();` → `"::r1"` |
| `useActionState` | Form action hook (React 19); tracks state, pending transition, and payload | `const [state, formAction, isPending] = useActionState(fn, init);` |
| `useOptimistic` | Optimistic UI hook (React 19); render projected state immediately while action executes | `const [opt, setOpt] = useOptimistic(state, updateFn);` |
| `use()` API | Read promise or context conditionally/dynamically during render without nesting | `const data = use(fetchPromise);` |
| Server Component | Default in App Router; runs on server; can access DB directly | No `'use client'` directive at top |
| Client Component | `'use client'` directive; interactive client graph, also server-prerendered on initial load | Required for `useState`, `useEffect`, event handlers |
| Server Actions | `'use server'` directive; functions called from client, execute on server | `async function submitForm(data: FormData) { 'use server'; }` |
| App Router | File-based routing in `app/` directory; layouts, loading, error boundaries | `app/dashboard/layout.tsx` wraps `app/dashboard/page.tsx` |
| Pages Router | File-based in `pages/` directory; `getServerSideProps`, `getStaticProps` | Legacy, still supported |
| Layouts | Shared layouts retain state across child navigation; crossing root layouts or identity changes can reset it | `app/layout.tsx` → wraps all pages |
| Loading UI | `loading.tsx` — shows Suspense fallback while route segment loads | `app/dashboard/loading.tsx` |
| Error Boundaries | `error.tsx` — catches errors in route segment | `app/dashboard/error.tsx` |
| Not Found | `not-found.tsx` — custom 404 for route segment | `app/not-found.tsx` |
| Proxy (Next.js 16) | Request boundary for rewrites/redirects; Node.js runtime | `proxy.ts`; older versions used `middleware.ts` |
| Route Handlers | `route.ts` — API endpoints in App Router | `export async function GET() { return Response.json({}); }` |
| Metadata API | `generateMetadata` — SEO metadata per route | `export const metadata: Metadata = { title: 'Page' };` |
| Dynamic Routes | `[slug]` — catch dynamic segments; `[[...slug]]` for optional | `app/blog/[slug]/page.tsx` |
| Catch-All Routes | `[...slug]` — matches `/a/b/c` as `params.slug = ['a','b','c']` | `app/docs/[...slug]/page.tsx` |
| Parallel Routes | `@slot` — render multiple pages simultaneously in same layout | `app/dashboard/@analytics/page.tsx` |
| Intercepting Routes | `(..)` — intercept modal navigation; `(.)` same level, `(...)` root | Segment levels, excluding `@slot` and route groups, determine the marker |
| Caching (Data) | Next.js 15+ fetch is not persistently cached by default; opt in explicitly | `fetch(url, { next: { revalidate: 3600 } })` |
| Caching (Router) | Client-side reuse of route segments; prefetch and staleness affect reuse | Router Cache: in-memory, per-session |
| ISR | Incremental Static Regeneration; regenerate static pages at runtime | `export const revalidate = 60;` per page |
| Streaming | Send HTML progressively; Suspense boundaries define chunks | `<Suspense fallback={<Loading />}>` |
| `fetch` in RSC | Matching GET/HEAD fetches memoize during a render; persistent caching is a separate opt-in | `const data = await fetch(url, { cache: 'no-store' });` |
| `cookies()` / `headers()` | Read cookies/headers in Server Components and Route Handlers (async in Next.js 15) | `const token = (await cookies()).get('token');` |
| `redirect()` | Redirect from Server Component or Server Action | `redirect('/login');` |
| `notFound()` | Trigger 404 from Server Component | `if (!post) notFound();` |
| `useRouter()` | Client-side navigation; `push`, `replace`, `back`, `prefetch` | `const router = useRouter(); router.push('/dashboard');` |
| `usePathname()` | Current URL pathname (client) | `const pathname = usePathname();` |
| `useSearchParams()` | URL search params (client) | `const searchParams = useSearchParams();` |
| `useParams()` | Dynamic route params (client) | `const { slug } = useParams();` |
| `useSelectedLayoutSegment()` | Active child segment under a layout | `const segment = useSelectedLayoutSegment('nav');` |
| `next/image` | Optimized images; lazy loading, resize, WebP | `<Image src="/pic.jpg" alt="..." width={500} height={300} />` |
| `next/font` | Self-host fonts and reduce font-related layout shifts; CSS variables | `const inter = Inter({ subsets: ['latin'] });` |
| `next/link` | Client-side navigation; prefetch behavior depends on version and route | `<Link href="/about">About</Link>` |
| `next/script` | Script loading strategies: `beforeInteractive`, `afterInteractive`, `lazyOnload` | `<Script src="..." strategy="lazyOnload" />` |
| `next/headers` | Read request headers/cookies (server only) | `import { headers, cookies } from 'next/headers';` |
| Prisma (Next.js) | Instantiate outside route handlers to reuse connection | `const prisma = new PrismaClient();` (singleton in `lib/prisma.ts`) |
| `generateStaticParams` | Pre-generate dynamic routes at build time | `export async function generateStaticParams() { return [{ slug: '...' }]; }` |
| `generateMetadata` | Dynamic metadata per page (params is a Promise in Next.js 15) | `export async function generateMetadata({ params }) { const { slug } = await params; return { title: slug }; }` |

## Apply the Boundaries to a Small Example

### Reveal a Slow Server Read Under a Fallback

```typescript
// app/posts/page.tsx (Server Component)
import { Suspense } from 'react';

export default function PostsPage() {
  return (
    <div>
      <h1>Posts</h1>
      <Suspense fallback={<PostsSkeleton />}>
        <PostsList />
      </Suspense>
    </div>
  );
}

// Sketch: validate the response schema and supply PostsSkeleton in the application.
async function PostsList() {
  const posts = await fetch('https://api.example.com/posts')
    .then(res => {
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      return res.json();
    });
  return (
    <ul>
      {posts.map(post => <li key={post.id}>{post.title}</li>)}
    </ul>
  );
}

```

### Authorize and Validate a Server Mutation

```typescript
// app/actions.ts
'use server';

import { revalidatePath } from 'next/cache';
import { redirect } from 'next/navigation';
import { db } from '@/lib/db';
import { requireEditor } from '@/lib/auth';

export async function createPost(formData: FormData) {
  const editor = await requireEditor(); // App helper verifies session + posting permission.
  const title = formData.get('title');
  const content = formData.get('content');
  if (typeof title !== 'string' || !title.trim() || title.length > 200
      || typeof content !== 'string' || content.length > 50_000) {
    throw new Error('Invalid post');
  }
  await db.post.create({ data: { title: title.trim(), content, authorId: editor.id } });
  revalidatePath('/posts');
  redirect('/posts');
}

// app/posts/new/page.tsx
import { createPost } from '../../actions';

export default function NewPost() {
  return (
    <form action={createPost}>
      <input name="title" required />
      <textarea name="content" required />
      <button type="submit">Create Post</button>
    </form>
  );
}

```

### Optimistic request redirect (Next.js 16 Proxy)

```typescript
// proxy.ts
import { NextResponse, type NextRequest } from 'next/server';

export function proxy(request: NextRequest) {
  // Presence is only an optimistic UX check, not verified authentication.
  if (!request.cookies.has('auth-token')) {
    return NextResponse.redirect(new URL('/login', request.url));
  }
  return NextResponse.next();
}

export const config = { matcher: ['/dashboard/:path*'] };
```

Verify the session and permissions in every protected data access and mutation. Server Actions also need input validation; form casts do not validate hostile input.

### Preserve a Background Route While Showing a Modal

```typescript
// app/@modal/(.)photos/[id]/page.tsx
import Modal from '@/components/Modal';

export default async function PhotoModal({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params; // params is a Promise in Next.js 15+
  return (
    <Modal>
      <img src={`/photos/${id}`} alt="Photo" />
    </Modal>
  );
}

```

### Optimistic Updates with `useOptimistic`

```typescript
'use client';
import { useOptimistic } from 'react';

function TodoList({ todos, addTodo }) {
  const [optimisticTodos, addOptimisticTodo] = useOptimistic(
    todos,
    (state, newTodo: { id: string; text: string }) => [...state, { ...newTodo, done: false }]
  );

  async function handleAdd(formData: FormData) {
    const text = formData.get('text') as string;
    addOptimisticTodo({ id: crypto.randomUUID(), text }); // Action runs this outside render
    await addTodo(text); // Server mutation
  }

  return (
    <form action={handleAdd}>
      <ul>{optimisticTodos.map(t => <li key={t.id}>{t.text}</li>)}</ul>
      <input name="text" />
    </form>
  );
}

```

### Validate a Public Read at a Route Handler

```typescript
// app/api/products/route.ts — public catalog only.
import { db } from '@/lib/db';

export async function GET(request: Request) {
  const rawPage = new URL(request.url).searchParams.get('page') ?? '1';
  if (!/^[1-9]\d{0,3}$/.test(rawPage)) {
    return Response.json({ error: 'Invalid page' }, { status: 400 });
  }
  const products = await db.product.findMany({
    where: { published: true },
    orderBy: { id: 'asc' },
    skip: (Number(rawPage) - 1) * 10,
    take: 10,
    select: { id: true, name: true },
  });
  return Response.json(products);
}
```

`db` and `requireEditor` above are application dependencies, not framework APIs. Protect private reads and mutations at their data-access boundary. The public-read example uses bounded offset pagination; for large changing collections, use a stable cursor and unique tiebreaker. Never pass an unchecked request body directly into an ORM create operation.


## Connect Route Files to Navigation Behavior

| File or convention | Role in the screen |
| ------------------------------------ | -------------------------------------------------------------------------------------- |
| `layout.tsx` | Shared surrounding UI; a root layout supplies `html` and `body` |
| `loading.tsx` | Suspense fallback for a route segment |
| `error.tsx` | Client error boundary for descendants; errors in its own layout need a higher boundary |
| `not-found.tsx` / `notFound()` | Missing-resource UI and status behavior |
| `[slug]`, `[...slug]`, `[[...slug]]` | One dynamic segment, required catch-all, optional catch-all |
| `@slot` | Parallel layout input; it does not add a URL segment |
| `(.)`, `(..)`, `(...)` | Intercept at the same, parent, or root segment level |
| `default.tsx` | Fallback for an unmatched parallel slot during a hard load |
| `template.tsx` | A fresh instance when its route identity changes, unlike a shared layout |

For the root-level `@modal` example, `(.)photos` matches sibling `/photos`. Soft navigation can show a modal; direct navigation needs the regular `app/photos/[id]/page.tsx`. Supply the layout’s `modal` slot and its unmatched-route fallback; one intercepted page file alone is not a complete modal flow.

Use `next/link` and the navigation hooks for route changes; `useParams`, `useSearchParams`, `usePathname`, and `useSelectedLayoutSegment` read different pieces of route state. Use context for shared client state, and `useImperativeHandle` only when a parent needs an explicit imperative interface. Full examples live in the [context chapter](../../10-frontend/10.3-react/02-core-hooks/10.3.2.05-context-api.md) and [App Router chapter](../../10-frontend/10.4-next.js/01-rendering-fundamentals/10.4.1.02-app-router.md).

## Separate Render Reuse From Persistent Caching

Matching eligible GET/HEAD fetches can share results during React rendering. That request memoization is distinct from persistent data caching, route output, and browser router reuse. Route Handlers are outside the React render tree.

Next.js 15+ does not persistently cache `fetch` by default. In the previous cache model, explicit fetch cache/revalidation options and route behavior determine persistence. Next.js 16 can opt into `cacheComponents`, with `use cache`, `cacheLife`, and `cacheTag`; this also changes prerendering and navigation behavior. Check the model enabled in the application rather than mixing examples from both.

`generateStaticParams` enumerates build-time route parameters; `generateMetadata` provides metadata and may await dynamic params. On Next.js 15+, `params`, `cookies()`, and `headers()` use asynchronous access. Read one decoded slug, validate it, and load the resource before using it in metadata or markup. `notFound()` and `redirect()` terminate the relevant render/control flow; they are not ordinary values to ignore.

Image, font, and script components address different work: `next/image` manages image loading and sizing, `next/font` manages font delivery, and `next/script` schedules third-party scripts. None guarantees a universally fast page; verify their effects with the actual content and device workload.

## Summary

Trace render, commit, server data access, browser interaction, and mutation as separate steps. Choose routing and cache APIs for their role in that trace, and enforce authorization and validation at the privileged operation.

# Backend Cheat Sheet

When two requests read the same balance and each decides to debit it, both can pass the check. The design question is what serializes that decision — and what the caller should do if the reply is lost.

```sql
-- Lock both accounts in stable ID order, then commit debit and credit together.
PERFORM id FROM accounts
  WHERE id IN (source_id, target_id) ORDER BY id FOR UPDATE;
```

## Definition

A **backend** turns a request into an authorized operation on data and returns an observable result. Routing, validation, transactions, and monitoring each protect a different part of that path.

> **Textbook Definition:** Backend application services expose operations, enforce domain and access constraints, coordinate persistence and external work, and communicate results through defined interfaces.

## First Principles

Clients can send unexpected data, two requests can run concurrently, and remote work can fail after its local caller loses contact. A useful design states what each boundary trusts, which changes commit together, and how an uncertain or repeated operation is resolved.

## How It Works

### 1. Follow a Request Before Naming Framework Features

```text
request → middleware → guards → interceptors (in) → pipes
        → controller → service / transaction
        → interceptors (out) → response
                  unhandled exception → exception filter
```

For an order request, middleware may attach a request ID, a guard checks the caller, a pipe validates the quantity, and a service checks current stock inside the operation that reserves it. The response should describe the committed order; authentication alone does not establish permission to use another customer's account.

| NestJS component | Job in that path | Boundary |
| ---------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Module | Registers, imports, and exports providers | It organizes dependencies; not every value is a module |
| Controller | Maps Hypertext Transfer Protocol (HTTP) routes to application calls | Keep resource ownership and output fields explicit |
| Provider | Supplies an injected service or dependency | Its scope determines lifetime and reuse |
| Middleware | Performs pre-route work | Use `NestMiddleware` consumer registration or the adapter's middleware; there is no general `@Middleware()` decorator |

| Pipeline component | Job in that path | Boundary |
| ------------------ | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Guard | Allows or denies handler execution | Per-resource authorization may also need service-layer checks |
| Pipe | Validates or transforms arguments | A TypeScript data transfer object (DTO) type alone has no runtime effect |
| Interceptor | Wraps the handler's observable flow | A shared response cache must include identity, tenant, and query variation where needed |
| Filter | Maps unhandled exceptions to responses | Do not expose internal queries or secrets |

Initialization hooks and shutdown hooks govern application lifetime, not request order. Configure shutdown handling and close connections deliberately. Logs, metrics, and tracing should identify the operation without logging tokens or sensitive payloads.

### 2. Define the HTTP Contract

| Decision | Useful rule |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Resource and method | Use stable resource URLs; `GET` is safe, `PUT` replaces a selected representation, `PATCH` applies defined partial changes, and `POST` submits a resource-specific operation |
| Status | Use `201` for a newly created resource, `204` for a successful empty response, and error statuses that describe the failure; `DELETE` need not always return `204` |
| Pagination | Bound page size; cursor pagination needs a stable ordering and unique tiebreaker; offset can suit small stable datasets |
| Evolution | Version only where compatibility requires it; URL and header strategies have different cache and client implications |
| Discoverability | Links and an accurate OpenAPI contract help clients find and exercise related operations |
| Retry | Idempotent effects are not necessarily identical response bodies; a `POST` idempotency key needs atomic reservation, request matching, and stored outcome semantics |

### 3. Preserve an Invariant Under Concurrent Writes

A transaction groups changes, though a default-isolation read followed by a later decrement can still race. Protect the decision with a lock, a conditional write, or an isolation level and retry policy that enforces the invariant.

The following PostgreSQL example transfers integer minor units between two accounts of the same currency, locking both accounts in stable ID order and committing debit and credit together. It is strictly an invariant example: the application must authorize the source account, record an audit or ledger entry, and implement request idempotency before using this as a complete transfer endpoint.

```sql
CREATE TABLE accounts (
  id bigint PRIMARY KEY,
  currency text NOT NULL,
  balance_minor bigint NOT NULL CHECK (balance_minor >= 0)
);

CREATE FUNCTION transfer_minor(source_id bigint, target_id bigint, amount bigint)
RETURNS void LANGUAGE plpgsql AS $$
DECLARE
  locked_count integer;
  source_currency text;
  target_currency text;
BEGIN
  IF source_id IS NULL OR target_id IS NULL OR source_id = target_id
     OR amount IS NULL OR amount <= 0 THEN
    RAISE EXCEPTION 'Invalid transfer';
  END IF;
  PERFORM id FROM accounts
    WHERE id IN (source_id, target_id) ORDER BY id FOR UPDATE;
  GET DIAGNOSTICS locked_count = ROW_COUNT;
  IF locked_count <> 2 THEN RAISE EXCEPTION 'Missing account'; END IF;
  SELECT currency INTO source_currency FROM accounts WHERE id = source_id;
  SELECT currency INTO target_currency FROM accounts WHERE id = target_id;
  IF source_currency <> target_currency THEN
    RAISE EXCEPTION 'Currency mismatch';
  END IF;
  UPDATE accounts SET balance_minor = balance_minor - amount
    WHERE id = source_id AND balance_minor >= amount;
  IF NOT FOUND THEN RAISE EXCEPTION 'Insufficient funds'; END IF;
  UPDATE accounts SET balance_minor = balance_minor + amount WHERE id = target_id;
END;
$$;
```

If credit overflows or a later statement fails, the transaction rolls back the debit too. Stable lock order reduces this operation's deadlock risk; other operations can still contend, so handle database failures explicitly, and never retry an external payment side effect merely because a database transaction was retried.

PostgreSQL defaults to `Read Committed` (`Read Uncommitted` behaves as `Read Committed`). `Repeatable Read` provides a stable snapshot yet can still permit serialization anomalies, and `Serializable` can abort work that would violate a serial ordering (retry the whole transaction with a bounded policy); savepoints undo part of a transaction rather than acting as independent nested commits.

### 4. Choose Data Access for the Query Shape

| Index need | Mechanism and limit |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Equality, range, or order | B-tree is the default index; composite leading columns and query predicates affect its usefulness |
| Full-text and JavaScript Object Notation (JSON) containment | Generalized Inverted Index (GIN) supports relevant operators; index the expression or operator actually queried |
| Spatial or other supported searches | Generalized Search Tree (GiST) is extensible; its operator class determines behavior |
| Physically correlated large ranges | Block Range Index (BRIN) summarizes block ranges; it is not a small substitute for every B-tree |
| Smaller selected population | Partial indexes require query predicates that imply the index predicate |
| Return columns from the index | `INCLUDE` can enable index-only scans; visibility checks can still require heap access |

| Query operation | Mechanism and limit |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Inspect execution | `EXPLAIN` estimates; `EXPLAIN ANALYZE` executes, including write side effects |
| Remove dead tuples and statistics drift | `VACUUM` makes space reusable; `ANALYZE` updates planner statistics; ordinary `VACUUM` usually does not shrink the file |
| Split a large table | Partition by range, list, or hash for a justified access or maintenance pattern; pruning and keys matter |
| Structure a query | A common table expression (CTE) may be folded or materialized depending on its semantics and use; it is not always an optimization barrier |
| Compute per-row rankings and aggregates | Window functions retain rows; frame and tie ordering affect the result |
| Store structured documents | Binary JSON (`JSONB`) supports operators such as containment and field extraction; it still needs schema and validation decisions |

An object-relational mapper (ORM) helps with query construction and client types; it does not supply application authorization or guarantee a good plan. Select only needed fields, use supported parameterized raw-query APIs, and review generated queries.

Relation definitions and indexes must reference fields that actually exist; a unique constraint already supplies its enforcing index in PostgreSQL. Prisma client generation, connection setup, migrations, and transaction APIs vary by major version — verify them against the installed client, and consult the [database chapters](../../20-backend/20.4-database/INDEX.md) for full ORM examples.

### 5. Verify Identity and Retain Session State Deliberately

A signed JSON Web Token (JWT) is not necessarily encrypted and is not inherently revocable. Verify its allowed algorithm, signature, issuer, audience, and expiry before trusting claims; token lifetime depends on the application's risk and session policy rather than fixed "15 minutes or 7 days" values.

Refresh rotation needs an identifiable session or token record, expiry and revocation checks, and an atomic consume-and-replace operation — concurrent requests must not both consume the same old token. Add a fresh random identifier to each token, and define reuse handling and response-loss behavior.

Open Authorization (OAuth) grants delegated authorization, while OpenID Connect adds authentication. Authorization-code flow with Proof Key for Code Exchange (PKCE) suits public clients, whereas client-credentials flow represents a service; validate the protocol's anti-forgery and redirect conditions and request only required scopes. A cookie can protect a token from direct JavaScript reads with `HttpOnly`, yet cookies also need `Secure` and an appropriate `SameSite` and cross-site request forgery (CSRF) design.

### 6. Keep Validation, Authorization, Abuse Controls, and Delivery Separate

Validate DTO fields at the server boundary and reject or strip unknown fields deliberately; a registration DTO must not accept a privileged role merely because it is a valid `enum` value. A custom decorator setting arbitrary metadata has no effect unless the relevant guard reads it, so pair `Throttle` and `SkipThrottle` from `@nestjs/throttler` with a registered `ThrottlerGuard`.

For cross-site scripting (XSS), encode text for its output context and sanitize intentionally allowed HyperText Markup Language (HTML); Content Security Policy (CSP) is an additional control, and CSRF requires a design suited to cookie authentication and browser request behavior. Cross-Origin Resource Sharing (CORS) controls browser cross-origin access — it is not authorization and does not stop non-browser clients — while parameterized Structured Query Language (SQL) prevents data from becoming query syntax.

Use an appropriate password-hashing algorithm with tuned cost and accepted input bounds. Circuit breakers, bounded timeouts, and health checks address dependency failure rather than caller permissions, and separating liveness from readiness stops a downstream outage from causing a restart storm. A transactional outbox writes the domain change and event in the same database transaction so a publisher sends it to the broker, while stable event identity and idempotent consumers handle crashes between publish and acknowledgment.

Field-level encryption separates a data-encryption key from the key-encryption key wrapping it, with correct nonce handling and a rotation plan. Model Context Protocol (MCP) standardizes tool and resource interactions through JavaScript Object Notation Remote Procedure Call (JSON-RPC); the 2026-07-28 specification makes Streamable HTTP stateless at the protocol layer, while older 2025-11-25 peers retain the earlier handshake — verify the negotiated revision and software development kit (SDK) support.

## Summary

Trace a request through identity, validation, ownership, and committed data changes. Then explain concurrent-write invariants, uncertain remote outcomes, and delivery recovery. Framework decorators and transaction APIs are tools for these contracts, not substitutes for them.

# Backend Cheat Sheet

## Definition

A backend turns a request into an authorized operation on data and returns an observable result. Routing, validation, transactions, and monitoring each protect a different part of that path.

> **Textbook Definition:** Backend application services expose operations, enforce domain and access constraints, coordinate persistence and external work, and communicate results through defined interfaces.

## First Principles

Clients can send unexpected data, two requests can run concurrently, and remote work can fail after its local caller loses contact. A useful design states what each boundary trusts, which changes commit together, and how an uncertain or repeated operation is resolved.

## Follow a Request Before Naming Framework Features

```text
request → middleware → guards → interceptors (in) → pipes
        → controller → service / transaction
        → interceptors (out) → response
                  unhandled exception → exception filter
```

For an order request, middleware may attach a request ID, a guard checks the caller, a pipe validates the quantity, and a service checks current stock inside the operation that reserves it. The response should describe the committed order; authentication alone does not establish permission to use another customer’s account.

| NestJS component | Job in that path | Boundary |
| ---------------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| Module | Registers and imports/exports providers | It organizes dependencies; not every value is a module |
| Controller | Maps HTTP routes to application calls | Keep resource ownership and output fields explicit |
| Provider | Supplies an injected service or dependency | Its scope determines lifetime and reuse |
| Middleware | Performs pre-route work | Use `NestMiddleware`/consumer registration or the adapter’s middleware; there is no general `@Middleware()` decorator |
| Guard | Allows or denies handler execution | Per-resource authorization may also need service-layer checks |
| Pipe | Validates or transforms arguments | A TypeScript DTO type alone has no runtime effect |
| Interceptor | Wraps the handler’s observable flow | A shared response cache must include identity/tenant and query variation where needed |
| Filter | Maps unhandled exceptions to responses | Do not expose internal queries or secrets |

Initialization hooks and shutdown hooks govern application lifetime, not request order. Configure shutdown handling and close connections deliberately. Logs, metrics, and tracing should identify the operation without logging tokens or sensitive payloads.

## Define the HTTP Contract

| Decision | Useful rule |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Resource and method | Use stable resource URLs; GET is safe, PUT replaces a selected representation, PATCH applies defined partial changes, POST submits a resource-specific operation |
| Status | Use 201 for a newly created resource, 204 for a successful empty response, and error statuses that describe the failure; DELETE need not always return 204 |
| Pagination | Bound page size; cursor pagination needs a stable ordering and unique tiebreaker; offset can suit small stable datasets |
| Evolution | Version only where compatibility requires it; URL/header strategies have different cache and client implications |
| Discoverability | Links and an accurate OpenAPI contract help clients find and exercise related operations |
| Retry | Idempotent effects are not necessarily identical response bodies; a POST idempotency key needs atomic reservation, request matching, and stored outcome semantics |

## Preserve an Invariant Under Concurrent Writes

A transaction groups changes, but a default-isolation read followed by a later decrement can still race. Protect the decision with a lock, a conditional write, or an isolation level and retry policy that enforces the invariant.

The following PostgreSQL example transfers integer minor units between two accounts of the same currency. It locks both accounts in stable ID order and commits debit and credit together. It is an invariant example: the application must authorize the source account, record an audit/ledger entry, and implement request idempotency before using this as a complete transfer endpoint.

```sql
CREATE TABLE accounts (
  id bigint PRIMARY KEY,
  currency text NOT NULL,
  balance_minor bigint NOT NULL CHECK (balance_minor >= 0)
);

CREATE FUNCTION transfer_minor(source_id bigint, target_id bigint, amount bigint)
RETURNS void LANGUAGE plpgsql AS $$
DECLARE
  locked_count integer;
  source_currency text;
  target_currency text;
BEGIN
  IF source_id IS NULL OR target_id IS NULL OR source_id = target_id
     OR amount IS NULL OR amount <= 0 THEN
    RAISE EXCEPTION 'Invalid transfer';
  END IF;
  PERFORM id FROM accounts
    WHERE id IN (source_id, target_id) ORDER BY id FOR UPDATE;
  GET DIAGNOSTICS locked_count = ROW_COUNT;
  IF locked_count <> 2 THEN RAISE EXCEPTION 'Missing account'; END IF;
  SELECT currency INTO source_currency FROM accounts WHERE id = source_id;
  SELECT currency INTO target_currency FROM accounts WHERE id = target_id;
  IF source_currency <> target_currency THEN
    RAISE EXCEPTION 'Currency mismatch';
  END IF;
  UPDATE accounts SET balance_minor = balance_minor - amount
    WHERE id = source_id AND balance_minor >= amount;
  IF NOT FOUND THEN RAISE EXCEPTION 'Insufficient funds'; END IF;
  UPDATE accounts SET balance_minor = balance_minor + amount WHERE id = target_id;
END;
$$;
```

If credit overflows or a later statement fails, the transaction rolls back the debit too. Stable lock order reduces this operation’s deadlock risk; other operations can still contend, so handle database failures explicitly. Do not retry an external payment side effect merely because a database transaction was retried.

PostgreSQL defaults to Read Committed. Read Uncommitted behaves as Read Committed; Repeatable Read provides a stable snapshot but can still permit serialization anomalies. Serializable can abort work that would violate a serial ordering; retry the whole transaction with a bounded policy. Savepoints undo part of a transaction; they are not independent nested commits. Multiversion concurrency control (MVCC) reduces ordinary reader/writer contention, but locks, schema changes, and conflicting writes can still block.

## Choose Data Access for the Query Shape

| Need | Mechanism and limit |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Equality/range/order | B-tree is the default index; composite leading columns and query predicates affect its usefulness |
| Full-text/JSON containment | GIN supports relevant operators; index the expression/operator actually queried |
| Spatial or other supported searches | GiST is extensible; its operator class determines behavior |
| Physically correlated large ranges | BRIN summarizes block ranges; it is not a small substitute for every B-tree |
| Smaller selected population | Partial indexes require query predicates that imply the index predicate |
| Return columns from the index | `INCLUDE` can enable index-only scans; visibility checks can still require heap access |
| Inspect execution | `EXPLAIN` estimates; `EXPLAIN ANALYZE` executes, including write side effects |
| Remove dead tuples/statistics drift | VACUUM makes space reusable; ANALYZE updates planner statistics; ordinary VACUUM usually does not shrink the file |
| Split a large table | Partition by range/list/hash for a justified access or maintenance pattern; pruning and keys matter |
| Structure a query | A CTE may be folded or materialized depending on its semantics and use; it is not always an optimization barrier |
| Compute per-row rankings/aggregates | Window functions retain rows; frame and tie ordering affect the result |
| Store structured documents | JSONB supports operators such as containment and field extraction; it still needs schema/validation decisions |

An ORM helps with query construction and client types; it does not supply application authorization or guarantee a good plan. Select only needed fields, use supported parameterized raw-query APIs, and review generated queries. Relation definitions and indexes must reference fields that actually exist; a unique constraint already supplies its enforcing index in PostgreSQL.

Prisma client generation, connection setup, migrations, and transaction APIs vary by major version. `PrismaClient`-style clients use patterns such as `$transaction`; verify them against the client installed in the application. Development migration commands can reset development data; use the production migration workflow specified for that version and deployment. The full [database chapters](../../20-backend/20.4-database/INDEX.md) own the larger ORM examples.

## Verify Identity and Retain Session State Deliberately

A signed JSON Web Token (JWT) is not necessarily encrypted and is not inherently revocable. Verify its allowed algorithm, signature, issuer, audience, and expiry before trusting claims. Token lifetime depends on the application’s risk and session policy, not fixed “15 minutes / 7 days” values.

Refresh rotation needs an identifiable session/token record, expiry and revocation checks, and an atomic consume-and-replace operation. Concurrent requests must not both consume the same old token. Add a fresh random identifier to each token, and define reuse handling and response-loss behavior. A query for the first unrevoked token belonging to a user does not identify the supplied token. Do not use a password-hashing API that silently truncates a long JWT as a general token comparison mechanism.

OAuth grants delegated authorization; OpenID Connect adds authentication. Authorization-code flow with Proof Key for Code Exchange (PKCE) suits public clients; client-credentials flow represents a service. Validate the protocol’s anti-forgery and redirect conditions and request only required scopes. A cookie can protect a token from direct JavaScript reads with HttpOnly, but cookies also need Secure and an appropriate SameSite/CSRF design.

## Keep Validation, Authorization, and Abuse Controls Separate

Validate DTO fields at the server boundary and reject or strip unknown fields deliberately. A registration DTO should not accept a privileged role merely because it is a valid enum. A custom decorator that sets arbitrary metadata has no effect unless the relevant guard reads it; use `Throttle`/`SkipThrottle` from `@nestjs/throttler` with a registered `ThrottlerGuard`. Its v5+ TTL values are milliseconds, and shared deployments need appropriate shared storage and trusted-proxy configuration.

For cross-site scripting (XSS), encode text for its output context and sanitize intentionally allowed HTML; CSP is an additional control. For cross-site request forgery (CSRF), use a design suited to cookie authentication and browser request behavior. Cross-Origin Resource Sharing (CORS) controls browser cross-origin access; it is not authorization and does not stop non-browser clients. Parameterized SQL prevents data from becoming query syntax; unchecked unsafe raw-query construction bypasses that protection.

Use an appropriate password-hashing algorithm with tuned cost and accepted input bounds. Keep authentication responses, rate-limit identities, and logging policies consistent. Circuit breakers, bounded timeouts, and health checks address dependency failure rather than caller permissions. Separate liveness from readiness so a downstream outage does not create a restart storm; health-check libraries expect their own result contracts, not an arbitrary raw-query result.

## Publish Committed Work Without Pretending Delivery Is Atomic

A transactional outbox writes the domain change and event into the same database transaction. A publisher later sends it to the broker; a crash between publish and acknowledgment can duplicate delivery, so use stable event identity and idempotent consumers. A `FOR UPDATE SKIP LOCKED` queue claim needs a transaction that records ownership/status before releasing its locks, plus lease expiry, retry, and recovery behavior.

Field-level encryption separates a data-encryption key from a key-encryption key that wraps it. Authenticated encryption also requires correct nonce handling, associated context, key access controls, and an operational rotation plan; encrypting a column does not settle retention or authorization.

Model Context Protocol (MCP) standardizes tools/resources and JSON-based remote procedure call messages. The 2025-11-25 specification defines stdio and Streamable HTTP, replacing the older HTTP+SSE transport. A subprocess is not automatically sandboxed; the host’s permissions and authentication still determine what operations it can perform.

## Summary

Trace a request through identity, validation, ownership, and committed data changes. Then explain concurrent-write invariants, uncertain remote outcomes, and delivery recovery. Framework decorators and transaction APIs are tools for these contracts, not substitutes for them.

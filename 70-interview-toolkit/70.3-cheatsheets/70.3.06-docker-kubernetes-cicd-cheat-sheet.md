# Docker, Kubernetes & CI/CD Cheat Sheet

## Quick Reference Table

| Command / Concept         | Key Point                                             | Example                                                  |
| ------------------------- | ----------------------------------------------------- | -------------------------------------------------------- |
| `docker build`            | Build with tags; use BuildKit                         | `DOCKER_BUILDKIT=1 docker build -t app:1.4.2 .`          |
| `docker run`              | `-e` env, `-p` ports, `--rm` cleanup                  | `docker run --rm -p 3000:3000 --env-file .env app:1.4.2` |
| `docker exec`             | Shell into running container                          | `docker exec -it app sh`                                 |
| `docker logs`             | Follow + tail                                         | `docker logs -f --tail 100 app`                          |
| `docker system prune`     | Reclaim disk; `-a` includes images                    | `docker system prune -af --volumes`                      |
| Multi-stage build         | Compile stage heavy, runtime stage slim               | see pattern below                                        |
| `.dockerignore`           | Exclude node_modules, .git, dist                      | speeds context upload massively                          |
| Distroless/alpine runtime | Smaller image = smaller attack surface + faster pulls | `node:20-alpine` or `gcr.io/distroless/nodejs20`         |
| `kubectl get`             | `-o wide`, `-o yaml`, label selectors                 | `kubectl get pods -l app=api -o wide`                    |
| `kubectl describe`        | First stop for debugging                              | `kubectl describe pod api-7d9f-x2v`                      |
| `kubectl logs`            | `-f` follow, `-c` container, `-p` previous crash      | `kubectl logs api-7d9f-x2v -c worker --previous`         |
| `kubectl exec`            | Interactive shell in pod                              | `kubectl exec -it api-7d9f-x2v -- sh`                    |
| `kubectl port-forward`    | Local access to svc/pod                               | `kubectl port-forward svc/api 8080:80`                   |
| `kubectl rollout status`  | Watch deployment progress                             | `kubectl rollout status deploy/api`                      |
| `kubectl rollout undo`    | Rollback to previous revision                         | `kubectl rollout undo deploy/api --to-revision=3`        |
| `kubectl rollout restart` | Rolling restart (config reload)                       | `kubectl rollout restart deploy/api`                     |
| `kubectl scale`           | Manual replica count                                  | `kubectl scale deploy/api --replicas=5`                  |
| `kubectl top`             | Live resource usage                                   | `kubectl top pods --sort-by=memory`                      |
| `kubectl events`          | Chronological event stream                            | `kubectl events --for pod/api-7d9f-x2v`                  |
| `kubectl diff`            | Preview apply changes                                 | `kubectl diff -f k8s/`                                   |
| `kubectl apply`           | Declarative upsert                                    | `kubectl apply -f k8s/ --recursive`                      |
| CrashLoopBackOff          | App dies at startup → check logs `--previous`         | usually bad config or missing secret                     |
| ImagePullBackOff          | Bad tag / registry auth                               | check `describe` Events section                          |
| OOMKilled                 | Exit 137; memory limit too low                        | raise limits or fix leak                                 |
| Liveness probe            | Restart unhealthy container                           | must be cheap; never depends on external services        |
| Readiness probe           | Gate traffic until ready                              | startup slow? add `startupProbe` instead of huge delays  |
| Resource requests/limits  | requests = scheduling, limits = cap                   | set both; memory limit kill is silent                    |
| PDB (PodDisruptionBudget) | Survives node drains during deploys                   | `minAvailable: 1` for small fleets                       |
| HPA                       | Autoscale on CPU/memory/custom metrics                | needs `requests` set to work                             |
| Helm install/upgrade      | Package manager for k8s manifests                     | `helm upgrade --install api ./chart -f values.prod.yaml` |
| Argo CD sync              | GitOps pull-based deploy                              | `argocd app sync api --prune`                            |

## Dockerfile Patterns

### Production multi-stage TypeScript API

```dockerfile
# ── Stage 1: deps ─────────────────────────────────────────────
FROM node:20-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci

# ── Stage 2: build ────────────────────────────────────────────
FROM node:20-alpine AS build
WORKDIR /app
COPY --from=deps /app/node_modules ./node_modules
COPY . .
RUN npm run build && npm prune --omit=dev

# ── Stage 3: runtime ──────────────────────────────────────────
FROM node:20-alpine AS runtime
ENV NODE_ENV=production
WORKDIR /app
RUN addgroup -S app && adduser -S app -G app
COPY --from=build --chown=app:app /app/dist ./dist
COPY --from=build --chown=app:app /app/node_modules ./node_modules
COPY --from=build --chown=app:app /app/package.json ./
USER app
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s CMD wget -qO- http://localhost:3000/health || exit 1
CMD ["node", "dist/main.js"]
```

### Layer-order rules (cache hits)

```text
Order from least to most volatile:
1. base image + system deps   (apt/apk)
2. dependency manifests       (package.json lockfile) → npm ci
3. source code                (COPY . .)
4. build output               (npm run build)

Never COPY . . before npm ci — every source edit nukes the
dependency layer and rebuilds take minutes instead of seconds.
```

### .dockerignore essentials

```text
node_modules
dist
.git
.env*
*.md
coverage
.github
```

## kubectl One-Liners

### Debugging flow (the order interviewers expect)

```bash
kubectl get pods -l app=api                       # state overview
kubectl describe pod api-7d9f-x2v                  # events at bottom = gold
kubectl logs api-7d9f-x2v --previous --tail=50     # crashed container's last words
kubectl exec -it api-7d9f-x2v -- sh                # live inspection
kubectl top pod api-7d9f-x2v                       # CPU/mem vs limits
kubectl events --for pod/api-7d9f-x2v --watch      # event stream
```

### Rollouts and rollbacks

```bash
kubectl rollout status deploy/api
kubectl rollout history deploy/api
kubectl rollout undo deploy/api                    # previous revision
kubectl rollout undo deploy/api --to-revision=3
kubectl rollout restart deploy/api                 # pick up configmap/secret changes
kubectl set image deploy/api api=app:1.4.3
kubectl annotate deploy/api kubernetes.io/change-cause="release 1.4.3"  # audit trail
```

### Cross-cutting utilities

```bash
kubectl get all -n staging
kubectl get events -A --sort-by=.lastTimestamp | tail -20
kubectl auth can-i create deployments --as=system:serviceaccount:staging:ci-bot
kubectl cp api-7d9f-x2v:/tmp/dump.json ./dump.json
kubectl drain node-3 --ignore-daemonsets --delete-emptydir-data
```

### Pod states quick table

| State                   | Meaning                  | First move                                            |
| ----------------------- | ------------------------ | ----------------------------------------------------- |
| `CrashLoopBackOff`      | process exits repeatedly | `logs --previous`; check env/secrets/config           |
| `ImagePullBackOff`      | can't fetch image        | verify tag exists; registry secret present            |
| `Pending`               | unschedulable            | `describe` → insufficient CPU/mem? taints? PVC bound? |
| `OOMKilled` (exit 137)  | memory limit exceeded    | raise limit or fix leak; check `top` trend            |
| `Running` but not ready | failing readiness probe  | hit the probe endpoint from inside the pod            |
| `Evicted`               | node under pressure      | check node resources; PDB may block drains            |

## Kubernetes Manifest Snippets

### Probes that don't lie

```yaml
startupProbe:                      # gives slow boots time before liveness kicks in
  httpGet: { path: /health, port: 3000 }
  failureThreshold: 30             # 30 x 5s = 150s boot budget
  periodSeconds: 5
livenessProbe:                     # dead process → restart. NEVER check downstream DBs here
  httpGet: { path: /health, port: 3000 }
  periodSeconds: 10
  timeoutSeconds: 2
readinessProbe:                    # not ready → removed from Service endpoints
  httpGet: { path: /ready, port: 3000 }
  periodSeconds: 5
```

### Resources + PDB + anti-affinity (production trio)

```yaml
resources:
  requests: { cpu: 250m, memory: 512Mi }   # scheduling + HPA baseline
  limits:   { cpu: "1",  memory: 1Gi }     # memory limit = hard kill line
---
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata: { name: api-pdb }
spec:
  minAvailable: 1                 # never all-at-once during drains
  selector: { matchLabels: { app: api } }
---
strategy:
  rollingUpdate: { maxSurge: 1, maxUnavailable: 0 }   # zero-downtime default
```

### HPA skeleton

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata: { name: api-hpa }
spec:
  scaleTargetRef: { apiVersion: apps/v1, kind: Deployment, name: api }
  minReplicas: 3
  maxReplicas: 20
  metrics:
    - type: Resource
      resource: { name: cpu, target: { type: Utilization, averageUtilization: 70 } }
```

## Helm Essentials

```bash
helm upgrade --install api ./chart \
  --namespace prod --create-namespace \
  -f values.prod.yaml \
  --set image.tag=1.4.3 \
  --wait --timeout 5m                # blocks until ready; fails on timeout

helm rollback api 12 -n prod         # release revision, not k8s revision
helm history api -n prod
helm diff upgrade api ./chart -f values.prod.yaml   # plugin; preview like terraform plan
helm template api ./chart -f values.prod.yaml       # render locally, pipe to kubectl diff
helm lint ./chart && helm show values ./chart
```

## GitHub Actions Skeleton (Node CI/CD with caching)

```yaml
name: ci-cd
on:
  push: { branches: [main] }
  pull_request: { branches: [main] }

concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true           # supersede stale runs on same branch

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm                 # built-in dependency cache
      - run: npm ci
      - run: npm run lint && npm run typecheck
      - run: npm test -- --coverage
      - uses: actions/upload-artifact@v4
        if: always()
        with: { name: coverage, path: coverage/ }

  build-push:
    needs: test
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    permissions: { contents: read, packages: write }
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with: { registry: ghcr.io, username: ${{ github.actor }}, password: ${{ secrets.GITHUB_TOKEN }} }
      - uses: docker/build-push-action@v6
        with:
          context: .
          push: true
          tags: |
            ghcr.io/${{ github.repository }}:${{ github.sha }}
            ghcr.io/${{ github.repository }}:latest
          cache-from: type=gha       # layer cache across builds
          cache-to: type=gha,mode=max

  deploy:
    needs: build-push
    runs-on: ubuntu-latest
    environment: production          # gates on required reviewers
    steps:
      - uses: actions/checkout@v4
      - run: |
          helm upgrade --install api ./chart \
            --set image.tag=${{ github.sha }} --wait
```

**Caching cheat table:**

| What            | How                                           |
| --------------- | --------------------------------------------- |
| npm/pnpm deps   | `setup-node` with `cache: npm`                |
| Docker layers   | buildx `cache-from/cache-to: type=gha`        |
| Anything custom | `actions/cache` keyed on lockfile hash        |
| Turborepo/Nx    | remote cache via `actions/cache` restore-keys |

## Argo CD Commands

```bash
argocd login argocd.example.com --sso
argocd app list
argocd app get api                        # sync status + health
argocd app diff api                       # git vs cluster drift
argocd app sync api                       # deploy git state
argocd app sync api --revision 1a2b3c4    # sync specific commit
argocd app sync api --prune --resource deployments:apps:api   # scoped sync
argocd app history api
argocd app rollback api 14                # NOT recommended in GitOps: revert the commit instead
argocd app terminate-op api               # kill stuck sync
```

GitOps rule: rollback = revert the commit and let Argo reconcile. CLI `rollback` creates drift that the next sync will undo anyway — mentioning this distinction is an interview green flag.

## Top 10 Things to Remember

1. **Multi-stage builds**: deps → build → runtime. Runtime image carries no compilers, no dev deps, non-root user.
2. **Layer order is performance**: lockfile before source, always.
3. **Debug order**: `get` → `describe` (events!) → `logs --previous` → `exec` → `top`.
4. **Liveness ≠ readiness**: liveness restarts (cheap check only), readiness gates traffic. Slow boots need a `startupProbe`.
5. **Memory limits are kill switches**: exit 137 means OOMKilled. Requests drive scheduling AND HPA math — unset requests break autoscaling.
6. **PDB + maxUnavailable: 0** is the zero-downtime rolling default for small fleets.
7. **Rollback muscle memory**: `rollout undo` (k8s), `helm rollback N` (helm), revert-commit (Argo). Know which system owns truth in each setup.
8. **CI caching**: deps via `setup-node cache`, layers via buildx GHA cache. Cancel stale runs with `concurrency`.
9. **Deploy gates**: `environment:` blocks with manual approval; `--wait` so failures surface in the pipeline, not in Slack later.
10. **Secrets are not YAML**: sealed-secrets/external-secrets/SOPS; never plaintext in git — including "temporary" values files.

## Red Flags (Things NOT to Say)

- "I debug pods by deleting them" — describes tells you why it crashed; delete-recreate hides root causes.
- "Liveness probe hits `/health` which pings the database" — DB blip restarts your whole fleet. Liveness = self-check only.
- "We set limits high so nothing gets killed" — unbounded memory on one pod starves co-tenants; that's what QoS classes punish.
- "CI passes, so we ship Friday 5pm manually" — no progressive delivery story, no rollback plan.
- "Helm vs Argo — we picked Helm" — they solve different halves: packaging vs reconciliation. Mature setups use both.
- "Secrets in env vars are fine because base64" — base64 is encoding, not encryption.

## Green Flags (Things TO Say)

- "I pin base images by digest and run scans (Trivy) in CI."
- "Readiness gates traffic; startupProbe covers slow boots; liveness stays cheap."
- "Every service ships with requests, limits, and a PDB before it sees production traffic."
- "Our rollback is `git revert` + Argo reconcile — cluster state never diverges from git."
- "We use `kubectl diff` / `helm diff` before every apply."
- "Deploys are blocked by required reviewers via GH environments."

## 5-Minute Pre-Interview Review

- **Docker**: multi-stage (deps/build/runtime), non-root user, lockfile-before-source ordering, `.dockerignore`, HEALTHCHECK.
- **kubectl debug**: get → describe(events) → logs --previous → exec → top. States: CrashLoopBackOff / ImagePullBackOff / Pending / OOMKilled(137).
- **Rollouts**: status/history/undo/restart; annotate change-cause for history.
- **Probes**: startup (boot budget), liveness (restart, self-only), readiness (traffic gate).
- **Production trio**: requests+limits, PDB minAvailable, rollingUpdate maxUnavailable: 0.
- **HPA**: needs requests set; scales on utilization vs target.
- **Helm**: `upgrade --install --wait`, `history`/`rollback`, `template`+`diff` before apply.
- **GH Actions**: concurrency cancel, `cache: npm`, buildx gha layer cache, environments as approval gates, artifact upload `if: always()`.
- **Argo CD**: sync/diff/history; rollback = revert commit, not CLI rollback.

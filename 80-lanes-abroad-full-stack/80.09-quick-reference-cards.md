# Quick Reference Cards — Print and Use

> **One-page cheat sheets** for the most-asked things in EU mid-stage interviews. Print or save these to your phone for the morning of an interview.

## TL;DR

- **8 cards:** STAR prompts, system design framework, take-home checklist, behavioral questions, comp negotiation, country tier matrix, common DSA patterns, red flags
- **Each card:** 1 page, scannable, no fluff
- **Use them the morning of an interview** — 10 min review beats 1 hour of cramming the night before

---

## Card 1: STAR+R Story Prompts

When asked a behavioral question, use this to map it to one of your 8 stories:

| Question pattern                                        | Story to use                                                                                    |
| ------------------                                        | --------------                                                                                    |
| "Tell me about a time you had a conflict"               | Story 4 (4 engineers mentored, 20% better sprint predictability) — disagreement on stack choice |
| "Tell me about a time you failed"                       | Story 6 (RBAC + audit logging for healthcare) — initial under-design                            |
| "Tell me about your most impactful project"             | Story 1 (0→1 founding at Docita) — sole engineer, full SaaS                                     |
| "Tell me about a time you shipped under pressure"       | Story 2 (30% API latency reduction at MAQ) — under deadline, optimized queries                  |
| "Tell me about a system you designed"                   | Story 5 (Microservices platform at Cognizant) — full architecture                               |
| "Tell me about a time you improved a process"           | Story 3 (25% faster delivery at MAQ) — refactored around reusable patterns                      |
| "Tell me about a time you handled an incident"          | Story 8 (Production observability + incident response)                                          |
| "Tell me about a time you mentored someone"             | Story 4 (4 engineers mentored)                                                                  |
| "Tell me about a time you dealt with ambiguity"         | Story 1 (0→1 founding) — had to make every product + tech decision                              |
| "Tell me about a time you used data to make a decision" | Story 7 (85% test coverage, 15% fewer production incidents)                                     |

See [story-bank.md](80.12-story-bank.md) for the full 8 stories with delivery scripts.

## Card 2: System Design 4-Phase Framework

```
┌────────────────────────────────────────────┐
│ 1. CLARIFY (5 min) — ask 3-5 questions │
│ • Functional scope │
│ • Scale (DAU, QPS) │
│ • In/out of scope │
│ • Non-functional (latency, durabil.) │
│ │
│ 2. ESTIMATE (2 min) — back-of-envelope │
│ • QPS: peak + average │
│ • Storage: per day + total │
│ • Bandwidth: peak │
│ │
│ 3. HIGH-LEVEL (10 min) — boxes + arrows │
│ Client → CDN → API → Service → DB │
│ ↓ │
│ Queue → Worker │
│ │
│ 4. DEEP-DIVE (20 min) — pick 2-3 critical │
│ • Database (schema, indexes) │
│ • Queue (idempotency, retry, DLQ) │
│ • Cache (what, TTL, invalidation) │
│ • Trade-offs always (CAP, cost) │
└────────────────────────────────────────────┘
```

For 5 cases to practice, see [System Design Case Bank](80.08-system-design-case-bank.md).

## Card 3: Take-Home Checklist (before submitting)

- [ ] All tests pass locally
- [ ] Type-check passes (`tsc --noEmit`)
- [ ] Lint passes (`eslint .`)
- [ ] README is filled in:
  - [ ] What this does
  - [ ] Quick start
  - [ ] Design decisions
  - [ ] What I'd do with 24 more hours
- [ ] `.env.example` exists, no real secrets in commits
- [ ] Repo is public (or shared with their HR)
- [ ] Commit history is clean (meaningful messages, no force pushes)
- [ ] Optional: 2-3 min Loom walkthrough
- [ ] 1-paragraph cover note explaining your approach

For the full playbook, see [Take Home Playbook](80.01-take-home-playbook.md).

## Card 4: Behavioral — 60-second "Tell me about yourself"

```
"I'm a [role] with [X] years of experience building [domain].
Most recently at [company], I [achievement 1 with metric] and
[achievement 2 with metric]. Before that, [brief context]. I'm
looking for [what you want] because [reason]."
```

**Example:**
"I'm a senior full-stack engineer with 5 years of experience building multi-tenant healthcare SaaS. Most recently at Docita, I shipped a production multi-tenant system from scratch as the sole engineer, supporting 50+ clinics. Before that at MAQ Software, I reduced API latency by 30% and mentored 4 engineers. I'm looking for an EU mid-stage role with a take-home + system design loop because I want to ship production code in a smaller team and build toward staff."

## Card 5: Behavioral — "Why this company?" 60 seconds

```
1. 1 product feature or engineering blog post that excited you
2. 1 specific person/team you'd learn from
3. 1 thing about the company culture that aligns with how you work
4. Close with a recent product/launch you're excited about
```

**For n8n example:**
"I read your engineering blog post on the new execution engine — the way you handled state recovery on partial failure is exactly the kind of distributed systems work I want to do. I'm also excited about [person, e.g., your CTO X] based on [their talk / their GitHub]. Your culture of async-first communication + the 4-day workweek aligns with how I work best. And I'm particularly excited about the recent [Workflow Code] launch — that's the kind of feature that opens a new category."

## Card 6: "When are you available to start?"

**The safe answer:**
"I need to give [current employer / co-founder / team] 4 weeks notice. I can start [4-6 weeks from offer date]."

**The flexible answer (if you really want the role):**
"I can be flexible. If we close quickly, I can start in 2-3 weeks. If you need 6 weeks, that works too."

**The pushback answer (if they pressure for <2 weeks):**
"Ideally I'd like to give proper notice. What's the latest start date that works for you? If it's 2 weeks, I can do that but I'd appreciate flexibility on the actual onboarding date vs. contract start."

## Card 7: Comp Negotiation Script

When asked: "What are your salary expectations?"

**Don't go first.** Say:
"I'm flexible based on the full package. Based on my research, senior full-stack roles in [city] are in the EUR X-Y range base + 0.0Z% equity. I'm more interested in the right role and team. Can you share the budgeted range for this position?"

When they make an offer, always counter:
"Thank you for the offer — I'm very excited about [specific thing]. Based on my research and competing opportunities, I'd like to discuss the base salary. I was thinking [X% higher] or [higher absolute number]. I'm also interested in [more equity / signing bonus / relocation package]. Can we discuss?"

For full comp tables, see [Comp Eu Benchmarking](80.05-comp-eu-benchmarking.md).

## Card 9: Common DSA Patterns (the 6)

| Pattern            | Use when                           | Signature problem          |
| ---------            | ----------                           | -------------------          |
| **HashMap**        | O(1) lookup, dedup, frequency      | Two Sum                    |
| **Sliding Window** | Contiguous subarray/substring      | Max sum subarray of size K |
| **Two Pointers**   | Sorted array, pair-finding         | Two Sum II                 |
| **BFS/DFS**        | Tree/grid traversal, shortest path | Number of islands          |
| **1D DP**          | Linear optimization, recurrence    | Climbing stairs            |
| **Stack/Queue**    | Matching, monotonic, BFS           | Valid parentheses          |

**Skip for this lane:** hard DP, segment tree, bitmask, monotonic stack, KMP, union-find.

For the full 30-40 problem set, see [Tech Screen Patterns](80.02-tech-screen-patterns.md).

## Card 10: Red Flags to Avoid

**In the interview:**
- Starting to code before clarifying
- Silent for 5+ min when stuck
- No questions at the end
- Generic "Why this company?" (great products, smart people)
- "I don't have conflicts" or "I don't really fail"
- No metrics in STAR results
- No reflection in STAR (the senior signal)

**In the take-home:**
- No tests
- No README
- `any` everywhere in TypeScript
- Hardcoded credentials
- `git push --force` history
- AI-generated looking code

**In negotiation:**
- Going first on comp (let them anchor)
- Accepting the first offer without countering
- Bluffing about competing offers
- Negotiating only base (also negotiate equity, relocation, 30% ruling)

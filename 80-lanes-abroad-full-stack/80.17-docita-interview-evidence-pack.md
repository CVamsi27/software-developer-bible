## 3. Five technical answers to know cold

### Tenant isolation

Every clinic-owned resource carries clinic ownership. `TenantContextInterceptor` derives the authenticated clinic/user context and can apply PostgreSQL RLS inside the request transaction. `packages/authorization/src/policies/` applies ABAC to subject/resource clinic and ownership attributes. Tests cover cross-clinic denial. This is defense in depth, not one magic wrapper.

### Durable booking and retries

Use a transaction for the minimal atomic business effect, plus an idempotency key for client retries. If downstream work is required, persist a durable outbox event and let the worker handle retryable provider work. Keep external calls out of the request transaction.

### PostgreSQL choice

Clinic workflows are relational and consistency-sensitive: patients, appointments, prescriptions, invoices, roles, audit records, and jobs. PostgreSQL gives constraints, transactions, joins, indexes, and query plans. A document store would move too much consistency work into application code.

### Performance story

Measure p95 and round trips, inspect the query shape, identify N+1 work, fetch/batch/select deliberately, then re-measure. The repository includes N+1 and API-latency guardrails; do not invent a historical measurement, APM vendor, or reconciliation job without current evidence.

### Worker boundary

The worker handles retryable work such as messaging, documents, scheduled processing, and integrations. Its contract has attempts, backoff, idempotency keys, dead-letter behavior, and replay metadata. Describe it as at-least-once processing with idempotent consumers, not exactly-once delivery.

## 4. Security answers that distinguish you

- **ABAC:** subject, resource, and clinic ownership are evaluated on the backend; hiding a UI button is never the security boundary.
- **Audit:** patient-PHI access helpers and audit E2E tests capture accountable access information; retention and legal policy must be confirmed separately.
- **PHI in telemetry:** `sentry.utils.ts` redacts request payloads, query strings, headers, cookies, contexts, tags, extras, breadcrumbs, and messages before error tracking.
- **Webhooks:** verify signatures, deduplicate retries, create durable work atomically, and return safe responses. E2E tests cover valid/tampered signatures and duplicates.
- **Uploads:** authorize and tenant-scope first, validate server-side, avoid PHI in logs, and confirm malware scanning/storage encryption from deployed evidence before claiming it.
- **Compliance:** describe controls, never claim certification. Consent, export, and deletion code exist; legal retention and notification obligations need policy confirmation.

## 5. Trade-offs to state explicitly

- **Shared-schema tenancy:** simpler operations; demands ABAC, scoped queries, tests, and RLS where enabled.
- **Outbox + worker:** durable and provider-resilient; introduces eventual consistency and queue operations.
- **Vite SPA:** simple dashboard delivery and explicit client state; less built-in server rendering/SEO than Next.js.
- **Denormalized read model:** can improve hot reads; adds reconciliation/drift responsibility.
- **Caching:** only for tenant-scoped values with explicit invalidation and database fallback.
- **Migrations:** application rollback is easier than database rollback; use expand/contract compatibility rather than destructive changes.

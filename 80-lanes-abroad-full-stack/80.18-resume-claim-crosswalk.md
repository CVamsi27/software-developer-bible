# Resume Claim Crosswalk

[![Role priority](https://img.shields.io/badge/role--priority-Important-blue)](../docs/topic-importance.md)
[![General importance](https://img.shields.io/badge/general--importance-Important-blue)](../docs/topic-importance.md)

Every impressive phrase on a senior engineer's resume is a target for a 10-minute whiteboard drill. If your bullet says *"guaranteed zero-leak Row-Level Security (RLS)"* or *"cut application programming interface (API) latency by 65%"* and you cannot explain the exact runtime role, transaction scope, or before-and-after workload, one follow-up question erodes trust across the whole interview.

A **claim crosswalk** audits every major bullet against its actual proof *before* you submit your curriculum vitae (CV). Keep your actual CV and private records in your private workspace.

## First Principles

Resume bullets outlive the code revision and metrics they came from. Linking each claim to its **source, check date, scope, and boundary** ensures you only say what you can defend calmly under deep technical probing.

## 1. Audit Every Bullet With a 5-Step Chain

```text
Draft CV bullet ─► Supporting artifact ─► Date & exact scope ─► Known limit ─► Defensible wording
```

*Example:* Seeing an index in a Prisma schema proves the index was added — it does **not** prove historical 95th-percentile (`p95`) latency dropped by 60% if the old dashboard is gone. If you lack an exact before-and-after number, state the verified engineering work cleanly (*"Implemented tenant-scoped resource authorization with cross-tenant integration tests"*) instead of inventing a percentage.

## 2. What Proof Each Type of Claim Actually Needs

| Claim type | Required proof | How to keep wording accurate |
| ------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| **Feature or system ownership** | Commit history, design notes, key files, and tests | Separate *your* contribution from shared team work |
| **Performance improvement** | Matching before-and-after workload, environment, percentile, and error rate | Never pass a local benchmark off as production traffic |
| **Usage or product scale** | Approved report with date range and clear definition | Distinguish booked slots from completed visits |
| **Security control** | Real enforcement path plus negative (denial) tests | A configuration flag or policy file alone is not proof |
| **Production operations** | Live deployment identity, runbooks, and monitoring ownership | Source code alone does not prove deployed runtime state |
| **Work authorization or visa** | Official current route and qualification criteria | Eligibility for an EU Blue Card is not existing work authorization |

## 3. Seven Common Overclaims — and How to Tighten Them

| Risky resume phrasing | What a senior interviewer will probe (and how to scope it cleanly) |
| ------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **"RLS prevents all leaks in production"** | Confirm active database policies, non-owner or non-`BYPASSRLS` runtime role, transaction-local context, and cross-tenant denial tests |
| **"Immutable audit trail"** | Clarify whether immutability is application-level or database-enforced (triggers or permissions) and who holds privileged administrator access |
| **"Hard artificial intelligence (AI) spend cap"** | Check atomic pre-flight reservation under concurrent calls, retry accounting, and fail-open versus fail-closed behavior |
| **"Exactly-once notifications"** | State atomic local outbox write separately from remote provider idempotency and reconciliation after crashes |
| **"Fully compliant healthcare platform"** | Name the exact technical controls you built; full legal compliance requires organizational governance and formal assessment |
| **"Hundreds of tests"** | Distinguish test cases versus files, confirm they run in CI, and highlight the risky edge cases covered |
| **"No sponsorship required"** | Be accurate: explain the exact European Union (EU) Blue Card route and employer employment-declaration step honestly |

## 4. Final Pre-Submit Check

Pick one implementation boundary, one verified outcome, and one real ownership decision tailored to the target role. After editing your CV, always re-inspect the final exported Portable Document Format (PDF) file so text order, dates, and wording match your audited crosswalk, and never attach unredacted patient data, secrets, or private client contracts.

## Summary

Keep every resume bullet strictly within the scope of proof you can defend aloud. Attach source, date, and measurement boundaries in your private crosswalk, trim vague superlatives into crisp engineering facts, and verify the exported PDF before sending.

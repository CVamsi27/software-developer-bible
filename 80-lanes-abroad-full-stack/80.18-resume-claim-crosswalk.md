# Resume Claim Crosswalk

[![Role priority](https://img.shields.io/badge/role--priority-Important-blue)](../docs/topic-importance.md)
[![General importance](https://img.shields.io/badge/general--importance-Important-blue)](../docs/topic-importance.md)

Every impressive phrase on a senior engineer's resume is a target for a 10-minute whiteboard drill. If your bullet says *"guaranteed zero-leak RLS"* or *"cut API latency by 65%"* and you cannot explain the exact runtime role, transaction scope, or before/after workload, one follow-up question erodes trust across the whole interview. A **claim crosswalk** audits every major bullet against its actual proof *before* you submit your CV. Keep your actual CV and private records in your private workspace.

## First Principles

Resume bullets outlive the code revision and metrics they came from. Linking each claim to its **source, check date, scope, and boundary** ensures you only say what you can defend calmly under deep technical probing.

## 1. Audit Every Bullet With a 5-Step Chain

```text
Draft CV bullet ─► Supporting artifact ─► Date & exact scope ─► Known limit ─► Defensible wording
```

*Example:* Seeing an index in a Prisma schema proves the index was added — it does **not** prove historical p95 latency dropped by 60% if the old dashboard is gone. If you lack an exact before/after number, state the verified engineering work cleanly (*"Implemented tenant-scoped resource authorization with cross-tenant integration tests"*) instead of inventing a percentage.

## 2. What Proof Each Type of Claim Actually Needs

| Claim type | Required proof | How to keep wording accurate |
| ------------------------------ | ------------------------------------------------------------ | -------------------------------------------------------------- |
| **Feature / system ownership** | Commit history, design notes, key files & tests | Separate *your* contribution from shared team work |
| **Performance improvement** | Matching before/after workload, env, percentile & error rate | Never pass a local benchmark off as production traffic |
| **Usage / product scale** | Approved report with date range & clear definition | Distinguish booked slots from completed visits |
| **Security control** | Real enforcement path + negative (denial) tests | A config flag or policy file alone is not proof |
| **Production operations** | Live deployment identity, runbooks & monitoring ownership | Source code alone does not prove deployed runtime state |
| **Work authorization / visa** | Official current route & qualification criteria | Eligibility for a Blue Card is not existing work authorization |

## 3. Seven Common Overclaims — and How to Tighten Them

| Risky resume phrasing | What a senior interviewer will probe (and how to scope it cleanly) |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| **"RLS prevents all leaks in production"** | Confirm active DB policies, non-owner/non-`BYPASSRLS` runtime role, transaction-local context, and cross-tenant denial tests |
| **"Immutable audit trail"** | Clarify whether immutability is app-level or DB-enforced (triggers/permissions) and who holds privileged admin access |
| **"Hard AI spend cap"** | Check atomic pre-flight reservation under concurrent calls, retry accounting, and fail-open vs. fail-closed behavior |
| **"Exactly-once notifications"** | State atomic local outbox write separately from remote provider idempotency/reconciliation after crashes |
| **"Fully compliant healthcare platform"** | Name the exact technical controls you built; full legal compliance requires organizational governance and formal assessment |
| **"Hundreds of tests"** | Distinguish test cases vs. files, confirm they run in CI, and highlight the actual risky edge cases covered |
| **"No sponsorship required"** | Be accurate: explain the exact route (e.g., EU Blue Card) and employer employment-declaration step honestly |

## 4. Final Pre-Submit Check

Pick one implementation boundary, one verified outcome, and one real ownership decision tailored to the target role. After editing your CV, always re-inspect the final exported PDF so text order, dates, and wording match your audited crosswalk, and never attach unredacted patient data, secrets, or private client contracts.

## Summary

Keep every resume bullet strictly within the scope of proof you can defend aloud. Attach source, date, and measurement boundaries in your private crosswalk, trim vague superlatives into crisp engineering facts, and verify the exported PDF before sending.

# Resume Claim Crosswalk — Docita Evidence and Interview Coverage

> Use this before submitting the resume or entering a technical interview. It is a truth ledger: each Docita line is either code-confirmed, an approved business metric, or a personal claim that needs your own evidence. It does not manufacture proof from source code.

## Evidence standard

- **Code-confirmed** means the current repository contains the implementation, configuration, or automated check.
- **Approved business metric** means it may appear on the resume only with the stated measurement boundary and a current analytics check before an interview.
- **Personal claim** means it can be true, but needs your own work history, manager reference, PR, or artifact—not this repository.

When documentation conflicts with executable code, prefer the current code and package manifest. For example, the app manifests resolve React Router v8 even though older architecture prose mentions v7.

## Proof packet to prepare

1. A sanitized repository walk-through: schema, tenant interceptor, an ABAC policy, PHI scrubber, webhook test, worker README, and safe migration script.
2. One current analytics screenshot or approved internal report for clinic count and appointment workflow volume, with the date and measurement definition visible.
3. One current performance dashboard, benchmark, or PR if you want to quote a before/after latency or query count.
4. Personal evidence for MAQ and Cognizant achievements: manager reference, review, PR, release note, or sanitized project artifact.

## Final answer rule

For any claim: **problem → decision → trade-off → evidence → next improvement**. If you cannot show the evidence, narrow the claim rather than guessing.

## The 6-Phase Take-Home Process

### Phase 0: Understand (30 min)
```markdown
## Before Writing Any Code
1. Read the brief 3 times
2. List all requirements (must-have vs nice-to-have)
3. List questions to ask (clarify ambiguity)
4. Identify the core technical challenge
5. Plan your time (usually 4-6 hours of actual work)
6. Set up project structure
```

### Phase 1: Architecture (1 hour)
```markdown
## Design Before Code
1. Sketch the high-level architecture
2. Design the database schema
3. Plan the API endpoints
4. Decide on auth strategy
5. Plan error handling
6. Write a brief architecture doc
```

### Phase 2: Backend (2-3 hours)
```markdown
## Build the API
1. Set up NestJS + Prisma + PostgreSQL
2. Implement auth (JWT + refresh)
3. Build core CRUD endpoints
4. Add validation (class-validator)
5. Add error handling (exception filter)
6. Add audit logging
7. Write unit tests for business logic
8. Write integration tests for API endpoints
```

### Phase 3: Frontend (1-2 hours)
```markdown
## Build the UI (if required)
1. Set up React + TypeScript + Tailwind
2. Implement auth flow (login/register)
3. Build core views
4. Add loading states and error handling
5. Add optimistic updates
6. Make it responsive
7. Write component tests (RTL)
```

### Phase 4: Polish (1 hour)
```markdown
## Make It Production-Quality
1. Add comprehensive README
2. Document design decisions
3. Add environment setup instructions
4. Add Docker Compose for local dev
5. Add linting (ESLint + Prettier)
6. Add CI config (GitHub Actions)
7. Write "what I'd do with 24 more hours" section
```

### Phase 5: Review (30 min)
```markdown
## Self-Review Before Submitting
1. Run all tests (they must pass)
2. Check for hardcoded values
3. Check for console.logs in production code
4. Verify error handling works
5. Test edge cases manually
6. Review commit messages
7. Read README as if you're a new developer
```

const crudWithAuth = {

## What Separates Good from Great

### Good (Passes)
```typescript
const goodTakeHome = {
  code: 'Clean, follows conventions',
  tests: 'Happy path tests only',
  docs: 'Basic README with setup',
  errors: 'Generic error messages',
  security: 'Basic JWT auth',
  edge: 'Handles some edge cases'
};
```

### Great (Strong Hire Signal)
```typescript
const greatTakeHome = {
  code: {
    structure: 'Clean architecture, separation of concerns',
    types: 'Full TypeScript, no any',
    naming: 'Descriptive names, self-documenting'
  },
  tests: {
    unit: 'Business logic tests (90%+ coverage)',
    integration: 'API endpoint tests with real DB',
    edge: 'Error cases, validation, auth failures',
    strategy: 'Testing pyramid, not just coverage'
  },
  docs: {
    readme: 'Setup, architecture, design decisions, trade-offs',
    api: 'OpenAPI spec or endpoint documentation',
    decisions: 'ADR for key choices',
    future: '"What I\'d do with 24 more hours" section'
  },
  errors: {
    handling: 'RFC 7807 problem details',
    validation: 'Field-level error messages',
    auth: 'Proper 401/403/404/409 responses',
    logging: 'Structured logs with request IDs'
  },
  security: {
    auth: 'JWT + refresh token rotation',
    validation: 'Input validation on all endpoints',
    rateLimit: 'Rate limiting on auth endpoints',
    audit: 'Audit log for sensitive operations'
  },
  edge: {
    concurrency: 'Idempotency keys for writes',
    tenantIsolation: 'Cross-clinic denial tests',
    offline: 'WebSocket reconnection handling',
    performance: 'Pagination, caching hints'
  }
};
```

## README Template

```markdown
# [Project Name]

## Overview
[1-2 sentences describing what this does]

## Architecture
[High-level diagram or description]

## Tech Stack
- Backend: NestJS, Prisma, PostgreSQL
- Frontend: React, TypeScript, Tailwind
- Auth: JWT with refresh token rotation
- Testing: Jest, Supertest, RTL

## Setup
### Prerequisites
- Node.js 20+
- PostgreSQL 15+
- Docker (optional)

### Installation
npm install

### Database
npx prisma migrate dev
npx prisma db seed

### Running
npm run dev

## API Endpoints
[Table of endpoints with method, path, description]

## Design Decisions
[Why you made key choices]

## Trade-offs
[What you chose and what you gave up]

## What I'd Do With 24 More Hours
[Specific improvements you'd make]

## Testing
npm test # Unit tests
npm run test:e2e # Integration tests

## Deployment
[Docker Compose or deployment instructions]
```

## Common Mistakes

| Mistake              | Why It Hurts                            | Fix                               |
| ---------              | -------------                             | -----                               |
| No tests             | Shows you don't value quality           | Add unit + integration tests      |
| No README            | Shows you don't think about others      | Write comprehensive README        |
| Hardcoded values     | Shows you don't think about deployment  | Use environment variables         |
| No error handling    | Shows you don't think about failure     | Add exception filter + validation |
| `any` everywhere     | Shows you don't value TypeScript        | Use proper types                  |
| No linting           | Shows you don't care about code quality | Add ESLint + Prettier             |
| Messy commits        | Shows you don't think about history     | Meaningful commit messages        |
| No architecture docs | Shows you don't think about design      | Add ADR or design section         |
| Missing edge cases   | Shows you don't think about failure     | Add error + validation tests      |
| No Docker            | Shows you don't think about deployment  | Add docker-compose.yml            |

## Time Management

### 6-Hour Take-Home
| Phase        | Time      | Deliverable                        |
| -------        | ------      | -------------                        |
| Understand   | 30 min    | Requirements list, questions       |

## Interview Tips
- Start with architecture, not code
- Write README first (forces you to think about design)
- Add tests as you go, not at the end
- Use environment variables for all config
- Add a "what I'd do with 24 more hours" section
- Commit with meaningful messages
- Self-review before submitting

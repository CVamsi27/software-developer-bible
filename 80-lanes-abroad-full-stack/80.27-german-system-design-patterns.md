# Domain Constraints for System Design

[![Role priority](https://img.shields.io/badge/role--priority-Important-blue)](../docs/topic-importance.md)
[![General importance](https://img.shields.io/badge/general--importance-Important-blue)](../docs/topic-importance.md)



Payments, logistics, healthcare, and workflow software differ in what must remain true when something fails. These are design exercises, not descriptions of particular German companies' implementations. Start with the [system-design method](80.03-system-design-eu-patterns.md), then use the relevant domain below to sharpen the invariant.

## First Principles

Different domains assign different meaning to a state change: a payment moves money, a position has units and time, and a clinical record carries identity and privacy boundaries. A design must derive its invariant from that meaning before selecting shared technical patterns.

## Payments: distinguish failure from unknown outcome

A payment request times out. The provider may have rejected it, accepted it, or still be processing it. Releasing a funds reservation immediately and retrying under a new key can create inconsistent balances or duplicate effects.

```text
validated authorized request → atomic local reservation and durable intent
  → provider attempt → confirmed result OR pending reconciliation
```

Bind a scoped idempotency key to the operation's normalized payload and claim it atomically. Use the provider's supported mechanism within its scope and retention limits. Deduplication at your API does not automatically deduplicate the provider's effects.

Keep monetary amounts, currencies, rounding, fees, and ledger entries explicit. A balanced ledger checks accounting consistency; it does not independently prove that an external transfer settled. Reconcile internal state with authoritative provider evidence and define a procedure for discrepancies. A timeout is not definitive cancellation.

For trading, distinguish the venue's matching behavior from a broker application's order-routing workflow. Do not assume that a generic PostgreSQL transaction atomically settles securities and cash across external institutions. For portfolio display, name the valuation time, price source, currency conversion and missing-data behavior; an indicative value is not an executable quote.

## Logistics: preserve identity, order and units

A driver sends an old position after reconnecting. If the system overwrites the latest position by arrival time, the map can jump backward.

| Input boundary | Required decision |
| -------------- | ------------------------------------------------------------------------ |
| Position | Authorized source, event identity, event time and ordering policy |
| Coordinates | Coordinate system, latitude/longitude order and accuracy |
| Capacity | Compatible weight/volume units and committed versus offered capacity |
| Route | Feasible route and time window rather than geographic proximity alone |
| Alert | Boundary semantics, noisy readings, repeated crossings and deduplication |

Separate a display of the latest accepted position from historical retention. Define how delayed and missing updates appear; “every ten seconds” is a proposed sampling rate, not an observed latency guarantee. A geofence needs an explicit boundary policy, and one noisy point should not automatically become a confirmed route deviation.

If matching uses a weighted score, normalize the inputs and explain whose objective it serves. Arbitrary 40/30/30 weights cannot establish a good operational match. Start with hard feasibility constraints, then evaluate ranking against the chosen outcome.

## Healthcare: scope the resource and the disclosure

A patient, clinician, and room can each impose a different scheduling constraint. Equal-start checks do not cover overlapping intervals. Lock or constrain every contested resource consistently, and ensure all participating write paths follow the mechanism. Distinguish repeated-request idempotency from competing bookings.

A clinic-wide realtime room can include users with different permissions. Authorize the actual resource payload rather than assuming room membership grants access to all clinical records. Keep sensitive content out of unintended telemetry and caches; identifiers and aggregates may still be personal data.

Retention, exports, deletion, lawful processing and cross-border access depend on the actual data and obligations. There is no universal seven-year healthcare retention rule or thirty-day export lifetime established by this exercise. Use the [compliance guide](80.24-eu-regulatory-compliance.md) to identify scope, then implement and verify the assessed policy.

## Workflow SaaS: version the run and own the attempt

A workflow changes while an old run is paused. The resumed run needs a defined version and input, not whichever steps happen to be current.

| Boundary | Contract |
| ---------------------- | ----------------------------------------------------------------------------- |
| Run creation | Authorized immutable definition snapshot and bounded input |
| Attempt | Durable ownership, timeout, recovery and terminal result |
| Step retry | Classified failure, budget, remote effect uncertainty |
| Parallel steps | Dependency order, concurrency bound, shared-state rules |
| Cancellation | What stops immediately and what already-started work may still complete |
| Cross-tenant analytics | Explicit purpose, authorization and minimization, including privileged access |

A unique `(run, step)` row does not make an arbitrary remote call idempotent. A queue per workflow does not automatically provide resource isolation. Removing tenant filters from an analytics replica is not an authorization design. Use the [workflow starter](80.15-take-home-starter-prompt.md) to practice a small inspectable subset.

## Summary

Choose the domain's invariant before choosing a pattern. Trace an uncertain payment, a delayed location, a contested slot, or a resumed run through failure and recovery. Treat numbers and legal policies as requirements to establish, not defaults to copy.

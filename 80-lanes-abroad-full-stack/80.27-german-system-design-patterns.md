# Domain Constraints for System Design

[![Role priority](https://img.shields.io/badge/role--priority-Important-blue)](../docs/topic-importance.md)
[![General importance](https://img.shields.io/badge/general--importance-Important-blue)](../docs/topic-importance.md)

Generic system design advice tells you to "add a queue and a cache." In real senior interviews across European product startups — fintech, logistics, healthtech, and workflow SaaS — the **domain itself dictates what must never break**. Start with the general framework in [System Design — From Requirements to Failure Recovery](80.03-system-design-eu-patterns.md), then use the four domain blueprints below to derive the exact invariants before picking tools.

## First Principles

State transitions mean radically different things across domains: a payment moves real money through an external bank, a delivery GPS ping can arrive out of order from a tunnel, a clinical record carries strict privacy scope, and a paused workflow can outlive a code deploy. Derive the **domain invariant first**, then pick the database constraint, queue, or reconciliation rule that protects it.

## 1. Payments & Fintech: Timeout Means "Unknown," Never "Failed"

When a payment call to Stripe/Adyen times out, the provider may have **rejected it, accepted it, or still be processing it**. If you immediately release the customer's funds reservation and retry with a brand-new key, you risk charging them twice.

```text
Validated request ─► Atomic local reservation + durable payment intent
                       ─► External PSP call (with scoped idempotency key)
                            ├─ Confirmed success / definite decline ─► finalize ledger
                            └─ Network timeout ─► mark PENDING ─► reconcile via webhook / status poll
```

- **Key rules:** Bind your idempotency key to the exact normalized payload and scope (reject key reuse with a different amount); keep amounts in integer minor units (cents) with explicit currency; remember that a balanced internal double-entry ledger proves accounting consistency, **not** that an external bank transfer settled — always run reconciliation against authoritative provider reports.
- **Trading/brokerage note:** Order matching at an exchange and order routing inside a broker app are separate systems; a single PostgreSQL transaction cannot atomically settle securities across external clearing houses, and cached quote prices must show their valuation timestamp.

## 2. Logistics & Mobility: Preserve Event Time, Units, and Order

A delivery van enters an underground tunnel, loses signal, and reconnects ten minutes later uploading buffered GPS points. If your backend blindly overwrites `driver.last_location` by server arrival time, the customer's live map jumps backward in time.

| Input boundary | Design decision to make explicit |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **Position updates** | Track `event_time` separately from `received_at`; reject or archive out-of-order updates instead of overwriting newer state |
| **Coordinates** | Lock down coordinate system (`WGS 84 / SRID 4326`), `(lat, lng)` vs. `(lng, lat)` order, and GPS accuracy radius |
| **Vehicle capacity** | Use consistent units (kg vs. m³) and track committed load vs. remaining capacity |
| **Routing & ETA** | Match on feasible road routes and delivery windows — straight-line distance ignores rivers and highways |
| **Geofence alerts** | Require hysteresis or consecutive readings so one noisy GPS jump does not spam false "arrived" alerts |

Separate the **latest-position view** from append-only historical tracks, and filter hard feasibility constraints (vehicle size, time window, legal driving hours) before ranking routes.

## 3. Healthcare: Guard Overlapping Intervals and Payload Privacy

Booking a medical visit involves multiple overlapping constraints: **clinician availability, room/equipment capacity, and patient schedule**.

- **Overlap trap:** A simple `UNIQUE (clinician_id, start_time)` constraint allows a `10:00–10:30` appointment and a `10:15–10:45` appointment to coexist! Enforce interval exclusion (e.g., PostgreSQL exclusion constraint `EXCLUDE USING gist`) or lock the contested capacity consistently across every write path. Keep **idempotency** (same user retrying a double-click) separate from **concurrency control** (two different patients racing for the same slot).
- **Realtime privacy trap:** Being connected to a clinic-wide WebSocket room does *not* authorize every staff role to see sensitive clinical notes — filter and authorize payload fields per recipient role, and keep patient identifiers out of unredacted logs and caches. Check applicable retention and transfer rules via [EU Regulatory Compliance](80.24-eu-regulatory-compliance.md) rather than assuming universal 7-year retention rules.

## 4. Workflow SaaS: Pin the Definition Version to Each Run

Suppose an admin edits a multi-step approval workflow while 50 older runs are paused waiting for a webhook. If resumed runs execute the *newly edited* graph against old step outputs, data breaks unpredictably.

| Workflow boundary | Concrete contract to design |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Run creation** | Save an immutable snapshot of the workflow definition version + bounded input payload |
| **Step ownership** | Persist durable attempt claims with lease expiry; reject stale writes if a slow worker wakes up after its lease expired |
| **Retries** | Retry only classified transient failures with capped attempts; recognize that a unique `(run, step)` row does not make an external API idempotent |
| **Parallel branches** | Bound fan-out concurrency and define explicit join/failure semantics |
| **Cancellation** | State clearly which pending steps stop immediately and which already-dispatched remote calls may still finish |
| **Analytics** | Keep tenant authorization enforced even on read replicas and aggregated reporting tables |

Practice a clean, bounded slice of this architecture using [Workflow Portfolio Starter](80.15-take-home-starter-prompt.md).

## Summary

Always derive the domain's real-world failure invariant before reaching for generic architecture patterns: treat timed-out payments as pending until reconciled, order logistics updates by event time, protect healthcare slots against overlapping intervals and overbroad room broadcasts, and pin immutable definition versions onto every workflow run.

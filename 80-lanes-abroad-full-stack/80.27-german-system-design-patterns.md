## Fintech Patterns (Scalable Capital, Trade Republic, N26, Solarisbank)

### Payment Processing
```typescript
// Idempotent payment flow
const paymentFlow = {
  // Step 1: Validate and create idempotency key
  validate: {
    input: 'PaymentRequest { amount, currency, userId, idempotencyKey }',
    checks: ['Amount > 0', 'Valid currency', 'User exists', 'Idempotency key unique']
  },

  // Step 2: Hold funds (reserves)
  hold: {
    service: 'Ledger Service',
    operation: 'CREATE hold entry',
    consistency: 'Strong (PostgreSQL transaction)',
    idempotency: 'Idempotency key prevents double-hold'
  },

  // Step 3: Call PSP (Payment Service Provider)
  psp: {
    provider: 'Stripe / Adyen',
    operation: 'Create payment intent',
    timeout: '10 seconds',
    retry: '3 attempts with exponential backoff',
    idempotency: 'PSP idempotency key = our idempotency key'
  },

  // Step 4: Confirm or cancel
  confirm: {
    success: 'Update ledger: HOLD → SETTLED',
    failure: 'Update ledger: HOLD → CANCELLED',
    webhook: 'PSP sends async confirmation'
  },

  // Step 5: Reconciliation
  reconcile: {
    frequency: 'Daily batch',
    comparison: 'Internal ledger vs PSP records',
    discrepancies: 'Alert + manual review queue'
  }
};
```

### Trading System
```typescript
// Order execution flow
const tradingFlow = {
  // Order types
  orderTypes: ['MARKET', 'LIMIT', 'STOP_LOSS', 'TAKE_PROFIT'],

  // Execution engine
  execution: {
    // Step 1: Validate order
    validate: {
      checks: [
        'User has sufficient balance',
        'Asset is tradeable',
        'Market is open',
        'Order size within limits',
        'Price within circuit breaker bounds'
      ]
    },

    // Step 2: Find matching order (for limit orders)
    matching: {
      algorithm: 'Price-time priority (FIFO)',
      dataStructure: 'Sorted order book per asset',
      consistency: 'Strong (single-threaded matching engine)'
    },

    // Step 3: Execute trade
    execute: {
      operation: 'Atomic swap: buyer gets asset, seller gets cash',
      consistency: 'Strong (PostgreSQL transaction)',
      idempotency: 'Trade ID is idempotency key'
    },

    // Step 4: Notify
    notify: {
      channels: ['In-app', 'Email', 'Push notification'],
      timing: 'Async (outbox pattern)',
      idempotency: 'Notification ID prevents duplicates'
    }
  }
};
```

### Portfolio Management
```typescript
// Real-time portfolio valuation
const portfolioValuation = {
  // Data sources
  sources: {
    marketData: 'Real-time price feeds (WebSocket)',
    positions: 'PostgreSQL (user holdings)',
    transactions: 'PostgreSQL (trade history)'
  },

  // Calculation
  calculation: {
    // For each position:
    // market_value = quantity × current_price
    // unrealized_pnl = market_value - cost_basis
    // portfolio_value = sum(market_values)
    frequency: 'On-demand (user opens app) + every 5 min (background)',
    consistency: 'Eventual (market data may lag 100ms)'
  },

  // Caching
  caching: {
    strategy: 'Cache-aside with short TTL',
    key: 'portfolio:{userId}',
    ttl: '30 seconds',
    invalidation: 'On trade execution, on price update > 1%'
  },

  // Scaling
  scaling: {
    // For 600K users × 10 positions each = 6M valuations
    approach: 'Pre-compute valuations for active users, lazy for inactive',
    consistency: 'Eventual (30s stale acceptable for display)'
  }
};
```

## Logistics Patterns (sennder, Delivery Hero)

### Freight Matching
```typescript
// Match shipper with carrier
const freightMatching = {
  // Constraints
  constraints: {
    route: 'Carrier must cover the origin-destination route',
    capacity: 'Carrier capacity >= shipment weight/volume',
    timing: 'Carrier availability matches pickup window',
    price: 'Bid within shipper's budget'
  },

  // Matching algorithm
  algorithm: {
    // Step 1: Filter carriers by route + capacity + timing
    filter: 'PostGIS spatial query + capacity check',
    
    // Step 2: Score by price + rating + reliability
    scoring: 'Weighted sum: price (40%) + rating (30%) + reliability (30%)',
    
    // Step 3: Present top 3 to shipper
    presentation: 'Shipper selects or negotiates'
  },

  // Data model
  schema: {
    shipment: 'origin, destination, weight, volume, pickup_window, budget',
    carrier: 'routes, capacity, price_per_km, rating, reliability_score',
    match: 'shipment_id, carrier_id, price, status, created_at'
  }
};
```

### Real-Time Tracking
```typescript
// GPS tracking for shipments
const realTimeTracking = {
  // Data flow
  flow: {
    // Driver app sends GPS every 10 seconds
    collect: 'WebSocket from driver app → API',
    
    // Store in time-series database
    store: 'PostgreSQL (recent) + TimescaleDB (historical)',
    
    // Push to shipper dashboard
    push: 'WebSocket to shipper dashboard',
    
    // Geofence alerts
    alerts: 'PostGIS geofence check on each update'
  },

  // Scaling
  scaling: {
    // 10K drivers × 1 update/10s = 1K QPS
    approach: 'Redis for latest position, PostgreSQL for history',
    consistency: 'Eventual (10s lag acceptable)'
  },

  // Geofencing
  geofencing: {
    // Check if driver is within delivery area
    query: 'PostGIS ST_Within(driver_location, delivery_zone)',
    frequency: 'On each GPS update',
    alerts: 'Push notification if driver deviates from route'
  }
};
```

## Healthtech Patterns (Docita, healthcare SaaS)

### Appointment Scheduling
```typescript
// Concurrent booking with conflict detection
const appointmentScheduling = {
  // Conflict detection
  conflicts: {
    // Patient cannot be in two appointments at the same time
    patientConflict: {
      query: 'SELECT COUNT(*) FROM appointments WHERE patient_id = $1 AND scheduled_at = $2 AND status = \'booked\'',
      lock: 'SELECT ... FOR UPDATE on patient row',
      response: '409 Conflict if overlap detected'
    },

    // Practitioner cannot have overlapping appointments
    practitionerConflict: {
      query: 'SELECT COUNT(*) FROM appointments WHERE practitioner_id = $1 AND scheduled_at = $2 AND status = \'booked\'',
      lock: 'SELECT ... FOR UPDATE on practitioner row',
      response: '409 Conflict if overlap detected'
    },

    // Room cannot exceed capacity
    roomCapacity: {
      query: 'SELECT COUNT(*) FROM appointments WHERE room_id = $1 AND scheduled_at = $2 AND status = \'booked\'',
      lock: 'SELECT ... FOR UPDATE on room row',
      response: '409 Conflict if capacity exceeded'
    }
  },

  // Lock ordering (prevent deadlocks)
  lockOrdering: {
    order: 'Patient → Practitioner → Room',
    reason: 'Consistent lock ordering prevents circular wait',
    implementation: 'Prisma $transaction with explicit locks'
  }
};
```

### PHI Handling
```typescript
// Protected Health Information (PHI) handling
const phiHandling = {
  // Never expose PHI in logs
  logging: {
    rule: 'Scrub all patient names, IDs, medical data from logs',
    implementation: 'Sentry redactor, custom log filter',
    testing: 'E2E test: trigger error, assert no PHI in Sentry payload'
  },

  // Never cache PHI at CDN
  caching: {
    rule: 'Patient records never cached at edge',
    implementation: 'Cache-Control: private, no-store',
    exception: 'Non-PHI data (clinic info, public pages) can be cached'
  },

  // Audit all PHI access
  audit: {
    rule: 'Every access to patient data is logged',
    fields: ['actor', 'action', 'resource', 'clinicId', 'timestamp', 'ipAddress'],
    retention: '7 years (healthcare requirement)',
    immutability: 'Append-only, no updates or deletes'
  },

  // Data export (GDPR)
  export: {
    endpoint: 'GET /api/patients/:id/export',
    format: 'JSON bundle of all patient records',
    scope: 'Clinic-scoped (admin can only export their patients)',
    retention: 'Export available for 30 days, then deleted'
  }
};
```

## SaaS Patterns (n8n, Contentful, Personio)

### Multi-Tenant Architecture
```typescript
// Shared-schema tenancy
const multiTenant = {
  // Tenant isolation
  isolation: {
    // Every query includes clinic_id
    query: 'WHERE clinic_id = $1',
    
    // Row-level security
    rls: {
      policy: 'CREATE POLICY clinic_isolation ON table USING (clinic_id = current_setting(\'app.current_clinic\')::uuid)',
      implementation: 'Prisma $transaction with SET app.current_clinic'
    },

    // ABAC policies
    abac: {
      subject: 'role, clinic_id, ownership',
      resource: 'clinic_id, created_by, assigned_to',
      decision: 'ALLOW, DENY, NOT_APPLICABLE'
    }
  },

  // Cross-tenant analytics
  analytics: {
    // Separate analytics database (no tenant_id filter)
    database: 'Analytics DB (read replica)',
    queries: 'Aggregate across all tenants',
    access: 'Internal admin only'
  }
};
```

### Workflow Engine (n8n pattern)
```typescript
// DAG-based workflow execution
const workflowEngine = {
  // State machine
  states: {
    draft: 'Workflow defined, not active',
    active: 'Workflow accepting triggers',
    paused: 'Workflow temporarily disabled',
    archived: 'Workflow permanently disabled'
  },

  // Execution states
  executionStates: {
    queued: 'Execution waiting to start',
    running: 'Execution in progress',
    completed: 'All steps succeeded',
    failed: 'One or more steps failed',
    waiting: 'Execution paused (human input needed)',
    cancelled: 'User cancelled execution'
  },

  // Step execution
  stepExecution: {
    // Each step is idempotent
    idempotency: 'Step ID + execution ID = unique key',
    
    // Steps can be retried
    retry: {
      strategy: 'Exponential backoff',
      maxRetries: 3,
      dlq: 'Move to DLQ after max retries'
    },

    // Steps can run in parallel
    parallelism: {
      strategy: 'BullMQ worker pool',
      concurrency: 'Configurable per workflow',
      isolation: 'Separate queue per workflow'
    }
  }
};
```

## Interview Questions (German-Specific)

### Fintech
| Question | Answer |
|----------|--------|
| "How do you handle payment idempotency?" | "Idempotency key in request → stored in DB → checked before processing → prevents double-charge" |
| "How do you reconcile with PSP?" | "Daily batch: compare internal ledger with PSP records → alert on discrepancies → manual review queue" |
| "How do you handle market data feeds?" | "WebSocket for real-time → Redis for latest price → PostgreSQL for historical → cache portfolio valuations with 30s TTL" |

### Logistics
| Question | Answer |
|----------|--------|
| "How do you match shipments with carriers?" | "PostGIS spatial query for route → filter by capacity + timing → score by price + rating → present top 3" |
| "How do you handle real-time tracking?" | "Driver GPS every 10s → Redis for latest position → PostgreSQL for history → WebSocket to shipper dashboard" |
| "How do you handle geofencing?" | "PostGIS ST_Within check on each GPS update → push notification if driver deviates from route" |

### Healthtech
| Question | Answer |
|----------|--------|
| "How do you prevent double-booking?" | "SELECT FOR UPDATE on patient row → check overlap → insert if no conflict → 409 if conflict" |
| "How do you handle PHI?" | "Never in logs, never cached at CDN, audit all access, 7-year retention" |
| "How do you implement tenant isolation?" | "clinic_id on every query + RLS + ABAC + cross-clinic E2E tests" |

### SaaS
| Question | Answer |
|----------|--------|
| "How do you handle multi-tenant data?" | "Shared schema + tenant_id column + RLS + ABAC policies" |
| "How do you handle workflow execution?" | "State machine + idempotent steps + BullMQ for parallelism + DLQ for failures" |
| "How do you handle schema migrations?" | "Expand/contract pattern + backward-compatible code + automated rollback" |

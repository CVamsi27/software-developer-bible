# Weekly Study Review Template

Use one short weekly record to compare planned effort with observed learning. The [study plan](80.13-study-plan.md) owns the schedule; the [preparation tracker](80.10-weekly-tracker.md) owns gap-to-next-action reasoning. Keep completed personal records and application statuses in the [private canonical workspace](personal/README.md).

## First Principles

Planned work and completed work are different observations. A tracker must preserve that difference, record what an attempt exposed and feed the next plan; checking a box cannot establish learning or readiness.

## Record a week without inventing progress

Use this blank structure in your private study record:

| Field | Entry |
| ------------------------- | ---------------------------------------------------- |
| Week and available budget | Dates and realistic hours |
| Upcoming confirmed stage | Format, deadline, required artifact |
| Selected learning goal | One mechanism or explanation to improve |
| Planned task | Relevant chapter, attempt or mock |
| Actual effort | Time used, including setup and feedback |
| Observed result | Correct behavior, missed assumption or blocked check |
| Evidence | Attempt, artifact, feedback or executed result |
| Next action | Repair and changed-case recheck |

A checkbox can record that an activity occurred. It cannot prove the skill was learned. Keep an uncompleted or blocked task visible rather than replacing it with a confidence score.

## Compare the plan with reality

| Observation | Planning response |
| -------------------------------------- | ------------------------------------------------------- |
| A real assignment displaced practice | Record the replacement and respect its actual timebox |
| Setup consumed most of a session | Reduce optional scope and fix the reproducibility issue |
| Same-answer recall improved | Try a changed case before treating it as transfer |
| A failure boundary remains unexplained | Read that mechanism and produce a concrete trace |
| The next interview format changed | Reprioritize against the confirmed stage |
| The budget was unrealistic | Reduce the plan rather than carrying every task forward |

Keep plan and actual totals separate. Do not describe a sixty-hour calendar as a fifty-hour target or count an unrun check as passed.

## Choose the next week from evidence

Keep the most consequential unresolved gap and drop redundant reading. Select a manageable next action and a later recheck. Use [mock feedback](80.30-mock-interview-script.md) for concrete observations and [focused brushup](80.29-topic-brushup-roadmap.md) to locate the relevant chapter.

Track applications separately from learning attempts. Sending a message or application is a campaign action, not proof of technical readiness. Actual target companies, contact details and submissions belong in private records rather than a public repeated table.

## Summary

Record the budget, actual effort, observed result and next action. Use the difference between plan and reality to adjust one canonical schedule.

## First Principles

Clinical data and spatial data depend on meaning beyond their storage type. Identity, units, coordinates, time and provenance determine whether an operation is valid. Naming a standard or library without those boundaries leaves the domain problem unexplained.

## Part I — Healthtech Germany (Snke · MVST · Redcare)

Start with **which clinical information, from which system, for which authorized use**. A schema can be valid while the patient identity, code meaning, units, or clinical interpretation is wrong.

| Term | Role in the information flow |
| --------------------- | ------------------------------------------------------------------------ |
| HIS | Hospital operational and clinical information system |
| RIS | Radiology workflow and reporting system |
| PACS | Imaging storage and retrieval system |
| HL7 v2 | Healthcare message standard used by many integrations |
| FHIR | Resource-based healthcare exchange standard |
| DICOM | Medical imaging information and exchange standard |
| ICD, SNOMED CT, LOINC | Different diagnosis, clinical terminology and observation coding systems |

Do not treat these systems and code sets as interchangeable. An interface needs a version, identifiers, terminology, units, timestamps, authorization and error handling. Duplicate or delayed messages need a defined reconciliation behavior.

### FHIR: model and implementation agreement

FHIR resources such as `Patient` and `Observation` represent exchangeable information. Profiles constrain resources for a use case; an implementation's CapabilityStatement describes its exposed interfaces. FHIR supports multiple exchange patterns and JSON/XML representations, not only REST and JSON. Select the actual version and implementation guide. See the [HL7 R5 overview](https://hl7.org/fhir/R5/overview.html).

A small observation exercise is to represent a measured value with a subject, code, units, status and relevant time, then inspect what the selected profile additionally requires. Do not present an abbreviated JSON object as automatically conformant to every implementation guide. Format validation also does not establish authorization or clinical correctness.

### Regulatory scope starts with intended use

A healthcare label alone does not determine medical-device status. Assess the software's intended purpose and behavior under the applicable framework; storage, transmission, diagnostic support and treatment decisions have different implications. A wellness label cannot override an actual medical intended purpose.

Keep qualification/classification, engineering controls, conformity assessment and certification claims distinct. ISO 13485 terminology alone is not proof of an assessed release process. Use the [compliance guide](80.24-eu-regulatory-compliance.md) and actual product assessment before naming obligations.

## Part II — Geospatial & Satellite Analytics (LiveEO)

Start with **where, when, in which coordinate system, and with what uncertainty**. Spatial proximity and direct intersection answer different questions.

```text
vector: roads, parcels, corridors → geometric relationships
raster: imagery, elevation grids → windows, bands, resolutions
                         ↘ aligned analysis → bounded risk result
```

### PostGIS: choose the predicate and its units

| Mechanism | Meaning and boundary |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| `geometry` | Coordinates and distance in the chosen spatial reference system's units |
| `geography` | Geodetic operations; `ST_DWithin` distance is in meters |
| `ST_Intersects` | Whether geometries share space; it is not a containment test |
| `ST_DWithin` | Whether objects are within a specified distance, with an index-assisted bounding-box stage |
| GiST index | Helps supported spatial search; expression and data distribution still affect the plan |
| `ST_AsMVT` | Encodes rows into vector-tile data; geometry preparation and query scope remain application concerns |

For a thirty-meter asset corridor, use the correct distance relationship with compatible coordinates and tenant/network authorization. Requiring direct intersection as well would wrongly exclude nearby objects that do not intersect. Geometry distance in an angular CRS is not automatically meters; reproject or choose an appropriate geodetic operation.

See the official [distance predicate](https://postgis.net/docs/ST_DWithin.html), [intersection predicate](https://postgis.net/docs/ST_Intersects.html), and [vector-tile encoder](https://postgis.net/docs/ST_AsMVT.html). An SRID label describes a coordinate system; assigning a label is not transforming coordinates. Mixed systems may be rejected rather than silently repaired.

### Imagery: discovery is different from reading pixels

| Term | Purpose |
| ---------------- | --------------------------------------------------------------------------------------------------- |
| STAC | Catalog items and assets with spatial/temporal metadata for discovery |
| COG | Organizes GeoTIFF imagery for efficient partial reads using tiles, overviews and HTTP range support |
| Vector tiles | Deliver bounded geometry for map rendering and client styling |
| GDAL / Rasterio | Tools for raster access and processing |
| Change detection | Compares suitably aligned observations while accounting for acquisition and measurement differences |

A catalog does not process an image, and a COG does not guarantee the serving endpoint supports range requests. See the [STAC specification](https://stacspec.org/en/about/stac-spec/) and [OGC COG standard](https://docs.ogc.org/is/21-026/21-026.html).

### Trace a detection-to-action exercise

```text
scene identity and acquisition time → authorized asset selection
  → aligned processing with model/version provenance
  → bounded detections and uncertainty
  → durable delivery attempt → user review and action
```

Key repeatable work by the relevant scene, region/tile and processing version. Define reprocessing, deduplication, queue limits, missing data and the distinction between detection time and delivery time. Optical and radar observations have different acquisition and interpretation constraints; neither provides a universal all-conditions accuracy guarantee.

## Transfer mechanisms without claiming domain equivalence

Durable work, authorization, observability and API contracts can transfer from another application. Explain the mechanism you actually implemented, then name the new domain knowledge still required. A reliable notification design does not establish image-model expertise; a tenant policy does not establish medical-device or government-clearance compliance.

## Summary

For health data, trace identity, meaning and authorized use. For spatial data, trace coordinates, time, provenance and uncertainty. Learn the standard and version that the actual workflow uses, then keep experience and regulatory claims within their evidence.

# Daily Study Timer — Measure a Session Without Confusing Time With Learning

## Start with a result you can observe

Choose one task before starting the timer: derive an invariant, implement a boundary case, explain a mechanism or check a delayed recall prompt. The timer helps limit the session and estimate future work. It cannot establish whether the explanation or solution is correct.

## First Principles

Elapsed time includes interruptions and breaks, while focused time can still produce an incorrect result. Planning needs both duration and observed outcome. A session record must therefore keep these separate rather than treating minutes or completed timer cycles as mastery.

## Choose a block that fits the task

A twenty-five-minute focus block followed by a five-minute break is one possible structure. A longer uninterrupted task may need another allocation. Choose a feasible duration, pause when necessary and record what actually happened; no fixed timer length guarantees productivity or prevents burnout.

For a sixty-minute practice window, this illustrative allocation is consistent:

| Activity | Minutes |
| --------------------------------- | ------: |
| Define the task and success check | 5 |
| Focused attempt | 25 |
| Break | 5 |
| Focused repair or changed case | 20 |
| Record result and next action | 5 |
| **Elapsed total** | **60** |

The forty-five minutes of focused attempt and repair are separate from setup, break and logging. Eight twenty-five-minute blocks give 200 minutes of focus, not three and a half hours.

## Keep one compact session record

| Date | Task | Planned focus | Actual focus | Breaks or interruptions | Observed result | Next action |
| ----------- | ------------- | ------------- | ------------ | ----------------------- | --------------------------------- | -------------------------------- |
| Actual date | Specific task | Minutes | Minutes | Minutes and context | What worked or failed; hints used | A concrete repair or later check |

For example: “The twenty-five-minute attempt found a correct state definition but failed the empty-input case. The twenty-minute repair added that case; check a variant later.” That supplies more information than a score based only on completed timer blocks.

Use the [progress tracker](81.08-progress-tracker.md) for the learning record rather than maintaining separate daily, weekly and monthly copies of the same results. Aggregate durations only when they help revise the [weekly schedule](81.21-week-study-schedule.md).

## Stop and preserve the useful state

When the block ends, note the current hypothesis, failing example or next step. If the task needs more time, schedule it explicitly. Do not count an unfinished solution as solved because its timer finished.

An ordinary phone, desktop or physical timer is sufficient. For a basic terminal reminder, this command waits twenty-five minutes and prints a message afterward:

```bash
sleep 1500
printf "Study block finished. Record the result and next step.\n"
```

It does not provide a visible countdown, guaranteed audible notification or accurate accounting through system sleep. Use a suitable timer when those features matter.

## Review duration together with outcome

If similar tasks routinely take longer than planned, change the estimate or reduce the session scope. If you work for many minutes without identifying the next step, inspect the missing concept or seek a focused hint rather than maximizing a “focus percentage.”

Minutes per problem are comparable only when difficulty, familiarity and assistance are considered. Avoid universal daily timer quotas or treating breaks as wasted time.

## Summary

Define a task, time the attempt, distinguish focus from elapsed time and record the result. Use the observation to improve the next plan; a completed block is not a correctness or readiness certificate.

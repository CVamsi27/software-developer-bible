# Quick Reference Cards — Keep the Invariant Beside the Technique

[![Role priority](https://img.shields.io/badge/role--priority-Deferred-lightgrey)](../docs/topic-importance.md)
[![General importance](https://img.shields.io/badge/general--importance-Important-blue)](../docs/topic-importance.md)



A useful card preserves the reason an algorithm works. A loop with `condition` or `window_invalid` left undefined hides precisely the decision you need to make.

## Definition

A reference card is a compact reminder of a technique’s state, invariant, assumptions, and failure boundary. The complete implementation and explanation belong in the canonical chapter.

> **Textbook Definition:** A reference card is a compact representation of a learned method’s state, invariant and applicability conditions, used as a cue to reconstruct the method.

## First Principles

Compression removes context. To remain useful, a card must retain the condition that justifies each operation; otherwise two superficially similar problems can invite the same incorrect template.

## Build a card from an observed gap

Choose an error from [your practice log](81.08-progress-tracker.md). Record the missing decision, a tiny trace, and the canonical explanation. Keep only cards that still help with an observed gap. Review questions belong in [category revision](REVISION.md).

## Example card: prefix sums over a half-open range

**State:** `prefix[i]` is the sum of the first `i` values, with `prefix[0] = 0`.

**Operation:** the sum over `[left, right)` is `prefix[right] - prefix[left]`, with `0 <= left <= right <= n`.

```text
values:       3  -2   5
prefix:   0   3   1   6
range [1, 3): -2 + 5 = prefix[3] - prefix[1] = 6 - 3 = 3
```

**Boundary:** an empty range has sum zero. Use a numeric representation large enough for cumulative sums. Updating an input invalidates the old prefix array unless you rebuild it or choose a structure that supports updates.

This card is useful because it states what each index means. “Running sum for range queries” alone leaves inclusive and exclusive endpoints ambiguous.

## Keep these boundaries on the corresponding cards

| Technique | Invariant or assumption to preserve | Common missing boundary |
| ---------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Binary search for the first valid answer | A false-to-true predicate partitions the search domain | Establish that a valid answer exists or define a no-answer result |
| BFS | Queue distance increases by one edge level | Shortest-path claim requires equal edge costs; mark discovery to avoid repeated insertion |
| Kahn’s topological sort | Indegree counts incoming edges not yet removed | Compute indegrees from actual edges first; fewer than `V` emitted vertices means a cycle |
| Tree level traversal | Queue holds discovered, unprocessed nodes | Handle an empty root before adding it |
| BST validation | Each node satisfies bounds inherited from all ancestors | Parent-only comparisons are insufficient; specify the duplicate policy |
| Dynamic programming | State meaning and recurrence determine dependency order | Allocate and initialize only valid base states, including the smallest input |
| Reverse a linked list | The reversed prefix and remaining suffix remain connected through a saved next pointer | Save the old next pointer before replacing the link |
| Largest `k` values | A min-heap retains the largest values seen, up to `k` entries | Define `k = 0`, `k > n`, and whether output order matters |
| Next greater value | Stack stores unresolved indices in monotonic order | Define the result for unresolved indices and whether equal values count |

Follow [coding patterns](../70-interview-toolkit/70.2-coding-patterns/INDEX.md) for complete algorithms and tested examples. These reminders do not replace their input contracts.

## Design cards: record a boundary, not a product list

For a payment retry, a useful card identifies the stable operation key, durable local state, remote outcome lookup, and what happens after a timeout. Listing databases and queues does not establish how a duplicate charge is prevented.

For a saga, record the business steps and compensations. Compensation can fail and does not necessarily restore the world exactly; a saga is not an ACID transaction spanning remote services. See [the design guide](81.03-system-design-apis-security.md).

## Summary

Keep enough context to reconstruct the decision: state meaning, invariant, assumptions, and one boundary trace. Link the implementation rather than duplicating an incomplete template.

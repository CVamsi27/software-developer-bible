# Flashcard Decks — Import Selected Revision Prompts

[![Role priority](https://img.shields.io/badge/role--priority-Deferred-lightgrey)](../docs/topic-importance.md)
[![General importance](https://img.shields.io/badge/general--importance-Important-blue)](../docs/topic-importance.md)



Keep the questions in [category revision](REVISION.md). This page explains how to select and import them without maintaining a second copy of every answer.

## Definition

A flashcard presents a prompt before revealing its answer. It can rehearse a definition, an invariant, or a short reasoning step. Solving a complete problem still requires an implementation and trace.

## First Principles

A prompt must identify enough context for an answer to be judged. “What is the complexity of DP?” has no single answer: count reachable states and work per state. Shortening a prompt must not erase its assumptions.

## Select prompts from an actual mistake

Start with the source-linked group in revision. Select a distinction you missed, such as the difference between an expected hash lookup cost and a worst-case guarantee. Keep the relevant input assumptions in the prompt or answer.

After answering, explain a changed example. If you can repeat the phrase but cannot use it, return to the source chapter and solve a small case. See [reference cards](81.12-quick-reference-cards.md) for preserving an invariant and [the study sequence](81.06-leetcode-study-plan.md) for implementation practice.

## Import a small selection into Anki

1. Put selected prompts and answers into two columns in a plain-text UTF-8 file, separated by tabs. Use actual tab characters.
2. Import the file and inspect the preview. Map the columns to the front and back fields and select the destination deck.
3. Check that each row has the intended two fields. Quote fields containing separators or newlines according to Anki’s text-import rules.
4. Check duplicate handling before importing again. Anki normally uses the first field to identify matching notes of the same type.

Keep the default scheduling settings until you understand them. Adjust the new-card workload to the time you actually have; a preset of twenty new cards per day is not a universal study target.

The import file is a personal export, not another maintained chapter. Correct the canonical revision answer before exporting it again.

## Fix ambiguous cards before repeating them

| Ambiguous claim | Missing condition |
| ---------------------------------------- | ---------------------------------------------------------------------------------- |
| “Two pointers take linear time” | The pointer movements and work per movement determine the bound |
| “Interval DP takes quadratic time” | There may be quadratic states but a linear split loop per state, giving cubic time |
| “BST lookup takes logarithmic time” | A balanced-height guarantee or stated distribution is needed |
| “Quicksort uses logarithmic stack space” | Ordinary recursion can reach linear depth in the worst case |
| “Every hash map resizes at 0.75” | Load policy depends on the implementation and configuration |
| “Horizontal scaling is preferred” | Workload, state coordination, cost and failure requirements determine the choice |
| “A latency target is p95 below 200 ms” | Targets depend on the actual operation and user need |

## Summary

Select revision prompts from observed gaps, preserve their assumptions, and preview a small import before expanding the deck. Test understanding with a changed case as well as recall.

The canonical ledger is [`docs/review-ledger.json`](../review-ledger.json), read
by `scripts/review_ledger.py`. It carries one hash-pinned row per tracked
Markdown file and the six axes a reader can act on: current, readable, concise,
focused, fast, best.

## Measured input

[`page-weight.json`](page-weight.json) is generated by
`python3 scripts/measure_page_weight.py --write`. It maps each tracked Markdown
file to its built HTML page and records raw bytes, gzip bytes, and asset counts.
The enforced transport budget is 64 KiB gzip (`--check`); raw HTML remains a
120,000-byte diagnostic for DOM and review triage, not a failure threshold.
The 25 files in `81-lanes-indian-sde-faang` are `excluded` by `_config.yml`;
they are still reviewed, but their `fast` evidence says they are unpublished.

## Reviewer protocol

Read the file end to end. Do not sample. Then fill one batch entry:

```json
{
  "path": "00-strategy/00.01-communication.md",
  "genre": "chapter",
  "current": "No version-sensitive claim. The advice was checked against the chapter's own examples; no hiring statistic is asserted.",
  "readable": "Full read of 87 lines. It opens with a concrete cached-endpoint answer, then traces listener, decision, pushback and practice.",
  "concise": "644 prose words. Each section adds a distinct move; the mistakes table supplies repairs instead of restating the rules.",
  "focused": "Communication only. Resume and behavioral mechanics are linked, not retold; the analogy boundary is stated where it matters.",
  "fast": "50.4 KB raw / 13.7 KB gzip on the shared shell; text only, within budget.",
  "best": "Genre: strategy chapter. It gives a reusable answer shape plus a failure boundary; the remaining limit is that it cannot prove delivery under a real interviewer.",
  "defects": [],
  "notes": ""
}
```

The gate checks the measurable parts:

- `readable` must say `Full read of N lines`, and N must equal the file's line
  count.
- `concise` must carry a prose word count within 2% of
  `python3 scripts/review_ledger.py words <path>`.
- `fast` must contain the exact value from
  `python3 scripts/review_ledger.py page <path>`.
  The value reports both raw and gzip bytes; only gzip is enforced by the
  page-weight check.
- `current` must name a source, an execution, a version check, or an explicit
  “no version-sensitive claim”.
- `focused` must name the canonical home or the duplication check.
- `best` must name a boundary, limit or failure.
- No row may reuse a 2026-11-14 template phrase.

Useful commands:

```bash
python3 scripts/review_ledger.py template <path>   # skeleton with hash, lines, words, page
python3 scripts/review_ledger.py words <path>
python3 scripts/review_ledger.py page <path>
python3 scripts/review_ledger.py hash <path>
python3 scripts/review_ledger.py apply docs/corpus-review/batches/<batch>.json
python3 scripts/review_ledger.py audit --verbose
python3 scripts/review_ledger.py status
```

A batch is a JSON list of entries, or `{"files": [...]}`. `apply` refuses the
whole batch if any entry fails, so a bad row cannot half-land.

## Repair rules

- Fix both factual/structural defects **and** comprehension barriers (2026-11-23 update). If a chapter reads like dense audit prose or skips concrete traces/examples, rewrite it for clear first-pass understanding while preserving every incoming heading anchor, required section, and authored `REVISION.md` Q/A pair.
- Do not renumber files or change counts by hand. The section owner runs
  `python3 scripts/check_counts.py --write` after the batch is applied.
- Do not run a repository-wide writer concurrently with another reviewer.
- If a fix changes a count, a navigation table or a shared baseline, record the
  issue in the batch and leave the shared file to the section owner.
- Claims that need a paid account, a missing runtime or private source are
  `exception` evidence, not `pass`. Say what could not be verified and why.

## The defect this pass fixes

A section that **names a mechanism and never shows it working**. The reference case was
`10.1.1.07-v8-execution-and-optimization.md`, whose Hidden Classes section stated
"V8 uses an internal Map and descriptors… a shape and a known field offset" without ever
showing what a Map holds, how an object acquires one, or why an offset replaces a lookup.

Contrast: it explained the *conclusion* but not the *model*. A reader could repeat the
sentence and still not predict what happens when two objects are built in a different
order. That is the test for this pass — **can the reader predict an outcome the section
did not spell out?**

Not in scope, because the corpus is not defective there:

- Interview banks and `REVISION.md` files, whose short `###`-per-question shape is correct.
- `INDEX.md` navigation tables and dated plan records under `docs/superpowers/plans/`.
- Advisory lists (`Common Mistakes`, `Best Practices`) that legitimately run short.
- Headings immediately followed by a subheading, which measure as "0 words".

## Method, per file

1. **Read the whole file.** Not a diff, not a section — the pass judges whether the
   chapter builds its model, which only makes sense end to end.
2. **Test the arithmetic and the claims.** Re-derive capacity numbers, re-check version
   claims against their date, and verify that code samples would run as written.
3. **Rewrite only genuine instances.** A section qualifies when it asserts a mechanism
   without an example, a trace, a table or a diagram that makes the mechanism visible.
4. **Leave sound sections alone.** Padding a good section is a defect, not a fix.
5. **Restamp and verify.** Every `.md` edit invalidates its review record in
   `docs/2026-10-25-fullstack-review-records.json`, and the canonical writers
   (`read_time.py`, `gen_master_index.py`, `check_counts.py`) restamp owned claims.
   Then `bash scripts/verify.sh` must pass.

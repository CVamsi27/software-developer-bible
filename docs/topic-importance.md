# Topic importance for your full-stack preparation

Each topic has two independent badges. **Role priority** follows your current React/TypeScript/Node.js full-stack goal, across remote India/global work and conditionally eligible remote EU/Germany roles, with emphasis on end-to-end feature ownership, core engineering and system design. **General importance** describes the concept’s breadth across software engineering. These are editorial study decisions, not hiring statistics or a guarantee of interview coverage.

## What the two tags mean

| Role priority | Study decision |
| ------------- | --------------------------------------------------------------------------------------------------------------- |
| Essential | Build and explain the mechanism; practise its failure cases during the active interview cycle |
| Important | Learn the mechanism and a relevant example after the core; deepen it when a résumé claim or vacancy requires it |
| Optional | Skip detailed study for now unless a concrete product or vacancy needs it |
| Deferred | Outside the current target track; reconsider if the target changes |

| General importance | Meaning |
| ------------------ | ----------------------------------------------------------------------------------------- |
| Foundational | A broad building block that other engineering decisions rely on |
| Important | A common professional capability or recurring design decision |
| Specialized | Valuable within a particular technology, domain or workload; not a dismissal of its value |

General importance is independent of your role priority. A specialized mechanism can be Essential for your own project, and a broadly important technology can be Deferred for this search. A badge prioritizes the topic’s main mechanism; it does not require memorizing every implementation detail or example on the page.

## Your study order

1. **Core language and runtime:** JavaScript execution, values, closures, promises, errors, TypeScript contracts and Node.js request/resource behavior.
2. **Product implementation:** React state, identity, effects and forms; NestJS/HTTP boundaries, PostgreSQL queries and transactions, authorization, tenant isolation and meaningful testing.
3. **System design:** requirements and invariants, consistency, caching, queues, retries, idempotency, capacity, overload and recovery. Practise representative cases rather than memorizing all architectures.
4. **Project evidence:** trace Docita and MAQ work you actually performed; connect each résumé claim to a mechanism, check and limitation.
5. **Working delivery depth:** Docker, CI/CD, observability, release compatibility and rollback; learn the tools you operate before deeper platform specialization.
6. **Conditional specialization:** GraphQL, Kubernetes/IaC, deeper broker administration, AI serving, mobile and motion libraries when a relevant role needs them.

Continue applying while studying. Essential is a learning queue, not a requirement to finish the entire corpus before submitting an application. Use your private execution plan (career workspace, kept outside this repository) as your timetable.

## HTML and CSS: a practical baseline

Learn semantic elements, labels and forms, keyboard behavior, the cascade, specificity, box model, Flexbox/Grid and responsive layout. Build a usable form and list at narrow and wide widths. Explain loading, error and empty states without relying on visual polish.

Browser rendering and storage remain important because they connect to interaction performance, hydration and session safety. CSS architecture needs working understanding; deep design-token systems, PWA/offline behavior and SEO can wait unless the target product needs them.

## Animation: optional depth, essential accessibility boundaries

You can skip the animation library chapters for the current preparation cycle. Still respect reduced-motion preferences if the product already contains motion, preserve keyboard access and avoid making motion the only way to communicate state. The animation badge does not make accessibility optional.

## How to use a mixed category or interview companion

Topic rows in INDEX tables show both priorities before you open the page. A category’s revision/drill covers several concepts, so its badge is a category-level starting point: practise Essential concepts first and select specialist questions only when relevant. Do not infer that every question in a mixed companion has equal priority.

Next.js remains a working-depth improvement area rather than a claim that Docita uses it. AI topics matter for defending the bounded features on the résumé, while advanced model hosting can follow a concrete need. Java and the Indian SDE lane remain Deferred in this cycle.

## Maintaining the classifications

The [per-topic assessment](topic-importance.csv) is the recorded mapping with a rationale for every tagged page. Keep its row, the topic metadata/badges and the corresponding INDEX table entry consistent when changing priorities. Reassess against the actual vacancy; general importance should not change merely because one advertisement names a tool.

Run the repository’s verification gates after edits. These validate formatting, links and metadata consistency; they do not independently prove that an editorial importance judgment is correct.

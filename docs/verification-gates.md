# Verification Gates — what enforces what

> **TL;DR:** Every integrity claim in this repo is enforced by a script, and
> `bash scripts/verify.sh` runs all of them. This page maps each gate to the
> rule it enforces, the files it scans, and the canonical fix when it fails.
> Gates are cheap by design (stdlib text scans) so they run on every push,
> not on a schedule. For the full scripts inventory — fixers, restampers,
> workflow tools, and the doctrine for adding new scripts — see
> [Scripts Map](scripts-map.md); for the design rationale — why the suite is
> shaped the way it is — see [Gate Design Principles](gate-design-principles.md).

Run everything locally before any commit:

```bash
bash scripts/verify.sh          # all 21 gates; exit 1 blocks the push
```

CI (`.github/workflows/code-whitespace.yml`) runs the same scripts on every
push/PR — a red X means a gate your local run should have caught.

| 1 | `check_counts.py` | Every count in the navigation surface matches live disk: repo-scale strings ("866 files, 365K lines"), each INDEX's `Files` badge **and** its `> **N files** …` opening blurb, the `N files in M sub-stacks` stack headers, the `Files` column of every navigation table, and the prose counts that quote one (interview banks, cheat-sheet formats, `{% raw %}` files, the walker-scope self-description on this page, and the totals example in `docs/api-contract.md`, sourced from the generated `api/index.json` that gate 14 byte-locks). | 2 | `check_alignment.py` | Table pipes and ASCII box walls align (screen-width safe), **and every table has a header row**. | 3 | `check_structure.py` | Unified numbering: IDs resolve, sequences contiguous, interview files last — concretely, every **flat** stack (files directly in the folder, no `NN-category/` subfolders) must carry at least one `*-interview-questions.md`; category stacks instead hold a single bank in a dedicated final interview category. `70.1` (behavioral drills) and `70.3` (cheat sheets) are exempt by name — those stacks *are* interview material. The gap was real: `40.9` and `40.11` grew concept chapters but no bank while sibling `40.12` had one. Also **no two H2 sections in one file may share a slug** — a duplicate means two identically-named outline entries and an ambiguous anchor, and it is the tell that repeated sub-structures were written as *siblings* rather than nested under their section. `80.12-story-bank.md` presented 13 stories as 65 sibling H2s with no story titles at all, and `81.05-advanced-topics.md` declared "Segment Tree" twice in a row while mixing topic titles with their own subsections. Repeats belong at `###` or deeper, where the same label under a different parent is legitimate (the 13 per-story `### Situation` blocks). Also enforces **exactly one H1 per document** (Jekyll front-matter pages exempt) — the title IS the document; the legacy `# Phase N:` / `# Wave N:` stubs in 81.01–81.04 and the outreach playbook buried it under competing H1s and flattened the outline, and were normalized in one deliberate pass. Also enforces **INDEX completeness** — an INDEX.md in a numbered directory must link every numbered subdirectory that has its own INDEX.md, so a sub-stack can never become invisible to navigation again (the top INDEX's 20.9 Message Brokers row was hand-omitted while the computed count above it said the stack existed; a link to the subdir, its INDEX.md, or any file directly inside it satisfies the rule). Also enforces **doc reachability** — every file under `docs/` (except `superpowers/` planning material) must be reachable by a link graph walk from README.md, the root INDEX, `contributing.md`, or any lane/stack INDEX, transitively through other reachable docs (the first-visitor pass found 7 of 10 docs linked from nowhere outside the folder — invisible documentation is the doc-layer twin of the invisible sub-stack). Also enforces **chapter reachability** — every non-INDEX file under the study stacks (10-70) must be linked from at least one INDEX.md, the file-level twin (a chapter written without its INDEX row is invisible to navigation; the baseline held at 556/556 linked). | Rename/renumber per the gate's message; for a duplicate H2, nest the repeats as `###` (and see contributing.md "Unified numbering"). |
| 4 | `check_links.py` | Zero broken internal links (fence-aware, anchor-verified) **and zero stale link *labels***. Every relative prose link must resolve, and a visible label that is itself a relative path (`../../2-Backend-Stack/12-Microservices/03-Saga-Pattern.md`) must point at a path that exists — those are pre-renumbering relics where the *target* was updated but the *label* was not, so a target-only checker never sees them while the reader is shown archaeology from a folder layout that no longer exists. The Sept 2026 redundancy audit fixed 10 such lines in 2 files; ~18 more survived in 10 files undetected, including two links that displayed a dead path *and* pointed at the wrong destination (Observability and Microservices both silently resolved to the local theory INDEX). Spaced labels (the generated `← Previous: ../02 Io And Data/index` footers) are humanized titles, not paths, and are not judged; post-mortem reports under `personal/` are exempt because they quote dead paths as documentation. | Fix the path/anchor the gate prints; for a stale label, rewrite it as the target's human title (a reader should never see a folder path). |
| 5 | `check_freshness.py` | Known stale-API signatures can't ship (deprecated `url.parse`, sync Next.js `params`, fake archive timestamps, …), and **base-image pins past end-of-life fail automatically** — `EOL_BASE_IMAGES` is a date-gated data table (`{major: eol_date}` per image); when a pinned major crosses its EOL date the gate starts failing the same day, no regex edit needed (added after ~55 Dockerfile examples were found pinning node:18/20, both past EOL, with the corpus drifted against itself). | 6 | `link_baseline.py` (diff) | Every cited external URL is in the probe-verified baseline. | Probe-verify each new URL in a browser, then `python3 scripts/link_baseline.py --update` and commit the JSON with the doc change. |
| 6b | `check_template.py` | Chapter template: required sections per genre, canonical order, and the file-metadata contract (comment at top, canonical category, 4 badges present and **ordered and correctly targeted** — content-file badges must link to `#` per contributing.md's "File Metadata"; only INDEX/README Files badges point at the central INDEX. Twelve newly authored chapters had drifted to `INDEX.md`/`../../INDEX.md` because only presence and order were ever checked). It also rejects **empty sections** — a heading immediately followed by a heading at the *same or shallower* level, which renders as a dead entry in the outline with its apparent children sitting beside it (`## Remediation Strategies` → `## Strangler Fig Pattern`, `## Consensus Algorithms` → `## Raft`). | 15 | `check_verify_wiring.py` | **The harness audits itself, and so does CI.** Locally: every gate's failure branch sets the same variable the trailing summary reads; no `X=$((X+1))` on an uninitialized variable (the `set -u` abort); every script a gate invokes exists; gate labels are unique, gap-free and monotonic; and the gate count quoted in `verify.sh`, `contributing.md` and this page all agree. | 17 | `test_fixers.py` | The fixers' repair output is pinned by planted-defect round-trip tests. The gates catch defects; these catch **fixers that repair wrongly** — the failure mode this session proved real twice (a repair pass built on a naive fence toggle corrupted three files, and the desyncing box fixer silently skipped whole files). Each case plants one canonical defect in a temp-tree sandbox (every fixer derives its repo root from `__file__`, so the real corpus is never touched) and asserts the repaired file **byte-for-byte** against the fixer's recorded contract — table/box alignment canonical form, trailing-whitespace scoping, paste-shift rebasing, box narrowing arithmetic, brace-depth rebasing inside box walls — plus idempotence and a no-mangle negative case (canonical content passes through byte-identical). | 18 | `test_gates.py` | **The suite self-test: the gates still catch, not just pass.** Every rule was plant-tested once at creation and never again — a gate that silently stops firing after a refactor would stay green forever, and gates 15–17 watch wiring, the fence reader and the fixers, not detection itself. Each sandboxable gate's canonical defect is planted in a temp tree and the gate must exit non-zero (**fire side**); the same gate then runs on clean content — including a real, currently-passing corpus chapter, so a gate broken to fire on everything cannot pass either (**clean side**). Honest exclusions are named in the script's docstring: the baseline diff needs git history, twins/first-principles need real corpus baselines, and the byte-locked generators are their own plant test (any drift fails verify) — while the corpus-scale gates (cross-refs, freshness, duplication) turned out to be provable with **realistic plants** (chapter-shaped files in real directory structure; naive snippet plants do not fire, itself worth pinning). The two-sided design caught its first bug before landing: the wiring checker's write path defaulted the spelled count past twenty while its check path did not — write stamped "21", check compared against nothing. | `python3 scripts/test_gates.py` — if it fails, a gate's detection drifted; fix the gate, not the plant. |

Two walks exist, and knowing which is which explains most "why wasn't this
flagged?" surprises:

**Filename-numbered concept chapters** — gate 9 (`check_first_principles.py`)
walks every top-level dir starting with a digit and selects files matching
`N(.N)+-` that aren't interview/cheat/quick-reference. This *includes* the
80-lanes trees (their planning docs carry First-Principles sections too) and
*excludes* INDEX files and interview banks by name.

**All content markdown** — gates 6b, 10–13 walk every `*.md` outside
`INDEX.md`/`README.md` and the exempt prefixes (`80-lanes-*`, `81-lanes-*`,
`projects/`, and for 6b `docs/`), i.e. today's 560 content files (the same
computation `check_counts.py` uses for the "search all N chapters" claim, so
the two cannot disagree). Lanes and
projects are exempt *here* on purpose: they are personal campaign/planning
material with their own genres (phase guides, trackers), not chapter-shaped
teaching documents. Gate 7 (`check_claims.py`) covers their campaign-content
risk separately.

**Whole-tree** — gates 1–5, 8–8c (counts, alignment, structure, links,
freshness, whitespace) scan everything including lanes and docs, because
broken links and misaligned tables are genre-independent defects. Gate 14
regenerates `search.html` from gates 6b+13 data, so it inherits their scope.

**Not content at all** — gate 15 (`check_verify_wiring.py`) never reads a
chapter. It reads only `scripts/verify.sh`, `contributing.md` and this page,
checking the harness's own wiring and self-description. It is the only gate
whose subject is the gate system, and it exists because a gate can be
perfectly correct and still not block anything.


## Adding a gate

1. Write `scripts/check_<thing>.py`, stdlib-only, exit 0/1, deterministic
   (sort every walk — union-find over unsorted `os.walk` produced different
   twin groups on macOS vs Linux once). Prefer giving the gate a `--write`
   that *restamps* the claim from the same computation it checks (the
   `check_counts.py` / `read_time.py` pattern): a claim with one owner and a
   rewriter cannot drift, and the fix command is never guesswork.
2. Prove it can fire — **both halves**. Plant the defect in a scratch file and
   watch the *script* fail, then run `bash scripts/verify.sh` and confirm it
   fails too. The second half is not ceremony: gate 10's failure branch wrote a
   variable named `FAILURES` instead of `FAIL`, so its own correct `exit 1`
   never reached the suite's exit code and a broken cross-reference passed CI
   for as long as the bug existed. Gate 15 now checks that wiring statically —
   run it after touching `verify.sh`, and remember that planting a defect
   manually leaves the tree dirty if the script you test aborts early (use a
   scratch copy and restore in a `finally`).
3. Calibrate to corpus reality (both documented TL;DR styles, case-study
   genre, …) — a gate stricter than the corpus buries real signal in noise.
4. Wire it into `scripts/verify.sh` with the canonical fix in the FAIL
   message, add the CI step, and add a row here. Use `FAIL=1` in the failure
   branch — gate 15 enforces that, along with the label order and the gate
   count quoted in all three files (`--write` restamps the count). If you add
   a CI step, make it propagate its exit status (`exit "$code"` after
   `set +e`) and make sure the workflow's `paths:` filter covers the script;
   gate 15 enforces both, so a gate that cannot fail the job and a gate that
   no push can trigger are caught before they ship.
